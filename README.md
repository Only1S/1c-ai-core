# ones-core — Claude Code для разработки на 1С

Плагин для Claude Code. С ним Claude работает с конфигурацией 1С как аккуратный разработчик. Факты он берёт из справки по платформе, стандартов и индекса кода, а не из памяти. Метаданные, формы, роли и отчёты он правит проверенными скриптами. Каждый изменённый модуль он проверяет. Опасное плагин запрещает: сброс git, работу с рабочей базой, ручную правку объекта поставщика.

## Как подключить

Понадобятся: Claude Code, Git, Python 3.8 или новее, Java 17 или новее (для справки по платформе) и установленная платформа 1С 8.3. Репозиторий закрытый — нужен доступ к нему на GitHub (вход: `gh auth login`).

В папке проекта выполните команду:

```bash
claude plugin install ones-core --marketplace Only1S/1c-ai-core --scope project
```

Затем откройте проект в Claude Code и наберите `/ones-core:setup`. Команда спросит, где лежит выгрузка конфигурации и какая у вас платформа. Потом она покажет, что изменит, и после вашего «да» подключит проект и поставит программы инструментов.

### Что спросит `/ones-core:setup` и где это взять

| Вопрос | Что это | Где взять |
|---|---|---|
| Папка выгрузки | Конфигурация в виде файлов: папка `src` с файлом `Configuration.xml` (или проект EDT) | Конфигуратор → «Конфигурация» → «Выгрузить конфигурацию в файлы»; или скилл `ones-core:db-dump-xml`. Держите выгрузку вне папки проекта, если она большая |
| Платформа 1С | Папка `bin` установленной платформы, например `C:\Program Files\1cv8\8.3.27.2214\bin` | Команда сама покажет найденные версии; выберите ту, под которой работает ваша база |
| Порт `1c-toolkit` | Номер порта сервера внутри тестовой базы, по умолчанию 6003 | Если на этой машине несколько проектов — у каждого свой порт. Сам сервер запускается обработкой `MCP_Toolkit.epf` в **тестовой** базе |
| EDT | Нужен ли сервер `edt-mcp` | Только если проект ведётся в 1C:EDT |

Что команда сделает:

- заведёт git: история проекта обязательна;
- запишет запреты опасных команд в `.claude/settings.json`;
- запишет переменные проекта в `.claude/settings.local.json` — этот файл не попадает в git;
- добавит в `.gitignore` секреты и журналы;
- поставит проверку секретов и правил сообщения перед каждым коммитом;
- подключит выгрузку к фоновому индексатору кода. Без него сервер `code-index` не отвечает. Автозапуск при входе в Windows — только после вашего «да»;
- создаст папку `docs-project/` для журналов.

Перед записью команда покажет список изменений и дождётся вашего «да».

После подключения отметьте каждую базу в `.v8-project.json` полем `"pd"`: `"none"` — данных о людях в базе нет, `"masked"` — копия обезличена. Без отметки данные базы к Claude не уходят: инструменты `1c-toolkit`, которые их отдают, откажут, а метаданные и код читаются как обычно. Отметку ставит владелец данных.

## Что внутри

| Что | Для чего |
|---|---|
| **Скиллы** (104) | Изучить и изменить объект метаданных, управляемую или обычную форму, роль, отчёт (СКД), макет, расширение; выгрузить и загрузить конфигурацию; перевести доработанную типовую на новый релиз поставщика; составить и ускорить запрос; работать с БСП; нарисовать схему доработки; решить, какие тесты нужны; написать сценарий Vanessa Automation; проверить 1С через веб-клиент |
| **Проверка модулей** | Каждый изменённый модуль `.bsl` сразу проверяет анализатор; ошибка возвращается Claude, и он её исправляет |
| **Проверка в клиенте 1С** | Скилл `vanessa` пишет сценарий только из библиотеки готовых шагов (1569) и проверяет его; `/ones-core:tests vanessa` гоняет сценарий на тестовой базе. Как настроить — раздел «Тесты на тестовой базе» ниже |
| **Защита** | Отказ на опасные команды (сброс и перезапись истории git, удаление файлов, чтение ключей и `.env`, изменяющий SQL к серверу не из реестра, остановка процессов 1С по имени), на работу с незарегистрированной (боевой) базой, на ручную правку объекта поставщика на поддержке. Данные базы — только с баз с отметкой `pd`. MCP-серверы — только свои: из `.mcp.json` проекта, плагина и списка `ONEC_MCP_ALLOW` |
| **Справка и стандарты** | Серверы `v8std` (стандарты 1С), `bsl-platform` и `bsl-context` (методы и типы платформы, проверка выражений), `code-index` (кто кого вызывает в вашей конфигурации), `bsl-ls` (анализ модулей), `1c-toolkit` (запросы к тестовой базе) |
| **Правила работы** | Как проектировать до кода, как называть объекты, как проверять, как писать тексты — по темам в `plugin/docs/`; Claude получает их сам |
| **Команды** | `/ones-core:setup` — подключение, `/ones-core:consilium` — разбор задачи пятью ролями, `/ones-core:plan` — карточка доработки и её стадии (`new`, `move`, `close`), `/ones-core:tests` — прогон тестов YAXUnit и сценариев Vanessa, `/ones-core:toolkit [база] [порт]` — поднять сервер `1c-toolkit` на тестовой базе (по умолчанию — на базе `default` из реестра), `/ones-core:protect` — запутать модули выгрузки перед поставкой (программу для этого команда при первом запуске предложит скачать из канала), `/ones-core:version` — какая версия плагина стоит в проекте и нужно ли обновляться, `/ones-core:report-issue` — сообщить о проблеме |

## Тесты на тестовой базе

`/ones-core:tests` прогоняет юнит-тесты YAXUnit и сценарии Vanessa Automation на тестовой базе и показывает итог таблицей:

```
/ones-core:tests yaxunit <имя тестового расширения>
/ones-core:tests vanessa <путь к .feature>
```

Без аргументов команда прогоняет оба вида.

Что нужно сделать один раз:

1. **Запишите тестовую базу в реестр.** База должна быть в `.v8-project.json` с отметкой `"pd": "none"` или `"pd": "masked"`. Базу без отметки прогон не откроет.
2. **Поставьте программы.** Скажите Claude: «поставь программы для тестов». Он запустит установщик плагина: для Vanessa это OneScript, vanessa-runner, vanessa-add и vanessa-automation. Свой OneScript укажите в переменной `ONEC_ONESCRIPT_HOME`. Расширение движка YAXUnit установщик кладёт в папку программ плагина; загрузить его в тестовую базу Claude поможет по вашей просьбе.
3. **Задайте вход в базу.** Если база просит логин и пароль, задайте переменные среды Windows `ONEC_DB_USER_<id>` и `ONEC_DB_PWD_<id>`, где `<id>` — имя базы в реестре. Без них прогон входит под пользователем Windows. Пароль в файлы проекта не пишите.
4. **Получите сценарий.** Попросите Claude: «напиши сценарий Vanessa для …». Скилл `vanessa` соберёт `.feature` только из библиотеки готовых шагов и проверит его. Тест YAXUnit пишет скилл `yaxunit`.

Итог прогона — «зелёные», «КРАСНЫЕ» со списком упавшего или «не выполнен», если движок не подключился или клиент не вошёл в базу. Пропущенный тест или шаг сценария проходом не считается. Отчёт Vanessa лежит в папке `<сценарий>.report`.

## Обновление

```bash
claude plugin marketplace update ones-core
claude plugin update ones-core@ones-core --scope project
```

Вторую команду запускайте в папке проекта, затем перезапустите Claude Code. После обновления на новую мажорную версию (например, с 4.x на 5.x) повторите `/ones-core:setup` — что ещё сделать, написано в блоке «Нужно сделать при обновлении» записи версии.

Что изменилось в каждой версии — в [RELEASES.md](RELEASES.md) и на страницах Releases. Новые версии программ инструментов ставит тот же установщик: команду подскажет сообщение в начале сессии.

## Если что-то не так

Наберите `/ones-core:report-issue` — команда соберёт версию и итог проверки и откроет Issue после вашего «да». Или заполните форму на вкладке Issues.

Установка падает с `Filename too long` — папка настроек Claude Code лежит слишком глубоко для Windows. Разрешите git длинные пути и повторите установку:

```bash
git config --global core.longpaths true
```
