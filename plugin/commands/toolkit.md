description: Поднять сервер 1c-toolkit на тестовой базе — открыть её с обработкой MCP_Toolkit.epf; если сервер уже работает, второй сеанс не открывается
argument-hint: [база] [порт]
---
Подними сервер `1c-toolkit` на тестовой базе проекта. Говори с пользователем простыми словами. Аргументы команды: `$ARGUMENTS`.

1. **Какая база.** Без аргументов — база `default` из `.v8-project.json`. Первый аргумент — id другой базы из этого реестра (`--db <id>`), второй — порт (`--port <порт>`), по умолчанию — переменная `ONEC_TOOLKIT_PORT`. **Только тестовые базы:** если выбранная база не тестовая — остановись и скажи об этом (боевые базы не регистрируются — secrets-and-production-database).
2. **Запуск:** `python "${CLAUDE_PLUGIN_ROOT}/tools/1c/run-1c-toolkit.py" --plugin-data "${CLAUDE_PLUGIN_DATA}"` и, если заданы, `--db <id>` и `--port <порт>`. Тонкий клиент `1cv8c.exe` вместо толстого — поле `"client": "thin"` у базы в `.v8-project.json` или ключ `--client thin`. Скрипт открывает базу через скилл `db-run` с входом `/WA` и ждёт, пока сервер начнёт слушать порт (до 3 минут). Если порт уже слушает — сразу выходит, второй сеанс 1С не открывает; на какой базе работает тот тулкит, скрипт не проверяет — скажи это пользователю.
3. **Итог:** код 0 — сервер работает. На порту `ONEC_TOOLKIT_PORT` его инструменты (`execute_query` и др.) доступны через сервер `1c-toolkit` плагина; на другом порту — через свой сервер проекта в `.mcp.json` с этим портом (если его нет — скажи, что нужно добавить). Код 1 — прочитай `logs/1c-toolkit.log` проекта и объясни причину: чаще всего вход по `/WA` не настроен для этого пользователя Windows или обработка ждёт подтверждения в окне 1С. Код 2 — нет такой базы в реестре (скрипт перечислит зарегистрированные), нет обработки (поставит установщик программ — команду подскажет сообщение в начале сессии) или скилла `db-run`.
