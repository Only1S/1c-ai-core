Прогони проверки доработки и отчитайся вердиктом. Аргументы: `$ARGUMENTS`. Первое слово — движок: `yaxunit` (логика, юнит-тесты), `vanessa` (поведение в клиенте 1С, сценарии), `all` или пусто — оба. Остальное — имя тестового расширения для YAXUnit или путь к `.feature` для Vanessa.

**0. База — только тестовая.** Её берут харнессы из `.v8-project.json` проекта (по умолчанию — `default`). Незарегистрированная база считается рабочей, туда не ходим (secrets-and-production-database). Нет тестовой базы — скажи владельцу, какую базу добавить в реестр, и остановись. Харнесс отказал с `personal-data-masked-from-1c` — у базы нет отметки `pd: none` или `pd: masked`: тест выполняет код на данных базы, а текст падений идёт к модели. Отметку ставит только владелец: скажи ему, какую базу отметить, и остановись.

**1. YAXUnit — юнит-тесты логики** (рецепт — docs/tools/task-recipes.md §12):

```bash
python "${CLAUDE_PLUGIN_ROOT}/tools/yaxunit/run-tests.py" --project . [--base <id>] [--extensions <ИмяРасширенияТестов>] [--no-skips]
```

В мастере ядра — `python plugin/tools/yaxunit/run-tests.py …`. Харнесс сам пишет `run-config.json` в `logs/yaxunit/<метка>/`, запускает клиент без ожидания процесса, ждёт файл кода выхода до 120 с, при зависании останавливает только свой процесс. Вердикт — по отчёту этого прогона:
- **зелёные** — тестов N, падений 0, пропущено 0;
- **зелёные с пропусками** — прошли не все: пропущенный тест не проверен, назови его владельцу. Тест обязателен (тест на баг, приёмка) — запускай с `--no-skips`: тогда пропуск даёт **НЕ зелёные**; все тесты пропущены — **не выполнен**;
- **КРАСНЫЕ** — список упавших тестов с сообщениями утверждений: правка не готова (full-checker-set-before-done), чинить код, а не тест — если тест не тавтологичен (§12 «Каким должен быть тест»);
- **не выполнен** — движок не подключился или клиент завис: причины по §12 п.4 (в модуле приложения хоста нет `ПриНачалеРаботыСистемы()`, расширение YAXUnit не применено `ibcmd config apply --extension`, режим совместимости расширений хоста выше движка). Установить движок: расширение `YAxUnit-<версия>.cfe` из `bin/yaxunit/` папки программ плагина — по §12 п.4, скиллом `db-cfe-admin` для проверки применимости.

**2. Vanessa — сценарии в клиенте 1С** (скилл `vanessa`):
- Нет `.feature` — сперва собери сценарий скиллом `vanessa` из библиотеки шагов (свои шаги не придумывать) и прогони его валидатор.
- Прогон:

```bash
python "${CLAUDE_PLUGIN_ROOT}/tools/vanessa/run-scenario.py" "<путь к .feature>" --project . [--base <id>]
```

В мастере ядра — `python plugin/tools/vanessa/run-scenario.py …`. Харнесс сам гоняет валидатор (красный — сценарий не запускает), отчёт кладёт в каталог `<сценарий>.report`, засчитывает только отчёт этого прогона. Нужны OneScript с vanessa-runner и vanessa-add — нет их, харнесс скажет «не найден OneScript»; поставить один раз на машину: `python "${CLAUDE_PLUGIN_ROOT}/tools/setup/install-tools.py" --only onescript vanessa-runner vanessa-add vanessa-automation` (своя установка — `ONEC_ONESCRIPT_HOME`); вход в базу — переменные окружения `ONEC_DB_USER_<id>` и `ONEC_DB_PWD_<id>`, иначе вход ОС. «не выполнен» при коде vrunner 0 — клиент не прошёл вход в базу или не стартовал; «не выполнен полностью» — в отчёте есть пропущенные сценарии или шаги: сценарий проверки обязателен, пропуск не проход.

**3. Итог для владельца — таблицей:** движок · что прогнано (расширение или сценарий) · вердикт · что упало (имя и сообщение) · что делать дальше. Красное или «не выполнен» — правка не готова, коммит вехи не делать. Результат назвать в отчёте по чекерам (full-checker-set-before-done).

**4. Новый тест на баг — до фикса и красным** (bug-diagnosis-loop): сначала прогон показывает красный, потом правка, потом зелёный тем же харнессом с `--no-skips`, чтобы пропущенный тест не сошёл за зелёный. Тест YAXUnit пишется скиллом `yaxunit` (структура модуля, утверждения и моки по справочнику API движка), сценарий Vanessa — скиллом `vanessa`.
