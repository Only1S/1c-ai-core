---
description: Защитить XML-выгрузку проекта закрытым движком обфускации (переименование, сокрытие строк, запутывание ветвлений) — машинным бинарником ones-core, без исходников движка
---
Защити выгрузку проекта закрытым движком обфускации. Говори простыми словами, вопросы — окном вариантов.

1. **Узнай** (одним окном вариантов, рекомендуемый вариант первым): папку XML-выгрузки (`src` с `Configuration.xml` или объект обработки/расширения) и приёмы защиты — по умолчанию переименование + сокрытие строк (`--strings`) + запутывание ветвлений (`--flow`). Куда собрать (`--out`) — новая пустая папка; исходники из `--src` не меняются.

2. **Проверь движок.** Бинарник — `${CLAUDE_PLUGIN_DATA}/bin/obfuscator/onescore-obfuscator.exe`. Если его нет, скажи и предложи поставить (скачивание закрытого бинарника из релиза канала, авторизация GitHub проекта): `python "${CLAUDE_PLUGIN_ROOT}/tools/setup/install-tools.py" --dest "${CLAUDE_PLUGIN_DATA}/bin" --only obfuscator`. Только после «да».

3. **Собери защищённую поставку:** `python "${CLAUDE_PLUGIN_ROOT}/tools/obfuscator/protect.py" --engine "${CLAUDE_PLUGIN_DATA}/bin/obfuscator/onescore-obfuscator.exe" --src "<выгрузка>" --out "<папка сборки>" --strings --flow [--keep <файл неприкосновенных имён>] [--report "<отчёт.json>"]`. Перескажи отчёт простыми словами: сколько модулей обработано, что переименовано/скрыто/обёрнуто, что отклонено и почему.

4. **Живые шаги — по слову владельца, на ТЕСТОВОЙ базе:** собрать `.epf`/`.erf` (скиллы `epf-build`/`erf-build`) или загрузить конфигурацию/расширение в тестовую базу; прогнать тесты YAXUnit на исходной и на собранной поставке — **поведение должно совпасть**; запустить форму в веб-клиенте; замерить скорость. Боевую базу не трогать.

5. **Замок модулей** (поставка без исходного текста, пароль, запрет изменений) — отдельный штатный шаг платформы, для режима `hidden` необратимый. Если нужен, собери файл политики `{"hidden": ["<модуль>"], "encrypted": ["<модуль>"], "support_ban": true}` и покажи план: `python "${CLAUDE_PLUGIN_ROOT}/tools/obfuscator/lock.py" plan --platform <8.5.1|8.3.27> --policy "<политика.json>" [--access-list "<файл GET>" --set-out "<файл SET>"]`. На 8.3.27 план — инструкция для Конфигуратора, на 8.5.1 — пакетные команды. Применяет владелец или ты по его слову и только на тестовой базе. Пароль — только в `ONEC_OBFUSCATOR_MODULE_PASSWORD`, файл SET после применения удалить. После замка и после любой загрузки конфигурации выполни `/UpdateDBCfg`, сними список GET заново и сверь режимы: `lock.py verify --policy "<политика.json>" --access-list "<файл GET>"`, о пропущенной строке платформа не сообщает, а до обновления базы список показывает прежние режимы. Загрузка со списком, где есть `Configuration.xml`, подхватывает открытый текст модуля из папки, даже если его нет в списке, и снимает замок без предупреждения: держи для закрытого модуля в папке `Module.bin` из свежей выгрузки. Замок идёт только поверх обфускации: на 8.5.1.1343 рядом с закрытым модулем может остаться до 0,5 КБ исходного текста, а малый модуль — целиком, и в файле поставки `.cf`, и в XML-выгрузке, в режимах `hidden` и `encrypted` (хвосты страниц контейнера, `v8unpack` их не показывает). Имена методов тоже видны.

Итог: что собрано, где лежит, что проверить на тестовой базе. Движок закрыт — раздаётся машинным кодом, исходники не входят.
