# Правило: использовать только свой MCP

Проект работает **только с теми MCP-серверами, что объявлены в `.mcp.json` его папки и в `.mcp.json` плагина ones-core** (общие серверы — к проекту их привязывают его переменные `ONEC_PROJECT_SRC`, `ONEC_PLATFORM_BIN`, `ONEC_TOOLKIT_PORT`). Не обращаться к MCP другого проекта или чужой конфигурации — даже если такой мост доступен в текущей сессии.

**Why:** изоляция и предсказуемость. Чужой мост может вести в другую (в т.ч. боевую) базу — риск задеть не тот проект. Свои `edt-mcp`, `code-index`, `bsl-platform`, `1c-toolkit` указывают именно на этот проект (его пути/порты/исходники), поэтому результат корректен.

**How to apply:**
1. Запускать Claude Code **из папки самого проекта** — тогда грузится его `.mcp.json`, а не соседний.
2. Работать через серверы, привязанные к ЭТОМУ проекту: его `edt-mcp` (его порт), `code-index` на его `src`, `bsl-platform`/`1c-toolkit` с переменными его `settings.local.json`.
3. Нужного моста нет или он не поднят — сообщить и попросить поднять **именно его**, не подменять чужим (например, `edt-*` другого проекта/порта).
4. Не тянуть данные/объекты через MCP другого проекта, даже «просто посмотреть».
5. **Подключения claude.ai владельца** (`mcp__<uuid>__…`: Firecrawl, Docs, календарь и др.) **разрешены во всех проектах** (решение владельца 20.11.2026). Они видят то, что им передано: данные базы 1С по-прежнему идут только по правилу [[personal-data-masked-from-1c]], а входящий текст проверяет `scan-inbound`.

**Принуждение (с волны 1, 29.10.2026):** барьер `guard-skills` видит каждый MCP-вызов. Сервер 1С (в имени `edt`, `1c`, `onec`, `bsl`, `v8`, `nkdk`, `yaxunit`, `code-index`) — только из `.mcp.json` проекта или плагина ones-core. Подключения claude.ai (`mcp__<uuid>__…`) с 20.11.2026 проходят всегда. Любой другой сервер проходит, только если они в `.mcp.json`, это серверы приложения (`ccd_*`, браузеры, `visualize`, `mcp-registry`, `scheduled-tasks`; терминал — только чтение: запуск команды в нём шёл бы мимо барьера Bash) или владелец вписал их в `ONEC_MCP_ALLOW` (env в `.claude/settings.json`, записи через запятую); расширить этот список агент не может: запись в настройки через Write и Edit судит `guard-skills`, запись из оболочки отклоняет `guard-destructive` (с 30.10.2026). Новый или перенаправленный сервер в `.mcp.json` проекта и одобрение серверов в настройках (`enabledMcpjsonServers`, `enableAllProjectMcpServers`) вносит только владелец; `claude mcp add` — тоже (`contour-tests` §113, §118). Граница: запись скриптом из файла по тексту команды не видна. При старте сессии `session-start` перечисляет посторонние плагины и их модули. Регресс — `contour-tests` §9g и §35. Одноимённый чужой мост (тот же ключ, другой порт в настройках вне проекта) барьер от своего не отличает.

Связано: [[allowed-skill-sources]] (тот же барьер источника, но для скиллов: локальные первыми, внешние — только санкционированные), [[use-skills-not-manual-edits]] (скилл обязателен), [[plugin-in-project]] (свои серверы проекта — в его `.mcp.json`).
