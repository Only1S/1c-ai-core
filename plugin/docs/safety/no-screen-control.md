# Правило: управление экраном — браузер всегда, компьютер по просьбе

**Решение владельца 20.11.2026** (отменяет прежний полный запрет «без computer-use»):
- **Браузер** — встроенный браузер приложения и Chrome: разрешён весь слой экрана — скриншот, клик по координатам, клавиатура, перетаскивание. Барьер `guard-skills` их больше не отклоняет, запретов в `permissions.deny` нет.
- **Компьютер** (рабочий стол, клиент 1С, EDT, Проводник, любое приложение) — только когда владелец сам просит об этом в запросе этого хода. Каждое приложение владелец разрешает в окне доступа computer-use (`request_access`) — это и есть его согласие; без просьбы computer-use не вызывается, даже если доступ к приложению выдан раньше.
- **Из оболочки** (SendKeys, CopyFromScreen, pyautogui и подобное) — по-прежнему нет: такой путь идёт мимо окна доступа (п.7, `guard-destructive`).
- Запрещённое правилами безопасности самого Claude (пароли, оплата, капча и т. п.) остаётся запрещённым при любом способе.

Прежний текст ниже остаётся в силе как порядок по умолчанию: состояние 1С и EDT узнаётся через MCP и файлы, результат показывается текстом, экран — когда без него задачу не решить.

**Why:** пользователь работает в своей среде сам; вмешательство в его экран и приложения без просьбы мешает ему и ненадёжно. Состояние 1С и EDT доступно через MCP и файлы. Браузер приложения — отдельное окно, работа в нём владельцу не мешает, а проверка веб-клиента 1С и форм «глазами» без снимка экрана неполна (решение 20.11.2026).

**How to apply:**
1. Узнать состояние конфигурации/формы/модуля — через edt-mcp (`get_*`, `read_*`) и чтение файлов, а не скриншотом.
2. Результат/находки показывать текстом (таблицы, фрагменты кода), а не картинками экрана.
3. Обновление БД, запуск клиента — штатными `update_database`/`debug_launch`, а не «руками» через ОС.

4. **Граница проходит по СЛОЮ, а не по названию инструмента** (уточнение 14.10.2026, волна G — [[external-skills-review]]). Правило читалось как запрет инструментов, а применялось как запрет слоя; формулировка приведена к фактическому применению.

   | Запрещено (слой ОС) | Разрешено (контракт объекта) |
   |---|---|
   | скриншот экрана, окна, рабочего стола | снимок состояния, отданный самим объектом: дерево элементов формы от `edt-mcp`, a11y-дерево страницы, выгрузка структуры |
   | физический курсор, координатный клик, эмуляция клавиатуры | адресация по идентификатору элемента в протоколе объекта (`uid`, имя элемента формы, селектор) |
   | запуск и переключение приложений через ОС | штатный запуск объекта его же средствами: `update_database`, `debug_launch`, клиент тестирования 1С, headless-прогон |
   | «посмотри на картинку и нажми там» — модель, работающая по координатам из изображения | отладочный протокол: CDP, API EDT, HTTP-сервис тестовой базы |

   **Признак нарушения — координаты и пиксели.** Если для действия нужно *увидеть* экран и вычислить, куда нажать, — это computer-use и запрещено. Если действие адресуется именем или идентификатором, которое отдал сам объект, — это его штатный протокол, и правило не нарушается.

5. **Два прецедента, на которых граница уже применялась** (теперь они записаны, а не выводятся заново): клиент тестирования Vanessa Automation признан штатным механизмом платформы ([[external-mcp-servers-review]]), а скилл `web-test` открывает сессию CDP к браузеру для проверки веб-клиента 1С — и это не считалось нарушением. Независимое подтверждение извне: у `ChromeDevTools/chrome-devtools-mcp` координатный инструмент `click_at(x,y)` заперт отдельным флагом `experimentalVision` (по умолчанию выключен) с формулировкой апстрима «обычно требует **computer-use** модель, умеющую давать координаты по скриншотам» — то есть сторонний проект проводит ту же границу в том же месте (зонд 14.10.2026).

6. **Что из этого НЕ следует.** Разрешение протокола не разрешает: действия на боевом контуре ([[secrets-and-production-database]]), подмену пользователя в чужих залогиненных сессиях, обход защиты клиента или сервера, которыми мы не владеем ([[secrets-and-production-database]], раздел про перехват трафика), и управляющие действия там, где задачу решает наблюдение. Браузерный слой у нас — **наблюдатель**: читать консоль, сеть, трассировки; действовать в веб-клиенте 1С по-прежнему через `web-test`.

7. **Принуждение и его граница (замер 30.10.2026; с 20.11.2026 серверы экрана открыты — браузер всегда, компьютер через окно доступа computer-use, запреты в `permissions.deny` сняты, в шаблоне проектов они в списке снятых).** Из оболочки `guard-destructive` отклоняет вызовы по имени: `SendKeys`, `SendInput`, `CopyFromScreen`, `mouse_event`, `keybd_event`, `SetCursorPos`, `pyautogui`, `pynput`, `nircmd`, `xdotool`, `AutoHotkey` (`contour-tests` §117). Скрипт в файле, закодированная команда и запуск приложения из оболочки (`start notepad`) по тексту команды не видны: там правило держится текстом.
