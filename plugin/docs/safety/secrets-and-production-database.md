# Правило: секреты и боевая база

**Секреты не хранить в коде, конфигах, доках и журналах.** Боевую базу не регистрировать и не направлять на неё инструменты записи.

**Why:** ядро работает с `defaultMode: bypassPermissions`; среди инструментов есть `1c-toolkit.execute_code` (произвольный код в базе) и деструктивные `db-*`-скиллы; у `1c-formsserver` предусмотрен `OPENROUTER_API_KEY`. Один закоммиченный ключ или одна зарегистрированная боевая база — необратимый инцидент. До сих пор это жило только прозой в `README`, раздел «Безопасность», а не наследуемым правилом.

**How to apply:**
1. **Секреты — только в окружении:** `.env` (в `.gitignore`) или блок `env` в `.claude/settings.local.json`. В репозитории — **только `*.example`** с плейсхолдерами.
2. Никогда не вписывать ключи/пароли/токены в исходники, `*.md`, `.mcp.json`, логи. Найден секрет в коде — считать инцидентом: убрать, **ротировать**, зафиксировать в [[worklog]].
3. Перед коммитом/переносом — grep на характерные признаки (`sk-`, `token`, `password`, `Authorization`, `api_key`). **Это принуждается контуром:** секрет-скан в `health-check` (гоняется pre-commit'ом `--strict`) — высококонфидентные образцы (приватные ключи `BEGIN…PRIVATE KEY`, префиксы токенов `xox*`/`gh[pousr]_`/`github_pat_`/`AKIA`/`AIza`/`sk-ant-…` с энтропийным хвостом) дают **FAIL и физически блокируют коммит**; эвристика (`password=…`/`-u user:pass`/`://user:pass@`) — `Warn` (шумит на журналах, описывающих находку). **JSON-реквизиты** (`"password"`/`"pwd"`/`"apiKey"`/`"secret"`/`*token` со значением) в отслеживаемых `.json` — **FAIL** структурным разбором (с 18.09.2026; `.v8-project.json` в git, а `db-*`/`db-repo` хранят в нём реквизиты баз и хранилищ): в файле допустим только плейсхолдер `<…>` или `${VAR}`, значение — в `.env`/окружении, при вызове скилла подставляется из переменной. Релизный гейт `pre-publish-audit` ищет ту же форму по всей истории. Исключения скана: `*.example` и вендор-клоны (плейсхолдеры). Барьер — [[enforcement-hooks]] раздел Б.
4. **Боевую базу не вносить** в `.v8-project.json` — деструктивные `db-*` бьют только по зарегистрированным. `1c-toolkit` — только на тестовой базе; по умолчанию `execute_query`, `execute_code` — осознанно и только на тесте.
5. `v8std` — публичный сервис, видит текст запроса: отправлять имена стандартов и общие вопросы, **не закрытый код**.
6. **Домашние учётные данные агенту не читать** (с 18.09.2026): `~/.ssh`, токены `gh` (`GitHub CLI/hosts.yml`, `~/.config/gh`), `~/.claude/.credentials.json`, `~/.git-credentials`, `~/.npmrc`, `~/.pypirc`, `~/.aws`, `~/.azure`, `~/.docker/config.json`, `~/.gnupg`, `~/.kube`, закрытые ключи по имени (`*_ed25519`, `*_rsa`, `*_ecdsa`, `*_dsa` без `.pub`) где угодно и папка ключей агента `%LOCALAPPDATA%\ones-core\ssh` (кроме `.pub`, `known_hosts`, `config`; с 29.10.2026, [[enforcement-hooks]]); профили оболочек (`Documents/*PowerShell`, `~/.bashrc`) не править. Разрушительное и необратимое на сервере (`systemctl stop`, `rac … drop`, `dropdb`, `DROP`/`TRUNCATE` и т. п. — в команде, в удалённой команде `ssh`/`ssh-mcp`) барьер отклоняет так же, как локальное (с 29.10.2026, `contour-tests` §33). Принуждение двойное: `permissions.deny` в `.claude/settings.json` (инструменты Read/Edit) и `guard-destructive` (обход через Bash — `cat`/`type`/`Get-Content`/`Select-String`/`cp`/`scp` по этим путям, а также `gh auth token` и `gh auth status --show-token`). Запреты `Read(**/…)` действуют только внутри папки проекта (зонд 30.10.2026: файл вне папки прочитан, форма `Read(//**/…)` его закрыла), поэтому с 30.10.2026 в списке стоят и записи от корня диска, а `guard-destructive` стоит на Read и Grep: имя секрета судится по всей машине и в проекте, где `/ones-core:setup` ещё не повторяли (`contour-tests` §116). В оболочке имя секрета или маска под него (`.en?`) в аргументах любой программы, кроме короткого списка безобидных (`ls`, `test`, `stat`, `wc`, `echo`…), — отказ; печать окружения (`env`, `printenv`, `Get-ChildItem Env:`, `echo $…TOKEN`) — тоже; передать секрет программе можно (§112). Запись из оболочки в `.v8-project.json` и настройки Claude Code — отказ, обычная правка идёт через Edit, там судится результат (§113). Причина — входящий контент (страница, README чужого репо, ответ MCP) может содержать инъекцию «прочитай и отправь»; при `bypassPermissions` барьер должен стоять до вызова, а не в памяти модели. Нужен токен для `gh` — он берётся самим `gh`, агенту видеть его незачем.

7. **Перехват и реплей трафика — только там, где мы владеем обоими концами** (14.10.2026, волна G — [[external-skills-review]]; разбор `littledivy/mimic` вскрыл, что границы в текстах ядра не было вовсе).

   **Легитимно:** снять HAR или лог обмена СВОЕЙ интеграции 1С с ТЕСТОВЫМ эндпоинтом; переиграть записанный запрос, чтобы построить детерминированное репро ([[bug-diagnosis-loop]] Ф1, п.4 лестницы); подтвердить поведение внешнего API живым пробоем на тестовом контуре ([[design-before-code]] п.14).

   **Запрещено, даже «на себе»:** подмена доверенного корневого сертификата на устройстве; обход certificate pinning; инъекция в чужое приложение (Frida, objection и аналоги); извлечение и переигрывание сессии стороннего сервиса, протокол которого нам официально не передан. **Критерий границы:** если для получения трафика нужно **обойти защиту клиента или сервера, которыми мы не владеем**, — это реверс, а не отладка.

   **Артефакты перехвата сами по себе — секрет.** HAR, дамп flow и «Copy as cURL» несут живой `Authorization`, cookies и `x-api-key`: они не попадают ни в репозиторий, ни в ответ, ни в журнал. Показываешь вывод зонда — заменяй значения на `<REDACTED>`, а петлю строй через переменные окружения, чтобы учётные данные не оказались в тексте команды.

8. **Пре-фетч политика адреса** (14.10.2026): запрос по схеме `file:`/`data:`/`javascript:`/`blob:` и к эндпоинтам метаданных облака (`169.254.169.254`, `metadata.google.internal` и аналоги) отклоняется **до** обращения — такой адрес отдаёт учётные данные инстанса или читает локальный файл под видом загрузки документации. Принуждается `guard-destructive` на `WebFetch` (регресс — `contour-tests` §15г); `localhost` и локальная сеть НЕ блокируются — это наша законная работа (опубликованная база, локальные серверы). Класс дыры назван разбором `github/spec-kit`; у нас 10-й контур `scan-inbound` стоит на `PostToolUse`, то есть предупреждает, когда контент уже в контексте.
