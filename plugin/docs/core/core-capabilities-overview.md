# Claude Code для 1С — что умеет этот стенд

**Что это:** AI-инженер для 1С:Предприятие на базе Claude (Anthropic) с собственным рабочим окружением: MCP-серверов на стенде — 12 (8 из них плагин ставит в каждый проект), скиллов — 104 (инструментальные из `cc-1c-skills`, базы знаний `bsp` и `1c-standards`, свои и внешние наборы, в том числе схемы `archify`), автоматические проверки качества. Ключевое отличие: работает **не «по памяти», а инструментами** — каждое утверждение о коде, метаданных или стандартах подтверждается фактическим вызовом, а своё решение пишется только после подтверждения, что штатного механизма (БСП/платформа) нет.

## Разработка
- Читает и правит код BSL прямо в живом EDT-проекте: модули, метаданные, валидация, навигация по вызовам.
- Создаёт объекты метаданных целиком из компактного описания: справочники, документы с движениями, регистры, перечисления, роли, HTTP-сервисы — с реквизитами и табличными частями.
- Управляемые формы: генерация, валидация, конвертация форматов, контроль **скриншотом** — видит результат, а не верит XML.
- Обычные формы (обычное приложение): разбор `Form.bin`, правка кнопок, полей и подписей с отчётом о масштабе правки, картинка «до / после», сборка обратно. Разбор и сборка байт в байт проверены на копиях 1617 форм реальной конфигурации (1616 совпали, одна — отказ с причиной); загрузка изменённой формы платформой ещё не проверялась, поэтому каждая правка подтверждается загрузкой в тестовую базу.
- Перевод доработанной типовой на новый релиз поставщика: трёхстороннее слияние выгрузок и отчёт о конфликтах по классам (обе стороны изменили, поставщик удалил, двойники, «сироты»). Описания объектов и права сливаются автоматически по элементам, различия выгрузки, не меняющие смысла, снимаются. Перед импортом проверяются оставшиеся конфликты, состав, ссылки на удалённое, права и формы, считается влияние на расширения; затем результат загружается в одноразовую базу с проверкой модулей. Модули с правками обеих сторон и формы разбираются вручную. На пробе с ERP 2.5.20.85 (около 33 тысяч файлов) импорт прошёл без синтаксических ошибок.
- Запросы: проверка полей/типов против схемы до вклейки в модуль; выполнение на тестовой базе.
- Именование и структура — по стандартам 1С (std469 и др.), с единым префиксом подсистемы и правильными суффиксами модулей; языковой профиль проекта (английский или русский код) выдерживается автоматически, синонимы — на всех языках конфигурации.

## Проектирование
- **Консилиум ролей**: архитектор, аналитик, дизайнер интерфейса, программист и тестировщик 1С прорабатывают задачу параллельно, каждое решение обосновывается стандартом / механизмом БСП / API платформы; состязательный критик ловит противоречия и «изобретение своего при живом штатном»; на выходе — единый согласованный план.
- Архитектура подсистем: слои, швы расширяемости (Переопределяемый/ОпределяемыеТипы), развязка с конфигурацией-хостом, спецификации объектов и детальные ТЗ.

## Ревью и аудит
- Многоагентные аудиты: параллельные «линзы» по модулям и аспектам + состязательная проверка каждой находки с доказательством файл:строка (вплоть до живого воспроизведения бага). Ложные срабатывания отсеиваются до отчёта.
- Приведение присланных модулей к стандартам: структура областей, директивы компиляции, асинхронность, дубли, мёртвый код — каждая правка со ссылкой на номер стандарта.

## Контроль качества
- После правок — весь стек чекеров: валидация EDT, статический линтер BSL, сверка вызовов с API платформы (ловит «выдуманные» методы), стандарты (v8std/АПК), соответствие БСП, скриншоты форм, юнит-тесты; функциональный чек-лист — стенд готовит кейсы «вход → ожидаемо» и разбирает результаты, прогон на данных — за человеком.
- Автоматика на уровне среды: правка `.bsl` сама прогоняется линтером и контролем смешения языков; красное состояние проверок физически блокирует фиксацию в git.

## База, производительность, эксплуатация
- Запросы и код на живой **тестовой** базе через MCP (боевые базы в контур не допускаются — правило).
- Технологический журнал: разбор, топ долгих операций, блокировки/дедлоки; глубокая аналитика ТЖ с агрегациями → готовый Excel.
- Выгрузка/загрузка конфигурации, сборка/разборка внешних обработок и отчётов, операции с базой через ibcmd.

## Интеграции и знания
- Разбирает любую присланную документацию/API (платёжные, фискальные, гос-сервисы) и сохраняет в структурированную базу знаний проекта; проектирует интеграции на этой основе.
- Ведёт журнал работы: посекундная история каждой правки, нарратив по вехам, версионирование git — новая сессия продолжает работу без потери контекста.

## Переносимость
- Всё окружение — плагин ones-core, не привязанный к конкретной конфигурации: ставится в проект командой `claude plugin install ones-core …` и `/ones-core:setup` (пути, порты, языковой профиль спрашиваются один раз), обновляется `claude plugin update ones-core`.
