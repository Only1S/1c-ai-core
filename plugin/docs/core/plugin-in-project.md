# Ядро в проекте: плагин ones-core

Проект не хранит копию ядра. Правила, скиллы, защитные хуки и общие MCP-серверы приходят из плагина **ones-core**; в проекте — только своё. Где лежат правила и программы, называет сообщение в начале сессии.

## Подключение

```
claude plugin install ones-core --marketplace Only1S/1c-ai-core --scope project
```

Затем в папке проекта — `/ones-core:setup`. Он спрашивает окном вариантов ([[questions-as-options]]):

| Вопрос | Зачем |
|---|---|
| где выгрузка конфигурации (`src` или проект EDT) | индекс кода, проверки, переменная `ONEC_PROJECT_SRC` |
| какая платформа 1С | `ONEC_PLATFORM_BIN`, справка по платформе |
| есть ли EDT, порт `1c-toolkit` | свой сервер проекта в `.mcp.json`, порты без столкновений с соседями ([[server-ports-per-project]]); сервер `1c-forms` идёт в плагине |
| **языковой профиль**: язык кода (английский или русский) и языки синонимов | задаётся **один раз** и записывается строкой «Языковой профиль» в `CLAUDE.md` проекта; в задачах не переспрашивается ([[language-profile]]) |

Сначала setup показывает, что изменит (пробный прогон), и только после «да» пишет: в `.claude/settings.json` — плагин, запреты опасных команд, разрешения на читающие серверы и на чтение статей скиллов из кэша плагина (`Read(~/.claude/plugins/cache/ones-core/**)`; запись туда не разрешается), бюджет списка скиллов `skillListingBudgetFraction: 0.02` (при 1% по умолчанию описания редких скиллов плагина срезаются; своё значение проекта не перетирается); в `.claude/settings.local.json` (вне git) — переменные проекта (приставка `ONEC_` — «1C» латиницей: имя переменной окружения не может начинаться с цифры — в sh имя только с буквы или `_`, в `.cmd` `%1C_…%` читается как аргумент `%1`; это не название плагина `ones-core`); заготовки журналов `docs-project/`; проверку секретов перед коммитом; ссылку `.code-index` из выгрузки и выгрузку в списке общего индексатора ([[code-index-outside-sources]]). Программы инструментов (индекс кода, анализатор, справка по платформе, YAXUnit) ставятся в папку данных плагина по отдельному согласию.

## Три слоя свойств

| Слой | Что | Где живёт |
|---|---|---|
| **A — ядро** | правила, справочники, скиллы, хуки, общие серверы | в плагине; в проекте не копируется и не правится |
| **B — проект** | пути выгрузок, базы (только тестовые), порты, языковой профиль, свои серверы и знания | `.claude/settings.local.json`, `.mcp.json`, `.v8-project.json`, `CLAUDE.md`, `docs-project/` проекта |
| **C — машина** | платформа 1С, EDT, Java, Node.js, uv, Git Bash, программы в папке данных плагина, общий фоновый индексатор | общие для всех проектов машины; к папке проекта не приклеиваются — иначе переезд на другой ПК ломается |

Значения слоя B в `.mcp.json` проекта — через переменные системы (`${USERPROFILE}`) и `${VAR:-значение}`: переменные из `settings.local.json` в `.mcp.json` проекта не подставляются ([[server-ports-per-project]] п.4).

## Панель ядра

Рядом с чатом плагин показывает панель `ones-core`. Это мод — модуль `hooks/status-band.tsx`, нужен Claude Code 2.1.287+; остальные моды подключены к нему импортом. Строки над полем ввода больше нет. Панель открывается сама на старте сессии, если окно достаточно широкое (движок: от 144 колонок, после первого открытия — от 110), иначе — командой `/core`; где поверхность панелей не ставит, команда отвечает тем же текстом в чате. В Desktop она встаёт отдельной колонкой справа, за карточками Claude (проба 31.10.2026): в колонку этих карточек мод рисовать не может, она принадлежит приложению. Ширина — просьба к окну, 54 колонки; граница, перетащенная человеком, важнее. Версия ядра — в заголовке: `ones-core · ядро 5.2.4`. Под полем ввода ядро ничего не показывает: свою строку там окно прижимает вправо, к названию модели, а слева мод рисовать не может — `$.ui.status` не принимает места, пустые символы окно отбрасывает, `PromptHint` в Desktop не показывается (пробы 31.10.2026).

| Часть | Откуда |
|---|---|
| сбой фильтра | красная надпись с причиной и кнопкой «Что делать», пока фильтр входящих не работает; после первого успешного запуска исчезает |
| новая версия | надпись «Есть новая версия X», если в канале `Only1S/1c-ai-core` есть тег новее установленной; один запрос `git ls-remote` на старт сессии, нет сети или доступа — надписи нет |
| ждёт вас | счётчик «ждёт вас: N» сверху и раздел «Ждёт вас»: дела, которые может сделать только владелец, — номер, что сделать, «Почему», «Готово, когда», возраст и кнопки «Сделано», «Ответить», «Отказать»; кнопка вставляет ответ в поле ввода, отправляет человек (с 05.11.2026, `hooks/owner-tasks.tsx`) |
| доработки | до 5 идущих карточек `docs-project/**/*.md` с полем `Стадия:` в шапке ([[customization-pipeline]]), свежие первыми: `слаг · стадия` и шесть подписанных кружков — зелёный с галочкой пройден, жёлтый с вращением идёт, пустой впереди; вне Desktop те же стадии символами `✓ ● ○`; закрытые не показываются |
| база | ключ `default` в `.v8-project.json` |
| шаги | список инструмента «шаги задачи»: готовые с галочкой, текущий (первый неотмеченный) со стрелкой, а пока идёт ход главного агента — с вращающимся значком и временем шага от минуты (значок только в Desktop: анимация живёт в самой картинке, панель не перерисовывается); нет шагов — строка `**Следующий шаг:**` журнала ([[work-journals-and-commits]] п.12) |
| проверка | итог последней `/check`: время, вердикт и все замечания списком, во время прогона — «идёт…»; чистый итог уходит сам через минуту, замечания и ошибки остаются до следующей проверки |
| кнопки | «✓ Проверить» запускает проверку, как `/check`; «▶ Тесты» подставляет `/ones-core:tests` в поле ввода, запускает человек; «★ Что нового» открывает запись установленной версии из `RELEASE-NOTES.md` |

Данные обновляются при старте сессии и после каждого хода, шаги, сбой и итог проверки — сразу. Нет реестра баз или карточки — эта часть не показывается. «Следующий шаг:» карточки приходит подсказкой в поле ввода, один раз на текст. Панель только читает файлы проекта, в сеть обращается один раз за новой версией; выключается настройкой `ones-core.statusBand`. После обновления ядра при первом старте сессии всплывает «Ядро обновлено до X» (версия запоминается на проект в `$.store`). Ход главного агента дольше 10 минут заканчивается уведомлением системы, а где его некуда отправить — всплывашкой. Регресс — `plugin/hooks/tests/status-band.test.tsx`, `core-pane.test.tsx`.

**Ждёт вас** (решение владельца 05.11.2026, по мотивам human-in-the-loop — [[claude-code-mods-review]]). Инструмент модели `owner_tasks` (`mcp__ones-core__owner_tasks`): `add` с `title` (что сделать, глаголом), `why`, `done_when`; `close` с номерами; `show`. Дела лежат в `.claude/owner-tasks.json` проекта и переживают перезапуск и сжатие контекста, их не больше 20. Пароли и ключи в дело не пишутся. Работает только вместе с панелью; выключается настройкой `ones-core.ownerTasks`. Тесты мода — `plugin/hooks/tests/owner-tasks.test.tsx`.

**Выжимка длинного вывода** (решение владельца 05.11.2026, по мотивам context-diet — [[claude-code-mods-review]]). Вывод `Bash` и `PowerShell` длиннее 8000 знаков модель видит выжимкой: первые и последние 12 строк и строки с ошибками, предупреждениями и итогом с двумя строками до и тремя после. Полный текст — в `logs/output-NN.txt` проекта, по кругу из 50 файлов; в заголовке выжимки — путь и «прочитай его, прежде чем отвечать о том, чего здесь нет». Не режется: ответ `1c-toolkit` (данные базы), помеченный внешний текст, печать файла целиком (`cat`, `type`, `Get-Content`, `head`, `tail`, `sed -n`), вывод, где выжимка не короче половины. Не записался полный текст — вывод идёт целиком. Работает в моде чистки входящих после маски ПДн; выключается настройкой `ones-core.outputDigest`. Тесты — `plugin/hooks/tests/inbound-filter.test.ts`.

**Шаги задачи.** Инструмент модели `task_steps` (полное имя `mcp__ones-core__task_steps`): агент ведёт список шагов с галочками — `add`, `done`, `show`, `clear`, шаг можно привязать к карточке. Список лежит в `.claude/task-steps.json` проекта (вне git — строка в `.gitignore` от `/ones-core:setup`) и переживает перезапуск и сжатие контекста; вызовы идут по одному, два подряд не теряют друг друга.

**Панель «Доработка» и инструменты на чтение (волна 3, шаги 3.2 и 3.8; выключены по умолчанию до проверки в приложении — настройка `ones-core.workPane`).** Команда `/work` открывает панель рядом с чатом: карточка доработки (последняя изменённая) — стадия, следующий шаг, чего не хватает выходу стадии, строки матрицы готовности по статусам; шаги задачи с галочками; проверки — что гейт конца хода требовал в последнем ходе, что в нём уже проверено, взведён ли гейт качества по правкам `.bsl`, последний след прогона (`logs/gate-evidence.md`) и замечания проверок конца хода в сессии; портфель всех доработок со сверкой `docs-project/pipeline.md`. Обновляется после каждого хода главного агента, пока открыта (при выключенной панели ядра `statusBand` — только командой и кнопкой «Обновить»), и сразу, когда агент отмечает шаг. Где поверхность панелей не ставит (`$.ui.open` отвечает `isPlaced: false`), команда отвечает тем же текстом в чате. Инструменты модели — оба только читают: `work_status` (`mcp__ones-core__work_status`, необязательный `card` — слаг) — карточка, шаги и портфель; `turn_checks` (`mcp__ones-core__turn_checks`) — проверки текущего хода тем же кодом, что гейт конца хода, чтобы досдать недостающее до отказа гейта. Данные берут два скрипта плагина в режиме чтения: `tools/pipeline/gen-portfolio.py --json` и `tools/checks/turn-checks.py` (журнал хода — `~/.claude/projects/*/<сессия>.jsonl`). «Только чтение» держится устройством (`hooks/work-data.ts`: обработчики инструментов получают чтение файла и эти два скрипта, а не весь `$`) и проверками — `plugin/hooks/tests/work-pane.test.tsx` (ни записи, ни чужого процесса), `contour-tests` §77–§79 (оба скрипта не меняют ни одного файла).

**Правила коммита.** Мод отвечает на просьбу Claude Code об атрибуции пустым текстом: строки Co-Authored-By в коммите и подписи в описании PR модель не получает ([[work-journals-and-commits]] п.8). Действует там, где модуль плагина загружен: в проекте с плагином при включённом у Claude Code флаге выкатки модулей; в мастере ядра (без плагина) и без флага подсказка об атрибуции до модели доходит. Последний рубеж везде один — git `commit-msg` отклоняет коммит со строкой.

**Спросить вместо запрета (М-2, ADR-0010 мастера).** Когда барьер `guard-destructive` отклоняет локальное удаление файлов или правку истории git с пометкой «Если это осознанное решение — выполни вручную сам», мод `ask-guard.tsx` показывает окно вариантов: «Отказать (Рекомендую)» или «Разрешить один раз». Только явное «Разрешить один раз» пропускает ровно этот вызов, и дальше он идёт обычной проверкой разрешений сессии (`permissions.deny` проекта по-прежнему отклоняет — тогда окна нет). Закрытое окно, свой текст, ошибка, запуск без интерфейса (`-p`) — отказ, как раньше. Никогда не спрашивается: секреты, базы 1С и СУБД, сервер, плагин, хуки, разрешения и настройки, обход хуков, вызовы помощников. В составной команде окно появляется, только если все её отказы такие же и она видна целиком: длиннее 300 знаков или с одиночным `&` — отказ без окна. Журнал — `logs/ask-guard.jsonl` проекта, без текста команды. Контракт композиции — [[enforcement-hooks]]. Регресс — `plugin/hooks/tests/ask-guard.test.tsx`, `contour-tests` §73, §120.

**Проверка проекта.** Команда `/check` (мод `project-check.tsx`) отвечает сразу и запускает в фоне `plugin/tools/checks/project-check.py` (в установленном плагине — `tools/checks/`): изменённые против `HEAD` модули `.bsl` — те же проверки, что после правки (`bsl-analyzer`, смешение алфавитов, бюджет комментариев), по изменённым строкам; изменённые доки `docs-project/` — линтер проектных доков; подготовленное к коммиту — проверка секретов; запреты проекта против шаблона ядра; программы ядра. Только чтение: без платформы 1С, без сети, гейт качества не взводит. Вердикт приходит уведомлением системы (где его некуда отправить — всплывашкой) и остаётся в панели ядра, в чат не пишется; отчёт — `logs/project-check.txt`. Повторная команда во время прогона его не дублирует. Регресс — `plugin/hooks/tests/project-check.test.tsx`, `contour-tests` §76.

Настройки — `claude plugin configure ones-core` или меню `/config` (`ones-core.statusBand`, `ones-core.taskSteps`, `ones-core.workPane`, `ones-core.askInsteadOfDeny`, `ones-core.projectCheck`); выключенные панель, шаги или мод не подключают ни одного своего обработчика, правила коммита этими настройками не выключаются. Хранятся в пользовательских настройках (`~/.claude/settings.json` → `pluginConfigs`): проектные настройки Claude Code для опций плагина не читает (журнал отладки), поэтому выключение действует на все проекты машины. Модули установленных плагинов Claude Code включает флагом выкатки `tengu_plugin_hooks_modules`; без него панели нет, а хуки-команды плагина работают как обычно.

## Обновление

```
claude plugin marketplace update ones-core
```

Затем в папке проекта `claude plugin update ones-core@ones-core --scope project` и перезапуск Claude Code. Если в записи версии (`RELEASES.md`) в разделе «Нужно сделать при обновлении» сказано повторить `/ones-core:setup` — повторить: он идемпотентен и меняет только то, что требует новая версия. Файлы плагина в проекте не правятся: своё правило проекта — в `docs-project/`, правило для всех проектов — предложением через `/ones-core:report-issue`.

Старые версии плагина удаляет сам Claude Code: при обновлении он кладёт в папку прежней версии (`~/.claude/plugins/cache/ones-core/ones-core/<версия>/`) пометку `.orphaned_at` и стирает папку фоновой уборкой через 14 дней, чтобы сессии, открытые до обновления, доработали на своей версии (документация Claude Code, «Plugin loading reference → Cleanup of previous versions»; пометки на старых версиях сверены на диске 04.11.2026). Уборка идёт, только пока в `installed_plugins.json` есть хоть одна установка. Удалять раньше ядро не берётся — решение владельца 04.11.2026.

Узнать, нужно ли обновляться, — команда `/ones-core:version`: какая версия работает в сессии, какая установлена в проекте и какая последняя в канале (по тегам GitHub, без сети — по локальной копии каталога), плюс итог «актуальна / обновите / перезапустите». Скрипт — `plugin/tools/setup/show-version.py`, ничего не меняет.

Сверить установленный плагин с выпуском: к странице Release (начиная с версии, в которой пришёл этот абзац) приложен `SHA256SUMS.txt` — суммы всех файлов плагина и ассетов. Скачать его со страницы Release и запустить `python "<папка плагина>/tools/setup/plugin-sums.py" verify "<папка плагина>" SHA256SUMS.txt`: итог «сверено N, расхождений 0, вне списка K» или список изменённых и пропавших файлов (код 1). Испорченный, пустой или не тот файл списка — ошибка с кодом 2: скачать его заново; «сверено 0» зелёным не бывает. Большое K при малом N — список оборван. Программы инструментов установщик ставит атомарно: файлы раскладываются рядом, сверяются с суммой из манифеста, и папка программы заменяется целиком; занятая программа (запущен сервер или открыта сессия) — отказ без изменений, повторить после закрытия.

## Переезд на другой ПК

1. Клонировать проект из его git.
2. Поставить на машине слой C (платформа, EDT, Git Bash и др.).
3. В папке проекта — установка плагина и `/ones-core:setup` с путями новой машины; программы инструментов и автозапуск индексатора — по его вопросам.

## Проверка после подключения

Итог — **пробная сессия в папке проекта**: сообщение плагина в начале сессии, общие и свои серверы подключаются, опасная команда отклоняется хуком. `claude mcp list` из командной строки обманчив: доверие к папке он ищет под другим написанием пути (`D:/проект` вместо `D:\проект`), а переменные проекта не подставляет — «ожидает одобрения» и упавший `bsl-platform` там не дефект проекта.
