# Карта: ситуация в коде → стандарты 1С

[[work-through-tools]] требует сверять код со стандартами инструментом, но **какой** стандарт открыть, агент выбирал по памяти. Карта убирает этот выбор: сработало действие — вот номера. Это указатель, а не текст стандарта: сам текст — `v8std_get_page("stdNNN")` ([[v8std-mcp-server]]) или офлайн-копия в скилле `1c-standards` (`rules/*.md`, якорь `#stdNNN`).

`v8std_explain_snippet` карту не заменяет: он ранжирует по сходству и срабатывает не на всё. При отборе источника (19.09.2026) на фрагменте «`ОбработкаПроведения` + запрос + привилегированный режим» он не выдал ни одного стандарта проведения (std450/603/633).

## Уровни

| Уровень | Что значит |
|---|---|
| **always** | Сверка обязательна каждый раз, когда строка сработала |
| **conditional** | Только если есть подситуация, названная в строке |
| **optional** | Нестандартное решение или сомнение в подходе |

## Как пользоваться

1. Перед BSL-правкой, проектированием или ревью найти сработавшие строки (помогают признаки в тексте — раздел ниже).
2. Номера уровня always открыть инструментом; conditional — если подситуация есть.
3. Вывод «подходящих стандартов нет» — только после `v8std_search` по теме, не по памяти.
4. Нарушение на ревью называется номером стандарта или кодом диагностики (ось «Стандарты», [[two-axis-code-review]]); код из отчёта анализатора → `v8std_explain_diagnostics`.

† — номера, которых нет в офлайн-копии `1c-standards`: их текст только через `v8std`.

## Проектирование решения

| Ситуация | Уровень | Стандарты |
|---|---|---|
| Выбор вида объекта (справочник / документ / регистр / ПВХ / определяемый тип), общие реквизиты | always | std467 общие требования к конфигурации · std474 имя, синоним, комментарий · std704 определяемые типы · std677 общие реквизиты |
| Структура регистра: независимость от регистратора, индексы, составные типы | always | std477 самодостаточность регистров (АПК:123) · std791† дополнительные индексы · std728 реквизиты составного типа |
| Общий модуль: вид и постфикс | always | std469; экспорт — std544, std640; кэширование — std724; переиспользование между конфигурациями — std551, std644 |
| Права, роли, RLS, параметры сеанса, функциональные опции | always | std488 стандартные роли · std689 настройка прав · std491 влияние параметров сеанса и ФО на RLS · std413 параметры сеанса · std470 функциональные опции |
| Обработчики записи объекта (`ПередЗаписью`, `ПриЗаписи`, `ОбменДанными.Загрузка`) | always | std464 · std465 · std773; `ОбработкаЗаполнения` и ввод на основании — std396 |
| `ОбработкаПроверкиЗаполнения`, условная проверка реквизитов | always | std463 · std478 · std686 (параметр `Отказ`) |
| Проведение документа, движения регистров | always | std450 порядок записи движений (АПК:105) · std603 требования к проведению · std633 активность движений; при контроле остатков — std477; многократная запись наборов — std792† |
| Удаление или переименование объекта метаданных | conditional | std534 удаление устаревших объектов · std706 ограничения на переименование. **Порог (бекпорт из экземпляра 16.10.2026):** есть развёрнутые базы, обмен или внешний потребитель имени (отчёт, интеграция, запрос в коде заказчика) → ИМЯ не меняем вовсе, меняем только синоним; переименование имени допустимо, пока объект не ушёл дальше разработки. **Контр-сигнал:** объект создан в этой же незакрытой доработке и ещё никуда не загружался — тогда переименование законно и дешевле синонима-заплатки |
| Регламентное задание | conditional | std540 общие требования · std539 запуск; наименование предопределённого — std767 |
| Транзакции и блокировки | conditional | std783 правила транзакций · std460 управляемый режим блокировок · std659 избыточные блокировки |
| Обмен данными: планы обмена, правила регистрации | conditional | std701 планы обмена с отборами · std799† правила регистрации (в карте-источнике раздела нет, добавлено по поиску `v8std`) |
| Доработка в расширении (заимствование, выбор перехватчика) | always | отдельного стандарта в корпусе `v8std` нет (два поиска 19.09.2026); `1c-standards`, требования к расширениям п. 8.4–8.6; диагностики `v8cs:extension-md-object-prefix` / `extension-method-prefix` / `extension-variable-prefix`, АПК:1310 (префикс), АПК:1314 (описание расширяющего метода); выбор точки врезки — [[naming-and-module-design]] |
| Подключение внешнего кода (внешние обработки, расширения, `Выполнить` / `Вычислить`) | conditional | std669 (АПК:554 — небезопасное подключение расширения) |

## Написание кода: запросы

| Ситуация | Уровень | Стандарты |
|---|---|---|
| Любой запрос | always | std437 оформление · std729 общие требования к оптимальным запросам · std438 проверка на пустой результат |
| Условия отбора, индексы | conditional | std652 несоответствие индексов и условий · std658 эффективные условия (АПК:316) · std791†; `ПОДОБНО` с ведущим `%` или `_` — std652 и std658 п.3 вместе |
| Виртуальная таблица регистра | conditional | std657 обращения к виртуальным таблицам · std733 эффективное обращение к «Остатки»; поля регистратора — std477; соединение с таблицей без параметров отбора — std657 и std655 п.2 вместе |
| Соединения, вложенные запросы, временные таблицы | conditional | std655 · std656 · std777; `ПОМЕСТИТЬ` без `ИНДЕКСИРОВАТЬ ПО` при соединении или `В (…)` — std777 п.3.1, если размер кодом не ограничен |
| Реквизит составного типа (в выборке, в условии, через точку) | conditional | std654 разыменование (АПК:1377) · std728. Тип поля по тексту запроса не виден — состав типов смотреть `meta-info` до написания |
| Сортировка; однотипные запросы в цикле | conditional | std412 упорядочивание · std436 многократное выполнение однотипных запросов |
| `РАЗРЕШЕННЫЕ` | conditional | std415 |
| Строковый литерал запроса или СКД виден пользователю | conditional | std762 |

Ловушки запросов, которые стандартом не описаны и чекерами не ловятся, — таблица в скилле `query-compose`.

## Признаки ситуации в тексте

Подстроки, по которым строка карты узнаётся при чтении кода и находится поиском (`code-index`, `Grep`). Это подсказка, а не детектор: исполняемого потребителя у списка нет ни в источнике, ни у нас.

| Признак в коде | Строка карты |
|---|---|
| `ОбработкаПроведения`, `Движения.`, `.Записать(` у набора записей | проведение |
| `ПередЗаписью`, `ПриЗаписи`, `ОбменДанными.Загрузка` | обработчики записи |
| `.Остатки(`, `.Обороты(`, `.СрезПоследних(` | виртуальная таблица |
| `УстановитьПривилегированныйРежим` | привилегированный режим |
| `Процедура … Экспорт`, `Функция … Экспорт` | новая экспортная |
| `&НаКлиенте`, `&НаСервере`, `Подключаемый_` | модуль формы, клиент-сервер |
| `НСтр(` | локализация |
| `ВЫРАЗИТЬ(`, `ССЫЛКА Документ.`, `ССЫЛКА Справочник.` | составной тип (по тексту узнаётся не всегда — смотреть метаданные) |
| `ДинамическийСписок`, `УстановитьСвойстваДинамическогоСписка` | динамический список |
| `СхемаКомпоновкиДанных`, `КомпоновщикНастроек` | отчёт на СКД |
| `ТабличныйДокумент`, `ПолучитьМакет`, `УправлениеПечатью` | печатная форма |
| `ПолучитьИмяВременногоФайла`, `УдалитьФайлы` | файлы |
| `ЗаписьЖурналаРегистрации` | журнал регистрации |
| `&Перед`, `&После`, `&Вместо`, `&ИзменениеИКонтроль`, `ПродолжитьВызов(` | расширение |

Новая строка карты заводится вместе со своими признаками здесь: строку без признаков находит только память.

## Происхождение и сверка

- **Источник:** `axelboman277/v8std-standards-harness`, файлы `references/situations.md` и `references/standards-map.md` (ревизия 2026-08-01, коммит `343c570a`), лицензия MIT, Copyright (c) 2026 axelboman277. Карта пересказана и перестроена под наш стек: уровни сохранены, группировка изменена, строки «Обмен данными» и «машиночитаемая строка» добавлены нами, ссылки на паттерны проектирования (`patterns:*`) опущены. Валидатор следа, инструкция установки и pre-commit из источника не взяты.
- **Сверка 19.09.2026:** каждый номер карты открыт инструментом `v8std` (`v8std_get_page`, `v8std_get_related`) — все найдены, темы совпадают с подписями выше. Коды диагностик сверены через `v8std_explain_diagnostics`.
- **Офлайн-копия отстаёт:** в `1c-standards/rules` 311 якорей `#stdNNN`, последний — std790; std768, std791, std792 и std799 там нет (помечены †). Остальные номера карты ищутся по якорю в папке `rules/` скилла `1c-standards`: в проекте — `grep -l "#std437" "<папка плагина>/skills/1c-standards/rules/"*.md` (скиллы лежат в папке плагина, её путь называет сообщение ones-core в начале сессии), в мастере — `grep -l "#std437" .claude/skills/1c-standards/rules/*.md`.
- **Сопровождение — наше.** У источника один день активности, обновлений из него не ждать. Новый номер перед записью в карту сверяется через `v8std_get_page`.
