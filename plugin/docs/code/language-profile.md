# Правило: языковой профиль проекта (язык кода и синонимы)

Язык кода и набор языков синонимов — **свойство проекта**, выбирается один раз и дальше действует автоматически.

**Why:** смешение языков в идентификаторах и «однобокие» синонимы — системная порча конфигурации: имена не ищутся, интерфейс не локализован, каждый разработчик решает по-своему. Профиль, спрошенный один раз при развертывании, снимает вопрос навсегда и делает результат единообразным (пользователь: «код на английском либо на русском — от выбора языка кода; по этой схеме имена; синонимы — по языкам проекта»).

**Исключение — латинские аббревиатуры самой платформы.** `ЧтениеXML`, `ЗаписьJSON`, `ФабрикаXDTO`, `HTTPСоединение`, `ЗащищенноеСоединениеOpenSSL`, `ВызватьHTTPМетод` — это имена типов и методов 1С, а не смешение языков: переименовать их нельзя, и правило к ним не применяется. Контур 2 (`validate-bsl`) держит список таких аббревиатур и считает идентификатор нарушением, только если **хотя бы один** латинский сегмент вне списка — поэтому `СуммаTotal` и `ЧтениеXMLTotal` по-прежнему блокируются. Состав собран 30.10.2026 обходом контекста платформы `bsl-context` 8.3.27 и 8.5.1 (типы, глобальные имена, члены типов): `bsl-platform` знает не всё, `WebЦвета` там нет. Имена, чей латинский кусок — обычное слово или короткая метка (`ObjectТеги`, `ПриНажатииEnter`), стоят в списке `PLATFORM_NAMES` целиком: сегментом они пропустили бы `ИмяSource`. До 06.08.2026 списка не было, и контур отклонял любую правку модуля с XML/JSON/XDTO/HTTP, то есть практически весь интеграционный код (найдено аудитом, подтверждено зондом). Новая аббревиатура платформы добавляется в список хука вместе с кейсом в `contour-tests` §133.

**Исключение — обработчики, которых требует движок тестов YAxUnit** (решение владельца 30.10.2026). YAxUnit 25.12 перехватывает обработчик ошибок модуля приложения под обоими именами — `ОбработкаОтображенияОшибки` и `ErrorDisplayProcessing`, — и без обоих методов в хосте расширение не применяется ([[task-recipes]] §12 п.4). Пустой метод с именем второго языка в модуле приложения — требование движка, а не смешение языков: правило к нему не применяется, как и к латинским аббревиатурам платформы. Тело — пустое, комментарий одной строкой называет причину.

**How to apply:**
1. **Выбор — один раз, при развертывании проекта** (`/ones-core:setup` — [[plugin-in-project]], через окно вариантов [[questions-as-options]]):
   - **язык кода**: английский или русский;
   - **языки синонимов**: предварительно посмотреть ветку **Languages** конфигурации (`edt-mcp` `get_metadata_objects` / выгрузка) и показать заведённые языки; профиль = подтверждённый пользователем набор (есть казахский — входит и казахский).
   Профиль записывается строкой «Языковой профиль» в `CLAUDE.md` проекта; в задачах **не переспрашивать**.
2. **Язык кода определяет всё, без смешения:** текст модулей (ключевые слова `Procedure…` ↔ `Процедура…`, имена процедур/функций, переменных, параметров) и **все имена метаданных** (объекты, реквизиты, измерения/ресурсы, ТЧ, элементы/команды/реквизиты форм, роли, подсистемы, макеты). Мешанина (`СуммаTotal`) — нарушение. Префиксы/суффиксы std469 ([[naming-and-module-design]]) — поверх выбора.
3. **Комментарии — всегда на русском** (включая шапки методов), независимо от языка кода.
4. **Всё, что видит пользователь, — на ВСЕХ языках профиля** (не только синонимы). Два слоя:
   - **Метаданные (design-time):** синонимы объектов/реквизитов/ТЧ/измерений/ресурсов/команд, представления объекта/списка/расширенные, заголовки форм и элементов, подсказки, тексты кнопок — на каждом языке профиля.
   - **Строки в КОДЕ (runtime) — через `НСтр` по ВСЕМ языкам профиля**, а не литералом одного языка. Это касается **всего видимого пользователю**, не только «сообщений»: сообщения (`Сообщить`, `ОбщегоНазначения.СообщитьПользователю`), **предупреждения** (`Предупреждение`), **вопросы** (`Вопрос`), статусы и прогресс (`Состояние`), оповещения (`ПоказатьОповещениеПользователя`), **тексты исключений, видимые пользователю** (`ВызватьИсключение НСтр(…)`), заголовки/колонки/кнопки/подсказки, устанавливаемые кодом, пользовательские тексты в настройках СКД. Синтаксис — `НСтр("ru='…'; en='…'; uz='…'")` со **всеми** языками профиля; параметры подставлять `СтрШаблон`, локализуемые строки **не конкатенировать** (v8std std761/std762/std585, источник — [[v8std-mcp-server]]; диагностики АПК:1297 «строка не локализована», АПК:1298 «синтаксис НСтр», АПК:1355 «конкатенация локализуемых строк»).
   - **Карвэ-аут — НЕ локализовать** (v8std std764, АПК:334): внутренние идентификаторы, ключи, строковые константы алгоритма, имена вариантов/полей в коде, токены запроса и полей СКД, теги XML/JSON, **технические строки журнала регистрации и исключения только для разработчика** — остаются на одном языке (по-русски, как комментарии). `НСтр` для внутреннего идентификатора — **тоже нарушение** (АПК:334). Правило простое: **видит пользователь → `НСтр` на всех языках; видит только разработчик/машина → один язык, без `НСтр`.**
   - **Алфавит нелатинской локали** (uz, kk, tg, az и т.п.) фиксируется в профиле при развертывании; конкретного алфавита для конкретного языка ядро не предписывает. Выбор делается **подсчётом по выгрузке, а не по примеру**: в `*.xml` посчитать значения `<v8:content>` у элементов с `<v8:lang>xx</v8:lang>`, в `*.bsl` — строки `xx='…'` внутри `НСтр`, разложив их на кириллицу / латиницу / смешанные. Цифры показать в окне вариантов ([[questions-as-options]]) и рекомендовать алфавит, который в конфигурации уже доминирует. В одном из экземпляров первый выбор «по примеру» после такого подсчёта пришлось сменить на противоположный.
5. **Новые языки в конфигурацию самостоятельно не добавлять** — ветка Languages это корень конфигурации; не хватает языка для профиля → показать и согласовать ([[ask-before-changing]]).
6. Проверка при работе — по гейту [[work-through-tools]]: соответствие имён стандартам — `v8std`/`1c-standards`; фактические языки конфигурации — `edt-mcp`/`nkdk` (аспект «метаданные», [[task-recipes]] §9). **Пропущенную локализацию пользовательских строк ловит `bsl-analyzer`/`1c-standards` (АПК:1297/1298/334/1355), а НЕ хук `validate-bsl`** — он видит только смешение алфавитов (п.7); поэтому НСтр-полнота проверяется полным сетом чекеров ([[full-checker-set-before-done]]), не хуком.
7. **Контур принуждения:** PostToolUse-хук `validate-bsl.py` автоматически ловит **смешение кириллицы и латиницы в одном идентификаторе** (`СуммаTotal`) в правленных `.bsl` (комментарии и строковые литералы исключены из скана) → exit 2 с фидбеком; живость хука стережёт `health-check.py` (1b).
   - **Вне `.bsl` хук слеп.** Наброски кода и имена символов в ТЗ и спецификациях (`.md`, `.docx`) он не видит. На реальном ТЗ стадия сверки имён нашла латинскую `o` внутри кириллического имени; платформа такое имя компилирует (оно одинаково везде, куда его скопировали), и ошибка всплывает только при следующем наборе имени руками. Для таких текстов — отдельный поиск гомоглифов регуляркой `[А-Яа-яЁё][a-z]|[A-Za-z][а-яё]` (в `.docx` — по извлечённому тексту): она ловит латинскую букву внутри кириллического слова и не задевает платформенные аббревиатуры (`ЧтениеXML`, `HTTPСоединение`, `ЗащищенноеСоединениеOpenSSL` — проверено на образцах). Смешение целыми словами (`СуммаTotal`) она не ловит — это зона хука в `.bsl`.

Пример (язык кода = English; языки конфигурации ru/en/uz; для uz профиль этого примера выбрал латиницу — это решение профиля, не умолчание ядра):

```bsl
// Рассчитывает сумму строки по цене и количеству.
Procedure CalculateLineTotal(Row)
```

## Ловушки имён и строк в коде

- **Число в машинную строку — не через `Строка()` и не через `Формат()`.** `Строка(Число)` строит представление по национальным установкам (`bsl-platform`, описание `Строка`), то есть с разделителем групп: `1234` → «1 234» (символ разделителя — по локали). Ключи и идентификаторы от 1000 и выше молча перестают совпадать со строковыми из внешней системы; в одном из экземпляров это нашлось только вычиткой, анализатор молчал. Для ключей, ID и обмена — `XMLСтрока(Число)`: std763 п.4.2 прямо называет `Строка(Число)` и `Формат(Число)` неправильной сериализацией. `Формат(Число, "ЧГ=0")` не замена: для нуля он возвращает пустую строку (замер на живой базе в одном из экземпляров; без `ЧН=0` ноль пропадает).
- **Имя переменной не совпадает с вызываемой функцией** — ни со встроенной (`Строка`, `Дата`, `Тип`, `Формат`), ни со своей. На реальном коде переменная `Строка` затенила вызов `Строка()` рядом с ней; анализаторы такое не ловят. Для своей функции, вызываемой в цикле, поломку со второй итерации в одном из экземпляров заподозрили, но исполнением **не проверили** — до репро на тестовой базе ([[bug-diagnosis-loop]]) это стилевое правило, а не установленный факт. Проверка — вычиткой и поиском по именам-омонимам.
