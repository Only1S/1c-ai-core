# Разбор 1c-quality-gate и claude-code-mode

Разобрано 10.11.2026 по ссылкам владельца, без помощников: `gh api` (метаданные, дерево, README, LICENSE, документация code-mode). Обе лицензии — MIT (GitHub лицензию не распознал, файлы LICENSE — MIT). Ниже пересказ, не цитаты.

## 1c-quality-gate (Romandredan)

Плагин Claude Code и OpenCode для разработки 1С; 50 звёзд, 398 файлов, активная разработка (последний push 10.11.2026). Правка `.bsl` или XML метаданных «взводит» гейт: хук `Stop` не даёт закончить сессию, пока не прогнан навык `quality-gate`. Навык считает **профиль правки** по трём осям, запускает только нужные **контуры** (`code`, `arch`, `xml`, `hygiene`) и пишет **след** — секцию `## quality evidence` со строками `scope` / `applied` / `skipped` / `not_verified` / `sentinel`. Гейт снимается только по следу, который разобрал `evidence-validator.mjs` и сверил с журналом прогонов инструментов.

| Механизм | Как у них | У нас | Вердикт |
|---|---|---|---|
| Гейт конца хода после правки 1С | `Stop`-хук `gate-check.mjs` | `stop-guard.py` + `turn-checks.py`: стандарты, `validate_module`, валидаторы после генераторов | есть |
| След прогона, сверяемый с журналом инструментов | `evidence-validator.mjs`, закрытый словарь проверок | `gate-evidence.py`, строки следа хода | есть иначе |
| «Не проверено» — отдельная категория | `not_verified: compilation / query-execution` | [[full-checker-set-before-done]] п.9 | есть |
| **Взвод по правкам из оболочки** | снимок `git status` до и после `Bash`/`PowerShell`, отпечаток файла, «чья правка» | **нет**: видим Edit/Write и известные скиллы-генераторы; скрипт, записавший BSL, невидим (10.11.2026 конвертер перевода записал 14 тыс. строк — гейт заметил только модуль харнесса) | **берём** |
| **Часовой источника** | на каждый прогон: анализатор на образце с заведомой ошибкой, `v8std` — заведомо существующий стандарт | только недельная живость в `health-check` и `DEGRADED` при отсутствии отчёта; молчащий анализатор (например, `BSLLS:…-off` на кириллице) даёт ложный зелёный | **берём** (анализатор) |

| **Класс глубины C0–C3 + архетипы + сложность** | глубина = max(объём, минимум архетипов, сложность); `driver` — что подняло | одна глубина на любую правку | **берём** в объёме C0 (решение ниже) |
| Контур архитектуры с порогами и контр-сигналом | `ARCH-A1…A11`, `signs-map.json` | скилл `architecture-review`, [[two-axis-code-review]] — без порогов | не сейчас |
| Каталог антипаттернов: индекс триггеров всегда, карточка по попаданию | -60% обязательного чтения | [[code-situation-standards-map]] | идея на будущее |
| Анализ расширения вместе с основной конфигурацией | треть ложных на боевых CFE | не настроено | наблюдение |

### Что берём — решение владельца 10.11.2026

1. **Взвод по правкам из команд.** Сделано 10.11.2026 — хук `shell-arm.py` ([[enforcement-hooks]]). Проводка `PreToolUse`/`PostToolUse`/`PostToolUseFailure` для `Bash`/`PowerShell`: до команды — время старта; после — `git status --porcelain` рабочих деревьев проекта и изменённые или новые файлы 1С (`.bsl`, `.mdo`, XML объектов и форм), записанные не раньше старта команды. Снимок `git status` до команды, как у 1c-quality-gate, не нужен: грязный до команды нетронутый файл отсекается временем записи, а цена вызова оболочки на тяжёлом проекте падает вдвое. Игнорируемые git файлы не берутся. Найденное пишется в `logs/shell-arm.json`, и `stop-guard` требует для него те же проверки, что для правки инструментом. Фоновой команде — подсказка «её запись гейт не увидит».
2. **Часовой анализатора.** Сделано 10.11.2026 ([[enforcement-hooks]], образец — синтаксическая ошибка, гоняется, только когда модуль чист). `validate-bsl` раз в сессию (и при смене версии `bsl-analyzer`) прогоняет анализатор на образце модуля с заведомой находкой. Находки нет — каждое срабатывание пишет громкое «анализатор не работает, вердикт недостоверен» вместо зелёного.
3. **Гигиена в строках правки** — сделано 10.11.2026 ([[enforcement-hooks]]; добавлены невидимые знаки направления и минус «−»; потеря BOM сверяется с `HEAD`) (`validate-bsl`): управляющие символы, смешанные переводы строк в файле, тире «–»/«—» в коде вне строк и комментариев, потеря BOM у файла, где он был. Блокирует, как и прочие находки в строках правки.
4. **Класс глубины — C0.** Сделано 10.11.2026 ([[full-checker-set-before-done]] п.8а; классификатор один — `change-profile.cosmetic`, он же исправлен: закомментированный и удалённый код больше не считается косметикой). Если правка модуля меняет только комментарии и пустые строки, `stop-guard` не требует стандартов и `validate_module` — хватает автоматических проверок хука (анализатор, гигиена). Любая другая правка — полный набор, как сейчас. Это исключение вносится в [[full-checker-set-before-done]] отдельным пунктом.

Порядок: тест первым на каждый пункт (`contour-tests`), затем код; хуки изменены — до выпуска живая проба на самом тяжёлом проекте.

## claude-code-mode (gabe4coding)

Плагин: вместо многих вызовов MCP модель пишет одну программу на JavaScript, она выполняется в песочнице (отдельный процесс Node, `vm`, модель разрешений Node, без сети на Linux/macOS) и возвращает только ответ. Подсказки по серверам MCP, сохраняемые функции. Замер авторов: те же 30/30 ответов на 43% дешевле на Haiku 5.5.

**В проекты 1С не ставить.** Вложенные вызовы MCP внутри программы проверяются только правилами разрешений (allow/deny); про хуки `PreToolUse` и обработку результата в документации ничего нет. Ответ `1c-toolkit` пришёл бы модели внутри результата `run_code` мимо маскировки персональных данных ([[personal-data-masked-from-1c]]) и мимо барьеров. Барьер [[use-own-mcp-servers-only]] сторонний инструмент, скорее всего, остановит, но полагаться на это не стоит. Идея «большой вывод не идёт в контекст» у нас уже есть — выжимка длинного вывода (веха 170, [[token-economy-and-local-tools]] п.6).
