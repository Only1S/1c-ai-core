# Разбор статьи «Подключение ИИ-агента к разработке 1С: по шагам»

Разобрано 06.11.2026 по ссылке владельца, без помощников. Источник — https://infostart.ru/1c/articles/2837232/ (автор Илья Елагин, опубликовано 05.11.2026). `defuddle` получил 429, страница прочитана во встроенном браузере целиком (34 тыс. знаков). Ниже — пересказ, не цитаты.

## Что это

Практика одного разработчика: обработка «Почему не закрывается месяц» для пяти типовых (УТ 11, КА 2, ERP 2, БП 3.0, УНФ 3.0), код целиком написал агент в Claude Code. Основа — одна папка, копия демобазы и три скрипта: `lint.ps1` (BSL LS), `build.ps1` (сборка `.epf`), `test.ps1` (YAxUnit). Поверх выросли ферма из 12 демобаз на 8.3.24, 8.3.27 и 8.5.1, конвейер на Python (код пишет Opus, ревью и приёмка — Sonnet), свой лёгкий тест-менеджер форм вместо MCP Vanessa и «проверка порчей» — агент ломает условие, ядро ждёт красный тест. Итог: 8 дней, 162 запуска агентов, около 50 часов машинного времени, $277,73 по ценам API (85 % — разработка).

## Три ошибки запросов

1. **Сложение `ПРЕДСТАВЛЕНИЕ()` со строкой** упало на БП и УНФ: по статье представление строит платформа при чтении результата, в СУБД его нет, поэтому в запросе его нельзя ни складывать, ни сортировать (автор ссылается на статью ИТС о поле «Представление»). У нас: `v8std` и база знаний платформы этого запрета не содержат. **Ждёт проверки запросом на тестовой базе** — до неё строку `query-compose` «сортировать по `ПРЕДСТАВЛЕНИЕ(…)`» не меняем.
2. **Организация без движений в месяце**, но с минусом с прошлого года, выпала из проверки. Урок про данные одной базы, к ядру не относится.
3. **`УПОРЯДОЧИТЬ ПО` в запросе с `РАЗЛИЧНЫЕ`** по замечанию ревьюера: сортировка по полям-представлениям уронила пакет на трёх типовых. Подтверждено `v8std`: std412 п.2 — с `РАЗЛИЧНЫЕ` сортировать только по выбранным полям. **Сделано**: строка в таблице «Правила, за которыми стоит стандарт» скилла `query-compose`.

Общий вывод автора: текст запроса — строка, статика его почти не видит, ошибка появляется только при выполнении на нужной базе. У нас это закрывают `validate_query` (EDT) и `execute_query` на тестовой базе ([[full-checker-set-before-done]]).

## Сделано 06.11.2026

Решение владельца — три пункта из четырёх.
- **`epf-build`: свежесть файла.** Патч `tools/patches/epf-build-fresh-output.py` ([[vendor-patches]]): файл старше начала сборки — не результат. Регресс — `contour-tests` §185; живая сборка пробной обработки дважды на временной базе прошла.
- **[[bug-diagnosis-loop]] Ф5: «Красного не бывает».** Сказать вслух, одна честная попытка, исход «закрыт частично», решение — владельцу.
- **`query-compose`:** правило std412 п.2 про `РАЗЛИЧНЫЕ`.
