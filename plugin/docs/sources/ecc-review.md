# Разбор ECC

Разобрано 05.11.2026 по ссылке владельца, без помощников. Источник — репозиторий через `gh api`: метаданные, дерево (4701 файл), README (разделы «ECC», «What's Inside», «Key Concepts», «Why Choose ECC?», память), `hooks/README.md`, `hooks/hooks.json`, шапки хуков `gateguard-fact-force.js`, `mcp-health-check.js`, `config-protection.js`, скиллы `continuous-learning-v2`, `security-scan`, `strategic-compact`, описание опыта `docker/gateguard-effectiveness/`. Наличие у нас — греп по `docs/`, `plugin/hooks/`.

## Что это

Набор для харнесса агента: «план → тест → реализация → ревью → проверка → память → улучшение». Работает с Claude Code, Codex, Qoder; адаптеры для Cursor, OpenCode, Gemini и др.

| Свойство | Значение на 05.11.2026 |
|---|---|
| Автор | affaan-m (1778 коммитов), ещё десятки участников |
| Популярность | ~298 тыс. звёзд, 44 тыс. форков, 234 открытые задачи |
| Выпуск | v2.2.3 от 01.10.2026; создан 18.01.2026 |
| Лицензия | MIT |
| Состав | 71 агент, 314 скиллов, 98 команд, хуки на 8 событиях (`PreToolUse` — 10 обработчиков, `Stop` — 8), правила по языкам, «инстинкты», сканер AgentShield, хранилище памяти между харнессами |
| Предметная область | общая разработка: TypeScript, Python, Go, Java, Kotlin, Rust, C++ и др.; 1С нет |

## Механизмы

- **Инстинкты (continuous-learning-v2).** Хуки пишут наблюдения сессии в `observations.jsonl` проекта. Фоновый агент на малой модели выделяет «инстинкты»: триггер, действие, уверенность 0,3–0,9, доказательства. На старте сессии вставляется до 6 инстинктов с уверенностью от 0,7. Инстинкт из 2 проектов поднимается до общего. Кластер инстинктов превращается в скилл, команду или агента.
- **GateGuard** (`gateguard-fact-force.js`, 103 КБ). Перед первой правкой файла требует факты: кто импортирует, публичный API, схема данных. Перед разрушительной командой — список целей, план отката, цитата поручения. Собственный опыт авторов (`docker/gateguard-effectiveness/`): в одноразовых сессиях разницы в исходе между вариантами «с вопросами» и «без» не нашлось; это мерило цены, а не пользы.
- **config-protection.js.** Блокирует правку конфигов линтеров и форматтеров (ESLint, Prettier и др.): «агенты часто правят конфиг, чтобы проверка прошла, вместо исправления кода». Создание нового конфига разрешено.
- **mcp-health-check.js.** Перед вызовом MCP проверяет, отвечает ли сервер; после сбоя (`PostToolUseFailure`) отмечает сервер больным, переподключает, держит паузу с ростом до 10 минут.
- **AgentShield** (`ecc-agentshield`, npm). Сканирует сам харнесс как поверхность атаки: секреты и инструкции автозапуска в `CLAUDE.md`, широкие разрешения и флаги обхода в `settings.json`, рискованные MCP-серверы и `npx` в `.mcp.json`, подстановку в командах хуков, агентов без ограничения инструментов.
- **Профили хуков.** `ECC_HOOK_PROFILE` = `minimal`/`standard`/`strict`, `ECC_DISABLED_HOOKS` — список ID; стабильные ID и отпечатки хуков — в `hooks.metadata.json`, CI ловит расхождение с `hooks.json`. Потолок вставки на старте — 8000 знаков.
- **Hookify.** Правила проекта в `.claude/hookify.*.local.md` (предупредить или заблокировать). Файлы под git по умолчанию выключены: открытие репозитория не должно включать инструкции, написанные в нём.
- **Strategic compact.** Подсказка сжать контекст вручную на логической границе (примерно каждые 50 вызовов), а не ждать автосжатия посреди задачи.
- **TDD с доказательствами**, ревью из свежего контекста, сводка сессии и оценка стоимости на `Stop`, хранилище памяти `.ecc/memory/` для передачи между харнессами.

## Кандидат: не подгонять проверки — сделан 05.11.2026

Решение владельца — «подсказка + запрет настроек». Сделано: подсказка `validate-bsl` на новую директиву подавления в строках правки, отказ `guard-skills` на правку существующего `.bsl-language-server.json` ([[bug-diagnosis-loop]] Ф5, [[enforcement-hooks]], `contour-tests` §181). Настройки проверок EDT не покрыты: имена их файлов не сверены.


Запрет [[bug-diagnosis-loop]] Ф5 («красный тест чинится кодом») касается тестов. Тот же приём на анализаторе — подавить диагностику вместо исправления. У нас это ещё и ложный зелёный: `// BSLLS:<Rule>-off` ломает парсер подавлений `bsl-analyzer` на кириллице, анализ обрывается ([[installed-tools-and-servers]]).

Что сделать:
1. **`validate-bsl.py`:** директива подавления (`BSLLS:…-off`, `@skip-check`, `ACC:`, `АПК:`) в строках правки — подсказка модели: «исправь код; подавить диагностику — только после «да» владельца». Блокировать или подсказывать — решение владельца.
2. **`guard-skills.py`:** правка существующих конфигов анализаторов (`.bsl-language-server.json`, настройки проверок EDT в `.settings/`) — отказ; новый файл — пропуск. Как `config-protection.js` ECC.
3. Самотест в `contour-tests`, живая проба до выпуска.

## Ставить ли сам ECC

Нет.
- Своих MCP-серверов в обычной установке нет, но 314 скиллов и 71 агент для других языков забьют список скиллов.
- Хуки на `PreToolUse` и `Stop` пересекутся с нашими барьерами и гейтом конца хода.
- Для 1С в нём ничего нет. Проверки качества — для JS/TS и других языков.
