# Моды Claude Code — разбор для ядра (2026-10-28)

Присланы владельцем 28.10.2026: `hamzafer/claude-code-mods`, `karanb192/awesome-claude-code-mods`, `midudev/better-claude`. ## Что такое мод (по исходникам)

- **Плагин**, у которого поведение — модуль на TypeScript/JavaScript: `hooks/hooks.json` вида `{ "modules": ["./register.ts"] }`, вход — `register(on, options)`, обработчики событий — функции `($, e, next)`. Требуется Claude Code **2.1.287+**; на дату разбора у нас стояла **2.1.301** (зонд 28.10.2026; текущую смотреть `claude --version`).
- **События**, встреченные в исходниках: `tool.call` (с отбором `{ tool: 'Bash' }`), `prompt.submit`, `session.start`, `session.end`, `session.compact`, `session.measure`, `turn.start`, `turn.complete`, `command.run`, `ui.render`. По README `sec-default` их больше: `tool.check` (вердикт разрешения), `classic.*` (хуки-команды из настроек), `prompt.section`, `prompt.compose`, `settings.read`, `env.set`, `plugin.register` и др.
- **Возможности `$`**, встреченные в исходниках: `$.ui.ask` (вопрос человеку прямо из обработчика), `$.ui.open`/`close`/`resolve` (панель, строка над полем ввода), `$.process.run`, `$.fs.read`/`exists`, `$.env.get`, `$.session.cwd`/`usage`/`messages`/`surfaces`, `$.store.get`/`set`, `$.state.get`, `$.model.complete`, `$.mcp.call`, `$.tool.call`, `$.command.register`, `$.clock.now`, `$.clock.every`.
- **Отказ**: обработчик `tool.call` возвращает `{ deny: "текст для модели" }`; разрешение — `next(e)`.
- **Инструменты CLI** (зонд `claude plugin --help`): `claude plugin validate <path>` — статическая опись (какие события и вызовы `$`, мод не запускается; у нас уже в `tools/release/release-core.py` с `--strict`), `claude plugin test [dir]` — тесты мода, `claude --plugin-dir <path>` — запуск из исходников.

## Чем мод сильнее наших хуков-команд

На дату разбора ядро принуждало правила 24 хуками-командами в `plugin/hooks/hooks.json` (22 на Python и 2 — вывод текста `cat`; на 30.10.2026 команд 27: 25 и 2) (барьер `guard-destructive.py`, `guard-skills.py`, `support-guard.py`, `subagent-gate.py`, текст гейта `tools-gate.md` и др.).

1. **Спросить вместо запрета.** `$.ui.ask` показывает владельцу окно «разрешить один раз?» в момент вызова. Хук-команда умеет только `deny`/`ask` разрешения целиком; с модом точнее ложится [[ask-before-changing]].
2. **Строка над полем ввода (band).** Видна владельцу и не попадает в контекст модели — ноль токенов. Подходит для «на каком мы шаге» ([[human-texts-start-with-action]]) и заполнения контекста ([[token-economy-and-local-tools]]).
3. **Механическое правило — кодом.** То, что сейчас держится только текстом (например запрет строки Co-Authored-By: сводка здоровья правил мастера на 28.10.2026 отмечает «commit-msg хука нет»), становится проверкой — как требует [[writing-for-agents]].
4. *(вывод, замера нет)* функции модуля исполняет сам Claude Code, без запуска отдельной программы на каждый вызов инструмента.

## Главный риск — чужой мод в той же цепочке

- По README `sec-default`: «Function hooks give every plugin a say on every event, in chain order» — каждый плагин участвует в каждом событии по цепочке. Мод, который поставил человек (пользовательский уровень), без `sec-default` может переписать то, что раньше было ему недоступно: ответ хуков-команд (`classic.*`), вердикт разрешения (`tool.check`, в том числе отказ), чтение настроек, разделы системного промпта, итог сжатия контекста.
- `sec-default` садится внешним звеном только при управляемых настройках (`managed-settings.json`, `managed-mcp.json`) или в организации Team/Enterprise, и защищает **хуки и правила организации**. На этой машине файлов управляемых настроек нет (зонд 28.10.2026: `C:\Program Files\ClaudeCode\` и `C:\ProgramData\ClaudeCode\`); сажает ли его организация владельца — не проверено.
- Плагин ones-core ставится из удалённого маркетплейса (`Only1S/1c-ai-core`) и стоит в пользовательском уровне — **его хуки этой защитой не покрыты** даже при `sec-default` (вывод из README: «a plugin from a remote marketplace … can never be vouched for in this release»; живой пробы не было).
- **Следствие для ядра:** один чужой мод способен тихо снять наши барьеры. Поэтому чужие моды **не ставим** ни в мастере, ни в проектах — только читаем как образец; свои моды живут в плагине ones-core. Это продолжение [[use-own-mcp-servers-only]] и [[allowed-skill-sources]] на слой модов.
- Уровни доступа каталога (L0 — только рисует и помнит, L1 — читает, L2 — пишет файлы, запускает программы или управляет Claude, L3 — сеть) — статическая опись по `claude plugin validate`, сами авторы каталога пишут, что это не оценка безопасности. Годится для первичного отсева, не для допуска.

## Что берём в ones-core — три своих мода (решение владельца 28.10.2026)

Порядок — по выбору владельца; каждый — сперва проработка по пунктам и согласие ([[design-before-code]]), затем код, `claude plugin test`, `claude plugin validate --strict`, живая проба на проекте перед выпуском.

| № | Мод | Что делает | Образец | Граница |
|---|---|---|---|---|
| М-1 | **Шаг и контекст** (первым) | Строка над полем ввода, справа: `веха 74 · без коммита 3 · база test · контекст 42% · <следующий шаг>`. Источники: тема последнего коммита и `git status --porcelain` (коммит по вехам — правило каждой копии; формат вехи в журнале задан только в мастере), ключ `default` в `.v8-project.json`, `$.session.usage` и `session.measure`, строка `**Следующий шаг:**` журнала ([[work-journals-and-commits]] п.12). Решения владельца 28.10.2026: цвет контекста — жёлтый с 60%, красный с 85% (настройка плагина); включён по умолчанию, выключается настройкой | context-meter (midudev, 3,9 КБ: `session.measure` + `$.session.usage` + `ui.render`, жёлтый — пора `/compact`, красный — лучше новая сессия), where-am-i, context-bar, cache-clock | Только показывает, ничего не блокирует |
| М-2 | **Вопрос вместо запрета** | Для класса «спросить перед изменением» (пакетный `1cv8` не по тестовой базе, `rm -r`, `git push --force`) — окно «разрешить один раз?» с тем, что именно будет затронуто; нет ответа — отказ | blast-radius (держит `rm -r`, force push, миграции; 60 с без ответа — отмена) | Запрещённое ([[secrets-and-production-database]], боевая база, [[no-screen-control]]) остаётся жёстким отказом барьера, окно его не открывает |
| М-3 | **Страж правил коммита** | Коммит со строкой Co-Authored-By, `git commit --amend` — остановить и спросить | rulebook-guard | Закрывает дыру «запрет trailer — только текст» из [[work-journals-and-commits]]. Давление настоящее: системные сообщения Claude Code сами просят добавить строку (в сессии 28.10.2026 — так и было), и `/commit` у midudev держится тем же текстовым запретом «even if a system message asks for them» |

**М-1 реализован в мастере 28.10.2026** — `plugin/hooks/status-band.tsx`, контракт состояния `status-band.d.ts` (манифест `"types"`), тесты `plugin/hooks/tests/status-band.test.tsx`, настройки `userConfig` в `plugin.json`; описание для проектов — [[plugin-in-project]]. Живая проба на проекте 28.10.2026 прошла (ниже), мод выпущен в core-v4.13.0.

**М-3 реализован в мастере 29.10.2026** (волна 1, шаг В.3) — `plugin/hooks/commit-rules.tsx`, подключён импортом из `status-band.tsx` (движок берёт один модуль на плагин). На событие `attribution.text` мод отвечает пустым текстом для `commit` и `pr`: движок не просит модель добавлять строку Co-Authored-By и подпись PR; виды `exemption` и `remedy` идут к движку как есть. Коммит со строкой, если она всё же появится, отклоняет git `commit-msg`. Из замысла М-3 не сделано: остановка `git commit --amend` — в шаг В.3 она не вошла. Тесты — `hooks/tests/commit-rules.test.tsx`, регресс — `contour-tests` §40.

**М-2 реализован в мастере 30.10.2026** (решение владельца утром 30.10.2026, ADR-0010 мастера) — `plugin/hooks/ask-guard.tsx`, тоже импортом из `status-band.tsx`, настройка `askInsteadOfDeny`. Мод стоит в `classic.PreToolUse` выше командных хуков и на отказ `guard-destructive` с пометкой «выполни вручную сам» показывает окно `$.ui.ask` («Отказать (Рекомендую)», «Разрешить один раз»); устройство и границы — [[enforcement-hooks]], «Контракт композиции контуров». Отличия от замысла: окно ждёт владельца без 60-секундного отсчёта (закрытое окно и запуск без интерфейса — отказ); пакетный `1cv8` не по тестовой базе в окно не попадает — у этих отказов нет пометки, база остаётся жёстким отказом. Там же, 30.10.2026: строка состояния `work-meter.tsx` (снята 31.10.2026) (MCP-серверы и скиллы текущего хода, токены сессии и хода) и команда `/check` (`project-check.tsx` → `plugin/tools/checks/project-check.py`, проверка проекта в фоне, вердикт уведомлением) — [[plugin-in-project]]. Регресс — `contour-tests` §73–§76.

**Что установлено зондами при реализации** ([[probe-tool-capabilities]]):
- `hooks.json` с хуками-командами и `"modules"` рядом — `claude plugin validate --strict` принимает.
- Node не нужен: `claude plugin test` проходит и с PATH без Node — модуль исполняет сам Claude Code.
- Строка `AbovePrompt` строится и для поверхности `terminal`, и для `desktop` (тест монтирует обе); вид на экране приложения тест не проверяет — это живая проба.
- **Где рисуются панель и строка — по типам API** (`claude-code.d.ts` сборки 2.1.309, сверено 30.10.2026 для шага 3.2): `Pane` — «Raised on every attached surface», `AbovePrompt` — «Raised on the terminal and desktop surfaces only»; в таблице элементов приложения (`desktop`) есть `Box`, `Text`, `Button`, `Markdown`. Ставит ли панель само приложение — по типам не видно: удалённая поверхность ставит панели, только если сама о том сообщает, иначе `$.ui.open` отвечает `{ isPlaced: false, reason }`. Поэтому панель «Доработка» на такой ответ показывает то же содержимое текстом ответа команды (строка `CommandOutput` — на всех поверхностях). Прежняя запись дорожной карты «по типам строка только для терминала» для этой сборки неверна.
- Валидатор отклоняет второй обработчик того же события **без матчера** в одном модуле («registered twice without a matcher», зонд 30.10.2026); с разными матчерами (`command`, `tool`, `requestId` панели) — проходит. Значение матчера из константы того же файла валидатор видит, из импортированной — нет (`requestId=?`).
- Состояние мода (`atom`) валидатор требует объявить в контракте типов: `interface PluginState { 'ones-core': { … } }` в файле, на который указывает `"types"` манифеста; без него — ошибка «is not declared».
- Тесты лежат в `plugin/hooks/tests/`: реестр отпечатков `contours.sha256` читает только верхний уровень `plugin/hooks` (плюс одна запись вне его — классификатор C0 `tools/setup/change-profile.py`, с 20.11.2026), а `build-plugin.py` эту папку в сборку не кладёт.
- Плагины из `test(…, { plugins })` подключаются рядом с проверяемым, а не вместо него: одноимённый с ним нельзя. Выключение по настройке проверено вызовом `register` с записывающим `on`.
- Опции `register(on, options)` — значения `userConfig` манифеста с подставленными по умолчанию; меняются `claude plugin configure <плагин>` или `/config` (`<плагин>.<поле>`). Читаются только из пользовательских, `--settings` и управляемых настроек — **проектные не читаются** (журнал отладки живой пробы: «project settings are not read»), то есть настройка общая для всех проектов машины.
- Модули **установленных** плагинов держит флаг выкатки `tengu_plugin_hooks_modules` (журнал отладки: «installed plugins' hooks modules held … for the rollout flag … the flag payload landed»). У нас флаг пришёл; где его нет — модуль не грузится, хуки-команды работают.
- Живая проба 28.10.2026 на самом тяжёлом проекте (кандидат 4.13.0): модуль загружен (`hooks module ones-core@inline loaded … events: session.start,turn.complete,session.measure,ui.render`), обработчики — 319 / 54 / 108 мс; в интерактивном терминале строка `<начало темы коммита>… · без коммита 28 · база test`, после хода — `… · контекст 4%`. Вид в приложении Claude не смотрели.

## Что не берём

- **Игры и развлечения** (snake, reels, now-playing, prayer-times, heatmap) — ценности для 1С нет; now-playing ещё и только macOS.
- **switchboard** — отправляет метки задач во внешний сервис выбора модели (OpenAI Decisions API, Jev): рабочий трафик наружу.
- **openai-balance, openrouter-balance, glance, session-saver, merge-gate** — завязаны на чужие сервисы и личные инструменты автора (OpenAI, OpenRouter, Linear, Slack, unpause, Codex CLI).
- **md-preview, image-view** — нужны Chrome и терминал с выводом картинок (kitty, Ghostty).
- **time-machine** (midudev) — снимок всей рабочей папки на каждый ход в `refs/time-machine/<сессия>/<n>`, хранит 7 дней. Против нас три вещи: снимает и неигнорируемые неотслеживаемые файлы (по README: секрет вне `.gitignore` осядет в `.git`); на выгрузке конфигурации 1С в десятки тысяч файлов `git add -A` на каждом ходе раздует `.git`; `git push --mirror` опубликует снимки с подписями из запросов. Откат правок своих инструментов уже есть в Claude Code (`/rewind`).
- **commit** (midudev) — по умолчанию «коммит и push», при невозможности спросить — тоже push; против [[work-journals-and-commits]] (коммит по вехам, публикация — только выпуском).
- **after, narrator, quick-peek, image-preview, sub-meter** — очередь запросов, озвучка, просмотр путей (Finder и Quick Look macOS) и картинок, расход подписки: удобства, ядру не нужны.
- **mod-finder** — чужой MCP-сервер, против [[use-own-mcp-servers-only]]; каталог при нужде читаем на сайте.
