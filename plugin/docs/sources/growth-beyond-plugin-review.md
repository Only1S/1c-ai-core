## 1. Свой сервис «инженер 1С» на Claude Agent SDK

**Что.** Agent SDK запускает того же агента, что Claude Code, из своей программы: подпроцесс на запрос, своя рабочая папка, своя папка настроек на каждого арендатора (`CLAUDE_CONFIG_DIR`, `settingSources: []`), отключаемая автопамять. На этом строится сервис: очередь задач команды → агент с нашими правилами, скиллами и хуками → результат в репозиторий.

**Источник.** code.claude.com/docs/en/agent-sdk/hosting (раздел «Multi-tenant isolation»).

**Наши правила.** Код остаётся на нашем сервере, модель — та же, что сейчас. Хуки и барьеры ядра переносятся, если сервис грузит плагин; ПДн — через тот же фильтр. Нужны правило о данных (волна 2) и отдельная живая проба.

**Вердикт:** позже — это и есть шаг 3.6 «общий сервис для команды», первым срезом — один арендатор на ВМ `vmrus`.

## 2. Командный центр агентов (OpenHands Agent Canvas)

**Что.** Самостоятельно размещаемый центр управления агентами (лицензия MIT): параллельные сессии, автоматизации по расписанию, журнал «кто запустил, что тронул, сколько стоило»; запускает в том числе Claude Code через протокол ACP.

**Источник.** openhands.dev; github.com/OpenHands/openhands (раздел «Architecture», «Self-host your way»).

**Наши правила.** Сам центр — чужой код с доступом ко всему; ставить как есть нельзя («не ставить чужое как есть», дорожная карта, раздел 4).

**Вердикт:** идея — журнал запусков, стоимость и расписание берём в свою панель «Доработка» (3.2) и ночной дозор (3.3).

## 3. Развёртывание на команду: управляемые настройки и свой каталог плагинов

**Что.** Управляемые настройки Claude Code имеют приоритет над локальными и не снимаются пользователем: запреты, разрешённые каталоги плагинов (`strictKnownMarketplaces`, `blockedMarketplaces`), запрет подгрузки плагинов и MCP флагами (`disableSideloadFlags`), политика организации в CLAUDE.md. Планы Team и Enterprise дают каталог плагинов организации с раздачей по группам.

**Источник.** code.claude.com/docs/en/admin-setup (таблица «Decide what to enforce»); support.claude.com, статья «Manage plugins for your organization».

**Наши правила.** Закрывает две находки замера: запреты не доходят до проектов и чужие моды и плагины не видны. Системные настройки меняет владелец, не агент.

**Вердикт:** взять — инструкция владельцу и шаблон `managed-settings.json` с нашими запретами и списком разрешённых каталогов; работает как второй рубеж к Б.1 и Б.11.

## 4. Шлюз MCP с политиками и журналом

**Что.** Посредник между агентом и MCP-серверами: каждый сервер в своём контейнере, политики на вызов инструмента (в Docker MCP Gateway — правила Cedar), журнал вызовов. Открытые варианты: ToolHive (Apache-2.0), agentgateway (Apache-2.0), Docker MCP Gateway, IBM ContextForge (MIT).

**Источник.** Сравнения requesty.ai (MCP Gateway Comparison 2026) и speakeasy.com (best MCP gateways for enterprise 2026).

**Наши правила.** Это готовое место для фильтра ПДн по ответам `1c-toolkit` и для журнала доступа без значений (п.7 правила ПДн). Но это ещё один слой чужого кода между агентом и базой.

**Вердикт:** идея — фильтр и журнал строим своим модом по `tool.call` (Б.13, следующие срезы); к шлюзу вернёмся, если серверов станет много или появится команда.

## 5. Ночной дозор и ревью в CI без человека

**Что.** `claude -p` в режиме без интерфейса запускается в любом CI, в том числе в GitLab: структурированный вывод, ограничение ходов, расписание, защита от наложения запусков. Готовый GitHub Action — только удобство, не обязательное условие.

**Источник.** hidekazu-konishi.com, «Claude Code in CI/CD and Headless Automation» (разделы 5.4 и 10); about.gitlab.com/blog/claude-code-and-gitlab.

**Наши правила.** Хуки плагина должны работать и в таком запуске — это проверяется пробой. Ночной прогон без модели (3.3) идёт первым; с моделью — только после правила о данных.

**Вердикт:** взять — после 3.3 добавить второй слой: ночное ревью изменений дня с отчётом утром, на своём сервере.

## 6. Самообучение на принятых ревью

**Что.** Правила поведения агента выводятся только из **принятых** итогов ревью: замкнутый цикл «ревью → правило → замер → оставить или откатить». В отчёте о внедрении 39% правил пришли от людей-ревьюеров.

**Источник.** arXiv 2607.13091, «Self-Improving AI Coding Agents Through Accumulated Behavioral Rules: A Closed-Loop Framework»; addyosmani.com/blog/self-improving-agents.

**Наши правила.** У нас уже есть носитель — `observations.md` и разбор на границе вехи ([[capture-knowledge]] п.0), но нет цикла с замером «стало лучше или хуже».

**Вердикт:** взять — каждое новое правило из наблюдений получает кейс в замере (3.1); правило без улучшения в замере возвращается на разбор.

## 7. Общий эталон качества 1С

**Что.** Лидерборд 1C Code Bench оценивает генерацию функций BSL по компиляции и правильности; в статье о поиске кода 1С по описанию на естественном языке — эталон поиска, полезный для проверки `code-index`.

**Источник.** arXiv 2608.19957, «Natural Language Code Retrieval for 1C:Enterprise» (ссылка [8] — на лидерборд); адрес самого лидерборда ещё надо найти по статье.

**Наши правила.** Прогон без публикации наружу; задачи эталона — не наш код, утечки нет.

**Вердикт:** взять — внешняя точка отсчёта к замеру 3.1: «с плагином и без» на общих задачах, а не только на своих кейсах.

## 8. Проверка доработки в клиенте через Vanessa Automation

**Что.** va-ai — набор для генерации сценариев Vanessa Automation агентом: библиотека из 1569 шагов, шаблоны, правило «только шаги из библиотеки», проверка после генерации. Автор — тот же, что у `cc-1c-skills`. Есть разборы на Хабре (Vanessa_for_AI) и MCP для Vanessa Automation. Сценарии гоняются без интерфейса через vanessa-runner в CI.

**Источник.** github.com/Nikolay-Shirokov/va-ai; habr.com/ru/articles/1093504; confaster.ru/blog/ci-cd-1c-gitlab.

**Наши правила.** Только тестовая база; лицензию va-ai сверить до установки; правки — в реестр патчей.

**Вердикт:** взять — шаг 3.4 «проверка в клиенте 1С» строится на Vanessa Automation и va-ai, а не на голом `ТестируемоеПриложение`: шаги уже есть и проверены сообществом.

## 9. Живая отладка 1С агентом

**Что.** AI-EDT — MCP-сервер внутри запущенной EDT 2026.1–2026.2: точки останова, стек, переменные, вычисление выражений, пошаговое выполнение. Отдельно в каталоге aitools1c.dev — MCP для управления отладкой по HTTP без Конфигуратора.

**Источник.** github.com/desko77/ai-edt (лицензия AGPL-3.0); aitools1c.dev/tools/ai-edt.

**Наши правила.** Новый MCP — только через разбор и `.mcp.json` проекта; AGPL — ставим как отдельную программу, не встраиваем код. Пересекается с нашим `edt-mcp`.

**Вердикт:** позже — полезно для [[bug-diagnosis-loop]] (репро до гипотезы); решение владельца после разбора совместимости с `edt-mcp`.

## 10. 1С:Напарник как второй источник

**Что.** Официальная нейросеть 1С, обученная на типовых конфигурациях и стандартах; работает с EDT; внешним агентам доступна через MCP-серверы с токеном ИТС.

**Источник.** v8.1c.ru/platforma/iskusstvennyy-intellekt; github.com/Untru/1c-mcp (раздел «1С:Напарник»).

**Наши правила.** Запрос уходит на сервер 1С — это «наружу». Решает правило о данных: общие вопросы о платформе и типовых можно, наш код — нельзя.

**Вердикт:** позже — после правила о данных (2.1), только для вопросов без нашего кода.

## 11. Локальная модель для чувствительных данных

**Что.** Открытые модели для кода (Qwen Coder и др.) запускаются у себя через Ollama; на типовых задачах — ревью, тесты, шаблонный код — «часто достаточно», на сложных уступают облачным.

**Источник.** shattered.io, «Self-Hosted AI Coding Assistant» (шаг 4); atomic.chat, «Best Local LLM for Coding in 2026».

**Наши правила.** Единственный вариант, при котором данные не уходят никуда. Нужна видеокарта; качество ниже.

**Вердикт:** позже — кандидат для фильтра ПДн: локальная модель распознаёт ПДн в ответах базы рядом с Presidio, ничего не отправляя наружу.

## 12. Наш агент в других редакторах (протокол ACP)

**Что.** Открытый протокол Zed для связи любого агента с любым редактором (JSON-RPC по stdin/stdout); поддерживают Zed и JetBrains, есть реестр агентов.

**Источник.** agentclientprotocol.com; zed.dev/acp.

**Наши правила.** Нейтрально.

**Вердикт:** не брать сейчас — разработка 1С идёт в EDT и Конфигураторе, а не в Zed или JetBrains.

## 13. Радары экосистемы 1С-ИИ

**Что.** Каталоги, которые сами следят за новинками: Untru/1c-mcp — MCP-серверы, плагины и скиллы для 1С с сортировкой по звёздам и дате последнего коммита; aitools1c.dev — каталог инструментов с условиями работы.

**Источник.** github.com/Untru/1c-mcp; aitools1c.dev.

**Наши правила.** Только чтение, радар сигнализирует, а не ставит.

**Вердикт:** взять — источник для ночного дозора (3.3): новое в каталогах попадает в еженедельный отчёт с пометкой «разобрать».
