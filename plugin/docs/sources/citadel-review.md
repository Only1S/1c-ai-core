# Разбор Citadel

Разобрано 05.11.2026 по просьбе владельца, без помощников. Источник — репозиторий через `gh api`: метаданные, дерево файлов (2122 файла), README, `.claude-plugin/plugin.json`, `docs/ARCHITECTURE.md`, `docs/HOOKS.md`, `docs/CONSTITUTION.md`, `docs/JUDGE_TIERING.md`, `docs/QUALITY_LOOPS.md`, `docs/REPOSITORY_MEMORY.md`, `docs/RELIABILITY_LEARNING.md`, скиллы `postmortem`, `grill`, `learn`, `evolve`. Наличие у нас — по `plugin/hooks/hooks.json` и грепу по `docs/`. Найден через каталог 500-AI-Agents ([[ai-agent-courses-review]]).

## Что это

«Операционный слой» поверх Claude Code и OpenAI Codex: один вход `/do`, состояние проекта в репозитории между сессиями, параллельные помощники, защитные хуки, учёт стоимости, отчёт о доказательствах. Ставится плагином из маркетплейса с привязкой к тегу (`claude plugin marketplace add SethGammon/Citadel@v1.4.5 --scope local`). Нужны Node.js 22+ и git.

| Автор | SethGammon (733 из ~810 коммитов), ещё 4 участника |

| Предметная область | общая разработка на JS/TS, Python, Go, Rust: проверка типов после правки, правила качества для JS/CSS |

## Как устроен

- **Лестница оркестрации — «бери самую дешёвую ступень».** Скилл (минуты, без состояния) → `/marshal` (одна сессия, цепочка скиллов) → `/archon` (кампания на часы и дни, файл кампании) → `/fleet` (волны помощников в отдельных рабочих копиях git).
- **Маршрутизатор `/do` в 4 ступени.** Точная команда по равенству всей строки (0 токенов) → активное состояние (кампании, сессии) → кандидаты по ключевым словам скиллов (только подсказка, не право на запуск) → семантическая классификация моделью (~500 токенов). Принудительный маршрут `/do --route` меняет только выбор, границы одобрения не обходит.
- **Пять состояний работы:** Request → Run → Evidence → Needs You → Resume. Доказательство — `passed`/`failed`/`blocked`/`unknown`; «нет доказательства» не превращается в успех.
- **Файл кампании** `.planning/campaigns/*.md`: фазы со статусами, журнал фич, журнал решений, активный контекст, машинно-читаемая точка продолжения. Каждый запуск `/archon` читает его, каждое завершение фазы — обновляет.
- **Волны и передача находок.** Помощники волны 1 работают в разных папках; их находки сжимаются (~500 токенов на помощника) и передаются волне 2. Захват файлов — `.planning/coordination/claims/`: пересечение родитель/потомок — конфликт, соседние папки — нет, «только чтение» не конфликтует.
- **Конституция в 3 уровня** (`docs/CONSTITUTION.md`): уровень 1 блокирует (force-push в main, `--no-verify`, секреты в коммите, правка защищённых файлов, push без согласия в кампании), уровень 2 предупреждает с записью в журнал решений, уровень 3 — советы. У каждого правила уровня 1 — колонка «чем принуждается» и честная оговорка, что хук — ограждение, а не песочница.
- **Правило P-008:** разрешить зависимость, успех, выдачу или слияние может только текущее `passed`-доказательство с полным покрытием. Тайм-аут, битый ответ, частичный прогресс, исчерпанные повторы — не разрешают.
- **Судьи по уровням** (`docs/JUDGE_TIERING.md`): объективное (тесты, линтер, код возврата) решает команда, без модели; «прочитать отчёт и сверить условие» — малая модель; целостное суждение (архитектура, тонкая ошибка) — сильная модель **другого семейства**, которая сама перезапускает проверки. Тезис: судья — худшее место для экономии токенов.
- **Разбор после кампании** (`/postmortem`): по каждой поломке 5 полей — что случилось, чем поймано (хук, проверка, человек, ничем), цена, исправление, какая защита создана. Отдельно — что поймали защиты («невидимая польза»), дрейф объёма, повторяющиеся шаблоны. Затем `/learn` вливает выводы в вики проекта: обновляет страницы, повышает уверенность при повторе, помечает противоречия.
- **`/grill`** — опрос по одному вопросу, у каждого вопроса рекомендуемый ответ, всё, что знает репозиторий, — не спрашивать.
- **Хуки (выборка):** `protect-files.js` и `external-action-gate.js` (блокировки до вызова), `governance.js` (журнал значимых вызовов), `circuit-breaker.js` (3 сбоя подряд — подсказать другой путь, 5 — «остановись и пересмотри»), `cost-tracker.js` (стоимость сессии на лету), `post-tool-batch.js` (тяжёлая проверка один раз после волны параллельных вызовов, `async` + `asyncRewake`: будит модель только при провале), `permission-request.js` (одобряет свои безопасные операции и пишет каждое решение о разрешении в `.planning/telemetry/permission-events.jsonl` с отчётом аномалий), `pre-compact.js`/`post-compact.js` (сохранить и вернуть состояние вокруг сжатия).
- **Установка и снятие:** `adopt.js plan` → `apply --confirm <токен плана>` → `doctor`; план вне репозитория, иначе `TARGET_DRIFT`. `/unharness` строит план снятия по квитанциям установки.
- **Честные замеры.** README публикует и отрицательные итоги: экономии не доказано, у одного из сравнений слабая база («прямой Claude проверен только на 12,5%»).

## Ставить ли сам Citadel

Нет.
- Он принесёт 3 своих MCP-сервера, а у нас правило [[use-own-mcp-servers-only]]: барьер их не пропустит.
- Два плагина с хуками на одних событиях дадут двойные блокировки и двойные вставки в контекст. Его `/do` спорит с маршрутом через скиллы и [[task-recipes]].
- Его проверки качества — для JS/TS и подобных языков; для 1С у него нет ничего.

Брать идеи по одной, своим кодом и с самотестом.

## Кандидаты

1. **Предохранитель повторных сбоев — сделан 05.11.2026** (`plugin/hooks/failure-streak.py`, 13-й контур, [[enforcement-hooks]]; счёт — по журналу, а не своим счётчиком, потому что отказ барьера не порождает `PostToolUseFailure`). Сбои подряд считаются по хвосту журнала сессии после последнего успешного ответа или запроса владельца. После 3 — подсказка «смени подход», после 5 — «остановись, опиши причину владельцу». Самотест §180, живая проба настоящего хука прошла; живая проба сборки — до выпуска.
2. **Форма разбора поломки — сделана 05.11.2026** ([[capture-knowledge]] п.0б). В разбор наблюдений на границе вехи — 5 полей Citadel: что случилось · чем поймано · цена · исправление · какая защита создана (тест, правило, барьер или «не нужна»). Цена — абзац в [[capture-knowledge]].
3. **Тяжёлые проверки асинхронно — замерено, не нужно (05.11.2026).** `validate-bsl.py` с настоящим анализатором, правка одной строки в середине модуля, 3 прогона, модули выгрузки БП 3.0: 26 КБ (315 строк) — 0,9 с (первый прогон 2,2 с); 194 КБ (3094 строки) — 1,1 с; 4,5 МБ (50161 строка) — 5,5–6,6 с; 6,9 МБ (91804 строки) — 4,6–4,9 с. Код 0, отметок DEGRADED нет, до тайм-аута хука (60 с) далеко. Секунда на обычный модуль терпима, а асинхронный запуск отпустил бы модель к следующим вызовам до ответа проверки — ошибка в строке правки дошла бы позже. Оставлено синхронно; вернуться, если правки гигантских модулей станут частыми.
4. **Журнал разрешений и план снятия ядра** — позже, когда появится запрос.

Понадобится ядро под Codex — образец переноса хуков на него: `hooks_src/codex-adapter.js` Citadel.
