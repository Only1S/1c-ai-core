# Разбор соседей: unica и AI_agent

Оба проекта разобраны 05.08.2026 веером из 12 агентов (6 линз, на каждой состязательный скептик с грепом по ядру). Из 28 находок состязательную проверку пережила **одна** — контрактный смоук MCP. Планка была намеренно жёсткой («при сомнении отклоняй»), поэтому низкий выход — не приговор соседям, а цена строгости.

## Что это за проекты

| | **unica** (IngvarConsulting) | **AI_agent** (msrv-tech) |
|---|---|---|
| Что | плагин Codex + Claude Code для разработки на 1С | ИИ-агент **внутри** 1С для конечных пользователей |
| Ниша | та же, что у нас — среда разработки | другая — рантайм-агент в конфигурации |
| Форма | навыки + **один** MCP-сервер `unica`, Rust-рантайм | расширение 1С (префикс `ИИА_`) + Python-обвязка |
| Дистрибуция | marketplace-плагин, рантайм качается из релиза | поставка расширения |

## Сравнение состава навыков (счётом, не на глаз)

У unica **68** навыков, у нас **88**. Пересечение — **43**. Часть расхождения мнимая: их `dcs-*` — это наши `skd-*` (одна и та же СКД), их один `xdto` против наших пяти `xdto-*`.

- **Только у них (25)**, из ценного — тематические знаниевые навыки: `bsp-patterns`, `api-design`, `background-jobs`, `data-exchange`, `data-separation`, `db-performance`, `security-auth-crypto`, `test-authoring`, `log-analysis`, `platform-help`, плюс `code-review`/`code-search`/`code-diagnostics`/`code-patch`, `v8-runner`, `release-support`, `source-access`, `autonomous-server`, `integration-implement`, `db-auth-check`.
- **Только у нас (45)**: весь блок работы с базой (`db-*`, 11 на дату разбора), веб-публикация (`web-*`, 5), сборка/разбор обработок и отчётов (`epf-*`/`erf-*`), запросы (`query-compose`/`query-optimize`), `1c-standards`, `bsp`, `uuid-validate`, `cf-unpack`, Obsidian-набор, `page-fetch`.

## Где соседи сильнее нас — честно

- **Верификация рантайма (unica).** Скачанный рантайм проверяется двухслойно: sha256 архива и каждого файла плюс запрет путей за пределы каталога, а затем — **живой протокольный хендшейк**. У нас до этого разбора проверка stdio-сервера сводилась к «файл на месте, `--version` ответил».
- **Норма отделена от носителя (unica, `spec/`).** ADR владеет выбором, реестр `INV-*`/`REQ-*` — проверяемым обязательством, приёмка — доказательством; каждый слой обязан назвать падающую проверку, а границы того, что проверка **не** доказывает, объявлены вслух. У нас мысли те же ([[design-before-code]], [[decision-records-and-glossary]]), но машинерии удержания на дату разбора не было. **Закрыто 05.08.2026:** карта «правило → чем принуждается» — [[rule-enforcement-map]].
- **Релизный гейт шире (unica).** На дату разбора наш гейт был односторонним — гигиена истории (`release-core` мастера). У них дополнительно: пригодность артефакта, класс дельты, отзыв релиза, наблюдение за каналом — и всё это исполняемым кодом с юнит-тестами, а не прозой. **Закрыто частично (сверка 30.10.2026):** `release-core.py` отказывает по пригодности сборки (`fitness`), классу дельты и правилу «не хуже прошлого тега» (`quality_gate`); гейт замера проверен по поведению (`contour-tests` §80), класс дельты — только поиском текста в исходнике. **Остаток:** механизма отзыва релиза нет; отдельного наблюдения за каналом нет, ближайшее — `tools/checks/projects-watch.py` (сравнивает версии проектов с последним тегом клона канала).
- **Ступенчатое принуждение с журналом (AI_agent).** Политика подтверждений вынесена в отдельный модуль (`ИИА_ApprovalPolicy`), а не размазана по оркестратору; результат детерминированно сверяется с системными фактами.

## Где сильнее мы

- **Предметная глубина.** Их `code-review` беднее нашего двухосевого [[two-axis-code-review]] (ось «Стандарты» с номерами v8std/BSLLS против оси «Спека»); `log-analysis` беднее [[task-recipes]] §7 (ТЖ через бандл `OneSTools.PS.TechLog` + `loga`); `api-design` пересказывает стандарты, которые у нас лежат корпусом в `.claude/skills/1c-standards`.
- **Охват операций с базой и публикацией** — `db-*`/`web-*`/`epf-*` у них отсутствуют как класс.
- **Контуры принуждения.** 9 контуров (на дату разбора; текущий состав — [[rule-enforcement-map]]) с регрессионным самотестом поведения ([[full-checker-set-before-done]], `tools/checks/contour-tests.py`) — у соседей аналога нет.
- **`quality_gate_matrix.py` (AI_agent) — это наш `tools/checks/weekly-check.py`** под другим именем: оба не дублируют ассерты, а запускают существующие проверки и агрегируют отчёты.

## Что забрано: контрактный смоук MCP

**Дыра, которую нашли.** `tools/checks/mcp-smoke.py` для HTTP-серверов делал настоящий end-to-end (`/health` с разбором `index_loaded`), а для **всех пяти stdio-серверов** (`headroom`, `bsl-platform`, `code-index`, `nkdk`, `bsl-ls`) деградировал до `Test-Path` + `--version`. Сервер с поехавшим MCP-контрактом проходил зелёным — тот же класс ложно-зелёного, ради борьбы с которым скрипт и написан.

**Как закрыто.** Для stdio теперь идёт настоящий хендшейк `initialize` → `notifications/initialized` → `tools/list`, затем сверка **якорных** имён инструментов. Якорей по два на сервер намеренно: полный список превратил бы смоук в ложно-красный при каждом обновлении сервера — у `code-index` инструментов стало 11 → 20, и точный список сломался бы на ровном месте.

Прогон после внедрения: `headroom` 3 · `bsl-platform` 5 · `code-index` 20 · `nkdk` 8 · `bsl-ls` 10 — контракт подтверждён у всех пяти, весь смоук 23 секунды. Негативным тестом проверено, что подменённый якорь даёт «КОНТРАКТ НАРУШЕН», а не зелёное.

## Четыре грабли реализации (все пойманы прогоном, не рассуждением)

1. **Перенаправил stderr — обязан его читать.** Нечитаемый перенаправленный поток переполняет буфер ОС (~4 КБ), и процесс встаёт намертво. `bsl-ls` сыплет предупреждениями JVM на старте и умирал, не дойдя до ответа, — тогда как тот же лаунчер с отброшенным stderr отвечает за 7 секунд. Лечится `BeginErrorReadLine` с обработчиком; заодно последняя строка stderr идёт в текст вердикта.
2. **`ReadLineAsync` + `Wait()` в PowerShell 5.1 подвисает** (синхронное ожидание Task в однопоточном апартаменте), и сервер, отвечающий за секунды, получает вердикт «нет ответа за 120 с». Рабочая схема — события `OutputDataReceived` в `ConcurrentQueue` с досрочным выходом по нужному ответу.
3. **`ReadToEndAsync` ждёт закрытия потока**, а долгоживущий сервер его не закрывает: каждый выжидал полный таймаут, и смоук ушёл за 10 минут вместо 23 секунд.
4. **Закрывать stdin нельзя.** Часть серверов трактует EOF как «клиент ушёл» и завершается, не ответив (`bsl-platform` на EOF отвечал только на `initialize` и умирал).

Отдельно — **имена инструментов берутся из протокольного ответа, а не из клиентских**: у Claude Code инструмент виден как `mcp__nkdk__nkdk_validate_project`, но сервер отдаёт `nkdk.validate_project` **через точку**. Якоря, списанные с клиентских имён, дают ложное «контракт нарушен».

## Что не берём

- **Одно-серверная архитектура MCP** (unica) — сознательно противоположна нашей: у нас 10 специализированных серверов (на дату разбора), каждый со своим источником истины ([[installed-tools-and-servers]]), и слияние их в один противоречит [[use-own-mcp-servers-only]] и лишает независимой сверки.
- **Продуктовая часть AI_agent** (DSL, планировщик, RAG по метаданным, tool-loop, Telegram-контур согласования) — они рантайм-агент, мы среда разработки; прикладывать некуда.
- **Их навыки как файлы** — заимствование чужих SKILL.md означало бы смешение префиксных и беспрефиксных имён и конфликт маршрутов ([[external-skills-review]]); темы, которых нам недостаёт (`data-separation`, `background-jobs`, `db-performance`), закрываются нашими источниками — `bsp`, `v8std`, `1c-standards`.

## Новые соседи — волна 19.09.2026

Разобраны по коду, вердикты — [[external-mcp-servers-review]]. Где они сильнее нас:
- **`comol/ai_rules_1c`** — у каждого гейта правила есть поведенческий приёмочный сценарий, гейт без сценария считается ошибкой. Наши `contour-tests` проверяют логику хуков, а у совещательных правил сценариев нет.
- **`bigsofter/tiny1C`** — у каждого правила названы источник и способ проверки, корпус собран из реальных инцидентов.
- **`blessed2k/1c-ai-skills`** — явная лестница выбора точки врезки до ТЗ: переопределяемый модуль БСП → подписка → `&После` → `&Вместо`.
- **`AndreevED/1c-ai-feature-dev-workflow`** — объём процесса по размеру задачи; наш `design-consilium` всегда запускает всех агентов.

Взяты только идеи, своими словами. Их плагины рядом с нашими не ставим — по той же причине, что в «Что не берём».
