# Правило: формы — через штатные средства и «с глазами»

Управляемые формы разрабатывать **штатным инструментарием, а не ручной правкой `.form` вслепую**, и обязательно **видеть результат** до вывода «готово». Полный практикум — [[managed-forms-guide]].

**Why:** правка `.form` как сырого XML без просмотра результата — источник ошибок раскладки (разъехавшиеся колонки, узкие таблицы, потерянные привязки) и повреждений (кириллица/CRLF). Штатные средства знают структуру формата, а скриншот показывает фактический результат.

**How to apply:**
0. **Опция профиля «предпросмотр формы»** (19.09.2026, по находке экземпляра; по умолчанию выключена — удлиняет каждую правку): если профиль проекта её включает, видимая правка формы сначала делается во временной форме `<Имя>Preview` → скриншот `get_form_screenshot` → одобрение владельца → перенос в рабочую форму → удаление временной формы.
0б. **Текстовый эскиз формы — до генерации XML** (с 05.10.2026; по мотивам «Накидки» `crimsongoldteam/md_design`, MIT — идея, нотация своя). Прежде чем звать `form-compile`, форма показывается владельцу **эскизом в ответе** (нотация — [[managed-forms-guide]], раздел «Эскиз формы в ответе»): видно состав, порядок и раскладку, правки стоят одну строку. Эскиз не заменяет ни `form-validate`, ни скриншот `get_form_screenshot` (он про компоновку платформой, а не про замысел) — он снимает вопрос «то ли я понял» до того, как появился XML. Для правки существующей формы эскиз рисуется по `form-info`, а не по памяти.
1. **Инструмент — по формату формы** (единая таблица с 16.10.2026; так же делит маршрут защита `guard-skills`):

   | Формат | Изучить | Построить / изменить | Проверить |
   |---|---|---|---|
   | Управляемая форма в выгрузке Конфигуратора (`Ext/Form.xml`) | `form-info`, `form-patterns`, эскиз (п.0б) | `form-compile` / `form-edit` | `form-validate`, `1c-standards` |
   | Управляемая форма в проекте EDT (`Form.form`) | `edt-mcp` (реквизиты, скриншот) | `1c-forms`: `generate_form` → правка по [[forms-from-edt-metadata]] | `1c-forms` `validate_form` + скриншот `edt-mcp` |
   | Конвертация между форматами | — | `1c-forms` `convert_form` (по согласию) | валидатор целевого формата |
   | Обычная форма (обычное приложение, `Form.bin` / `form.frm`) | `form-ordinary`: `unpack`, `decode`, `brief`, `render`; поиск по модулям всех форм — `form-bin-module` | `form-ordinary` `edit --ops` (правка в объёме просьбы, отчёт о масштабе) или `generate` | `form-ordinary` `validate`, `lint`, `render --before` «до / после»; затем загрузка в тестовую базу ([[platform-version-and-optional-edt]] п.4) |

   Скрипты `form-*` понимают только выгрузку Конфигуратора; для `Form.form` и обычных форм они не годятся. `form-ordinary` (с 19.10.2026) проверен на копиях 1617 обычных форм: разбор и сборка `form.frm` байт в байт — 1616 из 1617 (одна форма — отказ с причиной), загрузка изменённой формы в конфигуратор у нас ещё не проверялась — поэтому загрузка в тестовую базу обязательна.
2. **Обязательно увидеть форму** после правки: `get_form_screenshot`/`get_form_layout_snapshot` (нужен флаг рендера, см. [[edt-mcp-pitfalls]]) или прогон через `web-test`.
3. Пройти форму **поэлементно** по чек-листу свойств из [[managed-forms-guide]]; проверить привязку событий в обе стороны.
4. Ручная правка `.form` — только крайняя мера и **байтобезопасно** (см. [[edt-mcp-pitfalls]]).
5. «Готово» — лишь после протокола проверки формы из [[managed-forms-guide]].
