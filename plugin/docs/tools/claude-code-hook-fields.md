# Справка: поля хуков Claude Code и матчеры событий

Источник — официальная документация `code.claude.com/docs/en/hooks` (сверено 04.08.2026 через WebFetch; прежний адрес `docs.claude.com/en/docs/claude-code/hooks` отвечает 301). Повод — разбор [[external-skills-review]]-подобного каталога `sfrangulov/claude-code-handbook-ru`: из всего справочника единственной находкой, пережившей состязательную проверку, оказалось поле `if`, а сверка с первоисточником вскрыла ещё пять полей, которых ядро не использует.

## Поля командного хука

| Поле | Обяз. | Что делает | Грабли |
|---|---|---|---|
| `type` | да | `"command"`, `"http"`, `"mcp_tool"`, `"prompt"` или `"agent"` (сверено 18.09.2026) | в ядре везде `command`; у `SessionStart` допустимы только `command` и `mcp_tool` |
| `command` | да | команда оболочки (shell-форма) либо исполняемый файл (exec-форма, если задан `args`) | — |
| `args` | нет | вектор аргументов; включает **exec-форму** — оболочка не запускается, токенизации нет | На Windows `command` обязан быть **настоящим `.exe`**: `.cmd`/`.bat`-шимы в exec-форме не стартуют. Плейсхолдеры (`${CLAUDE_PROJECT_DIR}`) подставляются как есть — **это и есть рекомендованный способ обойти проблемы с пробелами и кавычками в путях** |
| `if` | нет | фильтр в синтаксисе правил разрешений: `"Bash(git *)"`, `"Edit(*.ts)"` — хук запускается, только если вызов совпал | ⛔ **Две тихие ловушки сразу.** (1) Работает только на тул-событиях (`PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PermissionRequest`, `PermissionDenied`); на любом другом событии хук с `if` **никогда не запускается**. (2) Файловый фильтр пишется **только формой `Edit(...)`** — см. отдельный раздел ниже |
| `timeout` | нет | секунды до отмены, по умолчанию **600** | В ядре везде проставлен явно (10–60) |
| `statusMessage` | нет | текст спиннера | — |
| `shell` | нет | `"bash"` или `"powershell"` — какой оболочкой исполнять shell-форму | По умолчанию на Windows `powershell`, если не установлен Git Bash. **Игнорируется**, когда задан `args` |
| `async` | нет | фоновый запуск, Claude не ждёт | ⛔ Асинхронный хук **не может блокировать и не возвращает решение**: exit-код и stdout игнорируются. Барьер асинхронным делать нельзя — останется только журналирование |
| `asyncRewake` | нет | то же плюс: **exit code 2** будит Claude, stderr (или stdout, если stderr пуст) приходит system-reminder'ом | Подразумевает `async`. Код 2 — единственный, который будит. Заблокировать действие всё равно не может, только уведомить постфактум |
| `once` | нет | один раз за сессию, потом снимается (неуспешный, заблокированный exit 2 или истёкший прогон хук оставляет) | ⛔ Учитывается **только во frontmatter скилла**; в `settings.json` и во frontmatter агента **молча игнорируется** (сверено 18.09.2026 — раньше тут было «скилла или агента») |

## Вывод хука — второй класс: не решение, а контекст

Поля выше описывают, **как хук объявляется**. Отдельный вопрос — **что он возвращает**, и здесь у ядра была слепая зона: все 8 контуров, существовавших до 19.08.2026, использовали ровно одну форму вывода — запрет (`permissionDecision = deny`) либо блокирующий фидбек (`exit 2` + stderr). Есть вторая форма, которой ядро не пользовалось ни разу: **`additionalContext` — хук не запрещает вызов, а добавляет факты в контекст модели.**

```json
{"hookSpecificOutput": {"hookEventName": "PreToolUse", "additionalContext": "текст, который увидит модель"}}
```

Сверено с официальной документацией 19.08.2026: поле принимают `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PermissionRequest`, `Stop`. На `PreToolUse` оно работает **без** `permissionDecision` — вызов идёт своим ходом, а модель дополнительно получает справку. Это ортогонально запрету: один и тот же хук может либо запретить, либо обогатить, либо промолчать.

⛔ **С `async` несовместимо** (см. таблицу выше): асинхронный хук не возвращает решение и его stdout игнорируется — значит `additionalContext` из фонового хука до модели не дойдёт. Обогатитель обязан быть синхронным, и отсюда следует его главная проблема — цена.

**Цена вызова — конструктивное ограничение, а не деталь.** Обогатитель, который лезет за настоящими фактами, платит стартом внешнего процесса. Замер 19.08.2026 на этой машине: `bsl-indexer.exe query <имя>` — **321 / 431 / 321 мс**, причём на индексе из **двух** файлов, то есть почти всё это время — старт процесса, а не поиск. Хук, дергающий индексатор на каждый `Grep`, добавил бы эти сотни миллисекунд к каждому поиску за сессию. Отсюда четыре обязательных свойства обогатителя: **узкий матчер** (срабатывать редко и по делу), **троттлинг** (повтор той же подсказки в одной сессии бесполезен), **таймаут** (внешний процесс может зависнуть) и **fail-open** (любая ошибка = молчание, не блокировка). Без них обогатитель не помощник, а налог на каждый ход.

Приём подсмотрен у `DeusData/codebase-memory-mcp` (разбор дельты 19.08.2026 — [[external-mcp-servers-review]]): их хуки объявлены "fail-open and context-only" и на `Grep`/`Glob` подмешивают символы графа, ничего не запрещая. Заимствован **механизм вывода**, не их сервер (BSL он не поддерживает).

## Куда уходит вывод хука — три немых контура (сверено 18.09.2026)

Сверено по тексту `code.claude.com/docs/en/hooks.md` (скачан целиком и прочитан по строкам, а не пересказом): находка агента разбора официального репозитория Claude Code, перепроверенная вручную после того, как справочный агент ответил «не описано».

- **Обычный stdout при exit 0** доходит до модели **только** на `UserPromptSubmit`, `UserPromptExpansion`, `SessionStart` и `PostModelSwitch`. На всех прочих событиях он уходит в debug-лог и в переписке не виден.
- **stderr при exit 0** — только в debug-лог; ни модель, ни пользователь его не видят. Показать предупреждение пользователю — поле `systemMessage` в JSON; дать модели фидбек после `PostToolUse` — exit 2.
- **`SubagentStart`** передаёт текст субагенту только полем `hookSpecificOutput.additionalContext` (в начало его контекста, до первого промпта). Лимит у `additionalContext`, `systemMessage` и обычного stdout — 10 000 символов; больше — Claude Code кладёт текст в файл и отдаёт путь и превью 2 000 символов.
- **`PostCompact`** — только для реакции на компакцию (журнал и т. п.): его `systemMessage` и `continue` отбрасываются, в контекст он ничего не добавляет. Восстанавливать контекст после компакции — через `SessionStart` с matcher `compact`, где обычный stdout доходит до модели.
- **`Stop`**: `hookSpecificOutput.additionalContext` **продлевает ход** (модель получает текст как «Stop hook feedback» и продолжает); защита от зацикливания — поле `stop_hook_active` на входе и потолок в 8 продолжений подряд. `systemMessage` — предупреждение пользователю без продления хода.

**Что это значило для ядра.** Три контура с момента введения «работали» только в health-check: `SubagentStart` печатал `tools-gate.md` обычным stdout — субагенты гейт не получали; `PostCompact` печатал `postcompact-note.md` — после компакции не восстанавливалось ничего; `stop-guard` писал напоминание в stderr при exit 0 — его не видел никто. Исправлено 18.09.2026: `SubagentStart` → `plugin/hooks/subagent-gate.py` (JSON `additionalContext`, UTF-8 байтами), дисциплина после компакции → `SessionStart` matcher `compact`, `stop-guard` → JSON `systemMessage`. Стерегут: health-check 1b (проверка формы вывода, запрет `cat` на событиях без доставки, длина `tools-gate.md` ≤ 10 000) и contour-tests §13 (разбирают выход хуков как JSON).

**Самозащита контуров.** В `bypassPermissions` родная защита `.claude/` выключена, и одна правка `settings(.local).json` с `"disableAllHooks": true` снимает все хуки проекта (управляемые политикой — нет). С 18.09.2026 барьер `guard-skills` проверяет **результат** правки настроек: итоговое `disableAllHooks: true`, пропажа проводки любого контура или сокращение `permissions.deny` — отказ; обычное обслуживание проходит (contour-tests §9d). health-check дополнительно держит белый список команд хуков (посторонняя команда — FAIL) и проверяет `disableAllHooks` в проектных и пользовательских настройках. Граница: правка настроек через Bash-скрипт (python и т. п.) этим барьером не видна.

## Матчеры по событиям

| Событие | `matcher` | По чему матчит |
|---|---|---|
| `PreToolUse` / `PostToolUse` | да | имя инструмента (`Bash`, `Write\|Edit`, …) |
| `SessionStart` | **да** | источник сессии: `startup`, `resume`, `clear`, `compact`, `fork` |
| `SubagentStart` | **да** | тип агента: `general-purpose`, `Explore`, `Plan`, свои имена |
| `PostCompact` | **да** | что вызвало компакцию: `manual`, `auto` |
| `UserPromptSubmit`, `Stop`, `PostToolBatch`, `TaskCreated`/`TaskCompleted`, `WorktreeCreate`/`WorktreeRemove`, `MessageDisplay`, `CwdChanged`, `TeammateIdle` | **нет** | всегда срабатывают; лишний `matcher` **молча игнорируется** |

## Сбой инструмента — `PostToolUseFailure` (зонд 05.11.2026, Claude Code 2.1.3xx, `claude -p` с `--settings`)

- **Когда приходит:** `Read` несуществующего файла (`error`: «File does not exist…»), `Bash` с ненулевым кодом (`error`: «Exit code 3»). Успешный вызов — только `PostToolUse`.
- **Отказ хука `PreToolUse` (код 2) не порождает ни `PostToolUseFailure`, ни `PostToolUse`.** В журнале сессии он записан обычным ответом инструмента: `tool_result` с `is_error: true` и текстом «PreToolUse:Bash hook error: […]». Посчитать серию отказов барьеров можно только по журналу.
- **Поля входа:** `hook_event_name`, `tool_name`, `tool_input`, `tool_use_id`, `error`, `is_interrupt`, `duration_ms`, `prompt_id`, `session_id`, `transcript_path`, `cwd`, `permission_mode`, `effort`, `scratchpad_dir`. Поля `tool_response` нет.
- **Журнал:** ответ инструмента — запись `type: user`, в `message.content` — список `tool_result` (`tool_use_id`, `is_error`, `content`) и рядом `toolUseResult`. Записи `type: api-request-blob` повторяют то же содержимое — считать их нельзя.
- **Вывод:** `hookSpecificOutput.additionalContext` с `hookEventName: "PostToolUseFailure"` модель видит. Кириллицу писать байтами UTF-8 (`sys.stdout.buffer.write(...encode('utf-8'))`): через `print` на Windows текст пришёл модели битым.
- Применено в ядре: `plugin/hooks/failure-streak.py` (стоп при повторных сбоях, `contour-tests` §180).

## ⛔ Файловый фильтр — только формой `Edit(...)`

Правила разрешений с путём Claude Code сверяет **только для `Edit(path)` и `Read(path)`**. Правило для `Write`, `MultiEdit`, `NotebookEdit` или `Glob` платформа **принимает, но никогда не консультирует** (при старте выдаёт предупреждение). Прямая цитата документации:

> Use `Edit(docs/**)` in place of `Write(docs/**)` … Edit rules cover all file-editing tools.

Значит `"if": "Write(**/*.bsl)"` — не фильтр, а выключатель: хук молча перестанет запускаться. Правильно — `"if": "Edit(**/*.bsl)"`, эта форма покрывает и `Write`, и `Edit`. Ловушка тем опаснее, что конфиг остаётся валидным JSON, health-check «файл на месте» её не видит, а `contour-tests` гоняет скрипт пайпом **мимо проводки** — то есть без отдельной проверки все три наших гейта показали бы зелёное.

⛔ **Поправка по живому зонду 17.10.2026: на инструменте `Write` фильтр `if: "Edit(…)"` НЕ срабатывает.** Цитата выше — про правила разрешений, а у хуков `if` сверяется с самим инструментом. Зонд: модуль `.bsl`, созданный `Write`, проверку не получил (в `logs/gate-state.json` нет отметки сессии), та же правка через `Edit` — получила. Значит, с 04.08.2026 контур 1 (`validate-bsl`: анализатор, смешение алфавитов) молча не запускался на модулях, записанных целиком. Исправлено: у `Edit` — прежний фильтр `Edit(//**/*.bsl)`, у `Write` — отдельная проводка **без** `if` (скрипт сам отсеивает не-`.bsl`, цена — старт процесса на каждую запись файла целиком). Повторный зонд через `Write` получил блокирующий фидбек. Стережёт `contour-tests` §10.

Синтаксис путей — gitignore-подобный: `//путь` — абсолютный от корня ФС, `~/путь` — от домашнего каталога, `/путь` — от источника настроек (для `.claude/settings.json` это корень проекта), `путь` без слэша — от текущего каталога и **на любой глубине**. На Windows пути перед сверкой нормализуются в POSIX-форму (`C:\Users\<name>` → `/c/Users/<name>`), поэтому шаблон на весь диск пишется как `//c/**/.env`, а на все диски — `//**/.env`.

## ⛔ Смена команды хука применяется сразу (грабля 16.10.2026)

Claude Code перечитывает хуки из `.claude/settings.json` на лету: следующий же вызов инструмента идёт по новой команде. Если команда указывает на файл, которого ещё нет (или с опечаткой в имени), интерпретатор завершается с кодом 2 (`python` — «can't open file»), а код 2 у `PreToolUse` — это **отказ**. В ядре так за одну правку заблокировались и Bash (барьер `guard-destructive`), и Edit/Write (барьер `guard-skills`) — чинить пришлось через терминал, куда хуки не стоят.

Как делать: сперва положить файлы хуков, потом **одной** правкой сменить все команды (весь файл целиком — Write — или одна замена, покрывающая и путь, и расширение); после правки — пробный безобидный вызов Bash. Хук `Stop` с той же ошибкой не даёт закончить ход (код 2 = продолжать).

## Внедрено в ядре (04.08.2026)

- **Контур 1** (`PostToolUse` → `validate-bsl`) получил `"if": "Edit(**/*.bsl)"`, а 18.09.2026 — абсолютную форму `"Edit(//**/*.bsl)"`: шаблон без слэша считается от текущего каталога сессии, и правки `.bsl` в исходниках вне корня проекта (`ONEC_PROJECT_SRC`, каноничная раскладка) хук не запускали вовсе — контур 1 молчал на реальном коде (находка экземпляра). На Windows пути перед сопоставлением приводятся к POSIX-виду (`C:\Users\<name>` → `/c/Users/<name>`), `//**` совпадает с любым диском (docs permissions). Проверено живым зондом: правка `.bsl` с синтаксической ошибкой в каталоге вне корня получила блок `ParseError`; правка настроек подхватилась без перезапуска сессии (Claude Code перечитывает `settings.json` на лету). До этого процесс PowerShell стартовал на каждую правку любого файла, а скрипт сам отбраковывал не-`.bsl` первой же строкой.
- **Двойная проверка проводки** (одна ошибка тут = мёртвый контур):
  - `contour-tests.py` §10 — разбирает `settings.json` и краснеет, если `if` стоит на не-тул-событии либо задан формой `Write`/`MultiEdit`/`NotebookEdit`; отдельно сверяет, что у `validate-bsl` шаблон именно `Edit(//**/*.bsl)` (относительная форма `Edit(**/*.bsl)` — FAIL);
  - `health-check.py` секция 1b — тот же ассерт короткой формой, потому что health-check гоняется на каждом старте сессии и в `git pre-commit`, а `contour-tests` — по регламенту.
  - Обе проверки **проверены негативом**: на подсунутом `Write(**/*.bsl)` и на `if` у события `Stop` тест краснеет, а не проходит.
- **Чего эти проверки НЕ доказывают:** что платформа матчит шаблон именно так, как мы ожидаем. Это статика по конфигу. Финальная верификация — эмпирическая, в новой сессии: правка `.bsl` с заведомой ошибкой должна получить блокирующий фидбек контура (`exit 2`), а правка `.md` — пройти без запуска хука.

## Что из этого применимо к контурам ядра

Фактическая проводка (`plugin/hooks/hooks.json` и `.claude/settings.json` мастера, сверка 30.10.2026): кроме `type`/`command` задействованы `if` (шесть фильтров: `Edit(//**/*.bsl)`, `Edit(//**/*.md)`, `Bash(gh *)`, `Bash(curl *)`, `Bash(defuddle *)`, `Read(//**/page-*.md)`), `timeout` и `statusMessage` (почти у каждого хука); `args`/`shell`/`async`/`asyncRewake`/`once` не используются. Матчеры стоят на тул-событиях и на `SessionStart` (`compact` — напоминание после компакции).

- **`if` на PostToolUse → `validate-bsl`** (контур 1) — **внедрено**: `"if": "Edit(//**/*.bsl)"` (с 18.09.2026 абсолютная форма, см. выше), хук больше не стартует на правках не-BSL. Форму `Write(...)` не использовать ни при каких обстоятельствах — см. раздел выше, она не фильтр, а выключатель. Проводка проверяется не скриптом, а отдельными ассертами (`contour-tests` §10 + короткий дубль в `health-check`), потому что пайп-матрица промах шаблона не увидит.
- **`if` на PreToolUse → `guard-destructive`** (контур 6) — **не сужать**: барьеру нужен весь трафик `Bash|PowerShell`, любое сужение = дыра.
- **`matcher` на `SessionStart`** — сейчас health-check гоняется на `startup`, `resume` **и** `compact`. Разделение по источнику позволяет решать это осознанно (например, полный прогон на `startup`, ничего на `resume`).
- **`matcher` на `SubagentStart`** — можно давать разным типам агентов разный текст гейта вместо одного общего `tools-gate.md`.
- **`args` (exec-форма)** — устойчивее нынешней shell-формы к пробелам в пути экземпляра; хуки ядра на Python, так что в `command` встал бы `python` (сейчас — shell-форма `python "${CLAUDE_PLUGIN_ROOT}/hooks/<хук>.py"`), а не `.cmd`-обёртка.
- **`asyncRewake` для тяжёлых проверок** — теоретический способ не держать старт сессии: прогон в фоне, `exit 2` будит с текстом. Требует смены контракта наших скриптов (сейчас exit нормализован в 0/1 — см. `contour-tests`), поэтому не бесплатно.
- **`async` для барьеров — запрещено**: решение игнорируется, барьер превращается в журнал.

Связано: [[probe-tool-capabilities]], [[claude-code-context-engineering]], [[run-checks-quietly-in-background]], [[docs-match-reality]].
