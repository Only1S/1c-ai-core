# Ночной дозор ядра (GitHub Actions)

> Программа `tools/checks/nightwatch.py` есть только в мастере ядра: в плагин она не входит, и в проекте её нет.

Ежедневно без человека: разобрать изменения дня и дать отчёт утром (#5 волны 3, решение владельца — **с моделью**). Что делает `tools/checks/nightwatch.py`:

- собирает коммиты и дифф за сутки (`git log --since`);
- прогоняет `health-check` и `contour-tests`, если они есть в репозитории (вердикты — в отчёт);
- с `--review` просит модель (`claude -p`, режим **plan** — только чтение) разобрать дифф: риски, сломанные инварианты, снятые проверки, расхождение доков и кода;
- пишет отчёт markdown (артефакт + issue). Ничего не меняет и не публикует наружу.

## Куда положить

Workflow `.github/workflows/nightwatch.yml` работает в том **GitHub-репозитории**, где лежит вместе с `tools/checks/nightwatch.py`, — за изменениями этого репозитория дозор и следит. Без заданного секрета ревью моделью не проходит.

В CI дозор запускается с `--ci`: проверки машины (`health-check`, `contour-tests`) там не гоняются — на раннере нет установленных программ, платформы 1С, настроек и git-хуков, и они дали бы шум (первый прогон 30.10.2026 — FAIL=14 только от окружения). Их гоняет pre-commit на машине на каждой вехе. В CI — гейт истории `pre-publish-audit --since <база>` (база — `.github/audit-baseline`, общая с workflow `pre-publish-audit`) и ревью модели. Сам workflow на push и запрос читает этот файл из состояния ДО проверяемых коммитов (`--since-at`): коммит, который и добавляет секрет, и сдвигает базу, гейт не отключает. Отправка, сдвигающая базу, поэтому проверяется ещё от старой; красный итог такой отправки снимает ручной запуск workflow, он берёт файл из проверяемого дерева. Ночной дозор читает файл из проверяемого дерева всегда. Расписание — `cron` (по умолчанию 02:00 UTC), плюс запуск вручную из вкладки Actions.

## Что завести

- **Секрет `CLAUDE_CODE_OAUTH_TOKEN`** в настройках репозитория (Settings → Secrets and variables → Actions) — токен подписки Claude: его печатает `claude setup-token` (браузерный вход, действует год, планы Pro/Max/Team/Enterprise; работа идёт от подписки, без отдельного счёта). Режим `--bare` этот токен не читает — в workflow его нет. Вместо токена можно API-ключ с platform.claude.com — секрет `ANTHROPIC_API_KEY` и та же переменная в шаге workflow (оплата по обращениям).
- **Доступ Actions**: `permissions: contents read, issues write` (уже в workflow) — чтобы открыть issue с отчётом.
- **Claude Code в CI** — версия и сумма сборки `linux-x64` закреплены в шаге установки: `CLAUDE_VERSION` и `CLAUDE_SHA256`, одинаковые в трёх workflow и двух шаблонах `plugin/tools/service/` (держит `contour-tests` §175). Чтобы поднять версию, возьмите `platforms.linux-x64.checksum` из `https://downloads.claude.ai/claude-code-releases/<версия>/manifest.json` и замените оба значения во всех пяти файлах.

## Что получится

Каждую ночь — артефакт `nightwatch-report.md` и issue «Ночной дозор `<дата>`»: коммиты дня, вердикты чекеров, 3–7 пунктов «что проверить» от модели со ссылками `файл:строка`. Это кормит разбор на границе вехи и еженедельный отчёт (`weekly-check` с радарами экосистемы).

## Границы и безопасность

- Ревью идёт **только на чтение** (`--permission-mode plan`, `--allowedTools Read Grep Glob Bash(git*)`) — ночной прогон код не трогает.
- Первый срез — на репозитории **без данных 1С** (мастер/канал), ПДн-риска нет. На проектном репозитории с выгрузкой — сперва правило о данных (волна 2): дифф выгрузки может нести персональные данные, их к модели не отправлять ([[personal-data-masked-from-1c]]).
- Расход токенов: один прогон модели в сутки на репозиторий. Регресс детерминированной части (сборка отчёта, без модели) — `contour-tests` §56.
