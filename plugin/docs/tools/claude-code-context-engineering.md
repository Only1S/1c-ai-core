# Контекст-инженерия Claude Code (конспект + проекция на ядро)

Источник: «Что вы не знали о Claude Code» — https://habr.com/ru/articles/1012412/ (сохранено 13.07.2026 по правилу [[capture-knowledge]]). Главный тезис: устойчивость агента определяется не длиной промптов, а **архитектурой слоёв системы**; проблемы модели чаще оказываются проблемами архитектуры.

## Шесть слоёв (и их аналоги в ядре)

| Слой (статья) | Назначение | В ядре |
|---|---|---|
| CLAUDE.md | контракт проекта, всегда в контексте | CLAUDE.md (один канонический слой + автоиндекс генератором) |
| Skills | рабочие процессы по требованию | 97 скиллов (на 17.10.2026) + команды `/health` `/release` … |
| MCP/Tools | доступные возможности | серверы `.mcp.json` (на 30.10.2026: в мастере 12, в плагине 7) |
| Hooks | принудительные проверки вне контекста | контуры принуждения (число — в `CLAUDE.md`, состав — [[enforcement-hooks]], [[rule-enforcement-map]]): барьеры, пост-фактум проверки, совещательные напоминания, обогатители |
| Subagents | изолированные экземпляры для массовых операций | [[subagents-on-explicit-consent]], workflows |
| Verification | замкнутый цикл проверки | [[full-checker-set-before-done]], health-check/contour |

Усиление одного слоя без остальных разбалансирует систему.

## Бюджет контекста (~200K)

- Фиксированные ~15-20K: системные инструкции, определения Skills и MCP-серверов. **Один MCP-сервер с 20-30 инструментами ≈ 4-6K токенов** — пять серверов съедают ~12% контекста до начала работы (в нашей среде смягчено deferred-загрузкой инструментов через ToolSearch).
- Полуфиксированные ~5-10K: CLAUDE.md, Memory. Рекомендация статьи — CLAUDE.md держать коротким (~2.5K токенов у самого Anthropic); крупные справочники — в supporting files скиллов/доках по требованию. В ядре: полные описания — в `docs/MEMORY.md`, CLAUDE-индекс — усечённый (генератор).
- Динамические ~160-180K: история, файлы, **Tool Output**. Полный вывод тестов/линтеров на тысячи строк — главный скрытый расход; фильтровать до сути («262 passed, 0.08s»). В ядре это правило [[run-checks-quietly-in-background]] (фон + вердикты, не простыни).

## Сжатие контекста и передача между сессиями

- Алгоритм авто-сжатия выбрасывает «переоцениваемые» файлы и Tool Output — **вместе с архитектурными решениями и обоснованиями**. Противоядие — секция **Compact Instructions в CLAUDE.md** (что сохранять в приоритете: решения, изменённые файлы, статус верификации, открытые TODO). В ядре добавлена. Напоминание перечитать журналы после компакции подмешивает `SessionStart` с matcher `compact`: у события `PostCompact` обычный вывод до модели не доходит (сверка с документацией хуков, 19.09.2026).
- **HANDOFF-приём:** перед завершением длинной сессии/сменой контекста — записать «что сделано / что пробовали / что сработало-нет / следующий шаг». В ядре роль HANDOFF выполняет веха в [[work-journals-and-commits]] (worklog+changelog) — писать её ДО исчерпания контекста, не после.
- `/clear` при смене задачи, `/compact` при продолжении этапа; расход мониторить `/context`, не ждать автосжатия.

## Скиллы высокого риска и критерии завершения

- Скиллы-чеклисты перед рисковыми операциями (релиз: сборка чистая, версия поднята, **CHANGELOG/RELEASES обновлён**, smoke на чистом окружении) — в мастере ядра гейт-релиз `release-core` (правило мастера `release-core-after-milestone`) + запись в RELEASES.md обязана существовать до тега.
- Скиллы-процессы с побочными эффектами — `disable-model-invocation: true` (модель не запускает сама; только явный приказ) + шаги Backup → Dry run → Apply → Verify → **Rollback**.
- **Definition of done обязателен**: «если нельзя объяснить, как узнать, что сделано правильно — задача не для автоматизации». В ядре — [[full-checker-set-before-done]] (каждый чекер назван с результатом).
- Plan Mode: исследование отдельно от выполнения; практика «один агент пишет план, другой ревьюирует» — в ядре консилиум + состязательный критик ([[five-role-design-review]]).

## Паттерны наборов оркестрации (сверка с orchestrator-kit, MIT)

Разбор `github.com/maslennikov-ig/claude-code-orchestrator-kit` (14.07.2026, вердикт — [[external-mcp-servers-review]]) подтвердил курс ядра теми же выводами независимого автора: (1) **оркестратор делегирует, не делает сам** — у нас Workflow + субагенты по нужде в широте ([[subagents-on-explicit-consent]]); (2) их эволюция «тяжёлые агенты-оркестраторы → лёгкие inline-скиллы» (≈10K → ≈0.5K токенов на вызов) — мы сразу на inline-командах; (3) «85% context reduction — MCP-инструменты по требованию через ToolSearch» — в нашей среде это штатный deferred-механизм; (4) **профили MCP-конфигов по типу сессии** (минимальный/полный `.mcp.json`) — запасной приём для сред без deferred-загрузки: узкой задаче не нужны все серверы. Принятое к нам: типовые **оси здоровья** (bugs/dead-code/reuse/security/deps) как готовые фокусы `/audit`.

## Устройство самого харнесса Claude Code (разбор walkinglabs, 14.10.2026)

Второй внешний разбор того же предмета — `walkinglabs/learn-harness-engineering` (MIT), раздел «Frontier Harness Design Breakdowns» (вердикт по источнику — [[external-skills-review]], волна F). Ценность не в новизне, а в **рамке**: курс раскладывает харнесс на пять подсистем — **инструкции · состояние · верификация · границы · жизненный цикл** — и показывает, чем каждую закрывает сам Claude Code. Рамка годится как линза самооценки ядра: пустая подсистема заметна сразу.

Самое полезное одной строкой — **разделение ответственности слоёв**: `CLAUDE.md` отвечает на «ЧТО», скиллы — на «КАК», MCP — на «КУДА подключиться», хуки — на «КОГДА принудить». Отсюда рабочий тест при правке ядра: правило, которое формулируется как «всегда проверяй X синтаксически», лежит в слое `CLAUDE.md` **ошибочно** — его место в хуке ([[writing-for-agents]] п.8, [[capture-knowledge]] п.0б).

Факты о платформе из разбора (источник **вторичный** — курс опирается на офдоку и сторонний анализ исходников v2.1.88; зондом в ядре не проверялись, ставить в основание гейта нельзя — [[probe-tool-capabilities]]):

- **Четыре области инструкций** по возрастанию специфичности: политика организации → пользовательская `~/.claude/CLAUDE.md` → проектная `./CLAUDE.md` → локальная `./CLAUDE.local.md`. Более специфичная идёт в контексте **позже**, то есть **локальный файл перебивает проектный** — ловушка при отладке «почему правило не действует». У нас соответствующий класс дефекта уже ловится белым списком команд хуков и самозащитой настроек ([[rule-enforcement-map]]).
- **`CLAUDE.md` подкаталогов не грузится на старте** — подмешивается только при чтении файлов из этого каталога. Прямая реализация яруса 3 из [[writing-for-agents]].
- **Авто-память** (заметки, которые агент пишет себе) грузится с жёстким потолком — порядка **200 строк / 25 КБ за сессию**, и обрезается **молча**. Отсюда требование к индексу памяти: одна строка-зацепка на запись, детали — в файле записи; длинные абзацы в индексе вытесняют свежие записи незаметно.
- **Компакция — конвейер, а не «суммаризация при заполнении»**: сперва потери-без-потерь (выброс избыточных Tool Output), затем структурное сжатие, и лишь затем сжатие моделью, с предохранителями против пересжатия. Практический вывод для нас прежний: Tool Output — первая цель экономии ([[run-checks-quietly-in-background]]), а решения и обоснования защищаются разделом Compact Instructions.
- **История сессии — журнал на добавление** (`history.jsonl`) с восстановлением и ветвлением. Наш аналог durable-слоя — worklog и changelog ([[work-journals-and-commits]]): хэндофф пишется **до** исчерпания контекста, потому что на наш слой «воспроизведение из журнала» не распространяется.
- **Контекст субагента изолирован** (своя ветка истории, родительское окно не раздувается) — ровно то, на чём стоит ISOLATE в [[writing-for-agents]] п.7 и правило [[subagents-on-explicit-consent]].

Позиция курса, совпадающая с нашей практикой дословно: агенты «уверенно хвалят свою работу», поэтому проверку выносят в **детерминированные** хуки, а не в самооценку модели; `Stop`-хук существует именно как перехват момента «объявил готово». У нас это 7-й контур `stop-guard` плюс трёхслойный критерий завершения ([[full-checker-set-before-done]] п.11).

## Выводы статьи

1. Контекст — про качество, не объём: зашумленный хуже пустого. 2. Стадии зрелости: «как использовать» → «как сделать надёжно» → «как работает самостоятельно в рамках ограничений». 3. Критерии завершения обязательны. 4. Prompt Caching — основа: стабильный префикс = скорость и дешевизна (не перетасовывать резидентные слои без нужды).
