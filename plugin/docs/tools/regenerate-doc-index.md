# Правило: индексы и счётчики — генератором, атомарно с изменением состава

Состав ядра (доки, MCP-серверы, скиллы) продублирован индексами и счётчиками в нескольких местах. Единственный источник истины — **frontmatter доков** (`name`/`description`/`metadata.type`) и **факты** (`.mcp.json`, каталоги скиллов). Меняешь состав — **в той же правке запусти `tools/indexes/gen-doc-index.py`**: он пересобирает `docs/MEMORY.md`, индекс-блок `CLAUDE.md` (между маркерами `<!-- BEGIN:DOC-INDEX -->`/`<!-- END:DOC-INDEX -->`) и счётчики в `project-status`/`worklog` (строка «Текущий состав базы»)/`README`.

**Why:** счётчики дрейфовали неоднократно (серверы 7→8; доки-правила 16→18, 18→19; тул-доки 8→9), а описания правил расходились в 3-4 редакциях (CLAUDE-индекс vs CLAUDE-буллет vs MEMORY) — каждый раз ловил аудит, а не автор правки. Один факт жил в ≥5 местах руками; генератор сводит его к одному месту (frontmatter) по построению.

**How to apply:**
1. Добавил/удалил/переописал `docs/<тема>/<имя>.md` → проверь его frontmatter (`description` — каноничное описание; секция = тема (папка) по таблице `TOPICS` в `gen-doc-index.py`, внутри темы сначала правила (`metadata.type: feedback`), затем справочники (`reference`); новая тема — добавить строку в `TOPICS`, иначе она уйдёт в конец под именем папки) → **запусти `tools/indexes/gen-doc-index.py`** в той же правке.
2. Изменил `.mcp.json` или состав скиллов → тоже генератор (счётчики берёт фактом: длина `mcpServers`, число каталогов `.claude/skills`).
3. Вручную индексы **не** правишь; порядок строк генератор наследует из текущего `MEMORY.md` (новые доки — в конец секции; хочешь другой порядок — переставь строку в MEMORY один раз, генератор сохранит).
4. Курируемая проза остаётся ручной: буллеты «Правила работы (оперативные инварианты)» в `CLAUDE.md` (новому правилу — добавить однострочник), таблицы `README.md`.
5. Проверка — `tools/indexes/gen-doc-index.py --check` (0 = дрейфа нет; его же вызывает health-check, регресс — `contour-tests` §137) и health-check (ассерты счётчиков/секций остаются вторым барьером). Доки `docs-project/` в счётчики ядра не входят ([[project-knowledge-folder]]); маркеры `<!-- BEGIN:DOC-INDEX -->`/`<!-- END:DOC-INDEX -->` в `CLAUDE.md` руками не удалять.

Связано: [[capture-knowledge]], [[docs-match-reality]].
