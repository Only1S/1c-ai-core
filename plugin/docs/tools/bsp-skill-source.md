В `D:\dev_core\.claude\skills\` установлен **один** скилл **`bsp`** (источник: https://github.com/brake71/1c-ssl-skills, тег **`v0.15`** (09.10.2026, commit 4f7b728; перенос 16.10.2026), commit 5b5ea98 — это прежний v0.11; с v0.11 скилл в апстриме лежит в `skills/bsp`, а не в `.claude/skills/bsp`). Состав: `SKILL.md` (единый навигатор; **маркера версии в файлах скилла НЕТ** — во frontmatter только `name` и `description`, сверено 16.10.2026, а «3.1.11» в тексте означает целевую версию БСП, не версию скилла. Установленная версия определяется контент-сверкой с тегом апстрима: `git show <тег>:skills/bsp/SKILL.md`) + `references/` (24 файла) + `scripts/bsp_api.py`. Покрывает применение БСП **3.1.11** (методы общих модулей, фоновые задания, обмен, ЭП/МЧД, печать, файлы, доступ, мониторинг; границы стабильного vs внутреннего API).

**История:**
- **2026-06-30 (`v0.3` → `v0.4`):** в v0.3 было 4 раздельных скилла (`bsp-core`, `bsp-data`, `bsp-ops`, `bsp-ui-forms`) — в v0.4 они объединены в один самодостаточный `bsp`. Старые 4 папки удалены, поставлена одна `bsp`.
- **2026-10-16 (`v0.11` → `v0.15`):** зеркалирование `skills/bsp` тега v0.15 (27 файлов) из дерева тега, дерево клона на тот момент не трогалось (на 16.10.2026 оно уже грязное: 27 удалённых файлов и 2 изменённых — расхождение внесено в [[vendor-patch-registry]], граница правила расширена на клоны вне `tools/`), извлечение шло через `git archive`, и так же сделан перенос v0.15; прежняя формулировка «рабочее дерево клона не трогалось» как утверждение о ТЕКУЩЕМ состоянии неверна. `SKILL.md` апстрим переписал радикально: роутер стал ASCII-английским, русские discovery-подсказки ушли внутрь `description` в JSON-экранировании, и появились явные АНТИ-триггеры («Pure BSL, existing form element properties, or explicitly platform-only exchange -> answer without opening this skill») — это меняет вероятность активации скилла на русских формулировках, и для правила [[use-skills-not-manual-edits]] важно, что решение «открывать или нет» теперь подсказывает сам апстрим. Вендор-патч `bsp_api.py` переналожен трёхсторонним слиянием (база — тег v0.11): апстрим сам файл не менял, **оба дефекта на месте** — `"Экспорт" in stripped` подстрокой и единственная раскладка `entry/"Ext"/"Module.bsl"`.
- **2026-09-18 (`v0.5` → `v0.11`):** зеркалирование `skills/bsp` тега v0.11 (27 файлов, новый `agents/openai.yaml`), рабочее дерево клона не трогалось (извлечение через `git archive`).
- **2026-07-07 (`v0.4` → `v0.5`):** обновление контента (структура прежняя — 24 reference + `bsp_api.py`, БСП 3.1.11). Клон `D:\dev_core\1c-ssl-skills` переключён на тег `v0.5`, скилл пересинхронизирован в `.claude/skills/bsp` (с 16.10.2026 клон лежит в `D:\dev_core\tools\1c-ssl-skills`).

Важно:
- **Устарел README рабочей копии клона, а не апстрима:** клон `tools/1c-ssl-skills` стоит на v0.5, и его README описывает раскладку 4 папок/v0.2; README тега v0.15 свежий (БСП 3.1.11, штатные установщики `install.sh`/`install.ps1` + ZIP с `skills/bsp/`). Наш маршрут остаётся «дерево тега через `git archive`» — он не трогает рабочее дерево клона и не тянет чужой установщик; текущий скилл зеркалирован **из дерева тега v0.15** (16.10.2026), не по README.
- `agents-best-practices` в репозитории — пустой плейсхолдер (файлов нет), не ставился.
- `scripts/bsp_api.py` — python-валидатор сигнатур по выгрузке конфигурации. Python в среде **есть** (3.14.6, зонд 18.09.2026; прежняя запись «python нет, заглушка MS Store» устарела), но у скрипта v0.5 три подтверждённых дефекта (аудит 18.09.2026, воспроизведено на синтетическом модуле): (1) конец метода ищется по `"Конец" + keyword` → «КонецФункция»/«КонецПроцедура», таких слов в BSL нет (`КонецФункции`/`КонецПроцедуры`), и сканирование уходит за границу метода; (2) экспорт определяется подстрокой `"Экспорт" in …` — в экспортные попадают методы со словом «Экспорт» в комментарии; (3) модули ищутся только по раскладке Конфигуратора `CommonModules/<имя>/Ext/Module.bsl` — на EDT-исходниках (`src/CommonModules/<имя>/Module.bsl`) не находится ни одного. Источник фактов из [[task-recipes]] §20 (`D:\1c-bsp-src`) на машине отсутствует. Итог: выводу скрипта не доверять; скилл используется как markdown-справочник, сигнатуры — через `code-index`/`edt-mcp` по исходникам проекта.
- **Обновлено до v0.11 (18.09.2026):** апстрим исправил дефект (1) (`end_keyword` → `КонецФункции`/`КонецПроцедуры`), в `SKILL.md` добавлен обязательный «Порядок работы» и `rg` вместо `grep` (ripgrep 14.1.1 в среде есть). Дефекты (2) и (3) в v0.11 **остались** — закрыты нашим вендор-патчем `bsp_api.py` ([[vendor-patch-registry]]): «Экспорт» ищется как ключевое слово вне `//`-комментария, модуль находится и в раскладке EDT. Зонд на синтетическом модуле: v0.5 и v0.11 — 4 «экспортных» метода из 2 настоящих и EDT-модуль не найден; с патчем — 2 из 2 в обеих раскладках. **Граница патча (замер 29.10.2026):** слово «Экспорт» в строковом литерале всё ещё делает метод экспортным — `_has_export` пропускает в разбор и символы внутри кавычек, а сбор сигнатуры, если в строке объявления «Экспорт» нет, продолжается в тело метода (так у апстрима); метод вида `Процедура Текст()` с телом `Т = "Экспорт";` попадает в экспортные. Редко, но выводу о «экспортности» такого метода не верить.
- **Наши правки скилла — полный список в реестре [[vendor-patches]]:** `bsp_api.py` (а) раскладка EDT и (б) «Экспорт» вне комментария (с 18.09.2026), (в) приставка «Асинх» у объявления (чекап 17.10.2026, `tools/patches/checkup-1017-other.py`); `description` в `SKILL.md` — развёрнут из JSON-экранирования в UTF-8 (v0.15 давал 1309 знаков при пределе 1024) и затем переписан по-русски (ревизия Р-36, 16.10.2026). База слияния всех правок — тег v0.15.
- **Версия БСП в `epf-bsp-init`:** шаблон параметризован `{{ВерсияБСП}}` (вендор-патч Р-26, 16.10.2026; до него было жёсткое `"2.2.2.1"`); `bsp` (`references/commands-external.md`) даёт пример `("3.1.11.0")`. Аргумент — версия БСП целевой конфигурации (`ОбновлениеИнформационнойБазыБСП.ПриДобавленииПодсистемы`, `Описание.Версия`), смотреть через `code-index`/`edt-mcp`.
- Новый скилл подхватывается **после перезапуска Claude Code** (скиллы читаются при старте сессии).

Стандарты 1С — через [[v8std-mcp-server]]; API платформы — через MCP `bsl-platform` ([[installed-tools-and-servers]]); машинный линтер BSL — `bsl-analyzer` ([[installed-tools-and-servers]]).
