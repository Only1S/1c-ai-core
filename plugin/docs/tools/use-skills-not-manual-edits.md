# Правило: скиллы — обязательный путь исполнения

Скиллы — не «доступная опция», а **штатный исполнительный слой** ядра. Если под операцию есть скилл — операция выполняется **через скилл**. Ручная правка XML/`.bsl`/офисных файлов в обход скилла — нарушение гейта, а не «более быстрый способ».

**Why:** скилл несёт три вещи, которых нет у ручной правки: (1) **знание схемы** — правильные теги, порядок, UUID, обязательные секции (руками это воспроизводится по памяти, то есть с ошибками); (2) **валидатор** — почти у каждого генератора есть парный `*-validate`, то есть артефакт проверяется сразу, а не «потом чекерами»; (3) **воспроизводимость** — вызов скилла виден в следе и повторяем, ручная правка — нет. Ручной путь систематически даёт ошибки, которые скилл не допускает по построению, а «сэкономленные» на нём токены возвращаются кратно на отладке. Это прямое продолжение [[work-through-tools]] п.2 («нулевой ручной факт») в сторону «нулевого ручного артефакта».

Ось этого правила — **скилл против ручной работы**. Ортогональная ось — **источник скилла** (локальный ↔ внешний): её задаёт [[allowed-skill-sources]] (локальные первыми, внешние — только санкционированные). Два правила складываются.

**How to apply:**
1. **Сначала — есть ли скилл.** Перед любой операцией над артефактом 1С или деловым документом сверься со списком скиллов. Если скилл есть — маршрут идёт через него. Какой именно скилл брать при выборе локальный/внешний — [[allowed-skill-sources]].
2. **Карта юрисдикций** покрывает **локальные** скиллы ядра (в мастере — `.claude/skills/`, в проекте — скиллы плагина `ones-core:*`) **и** санкционированные внешние ([[allowed-skill-sources]] — офисные `docx`/`xlsx`/`pptx`/`pdf`, `engineering:architecture`); внешние помечены как таковые (**⧉**). Карта не закрытая — правило распространяется на все скиллы ядра. Пометки: **⛔** — `disable-model-invocation: true`, скилл **не вызывается моделью самостоятельно**, только по явной просьбе пользователя; **⚠** — необратимая операция над базой, обязателен цикл из п. 9; **⧉** — внешний плагинный скилл (не скилл ядра), санкционированный белым списком [[allowed-skill-sources]], его доступность проверяется зондом ([[probe-tool-capabilities]]), иначе — локальная замена или фолбэк.

3. **Изучение — тоже через скилл.** Понять объект/форму/роль/СКД — это `*-info`, а не чтение сырого XML глазами. Сырой XML читается только когда `*-info` не покрывает нужный срез, и это сказано вслух.
4. **Генератор → его валидатор, в той же правке.** Породил артефакт скиллом-генератором — прогони парный `*-validate`. Хук `validate-bsl.py` ловит только Write/Edit по `.bsl`; артефакты скиллов он **не видит** — валидатор здесь единственный барьер ([[enforcement-hooks]]в).
5. **Правило подпёрто барьером, а не только текстом (8-й контур).** С 03.08.2026 ручная правка артефакта 1С через Write/Edit **отклоняется до исполнения** хуком `plugin/hooks/guard-skills.py` (`PreToolUse`, matcher `Write|Edit`): `Form.form`/`Form.xml`, `*.mdo`, `Rights.rights`/`Rights.xml`, `*.dcs`, `*.mxl`, `Configuration.mdo|xml`, `CommandInterface.*` → отказ с указанием маршрута; с 18.09.2026 ещё `Ext/Template.xml`, `Ext/Package.bin`, `*.xdto`, с 30.10.2026 — обычные формы `form.frm` и `Ext/Form.bin` (маршрут — `form-ordinary`, модуль прочитать — `form-bin-module`) и все оставшиеся виды объектов выгрузки: `CommonAttributes`, `CommonPictures`, а ещё `StyleItems`, `IntegrationServices`, `Bots`, `PaletteColors`, `WebSocketClients`, `Interfaces` — их `meta-compile` не создаёт, поэтому там ручная правка возможна названным исключением (п.6), — и маршрут зависит от формата: EDT-файлы (`.mdo`, `.form`, `.rights`, `.cmi`, `.dcs`, `.mxl`, `.xdto`) ведут в `edt-mcp` (скрипты скиллов этих семейств читают только XML-выгрузку Конфигуратора), подсистемы выгрузки — в `subsystem-*`, командный интерфейс выгрузки — в `interface-edit`. До этого правило было **совещательным** — жило в тексте хука-напоминания, и «быстрее дописать XML руками» проходило без единого барьера (`validate-bsl` видит только `.bsl`, п.4). Границы барьера сознательные: `.bsl` пропускается (свой контур), служебные зоны (`.claude/`, `docs/`, `docs-project/`, `tools/`, scratchpad) исключены — там **примеры** внутри скиллов и вендорные клоны; правка через Bash (perl/python) не ловится — байтобезопасная правка `.form` остаётся штатной крайней мерой ([[edt-mcp-pitfalls]]). Регресс — `tools/checks/contour-tests.py` §9 (блоки, проверки маршрута и пропуски — списки `SKILL_DENY`, `SKILL_ROUTE` и случаи пропуска там же), живость — `health-check` 1b. Полная раскладка контуров — [[enforcement-hooks]].
6. **Обход — только named exception.** Ручной путь допустим, когда скилл проверенно не покрывает случай (зондом, не по памяти — [[probe-tool-capabilities]]). Тогда в ответе явно: «скилл `X` не покрывает Y (проверено: …) → делаю вручную». Молчаливый обход = нарушение.
7. **Субагенты — под тем же правилом.** Веерным агентам в промпте задаётся тот же мандат: анализ и правки — через скиллы, а не ручным чтением/записью файлов.
8. **След.** Задействованные скиллы перечисляются в следе инструментов наравне с MCP-серверами ([[work-through-tools]] п.7).
8а. **Свой скилл сверяется с правилами ядра — при создании и при каждой правке** (с 05.10.2026; идея сквозных принципов — по мотивам `rebelytics/one-skill-to-rule-them-all`, CC BY 4.0, пересказ). Чек-лист на семь позиций; вендорные скиллы под него не подпадают — их ведёт апстрим:
   1. **Контракт `SKILL.md`**: `name` = имя папки, `[a-z0-9-]`, `description` до 1024 символов и с русскими триггерами — иначе скилл не вызовется по смыслу (ассерт в `health-check`).
   2. **Место в карте юрисдикций** (п.2 выше): скилл без строки в карте для меня не существует. Обратная сторона проверяется ассертом: имя в карте без скилла на диске — `Bad` в `health-check` (мёртвая ссылка после переименования апстримом).
   3. **Язык**: комментарии и тексты для владельца по-русски, код и имена — по языковому профилю ([[language-profile]]).
   4. **Проверка результата**: у генератора — парный валидатор; у читающего скилла — раздел «Проверка результата» с кодом возврата и тем, что считается зелёным.
   5. **Границы вслух**: раздел «Ограничения» — что скилл НЕ делает и что не проверено ([[docs-match-reality]]).
   6. **Деструктивность**: операция сносит данные или правит поставщика — режим из п.9 (⛔ или ⚠-цикл), плюс строка в `guard-destructive`, если скрипт запускается напрямую.
   7. **Происхождение**: порт или заимствование — лицензия и атрибуция в шапке скрипта и строкой в `THIRD-PARTY.md`.
   Скрипты скилла — самолокующиеся, `.ps1` с кириллицей — UTF-8 с BOM ([[designer-batch-runs]]).
9. **Разрушительные скиллы — отдельный режим.** «Скилл обязателен» не значит «скилл автоматичен»: там, где операция необратима, барьер стоит **до** исполнения.
   - **Только по явной просьбе пользователя (⛔ `disable-model-invocation: true`).** `meta-remove` (удаление объекта метаданных) и `support-edit` (снятие с поддержки) необратимы и не оставляют бэкапа — модель **не вызывает их сама** ни по своей инициативе, ни «по смыслу задачи». Тем же флагом закрыты вендорные `meta-decompile`, `form-decompile`, `form-remove`, `skd-decompile`, `template-remove`, `db-load-dt`.
   - **Обязательный цикл (⚠).** `db-load-cf` и `db-update` остаются вызываемыми моделью (иначе рвётся маршрут «через скилл»), `db-load-dt` вдобавок закрыт флагом ⛔ (вендорный дефолт — полная перезапись базы с данными). Во все три вшит и **исполняется целиком** цикл: **бэкап** (`db-dump-dt` / `db-dump-cf`) → **проверка целевой базы** по `.v8-project.json` → **сухой прогон** (что и где будет перезаписано) → **явное подтверждение пользователя окном вариантов** ([[ask-before-changing]], [[questions-as-options]]) → **применение** → **проверка полным сетом чекеров** ([[full-checker-set-before-done]]) → **путь отката**. У `db-cfe-admin` цикл касается только меняющих подкоманд (`set-properties`, `delete`; ослабление `SafeMode`/`UnsafeActionProtection` называется в подтверждении отдельно), `list`/`check` — чтение. У `db-repo` подтверждение окном вариантов добавлено к вендорному списку для `commit` (помещение видно всей команде) и захвата, не следующего прямо из просьбы; пароль хранилища — из окружения, не в `.v8-project.json`. У `db-load-xml`/`db-load-git` цикл обязателен для полной загрузки и для `-UpdateDB` (реструктуризация базы — тот же необратимый шаг, что `db-update`); частичная загрузка без `-UpdateDB` откатывается повторной загрузкой, для неё обязательна только проверка целевой базы. Вендорная строка «параметры подключения, указанные пользователем, — используй напрямую» во всех семи пишущих скиллах заменена на «только если база есть в `.v8-project.json`».
   - **Целевая база обязана быть зарегистрирована в `.v8-project.json`; незарегистрированная считается боевой ([[secrets-and-production-database]]) — не трогать.** То же требование продублировано ДО-исполнительным барьером (хук `guard-destructive.py`, 6-й контур): с 18.09.2026 он сверяет с реестром и базу исполняемых скриптов `db-*` (имя в кавычках, путь файловой базы), а прямой запуск скриптов ⛔-скиллов встречает отказ (с 14.10.2026, прежде был `ask`) — флаг `disable-model-invocation` закрывает только инструмент Skill, не Bash; команду выполняет владелец сам. Скилл на хук не полагается: проверка идёт и на его стороне.
   - Правки этих скиллов — **вендорные** (`cc-1c-skills`): при обновлении инструмента они исчезнут. Переналожить по реестру [[vendor-patch-registry]].

**Парный валидатор принуждается (с 17.10.2026):** после скрипта скилла-генератора (`meta-compile`, `form-edit`, `role-compile`, `skd-edit` и др.) блокирующий гейт конца хода в `stop-guard` не даёт закончить ход без запуска парного `*-validate` позже в том же ходе ([[full-checker-set-before-done]], регресс `contour-tests` §8c).
