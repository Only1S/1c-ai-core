# Правило: индекс code-index — вне EDT-проекта

Артефакт индекса (`.code-index\index.db`, в реальном проекте десятки–сотни МБ) **не хранить внутри EDT-проекта / выгрузки `src`**. Он должен лежать в **папке проекта Claude Code** — `<проект>\.code-index`, а в `src` остаётся только ссылка.

**Why:** бинарный индекс в дереве исходников пачкает выгрузку: попадает под git, виден EDT, раздувает бэкапы и синхронизацию. Штатной опции переноса у индексатора **нет** (проверено по `--help`: ни у `index`, ни у `serve`/`stats` нет флага релокации каталога индекса, а `.code-index\config.json` содержит лишь фильтры и лимиты — `exclude_dirs`, `max_files`, `languages`, `storage_mode`). Единственный рабочий способ — **directory junction**; проверено эмпирически: база ложится во внешний каталог, `index` и `stats` работают через ссылку прозрачно.

**How to apply:**

**С плагином ones-core (с 4.1.0, ADR-0006):**
- Каталог индекса — `<проект>\.code-index`; в выгрузке — ссылка `<выгрузка>\.code-index` на него. Ссылку и запись выгрузки в списке индексатора делает `/ones-core:setup` (скрипт `tools/setup/code-index-daemon.py add`); выгрузку с уже существующей ссылкой в другое место или со своей папкой индекса он не трогает. У проекта с несколькими выгрузками у каждой своя папка — `<проект>\.code-index\<алиас>` (`add --index-dir`). Сначала ставится ссылка, потом выгрузка попадает в список: индексатор, увидевший выгрузку без ссылки, сразу заводит индекс внутри исходников.
- Индекс строит и обновляет **общий фоновый индексатор**: один на машину, `CODE_INDEX_HOME` = `<папка данных плагина>/code-index` (там `daemon.toml` со списком выгрузок и `daemon.json`). Серверу `code-index` плагина эта папка передаётся в `.mcp.json` (`env`). Без запущенного индексатора `serve` на запросы отвечает `daemon_offline`, даже если `index.db` есть (проба 16.10.2026; документация code-index-mcp). Запуск — `code-index-daemon.py start`, автозапуск при входе в Windows — `autostart on` (папка «Автозагрузка» пользователя, по согласию владельца), состояние — `status`. Убрать выгрузку — `remove --src` (с 4.2.1): убирает из списка и перезапускает индексатор, потому что `reload` не отпускает файл индекса убранной выгрузки; ссылка и индекс остаются. Остановка — `stop`, она ждёт выхода процесса: сама команда `daemon stop` возвращается раньше (зонд 17.10.2026: процесс живёт ещё около 7 с).
- **Писатель индекса — один.** Выгрузку, которую ведёт другой запущенный индексатор (прежней копии ядра), `add` не добавляет (код 3): сначала тот индексатор останавливается, его автозапуск снимается, индекс переносится в `<проект>\.code-index`.

**Общие приёмы с индексом:**
1. В `.gitignore` репозитория исходников добавить `.code-index/`; в EDT пометить как исключённый ресурс (в `src` физически остаётся лишь reparse-point). **Как именно** — фильтр ресурсов в `.project` **каждого** проекта воркспейса (основная конфигурация и каждое расширение), внутри `<projectDescription>`:
   ```xml
   <filteredResources>
     <filter>
       <id>1</id>
       <name></name>
       <type>26</type>
       <matcher>
         <id>org.eclipse.ui.ide.multiFilter</id>
         <arguments>1.0-name-matches-false-false-.code-index</arguments>
       </matcher>
     </filter>
   </filteredResources>
   ```
   `type` 26 = EXCLUDE_ALL (2) | FOLDERS (8) | INHERITABLE (16): папка с этим именем исключается на любой глубине. `.project` перед правкой — в бэкап; фильтры читаются при **открытии** проекта → закрыть и открыть проект (или перезапустить EDT). Проверено в одном из экземпляров, где индекс лежал в `src` физически; **поверх junction — не проверено**. Гипотезу «`index.db` держит updateState EDT» не переносить — экземпляр сам её опроверг.
2. Перед перемещением или удалением выгрузки — остановить индексатор: `code-index-daemon.py stop` (ждёт выхода процесса: индексатор держит файлы открытыми) или убрать выгрузку из его списка — `remove --src` (с перезапуском, иначе файл индекса остаётся занят).
3. **Worktree/копия `src` с junction внутри.** Зонд на Git for Windows 2.54: `git worktree remove` в junction не заходит (цель — индекс проекта — цела), но и саму ссылку не снимает: регистрация worktree и файлы исчезают, а каталог с junction остаётся, код возврата 0. Снимать только ссылку: `rmdir "<путь>\.code-index"` **без `/S`** (зонд: ссылка ушла, цель цела). Прочие грабли удаления worktree — [[config-git-forks-and-merges]].

> Сам `code-index` — read-only по отношению к коду: он ничего не переписывает в исходниках, единственная его запись — этот индекс. Риск не в порче конфигурации, а в замусоривании проекта.

**Принуждение (с 4.7.0):** проверка при старте сессии в проекте — `plugin/hooks/session-start.py`: индекс настоящей папкой внутри `ONEC_PROJECT_SRC` вместо ссылки — предупреждение модели; регресс `contour-tests` §24а.
