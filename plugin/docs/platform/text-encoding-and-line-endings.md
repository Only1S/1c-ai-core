# Правило: кодировка и переводы строк — одни на весь проект

1. **Кодировка — UTF-8.** BOM обязателен только у `.ps1`: без него PowerShell 5.1 читает кириллицу как ANSI, скрипт падает на разборе, а хук молча перестаёт работать. У остальных файлов BOM сохраняется таким, каким был.
2. **Переводы строк определяет тип файла:** `.cmd`, `.bat`, `.vbs` — CRLF (у `cmd.exe` в файлах с LF ломаются метки и `goto`); всё остальное — LF. Так и в репозитории, и в рабочей папке, на любой машине — независимо от настройки `core.autocrlf`.
2а. **Исходники и выгрузки 1С** (`.bsl`, `.xml`, `.mdo`, `.form`, `.dcs`, `.mxl` и др.) — **байт в байт, без преобразований** (`-text` в `.gitattributes`). Платформа и EDT пишут их по-своему, и в репозиториях конфигураций они бывают сохранены с CRLF: перекодировка дала бы изменение всей конфигурации разом. Проверка переводов строк их пропускает.
3. **Правило задают два файла в корне:** `.gitattributes` (для git) и `.editorconfig` (для редакторов). Вручную переводы строк не конвертировать.
4. **Файлы из скриптов пишутся через `tools/lib/textio.py`:** `read` / `write` / `replace` сохраняют BOM и ставят положенный перевод строк, а `replace` падает, если заменяемый фрагмент найден не ровно столько раз, сколько ожидалось. Привести готовый файл: `python tools/lib/textio.py <файл>`.
5. **Стережёт `health-check`** (раздел 5d): нет `.gitattributes` или отслеживаемый файл не по правилу — FAIL с именем файла и командой исправления.
6. **Обратный слэш в тексте, который я передаю в инструменты, не пишу.** При передаче двойной обратный слэш схлопывается в одинарный, а дальше `\n`, `\t`, `\b` становятся переводом строки, табуляцией, управляющим байтом. Так за неделю испорчены `tools-folder-map.md`, `RELEASES.md`, `changelog.md` и два скрипта — седьмой раз 16.10.2026, когда разорвалась строка журнала. В коде путь собирается `os.path.join` / `Join-Path`, обратный слэш — `chr(92)`; в прозе — словами («обратный слэш + n»). Разорванную строку журнала ловит `health-check` (раздел 5e).

**Why:** до 16.10.2026 рабочая папка мастера была смесью — 591 файл с LF, 62 с CRLF, 6 со смешанными строками — при том что в самом репозитории все 659 текстовых файлов хранились с LF. Каждая запись файла давала предупреждения git «LF will be replaced by CRLF», журналы экземпляров получали строки с разными переводами (вставка по разбиению строк промахивалась), а проверки, сравнивающие текст, были вынуждены угадывать стиль. Причина — сразу три источника: `core.autocrlf` на машине, PowerShell и мои Python-вставки писали каждый по-своему.

**How to apply:** новый или изменяемый текстовый файл из скрипта — только через `textio`. Увидел FAIL раздела 5d — `python tools/lib/textio.py <файл>`, затем коммит. Побайтовое извлечение файлов из git — по [[designer-batch-runs]] п.11. Скрипты ядра постепенно переходят на Python (решение мастера ADR-0002) — тогда пункт про BOM у `.ps1` уходит вместе с PowerShell.
