# Правило: сперва макет мода в окне, потом код

Распоряжение владельца 31.10.2026: «Перед тем как создавать моды, сделай это в окне claude code desktop как на скрине, покажи что где как будет выглядеть. А потом делай».

**Why:** строка над полем и след хода вышли без макета и на Desktop оказались обрезанными, с сырой разметкой в тексте; владелец увидел это только в работе. Макет дешевле переделки: за один разговор он дал иное решение, чем задумывалось в коде, — панель сбоку вместо строки в чате.

**How to apply:**
1. **Когда:** новый мод или правка того, что мод показывает (строка, панель, кнопка, уведомление, текст в чате). Исправление без видимых изменений макета не требует — так прошла починка запуска python в issue №1.
2. **Что показать:** окно целиком, как на Desktop: боковая колонка, чат, поле ввода, строка под ним. Тексты элементов — настоящие, из кода или снимка экрана. Инструмент — `show_widget` (сервер `visualize`), прямо в чате.
3. **Что назвать словами:** что в макете точно, что показано для примера, что не проверено. Несколько вариантов — кнопками над окном, а не отдельными картинками.
4. **Место подтверждается живьём.** Где окно поставит панель, решает само окно, а типы движка говорят только «сбоку или над полем». Пока место важно, собирается пробный мод вне репозитория (скилл `plugin-authoring`), и владелец смотрит его в настоящем окне.
5. **Код — после согласования макета**, ответ на вопрос о макете — не команда начинать: работает [[ask-before-changing]] п.6а. Новое пожелание владельца — новый макет, затем снова согласование.
6. Обязательный вид окна на других поверхностях проверяется по типам: строка над полем есть только в Desktop и терминале, в VS Code и на телефоне её нет.

**Чем принуждается:** напоминанием каждого хода (`plugin/hooks/tools-gate.md`). Автоматической проверки нет: вызов `show_widget` не доказывает, что макет согласован, а правки модов идут только в мастере.

Связано: [[ask-before-changing]], [[human-texts-start-with-action]], [[requirements-by-interview]].
