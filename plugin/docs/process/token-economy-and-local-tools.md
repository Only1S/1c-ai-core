# Правило: экономия токенов и приоритет локальных MCP

Работать максимально экономно по токенам и в первую очередь опираться на инструменты, уже подключённые к проекту (локальные MCP-серверы и скиллы), а не на веб-поиск, догадки или сплошное чтение файлов.

> ⚠️ **Граница правила (уточнение пользователя, 11.07.2026):** экономия = **не транжирить впустую** (сжатие, точечные чтения, без дублей-вызовов), а НЕ причина ошибаться. **При разработке 1С корректность-через-инструменты важнее экономии:** глубокое обдумывание (вплоть до целого проекта) и согласование каждого решения **со всеми инструментами стека** (стандарты/БСП/API/код/метаданные/формы/база — карта [[task-recipes]] §0) — легитимная и обязательная трата токенов; пропуск проверки или «мелкое» обдумывание экономией не оправдываются. Гейт — [[work-through-tools]] пп. 3–4.

**Why:** пользователь требует очень малого расхода токенов и максимальной опоры на подключённый инструментарий; локальные MCP дают точные факты дёшево.

**How to apply:**
1. Прежде чем читать большие файлы или искать в вебе — задать точечный вопрос локальному MCP/скиллу:
   - код (функции, вызовы, impact, поиск) → `code-index`;
   - API платформы / валидация BSL / стандарты → `bsl-platform`, `bsl-context`, `v8std`;
   - метаданные / модули / формы / YAXUnit в живом EDT → `edt-mcp`;
   - данные и метаданные живой базы → `1c-toolkit`;
   - применение БСП и проверка по стандартам → скиллы `bsp`, `1c-standards`.
2. Файлы читать точечно (offset/limit, Grep), не целиком; не перечитывать прочитанное.
3. Отвечать кратко и по делу; не дублировать сказанное, не расписывать неиспользуемые варианты.
4. Вееры субагентов/Workflow дорогие; когда они уместны и с чьего согласия — [[subagents-on-explicit-consent]]. Иначе — solo и локальные инструменты.
5. Дорогие внешние вызовы (WebSearch/WebFetch, большие дампы) — по необходимости, не по умолчанию.
6. **Длинный вывод команд в проектах сжимает мод** (с 05.11.2026): вывод `Bash`/`PowerShell` длиннее 8000 знаков приходит выжимкой, полный текст — в `logs/output-NN.txt` ([[plugin-in-project]], «Выжимка длинного вывода»). Нужна строка, которой нет в выжимке, — прочитай полный файл частями, а не перезапускай команду.

## Headroom — сжатие контекста (через MCP-инструменты)

На машине установлен **headroom** (`D:\tools\uv\bin\headroom.exe`, через uv + собственный Python 3.13; версию смотреть `headroom --version`, а не в этом тексте) — сжимает контекст (вывод инструментов, файлы, историю) на 60–95%.
- ⚠️ **Прозрачное автосжатие через прокси в этой связке НЕ работает.** Прокси запущен (`127.0.0.1:8787`, health 200), но Claude Code на подписке (OAuth) ходит напрямую на `api.anthropic.com` и перебивает `ANTHROPIC_BASE_URL` из `settings.json` — трафик идёт мимо прокси (`headroom savings` = 0). Прокси-путь рассчитан на API-ключ, не на OAuth.
- **Использовать MCP-инструменты** (подключены, работают независимо от маршрутизации): `headroom_compress` (сжать большой фрагмент), `headroom_retrieve` (развернуть по маркеру), `headroom_stats`. Сервер `headroom` (= `headroom mcp serve`) прописан в `.mcp.json`.
- Команды: `headroom doctor` (статус), `headroom savings` (экономия), `headroom dashboard` (веб-панель).
- Путь к программе задаёт переменная `HEADROOM_EXE`: в плагине (`plugin/.mcp.json`) без неё берётся `headroom` из `PATH`, в мастере (`.mcp.json`) — `D:\tools\uv\bin\headroom.exe`. Программы на машине нет — сервер `headroom` просто не поднимется, остальное работает.

**Замеренная ловушка: сырой ответ инструмента бывает ХУЖЕ grep.** Проверено 19.08.2026 на корпусе БСП (8667 файлов): один и тот же запрос по 11 функциям дал **24 633 симв.** в виде `query --json` (он тянет ТЕЛА функций), **5 442** сырым `grep` и **396** в виде выжимки «имя + сигнатура + строки». Неаккуратный вызов индекса вышел в 4,5 раза дороже grep, аккуратный — в 14 раз дешевле. Отсюда практика: **сначала выжимка, тело — отдельным адресным запросом** (`get_function` по точному имени), а не «возьму всё и разберусь». Правило «факт — инструментом» ([[work-through-tools]] п.2) обязывает добыть факт вызовом, но не обязывает тащить в контекст всё, что инструмент готов отдать. Тот же принцип лежит в основе 9-го контура `enrich-code-facts` (отдаёт выжимку, не тела) и в чужом `rlm-tools-bsl` ([[external-mcp-servers-review]], волна 19.08.2026).

**Принуждение (с 4.8.0):** проверка после факта по п.2 — файл прочитан сплошняком (ответ `Read` больше 100 КБ текста): `stop-guard` пишет срабатывание в `logs/answer-check.jsonl`, `answer-feedback` показывает его модели в начале следующего хода. Регресс — `contour-tests` §25. Граница: `Read` без `offset`/`limit` и без `allow_large` Claude Code сам отклоняет раньше порога (по умолчанию предел ответа ~25 тыс. токенов — меньше 100 КБ кириллицы и кода), поэтому на деле детектор ловит только чтение с `allow_large`; от сплошного чтения обычного крупного файла защищает сам предел Claude Code. Повторное чтение не судится (решение владельца 18.10.2026): неизменённый файл второй раз Claude Code не отдаёт сам («Wasted call»), а файл, изменённый скриптом, перечитать законно. Выбор локального MCP вместо веба и краткость ответа не проверяются.
