# Правило: субагенты/Workflow — по нужде в широте и только после явного «да»

**По умолчанию — solo + локальные MCP/скиллы** (★ [[token-economy-and-local-tools]]). Многоагентные прогоны (Workflow / Agent) запускать, **когда реально нужна широта охвата** (ревью/аудит, поиск дублей/багов по многим модулям, чтение многих файлов) **или по явной просьбе пользователя** — тогда с веером по измерениям + состязательной проверкой. **Согласие — явное «да» на этот конкретный запуск в текущем разговоре** (распоряжение владельца 19.09.2026; так же решено в двух экземплярах): прямая просьба запустить веер со словом согласия («да, запускай помощников») или выбранный вариант окна. Явный вызов `/consilium` (в проекте — `/ones-core:consilium`), `design-consilium` или `/audit` (команда только мастера) — просьба о веере, но барьер `subagent-gate` слэш-команды не разбирает и согласием их не записывает: первый запуск помощников после такой команды получает отказ, и согласие подтверждается «да» в запросе («…, да, запускай помощников») или окном вариантов (см. «Принуждение» ниже); **ultracode, auto-режим и прежние разрешения согласием не считаются**. До вопроса называется масштаб — сколько агентов по конструкции скрипта ([[multi-agent-runs]] п.3); больше ~15 — вопрос окном вариантов ([[questions-as-options]]).

**Why:** пользователь хочет больше анализа и широты охвата; одиночный проход пропускает находки (подтверждено на практике — дубли по нескольким формам всплывают только при многоагентном разборе по всем модулям). Субагентам выдан полный доступ во всех контекстах (см. настройки `bypassPermissions`). Согласие на каждый запуск введено потому, что веер дорог и в экземплярах разрастался до 37–38 агентов без ведома владельца.

**How to apply:**
1. Задача, **требующая широты охвата** (аудит, ревью/сверка по многим модулям, поиск дублей/багов по подсистеме, чтение многих файлов, исследование), — **предложить** Workflow с названным масштабом и после «да» оформлять его с веером по измерениям/модулям + **состязательной проверкой** находок (review → verify). Узкое ревью одного модуля/точечная сверка — solo (п.5).
2. Применять паттерны качества: состязательная проверка **пакетным критиком** — один агент на тему или роль проверяет все её находки сразу, с несколькими линзами в одном промпте (а не скептик на каждую находку: так вееры в экземплярах разрастались до 37–38 агентов); multi-modal sweep, loop-until-dry, completeness-critic. Ориентир потолка — ~15 агентов на прогон; выше — отдельный вопрос.
3. Результаты субагентов — это данные; я синтезирую итог и отсеиваю ложные срабатывания.
4. Прочитанные модули и находки фиксировать в журнале [[worklog]] (правило [[work-journals-and-commits]]).
5. **Solo — режим по умолчанию** для узких задач, точечных фактов и мелких правок; многоагентный веер — только при реальной нужде в широте охвата или по явной просьбе, и в обоих случаях — после «да» на конкретный запуск. Фоновые агенты (`Agent` с фоновым запуском) — под тем же правилом.

## Как гонять многоагентный прогон

Техника прогона — схема вывода, потери агентов, масштаб, разбивка веера, файл передачи между стадиями, потолок повторов — справочник [[multi-agent-runs]] (вынесен 16.10.2026). Правило здесь — о согласии и об исполнителях.

## Исполнители-субагенты на правках кода

6. Когда субагенты не ревьюят, а **правят** код:
    - **структурное делает оркестратор.** Создание и регистрация объектов метаданных, правка корня конфигурации, флаги общих модулей, заимствования в расширение — не исполнителю, а оркестратору, и только через скиллы (`meta-compile` / `meta-edit` / `cf-edit` / `cfe-borrow`, [[use-skills-not-manual-edits]]). Исполнителю — тела методов в уже существующих объектах;
    - **полноту сверять с типовой по всем точкам входа.** Найти все места, где типовая делает то же самое (все вызовы добавления строк, а не первый найденный), и весь набор связанных табличных частей, который очищает типовой обработчик. На реальной доработке исполнитель перехватил одно место из четырёх и пропустил одну из связанных табличных частей;
    - **самопроверка исполнителя не заменяет EDT и полный сет** [[full-checker-set-before-done]]: ошибки компиляции, внесённые агентами, на практике поймала только EDT;
    - **параллельно — только исполнители без пересечения по файлам.** Этапы, которые правят одни и те же файлы, идут строго последовательно.
7. **Отчёт субагента «готово» — не доказательство.** Итог принимается по git diff и выводу инструмента (валидатор, EDT, чекеры), а не по словам агента. Идея — по мотивам obra/superpowers (MIT), пересказ своими словами.

8. **Другие сессии — только по прямой просьбе владельца** (распоряжение 18.10.2026: «плагин сам предлагает создать новые сессии — это надо исключить в обязательном порядке»). Приложение Claude своей инструкцией подсказывает модели предлагать отдельные сессии: карточки-предложения, окно «New session / Do it here», перенос задачи в новую сессию (инструменты `start_session` и `hand_off_to_session`). Распоряжение владельца выше этой подсказки: работа идёт в текущей сессии; другая сессия — только когда владелец в этом запросе сам попросил её («запусти это в отдельной сессии»). Это тот же класс, что помощники и фоновые прогоны: параллельная работа без участия владельца.

**Принуждение (с 17.10.2026):** барьер `subagent-gate` проверяет явное «да» владельца на помощников (в запросе или выбранным вариантом окна, без отрицания и без условия вроде «только после…»): вызов `Agent`/`Workflow` без него — отказ, сверх названного числа помощников — отказ. Источник правды — журнал сессии, его пишет Claude Code, а не модель; с 30.10.2026 так же решаются расписание (`CronCreate`, `RemoteTrigger`, `scheduled-tasks`) и другие сессии. Запись `logs/consent.json` — только для события без `transcript_path` (старый Claude Code, самотест). ultracode и режим без подтверждений согласием не считаются. Регресс — `contour-tests` §13c, §36, §121. Согласие, сказанное непривычными словами, барьер не распознает — цена ошибки: лишний вопрос окном вариантов. Обратная ошибка закрыта с 30.10.2026: слова 1С и GitHub («реквизит Агент», «справочник Агенты», «агент обмена», «контрагент», workflow в GitHub) согласием не считаются, а помощники считаются только в форме запуска — глагол запуска рядом со словом, число помощников, «веером», «через агентов» или одно это слово после «да». С 4.9.1 (п.8) — барьер `subagent-gate` на инструментах сессий приложения Claude: `start_session` по своей инициативе (`own_initiative`, `offer`, запуск предложения `proposal_id`) — отказ всегда; `start_session` `user_asked` и `hand_off_to_session` — отказ, если в текущем запросе владелец сам не попросил отдельную сессию (предложение со словом «сессия» и глаголом действия, без запрета и не вопрос; «надо исключить» — запрет). Регресс — `contour-tests` §13c.

Связано с правилами [[two-axis-code-review]], [[capture-knowledge]], [[ask-before-changing]] (согласие на запуск и масштаб), [[use-skills-not-manual-edits]] (структурное — скиллом), [[full-checker-set-before-done]] (что считается проверкой), [[writing-for-agents]] (ISOLATE: веер не загрязняет мой контекст).
