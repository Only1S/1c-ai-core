# Правило: как называть файлы и папки

1. **Латиница, строчные буквы, слова через дефис, по-английски** (распоряжение владельца 16.10.2026, п.21 программы): `forms-skills-and-visual-check.md`, `stock-transfer.md`, `tools/analysis/`. Не транслит (`kmp-ostatki-konec-mesyaca.md`) и не кириллица.
2. **Имя называет содержимое, а не историю его появления.** Плохо: `wave-h-slice-3.md`, `new-check-2.ps1`, `design-before-code.md` для правила, где ТЗ как раз *не* обязательно. Хорошо: имя, по которому человек, впервые открывший папку, поймёт, что внутри.
3. **Папка — тема, файл — один предмет.** Если имени файла нужно уточнение «про формы», файл лежит в папке `forms/`, а не называется `forms-…` в общей куче.
4. **Скрипт называется действием и предметом:** `install-tools.py`, `check-line-endings.py`; документ — предметом: `release-notes.md`.
5. **Исключения — только по внешнему требованию:** имена, которые диктует инструмент (`SKILL.md`, `plugin.json`, `.mcp.json`, `CLAUDE.md`, `README.md`), и имена объектов 1С (`Справочник.Номенклатура`, файлы выгрузки конфигурации, `fs_Маркировка.cfe`) — их не трогаем: их пишет платформа. Ещё одно исключение — **готовый набор документации для людей со своими внутренними ссылками** (например, руководство пользователя конфигурации, выгруженное деревом страниц с картинками): его не переименовывают, имена страниц — для читателей набора, а переименование ломает его ссылки (решение владельца 17.10.2026). Отдельные файлы для людей (ТЗ, инструкции, отчёты) под исключение не подпадают — им латинское имя.
6. **Переименование — вместе со всеми ссылками в одной правке**, затем `tools/indexes/gen-doc-index.py` и проверка проекта: в мастере битую вики-ссылку ловит health-check (§5), в проекте health-check нет — старое имя ищи поиском (Grep) по `docs-project/` и `CLAUDE.md`. Шаблон имени машинно проверяется только у нового файла в `docs-project/` (подсказка `lint-project-docs` при заведении: латиница, строчные, слова через дефис; `INDEX.md`, `README.md` и другие имена по требованию инструмента — исключение п.5; с 30.10.2026), у имени ADR (`NNNN-slug`, подсказка `lint-project-docs`) и у имени скилла (шаблон и совпадение с папкой — health-check в мастере; совпадение с папкой — подсказка `lint-project-docs`); имена папок и файлов вне `docs-project/` не проверяются.

**Why:** владелец 16.10.2026: «нужно, чтобы максимально научился давать правильные имена для файлов и папок». Сегодня же кириллические имена файлов сломали два инструмента: git отдаёт их экранированными, и модуль выравнивания переводов строк их молча пропускал. Транслит и имена «по истории» (`wave-h`, `slice-3`) не говорят новому человеку, что внутри.

**How to apply:** новый файл или папка — сразу по правилу; старые имена ядра уже приведены к правилу (программа 16.10.2026, п.21). Сомневаешься в имени — спроси себя, поймёт ли его человек, который видит папку впервые.
