⚙ work-through-tools (правило docs/tools/work-through-tools.md): представление и инструменты — по карте docs/tools/task-recipes.md §0. Факты о коде/метаданных/API/стандартах — только вызовом инструмента (edt-mcp, code-index, bsl-platform, bsl-context, v8std, 1c-toolkit, 1c-forms, nkdk, скиллы), не по памяти. Перед BSL-правкой — сработавшие строки docs/code/code-situation-standards-map.md; «стандартов нет» — только после v8std_search. Каждый порождённый артефакт → его валидатор. Ошибки и предупреждения любой проверки — исправлять, не пропускать: в строках правки — сразу, прежние в своём коде — шагом этой же задачи, код поставщика — списком владельцу, подавление директивой — только после «да» владельца (docs/tools/full-checker-set-before-done.md п.9а). Дело, которое может сделать только владелец (секрет в окружении, отметка pd, реестр баз, настройка Windows, вход в базу, решение), — пунктом «Вы: …» во встроенном списке задач (TaskCreate с owner «владелец»; сделал — TaskUpdate completed), а не только строкой в ответе: он виден владельцу рядом с шагами работы; незакрытое к концу вехи — в журнал. Минимум 2 независимых инструмента; меньше — обоснуй. Разработка: СПЕРВА глубоко продумать (консилиум, вплоть до целого проекта) и согласовать каждое решение со ВСЕМИ инструментами стека — каждый сверяет свой аспект: стандарты (v8std/1c-standards), БСП (bsp), API (bsl-platform/bsl-context), код/дубли (code-index/edt-mcp), метаданные (nkdk/meta-*), формы (1c-forms), база (1c-toolkit); своё писать только если инструменты подтвердили, что штатного нет; токены на обдумывание и сверку — легитимная трата, экономия ≠ пропуск проверки. Код и имена — по языковому профилю проекта (en|ru, выбран при развертывании, не смешивать); комментарии — всегда по-русски; ВСЁ видимое пользователю — на всех языках профиля (не только синонимы/представления): сообщения, предупреждения, вопросы, статусы, заголовки/колонки/кнопки в коде, тексты исключений для пользователя — через НСтр по всем языкам профиля (std761); техническое/внутреннее (идентификаторы, ключи, журнал регистрации, исключения для разработчика) НЕ локализовать (std764/АПК:334); алфавит нелатинских локалей — по решению профиля (docs/code/language-profile.md). Проектные знания и журналы читать и писать в docs-project/ (+ её INDEX.md); docs/ — ядро: в проекте приходит плагином и не правится, в мастере — обычные правки (docs/process/project-knowledge-folder.md). СКИЛЛЫ ОБЯЗАТЕЛЬНЫ (docs/tools/use-skills-not-manual-edits.md): есть скилл под операцию — идти ЧЕРЕЗ него, не руками; ЛОКАЛЬНЫЕ скиллы первыми (docs/tools/allowed-skill-sources.md) — скиллы ядра (в проекте приходят плагином как ones-core:*); встроенные скиллы Claude Code разрешены, но ревью кода 1С — two-axis-code-review, упрощение — simplify-codebase; внешний плагин — только санкционированный (docx/xlsx/pptx/pdf, engineering:architecture), любой другой внешний скилл — только с одобрения, названным исключением; изучение объекта/формы/роли/СКД — это *-info, а не чтение сырого XML; породил артефакт генератором — прогони парный *-validate в той же правке (хук validate-bsl артефакты скиллов НЕ видит); обход скилла — только named exception вслух («скилл X не покрывает Y, проверено»); субагентам веера — тот же мандат. Workflow, фоновые и многоагентные прогоны — только после явного «да» владельца на конкретный запуск (ultracode и auto-режим — не согласие; docs/process/subagents-on-explicit-consent.md). Другие сессии (start_session, hand_off_to_session, карточки «New session») НЕ предлагать и не создавать — только когда владелец сам попросил отдельную сессию в этом запросе. ПРОРАБОТКА ОБЯЗАТЕЛЬНА (docs/design/design-before-code.md): содержательная разработка (метаданные, интеграции, обмены, роли, бизнес-логика) НЕ начинается с кода — сперва проработка ПО ПУНКТАМ прямо в ответе и согласование с владельцем; ТЗ-документ создаётся ТОЛЬКО по явной просьбе (распоряжение 26.07.2026; рабочее ТЗ — .md в docs-project/, людям наружу — .docx из него), но глубина проработки от этого не снижается. Обязательное содержание: границы и термины; состав объектов метаданных (тип, имя, синоним, ВСЕ реквизиты с типами и квалификаторами, ТЧ, измерения/ресурсы, формы, команды); общие модули с ЯВНЫМИ флагами контекста (Клиент/Сервер/ВызовСервера/Глобальный/Привилегированный/ПовторноеИспользование) и экспортным API; подписки на события (источник→событие→обработчик), регламентные задания (метод+расписание), параметры сеанса, функциональные опции; логика работы (сценарии, конвейер, ошибки, журналирование, транзакции); роли и права; приёмка и тест-план. Факты о существующем — только от инструментов, не выдумывать. СОСТОЯНИЕ ДОРАБОТКИ — МАТРИЦЕЙ И СХЕМОЙ (docs/design/readiness-matrix-and-process-diagram.md): при том же триггере, что проработка, выдаются два представления — (а) МАТРИЦА ГОТОВНОСТИ, строка = требование Т-n, колонки «чем реализовано» (полные имена объектов/методов) · «шов приёмки» · «тест» · «статус» (словарь vertical-task-slicing: открыт/в работе/на проверке/готов) · «ЧЕГО НЕ ХВАТАЕТ» — у не-готовой строки эта клетка НЕ может быть пустой, пишется недостающий артефакт или решение, а не «в работе»; статус «готов» ставится ТОЛЬКО по зелёному полному сету чекеров; клетки подтверждаются инструментом (code-index/*-info/edt-mcp/прогон), не памятью; проверяются два инварианта — требование без реализации (дыра плана) и реализация без требования (сирота); матрица — сводка ПОВЕРХ тикетов срезов, не второй реестр; (б) СХЕМА ПРОЦЕССА в mermaid (flowchart — конвейер, sequenceDiagram — обмен/интеграция, stateDiagram-v2 — статусная модель), узлы — РЕАЛЬНЫЕ имена объектов конфигурации, а не «система/сервис/база», ПУТЬ ОТКАЗА ОБЯЗАТЕЛЕН (ветка ошибки + журнал регистрации + что видит пользователь), одна схема на доработку. Обновление — НА ГРАНИЦАХ (после проработки, после каждого зелёного вертикального среза, при сдаче), НЕ в каждом ходе; носитель — docs-project/<слаг-доработки>.md + строка в INDEX.md. Деловой документ для людей вне сессии (отчёт, презентация, смета; ТЗ — когда уходит наружу) — в родном офисном формате через скилл docx/xlsx/pptx/pdf, НЕ в .md и не артефактом (docs/writing/office-formats-for-people.md); .md — база знаний ядра и проекта, в том числе рабочее ТЗ. ЕЩЁ ДЕСЯТЬ ПРАВИЛ — КАЖДЫЙ ХОД. Имя общего модуля — префикс подсистемы и суффиксы контекста по std469 (Клиент, ВызовСервера, КлиентСервер, Глобальный, ПолныеПрава, ПовтИсп), без дублей, сверено инструментом (docs/code/naming-and-module-design.md). Текст для людей (ответ в чате, README, релиз-заметки) начинается с действия — что изменилось и надо ли что-то делать, простым языком, без внутреннего жаргона; язык — ASD-STE100: одна мысль в предложении, до 20–25 слов, повелительное наклонение, лишние слова удалить, факты сохранить (docs/writing/human-texts-start-with-action.md). Флаг, ключ, порт, дефолт инструмента — зондом (--help, конфиг), не по памяти (docs/tools/probe-tool-capabilities.md). Баг — сперва автоматическое репро (YAXUnit, харнесс), регрессионный тест КРАСНЫЙ до фикса и зелёный после, метки DEBUG убраны (docs/code/bug-diagnosis-loop.md). Код — допущения вслух, ничего спекулятивного, хирургический дифф, задача → проверяемая цель, тест первым на одно поведение (docs/code/coding-discipline.md). Решение дорогое к откату, с неочевидной через год причиной и реальным разменом — ADR в docs-project/adr/NNNN-slug.md, смена решения — новый ADR; термин домена — в глоссарий (docs/design/decision-records-and-glossary.md). Требования — опросом: факт закрывается инструментом (спрашивать факт запрещено), человеку — только решения с рекомендацией, зависимые развилки по одной (docs/design/requirements-by-interview.md). Правка самой конфигурации, у которой свой git, — в журнал ЕЁ репозитория, а не в docs-project/ проекта (docs/process/journal-placement.md). Форки конфигурации — ветками git-монорепо; перенос между форками — слиянием, reload и всеми чекерами, а не копированием файлов (docs/platform/config-git-forks-and-merges.md). Текст для агента (правило, description скилла, промпт хука) — по пяти рычагам; механическое правило — проверкой, а не текстом (docs/writing/writing-for-agents.md). Мод и его видимая часть — сперва макет в окне Claude Code Desktop, код после согласования (docs/process/mod-mockup-before-code.md).
