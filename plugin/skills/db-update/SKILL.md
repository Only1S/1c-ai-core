# /db-update — Обновление конфигурации БД

Применяет изменения основной конфигурации к конфигурации базы данных (`/UpdateDBCfg`) —
отдельным шагом после загрузки. У `/db-load-xml` и `/db-load-git` то же самое делает
ключ `-UpdateDB`.

## ⚠️ Необратимая операция

`/UpdateDBCfg` **реструктурирует базу данных**: удалённые реквизиты и табличные части сносятся вместе с данными, изменённые типы конвертируются с потерями. Штатного «отменить» нет — откат возможен **только из бэкапа, сделанного заранее**. Цикл ниже обязателен, шаги не пропускаются и не переставляются.

> **Не путать с обновлением через EDT.** Если правка шла через модель проекта в EDT, база обновляется вызовом `update_database` (edt-mcp) — это **другой путь, и он выполняется сразу, без вопроса** (`docs/process/ask-before-changing.md` п.8). Цикл ниже — только для платформенного `/UpdateDBCfg` (`1cv8`/`ibcmd`): он применяет конфигурацию мимо валидации EDT и реструктурирует данные.

1. **Бэкап — точка отката.** До обновления: `/db-dump-dt` (вся база — единственный снимок, возвращающий и данные) или как минимум `/db-dump-cf` (конфигурация БД до применения). Бэкапа нет → операция не начинается.
2. **Проверка целевой базы.** База разрешается по `.v8-project.json` (id / alias / name, иначе ветка Git → `default`) и **называется пользователю явно** (путь файловой базы либо сервер + имя). **Целевая база обязана быть зарегистрирована в `.v8-project.json`; незарегистрированная считается боевой (`docs/safety/secrets-and-production-database.md`) — не трогать.**
3. **Сухой прогон.** Показать пользователю: какая база, какие изменения структуры применяются (что удаляется/меняет тип — по диффу конфигурации), режим (`-Dynamic on/off`, монопольный доступ, фоновое обновление), где лежит бэкап из шага 1. Предупреждения проверять как ошибки — `-WarningsAsErrors`.
4. **Явное подтверждение пользователя** — окном вариантов (AskUserQuestion), «применить / отменить»; отдельно подтверждается потеря данных, если структура сносится. Общее «продолжай» из контекста подтверждением **не** считается (`docs/process/ask-before-changing.md`, `docs/process/questions-as-options.md`).
5. **Применение** — только после подтверждения.
6. **Проверка** — полный сет чекеров после правки (`docs/tools/full-checker-set-before-done.md`): база открывается, конфигурация БД синхронна основной, ключевые данные на месте.
7. **Откат** — если результат не тот: `/db-load-dt <бэкап.dt>` (полное восстановление) либо `/db-load-cf <бэкап.cf>` + повторный `/db-update` (только конфигурация; потерянные при реструктуризации данные так не вернуть).

## Usage

```
/db-update [database]
/db-update dev
/db-update dev -Dynamic on
```

## Параметры подключения

Прочитай `.v8-project.json` из корня проекта. Возьми `v8path` (путь к платформе) и разреши базу:
1. Если пользователь указал параметры подключения (путь, сервер) — используй их, **только если такая база есть в `.v8-project.json`** (правка ядра: незарегистрированная база считается боевой, `docs/safety/secrets-and-production-database.md`; барьер `guard-destructive` такой вызов отклонит)
2. Если указал базу по имени — ищи по id / alias / name в `.v8-project.json`
3. Если не указал — сопоставь текущую ветку Git с `databases[].branches`
4. Если ветка не совпала — используй `default`
Если `v8path` не задан — спроси пользователя, какую платформу брать, и впиши её в `v8path` в `.v8-project.json` (правка ядра: без `-V8Path` скрипт взял бы новейшую установленную платформу — она может быть другой линейки, например 8.5, и сконвертировать базу; барьер `guard-destructive` такой запуск отклоняет).
Если файла нет — предложи `/db-list add`.
Если база не зарегистрирована — операция **не выполняется**: сперва пользователь решает, регистрировать ли её как тестовую (`/db-list add`) (правка ядра).

## Команда

```powershell
python "${CLAUDE_SKILL_DIR}/scripts/db-update.py" <параметры>
```

### Параметры скрипта

| Параметр | Обязательный | Описание |
|----------|:------------:|----------|
| `-V8Path <путь>` | нет | Каталог bin платформы, или полный путь к `1cv8.exe` / `ibcmd.exe` |
| `-InfoBasePath <путь>` | * | Файловая база |
| `-InfoBaseServer <сервер>` | * | Сервер 1С (для серверной базы) |
| `-InfoBaseRef <имя>` | * | Имя базы на сервере |
| `-UserName <имя>` | нет | Имя пользователя |
| `-Password <пароль>` | нет | Пароль |
| `-Extension <имя>` | нет | Обновить расширение |
| `-AllExtensions` | нет | Обновить все расширения |
| `-NoApplyCheck` | нет | Не проверять применимость расширения после обновления |
| `-Dynamic <on/off>` | нет | `on` — динамическое обновление, без монопольного доступа к базе; `off` — отключить |
| `-Server` | нет | Обновление на стороне сервера |
| `-WarningsAsErrors` | нет | Предупреждения считать ошибками |
| `-AdditionalV8Arguments <список>` | нет | Доп. аргументы запуска `1cv8.exe` через запятую, напр. `/UseHwLicenses+` |
| `-AdditionalIbcmdArguments <список>` | нет | Доп. аргументы `ibcmd` через запятую, в форме `--ключ=значение` |

> `*` — нужен либо `-InfoBasePath`, либо пара `-InfoBaseServer` + `-InfoBaseRef`

### Фоновое обновление (серверная база)

| Параметр | Описание |
|----------|----------|
| `-BackgroundStart` | Начать фоновое обновление |
| `-BackgroundFinish` | Дождаться окончания |
| `-BackgroundCancel` | Отменить |
| `-BackgroundSuspend` | Приостановить |
| `-BackgroundResume` | Возобновить |

## Примеры

```powershell
# Обычное обновление (файловая база)
python "${CLAUDE_SKILL_DIR}/scripts/db-update.py" -InfoBasePath "C:\Bases\MyDB" -UserName "Admin"

# Динамическое обновление
python "${CLAUDE_SKILL_DIR}/scripts/db-update.py" -InfoBaseServer "srv01" -InfoBaseRef "MyDB" -UserName "Admin" -Password "secret" -Dynamic on

# Обновление расширения
python "${CLAUDE_SKILL_DIR}/scripts/db-update.py" -InfoBasePath "C:\Bases\MyDB" -UserName "Admin" -Extension "МоёРасширение"
```
