# Чек-листы сверки ТЗ

Открывать на шагах 3–5 скилла. Запреты платформы сверены по `1c-platform-kb` (`references/its-docs/dev-gl30-rasshireniya.md`, 8.3.27); версия платформы новее — перечитать главу.

## Запреты расширения

| ТЗ требует | Что проверить |
|---|---|
| Реквизит или табличную часть в плане видов расчёта, плане счетов, плане видов характеристик | Расширение этого не умеет: нужен свой регистр сведений или дополнительные реквизиты БСП |
| Новое поле в типовом регистре | Структуру регистра менять нельзя, можно только расширить состав регистраторов |
| Безопасный режим при перехвате серверного кода | В безопасном режиме серверные общие модули и серверные методы форм с аннотациями не расширяются |
| Запись в свои регистры из типового документа у пользователя с типовыми ролями | На свои объекты права дают только роли расширения; без третьей роли нужен привилегированный режим в коде, а он недоступен в безопасном режиме |
| Привилегированный или глобальный общий модуль в расширении | Свой модуль таким быть не может; расширение привилегированного модуля работает непривилегированно |
| Новые права на объекты конфигурации ролью расширения | В клиент-серверном варианте без профиля безопасности не работает |
| `&Вместо` в расширении с назначением «Дополнение» | Такое расширение должно переживать обновления: каждую замену считать риском обновления |
| Сохранение файлов и внешние компоненты в безопасном режиме | Проверить по той же главе и по `dev-gl05-obekty-konfiguracii.md` |

## Противоречия внутри ТЗ

- Каждое «только», «единственное исключение», «всегда», «никогда»: поискать случаи, которые это нарушают.
- Каждая ставка и порог: текст раздела, таблица приложения и ожидаемый итог сценария должны давать одно число.
- Пересчитать суммы, доли и округления в сценариях приёмки.
- «Дата документа» против «месяц начисления», «выручка» против «поступления», «на дату» против «за период»: сверить с формулировками и со сценариями.
- Обязательные реквизиты на существующих данных: перепроведение старых документов не должно ломаться.
- Счета, виды документов и имена объектов из примеров сверить с планом счетов и метаданными.
- «Исполнитель уточняет перечень», «определяет исполнитель»: это незакрытый объём, а не деталь.
- Правило опирается на реквизит: посчитать в базе, заполнен ли он в реальных документах. Пустой реквизит тихо выключает правило.

## Чего обычно нет на входе

- Точный номер релиза конфигурации: готовый механизм может быть в новом релизе и отсутствовать в базе заказчика.
- Внешняя форма или файл, на которые ТЗ ссылается: приложить или признать неизвестным объёмом.
- Копия базы заказчика, его доработки и план счетов.
- Заключение юриста по спорным нормам: требование может отпасть целиком.
- Учётная запись и лицензии для прогона сценариев в клиенте 1С.
