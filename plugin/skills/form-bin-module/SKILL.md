# /form-bin-module — модули обычных форм из Form.bin

> Разобрать, поправить или нарисовать одну обычную форму (не только модуль) — скилл `form-ordinary`. Этот скилл — для поиска по модулям всех обычных форм выгрузки (зеркало `.bsl`).

В выгрузке Конфигуратора (`DumpConfigToFiles`, а также `epf-dump`/`erf-dump`) у **обычной** формы нет отдельного `.bsl`: модуль лежит внутри бинарного контейнера `<...>/Ext/Form.bin` (внутренние файлы `form` и `module`). Такой код не видят `Grep`, `code-index`, BSL LS, `validate-bsl` и ревью. Скилл складывает тексты модулей в **параллельное дерево вне выгрузки**, где их видно обычными средствами. Исходная выгрузка открывается только на чтение.

## Когда этот скилл, а когда другой путь

| Задача | Инструмент |
|---|---|
| Найти/прочитать код **обычной** формы в выгрузке Конфигуратора или `epf-dump` | **`/form-bin-module`** |
| Проверить, свежее ли зеркало после новой выгрузки | **`/form-bin-module report --out`** |
| Управляемая форма (`Ext/Form.xml` + `Ext/Form/Module.bsl`) | `form-info` + чтение `Module.bsl` напрямую — этот скилл не нужен |
| Целый `.cf`/`.cfe`/`.epf` без платформы | `cf-unpack` |
| **Изменить** модуль обычной формы | владелец в Конфигураторе, затем новая выгрузка и `extract`. Записи обратно в `Form.bin` у скилла нет |

## Требование среды

```bash
python -c "import v8unpack" || pip install v8unpack
```

Та же Python-библиотека `v8unpack`, что и у `cf-unpack` (TIER C, в ядро не бандлится). Нет Python или пакета — не блокируемся: код обычной формы смотрит владелец в Конфигураторе, и в ответе об этом говорится прямо.

## Команды

**Извлечь** (пишутся только новые и изменившиеся файлы, повторный прогон ничего не трогает):
```bash
python "${CLAUDE_SKILL_DIR}/scripts/form_bin_module.py" extract "<каталог выгрузки>" --out "<каталог зеркала>"
```

**Отчёт** без записи: сколько обычных форм, у скольких есть модуль, ошибки разбора. С `--out` сверяет и зеркало: актуально, устарело, отсутствует, сироты.
```bash
python "${CLAUDE_SKILL_DIR}/scripts/form_bin_module.py" report "<каталог выгрузки>" --out "<каталог зеркала>"
```

`--json <файл>` сохраняет полный отчёт: все ошибки и сироты, версию `v8unpack`. Код возврата: `0` — все Form.bin разобраны, `1` — есть ошибки разбора (список в выводе), `2` — ошибка аргументов.

**Раскладка зеркала:** `<выгрузка>/<...>/Ext/Form.bin` → `<зеркало>/<...>/Ext/Module.bsl`. Путь повторяет выгрузку, так что форму видно по пути (`Catalogs/<Объект>/Forms/<Форма>/...`, `CommonForms/<Форма>/...`). Текст — содержимое внутреннего `module` в UTF-8 с BOM и CRLF: если в контейнере уже CRLF и BOM, файл совпадает с ним байт-в-байт, иначе переводы строк и BOM приводятся к этому виду. Каталоги обходятся с префиксом длинного пути, а сбой обхода считается ошибкой (код выхода 1), поэтому глубокая форма не может выпасть из отчёта молча. Вложенный 64-битный контейнер распознаётся по сигнатуре, но на реальном файле не проверен.

От раскладки управляемой формы (`Ext/Form/Module.bsl`) отказались намеренно. На такой раскладке анализатор принимает модуль за управляемую форму. Замер bsl-analyzer 0.2.79 на трёх модулях реальной выгрузки: +204 `CompilationDirectiveLost` и +89 `UnavailableInEnvironment`. Оба ложные: по v8std `CompilationDirectiveLost` относится к управляемым формам и командам, а модуль обычной формы исполняется в толстом клиенте без директив. На `Ext/Module.bsl` этих диагностик 0, `ParseError` тоже 0.

**Куда класть зеркало.** Только в каталог вне выгрузки. Скрипт откажет, если `--out` совпадает с выгрузкой, лежит внутри неё или содержит её. Как лишний `.bsl` рядом с `Form.bin` повлияет на загрузку выгрузки в базу, не проверено, поэтому такой вариант просто запрещён. Зеркало — производные данные. Его не правят и не коммитят в репозиторий конфигурации, а пересобирают после каждой новой выгрузки.

**Конвенция места (19.09.2026).** По умолчанию зеркало — каталог `.form-bin-mirror/` в корне проекта Claude Code (он в `.gitignore` ядра), по аналогии с индексом `code-index` ([[code-index-outside-sources]]): вне выгрузки, вне EDT-проекта, вне git. Для мульти-конфига — подкаталог на алиас: `.form-bin-mirror/<алиас>/`. Подключать зеркало к `code-index` — только после зонда: как индексатор классифицирует `<...>/Ext/Module.bsl` обычной формы, не проверено.

## Проверка результата

1. Код возврата `0`. Если есть ошибки разбора, они перечислены поимённо.
2. `report --out` после `extract`: «актуально» = «с модулем», «устарело 0», «отсутствует 0».
3. **Сироты** — `Module.bsl` в зеркале, модуля которого в выгрузке больше нет (форму удалили или модуль опустел). Скрипт их **не удаляет**, только перечисляет. Пока сирота лежит в зеркале, поиск находит код несуществующей формы. Удалить сироту или пересоздать зеркало в новый каталог решает владелец.

## Ограничения

- **Только чтение, без упаковки.** Формат контейнера формы не документирован. В разборе источника пересобранный контейнер отличался по размеру от исходного, хотя `form` и `module` совпадали. Примет ли его платформа — не проверено. Поэтому правка модуля идёт только через Конфигуратор.
- **Разметку формы** (`form`, элементы) скилл не разбирает, `form-*` и `1c-forms` работают только с управляемыми формами.
- Правки в зеркале никуда не попадают, а хук `validate-bsl` их не видит (файлы пишет скрипт, не `Edit`). Зеркало — только для чтения и поиска.
- Диагностики, рассчитанные на управляемые формы (`GetFormMethod`, `UsingThisForm`), на модуле обычной формы оценивать с учётом толстого клиента, а не автоматически.
- Модуль не в UTF-8 (например, зашифрованный) даёт ошибку формы, прогон при этом продолжается. На реальном зашифрованном модуле не проверено.
- Скрипт опирается на внутренний API `v8unpack` (`detect_format`, `Container.files`). После обновления библиотеки повторить проверку из раздела выше.
- `.epf` напрямую скилл не читает: сначала `epf-dump` (платформа), затем этот скилл по результату, либо `cf-unpack`.
- Проверено 19.09.2026: `v8unpack 1.2.6`, Python 3.14. Материал: три копии `Form.bin` реальной выгрузки Конфигуратора (от 2,6 КБ до 3 МБ, в том числе общая форма) и синтетические контейнеры (нет `module`, пустой модуль, LF без BOM, чужая сигнатура, обрезанный файл). Результат сверен по sha1 со штатной распаковкой `v8unpack`. Полный прогон 19.09.2026 по целой реальной выгрузке: 1808 `Form.bin`, модулей 1659, пустых 149, ошибок разбора 0; `extract` — 5 с, зеркало 78 МБ; повторный `report --out` — актуально 1659, сирот 0; выгрузка после прогона не изменилась (`git status` чистый). BSL LS (MCP) и `code-index` по зеркалу не проверены.

Скилл наш. Идея и основа — по мотивам `Caponid/1c-form-tools` (MIT, Copyright (c) 2025 Caponid), полный текст лицензии — в шапке скрипта. От оригинала отличается: контейнер читается в памяти, вывод идёт в отдельный каталог, а не рядом с `Form.bin`, исправлен CRLF→CRCRLF (issue #1 источника), добавлены сверка зеркала и сироты. Упаковку в `Form.bin` и pre-commit-хук оригинала не переносили.
