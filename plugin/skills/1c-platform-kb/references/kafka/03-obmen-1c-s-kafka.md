## Кратко — главные факты

1. **Встроенного клиента Kafka в платформе 1С нет.** Платформа умеет: веб-сервисы (SOAP), HTTP-сервисы и `HTTPСоединение` (REST), OData, планы обмена, внешние компоненты и **сервисы интеграции** — адаптер к сервисной шине по протоколу **AMQP** [ИТС-разр гл. 17.1]. Kafka по AMQP не работает.
2. **Сервисы интеграции рассчитаны на «1С:Шину»**: внешний сервис интеграции — это продукт «1С:Шина» [ИТС-разр гл. 17.8.1]. В справочнике узлов схемы «1С:Шины» версии 3 есть узлы RabbitMQ, JMS, HTTP, SQL, FTP, файлы — **узла Kafka нет** (по оглавлению `esbdoc3`, 20.10.2026). В презентациях 1С упоминается «коннектор Kafka» ⚠ — в какой версии «Шины» и в каком виде, по открытым источникам не установить.
3. **Рабочие способы:** (а) **HTTP-мост** Kafka (Strimzi HTTP Bridge, Apache 2.0) + `HTTPСоединение` из 1С — без компонент, проще всего сопровождать; (б) **внешняя компонента Native API** на `librdkafka` (открытая Simple Kafka, коммерческая Yellow Kafka) — быстрее и богаче, но это сторонний код в процессе сервера 1С; (в) **промежуточный сервис**, который сам ходит в 1С (HTTP-сервис) и в Kafka.
4. **Захват изменений из таблиц СУБД 1С (Debezium и т. п.) — не вариант:** сведения о таблицах 1С нельзя использовать для работы с данными нештатными способами, а состав таблиц и полей может меняться от версии к версии [ИТС-мет «Размещение данных», `../its-metod/razmeshchenie-dannyh-tablicy-i-polya.md`, п. 1–2].
5. **Надёжность обмена делает сама 1С, а не Kafka.** Шаблон **outbox**: сообщение пишется в регистр-очередь **в той же транзакции**, что и документ; регламентное задание отправляет очередь и удаляет отправленное после подтверждения. Так ведут себя и сервисы интеграции платформы: исходящее сообщение хранится в базе до подтверждения получения [ИТС-разр гл. 17.8.1].
6. **Получатель должен быть идемпотентным.** И мост, и компонента, и сама платформа дают доставку «хотя бы один раз»: при сбое между обработкой и фиксацией смещения сообщение придёт снова. Платформа прямо требует того же для каналов без транзакции [ИТС-разр гл. 17.8.2]. Храните идентификаторы обработанных сообщений.
7. **Порядок** сохраняется только внутри раздела Kafka: ключ сообщения = УИД объекта (`Ссылка.УникальныйИдентификатор()`) — тогда все версии одного объекта читаются по порядку [Kafka-док 4.4 `design`].
8. **Размер:** по умолчанию предел сообщения ~1 МБ [Kafka-код 4.4]. Пакеты 1С — по объекту или небольшими порциями; файлы — ссылкой.
9. **HTTP-мост не проверяет подлинность клиентов** — ставьте его за обратный прокси с TLS и паролем или открывайте только серверам 1С [Strimzi]. В примере настроек моста `kafka.producer.acks=1` — для обмена ставьте `all`.
10. **Внешнюю компоненту подключайте изолированно** (`ТипПодключенияВнешнейКомпоненты.Изолированно`): тогда её падение не роняет процесс `rphost` и сеансы [ИТС-разр гл. 32.1]. На сервере изолированный режим и так выбирается по умолчанию, если режим совместимости конфигурации новее 8.3.20 [там же].

## 1. Что умеет платформа и чего не умеет

| Механизм платформы | Пригоден для Kafka? | Почему |
|---|---|---|
| Сервисы интеграции (AMQP) | Нет напрямую | Говорят с «1С:Шиной» по AMQP и её HTTP-интерфейсу; Kafka — свой протокол [ИТС-разр гл. 17.8] |
| `HTTPСоединение` | **Да, через HTTP-мост** | Мост переводит REST в протокол Kafka |
| HTTP-сервисы 1С | Да, как точка, куда **внешний** сервис кладёт/забирает данные | Сервис-посредник читает Kafka и вызывает 1С |
| Внешние компоненты Native API | **Да** | Компонента сама реализует клиента Kafka (обычно на `librdkafka`) [ИТС-разр гл. 32] |
| Планы обмена | Как источник изменений | Регистрация изменений + выгрузка в сообщения; сами по себе в Kafka не отправляют |
| Внешние источники данных | Нет | Это доступ к СУБД по ODBC |

Механизм сервисов интеграции «не является альтернативой планам обмена», он только транспортирует сообщения; планы обмена могут быть источником данных для них [ИТС-разр гл. 17.8.1]. То же верно для любого транспорта в Kafka: что отправлять, формирует прикладной код.

## 2. Сравнение способов

| Способ | Плюсы | Минусы | Когда брать |
|---|---|---|---|
| **HTTP-мост** (Strimzi HTTP Bridge) + `HTTPСоединение` | Только штатный встроенный язык; мост — отдельный процесс, его падение не трогает 1С; легко отлаживать `curl` | Лишнее звено; HTTP-накладные расходы; состояние потребителя живёт в процессе моста | Объёмы до тысяч сообщений в минуту, нет разработчиков C++/Rust, важна простота [практика] |
| **Внешняя компонента** (Simple Kafka, Yellow Kafka) | Прямой клиент Kafka: пакеты, сжатие, SASL/TLS, высокая скорость | Сторонний двоичный код в процессе сервера 1С (смягчается изолированным режимом); обновление компоненты вместе с конфигурацией; поддержка — авторы компоненты | Большие потоки, нужен потребитель с долгоживущим соединением |
| **Сервис-посредник** (своя программа, DaJet, Kafka Connect с HTTP-коннектором) | 1С ничего не знает о Kafka, отдаёт/принимает JSON по HTTP-сервису | Ещё одна программа: разработка, мониторинг, отказоустойчивость | В организации уже есть команда интеграции и свой стек |
| **«1С:Шина»** | Продукт 1С, сервисы интеграции «из коробки», гарантированная доставка | Узла Kafka в справочнике v3 нет; своя инфраструктура и лицензирование | Если «Шина» уже внедрена: Kafka подключать через промежуточный брокер или сервис ⚠ |
| **CDC из СУБД 1С** (Debezium) | Без доработки конфигурации | Противоречит требованию ИТС; таблицы `_Reference123`, `_Fld456` нечитаемы и меняются при реструктуризации | Не использовать |

Оценки «плюсов и минусов» внешних компонент и прокси подробно разобраны в статьях сообщества (утечки памяти и зависания у части компонент, «долгий опрос» и лишняя точка отказа у прокси) [сторонний: infostart.ru/1c/articles/2652150/, 30.03.2026].

## 3. Сообщение: формат и правила

### 3.1. Конверт

Удобно, чтобы у всех сообщений обмена была одна «обёртка», а данные лежали внутри:

```json
{
  "id": "6f1c2a64-0b1d-4a0e-9a3b-6d6c0b2b7c11",
  "type": "erp.nomenclature.changed",
  "version": 1,
  "source": "erp-1c",
  "created": "2026-10-20T07:15:42Z",
  "payload": {
    "ref": "1a2b3c4d-....",
    "code": "00-00001234",
    "name": "Кабель ВВГнг 3x2,5",
    "deleted": false
  }
}
```

| Поле | Правило | Зачем |
|---|---|---|
| `id` | Новый УИД на каждое сообщение (`Новый УникальныйИдентификатор`) | Идемпотентность у получателя |
| ключ Kafka (не в теле) | УИД объекта | Порядок версий одного объекта |
| `type`, `version` | Тип события и версия формата | Получатель различает форматы при доработках |
| `created` | Время в UTC, ISO 8601 (`ТекущаяУниверсальнаяДата()`) | Часовые пояса серверов и получателей различаются |
| ссылки | УИД (`Ссылка.УникальныйИдентификатор()`), а не представление | Представления не уникальны и меняются |
| числа | Числом JSON, без пробелов-разделителей разрядов | Разбор на стороне Java/Python |

Это [практика] обмена событиями; формат согласуйте с получателями до разработки.

### 3.2. Сериализация во встроенном языке

```bsl
// Сервер. Структура/Соответствие -> строка JSON
Функция ВJSON(Значение) Экспорт
	Запись = Новый ЗаписьJSON;
	Запись.УстановитьСтроку(Новый ПараметрыЗаписиJSON(ПереносСтрокJSON.Нет));
	ЗаписатьJSON(Запись, Значение);
	Возврат Запись.Закрыть();
КонецФункции

// Строка JSON -> Соответствие (ключи могут быть любыми строками)
Функция ИзJSON(Текст) Экспорт
	Чтение = Новый ЧтениеJSON;
	Чтение.УстановитьСтроку(Текст);
	Результат = ПрочитатьJSON(Чтение, Истина);
	Чтение.Закрыть();
	Возврат Результат;
КонецФункции
```

`ПрочитатьJSON(…, Истина)` возвращает `Соответствие` — ключи вида `message-id` в `Структуру` не поместятся. Даты в `ЗаписатьJSON` пишите строкой заранее (`XMLСтрока(ТекущаяУниверсальнаяДата()) + "Z"`) или параметрами `НастройкиСериализацииJSON` ⚠ (сверить в синтакс-помощнике своей версии, как сериализуются даты по умолчанию).

## 4. Шаблон outbox в 1С

### 4.1. Объекты конфигурации

| Объект | Реквизиты | Назначение |
|---|---|---|
| Регистр сведений `ОчередьОтправкиKafka` (независимый) | Измерения: `ИдСообщения` (Строка 36); ресурсы: `Тема` (Строка 249), `Ключ` (Строка 100), `Тело` (Строка неогр.), `Создано` (Дата), `Попыток` (Число), `ПоследняяОшибка` (Строка неогр.) | Сообщения, ждущие отправки |
| Регистр сведений `ОбработанныеСообщенияKafka` | Измерение `ИдСообщения`; ресурсы `Тема`, `Обработано` (Дата) | Идемпотентность приёма |
| Регламентное задание `ОтправкаВKafka` | Расписание — каждые 10–60 с | Отправка очереди |
| Регламентное задание `ПриёмИзKafka` | Каждые 10–60 с | Чтение тем |

Это [практика]; при использовании БСП вместо своих регламентных заданий можно взять подсистему «Обмен данными» или очереди заданий ⚠ (не сверялось с документацией БСП).

### 4.2. Запись в очередь — в той же транзакции

```bsl
// Модуль объекта справочника Номенклатура (или подписка на событие ПриЗаписи)
Процедура ПриЗаписи(Отказ)
	Если ОбменДанными.Загрузка Тогда
		Возврат; // не отражать обратно то, что пришло обменом
	КонецЕсли;
	Данные = Новый Соответствие;
	Данные.Вставить("ref", Строка(Ссылка.УникальныйИдентификатор()));
	Данные.Вставить("code", Код);
	Данные.Вставить("name", Наименование);
	Данные.Вставить("deleted", ПометкаУдаления);
	ОчередьKafka.Поставить("erp.nomenclature.v1", Строка(Ссылка.УникальныйИдентификатор()),
		"erp.nomenclature.changed", Данные);
КонецПроцедуры
```

```bsl
// Общий модуль ОчередьKafka (сервер)
Процедура Поставить(Тема, Ключ, ТипСобытия, Данные) Экспорт
	Ид = Строка(Новый УникальныйИдентификатор);
	Конверт = Новый Соответствие;
	Конверт.Вставить("id", Ид);
	Конверт.Вставить("type", ТипСобытия);
	Конверт.Вставить("version", 1);
	Конверт.Вставить("source", "erp-1c");
	Конверт.Вставить("created", XMLСтрока(ТекущаяУниверсальнаяДата()) + "Z");
	Конверт.Вставить("payload", Данные);

	Запись = РегистрыСведений.ОчередьОтправкиKafka.СоздатьМенеджерЗаписи();
	Запись.ИдСообщения = Ид;
	Запись.Тема = Тема;
	Запись.Ключ = Ключ;
	Запись.Тело = ОбменJSON.ВJSON(Конверт);
	Запись.Создано = ТекущаяУниверсальнаяДата();
	Запись.Записать();
КонецПроцедуры
```

Если транзакция записи документа откатится, откатится и запись в очередь — «фантомных» сообщений о несохранённых данных не будет. Это то же поведение, что у сервисов интеграции: при вызове `ОтправитьСообщение()` в транзакции сообщение попадает в очередь только при её фиксации [ИТС-разр гл. 17.8.6.2].

### 4.3. Отправка очереди

Порядок: выбрать порцию по возрастанию `Создано` → отправить → удалить отправленные. При ошибке — увеличить `Попыток`, записать текст и **остановиться** (не отправлять следующие для той же темы), иначе нарушится порядок. Так же поступает платформа: если первое сообщение канала не ушло, остальные не отправляются, пока не уйдёт оно [ИТС-разр гл. 17.8.6.2].

Сообщения с одинаковым ключом отправляйте последовательно в одном запросе/пакете; производитель Kafka с идемпотентностью (умолчание) не создаст дублей при повторе внутри одной сессии [Kafka-код 4.4 `ProducerConfig`], но повтор **после** сбоя 1С (отправили, а удалить из очереди не успели) даст дубль — его отсекает идемпотентный получатель.

## 5. Идемпотентный приём

```bsl
// Общий модуль ПриёмKafka (сервер)
Функция УжеОбработано(Ид)
	Запрос = Новый Запрос("ВЫБРАТЬ ПЕРВЫЕ 1 1 ИЗ РегистрСведений.ОбработанныеСообщенияKafka ГДЕ ИдСообщения = &Ид");
	Запрос.УстановитьПараметр("Ид", Ид);
	Возврат Не Запрос.Выполнить().Пустой();
КонецФункции

Процедура ОбработатьСообщение(Тема, Текст) Экспорт
	Конверт = ОбменJSON.ИзJSON(Текст);
	Ид = Конверт.Получить("id");
	НачатьТранзакцию();
	Попытка
		Блокировка = Новый БлокировкаДанных;
		Элемент = Блокировка.Добавить("РегистрСведений.ОбработанныеСообщенияKafka");
		Элемент.УстановитьЗначение("ИдСообщения", Ид);
		Блокировка.Заблокировать();
		Если Не УжеОбработано(Ид) Тогда
			ЗагрузитьДанные(Конверт);                 // прикладная загрузка
			Запись = РегистрыСведений.ОбработанныеСообщенияKafka.СоздатьМенеджерЗаписи();
			Запись.ИдСообщения = Ид;
			Запись.Тема = Тема;
			Запись.Обработано = ТекущаяУниверсальнаяДата();
			Запись.Записать();
		КонецЕсли;
		ЗафиксироватьТранзакцию();
	Исключение
		ОтменитьТранзакцию();
		ВызватьИсключение;
	КонецПопытки;
КонецПроцедуры
```

Отметка «обработано» и сами данные пишутся в одной транзакции; смещение в Kafka фиксируется **после** неё. Сбой между ними → сообщение придёт снова → `УжеОбработано` вернёт `Истина`. Регистр обработанных периодически чистите старше срока хранения темы (раздел 6.5 `01-…`).

Ошибка в данных одного сообщения не должна останавливать весь обмен навсегда: после N неудач откладывайте сообщение в регистр «Ошибки приёма» (или отдельную тему-«отстойник» в Kafka) и идите дальше [практика]. В Kafka 4.4 есть очереди-«отстойники» (DLQ) только для share-групп, обычным группам потребителей это не помогает [Kafka-док 4.4 `upgrade`].

## 6. Способ А: HTTP-мост (Strimzi HTTP Bridge)

### 6.1. Что это

Отдельный Java-процесс, который принимает REST-запросы и работает с Kafka как обычный клиент. Выпуск **1.2.0** от 01.10.2026, лицензия Apache 2.0 [Strimzi; API выпусков GitHub]. Рассчитан и на Kubernetes (оператор Strimzi), и на запуск отдельно: `bin/kafka_bridge_run.sh --config-file config/application.properties` [Strimzi README]. Образ — `quay.io/strimzi/kafka-bridge` (метка для 1.2.0 — ⚠ сверить на quay.io), внутри Java 21 на UBI 9 [Strimzi `Dockerfile`].

Альтернатива — Confluent REST Proxy, но его лицензия не Apache (Confluent Community License) [сторонний: репозиторий `confluentinc/kafka-rest`]; для внутреннего использования это обычно допустимо ⚠ — прочитайте условия.

### 6.3. Защита

Мост **сам не проверяет подлинность HTTP-клиентов**; документация предлагает для этого внешний обратный прокси с TLS [Strimzi «Securing connectivity»]. TLS на самом мосте включается `http.ssl.enable=true` (протоколы по умолчанию TLSv1.2, TLSv1.3), но служебные адреса `/ready`, `/healthy`, `/metrics` остаются без TLS [Strimzi]. Практичная схема — Apache на том же узле:

```apache
# /etc/apache2/sites-available/kafka-bridge.conf (фрагмент)
<VirtualHost *:443>
    ServerName kafka-bridge.example.local
    SSLEngine on
    SSLCertificateFile    /etc/ssl/certs/kafka-bridge.pem
    SSLCertificateKeyFile /etc/ssl/private/kafka-bridge.key
    <Location />
        AuthType Basic
        AuthName "kafka-bridge"
        AuthUserFile /etc/apache2/kafka-bridge.htpasswd
        Require valid-user
    </Location>
    ProxyPass        / http://127.0.0.1:8080/
    ProxyPassReverse / http://127.0.0.1:8080/
</VirtualHost>
```

Мост при этом слушает `http.host=127.0.0.1`. Как настраивать TLS, Basic и обратный прокси в Apache — `../apache/02-…`, `../apache/03-…`. Мост ходит в Kafka от одной учётной записи (`bridge`) — права в Kafka (ACL) общие для всех, кто дошёл до моста; разные системы — разные экземпляры моста или разграничение путей в прокси [практика].

### 6.4. Отправка из 1С

```bsl
// Общий модуль КафкаМост (сервер)
Функция Соединение()
	// Параметры подключения храните в безопасном хранилище (БСП) или в константах с ограниченными правами
	Возврат Новый HTTPСоединение("kafka-bridge.example.local", 443, "erp-1c", ПарольМоста(), , 30,
		Новый ЗащищенноеСоединениеOpenSSL());
КонецФункции

// Записи — массив структур с полями Ключ, Тело (строка JSON)
// Возвращает массив смещений или вызывает исключение
Функция Отправить(Тема, Записи) Экспорт
	СписокЗаписей = Новый Массив;
	Для Каждого З Из Записи Цикл
		Элемент = Новый Соответствие;
		Элемент.Вставить("key", З.Ключ);
		Элемент.Вставить("value", ОбменJSON.ИзJSON(З.Тело)); // формат json: value — объект JSON
		СписокЗаписей.Добавить(Элемент);
	КонецЦикла;
	Тело = Новый Соответствие;
	Тело.Вставить("records", СписокЗаписей);

	Запрос = Новый HTTPЗапрос("/topics/" + Тема);
	Запрос.Заголовки.Вставить("Content-Type", "application/vnd.kafka.json.v2+json");
	Запрос.Заголовки.Вставить("Accept", "application/vnd.kafka.v2+json");
	Запрос.УстановитьТелоИзСтроки(ОбменJSON.ВJSON(Тело), КодировкаТекста.UTF8,
		ИспользованиеByteOrderMark.НеИспользовать);
	Ответ = Соединение().ОтправитьДляОбработки(Запрос);
	ТекстОтвета = Ответ.ПолучитьТелоКакСтроку(КодировкаТекста.UTF8);
	Если Ответ.КодСостояния <> 200 Тогда
		ВызватьИсключение СтрШаблон("Мост Kafka: %1 %2", Ответ.КодСостояния, ТекстОтвета);
	КонецЕсли;
	Результат = ОбменJSON.ИзJSON(ТекстОтвета);
	Смещения = Результат.Получить("offsets");
	Для Каждого С Из Смещения Цикл
		Если С.Получить("error_code") <> Неопределено Тогда
			ВызватьИсключение СтрШаблон("Мост Kafka, запись не принята: %1", ТекстОтвета);
		КонецЕсли;
	КонецЦикла;
	Возврат Смещения;
КонецФункции
```

Формат запроса и ответа: `POST /topics/{тема}`, тело `{"records":[{"key":…, "value":…, "partition":…, "headers":[{"key":…, "value":"<base64>"}]}]}`; ответ 200 `{"offsets":[{"partition":2,"offset":0},…]}`, ошибки 404 (нет темы) и 422 (неверные записи) с `{"error_code":…, "message":…}` [Strimzi API]. Может ли в ответе 200 отдельная запись прийти с `error_code` — ⚠ (в модели `OffsetRecordSent` описаны только `partition` и `offset`; проверка в коде — на всякий случай). Тип `application/vnd.kafka.json.v2+json` требует, чтобы `value` был JSON; для произвольной строки — `application/vnd.kafka.text.v2+json`, для двоичных данных — `…binary…` (значение в base64) [Strimzi API].

Регламентное задание отправки (по шаблону outbox, раздел 4.3):

```bsl
Процедура ОтправкаВKafka() Экспорт
	Запрос = Новый Запрос(
	"ВЫБРАТЬ ПЕРВЫЕ 200 О.ИдСообщения, О.Тема, О.Ключ, О.Тело
	|ИЗ РегистрСведений.ОчередьОтправкиKafka КАК О
	|УПОРЯДОЧИТЬ ПО О.Тема, О.Создано");
	Таблица = Запрос.Выполнить().Выгрузить();
	Для Каждого Тема Из ОбщегоНазначенияКлиентСервер.СвернутьМассив(Таблица.ВыгрузитьКолонку("Тема")) Цикл
		Строки = Таблица.НайтиСтроки(Новый Структура("Тема", Тема));
		Пакет = Новый Массив;
		Для Каждого С Из Строки Цикл
			Пакет.Добавить(Новый Структура("Ключ, Тело", С.Ключ, С.Тело));
		КонецЦикла;
		Попытка
			КафкаМост.Отправить(Тема, Пакет);
		Исключение
			ОтметитьОшибку(Строки, ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
			Продолжить; // эта тема ждёт следующего запуска, порядок не нарушен
		КонецПопытки;
		Для Каждого С Из Строки Цикл
			Набор = РегистрыСведений.ОчередьОтправкиKafka.СоздатьНаборЗаписей();
			Набор.Отбор.ИдСообщения.Установить(С.ИдСообщения);
			Набор.Записать(); // пустой набор = удаление
		КонецЦикла;
	КонецЦикла;
КонецПроцедуры
```

`ОбщегоНазначенияКлиентСервер.СвернутьМассив` и `ОбработкаОшибок.ПодробноеПредставлениеОшибки` — из БСП и платформы 8.3.17+ соответственно ⚠ (без БСП свернуть массив вручную; в старых версиях — `ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())`). Удаление по одной записи — для наглядности; для больших очередей удаляйте набором.

### 6.5. Приём в 1С через мост

У моста потребитель — объект **внутри процесса моста**: его создают, подписывают на темы, опрашивают и удаляют [Strimzi API]:

| Шаг | Запрос | Ответ |
|---|---|---|
| Создать | `POST /consumers/{группа}`, `Content-Type: application/vnd.kafka.v2+json`, тело `{"name":"erp-1c-1","format":"json","auto.offset.reset":"earliest","enable.auto.commit":false}` | 200 `{"instance_id":…, "base_uri":…}`; 409 — такой уже есть |
| Подписать | `POST /consumers/{группа}/instances/{имя}/subscription`, `{"topics":["site.orders.v1"]}` | 204 |
| Получить | `GET …/instances/{имя}/records?timeout=3000&max_bytes=1000000`, `Accept: application/vnd.kafka.json.v2+json` | 200 — массив `{topic,key,value,partition,offset}`; **первый** опрос после подписки обычно пустой (идёт распределение разделов); 404 — потребителя нет |
| Зафиксировать | `POST …/instances/{имя}/offsets` без тела | 204 — зафиксированы смещения всех полученных записей |
| Удалить | `DELETE …/instances/{имя}` | 204 |

```bsl
Процедура ПриёмИзKafka() Экспорт
	Группа = "erp-1c-orders"; Имя = "erp-1c-1";
	База = "/consumers/" + Группа + "/instances/" + Имя;
	С = КафкаМост.Соединение();
	Запрос = Новый HTTPЗапрос(База + "/records?timeout=3000&max_bytes=1000000");
	Запрос.Заголовки.Вставить("Accept", "application/vnd.kafka.json.v2+json");
	Ответ = С.Получить(Запрос);
	Если Ответ.КодСостояния = 404 Тогда
		КафкаМост.СоздатьПотребителя(Группа, Имя, "site.orders.v1"); // POST /consumers + subscription
		Возврат; // записи придут при следующем запуске
	ИначеЕсли Ответ.КодСостояния <> 200 Тогда
		ВызватьИсключение СтрШаблон("Мост Kafka, приём: %1 %2", Ответ.КодСостояния,
			Ответ.ПолучитьТелоКакСтроку(КодировкаТекста.UTF8));
	КонецЕсли;
	Записи = ОбменJSON.ИзJSON(Ответ.ПолучитьТелоКакСтроку(КодировкаТекста.UTF8));
	Если Записи.Количество() = 0 Тогда
		Возврат;
	КонецЕсли;
	Для Каждого З Из Записи Цикл
		ПриёмKafka.ОбработатьСообщение(З.Получить("topic"), ОбменJSON.ВJSON(З.Получить("value")));
	КонецЦикла; // исключение здесь = смещения не зафиксированы, пакет придёт снова
	Фиксация = Новый HTTPЗапрос(База + "/offsets");
	Фиксация.Заголовки.Вставить("Content-Type", "application/vnd.kafka.v2+json");
	Ответ = С.ОтправитьДляОбработки(Фиксация);
	Если Ответ.КодСостояния <> 204 Тогда
		ВызватьИсключение СтрШаблон("Мост Kafka, фиксация смещений: %1", Ответ.КодСостояния);
	КонецЕсли;
КонецПроцедуры
```

Особенности [Strimzi; выводы — практика]:

- Потребитель с одним именем живёт в **одном** экземпляре моста. За балансировщиком из нескольких мостов запросы одного потребителя должны приходить на тот же экземпляр (привязка сеанса) — или держите один мост на группу.
- Если регламентное задание не опрашивает дольше `max.poll.interval.ms` клиента Kafka (по умолчанию 300 000 мс = 5 минут [Kafka-код 4.4 `ConsumerConfig`]; переопределяется ли он у потребителей моста — ⚠), группа считает потребителя мёртвым и перераспределяет разделы; следующий опрос может вернуть ошибку. Расписание задания — чаще этого срока.
- Перезапуск моста удаляет всех потребителей — код выше пересоздаёт его по 404.
- Регламентные задания 1С одного имени не выполняются параллельно в одной базе ⚠ (сверить поведение для заданий с одинаковым ключом); если запустить приём в нескольких базах/заданиях — давайте разные `name` в одной группе: Kafka распределит разделы между ними.

### 7.2. Как подключать на сервере 1С

Правила платформы [ИТС-разр гл. 32.1]:

- Компонента в zip-архиве с манифестом хранится в макете конфигурации (`ДвоичныеДанные`) и подключается `ПодключитьВнешнююКомпоненту(<путь к макету>, <имя>, ТипВнешнейКомпоненты.Native, ТипПодключенияВнешнейКомпоненты.Изолированно)`; объект — `Новый("AddIn.<имя>.<класс>")`.
- **Изолированно** — компонента в отдельном хост-процессе; её аварийное завершение не роняет процесс встроенного языка. **Не изолированно** — падение компоненты аварийно завершает процесс (на сервере — `rphost` со всеми его сеансами).
- Если тип подключения не указан: при режиме совместимости 8.3.20 и старше — не изолированно; иначе на сервере — изолированно.
- Если хост-процесс создать не удалось (нет прав), компонента подключится не изолированно — проверьте права пользователя `usr1cv8` и журнал.
- Компонента должна быть написана с учётом работы в хост-процессе; иначе изолированное подключение даст исключение.
- Аварийное завершение изолированной компоненты обрабатывается в `ОбработкаОтключенияВнешнейКомпонентыПриОшибке()` модуля приложения — там переподключают и инициализируют заново.

Администратору:

- Если на базе включён **профиль безопасности** кластера, компонента должна быть в нём разрешена (событие техжурнала `setSecurityProfileAddIn` фиксирует изменение записи профиля) [`../its-docs/adm-pr03-sluzhebnye-fajly-p4.md`]; ошибка «…запрещено профилем безопасности» — `../1c/08-…`.
- Клиент Kafka в компоненте держит соединения и фоновые потоки. Потребителя создавайте в **долгоживущем** фоновом задании (а не на каждый вызов), производителя — переиспользуйте; иначе каждое подключение — новое соединение и перебалансировка группы [практика].
- Компонента на `librdkafka` читает свои параметры (`bootstrap.servers`, `security.protocol`, `sasl.*`, `ssl.ca.location`); путь к файлу УЦ на сервере Linux — например `/etc/ssl/certs/ca-certificates.crt` ⚠ (как компонента принимает настройки — по её документации).

## 8. Способ В: сервис-посредник и «1С:Шина»

### 8.1. Посредник

Внешняя программа (Python, Java, Go или готовая — DaJet, Kafka Connect с коннектором HTTP) забирает из 1С очередь через **HTTP-сервис** 1С (`GET /hs/kafka/outbox?limit=200`, затем `POST /hs/kafka/outbox/ack`) и кладёт в Kafka; обратное направление — читает Kafka и вызывает HTTP-сервис 1С. Плюс — 1С не знает о Kafka, минус — ещё одна программа. Публикация HTTP-сервисов — `../1c/05-…`.

### 8.2. «1С:Шина»

Что видно по открытым материалам:

- сервисы интеграции платформы подключаются к «1С:Шине»: адрес внешнего сервиса, загрузка каналов из «Шины», ключ API информационной системы как имя пользователя и пароль [ИТС-мет i8105995; ИТС-разр гл. 17.8.2, 17.8.5];
- «1С:Шина» обменивается со сторонними брокерами: по AMQP — с **RabbitMQ**, по JMS — с **Apache ActiveMQ Artemis** [ИТС-мет i8105995];
- справочник узлов схемы «1С:Шины» версии 3: `Канал1СИсточник/Назначение`, `ФайлИсточник/Назначение`, `FtpИсточник/Назначение`, `JmsИсточник/Назначение`, `ОчередьШиныИсточник/Назначение`, `Http`, `RabbitMqИсточник/Назначение`, `Sql`, маршрутизатор, транслятор, таймер — **Kafka среди них нет** (оглавление `its.1c.ru/db/esbdoc3`, 20.10.2026);
- в докладе на Infostart (11.10.2023) работа с Kafka через «1С:Шину» оценена как неполноценная [сторонний] — с тех пор могло измениться ⚠.

Если «Шина» уже есть, путь в Kafka — через RabbitMQ (узел `RabbitMqНазначение` → коннектор RabbitMQ для Kafka Connect) или свой сервис ⚠ (схема не проверялась). Подробно о сервисах интеграции, их очередях и фоновых заданиях — `../rabbitmq/03-…`.

## 10. Типовые ошибки

| Симптом | Причина | Решение |
|---|---|---|
| Мост отвечает 404 `The specified topic was not found.` | Темы нет, автосоздание выключено | Создать тему (`01-…`, раздел 6) |
| 422 `The record list contains invalid records.` | Неверный JSON или тип содержимого не тот (`json` требует объект в `value`) | Проверить тело и `Content-Type` |
| 401 от прокси перед мостом | Неверный пароль Basic | Проверить пользователя в `htpasswd` |
| Мост пишет, но сообщения не видны получателю | Получатель в другой группе с `auto.offset.reset=latest` создан позже | `earliest` для новых групп; сдвинуть смещения (`02-…`, 7.3) |
| `GET records` всегда пуст сразу после создания потребителя | Первый опрос запускает распределение разделов | Нормально; данные — со следующего опроса |
| 404 на `GET records` | Мост перезапускался или закрыл брошенного потребителя (`http.timeoutSeconds`) | Пересоздать потребителя (код 6.5 делает это сам) |
| Дубли в 1С | Повтор после сбоя (доставка «хотя бы один раз») | Идемпотентный приём (раздел 5) |
| Нарушен порядок изменений одного объекта | Нет ключа или ключ разный | Ключ = УИД объекта; не отправлять параллельно одну тему |
| Сеансы 1С аварийно завершаются при работе с компонентой | Компонента подключена не изолированно и упала | `ТипПодключенияВнешнейКомпоненты.Изолированно`; обработчик отключения |
| Ошибка «…запрещено профилем безопасности» при подключении компоненты | Профиль безопасности базы | Разрешить компоненту в профиле (`../1c/08-…`) |
