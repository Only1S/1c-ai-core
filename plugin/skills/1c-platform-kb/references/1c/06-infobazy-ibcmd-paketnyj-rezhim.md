## Кратко — 20 главных фактов и команд

1. С базой из командной строки работают три инструмента: `rac` (через кластер: регистрация, блокировки, сеансы), `1cv8 DESIGNER` (пакетный режим конфигуратора: нужен толстый клиент и X-сервер) и `ibcmd` (напрямую с СУБД, без кластера и без графики) [офиц.].
2. `ibcmd` и `ibsrv` **нельзя применять к базе, которая в этот момент обслуживается кластером серверов** — документация прямо предупреждает о возможном разрушении базы данных. Перед `ibcmd` базу нужно освободить (надёжнее всего — остановить службу сервера 1С) [офиц.].
3. Создать базу в кластере и в PostgreSQL одной командой [практика, синтаксис `rac help infobase`]:
   ```bash
   $B/rac infobase --cluster=$CL create --create-database --name=demo --dbms=PostgreSQL \
        --db-server=localhost --db-name=demo --locale=ru_RU --db-user=postgres --db-pwd='***' \
        --license-distribution=allow --scheduled-jobs-deny=off
   ```
4. То же через клиент: `1cv8 CREATEINFOBASE 'Srvr="srv1c";Ref="demo";DBMS=PostgreSQL;DBSrvr="localhost";DB="demo";DBUID="postgres";DBPwd="***";CrSQLDB=Y;LicDstr=Y;Locale=ru_RU' /Out /tmp/create.log /DumpResult /tmp/create.res` [офиц.]. Добавление базы в список `ibases.v8i` — отдельной командой: в документации 8.3.27 она записана как `/AddToList [<имя>]`, а библиотека v8runner (и старая справка) используют `/AddInList<имя>`; официальное написание по документации 8.3.27 — `/AddToList [<имя ИБ>]` (приложение 7, сверено 10.10.2026); какое написание принимает ваша сборка, не подтверждено — на сервере без графики список баз не нужен, команду проще не указывать.
5. Пользователю PostgreSQL привилегия `SUPERUSER` нужна только в момент создания ИБ; потом её можно снять: `ALTER USER dbuser WITH NOSUPERUSER;` [офиц.].
6. Если база данных уже содержит данные ИБ 1С, регистрация в кластере просто подключает её; если база пустая — в ней создаётся новая ИБ [офиц.]. Так регистрируют восстановленные из `pg_restore` копии.
7. Синтаксис `ibcmd`: `ibcmd <режим> <команда> [--параметр[=значение]]`. Параметры СУБД: `--dbms=PostgreSQL --db-server=… --db-name=… --db-user=… --db-pwd=…` (или `-W` — пароль из stdin), пользователь ИБ: `--user=… --password=…`, каталог служебных данных: `--data=…`, либо всё в YAML: `--config=файл.yml` [офиц.].
8. Выгрузка и загрузка `.dt` без графики: `ibcmd infobase dump … /backup/demo.dt`, `ibcmd infobase restore … /backup/demo.dt`. Выгрузка `.dt` **не является резервной копией** [офиц.].
9. Загрузка конфигурации и обновление БД: `ibcmd infobase config load … 1Cv8.cf`, затем `ibcmd infobase config apply … --force` [офиц.].
10. Пакетный режим конфигуратора на сервере без монитора запускают через виртуальный дисплей [практика]:
    ```bash
    xvfb-run -a $B/1cv8 DESIGNER /S "srv1c/demo" /N "Администратор" /P "***" \
        /DisableStartupDialogs /DisableStartupMessages /Out /tmp/1c.log /DumpResult /tmp/1c.res \
        /DumpIB /backup/demo.dt
    ```
11. Адрес базы в `/S` на Linux пишется через прямой слеш: `/S "srv1c/demo"` [офиц.].
12. Коды возврата пакетного режима конфигуратора: `0` — успех, `1` — ошибка, `101` — ошибки в данных. Текст сообщений — в файле `/Out` (UTF-8), число результата — в файле `/DumpResult` [офиц.].
13. Обновление конфигурации на поддержке: `/UpdateCfg <файл .cfu или .cf> -Settings <файл> [-force]`, затем в той же строке `/UpdateDBCfg [-Dynamic-] [-Server] [-SessionTerminate force]` [офиц.]. На практике для типовой конфигурации без доработок `-Settings` не указывают: так вызывают `/UpdateCfg` библиотека v8runner и `vrunner cf vendor-update` (у него файл настроек — необязательная опция `--update-settings`) [практика].
14. Вход в заблокированную базу — параметр `/UC <код разрешения>`; блокировку ставит `rac infobase update --sessions-deny=on --permission-code=<код>` [офиц. + практика].
15. Расширение `.cfe`: загрузка `/LoadCfg файл.cfe -Extension Имя` + `/UpdateDBCfg -Extension Имя`; удаление `/DeleteCfg -Extension Имя`; через `ibcmd` — `config load --extension=Имя`, `config apply --extension=Имя`, `extension delete --name=Имя` [офиц.].
16. Режим агента конфигуратора: `1cv8 DESIGNER /S "srv1c/demo" /AgentMode /AgentSSHHostKeyAuto`; слушает `127.0.0.1:1543`, команды подаются по SSH, файлы — по SFTP [офиц.].
17. Сервер хранилища конфигураций: `crserver -port 1542 -d /var/lib/1c/crs [-daemon]`; адрес для разработчиков `tcp://srv1c/имя` либо `http://srv1c/repo/repo.1ccr/имя` через Apache. Версии конфигуратора и сервера хранилища должны совпадать [офиц., старая редакция + практика].
18. Список баз клиента на Linux: `~/.1C/1cestart/ibases.v8i` (UTF-8); настройки программы запуска: `~/.1C/1cestart/1cestart.cfg` (UTF-16LE). Общий файл `1cescmn.cfg` в Linux не используется [офиц.].
19. Копия базы внутри сервера PostgreSQL: `createdb -T demo demo_copy` (к исходной базе не должно быть ни одного подключения) или `pg_dump -Fc demo | pg_restore -d demo_copy`, затем регистрация в кластере `rac infobase create … --db-name=demo_copy --scheduled-jobs-deny=on` [офиц. PostgreSQL + практика].
20. Автоматизация: OneScript 2.x (на .NET 8) + vanessa-runner 3.0 (`vrunner infobase update`, `vrunner cluster session lock`; требует OneScript 2.0.0+), gitsync 3.9.0 (хранилище → git; требует OneScript 2.2.1+), 1C:EDT с `1cedtcli` [офиц. сайты проектов].

## 1. Инструменты и общие правила

### 1.1. Что чем делается

| Задача | `rac` (+ `ras`) | `1cv8 DESIGNER` (пакетный режим) | `ibcmd` |
|---|---|---|---|
| Создать базу в PostgreSQL и зарегистрировать в кластере | да (`infobase create --create-database`) | да (`CREATEINFOBASE`, режим клиента) | создаёт базу в СУБД, но в кластере не регистрирует |
| Заблокировать сеансы и регламентные задания, завершить сеансы | да | нет | только для автономного сервера |
| Выгрузить / загрузить `.dt` | нет | `/DumpIB`, `/RestoreIB` | `infobase dump`, `infobase restore` |
| Загрузить `.cf`, обновить конфигурацию БД | нет | `/LoadCfg`, `/UpdateCfg`, `/UpdateDBCfg` | `config load`, `config apply` |
| Обновление по `.cfu` (конфигурация на поддержке) | нет | `/UpdateCfg` | в 8.3.x нет; в 8.5.4 появилась команда `ibcmd config update` («прямая загрузка обновления в основную конфигурацию» — существование команды подтверждено V8Update 8.5.4 и обзором «Новое в платформе 8.5.4») — ⚠ не подтверждено: форматы файлов и параметры (документация 8.5.4 на ИТС закрыта; смотреть `ibcmd help config`) |
| Выгрузка / загрузка конфигурации в XML | нет | `/DumpConfigToFiles`, `/LoadConfigFromFiles` | `config export`, `config import` |
| Тестирование и исправление | нет | `/IBCheckAndRepair` | нет (есть только `config repair` — восстановление после незавершённой операции) |
| Хранилище конфигурации | нет | `/ConfigurationRepository*` | нет |
| Нужен графический стек (X-сервер) | нет | да | нет |
| Нужен запущенный кластер | да | да (для клиент-серверной базы) | нет, и база должна быть свободна от кластера |

### 1.2. Переменные, используемые в примерах

```bash
V=8.3.27.2074                      # ваша сборка: ls /opt/1cv8/x86_64/
B=/opt/1cv8/x86_64/$V              # каталог версии платформы
RAC="$B/rac"                       # по умолчанию обращается к ras на localhost:1545
CL=$($RAC cluster list | awk -F' *: *' '$1=="cluster"{print $2; exit}')   # UUID кластера
```

`rac` требует работающего сервера администрирования `ras` (порт 1545) той же линейки версий. Вывод `rac` — строки `имя : значение`, объекты разделены пустой строкой; код возврата `0` при успехе, текст ошибки — в stderr [офиц.].

### 1.3. Правила записи командной строки 1С [офиц.]

- Команды `1cv8` начинаются с `/`, параметры команд — с `-`. У `ibcmd`, `rac`, `ras` полное имя параметра начинается с `--`, короткое — с `-`.
- Угловые скобки из описаний (`<имя файла>`) в команду не переносят: для оболочки это перенаправление ввода-вывода.
- Значение с пробелами берут в кавычки. Кавычка внутри значения пишется как `\"`, обратная косая черта перед кавычкой — как `\\`. В `/IBName` и `/IBConnectionString` внутренние кавычки удваиваются.
- В bash строку соединения удобнее целиком брать в одинарные кавычки: `'Srvr="srv1c";Ref="demo";'`.
- Если в команде указан файл с полным путём, все каталоги этого пути должны существовать заранее.
- Длинную командную строку можно вынести в файл: `1cv8 /@ /path/cmd.txt` (команда в файле одной строкой, `/@` должна быть первой).

## 2. Создание информационной базы на PostgreSQL

### 2.1. Требования к PostgreSQL и к пользователю СУБД

| Требование | Значение | Статус |
|---|---|---|
| Сборка PostgreSQL | с патчем 1С (от фирмы «1С» или Postgres Pro) либо Postgres Pro Standard / Enterprise | [офиц.] |
| Версии PostgreSQL в документации 8.3.27 | 8.1.5, 8.2.4, 8.3.8, 8.4.3, 9.0.3, 9.1–9.4, 9.6, 10, 11, 12, 13, 14, 15, 16, 17 (раздел 1.5.6; версии 18 в перечне нет — её поддержку проверять по документации своей сборки платформы) | [офиц., англ. редакция руководства 8.3.27 — перепроверено 2026-10-10] |
| Права пользователя СУБД | `SUPERUSER` — только на момент создания ИБ, затем можно отозвать | [офиц.] |
| Пользовательские табличные пространства | для их создания пользователю нужна роль `SUPERUSER` | [офиц.] |
| Имя базы данных | до 63 символов, первый символ — буква или `_`, далее буквы, `_`, `$`; без пробелов; не зарезервированное слово | [офиц.] |
| Нестандартный порт PostgreSQL | в поле сервера СУБД: `localhost port=5433;` | [офиц.] |
| Кто подключается к СУБД | рабочие процессы кластера (`rphost`), а не клиент; `localhost` в параметре сервера СУБД означает машину сервера 1С | [офиц.] |

Практика выбора пользователя [практика]:

- Простой вариант: база создаётся от роли `postgres` (или другой роли с `SUPERUSER`), она же остаётся владельцем.
- Аккуратный вариант: отдельная роль, например `usr1c`; на время создания базы дать ей `SUPERUSER`, после успешного создания выполнить `ALTER USER usr1c WITH NOSUPERUSER;`. Роль остаётся владельцем базы и сохраняет все права внутри неё.
- Роль PostgreSQL и системный пользователь `usr1cv8` — разные сущности; совпадение имён необязательно.

```bash
# роль для 1С (пароль запросит интерактивно)
sudo -u postgres createuser --superuser --pwprompt usr1c
# после создания информационной базы:
sudo -u postgres psql -c "ALTER USER usr1c WITH NOSUPERUSER;"
```

**Уточнено 10.10.2026** (полный русский текст документации 8.3.27, глава 5, разд. 5.2.1.3.3): пользователь СУБД должен обладать `SUPERUSER` только в момент создания информационной базы, после чего привилегию можно отозвать (`alter user dbuser with nosuperuser;`); о `CREATEDB` для PostgreSQL документация не говорит. Ранее было не подтверждено: достаточно ли для создания базы средствами 1С привилегии `CREATEDB` без `SUPERUSER`. Документация 8.3.27 (русская и англоязычная редакции, глава о списке информационных баз) называет именно `SUPERUSER` — «только на момент создания информационной базы» (для IBM Db2 — «`CREATEDB` или `SUPERUSER` либо собственник базы»). Считайте `SUPERUSER` обязательным: при создании ИБ в базе появляются объекты модулей патча 1С (`mchar`, `mvarchar` и др.) с функциями на языке C, а такие объекты в PostgreSQL создаёт только суперпользователь [офиц. PostgreSQL / Postgres Pro — по смыслу; прямого текста 1С о причине нет]. Требование относится к моменту создания **информационной базы**, а не только базы данных: если пустую базу данных заранее создал `postgres` (раздел 2.6), роли 1С на время первой регистрации всё равно нужен `SUPERUSER`.

### 2.2. Способ 1: `rac infobase create`

Требуется: работает служба сервера 1С (`srv1cv8-$V@default`), работает `ras`, известен UUID кластера.

```bash
$RAC infobase --cluster=$CL create \
     --create-database \
     --name=demo \
     --dbms=PostgreSQL \
     --db-server=localhost \
     --db-name=demo \
     --locale=ru_RU \
     --db-user=usr1c \
     --db-pwd='Secret#1' \
     --descr="Демонстрационная база" \
     --license-distribution=allow \
     --scheduled-jobs-deny=off
# ответ:  infobase : 7c4f1e2a-…   (UUID новой базы)
```

Параметры команды `create` (по встроенной справке `rac help infobase`; документация ИТС отсылает к `rac help`). Перепроверено 2026-10-10 по исходному коду vanessa-runner 2.6 — он формирует именно такие командные строки: `infobase create --create-database --name=… --dbms=… --db-server=… --db-name=… --locale=… --db-user=… --db-pwd=… --license-distribution=…`, `infobase update … --sessions-deny=… --denied-message=… --denied-from=… --denied-to=… --permission-code=…`, `infobase update … --scheduled-jobs-deny=…`, `infobase summary list`, `session list --infobase=…`, `session terminate --session=…`, `connection list --infobase=…`, а допустимые значения `--dbms` описывает как `MSSQLServer|PostgreSQL|IBMDB2|OracleDatabase` [практика]. ⚠ не подтверждены независимым источником только `--descr`, `--date-offset`, `--security-level` у `create` (записаны по справке `rac`, в коде vanessa-runner не используются) — сверить по `rac help infobase`:

| Параметр | Назначение | Значения |
|---|---|---|
| `--cluster=<uuid>` | кластер (общий параметр режима) | обязателен |
| `--cluster-user=<имя>`, `--cluster-pwd=<пароль>` | администратор кластера | нужны, если в кластере заведены администраторы |
| `--create-database` | создать базу данных в СУБД, если её нет | флаг |
| `--name=<имя>` | имя ИБ в кластере (уникально, регистр не важен) | обязателен |
| `--dbms=<тип>` | тип СУБД | `MSSQLServer`, `PostgreSQL`, `IBMDB2`, `OracleDatabase`; обязателен |
| `--db-server=<хост>` | сервер СУБД (с точки зрения сервера 1С) | обязателен; порт: `"localhost port=5433"` |
| `--db-name=<имя>` | имя базы данных | обязателен |
| `--locale=<код>` | национальные настройки ИБ | обязателен; `ru_RU` (встречается и `ru`) |
| `--db-user=<имя>`, `--db-pwd=<пароль>` | пользователь СУБД и его пароль | — |
| `--descr=<текст>` | описание | — |
| `--date-offset=<число>` | смещение дат | `0` или `2000`; имеет смысл только для MS SQL Server |
| `--security-level=<уровень>` | уровень безопасности соединений | `0`, `1`, `2` |
| `--scheduled-jobs-deny=on\|off` | блокировка регламентных заданий | для копий баз ставить `on` |
| `--license-distribution=deny\|allow` | выдача клиентских лицензий сервером | `allow` — сервер выдаёт лицензии клиентам |
| `--db-schema=<схема>` | схема PostgreSQL для таблиц ИБ (вместо `public`) | только 8.5.4+ |

Сопутствующие команды:

```bash
$RAC infobase --cluster=$CL summary list                  # список баз: infobase, name, descr
IB=$($RAC infobase --cluster=$CL summary list | awk -F' *: *' -v n=demo \
      '$1=="infobase"{id=$2} $1=="name"{gsub(/"/,"",$2); if($2==n){print id; exit}}')
$RAC infobase --cluster=$CL info   --infobase=$IB --infobase-user=Администратор --infobase-pwd='***'
$RAC infobase --cluster=$CL update --infobase=$IB --infobase-user=Администратор --infobase-pwd='***' \
     --descr="Новое описание" --license-distribution=allow
# удалить регистрацию; базу в СУБД: оставить (без флагов), очистить или удалить
$RAC infobase --cluster=$CL drop   --infobase=$IB --infobase-user=Администратор --infobase-pwd='***' \
     [--clear-database | --drop-database]
```

Пояснения:

- `--infobase-user` / `--infobase-pwd` — администратор **информационной базы**; нужны, когда в базе уже есть пользователи. В пустой базе пользователей нет, параметры опускают.
- Удаление [офиц.]: «Удалить базу данных» (`--drop-database`), «Очистить базу данных» (`--clear-database`), «Оставить без изменений» (без флагов). Если при удалении с `--drop-database` к базе подключены пользователи, регистрация удалится, а СУБД вернёт ошибку и саму базу не удалит.
- Изменения по версиям [офиц., V8Update]: 8.3.16 — параметр резервирования рабочих процессов; 8.3.24 — свойство `disable-local-speech-to-text`; 8.3.25 — параметры задержки выгрузки конфигурации рабочим процессом и запуска регламентных заданий без активных пользователей; 8.3.27 — режим `rac binary-data-storage`, «уточнено назначение параметров режима `infobase`»; 8.5.4 — `rac infobase create` принимает все параметры, которые раньше задавались только через `update`, `rac infobase info` выводит имя, версию и поставщика конфигурации, добавлен `--db-schema`; у `rac infobase update` появились `--allow-arbitrary-safe-mode-security-profile-setting` и `--allowed-additional-safe-mode-security-profiles`; у команд `rac connection` и `rac binary-data-storage` **удалены** параметры `--infobase-user` и `--infobase-pwd` (скрипты, передающие их в `rac connection list`, для 8.5.4 нужно править) [перепроверено по V8Update 8.5.4].

### 2.3. Способ 2: `1cv8 CREATEINFOBASE` со строкой соединения

Режим создания базы есть у клиентского приложения (`1cv8`, `1cv8c`). На сервере без графики запускается через `xvfb-run` (раздел 4.1).

```bash
xvfb-run -a $B/1cv8 CREATEINFOBASE \
  'Srvr="srv1c";Ref="demo";DBMS=PostgreSQL;DBSrvr="localhost";DB="demo";DBUID="usr1c";DBPwd="Secret#1";CrSQLDB=Y;SchJobDn=N;LicDstr=Y;Locale=ru_RU' \
  /Out /tmp/createib.log /DumpResult /tmp/createib.res
cat /tmp/createib.res      # 0 — успех
# добавить базу в список ibases.v8i текущего пользователя (на сервере обычно не нужно):
#   … /AddToList "Демо (сервер)"      — написание из документации 8.3.27
#   … /AddInList"Демо (сервер)"       — написание, которое использует v8runner (слитно с именем); см. ⚠ ниже
```

Синтаксис [офиц., 8.3.27]:

```text
1cv8 CREATEINFOBASE <строка соединения> [/AddToList [<имя ИБ>]] [/UseTemplate <имя файла шаблона>]
     [/Out <имя файла>] [/L<код языка>] [/VL<код локализации>] [/O<скорость соединения>] [/DumpResult <имя файла>]
```

| Команда | Назначение |
|---|---|
| `/AddToList [<имя>]` | добавить созданную базу в список баз (`ibases.v8i`) под указанным именем; без команды в список не добавляется. В старой справке (8.3.3–8.3.8), во многих статьях и в актуальном коде библиотеки v8runner (`ПараметрыЗапуска.Добавить("/AddInList""" + ИмяБазыВСписке + """")` — и для файловой, и для серверной базы) команда записана как `/AddInList`. **Официальное написание — `/AddToList`** (документация 8.3.27, приложение 7, «Запуск в режиме создания информационной базы»: `1cv8 CREATEINFOBASE <строка соединения> [/AddToList [<имя ИБ>]] [/UseTemplate <имя файла шаблона>] [/Out <имя файла>] [/L<код языка>] [/VL<код локализации>] [/O<скорость соединения>] [/DumpResult <имя файла>]`; сверено по тексту ИТС 10.10.2026, конспект — `../its-docs/adm-pr07-parametry-zapuska-1cv8-p1.md`). Написания `/AddInList` в документации 8.3.27 нет; принимает ли его платформа для совместимости — живой проверки нет. Если база в списке нужна, проверьте оба варианта на своей сборке и посмотрите, появилась ли секция в `~/.1C/1cestart/ibases.v8i` (как платформа реагирует на нераспознанное написание — тоже не проверено, поэтому результат смотрите в `/DumpResult` и `/Out`) |
| `/UseTemplate <файл>` | создать базу из шаблона: файл конфигурации `.cf` или выгрузка `.dt` |
| `/Out <файл> [-NoTruncate]` | файл служебных сообщений (UTF-8) |
| `/DumpResult <файл>` | записать числовой результат; `0` — успех |
| `/L<код>`, `/VL<код>` | язык интерфейса и локализация сеанса (например `/Lru /VLru_RU`) |

Параметры строки соединения. Фрагменты вида `Имя=Значение` разделяются `;`, значение с пробелами берут в двойные кавычки [офиц.].

| Параметр | Назначение | Значения и умолчания |
|---|---|---|
| `Srvr` | адрес кластера серверов 1С: `[tcp://]<адрес>[:<порт>]` | порт главного менеджера по умолчанию 1541; допустим список через запятую без пробелов: `srv1,srv2:1641` |
| `Ref` | имя ИБ в кластере | — |
| `DBMS` | тип СУБД | `MSSQLServer`, `PostgreSQL`, `IBMDB2`, `OracleDatabase` |
| `DBSrvr` | сервер СУБД | для нестандартного порта PostgreSQL: `"localhost port=5433"` |
| `DB` | имя базы данных | — |
| `DBUID` | пользователь СУБД | — |
| `DBPwd` | пароль пользователя СУБД | можно не указывать, если пароль не задан |
| `CrSQLDB` | создать базу данных, если её нет | `Y` / `N`; по умолчанию `N` |
| `SchJobDn` | запретить регламентные задания в созданной базе | `Y` / `N`; по умолчанию `N` |
| `LicDstr` | разрешить получение клиентских лицензий через сервер 1С | `Y` / `N`; по умолчанию `N` |
| `Locale` | язык (страна) базы | как форматная строка метода `Формат()`, например `ru_RU`; не задан — региональные установки текущей среды |
| `SQLYOffs` | смещение дат, только Microsoft SQL Server | `0` или `2000`; по умолчанию `0` |
| `SUsr`, `SPwd` | имя и пароль администратора кластера | нужны, если в кластере заведены администраторы и аутентификация ОС не подходит |
| `Usr`, `Pwd` | пользователь ИБ и пароль (общие параметры) | — |
| `Zn` | значения разделителей (общий параметр; в документации 8.3.27 — `Z`) | список через запятую, каждый элемент начинается с `+` или `-` |
| `prmod` | привилегированный режим (общий параметр) | `1` |
| `disstt` | запрет локального распознавания речи (общий параметр, 8.3.24+) | `Y` / `N`; по умолчанию `N` |
| `DBSchema` | схема PostgreSQL для таблиц ИБ | только 8.5.4+, только клиент-серверный вариант на PostgreSQL |
| `File` | каталог файловой базы (файловый вариант) | — |
| `DBFormat`, `DBPageSize` | формат и размер страницы файловой базы | `8.2.14` / `8.3.8`; `4k`…`64k` |

Особенности:

- При `/DisableStartupDialogs` и заданном администраторе кластера попытка `CREATEINFOBASE` завершается ошибкой [офиц.]. Надёжнее в этом случае использовать `rac infobase create --cluster-user=… --cluster-pwd=…`. Параметры `SUsr` / `SPwd` в строке соединения `CREATEINFOBASE` на практике применяют именно для этого: v8runner в процедуре `СоздатьСервернуюБазу` дописывает `;SUsr=<администратор кластера>` и `;SPwd=<пароль>`, когда они заданы [практика, исходный код v8runner]. ⚠ не подтверждено официальным текстом: в документации `SUsr` / `SPwd` описаны для создания начального образа, а не для `CREATEINFOBASE`; снимают ли они ошибку при `/DisableStartupDialogs` в актуальной сборке — проверьте на тестовом кластере.
- Умолчания, которые закладывает библиотека v8runner при создании серверной базы через `CREATEINFOBASE` (полезно знать, если база создаётся скриптом OneScript на этой библиотеке; сам vanessa-runner создаёт серверные базы через `rac`): тип СУБД `MSSQLServer`, `SQLYOffs=2000`, `LicDstr=N`, `CrSQLDB=N`, `SchJobDn=Y` (регламентные задания **заблокированы**), параметр `Locale` не передаётся вовсе [практика].
- Создание из шаблона: `/UseTemplate /distr/1Cv8.cf` создаёт базу и загружает в неё конфигурацию; `/UseTemplate /backup/demo.dt` — создаёт базу и загружает выгрузку.
- База, добавленная через клиентское приложение, регистрируется в кластере автоматически [офиц.].

### 2.4. Способ 3: `ibcmd infobase create` и регистрация в кластере

`ibcmd` создаёт базу данных и структуру ИБ прямо в PostgreSQL. В кластере она сама не появится — после создания её регистрируют командой `rac infobase create` без `--create-database`.

```bash
sudo -u usr1cv8 mkdir -p /var/lib/1c/ibcmd/demo
# создать базу из файла конфигурации и сразу обновить конфигурацию БД; пароль СУБД — из stdin
sudo -u usr1cv8 $B/ibcmd infobase create \
     --dbms=PostgreSQL --db-server=localhost --db-name=demo \
     --db-user=usr1c --request-db-pwd \
     --create-database --locale=ru_RU \
     --data=/var/lib/1c/ibcmd/demo \
     --load=/distr/1Cv8.cf --apply --force <<< 'Secret#1'
# зарегистрировать уже существующую базу в кластере
$RAC infobase --cluster=$CL create --name=demo --dbms=PostgreSQL --db-server=localhost \
     --db-name=demo --locale=ru_RU --db-user=usr1c --db-pwd='Secret#1' --license-distribution=allow
```

Вместо `--load=<cf>` можно указать `--restore=<dt>` (создать и загрузить выгрузку) или `--import=<каталог XML или zip>` (собрать конфигурацию из файлов). Полное описание параметров — раздел 3.4.

### 2.5. Способ 4: консоль администрирования с Windows

Оснастка MMC «Администрирование серверов 1С:Предприятия» работает только в Windows и должна быть той же версии, что и сервер [офиц.].

1. На Windows-машине установить компонент «Администрирование сервера 1С:Предприятия» той же версии; имя Linux-сервера должно разрешаться в IP (DNS или `hosts`).
2. В консоли: «Центральные серверы 1С:Предприятия» → «Создать» → «Центральный сервер»: протокол `tcp`, имя `srv1c`, порт `1540`.
3. Раскрыть кластер → «Информационные базы» → «Создать» → «Информационная база».
4. Заполнить поля: имя (`demo`), защищённое соединение (выключено), сервер баз данных (`localhost` — адрес с точки зрения сервера 1С), тип СУБД `PostgreSQL`, база данных (`demo`), пользователь и пароль сервера БД, «Разрешить выдачу лицензий сервером 1С:Предприятия» — «Да», язык (страна) — «русский (Россия)», флажок «Создать базу данных в случае ее отсутствия», при необходимости «Установить блокировку регламентных заданий».
5. В свойствах базы там же задаются блокировка начала сеансов (начало, конец, сообщение, код разрешения, параметр блокировки) и блокировка регламентных заданий [офиц.].

Альтернатива: в окне запуска клиента на Windows «Добавить…» → «Создание новой информационной базы» → «На сервере 1С:Предприятия» с теми же полями; база регистрируется в кластере автоматически.

### 2.6. Регистрация заранее созданной или восстановленной базы данных

Правило [офиц.]: при регистрации система проверяет базу данных на сервере СУБД. Если в ней уже есть данные ИБ 1С — кластер подключается к существующей базе; если база пустая — в ней создаётся новая ИБ.

```bash
# пустая база, созданная вручную [практика]
sudo -u postgres createdb -T template0 -E UTF8 -l ru_RU.UTF-8 -O usr1c demo2
$RAC infobase --cluster=$CL create --name=demo2 --dbms=PostgreSQL --db-server=localhost \
     --db-name=demo2 --locale=ru_RU --db-user=usr1c --db-pwd='Secret#1'
```

Локаль `ru_RU.UTF-8` должна быть сгенерирована в ОС до инициализации кластера PostgreSQL. Параметры `createdb` [офиц. PostgreSQL 18]: `-T` шаблон, `-E` кодировка, `-l` локаль (равносильно одновременному заданию `--lc-collate`, `--lc-ctype` и `--icu-locale`), `-O` владелец. Задать кодировку и локаль, отличные от шаблона, можно только при копировании `template0`.

Важно: правило «пустая база → в ней создаётся новая ИБ» подтверждено документацией 8.3.27 (раздел о регистрации информационной базы в кластере), но создание ИБ в пустой базе — это тоже «момент создания информационной базы», поэтому роли `usr1c` на время этой команды нужен `SUPERUSER` (раздел 2.1); после регистрации его снимают.

### 2.7. Проверка результата

```bash
$RAC infobase --cluster=$CL summary list
sudo -u postgres psql -c '\l+ demo'                           # база, владелец, кодировка, размер
sudo -u postgres psql -d demo -c '\dt' | head                 # таблицы 1С: config, params, _yearoffset …
```

## 3. `ibcmd`: полный справочник

### 3.1. Назначение, требования, ограничения

`ibcmd` — утилита администрирования автономного сервера (`ibsrv`) и выполнения административных операций над информационной базой. Устанавливается вместе с кластером серверов (компонент `server`), лежит в каталоге версии: `/opt/1cv8/x86_64/<версия>/ibcmd`. Графический стек и запущенный кластер не нужны [офиц.].

| Свойство | Значение | Статус |
|---|---|---|
| Синтаксис | `ibcmd mode command [command] [--parameter[=value]] …` | [офиц.] |
| Справка и версия | `ibcmd help`, `ibcmd help <режим>`, `ibcmd --help`, `ibcmd --version` | [офиц.] |
| Вывод | ход выполнения — stdout; ошибки — stderr; код возврата `0` — успех, иначе ошибка | [офиц.] |
| Приоритет настроек | параметр командной строки перекрывает одноимённый параметр конфигурационного файла | [офиц.] |
| Аутентификация в ИБ | с 8.3.17 обязательна: `--user` / `--password`; если пароль не задан — утилита запросит его в консоли | [офиц., V8Update] |
| Сеанс | команда, работающая с ИБ, создаёт сеанс; пользователь должен иметь права на действие | [офиц.] |
| Лицензия | для клиент-серверной базы и для подключения по SSH нужна серверная лицензия на этом компьютере | [офиц., V8Update 8.3.20] |
| СУБД на Linux | PostgreSQL и файловая база; Microsoft SQL Server с Linux не поддерживается | [офиц.] |
| Формат XML-выгрузки | только иерархический (линейный не поддерживается) | [офиц.] |
| Статус | автономный сервер и `ibcmd` вышли из бета-версии в 8.3.23 | [офиц., V8Update] |

Главные ограничения [офиц.]:

- Нельзя применять `ibsrv` / `ibcmd` к базе, которая в этот момент работает под управлением кластера серверов: возможна порча базы данных.
- С одним каталогом данных (`--data`) одновременно работает что-то одно: либо запущенный `ibsrv`, либо `ibcmd` в offline-режиме.
- Автономный сервер не поддерживает фоновую реструктуризацию, обычное приложение, COM-соединение, управление через `ras`, аутентификацию ОС, HTTPS без обратного прокси, сервисы интеграции, «1С:Аналитику».

Как освободить клиент-серверную базу перед `ibcmd` [практика]:

```bash
# надёжно: остановить службу сервера 1С (затрагивает все базы этого сервера)
sudo systemctl stop  srv1cv8-$V@default
#   … операции ibcmd …
sudo systemctl start srv1cv8-$V@default
```

Если остановить сервер нельзя, базу блокируют (сеансы и регламентные задания), завершают все сеансы и убеждаются, что соединений нет: `$RAC connection --cluster=$CL list --infobase=$IB …` должен вернуть пустой список (до 8.5.3 вместе с `--infobase-user` / `--infobase-pwd`; в 8.5.4 эти два параметра у `rac connection` удалены). ⚠ Этот вариант распространён, но **официально не поддерживается**: документация 8.3.27 относит использование средств автономного сервера (`ibsrv`, `ibcmd`) «в информационных базах, которые в данный момент работают под управлением кластера серверов» к неподдерживаемым сценариям и предупреждает, что такая попытка может разрушить базу данных; исключений для заблокированной базы в тексте нет. База, зарегистрированная в кластере, остаётся «под управлением кластера», пока работает служба: рабочий процесс может держать соединение с СУБД и кеш метаданных базы и без пользовательских сеансов. На рабочей базе используйте только вариант с остановкой службы; вариант с блокировкой допустим на свой риск и только после свежей резервной копии.

### 3.2. Три способа указать, с чем работать [офиц.]

| Способ | Ключи | Когда | Недоступно |
|---|---|---|---|
| Offline (сервер не запущен) | `--data=<каталог>` плюс параметры СУБД или `--config=<yml>` | администрирование базы напрямую | режимы `session` и `lock` |
| Локальный запущенный `ibsrv` | `--pid=<PID>` / `-p <PID>` | сервер на том же компьютере | `server config …`, `infobase create`, `infobase repair` |
| Удалённый `ibsrv` | `--remote=ssh://host:port` / `-r <url>` | через SSH-шлюз автономного сервера | то же |

При `--pid` и `--remote` параметры СУБД и `--data` не указывают: работающий сервер их уже знает.

### 3.3. Общие параметры offline-режима [офиц., 8.3.27]

| Параметр (синонимы) | Назначение | Значения, умолчания |
|---|---|---|
| `--config=<path>`, `-c <path>` | конфигурационный файл автономного сервера (YAML) | пути по умолчанию нет |
| `--system=<path>` | системный конфигурационный файл | — |
| `--dbms=<kind>` | тип СУБД | `MSSQLServer`, `PostgreSQL`, `IBMDB2`, `OracleDatabase`; не указан — файловая база |
| `--database-server=<address>`, `--db-server=<address>` | сервер СУБД | — |
| `--database-name=<name>`, `--db-name=<name>` | имя базы данных | — |
| `--database-user=<name>`, `--db-user=<name>` | пользователь СУБД | — |
| `--database-password=<password>`, `--db-pwd=<password>` | пароль пользователя СУБД | — |
| `--request-database-password`, `--request-db-pwd`, `-W` | прочитать пароль СУБД из stdin (без приглашения) | флаг |
| `--database-path=<path>`, `--db-path=<path>` | каталог файловой базы | по умолчанию `db-data` в каталоге данных |
| `--user=<name>`, `-u <name>` | пользователь **информационной базы** | — |
| `--password=<password>`, `-P <password>` | пароль пользователя ИБ | — |
| `--data=<path>`, `-d <path>` | каталог данных сервера | Linux: `~/.1cv8/standalone-server` |
| `--lock=<path>` | файл блокировки каталога данных | `lock.pid` в каталоге данных |
| `--temp=<path>`, `-t <path>` | каталог временных файлов | `temp` в каталоге данных |
| `--session-data`, `--log-data`, `--ftext-data`, `--ftext2-data`, `--openid-data`, `--stt-data`, `--users-data` | служебные каталоги (сеансовые данные, журнал регистрации, полнотекстовый поиск и т. д.) | одноимённые подкаталоги каталога данных; с 8.3.24 также `--binary-storage-data`, с 8.3.26 — `--clnt-notif-data`; в 8.5.4 вместо устаревшего `--stt-data` введён `--ai-data` (каталог моделей) [V8Update] |
| `--db-schema=<схема>` | схема PostgreSQL | только 8.5.4+ (режим `infobase` и `server config init`) |

Расхождение в документации о каталоге данных по умолчанию: русская редакция (приложение 4, по конспекту) называет `~/.1cv8/standalone-server` (Windows: `%LOCALAPPDATA%\1C\1cv8\standalone-server`), а англоязычная редакция главы 7 руководства 8.3.27 — `~/.1cv8/ss-data/db-data` для файловой базы по умолчанию (Windows: `%LOCALAPPDATA%\1C\1cv8\ss-data\db-data`). **Уточнено 10.10.2026** (полный текст приложения 4 документации 8.3.27): умолчание `--data` в Linux — `~/.1cv8/standalone-server`, в Windows — `%LOCALAPPDATA%\1C\1cv8\standalone-server`. Прежняя оговорка автора: Какой каталог использует ваша сборка, не подтверждено — **всегда задавайте `--data` явно** (так сделано во всех примерах ниже) и не полагайтесь на умолчание.

Замечания:

- Короткие ключи у `ibsrv` и `ibcmd` различаются: `-p` у `ibcmd` — это PID, у `ibsrv` — порт HTTP; `-P` у `ibcmd` — пароль пользователя ИБ.
- Каталог `--data` свой для каждой базы. Журнал регистрации операций `ibcmd` пишется в его подкаталог `log-data`, а не в журнал кластера.
- Запускайте `ibcmd` от того же пользователя, которому принадлежит каталог данных (обычно `usr1cv8`): `sudo -u usr1cv8 …`. Запуск от `root` без `--data` создаст каталог данных в домашнем каталоге `root` (`/root/.1cv8/standalone-server` либо `/root/.1cv8/ss-data` — см. расхождение выше), а файлы в явно указанном `--data` станут принадлежать `root`, после чего `usr1cv8` не сможет с ними работать.
- Пароли в командной строке видны в `ps`. Безопаснее `-W` (stdin) или YAML-файл с правами `600`.

### 3.4. Конфигурационный файл и режим `server`

Файл формирует сама утилита; писать его руками не обязательно.

```bash
sudo install -d -o usr1cv8 -g grp1cv8 -m 750 /etc/1c/ibcmd /var/lib/1c/ibcmd/demo
sudo -u usr1cv8 $B/ibcmd server config init \
     --dbms=PostgreSQL --db-server=localhost --db-name=demo \
     --db-user=usr1c --db-pwd='Secret#1' \
     --name=demo --http-base=/demo --out=/etc/1c/ibcmd/demo.yml
sudo chmod 600 /etc/1c/ibcmd/demo.yml
```

Получается файл такого вида (отступы восстановлены по смыслу; пароль хранится открытым текстом):

```yaml
server:
  address: localhost
  port: 8314
database:
  dbms: PostgreSQL
  server: localhost
  name: demo
  user: usr1c
  password: Secret#1
infobase:
  id: 7b88938e-5aa8-4933-afea-8a9ec121724f
  name: demo
  distribute-licenses: yes
  schedule-jobs: allow
http:
  base: /demo
```

| Команда | Что делает | Ключевые параметры |
|---|---|---|
| `ibcmd server config init` | формирует конфигурационный файл по параметрам командной строки | параметры СУБД; `--name` / `-n` (имя ИБ); `--id=<uuid>\|auto`; `--http-address` / `-a` (`localhost`, `any`, IPv4, IPv6); `--http-port` / `-p` (8314); `--http-base` / `-b` (`/`); `--distribute-licenses=allow\|deny`; `--schedule-jobs=allow\|deny`; `--out` / `-o` |
| `ibcmd server config import` | формирует конфигурационный файл по базе, зарегистрированной в кластере | `--cluster-data=<каталог данных кластера>`; `--manager-port` (1541); `--name`; `--publication` / `-p` (`default.vrd`); `--address`; `--port`; `--base`; `--out` |

```bash
# перенос параметров базы demo из реестра кластера в YAML автономного сервера
sudo -u usr1cv8 $B/ibcmd server config import \
     --cluster-data=/home/usr1cv8/.1cv8/1C/1cv8 --name=demo --out=/etc/1c/ibcmd/demo.yml
```

Дальше в примерах используется сокращение:

```bash
IBC=(sudo -u usr1cv8 "$B/ibcmd")
CONN=(--config=/etc/1c/ibcmd/demo.yml --data=/var/lib/1c/ibcmd/demo --user=Администратор --password='***')
```

### 3.5. Режим `infobase`: `create`, `dump`, `restore`, `clear`, `replicate` [офиц., 8.3.27]

**`ibcmd infobase create`** — создание информационной базы.

| Параметр | Назначение |
|---|---|
| `--create-database` | создать базу данных, если её нет |
| `--locale=<name>` / `-l <name>` | код локализации создаваемой ИБ; по умолчанию — локализация текущего сеанса ОС |
| `--date-offset=<years>` | смещение дат, только MS SQL Server; по умолчанию `2000` |
| `--load=<file>` | создать на основе файла конфигурации `.cf` |
| `--restore=<file>` | после создания загрузить выгрузку `.dt` |
| `--import=<directory>` | собрать конфигурацию из XML-файлов иерархической выгрузки (с 8.3.20 — каталог или zip-архив) |
| `--apply` | после загрузки конфигурации обновить конфигурацию базы данных |
| `--force` / `-F` | подтверждать операцию при предупреждениях |

**`ibcmd infobase dump <path>`** — выгрузка ИБ в dt-файл. Параметры: путь к файлу, `--user`, `--password`. На время выгрузки к базе не должно быть никаких подключений. Это не средство резервного копирования.

**`ibcmd infobase restore <path>`** — загрузка ИБ из dt-файла (текущее содержимое базы заменяется полностью).

| Параметр | Назначение |
|---|---|
| `--create-database` | создать базу данных, если её нет |
| `--force` / `-F` | принудительно завершить сеансы ИБ перед загрузкой |
| `--session-terminate-message` | текст для пользователей перед завершением сеанса (вместе с `--force`; 8.3.25+) |
| `--use-binary-data-storage` | сразу размещать двоичные данные во встроенном хранилище (8.5.4+, лицензия КОРП) |

**`ibcmd infobase clear`** — очистка текущей информационной базы (параметры `--user`, `--password`).

**`ibcmd infobase replicate`** — перенос клиент-серверной базы из одной СУБД в другую напрямую, без dt-файла (8.3.23+). Из файловой базы в клиент-серверную не работает.

| Параметр | Назначение | Умолчание |
|---|---|---|
| `--target-dbms=<kind>` | тип целевой СУБД | файловая база |
| `--target-database-server` / `--target-db-server` | целевой сервер СУБД | — |
| `--target-database-name` / `--target-db-name` | целевая база | — |
| `--target-database-user` / `--target-db-user`, `--target-database-password` / `--target-db-pwd` | доступ к целевой СУБД | — |
| `--target-request-database-password` / `--target-request-db-pwd` | пароль целевой СУБД из stdin | — |
| `--target-create-database` | создать целевую базу, если её нет | — |
| `--target-date-offset=<years>` | смещение дат (MS SQL Server) | `2000` |
| `--jobs-count=<n>` / `-j <n>` | потоков и соединений при выгрузке | число логических ядер |
| `--target-jobs-count=<n>` / `-J <n>` | потоков и соединений при загрузке | число логических ядер |
| `--batch-size=<n>` / `-B <n>` | строк в порции | `10000` |
| `--batch-data-size=<n>` | байт в пакете данных | `10485760` |
| `--force` | принудительно завершить сеансы исходной ИБ | — |
| `--target-database-schema` | схема PostgreSQL в приёмнике | только 8.5.4+ |

Примеры:

```bash
# выгрузка в .dt (сервер 1С остановлен либо база освобождена)
"${IBC[@]}" infobase dump "${CONN[@]}" /backup/demo_$(date +%F).dt
# загрузка .dt в существующую базу
"${IBC[@]}" infobase restore "${CONN[@]}" --force /backup/demo_2026-10-10.dt
# создать новую базу в PostgreSQL сразу из .dt
"${IBC[@]}" infobase create --dbms=PostgreSQL --db-server=localhost --db-name=demo_test \
     --db-user=usr1c --db-pwd='Secret#1' --data=/var/lib/1c/ibcmd/demo_test \
     --create-database --restore=/backup/demo_2026-10-10.dt
# перенос PostgreSQL -> PostgreSQL на другом сервере без .dt
"${IBC[@]}" infobase replicate --data=/var/lib/1c/ibcmd/demo \
     --dbms=PostgreSQL --db-server=localhost --db-name=demo --db-user=usr1c --db-pwd='Secret#1' \
     --target-dbms=PostgreSQL --target-db-server=pg2 --target-db-name=demo \
     --target-db-user=usr1c --target-db-pwd='Secret#2' --target-create-database
```

### 3.6. Режим `infobase config` (он же режим `config`) [офиц., 8.3.27]

`ibcmd config …` полностью эквивалентен `ibcmd infobase config …`.

| Команда | Назначение | Параметры |
|---|---|---|
| `load <path>` | загрузить конфигурацию (расширение) из `.cf` / `.cfe` в рабочую конфигурацию | `--extension=<имя>` / `-e`; `--force` / `-F` |
| `save <path>` | выгрузить конфигурацию в `.cf` / `.cfe` | `--extension`; `--db` — взять конфигурацию базы данных, а не рабочую |
| `check` | проверить конфигурацию | `--extension`; `--force` |
| `apply` | обновить конфигурацию базы данных | см. таблицу ниже |
| `reset` | вернуть рабочую конфигурацию к конфигурации базы данных | `--extension` |
| `repair` | восстановление после незавершённой операции (только offline) | `--commit` — завершить операцию; `--rollback` — отменить; `--fix-metadata` — восстановить структуру метаданных |
| `export …` | выгрузка конфигурации в XML | см. ниже |
| `import …` | загрузка конфигурации из XML | см. ниже |
| `support disable` | снять конфигурацию с поддержки | `--force` / `-F` — даже если редактирование запрещено |
| `data-separation list` | список разделителей ИБ | — |
| `extension …` | работа с расширениями | раздел 3.7 |
| `generation-id` | идентификатор поколения конфигурации | `--extension`; в 8.5.4 — также из файла |
| `sign <path>` | цифровая подпись конфигурации или расширения | `--key=<pem>` / `-k`; `--out` / `-o`; `--db`; `--extension` |
| `checksum` | хеш-сумма конфигурации, расширения, внешнего отчёта или обработки (парные методы встроенного языка — `ПолучитьКонтрольнуюСуммуКонфигурации()`, `ПолучитьКонтрольнуюСуммуРасширенияКонфигурации()`) | только 8.5.4+ [V8Update 8.5.4]; ⚠ параметры не подтверждены, см. `ibcmd help config` |
| `update` | прямая загрузка обновления в основную конфигурацию | только 8.5.4+ [V8Update 8.5.4, обзор «Новое в платформе 8.5.4»]; ⚠ параметры и принимаемые форматы файлов не подтверждены, см. `ibcmd help config` |

Параметры `config apply`:

| Параметр | Назначение | Значения |
|---|---|---|
| `--force` / `-F` | автоматически подтверждать операцию при предупреждениях (в том числе принятие изменений структуры) | флаг |
| `--dynamic=<режим>` | динамическое обновление | `auto` (по умолчанию), `disable`, `prompt`, `force` — только динамическое |
| `--session-terminate=<режим>` | завершение сеансов, мешающих монопольной блокировке | `disable` (по умолчанию с 8.3.23), `prompt`, `force` |
| `--session-terminate-message` | текст для отключаемых пользователей | 8.3.25+ |
| `--extension=<имя>` / `-e` | обновить расширение | — |
| `--dynamic-restuct` | динамическая реструктуризация | только 8.5.4+. Написание `--dynamic-restuct` (без буквы «r») стоит в V8Update 8.5.4 — перепроверено 2026-10-10, в источнике именно так; у агента конфигуратора в том же документе параметры записаны как `--dynamic-restruct-enable` / `--dynamic-restruct-disable`. ⚠ не подтверждено, опечатка ли это в V8Update: настоящее имя параметра смотреть в `ibcmd help config` своей сборки, в скрипты без проверки не вставлять |

В выводе `apply` есть строка с идентификатором созданного поколения конфигурации (8.3.24+); текущий идентификатор возвращает `config generation-id`.

Группа `config export` (выгрузка в XML):

| Вариант | Назначение | Параметры |
|---|---|---|
| `export <каталог>` | полная выгрузка или синхронизация | `--sync` — обновить существующую выгрузку; `--force` — полная выгрузка при несовпадении версии формата в `ConfigDumpInfo.xml`; `--base=<файл>` / `-b` — `ConfigDumpInfo.xml`, относительно которого считаются изменения; `--extension` / `-e`; `--archive` / `-A` — упаковать в zip; `--threads=<n>` / `-T`; `--ignore-unresolved-refs`; `--file=<файл>` / `-f` — источник: `.cf`, `.cfe`, `.epf`, `.erf` |
| `export info` | сформировать `ConfigDumpInfo.xml` | `--out` / `-o`; `--extension` |
| `export status` | показать отличия базы от каталога выгрузки | `--base` / `-b`; `--out` / `-o`; `--short` / `-s`; `--extension` |
| `export objects <Объект1 … ОбъектN>` | выгрузить выбранные объекты | `--out` / `-o` (каталог или архив); `--recursive` / `-r`; `--archive`; `--threads`; `--ignore-unresolved-refs`; `--extension` |
| `export all-extensions <каталог>` | выгрузить все расширения | `--archive`; `--threads`; `--ignore-unresolved-refs` |

Группа `config import` (загрузка из XML):

| Вариант | Назначение | Параметры |
|---|---|---|
| `import <каталог>` | полная загрузка — **полностью заменяет** конфигурацию | `--extension` / `-e`; `--out=<файл>` / `-o` — записать результат в файл (для внешней обработки или отчёта обязателен); `--partial` — частичная загрузка (8.3.24+); `--no-check` — без проверки метаданных (8.3.20+) |
| `import files <Файл1 … ФайлN>` | загрузка выбранных файлов | `--base-dir=<каталог>`; `--archive=<zip>`; `--extension`; `--no-check`; список файлов можно подать на stdin |
| `import all-extensions <каталог>` | загрузка всех расширений | `--no-check` |

Многопоточная загрузка из файлов: по документации 8.5.1 (конспект `kb/its-docs/otlichiya-8.5.1-ot-8.3.27.md`) у группы `import` появился параметр количества потоков, по умолчанию — число логических ядер процессора. Имя параметра у группы `export` — `--threads=<n>`: подтверждено текстом документации 8.3.27 (приложение 4, описание `ibcmd`, сверено 10.10.2026). В документации 8.5.1 в таблицу параметров `import` добавлена строка «Количество потоков, используемых при импорте»; само имя параметра в сравнение редакций не попало, то есть совпадает с уже существующим написанием `--threads=<n>` (вывод по сравнению текстов, короткая форма не проверялась — смотреть `ibcmd help config`). В 8.3.27 параметр потоков есть только у группы `export`. Блог разработчиков платформы (18.08.2026) относит оптимизацию многопоточной полной и частичной загрузки к версии 8.5.5 («планируется») — см. таблицу 3.10.

Примеры:

```bash
# загрузить новую конфигурацию из .cf и обновить конфигурацию базы данных
"${IBC[@]}" infobase config load  "${CONN[@]}" --force /distr/1Cv8.cf
"${IBC[@]}" infobase config apply "${CONN[@]}" --force --dynamic=disable --session-terminate=force
# сохранить конфигурацию базы данных в файл
"${IBC[@]}" infobase config save  "${CONN[@]}" --db /backup/demo_$(date +%F).cf
# выгрузить конфигурацию в XML, позже — только изменения
"${IBC[@]}" infobase config export "${CONN[@]}" /srv/src/demo
"${IBC[@]}" infobase config export "${CONN[@]}" --sync /srv/src/demo
# полная загрузка конфигурации из XML и применение
"${IBC[@]}" infobase config import "${CONN[@]}" /srv/src/demo
"${IBC[@]}" infobase config apply  "${CONN[@]}" --force
# собрать .cf из XML без информационной базы (8.5.4+: подключение к ИБ не требуется)
# ⚠ не проверено на живой 8.5.4: параметр --out у import описан в документации 8.3.27 («файл, в который записывается
#    импортируемая конфигурация, внешняя обработка или отчёт»), работа без подключения к ИБ — по V8Update 8.5.4;
#    в 8.3.22–8.5.3 эта же команда требует параметров подключения к базе ("${CONN[@]}")
$B/ibcmd infobase config import --out=/build/demo.cf /srv/src/demo
```

### 3.7. Режим `infobase config extension` (он же режим `extension`) [офиц., 8.3.27]

Имя расширения — одно слово, начинается с буквы, из спецсимволов допустим только `_`.

| Команда | Назначение | Параметры |
|---|---|---|
| `create` | создать пустое расширение | `--name=<имя>`; `--name-prefix=<префикс>`; `--synonym=<строка в формате НСтр()>`; `--purpose=<customization\|add-on\|patch>` |
| `info` | сведения о расширении | `--name` |
| `list` | список расширений | — |
| `update` | изменить свойства | `--name`; `--active=yes\|no`; `--safe-mode=yes\|no`; `--security-profile-name=<имя>`; `--unsafe-action-protection=yes\|no`; `--used-in-distributed-infobase=yes\|no`; `--scope=infobase\|data-separation` |
| `delete` | удалить | `--name=<имя>` или `--all` |

```bash
"${IBC[@]}" infobase config extension list   "${CONN[@]}"
"${IBC[@]}" infobase config extension create "${CONN[@]}" --name=Patch1 --name-prefix=p1 --purpose=patch
"${IBC[@]}" infobase config load   "${CONN[@]}" --extension=Patch1 /distr/Patch1.cfe
"${IBC[@]}" infobase config apply  "${CONN[@]}" --extension=Patch1 --force
"${IBC[@]}" infobase config extension update "${CONN[@]}" --name=Patch1 --active=yes --safe-mode=no --unsafe-action-protection=no
"${IBC[@]}" infobase config extension delete "${CONN[@]}" --name=Patch1
```

При загрузке `config load --extension=Имя` расширение, которого нет в базе, создаётся (так же ведёт себя `/LoadCfg -Extension`). Шаг `extension create` нужен, когда требуется задать префикс и назначение явно.

### 3.8. Остальные режимы [офиц., 8.3.27]

| Режим | Команды | Особенности |
|---|---|---|
| `session` | `list [--licenses]`; `info --session=<uuid> [--licenses]`; `terminate --session=<uuid> [--error-message=<текст>]`; `interrupt-current-server-call --session=<uuid> [--error-message=<текст>]` | только с работающим `ibsrv` (`--pid`, `--remote`) |
| `lock` | `list [--session=<uuid>]` | только с работающим `ibsrv` |
| `eventlog` (8.3.25+) | `export [--format=xml\|json] [--skip-root] [--from=<дата>] [--to=<дата>] [--follow[=<мс>]] [--out=<файл>] <каталог журнала>`; `model export <файл.xsd>` | к ИБ не подключается; формат дат `YYYY-MM-DDThh:mm:ss`; `--follow` — ждать новые события (по умолчанию 1000 мс) |
| `binary-data-storage` (8.3.27+) | `list`; `info --name=…\|--storage=…`; `create-full-backup --server-path=…`; `create-diff-backup --server-path=… --full-backup-server-path=…`; `load-full-backup`; `load-diff-backup`; `clear-unused-space [--by-universal-date=…\|--keep-days=…]` | хранилища двоичных данных этой ИБ |

Выгрузка журнала регистрации клиент-серверной базы в JSON (читает каталог журнала напрямую, базу не трогает):

```bash
sudo -u usr1cv8 $B/ibcmd eventlog export --format=json --from=2026-10-01T00:00:00 \
     --out=/tmp/demo_eventlog.json /home/usr1cv8/.1cv8/1C/1cv8/reg_1541/<UUID базы>/1Cv8Log
```

Режим `eds`, упоминаемый в некоторых материалах (и в постановке задачи на эту статью): в справочнике `ibcmd` документации 8.3.27 его нет — оглавление раздела 4.10 англоязычной редакции руководства 8.3.27 содержит ровно режимы `server`, `infobase`, `config`, `extension`, `mobile-app`, `mobile-client`, `session`, `lock`, `eventlog`, `binary-data-storage` (перепроверено 2026-10-10). В V8Update 8.5.4 (разделы 8.5.1 и 8.5.4) режим `eds` среди новшеств `ibcmd` также не упоминается; новые возможности 8.5.4 — это команды `config checksum`, `config update` и параметры схемы PostgreSQL. ⚠ не подтверждено только отсутствие режима в сборках новее 8.5.4. Список режимов вашей версии: `ibcmd help`.

### 3.9. Работа с запущенным автономным сервером

```bash
PID=$(pidof ibsrv)
$B/ibcmd --pid=$PID session list
$B/ibcmd --pid=$PID infobase config load --user=Администратор --password='***' /distr/1Cv8.cf
$B/ibcmd --remote=ssh://srv1c:1543 lock list          # через SSH-шлюз (порт шлюза по умолчанию 1543)
```

SSH-шлюз у `ibsrv` включён по умолчанию (`--enable-ssh-gate` / `--disable-ssh-gate`), но слушает только `localhost` (`--ssh-address`, умолчание `localhost`; `--ssh-port`, умолчание `1543`): для подключения с другой машины сервер запускают с `--ssh-address=any` или конкретным адресом интерфейса. В примерах документации порт шлюза задан явно (`ssh://Server1C:8282`) [офиц.].

SSH-шлюз автономного сервера дополнительно принимает обычные SSH- и SFTP-клиенты и исполняет подмножество команд агента конфигуратора (`config dump-cfg`, `config load-cfg`, `config update-db-cfg`, `infobase-tools dump-ib`, `infobase-tools restore-ib` и др.; раздел 4.8) [офиц.].

## 4. Пакетный режим конфигуратора на Linux

### 4.1. Что нужно на сервере без монитора

Конфигуратор — это толстый клиент (`1cv8`), графическое приложение. Режима «без графики» у него нет, поэтому на сервере ему дают виртуальный X-сервер Xvfb [практика; в документации 1С не описано].

| Что нужно | Как обеспечить | Статус |
|---|---|---|
| Толстый клиент той же сборки, что и сервер | компонент установщика `client_full` (в образах onec-docker ставят `--enable-components server,client_full,ru`) | [офиц.: идентификатор компонента; практика] |
| Системные библиотеки клиента | компонент установщика `v8_install_deps` либо скрипт `v8-install-deps.sh` из поставки клиента (запуск от root, до установки клиента) | [офиц.] |
| Проверка библиотек | `ldd $B/1cv8 \| grep 'not found'` — вывод должен быть пустым | [практика] |
| Шрифты Microsoft Core Fonts | `ttf-mscorefonts-installer` | [офиц.] |
| Виртуальный дисплей | пакет `xvfb` (в нём же сценарий `xvfb-run`), пакет `xauth` | [офиц. Ubuntu] |
| Клиентская лицензия | конфигуратору нужна клиентская лицензия: файл в `/var/1C/licenses`, либо выдача сервером (свойство базы «Разрешить выдачу лицензий сервером», `LicDstr=Y`, `--license-distribution=allow`) | [офиц.] |
| Домашний каталог пользователя | клиент пишет кеш и настройки в `~/.1cv8` и `~/.1C`; при запуске через `sudo -u` добавляйте `-H` | [практика] |

Библиотеки, которые ставят для толстого клиента в образе onec-docker (`client/Dockerfile`, базовый образ **Ubuntu 20.04**; файл перечитан 2026-10-10) [практика]: `libgtk-3-0`, `libgtk2.0-0`, `libwebkit2gtk-4.0-37`, `libwebkitgtk-3.0-0`, `libsoup2.4-1`, `libenchant1c2a`, `libharfbuzz-icu0`, `libgstreamer1.0-0`, `libgstreamer-plugins-base1.0-0`, `gstreamer1.0-plugins-good`, `gstreamer1.0-plugins-bad`, `libsecret-1-0`, `libsqlite3-0`, `libgl1`, `libegl1`, `libglu1-mesa`, `libxrender1`, `libxfixes3`, `libxslt1.1`, `libfontconfig1`, `libgsf-1-114`, `libglib2.0-0`, `libodbc1`, `libmagickwand-6.q16-3`, `geoclue-2.0`, `dbus-x11`, `locales`, `ca-certificates`, `ttf-mscorefonts-installer`.

Этот список **нельзя переносить на Ubuntu 22.04 / 24.04 как есть**: он составлен для 20.04, и часть имён в новых выпусках другая или отсутствует. Проверено по packages.ubuntu.com 2026-10-10: в Ubuntu 24.04 (noble) пакетов `libwebkit2gtk-4.0-37` и `libodbc1` нет («Package not available in this suite»); вместо первого есть `libwebkit2gtk-4.1-0`. **Уточнено 10.10.2026** (packages.ubuntu.com): пакет `libwebkit2gtk-4.0-37` есть только в 22.04; `libwebkit2gtk-4.1-0` — в 22.04, 24.04 и 26.04; `libenchant-2-2` — во всех трёх выпусках. Ранее было не подтверждено для каждого пакета отдельно: точные имена замен в 22.04 / 24.04 и то, с какой библиотекой WebKit собрана ваша сборка 8.3.27 / 8.5. Рабочий порядок: поставить зависимости штатным способом (компонент `v8_install_deps` или `v8-install-deps.sh`), затем проверить `ldd $B/1cv8 | grep 'not found'` и доустановить недостающее по именам файлов (`apt-file search <имя .so>`); подробнее — статья `02-ustanovka-servera-ubuntu.md`, раздел 3.6. Пакет `xvfb` в Ubuntu лежит в компоненте `universe` (он должен быть включён в `sources.list`) и тянет `xauth` как обязательную зависимость.

```bash
sudo apt install -y xvfb xauth
# разовая проверка: окно не нужно, достаточно успешного создания файла результата
xvfb-run -a $B/1cv8 DESIGNER /S "srv1c/demo" /N "Администратор" /P "***" \
    /DisableStartupDialogs /DisableStartupMessages /Out /tmp/t.log /DumpResult /tmp/t.res /DumpDBCfgList
echo "rc=$?"; cat /tmp/t.res; cat /tmp/t.log
```

`xvfb-run [опции] команда` запускает Xvfb, выставляет `DISPLAY` и `XAUTHORITY`, выполняет команду и останавливает Xvfb [офиц. Ubuntu, man xvfb-run]:

| Опция | Назначение | Умолчание |
|---|---|---|
| `-a`, `--auto-servernum` | взять первый свободный номер дисплея (нужно при параллельных запусках) | начинает с 99 |
| `-n N`, `--server-num=N` | номер дисплея | 99 |
| `-s "аргументы"`, `--server-args=…` | аргументы Xvfb | `-screen 0 1280x1024x24` |
| `-e файл`, `--error-file=файл` | куда писать вывод Xvfb и xauth | `/dev/null` |
| `-f файл`, `--auth-file=файл` | файл авторизации X | временный каталог |

Вариант с постоянным дисплеем (удобен для агента конфигуратора и CI) [практика]:

```bash
Xvfb :99 -screen 0 1280x1024x24 -nolisten tcp &
export DISPLAY=:99
$B/1cv8 DESIGNER /S "srv1c/demo" …
```

Прочее:

- Одну информационную базу одновременно может открыть только один конфигуратор. Параллельные пакетные задания для одной базы ставьте в очередь.
- Оборачивайте вызовы в `timeout` (например `timeout 4h xvfb-run …`): при неожиданном диалоге процесс будет ждать бесконечно.
- Если графика на сервере нежелательна, большинство операций закрывает `ibcmd` (раздел 3) или конфигуратор на рабочей станции администратора.

### 4.2. Общий вид команды и общие параметры [офиц., 8.3.27]

```text
1cv8 DESIGNER <параметры подключения> <аутентификация> [/UC <код>] [/DisableStartupDialogs] [/DisableStartupMessages]
     [/Out <файл> [-NoTruncate]] [/DumpResult <файл>] <одна команда пакетного режима> [/UpdateDBCfg …]
```

| Параметр | Назначение |
|---|---|
| `/S <сервер>/<база>` | клиент-серверная база; на Linux — прямой слеш, либо значение в кавычках; нестандартный порт: `/S "srv1c:2541/demo"` |
| `/F <каталог>` | файловая база (каталог с `1Cv8.1CD`) |
| `/IBName <имя>` | база по имени из списка `ibases.v8i` |
| `/IBConnectionString <строка>` | полная строка соединения |
| `/N <имя>`, `/P <пароль>` | пользователь ИБ и пароль (в документации запись слитная: `/N<имя>`, `/P<пароль>`) |
| `/WA-` | запретить аутентификацию ОС (по умолчанию `/WA+`) |
| `/UC <код доступа>` | войти в базу, на которую установлена блокировка начала сеансов с этим кодом |
| `/Out <файл> [-NoTruncate]` | файл служебных сообщений, UTF-8, пишется без буферизации; `-NoTruncate` — не очищать файл |
| `/DumpResult <файл>` | записать числовой результат работы конфигуратора; `0` — успех |
| `/DisableStartupDialogs` | не показывать стартовый диалог и диалоги аутентификации — вместо них будет ошибка |
| `/DisableStartupMessages` | не задавать стартовые вопросы (например «Конфигурация базы данных не соответствует сохраненной конфигурации. Продолжить?») |
| `/DisableUnrecoverableErrorMessage` | при невосстановимой ошибке не показывать окно, завершиться с ненулевым кодом |
| `/L<код языка>`, `/VL<код локализации>` | язык интерфейса и локализация сеанса |
| `/Visible` | показать окно заставки на время пакетной команды |
| `/RunEnterprise ["доп. параметры"]` | после пакетной команды запустить «1С:Предприятие» |
| `/@ <файл>` | взять командную строку из файла |

Правила [офиц.]:

- Команды пакетного режима между собой не комбинируются, если это прямо не разрешено. Разрешено указывать `/UpdateDBCfg` после `/LoadCfg`, `/UpdateCfg`, `/ConfigurationRepositoryUpdateCfg`, `/LoadConfigFiles`, `/LoadConfigFromFiles` и команд мобильных приложений.
- Модули, закрытые паролем, в пакетном режиме пропускаются с диагностическим сообщением.
- Нельзя одновременно указывать `-Extension` и `-AllExtensions`.

### 4.3. Коды возврата и разбор результата [офиц.]

| Код | Смысл |
|---|---|
| `0` | команда выполнена успешно |
| `1` | ошибка (текст — в файле `/Out`) |
| `101` | в данных имеются ошибки |

Число результата дублируется в файле `/DumpResult`. Заготовка функции для скриптов [практика]:

```bash
# использование: designer /DumpIB /backup/demo.dt
designer() {
  local log res rc
  log=$(mktemp /tmp/1c-XXXXXX.log); res=$(mktemp /tmp/1c-XXXXXX.res)
  timeout "${TMO:-4h}" xvfb-run -a "$B/1cv8" DESIGNER /S "$SRV/$IBNAME" /N "$IBUSER" /P "$IBPWD" \
      ${UC:+/UC "$UC"} /DisableStartupDialogs /DisableStartupMessages \
      /Out "$log" /DumpResult "$res" "$@"
  rc=$?
  cat "$log"
  [[ $rc -eq 0 && "$(tr -cd '0-9' < "$res")" == "0" ]]
}
```

### 4.4. Команды пакетного режима: сводная таблица [офиц., 8.3.27]

| Команда | Назначение |
|---|---|
| `/DumpIB <файл>` | выгрузить информационную базу в dt-файл |
| `/RestoreIB <файл> [-JobsCount <N>]` | загрузить информационную базу из dt-файла; `-JobsCount` — число фоновых заданий (8.3.19+; `0` — по числу процессоров); в 8.5.4 добавлен `-UseBinaryDataStorage` |

Примеры:

```bash

designer /RestoreIB /backup/demo_2026-10-10.dt -JobsCount 4           # загрузка .dt
designer /DumpCfg /backup/demo_$(date +%F).cf                         # сохранить конфигурацию
designer /LoadCfg /distr/1Cv8.cf /UpdateDBCfg -Dynamic- -Server       # загрузить .cf и обновить БД
designer /UpdateCfg /distr/1cv8.cfu -Settings /etc/1c/merge.xml -force /UpdateDBCfg -Dynamic- -Server
designer /CheckConfig -ConfigLogIntegrity -IncorrectReferences -ThinClient -Server
designer /ReduceEventLogSize 2026-01-01 -saveAs /backup/eventlog_do_2026-01-01     # журнал до даты — в файл
```

Параметры `/UpdateCfg` [офиц.]:

| Параметр | Назначение |
|---|---|
| `<файл>` | файл конфигурации `.cf` или файл обновления `.cfu` |
| `-Settings <файл>` | файл настроек объединения. В строке синтаксиса документации показан без квадратных скобок, то есть формально обязателен. На практике команду вызывают и без него: в v8runner метод `ОбновитьКонфигурацию` формирует `/UpdateCfg "<файл>"` без `-Settings`, а `ОбновитьКонфигурациюИзФайла` добавляет `-Settings` только когда файл настроек задан; у `vrunner cf vendor-update` файл настроек — необязательная опция `--update-settings` [практика, исходный код v8runner и документация vanessa-runner 3.0 — проверено 2026-10-10]. ⚠ не подтверждено официальным текстом и живым запуском на 8.3.27 / 8.5: поведение без `-Settings` для конфигурации с доработками (какие настройки объединения берутся по умолчанию); для доработанной конфигурации файл настроек готовьте явно |
| `-IncludeObjectsByUnresolvedRefs` \| `-ClearUnresolvedRefs` | что делать с неразрешёнными ссылками: добавить объекты в объединение либо очистить ссылки |
| `-DumpListOfTwiceChangedProperties` | вывести список дважды изменённых свойств в файл служебных сообщений |
| `-force` | не прерывать обновление при предупреждениях (удаляемые объекты со ссылками, дважды изменённые свойства без выбранного режима, объекты, изменение которых запрещено правилами поддержки, предупреждения о применении настроек) |

### 4.5. `/UpdateDBCfg` — обновление конфигурации базы данных [офиц., 8.3.27]

```text
/UpdateDBCfg [-Dynamic<Режим>] [-BackgroundStart] [-BackgroundCancel] [-BackgroundFinish [-Visible]]
             [-BackgroundSuspend] [-BackgroundResume] [-WarningsAsErrors] [-Server] [-v1|-v2]
             [-Extension <Имя расширения>] [-SessionTerminate <режим>]
```

| Параметр | Назначение | Значения и умолчания |
|---|---|---|
| `-Dynamic+` / `-Dynamic-` | разрешить или запретить динамическое обновление | без параметра — разрешено: сначала попытка обычного обновления, при неудаче — динамического |
| `-BackgroundStart` | запустить фоновое обновление и завершить работу | с `-Dynamic+` сначала пробует динамическое |
| `-BackgroundFinish [-Visible]` | завершить фоновое обновление (монопольная блокировка и финальная фаза) | без `-Visible` при невозможности — ошибка |
| `-BackgroundCancel`, `-BackgroundSuspend`, `-BackgroundResume` | отменить, приостановить, продолжить фоновое обновление | — |
| `-WarningsAsErrors` | считать предупреждения ошибками | — |
| `-Server` | выполнять обновление на сервере | только клиент-серверный вариант |
| `-v1` \| `-v2` | механизм реструктуризации: обычный или оптимизированный | не указан — берётся параметр `UpdateDBCfg` файла `conf.cfg` на компьютере, где запущен конфигуратор (по умолчанию `v1`); при фоновом обновлении игнорируется |
| `-Extension <имя>` | обновить указанное расширение | — |
| `-SessionTerminate <режим>` | завершение сеансов, мешающих монопольной блокировке (8.3.23+) | `disable` (по умолчанию), `force` |
| `-DynamicRestruct` | динамическая реструктуризация при активных сеансах | только 8.5.4+, клиент-серверный вариант, механизм `v1`, лицензия КОРП |

Пояснения:

- Оптимизированная реструктуризация `v2`: только клиент-серверный вариант, только Microsoft SQL Server и PostgreSQL; работает через Java (путь — `JavaHome` в `conf.cfg` сервера или переменная `JAVA_HOME`; параметры JVM — `RestructJavaOpts`, например `RestructJavaOpts=-Xmx2048m`) [офиц.].
- Фоновое обновление конфигурации БД — функциональность уровня КОРП; автономный сервер его не поддерживает [офиц.].
- Для обновления по регламенту с заблокированными сеансами используйте `-Dynamic-`: динамическое обновление оставляет базу в состоянии, когда часть сеансов работает со старой конфигурацией.
- Если обновление оборвалось (аварийное завершение, выключение питания), запустите конфигуратор с `/IBRestoreIntegrity` и `/Out` [офиц.].

### 4.6. Выгрузка и загрузка конфигурации в XML-файлы [офиц., 8.3.27]

```text
/DumpConfigToFiles <каталог> [-Format <Plain|Hierarchical>] [-Extension <имя>] [-AllExtensions] [-update] [-force]
      [-getChanges <файл>] [-configDumpInfoForChanges <файл>] [-listFile <файл>] [-configDumpInfoOnly]
      [-Server [-JobsCount <N>]] [-Archive <zip>] [-ignoreUnresolvedReferences]
/LoadConfigFromFiles <каталог> [-Extension <имя>] [-AllExtensions] [-files "<файлы>"] [-listFile <файл>]
      [-Format <Plain|Hierarchical>] [-updateConfigDumpInfo] [-NoCheck] [-Archive <zip>] [-partial]
      [-JobsCount <N>]                      # -JobsCount у загрузки — только 8.5.1+
```

| Параметр выгрузки | Назначение |
|---|---|
| `-Format` | `Hierarchical` (по умолчанию) или `Plain`; в 8.5.4 параметр удалён — остался только иерархический формат |
| `-Extension <имя>`, `-AllExtensions` | выгрузить расширение или все расширения (каждое в свой подкаталог; основная конфигурация не выгружается) |
| `-update` | обновить существующую выгрузку по файлу версий `ConfigDumpInfo.xml` (выгружаются только изменённые объекты) |
| `-force` | вместе с `-update`: при несовпадении версии формата выполнить полную выгрузку |
| `-getChanges <файл>` | записать список изменений относительно выгрузки |
| `-configDumpInfoForChanges <файл>` | файл версий, относительно которого считаются изменения |
| `-listFile <файл>` | выгрузить только перечисленные объекты |
| `-configDumpInfoOnly` | сформировать только `ConfigDumpInfo.xml` |
| `-Server [-JobsCount <N>]` | многопоточная выгрузка на стороне сервера 1С (8.3.21+); в 8.5.4 `-JobsCount` работает и без `-Server` |
| `-Archive <zip>` | выгрузить в zip-архив (8.3.21+) |
| `-ignoreUnresolvedReferences` | не выгружать ссылки на удалённые объекты |

| Параметр загрузки | Назначение |
|---|---|
| `-Extension <имя>`, `-AllExtensions` | загрузить расширение (создаётся, если его нет) или все расширения из подкаталогов |
| `-files "<файлы>"`, `-listFile <файл>` | частичная загрузка: список файлов через запятую либо файл со списком (UTF-8, по одному имени в строке, без пустых строк) |
| `-Format` | формат при частичной загрузке (при полной определяется автоматически) |
| `-updateConfigDumpInfo` | после загрузки создать или обновить `ConfigDumpInfo.xml` |
| `-NoCheck` | не проверять целостность загружаемой конфигурации (8.3.20+) |
| `-Archive <zip>` | загрузить из zip-архива вместо каталога (8.3.20+) |
| `-partial` | загружать только те элементы описания объекта, которые представлены файлом (8.3.24+) |
| `-JobsCount <N>` | число одновременно работающих потоков загрузки из файлов; `0` (по умолчанию) — платформа выбирает сама по числу ядер процессора компьютера, выполняющего загрузку. Появился в документации 8.5.1 (в 8.3.27 у `/LoadConfigFromFiles` его нет — там `-JobsCount` есть только у `/DumpConfigToFiles -Server`, `/RestoreIB` и `/IBCheckAndRepair`) [офиц., конспект `otlichiya-8.5.1-ot-8.3.27.md`] |

Начиная с 8.5.1 документация прямо требует `/Out`, если команда пакетного режима формирует текстовый вывод: без `/Out` этот вывод не сохраняется [офиц., 8.5.1].

```bash
designer /DumpConfigToFiles /srv/src/demo                       # полная выгрузка
designer /DumpConfigToFiles /srv/src/demo -update -force        # обновить выгрузку
designer /DumpConfigToFiles /srv/src/ext -Extension Patch1      # выгрузить расширение
designer /LoadConfigFromFiles /srv/src/demo /UpdateDBCfg -Dynamic- -Server
```

Версия формата XML-выгрузки растёт вместе с платформой: 2.11 (8.3.17) … 2.14 (8.3.21), 2.15 (8.3.22), 2.16 (8.3.23), 2.17 (8.3.24), 2.18 (8.3.25), 2.19 (8.3.26), 2.20 (8.3.27), 2.21 (8.5.1) [офиц., V8Update]. Выгрузку, сделанную новой платформой, старая не загрузит.

### 4.7. `/IBCheckAndRepair` — тестирование и исправление [офиц., 8.3.27]

```text
/IBCheckAndRepair [-ReIndex] [-LogIntegrity [MDtype,…] | -LogAndRefsIntegrity [MDtype,…]] [-RecalcTotals]
     [-IBCompression] [-Rebuild] [-RebuildStandaloneCfg]
     [-TestOnly | [[-BadRefCreate | -BadRefClear | -BadRefNone] [-BadDataCreate | -BadDataDelete]]]
     [-UseStartPoint] [-TimeLimit:hhh:mm] [-ConfigurationExtensionsLogIntegrity] [-RefreshTableLocation]

```

| Ключ | Действие |
|---|---|
| `-ReIndex` | реиндексация таблиц |
| `-LogIntegrity` \| `-LogAndRefsIntegrity` | проверка логической либо логической и ссылочной целостности; можно ограничить видами объектов (`Documents`, `Catalogs`, `InformationRegisters`, `AccumulationRegisters`, `AccountingRegisters`, `Constants` и др.) |

| `-BadRefCreate` \| `-BadRefClear` \| `-BadRefNone` | ссылки на несуществующие объекты: создавать объекты, очищать ссылки, не изменять |

| `-UseStartPoint`, `-TimeLimit:hhh:mm` | продолжить с точки прерывания; ограничить длительность сеанса проверки |
| `-ConfigurationExtensionsLogIntegrity` | проверка логической целостности расширений (монопольный доступ не нужен, если ключ единственный) |

### 4.8. Режим агента конфигуратора [офиц., 8.3.27]

Конфигуратор запускается как SSH- и SFTP-сервер и исполняет команды, приходящие по SSH. Один агент — одна база, один SSH-клиент и несколько SFTP-клиентов.

```text
1cv8 DESIGNER <информационная база> /AgentMode [/AgentPort <порт>] [/AgentListenAddress <адрес>]
     [/AgentSSHHostKey <ключ> | /AgentSSHHostKeyAuto] [/AgentBaseDir <каталог>] [/Visible]
```

| Параметр | Назначение | Умолчание |
|---|---|---|
| `/AgentMode` | включить режим агента; `/DisableStartupDialogs`, `/DisableStartupMessages`, `/N`, `/P` игнорируются | — |
| `/AgentPort <порт>` | порт SSH-сервера агента | `1543` |
| `/AgentListenAddress <адрес>` | адрес, который слушает агент | `127.0.0.1` |
| `/AgentSSHHostKey <файл>` | закрытый ключ хоста | — |
| `/AgentSSHHostKeyAuto` | взять ключ из `~/.1cv8/1C/1cv8/host_id`; если файла нет — создать RSA 2048 бит | одна из двух команд о ключе обязательна |
| `/AgentBaseDir <каталог>` | рабочий каталог SFTP и команд выгрузки и загрузки | `~/.1cv8/1C/1cv8/<идентификатор ИБ>/sftp` |
| `/Visible` | окно, из которого можно остановить агента | без него остановка — только командой `common shutdown` |

Имя и пароль пользователя ИБ вводятся при подключении по SSH (пользователей с национальными символами в имени использовать не рекомендуется).

| Группа | Команды |
|---|---|
| `common` | `connect-ib`, `disconnect-ib`, `shutdown` |
| `options` | `list`; `get`; `set --output-format=text\|json --show-prompt=yes\|no --notify-progress=yes\|no --notify-progress-interval=<сек>` |
| `config` | `dump-cfg --file=… [--extension=…]`; `load-cfg --file=… [--extension=…]`; `dump-config-to-files --dir=… [--update] [--force] [--extension=…] [--all-extensions] [--archive=…] [--server] [--threads=…]`; `load-config-from-files --dir=… \| --archive=… [--files=…] [--list-file=…] [--partial] [--no-check] [--update-config-dump-info]`; `update-db-cfg`; `manage-cfg-support --disable-support [--force]`; `generation-id`; `sign-cfg`; `extensions create \| delete \| properties get \| properties set` |
| `infobase-tools` | `dump-ib --file=…`; `restore-ib --file=…`; `erase-data`; `debug-info`; `data-separation-common-attributes-list` |

Параметры `config update-db-cfg`: `--prompt-confirmation`, `--dynamic-enable` / `--dynamic-disable`, `--warnings-as-errors`, `--background-start` / `--background-cancel` / `--background-finish` / `--background-resume`, `--server`, `--extension=<имя>`, `--session-terminate=disable|prompt|force` (умолчание `disable`), `--session-terminate-message=<текст>`; в 8.5.4 — `--dynamic-restruct-enable` / `--dynamic-restruct-disable`. У `config load-config-from-files` в 8.5.1 добавлен `--threads=<количество>` (по умолчанию `auto` — по числу ядер); в 8.3.27 `--threads` есть только у `config dump-config-to-files` и только вместе с `--server` (в 8.5.4 — и без `--server`). В 8.5.4 у `dump-config-to-files` и `load-config-from-files` удалён параметр формата, а у `infobase-tools restore-ib` добавлен `--use-binary-data-storage` [V8Update 8.5.4, конспект отличий 8.5.1].

```bash
# терминал 1: запуск агента (каталог обмена файлами — /var/lib/1c/agent/demo)
xvfb-run -a $B/1cv8 DESIGNER /S "srv1c/demo" /AgentMode /AgentSSHHostKeyAuto \
    /AgentPort 1543 /AgentListenAddress 127.0.0.1 /AgentBaseDir /var/lib/1c/agent/demo
# терминал 2: сеанс управления (логин — пользователь ИБ)
ssh -p 1543 admin@127.0.0.1
#   designer> options set --output-format=json --show-prompt=no
#   designer> common connect-ib
#   designer> config load-cfg --file=1Cv8.cf
#   designer> config update-db-cfg --session-terminate=force
#   designer> common disconnect-ib
#   designer> common shutdown
```

Особенности: пути в командах — относительно `/AgentBaseDir`; ответы в режиме JSON — массив сообщений с полем `type` (`success`, `error`, `canceled`, `question`, `log`, `progress`, …); после `restore-ib` SSH-соединение разрывается, агент остаётся работать и ждёт нового подключения. Для PuTTY документация рекомендует: Local echo — Force on, локальное редактирование строки — Force on, кодировка UTF-8, не выделять псевдотерминал.

### 4.9. Команды работы с хранилищем конфигурации [офиц., 8.3.27]

Параметры доступа указываются вместе с любой командой хранилища: `/ConfigurationRepositoryF <адрес или каталог>`, `/ConfigurationRepositoryN <пользователь>`, `/ConfigurationRepositoryP <пароль>`. Почти все команды принимают `-Extension <имя>` — тогда операция выполняется с хранилищем расширения.

| Команда | Назначение и ключи |
|---|---|
| `/ConfigurationRepositoryCreate` | создать хранилище: `[-AllowConfigurationChanges -ChangesAllowedRule <правило> -ChangesNotRecommendedRule <правило>] [-NoBind]`; правила: `ObjectNotEditable`, `ObjectIsEditableSupportEnabled`, `ObjectNotSupported`; с 8.3.24 — ключи минимальной длины пароля (в документации `-MinPasswordLenght`, в V8Update `-MinPasswordLength`) и `-CheckPasswordComplexity` |
| `/ConfigurationRepositoryAddUser` | `-User <имя> -Pwd <пароль> -Rights <ReadOnly\|LockObjects\|ManageConfigurationVersions\|Administration> [-RestoreDeletedUser]` |
| `/ConfigurationRepositoryCopyUsers` | `-Path <хранилище-источник> -User <имя> -Pwd <пароль> [-RestoreDeletedUser]` |
| `/ConfigurationRepositoryBindCfg` | подключить базу к хранилищу: `[-forceBindAlreadyBindedUser] [-forceReplaceCfg]` |
| `/ConfigurationRepositoryUnbindCfg` | отключить от хранилища: `[-force]` |
| `/ConfigurationRepositoryUpdateCfg` | получить конфигурацию из хранилища: `[-v <версия>] [-revised] [-force] [-Objects <файл>]`; после неё допустим `/UpdateDBCfg` |
| `/ConfigurationRepositoryDumpCfg <cf>` | сохранить версию из хранилища в файл: `[-v <версия>]` (без ключа или `-1` — последняя) |
| `/ConfigurationRepositoryLock` | захватить объекты: `[-Objects <файл>] [-revised]` |
| `/ConfigurationRepositoryUnLock` | отменить захват: `[-Objects <файл>] [-force]` (с `-force` локальные изменения теряются) |
| `/ConfigurationRepositoryCommit` | поместить изменения: `[-Objects <файл>] [-comment "<текст>"] [-keepLocked] [-force]` |
| `/ConfigurationRepositorySetLabel` | поставить метку: `[-v <версия>] -name "<метка>" [-comment "<текст>"]` |
| `/ConfigurationRepositoryReport <файл>` | отчёт по истории: `[-NBegin <N>] [-NEnd <N>] [-DateBegin <дата>] [-DateEnd <дата>] [-GroupByObject] [-GroupByComment] [-ReportFormat <txt\|mxl>]` и др. |
| `/ConfigurationRepositoryOptimizeData` | оптимизировать хранение данных хранилища |
| `/ConfigurationRepositoryClearCache`, `…ClearLocalCache`, `…ClearGlobalCache` | очистить локальную базу хранилища, локальный и глобальный кеш версий |

```bash
REPO=(/ConfigurationRepositoryF "tcp://srv1c/erp" /ConfigurationRepositoryN "builder" /ConfigurationRepositoryP '***')
designer "${REPO[@]}" /ConfigurationRepositoryUpdateCfg -force /UpdateDBCfg -Dynamic- -Server   # обновить базу из хранилища
designer "${REPO[@]}" /ConfigurationRepositoryDumpCfg /build/erp_last.cf                         # последняя версия в .cf
designer "${REPO[@]}" /ConfigurationRepositoryReport /build/history.txt -NBegin 100 -ReportFormat txt
```

Команды `Lock`, `UnLock`, `Commit`, `SetLabel` возвращают `0` или `1`; текст ошибки — в файле `/Out`. Если авторизация в хранилище в командной строке ошибочна при `/DisableStartupDialogs` — будет ошибка; если её нет совсем — конфигуратор запустится без связи с хранилищем.

## 5. Клиентское приложение в пакетном режиме

### 5.1. Команды запуска [офиц., 8.3.27]

```text
1cv8  ENTERPRISE <параметры подключения> [/N <имя>] [/P <пароль>] [/UC <код>] [/C "<строка>"] [/Execute <файл.epf>]
      [/DisableStartupDialogs] [/DisableStartupMessages] [/Out <файл>] …
1cv8c ENTERPRISE …        # тонкий клиент: те же общие параметры, плюс /WS <url> для подключения через веб-сервер
```

| Команда | Назначение |
|---|---|
| `/C "<строка>"` | передать строку в прикладное решение; в коде доступна как `ПараметрЗапуска` |
| `/Execute <файл.epf>` | открыть внешнюю обработку (полный путь) сразу после запуска; при наличии `/Execute` команда `/URL` игнорируется |
| `/URL <ссылка>` | перейти по навигационной ссылке (`e1c://…`, для тонкого клиента также `http(s)://…`) |
| `/UC <код>` | войти в базу при установленной блокировке начала сеансов |
| `/AllowExecuteScheduledJobs -Off\|-Force` | управление выполнением регламентных заданий на клиенте (актуально для файловых баз) |
| `/RunModeOrdinaryApplication`, `/RunModeManagedApplication` | принудительный выбор режима толстого клиента |
| `/DisableStartupDialogs` | включает **пакетный режим запуска клиентского приложения** |
| `/ClearCache` | очистить клиентский кеш базы (`~/.1cv8/1C/1cv8/<UUID>`: `vrs-cache`, `cfg-cache`) |
| `/TESTMANAGER`, `/TESTCLIENT [-TPort<порт>]` | автоматизированное тестирование (порт клиента тестирования по умолчанию 1538) |
| `/DisableExtension` | отключить выбранные или все расширения на время сеанса (8.5.4+) |

Пакетный режим запуска клиента [офиц.]:

- поддерживается тонким и толстым клиентом (не веб-клиентом);
- действует от запуска до конца обработчика `ПередНачаломРаботыСистемы`; в это время открытие форм запрещено (ошибка), проверка — метод `ЗапрещеноОткрытиеФорм()`;
- `ПриНачалеРаботыСистемы` вызывается уже после окончания пакетного режима;
- клиент **сам не завершается** — работу должен завершить прикладной код или внешняя обработка;
- внешняя обработка из `/Execute` запускается после окончания пакетного режима;
- ошибки можно собрать в файл `/Out`.

### 5.2. Практические приёмы

```bash
# запуск обработки в базе от имени администратора, с ограничением по времени
timeout 2h xvfb-run -a $B/1cv8 ENTERPRISE /S "srv1c/demo" /N "Администратор" /P "***" \
    /DisableStartupDialogs /DisableStartupMessages /Out /tmp/ent.log \
    /C "Режим=Ночной;Файл=/exchange/in.xml" /Execute /opt/1c-tools/ЗагрузкаДанных.epf
```

- Обработка сама отвечает за завершение сеанса (`ЗавершитьРаботуСистемы(Ложь)`), иначе клиент останется висеть до `timeout`.
- Запуск обработчиков обновления после смены конфигурации [практика, vanessa-runner]: типовые конфигурации на БСП выполняют обновление данных при первом входе полноправного пользователя. Распространённый приём — `/C "ЗапуститьОбновлениеИнформационнойБазы;ЗавершитьРаботуСистемы;"` вместе с `/Execute <каталог vanessa-runner>/epf/ЗакрытьПредприятие.epf`: обработка дожидается окончания обновления и закрывает клиент. Приём подтверждён 2026-10-10 по README vanessa-runner (ветка LTS `release/2.6`), где он приведён дословно: `vrunner run --command "ЗапуститьОбновлениеИнформационнойБазы;ЗавершитьРаботуСистемы;" --execute $runnerRoot\epf\ЗакрытьПредприятие.epf`; в документации 3.0 тот же вызов записан как `vrunner run enterprise --command … --execute '$runnerRoot/epf/ЗакрытьПредприятие.epf'` (макрос `$runnerRoot` раскрывается в каталог установки vanessa-runner). ⚠ не подтверждено документацией БСП: как именно библиотека вашей версии обрабатывает эти параметры запуска (первоисточник — документация БСП — в этой сессии не прочитан); проверьте на копии базы, что после запуска версия в регистре обновлений изменилась, а клиент закрылся сам.
- Подводный камень `/Execute` [практика + офиц.]: при открытии внешней обработки платформа может показать предупреждение безопасности, а в пакетном режиме (`/DisableStartupDialogs`) диалог невозможен — клиент повиснет или завершится с ошибкой. Условия успешного запуска: у пользователя, под которым идёт запуск, снят флажок «Защита от опасных действий» (свойство пользователя ИБ) либо защита отключена для этой базы параметром `DisableUnsafeActionProtection=<регулярные выражения POSIX BRE по строке соединения через «;»>` в файле `conf.cfg` (при загрузке внешних обработок его читает сервер — процесс `rphost`, а для толстого клиента в режиме обычного приложения — сам клиент; подробнее — `08-konfiguracionnye-fajly-kerberos-bezopasnost.md`); у пользователя есть право интерактивно открывать внешние обработки (в типовых конфигурациях — у полноправного администратора). Файл `.epf` должен быть доступен на чтение пользователю ОС, от имени которого запущен `1cv8`.
- Регулярные задачи (обмены, расчёты) в клиент-серверной базе правильнее оформлять регламентными заданиями: они выполняются на сервере и не требуют ни клиента, ни X-сервера.

## 6. Расширения конфигурации (`.cfe`): сводка способов

| Действие | Пакетный режим конфигуратора | `ibcmd` | Агент конфигуратора |
|---|---|---|---|
| Список расширений | `/DumpDBCfgList -AllExtensions` | `infobase config extension list` | `config extensions properties get --all-extensions` |
| Создать пустое | — (создаётся при загрузке) | `extension create --name=… --name-prefix=… --purpose=…` | `config extensions create --extension=… --name-prefix=…` |
| Загрузить из `.cfe` | `/LoadCfg файл.cfe -Extension Имя` | `infobase config load --extension=Имя файл.cfe` | `config load-cfg --file=… --extension=Имя` |
| Применить (обновить БД) | `/UpdateDBCfg -Extension Имя` | `infobase config apply --extension=Имя --force` | `config update-db-cfg --extension=Имя` |
| Выгрузить в `.cfe` | `/DumpCfg файл.cfe -Extension Имя` (из БД — `/DumpDBCfg`) | `infobase config save --extension=Имя [--db] файл.cfe` | `config dump-cfg --file=… --extension=Имя` |
| Выгрузить в XML | `/DumpConfigToFiles каталог -Extension Имя` или `-AllExtensions` | `config export --extension=Имя каталог`; `config export all-extensions каталог` | `config dump-config-to-files --dir=… --extension=Имя` |
| Загрузить из XML | `/LoadConfigFromFiles каталог -Extension Имя` или `-AllExtensions` | `config import --extension=Имя каталог`; `config import all-extensions каталог` | `config load-config-from-files --dir=… --extension=Имя` |
| Свойства (активность, безопасный режим, защита от опасных действий, область действия) | нет (задаются в режиме «1С:Предприятие») | `extension update --name=Имя --active=yes\|no --safe-mode=yes\|no --unsafe-action-protection=yes\|no --scope=…` | `config extensions properties set --extension=Имя --active=… --safe-mode=…` |
| Проверить применимость | `/CheckCanApplyConfigurationExtensions [-Extension Имя]` | — | — |
| Удалить | `/DeleteCfg -Extension Имя` или `-AllExtensions` | `extension delete --name=Имя` или `--all` | `config extensions delete --extension=Имя` или `--all-extensions` |

Типовая установка или обновление расширения в рабочей базе:

```bash
designer /LoadCfg /distr/МоёРасширение.cfe -Extension МоёРасширение /UpdateDBCfg -Extension МоёРасширение
designer /CheckCanApplyConfigurationExtensions -Extension МоёРасширение
designer /DumpDBCfgList -AllExtensions            # список имён попадёт в файл /Out
```

Замечания [офиц.]:

- При работе с расширениями код возврата `0` — успех, `1` — ошибка (в том числе «расширение не найдено»).
- Если расширение подключено к хранилищу, `/LoadCfg -Extension` для него невозможен.
- Обновление расширения, меняющего структуру данных, требует тех же условий, что и обновление основной конфигурации (монопольный доступ либо динамическое обновление).
- Расширение, загруженное конфигуратором, по умолчанию получает безопасный режим и защиту от опасных действий по общим правилам платформы; для расширений типовых поставщиков их обычно отключают в режиме «1С:Предприятие» (форма «Управление расширениями конфигурации») или через `ibcmd … extension update` [практика].

## 7. Типовой регламент обновления типовой конфигурации из скрипта

### 7.1. Порядок действий

| Шаг | Что делается | Чем |
|---|---|---|
| 0 | Проверка на копии базы; чтение файла описания обновления (минимальная версия платформы, с каких релизов возможен переход) | копия базы (раздел 11.2) |
| 1 | Блокировка начала сеансов с кодом разрешения и блокировка регламентных заданий | `rac infobase update --sessions-deny=on --permission-code=… --scheduled-jobs-deny=on` |
| 2 | Ожидание и принудительное завершение оставшихся сеансов | `rac session list`, `rac session terminate` |
| 3 | Резервная копия базы данных (и при необходимости журнала регистрации) | `pg_dump -Fc` |
| 4 | Загрузка обновления в конфигурацию и обновление конфигурации базы данных | `1cv8 DESIGNER /UC <код> /UpdateCfg … /UpdateDBCfg …` |
| 5 | Запуск обработчиков обновления данных | `1cv8 ENTERPRISE /UC <код> …` |
| 6 | Снятие блокировок | `rac infobase update --sessions-deny=off --scheduled-jobs-deny=off` |
| 7 | Проверка: вход пользователя, версия конфигурации, журнал регистрации | вручную или тестами |

Правила [офиц. + практика]:

- Блокировка начала сеансов не трогает уже работающие сеансы — их нужно завершить отдельно. Войти в заблокированную базу можно только с `/UC <код разрешения>` (в строке соединения — параметр `UC`).
- Свойства блокировки: начало и конец действия, сообщение, код разрешения, параметр блокировки (`--denied-from`, `--denied-to`, `--denied-message`, `--permission-code`, `--denied-parameter`). Блокировка действует после наступления времени начала; если начало не задано — сразу.
- Файл обновления `.cfu` применим только к тем релизам, которые перечислены в его описании; «перепрыгивать» через обязательные релизы нельзя. Полный файл `1Cv8.cf` загружается командой `/LoadCfg` и **полностью заменяет** конфигурацию — годится только для конфигураций без доработок.
- Обновление выполняет пользователь ИБ с административными правами.
- Файлы `1cv8.cfu` и `1Cv8.cf` берутся из каталога шаблонов после установки дистрибутива обновления. Проще всего распаковать дистрибутив на Windows-машине и передать файл на сервер (`scp`). Каталог шаблонов по умолчанию: Linux и macOS — `~/.1cv8/1C/1cv8/tmplts`, Windows — `%APPDATA%\1C\1cv8\tmplts` [офиц., глава 3 руководства 8.3.27 — перепроверено 2026-10-10]. Документация описывает программу установки шаблона и для Linux (файл `setup` в распакованном архиве дистрибутива; мастер копирует шаблон в каталог шаблонов и записывает его в `1cestart.cfg`), но это графический мастер — на сервере без графики файл обновления удобнее привезти готовым.

### 7.2. Пример bash-скрипта [практика]

```bash
#!/usr/bin/env bash
# update-1c.sh <файл обновления .cfu или .cf>
# Регламент обновления клиент-серверной базы: блокировка -> бэкап -> обновление -> обработчики -> разблокировка
set -Eeuo pipefail

V=8.3.27.2074                         # сборка платформы
B=/opt/1cv8/x86_64/$V
RAS=localhost:1545                    # сервер администрирования
SRV=srv1c                             # имя сервера 1С, как в строке соединения
IBNAME=demo                           # имя базы в кластере
IBUSER='Администратор'                # администратор ИБ
IBPWD=${IBPWD:?задайте переменную IBPWD}
PGDB=demo                             # имя базы в PostgreSQL
BACKUP_DIR=/backup/1c
LOGDIR=/var/log/1c-update
CLOSE_EPF=/opt/1c-tools/ЗакрытьПредприятие.epf   # обработка из каталога epf пакета vanessa-runner
UPDATE_FILE=${1:?укажите файл обновления (.cfu или .cf)}
UC="upd$(date +%s)"                   # код разрешения на время обновления
STAMP=$(date +%F_%H%M)
mkdir -p "$BACKUP_DIR" "$LOGDIR"

log() { printf '%s %s\n' "$(date '+%F %T')" "$*"; }
rac() { "$B/rac" "$@" "$RAS"; }
trap 'log "ОШИБКА на строке $LINENO. Если база уже заблокирована, блокировка НЕ снята; код разрешения: $UC"' ERR

CL=$(rac cluster list | awk -F' *: *' '$1=="cluster" && !f {print $2; f=1}')
IB=$(rac infobase --cluster="$CL" summary list | awk -F' *: *' -v n="$IBNAME" \
      '$1=="infobase"{id=$2} $1=="name"{gsub(/"/,"",$2); if($2==n && !f){print id; f=1}}')
[[ -n "$IB" ]] || { log "база $IBNAME не найдена в кластере"; exit 2; }
IBAUTH=(--infobase-user="$IBUSER" --infobase-pwd="$IBPWD")

lock() {
  rac infobase --cluster="$CL" update --infobase="$IB" "${IBAUTH[@]}" \
      --sessions-deny=on --scheduled-jobs-deny=on --permission-code="$UC" \
      --denied-message="Идёт обновление программы. Повторите вход позже." >/dev/null
}
unlock() {
  rac infobase --cluster="$CL" update --infobase="$IB" "${IBAUTH[@]}" \
      --sessions-deny=off --scheduled-jobs-deny=off >/dev/null
}
sessions() { rac session --cluster="$CL" list --infobase="$IB" | awk -F' *: *' '$1=="session"{print $2}'; }
wait_free() {                         # до 5 минут: завершать сеансы, пока список не опустеет
  local i s list
  for i in $(seq 1 20); do
    # ошибка rac (ras недоступен, нет прав) НЕ должна читаться как «сеансов нет»: благодаря pipefail
    # sessions вернёт ненулевой код, и мы выходим с ошибкой, а не продолжаем обновление
    list=$(sessions) || { log "rac session list завершился ошибкой"; return 2; }
    [[ -z "$list" ]] && return 0
    for s in $list; do rac session --cluster="$CL" terminate --session="$s" >/dev/null 2>&1 || true; done
    sleep 15
  done
  return 1
}
backup() {
  local f="$BACKUP_DIR/${PGDB}_${STAMP}.dump"
  sudo -u postgres pg_dump -Fc "$PGDB" > "$f"
  pg_restore -l "$f" > /dev/null                         # файл читается как архив
  log "резервная копия: $f ($(du -h "$f" | cut -f1))"
}
onec() {                              # onec DESIGNER|ENTERPRISE <команды…>
  local mode=$1; shift
  local out="$LOGDIR/${IBNAME}_${STAMP}_${mode}.log" res rc=0
  local extra=()
  res=$(mktemp)
  [[ "$mode" == DESIGNER ]] && extra=(/DumpResult "$res")
  timeout 6h xvfb-run -a "$B/1cv8" "$mode" /S "$SRV/$IBNAME" /N "$IBUSER" /P "$IBPWD" /UC "$UC" \
      /DisableStartupDialogs /DisableStartupMessages /Out "$out" -NoTruncate "${extra[@]}" "$@" || rc=$?
  tail -n 30 "$out" || true
  if [[ "$mode" == DESIGNER ]]; then
    [[ $rc -eq 0 && "$(tr -cd '0-9' < "$res")" == "0" ]]      # код возврата и число из /DumpResult
  else
    return "$rc"
  fi
}

log "1. блокировка сеансов и регламентных заданий"; lock
log "2. завершение сеансов";                         wait_free || { log "сеансы не завершились"; exit 3; }
log "3. резервная копия";                            backup
log "4. загрузка обновления и обновление конфигурации БД"
case "$UPDATE_FILE" in
  *.cfu) onec DESIGNER /UpdateCfg "$UPDATE_FILE" -force /UpdateDBCfg -Dynamic- -Server ;;
  *.cf)  onec DESIGNER /LoadCfg  "$UPDATE_FILE"        /UpdateDBCfg -Dynamic- -Server ;;   # полная замена конфигурации!
  *)     log "неизвестный тип файла"; exit 4 ;;
esac
log "5. обработчики обновления"
onec ENTERPRISE /C "ЗапуститьОбновлениеИнформационнойБазы;ЗавершитьРаботуСистемы;" /Execute "$CLOSE_EPF"
log "6. снятие блокировки";                          unlock
log "готово"
```

Пояснения к скрипту:

- Пароль администратора ИБ передаётся через окружение (`IBPWD='…' ./update-1c.sh файл`), чтобы не хранить его в тексте скрипта. Пароль всё равно виден в списке процессов на время работы `1cv8` — запускайте скрипт на доверенном сервере.
- Скрипту нужны права `sudo -u postgres` без пароля (либо замените `pg_dump` на подключение по TCP с файлом `~/.pgpass`).
- При ошибке блокировка **не снимается** намеренно: администратор разбирается и либо повторяет шаг (войдя с `/UC <код>`), либо восстанавливает копию.
- `/UpdateCfg` вызван без `-Settings` — так же поступают v8runner и `vrunner cf vendor-update` (раздел 4.4); годится только для типовой конфигурации без доработок. При ошибке или для доработанной конфигурации добавьте файл настроек объединения.
- Параметры запуска на шаге 5 — приём из README vanessa-runner (подтверждён, раздел 5.2). Обработку `ЗакрытьПредприятие.epf` берут из каталога `epf` установленного пакета vanessa-runner и кладут по пути `CLOSE_EPF`; пользователю `IBUSER` нужна отключённая защита от опасных действий (раздел 5.2), иначе шаг повиснет до `timeout`. Если обработки нет, шаг 5 заменяют первым интерактивным входом администратора.
- Скрипт рассчитан на кластер **без** администратора кластера. Если администратор задан, во все вызовы `rac` с `--cluster=` добавьте `--cluster-user=… --cluster-pwd=…` — иначе шаг 1 завершится ошибкой (и это правильное поведение: дальше скрипт не пойдёт).
- Запускайте скрипт от обычного пользователя с настроенным `sudo` (не от `root`): `1cv8` создаёт кеш и настройки в домашнем каталоге запускающего (`~/.1cv8`, `~/.1C`), а лицензию ищет по общим правилам.
- Функция `wait_free` отличает «сеансов нет» от «`rac` вернул ошибку»: при ошибке `rac session list` обновление не начинается.
- Перед первым боевым применением прогоните скрипт на копии базы (раздел 11.2) — в этой статье он не запускался на живом сервере.
- Для большой базы дамп ускоряют: `pg_dump -Fd -j 4 -f <каталог>` (параллельно, формат «каталог»).

Восстановление базы из копии, если обновление не удалось:

```bash
sudo systemctl stop srv1cv8-$V@default                 # либо убедиться, что соединений с базой нет
sudo -u postgres dropdb demo
sudo -u postgres createdb -T template0 -E UTF8 -l ru_RU.UTF-8 -O usr1c demo
sudo -u postgres pg_restore -d demo /backup/1c/demo_2026-10-10_2200.dump
sudo systemctl start srv1cv8-$V@default
```

### 7.3. Вариант через `ibcmd` (без графики)

Подходит, если на время обновления можно остановить службу сервера 1С (раздел 3.1).

```bash
sudo systemctl stop srv1cv8-$V@default
sudo -u postgres pg_dump -Fc demo > /backup/1c/demo_$(date +%F_%H%M).dump
"${IBC[@]}" infobase config load  "${CONN[@]}" --force /distr/1Cv8.cf        # полная замена конфигурации
"${IBC[@]}" infobase config apply "${CONN[@]}" --force --dynamic=disable

# обработчики обновления — запуском клиента (шаг 5 скрипта) или первым входом администратора
```

В 8.3.x утилита `ibcmd` не умеет обновлять конфигурацию на поддержке по файлу `.cfu` — для этого нужен конфигуратор (`/UpdateCfg`). В 8.5.4 добавлена команда `ibcmd config update` — «прямая загрузка обновления в основную конфигурацию» [офиц., V8Update 8.5.4 — перепроверено 2026-10-10; обзор «Новое в платформе 8.5.4» описывает её как команду, которая «загружает обновление в базу»]; ⚠ не подтверждено, какие файлы она принимает (`.cfu`? `.cf`?), с какими параметрами и учитывает ли правила поддержки (смотреть `ibcmd help config` версии 8.5.4+ и раздел 4.10 документации `v854doc`). До проверки на копии базы считайте, что обновление конфигурации на поддержке без графики по-прежнему делается только конфигуратором.

### 7.4. То же средствами vanessa-runner 3.0 [офиц. документация проекта]

```bash
COMMON=(--ras localhost:1545 --db-name demo --db-user Администратор --db-pwd '***')
vrunner cluster session lock   "${COMMON[@]}" --uccode UPD2026 --denied-message "Обновление программы"
vrunner cluster jobs lock      "${COMMON[@]}"
vrunner cluster session closed "${COMMON[@]}" --filter-app BackgroundJob --timeout 600   # дождаться фоновых заданий
vrunner cluster session kill   "${COMMON[@]}" --timeout 120                               # завершить остальные сеансы
sudo -u postgres pg_dump -Fc demo > /backup/1c/demo_$(date +%F_%H%M).dump
vrunner cf vendor-update -s /distr/1cv8.cfu --ibconnection '/Ssrv1c\demo' \
        --db-user Администратор --db-pwd '***' --uccode UPD2026 --force                   # /UpdateCfg + обновление БД
vrunner run enterprise --ibconnection '/Ssrv1c\demo' --db-user Администратор --db-pwd '***' --uccode UPD2026 \
        --command "ЗапуститьОбновлениеИнформационнойБазы;ЗавершитьРаботуСистемы;" \
        --execute '$runnerRoot/epf/ЗакрытьПредприятие.epf'
vrunner cluster jobs unlock    "${COMMON[@]}"
vrunner cluster session unlock "${COMMON[@]}"
```

`vrunner cluster session kill` сам ставит блокировку перед завершением сеансов (отключается ключом `--no-lock`), делает до трёх попыток с паузой 3 секунды (число попыток — `--retry`, по умолчанию 3; при заданном `--timeout` игнорируется) и возвращает код 1, если сеансы остались. `vrunner cluster session closed` проверяет отсутствие сеансов каждые 3 секунды в пределах `--timeout` (по умолчанию `0` — одна проверка). `vrunner cf vendor-update` после `/UpdateCfg` сам обновляет конфигурацию БД (отключается `--no-update-db`); файл настроек объединения — необязательная `--update-settings`. На Linux команды, запускающие конфигуратор или клиент, оборачивают в `xvfb-run -a` [документация vanessa-runner 3.0 — перепроверено 2026-10-10].

О записи `--ibconnection` для серверной базы: документация vrunner даёт только форму с обратной косой чертой — `/S<сервер>\<база>` (пример `"/SMyServer\MyInfobase"`). vanessa-runner передаёт это значение платформе как есть, а платформа по своей документации принимает `server/base` в любой ОС, а `server\base` на Linux — только если значение дошло до неё целиком (в bash — в одинарных кавычках, как в примерах выше). ⚠ не подтверждено живым запуском vrunner 3.0 на Linux, какая из двух записей надёжнее; если с `'/Ssrv1c\demo'` база «не обнаружена», попробуйте `--ibconnection /Ssrv1c/demo`.

## 8. Хранилище конфигураций: сервер `crserver` на Linux

### 8.1. Что это и когда нужно

Хранилище конфигурации — средство групповой разработки. Оно может лежать в общем каталоге (тогда сервер не нужен) либо обслуживаться сервером хранилища `crserver` по протоколу TCP или, через веб-сервер, по HTTP. Администратору рабочей базы сервер хранилища нужен только там, где ведётся доработка конфигурации.

| Параметр | Значение | Статус |
|---|---|---|
| Исполняемый файл | `/opt/1cv8/x86_64/<версия>/crserver` | [офиц.] |
| Компонент установщика `.run` | `config_storage_server` (пакет `crs` зависит от `common`, `server`, `ws`) | [офиц.] |
| Порт по умолчанию | `1542/tcp` | [офиц., редакция документации 8.3.3; практика] |
| Версия | версии конфигуратора и сервера хранилища должны совпадать, иначе хранилище недоступно | [офиц., редакция 8.3.3] |
| Адрес по TCP | `tcp://<сервер>[:<порт>]/<имя хранилища>` — имя есть путь относительно корневого каталога | [офиц., редакция 8.3.3] |
| Адрес по HTTP | `http://<сервер>/<виртуальный каталог>/<файл>.1ccr/<имя хранилища>` | [офиц., редакция 8.3.3] |
| Хранилище по умолчанию | каталог `maincr` в корневом каталоге (используется, если имя не указано) | подтверждено «Руководством разработчика» 8.3.27, разд. 37.4.6–37.4.7 (хранилище по умолчанию — каталог `maincr`; сверено 11.10.2026); ранее: по редакции 8.3.3, в актуальной документации не проверено |

Параметры запуска [офиц., редакция 8.3.3 — сверено 11.10.2026 с «Руководством разработчика» 8.3.27, разд. 37.4.5.2: для Linux — `./crserver -daemon -port <порт> -d <каталог>`; `-d` — корневой каталог хранилищ (по умолчанию `/home/usr1cv8/.1cv8` или `~/.1cv8`), `-port` — рабочий порт (по умолчанию 1542), `-daemon` — запуск демоном; при ошибке «too many open files» документация советует поднять `nofile` в `/etc/security/limits.conf`; ранее: сверить с документацией своей версии, раздел о сервере хранилища в «Руководстве разработчика»]:

| Параметр | Назначение |
|---|---|
| `-port <порт>` | рабочий порт (по умолчанию 1542) |
| `-d <каталог>` | корневой каталог хранилищ |
| `-daemon` | запуск в режиме демона (Linux) |
| `-instsrvc`, `-rmsrvc`, `-start`, `-stop`, `-usr`, `-pwd` | регистрация и управление службой — только Windows |

Имя параметра и значение разделяются пробелом.

### 8.2. Установка и запуск службой [практика]

```bash
# 1. компонент сервера хранилища (если не был установлен вместе с сервером)
sudo ./setup-full-$V-x86_64.run --mode unattended --enable-components server,ws,config_storage_server,ru
ls -l $B/crserver

# 2. каталог хранилищ
sudo install -d -o usr1cv8 -g grp1cv8 -m 750 /var/lib/1c/crs

# 3. юнит systemd (в поставке платформы готового юнита для crserver нет)
sudo tee /etc/systemd/system/crserver.service >/dev/null <<EOF
[Unit]
Description=1C:Enterprise configuration repository server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=usr1cv8
Group=grp1cv8
ExecStart=$B/crserver -port 1542 -d /var/lib/1c/crs
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now crserver
systemctl status crserver --no-pager
sudo ss -tlnp | grep 1542
sudo ufw allow from 192.168.1.0/24 to any port 1542 proto tcp comment '1C repository'
```

- Без `-daemon` процесс работает на переднем плане — это подходит для `Type=simple` (так запускают `crserver` в образах onec-docker: `crserver -port 1542 -d /home/usr1cv8/.1cv8`). С `-daemon` нужен `Type=forking`.
- Путь в `ExecStart` содержит номер версии: при обновлении платформы юнит правят, а конфигураторы разработчиков обновляют до той же сборки.

Создание хранилища и пользователей — из конфигуратора (меню «Конфигурация → Хранилище конфигурации → Создать хранилище», адрес `tcp://srv1c/erp`) либо пакетно:

```bash
designer /ConfigurationRepositoryF "tcp://srv1c/erp" /ConfigurationRepositoryN "Администратор" /ConfigurationRepositoryP '***' \
         /ConfigurationRepositoryCreate -AllowConfigurationChanges -ChangesAllowedRule ObjectNotEditable -ChangesNotRecommendedRule ObjectNotEditable
designer /ConfigurationRepositoryF "tcp://srv1c/erp" /ConfigurationRepositoryN "Администратор" /ConfigurationRepositoryP '***' \
         /ConfigurationRepositoryAddUser -User ivanov -Pwd 'P@ss' -Rights LockObjects
```

### 8.3. Доступ по HTTP через Apache 2.4 [практика, по образу onec-docker `crs-apache`]

Нужны: работающий `crserver`, Apache 2.4 и модуль расширения веб-сервера `wsap24.so` (компонент `ws`) той же версии.

```bash
sudo apt install -y apache2
sudo install -d -o www-data -g www-data /var/www/repo
sudo tee /var/www/repo/repo.1ccr >/dev/null <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<repository connectString="tcp://localhost"/>
EOF
sudo tee /etc/apache2/conf-available/1c-repo.conf >/dev/null <<EOF
LoadModule _1cws_module "$B/wsap24.so"
AddHandler 1cws-process .1ccr
Alias /repo /var/www/repo
<Directory /var/www/repo>
    AllowOverride None
    Options None
    Require all granted
    SetHandler 1cws-process
</Directory>
EOF
sudo a2enconf 1c-repo && sudo apachectl configtest && sudo systemctl reload apache2
```

Адрес хранилища для разработчиков: `http://srv1c/repo/repo.1ccr/erp`.

- Файл `.1ccr` содержит адрес сервера хранилища: `connectString="tcp://<хост>[:<порт>]"`.
- Если модуль `_1cws_module` уже подключён в `apache2.conf` утилитой `webinst`, строку `LoadModule` в этом файле уберите (Apache предупредит о повторной загрузке).
- В редакции документации 8.3.3 для Apache 2.0/2.2 пример даётся с директивой `SetHandler 1c-application`; обработчик `1cws-process` для `.1ccr` взят из рабочего образа onec-docker. **Уточнено 11.10.2026** («Руководство разработчика» 8.3.27, разд. 37.4.4): и в актуальной документации идентификатор обработчика для каталога хранилища — `1c-application` (пример для Linux: `Alias "/repos" "/var/1C/www/repos"` и в секции `<Directory>` — `SetHandler 1c-application`), а файл `.1ccr` с узлом вида `<storage connectString="tcp://RepServ"/>` кладут в этот каталог; примеры в документации по-прежнему даны в синтаксисе Apache 2.2 (`Order allow,deny`). Обработчик `1cws-process` в этой главе не упоминается. Ранее было не подтверждено по актуальной документации — при ошибке 404/500 сверить с разделом о настройке веб-сервера для хранилища.
- HTTPS и аутентификация настраиваются средствами Apache; доступ к хранилищу из интернета без HTTPS не открывают.

## 9. Инструменты автоматизации

### 9.1. OneScript (`oscript`) и менеджер пакетов `opm`

OneScript — открытая кроссплатформенная реализация исполнителя встроенного языка 1С для скриптов (`.os`); платформа 1С для него не нужна. На нём написаны vanessa-runner, gitsync и другие утилиты. Линейка 2.x работает на .NET 8; 1.x — на .NET Framework 4.8 / Mono [офиц. oscript.io].

| Способ установки | Суть | Статус |
|---|---|---|
| Менеджер версий `ovm` (рекомендуется проектом) | `ovm.exe` с GitHub (`oscript-library/ovm`), на Linux запускается как `mono ovm.exe`; нужен Mono 6+ | [офиц. oscript.io] |
| Независимый дистрибутив (SCD) | архив для Linux со встроенной средой .NET: распаковать, выдать право исполнения, добавить `bin` в `PATH` | [офиц. oscript.io] |
| Дистрибутив, требующий .NET (FDD) | нужен установленный .NET 8 | [офиц. oscript.io] |
| Пакеты `deb` / `rpm`, zip-архив | есть на странице загрузок | [офиц. oscript.io] |

```bash
# вариант 1: ovm
sudo apt install -y mono-complete
wget https://github.com/oscript-library/ovm/releases/latest/download/ovm.exe
mono ovm.exe install stable && mono ovm.exe use stable
mono ovm.exe ls                                   # установленные версии

# вариант 2: независимый дистрибутив (SCD), скачанный со страницы https://oscript.io/downloads
sudo mkdir -p /opt/onescript && sudo unzip OneScript-*-linux-x64.zip -d /opt/onescript   # имя архива условное
sudo chmod +x /opt/onescript/bin/oscript
echo 'export PATH=/opt/onescript/bin:$PATH' | sudo tee /etc/profile.d/onescript.sh
sudo apt install -y tzdata libicu74               # Ubuntu 24.04; в 22.04 пакет называется libicu70

# проверка
echo 'Сообщить("Привет, OneScript!");' > /tmp/test.os && oscript /tmp/test.os
```

- Каталог установки `ovm` по умолчанию — `ovm` в домашнем каталоге пользователя, меняется переменной `OVM_INSTALL_PATH`; каталог `bin` активной версии добавляют в `PATH` [офиц. oscript.io].
- Адреса для скриптов скачивания строятся как `https://oscript.io/downloads/<версия>/<тип>` (версия: `latest`, `lts`, `preview`; тип: `deb`, `rpm`, `zip`, `scd-lin`, `fdd`) — ⚠ точный вид адреса сверить на странице загрузок.
- Пакеты ставит `opm`: `opm install <пакет>`, `opm update <пакет>`, `opm install -f файл.ospx` (без интернета).

### 9.2. vanessa-runner (`vrunner`)

Консольная утилита автоматизации задач разработчика и администратора 1С: сборка и разборка конфигураций, расширений и обработок, создание и обновление баз, работа с хранилищем, управление кластером, запуск тестов. Операции с базой выполняются через конфигуратор либо через `ibcmd` (ключ `--ibcmd`) [офиц. документация проекта].

| Факт | Значение |
|---|---|
| Актуальная линейка | 3.0 — несовместима с 2.x по набору команд, файлу настроек и переменным окружения |
| Требования 3.0 | OneScript 2.0.0+; платформа 1С — для команд, работающих с базами |
| Установка | `opm install vanessa-runner`; LTS 2.x: `opm install vanessa-runner@2.6.1` (ветка `release/2.6`, OneScript 1.9.2+) |
| Проверка | `vrunner --version` |
| Синтаксис 3.0 | `vrunner <группа> <подкоманда> [опции] [аргумент]` (опции — перед позиционным аргументом) |
| Файл настроек | `autumn-properties.json` (в 2.x — `vrunner.json`); другой файл — `--settings` |
| Переменные окружения | `VRUNNER_*` (в 2.x — `RUNNER_*`): `VRUNNER_IBCONNECTION`, `VRUNNER_DBUSER`, `VRUNNER_DBPWD`, `VRUNNER_V8VERSION`, `VRUNNER_UCCODE` |

| Группа 3.0 | Подкоманды | Старые имена 2.x |
|---|---|---|
| `cf` | `compile`, `decompile`, `load`, `unload`, `convert`, `make-dist`, `merge`, `vendor-update`, `compare` | `compile`, `decompile`, `update` |
| `cfe` | `compile`, `decompile`, `load`, `unload`, `convert`, `compare` | `compileext`, `decompileext` |
| `epf` | `compile`, `decompile`, `convert` | `compileepf`, `decompileepf` |
| `infobase` | `init`, `update`, `dump-dt`, `restore-dt`, `create-user`, `extensions`, `scheduled-job`, `lock-resources` | `init-dev`, `update-dev`, `updatedb` |
| `repo` | `create`, `bind`, `unbind`, `load`, `lock`, `unlock`, `commit`, `save-cf`, `create-user`, `copy-user` | `loadrepo` |
| `cluster` | `create`, `remove`, `info`, `session lock\|unlock\|list\|kill\|closed`, `jobs lock\|unlock` | `session …`, `scheduledjobs …` |
| `run` | `designer`, `enterprise` | `designer`, `run` |
| `test` | `xunit`, `yaxunit`, `vanessa` | `xunit`, `vanessa` |
| `validate` | `syntax-check`, `edt` | `syntax-check` |

Общие опции: `--ibconnection` (`/F<путь>` или `/S<сервер>\<база>`), `--db-user` / `--db-pwd` (пользователь **информационной базы**), `--v8version`, `--uccode`, `--ibcmd`, `--language`, `--locale`, `--additional`; для кластера — `--ras` (по умолчанию `localhost:1545`), `--rac`, `--db-name`, `--cluster`, `--cluster-admin`, `--cluster-pwd`; для СУБД — `--dbms-type`, `--dbms-server`, `--dbms-base`, `--dbms-user`, `--dbms-pwd`; для хранилища — `--storage-name`, `--storage-user`, `--storage-pwd`, `--storage-ver`.

```bash
vrunner cluster create --db-name demo --dbms-type PostgreSQL --dbms-server localhost --dbms-base demo \
        --dbms-user usr1c --dbms-pwd '***' --ib-locale ru_RU        # создать базу в кластере (rac)
vrunner cluster info   --db-name demo
vrunner infobase dump-dt    --ibconnection '/Ssrv1c\demo' --db-user Администратор --db-pwd '***' /backup/demo.dt
vrunner infobase restore-dt --ibconnection '/Ssrv1c\demo' --db-user Администратор --db-pwd '***' /backup/demo.dt
vrunner cf load --ibconnection '/Ssrv1c\demo' --db-user Администратор --db-pwd '***' /distr/1Cv8.cf   # загрузить .cf и обновить БД
vrunner cfe load --ibconnection '/Ssrv1c\demo' --extension-name Patch1 /distr/Patch1.cfe
vrunner infobase extensions list --ibconnection '/Ssrv1c\demo' --json
vrunner cf compile --ibcmd -s ./src ./build/1Cv8.cf                 # собрать .cf из исходников через ibcmd, без графики
```

Точные значения опций `--dbms-type` и других — в справке `vrunner cluster create --help` (⚠ в примере значение `PostgreSQL` указано по аналогии с `rac`).

### 9.3. gitsync — выгрузка истории хранилища в git

| Факт | Значение | Статус |
|---|---|---|
| Назначение | синхронизация хранилища конфигурации 1С с репозиторием git (каждая версия хранилища — коммит) | [офиц. README] |
| Версия | 3.9.0; требует OneScript 1.9.2+ | [офиц. README] |
| Установка | `opm install gitsync`; без интернета — `opm install -f gitsync-*.ospx` | [офиц. README] |
| Доступ к хранилищу | файловый каталог, `tcp://`, `http://` | [офиц. README] |
| Плагины | `gitsync plugins init`, `gitsync plugins enable <имя>` или `-a`, `gitsync plugins list [-a]`; на Linux лежат в `$HOME/.local/share` | [офиц. README] |

```bash
opm install gitsync && gitsync plugins init
export GITSYNC_V8_PATH=$B/1cv8                                  # либо глобальная опция --v8-path
export GITSYNC_STORAGE_USER=gitsync GITSYNC_STORAGE_PASSWORD='***'
gitsync init  tcp://srv1c/erp /srv/git/erp/src                  # подготовить каталог: файлы AUTHORS и VERSION
xvfb-run -a gitsync sync tcp://srv1c/erp /srv/git/erp/src       # выгрузить новые версии хранилища коммитами
gitsync set-version 120 /srv/git/erp/src                        # задать номер последней синхронизированной версии
```

Синтаксис: `gitsync init [ОПЦИИ] PATH [WORKDIR]`, `gitsync sync [ОПЦИИ] PATH [WORKDIR]` (сокращение `s`), `gitsync clone [ОПЦИИ] PATH URL [WORKDIR]`, `gitsync set-version <номер> [каталог]` (сокращение `sv`). Опции `sync`: `-u`, `--storage-user` (по умолчанию «Администратор»), `-p`, `--storage-pwd`, `-e`, `--ext` (имя расширения). Переменные: `GITSYNC_V8VERSION`, `GITSYNC_V8_PATH`, `GITSYNC_WORKDIR`, `GITSYNC_STORAGE_PATH`, `GITSYNC_STORAGE_USER`, `GITSYNC_STORAGE_PASSWORD`, `GITSYNC_EXTENSION`, `GITSYNC_TEMP`, `GITSYNC_VERBOSE`. gitsync вызывает конфигуратор, поэтому на сервере без графики нужен `xvfb-run`.

### 9.5. CI: Jenkins и GitLab CI [практика]

- Сборочный агент — Linux-машина (или контейнер) с платформой 1С нужной версии, `xvfb`, OneScript, vanessa-runner, при необходимости EDT. Готовые Dockerfile для таких агентов — репозиторий `firstBitMarksistskaya/onec-docker` (образы `onec-server`, `onec-client`, `onec-client-vnc`, `onec-crs`, `oscript`, `runner`, `edt`, агенты Jenkins для Docker Swarm и Kubernetes). Дистрибутивы платформы для сборки образов берутся с releases.1c.ru под учётной записью пользователя.
- Лицензии: агенту, запускающему конфигуратор и клиент, нужна клиентская лицензия; для `ibcmd` с клиент-серверной базой — серверная. Для файловых баз `ibcmd` обходится без лицензии до трёх сеансов [офиц., V8Update 8.3.20].
- Конвейер обычно состоит из шагов: сборка `.cf` из исходников → создание тестовой базы → синтаксический контроль → тесты → публикация артефакта.

```groovy
// Jenkinsfile (декларативный конвейер, агент с меткой linux-1c)
pipeline {
  agent { label 'linux-1c' }
  stages {
    stage('Сборка cf')       { steps { sh 'vrunner cf compile --ibcmd -s ./src ./build/1Cv8.cf' } }
    stage('Тестовая база')   { steps { sh 'xvfb-run -a vrunner infobase init --src ./build/1Cv8.cf' } }
  }
  post { always { archiveArtifacts artifacts: 'build/*.cf', allowEmptyArchive: true } }
}
```

```yaml
# .gitlab-ci.yml (shell-исполнитель GitLab Runner на сервере с платформой 1С)
stages: [build, deploy]
build_cf:
  stage: build
  tags: [linux-1c]
  script:
    - vrunner cf compile --ibcmd -s ./src ./build/1Cv8.cf
  artifacts:
    paths: [build/1Cv8.cf]
deploy_test:
  stage: deploy
  tags: [linux-1c]
  when: manual
  script:
    - xvfb-run -a vrunner cf load --ibconnection '/Ssrv1c\demo_test' --db-user "$IB_USER" --db-pwd "$IB_PWD" ./build/1Cv8.cf
```

Пароли в CI хранят в защищённых переменных (Jenkins Credentials, GitLab CI/CD Variables), а не в репозитории.

## 10. Список баз (`ibases.v8i`) и программа запуска `1cestart`

### 10.1. Файлы и их расположение [офиц., 8.3.27]

| Файл | Назначение | Linux | Windows |
|---|---|---|---|
| `ibases.v8i` | список информационных баз пользователя; UTF-8 | `~/.1C/1cestart/ibases.v8i` | `%APPDATA%\1C\1CEStart\ibases.v8i` |
| `1cestart.cfg` | настройки программ запуска и клиентов; **UTF-16LE** | `~/.1C/1cestart/1cestart.cfg` | `%APPDATA%\1C\1CEStart\`, для всех пользователей — `%ALLUSERSPROFILE%\1C\1CEStart\` |
| `1cescmn.cfg` | общий конфигурационный файл | в Linux не используется | каталог сетевой установки |
| `*.v8i` | списки общих баз (тот же формат, что `ibases.v8i`), подключаются параметром `CommonInfoBases` | любой доступный путь | любой доступный путь |

Программы запуска: `1cestart` (подбирает нужную установленную версию; на Linux — `/opt/1cv8/common/1cestart`) и `1cv8s` (окно со списком баз). В скриптах на сервере вызывают исполняемый файл нужной версии напрямую: `/opt/1cv8/x86_64/<версия>/1cv8`.

### 10.2. Формат `ibases.v8i`

Одна секция — одна база; имя секции (в квадратных скобках) — наименование базы в списке.

```ini
[Демо (сервер srv1c)]
Connect=Srvr="srv1c";Ref="demo";
ID=9d2c0c3e-7c8e-4a56-8d6f-0d1f2a3b4c5d
Folder=/Рабочие базы
OrderInList=16384
OrderInTree=16384
ClientConnectionSpeed=Normal
App=Auto
WA=1
Version=8.3
AdditionalParameters=/TechnicalSpecialistMode

[Демо (через веб-сервер)]
Connect=ws="https://srv1c.example.local/demo";
App=ThinClient
```

| Параметр | Назначение | Значения |
|---|---|---|
| `Connect` | строка соединения (обязателен) | `File=<путь>;` \| `Srvr=<сервер>;Ref=<база>;` \| `ws="<url>";` |
| `ID` | внутренний идентификатор базы | формируется автоматически; вручную задавать не рекомендуется; по нему назван каталог кеша `~/.1cv8/1C/1cv8/<ID>` |
| `Folder` | папка в дереве баз | например `/Рабочие базы`; пусто — корень |
| `OrderInList`, `OrderInTree` | порядок в списке и в ветви дерева | числа |
| `ClientConnectionSpeed` | скорость соединения | `Normal`, `Low` |
| `App` | тип клиента | `Auto`, `ThinClient`, `ThickClient`, `WebClient` |
| `DefaultApp` | клиент, определённый программой запуска автоматически | `ThinClient`, `ThickClient` |
| `WA` | аутентификация ОС | `1` — сначала средствами ОС, затем запрос; `0` — всегда логин и пароль |
| `WSA` | аутентификация ОС на веб-сервере | `1` / `0` |
| `Version` | версия платформы для запуска базы | `8.3` или полная `8.3.27.2074` |
| `DefaultVersion` | версия, реально использованная при последнем запуске | записывается автоматически |
| `AdditionalParameters` | дополнительные параметры запуска | например `/TechnicalSpecialistMode` |
| `UseProxy`, `PSrv`, `PPort`, `PUser`, `PPasswd` | прокси для ws-соединения | `UseProxy`: `0` — нет, `1` — авто, `2` — явно |
| `HttpsCA`, `HttpsCAFile`, `HttpsCert`, `HttpsCertFile` | источники сертификатов для HTTPS | `None`, `File`, `Windows`, `Linux`, `macOS` |
| `AppArch` | разрядность клиента | как у команды `/AppArch` |

Способы пополнить список без ручной правки: `1cv8 CREATEINFOBASE … /AddToList <имя>`; интерактивно «Добавить… → Добавление в список существующей информационной базы»; раздача общего списка через `CommonInfoBases`; запуск со списком из файла `1cv8 /RunShortcut /path/list.v8i`. Запуск базы по имени из списка: `1cv8 ENTERPRISE /IBName "Демо (сервер srv1c)"`.

### 10.3. `1cestart.cfg`

Строки вида `Параметр=Значение`, кодировка UTF-16LE.

| Параметр | Назначение |
|---|---|
| `CommonInfoBases` | путь к файлу списка общих баз (`*.v8i`); можно несколько строк |
| `DefaultVersion` | версия по умолчанию, например `DefaultVersion=8.3-8.3.27` |

## 11. Перенос и копирование базы

### 11.1. Выгрузка `.dt` и дамп PostgreSQL: что выбрать

| Критерий | Выгрузка `.dt` | `pg_dump` / `pg_restore` |
|---|---|---|
| Что это | образ информационной базы в формате платформы, не зависящий от СУБД | логический дамп одной базы PostgreSQL |
| Чем делается | конфигуратор (`/DumpIB`, `/RestoreIB`), `ibcmd infobase dump\|restore` | утилиты PostgreSQL |
| Работа пользователей во время выгрузки | невозможна: нужен монопольный доступ, никаких подключений | возможна: `pg_dump` делает согласованный снимок и не блокирует ни чтение, ни запись |
| Перенос между СУБД и между файловым и клиент-серверным вариантами | да — основное назначение | нет: только PostgreSQL → PostgreSQL (той же или более новой основной версии) |
| Скорость и ресурсы | медленно, большой расход памяти; загрузка требует на сервере 1С места под временные файлы примерно в размер развёрнутой базы; итоговая база может быть в несколько раз больше файла `.dt` | быстрее; параллельно в формате «каталог» (`-Fd -j N`), параллельное восстановление `pg_restore -j N` |
| Пригодность как резервной копии | **не рекомендуется** документацией 1С: при ошибках в базе файл может не загрузиться | для небольших баз годится; для промышленной эксплуатации — физические копии и архив WAL (`pg_basebackup`, pg_probackup) |
| Что не попадает | журнал регистрации; хранилище двоичных данных попадает только при выгрузке клиент-серверной базы, где оно создано | журнал регистрации, внешнее хранилище двоичных данных; роли и табличные пространства (`pg_dumpall --globals-only`) |
| Совместимость версий | `.dt` версий 8.1 и 8.2 загружается в 8.3; `.dt` из 8.3.1+ не загружается в более старые версии | архив восстанавливается на той же или более новой основной версии PostgreSQL |

Ускорение загрузки `.dt` [офиц.]: `/RestoreIB <файл> -JobsCount <N>` (8.3.19+); максимальный эффект — когда сервер 1С и сервер СУБД на одном компьютере или связаны сетью от 1 Гбит/с. Перенос между СУБД без `.dt` — `ibcmd infobase replicate` (8.3.23+).

Перенос файловой базы в клиент-серверный вариант [офиц.]: выгрузить файловую базу в `.dt` → создать пустую клиент-серверную базу → загрузить в неё `.dt`. Перед выгрузкой и загрузкой закрыть все сеансы.

```bash
"${IBC[@]}" infobase dump --db-path=/srv/1c/filebase --data=/var/lib/1c/ibcmd/filebase \
     --user=Администратор --password='***' /backup/filebase.dt                 # выгрузка файловой базы
"${IBC[@]}" infobase create --dbms=PostgreSQL --db-server=localhost --db-name=newbase --db-user=usr1c --db-pwd='Secret#1' \
     --data=/var/lib/1c/ibcmd/newbase --create-database --restore=/backup/filebase.dt
$RAC infobase --cluster=$CL create --name=newbase --dbms=PostgreSQL --db-server=localhost --db-name=newbase \
     --locale=ru_RU --db-user=usr1c --db-pwd='Secret#1' --license-distribution=allow
```

### 11.2. Копия базы внутри одного сервера PostgreSQL

Вариант А — `createdb -T` (самый быстрый, копирование на уровне файлов). Ограничение PostgreSQL: пока идёт копирование, к базе-источнику не должно быть **ни одного** другого подключения; при наличии подключений команда завершается ошибкой [офиц. PostgreSQL]. Рабочие процессы 1С держат соединения с базой, поэтому сервер 1С на это время останавливают либо освобождают базу.

```bash
sudo systemctl stop srv1cv8-$V@default
sudo -u postgres createdb -T demo -O usr1c demo_copy
sudo systemctl start srv1cv8-$V@default
```

Вариант Б — `pg_dump | pg_restore` (без остановки работы пользователей).

```bash
sudo -u postgres createdb -T template0 -E UTF8 -l ru_RU.UTF-8 -O usr1c demo_copy
sudo -u postgres pg_dump -Fc demo | sudo -u postgres pg_restore -d demo_copy          # через конвейер: без -j
# то же параллельно, через каталог на диске
sudo -u postgres pg_dump -Fd -j 4 -f /var/tmp/demo.dir demo
sudo -u postgres pg_restore -j 4 -d demo_copy /var/tmp/demo.dir && sudo rm -rf /var/tmp/demo.dir
```

Регистрация копии в кластере (база данных уже содержит ИБ — кластер просто подключится к ней):

```bash
$RAC infobase --cluster=$CL create --name=demo_copy --dbms=PostgreSQL --db-server=localhost --db-name=demo_copy \
     --locale=ru_RU --db-user=usr1c --db-pwd='Secret#1' --license-distribution=allow --scheduled-jobs-deny=on
```

Обязательно после копирования [практика]:

- Блокировка регламентных заданий (`--scheduled-jobs-deny=on`): иначе копия начнёт выполнять обмены, рассылки и загрузки наравне с рабочей базой.
- При первом входе типовые конфигурации спрашивают, перемещена база или это копия, — выбирать «Это копия», чтобы отключить синхронизации и работу с внешними ресурсами.
- У новой регистрации свой идентификатор и пустой журнал регистрации. Чтобы перенести журнал, каталог `1Cv8Log` копируют из каталога старой базы в каталог новой (`…/reg_1541/<UUID>/1Cv8Log`) при остановленном сервере 1С [офиц.: восстановление журнала — при остановленном кластере].

Параметры `pg_dump` / `pg_restore` [офиц. PostgreSQL 18]: `-F c|d|t|p` — формат (custom, каталог, tar, SQL); `-j N` — параллельность (у `pg_dump` только с `-Fd`; у `pg_restore` — для форматов custom и каталог, не из конвейера и не вместе с `-1`); `-Z` — сжатие (`gzip`, `lz4`, `zstd`, например `-Z zstd:level=9`); `-f` — файл или каталог; `-d` — база; `-C` — создать базу из архива; `-c --if-exists` — удалять объекты перед восстановлением; `-O` — не восстанавливать владельцев; `-x` — не восстанавливать права; `--no-tablespaces` — всё в табличное пространство по умолчанию; `-1` — одной транзакцией; `-e` — остановиться на первой ошибке; `-l` / `-L` — оглавление архива и выборочное восстановление.

### 11.3. Перенос базы на другой сервер

```bash
# на исходном сервере
sudo -u postgres pg_dumpall --globals-only > /backup/globals.sql      # роли и табличные пространства
sudo -u postgres pg_dump -Fc demo > /backup/demo.dump
scp /backup/globals.sql /backup/demo.dump admin@srv2:/backup/

# на новом сервере (PostgreSQL с патчем 1С, та же или более новая основная версия)
sudo -u postgres createuser --pwprompt usr1c                            # либо выборочно из globals.sql
sudo -u postgres createdb -T template0 -E UTF8 -l ru_RU.UTF-8 -O usr1c demo
sudo -u postgres pg_restore -j 4 -d demo /backup/demo.dump
$RAC infobase --cluster=$CL2 create --name=demo --dbms=PostgreSQL --db-server=localhost --db-name=demo \
     --locale=ru_RU --db-user=usr1c --db-pwd='***' --license-distribution=allow
```

- Целевой PostgreSQL должен быть сборкой для 1С: база использует типы и функции из патча 1С (`mchar`, `mvarchar`, `fulleq`, `fasttrun` и др.); на «ванильном» PostgreSQL восстановление завершится ошибками [практика].
- Если на источнике использовались табличные пространства (`v81c_data`, `v81c_index`), создайте их на приёмнике заранее либо восстанавливайте с `--no-tablespaces`.
- Журнал регистрации и хранилище двоичных данных переносятся отдельно (раздел 11.2); программные лицензии привязаны к оборудованию и не переносятся копированием файлов.
- Версия платформы на новом сервере — та же или новее; старее нельзя, если режим совместимости конфигурации её не допускает.

## Типичные ошибки и подводные камни (симптом → причина → решение)

Тексты сообщений приведены приблизительно — формулировки зависят от версии платформы и локали.

| № | Симптом | Причина | Решение |
|---|---|---|---|
| 1 | `1cv8` сразу завершается: `cannot open display`, `Gtk-WARNING … cannot open display` | нет X-сервера | запускать через `xvfb-run -a …` либо задать `DISPLAY` на работающий Xvfb |
| 2 | `error while loading shared libraries: libwebkit2gtk-4.0.so.37` (или другая библиотека) | не установлены зависимости толстого клиента | `ldd $B/1cv8 \| grep 'not found'`; поставить зависимости (`v8_install_deps`, `v8-install-deps.sh`), раздел 4.1 |
| 3 | `xvfb-run: error: Xvfb failed to start` | номер дисплея занят параллельным запуском | добавить `-a`; посмотреть причину: `xvfb-run -e /tmp/xvfb.err …` |
| 4 | Конфигуратор «висит», файл `/Out` пуст | ждёт ответа в невидимом диалоге (аутентификация, вопрос о несоответствии конфигураций) | `/DisableStartupDialogs /DisableStartupMessages`, верные `/N` `/P`, ограничение `timeout` |
| 5 | Код возврата 1, в `/Out` — «Не найдена лицензия» | конфигуратору нужна клиентская лицензия, на сервере только серверная | разрешить выдачу лицензий сервером для базы (`--license-distribution=allow`), установить клиентскую лицензию в `/var/1C/licenses` |
| 6 | «Начало сеанса с информационной базой запрещено» | на базу установлена блокировка начала сеансов | указать `/UC <код разрешения>`; снять блокировку: `rac infobase update … --sessions-deny=off` |
| 7 | «Ошибка исключительной блокировки информационной базы» при `/UpdateDBCfg`, `/DumpIB`, `/RestoreIB` | в базе есть сеансы (пользователи, фоновые задания, другой конфигуратор) | заблокировать и завершить сеансы (`rac session terminate`), `-SessionTerminate force` (8.3.23+), заблокировать регламентные задания |
| 8 | В bash `/S srv1c\demo` даёт «Информационная база не обнаружена» | обратная косая черта съедена оболочкой | писать `/S "srv1c/demo"` (прямой слеш) |
| 9 | `CREATEINFOBASE` с `/DisableStartupDialogs` завершается ошибкой | в кластере задан администратор | создавать базу через `rac infobase create --cluster-user=… --cluster-pwd=…` |
| 10 | `rac`: ошибка соединения с `localhost:1545` | не запущен `ras` либо он другой версии, чем сервер | `systemctl status ras-$V`; запустить `ras` из каталога версии работающего сервера |
| 11 | `rac infobase update` / `drop`: недостаточно прав пользователя на информационную базу | не указаны `--infobase-user` / `--infobase-pwd` администратора ИБ | добавить параметры; в 8.5.4 у `rac connection` эти параметры убраны |
| 12 | При создании базы: `permission denied to create database`, требование прав суперпользователя | роль PostgreSQL без `SUPERUSER` | выдать `SUPERUSER` на время создания, затем `ALTER USER … NOSUPERUSER` |
| 13 | При создании базы: ошибка локали (`invalid locale name` в PostgreSQL 14–15, `invalid LC_COLLATE locale name` / `invalid LC_CTYPE locale name` в 16+; несовместимая сортировка с шаблоном) | локаль `ru_RU.UTF-8` не сгенерирована либо кластер PostgreSQL инициализирован в другой локали | `sudo locale-gen ru_RU.UTF-8`; создать базу вручную `createdb -T template0 -l ru_RU.UTF-8` и зарегистрировать (раздел 2.6) |
| 14 | `pg_restore`: `type "mchar" does not exist` | целевой PostgreSQL без патча 1С | установить сборку PostgreSQL для 1С |
| 15 | `createdb -T`: `source database "demo" is being accessed by other users` | к базе-источнику есть подключения (рабочие процессы 1С) | остановить сервер 1С или использовать `pg_dump \| pg_restore` |
| 16 | `ibcmd`: каталог данных заблокирован (`lock.pid`) | с этим `--data` уже работает `ibsrv` или другой `ibcmd` | свой каталог `--data` на каждую базу; дождаться завершения; запускать от одного и того же пользователя |
| 17 | `ibcmd` останавливается и ждёт ввода | не задан пароль пользователя ИБ (запрос в консоли) либо `-W` ждёт пароль СУБД из stdin | передать `--password=…`; пароль СУБД подать через stdin (`<<< "$PGPWD"`) или в YAML |
| 18 | После операций `ibcmd` с базой кластера — ошибки в сеансах, повреждение данных | `ibcmd` применён к базе, обслуживаемой кластером | останавливать сервер 1С на время `ibcmd`; восстановить базу из резервной копии |
| 19 | После `/LoadCfg` пропали доработки конфигурации | `/LoadCfg` полностью заменяет конфигурацию | для доработанных конфигураций — `/UpdateCfg` с файлом настроек либо интерактивное обновление; вернуть `/RollbackCfg`, если БД ещё не обновлена |
| 20 | «Конфигурация базы данных не соответствует сохраненной конфигурации» | конфигурация загружена, но `/UpdateDBCfg` не выполнен или оборван | выполнить `/UpdateDBCfg`; после аварии — `/IBRestoreIntegrity`; отказаться от изменений — `/RollbackCfg` |
| 21 | После копирования базы дублируются обмены, письма, загрузки | в копии выполняются регламентные задания | регистрировать копию с `--scheduled-jobs-deny=on`; при первом входе выбрать «Это копия» |
| 22 | Загрузка `.dt` очень долгая, нехватка памяти или места | природа `.dt`; временные файлы на сервере 1С | переносить средствами PostgreSQL; `-JobsCount`; проверить место в каталоге временных файлов сервера |
| 23 | Конфигуратор не подключается к хранилищу после обновления платформы | версии конфигуратора и `crserver` не совпадают | обновить `crserver` до той же сборки, поправить путь в юните |
| 24 | XML-выгрузка не загружается старой платформой | версия формата выгрузки новее (2.20 для 8.3.27, 2.21 для 8.5.1) | выгружать и загружать одной версией платформы |
| 25 | Пароли видны в `ps aux` | параметры командной строки `1cv8`, `ibcmd`, `rac` | `-W` и YAML с правами `600` для `ibcmd`; запуск на доверенном сервере; отдельные служебные учётные записи ИБ |
| 26 | `rac … summary list` не показывает базу, созданную `ibcmd` | `ibcmd` не регистрирует базу в кластере | `rac infobase create` без `--create-database` |
| 27 | Скрипт получает код 0, но операция не выполнена | проверяется только код возврата | дополнительно читать число из `/DumpResult` и текст `/Out` |

Дополнительные замечания:

- Команды пакетного режима между собой не комбинируются, кроме `/UpdateDBCfg` после команд загрузки. Попытка указать, например, `/DumpCfg` и `/DumpIB` в одной строке не сработает.
- В документации `-Settings` у `/UpdateCfg` и `/AddToList` у `CREATEINFOBASE` записаны иначе, чем во многих статьях (`/AddInList`, вызов без `-Settings`) — проверяйте на своей версии.
- Динамическое обновление (`-Dynamic+`, `--dynamic=auto`) удобно для мелких правок, но при плановом обновлении типовой конфигурации его запрещают (`-Dynamic-`, `--dynamic=disable`).
- Автономный сервер и `ibcmd` не умеют фоновое обновление конфигурации БД.
