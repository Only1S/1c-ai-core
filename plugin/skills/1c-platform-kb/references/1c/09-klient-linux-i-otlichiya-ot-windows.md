## Кратко — 20 главных фактов и команд

1. Клиент ставится тем же установщиком, что и сервер: `setup-full-<версия>-x86_64.run` (компонент `client_full` — толстый клиент и конфигуратор) или `setup-thin-<версия>-x86_64.run` (только тонкий клиент). Тихая установка: `sudo ./setup-full-…run --mode unattended --enable-components client_full,ru` [офиц.].
2. Официально поддерживаются Ubuntu 20.04, 22.04, 24.04 LTS (x86-64 и ARM64). Ubuntu 26.04 в перечне нет [офиц.]. В 26.04 сеанс Ubuntu Desktop работает только на Wayland, приложения X11 идут через XWayland [офиц., Canonical].
3. Каталоги клиента [офиц.]: программы — `/opt/1cv8/x86_64/<версия>/` (`1cv8`, `1cv8c`, `1cv8s`), программа запуска — `/opt/1cv8/common/1cestart`; список баз — `~/.1C/1cestart/ibases.v8i` (UTF-8); настройки запуска — `~/.1C/1cestart/1cestart.cfg` (UTF-16LE); кеш и профиль — `~/.1cv8/1C/1cv8/`; файлы лицензий — `/var/1C/licenses`.
4. Адрес серверной базы в командной строке пишется через прямой слеш: `/S "srv1c/buh"`. Обратный слеш без кавычек допустим только в Windows [офиц.].
5. WebKit: в 8.3.20–8.3.23 платформа несла собственную WebKit1; **начиная с 8.3.24** клиент использует WebKit2 из состава ОС (плюс `evince` для предпросмотра поля HTML-документа) [офиц., `1cv8upd`]. Сборке 8.3.24.1624 нужна `libwebkit2gtk-4.0.so.37` (в Ubuntu 24.04 и 26.04 такого пакета нет) [практика]; для 8.3.27.2074 на современных Ubuntu ставят `libwebkit2gtk-4.1-0` [практика]. Что именно ждёт ваша сборка — показывает `ldd` (раздел 2.4).
6. Шрифты Microsoft Core Fonts обязательны и на клиенте, и на сервере [офиц.]: `sudo apt install ttf-mscorefonts-installer && sudo fc-cache -f -v`. В набор не входят Tahoma, Calibri, Cambria, Segoe UI — их копируют отдельно.
7. Сервер сам рассчитывает `ТабличныйДокумент`, диаграммы и PDF, поэтому `libfontconfig`, `libfreetype` и шрифты нужны **на сервере**, даже без графики [офиц.]. Без них печатные формы «плывут».
8. На Linux-сервере не работают: COM-объекты (модуль компилируется, ошибка при выполнении), объект `ИнтернетСоединение`, СУБД Microsoft SQL Server для информационной базы, NTLM (аутентификация ОС — только Kerberos) [офиц.].
9. Замены COM: Excel/Word → `ТабличныйДокумент.Прочитать()/Записать()`, DOCX-макеты БСП, LibreOffice headless; `V83.COMConnector` → веб- и HTTP-сервисы, OData, `rac`; `ADODB` → внешние источники данных через unixODBC; `WScript.Shell` → `ЗапуститьПриложение()` и bash; WMI → `СистемнаяИнформация`, `/proc`.
10. Внешние компоненты — только Native API, со сборкой `.so` под ОС и разрядность того процесса, куда компонента загружается (сервер, тонкий клиент, браузер) [офиц.].
11. Пути собираются функциями `ПолучитьРазделительПути()`, `ПолучитьРазделительПутиКлиента()`, `ПолучитьРазделительПутиСервера()`; имена файлов в Linux регистрозависимы; маска «все файлы» — `ПолучитьМаскуВсеФайлы()` (`*`, а не `*.*`) [офиц., стандарт № 723].
12. UNC-пути (`\\server\share`) в Linux не поддерживаются: ресурс монтируется (`mount -t cifs`), в настройках указывается точка монтирования [офиц.].
13. Серверный код выполняется от пользователя `usr1cv8` (группа `grp1cv8`): ему нужны права на каталоги обмена; у процесса нет графики и минимальный `PATH`. Проверка: `sudo -u usr1cv8 test -w /srv/1c/exchange && echo OK`.
14. Временные файлы сервера лежат в каталоге из `TMPDIR` (по умолчанию `/tmp`); в Ubuntu 26.04 `/tmp` — в оперативной памяти. Для сервера задают свой каталог (`kb/linux/07-diski-fs-lvm.md`, раздел 15).
15. Внешние источники данных: нужен unixODBC (`libodbc` 2.2.11+) на сервере [офиц.]; драйверы: `msodbcsql18` (MS SQL), `tdsodbc` (FreeTDS), `odbc-postgresql`. Диагностика: `odbcinst -j`, `odbcinst -q -d`, `isql -v DSN user pass`.
16. Криптография: КриптоПро CSP ставится из архива `linux-amd64_deb.tgz` (`sudo ./install_gui.sh`); путь к модулю для 1С — `/opt/cprocsp/lib/amd64/libcapi10.so:/opt/cprocsp/lib/amd64/libcapi20.so` [офиц., 1С-ЭДО]. Для подписания на сервере ключи и сертификаты ставятся под пользователем службы сервера.
17. Доверенные сертификаты для HTTPS в Linux — каталог `/etc/ssl/certs` и файл `/etc/ssl/certs/ca-certificates.crt` [офиц.]. Свой УЦ: `sudo cp ca.crt /usr/local/share/ca-certificates/ && sudo update-ca-certificates`.
18. Печать на клиенте идёт через CUPS: `lpstat -p -d`, `lpadmin -p NAME -E -v ipp://host/ipp/print -m everywhere`, `lp -d NAME file.pdf`. Оборудование подключается к клиентскому компьютеру, драйвер должен иметь сборку под Linux; права на последовательные порты даёт группа `dialout`.
19. Просмотр и печать офисных документов в окне приложения (8.5.4) требуют LibreOffice на рабочих серверах [офиц.]. Конвертация без офиса на экране: `soffice --headless --convert-to pdf --outdir /tmp/out file.docx`.
20. Вместо bat — bash, вместо планировщика Windows — cron или таймеры systemd; пакетный запуск `1cv8 DESIGNER` на сервере без графики — через `xvfb-run` или заменой на `ibcmd`. Перед переносом сервера с Windows на Linux конфигурацию выгружают в файлы и ищут `COMОбъект`, `"\"`, `C:\`, `\\`, `.bat`, `.exe`, `ТипВнешнейКомпоненты.COM`, `ИнтернетСоединение` (раздел 12).

## 2. Установка клиентских приложений на Ubuntu Desktop

### 2.1. Дистрибутивы и компоненты

Установщик для x86 и x86-64 сделан на базе VMware InstallBuilder [офиц.]. Шаблон имени: `setup-<name>-<A.B.C.D>-<arch>.run`.

| Файл | Что ставит |
|---|---|
| `setup-full-8.3.27.1688-x86_64.run` | любой компонент системы: клиенты, конфигуратор, сервер, модули веб-сервера |
| `setup-thin-8.3.27.1688-x86_64.run` | только тонкий клиент и компоненты доступа к серверу |
| `installAsRoot` (в том же архиве) | проверяет права, спрашивает пароль root и запускает первый найденный `setup-*.run` в графическом режиме |
| пакеты `1c-enterprise-<версия>-client_…deb`, `…-thin-client_…deb`, `…-common_…deb`, `…-server_…deb` | установка пакетным менеджером; единственный способ для ARM64 и Эльбруса |

- По документации установщик лежит в zip-архиве с тем же именем. На портале релизов архивы встречаются и под другими именами: `server64_8_3_20_1549.tar.gz` [практика, interface31], `deb64_8_3_27_2074.zip` для набора deb-пакетов (см. `kb/1c/02-…`).
- Способы установки несовместимы: что поставлено установщиком, удаляется утилитой `uninstaller-full` из каталога версии; что поставлено пакетами — пакетным менеджером [офиц.].
- Пакет `client` зависит от `server` и `common` (порядок установки: `common` → `server` → `client`). Пакет `thin-client` самодостаточен и конфликтует с `common`; с файловыми базами он не работает [офиц.].
- При установке пакетами системные зависимости ставит скрипт `v8-install-deps.sh` из комплекта клиентских приложений: запускается от root до установки клиента [офиц.].

Идентификаторы компонентов для `--enable-components` [офиц.]:

| Идентификатор | Что устанавливается |
|---|---|
| `client_full` | толстый клиент и возможность работы в конфигураторе |
| `client_thin` | тонкий клиент без работы с файловыми базами |
| `client_thin_fib` | тонкий клиент, работающий с любым вариантом базы |
| `desktop_icons` | ярлыки компонентов в меню |
| `v8_install_deps` | внешние зависимости платформы |
| `liberica_jre` | Java Runtime Environment (каталог `jre` версии) |
| `server`, `server_admin`, `ws`, `config_storage_server`, `additional_admin_functions`, `integrity_monitoring` | серверные компоненты — на рабочей станции обычно не нужны |
| `ru`, `uk`, `kk`, `de`, … | языки интерфейса; английский ставится всегда |

| unixODBC | `unixodbc` | внешние источники данных (толстый клиент, файловая база) |
| Kerberos | `libkrb5-3`, `libgssapi-krb5-2` | аутентификация средствами ОС |
| Проверка орфографии | `libenchant-2-2`; установщики 8.3.20–8.3.23 (эпоха встроенной WebKit1) требовали исчезнувший `libenchant1c2a` | см. `kb/1c/02-…`, раздел 3.6 |
| CUPS | `cups`, `cups-client` | печать; на Ubuntu Desktop уже установлен |

Как платформа ищет библиотеки [офиц.]: по имени вида `<имя>.so.X.Y`, только среди зарегистрированных в кеше динамического линковщика, и берёт самую старшую версию. Проверка: `ldconfig -p | grep -E 'libodbc|libfontconfig|libfreetype|libgsf-1|libkrb5'`.

Установщик сам пытается доставить недостающее [офиц.]: сначала внешние зависимости, затем шрифты Microsoft Core Fonts (ищет установленный пакет, потом репозиторий ОС, потом зеркала SourceForge по HTTP). В интерактивном режиме он может показать список пакетов, которые не нашёл, — их ставят вручную. Такое поведение появилось в 8.3.24: «во время работы программы установки происходит попытка установить все необходимые компоненты ОС», при неудаче выводится сообщение пакетного менеджера ОС; более ранние установщики зависимости не ставили [офиц., `1cv8upd` 8.3.24]. Для доустановки нужен доступ к репозиториям — в закрытом контуре пакеты ставят заранее.

```bash
# Подготовка Ubuntu 22.04 / 24.04 перед установкой клиента
echo "ttf-mscorefonts-installer msttcorefonts/accepted-mscorefonts-eula select true" | sudo debconf-set-selections
sudo apt update
sudo apt install -y ttf-mscorefonts-installer fontconfig unzip
sudo apt install -y libwebkit2gtk-4.1-0          # есть в 22.04, 24.04, 26.04
sudo apt install -y libwebkit2gtk-4.0-37         # только 22.04; нужна сборкам с ABI 4.0 (подтверждено для 8.3.24.1624)
sudo apt install -y evince                       # предпросмотр поля HTML-документа (8.3.24+); на Desktop 22.04/24.04 обычно уже есть
sudo fc-cache -f -v
```

На Ubuntu 22.04 можно поставить обе библиотеки WebKitGTK сразу (4.0 и 4.1) — они не конфликтуют, а клиент возьмёт ту, с которой слинкован.

### 2.3. Установка

```bash
mkdir -p ~/1c-distr && cd ~/1c-distr
unzip ~/Загрузки/setup-full-8.3.27.1688-x86_64.zip
chmod +x setup-full-8.3.27.1688-x86_64.run

# Вариант А: графический мастер (выбор компонентов флажками)
sudo ./setup-full-8.3.27.1688-x86_64.run
# Вариант Б: помощник для неподготовленного пользователя, сам спросит пароль root
./installAsRoot
# Вариант В: без диалогов — толстый клиент, конфигуратор, ярлыки, русский интерфейс
sudo ./setup-full-8.3.27.1688-x86_64.run --mode unattended \
     --enable-components client_full,desktop_icons,ru
# Только тонкий клиент (с поддержкой файловых баз)
sudo ./setup-thin-8.3.27.1688-x86_64.run --mode unattended \
     --enable-components client_thin_fib,desktop_icons,ru
# Все параметры установщика (штатная возможность InstallBuilder)
./setup-full-8.3.27.1688-x86_64.run --help
```

- Установка всегда выполняется с правами root. Запуск двойным щелчком не запрашивает повышение прав и завершается ошибкой [практика, interface31] — запускайте из терминала или через `installAsRoot`.
- ⚠ не подтверждено: нужно ли в пакетном режиме явно указывать `v8_install_deps`. По документации доустановка зависимостей и шрифтов выполняется и при пакетной установке.
- **Уточнено 11.10.2026**: в документации 8.3.27 (разд. 2.3.2) таблица идентификаторов одна для всех программ установки, и в ней есть `client_thin` (тонкий клиент без работы с файловой базой) и `client_thin_fib` (тонкий клиент для любого варианта базы); отдельного перечня для `setup-thin` нет. Ранее было не подтверждено: набор идентификаторов для `setup-thin` (ожидаются `client_thin`, `client_thin_fib`) — проверьте по `--help`.
- На финальном этапе установщик сам скачивает зависимости и шрифты; процесс может надолго «замереть» — прерывать нельзя [практика, interface31].
- В меню приложений (категория Office, подкатегория Finance) документация описывает три пункта [офиц., гл. 4.1.1]: «1С:Предприятие A.B.C.D» (интерактивная программа запуска `1cv8s`), «… - Тонкий клиент», «… - Толстый клиент». Уточнение по `1cv8upd` 8.3.24 [офиц.]: с 8.3.24 по умолчанию создаётся **один** ярлык — на интерактивную программу запуска (плюс ярлык программы удаления платформы), а остальные создаются, только если в установщике отмечен пункт «Установить ярлыки» (в пакетном режиме — компонент `desktop_icons`). Отдельного пункта для конфигуратора нет: он запускается кнопкой «Конфигуратор» в окне запуска или командой `1cv8 DESIGNER`.
- Несколько версий ставятся рядом (с 8.3.18), каждая в свой каталог `/opt/1cv8/x86_64/<версия>/`. Удаление версии: `sudo /opt/1cv8/x86_64/8.3.27.1688/uninstaller-full`.
- Версии клиента и сервера должны совпадать до последней цифры сборки.

Ubuntu 24.04 (где есть только 4.1) входит в официальный перечень ОС, поэтому актуальные сборки с 4.1 работать обязаны, но номер первой такой сборки в открытых источниках не найден. ### 2.5. X11 и Wayland

- В системных требованиях 1С графический сервер не упоминается вовсе: названы только дистрибутивы и библиотека GTK-3 (рецензент перепроверил страницу системных требований v8.1c.ru и просмотренные разделы `1cv8upd` за 8.3.19–8.3.27: слов Wayland, X11, XWayland там нет). ⚠ не подтверждено: ни официальным источником, ни двумя независимыми источниками сообщества (веб-поиск был недоступен и при написании, и при рецензии). По сведениям сообщества клиент 1С работает как приложение X11, в сеансе Wayland — через слой совместимости XWayland; называют неточности с буфером обмена, перетаскиванием, положением всплывающих окон и размытие при дробном масштабе. Считайте это гипотезой и проверяйте на своей машине:

```bash
echo "$XDG_SESSION_TYPE"                       # x11 или wayland
xlsclients | grep -i 1cv8                      # пакет x11-utils: клиент в списке — значит, он X11-приложение (в Wayland — под XWayland)
# диагностический запуск с принудительным X11-бэкендом GTK (переменная GDK_BACKEND — штатная для GTK 3)
GDK_BACKEND=x11 /opt/1cv8/x86_64/8.3.27.1688/1cv8c
```
- Узнать тип сеанса: `echo $XDG_SESSION_TYPE` (`x11` или `wayland`).
- Ubuntu 22.04 и 24.04: на экране входа (значок шестерёнки) можно выбрать сеанс «Ubuntu on Xorg» [практика]. Для всех пользователей — в `/etc/gdm3/custom.conf` в секции `[daemon]` раскомментировать `WaylandEnable=false` и перезапустить `gdm3` (это завершит все графические сеансы):

```bash
sudo sed -i 's/^#\s*WaylandEnable=false/WaylandEnable=false/' /etc/gdm3/custom.conf
grep -n WaylandEnable /etc/gdm3/custom.conf
sudo systemctl restart gdm3
```

- Ubuntu 26.04 [офиц., release notes]: сеанс Ubuntu Desktop работает только на Wayland, потому что GNOME Shell больше не запускается как сеанс X.org; приложения X11 выполняются через XWayland. Сеанс X.org остаётся в других окружениях (KDE на X11, Xfce, MATE, i3). Для рабочих мест 1С на 26.04 это ещё один довод остаться на 24.04 до появления выпуска в списке поддерживаемых.
- Доступ по RDP/VNC/xrdp создаёт сеанс X11 — клиент 1С в нём работает как в обычном Xorg [практика].

### 2.6. Запуск, список баз и служебные файлы

| Что | Где в Linux | Примечание |
|---|---|---|
| Программа запуска `1cestart` | `/opt/1cv8/common/` | ставится, только если разрядность ОС и приложения совпадают; выбирает нужную установленную версию |
| `1cv8s`, `1cv8`, `1cv8c` | `/opt/1cv8/x86_64/<версия>/` | окно запуска конкретной версии, толстый клиент и конфигуратор, тонкий клиент; подкаталога `bin` нет |
| Список баз `ibases.v8i` | `~/.1C/1cestart/` | текст UTF-8, одна секция — одна база |
| `1cestart.cfg` | `~/.1C/1cestart/` | текст **UTF-16LE**, строки `Параметр=Значение` |
| Кеш и данные клиента | `~/.1cv8/1C/1cv8/<UUID базы>/` | UUID — параметр `ID` из `ibases.v8i`; очистка кеша — параметр `/ClearCache` |
| `1cv8conn.pfl` | `~/.1cv8/1C/1cv8/` | сведения о центральных серверах кластера |
| Конфигурационные файлы (`conf.cfg`, `logcfg.xml`, `nethasp.ini`) | поиск по порядку: `/opt/1cv8/x86_64/<версия>/conf` → `/opt/1cv8/conf` → `~/.1cv8/1C/1cv8/conf` → каталог из `ConfLocation` | `nethasp.ini` дополнительно ищется в текущем каталоге, домашнем каталоге и `/etc` |
| Технологический журнал по умолчанию | `~/.1cv8/logs` | если в `logcfg.xml` не задано иное. Документация 8.3.27 расходится: разд. 6.14.3 даёт `~/.1cv8/1C/1cv8/logs`, прил. 3.24.1 — `~/.1cv8/logs` (см. `07-…`). Проверять на месте |
| Файлы программных лицензий `*.lic` | `/var/1C/licenses` (и каталоги `conf`) | владелец root, группа `grp1cv8` с правом записи |

Все строки таблицы — [офиц.], по приложениям 1 и 3 руководства администратора.

Общий для Windows файл `1cescmn.cfg` и параметр `InstallComponents` в Linux не используются; UNC-пути в настройках не работают — сетевой каталог с дистрибутивами монтируется, причём на всех компьютерах в одну и ту же точку (в примере документации `/mnt/server/1CDistr`) [офиц.].

Пример `~/.1C/1cestart/ibases.v8i`:

```ini
[Бухгалтерия (сервер)]
Connect=Srvr="srv1c";Ref="buh";
ID=cf9f0d4b-b4a3-11d8-861e-0050baaa2f3f
Folder=/Рабочие
App=ThinClient
WA=0
Version=8.3.27

[Демо (файловая)]
Connect=File="/home/user/bases/demo";
App=ThickClient
Version=8.3

[УТ через веб-сервер]
Connect=ws="https://srv1c.example.ru/ut";
App=ThinClient
WSA=0
```

- `ID` формируется автоматически; вручную задавать не рекомендуется. `App`: `Auto`, `ThinClient`, `ThickClient`, `WebClient`. `WA=1` — сначала аутентификация ОС, `WA=0` — всегда имя и пароль. `Version` — версия платформы для запуска базы [офиц.].
- Значения параметров `HttpsCA`, `HttpsCert` удобнее задавать в диалоге свойств базы (кнопка «Дополнительно…»), чем вручную.
- Раздать список баз нескольким пользователям проще всего копированием `ibases.v8i` в их `~/.1C/1cestart/` либо параметром `CommonInfoBases=<путь к общему .v8i>` в `1cestart.cfg`.

```bash
# Посмотреть 1cestart.cfg (он в UTF-16LE, обычный cat покажет «кашу»)
iconv -f UTF-16LE -t UTF-8 ~/.1C/1cestart/1cestart.cfg
# Развернуть готовый список баз новому пользователю
install -D -m 644 /mnt/server/1c/ibases.v8i ~/.1C/1cestart/ibases.v8i
# Сбросить локальный кеш клиента по всем базам (клиент должен быть закрыт)
rm -rf ~/.1cv8/1C/1cv8/*/vrs-cache
```

Лицензии на клиенте: каталог `/var/1C/licenses` создаётся при установке; в группу `grp1cv8` должны входить учётные записи, от имени которых запускаются клиентские приложения, иначе активация программной лицензии не сможет записать файл [офиц.]:

```bash
getent group grp1cv8
sudo usermod -aG grp1cv8 "$USER"      # вступает в силу после повторного входа в систему
ls -ld /var/1C/licenses
```

### 2.7. Параметры командной строки

Режимы [офиц.]: `ENTERPRISE` (1С:Предприятие), `DESIGNER` (конфигуратор), `CREATEINFOBASE` (создание базы). Параметры одинаковы во всех ОС; отличается только запись путей и адреса базы.

```bash
B=/opt/1cv8/x86_64/8.3.27.1688
$B/1cv8c ENTERPRISE /S "srv1c/buh" /N "Иванов" /P "secret"           # тонкий клиент, серверная база
$B/1cv8  ENTERPRISE /F "/home/user/bases/demo"                        # толстый клиент, файловая база
$B/1cv8c ENTERPRISE /WS "https://srv1c.example.ru/ut" /HttpsCA -linux # через веб-сервер, проверка сертификата по хранилищу ОС
$B/1cv8  DESIGNER   /S "srv1c/buh" /N "Администратор" /P "secret"     # конфигуратор
/opt/1cv8/common/1cestart ENTERPRISE /IBName "Бухгалтерия (сервер)"   # база по имени из списка
$B/1cv8c ENTERPRISE /S "srv1c/buh" /N "Иванов" /P "secret" /Execute "/home/user/epf/Загрузка.epf"
$B/1cv8c ENTERPRISE /S "srv1c/buh" /debug -http -attach /debuggerURL "http://srv1c:1550"
```

| Параметр | Назначение |
|---|---|
| `/F <каталог>` | файловая база (каталог с `1Cv8.1CD`) |
| `/S <сервер>/<база>` | серверная база. `server/ib` — в любой ОС; `server\ib` — только Windows; `"server\ib"` в кавычках — в любой ОС |
| `/WS <url>` | подключение через веб-сервер |
| `/IBName "<имя>"` | база по имени из списка; кавычки внутри имени удваиваются |
| `/N<имя>`, `/P<пароль>` | пользователь и пароль информационной базы |

| `/L<язык>`, `/VL<локализация>` | язык интерфейса и региональные настройки сеанса, например `/Lru /VLru_RU` |
| `/C <строка>` | строка, доступная в коде как `ПараметрЗапуска` |
| `/Execute <файл.epf>` | открыть внешнюю обработку сразу после старта (полный путь) |

| `/TComp [-None\|-Deflate\|-SDC\|-lz4\|-zstd]` | сжатие трафика между сервером и тонким клиентом (по умолчанию `-zstd`) |

Все строки — [офиц.], приложение 7 руководства администратора (`kb/its-docs/adm-pr07-*`). Особенности Linux: разрядность клиента не выбирается (`/AppArch` действует только в 64-разрядной Windows); угловые скобки из описаний в командную строку не переносят — для оболочки это перенаправление; значения с пробелами берут в кавычки.

### 2.8. Масштабирование интерфейса

- В самом клиенте масштаб форм меняется через главное меню → «Вид» → «Изменить масштаб…» (для текущей формы или для всех) [практика; ⚠ точное название пункта зависит от версии].
- Системный масштаб в GNOME: «Настройки → Экраны → Масштаб». В Ubuntu 26.04 дробное масштабирование включено по умолчанию [офиц., Canonical]. Приложения X11 под XWayland при дробном масштабе могут отрисовываться размыто — это общее свойство XWayland, а не 1С [практика].
- Увеличить только текст: `gsettings set org.gnome.desktop.interface text-scaling-factor 1.25`.
- ⚠ не подтверждено (источников не найдено ни автором, ни рецензентом; в `1cv8upd` и системных требованиях об этом ничего нет): каким именно системным параметром (DPI Xft, масштаб GDK) руководствуется клиент 1С на Linux и поддерживает ли он переменные `GDK_SCALE` / `GDK_DPI_SCALE`. Сами переменные — штатные для GTK 3 (`GDK_SCALE` — целый коэффициент масштаба окон, `GDK_DPI_SCALE` — дробный множитель размера шрифтов), поэтому пробный запуск безвреден: `GDK_SCALE=2 /opt/1cv8/x86_64/<версия>/1cv8c` или `GDK_DPI_SCALE=1.25 …`. Проверяйте на своём мониторе; надёжный вариант для экранов высокой плотности — целочисленный масштаб 200 % в сеансе Xorg.

## 3. Шрифты и печатные формы

### 3.1. Почему макеты «плывут»

- В макетах табличных документов записаны **имена** шрифтов (чаще всего Arial, реже Times New Roman, Courier New, Tahoma, Verdana). Ширина текста, перенос по словам, автовысота строк и разбиение на страницы считаются по метрикам того шрифта, который реально нашёлся в системе.
- Если шрифта нет, fontconfig подставляет замену (обычно DejaVu Sans). У неё другие ширины символов: текст не помещается в ячейку, обрезается или переносится, строки становятся выше, документ «переезжает» на лишнюю страницу, штрихкоды превращаются в цифры.
- Расчёт выполняется там, где формируется документ. В управляемом приложении это почти всегда **сервер**: документация прямо требует `libfontconfig` и `libfreetype` для работы сервера в управляемом режиме, для объектов `ТабличныйДокумент`, `Диаграмма`, `ГрафическаяСхема` на сервере и для сохранения в PDF, а Microsoft Core Fonts числит в обязательных библиотеках сервера [офиц.].
- Поэтому шрифты нужны в трёх местах: на сервере 1С (формирование и PDF), на клиентах Linux (просмотр и печать), на веб-сервере, если он обслуживает файловую базу.

Свободные шрифты Liberation (`fonts-liberation`) метрически совместимы с Arial, Times New Roman и Courier New — раскладка сохраняется, отличается только рисунок букв. Для Calibri и Cambria метрические аналоги — Carlito и Caladea (`fonts-crosextra-carlito`, `fonts-crosextra-caladea`). У Tahoma и Verdana свободных метрических аналогов в стандартной поставке нет [практика].

### 3.2. Установка Microsoft Core Fonts

```bash
# Ubuntu: пакет из компонента multiverse, сам скачивает шрифты из интернета
echo "ttf-mscorefonts-installer msttcorefonts/accepted-mscorefonts-eula select true" | sudo debconf-set-selections
sudo apt update
sudo apt install -y ttf-mscorefonts-installer fontconfig
sudo fc-cache -f -v
fc-list | grep -i -E 'arial|times|courier|verdana|georgia|trebuc' | sort | head -20
```

- Состав набора (описание пакета): Andale Mono, Arial Black, Arial, Comic Sans MS, Courier New, Georgia, Impact, Times New Roman, Trebuchet, Verdana, Webdings. **Tahoma, Calibri, Cambria, Segoe UI в набор не входят.**
- Пакет зависит от `cabextract` и `wget` и при установке качает файлы с SourceForge. Без доступа в интернет он установится «пустым». Повторить загрузку: `sudo apt install --reinstall ttf-mscorefonts-installer`.
- Файлы оказываются в `/usr/share/fonts/truetype/msttcorefonts/`.
- Установщик платформы пытается поставить шрифты сам (пакет из репозитория, затем зеркала SourceForge по HTTP), в том числе в пакетном режиме [офиц.].
- Методичка ИТС для Debian/Ubuntu даёт ровно эти две команды: установка `ttf-mscorefonts-installer` и `fc-cache -fv` [офиц.].

### 3.3. Копирование шрифтов из Windows и закрытый контур

Шрифты берут с машины, где они установлены законно (`C:\Windows\Fonts`, файлы `*.ttf`, `*.ttc`), и кладут в системный каталог:

```bash
sudo mkdir -p /usr/local/share/fonts/windows
sudo cp /mnt/usb/fonts/*.ttf /mnt/usb/fonts/*.ttc /usr/local/share/fonts/windows/ 2>/dev/null
sudo chmod 755 /usr/local/share/fonts/windows
sudo chmod 644 /usr/local/share/fonts/windows/*
sudo fc-cache -f -v
fc-match "Tahoma"                 # должно вернуть tahoma.ttf, а не DejaVuSans.ttf
fc-match "Arial:bold"
```

| Каталог | Для кого |
|---|---|
| `/usr/share/fonts/` | шрифты из пакетов |
| `/usr/local/share/fonts/` | шрифты, установленные администратором вручную, для всех пользователей |
| `~/.local/share/fonts/` | шрифты одного пользователя |
| `~/.fonts` | устаревший личный каталог; именно его называет документация 1С для ручной установки [офиц.] |

Ключи `fc-cache`: `-f` — пересоздать кеш принудительно, `-v` — подробный вывод, `-s` — только системные каталоги, `-r` — стереть кеш и построить заново. Диагностика: `fc-list` (все шрифты), `fc-list : family | sort -u` (только семейства), `fc-match "<имя>"` (что реально подставится).

Шрифты на сервере 1С проверяют от имени пользователя службы:

```bash
sudo -u usr1cv8 fc-match "Arial"
sudo -u usr1cv8 fc-list | grep -ci 'arial'
# после установки шрифтов перезапустить клиент, а на сервере — службу 1С (рабочие процессы кешируют список шрифтов)
sudo systemctl restart 'srv1cv8-8.3.27.1688@default'
```

Если шрифт взять неоткуда, задают подстановку в `/etc/fonts/local.conf` (пример — Tahoma заменяется на Verdana):

```xml
<?xml version="1.0"?>
<!DOCTYPE fontconfig SYSTEM "fonts.dtd">
<fontconfig>
  <alias binding="same">
    <family>Tahoma</family>
    <prefer><family>Verdana</family></prefer>
  </alias>
</fontconfig>
```

После правки — `sudo fc-cache -f -v`. Подстановка не восстановит раскладку «точь-в-точь», но сделает её предсказуемой и одинаковой на сервере и клиентах.

### 3.4. Шрифты штрихкодов

- Старые печатные формы (квитанции, ценники, налоговые бланки) выводят штрихкод специальным шрифтом — чаще всего `EanGnivc` (файл `EanGnivc.ttf`), реже шрифты EAN-13 или Code 128. Без шрифта вместо штрихов печатаются цифры. Шрифт ставится так же, как остальные (каталог `/usr/local/share/fonts/`, `fc-cache`), и нужен на сервере и на клиентах [практика].
- Современные типовые конфигурации формируют штрихкод картинкой с помощью внешней компоненты «1С:Печать штрихкодов» из состава БПО. Шрифт штрихов не нужен, но нужна сборка компоненты под Linux для того процесса, где формируется документ. ⚠ не подтверждено первоисточником: состав сборок компоненты под Linux и требование к шрифту подписи — проверьте печать ценника на стенде.

### 3.5. PDF и табличные документы на сервере

```bsl
&НаСервере
Функция СформироватьPDF(СсылкаНаДокумент)
    ТабДок = СформироватьПечатнуюФорму(СсылкаНаДокумент);      // вывод макета выполняется на сервере
    ИмяФайла = ПолучитьИмяВременногоФайла("pdf");
    ТабДок.Записать(ИмяФайла, ТипФайлаТабличногоДокумента.PDF);
    Данные = Новый ДвоичныеДанные(ИмяФайла);
    УдалитьФайлы(ИмяФайла);
    Возврат ПоместитьВоВременноеХранилище(Данные);
КонецФункции
```

- Этот код на Linux-сервере требует `libfontconfig`, `libfreetype` и шрифтов из макета [офиц.]. Запись и чтение старого формата XLS требует `libgsf-1` и `libglib-2.0` [офиц.].
- Признак нехватки шрифтов на сервере: документ на экране Windows-клиента выглядит правильно, а PDF из фонового задания, рассылки или веб-клиента — с обрезанным текстом и «съехавшими» страницами.
- `ТабличныйДокумент.Напечатать()` на сервере недоступен: печать — клиентская операция. Серверный сценарий — записать PDF и отправить его в очередь CUPS (раздел 8.1).

## 4. Отличия Linux от Windows в прикладном коде

Ограничения кластера серверов под Linux по документации [офиц., «Клиент-серверный вариант», 2.3]:

| Ограничение | Подробности |
|---|---|
| Нет работы с COM-объектами | серверные модули с COM компилируются, но при выполнении выдаётся ошибка |
| Нет работы с Microsoft SQL Server | рабочий процесс не может использовать MS SQL как СУБД информационной базы |
| Аутентификация ОС | только Kerberos и/или имя с паролем; NTLM — возможность Windows-версии |
| Нет объекта `ИнтернетСоединение` | функциональность недоступна |

Стандарт разработки № 723 «Особенности разработки конфигураций для ОС Linux и macOS» [офиц.; текст прочитан с искажённой кодировкой — формулировки сверить с оригиналом] требует: не использовать COM (в том числе `V83.ComConnector` для администрирования — вместо него сервер администрирования `ras`; офисные приложения Windows); внешние компоненты — только Native API, либо веб- и HTTP-сервисы; не применять графику WMF и EMF (заменять на PNG, JPG); учитывать регистр имён файлов; разделители путей и маски получать функциями платформы; Windows-специфичные фрагменты окружать проверкой ОС с понятным сообщением пользователю.

### 4.1. Определение операционной системы

```bsl
СистИнфо = Новый СистемнаяИнформация;
ЭтоWindows = СистИнфо.ТипПлатформы = ТипПлатформы.Windows_x86
         Или СистИнфо.ТипПлатформы = ТипПлатформы.Windows_x86_64;
ЭтоLinux   = СистИнфо.ТипПлатформы = ТипПлатформы.Linux_x86
         Или СистИнфо.ТипПлатформы = ТипПлатформы.Linux_x86_64
         Или СистИнфо.ТипПлатформы = ТипПлатформы["Linux_ARM64"]   // значения появились в 8.3.22; на 8.3.20–8.3.21
         Или СистИнфо.ТипПлатформы = ТипПлатформы["Linux_E2K"];    // эти две строки уберите (запись через ["…"] — как в БСП)

Если Не ЭтоWindows Тогда
    ВызватьИсключение НСтр("ru = 'Работа с Microsoft Word доступна только в ОС Windows.'");
КонецЕсли;
```

- Результат зависит от места выполнения: в процедуре `&НаКлиенте` это ОС клиента, в `&НаСервере` — ОС сервера. При Windows-клиентах и Linux-сервере они разные, поэтому путь к файлу надо строить для той стороны, которая будет с ним работать.
- Значения `ТипПлатформы` для ARM64 и Эльбруса: **`Linux_ARM64`** и **`Linux_E2K`** — так они записаны в рабочем коде БСП 3.1 (`ОбщегоНазначения.ЭтоLinuxСервер()` сравнивает с `ТипПлатформы["Linux_ARM64"]` и `ТипПлатформы["Linux_E2K"]`) [БСП, код]. Значения реализованы в 8.3.22 вместе с поддержкой ARM64 и Эльбруса [офиц., `1cv8upd`]. ⚠ Расхождение источников: в тексте `1cv8upd` значение для ARM записано как `ТипПлатформы.Linux_ARM_64` (с подчёркиванием перед 64) — судя по коду БСП, это опечатка документа; при сомнении сверьте с синтакс-помощником своей версии. Запись через квадратные скобки (`ТипПлатформы["Linux_ARM64"]`) — приём БСП: обращение к значению разрешается при выполнении, а не при компиляции, поэтому модуль компилируется и на платформе, где такого значения ещё нет (ошибка возможна только в момент выполнения этой строки).
- ⚠ не подтверждено: отдельное значение `ТипПлатформы` для macOS на процессорах Apple (ARM). Надёжнее проверять «не Windows», чем перечислять все варианты Linux.
- Другие свойства `СистемнаяИнформация`: `ВерсияОС`, `ВерсияПриложения`, `Процессор`, `ОперативнаяПамять`, `ИдентификаторКлиента`.
- [БСП]: `ОбщегоНазначения.ЭтоLinuxСервер()`, `ОбщегоНазначения.ЭтоWindowsСервер()`, `ОбщегоНазначенияКлиент.ЭтоLinuxКлиент()`, `ОбщегоНазначенияКлиент.ЭтоWindowsКлиент()`, `ОбщегоНазначенияКлиент.ЭтоMacOSКлиент()`; на сервере про клиента — `ОбщегоНазначения.ЭтоLinuxКлиент()`.

### 4.2. COM, OLE, ActiveX: что не работает и чем заменить

Конструкторы `Новый COMОбъект(...)` и `ПолучитьCOMОбъект(...)` на Linux завершаются исключением; тип внешней компоненты `ТипВнешнейКомпоненты.COM` не поддерживается; регистрация 1С как OLE-Automation-сервера (`V83.Application`) — только Windows.

| Windows-приём | Что делать на Linux |
|---|---|
| `Excel.Application` — чтение и запись XLS/XLSX | `ТабличныйДокумент.Прочитать()` и `.Записать()`; разбор XLSX как ZIP + XML (`ЧтениеZipФайла`, `ЧтениеXML`) |
| `Word.Application` — заполнение шаблонов | макеты офисных документов DOCX в БСП (заполняются на сервере без офиса); `ТабличныйДокумент.Записать(…, ТипФайлаТабличногоДокумента.DOCX)`; конвертация через LibreOffice headless |
| `V83.COMConnector`, `V82.COMConnector` — обмен между базами | веб-сервисы, HTTP-сервисы, стандартный интерфейс OData, обмен файлами, сервисы интеграции |
| `V83.COMConnector` — администрирование кластера | `rac` + `ras` (в БСП — тип подключения «RAS» модуля администрирования кластера), стандартная функция «Управление серверами» |
| `ADODB.Connection` — запросы к чужим СУБД | внешние источники данных через unixODBC (раздел 5) |
| `ADODB.Stream` — перекодировка, двоичные данные | `ЧтениеТекста`/`ЗаписьТекста` с явной кодировкой, `ПолучитьДвоичныеДанныеИзСтроки()`, `ЧтениеДанных`/`ЗаписьДанных` |
| `WScript.Shell` — запуск программ, переменные окружения | `ЗапуститьПриложение()`, `КомандаСистемы()`, сценарии bash (раздел 4.5) |
| `Scripting.FileSystemObject` | `Файл`, `НайтиФайлы()`, `КопироватьФайл()`, `ПереместитьФайл()`, `УдалитьФайлы()`, `СоздатьКаталог()` |

### 4.3. Внешние компоненты

- На Linux работают только компоненты по технологии **Native API** (динамические библиотеки `.so`). COM-компоненты (ActiveX `.dll`, регистрируемые `regsvr32`) не подключаются.
- Разрядность и тип компоненты должны совпадать с приложением, в которое она загружается: сервер, тонкий или толстый клиент, веб-браузер [офиц.]. Для сервера на Ubuntu x86-64 нужна сборка Linux x86-64; для клиентов на Windows — отдельно сборки Windows.
- Компонента поставляется ZIP-архивом с манифестом `MANIFEST.XML`, где перечислены файлы для каждой ОС и архитектуры. Архив кладут в макет с двоичными данными.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<bundle xmlns="http://v8.1c.ru/8.2/addin/bundle" name="MyAddIn">
  <component os="Windows" path="MyAddIn_Win32.dll" type="native" arch="i386"/>
  <component os="Windows" path="MyAddIn_Win64.dll" type="native" arch="x86_64"/>
  <component os="Linux"   path="libMyAddIn_Lin32.so" type="native" arch="i386"/>
  <component os="Linux"   path="libMyAddIn_Lin64.so" type="native" arch="x86_64"/>
</bundle>
```

```bsl
&НаСервере
Функция ПодключитьМоюКомпоненту()
    Подключено = ПодключитьВнешнююКомпоненту("ОбщийМакет.МояКомпонента", "MyAddIn", ТипВнешнейКомпоненты.Native);
    Если Не Подключено Тогда
        ВызватьИсключение НСтр("ru = 'Компонента MyAddIn не подключена: нет сборки под ОС сервера.'");
    КонецЕсли;
    Возврат Новый("AddIn.MyAddIn.MyClass");
КонецФункции
```

- Требования технологии [офиц., руководство по внешним компонентам]: библиотека экспортирует `GetClassNames`, `GetClassObject`, `DestroyObject`, `SetPlatformCapabilities`; объект наследуется от `IComponentBase`.
- Проверка сборки на сервере: `file libMyAddIn_Lin64.so` (должно быть `ELF 64-bit … x86-64`), `ldd libMyAddIn_Lin64.so | grep 'not found'` (пусто).
- Каталог временных файлов сервера не должен быть смонтирован с `noexec`: компонента извлекается туда перед загрузкой [практика].
- Профили безопасности (лицензия КОРП): для Native API нужно отдельное разрешение на каждую платформу — Windows 32 и 64 бит, Linux 32 и 64 бит, с контрольной суммой SHA1 в base64 [офиц.].
- Изолированное подключение — **с 8.3.21** [офиц., `1cv8upd` 8.3.21]: «реализована возможность загружать внешние компоненты в отдельном процессе»; при аварийном завершении компоненты платформа (в том числе `rphost`) не падает, но компоненту нужно подключить заново. Тогда же добавлены параметр `ТипПодключенияВнешнейКомпоненты` у `ПодключитьВнешнююКомпоненту()` и асинхронных аналогов, метод `ПроверитьПодключениеВнешнейКомпоненты()` и событие `ОбработкаОтключенияВнешнейКомпоненты`. Рекомендация документа: разрабатывать компоненты с поддержкой изолированной работы и подключать их изолированно, если компонента может работать в отдельном процессе. До 8.3.21 компонента всегда грузилась в адресное пространство процесса платформы. Значения перечисления (`Изолированно`, `НеИзолированно`) — подтверждены главой 32 «Руководства разработчика» 8.3.27 (системное перечисление `ТипПодключенияВнешнейКомпоненты`; сверено 11.10.2026); ранее: по памяти, в `1cv8upd` не названы; сверить с синтакс-помощником.
- ⚠ не подтверждено: каталог установленных компонент тонкого клиента на Linux (ожидается `~/.1cv8/1C/1cv8/ExtCompT` по аналогии с `%APPDATA%\1C\1cv8\ExtCompT` в Windows); проверка — `find ~/.1cv8 -maxdepth 4 -iname 'ExtComp*'`.
- В 8.5.4 для существующих компонент COM и Native API можно создавать адаптеры для веб-клиента [офиц., блог платформы; ⚠ в новости «Новое в 8.5.4» на v8.1c.ru рецензент этого пункта не нашёл — там говорится только о расширении интеграции веб-клиента в сторонние сайты].
- [БСП, код]: на сервере — `ОбщегоНазначения.ПодключитьКомпонентуИзМакета(Идентификатор, ПолноеИмяМакета, Изолированно)` (третий параметр управляет типом подключения; внутри вызывается `ПодключитьВнешнююКомпоненту(Местоположение, Идентификатор + "SymbolicName", , ТипПодключенияКомпоненты(Изолированно))`); на клиенте — `ОбщегоНазначенияКлиент.ПодключитьКомпонентуИзМакета(Оповещение, Идентификатор, ПолноеИмяМакета)`.

### 4.4. Файловая система: пути, регистр, маски, временные файлы

| Тема | Windows | Linux |
|---|---|---|
| Разделитель пути | `\` | `/` |
| Корень | буквы дисков `C:\`, UNC `\\server\share` | единое дерево от `/`; сетевые ресурсы монтируются |
| Регистр имён | не различается | различается: `Обмен.XML` и `обмен.xml` — разные файлы |
| Маска «все файлы» | `*.*` | `*` (`*.*` не найдёт файлы без точки) |
| Запрещённые символы в имени | `\ / : * ? " < > \|` | только `/` и нулевой байт |
| Временный каталог | `%TEMP%` | `/tmp` или значение `TMPDIR` |
| Владелец нового файла | учётная запись службы | `usr1cv8:grp1cv8`, права по `umask` |

```bsl
// Плохо: работает только в Windows
ИмяФайла = КаталогОбмена + "\Message_" + КодУзла + ".xml";

// Хорошо: разделитель той стороны, где выполняется код
ИмяФайла = КаталогОбмена + ПолучитьРазделительПути() + "Message_" + КодУзла + ".xml";

// Путь строится на сервере, а использоваться будет на клиенте (или наоборот)
ПутьНаКлиенте = КаталогКлиента + ПолучитьРазделительПутиКлиента() + ИмяФайлаБезПути;
ПутьНаСервере = КаталогСервера + ПолучитьРазделительПутиСервера() + ИмяФайлаБезПути;
```

```bsl
// Универсальная склейка пути
Функция ОбъединитьПути(Знач Каталог, Знач ИмяФайла) Экспорт
    Разделитель = ПолучитьРазделительПути();
    Если Не ПустаяСтрока(Каталог) И Прав(Каталог, 1) <> "/" И Прав(Каталог, 1) <> "\" Тогда
        Каталог = Каталог + Разделитель;
    КонецЕсли;
    Возврат Каталог + ИмяФайла;
КонецФункции

// Поиск без учёта регистра расширения: маска *.xml не найдёт DATA.XML
Для Каждого НайденныйФайл Из НайтиФайлы(Каталог, ПолучитьМаскуВсеФайлы(), Ложь) Цикл
    Если НайденныйФайл.ЭтоФайл() И НРег(НайденныйФайл.Расширение) = ".xml" Тогда
        ОбработатьФайл(НайденныйФайл.ПолноеИмя);
    КонецЕсли;
КонецЦикла;
```

- Функции платформы: `ПолучитьРазделительПути()`, `ПолучитьРазделительПутиКлиента()`, `ПолучитьРазделительПутиСервера()`, `ПолучитьМаскуВсеФайлы()`, `ПолучитьМаскуВсеФайлыКлиента()`, `ПолучитьМаскуВсеФайлыСервера()`.
- `КаталогВременныхФайлов()` на Linux возвращает `/tmp/` либо каталог из переменной `TMPDIR` процесса. Временные имена получайте только через `ПолучитьИмяВременногоФайла(Расширение)` — такие файлы платформа умеет удалять сама; при этом хорошим тоном остаётся явное `УдалитьФайлы()` [офиц., стандарты разработки].
- `КаталогПрограммы()` на Linux — `/opt/1cv8/x86_64/<версия>/` (отдельного `bin` нет).
- Нельзя рассчитывать, что файл, сохранённый одним серверным вызовом, будет доступен следующему: в кластере из нескольких серверов вызовы попадают на разные машины [офиц.]. Между вызовами данные передают через временное хранилище.
- Имена файлов, созданные на Linux, могут содержать символы, недопустимые в Windows (`:`, `?`, `*`, `"`, `<`, `>`, `|`). Если файл потом открывают Windows-клиенты, имя очищают заранее ([БСП]: `ОбщегоНазначенияКлиентСервер.ЗаменитьНедопустимыеСимволыВИмениФайла()`).
- Настройки с путями (каталоги обмена, тома хранения файлов, выгрузки в банк) после переноса сервера переписываются с `\\fs01\exchange\out` на точку монтирования, например `/mnt/exchange/out`. В БСП у томов хранения файлов два отдельных реквизита: путь для Windows-сервера и путь для Linux-сервера.
- Профиль безопасности: логический URL виртуального каталога должен выглядеть как начало реального пути файловой системы сервера и совпадать с началом пути в коде в точности [офиц.].

Каталог временных файлов сервера [офиц., методичка ИТС 2010 г.; способ через systemd — практика]:

```bash
sudo systemctl edit 'srv1cv8-8.3.27.1688@default'      # в секцию [Service]:  Environment=TMPDIR=/srv/1c-tmp
```

### 4.5. Запуск внешних программ

| Метод | Где выполняется | Особенности на Linux |
|---|---|---|
| `ЗапуститьПриложение(Команда, ТекущийКаталог, ДождатьсяЗавершения, КодВозврата)` | на сервере — от `usr1cv8`; на клиенте — от пользователя сеанса | нет `cmd /c`, `.bat`, `.exe`, `start`; путь к программе лучше указывать полностью |
| `КомандаСистемы(Команда, ТекущийКаталог)` | там же | выполняет команду через командный интерпретатор ОС |
| `ЗапуститьСистему(ДополнительныеПараметры, ДождатьсяЗавершения, КодВозврата)` | запускает ещё один клиент 1С | параметры командной строки те же, что в разделе 2.7 |
| `НачатьЗапускПриложения(Оповещение, Команда, …)` | тонкий и веб-клиент | в веб-клиенте требует расширение работы с файлами (и GTK-3 в Linux) |

Что меняется по сравнению с Windows:

- На сервере нет графического сеанса: программы с окнами не запустятся. Нужна консольная утилита или режим headless.
- Окружение службы systemd минимально: короткий `PATH`, нет переменных из профиля пользователя, локаль может оказаться `C`. Указывайте полные пути (`/usr/bin/soffice`), а нужные переменные задавайте в самом сценарии или в юните (`Environment=LANG=ru_RU.UTF-8`).
- Перенаправление вывода (`>`, `2>&1`), конвейеры и подстановки — конструкции оболочки. По коду БСП 3.1 [БСП, код] строка, переданная в `ЗапуститьПриложение()` на Linux, исполняется командным интерпретатором: функция `ФайловаяСистема.ЗапуститьПрограмму()` на сервере Linux передаёт в `ЗапуститьПриложение()` строку вида `LANGUAGE=ru_RU.UTF-8 <команда> > "<файл stdout>" 2>"<файл stderr>"` — то есть с присваиванием переменной окружения и перенаправлениями, которые умеет разбирать только оболочка (`sh`). Явная обёртка `bash -c "…"` поэтому не обязательна, но остаётся разумной: она делает поведение однозначным и нужна для возможностей именно bash (`set -o pipefail`, `[[ … ]]`, массивы), потому что системный `sh` в Ubuntu — это `dash`. Надёжнее всего выносить логику в файл сценария и передавать ему простые аргументы.
- У `usr1cv8` нет прав root. Если операция требует привилегий, заводят узкое правило в `/etc/sudoers.d/` на один конкретный сценарий (`usr1cv8 ALL=(root) NOPASSWD: /opt/1c-scripts/restart-print.sh`), а не дают общий `sudo`.
- Профили безопасности и механизм защиты от опасных действий ограничивают запуск приложений так же, как в Windows.

```bsl
&НаСервере
Функция ВыполнитьСценарийНаСервере(Знач ПутьКСценарию, Знач Аргументы = "")
    // Вывод перенаправляется в файл: перенаправление делает оболочка; bash -c задаёт её явно
    ФайлВывода = ПолучитьИмяВременногоФайла("log");
    Команда = "/bin/bash -c """ + ПутьКСценарию + " " + Аргументы + " > '" + ФайлВывода + "' 2>&1""";

    КодВозврата = Неопределено;
    ЗапуститьПриложение(Команда, , Истина, КодВозврата);

    Чтение = Новый ЧтениеТекста(ФайлВывода, "UTF-8");
    Вывод = Чтение.Прочитать();
    Чтение.Закрыть();
    УдалитьФайлы(ФайлВывода);

    Возврат Новый Структура("КодВозврата, Вывод", КодВозврата, Вывод);
КонецФункции

// Вызов: Результат = ВыполнитьСценарийНаСервере("/opt/1c-scripts/convert.sh", "/srv/1c/in/doc.docx");
```

- Как платформа на Linux разбирает строку команды: в документации (синтакс-помощник закрыт подпиской) рецензент описания не нашёл — ⚠ официально не подтверждено; косвенное подтверждение исполнения через оболочку даёт код БСП (см. выше). Практические выводы: (1) символы `$`, обратная кавычка, `|`, `&`, `;`, `>`, `<`, `*`, пробел в аргументах будут истолкованы оболочкой — экранируйте их или не допускайте; (2) никогда не подставляйте в строку команды данные, введённые пользователем, без проверки: это прямой путь к выполнению чужих команд от имени `usr1cv8`. БСП перед запуском сама отбраковывает строки с `${`, `$(`, обратной кавычкой, `|`, `&` (и `;` для не-администраторов) — функция `ОбщегоНазначенияСлужебныйКлиентСервер.БезопаснаяСтрокаКоманды()` [БСП, код]; (3) сложные значения передавайте через файл параметров.
- [БСП, код]: `ФайловаяСистема.ЗапуститьПрограмму(КомандаЗапуска, ПараметрыЗапускаПрограммы)` возвращает структуру `КодВозврата`, `ПотокВывода`, `ПотокОшибок`. `КомандаЗапуска` — строка или массив (первый элемент — программа, остальные — аргументы; аргументы с пробелами и спецсимволами берутся в кавычки автоматически). Параметры создаёт `ФайловаяСистема.ПараметрыЗапускаПрограммы()`: `ТекущийКаталог`, `ДождатьсяЗавершения` (по умолчанию `Ложь`), `ПолучитьПотокВывода`, `ПолучитьПотокОшибок` (учитываются только при `ДождатьсяЗавершения = Истина`), `КодировкаПотоков` (по умолчанию `"CP866"` в Windows и `"UTF-8"` в Linux), `КодировкаИсполнения` (в Linux подставляется как `LANGUAGE=<значение>` перед командой, например `"ru_RU.UTF-8"`; в macOS игнорируется). На клиенте — `ФайловаяСистемаКлиент.ЗапуститьПрограмму()`, открытие файла и ссылки — `ФайловаяСистемаКлиент.ОткрытьФайл()`, `ОткрытьНавигационнуюСсылку()`.

```bsl
&НаСервере
Функция СвободноеМестоНаСервере(Знач Каталог)
    // Вариант через БСП: вывод команды возвращается строкой, перенаправления БСП делает сама
    Параметры = ФайловаяСистема.ПараметрыЗапускаПрограммы();
    Параметры.ДождатьсяЗавершения = Истина;
    Параметры.ПолучитьПотокВывода = Истина;
    Параметры.ПолучитьПотокОшибок = Истина;
    Параметры.КодировкаИсполнения = "ru_RU.UTF-8";

    Команда = Новый Массив;                  // массив безопаснее строки: аргументы экранирует БСП
    Команда.Добавить("/usr/bin/df");
    Команда.Добавить("-h");
    Команда.Добавить(Каталог);

    Результат = ФайловаяСистема.ЗапуститьПрограмму(Команда, Параметры);
    Если Результат.КодВозврата <> 0 Тогда
        ВызватьИсключение Результат.ПотокОшибок;
    КонецЕсли;
    Возврат Результат.ПотокВывода;
КонецФункции
```
- Открыть файл программой по умолчанию на Linux-клиенте можно командой `xdg-open "<путь>"`.

### 4.6. Кодировки файлов и переводы строк

- Всегда указывайте кодировку явно и строкой: `"UTF-8"`, `"windows-1251"`, `"cp866"`, `"koi8-r"`. Значения `КодировкаТекста.ANSI` и `КодировкаТекста.OEM` — понятия Windows. ⚠ не подтверждено, чему они соответствуют на Linux; файлы обмена с банками, ККТ и старыми системами читайте с явным `"windows-1251"` или `"cp866"`.
- `КодировкаТекста.UTF8` при записи добавляет маркер BOM (байты `EF BB BF`). Утилиты Linux его не ждут: сценарий bash с BOM не запустится, первая колонка CSV получит «мусор» в имени. ⚠ [практика, по памяти рецензента; первоисточник закрыт]: строка `"UTF-8"` в `ЗаписьТекста` и `ТекстовыйДокумент.Записать()` даёт тот же BOM, что и значение перечисления, — совет «указывать кодировку строкой» от BOM не избавляет. Способы записать UTF-8 без BOM: `ПолучитьДвоичныеДанныеИзСтроки(Текст, "UTF-8", Ложь)` или `ЗаписьДанных` (пример ниже); либо создать пустой файл и открыть его `ЗаписьТекста` в режиме дописывания (`Дописывать = Истина` — BOM в середину файла не пишется). Проверяйте результат: `head -c 3 файл | xxd`.
- Переводы строк: Windows — CRLF (`ВК + ПС`), Linux — LF (`ПС`). У конструктора `ЗаписьТекста(ИмяФайла, Кодировка, РазделительСтрок, Дописывать, КонвертируемыйРазделительСтрок)` значения по умолчанию: `РазделительСтрок` — `ПС`, `КонвертируемыйРазделительСтрок` — `ВК + ПС`, то есть при записи каждый `ПС` в тексте заменяется на `ВК + ПС` на любой ОС, и файл получается «виндовым» даже на Linux. Подтверждено косвенно — документацией и кодом OneScript (совместимая открытая реализация языка, описание параметров повторяет синтакс-помощник: «Определяет разделение строк в файле для конвертации в стандартный перевод строк ПС. Значение по умолчанию: ВК + ПС»); сам синтакс-помощник 1С закрыт подпиской. Чтобы получить LF, пятым параметром передают `Символы.ПС`. Сценарий bash с CRLF падает с ошибкой `/bin/bash^M: bad interpreter`.
- У `ЧтениеТекста` параметры зеркальные: при чтении `ВК + ПС` по умолчанию превращается в `ПС`, поэтому файл с LF, созданный на Linux, читается на Windows и наоборот без дополнительных действий.

```bsl
// Текстовый файл для Linux: UTF-8 без BOM, переводы строк LF
Текст  = СтрЗаменить(Текст, Символы.ВК, "");
Данные = ПолучитьДвоичныеДанныеИзСтроки(Текст, "UTF-8", Ложь);     // третий параметр — не добавлять BOM
Данные.Записать(ИмяФайла);

// То же через ЗаписьТекста: явный разделитель строк и отключённая конвертация в CRLF
Запись = Новый ЗаписьТекста(ИмяФайла, "windows-1251", Символы.ПС, Ложь, Символы.ПС);
Запись.Записать(Текст);
Запись.Закрыть();

// Чтение файла, пришедшего из Windows
Чтение = Новый ЧтениеТекста(ИмяФайла, "windows-1251");
Текст  = Чтение.Прочитать();
Чтение.Закрыть();
```

Диагностика и исправление средствами ОС:

```bash
file -i обмен.txt                               # определить кодировку: charset=utf-8 / iso-8859-1 / unknown-8bit
head -c 3 обмен.txt | xxd                       # efbbbf в начале — это BOM
iconv -f windows-1251 -t utf-8 in.txt > out.txt
sed -i 's/\r$//' script.sh                      # убрать CR (или dos2unix script.sh)
sed -i '1s/^\xEF\xBB\xBF//' script.sh           # убрать BOM
unzip -O cp866 архив_из_windows.zip             # имена файлов внутри ZIP в кодировке DOS
locale -a | grep -i ru_RU                       # ru_RU.utf8 должна быть в списке
```

- Имена файлов внутри ZIP: для переносимости создавайте архивы с `КодировкаИменФайловВZipФайле.UTF8`.
- Процессу сервера нужна локаль UTF-8 (`LANG=ru_RU.UTF-8`), иначе имена файлов с кириллицей превращаются в вопросительные знаки [практика]. Генерация локали: `sudo locale-gen ru_RU.UTF-8`.

### 4.7. Права на каталоги обмена

Серверный код 1С работает от `usr1cv8` (группа `grp1cv8`). Типовая настройка каталога, в который пишет и сервер 1С, и люди или другие службы:

```bash
sudo mkdir -p /srv/1c/exchange/{in,out,archive}
sudo chown -R usr1cv8:grp1cv8 /srv/1c/exchange
sudo chmod -R 2770 /srv/1c/exchange            # 2 = set-group-ID: новые файлы наследуют группу каталога
sudo usermod -aG grp1cv8 operator1             # человек или служба, которым нужен доступ
sudo -u usr1cv8 touch /srv/1c/exchange/in/test && echo "запись есть"
namei -l /srv/1c/exchange/in/test              # права на каждом компоненте пути
```

- Чтобы новые файлы были доступны группе на запись, службе задают `UMask=0007` (drop-in через `systemctl edit`), либо используют ACL по умолчанию: `sudo setfacl -R -m g:grp1cv8:rwX -m d:g:grp1cv8:rwX /srv/1c/exchange`.
- Файловая база, с которой работают несколько пользователей одного компьютера: платформа создаёт файлы с режимом `0660`, поэтому пользователей включают в одну группу, делают её владельцем каталога базы и ставят `chmod g+s <каталог базы>`; `umask` может только отнять права [офиц.]. То же для хранилища конфигурации.
- Сервер читает каталог временных файлов; на каталог данных кластера ему нужны полные права [офиц.].

### 4.8. Сетевые каталоги: CIFS вместо UNC

Подробно — `kb/linux/07-diski-fs-lvm.md`, раздел 14. Минимум для каталога обмена на файловом сервере Windows:

```bash
sudo apt install -y cifs-utils
sudo mkdir -p /mnt/exchange /etc/cifs-creds
printf 'username=svc_1c\npassword=СЕКРЕТ\ndomain=CORP\n' | sudo tee /etc/cifs-creds/exchange >/dev/null
sudo chmod 600 /etc/cifs-creds/exchange
```

Строка `/etc/fstab` (одна строка):

```text
//fs01.corp.local/exchange  /mnt/exchange  cifs  credentials=/etc/cifs-creds/exchange,uid=usr1cv8,gid=grp1cv8,file_mode=0660,dir_mode=0770,iocharset=utf8,vers=3.0,_netdev,nofail,x-systemd.automount  0  0
```

```bash
sudo systemctl daemon-reload && sudo mount -a
findmnt /mnt/exchange
sudo -u usr1cv8 ls -la /mnt/exchange
```

- `uid`, `gid`, `file_mode`, `dir_mode` задают, кем и с какими правами файлы видны на Linux: сервер Windows не передаёт владельцев в понятиях UNIX. `credentials` хранит имя, пароль и домен вне `fstab`. `vers` — диалект SMB (`3.0`, `3.1.1`; по умолчанию согласуется не ниже 2.1). `_netdev` и `nofail` не дают системе зависнуть при загрузке, если ресурс недоступен.
- Для каталога с **файловой информационной базой** нельзя использовать опцию `nobrl` в `mount.cifs` и `locking = no` в Samba: платформе нужны блокировки диапазонов байтов [офиц.].
- Альтернативы: NFS между Linux-машинами (`sudo apt install nfs-common`, тип `nfs4`), SFTP (`sftp`, `rsync -e ssh`, `sshfs`). Объект `FTPСоединение` умеет FTP и FTPS, но не SFTP — для SFTP вызывают системные утилиты или монтируют `sshfs`.
- Windows-клиенты и Linux-сервер видят один ресурс под разными путями. В настройках конфигурации заводят два значения («путь для клиента», «путь для сервера») либо выполняют все файловые операции на одной стороне.

## 5. Внешние источники данных и ODBC

### 5.1. Как это устроено на Linux

- Внешний источник данных получает данные из ODBC-источников в Windows и Linux; полные возможности языка запросов — для Microsoft SQL Server, IBM DB2, PostgreSQL и Oracle Database, для остальных СУБД часть конструкций может не работать из-за драйвера [офиц., v8.1c.ru].
- На Linux нужен менеджер драйверов **unixODBC** версии 2.2.11 и выше (библиотека `libodbc`) [офиц.]. Платформа ищет её в кеше линковщика по имени `libodbc.so.X.Y` и берёт старшую версию: `ldconfig -p | grep libodbc`.
- Драйвер и unixODBC ставятся там, где выполняется обращение: в клиент-серверном варианте — на **каждом рабочем сервере 1С**; для файловой базы — на клиенте; для файловой базы, опубликованной через веб-сервер, — на машине веб-сервера [офиц.].
- Соединение устанавливает процесс `rphost` от пользователя `usr1cv8`, поэтому источники описывают в системных файлах (`/etc/odbc.ini`), а не в `~/.odbc.ini` администратора, и проверяют от имени `usr1cv8`.
- Ограничение «сервер на Linux не работает с MS SQL» касается только хранения информационной базы. Читать чужую базу MS SQL как внешний источник через ODBC можно.
- Windows-драйверы Jet/ACE (`Microsoft.ACE.OLEDB`, «Driver={Microsoft Excel Driver}») на Linux отсутствуют: Excel читают через `ТабличныйДокумент.Прочитать()`, DBF — объектом `XBase`.

### 5.2. unixODBC: файлы и команды

```bash
sudo apt install -y unixodbc            # isql, iusql; тянет libodbc2 и odbcinst
odbcinst -j                             # версия и расположение файлов конфигурации
odbcinst -q -d                          # зарегистрированные драйверы (секции /etc/odbcinst.ini)
odbcinst -q -s                          # источники данных (DSN)
```

| Файл | Содержимое |
|---|---|
| `/etc/odbcinst.ini` | описания драйверов: имя секции — имя драйвера, параметр `Driver` — путь к `.so` |
| `/etc/odbc.ini` | системные источники данных (DSN), видны всем пользователям |
| `~/.odbc.ini` | источники одного пользователя |

| Команда | Что делает |
|---|---|
| `odbcinst -i -d -f <шаблон>` | зарегистрировать драйвер из файла-шаблона |
| `odbcinst -u -d -n "<имя драйвера>"` | удалить регистрацию драйвера |
| `odbcinst -i -s -l -f <шаблон>` | добавить системный DSN (`-l`); `-h` — пользовательский |
| `isql -v <DSN> <пользователь> <пароль>` | проверить подключение, `-v` — подробные ошибки |
| `isql -v -k "<строка соединения>"` | подключиться строкой соединения без DSN (ключ `-k` — «use SQLDriverConnect»); строка ставится на место DSN |
| `iusql …` | то же в Unicode-варианте (в man отдельно указана форма `iusql "ConnectionString" [options]`) |
| ключи `isql`/`iusql` [офиц., isql(1)] | `-b` — пакетный режим (по одной команде SQL в строке со стандартного ввода); `-d<символ>` — разделитель колонок (`-d,`); `-x0xNN` — разделитель кодом (`-x0x09` — табуляция); `-c` — имена колонок первой строкой (только с `-d`/`-x`); `-m<N>` — ограничить ширину колонок; `-q` — строки в кавычках; `-n` — многострочный SQL, конец команды — `GO`; `-e` — `SQLExecDirect` вместо `Prepare`; `-L<N>` — предел длины символьного поля (по умолчанию 300); `-3` — вызовы ODBC 3; `-v` — подробные ошибки; `--version` |

Проверять всегда от имени службы сервера:

```bash
echo "SELECT 1;" | sudo -u usr1cv8 isql -b -v MSSQLTest reader 'ПАРОЛЬ'
```

### 5.3. Microsoft SQL Server: msodbcsql18

```bash
# Ubuntu 18.04 / 20.04 / 22.04 / 24.04 / 26.04 — команды из документации Microsoft
curl -sSL -O https://packages.microsoft.com/config/ubuntu/$(grep VERSION_ID /etc/os-release | cut -d '"' -f 2)/packages-microsoft-prod.deb
sudo dpkg -i packages-microsoft-prod.deb && rm packages-microsoft-prod.deb
sudo apt-get update
sudo ACCEPT_EULA=Y apt-get install -y msodbcsql18
sudo ACCEPT_EULA=Y apt-get install -y mssql-tools18        # необязательно: sqlcmd и bcp в /opt/mssql-tools18/bin
odbcinst -q -d -n "ODBC Driver 18 for SQL Server"
```

`/etc/odbc.ini` (пример из документации Microsoft с дополнениями):

```ini
[MSSQLTest]
Driver = ODBC Driver 18 for SQL Server
Server = tcp:sql01.corp.local,1433
Database = wms
Encrypt = yes
TrustServerCertificate = yes
```

- Имя драйвера — `ODBC Driver 18 for SQL Server`; библиотека лежит в `/opt/microsoft/msodbcsql18/lib64/`.
- Порт указывают в `Server` через запятую: ключевого слова `Port` у драйвера Microsoft для Linux нет. Протокол поддерживается только `tcp`.
- В драйвере 18 шифрование включено по умолчанию и сертификат сервера проверяется. Для сервера с самоподписанным сертификатом добавляют `TrustServerCertificate=yes` либо отключают шифрование `Encrypt=no`. Хранилище доверенных сертификатов драйвера на Ubuntu — `/etc/ssl/certs`.
- Принять лицензию без переменной окружения: `echo msodbcsql18 msodbcsql/ACCEPT_EULA boolean true | sudo debconf-set-selections`.
- Драйвер 17 (`msodbcsql17`) на Ubuntu 26.04 в перечне Microsoft не значится — берите 18.

### 5.6. Oracle

Нужны пакеты Oracle Instant Client (Basic или Basic Light и ODBC). Подтверждено по документации Oracle (docs.oracle.com, «Using the Oracle ODBC Driver»): в UNIX-поставке драйвера есть сценарий установки `odbc_update_ini.sh` («Unix users must use the odbc_update_ini.sh file to create a DSN»), библиотека драйвера называется `libsqora.so.nn.n` (в документации пример — `libsqora.so.20.1`; в комплектах 19c и 21c это `libsqora.so.19.1` и `libsqora.so.21.1`), приложение работает через менеджер драйверов unixODBC (`libodbc.so`), описание — в файле `ODBC_IC_Readme_Unix.html` из комплекта.

```bash
# ⚠ последовательность записана по памяти (см. оговорки ниже) — сверить с ODBC_IC_Readme_Unix.html
# Instant Client распакован в /opt/oracle/instantclient_21_x (zip-архивы Basic + ODBC с сайта Oracle)
sudo apt install -y unixodbc libaio1t64 || sudo apt install -y unixodbc libaio1   # 24.04+: libaio1t64; 22.04: libaio1
echo /opt/oracle/instantclient_21_x | sudo tee /etc/ld.so.conf.d/oracle-instantclient.conf && sudo ldconfig
cd /opt/oracle/instantclient_21_x
sudo ./odbc_update_ini.sh /              # первый аргумент — корень установки unixODBC («/» для системного пакета)
odbcinst -q -d                           # появится секция вида [Oracle 21 ODBC driver]
ldd ./libsqora.so.21.1 | grep 'not found'
```

- ⚠ не подтверждено первоисточником (страницы загрузки и readme Oracle возвращают 403; записано по памяти): точный синтаксис `odbc_update_ini.sh <каталог unixODBC> [<каталог Instant Client> <имя драйвера> <DSN> <файл odbc.ini>]` и имена секций по умолчанию — сверяйте с `ODBC_IC_Readme_Unix.html` своего комплекта.
- Имя пакета подтверждено по packages.ubuntu.com 10.10.2026: в 22.04 — `libaio1`, в 24.04 и 26.04 — `libaio1t64`. Остальное [практика, по памяти]: в Ubuntu 24.04 и новее пакет называется `libaio1t64`, а библиотека в нём — `libaio.so.1t64`; Instant Client ищет `libaio.so.1`. Если `ldd` показывает `libaio.so.1 => not found`, создают ссылку: `sudo ln -s /usr/lib/x86_64-linux-gnu/libaio.so.1t64 /usr/lib/x86_64-linux-gnu/libaio.so.1`.
- Строка соединения без `tnsnames.ora` (Easy Connect): `DRIVER={Oracle 21 ODBC driver};DBQ=ora01.corp.local:1521/ORCLPDB1;` — имя драйвера берётся из `odbcinst -q -d`. Процессу `rphost` нужны локаль и переменная `NLS_LANG` (например, `AMERICAN_AMERICA.AL32UTF8`) в окружении службы, иначе кириллица придёт вопросительными знаками [практика].

### 5.7. Настройка в 1С

```bsl
&НаСервере
Процедура ПодключитьСклад()
    Параметры = ВнешниеИсточникиДанных.Склад.ПолучитьОбщиеПараметрыСоединения();
    Параметры.АутентификацияСтандартная = Истина;
    Параметры.ИмяПользователя = "reader";

    Параметры.СтрокаСоединения =
        "DRIVER={ODBC Driver 18 for SQL Server};SERVER=tcp:sql01.corp.local,1433;DATABASE=wms;TrustServerCertificate=yes";
    // Свойство СУБД выставляется в диалоге «Параметры соединения» или кодом — значение взять из синтакс-помощника
```

- Имя драйвера в фигурных скобках должно буква в букву совпадать с именем секции в `/etc/odbcinst.ini`.

## 6. Криптография и ЭДО

### 6.1. КриптоПро CSP для Linux

Установка по справочнику 1С-ЭДО и вики ALT Linux:

```bash
# дистрибутив скачивается с сайта производителя (нужна регистрация): linux-amd64_deb.tgz
tar -zxf ./linux-amd64_deb.tgz && cd linux-amd64_deb
sudo ./install_gui.sh                         # мастер: отметить «Поддержка токенов и смарт-карт», если будут токены
sudo apt-get install -y libpcsclite1 pcscd libccid     # работа с токенами
sudo systemctl enable --now pcscd

# утилиты лежат вне PATH
export PATH="$PATH:/opt/cprocsp/bin/amd64:/opt/cprocsp/sbin/amd64"
```

- Сервер без графики. ⚠ не подтверждено прочитанными источниками (1С-ЭДО, вики ALT Linux и база знаний support.cryptopro.ru для Debian 11 описывают только `install_gui.sh`; рецензент перепроверил все три): в том же архиве есть консольный сценарий `sudo ./install.sh`, который ставит базовый набор пакетов. Подтверждённая альтернатива без сценариев — поставить пакеты из распакованного архива пакетным менеджером; состав базового набора назван в вики ALT Linux (там команда `apt-get install cprocsp-curl* lsb-cprocsp-base* lsb-cprocsp-capilite* lsb-cprocsp-kc1-64* lsb-cprocsp-rdr-64*`), для Ubuntu это:

```bash
cd linux-amd64_deb
ls *.deb | head -30                              # посмотреть точные имена и версию
sudo dpkg -i lsb-cprocsp-base_*.deb
sudo dpkg -i lsb-cprocsp-rdr-64_*.deb lsb-cprocsp-kc1-64_*.deb lsb-cprocsp-capilite-64_*.deb cprocsp-curl-64_*.deb
sudo apt -f install                              # доустановить системные зависимости, если dpkg их запросил
/opt/cprocsp/sbin/amd64/cpconfig -license -view  # проверка: установлено и видна лицензия
```

- Базовые пакеты: `lsb-cprocsp-base`, `lsb-cprocsp-rdr-64`, `lsb-cprocsp-kc1-64`, `lsb-cprocsp-capilite-64`, `cprocsp-curl-64`; дополнительные: `cprocsp-rdr-gui-gtk-64`, `cprocsp-rdr-pcsc-64`, `cprocsp-rdr-rutoken-64`, `cprocsp-rdr-jacarta-64`, `cprocsp-rdr-cryptoki-64` (носители с неизвлекаемыми ключами), `lsb-cprocsp-pkcs11-64`, `lsb-cprocsp-ca-certs` (сертификаты Главного УЦ), `cprocsp-cptools-gtk-64` (графические «Инструменты КриптоПро», запуск — `cptools`) [практика, ALT Linux; в вики имена даны масками без суффикса архитектуры, точные имена файлов зависят от версии].
- Обновление КриптоПро: вики ALT Linux рекомендует удалить пакеты и поставить их заново (там удаление — `apt-get remove lsb-cprocsp-base`, остальные пакеты зависят от базового); каталог контейнеров `/var/opt/cprocsp/keys` и серийный номер лицензии перед этим сохраните.
- Каталоги: утилиты пользователя — `/opt/cprocsp/bin/amd64` (`certmgr`, `cryptcp`, `csptest`), административные — `/opt/cprocsp/sbin/amd64` (`cpconfig`), библиотеки — `/opt/cprocsp/lib/amd64`, контейнеры считывателя HDIMAGE — `/var/opt/cprocsp/keys/<пользователь>/`.
- Лицензия: без серийного номера действует ознакомительная полнофункциональная лицензия на 90 дней [офиц., cryptopro.ru: «ознакомительная полнофункциональная 90-дневная лицензия»; вики ALT Linux говорит о трёх месяцах]. Производитель различает лицензии на рабочее место и на сервер [офиц., cryptopro.ru]; вики ALT Linux утверждает: «Для версии КриптоПро CSP под Linux все лицензии считаются серверными» [практика; на сайте производителя такой формулировки рецензент не нашёл]. ⚠ не подтверждено: какой вид лицензии нужен именно вашему серверу 1С (подписание на сервере от имени организации обычно трактуется как серверное применение) — уточняйте у поставщика до закупки.

| Задача | Команда |
|---|---|
| Посмотреть лицензию | `cpconfig -license -view` |
| Ввести серийный номер | `sudo cpconfig -license -set <серийный номер>` |
| Список считывателей | `cpconfig -hardware reader -view` |
| Добавить считыватель «каталог на диске» | `sudo cpconfig -hardware reader -add HDIMAGE store` |
| Список контейнеров | `csptest -keyset -enum_cont -fqcn -verifyc` (при кириллице в именах добавить `-uniq`) |
| Создать тестовый контейнер | `csptest -keyset -provtype 80 -newkeyset -cont '\\.\HDIMAGE\test'` (в вики ALT есть оба примера: с `-provtype 75 … -cont '\\.\HDIMAGE\test'` и с `-provtype 80 -newkeyset -cont testinside_2012`); на сервере без графики биологический датчик случайных чисел просит нажимать клавиши прямо в терминале [практика] |
| Какие провайдеры зарегистрированы | `cpconfig -defprov -view_type` (типы) и `cpconfig -defprov -view -provtype 80` (имена провайдеров типа 80) |
| Скопировать контейнер | `csptest -keycopy -contsrc '\\.\FLASH\src' -contdest '\\.\HDIMAGE\dst'` |
| Удалить контейнер | `csptest -keyset -deletekeyset -cont '\\.\HDIMAGE\test'` |
| Установить личный сертификат с привязкой к контейнеру | `certmgr -inst -file cert.cer -store uMy -cont '\\.\HDIMAGE\dst'` |
| То же с выбором контейнера из списка | `certmgr -inst -f cert.cer -ask-container` (так в справочнике 1С-ЭДО: там используется запись `-f`, в вики ALT Linux — `-file`) |
| Корневой сертификат для пользователя | `certmgr -inst -store uRoot -file ca.cer` (в справочнике 1С-ЭДО — `certmgr -inst -store root -f ca.crt`) |
| Все сертификаты из файла `.p7b` | `certmgr -inst -all -file chain.p7b -store uRoot` |
| Сертификаты из контейнеров в хранилище `uMy` | `csptestf -absorb -certs -autoprov` (утилита именно `csptestf` — так в вики ALT Linux) |
| Сертификаты контейнера на токене | `certmgr -list -container '\\.\Aktiv Rutoken ECP - CP 00 00\Rutoken'` |
| Корневой сертификат для всех (от root) | `sudo certmgr -inst -store mRoot -file ca.cer` |
| Список сертификатов | `certmgr -list -store uMy` (строка `PrivateKey Link: Yes` — есть связь с ключом) |
| Экспорт сертификата | `certmgr -export -dn 'CN=…' -dest cert.cer` |
| Удалить сертификат | `certmgr -delete -dn 'CN=…'` |
| Подписать (присоединённая подпись) | `cryptcp -sign -dn 'E=user@example.ru' -der doc.pdf` |
| Подписать (отсоединённая подпись) | `cryptcp -signf -dn 'E=user@example.ru' -der doc.pdf` |
| Проверить подпись | `cryptcp -verify doc.pdf.sig`; отсоединённую — `cryptcp -vsignf doc.pdf` |

- В таблице тип провайдера 80 соответствует ГОСТ Р 34.10-2012 (256 бит), 81 — ГОСТ Р 34.10-2012 (512 бит), 75 — устаревший ГОСТ Р 34.10-2001 [офиц., методичка ИТС].
- Перенос ключа с Windows: контейнер из реестра копируют средствами КриптоПро на носитель (получается каталог `xxxxxxxx.000` с шестью файлами `*.key`), каталог кладут в `/var/opt/cprocsp/keys/<пользователь>/`, владельцем делают этого пользователя, права — только ему (каталог `700`, файлы `600`), затем ставят сертификат с привязкой к контейнеру [практика].
- Загрузка сертификатов из контейнеров (в том числе с токенов) в хранилище `uMy`: вики ALT Linux даёт команду `csptestf -absorb -certs -autoprov` — утилита называется **`csptestf`**, а не `csptest` (исправлено рецензентом; в первой редакции было `csptest`). ⚠ В других руководствах встречается и `csptest -absorb -certs` — по памяти, не проверено; если одна форма не сработала, попробуйте вторую.
- Списки отзыва (CRL): по вики ALT Linux они ставятся «точно так же, только с параметром `-crl`», то есть `certmgr -inst -crl -file list.crl` (готового примера команды в вики нет — ⚠ синтаксис восстановлен по этой фразе). Чтобы КриптоПро сам загружал CRL по сети, вики требует указать путь к libcurl: `sudo cpconfig -ini '\config\apppath' -add string libcurl.so /opt/cprocsp/lib/amd64/libcpcurl.so`.
- На сервере без графики все операции делаются этими утилитами; на рабочем месте с графикой то же доступно в приложении «Инструменты КриптоПро» (`cptools`): ввод лицензии, просмотр контейнеров, установка сертификатов [офиц., support.cryptopro.ru].

### 6.2. Настройка 1С для КриптоПро на Linux

- В прикладном решении: «Администрирование → Обмен электронными документами → Настройки электронной подписи и шифрования → Программы» (в конфигурациях без ЭДО — «Администрирование → Общие настройки → Электронная подпись и шифрование»). Программа — «КриптоПро CSP (ГОСТ 2012/256)».
- В поле пути к программе выбирают «Стандартный путь для Linux» или вводят строку [офиц., справочник 1С-ЭДО]:

```text
/opt/cprocsp/lib/amd64/libcapi10.so:/opt/cprocsp/lib/amd64/libcapi20.so
```

- В новых версиях БСП поле можно не заполнять — путь определяется автоматически. Если КриптоПро установлен в нестандартный каталог, пользователь, от имени которого работает 1С, должен иметь право чтения этих каталогов [офиц.].
- В коде второй параметр конструктора — путь к библиотекам, он имеет смысл только в Linux:

```bsl
// Имя провайдера должно существовать в установленном КриптоПро: cpconfig -defprov -view -provtype 80
// (на Linux это может быть и "Crypto-Pro GOST R 34.10-2012 KC1 CSP")
Менеджер = Новый МенеджерКриптографии(
    "Crypto-Pro GOST R 34.10-2012 Cryptographic Service Provider",
    "/opt/cprocsp/lib/amd64/libcapi10.so:/opt/cprocsp/lib/amd64/libcapi20.so",
    80);
Сертификаты = Менеджер.ПолучитьХранилищеСертификатов(
    ТипХранилищаСертификатовКриптографии.ПерсональныеСертификаты).ПолучитьВсе();
```

- Имена провайдеров на Linux отличаются от Windows. По коду БСП 3.1 (обработка `ПрограммыЭлектроннойПодписиИШифрования`) [БСП, код]:

| Представление в БСП | Имя программы (первый параметр `МенеджерКриптографии`) | Тип | Где есть |
|---|---|---|---|
| КриптоПро CSP (ГОСТ 2012/256) | `Crypto-Pro GOST R 34.10-2012 Cryptographic Service Provider` | 80 | Windows, Linux |
| КриптоПро CSP (ГОСТ 2012/256) KC1 | `Crypto-Pro GOST R 34.10-2012 KC1 CSP` | 80 | только не-Windows |
| КриптоПро CSP (ГОСТ 2012/256) KC2 | `Crypto-Pro GOST R 34.10-2012 KC2 CSP` | 80 | только не-Windows |
| КриптоПро CSP (ГОСТ 2012/512) | `Crypto-Pro GOST R 34.10-2012 Strong Cryptographic Service Provider` | 81 | Windows, Linux |
| КриптоПро CSP (ГОСТ 2012/512) KC1 / KC2 | `Crypto-Pro GOST R 34.10-2012 KC1 Strong CSP` / `… KC2 Strong CSP` | 81 | только не-Windows |
| ViPNet CSP (ГОСТ 2012/256) | `Infotecs GOST 2012/512 Cryptographic Service Provider` | 77 | в БСП помечен «нет в Linux» |
| ViPNet CSP (ГОСТ 2012/512) | `Infotecs GOST 2012/1024 Cryptographic Service Provider` | 78 | в БСП помечен «нет в Linux» |

  Пути к модулям КриптоПро, зашитые в БСП: Linux x86-64 — `/opt/cprocsp/lib/amd64/libcapi10.so` и `…/libcapi20.so`; Linux x86 — `/opt/cprocsp/lib/ia32/…`; для ARM64 и Эльбруса в коде БСП указан каталог `/opt/cprocsp/lib/lib64/` (порядок поиска модуля самой платформой описан в «Руководстве разработчика» 8.3.27, разд. 23.6.2: параметр `ПутьМодуляКриптографии`, затем каталоги из `CryptoAPILibraryLocation` файла `conf.cfg`, затем стандартные пути КриптоПро; сами пути документация не называет — на своей машине проверьте `ls /opt/cprocsp/lib/`). Какие имена реально зарегистрированы в установленном КриптоПро, показывает `cpconfig -defprov -view -provtype 80`: в КриптоПро 5.0 на Linux это и `Crypto-Pro GOST R 34.10-2012 KC1 CSP`, и `Crypto-Pro GOST R 34.10-2012 Cryptographic Service Provider` [практика, вики ALT Linux].
- Смешанная среда (сервер Linux, рабочие места Windows; КриптоПро 4.0): имя провайдера, записанное в Windows, на Linux может отсутствовать — отсюда ошибка «Сертификат связан с модулем криптографии … с типом 80». В КриптоПро 5.0 и актуальной БСП проблема обычно не возникает (Windows-имя зарегистрировано и в Linux, а БСП знает имена KC1/KC2), поэтому сначала проверьте `cpconfig -defprov -view -provtype 80` и обновите БСП/КриптоПро, а регистрацию имени вручную оставьте для КриптоПро 4.0 (его сертификаты соответствия истекли 15.01.2026). Методичка ИТС и справочник 1С-ЭДО предлагают зарегистрировать провайдер под Windows-именем [офиц.; в источниках пути даны для 32-разрядной сборки `ia32`, для x86-64 подставлен `amd64` — проверьте наличие файла]:

```bash
P='\cryptography\Defaults\Provider\Crypto-Pro GOST R 34.10-2012 Cryptographic Service Provider'
sudo /opt/cprocsp/sbin/amd64/cpconfig -ini "$P" -add string 'Image Path' /opt/cprocsp/lib/amd64/libcsp.so
sudo /opt/cprocsp/sbin/amd64/cpconfig -ini "$P" -add string 'Function Table Name' CPCSP_GetFunctionTable
sudo /opt/cprocsp/sbin/amd64/cpconfig -ini "$P" -add long Type 80
```

### 6.3. Подписание и шифрование на сервере

Порядок по справочнику 1С-ЭДО [офиц.], переложенный на Linux:

1. Определить пользователя, от имени которого работает агент сервера (по умолчанию `usr1cv8`): `systemctl show -p User 'srv1cv8-8.3.27.1688@default'` или `ps -o user= -C ragent`.
2. Установить криптопровайдер на сервере (на каждом рабочем сервере кластера) и ввести лицензию.
3. Разместить контейнеры так, чтобы они были доступны этому пользователю; установить личные и корневые сертификаты и списки отзыва в его хранилища («для текущего пользователя» достаточно).
4. В программе включить флажки «Проверять подписи и сертификаты на сервере» и «Подписывать на сервере».
5. Пароль контейнера сохранить или не задавать: сервер не может показать окно ввода.

```bash
CP=/opt/cprocsp/bin/amd64
sudo install -d -o usr1cv8 -g grp1cv8 -m 700 /var/opt/cprocsp/keys/usr1cv8
sudo cp -r /media/usb/abcd1234.000 /var/opt/cprocsp/keys/usr1cv8/
sudo chown -R usr1cv8:grp1cv8 /var/opt/cprocsp/keys/usr1cv8 && sudo chmod -R go-rwx /var/opt/cprocsp/keys/usr1cv8
sudo -u usr1cv8 -H $CP/csptest -keyset -enum_cont -fqcn -verifyc
sudo -u usr1cv8 -H $CP/certmgr -inst -file /tmp/org.cer -store uMy -cont '\\.\HDIMAGE\abcd1234'
sudo -u usr1cv8 -H $CP/certmgr -inst -store uRoot -file /tmp/ca.cer
sudo -u usr1cv8 -H $CP/certmgr -list -store uMy | grep -E 'Subject|PrivateKey Link|Not valid after'
```

- Ключ `-H` у `sudo` важен: домашним каталогом должен стать `/home/usr1cv8`, иначе хранилище окажется не там.
- Если криптооперации оставить «на клиенте», СКЗИ и ключи на сервере не нужны, но регламентные задания автоматического обмена работать не смогут [офиц., 1С-ЭДО].
- Для веб-клиента нужна внешняя компонента криптографии под конкретный браузер и библиотека GTK-3 [офиц.].
- Что нового в платформе [офиц.]: 8.3.26 — присоединённая подпись; 8.3.27 — ускорена криптография в Linux и построение цепочек сертификатов, срок действия закрытого ключа; 8.5.4 — хеширование ГОСТ Р 34.11-2012 во встроенном языке.

### 6.4. ViPNet CSP и другое

- ViPNet CSP: сертифицирована версия 4.4.8 (сертификат ФСБ № СФ/124-4702 от 28.12.2023, действует до 28.12.2026, классы КС1–КС3); версия для Linux приобретается у «ИнфоТеКС» (soft@infotecs.ru), а не скачивается свободно; создание защищённых TLS-соединений — только в Windows-версии [офиц., infotecs.ru]. Исправлено рецензентом: Ubuntu и Debian в перечне поддерживаемых ОС **есть**, но только старые выпуски — «Ubuntu 14.04 LTS, 16.04 LTS, 18.04 LTS, 20.04 LTS», «Ubuntu Server 18.04 LTS», «Debian 9, 10, 11» (плюс CentOS 7, RHEL 6–8, Astra Linux, РЕД ОС, ROSA, Альт и др.); Ubuntu 22.04, 24.04 и 26.04 в перечне нет.
- ViPNet CSP и 1С на Linux: в БСП 3.1 оба провайдера ViPNet («Infotecs GOST 2012/512 Cryptographic Service Provider», тип 77 — это ГОСТ 2012/**256**; «Infotecs GOST 2012/1024 Cryptographic Service Provider», тип 78 — ГОСТ 2012/**512**) описаны с признаками «нет в Linux» и «нет в macOS», а поставляемые пути к модулям заданы только для КриптоПро [БСП, код]. То есть типовая настройка «Программы электронной подписи и шифрования» ViPNet на Linux-сервере или Linux-клиенте не предлагает; справочник 1С-ЭДО тоже описывает только Windows-версию. Вывод для планирования: на Linux-сервере 1С рассчитывайте на КриптоПро CSP. **Уточнено 11.10.2026** («Руководство разработчика» 8.3.27, разд. 23.5): на уровне платформы при работе в Linux и macOS используется интерфейс КриптоПро CSP, и в списке поддерживаемых средств назван только КриптоПро (тип модуля криптографии 80). Модуль ищется так: путь из параметра `ПутьМодуляКриптографии` конструктора, затем каталоги из параметра `CryptoAPILibraryLocation` файла `conf.cfg`, затем стандартные пути КриптоПро. Ранее было не подтверждено: можно ли добавить ViPNet на Linux вручную (как «другую программу» с путём к библиотекам) — путей к библиотекам ViPNet в открытых источниках и в БСП нет.
- Браузерные сценарии: «КриптоПро ЭЦП Browser plug-in» ставится пакетами из архива плагина (`sudo dpkg -i cpro*.deb`), после чего браузер перезапускают; для входа на Госуслуги с токеном нужен отдельный плагин `IFCPlugin-x86_64.deb` и служба `pcscd` [практика, interface31].

## 7. Интернет-функции: HTTP, FTP, почта, сертификаты, прокси

### 7.1. Где в Linux лежат доверенные сертификаты

По документации платформы [офиц., руководство администратора, 4.3.9.3]:

| Источник | ОС | Примечание |
|---|---|---|
| Хранилище сертификатов ОС Linux — каталог `/etc/ssl/certs` | Linux | все сертификаты в каталоге считаются доверенными |
| `/etc/ssl/certs/ca-certificates.crt` | Debian, Mint, Ubuntu | дополнительно поддерживаемый файл-связка |
| `/etc/ssl/certs/ca-bundle.trusted.crt`, `/etc/pki/tls/certs/ca-bundle.crt` | CentOS, Fedora, RedHat | — |
| `/etc/share/ca-certificates/ca-bundle.crt` | Alt Linux | так в документации (конспект `kb/its-docs/adm-gl04-zapusk-komponentov-p2.md`) |
| Файловые сертификаты | все ОС | PEM (расширение `*.pem` и любое другое) или PKCS#12 (`*.p12`, `*.pfx`); формат определяется по расширению |

Файлы платформы `cacertnx.pem` и `cacert.pem` [офиц., приложение 3]:

| Версия платформы | Режим совместимости | Что используется |
|---|---|---|
| до 8.3.8 | «Версия 8.3.7» и ниже | только `cacert.pem` |
| с 8.3.8 до 8.3.19 | «Версия 8.3.8» | только механизм получения сертификатов УЦ, предоставляемый ОС |
| с 8.3.20 | «Версия 8.3.8» и последующие | сначала `cacertnx.pem`, затем механизм ОС |
| с 8.3.20 | «Версия 8.3.7» и ниже | только `cacert.pem` |

- В Windows эти файлы лежат в каталоге `bin` версии [офиц., методичка ИТС 2018 г.]. Расположение файлов в Linux документация 8.3.27 не называет (приложение 3, разд. 3.13 — сверено по полному тексту 10.10.2026), но задаёт правило выбора: до 8.3.8 и в режиме совместимости 8.3.7 и ниже используется только `cacert.pem`; с 8.3.8 до 8.3.19 — только хранилище сертификатов операционной системы; начиная с 8.3.20 в режиме совместимости 8.3.8 и выше — сначала `cacertnx.pem`, затем хранилище ОС. ⚠ По практике, без подтверждения первоисточником: в Linux — прямо в каталоге версии, `/opt/1cv8/x86_64/<версия>/cacert.pem` (так пишут практические руководства, по памяти). Проверьте на месте: `find /opt/1cv8 -name 'cacert*.pem' -exec ls -l {} +`. Файл принадлежит версии платформы: после установки новой сборки добавленные вручную сертификаты пропадут, поэтому свои корневые сертификаты добавляйте в хранилище ОС (ниже), а не в файл платформы.
- Что это значит для сервера на Linux с конфигурацией в режиме совместимости 8.3.8+ (то есть практически для всех современных конфигураций) и платформой 8.3.20+: при проверке сертификатов, предъявляемых при установке защищённого соединения, платформа сначала использует `cacertnx.pem`, затем механизм операционной системы [офиц., приложение 3, раздел 3.13]; в Linux механизм ОС — это каталог `/etc/ssl/certs` [офиц., 4.3.9.3]. Поэтому свой корневой сертификат достаточно добавить через `update-ca-certificates`. Обновлённый `cacertnx.pem` документация предлагает подкладывать только для MSI-дистрибутивов Windows; способ для Linux не описан.
- Клиентские сертификаты из хранилища Windows клиент под Linux не поддерживает [офиц.] — используйте файл (`СертификатКлиентаФайл`, параметр `/HttpsCert -file`).
- Для клиентского сертификата в формате PEM закрытый ключ дописывают в тот же файл; файл P12/PFX обязан содержать ключ [офиц.].

Добавить сертификат своего удостоверяющего центра в хранилище Ubuntu:

```bash
sudo cp corp-root-ca.crt /usr/local/share/ca-certificates/      # формат PEM, расширение обязательно .crt
sudo update-ca-certificates                                     # пересобирает /etc/ssl/certs и ca-certificates.crt
openssl s_client -connect api.example.ru:443 -servername api.example.ru </dev/null 2>/dev/null | grep 'Verify return code'
sudo -u usr1cv8 curl -sS -o /dev/null -w '%{http_code}\n' https://api.example.ru/
```

Так же добавляют корневой сертификат Минцифры (Russian Trusted Root CA), если серверы используют российские сертификаты [практика]. После изменения хранилища службу 1С лучше перезапустить.

### 7.2. HTTPСоединение и защищённое соединение

```bsl
// Проверка сертификата сервера по системной связке Ubuntu
СертификатыУЦ = Новый СертификатыУдостоверяющихЦентровФайл("/etc/ssl/certs/ca-certificates.crt");
Защита = Новый ЗащищенноеСоединениеOpenSSL(Неопределено, СертификатыУЦ);
Соединение = Новый HTTPСоединение("api.example.ru", 443, , , , 30, Защита);
Ответ = Соединение.Получить(Новый HTTPЗапрос("/v1/ping"));

// То же через хранилище ОС (в Linux — каталог /etc/ssl/certs)
Защита = Новый ЗащищенноеСоединениеOpenSSL(Неопределено, Новый СертификатыУдостоверяющихЦентровОС);

// Клиентский сертификат на Linux — только из файла
Клиентский = Новый СертификатКлиентаФайл("/etc/1c/certs/client.p12", "пароль");
Защита = Новый ЗащищенноеСоединениеOpenSSL(Клиентский, СертификатыУЦ);
```

- Если сертификаты УЦ не указаны, сертификат сервера не проверяется, но соединение всё равно шифруется [офиц., таблица вариантов в 4.3.9.2].
- Путь к файлу сертификатов в коде — путь на той стороне, где создаётся соединение. Хранить его в настройках, а не в тексте модуля: на Windows-сервере пути другие.
- Ошибка «Удаленный узел не прошел проверку» на Linux означает, что цепочка сертификатов сервера не строится до доверенного корня: добавьте корневой и промежуточные сертификаты в хранилище ОС либо передайте их файлом.
- `ИнтернетСоединение` на сервере Linux недоступен [офиц.] — в старом коде заменяется на `HTTPСоединение` или `FTPСоединение`.
- Тонкий клиент через веб-сервер: способ проверки сертификата задаётся в свойствах базы («Не проверять», «Файл сертификатов CA», «Хранилище сертификатов Linux») или параметрами `/HttpsCA -linux`, `/HttpsCA -file <путь>`, `/HttpsCA -none`. По умолчанию клиент начинает с TLS 1.3 и понижает версию по требованию веб-сервера [офиц.].

### 7.3. Прокси

```bsl
Прокси = Новый ИнтернетПрокси(Ложь);                         // Ложь — не брать системные настройки
Прокси.Установить("https", "proxy.corp.local", 3128, "svc_1c", "пароль", Ложь);
Прокси.Установить("http",  "proxy.corp.local", 3128, "svc_1c", "пароль", Ложь);
Прокси.НеИспользоватьПроксиДляЛокальныхАдресов = Истина;
Соединение = Новый HTTPСоединение("api.example.ru", 443, , , Прокси, 30, Защита);
```

- На сервере Linux нет «системных настроек прокси» в понимании Windows; Уточнено 15.10.2026 по «Руководству разработчика» 8.3.27 (приложение 7, п. 7.2.2) и перечню изменений 8.3.6: без режима совместимости 8.3.5 `Новый ИнтернетПрокси(Истина)` (прокси по умолчанию) на Linux берёт переменные `http_proxy`, `https_proxy`, `ftp_proxy`, `ftps_proxy`, `all_proxy`, если не найден файл `inetcfg.xml`; сами методы `HTTPСоединение` настройки прокси не определяют — используется то, что передано в параметре `Прокси`. Задавайте прокси явно; в БСП — «Параметры прокси-сервера на сервере 1С:Предприятия». Если всё же рассчитываете на переменные окружения, учтите, что у службы systemd их нет, пока вы не зададите их в юните (`Environment=https_proxy=http://proxy.corp.local:3128`), и проверьте результат на стенде.
- Источники настроек прокси по документации [офиц., гл. 4.3.8.2.1 и приложение 3]: параметр командной строки `/Proxy`, файл `inetcfg.xml` (корневой элемент `InternetProxy`) и объект `ИнтернетПрокси`. Файл `inetcfg.xml` — способ задать прокси по умолчанию для платформы без изменения кода; его формат и расположение — в `kb/its-docs/adm-pr03-sluzhebnye-fajly-p3.md`.
- Прокси с аутентификацией NTLM с Linux-сервера недоступен (аутентификация ОС — только Kerberos) — заводят служебную учётную запись с обычной (Basic) аутентификацией или исключение на прокси.
- Для тонкого клиента: `/Proxy -PSrv <адрес> -PPort <порт> [-PUser <имя> [-PPwd <пароль>]]` или `/NoProxy`; в `ibases.v8i` — `UseProxy`, `PSrv`, `PPort` [офиц.].

### 7.4. FTP и почта

- `FTPСоединение` работает одинаково; за NAT и межсетевым экраном включают пассивный режим. Защищённый вариант — FTPS через `ЗащищенноеСоединениеOpenSSL`. SFTP объект не поддерживает (раздел 4.8).
- Почта: `ИнтернетПочта` с `ИнтернетПочтовыйПрофиль` (SMTP, IMAP, POP3, шифрование SSL/TLS) работает без изменений. Отправка через Outlook, MAPI и `CDO.Message` невозможна.
- Проверка сетевой доступности от имени службы: `sudo -u usr1cv8 nc -vz smtp.example.ru 465`, `resolvectl query smtp.example.ru`.

## 8. Печать и оборудование

### 8.1. CUPS

Клиент 1С на Linux печатает через системную службу печати CUPS и стандартный диалог печати GTK. На Ubuntu Desktop CUPS установлен; на сервере — `sudo apt install cups cups-client`. Веб-интерфейс — `http://localhost:631`; администрировать без `sudo` могут члены группы `lpadmin`.

| Задача | Команда |
|---|---|
| Состояние службы | `systemctl status cups` |
| Принтеры и принтер по умолчанию | `lpstat -p -d` |
| Очереди и адреса устройств | `lpstat -v` |
| Полное состояние | `lpstat -t` |
| Какие устройства и протоколы видит CUPS | `sudo lpinfo -v` |
| Какие модели (драйверы) доступны | `lpinfo -m \| grep -i <модель>` |
| Добавить сетевой принтер без драйвера (IPP Everywhere) | `sudo lpadmin -p office1 -E -v ipp://192.168.1.50/ipp/print -m everywhere` |
| Добавить принтер с PPD-файлом производителя | `sudo lpadmin -p office2 -E -v socket://192.168.1.51:9100 -P /tmp/model.ppd` |
| Принтер по умолчанию | `sudo lpadmin -d office1` |
| Описание и расположение | `sudo lpadmin -p office1 -D "Бухгалтерия" -L "каб. 12"` |
| Параметры очереди | `lpoptions -p office1 -l` |
| Напечатать файл | `lp -d office1 /tmp/test.pdf` |
| Очередь заданий, отмена | `lpq -P office1`; `cancel -a office1` |
| Удалить принтер | `sudo lpadmin -x office1` |

- В `lpadmin` параметр `-E` после имени очереди включает её и разрешает приём заданий (тот же `-E`, поставленный **до** `-d`, `-p` или `-x`, означает другое — принудительное шифрование TLS при соединении с планировщиком, поэтому порядок ключей важен); `-v` — адрес устройства (`ipp://`, `ipps://`, `socket://`, `lpd://`, `usb://`, `smb://`); `-m everywhere` опрашивает принтер по IPP и не требует драйвера [офиц., lpadmin(8)].
- Команды `lpq`, `lpr`, `lprm` входят в пакет `cups-bsd`; на сервере с минимальной установкой его может не быть — тогда пользуйтесь `lpstat -o` (очередь), `lp` (печать), `cancel` (отмена) из `cups-client`.
- Драйверы и PPD-файлы объявлены в CUPS устаревшими (`-P` и модели, отличные от `everywhere`), но в CUPS 2.4 ещё работают [офиц.]. Пакеты драйверов: `printer-driver-gutenprint`, `hplip` (HP), `printer-driver-escpr` (Epson), `printer-driver-brlaser` (Brother), `printer-driver-splix` (Samsung); USB-принтеры без драйвера — пакет `ipp-usb` [практика].
- Принтер, расшаренный с Windows: адрес `smb://user:password@server/printer`, нужен пакет `smbclient` [практика].
- Термопринтеры этикеток (ZPL, EPL, TSPL) часто подключают «сырой» очередью: `sudo lpadmin -p zebra1 -E -v socket://192.168.1.60:9100 -m raw`, печать — `lp -d zebra1 -o raw label.zpl` [практика; режим raw в CUPS помечен устаревшим].

Особенности 1С:

- Имя принтера, сохранённое в настройках печати документа (свойство `ИмяПринтера` табличного документа, пользовательские настройки печати), после перехода на Linux не совпадает с именем очереди CUPS. Настройки сбрасывают или записывают в них имя очереди [практика].
- Поля и масштаб страницы зависят от области печати, которую сообщает драйвер. После смены ОС проверьте формы «в один лист»: счета, ТОРГ-12, этикетки.
- Печать с сервера (например, из фонового задания): `ТабличныйДокумент.Напечатать()` там недоступен, поэтому сервер записывает PDF и отправляет его в очередь командой `lp` [практика]:

```bsl
ТабДок.Записать(ИмяФайлаPDF, ТипФайлаТабличногоДокумента.PDF);
КодВозврата = Неопределено;
ЗапуститьПриложение("/usr/bin/lp -d office1 " + ИмяФайлаPDF, , Истина, КодВозврата);
```

### 8.2. Подключаемое оборудование

- «1С:Библиотека подключаемого оборудования» (БПО) унифицирует работу со сканерами штрихкода, считывателями магнитных карт, ТСД, ККТ, фискальными регистраторами, дисплеями покупателя, эквайринговыми терминалами, весами, RFID-считывателями, принтерами этикеток и чеков [офиц.].
- Оборудование подключается к **клиентскому** компьютеру, поэтому драйвер (внешняя компонента Native API) должен иметь сборку под Linux той же разрядности, что и клиент. Драйвер только для Windows на Linux-клиенте не заработает, даже если сервер на Windows.
- Загрузка драйвера в базу: БПО 3.1 — «Администрирование → Подключаемое оборудование → Ещё → Драйверы оборудования → Подключить новый → Загрузить в информационную базу»; БПО 2.1 — «… → Драйверы оборудования → Добавить новый драйвер из файла» [практика, interface31].
- Эмуляторы фирмы «1С» поддерживают 64 бита и Linux: «1С:Эмулятор ККТ с передачей данных (54-ФЗ)» версии 5.0 (ККТ, эквайринг, весы, дисплей покупателя, принтер этикеток) и эмулятор сканера штрихкодов — удобны для проверки рабочего места до покупки оборудования [практика, interface31].
- Перед закупкой проверяйте в перечнях сертифицированных драйверов БПО (страница библиотеки на v8.1c.ru) наличие сборки под Linux. ⚠ не подтверждено (ни автором, ни рецензентом: страница БПО на v8.1c.ru не содержит сведений о Linux, сайт интеграции АТОЛ отдаёт содержимое только через JavaScript и не прочитан): имена пакетов и состав Linux-поставки драйверов АТОЛ (ДТО 10), «Штрих-М» и драйвера «1С:Сканер штрихкода (NativeApi)». По памяти: драйвер АТОЛ ДТО 10 выпускается для Linux в виде deb- и rpm-пакетов (библиотека `libfptr10`, тестовая утилита), а компоненты 1С для сканера и печати штрихкодов имеют сборки для Linux x86-64 — но перед закупкой оборудования это нужно проверить по документации производителя и на эмуляторе.

Сканеры штрихкодов:

| Режим | Что нужно в Linux |
|---|---|
| Эмуляция клавиатуры (USB HID) | драйвер не нужен; в БПО выбирают клавиатурный режим, префикс и суффикс задают в настройках сканера |
| Виртуальный COM-порт (USB CDC) или RS-232 | устройство `/dev/ttyACM0` либо `/dev/ttyUSB0`; пользователю нужен доступ к порту |

```bash
lsusb                                   # устройство видно на шине
sudo dmesg | tail -20                   # какое имя порта получил сканер или ККТ
ls -l /dev/ttyACM* /dev/ttyUSB* 2>/dev/null       # владелец root, группа dialout
ls -l /dev/serial/by-id/                # постоянные имена — их и указывать в настройках
sudo usermod -aG dialout "$USER"        # доступ к последовательным портам; нужен повторный вход в систему
```

- ККТ и эквайринговые терминалы обычно требуют системных библиотек производителя и правил udev для доступа к USB без root — следуйте инструкции драйвера. Общий вид правила (идентификаторы берутся из `lsusb`, строка вида `ID 1234:abcd`):

```bash
# /etc/udev/rules.d/99-1c-equipment.rules — доступ группе dialout и постоянное имя порта
sudo tee /etc/udev/rules.d/99-1c-equipment.rules >/dev/null <<'EOF'
SUBSYSTEM=="usb", ATTR{idVendor}=="1234", ATTR{idProduct}=="abcd", MODE="0660", GROUP="dialout", ENV{ID_MM_DEVICE_IGNORE}="1"
SUBSYSTEM=="tty", ATTRS{idVendor}=="1234", ATTRS{idProduct}=="abcd", MODE="0660", GROUP="dialout", SYMLINK+="kkt0", ENV{ID_MM_PORT_IGNORE}="1"
EOF
sudo udevadm control --reload-rules && sudo udevadm trigger
udevadm info -a -n /dev/ttyACM0 | grep -E 'idVendor|idProduct|serial' | head    # атрибуты устройства для правила
```

- Два типовых «перехватчика» последовательных портов на Ubuntu Desktop [практика; общеизвестные особенности дистрибутива, к 1С не относятся]:
  - **ModemManager** опрашивает каждое новое устройство `ttyACM*`/`ttyUSB*` AT-командами — сканер или ККТ в это время «занят» либо получает мусор. Лечение: признаки `ENV{ID_MM_DEVICE_IGNORE}="1"` (на USB-устройстве) и `ENV{ID_MM_PORT_IGNORE}="1"` (на порту) в правиле udev, как выше, или, если модемов нет, `sudo systemctl disable --now ModemManager`.
  - **brltty** (служба для дисплеев Брайля) в Ubuntu 22.04 и новее захватывает распространённые USB–COM-переходники (CH340, CP210x, FTDI): в `dmesg` видно `usbfs: interface 0 claimed by ch341 while 'brltty' sets config #1`, а `/dev/ttyUSB0` появляется и сразу исчезает. Лечение: `sudo apt remove brltty` либо `sudo systemctl mask brltty-udev.service && sudo systemctl stop brltty-udev.service`.
- Проверить порт без 1С: `stty -F /dev/ttyACM0 9600 raw -echo && cat /dev/ttyACM0` (считать штрихкод — код появится в терминале), занятость порта — `sudo fuser -v /dev/ttyACM0` или `sudo lsof /dev/ttyACM0`.
- Веб-клиент: драйвер должен иметь вариант для браузера; в Linux для внешних компонент в браузере нужна GTK-3 [офиц.]. В 8.5.4 существующие компоненты можно использовать в веб-клиенте через адаптеры [офиц.].
- Аппаратные ключи защиты HASP: на ARM64 и Эльбрусе не поддерживаются [офиц.]; установка драйвера ключа на x86-64 — в статье о лицензировании.

## 9. Полнотекстовый поиск, изображения, PDF, офисные документы

**Полнотекстовый поиск.** Работает на Linux так же, как на Windows; индекс хранится в каталоге данных кластера. Версия 2 поиска требует Java 1.8 или новее той же разрядности, что и кластер (рекомендуется Liberica; компонент установщика `liberica_jre`) [офиц.]. В 8.3.27 ускорено построение индекса версии 1; в 8.5.4 добавлена синхронизация данных поиска версии 2 между серверами отказоустойчивого кластера, уменьшены словари и файлы индекса [офиц.]. Извлечение текста из вложенных файлов (DOC, PDF и т. п.) подсистемой БСП «Работа с файлами» **на Linux-сервере не выполняется** — подтверждено по коду БСП 3.1 [БСП, код]: процедура `РаботаСФайламиСлужебный.ИзвлечьТекстИзФайлов()`, которую вызывает регламентное задание «Извлечение текста» (`ИзвлечьТекстИзФайловНаСервере`), начинается с проверки `Если Не ОбщегоНазначения.ЭтоWindowsСервер() Тогда Возврат` с комментарием «Извлечение текста работает только под Windows». Функция `ИзвлекатьТекстыФайловНаСервере()` возвращает значение одноимённой константы: «Истина, если текст из файлов извлекается на сервере, а не на клиенте» [БСП, код]. Следствия после переноса сервера на Linux (пункты 1–2 — по памяти рецензента об устройстве настроек БСП, ⚠ проверьте в своей конфигурации): (1) флажок «Извлекать тексты файлов на сервере» в настройках работы с файлами нужно выключить, иначе тексты не извлекаются нигде; (2) извлечение тогда выполняют клиенты — в БСП есть форма автоматического извлечения текстов, которую держат открытой на одной из Windows-машин; (3) новые файлы не попадут в поиск по содержимому, пока текст не извлечён. ⚠ не подтверждено: работает ли клиентское извлечение на Linux-клиенте (объект платформы `ИзвлечениеТекста` исторически опирался на механизмы Windows) и изменилось ли поведение в БСП новее проверенной копии — проверьте поиск по содержимому файлов на стенде.

**Изображения.** Объекты `Диаграмма`, `ДиаграммаГанта`, `Дендрограмма`, `СводнаяДиаграмма` и их метод `ПолучитьКартинку()` на сервере требуют `libfreetype` [офиц.]. Форматы WMF и EMF в Linux не поддерживаются — картинки в макетах заменяют на PNG, JPG или SVG [офиц., стандарт № 723]. Практические руководства для старых версий (8.3.21–8.3.22) ставят на сервер ImageMagick (`imagemagick`, библиотека MagickWand). По документу `1cv8upd` библиотека ImageMagick значится в разделах «Обновление используемых библиотек» (рецензент видел запись для 8.3.21: «Библиотека ImageMagick обновлена до версии 7.1.…»; по `kb/1c/02-…` такие записи есть также для 8.3.16 и 8.3.27) — то есть платформа несёт **собственный** ImageMagick 7-й ветки, и системный пакет современным сборкам, по всей видимости, не нужен: в официальном перечне библиотек Linux его нет, в руководствах для 8.3.25 и 8.3.27 его не ставят. Сверено по полному тексту документации 8.3.27 (10.10.2026): ImageMagick в ней не упоминается вовсе; в перечне библиотек Linux — FreeType, libgsf, glib, unixODBC, Kerberos и шрифты Microsoft Core Fonts (`../its-docs/cs-gl01-trebovaniya.md`, разд. 1.3.3). ⚠ Не подтверждено только то, что ни одна операция актуальных сборок не обращается к системной `libMagickWand`. Установка `imagemagick` безвредна; в Ubuntu 26.04 в репозитории только ImageMagick 7. Окончательную проверку даёт `ldd` по модулям каталога версии (раздел 2.4) и `ldconfig -p | grep -i magickwand`.

**PDF.** Сохранение табличного документа в PDF выполняется платформой и требует `libfontconfig`, `libfreetype` и шрифтов [офиц.]. Новое: 8.3.26 — получение размеров и ориентации страниц PDF; 8.5.4 — просмотр и печать PDF с картинками JBIG2, получение страницы PDF в виде картинки (например, для распознавания штрихкодов) [офиц.]. Обработка средствами ОС: `pdftotext`, `pdftoppm` (пакет `poppler-utils`), `qpdf`, `gs` — вызываются через `ЗапуститьПриложение()`.

**Офисные документы.** Чтение и запись XLS/XLSX/ODS и запись DOCX — средствами `ТабличныйДокумент` (раздел 4.2); для XLS нужны `libgsf-1` и `libglib-2.0` [офиц.]. Просмотр и печать офисных документов в окне приложения (8.5.4) — через LibreOffice на рабочих серверах [офиц.]:

```bash
sudo apt install -y --no-install-recommends libreoffice-writer libreoffice-calc libreoffice-impress
sudo -u usr1cv8 soffice --headless --version
```

## 10. Замена типичных Windows-интеграций

### 10.1. bat → bash

| Windows (cmd) | Linux (bash) |
|---|---|
| `%VAR%`, `set VAR=1` | `$VAR`, `VAR=1` (в окружение — `export VAR=1`) |
| `%DATE%`, `%TIME%` | `$(date +%F)`, `$(date +%H%M%S)` |
| `echo %ERRORLEVEL%` | `echo $?` |
| `copy`, `xcopy /E`, `robocopy /MIR` | `cp`, `cp -r`, `rsync -a --delete` |
| `move`, `del`, `rmdir /S` | `mv`, `rm`, `rm -r` |
| `forfiles /D -30 /C "cmd /c del @file"` | `find /путь -type f -mtime +30 -delete` |
| `type`, `findstr` | `cat`, `grep` |
| `net use Z: \\fs\share` | `mount -t cifs //fs/share /mnt/share …` или запись в `/etc/fstab` |
| `sc stop/start "1C:Enterprise 8.3 Server Agent"` | `sudo systemctl stop/start 'srv1cv8-<версия>@default'` |
| `taskkill /IM rphost.exe /F` | `sudo pkill -9 rphost` (крайняя мера) |
| `tasklist`, `where` | `ps aux`, `command -v` |
| `timeout /t 10`, `ping -n 4` | `sleep 10`, `ping -c 4` |
| `7z a`, `powershell Compress-Archive` | `tar czf`, `zip -r`, `7z a` (пакет `7zip`, в Ubuntu 22.04 — `p7zip-full`) |
| `sqlcmd`, `osql` | `psql` |
| `schtasks`, «Планировщик заданий» | `crontab -e`, таймеры systemd |
| `1cv8.exe DESIGNER /DumpIB …` | `ibcmd infobase dump …` либо `xvfb-run -a 1cv8 DESIGNER /DumpIB …` |

Пример сценария обмена вместо bat-файла:

```bash
#!/usr/bin/env bash
# /opt/1c-scripts/exchange.sh — забрать файлы обмена из сетевого каталога
set -euo pipefail
SRC=/mnt/exchange/out
DST=/srv/1c/exchange/in
exec 9>/run/lock/1c-exchange.lock
flock -n 9 || { echo "$(date '+%F %T') уже выполняется"; exit 0; }

mountpoint -q /mnt/exchange || { echo "$(date '+%F %T') ресурс не смонтирован" >&2; exit 1; }
find "$SRC" -maxdepth 1 -type f -iname '*.xml' -mmin +1 -print0 |
  while IFS= read -r -d '' f; do
    mv -- "$f" "$DST/" && echo "$(date '+%F %T') принят $(basename "$f")"
  done
find "$DST/../archive" -type f -mtime +30 -delete
```

```bash
sudo install -d -o usr1cv8 -g grp1cv8 /opt/1c-scripts /var/log/1c-scripts
sudo install -o usr1cv8 -g grp1cv8 -m 750 exchange.sh /opt/1c-scripts/exchange.sh
bash -n /opt/1c-scripts/exchange.sh          # проверка синтаксиса без выполнения
```

Сценарий, созданный в Windows или записанный из 1С, должен быть в UTF-8 без BOM и с переводами строк LF (раздел 4.6); первая строка — `#!/usr/bin/env bash`; у файла должно быть право на выполнение.

### 10.2. Планировщик задач → cron и systemd

Регламентные задания 1С остаются внутри 1С и переносятся вместе с базой. Меняются только внешние задачи ОС.

```bash
sudo crontab -u usr1cv8 -e          # расписание пользователя службы
```

```text
# минута час день месяц день_недели  команда
*/15 * * * *  /opt/1c-scripts/exchange.sh >> /var/log/1c-scripts/exchange.log 2>&1
30 2 * * *    /opt/1c-scripts/nightly.sh  >> /var/log/1c-scripts/nightly.log 2>&1
```

То же таймером systemd (журнал — в journald, есть контроль пропущенных запусков):

```ini
# /etc/systemd/system/1c-exchange.service
[Unit]
Description=1C file exchange

[Service]
Type=oneshot
User=usr1cv8
Group=grp1cv8
ExecStart=/opt/1c-scripts/exchange.sh
```

```ini
# /etc/systemd/system/1c-exchange.timer
[Unit]
Description=Run 1C file exchange every 15 minutes

[Timer]
OnCalendar=*:0/15
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now 1c-exchange.timer
systemctl list-timers '1c-*'
journalctl -u 1c-exchange.service --since today
```

Задача планировщика Windows вида «запустить `1cv8.exe ENTERPRISE /Execute обработка.epf`» на сервере без графики требует виртуального дисплея (`sudo apt install xvfb`):

```bash
xvfb-run -a /opt/1cv8/x86_64/8.3.27.1688/1cv8 ENTERPRISE /S "srv1c/buh" /N "Робот" /P "***" \
  /DisableStartupDialogs /DisableStartupMessages /Execute "/opt/1c-scripts/epf/Загрузка.epf" /Out /var/log/1c-scripts/epf.log
```

Надёжнее перевести такую задачу в регламентное задание или вызывать HTTP-сервис базы из cron: `curl -fsS -u robot:*** https://srv1c.example.ru/buh/hs/exchange/run`.

### 10.3. Файловые обмены через общие папки

| Было в Windows | Вариант в Linux | Когда выбирать |
|---|---|---|
| `\\fs01\exchange` на файловом сервере Windows | монтирование CIFS в `/mnt/exchange` (раздел 4.8) | файловый сервер остаётся на Windows, партнёры по обмену тоже |
| Общая папка на самом сервере 1С | каталог `/srv/1c/exchange` + Samba для Windows-клиентов | сервер 1С сам раздаёт каталог |
| Обмен между двумя Linux-серверами | NFS (`nfs4`) или `rsync -a -e ssh` по расписанию | нет Windows-участников |
| FTP-обмен с контрагентом | `FTPСоединение` (FTP, FTPS) | остаётся как есть |
| SFTP-обмен | системные `sftp`, `lftp`, `rsync` или `sshfs`, запуск из 1С либо из cron | объект `FTPСоединение` SFTP не умеет |
| «Подложить файл и ждать» | HTTP-сервис или веб-сервис 1С | при возможности изменить вторую сторону — самый надёжный вариант |

## 11. Разработка под Linux

### 11.1. Конфигуратор на Linux

- Конфигуратор — это тот же исполняемый файл `1cv8`, режим `DESIGNER`; ставится компонентом `client_full` (пакет `client`). Рекомендуемый экран разработчика — от 1920×1080, память — от 8 Гбайт [офиц.].
- Подключение: к серверной базе (`/S "srv1c/buh"`), к файловой (`/F`), к хранилищу конфигурации по TCP (`crserver`) или к файловому хранилищу на смонтированном ресурсе с общей группой и флагом set-group-ID на каталоге [офиц.].
- Пакетный режим (`/DumpCfg`, `/LoadCfg`, `/UpdateDBCfg`, `/DumpConfigToFiles`, `/LoadConfigFromFiles`, `/DumpIB`, `/RestoreIB`) работает так же, как в Windows, но процессу нужен графический сервер; на сервере без графики — `xvfb-run` или утилита `ibcmd` (`kb/1c/06-infobazy-ibcmd-paketnyj-rezhim.md`).
- Режим агента конфигуратора (SSH/SFTP): ключ хоста при `/AgentSSHHostKeyAuto` — `~/.1cv8/1C/1cv8/host_id`, рабочий каталог SFTP — `~/.1cv8/1C/1cv8/<UUID базы>/sftp` [офиц.].
- Чего в Linux-поставке нет [офиц., приложение 1]: конвертера баз 7.7 (`v7cnv.exe`), утилиты `dumper`, файла `RegMSC.cmd` и MMC-консоли кластера; регистрация 1С как OLE-Automation-сервера и COM-соединение — только Windows; разрядность клиента не выбирается.
- Аварийные дампы клиента и конфигуратора формируются по настройкам ОС, а не `logcfg.xml` [офиц.].
- **Уточнено 11.10.2026**: приложение 7 «Руководства разработчика» 8.3.27 прочитано. Раздел 7.7 «Особенности работы клиентского приложения под управлением ОС Linux» перечисляет: не поддерживается технология COM (объект `COMОбъект`, запуск клиента как Automation-сервера, внешние компоненты на COM); не поддерживается консоль администрирования кластера (вместо неё — `ras` и `rac`); не поддерживается объект `Почта`; не поддерживаются метафайлы Windows (WMF, EMF). Глава 33 добавляет: механизмы COM, OLE и ActiveDocument недоступны в Linux и macOS. Отдельного перечня недоступных функций именно конфигуратора в этих разделах нет. Ранее было не подтверждено: полный перечень функций конфигуратора, недоступных в Linux (он приведён в закрытой части документации — «Руководство разработчика», приложение об особенностях поведения в разных режимах). До проверки не закладывайте в регламент сборки операции, которые выполняли только в Windows: создание комплектов поставки, сравнение через внешние программы, работу с макетами Active Document.
- Развитие: 8.5.5 — ускорение поиска по большим конфигурациям и загрузки конфигурации из файлов; 8.5.6 — возврат открытых окон после перезапуска, сохранение комментариев в тексте запроса после конструктора [офиц., планы и блог].

### 11.2. 1C:EDT

| Параметр | Значение [офиц., edt.1c.ru] |
|---|---|
| Версии на 10.10.2026 | стабильная 2026.1.3; релиз-кандидат 2026.2.1 |
| ОС | 64-разрядные: Windows 10+, **Ubuntu 18.04 LTS и выше**, macOS 10.15+ |
| Java | с EDT 2025.1 ставится вместе с EDT; для 2024.1–2024.2 требовалась Axiom JDK 17 Full или Azul Zulu 17 JDK FX |
| Память | минимум 4 Гбайт; рекомендуется 8 (около 6 под EDT); продвинутый профиль — 16 (10 и более под EDT) |
| Диск | около 1200 Мбайт на установку; рабочие области — на SSD |
| Платформа | 8.5.1 и 8.3.8–8.3.27 (для каждой версии указана минимальная сборка, например для 8.3.27 — 2202) |

- EDT хранит исходный код конфигурации в файлах и работает с Git; умеет вести несколько конфигураций, расширений и внешних обработок в одной рабочей области, проверяет код «на лету» [офиц.].
- Для запуска, отладки и обмена с информационной базой на том же компьютере должна быть установлена платформа нужной версии (толстый клиент) [практика].
- Документация: руководство — its.1c.ru/db/edtdoc; системные требования — edt.1c.ru/docs/intro/requirements.php.

### 11.3. Отладка

- На сервере: агент запускается с ключом `-debug` (TCP/IP) или `-debug -http` (через сервер отладки `dbgs`, порт по умолчанию 1550). В systemd это переменная `SRV1CV8_DEBUG` — см. `kb/1c/02-ustanovka-servera-ubuntu.md`.
- На клиенте: `/debug -http -attach /debuggerURL "http://srv1c:1550"`; `-attach` действует только при отладке по HTTP [офиц.].
- В конфигураторе: «Сервис → Параметры → Отладка» — протокол HTTP и адрес сервера отладки; «Отладка → Подключение» — выбор предметов отладки.
- Отладка по HTTP удобна, когда между конфигуратором и сервером есть NAT или межсетевой экран: и клиент, и рабочие процессы сами подключаются к `dbgs`.
- Межсетевой экран сервера: открыть 1550/tcp для рабочих мест разработчиков (`sudo ufw allow from 192.168.1.0/24 to any port 1550 proto tcp`).

### 11.4. Лицензия для разработчиков

Бесплатная лицензия для разработчиков (community) [офиц.]: платформа 8.3.23 и новее, только программная, активируется на один клиентский и один серверный компьютер, срок — неделя с автоматическим продлением через интернет, не более трёх сеансов с прямым подключением, коммерческое использование запрещено. На Linux сервер работает от `usr1cv8` и не видит лицензию, полученную в домашнем каталоге разработчика: файл должен попасть в `/var/1C/licenses`, а пользователь — входить в группу `grp1cv8` [офиц.]. На практике встречается и грубый обход — получить лицензию, запустив платформу от root, и раздать права `chmod -R g+w,o+w /var/1C/licenses` [практика, interface31].

## 12. Чек-лист переноса сервера с Windows на Linux

### 12.1. Поиск проблемных мест в конфигурации

Выгрузите конфигурацию и расширения в файлы и пройдитесь `grep`. Модули выгружаются в файлы `*.bsl` в кодировке UTF-8.

```bash
B=/opt/1cv8/x86_64/8.3.27.1688
xvfb-run -a $B/1cv8 DESIGNER /S "srv1c/buh" /N "Администратор" /P "***" \
  /DisableStartupDialogs /DumpConfigToFiles /tmp/cfg /Out /tmp/dump.log
cd /tmp/cfg

# 1. COM: сколько мест и какие ProgID
grep -rniE --include='*.bsl' 'COMОбъект|COMObject|ПолучитьCOMОбъект|GetCOMObject' . | wc -l
grep -rhoiE --include='*.bsl' '(COMОбъект|COMObject)\("[^"]+"' . | sed -E 's/.*\("//; s/"$//' | sort | uniq -c | sort -rn

# 2. Внешние компоненты COM, объект ИнтернетСоединение, OLE-серверы
grep -rniE --include='*.bsl' 'ТипВнешнейКомпоненты\.COM|AddInType\.COM|ИнтернетСоединение|InternetConnection|V8[23]\.(Application|COMConnector)' .

# 3. Пути Windows: буква диска, строки, начинающиеся или заканчивающиеся обратной косой чертой
grep -rnE --include='*.bsl' '"[A-Za-z]:\\|"\\|\\"' . | head -100

# 4. Исполняемые файлы и сценарии Windows
grep -rniE --include='*.bsl' '\.bat"|\.cmd"|\.exe|\.vbs"|\.ps1"|cmd /c|cmd\.exe|powershell|regsvr32|rundll32|%TEMP%|%APPDATA%|%USERPROFILE%' .
grep -rniE --include='*.bsl' 'ЗапуститьПриложение|КомандаСистемы|RunApp|RunSystem' . | wc -l

# 5. Подключение внешних компонент — для каждой проверить наличие сборки под Linux
grep -rniE --include='*.bsl' 'ПодключитьВнешнююКомпоненту|AttachAddIn|УстановитьВнешнююКомпоненту|InstallAddIn' .
grep -rlE --include='*.xml' '<TemplateType>(AddIn|ActiveDocument)</TemplateType>' .

# 6. Кодировки и маски
grep -rniE --include='*.bsl' 'КодировкаТекста\.(ANSI|OEM)|TextEncoding\.(ANSI|OEM)|"\*\.\*"' .

# 7. Строки соединения OLE DB и Windows-драйверы ODBC
grep -rniE --include='*.bsl' 'Provider=|SQLOLEDB|SQLNCLI|Microsoft\.(Jet|ACE)\.OLEDB|Driver=\{SQL Server\}|Driver=\{Microsoft' .

# 8. Ветки «только для Windows» и механизмы, которых нет на Linux-сервере (каждую найденную ветку прочитать глазами)
grep -rniE --include='*.bsl' 'ЭтоWindowsСервер|ТипПлатформы\.Windows|PlatformType\.Windows' . | wc -l
grep -rniE --include='*.bsl' 'ИзвлечениеТекста|TextExtraction|winmgmts|WbemScripting|ADODB\.|Scripting\.FileSystemObject' . | head -50

# 9. Запись текстовых файлов: умолчания дают CRLF и BOM (раздел 4.6) — проверить файлы, которые потом читают утилиты Linux
grep -rniE --include='*.bsl' 'Новый ЗаписьТекста|New TextWriter|КодировкаТекста\.UTF8|TextEncoding\.UTF8' . | wc -l
```

Замечания к командам: `grep -i` правильно сопоставляет кириллицу только в локали UTF-8 (`locale` должен показывать `ru_RU.UTF-8` или `C.UTF-8`); файлы `*.bsl` в выгрузке начинаются с BOM — на поиск это не влияет; расширения конфигурации выгружаются отдельной командой (`/DumpConfigToFiles <каталог> -Extension <имя>`) и проверяются так же.

То же можно найти глобальным поиском в конфигураторе (Ctrl+Shift+F). ⚠ не подтверждено: в «1С:Автоматизированной проверке конфигураций» и в проверках EDT есть правила стандарта № 723 — если инструмент доступен, запустите его.

| Что найдено | Что делать |
|---|---|
| `Новый COMОбъект("Excel.Application")`, `"Word.Application"` | переписать на средства платформы (раздел 4.2) либо перенести выполнение на Windows-клиент (`&НаКлиенте` с проверкой ОС) |
| `"V83.COMConnector"` | веб-сервисы, HTTP-сервисы, OData; администрирование — `rac` |
| `"ADODB.Connection"` | внешний источник данных + драйвер ODBC на сервере |
| `"WScript.Shell"`, `"Scripting.FileSystemObject"`, WMI | методы платформы, bash |
| строки с `\`, `C:\`, `\\server` | `ПолучитьРазделительПути()`; пути вынести в настройки |
| `.bat`, `.exe` | сценарии bash, утилиты Linux |
| `ТипВнешнейКомпоненты.COM`, макеты Active Document | компонента Native API со сборкой под Linux или отказ от функции |
| `ИнтернетСоединение` | `HTTPСоединение`, `FTPСоединение` |
| `КодировкаТекста.ANSI/OEM` | явное имя кодировки |
| `"*.*"` | `ПолучитьМаскуВсеФайлы()` |

Не всё найденное — ошибка: код в процедурах `&НаКлиенте` продолжит работать на Windows-клиентах при Linux-сервере. Ломается то, что выполняется на сервере: модули с директивой `&НаСервере`, общие модули с флажком «Сервер», модули объектов и менеджеров, регламентные и фоновые задания, веб- и HTTP-сервисы.

### 12.2. Окружение сервера

1. Версия платформы на новом сервере совпадает с версией клиентов; ОС — из списка поддерживаемых (Ubuntu 24.04).
2. СУБД: если база была в MS SQL — перенос в PostgreSQL через выгрузку `.dt` (см. статьи о PostgreSQL); сервер 1С на Linux с MS SQL не работает.
3. Лицензии: программные лицензии привязаны к оборудованию — потребуется повторная активация; каталог `/var/1C/licenses`.
4. Шрифты: Microsoft Core Fonts плюс все дополнительные шрифты, использованные в макетах (Tahoma, штрихкоды); `sudo -u usr1cv8 fc-match "Arial"`.
5. Локаль `ru_RU.UTF-8`, часовой пояс, синхронизация времени.
6. Библиотеки: `ldconfig -p | grep -E 'libfontconfig|libfreetype|libgsf-1|libglib-2.0|libodbc|libkrb5|libgssapi_krb5'`.
7. Каталог временных файлов (`TMPDIR`), права и объём; каталоги обмена с владельцем `usr1cv8:grp1cv8`.
8. Сетевые ресурсы смонтированы, пути в настройках базы переписаны (каталоги обмена, тома хранения файлов, каталоги выгрузок в банк, каталоги внешних обработок).
9. Внешние источники данных: unixODBC и драйверы, строки соединения, проверка `isql` от `usr1cv8`.
10. Криптография: криптопровайдер и его лицензия, контейнеры и сертификаты в хранилищах пользователя службы, путь к модулю в настройках 1С.
11. HTTPS: корневые сертификаты своих УЦ в `/usr/local/share/ca-certificates`; доступ в интернет и прокси от имени `usr1cv8`.
12. Аутентификация ОС: NTLM недоступен, нужен Kerberos (keytab) либо переход на пароли или OpenID.
13. Внешние компоненты: для каждой — сборка `.so`, проверка `ldd`.
14. Внешние задачи ОС: bat-файлы и задания планировщика переписаны на bash и cron или systemd.
15. Веб-сервер: публикации пересозданы утилитой `webinst` (см. `kb/1c/05-…`), сертификаты перенесены.
16. LibreOffice и Java (Liberica) — если используются просмотр офисных документов, полнотекстовый поиск версии 2, утилита `ring`.
17. Резервное копирование: сценарии `pg_dump` или `pg_basebackup` вместо заданий обслуживания MS SQL.

### 12.3. Что проверить после переноса

- Печатные формы: экранный вид, PDF из фонового задания, рассылка отчётов по почте — сравнить постранично с эталоном из Windows.
- Загрузка и выгрузка Excel, обмены (файловые, веб-сервисы, РИБ), загрузка курсов валют и классификаторов из интернета.
- Электронная подпись: тест сертификата с проверкой «на сервере», отправка и получение документа ЭДО, отчётность.
- Печать штрихкодов и этикеток, работа сканера и ККТ на Linux- и Windows-клиентах.
- Внешние источники данных, полнотекстовый поиск (перестроить индекс), работа с файлами (тома на диске).
- Регламентные задания: журнал регистрации за сутки без ошибок вида «COM», «не найден файл», «Удаленный узел не прошел проверку».
- Производительность типовых операций под нагрузкой.

| «Внешняя компонента не подключена» на сервере | в архиве компоненты нет сборки Linux x86-64 либо не хватает зависимостей `.so` | запросить сборку у поставщика; `ldd` на файл компоненты |
| Файл обмена «не найден», хотя он есть | регистр имени или расширения (`DATA.XML` против `data.xml`), маска `*.*` | поиск по `ПолучитьМаскуВсеФайлы()` и сравнение через `НРег()` |
| «Ошибка доступа к файлу», «Permission denied» на сервере | каталог не принадлежит `usr1cv8` или нет права на один из каталогов пути | `namei -l <путь>`, `chown`/`chmod 2770`, группа `grp1cv8` (4.7) |
| Путь вида `\\fs01\share\…` не работает | UNC в Linux не поддерживается | смонтировать ресурс и указать `/mnt/…` (4.8) |
| Файлы на смонтированном ресурсе создаются от root, 1С не может писать | в опциях `cifs` не заданы `uid`, `gid`, `file_mode`, `dir_mode` | исправить строку `fstab`, перемонтировать |
| Файловая база на сетевом ресурсе повреждается или «уже используется» | ресурс смонтирован с `nobrl` либо в Samba `locking = no` | убрать эти опции [офиц.] |
| Сценарий, записанный из 1С: `/bin/bash^M: bad interpreter` | переводы строк CRLF | записывать с `Символы.ПС`; `sed -i 's/\r$//' файл` |
| Сценарий или CSV начинается с «мусора» `ï»¿` | BOM от `КодировкаТекста.UTF8` | писать без BOM (`ПолучитьДвоичныеДанныеИзСтроки(…, "UTF-8", Ложь)`) |
| Кириллица в именах файлов превращается в `????` | у процесса сервера локаль `C`/`POSIX` | `LANG=ru_RU.UTF-8` в окружении службы, `locale-gen ru_RU.UTF-8` |

| Диск или память сервера заполняются временными файлами | `/tmp` мал либо находится в ОЗУ (Ubuntu 26.04) | отдельный каталог и `TMPDIR` для службы |

| `SSL Provider: … certificate verify failed` при подключении к MS SQL | `msodbcsql18` проверяет сертификат сервера | `TrustServerCertificate=yes` или `Encrypt=no`, либо доверенный сертификат |
| Внешний источник работает у администратора в `isql`, но не из 1С | DSN описан в `~/.odbc.ini` администратора | перенести в `/etc/odbc.ini`, проверять `sudo -u usr1cv8 isql …` |

| Вывод команды, запущенной из 1С, на английском или «кракозябрами» | у службы нет локали; БСП читает потоки в UTF-8 | `Environment=LANG=ru_RU.UTF-8` в юните; в БСП — `КодировкаИсполнения = "ru_RU.UTF-8"` (4.5) |
| `ldd` драйвера Oracle: `libaio.so.1 => not found` на Ubuntu 24.04+ | в пакете `libaio1t64` библиотека называется `libaio.so.1t64` | символическая ссылка `libaio.so.1` (5.6) ⚠ |
| Печать идёт не на тот принтер или «принтер не найден» | в настройках сохранено Windows-имя принтера | сбросить настройки печати, указать очередь CUPS |
| Аутентификация ОС перестала работать | на Linux нет NTLM | настроить Kerberos либо перейти на пароли или OpenID |
| Буфер обмена, перетаскивание, положение окон клиента ведут себя странно | сеанс Wayland, клиент работает через XWayland ⚠ | сеанс «Ubuntu on Xorg» (22.04, 24.04) |

## Что не удалось подтвердить

Состояние после рецензии 2026-10-10. Веб-поиск был недоступен и автору, и рецензенту, поэтому всё, что требует поиска по форумам и статьям сообщества, осталось открытым.

Закрыто рецензией (пометка «⚠» снята или сужена):

- Версия перехода на системный WebKit2 — 8.3.24 (`1cv8upd`), а не 8.3.26.
- Значения `ТипПлатформы` для ARM64 и Эльбруса — `Linux_ARM64`, `Linux_E2K` (код БСП; в `1cv8upd` — опечатка `Linux_ARM_64`).
- Версия появления изолированного подключения внешних компонент — 8.3.21 (`1cv8upd`).
- Строка команды в `ЗапуститьПриложение()` на Linux исполняется оболочкой — косвенно, по коду БСП.
- Умолчания `ЗаписьТекста` (`ПС` → `ВК + ПС`) — косвенно, по OneScript.
- ViPNet CSP: имена и типы провайдеров (77, 78), в БСП помечены «нет в Linux»; перечень ОС на сайте производителя.
- Извлечение текста из файлов на сервере (БСП) — только Windows (код БСП).
- `csptestf -absorb -certs -autoprov`, `certmgr -inst -f … -ask-container`, `cpconfig -defprov`, пример `-provtype 80` — вики ALT Linux и справочник 1С-ЭДО.
- Имя пакета GTK 3 в Ubuntu 26.04 (`libgtk-3-0t64`), версии пакетов WebKitGTK, enchant, шрифтов.
- Oracle: существование `odbc_update_ini.sh` и имя библиотеки `libsqora.so.nn.n` (docs.oracle.com).

Остаётся неподтверждённым:

- Работа клиента в сеансе Wayland (через XWayland) и перечень известных неудобств; поведение на Ubuntu 26.04.
- Каким системным параметром клиент на Linux определяет масштаб интерфейса; поддержка `GDK_SCALE`, `GDK_DPI_SCALE`; точное название пункта меню изменения масштаба.
- С какой сборки клиент слинкован с WebKitGTK ABI 4.1 и принимает ли он 4.0 в версиях 8.3.26/8.3.27 (проверяется `ldd` на конкретной сборке).
- Нужно ли указывать `v8_install_deps` в пакетном режиме; идентификаторы компонентов установщика `setup-thin`.
- Значение `ТипПлатформы` для macOS на ARM; имена значений перечисления `ТипПодключенияВнешнейКомпоненты`.
- Соответствие `КодировкаТекста.ANSI/OEM` на Linux; пишет ли `ЗаписьТекста` BOM при кодировке, заданной строкой `"UTF-8"` (по памяти — да).
