# ИТС-конспект: Руководство администратора — Приложение 1. Структура каталога установки и назначение каталогов и файлов
> Источник: документация «1С:Предприятие 8.3.27», its.1c.ru/db/v8327doc. Это конспект своими словами, не дословный текст. Составлен 2026-10-10.

Глава документации: `adm-pr01` (v8327doc/113). Приложение состоит из трёх разделов:

- 1.1 — как устроено дерево каталогов после установки (Linux, macOS, Windows);
- 1.2 — какие исполняемые файлы входят в поставку, зачем они нужны и где лежат;
- 1.3 — где платформа ищет конфигурационные файлы (`logcfg.xml`, `nethasp.ini` и т. д.) и в каком порядке.

Термины, которые вводит приложение и на которые дальше опирается вся документация:

| Термин | Что означает |
|---|---|
| Корневой каталог установки | Каталог, в который ставится система. В Linux и macOS — `/opt/1cv8`. В Windows зависит от режима установки (см. 1.1.4). |
| Каталог версии | Каталог с именем вида `A.B.C.D` — файлы одной конкретной версии платформы. |
| Каталог исполняемых файлов | В Linux и macOS — сам каталог версии. В Windows — подкаталог `bin` каталога версии. |

---

## 1.1. Структура каталогов установки

### 1.1.1. Общая информация

После установки на диске появляется фиксированная структура каталогов с исполняемыми файлами системы. Её вид зависит от операционной системы.

### 1.1.2. Для ОС Linux

Корневой каталог установки: `/opt/1cv8`.

**Содержимое корневого каталога установки**

| Каталог | Назначение |
|---|---|
| `common` | Общие файлы «1С:Предприятия»: программа установки драйвера ключа защиты и конфигурационный файл `1cescmn.cfg`. (По разделу 1.2.2 здесь же лежит программа запуска `1cestart` — если она установлена.) |
| `conf` | Конфигурационные файлы, необходимые для работы «1С:Предприятия» (общие для всех версий). |
| `arm64` | Каталог установки для процессоров архитектуры ARM64. Внутри — каталоги версий. |
| `e2kv4` | Каталог установки для процессоров архитектуры E2K. Внутри — каталоги версий. |
| `i386` | Каталог установки для процессоров архитектуры x86. Внутри — каталоги версий. |
| `x86_64` | Каталог установки для процессоров архитектуры x86-64. Внутри — каталоги версий. |

**Полный путь к каталогу версии**

| Архитектура | Путь |
|---|---|
| ARM64 | `/opt/1cv8/arm64/A.B.C.D` |
| E2K | `/opt/1cv8/e2kv4/A.B.C.D` |
| x86 | `/opt/1cv8/i386/A.B.C.D` |
| x86-64 | `/opt/1cv8/x86_64/A.B.C.D` |

**Несколько версий одновременно.** Программа установки допускает параллельную установку нескольких версий платформы. Тогда в каталоге архитектуры лежит несколько каталогов версий. Пример из документации (номера условные): при установке 8.3.18.100 и 8.3.18.150 появятся каталоги `8.3.18.100` и `8.3.18.150`.

```text
/opt/1cv8/
├── common/                  # общие файлы: установщик драйвера ключа защиты, 1cescmn.cfg, 1cestart
├── conf/                    # общие конфигурационные файлы
└── x86_64/                  # (или arm64, e2kv4, i386)
    ├── 8.3.18.100/          # каталог версии = каталог исполняемых файлов
    └── 8.3.18.150/
```

**Что лежит в каталоге версии.** В нём находятся все файлы данной версии, кроме `1cestart`: исполняемые файлы, сопроводительные файлы, лицензии на используемые программные продукты и т. д. В Linux каталог версии одновременно является каталогом исполняемых файлов (отдельного подкаталога `bin` нет).

Подкаталоги каталога версии:

| Подкаталог | Назначение |
|---|---|
| `conf` | Конфигурационные файлы конкретной версии либо файл `conf.cfg` (формат `conf.cfg` описан в другом месте документации — в источнике только ссылка). |
| `distr` | Каталог размещения дистрибутивов клиентских приложений (подробности — по ссылке в документации). |
| `jre` | Каталог размещения Java Runtime Environment (JRE). |
| `docs` | Сопроводительные файлы на русском и английском языках. Состав меняется от версии к версии. |
| `licenses` | Лицензионное соглашение на «1С:Предприятие»: на русском — `1CEnterpise_ru.htm`, на английском — `1CEnterpise_en.htm` (имена файлов приведены так, как в источнике), а также лицензионные соглашения на сторонние программные компоненты (список меняется от версии к версии). |
| `readme` | Файлы readme на языках локализации платформы. |
| `ExtDst` | Дополнительные утилиты, предназначенные для использования совместно с «1С:Предприятием». |

**Версии до 8.3.18.** Платформу предыдущих версий (до 8.3.18) можно вручную разместить в описанной структуре каталогов — для этого нужно корректно указать каталоги конкретных версий. После такого размещения программы запуска начинают учитывать эти версии при автоматическом подборе запускаемого клиентского приложения.

### 1.1.3. Для ОС macOS

Корневой каталог установки: `/opt/1cv8`.

Содержимое корневого каталога:

| Каталог | Назначение |
|---|---|
| `common` | Общие файлы: программа установки драйвера ключа защиты и конфигурационный файл `1cescmn.cfg`. |
| `conf` | Конфигурационные файлы, необходимые для работы «1С:Предприятия». |
| `A.B.C.D` | Каталог версии. Лежит прямо в корневом каталоге установки (подкаталогов по архитектуре, как в Linux, нет). |

Параллельная установка нескольких версий поддерживается так же: каталоги версий лежат рядом в корневом каталоге (пример из документации, номера условные: `8.3.24.100` и `8.3.24.150`). Каталог версии содержит все файлы версии, кроме `1cestart`, и является каталогом исполняемых файлов.

Подкаталоги каталога версии в macOS: `conf` (конфигурационные файлы версии или `conf.cfg`), `distr` (дистрибутивы клиентских приложений), `docs`, `licenses` (`1CEnterpise_ru.htm`, `1CEnterpise_en.htm` и лицензии сторонних компонентов), `readme`. Каталоги `jre` и `ExtDst` в перечне для macOS не упомянуты.

### 1.1.4. Для ОС Windows

*Только Windows — кратко.*

Корневой каталог установки по умолчанию зависит от режима установки и разрядности:

| Режим установки | Разрядность | Корневой каталог установки |
|---|---|---|
| «Для компьютера» | 32-разрядная система в 64-разрядной ОС | `%PROGRAMFILES(x86)%\1cv8` |
| «Для компьютера» | остальные случаи | `%PROGRAMFILES%\1cv8` |
| «Для пользователя» | 32-разрядная система в 32-разрядной ОС | `%LOCALAPPDATA%\Programs\1cv8` |
| «Для пользователя» | 32-разрядная система в 64-разрядной ОС | `%LOCALAPPDATA%\Programs\1cv8_x86` |
| «Для пользователя» | 64-разрядная система в 64-разрядной ОС | `%LOCALAPPDATA%\Programs\1cv8_x64` |

Содержимое корневого каталога:

| Каталог | Назначение |
|---|---|
| `common` | Общие файлы: программа запуска `1cestart`, программа установки драйвера ключа защиты, оснастка консоли управления для администрирования кластера серверов (`1CV8 Servers.msc`), библиотека пиктограмм файлов «1С:Предприятия» для ОС. |
| `conf` | Конфигурационные файлы, необходимые для работы системы. |
| `srvinfo` | Рабочий каталог центрального сервера. Содержит данные кластера серверов, если сервер «1С:Предприятия» установлен как сервис ОС Windows. |
| `A.B.C.D` | Каталог версии (может быть несколько, пример: `8.3.24.100` и `8.3.24.150`). Содержит все файлы версии, кроме `1cestart`. |

Структура каталога версии в Windows:

| Подкаталог | Назначение |
|---|---|
| `bin` | Исполняемые файлы версии (каталог исполняемых файлов). |
| `bin\conf` | Конфигурационные файлы конкретной версии либо файл `conf.cfg`, в котором записан путь к общему каталогу конфигурационных файлов (по умолчанию — каталог `conf` корневого каталога установки). |
| `bin\distr` | Дистрибутивы клиентских приложений. |
| `bin\jre` | Java Runtime Environment (JRE). |
| `bin\dmf` | Файлы, необходимые для работы оптимизированного механизма обновления конфигурации базы данных. |
| `docs` | Сопроводительные файлы на русском и английском языках. |
| `licenses` | Лицензионные соглашения (`1CEnterpise_ru.htm`, `1CEnterpise_en.htm`, лицензии сторонних компонентов). |
| `readme` | Файлы readme на языках локализации платформы. |

Каталоги с фиксированным расположением (не зависят от каталога, выбранного при установке):

- `common` и `conf` всегда находятся в каталогах из таблицы корневых каталогов выше (по режиму установки и разрядности).
- `srvinfo` создаётся программой установки только если при установке выбран запуск кластера серверов в виде сервиса ОС Windows; такой вариант возможен только при установке «для компьютера». Расположение: при совпадении разрядности платформы и ОС — `%PROGRAMFILES%\1cv8`; при 32-разрядной платформе на 64-разрядной ОС — `%PROGRAMFILES(x86)%\1cv8`.

### 1.2.2. 1cestart

Программа запуска системы «1С:Предприятие». Через неё запускаются все виды клиентов (толстый, тонкий, веб-клиент) и конфигуратор. В Linux и Windows лежит не в каталоге версии, а в каталоге общих файлов `common`.

Совет из документации: если программа запуска лежит в сетевом каталоге, рекомендуется брать её из самой новой версии из тех, что планируется устанавливать из этого сетевого каталога.

Расположение:

- **Linux:**
  - разрядность ОС и устанавливаемого приложения совпадает — `/opt/1cv8/common`;
  - разрядность не совпадает — файл не устанавливается.
- **macOS:** в каталоге исполняемых файлов конкретной версии.
- **Windows** (только Windows): в подкаталоге `common` корневого каталога установки, то есть
  - «для компьютера»: `%PROGRAMFILES(x86)%\1cv8\common` (32-разрядная система в 64-разрядной ОС) либо `%PROGRAMFILES%\1cv8\common` (остальные случаи);
  - «для пользователя»: `%LOCALAPPDATA%\Programs\1cv8\common` (32 в 32), `%LOCALAPPDATA%\Programs\1cv8_x86\common` (32 в 64), `%LOCALAPPDATA%\Programs\1cv8_x64\common` (64 в 64).

⚠ В источнике есть нестыковка: в разделе 1.1.3 сказано, что в macOS каталог версии содержит все файлы, кроме `1cestart`, а в 1.2.2 — что в macOS `1cestart` лежит именно в каталоге исполняемых файлов версии. Какое из утверждений верно — в источнике неясно.

### 1.2.3. 1cv8s

Интерактивная программа запуска «1С:Предприятия» конкретной версии. Запускает все виды клиентов (толстый, тонкий, веб-клиент) и конфигуратор.

Расположение:

- **Linux:** в каталоге исполняемых файлов конкретной версии.
- **macOS:** в каталоге исполняемых файлов конкретной версии.
- **Windows** (только Windows): подкаталог `A.B.C.D\bin` корневого каталога установки:
  - «для компьютера»: `%PROGRAMFILES(x86)%\1cv8\A.B.C.D\bin` (32 в 64) либо `%PROGRAMFILES%\1cv8\A.B.C.D\bin` (остальные случаи);
  - «для пользователя»: `%LOCALAPPDATA%\Programs\1cv8\A.B.C.D\bin` (32 в 32), `%LOCALAPPDATA%\Programs\1cv8_x86\A.B.C.D\bin` (32 в 64), `%LOCALAPPDATA%\Programs\1cv8_x64\A.B.C.D\bin` (64 в 64).

### 1.2.4. 1cv8

Исполняемый файл толстого клиента или конфигуратора. Тонкий клиент и веб-клиент запустить не может.

Расположение: Linux и macOS — в каталоге исполняемых файлов конкретной версии; Windows — те же пять вариантов `...\A.B.C.D\bin`, что и для `1cv8s` (см. 1.2.3).

### 1.2.5. 1cv8c

Исполняемый файл тонкого клиента.

Расположение: Linux и macOS — в каталоге исполняемых файлов конкретной версии; Windows — те же пять вариантов `...\A.B.C.D\bin`, что и для `1cv8s` (см. 1.2.3).

⚠ В источнике в заголовке раздела последняя буква имени набрана кириллицей («1cv8с»); здесь имя записано латиницей — `1cv8c`.

### 1.2.6. 1cv8a

Утилита административной консоли (её описание — в другом разделе документации, в источнике только ссылка).

Расположение: Windows, Linux, macOS — в каталоге исполняемых файлов конкретной версии.

### 1.2.7. ragent, rmngr, rphost

Исполняемые файлы сервера «1С:Предприятия». Устройство сервера описано в отдельной книге документации (название книги в источнике не приведено — только ссылка).

Расположение:

- **Linux:** в каталоге исполняемых файлов конкретной версии.
- **Windows:** в каталоге исполняемых файлов конкретной версии.
- **macOS:** отсутствуют.

### 1.2.8. crserver

Сервер хранилища конфигурации. Работа с хранилищем конфигурации описана в отдельной книге документации (в источнике — только ссылка).

Расположение: Linux и Windows — в каталоге исполняемых файлов конкретной версии; macOS — отсутствует.

### 1.2.9. dbgs

Сервер отладки системы «1С:Предприятие». Отладка прикладных решений описана в отдельной книге документации (в источнике — только ссылка).

Расположение: Windows, Linux, macOS — в каталоге исполняемых файлов конкретной версии.

### 1.2.10. dbda

Дата акселератор. Ограничение: работает только в составе 64-разрядного кластера серверов «1С:Предприятия». Назначение — ускорение выполнения сложных аналитических отчётов. Подробное описание — в отдельной книге документации (в источнике — только ссылка).

Расположение: Linux и Windows — в каталоге исполняемых файлов конкретной версии; macOS — отсутствует.

### 1.2.11. webinst

Утилита настройки публикации веб-клиента на веб-сервере (подробности — по ссылке в документации).

Расположение: Linux и Windows — в каталоге исполняемых файлов конкретной версии; macOS — отсутствует.

### 1.2.12. chdbfl

## 1.3. Конфигурационные файлы: расположение и поиск

### 1.3.1. Общая информация

Конфигурационные файлы платформы (`logcfg.xml`, `nethasp.ini` и т. д.) могут лежать в нескольких местах файловой системы; для них задан порядок поиска по каталогам. Это даёт четыре сценария настройки:

| Что нужно получить | Где держать конфигурационные файлы |
|---|---|
| Единые файлы для всех версий и компонентов на компьютере | Только в каталоге `conf` корневого каталога установки. |
| Отдельные файлы для каждой установленной версии | Только в каталоге конфигурационных файлов конкретной версии (в документации назван `bin\conf`; в Linux и macOS это подкаталог `conf` каталога версии — см. 1.3.2, 1.3.3). |
| Разные файлы для разных компонентов любой версии (например, для клиентского приложения и для сервера «1С:Предприятия», работающего под другим пользователем ОС) | В каталогах конфигурационных файлов, доступных всем пользователям компьютера. Перечень таких каталогов зависит от ОС и варианта установки платформы. |
| Смешанная схема | Комбинация перечисленных способов для разных конфигурационных файлов. |

### 1.3.2. Для ОС Linux

Места, где могут находиться конфигурационные файлы, в порядке поиска:

| № | Каталог | Пояснение |
|---|---|---|
| 1 | `/opt/1cv8/arch/A.B.C.D/conf` | Каталог `conf` конкретной версии. `arch` — каталог архитектуры (`arm64`, `e2kv4`, `i386`, `x86_64`). |
| 2 | `/opt/1cv8/conf` | Каталог `conf` корневого каталога установки. |
| 3 | `~/.1cv8/1C/1cv8/conf` | `~` — домашний каталог пользователя, от имени которого работает клиентское приложение «1С:Предприятия». |
| 4 | Каталог из параметра `ConfLocation` | Значение параметра `ConfLocation` конфигурационного файла конкретной версии (файл `conf.cfg`; его формат описан в другом разделе документации — в источнике только ссылка). |

Тот же порядок с подставленной архитектурой x86-64 (иллюстрация; номер версии условный, взят из примера раздела 1.1.2):

```text
1) /opt/1cv8/x86_64/8.3.18.100/conf
2) /opt/1cv8/conf
3) ~/.1cv8/1C/1cv8/conf
4) <каталог из параметра ConfLocation файла conf.cfg версии>
```

### 1.3.3. Для ОС macOS

Места в порядке поиска:

1. `/opt/1cv8/A.B.C.D/conf` — каталог `conf` конкретной версии.
2. `/opt/1cv8/conf` — каталог `conf` корневого каталога установки.
3. `~/.1cv8/1C/1cv8/conf` — в домашнем каталоге пользователя, от имени которого работает клиентское приложение.
4. Каталог из параметра `ConfLocation` файла `conf.cfg`, лежащего в каталоге `conf` конкретной версии.

### 1.3.4. Для ОС Windows

*Только Windows — кратко.* Места в порядке поиска:

1. Каталог `bin\conf` конкретной версии:
   - «для компьютера»: `%PROGRAMFILES(x86)%\1cv8\A.B.C.D\bin\conf` (32 в 64) либо `%PROGRAMFILES%\1cv8\A.B.C.D\bin\conf` (остальные случаи);
   - «для пользователя»: `%LOCALAPPDATA%\Programs\1cv8\A.B.C.D\bin\conf` (32 в 32), `%LOCALAPPDATA%\Programs\1cv8_x86\A.B.C.D\bin\conf` (32 в 64), `%LOCALAPPDATA%\Programs\1cv8_x64\A.B.C.D\bin\conf` (64 в 64).
2. `%LOCALAPPDATA%\1C\1cv8\conf` пользователя, от имени которого работает система.
3. Каталог из параметра `ConfLocation` файла `conf.cfg`, лежащего в `bin\conf` конкретной версии.
4. `%ALLUSERSPROFILE%\1C\1cv8\conf`.

Примечание документации (приведено в разделе про Windows): при установке системы конфигурационные файлы записываются в каталог `conf` корневого каталога установки, а путь к нему заносится в файл `bin\conf\conf.cfg` устанавливаемой версии.

## Что важно администратору Linux

1. **Корень установки — `/opt/1cv8`**, а файлы конкретной версии лежат в `/opt/1cv8/<архитектура>/A.B.C.D` (для архитектуры x86-64 — `/opt/1cv8/x86_64/A.B.C.D`). Подкаталога `bin`, как в Windows, нет: каталог версии и есть каталог исполняемых файлов.
2. **Полный путь к `ragent`, `rmngr`, `rphost` содержит номер версии** — они лежат в каталоге версии. То же относится к `crserver`, `dbgs`, `dbda`, `webinst`, `ci`, `chdbfl`, `cnvdbfl`, `1cv8a`, `1cv8`, `1cv8c`, `1cv8s`.
3. **Несколько версий платформы ставятся параллельно**: в каталоге архитектуры появляется по каталогу на версию. Каждый каталог версии содержит все файлы своей версии, кроме `1cestart`.
4. **Общее для всех версий — только `/opt/1cv8/common` и `/opt/1cv8/conf`.** В `common` лежат программа установки драйвера ключа защиты, `1cescmn.cfg` и (при совпадении разрядности ОС и приложения) `1cestart`.
5. **Порядок поиска конфигурационных файлов в Linux** (`logcfg.xml`, `nethasp.ini` и др.): `conf` каталога версии → `/opt/1cv8/conf` → `~/.1cv8/1C/1cv8/conf` → каталог из параметра `ConfLocation` файла `conf.cfg` версии. Если непонятно, откуда подхватился файл, каталоги стоит проверять именно в этом порядке (в источнике указан только сам порядок поиска, без дополнительных правил).
6. **Единая настройка для всех версий** — файл кладётся только в `/opt/1cv8/conf`. **Настройка для одной версии** — только в `conf` каталога этой версии. Для разных настроек у разных компонентов (клиент и сервер, работающий под другим пользователем ОС) используются каталоги, доступные всем пользователям компьютера.
7. **В каталоге `conf` версии может лежать не сами конфигурационные файлы, а `conf.cfg`** с параметром `ConfLocation`, указывающим на другой каталог. Формат `conf.cfg` в этом приложении не раскрыт — его надо смотреть в соответствующем разделе документации.
8. **Третий пункт поиска привязан к домашнему каталогу пользователя** (`~/.1cv8/1C/1cv8/conf`); в документации он описан для пользователя, от имени которого работает клиентское приложение.
9. **Каталога `srvinfo` в описании структуры для Linux нет** — он упомянут только для Windows (при установке сервера как сервиса). Где в Linux находятся данные кластера, это приложение не сообщает.
10. **Утилиты `dumper` в Linux нет**: она поставляется только для Windows и используется при атрибуте `externaldump="true"` в `logcfg.xml`. Также в Linux отсутствуют `v7cnv.exe`, `RegMSC.cmd`, `1ceunt.dll`.
11. **`dbda` (дата акселератор) работает только в составе 64-разрядного кластера серверов.**
12. **`1cestart` в Linux устанавливается только при совпадении разрядности ОС и приложения**; при несовпадении его не будет. Программа запуска конкретной версии `1cv8s`, а также `1cv8` и `1cv8c` лежат в каталоге версии.
13. **Подкаталоги каталога версии в Linux:** `conf`, `distr` (дистрибутивы клиентских приложений), `jre` (Java Runtime Environment), `docs`, `licenses`, `readme`, `ExtDst` (дополнительные утилиты). Каталог `bin\dmf` (оптимизированный механизм обновления конфигурации базы данных) в перечне указан только для Windows.
14. **Версии до 8.3.18 можно вручную разложить по этой структуре каталогов**, корректно указав каталоги версий, — тогда программы запуска будут учитывать их при автоматическом подборе клиентского приложения.
15. **Архитектуры Linux, для которых предусмотрены каталоги установки:** `arm64` (ARM64), `e2kv4` (E2K), `i386` (x86), `x86_64` (x86-64).
