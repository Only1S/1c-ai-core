## 24.1. Общая информация

- Разделение включается, когда у **общего реквизита** свойство «Разделение данных» установлено в `Разделять`. Такой реквизит называется **разделителем**; данные, доступные при выбранных значениях разделителей, вместе с неразделёнными данными образуют **область данных**.
- При чтении платформа автоматически отбирает записи с текущими значениями используемых разделителей. При записи проверяет, что в данных стоят текущие значения либо значения по умолчанию (тогда подставляются текущие); иначе исключение.
- В состав разделителя могут входить: константы, справочники, документы, последовательности, журналы документов, планы видов характеристик, счетов и расчёта, бизнес-процессы, задачи, регистры всех видов, планы обмена, регламентные задания, пользователи информационной базы.
- Тип разделителя не может быть составным.
- Не поддерживается на Microsoft SQL Server 2000 и IBM Db2 9.1. При разделителе строкового типа на MS SQL Server нельзя менять язык региональных настроек базы.

## 24.2. Свойства общего реквизита

### 24.2.1. Использование разделяемых данных

| Значение | Поведение |
|---|---|
| `Независимо` | Без включённого разделителя обращение к разделённым объектам запрещено (кроме планов обмена). Разделитель не виден в объектной модели, запросах, XML и ограничениях доступа. Ссылки объектов в разных областях **могут совпадать**. Расширения могут расширять данные. |
| `Независимо и совместно` | Работать можно и с включённым, и с выключенным разделителем; он доступен в запросах и ограничениях доступа. Ссылки в разных областях **не совпадают**. Нельзя создавать предопределённые элементы; расширение данных не поддерживается. |

### 24.2.2. Значение и признак использования

- Свойство «Значение разделения данных» указывает параметр сеанса с текущим значением (тип должен совпадать с типом разделителя); отдельный параметр сеанса хранит признак использования.
- Менять их в сеансе можно при наличии прав на эти параметры сеанса; при этом очищаются кеш объектов и повторно используемые значения. Целостность данных приложения после смены платформа не гарантирует.
- Значение можно задать в командной строке параметром `/Z`, в строке соединения — параметром `Zn`.

### 24.2.3. Разделение пользователей

Если включено, пользователь доступен в сеансе только при совпадении значения разделителя (когда разделитель в сеансе используется). Значения разделителей из свойств пользователя применяются при начале его сеанса; значения из командной строки приоритетнее, если у пользователя есть право менять соответствующие параметры сеанса.

### 24.2.4. Разделение аутентификации

При значении `Разделять` в разных областях можно создавать пользователей с одинаковыми именами; иначе имена уникальны во всей базе.

### 24.2.5. Разделение расширений конфигурации

При значении `Разделять` пользователю доступны только расширения, подключённые с тем же значением разделителя. Для разделителя в режиме `Независимо и совместно` разделение расширений рекомендуется отключать.

### 24.2.6. Условное разделение

- Позволяет одной и той же конфигурации работать и с разделением, и без него.
- Состояние хранит константа типа «Булево» либо булев реквизит ссылочного объекта, служащего типом **другого** разделителя. Объект не должен входить в состав настраиваемого разделителя.
- Задаётся для всего разделителя (свойство «Условное разделение») или для отдельных объектов в его составе (колонка «Условное разделение»).
- Если разделение условно выключено, при чтении и записи данных используется значение по умолчанию для типа разделителя; для списка пользователей разделитель считается неиспользуемым.
- После добавления условного разделения по константе её значение равно «Ложь», то есть разделение **выключено**.
- В конфигураторе условное разделение не действует: там оно считается включённым.
- В распределённой базе при автоматической регистрации изменений условное разделение в разделённом сеансе можно только включить, но не выключить. Право менять управляющий объект следует давать только администратору: выключение «прячет» данные у пользователей периферийных баз.

## 24.3. Несколько разделителей

Возможность действия определяется для каждого разделителя отдельно, результаты объединяются по «И».

## 24.4. Установка разделителей при запуске

### 24.4.1. Общее

- Не указанные при запуске разделители берутся из свойств пользователя. При расхождении командной строки и свойств пользователя действует командная строка, если у пользователя есть право менять параметры сеанса разделителя; иначе аутентификация завершается ошибкой.
- К началу выполнения любого кода (в том числе модуля сеанса) параметры сеанса разделителей уже установлены.

### 24.4.2. Параметр `/Z` клиентского приложения

```
/Z "[<Признак>][<Значение>][,[<Признак>][<Значение>]]"
```

- Пары идут в порядке расположения разделителей в дереве конфигурации; пропускать нельзя. Если порядок общих реквизитов изменился — параметр нужно править.
- `<Признак>`: `+` (по умолчанию) — разделитель используется; `-` — не используется, но значение всё равно записывается в параметр сеанса.
- `<Значение>`: «Булево» — `0` или `1`; «Число» — в каноническом виде; «Дата» — `ггггммддччммсс` (все 14 цифр); «Строка» — текст; ссылка — код или номер (должны быть уникальны; справочники с длиной кода 0 и документы с нумераторами недопустимы).
- Символы `+`, `-` в начале значения и запятая внутри значения удваиваются.
- Пример: `/Z " 0,+001,+,---3"` — первый не используется (значение 0), второй используется (001), третий используется со значением по умолчанию, четвёртый не используется (значение −3).

### 24.4.3. Веб-клиент и тонкий клиент через веб-сервер

- Параметр `Z` в адресной строке: `http://localhost/infobase?Z=" ПервыйРазделитель,+"` (недопустимые в URL символы кодируются в UTF-8 через `%`).
- Элемент `<zones>` файла `default.vrd`: значения разделителей задаются адресом публикации; атрибут `safe="true"` запрещает их менять — гарантия, что через интернет нельзя попасть в чужую область.

### 24.4.4. Внешнее соединение и строка соединения

Параметр `Zn` в том же формате: `Srvr=localhost;Ref=Demo82Srv;Zn=" ПервыйРазделитель,+,---3"`. Допустим и в строке соединения внутри `default.vrd`.

## 24.5. Безопасный режим разделения данных

- Методы `УстановитьБезопасныйРежимРазделенияДанных(<разделитель>, <включить>)` и `БезопасныйРежимРазделенияДанных()`. Равносилен `safe="true"` у элемента `zone` в `default.vrd`; включённый через `default.vrd` режим из кода снять нельзя.
- В безопасном режиме запрещено: выключать разделитель, менять его значение, менять объекты, управляющие условным разделением.
- Включения и выключения должны быть парными; незакрытые включения платформа снимает сама при выходе из процедуры, лишнее выключение даёт исключение.

## 24.6. Удаление области данных

- Метод `УдалитьДанныеИнформационнойБазы()` либо ключ `/EraseData` пакетного режима конфигуратора (область задаётся параметром `/Z`).
- Если в сеансе не используется **ни один разделитель** — удаляются **все данные информационной базы**: состояние как у новой пустой базы с загруженной конфигурацией.
- Если используется хотя бы один — удаляются полностью разделённые данные текущей области.
- Нужны право «Администрирование» и монопольный доступ (рекомендуется установить его заранее методом `УстановитьМонопольныйРежим()`).
- Удаляются: данные разделённых объектов (включая предопределённые и добавленные расширениями), хранилища настроек, история работы пользователя, список пользователей, часовой пояс базы, регистрация в сервисе взаимодействия, история данных области. Неразделённые константы получают значения по умолчанию; реквизиты узла `ЭтотУзел` планов обмена сбрасываются. Без разделителей — ещё и политики паролей.
- Совет документации: сразу после вызова сменить значения разделителей в сеансе.
