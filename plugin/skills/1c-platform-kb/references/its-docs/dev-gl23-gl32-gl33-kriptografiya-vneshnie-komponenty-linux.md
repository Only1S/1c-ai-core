# Глава 23. Механизм криптографии

## Общие положения

- **Платформа не содержит собственных реализаций криптоалгоритмов.** Она даёт объекты для работы с внешними модулями криптографии сторонних производителей.
- Основа — асимметричное шифрование (открытый и закрытый ключ); при шифровании данных дополнительно используется симметричный ключ.
- **На сервере используются синхронные методы, на клиенте — асинхронные.** В веб-клиенте нужно установленное расширение работы с криптографией; веб-клиент запрашивает у пользователя разрешение на доступ к файловой системе и закрытому ключу.
- Термины: ЭЦП — присоединённая (подпись и данные в одном файле) и отсоединённая (подпись отдельным файлом); удостоверяющий центр; сертификат открытого ключа; контейнер ключа; модуль криптографии; метка доверенного времени.

## Модули криптографии (23.5) — важно для Linux

- В Windows платформа работает с модулями через **Microsoft CryptoAPI**; в **Linux и macOS — через интерфейс КриптоПро CSP**.
- В списке поддерживаемых средств в документации одно: СКЗИ **КриптоПро**; параметр конструктора `ТипМодуляКриптографии` = **80**:

```
МенеджерКриптографии = Новый МенеджерКриптографии("", "", 80);
```

- Где платформа на Linux и macOS ищет модуль КриптоПро CSP:
  1. путь из параметра конструктора `ПутьМодуляКриптографии`, если он задан;
  2. иначе — каталоги из параметра **`CryptoAPILibraryLocation`** файла `conf.cfg`;
  3. если параметра нет — стандартные пути расположения КриптоПро.
- Если параметры модуля неизвестны, на клиенте можно создать менеджер без параметров и вызвать `ИнициализироватьАсинх(ИспользованиеИнтерактивногоРежимаКриптографии.Использовать)`.

## Шифрование и подпись

- **Шифрование:** `МенеджерКриптографии.Зашифровать()` с сертификатами получателей (`СертификатКриптографии`); платформа создаёт симметричный ключ, шифрует им данные, сам ключ шифрует открытыми ключами получателей; пакет формируется по спецификации CMS (на основе PKCS#7). Расшифровка — `Расшифровать()`, нужен закрытый ключ получателя. Исключение при расшифровке возникает только после неудачи со всеми доступными сертификатами.
- **Подпись:** `Подписать()`; свойство `ВключениеДанныхВПодпись` (`Истина` — присоединённая, `Ложь` — отсоединённая, по умолчанию). Сначала считается хеш, затем подписывается хеш. Рекомендуется явно задавать `АлгоритмХеширования` и `АлгоритмПодписи`, выбирая значения из `ПолучитьИнформациюМодуляКриптографии()` (свойства `АлгоритмыПодписи`, `АлгоритмыХеширования`). Алгоритмы лучше указывать идентификаторами объектов (OID), а не мнемоническими именами: разные провайдеры называют один алгоритм по-разному.
- **Проверка:** `ПроверитьПодпись()`; если модуль не поддерживает использованные алгоритмы — ошибка.
- **Форматы подписи** (параметр `ТипПодписи`): `CAdESBES` (по умолчанию), `CAdEST` (с доверенным временем), `CAdESC`, `CAdESXLongType2`, `CAdESAv3` (архивное хранение), `CMS` (устаревший; усовершенствовать нельзя — только переподписать).
- **Архивное хранение:** подпись CAdES-A (или `УсовершенствоватьПодпись()`), затем периодически (рекомендуется раз в год) `ДобавитьАрхивнуюМеткуВремени()`. Серверы меток времени задаются свойством `АдресаСерверовМетокВремени` (в документации пример — сервер фирмы «1С» `https://1stdss.1c.ru/TSP/tsp.srf`). Проверка метки — `ПроверитьМеткуВремени()`. Следствие для администратора: серверу или клиенту, выполняющему эти операции, нужен исходящий доступ к серверу меток времени.

## Сертификаты (23.4)

- Объект `СертификатКриптографии`: на сервере создаётся из файла или двоичных данных; на клиенте — пустой объект и `НачатьИнициализацию()` / `ИнициализироватьАсинх()`. Из хранилища — объект `ХранилищеСертификатовКриптографии` (`МенеджерКриптографии.ПолучитьХранилищеСертификатов(ТипХранилищаСертификатовКриптографии.…)`: `КорневыеСертификаты`, `ПерсональныеСертификаты` и др.).
- Свойства: `Версия`, `ДатаНачала`, `ДатаОкончания`, `СерийныйНомер`, `Издатель`, `Субъект`, `ИспользоватьДляПодписи`, `ИспользоватьДляШифрования`, `ОткрытыйКлюч`, `АлгоритмОткрытогоКлюча`, `ЗначениеПодписи`, `АлгоритмПодписи`, `Отпечаток` (хеш SHA-1 всего сертификата), `ДополненияСертификата`.
- **Закрытый ключ в объектной модели платформы не представлен** — он хранится в контейнере у владельца.
- Проверка сертификата: `ПроверитьСертификат()` (и асинхронные варианты) с режимами `ИгнорироватьВремяДействия`, `ИгнорироватьДействительностьПодписи`, `ИгнорироватьПроверкуВСпискеОтозванныхСертификатов`, `РазрешитьТестовыеСертифкаты` (так в документации). Необязательная дата проверки задаётся **в UTC**. При несоответствии — исключение.
- Код, выполняемый на сервере, видит хранилища сертификатов **компьютера кластера серверов** и пользователя, от имени которого работает сервер (на Linux — обычно `usr1cv8`); сертификаты и контейнеры для серверных операций устанавливаются там, а не на рабочих местах (вывод конспекта из примера 23.4 и архитектуры).

# Глава 32. Внешние компоненты

## Технологии и где что работает

| Среда | Что допустимо |
|---|---|
| Тонкий и толстый клиент | Native API и COM (COM — только Windows); файлами и zip-архивами |
| Веб-клиент | Native API и COM, **только в zip-архиве особого вида**; COM — только в Windows; подключение из файла на диске не поддерживается |
| **Сервер «1С:Предприятия»** | **только Native API** (файлом или zip-архивом) |
| Мобильное приложение | только Native API |

- Механизмы **COM, OLE, ActiveDocument в Linux и macOS недоступны** (глава 33) — COM-компоненты рекомендуется перерабатывать на Native API.
- zip-архив особой структуры содержит файл-манифест (имя файла, тип, архитектура, веб-браузер) и варианты компоненты для всех поддерживаемых ОС, браузеров и архитектур.

## Изолированное и неизолированное подключение

Параметр `ТипПодключения` метода `ПодключитьВнешнююКомпоненту()` (перечисление `ТипПодключенияВнешнейКомпоненты`):

- **`НеИзолированно`** — компонента загружается в тот же процесс, что исполняет встроенный язык. **Аварийное завершение компоненты завершает весь процесс — на сервере это рабочий процесс `rphost` со всеми сеансами, которые он обслуживает.**
- **`Изолированно`** — компонента работает в отдельном **хост-процессе**; при её падении завершается только хост-процесс.

Правила:

- Если хост-процесс создать не удалось (например, нет прав на создание процесса), компонента подключается неизолированно; если она этого не поддерживает — не подключается вовсе.
- Подключение только по идентификатору объекта (метод с одним параметром) — всегда неизолированное.
- **Если тип подключения не указан:** в режиме совместимости 8.3.20 и ниже — неизолированно; иначе **на клиенте — неизолированно, на сервере — изолированно**.
- Если компонента не поддерживает требуемый тип подключения — исключение.
- Обработчики аварийного завершения изолированной компоненты: `ОбработкаОтключенияВнешнейКомпонентыПриОшибке()` (модуль приложения), `ОтключениеВнешнейКомпонентыПриОшибке()` (модуль формы). Если компонента подключена на сервере, обработать её падение на сервере нельзя: серверный вызов завершается, управление возвращается на клиент.
- В веб-клиенте параметр игнорируется: Google Chrome и Mozilla Firefox — изолированно, Internet Explorer и Safari — неизолированно.

## На сервере (32.4)

- Метод `УстановитьВнешнююКомпоненту()` на сервере недоступен — используется только `ПодключитьВнешнююКомпоненту()`, причём **непосредственно перед использованием и каждый раз перед созданием экземпляра**: заранее неизвестно, на каком рабочем процессе и компьютере исполнится вызов.
- Серверная компонента должна поддерживать **все архитектуры и ОС**, на которых могут работать рабочие процессы кластера (Windows, Linux, 32 и 64 разряда).
- Файл компоненты кешируется рабочим процессом до его перезапуска. Для компонент из данных информационной базы отслеживается изменение данных (не чаще раза в секунду) — при изменении кеш очищается.

## На клиенте

- Схема для Native API: установка (`УстановитьВнешнююКомпоненту()`, интерактивно и отдельно от подключения) → `ПодключитьВнешнююКомпоненту()` → `Новый("AddIn.<Имя>.<ИмяОбъекта>")`. Не объединять установку и подключение в конструкции «если не подключилась — установить».
- Каталог установки в тонком и толстом клиенте (Windows): `%APPDATA%\1C\1Cv8\ExtCompT`; **это не кеш — ключ `/ClearCache` его не очищает**. Обновление компоненты — повторная установка.
- Загрузка из файла на диске: файл должен быть доступен по пути поиска (`PATH`); в примерах выбор файла идёт по `СистемнаяИнформация.ТипПлатформы` (`Windows_x86`, `Windows_x86_64`, `Linux_x86`, …).
- Асинхронная работа: `НачатьПодключениеВнешнейКомпоненты()`, `НачатьВызов<Метод>()` либо `ПодключитьВнешнююКомпонентуАсинх()`, `СоздатьОбъектВнешнейКомпонентыАсинх()`, `<Метод>Асинх()`. В Google Chrome и Mozilla Firefox поддерживается только асинхронная работа.
- Описание технологии внешних компонент — на ИТС: `http://its.1c.ru/db/metod8dev#content:3221:hdoc`.

# Глава 33. Особенности разработки кроссплатформенных прикладных решений

Рекомендации для решений, работающих и под Windows, и под Linux; администратору полезны как перечень типичных причин «в Windows работало, в Linux нет».

| Тема | В чём отличие Linux | Что предусмотрено в платформе |
|---|---|---|
| Регистр имён | `file.txt` и `File.txt` — разные файлы | — |
| Диски | букв дисков нет; носители монтируются в каталоги (часто `/mnt`, `/media`), автоматическое монтирование не гарантировано | не использовать жёстко заданные пути и проверки на букву диска |
| Разделитель пути | `/` вместо `\`; методы встроенного языка принимают оба, но во внешнюю программу нужно передавать «родной» | `ПолучитьРазделительПути()`, `ПолучитьРазделительПутиКлиента()`, `ПолучитьРазделительПутиСервера()` |
| Маски файлов | `*.*` в Linux — только файлы с точкой в имени | `ПолучитьМаскуВсеФайлы()`, `…Клиента()`, `…Сервера()`; затрагивает `НайтиФайлы()`, `УдалитьФайлы()`, `ДиалогВыбораФайла` |
| Сетевые ресурсы | UNC-пути (`\\server\folder\…`) не работают | ресурс нужно заранее смонтировать в файловую систему (или использовать `smbclient`, если установлен) |
| Внешние устройства | последовательные порты — `/dev/ttyS0`, `/dev/ttyUSB0` и т. п., а не `COM1` | список портов получать из самой внешней компоненты; пользователю может понадобиться членство в специальной группе |
| Права | работа не от `root`; для записи гарантированно доступны домашний каталог и каталог временных файлов | `КаталогДокументов()` — чтение и запись; `КаталогПрограммы()` — только чтение; `КаталогВременныхФайлов()` — чтение и запись; `РабочийКаталогДанныхПользователя()` — чтение и запись |
| Шрифты | набор шрифтов другой | использовать стилевые шрифты; при необходимости — Microsoft Core Fonts |
| COM, OLE, ActiveDocument | недоступны (как и в macOS) | обмен файлами XML, web-сервисы; COM-компоненты переписывать на Native API |

Практические замечания конспекта для сервера на Linux:

- Пути в настройках прикладного решения (каталоги обмена, выгрузок, файловых томов) после переноса с Windows нужно переписать на пути Linux и выдать права пользователю сервера (`usr1cv8`); сетевые каталоги — смонтировать (`../linux/07-diski-fs-lvm.md`, `../linux/08-set-ssh-firewall.md`).
- Группа для доступа к последовательным портам в Ubuntu — обычно `dialout` (это сведение не из документации 1С; проверять `ls -l /dev/ttyS0`).
