## 30.1. Общая информация

### Термины

| Термин | Смысл |
|---|---|
| Расширяемая конфигурация | основная конфигурация базы, к которой применяется расширение |
| Расширение конфигурации | набор объектов метаданных, подключаемых к расширяемой конфигурации; содержит заимствованные и собственные объекты |
| Собственный объект | самостоятельный объект (в конфигурации или в расширении) |
| Заимствованный объект | объект расширяемой конфигурации, добавленный в расширение |
| Результирующий объект | собственный объект плюс все расширяющие его объекты; пользователь всегда работает с результирующими объектами |
| **Контролируемое свойство** | при подключении сверяется с расширяемой конфигурацией; **несовпадение — расширение не подключается** |
| **Проверяемое свойство** | несовпадение даёт только предупреждение; расширение подключается |
| Модифицируемое свойство | в результирующем объекте берётся из расширения |
| Расширение данных | изменение структуры хранимых данных заимствованными и собственными объектами расширения |

Свойство не может быть одновременно контролируемым и модифицируемым. **Имя объекта — всегда контролируемое свойство.**

### Суть механизма

- Назначение — доработка прикладного решения **без снятия конфигурации с поддержки**.
- Объекты сопоставляются **по имени**: переименование объекта в расширяемой конфигурации (например, при обновлении) делает расширение неподключаемым, пока имя не исправлено и в расширении.
- Облегчает поиск таких проблем свойство расширения «Поддерживать соответствие объектам расширяемой конфигурации по внутренним идентификаторам» (для новых расширений включается автоматически): проверка применимости в конфигураторе тогда предлагает варианты исправления («Переименовать, сохранив соответствие», «Сохранить имя, изменив соответствие», «Выбрать соответствие», «Отключить проверку», «Очистить соответствие», «Установить значение из объекта конфигурации», «Удалить объект»).
- Расширение создаётся в конфигураторе, хранится в информационной базе, сохраняется в файл **`.cfe`**. Подключить расширение из файла можно без конфигуратора — стандартной функцией «Функции для технического специалиста — Стандартные — Управление расширениями конфигурации» или средствами прикладного решения.
- Подключение (интерактивное или из встроенного языка) возможно в небезопасном режиме либо когда профиль безопасности сеанса разрешает доступ к подключаемому расширению.
- В разделённой базе расширению задаётся область действия: вся информационная база или область данных.

### Назначение расширения

| Назначение | Для чего | Особенности |
|---|---|---|
| **Исправление** | исправление ошибок конкретной версии решения | допускает «опасные» приёмы (аннотация `&Вместо`); при выходе новой версии автор проверяет применимость |
| **Адаптация** | подгонка под конкретного клиента | «опасных» приёмов рекомендуется избегать; таких расширений должно быть минимальное число |
| **Дополнение** | новые возможности, слабо связанные с версией решения (например, набор отчётов) | должно переживать обновление решения; количество не ограничено |

### Особенности и ограничения

- В расширении нельзя создать собственные: общие реквизиты-разделители, хранилища настроек, языки.
- Нельзя добавлять реквизиты и табличные части планам видов характеристик, планам счетов, планам видов расчёта. Нельзя менять структуру регистров — только расширять состав регистраторов. Для собственных регистров накопления нет агрегатов.
- Одно и то же расширение нельзя подключить в одной базе (области данных) более чем в одном экземпляре.
- **После подключения расширения, расширяющего данные, фоновая реструктуризация в этой базе не поддерживается.**
- **«Тестирование и исправление» обрабатывает только структуры данных расширяемой конфигурации** (данные расширений не проверяет).
- В базовой версии расширение работает, только если подписано тем же ключом, что и конфигурация (патчи поставщика).
- Типы реквизитов внешней обработки или отчёта не могут включать типы объектов подключённых расширений.

## 30.2. Управление расширениями

- **В конфигураторе** — окно «Расширения конфигурации». Специальные команды: «Конфигурация — Проверка возможности применения» (текущее расширение) и «Действия — Проверка возможности применения всех расширений» (то же, что выполняется при старте клиентского приложения). Проверяется совпадение контролируемых свойств, наличие всех заимствованных объектов в расширяемой конфигурации, отсутствие конфликтов имён и идентификаторов, а для методов с аннотацией `&ИзменениеИКонтроль` — совпадение текста расширяемого метода (эта проверка не блокирует расширение: не применится только сам метод).
- При создании расширения из расширяемой конфигурации копируются и становятся контролируемыми свойства: основной режим запуска, назначение использования, основной язык, режим совместимости интерфейса, режим совместимости. Автоматически создаётся роль `<префикс>ОсновнаяРоль` (например, `Расш1_ОсновнаяРоль`) с доступом к собственным объектам расширения; она записывается в свойство «Основные роли» расширения.
- **В режиме «1С:Предприятие»** — стандартная функция «Управление расширениями конфигурации».
- **Удаление:** расширение, не расширяющее данные, удаляется после подтверждения. Расширение, расширяющее данные, удаляется в два шага: сначала отключить (снять флажок «Активно»), затем удалить. Из встроенного языка `РасширениеКонфигурации.Удалить()` выполняется без такого контроля; проверить можно свойством `Активно` и методом `ИзменяетСтруктуруДанных()`.
- **Блокировки:** список расширений общий для конфигуратора и «1С:Предприятия». Расширение, открытое в конфигураторе, нельзя удалить в режиме предприятия; расширение, записываемое в режиме предприятия, недоступно в конфигураторе.
- **Хранилище:** у каждого расширения — своё отдельное хранилище конфигурации; нельзя хранить расширение вместе с расширяемой конфигурацией или несколько расширений в одном хранилище (см. `dev-gl37-gl38-hranilishche-postavka-podderzhka.md`).

## 30.3. Заимствование объектов (кратко)

- Команда «Добавить в расширение». Вместе с объектом заимствуются его родители; подчинённые объекты не заимствуются.
- Модифицируемое свойство при нескольких расширениях получает значение из расширения, указанного последним в списке.
- Собственные объекты получают префикс расширения; уникальность имён проверяется при подключении среди конфигурации и всех расширений.

## 30.4. Объекты расширения (выборка)

### Свойства расширения

- «Режим совместимости расширения конфигурации» — аналог режима совместимости конфигурации; при использовании возможности, несовместимой с установленным режимом, конфигурация базы не сохраняется (с диагностикой).
- «Основные роли» — определяют доступность объектов расширения, когда в базе нет пользователей; основной может быть только собственная роль расширения, и она управляет доступом только к собственным объектам расширения.
- Расширение может заменить картинку основного раздела, логотип и заставку (берётся картинка из последнего применённого расширения) и расширить основной стиль.

### Программные модули

- Расширяется почти любой модуль управляемого приложения. **Нельзя расширять глобальные серверные модули.** Расширение привилегированного общего модуля выполняется **в непривилегированном режиме**, если иное не разрешено профилем безопасности. Собственные общие модули расширения не могут быть привилегированными и глобальными серверными.
- Перехват методов — аннотациями: `&Перед("ИмяМетода")`, `&После("ИмяМетода")`, `&Вместо("ИмяМетода")` (внутри можно вызвать исходный метод через `ПродолжитьВызов()`), `&ИзменениеИКонтроль("ИмяМетода")`.
- Расширяющий метод должен иметь то же описание параметров, что и расширяемый. Значения параметров общие для всей цепочки методов.
- Перед исполнением: синтаксический контроль модуля конфигурации → синтаксический контроль расширяющих модулей всех расширений → проверка применимости методов → компиляция. Следствия:
  - **ошибка в модулях, исполняемых при старте (модуль приложения, модуль сеанса), не даст прикладному решению запуститься**;
  - ошибка при инициализации объекта делает недоступным только этот объект.
- **Порядок при нескольких расширениях:** первым используется расширение, зарегистрированное последним. Методы `&Перед` вызываются от последнего расширения к первому, затем исходный метод, затем методы `&После` в обратном порядке. Метод `&Вместо` полностью заменяет исходный — замещать один и тот же метод более чем в одном расширении не рекомендуется (если только в замещающих методах нет безусловного `ПродолжитьВызов()`). Необработанное исключение прерывает всю цепочку.

### Модули, права и профили безопасности

**Расширение методов (30.4.2.5).** Успешное подключение расширения не гарантирует, что все его методы будут выполняться:

| Условия | Что расширяется |
|---|---|
| файловый вариант или клиент-серверный без профилей безопасности, обычный режим | клиентские и серверные методы без ограничений |
| те же условия, расширение в **безопасном режиме** | только клиентские методы и серверные обработчики форм, назначенные через панель свойств; серверные общие модули и аннотированные серверные методы модулей форм **не расширяются** |
| клиент-серверный вариант с профилем безопасности | расширение серверных общих модулей регулируется профилем |

**Расширение прав доступа (30.4.7.4).**

- Файловый вариант, расширение в безопасном режиме: права на объекты расширяемой конфигурации можно только ограничивать, но не расширять.
- Клиент-серверный вариант **без профиля безопасности: расширение ролей не допускается.**
- Клиент-серверный вариант с профилем безопасности: ограничивать права можно всегда; расширять — только при соответствующей настройке профиля:
  - установлен флажок расширения прав доступа в группе «Разрешен полный доступ» — расширять можно для любого объекта;
  - флажок снят, но заполнено свойство профиля «Роли, ограничивающие расширение прав доступа» (роли через «;») — роль расширения может дать право, только если это право установлено хотя бы в одной из перечисленных ролей (права перечисленных ролей складываются «по ИЛИ», результат — «по И» с правом из роли расширения). Перечисленные роли не обязаны быть назначены пользователям.
- На собственные объекты расширения права даются ролями расширения независимо от профиля безопасности.
- Описанное поведение прав действует при режиме совместимости расширения «Версия 8.3.14» и выше.

### Прочие объекты (обзорно)

- Ограничения доступа к данным из заимствованной роли применяются, только если право явно задано в заимствованной роли, и тогда полностью замещают ограничения расширяемой конфигурации для этого права и роли.
- В заимствованных справочниках, документах и планах обмена можно добавлять реквизиты, табличные части и их реквизиты; в заимствованном перечислении — новые значения. Для собственных документов расширения не поддерживаются нумераторы и последовательности.
- **HTTP-сервисы:** при подключении проверяется уникальность свойства «Корневой URL» собственных HTTP-сервисов расширения; расширение с неуникальным значением не подключается.
- **Регламентные задания** могут быть собственными и заимствованными; заимствованное задание менять нельзя.
- Общие реквизиты в расширении — только заимствованные (включая разделители).
- Собственными и заимствованными могут быть также: подсистемы, XDTO-пакеты, Web-сервисы, параметры сеанса, функциональные опции, критерии отбора, подписки на события, определяемые типы, сервисы интеграции, нумераторы, внешние источники данных, бизнес-процессы и задачи, макеты.

## 30.5. Расширения и распределённая информационная база

- Чтобы расширения передавались между узлами, у плана обмена ставят флажок «Включать расширения конфигурации» (только для планов обмена РИБ), а у расширения — свойство «Используется в распределенной информационной базе».
- `РасширениеКонфигурации.ГлавныйУзел`: `Неопределено` — расширение добавлено в текущем узле; ссылка — получено из главного узла.
- **Начальный образ и сообщение обмена не формируются**, если в сеансе есть:
  - неподключённые расширения с флагом использования в РИБ;
  - расширения, изменяющие данные, с этим флагом, но неактивные;
  - расширения, изменяющие данные, **без** этого флага;
  - расширения с этим флагом, для которых загружены новые версии (то есть сеанс не перезапущен).
- В периферийном узле нельзя менять свойства и удалять расширения, пришедшие из главного узла.
- Порядок применения при старте сеанса: сначала расширения из центрального узла (в его порядке), затем добавленные в текущем узле.
- Если пришло сообщение о снятии флага использования в РИБ — расширение в узле удаляется.
- Пока в базе есть расширения, полученные обменом, главным узлом можно назначить только тот, откуда они пришли, либо отключить базу от РИБ (`Неопределено`).

## 30.6. Безопасный режим и профили безопасности

- При подключении расширения указывают либо флажок «Безопасный режим», либо **имя профиля безопасности** (только клиент-серверный вариант) — тогда режим работы расширения определяется настройками профиля; доступ к расширению задаётся в профиле в элементе «Внешние модули».
- Если профиль запрещает небезопасное использование внешних модулей, а расширению оно нужно, расширение вносят в список исключений **по контрольной сумме** (её показывают диалоги работы с расширениями и программный интерфейс); значение вводится в консоли администрирования кластера.
- Если расширение не соответствует требованиям профиля — оно не подключается, выдаётся ошибка.
- Менять настройки безопасного режима расширения может пользователь с правом **`Администрирование`** (в дополнение к праву **`АдминистрированиеРасширенийКонфигурации`**, которое даёт остальные действия с расширениями).

## 30.7. Подключение расширений и время их работы

- Расширение подключается к сеансу **перед обработчиком `УстановкаПараметровСеанса`** и остаётся подключённым до конца сеанса. **Обновление расширения не действует на уже работающие сеансы** — нужен перезапуск сеанса.
- Таблицы для расширения данных создаются: в конфигураторе — при реструктуризации; в режиме предприятия — при добавлении или обновлении расширения, то есть при выполнении `РасширениеКонфигурации.Записать()`. При удалении расширения таблицы удаляются в том же порядке.
- **Порядок подключения:** Исправление → Адаптация → Дополнение; внутри каждого назначения сначала область действия «Информационная база», затем «Область данных». Для расширений с одинаковыми назначением и областью порядок в общем случае не определён.
- При несовпадении хотя бы одного контролируемого свойства расширение не подключается, пользователю выдаётся сообщение; подробности — по ссылке «Информация для технической поддержки» в диалоге.
- Проверка из встроенного языка: `РасширениеКонфигурации.ПроверитьВозможностьПрименения()`, `РасширенияКонфигурации.ПроверитьВозможностьПримененияВсех()`.

### Работа, когда расширение данных не подключилось (30.7.2)

- Чтение данных расширяемой конфигурации и подключённых расширений работает.
- Справочники, документы, планы обмена: создание, изменение и удаление поддерживаются; поля отключённых расширений у новых объектов получают значения по умолчанию, у изменяемых — сохраняются, при копировании — не копируются. Для табличных частей — так же.
- Регистры, список регистраторов которых расширен неактивным расширением: запись наборов возможна только для регистраторов из расширяемой конфигурации; набор с регистратором из неактивного расширения читается (регистратор — `Неопределено`), но изменить или удалить его нельзя.
- Реквизиты, тип которых изменён отключённым расширением: значения приводятся к типам конфигурации без учёта неактивных расширений; ссылки на объекты неактивных расширений читаются как `Неопределено`; при записи обновляются только изменённые значения.
- В запросах в условиях и группировках используются значения, хранимые в базе; обращение «через точку» к реквизитам ссылки на объект неактивного расширения даёт `NULL`.

## 30.8. Работа с расширениями из встроенного языка

- Менеджер — свойство глобального контекста `РасширенияКонфигурации`; нужен пользователь с правом `АдминистрированиеРасширенийКонфигурации`. Для `Записать()` сеанс должен работать в небезопасном режиме.
- Подключение: `РасширенияКонфигурации.Создать()` и затем `Записать(Новый ДвоичныеДанные(<путь к файлу>))` — либо `Создать(Новый ДвоичныеДанные(…))` без записи, чтобы сначала проверить (например, `ИзменяетСтруктуруДанных()`).
- `РасширенияКонфигурацииИзменены()` — аналог `КонфигурацияИзменена()` для расширений в текущем сеансе.
- `<Объект метаданных>.ЕстьИзмененияРасширениямиКонфигурации()`, `<Объект метаданных>.РасширениеКонфигурации()` — узнать, расширен ли объект и какому расширению он принадлежит.

## Что из этого важно администратору

1. После обновления типовой конфигурации расширение может перестать подключаться (изменились контролируемые свойства или имена). Проверять заранее: в конфигураторе — «Проверка возможности применения всех расширений».
2. Новая версия расширения начинает действовать только в новых сеансах; для серверных фоновых и регламентных заданий это означает перезапуск соответствующих сеансов.
3. Расширение, изменяющее структуру данных, отключает возможность фоновой реструктуризации и не охватывается «Тестированием и исправлением»; удалять такое расширение — в два шага, предварительно сделав резервную копию (при удалении его таблицы удаляются).
4. В клиент-серверном варианте без профиля безопасности роли расширения не могут расширять права на объекты конфигурации — частая причина «расширение подключено, а доступа нет».
5. В РИБ формирование сообщений обмена блокируется расширениями в «промежуточном» состоянии (неактивные, с загруженной, но не применённой версией, без флага использования в РИБ при изменении данных).
