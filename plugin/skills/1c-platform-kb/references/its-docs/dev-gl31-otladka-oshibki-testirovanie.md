## 31.2. Отладчик

### Два протокола отладки

| | TCP/IP | HTTP |
|---|---|---|
| Как связаны участники | отладчик соединяется с предметами отладки напрямую | всё взаимодействие идёт через **сервер отладки `dbgs`**; прямой связи отладчика с предметом отладки нет |
| Порты | **1560–1591** по умолчанию, на стороне отладчика и на стороне предмета отладки | порт сервера отладки: в клиент-серверном варианте **1550** по умолчанию; в файловом — задаётся явно или выбирается конфигуратором из 1560–1591 |
| Где должны быть открыты | на всех компьютерах, участвующих в отладке | только на компьютере сервера отладки |

- Диапазон портов для TCP/IP меняется настройками компонентов или конфигурационным файлом `debugcfg.xml`. Если все порты стандартного диапазона заняты, в `debugcfg.xml` (каталог конфигурационных файлов компьютера, где работает конфигуратор) задают **дополнительный диапазон** — элемент `<debugports range="1540:1550"/>` внутри `<config xmlns="http://v8.1c.ru/v8/debugcfg">` (значения из примера документации).
- Если нужные порты закрыты — отладка невозможна; возможны также увеличение времени запуска клиента и **замедление рабочего процесса `rphost`, пока сервер работает с ключом `-debug`**. Документация прямо не рекомендует держать отладочный режим для реальной работы пользователей.
- **Предмет отладки** — контекст встроенного языка: пользователь, тип, номер сеанса, имя компьютера и порт (TCP/IP) либо имя информационной базы (HTTP). Типы: тонкий, толстый, веб-клиент, сервер, фоновое задание, Web-сервис, HTTP-сервис, WebSocket, стандартный интерфейс OData, COM-соединение, сервер и фоновое задание файлового варианта; мобильные — только по HTTP.
- Если при нескольких рабочих процессах сеанс в ходе отладки переназначен на другой рабочий процесс, отладка серверного кода или веб-клиента становится невозможной.

### Перевод сервера «1С:Предприятия» в отладочный режим

**Сервер как приложение (любая ОС):** остановить и запустить с ключом отладки:

```
ragent /debug <остальные параметры>            # протокол TCP/IP
ragent /debug -http <остальные параметры>      # протокол HTTP
```

Для HTTP при необходимости добавляют `/debugServerAddr`, `/debugServerPort`, `/debugServerPwd`.

**Сервер как служба Windows:** перерегистрировать службу с тем же ключом (`ragent /instsrvc /debug …`).

**Сервер как сервис Linux (systemd):**

1. остановить сервис: `systemctl stop <юнит сервера>@<экземпляр>`;
2. в конфигурационном файле сервиса задать параметр **`SRV1CV8_DEBUG`**:
   - `SRV1CV8_DEBUG=-debug` — протокол TCP/IP;
   - `SRV1CV8_DEBUG=-debug -http` — протокол HTTP;
3. сохранить файл и запустить сервис: `systemctl start <юнит сервера>@<экземпляр>`.

Замечание конспекта: в этой главе юнит назван `srvc1v8-A.B.C.D@instanceName`, а в «Клиент-серверном варианте» — `srv1cv8-A.B.C.D@instName` (`cs-gl04-zapusk-komponentov.md`); правильным следует считать второе написание (файл юнита `srv1cv8-A.B.C.D@.service` в каталоге версии), на сервере проверить `systemctl list-units 'srv1cv8*'`. Где лежит файл с переменными `SRV1CV8_*`, см. там же.

**Автономный сервер:** ключ `--debug=tcp` или `--debug=http` либо секция конфигурационного файла:

```
debug:
  type: http
```

Порт сервера отладки автономного сервера по умолчанию 1550; меняется ключом `--debug-port` или параметром `port` секции `debug`.

### Отладка веб-клиента, сервисов и внешнего соединения

- Для отладки **веб-клиента** (включая клиентский код) в клиент-серверном варианте сервер должен работать в отладочном режиме. Адрес запуска: `http://host/base?debug=tcp`, `…?debug=tcp&debuggerurl="<IP>"`, для HTTP — `…?debug=http,attach&debuggerURL="<адрес>"`.
- **Web- и HTTP-сервисы файловой базы**: элемент `debug` в `default.vrd`, например `<debug enable="true" protocol="tcp" url="tcp://localhost"/>` или `<debug enable="true" protocol="http" url="http://<компьютер>:1561"/>`. Отсутствие элемента означает невозможность отладки сервиса. При протоколе TCP, если указан `url`, а конфигуратор недоступен, исполнение сервиса приостанавливается в ожидании; при HTTP сервис работает обычным образом без отладки.
- Сервисы клиент-серверной базы отлаживаются при сервере, запущенном в отладочном режиме.
- **Внешнее соединение:** файл настроек с элементом `<debugconfig debug="true" protocol="tcp" debuggerURL="tcp://localhost:1560"/>`.
- Ограничения веб-клиента: нет интерактивного включения отладки, нет автоматического поиска предметов отладки на удалённых компьютерах для файловой базы, не отлаживаются внешние отчёты и обработки. Внешняя обработка, хранящаяся в информационной базе, не отлаживается — её рекомендуют на время отладки извлечь в файл.
- В списке пользователей базы должны быть пользователи, которые могут аутентифицироваться и в конфигураторе, и в предмете отладки.

### Сервер отладки `dbgs` (протокол HTTP)

- Координатор: хранит списки доступных и подключённых предметов отладки, транслирует команды, хранит список пользователей отладки и их полномочия.
- Соединения устанавливают сами участники (отладчик и предметы отладки) — к серверу отладки, по HTTP. Если серверный процесс не запущен в отладочном режиме, он к серверу отладки не подключится.
- Сопоставление по имени информационной базы: в клиент-серверном варианте — имя базы в кластере; в файловом — предопределённое имя `DefAlias` (поэтому один сервер отладки — на одну файловую базу).
- Кем запускается: конфигуратором (файловый вариант), кластером серверов (если для кластера включён режим отладки) или вручную; вручную его можно зарегистрировать службой Windows или запустить демоном в Linux.
- Внешнему серверу отладки можно передать конфигурационный файл со списком баз, пользователей и их полномочий.
- **Проверка работоспособности:** открыть адрес сервера отладки в веб-браузере — должен вернуться текст вида `1C:Enterprise 8.3 Debug Server (<версия>) … - it works!`.
- Следствие архитектуры: невозможна одновременная пошаговая отладка разных предметов отладки одной базы; при остановке на точке останова останавливаются все подключённые предметы отладки, причём момент остановки «чужих» предметов непредсказуем.

### Работа в отладчике (обзорно)

- Точки останова (с условиями), пошаговое выполнение, окно «Выражение», табло, локальные переменные, изменение значения переменной, стек вызовов.
- Редактирование модуля во время отладки не перекомпилирует код: отлаживается конфигурация базы данных на момент запуска; для отладки изменений нужно обновить конфигурацию базы данных.
- В файловой базе при остановке на точке останова с открытой транзакцией некоторые операции (например, захват объектов в хранилище) могут завершаться ошибкой блокировки.
- При шаге в защищённый модуль отладчик запрашивает пароль.

## 31.3. Ошибки времени исполнения

### Отображение

- Ошибки делятся на **восстановимые** (перехватываются `Попытка … Исключение`; диалог с кнопкой «ОК») и **невосстановимые** (диалог с кнопками «Завершить» и «Перезапустить»).
- Текст в диалоге зависит от режима: обычный запуск — представление ошибки для пользователя (зависит от категории ошибки); **режим технического специалиста — подробный текст**; режим отладки — вся информация со стеком вызовов и кнопкой перехода в конфигуратор.
- В диалоге может быть ссылка «Сформировать отчет об ошибке» (не для всех категорий).

### Ошибка при входе в информационную базу (31.3.5)

Причины обычно две: сеть (нет соединения с сервером или базой) и регламентные работы (монопольная блокировка, запрет начала сеансов, отказ внешнего сервиса управления сеансами, ошибка лицензирования). Чтобы пользователь понимал, что делать, сообщение можно дополнить:

| Способ | Что задаётся | Особенности |
|---|---|---|
| Файл списка баз `*.v8i` | параметры **`StartupErrorHelpText`** и **`StartupErrorHelpURL`** для каждой базы | не требует изменения конфигурации; сервис обработки ошибок недоступен |
| Стандартная функция «Управление настройками обработки ошибок» | все параметры | нужен вход администратором в каждую базу |
| Встроенный язык: объект `НастройкиОбработкиОшибокПриЗапуске`, методы `ОбработкаОшибок.УстановитьНастройкиОбработкиОшибокПриЗапуске()` / `ПолучитьНастройкиОбработкиОшибокПриЗапуске()` | `ТекстПомощи`, `НавигационнаяСсылкаПомощи` (кнопка «Нужна помощь?»), `АдресСервисаОбработкиОшибокПриЗапуске`, `ДополнительнаяИнформацияЗапроса` | самый гибкий, но требует изменения кода конфигурации |

**Сервис обработки ошибок при запуске** — HTTP-сервис, которому платформа после ошибки входа отправляет GET-запрос с заголовками `errorDescr`, `appName`, `appVersion`, `clientID`, `additionalInfo`. Ответ — JSON:

```
{
    userMessage:string
    userMessageEndTime:string
}
```

`userMessage` показывается пользователю; `userMessageEndTime` (ISO 8601) — время, после которого текст не показывается (проверяется по часам клиентского компьютера). В простейшем случае сервис — это веб-сервер, отдающий по выбранному адресу статический файл `info.json`, который администратор правит вручную или автоматизацией (удобно на время регламентных работ).

### Отчёт об ошибке и сервис регистрации ошибок

- Объект `ОтчетОбОшибке` собирает сведения (текст ошибки, снимки окон, имя пользователя, сведения о конфигурации и системе, дамп аварийного завершения, приложенные файлы, дополнительные данные с JSON-сериализацией), формирует архив с файлом `report.json` и сохраняет его на диск или отправляет в **сервис регистрации ошибок** (HTTP-сервис с методами `getInfo` и `pushReport`).
- В `report.json` среди прочего: `clientInfo`, `serverInfo` (`appVersion`, `dbms` — тип СУБД, для файлового варианта `DBEng8`), `compatibilityMode`, `serverStack`, `serverStackHash`, `insufficientResources`.
- **Отчёт отправляется из того окружения, где работал процесс с ошибкой** — клиентское приложение или рабочий процесс кластера. Значит, для серверных ошибок доступ к адресу сервиса нужен **рабочему процессу сервера** (учитывать в правилах межсетевого экрана).
- Для автоматизированного тестирования и регламентных операций рекомендуется отключать автоматическую отправку отчётов для соответствующего пользователя.

### Настройки обработки ошибок (31.3.7)

Объект `НастройкиОбработкиОшибок`; общие настройки — `ОбработкаОшибок.ПолучитьОбщиеНастройки()` / `УстановитьОбщиеНастройки()`, для пользователя — `ПолучитьНастройкиПользователя()` / `УстановитьНастройкиПользователя()`. Свойства:

- `АдресСервисаОбработкиОшибок` — адрес сервиса регистрации ошибок;
- `ВариантОтображенияСообщения` — `СообщениеОбОшибкеДляПользователя`, `КраткоеПредставлениеОшибки`, `ПодробноеПредставлениеОшибки`, `Авто` (в режиме совместимости 8.3.16 и ниже — краткое представление, иначе — сообщение для пользователя);
- `ВключатьИмяПользователяВОтчет…`, `ВключатьИнформациюОСистемеВОтчетНаКлиенте`, `ВключатьСнимокОконВОтчетНаКлиенте`, `ВключатьПодробныйТекстОшибкиВОтчет…`, `ВключатьСведенияОбИнформационнойБазеВОтчет…` (суффиксы `НаКлиенте` / `НаСервере`);
- `ОтправлятьОчетНаКлиенте` (так в документации), `ОтправлятьОтчетНаСервере`, `ОтправлятьОтчетОбАварийномЗавершенииНаКлиенте` / `…НаСервере`;
- `ОтправлятьОтчетОбАварийномЗавершенииНаКлиентеВСервисРегистрацииОшибокПлатформы` / `…НаСервере…` — отправка отчётов об аварийном завершении в сервис «1С:Пульт» (`https://pult.1c.com/pult/platform/errors`); **отключается значением `РежимОтправкиИнформацииОбОшибке.НеОтправлять`**;
- `ДополнительнаяИнформацияОтчета` — произвольная строка (например, код базы или области);
- `ТекстыСообщенийОбОшибках` — шаблоны текстов по категориям ошибок (`КатегорияОшибки`), отдельно для ошибки, не требующей и требующей перезапуска. В шаблон в квадратных скобках подставляются параметры `[КраткоеПредставлениеОшибки]`, `[ПодробноеПредставлениеОшибки]`, `[ПредставлениеОшибкиДляПользователя]`, `[СтандартноеСообщениеОбОшибкеДляПользователя]`.

Те же настройки доступны без изменения конфигурации — стандартной функцией «Управление настройками обработки ошибок» (например, чтобы вписать в сообщения контакты своей службы поддержки).

## 31.4–31.6. Производительность

- **Замер производительности** («Отладка — Замер производительности»): количество и длительность выполнения строк кода с разделением на клиент и сервер; результаты сохраняются в файл `*.pff`. Действует на все подключённые предметы отладки. Сравнивать варианты нужно в одинаковых условиях.
- **Имитация задержек при вызове сервера** — только в тонком клиенте и управляемом режиме толстого клиента; задержка до 9,99 с.
- **Отображение вызовов сервера (показатели производительности):** включается настройкой конфигуратора, ключом командной строки **`/DisplayPerformance`** либо в режиме предприятия флажком «Отображать показатели производительности» («Сервис — Параметры»); по умолчанию выключено. Показывает счётчики «Текущие вызовы» и «Накопленные вызовы» и объём переданных данных.
  - В файловом варианте при прямом соединении объём показывается без сжатия.
  - В веб-клиенте учитываются только синхронные запросы, а объём считается в символах — сравнивать с другими клиентами нельзя.

## 31.7. Автоматизированное тестирование (обзорно)

- Имитация интерактивных действий пользователя и проверка результата; **только для управляемого приложения**.
- Роли: **менеджер тестирования** (толстый или тонкий клиент) и **клиент тестирования** (толстый, тонкий, веб-, мобильный клиент). Один менеджер может управлять несколькими клиентами.
- Есть запись журнала действий пользователя и преобразование журнала в сценарий тестирования. Ключи запуска клиента в этих режимах — в `adm-pr07-parametry-zapuska-1cv8-p1.md` … `p3.md`.
