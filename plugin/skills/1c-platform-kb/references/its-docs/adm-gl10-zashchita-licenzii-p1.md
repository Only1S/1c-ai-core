## 10.1. Общая информация

Защита платформы строится на одном из двух механизмов:

- **аппаратная** — сетевая система защиты HASP4 Net (раздел 10.2);
- **программная** — система программного лицензирования, СПЛ (раздел 10.3).

Оба механизма ограничивают число одновременно работающих пользователей (сеансов). Пользователи могут быть и в локальной сети, и вне её (веб-клиент, тонкий клиент через веб-сервер). Какой механизм применяется — определяется поставкой продукта.

### Сравнение программных и аппаратных лицензий

| Возможность | Программная | Аппаратная |
|---|---|---|
| Размещение на компьютере пользователя | Да | Да |
| Размещение на компьютере сервера «1С:Предприятия» | Да | Да |
| Размещение на другом компьютере локальной сети | Нет | Да |
| Произвольное суммирование лицензий на одном компьютере | Да | Нет, только ключи разных серий |
| Раздача по сети для любых видов ИБ (менеджер лицензий) | Нет | Да |
| Использование сервиса лицензирования | Да, клиентские и серверные | Нет |

### Как расходуется лицензия

| Вариант получения лицензии | Программная | Аппаратная |
|---|---|---|
| Клиентское приложение получило лицензию на локальном компьютере | На компьютер | На компьютер |
| Клиентское приложение получило лицензию по сети от менеджера лицензий | Не поддерживается | На компьютер |
| Клиентское приложение получило лицензию от сервера «1С:Предприятия» | На сеанс | На сеанс |
| Веб-клиент | На сеанс | На сеанс |
| Мобильный клиент | На сеанс | На сеанс |

Термины:

- **«на компьютер»** — компьютер, получивший лицензию, может запускать сколько угодно клиентских приложений с любым числом информационных баз;
- **«на сеанс»** — лицензия выдаётся конкретному сеансу; повторное подключение того же пользователя с того же компьютера к той же базе займёт ещё одну клиентскую лицензию.

Дополнительно существует проверка лицензионности использования самого прикладного решения — она опирается на сведения о решении и о пользователе, на которого оно зарегистрировано.

Важная оговорка документации: глава описывает только **технические** аспекты лицензирования. Для правомерного использования может требоваться иное количество лицензий. Ответы на типовые вопросы: https://v8.1c.ru/predpriyatie/questions_licence.htm.

## 10.2. Система защиты HASP

### 10.2.1. Общая информация

- Используется сетевая система защиты HASP4 Net. Подсчёт пользователей ведёт либо отдельная программа **HASP License Manager**, либо серверная часть «1С:Предприятия».
- **Взаимодействие с HASP License Manager возможно только по IPv4.**
- При любом способе подсчёта в сети должен быть один или несколько компьютеров с клиентскими аппаратными ключами HASP4 Net в USB-портах. Общее число пользователей = сумма лицензий всех подключённых клиентских ключей — с учётом особенностей (ссылка в источнике не раскрыта; по смыслу это 10.2.3 и 10.2.5.11).
- Несколько ключей HASP4 Net **одной серии** на одном компьютере бессмысленны: ключи неразличимы, реально работает только один, выбранный произвольно.
- HASP License Manager запускается как обычное приложение Windows, как служба Windows (только Windows 2000 и старше) и в ОС Linux.
- В многопользовательской схеме HASP Device Driver не нужен на тех пользовательских компьютерах, где запускается «1С:Предприятие», но ключ в USB не вставлен.

Где брать дистрибутивы:

| Компонент | Адрес |
|---|---|
| HASP Device Driver | https://releases.1c.ru/project/AddCompDriverHASP |
| HASP License Manager | https://releases.1c.ru/project/AddCompNetHASP |

### 10.2.2. Маркировка ключей защиты

| Назначение ключа | Маркировка |
|---|---|
| Локальный клиентский ключ | `ORGL8` |
| Многопользовательский клиентский ключ (число после `NET` — количество пользователей: 5, 10, 20, 50, 100) | `NET5 ORGL8`, `NET10 ORGL8`, `NET20 ORGL8`, `NET50 ORGL8`, `NET100 ORGL8` |
| Многопользовательский клиентский ключ на 300 пользователей | `NET250+ ORG8A` |
| Многопользовательский клиентский ключ на 500 пользователей | `NET250+ ORG8B` |
| Локальный ключ 32-разрядного сервера | `ENSR8` |
| Локальный ключ 64-разрядного сервера | `EN8SA` |

Лицензия на 1 000 пользователей — это комплект из двух лицензий на 500 (в поставке два ключа `NET250+ ORG8B`).

### 10.2.3. Особенности использования

- На одном компьютере одновременно может работать по одному ключу каждой из трёх серий. Порядок поиска лицензии: сначала ключ `ORGL8`, затем `ORG8A`, затем `ORG8B`.
  - ⚠ в источнике неясно: в вводной фразе серии названы «ORGL8, ORGL8A и ORGL8B», а в перечне порядка поиска и в таблице маркировки — `ORGL8`, `ORG8A`, `ORG8B`. По таблице 10.2.2 верным выглядит второй вариант.
- Ключ 32-разрядного сервера: любое число 32-разрядных рабочих процессов на одном физическом компьютере.
- Ключ 64-разрядного сервера: любое число 32- и 64-разрядных рабочих процессов на одном физическом компьютере.
- **USB over IP не поддерживается** (проброс USB-устройства физического компьютера/хоста в виртуальную машину). Для работы в виртуальной машине рекомендуется либо СПЛ (раздел 10.3), либо сервис лицензирования кластера серверов, размещённый на физическом компьютере.
- Запоминается ключ, из которого пользователь получил лицензию при прошлом подключении: следующая попытка сначала идёт к нему. Если там лицензии нет — поиск свободной лицензии выполняется в обычном порядке (см. выше).

### 10.2.4. Защита от несанкционированного использования

- Платформа поставляется в защищённом виде; право использовать её на одном или нескольких рабочих местах, а также право использовать сервер определяются лицензионными соглашениями.
- Аппаратный ключ — одна из составных частей системы защиты.
- Лицензия на одно рабочее место (или одно дополнительное рабочее место): ключ вставляется в USB-порт самого компьютера (нужен драйвер защиты — см. 10.2.7).
- Дополнительная многопользовательская лицензия: ключ вставляется в USB-порт компьютера, на котором работает HASP License Manager (см. 10.2.8).
- Сведения о последних изменениях в системе защиты — в файле `readme.htm`.

### 10.2.5. Особенности учета клиентских лицензий

#### 10.2.5.1. Общая информация

Способ учёта зависит от вида клиента и от того, где расположен ключ с клиентскими лицензиями (локально или в сети). Сводка по подразделам:

| Сценарий | Кто считает лицензии | Расход |
|---|---|---|
| Локальный ключ (файловый и клиент-серверный вариант) | — | на компьютер: любое число экземпляров в режимах 1С:Предприятие и Конфигуратор |
| Многопользовательский ключ через HASP License Manager (файловый и клиент-серверный вариант) | HASP License Manager | на компьютер: столько компьютеров, на сколько пользователей ключ |
| Многопользовательский ключ, лицензии выдаёт сервер (клиент-серверный вариант) | менеджер кластера с сервисом сеансовых данных | на сеанс |
| Веб-клиент, мобильный клиент | модуль расширения веб-сервера (файловая ИБ) или сервер (клиент-серверная ИБ) | на сеанс |
| Тонкий клиент через веб-сервер | сам клиент (локальный/сетевой ключ) либо модуль расширения веб-сервера / сервер | на компьютер либо на сеанс соответственно |
| Автономный сервер | сам тонкий клиент либо автономный сервер | на компьютер либо на сеанс соответственно |

#### 10.2.5.2. Файловый вариант

##### 10.2.5.2.1. Локальный ключ

На компьютере с ключом можно запустить любое количество экземпляров системы в режиме 1С:Предприятие или Конфигуратор.

##### 10.2.5.2.2. Многопользовательский клиентский ключ, доступный по сети через HASP License Manager

- Одновременно работает столько компьютеров, на сколько пользователей рассчитан ключ; на каждом компьютере — любое число экземпляров в режиме 1С:Предприятие или Конфигуратор.
- Предел — суммарное количество лицензий со всех компьютеров сети, где установлен и настроен HASP License Manager.

#### 10.2.5.3. Клиент-серверный вариант

##### 10.2.5.3.1. Локальный ключ

Как в файловом варианте: любое число экземпляров (1С:Предприятие или Конфигуратор) на компьютере с ключом.

##### 10.2.5.3.2. Многопользовательский клиентский ключ, доступный по сети через HASP License Manager

Как в файловом варианте: число одновременно работающих компьютеров равно номиналу ключа, на компьютере — любое число экземпляров; общий предел — сумма лицензий со всех компьютеров сети с установленным и настроенным HASP License Manager.

##### 10.2.5.3.3. Локальный многопользовательский клиентский ключ без установленного HASP License Manager и многопользовательский клиентский ключ, доступный по сети через HASP License Manager

- Ключ может стоять на компьютере сервера «1С:Предприятия» (локальный многопользовательский клиентский ключ) или находиться в сети.
- Лицензии считает **менеджер кластера, на который назначен сервис сеансовых данных**.
- Расход: «один сеанс — одна лицензия». Два экземпляра «1С:Предприятия» на одном компьютере (любой режим запуска, любой вид клиента) = две лицензии.
- См. также 10.2.5.11 (совместное использование ключей).

#### 10.2.5.4. Веб-клиент

- Лицензии считает модуль расширения веб-сервера (файловая ИБ) или сервер «1С:Предприятия» (клиент-серверная ИБ).
- Ключ может стоять на компьютере с модулем расширения веб-сервера (или с сервером «1С:Предприятия») либо в сети.
- Расход: «один сеанс — одна лицензия». Два окна браузера с одной и той же базой на одном компьютере = две лицензии.
- См. также 10.2.5.11.

#### 10.2.5.5. Тонкий клиент, работающий через веб-сервер

Источники лицензии для тонкого клиента:

1. локальный ключ;
2. многопользовательский ключ, доступный клиенту по сети через HASP License Manager;
3. модуль расширения веб-сервера или сервер «1С:Предприятия».

- Если лицензию получает сам тонкий клиент (варианты 1–2) — на компьютере можно запускать любое число экземпляров в режиме 1С:Предприятие.
- Если лицензию выдаёт модуль расширения веб-сервера (файловая ИБ) или сервер (клиент-серверная ИБ) — считает он же, расход «один сеанс — одна лицензия» (два экземпляра на одном компьютере = две лицензии). Ключ при этом может стоять на компьютере модуля расширения веб-сервера (или сервера) либо в сети.
- См. также 10.2.5.11.

#### 10.2.5.6. Локальный ключ и веб-клиент

Если на компьютере сервера «1С:Предприятия» (или веб-сервера — для файловой ИБ) установлен **локальный** ключ, можно запустить:

- любое число конфигураторов на компьютере с ключом;
- любое число клиентских приложений (кроме веб-клиента) на других компьютерах — при условии, что им доступны клиентские лицензии;
- и для файловой, и для клиент-серверной ИБ (перечни в документации одинаковы):
  - одно произвольное клиентское приложение (включая веб-клиент) на любом компьютере, которому клиентский ключ недоступен;
  - любое число клиентских приложений (кроме веб-клиента) на компьютере с ключом.

Вывод документации: разработку и отладку с веб-клиентом можно вести, имея только локальный ключ. Ограничение: с локальным ключом запускается **только один** веб-клиент.

#### 10.2.5.7. COM-соединение

Порядок поиска лицензии:

| Шаг | 32-разрядное COM-соединение | 64-разрядное COM-соединение |
|---|---|---|
| 1 | локальные клиентские лицензии | локальные клиентские лицензии |
| 2 | локальные серверные лицензии (и 32-, и 64-разрядные) | локальная серверная лицензия (только 64-разрядная) |
| 3 | сетевые клиентские лицензии | сетевые клиентские лицензии |
| 4 | клиентские лицензии на сервере «1С:Предприятия» (клиент-серверный вариант) или на веб-сервере (файловая ИБ, подключённая через веб-сервер) | то же |

#### 10.2.5.8. Интернет-сервисы, фоновые задания

- Интернет-сервисам (Web-сервисы, HTTP-сервисы, запросы к OData) и фоновым заданиям **клиентские лицензии не нужны**.
- Но если база, публикующая интернет-сервисы, клиент-серверная, для работы сервера «1С:Предприятия» необходима серверная лицензия.

#### 10.2.5.9. Терминальный сервер

Только Windows (терминальные сессии), кратко.

##### 10.2.5.9.1. Локальный ключ

- В терминальной сессии локальный ключ **не работает** на клиентских ОС Microsoft Windows 7 и новее и на серверных ОС Microsoft Windows Server 2012 и новее.
- На более старых ОС локальный ключ позволяет работать только одному пользователю — подключившемуся к терминальной сессии с идентификатором 0 (любое число экземпляров в режиме 1С:Предприятие или Конфигуратор). В сессиях с идентификатором, отличным от 0, локальные ключи недоступны.

##### 10.2.5.9.2. Многопользовательский клиентский ключ

- Лицензии многопользовательского ключа, вставленного в терминальный сервер, доступны только если на терминальном сервере установлен и настроен HASP License Manager.
- Учёт — как для многопользовательского ключа через HASP License Manager; одним рабочим местом считается одна терминальная сессия.

#### 10.2.5.10. Мобильный клиент

- Лицензии считает: файловая ИБ — модуль расширения веб-сервера; клиент-серверная ИБ — сервер «1С:Предприятия».
- Ключ — на компьютере модуля расширения веб-сервера (или сервера) либо в сети.
- Расход «один сеанс — одна лицензия»: две копии приложения на одном мобильном устройстве, подключённые к одной базе, = две лицензии.
- Мобильный клиент **всегда** требует отдельную клиентскую лицензию из многопользовательского комплекта. Следствие: полноценно разрабатывать приложение для мобильного клиента, имея только локальный ключ, нельзя.
- См. также 10.2.5.11.

#### 10.2.5.11. Особенности совместного использования ключей защиты

- Когда клиентские лицензии считает сервер «1С:Предприятия» (или расширение веб-сервера), лицензии, у которых в программе **Aladdin Monitor** в колонке `Timeout` стоит 0, считаются занятыми. Поэтому не рекомендуется одни и те же многопользовательские ключи HASP одновременно использовать и через HASP License Manager, и через сервер (или расширение веб-сервера).
- Если в сети найдено несколько многопользовательских клиентских ключей серии `ORGL8`, сервер выберет один произвольный. После исчерпания его лицензий можно использовать один многопользовательский ключ `ORG8A`, затем один `ORG8B`.
- Если клиентское приложение выбрало тот же сетевой клиентский ключ, что и сервер, оно тоже может прекратить поиск лицензии в других доступных по сети ключах той же серии.

#### 10.2.5.12. Автономный сервер

Источники лицензии при работе с автономным сервером:

1. локальный ключ (только тонкий клиент);
2. многопользовательский ключ, доступный тонкому клиенту по сети через HASP License Manager;
3. сам автономный сервер «1С:Предприятия».

- Если лицензию получил сам тонкий клиент — на компьютере можно запускать любое число экземпляров в режиме 1С:Предприятие.
- Если лицензию выдаёт автономный сервер — расход «на сеанс». Ключ должен быть доступен тому экземпляру автономного сервера, который обслуживает данную базу, и у автономного сервера должна быть включена раздача лицензий — параметр `infobase.distribute-licenses` его конфигурационного файла.

### 10.2.6. Особенности получения серверной лицензии

#### 10.2.6.1. Кластер серверов

- Аппаратный ключ сервера ставится на компьютер, где выполняется хотя бы один рабочий процесс (`rphost`) кластера серверов. Рабочие процессы могут относиться к разным кластерам.
- Наличие серверной лицензии проверяется **в момент подключения клиентского приложения к рабочему процессу**.
- Серверный ключ — локальный, по сети недоступен.

#### 10.2.6.2. Автономный сервер

- Ключ ставится на компьютер, где выполняется экземпляр автономного сервера; ключ локальный, по сети недоступен.
- Автономный сервер проверяет серверную лицензию в двух случаях:

**Случай 1. База не файловая** и происходит любое из подключений:

| № | Подключение | Признак |
|---|---|---|
| 1 | клиентское приложение «1С:Предприятия» | — |
| 2 | утилита `ibcmd` к запущенному экземпляру автономного сервера на локальном компьютере | протокол IPC, параметр запуска `--pid` |
| 3 | утилита `ibcmd` к запущенному экземпляру автономного сервера на удалённом компьютере | протокол SSH, параметр запуска `--remote` |
| 4 | подключение к автономному серверу по протоколу SSH | — |

**Случай 2. База файловая** и с ней одновременно работает более 3 клиентских сеансов.

- С файловой базой при числе клиентских сеансов до 3 включительно автономный сервер серверную лицензию не требует и не проверяет. Сеансы фоновых заданий и интернет-сервисов в этот подсчёт технически не входят.
- Утилита `ibcmd` в offline-режиме (параметр запуска `--data`) при подключении к клиент-серверной базе **требует серверную лицензию**. Следствие: `ibcmd` в offline-режиме можно запускать только на компьютере, где доступна серверная лицензия.

### 10.2.7. Установка HASP Device Driver

Общие для всех ОС правила: сначала установить драйвер, потом вставлять ключ в USB; отсоединять ключ от USB-порта во время работы нельзя.

#### 10.2.7.1. Для ОС Windows

Только Windows, кратко:

- Программа установки драйвера `haspdinst.exe` входит в поставку и попадает на компьютер при установке кластера серверов; лежит в каталоге `\Program Files\1cv8\common\`.

- Вручную из командной строки:

```
haspdinst -i
```

```
haspdinst -r
```

`-i` — установка, `-r` — удаление драйвера.

#### 10.2.7.2. Для ОС Linux

Предварительно загрузить HASP Device Driver для Linux (адрес — см. 10.2.1). Все действия выполняются от имени администратора.

1. Распаковать архив:

```
tar xzf HASP_SRM_LINUX_3.50_Run-time_Installer_script.tar.gz
```

2. Перейти в каталог распакованного драйвера:

```
cd HASP_SRM_LINUX_3.50_Run-time_Installer_script
```

3. Установить драйвер (точка в конце команды обязательна):

```

```

Удаление драйвера — из того же каталога распакованного драйвера:

```

```

#### 10.2.7.3. Для ОС macOS

Кратко: загрузить драйвер для macOS, открыть архив в Finder, запустить `Install Sentinel Runtime Environment` и следовать мастеру. Удаление — файл `Uninstall Sentinel Runtime Environment` из того же архива. Правила про порядок «драйвер → ключ» и запрет отсоединения ключа те же.

### 10.2.8. Установка HASP License Manager

#### 10.2.8.1. Для ОС Windows

Только Windows, кратко:

- Установщик — утилита `lmsetup.exe` из поставки (на установочном диске; запускается из командной строки или из меню программы установки платформы). В документации показан пример для HASP License Manager версии 8.32.
- Ставится на любой компьютер локальной сети под Microsoft Windows: как приложение — везде, как служба — в Windows 2000 и старше (в Windows 98/Me выбор режима не предлагается, доступно только приложение).
- **Не рекомендуется** ставить менеджер лицензий на компьютер, используемый как терминальный сервер: возможна нестабильная работа.
- Шаги мастера: выбор языка (выбирается английский) → согласие с лицензией → режим установки (Application / Service) → каталог (при установке службой исполняемые файлы попадают в системный каталог Windows, в выбранный каталог — только файл помощи) → программная группа (по умолчанию новая группа `HASP License Manager`) → для приложения — предложение поместить ярлык в Автозагрузку (Startup), иначе запуск вручную → предложение установить HASP Device Driver (нужен менеджеру для работы с ключом HASP4 Net) → предложение запустить менеджер.
  - ⚠ в источнике неясно: фраза про уже установленный драйвер сформулирована как «повторная установка HASP License Manager не требуется» — по смыслу речь о повторной установке драйвера.

##### 10.2.8.1.1. Запуск HASP License Manager как приложения Microsoft Windows

Только Windows. Приложение запускается программой `nhsrvw32.exe`. Параметрами командной строки можно уточнить используемые сетевые протоколы; делать это имеет смысл лишь если режим по умолчанию даёт неустойчивую работу или заметные задержки при запуске защищённых программ. Перед каждым параметром ставится `-` или `/`:

```
nsrvw32 -tcpip
```

```
nsrvw32 /tcpip
```

⚠ в источнике неясно: исполняемый файл назван `nhsrvw32.exe`, а в примерах командной строки написано `nsrvw32` (без буквы h) — сохранено как в документации.

Параметры `nhsrvw32.exe`:

| Параметр | Назначение | Умолчание / примечание |
|---|---|---|
| `-addrpath=<path>` | каталог, куда сохраняется файл `haspaddr.dat` | по умолчанию — каталог, из которого загружен HASP License Manager |
| `-ipx` | использовать протокол IPX с SAP | — |
| `-ipxnosap` | использовать IPX без SAP | для Win32-версии другие протоколы подключаются параметрами `-tcpip` или `-netbios`; менеджер создаёт файл `newaddr.dat` с адресом станции, на которой он запущен, и обмениваться с ним данными смогут только защищаемые приложения, имеющие доступ к этому файлу |
| `-ipxsocket num=<number>` | сменить сокет, используемый менеджером для обмена данными | сокет по умолчанию — 7483 (шестнадцатеричное значение) |
| `-localnet` | обслуживать только станции локальной сети | запросам от станций вне локальной сети возвращается код ошибки 140 |
| `-nbname=<name>` | задать менеджеру имя NetBIOS | действие идентично `-nethaspnb name` |
| `-netbios` | использовать исключительно NetBIOS | для Win32-версии другие протоколы подключаются параметрами `-tcpip` или `-ipxnosap` |
| `-portnum=<number>` | сетевой порт менеджера при использовании TCP/IP | порт по умолчанию — **475** |
| `-srvname=<name> [,name]` | присвоить менеджеру одно или несколько имён IPX, TCP/IP или NetBIOS | не более шести имён |
| `-tcpip` | использовать исключительно TCP/IP | для Win32-версии другие протоколы подключаются параметрами `-ipx` или `-netbios` |
| `-use lananum=<x> [,x]` | работать с указанными номерами коммуникационного канала | — |
| `-userlist` | ограничить число пользователей, обслуживаемых менеджером | значение по умолчанию — **250** |

##### 10.2.8.1.2. Запуск HASP License Manager как службы Microsoft Windows

Только Windows: служба возможна лишь при установке в режиме службы (Windows 2000 и старше), ставится с автоматическим запуском. #### 10.2.8.2. Для ОС Linux

Предварительно загрузить HASP License Manager для Linux (адрес — см. 10.2.1); для его успешной работы нужно также установить драйвер ключа защиты (см. 10.2.7.2). Действия выполняются от имени администратора.

1. Скопировать загруженный файл в каталог, где будет жить менеджер (пример из документации — `/opt/hasplm`).

3. Добавить в `/etc/rc.local` (до строки `exit 0`) команду запуска из каталога распаковки — тогда менеджер будет стартовать автоматически при перезапуске системы:

```

4. Запустить менеджер:

```

Если нужна настройка через конфигурационный файл `nhsrv.ini`, путь к нему передаётся в командной строке менеджера:

### 10.2.9. Настройка системы «1С:Предприятие» для работы с HASP License Manager

- Для связи с HASP License Manager платформа может использовать протоколы IPX, TCP/IP или NetBIOS. По умолчанию протокол определяется автоматически, и этот режим рекомендован всегда, кроме случаев нестабильной работы автоопределения или существенных задержек.
- **Обращение к HASP License Manager всегда идёт по UDP.** Указание в `nethasp.ini` протокола TCP/IP игнорируется.
- Параметры взаимодействия задаются конфигурационным файлом `nethasp.ini` (полное описание — в другом разделе документации).

Пример `nethasp.ini` из документации:

```ini
[NH_COMMON]
NH_TCPIP=Enabled
[NH_TCPIP]
NH_SERVER_ADDR=192.168.0.12
NH_PORT_NUMBER=475
NH_TCPIP_METHOD=UDP
NH_USE_BROADCAST=Disabled
```

Что задаёт пример:

| Параметр | Значение в примере | Смысл |
|---|---|---|
| `[NH_COMMON]` / `NH_TCPIP` | `Enabled` | ⚠ в источнике неясно: в этой части назначение параметра отдельно не поясняется |
| `[NH_TCPIP]` / `NH_SERVER_ADDR` | `192.168.0.12` | адрес сервера защиты в сети |
| `NH_PORT_NUMBER` | `475` | сетевой порт |
| `NH_TCPIP_METHOD` | `UDP` | для работы используются UDP-пакеты |
| `NH_USE_BROADCAST` | `Disabled` | широковещательный механизм TCP/IP запрещён |

- При установке платформы образец `nethasp.ini` копируется в каталог конфигурационных файлов «1С:Предприятия». Образец почти целиком состоит из закомментированных строк и значений по умолчанию не меняет, зато содержит наиболее полный список параметров настройки взаимодействия с HASP License Manager.

## 10.3. Система программного лицензирования

### 10.3.1. Общая информация

#### 10.3.1.1. Описание и термины

- СПЛ обеспечивает совместную работу пользователей без физических устройств. Основа — **файл программной лицензии платформы**: в нём в зашифрованном виде лежат параметры лицензии и характеристики объекта, для которого она активирована.
- **Активация (привязка)** — получение файла программной лицензии по её характеристикам: серийному номеру комплекта и пинкоду.
- Привязать лицензию можно либо к параметрам компьютера, либо к ключу HASP, доступному на этом компьютере или по сети.
- В комплекте поставки несколько пинкодов; сколько их всего и сколько может быть активно одновременно — зависит от варианта лицензии (см. 10.3.2).

Как приложение (клиентское или серверное) получает лицензию:

1. ищет файлы лицензий по всем доступным путям (перечень путей — в другом разделе документации);
2. читает из файлов параметры лицензии и характеристики объекта привязки;
3. если характеристики из файла совпали с текущими параметрами объекта — проверяет количество пользователей и тип лицензии (клиентская/серверная); если не совпали — лицензия отвергается.

Доступ к файлу лицензии регулируется **правами операционной системы**: если пользователь, от имени которого работает приложение, не имеет доступа к файлу или к каталогу с ним, лицензия получена не будет.

#### 10.3.1.2. Виды программных лицензий

| Вид | Что разрешает |
|---|---|
| Однопользовательская клиентская | любое число клиентских приложений на одном компьютере |
| Многопользовательская клиентская | не более номинала лицензии одновременно запущенных клиентских приложений с произвольных компьютеров |
| Комбинированная клиентская | набор однопользовательских лицензий плюс одна многопользовательская; что активировано первым, то и выбрано: после первой однопользовательской многопользовательскую активировать нельзя, и наоборот |
| Серверная на 32-разрядный сервер | любое число 32-разрядных рабочих процессов (`rphost`) на одном компьютере |
| Серверная на 64-разрядный сервер | любое число 32- или 64-разрядных рабочих процессов (`rphost`) на одном компьютере |
| Серверная с ограниченным количеством одновременно обслуживаемых сеансов | один рабочий сервер любой разрядности (32 или 64) на одном компьютере |

#### 10.3.1.3. Размещение и совместное использование

- Многопользовательские лицензии размещаются на компьютере сервера «1С:Предприятия», модуля расширения веб-сервера или на терминальном сервере.
- На клиентском компьютере могут лежать **только однопользовательские** лицензии.
- Программные лицензии на сервере («1С:Предприятия» или терминальном) суммируются без ограничений.
- Программные лицензии можно сочетать с ключами HASP — лицензии складываются; расходуются сначала программные, потом лицензии из ключей HASP.

#### 10.3.1.4. Ключевые параметры

Привязка возможна к параметрам компьютера либо к ключу защиты HASP (локальному или сетевому, через менеджер лицензий). Привязывать можно к любому ключу HASP, который используется системой «1С:Предприятие». При активации «на компьютер» собираются сведения о нём — ключевые параметры.

**Привязка к компьютеру — ключевые параметры:**

| Параметр | Уточнение |
|---|---|
| наименование операционной системы | в Linux при проверке не анализируется (см. ниже) |
| версия операционной системы | для Windows учитываются только первые две цифры номера версии; в Linux при проверке не анализируется |
| серийный номер операционной системы | только Windows, кроме Windows 10 |
| дата установки операционной системы | только Windows, кроме Windows 10 |
| сетевое имя компьютера | — |
| модель материнской платы | — |
| объём оперативной памяти | — |
| тип и версия BIOS | — |
| список процессоров и их параметры | — |
| список сетевых адаптеров и их MAC-адреса | с исключениями, см. ниже |
| список жёстких дисков и их параметры | — |

Из сравнения сетевых адаптеров исключаются:

- адаптеры Bluetooth;
- адаптеры, подключённые по IEEE 1394 или USB;
- программные адаптеры WAN и RAS;
- адаптеры без MAC-адреса и без данных `VEN_` и `DEV_` из PNP-идентификатора.

Особенности привязки к компьютеру:

- Изменение хотя бы одного ключевого параметра требует повторной активации **с новым пинкодом**.
- Параметры компьютера опрашиваются не чаще одного раза в сутки.
- Внешние накопители, подключаемые по IEEE 1394 и USB, в сравнении не участвуют.
- **В ОС Linux** при сверке параметров лицензии с параметрами текущего компьютера наименование и версия операционной системы не анализируются.

**Привязка к ключу защиты HASP — ключевые параметры:** серия ключа, тип ключа, идентификатор ключа.

Особенности привязки к ключу HASP:

- Один пинкод позволяет активировать лицензию только с одним ключом HASP. Повторять активацию с теми же параметрами владельца и тем же ключом можно неограниченно, тем же пинкодом.
- При работе ищется строго тот ключ, к которому лицензия была привязана при активации.
- Если ключ доступен через менеджер лицензий, проверка привязки занимает **1 свободную лицензию на 1 секунду**; проверка выполняется не чаще одного раза в 20 секунд. Для устойчивой работы в сетевом ключе постоянно должна быть хотя бы одна свободная лицензия.
- Если в сети несколько ключей одной серии, для надёжной привязки рекомендуется явно указать нужный менеджер лицензий в `nethasp.ini` на компьютере, где лежит файл активированной программной лицензии.

#### 10.3.1.5. Доступная программная лицензия

Файл программной лицензии считается доступным, если одновременно:

1. он не в чёрном списке;
2. имеет корректный формат;
3. привязан к текущему компьютеру, либо на текущем компьютере доступен ключ HASP, к которому выполнена привязка;
4. содержит свободную лицензию;
5. в сети не используются другие файлы лицензий, полученные для тех же пинкода и серийного номера программы.

Про пункт 5:

- если такое дублирование в сети обнаружено — файл лицензии делается непригодным и попадает в чёрный список;
- если несколько файлов для одного серийного номера найдены **на одном компьютере** — в чёрный список они не заносятся, используется только один: созданный или использованный позднее всех.

Далее в документации «файл программной лицензии» и «программная лицензия» означают именно доступную лицензию в этом смысле.

#### 10.3.1.6. Программные лицензии и виртуальные машины

- Программную лицензию нужно активировать на каждый виртуальный компьютер.
- Привязка идёт к параметрам виртуальной машины — они эквивалентны параметрам реального компьютера (перечень в 10.3.1.4).
- Изменение этих параметров (например, при миграции ВМ или перераспределении нагрузки) потребует повторной активации на новый пинкод.

Рекомендации, чтобы избежать повторной активации:

1. использовать сервис лицензирования, размещённый на физическом компьютере или на ВМ с фиксированными характеристиками (возможно только в клиент-серверном варианте);
2. привязывать программную лицензию к аппаратному ключу HASP — ключ должен быть доступен на ВМ и до, и после миграции;
3. сочетать оба способа, если это возможно.

#### 10.3.1.7. Особенности использования и активации

Ограничения доступа к файлу лицензии:

| Ограничение | Предел |
|---|---|
| процессов из одного сеанса операционной системы, одновременно обращающихся к одному файлу программной лицензии | не более 256 |
| сеансов операционной системы на одном компьютере, из которых можно получить доступ к одному файлу программной лицензии | не более 256 |

Изменение ключевых параметров компьютера при лицензии, привязанной к компьютеру:

- Анализируется только **удаление** устройств, не добавление. Пример: при активации был один сетевой адаптер — второй добавить можно без повторной активации, а заменить один адаптер на другой нельзя.
- Оперативную память можно увеличивать, но нельзя уменьшать ниже объёма на момент активации. Пример: активация при 2 Гбайт → можно увеличить до 6 Гбайт, затем уменьшить до 4 Гбайт; уменьшение ниже 2 Гбайт потребует повторной активации.
- Сравнение всегда идёт между текущим состоянием компьютера и состоянием на момент активации лицензии.

Адреса для получения лицензии:

| Назначение | Адрес |
|---|---|
| Получение программной лицензии на электронном носителе, российская версия платформы | `https://portal.1c.ru/support/license/license-from-file?lang=LL` |
| То же, международная версия платформы | `https://portal.1c.eu/support/license/license-from-file?lang=LL` |
| Веб-сервис автоматического получения программной лицензии | `http://users.v8.1c.ru/LicenseCenter/ws/lm.1cws` |

- `LL` в адресах — двухбуквенный код локализации (нужен для корректной обработки зависящих от языка конструкций).
- Страница «license-from-file» принимает подготовленный файл запроса на лицензию, передаёт его в Центр лицензирования и возвращает файл данных лицензии.

См. также в документации: описание файла `nethasp.ini`; сервисы кластера — сервис лицензирования.

Серверная лицензия с ограниченным количеством сеансов:

- один рабочий сервер произвольной разрядности (32 или 64) на одном компьютере;
- одновременно обслуживается не более **5 клиентских сеансов и 1 сеанса конфигуратора**;
- клиентскими сеансами считаются: толстый клиент, тонкий клиент, веб-клиент, внешнее соединение;
- клиентским приложениям по-прежнему нужны клиентские лицензии, получаемые обычным способом.

### 10.3.3. Защита от несанкционированного использования

Платформа поставляется в защищённом виде; возможность использовать продукт на одном или нескольких рабочих местах и возможность использовать сервер «1С:Предприятия» определяются лицензионными соглашениями.

### 10.3.4. Особенности учета клиентских лицензий

#### 10.3.4.1. Общая информация

Учёт зависит от вида клиента и от места расположения файлов программных лицензий; варианты разобраны в подразделах.

#### 10.3.4.2. Файловый вариант

- Допустимы только однопользовательские лицензии: на компьютере с файлом лицензии запускается любое число экземпляров в режиме 1С:Предприятие или Конфигуратор.
- Исключение — терминальный режим: в нём с файловой базой можно использовать многопользовательские лицензии (подробности — в отдельном разделе документации, в эту часть не вошёл).

#### 10.3.4.3. Клиент-серверный вариант

##### 10.3.4.3.1. Однопользовательская программная лицензия

На компьютере с файлом лицензии — любое число экземпляров в режиме 1С:Предприятие или Конфигуратор.

##### 10.3.4.3.2. Многопользовательская программная лицензия

- Файлы программных лицензий лежат на компьютере, где установлен сервер «1С:Предприятия»; считает лицензии сам сервер.
- Расход «один сеанс — одна лицензия»: два экземпляра «1С:Предприятия» на одном компьютере (любой режим запуска, любой вид клиента) = две лицензии.

#### 10.3.4.4. Веб-клиент

- Считает лицензии модуль расширения веб-сервера (файловая ИБ) либо сервер «1С:Предприятия» (клиент-серверная ИБ).
- Файл программной лицензии лежит на компьютере модуля расширения веб-сервера либо на компьютере сервера «1С:Предприятия».
- Расход «один сеанс — одна лицензия» (два экземпляра на одном компьютере в любом режиме запуска и с любым видом клиента = две лицензии).

#### 10.3.4.5. Тонкий клиент, работающий через веб-сервер

Источники лицензии:

1. однопользовательская программная лицензия — на компьютере с файлом лицензии можно запускать любое число экземпляров в режиме 1С:Предприятие;
2. модуль расширения веб-сервера или сервер «1С:Предприятия» — считает модуль расширения (файловая ИБ) или сервер (клиент-серверная ИБ), расход «один сеанс — одна лицензия»; файл лицензии лежит на компьютере модуля расширения веб-сервера либо на компьютере сервера.

#### 10.3.4.6. Однопользовательская программная лицензия и веб-клиент

Если на компьютере сервера «1С:Предприятия» (или веб-сервера — для файловой ИБ) установлена **однопользовательская** программная лицензия, можно запустить:

- любое число конфигураторов на компьютере с файлом однопользовательской лицензии;
- любое число клиентских приложений (кроме веб-клиента) на других компьютерах, если им доступны клиентские лицензии;
- плюс **один из двух** вариантов:
  - одно произвольное клиентское приложение (включая веб-клиент) на любом компьютере, которому клиентская лицензия недоступна;
  - любое число клиентских приложений (кроме веб-клиента) на компьютере с файлом программной лицензии.

Вывод документации: разработку и отладку с веб-клиентом можно вести на одной однопользовательской программной лицензии. При этом, пока используется веб-клиент, на локальном компьютере можно запускать только конфигуратор — другие виды клиентов не запустятся.

#### 10.3.4.7. COM-соединение

Порядок поиска лицензии одинаков для 32- и 64-разрядного COM-соединения:

1. однопользовательские программные лицензии;
2. многопользовательские программные лицензии;
3. клиентские лицензии на сервере «1С:Предприятия» (клиент-серверный вариант) или на веб-сервере (файловая ИБ, подключённая через веб-сервер).

Особый случай: если COM-соединение запускается из кода, исполняемого на сервере «1С:Предприятия», как внутрипроцессный COM-сервер, и сервер работает по серверной программной лицензии — COM-соединение использует **серверную** программную лицензию. Во всех остальных случаях действует порядок поиска клиентской программной лицензии, приведённый выше.

*Конец части 1. Продолжение раздела 10.3.4 и далее — в части 2.*

## Что важно администратору Linux

1. **Серверная лицензия проверяется при подключении клиента к рабочему процессу.** Аппаратный серверный ключ — только локальный: он должен стоять на той же машине, где работает `rphost`, по сети он не раздаётся (10.2.6.1).
2. **USB over IP для ключей HASP не поддерживается.** Для сервера 1С в виртуальной машине документация рекомендует программные лицензии либо сервис лицензирования кластера на физическом компьютере (10.2.3, 10.3.1.6).
3. **Программная лицензия на ВМ привязана к параметрам ВМ.** Миграция или перераспределение ресурсов, меняющие ключевые параметры, приводят к повторной активации на новый пинкод; в серверном комплекте поставляется всего 3 пинкода, из них активен 1 (10.3.1.6, 10.3.2).
4. **Что ломает привязку к компьютеру.** Ключевые параметры: сетевое имя компьютера, модель материнской платы, тип и версия BIOS, процессоры, сетевые адаптеры с MAC-адресами, жёсткие диски, объём ОЗУ. По устройствам анализируется только удаление: добавить сетевой адаптер или нарастить память можно, а заменить адаптер или уменьшить ОЗУ ниже объёма на момент активации — нельзя (нужна повторная активация новым пинкодом). В Linux наименование и версия ОС при сверке не анализируются. Параметры опрашиваются не чаще раза в сутки (10.3.1.4, 10.3.1.7).
5. **Права на файл лицензии.** Лицензия не будет получена, если пользователь ОС, от имени которого работает приложение (в том числе сервер), не имеет доступа к файлу лицензии или к каталогу с ним (10.3.1.1).
6. **Дубли файлов лицензий опасны.** Если в сети используются разные файлы, полученные для одного пинкода и серийного номера, файл попадает в чёрный список. На одном компьютере дубли по одному серийному номеру в чёрный список не заносятся — берётся файл, созданный или использованный позднее всех (10.3.1.5).
7. **Многопользовательские программные лицензии кладутся на сервер** (сервер «1С:Предприятия», модуль расширения веб-сервера, терминальный сервер); на клиентском компьютере допустимы только однопользовательские. На сервере лицензии суммируются без ограничений, расход — «один сеанс — одна лицензия». При смешении с HASP сначала тратятся программные лицензии (10.3.1.3, 10.3.4.3.2).
8. **Интернет-сервисы (Web-сервисы, HTTP-сервисы, OData) и фоновые задания клиентских лицензий не требуют**, но клиент-серверной базе всё равно нужна серверная лицензия (10.2.5.8).
9. **`ibcmd` и серверная лицензия.** В offline-режиме (`--data`) с клиент-серверной базой `ibcmd` требует серверную лицензию, поэтому запускать его можно только там, где она доступна. Автономный сервер с нефайловой базой проверяет лицензию и при подключениях `ibcmd` через `--pid` (IPC) и `--remote` (SSH). С файловой базой до 3 клиентских сеансов включительно серверная лицензия автономному серверу не нужна (10.2.6.2).
10. **Драйвер HASP в Linux:** `tar xzf HASP_SRM_LINUX_3.50_Run-time_Installer_script.tar.gz` → `cd` в каталог → `./dinst .` (точка обязательна); удаление — `./dunst`. Сначала драйвер, потом ключ; на работающей системе ключ не вынимать (10.2.7.2).
11. **HASP License Manager в Linux:** архив `hasplm_linux_8.30.tgz`, каталог, например, `/opt/hasplm`, автозапуск строкой `/opt/hasplm/hasplm` в `/etc/rc.local` до `exit 0`, конфигурация — `/opt/hasplm/hasplm -c /etc/nhsrv.ini`. Для ключей на 300/500/1 000 пользователей проверить параметр `NHS_USERLIST` (10.2.8.2, 10.2.8.3).
12. **Сеть для HASP License Manager:** только IPv4; обращения всегда по UDP (указание TCP/IP в `nethasp.ini` игнорируется); порт по умолчанию 475. Адрес менеджера задаётся в `nethasp.ini` (`NH_SERVER_ADDR`, `NH_PORT_NUMBER`, `NH_TCPIP_METHOD`, `NH_USE_BROADCAST`); образец файла лежит в каталоге конфигурационных файлов платформы (10.2.1, 10.2.9).
13. **Не делить один многопользовательский ключ HASP между HASP License Manager и сервером 1С** (или расширением веб-сервера): лицензии с `Timeout` = 0 в Aladdin Monitor сервер считает занятыми. Несколько ключей одной серии на одном компьютере бесполезны — работает один (10.2.1, 10.2.5.11).
14. **Программная лицензия, привязанная к сетевому ключу HASP,** требует постоянно хотя бы одну свободную лицензию в этом ключе (проверка раз в 20 секунд занимает 1 лицензию на 1 секунду); при нескольких ключах одной серии нужный менеджер лицензий стоит явно прописать в `nethasp.ini` (10.3.1.4).
15. **Серверная лицензия с ограничением сеансов** — один рабочий сервер на компьютере, не более 5 клиентских сеансов (толстый, тонкий, веб-клиент, внешнее соединение) и 1 сеанс конфигуратора; клиентские лицензии при этом нужны отдельно (10.3.2).
