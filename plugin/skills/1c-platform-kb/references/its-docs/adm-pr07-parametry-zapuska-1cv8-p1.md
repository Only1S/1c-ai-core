## 7.1. Общая информация об интерфейсе командной строки системы

Командная строка есть у разных приложений системы: где-то это дополнение к графическому интерфейсу (интерактивная программа запуска), где-то единственный способ управления (неинтерактивная программа запуска, сервер «1С:Предприятия»).

Общий вид:

```
Приложение|URL [Режим] [Команда1 [Команда2 […]]]
```

| Элемент | Смысл |
|---|---|
| `Приложение` | Имя запускаемого приложения. Нужен ли полный путь, важен ли регистр и прочие особенности — зависит от ОС и среды. Для веб-клиента вместо имени приложения выступает URL опубликованной на веб-сервере информационной базы. |
| `Режим` | Необязательный параметр запуска (есть не у всех приложений). |
| `КомандаN` | Одна или несколько команд (действий) вместе с уточняющими параметрами. У команды могут быть обязательные и необязательные параметры и необязательное значение. Можно ли сочетать несколько команд в одной строке — зависит от приложения, режима и самих команд; встречаются взаимоисключающие команды (из перечня допустима только одна). |

Все элементы разделяются пробелом.

### Три способа записи команд и параметров

| Способ | Как пишется команда | Как пишется параметр | Где применяется (примеры из документации) |
|---|---|---|---|
| 1 | начинается с `/`. Исключение — веб-клиент: команда без `/`, команды разделяются символом `&` | начинается с `-` | сервер «1С:Предприятия» (`ragent`), пакетный запуск конфигуратора (`1cv8`) |
| 2 | без предваряющих символов | `--` для полного имени параметра, `-` для сокращённого | утилита `ring` |
| 3 | `--` для полного имени команды, `-` для сокращённого | — | утилита `cnvdbfl` |

Для каждого приложения документация сначала приводит общий вид его командной строки — по нему и определяется, какой способ записи используется.

### Обозначения в описаниях синтаксиса

| Обозначение | Смысл |
|---|---|
| пробел | разделитель элементов командной строки |
| `[` … `]` | необязательная часть. `/команда [-параметр]` допускает и `/команда`, и `/команда -параметр`; без параметра берётся его значение по умолчанию |
| `\|` | взаимоисключающие варианты: `/команда1\|/команда2` — допустима одна из двух, но не обе сразу |
| `<` … `>` | краткое описание значения, которое надо подставить. Сами скобки в реальную командную строку не переносятся: в большинстве командных интерпретаторов это перенаправление стандартных потоков ввода/вывода, и смысл команды радикально изменится |

Значения бывают не только у команд, но и у параметров команд.

### Значения с пробелами и экранирование

- Значение команды или параметра, содержащее пробелы, рекомендуется заключать в кавычки.
- Символ `"` внутри значения записывается как `\"`.
- Символ `\`, стоящий в значении перед `"`, записывается как `\\`.

Пример из документации: значение

```
ef \abc \\" " \
```

записывается так:

```
ef \abc \\\\\" \" \\
```

### Как читать описания команд (примеры из документации)

```
/TComp [-None|-Deflate|-SDC|-lz4|-zstd]
```

Команда `TComp` с одним из пяти необязательных параметров; допустима и без параметров (`/TComp`).

```
/VA<режим>
```

Значение (`<режим>`) пишется сразу после имени команды, без пробела.

```
/MergeCfg <имя cf-файла> -Settings <имя файла настроек> [-EnableSupport | -DisableSupport] [-IncludeObjectsByUnresolvedRefs | -ClearUnresolvedRefs] [-force]
```

Здесь: обязательное значение команды (`<имя cf-файла>`); обязательный параметр `-Settings` со своим значением; необязательный выбор одного из `-EnableSupport` / `-DisableSupport`; необязательный выбор одного из `-IncludeObjectsByUnresolvedRefs` / `-ClearUnresolvedRefs`; необязательный `-force`.

## 7.2. Выбор режима запуска

При запуске используется один из перечисленных режимов; несколько режимов одновременно указывать нельзя.

### 7.2.1. Запуск в режиме 1С:Предприятие

```
1cv8 ENTERPRISE [<параметры запуска>]
```

Параметры запуска — общие параметры запуска (в источнике — ссылка; по названию это раздел 7.3 «Общие команды запуска»).

### 7.2.2. Запуск в режиме Конфигуратора

```
1cv8 DESIGNER [<команды >]
```

В состав команд входят:

- общие команды;
- один из следующих наборов:
  - команды запуска конфигуратора;
  - команды создания файлов поставки и обновления;
  - команды работы с хранилищем конфигурации;
  - регистрация «1С:Предприятия» в качестве OLE-Automation-сервера.

(Для каждого набора в источнике — ссылка на другой раздел документации.)

### 7.2.3. Запуск в режиме создания информационной базы

```
1cv8 CREATEINFOBASE <строка соединения> [/AddToList [<имя ИБ>]] [/UseTemplate <имя файла шаблона>] [/Out <имя файла>] [/L<код языка>] [/VL<код локализации>] [/O<скорость соединения>] [/DumpResult <имя файла>]
```

| Параметр | Назначение | Значения / умолчание / примечание |
|---|---|---|
| `<строка соединения>` | Строка с параметрами доступа к базе данных | Обязательна. Формат строки соединения — ссылка на другой раздел документации |
| `/AddToList [<имя ИБ>]` | Добавить созданную базу в список баз под именем `<имя ИБ>` | Если имя не задано — берётся имя по умолчанию, такое же, как при интерактивном добавлении базы в список. Если параметр не указан — база в список не добавляется |
| `/UseTemplate <имя файла шаблона>` | Создать базу по шаблону | Шаблон — файл конфигурации (`.cf`) или файл выгрузки информационной базы (`.dt`). Если шаблон не указан — параметр игнорируется |
| `/L<код языка>` | Код языка интерфейса платформы | Перечень поддерживаемых языков — ссылка на другой раздел документации |
| `/VL<код локализации сеанса>` | Код локализации сеанса | Влияет на форматирование значений типов Число и Дата, а также на методы `ЧислоПрописью()` и `ПредставлениеПериода()` |
| `/DumpResult <имя файла>` | Записать результат создания базы в файл | Результат — число; `0` означает успех |
| `/Out <имя файла>` | В описании режима отдельно не разобран | Общая команда, см. 7.3.11 |
| `/O<скорость соединения>` | В описании режима отдельно не разобран | Общая команда, см. 7.3.1 |

Связанное ограничение (из описания `/DisableStartupDialogs`, 7.3.11): если диалоги отключены, а для кластера серверов задан администратор, попытка `CREATEINFOBASE` завершается ошибкой.

## 7.3. Общие команды запуска

### 7.3.1. Указание параметров подключения

| Команда | Назначение | Значения / умолчание / примечание |
|---|---|---|
| `/F <каталог>` | Файловая база: каталог, где находится файл базы данных `1Cv8.1CD` | — |
| `/S <адрес>` | Клиент-серверная база: адрес ИБ на сервере «1С:Предприятия» | Формат: `<имя компьютера сервера приложений>/<ссылочное имя ИБ в рамках сервера>`. Правила записи разделителя — ниже |
| `/IBName <имя информационной базы>` | Запуск базы по её имени в списке информационных баз | Подробности — ниже |
| `/IBConnectionString` | Строка соединения с ИБ целиком | Подробности — ниже |
| `/WS <url>` | Строка ws-соединения | — |
| `/O<скорость соединения>` | Скорость соединения (используется в тонком клиенте); служит для настройки элемента списка информационных баз | `Normal` — обычная скорость (по умолчанию); `Low` — низкая скорость |
| `/TComp [-None\|-Deflate\|-SDC\|-lz4\|-zstd]` | Режим сжатия трафика между сервером и тонким клиентом | Параметры — ниже. По умолчанию `-zstd` |
| `UsePrivilegedMode` | Запуск клиентского приложения в привилегированном режиме | Разрешено аутентифицированному пользователю с административными правами. В журнал регистрации попадает как установка режима привилегированного сеанса, так и отказ в ней. ⚠ в источнике записано без «/» |
| `/SLev<Уровень>` | Уровень защищённости соединения клиента с сервером «1С:Предприятия» | К тонкому клиенту не применимо. Значения — ниже. Без значения эквивалентно `/SLev0` |
| `/Z "<Общий реквизит 1>,<Общий реквизит 2>,...,<Общий реквизит N>"` | Установка значений разделителей при запуске клиентского приложения | Подробное описание — ссылка на другую книгу документации |

**`/S` — запись разделителя.** Между именем компьютера и именем базы должен стоять прямой слеш, либо всё значение берётся в кавычки:

| Запись | Где допустима |
|---|---|
| `server-pc/ibName` | в любой ОС |
| `server-pc\ibName` | только в ОС Windows |
| `"server-pc\ibName"` | в любой ОС |

**`/IBName`.** Программа запуска (или исполняемый файл конкретного клиента) ищет базу с таким именем в списке информационных баз:

- если баз с таким именем больше одной — запуск прекращается с сообщением об ошибке;
- если база найдена — выполняется попытка её запуска согласно остальным параметрам и выбранной программе запуска (исполняемому файлу клиента);
- кавычки в названии базы при указании в параметре удваиваются, пример из документации: `База ""СтройТоргВсе""`.

**`/IBConnectionString`.** Принимает строку соединения в том виде, в каком её возвращает функция `СтрокаСоединенияИнформационнойБазы()`.

- Отдельные части строки можно переопределить «старыми» параметрами командной строки; для этого `/IBConnectionString` должен стоять в командной строке раньше них.
- Строка соединения содержит кавычки, поэтому всю её нужно взять в кавычки, а внутренние кавычки удвоить.
- Описание строки соединения — ссылка на другой раздел документации.
- Дополнительные параметры строки соединения в режиме тонкого клиента:

| Параметр | Назначение |
|---|---|
| `wsn` | имя пользователя для аутентификации на веб-сервере |
| `wsp` | пароль пользователя для аутентификации на веб-сервере |
| `wspauto` | использовать автоматические настройки прокси-сервера |
| `wspsrv` | адрес прокси-сервера |
| `wspport` | порт прокси |
| `wspuser` | имя пользователя для прокси с авторизацией |
| `wsppwd` | пароль для прокси с авторизацией |

**`/TComp` — параметры** (указывается один):

| Параметр | Сжатие |
|---|---|
| `-None` | отключено |
| `-Deflate` | стандартное для протокола HTTP сжатие по алгоритму deflate |
| `-SDC` | собственный алгоритм сжатия |
| `-lz4` | алгоритм LZ4 |
| `-zstd` | алгоритм Zstandard — используется по умолчанию |

**`/SLev<Уровень>` — значения:**

| Значение | Смысл |
|---|---|
| `0` | незащищённое соединение |
| `1` | защищённое соединение только на время аутентификации |
| `2` | защищённое соединение в течение всего сеанса |

### 7.3.2. Настройка аутентификации

| Команда | Назначение | Значения / умолчание / примечание |
|---|---|---|
| `/N<имя>` | Имя пользователя ИБ | Указывается точно так, как в списке пользователей, созданном в Конфигураторе |
| `/P<пароль>` | Пароль пользователя из `/N` | Если пароля у пользователя нет — параметр можно опустить |
| `/ModifyPassword <пароль>` | Установить пользователю из `/N` новый пароль (значение команды) | Только совместно с `/N` и `/P`. При корректном пароле в `/P`: аутентификация → смена пароля → продолжение работы в сеансе |
| `/WA<режим>` | Аутентификация средствами ОС при запуске «1С:Предприятия» | `+` — обязательное применение аутентификации ОС; `-` — запрет. Если команда не указана, действует `/WA+` |
| `/WSA<режим>` | Аутентификация средствами ОС на веб-сервере | `+` — принудительная аутентификация ОС на веб-сервере (по умолчанию); `-` — запрет. Если не указано, действует `/WSA+` |
| `/WSN <имя>` | Имя пользователя ОС для аутентификации на веб-сервере | Используется при `/WSA+`; пароль задаётся в `/WSP` |
| `/WSP <пароль>` | Пароль пользователя из `/WSN` для аутентификации на веб-сервере | — |
| `/NoProxy` | Запретить использование прокси | Только для ws-соединения |
| `/Proxy -PSrv <адрес прокси> -PPort <порт> [-PUser <имя пользователя прокси> [-PPwd <пароль>]]` | Использовать заданные настройки прокси, игнорируя настройки по умолчанию | Только для ws-соединения |
| `/OIDA<режим>` | Сквозная (OpenID) аутентификация пользователя между разными ИБ и/или внешними ресурсами для тонкого и веб-клиента | `+` — использовать OpenID-аутентификацию (по умолчанию); `-` — не использовать. Подробности — ниже |
| `/AccessToken` | Передать JWT для аутентификации пользователя | — |
| `/Authoff` | Выполнить OpenID logout (завершение сеанса работы пользователя) для протоколов OpenID и OpenID Connect | Выполняется независимо от того, какой метод аутентификации используется дальше |
| `/SAOnRestart` | При перезапуске клиентского приложения из этого сеанса обязательно запрашивать имя пользователя и пароль | По умолчанию пароль не запрашивается. В тонком клиенте не используется |
| `/ResetSavedAuth` | Удалить из хранилища сохранённый токен повторного входа и имена всех запомненных пользователей ИБ, проходивших аутентификацию с этого компьютера | — |
| `/EmailAuth <email>` | Аутентификация через электронную почту: на адрес уходит код подтверждения, открывается окно для его ввода | Не поддерживается в пакетном режиме запуска конфигуратора и при запуске конфигуратора с запретом диалогов (`/DisableStartupDialogs`) |

**`/OIDA` — как работает.**

- Если `/OIDA` не задан или задан `/OIDA+`, клиент пытается аутентифицироваться через OpenID-провайдера, адрес которого указан в файле `default.vrd` публикации этой информационной базы.
- Если провайдер требует интерактивной аутентификации (первое обращение либо истёк срок жизни признака аутентифицированности), клиент показывает диалог ввода имени и пароля.
- Проверка идёт по списку пользователей информационной базы OpenID-провайдера.
- Пользователь базы, использующей OpenID-аутентификацию, должен совпадать по имени с пользователем информационной базы OpenID-провайдера.

### 7.3.3. Определение режима запуска

| Команда | Назначение | Значения / умолчание / примечание |
|---|---|---|
| `/AppAutoCheckVersion<режим>` | Автоматический подбор нужной версии платформы для каждой ИБ | `+` — подбирать версию при запуске (по умолчанию); `-` — не подбирать. `/AppAutoCheckVersion` без значения ≡ `/AppAutoCheckVersion+` |
| `/AppAutoCheckMode` | Автоматическое определение нужного клиентского приложения по данным ИБ (основной режим запуска конфигурации и режим запуска пользователя) | Алгоритм — ниже |
| `/RunModeOrdinaryApplication` | Запуск толстого клиента в обычном режиме, невзирая на настройки конфигурации и пользователя | В тонком клиенте не используется |
| `/RunModeManagedApplication` | Запуск толстого клиента в режиме управляемого приложения; при этом учитывается настройка клиента «Основной режим запуска» в списке информационных баз | Соответствие — ниже. Автоматический подбор клиентского приложения при этом отключается |
| `/AppArch <разрядность>` | Разрядность используемого клиентского приложения | `x86`, `x86_prt` (по умолчанию), `x86_64`, `x86_64_prt` — см. ниже |
| `/MainWindowMode <режим запуска>` | Явное указание режима основного окна клиентского приложения | `-Normal`, `-Workplace`, `-EmbeddedWorkplace`, `-FullscreenWorkplace`, `-Kiosk` — см. ниже |

**Алгоритм `/AppAutoCheckVersion`:**

1. Определяется версия запускаемой базы: для файлового варианта — по параметру `Version` файла `*.v8i`, для клиент-серверного — по ответу сервера «1С:Предприятия».
2. Для версий 8.1 и 8.0: находится расположение исполняемых файлов нужной версии и запускается соответствующий исполняемый файл. Для «1С:Предприятия 8.0» параметр командной строки `DESIGNER` заменяется на `CONFIG` (ради совместимости).
3. Для версии 8.2 и выше:
   - **указан полный номер версии** — нужная версия ищется среди установленных (параметры `InstalledLocation` конфигурационных файлов). Если она не установлена — ищется дистрибутив этой версии (параметры `DistributiveLocation`). Найдена — устанавливается; не найдена — запуск прекращается с сообщением об ошибке;
   - **указан неполный номер версии** — делается попытка получить полный номер из используемых версий (параметр `DefaultVersion` конфигурационных файлов). Если не удалось — определяются максимальный номер установленной версии (`InstalledLocation`) и максимальный номер версии, доступной для установки (`DistributiveLocation`). Если доступная для установки версия старше установленной — устанавливается версия с большим номером.

**Алгоритм `/AppAutoCheckMode`:**

1. Определяется режим запуска конкретного пользователя.
2. Определяется основной режим запуска запускаемой информационной базы.
3. Если определённый режим не соответствует запускаемому клиенту и у текущего пользователя есть право на запуск требуемого клиентского приложения — перезапускается нужное клиентское приложение той же версии. Иначе продолжается загрузка запущенного клиентского приложения.

**`/RunModeManagedApplication` — что запускается в зависимости от настройки «Основной режим запуска» в списке информационных баз:**

| Тонкий клиент | тонкий клиент |
| Веб-клиент | веб-клиент |
| Толстый клиент | толстый клиент в режиме управляемого приложения |

### 7.3.4. Работа с сертификатами

#### `/HttpsCert` — источник клиентского сертификата

```
/HttpsCert [-windows] [-linux] [-macos] [-recent] [-auto] [-choose] [-file <path>] [-pwd <password>] [-none]
```

| Параметр | Назначение | Когда игнорируется / примечание |
|---|---|---|
| `-windows` | Клиентский сертификат берётся из системного хранилища сертификатов ОС Windows | Игнорируется, если задан `-file` или `-none` |
| `-linux` | Сертификат берётся из специального каталога ОС Linux, где хранятся сертификаты (расположение — ссылка на другой раздел документации) | Игнорируется, если задан `-file` или `-none` |
| `-macos` | Клиентский сертификат берётся из системного хранилища сертификатов ОС macOS | Игнорируется, если задан `-file` или `-none` |
| `-recent` | Выбирать либо использовать ранее выбранный клиентский системный сертификат (Windows или macOS). Если подходящих сертификатов в пользовательском хранилище несколько — показывается системный диалог выбора; далее выбранный сертификат применяется автоматически | Режим по умолчанию для `-windows` и `-macos`, когда не заданы `-auto` и `-choose` |
| `-auto` | Использовать автоматически выбранный клиентский сертификат из системного хранилища Windows или macOS | Игнорируется без `-windows` / `-macos` (соответственно) |
| `-choose` | Всегда выбирать сертификат заново (Windows или macOS): при нескольких подходящих сертификатах системный диалог выбора показывается независимо от того, был ли сертификат выбран ранее. Выбранный сертификат потом может применяться автоматически через `-recent`. Нужен, чтобы уйти от автоматического использования ранее выбранного сертификата | Игнорируется без `-windows` / `-macos` или при заданном `-auto` |
| `-file <path>` | Использовать клиентский сертификат и приватный ключ из указанного файла | Игнорируется, если задан `-none` |
| `-pwd <password>` | Пароль файла с клиентским сертификатом и приватным ключом. Если сервер требует клиентский сертификат, а файл защищён паролем — соединение возможно только при верном пароле | Игнорируется без `-file` |
| `-none` | Клиентский сертификат не используется; соединение возможно только с серверами, которые не требуют проверки клиентского сертификата | — |

Если не задан ни один из параметров `-windows`, `-linux`, `-macos`, `-file`, `-none` — команда `/HttpsCert` игнорируется целиком.

| `-linux` | Сертификаты УЦ берутся из специального каталога ОС Linux, где хранятся сертификаты (расположение — ссылка на другой раздел документации) | Игнорируется, если задан `-file` или `-none` |
| `-macos` | Сертификаты УЦ берутся из системного хранилища сертификатов ОС macOS | Игнорируется, если задан `-file` или `-none` |

#### Принудительный выбор версии TLS

Относится к работе через веб-сервер по протоколу HTTPS.

| Команда | Действие |
|---|---|
| `/HttpsForceTLS1_0` | принудительно использовать TLS версии 1.0 |

#### `/ClearCache` — что очищается

- Кеш клиент-серверных вызовов (метаданные форм, модули и т. д.) — хранится в подкаталоге `vrs-cache`.
- Сохранённый индекс поиска по текстам модулей — лежит в каталоге `cfg-cache`. Индекс не удаляется, а очищается.

Расположение каталога данных приложения:

| ОС | Путь |
|---|---|
| Linux | `~/.1cv8/1C/1cv8/<UUID DB>` |
| macOS | `~/.1cv8/1C/1cv8/<UUID DB>` |
| Windows | `%LOCALAPPDATA%\1C\1cv8\<UUID DB>` |

`<UUID DB>` — уникальный идентификатор информационной базы; берётся из свойства `ID` файла списка информационных баз пользователя (файл с расширением `v8i`).

#### `/AllowExecuteScheduledJobs -Off|-Force` — логика

- Регламентные задания выполняются на первом по порядку запущенном клиенте, у которого не указано `/AllowExecuteScheduledJobs -Off`.
- Когда сеанс этого клиента завершается, выполнение переходит к какому-либо из остальных запущенных сеансов.
- Если запускается сеанс с `/AllowExecuteScheduledJobs -Force`, регламентные задания начинают выполняться в нём независимо от наличия других сеансов.

#### `/Execute` без параметров подключения к базе

Если имя файла внешней обработки указано, а параметры соединения с ИБ — нет, соединение выполняется со специальной информационной базой, предназначенной главным образом для запуска универсальных внешних обработок. Она находится в каталоге `<каталог ibases.v8i>/EmptyIB`, где `<каталог ibases.v8i>` — каталог с файлом списка информационных баз на компьютере пользователя (расположение — ссылка на другой раздел документации). Если такого каталога нет либо базы в нём нет — каталог создаётся (при необходимости), и в нём создаётся пустая информационная база.

#### `/URL <адрес>` — алгоритм

**Общая схема:**

- Значение — **внешняя ссылка** (содержит адрес информационной базы): на текущем компьютере ищется уже запущенное клиентское приложение, работающее с нужной базой, и в нём делается попытка открыть объект по навигационной ссылке. Если ни одно клиентское приложение эту базу не обслуживает — запускается новое с командой `/url`.
- Значение — **внутренняя ссылка**: значение игнорируется, выполняется обычный запуск клиентского приложения.

**Поиск клиентского приложения:**

- Ищется запущенное приложение, обслуживающее базу с указанной в значении строкой соединения.
  - Регистр имени хоста и имени базы не учитывается.
  - DNS-имя в IP-адрес (и обратно) не преобразуется: если клиент подключён по DNS-имени, а во внешней ссылке указан IP-адрес, приложение найдено не будет.
  - Учитываются значения разделителей, если они заданы параметром `Z`.
- Приложение найдено, модального окна или окна, блокирующего весь интерфейс, в нём нет — приложение активизируется и пытается перейти по внутренней ссылке, полученной из внешней.
- Приложение найдено, но в нём открыто модальное окно или окно, блокирующее весь интерфейс, — это приложение пропускается, поиск продолжается.
- Приложение не найдено — запускается новое клиентское приложение, которому в `/url` передаётся внутренняя навигационная ссылка, полученная из исходной. Если исходная внешняя ссылка содержала значения разделителей — они передаются запускаемому клиенту командой `/Z`.
- Если ссылка содержит только адрес информационной базы (например, `e1c://host/ib-name`), после открытия клиентского приложения больше ничего не делается.

**Переход по внутренней навигационной ссылке:**

- Попытка перехода выполняется после вызова обработчика `ПриНачалеРаботыСистемы`.
- Если клиент работает в режиме «Формы в отдельных окнах» и внутренняя ссылка — это ссылка на точку навигации, то вместо открытия рабочего стола выполняется переход по ссылке. В остальных случаях форма открывается после открытия рабочего стола.
- При ошибке выводится диагностическое сообщение, приложение продолжает работу.

**Сочетание с другими командами:**

- При наличии `/Execute` команда `/url` игнорируется.
- `/url` с абсолютной навигационной ссылкой отменяет параметры соединения с базой, заданные другими командами: игнорируются `/F`, `/S`, `/WS`, `/IBName`. Для `/IBConnection` игнорируются части строки соединения, описывающие информационную базу. (⚠ в источнике здесь написано `/IBConnection`, а в разделе 7.3.1 команда называется `/IBConnectionString`.)

**Схемы внешних навигационных ссылок:**

| Схема | Какие клиенты |
|---|---|
| `e1c:` | толстый и тонкий клиенты |
| `http:` или `https:` | только тонкий клиент |

**Эквивалентные способы перехода:**

- метод встроенного языка `ПерейтиПоНавигационнойСсылке()`;
- специальный диалог из окна со списком информационных баз;
- стандартная форма полнотекстового поиска (только для схемы `e1c:`).

#### `/@ <файл с командой>`

- Назначение — обойти ограничение ОС на длину командной строки.
- В файле команда записывается целиком, со всеми параметрами, **в одну строку**.
- Кодировка файла должна совпадать с кодировкой командного интерпретатора, из которого запускается клиентское приложение.
- При разборе содержимое файла полностью заменяет командную строку запускаемого приложения. Следствия:
  1. `/@` должна быть первой или единственной командой командной строки.
  2. Если `/@` указана не первой — поведение не определено.

#### `/Out <имя файла> [-NoTruncate]`

- Задаёт файл для вывода служебных сообщений.
- `-NoTruncate` (через пробел после имени файла) — файл не очищается. В тонком клиенте параметр не используется.
- Во время исполнения пакетных команд файл сообщений можно открывать для просмотра: в пакетном режиме запись в файл не буферизуется, сообщения пишутся сразу.
- Файл формируется в кодировке UTF-8.

#### `/DisableStartupMessages` — какие сообщения отключаются

1. Вопрос «Конфигурация базы данных не соответствует сохраненной конфигурации. Продолжить?».
2. Сообщение о том, что возможностей компьютера недостаточно для редактирования справки по конфигурации (требуется Microsoft Internet Explorer версии 7.0 или выше).
3. Сообщение о том, что возможностей компьютера недостаточно для редактирования html-документов, включая разделы справки (требуется Microsoft Internet Explorer версии 7.0 или выше), и что в этом запуске редактирование html-документов будет недоступно.

#### `/DisableStartupDialogs`

Поддерживается конфигуратором, тонким и толстым клиентскими приложениями. При использовании в командной строке клиентского приложения включается **пакетный режим запуска клиентского приложения** (ссылка на другой раздел документации).

Вместо диалога выдаётся ошибка, если:

- командной строки недостаточно для выбора информационной базы или определения режима запуска;
- командной строки недостаточно для авторизации пользователя в информационной базе;
- в командной строке ошибочная авторизация в хранилище конфигурации;
- выполняется попытка создать информационную базу (`CREATEINFOBASE`), а для кластера серверов задан администратор.

Если авторизация в хранилище конфигурации в командной строке отсутствует — конфигуратор запускается без связи с хранилищем.

#### `/DisableUnrecoverableErrorMessage`

При невосстановимой ошибке (в том числе при аварийном завершении):

- окно с сообщением об ошибке не показывается;
- дамп аварийного завершения формируется: в ОС Windows — по настройкам файла `logcfg.xml`, в ОС Linux и macOS — по настройкам операционной системы;
- отчёт об ошибке отправляется, если настроена автоматическая отправка и размер отчёта не превышает порог отправки без вопроса о большом размере — 5 Мбайт;
- приложение завершается с кодом возврата, отличным от нуля.

Рекомендуется указывать эту команду при запуске клиентского приложения в окружении, где нет пользователя, способного отреагировать на сообщение о невосстановимой ошибке.

## 7.4. Команды пакетного режима запуска конфигуратора

### 7.4.1. Общая информация

- Команды этого раздела и его подразделов **не комбинируются** в одной командной строке, если в описании прямо не сказано обратное.
- Чтобы включить пакетный режим: выбрать режим запуска Конфигуратора (`DESIGNER`), указать нужные общие команды запуска (раздел 7.3) и требуемую команду пакетного режима.

Пример из документации (выгрузка информационной базы):

```
1cv8 DESIGNER /IBName "My db" /DumpIB c:\temp\dump.dt
```

- Если команда требует имя файла и оно задано с полным путём — все каталоги этого пути должны существовать, иначе операция не выполнится.
- Модули, для доступа к которым нужен пароль, в пакетном режиме игнорируются; при обработке такого модуля формируется диагностическое сообщение.
- Если команда поддерживает и `-Extension`, и `-AllExtensions`, указывать оба параметра одновременно нельзя — поведение системы не определено.
- При работе с расширениями (`-Extension`, `-AllExtensions`) код возврата: `0` — успех, `1` — неуспех.

### 7.4.2. Выгрузка/загрузка информационной базы

| Команда | Назначение | Параметры / умолчание |
|---|---|---|
| `/DumpIB <имя файла>` | Выгрузить информационную базу в файл | — |
| `/RestoreIB <имя файла> [-JobsCount <Количество>]` | Загрузить информационную базу из файла | `-JobsCount` — число системных фоновых заданий, используемых для загрузки. По умолчанию `0`: берётся столько фоновых заданий, сколько процессоров на компьютере, выполняющем загрузку |

Ускорение загрузки достигается, когда:

- кластер серверов «1С:Предприятия» и сервер СУБД расположены на одном компьютере;
- компьютер сервера СУБД и кластер серверов связаны каналом с высокой пропускной способностью (1 Гбит и более).

### 7.4.3. Восстановление структуры информационной базы

```
/IBRestoreIntegrity
```

- Выполняется попытка восстановить структуру информационной базы. Прочие параметры, если они обнаружены, игнорируются.
- Чтобы получить результат, нужно указать команду `/Out`; в заданный ею файл попадает один из вариантов:

| Что записано в файл `/Out` | Смысл | Код возврата |
|---|---|---|
| «Восстановление информационной базы не требуется» | структура базы не нарушена | `0` |
| «Информационная база успешно восстановлена» | структура успешно восстановлена | `0` |
| текст ошибки | в ходе восстановления произошла любая ошибка | `1` |

- Запуск конфигуратора с `/IBRestoreIntegrity` рекомендуется, если предыдущее обновление конфигурации базы данных (пакетное или интерактивное) не было доведено до конца — например, из-за аварийного завершения конфигуратора или выключения компьютера.

### 7.4.4. Конфигурация и расширения

Краткий перечень команд подраздела (в пределах части 1):

| Команда | Назначение |
|---|---|
| `/DumpCfg` | сохранить конфигурацию или расширение в файл |
| `/LoadCfg` | загрузить конфигурацию или расширение из файла |
| `/MergeCfg` | объединить текущую конфигурацию или расширение с файлом по файлу настроек |
| `/CompareCfg` | сравнить две конфигурации и сформировать отчёт |
| `/UpdateDBCfg` | обновить конфигурацию базы данных |
| `/DumpDBCfg` | сохранить в файл конфигурацию базы данных (или расширение, сохранённое в базе) |
| `/DumpDBCfgList` | вывести имя основной конфигурации или имена расширений |
| `/RollbackCfg` | вернуться к конфигурации базы данных |
| `/DeleteCfg` | удалить расширение (расширения) |
| `/DumpConfigFiles` | выгрузить отдельные свойства объектов конфигурации в файлы |
| `/LoadConfigFiles` | загрузить отдельные свойства объектов конфигурации из файлов |
| `/DumpConfigToFiles` | выгрузить конфигурацию в файлы |
| `/LoadConfigFromFiles` | загрузить конфигурацию из файлов |
| `/GetConfigGenerationID` | получить идентификатор «поколения» метаданных конфигурации |

#### `/DumpCfg`

```
/DumpCfg <имя cf/cfe файла> [-Extension <Имя расширения>]
```

Сохраняет конфигурацию или расширение конфигурации в файл. Расширение сохраняется при корректно указанном параметре `-Extension`.

#### `/LoadCfg`

```
/LoadCfg <имя cf/cfe файла> [-Extension <Имя расширения>]
```

Загружает конфигурацию или расширение из файла.

- Расширение загружается при корректно указанном `-Extension`.
- Если расширения на момент загрузки в информационной базе нет — оно создаётся с указанным именем.
- Если расширение из `-Extension` подключено к хранилищу конфигурации — загрузить его невозможно.

#### `/MergeCfg`

```
/MergeCfg <имя cf- или cfe-файла> -Settings <имя файла настроек> [-EnableSupport | -DisableSupport] [-IncludeObjectsByUnresolvedRefs | -ClearUnresolvedRefs] [-Extension <Имя расширения>] [-force]
```

Объединяет текущую конфигурацию или расширение с файлом конфигурации или расширения, используя файл настроек.

| Параметр | Назначение |
|---|---|
| `<имя cf- или cfe-файла>` | файл с объединяемой конфигурацией (cf) или расширением (cfe) |
| `-Settings <имя файла настроек>` | файл с настройками объединения конфигураций (формат и описание — ссылка на другой раздел документации) |
| `-EnableSupport` | поставить конфигурацию на поддержку, если объединение с постановкой на поддержку возможно. Правила поддержки в этом случае должны быть заданы в файле настроек |
| `-DisableSupport` | не ставить на поддержку, даже если такая возможность есть |
| `-IncludeObjectsByUnresolvedRefs` | если на объекты, не включённые в список объединяемых и отсутствующие в основной конфигурации, есть ссылки из включённых объектов — такие объекты тоже помечаются для объединения, и объединение пытаются продолжить. Попытки повторяются, пока не кончатся объекты со ссылками на невключённые либо пока не будет выбрана вся конфигурация. Аналог кнопки «Пометить все для объединения» в окне неразрешённых ссылок, но с повтором попыток |
| `-ClearUnresolvedRefs` | ссылки на объекты, не включённые в список объединяемых, очищаются. Аналог кнопки «Продолжить» в окне неразрешённых ссылок |
| `-Extension <Имя расширения>` | имя расширения, с которым выполняется объединение |
| `-force` | выполнять объединение при наличии: (а) предупреждений об удаляемых объектах, на которые ссылаются объекты, не участвующие в объединении (такие объекты исключаются из объединения); (б) предупреждений о применении настроек. Без `-force` в этих случаях объединение прерывается |

Когда объединение прерывается с ошибкой:

- одновременно заданы `-EnableSupport` или `-DisableSupport` и параметр `-Extension`;
- поставить конфигурацию на поддержку можно, но не задан ни `-EnableSupport`, ни `-DisableSupport`;
- поставить конфигурацию на поддержку нельзя, но задан `-EnableSupport` или `-DisableSupport`.

Правила поддержки по умолчанию — применяются, если постановка на поддержку возможна, задан `-EnableSupport`, но в файле настроек нет элемента `SupportRules`:

| Группа объектов | Правило поставщика | Устанавливаемое правило поддержки |
|---|---|---|
| Новые объекты поставщика | Изменения разрешены | Объект поставщика не редактируется |
| Новые объекты поставщика | Изменения не рекомендуются | Объект поставщика не редактируется |
| Идентичные объекты либо объекты с правилом объединения «Взять из новой конфигурации поставщика» | Изменения разрешены | Объект поставщика не редактируется |
| Идентичные объекты либо объекты с правилом объединения «Взять из новой конфигурации поставщика» | Изменения не рекомендуются | Объект поставщика не редактируется |
| Изменённые объекты с правилом объединения, отличным от «Взять из новой конфигурации поставщика» | Изменения разрешены | Объект редактируется с сохранением поддержки |
| Изменённые объекты с правилом объединения, отличным от «Взять из новой конфигурации поставщика» | Изменения не рекомендуются | Объект редактируется с сохранением поддержки |

Прочее:

- Если в объектах объединяемой (второй) конфигурации найдены неразрешённые ссылки, а `-IncludeObjectsByUnresolvedRefs` / `-ClearUnresolvedRefs` не заданы — объединение прерывается; в файл служебных сообщений для каждого объекта выводятся список свойств с неразрешёнными ссылками и список невключённых объектов по этим ссылкам.
- Предупреждения выводятся в файл служебных сообщений независимо от `-force`.

#### `/CompareCfg`

```
/CompareCfg -FirstConfigurationType <тип конфигурации> [-FirstName <имя конфигурации>] [-FirstFile <путь к файлу>] [-FirstVersion <номер версии>] -SecondConfigurationType <тип конфигурации> [-SecondName <имя конфигурации>] [-SecondFile <путь к файлу>] [-SecondVersion <номер версии>] [-MappingRule <правило>] [-Objects <имя файла>] -ReportType <тип отчета> [-IncludeChangedObjects] [-IncludeDeletedObjects] [-IncludeAddedObjects] -ReportFormat <тип формата> -ReportFile <имя файла>
```

Сравнивает две конфигурации и формирует файл с отчётом о сравнении.

| Параметр | Назначение | Значения / умолчание / примечание |
|---|---|---|
| `-FirstConfigurationType <тип конфигурации>` | Тип первой сравниваемой конфигурации | См. таблицу типов ниже |
| `-FirstName <имя конфигурации>` | Имя первой конфигурации (дополнительный идентификатор) | Смысл зависит от типа: `VendorConfiguration` — имя конфигурации поставщика; `ExtensionConfiguration` — имя конфигурации поставщика (так в источнике, ⚠ в источнике неясно); `ExtensionDBConfiguration` — имя конфигурации расширения (из базы данных). Для остальных типов не применим |
| `-FirstFile <путь к файлу>` | Путь к файлу конфигурации (`.cf`) или расширения (`.cfe`) | Имеет смысл только при типе `File` |
| `-FirstVersion <номер версии>` | Версия хранилища конфигурации | Имеет смысл только при типах `ConfigurationRepository` и `ExtensionConfigurationRepository` |
| `-SecondConfigurationType <тип конфигурации>` | Тип второй сравниваемой конфигурации | Значения те же, что у `-FirstConfigurationType` |
| `-SecondName <имя конфигурации>` | Имя второй конфигурации | Аналогично `-FirstName` |
| `-SecondFile <путь к файлу>` | Путь к файлу `.cf` / `.cfe` | Аналогично `-FirstFile` |
| `-SecondVersion <номер версии>` | Версия хранилища конфигурации | Аналогично `-FirstVersion` |
| `-MappingRule <правило>` | Правило установки соответствия объектов, когда конфигурации не связаны отношением «родитель–потомок» | `ByObjectName` — по именам объектов (по умолчанию); `ByObjectIDs` — по внутренним идентификаторам |

#### `/UpdateDBCfg`

```
/UpdateDBCfg [-Dynamic<Режим>] [-BackgroundStart] [-BackgroundCancel] [-BackgroundFinish [-Visible]] [-BackgroundSuspend] [-BackgroundResume] [-WarningsAsErrors] [-Server] [-v1|-v2] [-Extension <Имя расширения>] [-SessionTerminate <режим>]
```

Обновляет конфигурацию базы данных.

- Перед реструктуризацией выполняется проверка подписи мобильного клиента (ссылка на другой раздел документации). Диагностические сообщения этой проверки по умолчанию считаются предупреждениями и обновление не блокируют.
- Фоновое обновление не связано с выбором механизма реструктуризации: если задано фоновое обновление, выбор `-v1|-v2` игнорируется.

| Параметр | Назначение | Значения / умолчание / примечание |
|---|---|---|
| `-Dynamic<Режим>` | Признак использования динамического обновления | `-` — динамическое обновление явно запрещено. `+` — разрешено: сначала попытка обычного обновления, при неудаче — попытка динамического. Динамическое обновление разрешено также, если параметр не указан вовсе или указан `-Dynamic` без режима |
| `-BackgroundStart` | Запустить фоновое обновление конфигурации БД и завершить работу | Если дополнительно указан `-Dynamic` или `-Dynamic+` — сначала попытка динамического обновления, при неудаче запускается фоновое |
| `-BackgroundCancel` | Отменить ранее запущенное фоновое обновление | — |
| `-BackgroundFinish [-Visible]` | Завершить фоновое обновление (фаза принятия изменений): попытка наложить монопольную блокировку базы данных и выполнить финальную фазу | С флагом `-Visible`, если завершить не удаётся, показывается диалог с кнопками «Отмена», «Повторить», «Завершить сеансы и повторить». Без флага — выполнение завершается с ошибкой |
| `-BackgroundSuspend` | Приостановить фоновое обновление | — |
| `-BackgroundResume` | Продолжить ранее приостановленное фоновое обновление | — |
| `-WarningsAsErrors` | Трактовать все предупреждения как ошибки | — |
| `-Server` | Выполнять обновление на сервере | Имеет смысл только в клиент-серверном варианте. Особенности с фоновым обновлением — ниже |
| `-v1\|-v2` | Используемый механизм реструктуризации | Если версия не указана — берётся та, что задана в файле `conf.cfg` на стороне клиентского приложения. Если указан оптимизированный механизм, но он конфликтует с другими параметрами — применяется обычный механизм |
| `-Extension <Имя расширения>` | Обновить указанное расширение | — |
| `-SessionTerminate <режим>` | Завершение активных сеансов, когда нужна эксклюзивная блокировка информационной базы | `disable` — не завершать сеансы принудительно (по умолчанию); `force` — завершать принудительно |

`-Server` совместно с фоновым обновлением:

- фаза актуализации всегда выполняется на сервере;
- фаза обработки и фаза принятия изменений могут выполняться и на клиенте, и на сервере;
- можно запустить фоновое обновление на клиенте, а завершить на сервере (и наоборот);
- оптимизированный механизм реструктуризации не используется (`-v2`, если задан, игнорируется).

Как выбирается механизм реструктуризации:

1. Механизм явно указан в командной строке — используется он.
2. Указания нет — используется механизм, заданный параметром `UpdateDBCfg` файла `conf.cfg` (на стороне клиентского приложения).
3. `-Server` в любом случае означает, что реструктуризация идёт на сервере; на выбор механизма реструктуризации эта команда не влияет.

#### `/DumpConfigToFiles`

```
/DumpConfigToFiles <каталог выгрузки> [-Format <режим>] [-Extension <Имя расширения>] [-AllExtensions] [-update] [-force] [-getChanges <имя файла>] [-configDumpInfoForChanges <имя файла>] [-listFile <имя файла>] [-configDumpInfoOnly] [-Server [-JobsCount <количество>]] [-Archive <имя файла>] [-ignoreUnresolvedReferences]
```

Выгружает конфигурацию в файлы.

| Параметр | Назначение | Значения / умолчание / ограничения |
|---|---|---|
| `-Format <режим>` | Формат выгрузки конфигурации в файлы | `Plain` — плоский формат; `Hierarchical` — иерархический (по умолчанию; описание — ссылка на другой раздел документации) |
| `-Extension <Имя расширения>` | Выгрузить указанное расширение | — |
| `-AllExtensions` | Выгрузить все расширения | Основная конфигурация при этом не выгружается. Каждое расширение выгружается в каталог со своим именем |
| `-update` | Обновить ранее сделанную выгрузку: выгружаются только объекты, версии которых отличаются от ранее выгруженных | Подробности — ниже |
| `-force` | Выполнить полную выгрузку, если при обновлении выгрузки обнаружено, что текущая версия формата выгрузки не совпадает с версией формата в файле версий (`ConfigDumpInfo.xml`) | Только вместе с `-update`; в остальных случаях игнорируется |
| `-getChanges <имя файла>` | Сформировать в указанном файле список изменений текущей конфигурации относительно выгрузки (и её файла версий), каталог которой задан значением команды `/DumpConfigToFiles` | Имя файла обязательно. Можно сочетать с `-configDumpInfoForChanges` — тогда изменения считаются относительно файла версий из этого параметра; если этот файл версий не найден — ошибка |
| `-configDumpInfoForChanges <имя файла>` | Файл версий (`ConfigDumpInfo.xml`), относительно которого сравниваются изменения | Обязательно полное имя файла версий. Используется только совместно с `-update` и `-getChanges` |
| `-listFile <имя файла>` | Файл со списком объектов, которые выгружаются независимо от того, менялись они или нет | Имя файла обязательно. Используется только отдельно от других параметров. Подробности — ниже |
| `-configDumpInfoOnly` | Сформировать только файл версий (`ConfigDumpInfo.xml`) | Сочетается только с `-format`: тогда файл версий формируется для указанного формата; по умолчанию — для иерархического. Сочетание с другими параметрами недопустимо |
| `-Server [-JobsCount <количество>]` | Выполнить выгрузку на стороне сервера «1С:Предприятия» — в многопоточном режиме, быстрее | `-JobsCount` — число одновременно работающих фоновых заданий для выгрузки на сервере; по умолчанию `0` — платформа определяет число автоматически по количеству ядер процессора на компьютере с кластером серверов |
| `-Archive <имя файла>` | Выгрузить конфигурацию в файл zip-архива | Применим для полной выгрузки, частичной выгрузки, выгрузки только файла текущего состояния (`-configDumpInfoOnly`), выгрузки всех расширений (`-AllExtensions`) |
| `-ignoreUnresolvedReferences` | Не выгружать ссылки на недостижимые объекты — то есть на объекты, удалённые в одной из предыдущих версий конфигурации | Поведение — ниже |

**`-update` — подробности.**

- Файл версий (`ConfigDumpInfo.xml`) берётся из текущего каталога выгрузки.
- Если текущая версия формата выгрузки не совпадает с версией формата в файле версий либо файл версий не найден — ошибка.
- По завершении выгрузки файл версий обновляется.
- Совместно с `-force`: при несовпадении версии формата выполняется полная выгрузка.
- Совместно с `-configDumpInfoForChanges`: если текущий каталог выгрузки перед началом не пуст — ошибка; соответствие версий формата выгрузки не проверяется; при выгрузке создаётся новый файл версий; файл, указанный в `-configDumpInfoForChanges`, не изменяется.

**`-listFile` — подробности.**

- Объекты из списка выгружаются полностью, кроме подчинённых объектов, являющихся отдельными объектами разработки, — такие подчинённые объекты нужно явно перечислить в списке.
- Если у объекта из списка есть подчинённые объекты, не являющиеся отдельными объектами разработки, но имеющие внешние свойства, — внешние свойства таких объектов тоже выгружаются.
- В файле можно использовать идентификатор `Configuration` — эквивалент корня конфигурации. Если за ним не следует имя корневого объекта конфигурации, он равнозначен полному имени корневого объекта: запись `Configuration.Help` эквивалентна `Configuration.ИмяКонфигурации.Help`.
- Обе формы записи можно смешивать. Пример из документации (выгрузка двух внешних свойств корневого объекта — `Help` и `Splash`):

```
Configuration.Help
Configuration.ИмяКонфигурации.Splash
```

**`-ignoreUnresolvedReferences` — что происходит с недостижимыми ссылками:**

| Где находится недостижимая ссылка | Что делается |
|---|---|
| ссылки на команды в управляемых формах | заменяются ссылкой по умолчанию |
| ссылки на группы команд в управляемых формах | не выгружаются |
| пути к данным в формах | не выгружаются |
| ссылки на предопределённые элементы | не выгружаются |
| ссылки в связях параметров выбора объектов метаданных | не выгружаются |
| ссылки в связях по типу объектов метаданных | не выгружаются |
| ссылки на команды в командном интерфейсе подсистем | не выгружаются |
| ссылки на группы команд в командном интерфейсе подсистем | заменяются на `ПанельНавигацииОбычное` |

- Если командный интерфейс подсистемы очищен полностью, последующая загрузка такого XML-файла в конфигурацию очистит внешнее свойство в соответствующем объекте метаданных, и при следующей выгрузке в XML файла этого внешнего свойства не будет.
- Сравнение исходной конфигурации с конфигурацией, загруженной из XML-файлов, выгруженных с этим признаком, может показать изменения объектов конфигурации — в том числе без детализации изменений.

См. также: файл `ConfigDumpInfo.xml` (ссылка на другой раздел документации).

#### `/LoadConfigFromFiles`

```
/LoadConfigFromFiles <каталог загрузки> [-Extension <Имя расширения>] [-AllExtensions] -files "<файлы>" -listFile <файлСписка> -Format <режим> [-updateConfigDumpInfo] [-NoCheck] [-Archive <имя ZIP-архива>] -partial
```

(Строка синтаксиса приведена как в источнике: параметры `-files`, `-listFile`, `-Format`, `-partial` показаны без квадратных скобок, хотя по описанию относятся к частичной загрузке; значение `-files` в источнике заключено в кавычки-«ёлочки».)

Загружает конфигурацию из файлов.

- Загрузка расширения в основную конфигурацию (и наоборот) не поддерживается.
- При **полной** загрузке формат (линейный или иерархический) определяется автоматически.
- При **частичной** загрузке автоопределение формата не поддерживается — формат нужно явно указать параметром `-Format`.

| Параметр | Назначение | Значения / умолчание / ограничения |
|---|---|---|
| `-Extension <Имя расширения>` | Загрузить указанное расширение | Если расширения нет — оно создаётся. Если расширение подключено к хранилищу — полная загрузка не поддерживается; частичная возможна, если загружаемые объекты захвачены в хранилище конфигурации расширения |
| `-AllExtensions` | Загрузить расширения из файлов: каждый подкаталог указанного каталога считается расширением | Несовместим с `-files` и `-listFile` |
| `-files "<файлы>"` | Перечень файлов для частичной загрузки | Каждый файл — с полным путём либо с путём относительно каталога загрузки. Список в кавычках, файлы через запятую. Несовместим с `-AllExtensions` |
| `-listFile <файлСписка>` | Файл со списком загружаемых файлов | По одному имени файла в строке; имя — полное либо относительно каталога загрузки. Строки разделяются переводом строки (поддерживаются варианты и Windows, и Linux). Кодировка файла — UTF-8. Пустые строки не поддерживаются. Строка, начинающаяся с `REM`, может быть пропущена. Несовместим с `-AllExtensions` |
| `-Format <режим>` | Формат выгрузки конфигурации в файлы | `Plain` — плоский; `Hierarchical` — иерархический (в источнике помечен как используемый по умолчанию). Параметр используется только вместе с `-files` или `-listFile` |
| `-updateConfigDumpInfo` | По окончании загрузки создать в каталоге файл версий (`ConfigDumpInfo.xml`), соответствующий загруженной конфигурации | При частичной загрузке (`-files` / `-listFile`) существующий файл версий обновляется |
| `-NoCheck` | Не проверять целостность загружаемой конфигурации | Сокращает время загрузки; применять, когда конфигурация заведомо целостная |
| `-Archive <имя ZIP-архива>` | ZIP-архив, из которого загружаются файлы | Должен быть указан либо каталог загрузки, либо этот параметр; одновременно каталог и `-Archive` указывать нельзя |
| `-partial` | Загружать только те элементы описания объекта конфигурации, которые указаны как файл | Таким файлом может быть: файл описания объекта метаданных (без его внешних свойств); файл внешнего свойства (форма и т. д.); файл модуля формы (без файла описания самой формы) |

- Если одновременно заданы `-files` и `-listFile` — используется тот, который стоит в командной строке первым.
- ⚠ в источнике неясно: общий текст требует явно указывать `-Format` при частичной загрузке, а в описании самого параметра иерархический формат назван используемым по умолчанию.

См. также: файл `ConfigDumpInfo.xml` (ссылка на другой раздел документации).

#### `/GetConfigGenerationID`

```
/GetConfigGenerationID [-Extension <Имя расширения>]
```

Возвращает идентификатор текущего «поколения» метаданных конфигурации.

- Идентификатор меняется при любом изменении самой конфигурации.
- Сравнивать идентификаторы на «больше/меньше» бессмысленно — только на «равно/не равно»: так проверяется, менялась ли конфигурация с момента предыдущего получения идентификатора.
- Для получения идентификатора обязательно указывать команду `/Out`.
- Вид идентификатора: `4d8d1d994cd4534c9accd32a5b44b35300000000`.
- Для пустой информационной базы: `0000000000000000000000000000000000000000`.
- `-Extension <Имя расширения>` — получить идентификатор метаданных указанного расширения; без параметра идентификатор берётся для основной конфигурации.

## Что важно администратору Linux

1. **Адрес базы в `/S` — через прямой слеш.** `server-pc/ibName` работает в любой ОС; вариант с обратным слешем без кавычек (`server-pc\ibName`) — только Windows. Если нужен обратный слеш — всё значение в кавычках.
2. **Угловые скобки из описаний в команду не переносить**: в командном интерпретаторе это перенаправление потоков. Значения с пробелами — в кавычках; `"` внутри значения пишется как `\"`, а `\` перед кавычкой — как `\\`. В `/IBName` и `/IBConnectionString` внутренние кавычки удваиваются.
3. **Запуск без оператора.** `/DisableStartupDialogs` заменяет стартовый диалог и диалоги аутентификации ошибкой (и включает пакетный режим клиентского приложения), `/DisableStartupMessages` убирает стартовые вопросы, `/DisableUnrecoverableErrorMessage` убирает окно невосстановимой ошибки и даёт ненулевой код возврата — эту команду документация рекомендует для окружений без пользователя.
4. **Дампы при аварийном завершении клиента на Linux** (при `/DisableUnrecoverableErrorMessage`) формируются по настройкам операционной системы, а не по `logcfg.xml` (так только в Windows).
5. **Журнал выполнения — `/Out <файл>`**: кодировка UTF-8, в пакетном режиме запись не буферизуется (файл можно читать по ходу выполнения), `-NoTruncate` не очищает файл. Текст результата `/IBRestoreIntegrity` и идентификатор от `/GetConfigGenerationID` выдаются через файл `/Out`.
6. **Все каталоги пути к файлу должны существовать** до запуска пакетной команды, иначе операция не выполнится. Команды пакетного режима (раздел 7.4) между собой не комбинируются, если это прямо не разрешено; `/UpdateDBCfg` разрешено указывать после `/LoadCfg`, `/UpdateCfg`, `/LoadConfigFiles`, `/LoadConfigFromFiles` и ряда других.
7. **Коды возврата.** Работа с расширениями (`-Extension` / `-AllExtensions`): `0` — успех, `1` — ошибка. Пакетная команда в целом: `0` / `1`, а `101` — ошибки в данных. `/IBRestoreIntegrity`: `0` — восстановление не потребовалось или выполнено, `1` — ошибка. `CREATEINFOBASE` с `/DumpResult <файл>` пишет в файл число, `0` — успех.
8. **`CREATEINFOBASE` и администратор кластера**: при отключённых диалогах (`/DisableStartupDialogs`) создание базы завершится ошибкой, если для кластера серверов задан администратор.
9. **Загрузка dt-файла: `/RestoreIB <файл> -JobsCount <N>`.** `0` (по умолчанию) — фоновых заданий столько, сколько процессоров на компьютере, выполняющем загрузку. Ускорение достигается, когда кластер 1С и сервер СУБД стоят на одном компьютере либо связаны каналом от 1 Гбит.
10. **Обновление конфигурации БД: `/UpdateDBCfg`.** `-Server` — выполнение на сервере (только клиент-серверный вариант); `-SessionTerminate force` — принудительно завершать сеансы для эксклюзивной блокировки (по умолчанию `disable`); `-WarningsAsErrors` — предупреждения как ошибки; `-Dynamic-` — запретить динамическое обновление (без параметра оно разрешено). Механизм реструктуризации `-v1|-v2` при отсутствии указания берётся из параметра `UpdateDBCfg` файла `conf.cfg` на стороне клиентского приложения; при фоновом обновлении выбор `-v1|-v2` игнорируется.
11. **После оборванного обновления конфигурации БД** (аварийное завершение конфигуратора, выключение компьютера) документация рекомендует запуск конфигуратора с `/IBRestoreIntegrity`.
12. **Вход в заблокированную базу** — `/UC <код доступа>`, если при установке блокировки соединений задан непустой код.
13. **Клиентский кеш на Linux** лежит в `~/.1cv8/1C/1cv8/<UUID DB>` (`<UUID DB>` — свойство `ID` из файла `v8i`); `/ClearCache` очищает кеш клиент-серверных вызовов (`vrs-cache`) и индекс поиска по текстам модулей (`cfg-cache`).
14. **Сертификаты на Linux.** У `/HttpsCert` и `/HttpsCA` параметр `-linux` берёт сертификаты из специального каталога ОС Linux; `-recent`, `-auto`, `-choose` относятся только к системным хранилищам Windows/macOS. `-file <path>` (+ `-pwd`) — сертификаты из файла; `/HttpsCA -none` отключает проверку сертификата сервера. Без указания источника (`-windows`/`-linux`/`-macos`/`-file`/`-none`) команда игнорируется. По умолчанию клиент начинает с TLS 1.3 и понижает версию по требованию веб-сервера; команды `/HttpsForceTLS1_*` между собой не сочетаются.
15. **Длинные командные строки** — через `/@ <файл>`: команда в файле записывается одной строкой, кодировка файла — как у командного интерпретатора, `/@` должна стоять первой (иначе поведение не определено). Файл списка для `/LoadConfigFromFiles -listFile` — UTF-8, переводы строк допускаются и Linux, и Windows, пустые строки не поддерживаются.
