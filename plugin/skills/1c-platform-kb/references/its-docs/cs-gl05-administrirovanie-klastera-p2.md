## 5.2.8. Работа со списком администраторов кластера

- У каждого кластера, зарегистрированного на центральном сервере, свой отдельный список администраторов. Смысл списка — чтобы административные действия с кластером могли выполнять только аутентифицированные пользователи.
- **По умолчанию список пуст, и в этом состоянии аутентификация администратора кластера не требуется вообще.**
- Где смотреть: дерево центральных серверов → сервер → кластер → ветка **Администраторы** (рис. 60). Администратор идентифицируется именем; в поле свойств выводятся имя и описание.

### 5.2.8.1. Добавление администратора кластера

Действие: ветка **Администраторы** → контекстное меню **Создать → Администратор** (или то же в главном меню). Открывается диалог свойств (рис. 61).

| Поле диалога | Назначение | Значения / умолчание / примечание |
|---|---|---|
| Имя | Имя администратора кластера | Должно быть уникальным в пределах кластера |
| Описание | Свободный текст | — |
| Аутентификация паролем | Флажок: разрешить вход по паролю | По умолчанию установлен |
| Пароль | Пароль администратора | — |
| Подтверждение пароля | Повтор пароля | — |
| Аутентификация паролем только с локального компьютера | Если флажок установлен, вход по паролю для этого администратора возможен только с компьютера (компьютеров), на которых работает кластер серверов | Снимать не рекомендуется: это снижает защищенность административных функций кластера |
| Аутентификация операционной системы | Флажок: разрешить аутентификацию средствами ОС | — |
| Пользователь | Пользователь ОС для аутентификации средствами ОС | Формат: `\\имя домена\имя пользователя`, пример `\\domainname\username`. Вводится вручную или выбирается кнопкой «…» из пользователей ОС, видимых с компьютера, где запущена утилита администрирования |
| Аутентификация открытым ключом | Флажок: вход в консоль кластера по паре «открытый ключ / закрытый ключ»; при входе пользователь предъявляет закрытый ключ своей пары | Документация рекомендует именно этот способ как наиболее безопасный |
| Открытый ключ | Открытый ключ пары, удостоверяющей данного администратора (заполняется, если включена аутентификация открытым ключом) | Пару можно создать любой утилитой генерации ключей; для Windows в документации названа `ssh-keygen.exe` |

Способы аутентификации администратора кластера (допускается несколько одновременно):

| Способ | Как происходит |
|---|---|
| Открытым ключом | Появляется диалог аутентификации: имя пользователя и путь к закрытому ключу |
| Паролем | Появляется диалог аутентификации: имя пользователя и пароль |
| Средствами ОС | Диалог не показывается, ничего вводить не нужно: система смотрит, от имени какого пользователя ОС выполняется подключение, и по нему определяет администратора кластера |

Важно: если у администратора не включен ни один вид аутентификации, он может выполнять только действия, не требующие аутентификации.

### 5.2.8.2. Просмотр и изменение свойств администратора кластера

- Выбрать администратора в списке → **Свойства** (рис. 62).
- Редактируется всё, кроме имени. Содержимое полей «Пароль» и «Подтверждение пароля» скрыто.

### 5.2.8.3. Удаление администратора кластера

- Выбрать администратора в списке → **Удалить**.

### 5.2.8.4. Аутентификация администратора кластера

- Запрашивается автоматически при попытке выполнить действие, требующее аутентификации, — но только если список администраторов кластера не пуст.
- Диалог аутентификации администратора кластера работает так же, как диалог аутентификации администратора центрального сервера (ссылка на другой раздел).

## 5.2.9. Просмотр списка менеджеров кластера

- Раздел посвящен просмотру списка менеджеров кластера (рис. 63). Хотя во вводной фразе документации упомянуто и «изменение» списка, фактически изменить можно только описание менеджера (см. ниже).
- По умолчанию есть один менеджер кластера — основной; он определен в любом кластере.
- **Количество и размещение менеджеров кластер определяет сам.** На это влияют:
  - требования назначения функциональности (ссылка на другой раздел);
  - свойства рабочего сервера **Менеджер под каждый сервис** и **Центральный сервер** (ссылка на другой раздел).
- Вручную добавлять и удалять менеджеры кластера администратор не может.
- Команда **Свойства** в контекстном меню менеджера открывает окно (рис. 64), где можно изменить описание менеджера.

## 5.2.10. Просмотр списка рабочих процессов

Два варианта отображения:

| Область | Путь в дереве центральных серверов |
|---|---|
| Весь кластер | сервер → кластер → ветка **Рабочие процессы** (рис. 65) |
| Один рабочий сервер | сервер → кластер → нужный сервер кластера → ветка **Рабочие процессы** (рис. 66) |

- Рабочий процесс идентифицируется именем сервера и порядковым номером в пределах этого рабочего сервера.
- **Вручную добавлять и удалять рабочие процессы администратор не может.**
- Доступна команда **Выключить** (контекстное меню процесса или Главное меню → Действия): инициирует выключение рабочего процесса. Как именно проходит выключение, описано в другом разделе — в описании параметра **Расписание перезапуска** (ссылка на другой раздел).
- Команда **Свойства** открывает диалог свойств рабочего процесса (рис. 67). Все поля только для чтения.

Свойства рабочего процесса:

| Поле | Что показывает |
|---|---|
| Компьютер | Рабочий сервер, на котором выполняется процесс |
| Включен | Процесс сейчас включен и может использоваться системой |
| Активен | Процесс сейчас используется и активен |
| Резервный | Процесс сейчас является резервным (ссылка на другой раздел) |
| Время запуска | Время последнего запуска процесса |
| IP порт | Сетевой порт процесса; выделяется динамически при запуске из диапазона сетевых портов, заданного для данного сервера |
| Соединений | Текущее число соединений, обслуживаемых процессом |
| PID процесса ОС | Номер процесса в терминах операционной системы, под управлением которой он выполняется |
| Занято памяти | Объем памяти, занятый процессом |
| Доступная производительность | Текущая доступная производительность (ссылка на другой раздел) |
| Реакция сервера | Среднее время обслуживания одного соединения. Равно сумме трех следующих полей: «Затрачено сервером» + «Затрачено СУБД» + «Затрачено менеджером блокировок» |
| Затрачено сервером | Среднее время, которое на одно соединение тратит сам рабочий процесс |
| Затрачено СУБД | Среднее время, которое на одно соединение тратит СУБД |
| Затрачено менеджером блокировок | Среднее время, которое на одно соединение тратит менеджер блокировок |
| Клиентских потоков | Среднее число клиентских потоков, обработанных процессом; используется системой при вычислении производительности рабочего процесса (ссылка на другой раздел) |
| Серверная лицензия | Какая серверная лицензия используется этим рабочим процессом и ее характеристика; формат строки описан в другом разделе (ссылка) |

## 5.2.11. Работа со списком сеансов

### 5.2.11.1. Общая информация

Два варианта отображения:

| Область | Путь в дереве центральных серверов |
|---|---|
| Весь кластер | центральный сервер → кластер → ветка **Сеансы** (рис. 68) |
| Одна информационная база | центральный сервер → кластер → информационная база → ветка **Сеансы** (рис. 69) |

Колонки списка сеансов (в документации упорядочены по имени; имена приведены точно как в источнике, включая разнобой «5 мин.» / «5 мин» / «5 минут»):

|---|---|---|

| Время вызова СУБД (5 мин.) | Время обращений к СУБД в завершенных серверных вызовах за последние 5 минут | секунды |
| Время вызова СУБД (всего) | То же с момента старта сеанса | секунды |
| Время вызова СУБД (текущее) | Время обращения к СУБД с начала текущего незавершенного серверного вызова | секунды |
| Время вызовов (5 мин.) | Время завершенных серверных вызовов сеанса за последние 5 минут | секунды |
| Время вызовов (всего) | Суммарное время завершенных серверных вызовов с момента старта сеанса | секунды |

| Время вызовов сервисов (всего) | То же с начала сеанса | секунды |
| Время вызовов сервисов (текущее) | Время работы сервиса кластера в текущем незавершенном вызове | секунды; имя сервиса — в колонке «Текущий сервис» |
| Время начала | Когда создан сеанс | — |
| Данных СУБД (5 минут) | Объем данных, переданных между сервером «1С:Предприятия» и сервером БД в завершенных вызовах за последние 5 минут | байты |
| Данных СУБД (всего) | То же в завершенных серверных вызовах с начала сеанса | байты |
| Заблокировано СУБД | Номер сеанса, установившего блокировку, — если данный сеанс ждет освобождения автоматической транзакционной блокировки, установленной СУБД в транзакции другого сеанса | В остальных случаях пусто |
| Заблокировано упр. | Номер сеанса, установившего блокировку, — если данный сеанс ждет освобождения управляемой транзакционной блокировки, установленной сервисом транзакционных блокировок в транзакции другого сеанса | В остальных случаях пусто |
| Завершить через | Через сколько будет завершен спящий сеанс | секунды |
| Запись (5 мин) | Объем данных, записанных на диск завершенными вызовами сеанса за последние 5 минут | байты |
| Запись (всего) | То же с начала сеанса | байты |
| Запись (текущая) | Объем данных, записанных на диск с начала текущего вызова | байты |
| Заснуть через | Через сколько неактивный сеанс будет переведен в спящий режим | секунды |
| Захвачено СУБД | Сколько времени сеанс удерживает соединение с базой данных (от момента захвата до текущего момента) | Показывается только если соединение с СУБД захвачено сеансом |
| Информационная база | Имя информационной базы | — |

| Память (5 мин) | Разность между занятой и освобожденной памятью у потоков, выполнявших завершенные вызовы сеанса, за последние 5 минут | байты |

| Память (текущая) | Та же разность для потока, выполняющего текущий вызов, с начала этого вызова | байты |
| Пользователь | Имя пользователя информационной базы | — |
| Порт | Сетевой порт рабочего процесса, обслуживающего сеанс | — |
| Последняя активность | Время последней зафиксированной активности сеанса | — |

| Процессорное время (5 мин) | Процессорное время, израсходованное завершенными серверными вызовами сеанса за последние 5 минут | с точностью до миллисекунд |
| Процессорное время (всего) | То же за всё время жизни сеанса | с точностью до миллисекунд |
| Процессорное время (текущее) | Процессорное время текущего незавершенного серверного вызова | с точностью до миллисекунд |
| Сервер | Имя сервера кластера, с которым установлено соединение | — |
| Соединение | Номер соединения, подключенного к сеансу | — |
| Соединение с СУБД | Идентификатор процесса сервера баз данных | Показывается только пока соединение с БД захвачено сеансом: идет вызов СУБД, либо открыта транзакция, либо удерживается объект `МенеджерВременныхТаблиц`, в котором создана хотя бы одна временная таблица |
| Спящий | Признак того, что сеанс спящий | — |
| Текущий сервис | Имя сервиса кластера, который выполняется в данный момент | Пусто — значит сейчас никакой сервис кластера не работает |
| Чтение (5 мин) | Объем данных, прочитанных с диска завершенными вызовами сеанса за последние 5 минут | байты |
| Чтение (всего) | То же с начала сеанса | байты |
| Чтение (текущее) | Объем данных, прочитанных с диска с начала текущего незавершенного серверного вызова | байты |
| Язык | Язык локализации приложения | — |

Примечание документации: все три показателя «Процессорное время» выводятся в секундах с тремя знаками после запятой (то есть с точностью до миллисекунд).

### 5.2.11.2. Просмотр свойств сеанса

Выбрать сеанс в списке → **Свойства** (рис. 70). Все свойства только для чтения.

| Свойство | Что показывает |

| Компьютер | Сетевое имя компьютера пользователя. Пусто для веб-клиента, тонкого клиента через веб-сервер и Web-сервиса |
| Начало сеанса | Когда создан сеанс |
| Номер сеанса | Номер сеанса |
| Номер соединения | Номер соединения, подключенного к сеансу |
| Пользователь | Имя пользователя информационной базы |
| Порт | Сетевой порт рабочего процесса, обслуживающего сеанс |
| Последнее обращение | Время последней зафиксированной активности сеанса |
| Приложение | Режим запуска клиентского приложения (ссылка на другой раздел) |
| Процесс ОС | Номер (в терминах ОС) процесса рабочего сервера, обслуживающего сеанс |
| Рабочий сервер | Имя сервера кластера, с которым установлено соединение |
| Язык интерфейса | Язык локализации клиентского приложения |

Откуда берется «IP Клиента»:

| Способ подключения | Источник IP-адреса |
|---|---|
| Через веб-сервер | Из заголовков веб-сервера. Если перед веб-сервером стоит reverse proxy, на нем нужно настроить заголовок `X-Forwarded-For` |
| Напрямую к кластеру серверов | Из свойств TCP-соединения |
| Фоновое задание | Информация недоступна |

### 5.2.11.3. Завершение сеанса

Администратор может сделать с сеансом два действия (рис. 71):

| Действие | Что происходит | Ограничения |
|---|---|---|
| Прервать серверный вызов текущего сеанса | Прерывается только выполняющийся серверный вызов; клиентский сеанс при этом не завершается | Доступно только для клиентских приложений: тонкий клиент, веб-клиент, мобильный клиент. Возможно только тогда, когда клиентский сеанс инициирует исполнение кода на встроенном языке на стороне сервера |
| Удалить текущий сеанс | Сначала прерывается текущий серверный вызов, затем сеанс удаляется. Если в этот момент сеанс назначен соединению — выполняется попытка разрыва соединения (см. 5.2.12.3) | — |

Детали:

- Фактически прерывание срабатывает в момент перехода исполнения на следующую строку кода на встроенном языке.
- Обе команды (и прерывание вызова, и удаление сеанса) предлагают ввести текст сообщения, которое увидит пользователь (рис. 72).
- Если текст не задан, пользователь, чей серверный вызов прерван, получит стандартное сообщение: `Выполнение текущей операции прервано администратором`.
- Если в удаляемом сеансе нет серверного вызова, сеанс удаляется без каких-либо сообщений пользователю. При следующем действии в клиентском приложении, использовавшем этот сеанс, пользователь получит стандартную ошибку: `Сеанс отсутствует или удален`.
- Предупреждение документации: оба инструмента применять осторожно — возможна потеря данных, которые в этот момент обрабатывает пользователь.
- Для прерывания серверного вызова и для завершения сеанса нужны полномочия администратора кластера серверов (ссылка на другой раздел).

- Каждое следующее соединение с информационной базой получает номер на 1 больше предыдущего.

### 5.2.12.3. Разрыв соединения

Действие: выбрать соединение в списке → **Удалить** (рис. 79).

Предупреждение документации: применять осторожно — разрыв соединения активно работающего пользователя может привести к потере данных.

Поведение зависит от того, чем занято соединение:

| Ситуация | Что делает сервер «1С:Предприятия» | Условия / результат |
|---|---|---|
| Выполняется длительный запрос к БД **Microsoft SQL Server, IBM Db2 или Oracle Database** | Пытается разорвать соединение | Успех — только если у пользователя, от имени которого выполняется подключение к серверу БД, есть соответствующие права (какие именно — по документации СУБД). При успехе пользователь получает сообщение `Сеанс работы завершен администратором` |
| База данных — **PostgreSQL** (в источнике оговорка дана в том же абзаце о длительном запросе к СУБД) | **Ничего.** Для базы данных PostgreSQL удаление соединения невозможно | При попытке выполнить команду удаления никакие действия не производятся |
| Клиент выполняет код на сервере «1С:Предприятия» | Пытается разорвать соединение клиентского приложения с сервером | Нужны полномочия администратора кластера серверов (ссылка на другой раздел) **и** администратора информационной базы. При успехе пользователь получает сообщение `Сеанс работы завершен администратором` |

Когда соединение разорвать нельзя: сервер исполняет клиентский вызов, и исполнение не покидает одну строку кода на встроенном языке (исключение — обращение к СУБД). Примеры из документации: долгий вызов метода COM-объекта; выполнение http-вызова из кода на встроенном языке.

| Доступные для расширения модули | Перечень модулей, которые разрешено расширять расширениями | Подробности — в другом разделе (ссылка) |
| Недоступные для расширения модули | Перечень модулей, которые запрещено расширять расширениями | Подробности — в другом разделе (ссылка) |

Флажки-разрешения профиля (⚠ общий заголовок этой группы в текстовой копии источника не сохранился; названия приведены как в источнике — все начинаются с «к …»):

| Параметр | Что определяет | Примечание |
|---|---|---|
| к файловой системе сервера | Доступ прикладного решения к файловым ресурсам компьютера, на котором работает сервер «1С:Предприятия» | — |
| к объектам COM | Взаимодействие прикладного решения с COM-объектами компьютера сервера | **Для серверов под управлением ОС Linux параметр не имеет смысла** |
| к внешним компонентам | Возможность прикладного решения работать с внешними компонентами на стороне сервера | — |
| к внешним модулям | Возможность использовать внешние модули (внешние отчеты, внешние обработки, расширения конфигурации), а также оператор `Выполнить()` и функцию `Вычислить()` | — |
| к приложениям операционной системы | Доступность прикладному решению приложений ОС на стороне сервера | Перечень приложений зависит от ОС, под управлением которой работает сервер «1С:Предприятия» |
| к ресурсам интернет | Возможность кода прикладного решения, исполняемого на сервере, обращаться к ресурсам сети Интернет | — |
| к привилегированному режиму | Режим проверки прав доступа (и работу ограничений доступа к данным), когда текущий сеанс начинает работать под управлением профиля безопасности | Связан со свойством «Роли привилегированного режима» |
| к функциям криптографии | Возможность использовать механизмы криптографии в коде прикладного решения, исполняемом на сервере | — |
| к расширению прав доступа | Возможность расширить права доступа основной конфигурации для любого объекта расширяемой конфигурации | Подробности — «в книге» (так в источнике) |
| к расширению всех модулей | Возможность расширения всех серверных модулей конфигурации любым расширением | — |

Для каждого из параметров документация отсылает к подробному описанию в другом разделе (общее описание профиля безопасности); в этой части главы подробностей нет.

### 5.2.14.2. Просмотр и изменения параметров профиля

- Выбрать профиль в списке → **Свойства** → диалог редактирования свойств (рис. 86).
- Часть параметров профиля допускает **исключения из общего запрета**. Пример из документации: запретить доступ ко всем каталогам файловой системы сервера, кроме нескольких, перечисленных в списке исключений.
- Как задать исключение: встать в дереве на нужный подчиненный элемент и выбрать в контекстном меню **Создать → <имя создаваемого элемента>**, например **Создать → Виртуальный каталог**. ⚠ В источнике неясно: элемент назван подчиненным «выбранному виртуальному каталогу», хотя по смыслу речь об элементе, подчиненном выбранному профилю безопасности.
- В открывшемся окне свойство **Описание** — пояснение к создаваемому элементу; остальные параметры описаны в соответствующем разделе общего описания профиля безопасности (ссылка на другой раздел).

### 5.2.14.3. Удаление профиля

- Выбрать профиль в списке → **Удалить**.

## 5.2.15. Работа с механизмом управления потреблением ресурсов

### 5.2.15.1. Счетчики потребления ресурсов

#### 5.2.15.1.1. Общая информация

- **Доступно только для лицензии КОРП** (о видах лицензий — в другом разделе, ссылка).
- Счетчик потребления ресурсов собирает и накапливает данные о некоторых характеристиках производительности системы. У счетчика есть имя, описание и набор свойств, задающих, что именно накапливается.
- Накопленные данные можно просто смотреть в консоли кластера, а можно подать на вход механизму ограничения потребления ресурсов (5.2.15.2), который по ним решает, ограничивать ли действия пользователей.

Режим накопления задает свойство **Длительность сбора**:

| Значение свойства | Что накапливается | Как устроены экземпляры |
|---|---|---|
| Серверный вызов | Все показатели считаются по данным текущего серверного вызова | Каждый сеанс, выполняющий серверный вызов, — отдельный экземпляр счетчика |
| Другое значение (интервал времени) | Показатели накапливаются за указанный интервал, скользящим окном указанного размера | Разделения по сеансам нет: все сеансы суммируются внутри одного счетчика |

Что умеет накапливать счетчик:

| Группа | Показатель | Смысл | Единицы | Исходное значение из свойств сеанса |
|---|---|---|---|---|
| Время | Серверные вызовы | Время от начала до окончания серверного вызова | мс | Время вызова |
| Время | Процессорное время | Процессорное время, непосредственно потраченное на выполнение серверного вызова | мс | Процессорное время |
| Время | Время вызовов СУБД | Время, потраченное на вызов СУБД | мс | Время вызова СУБД |
| Время | Время вызовов сервисов | Время, потраченное на работу сервисов кластера | мс | Время вызовов сервисов |
| Объем данных | Память | Объем оперативной памяти, занятой сеансом в текущий момент; показатель всегда отражает текущее значение | байты | Память (всего) |
| Объем данных | Чтение | Объем данных, прочитанных с диска | байты | Чтение |
| Объем данных | Запись | Объем данных, записанных на диск | байты | Запись |
| Объем данных | Данных СУБД | Объем данных, переданных и полученных при работе с СУБД | байты | Данных СУБД |
| Количество | Количество вызовов | Число серверных вызовов | — | Количество вызовов |
| Количество | Количество активных сеансов | Текущее число активных сеансов | — | — |
| Количество | Количество сеансов | Общее число сеансов за интервал измерения, включая и активные, и уже завершенные | — | — |

Какое именно свойство сеанса берется — зависит от длительности сбора:

- **За серверный вызов** — берется значение свойства сеанса с суффиксом «(текущее)». Пример: длительность серверного вызова считается по свойству «Время вызова (текущее)».
- **За интервал времени** — берется разность итогового значения на конец интервала и итогового значения на начало интервала. Пример: «Серверные вызовы» за интервал = «Время вызова (всего)» на конец интервала минус «Время вызова (всего)» на начало интервала.

Свойства сеанса, на которые опирается счетчик, перечислены в 5.2.11.1.

#### 5.2.15.1.2. Просмотр и изменение параметров счетчика

- Создание: в консоли кластера ветка **Счетчики потребления ресурсов** → контекстное меню **Создать → Счетчик потребления ресурсов**.
- Изменение: курсор на нужный счетчик в списке → **Свойства**.
- В обоих случаях открывается окно параметров счетчика (рис. 87). У существующего счетчика свойство «Имя» изменить нельзя.

| Свойство | Назначение | Значения / примечание |
|---|---|---|
| Имя | Идентификация счетчика | После создания не меняется |
| Описание | Описание счетчика | — |
| Длительность сбора | Интервал, за который счетчик собирает данные | «Серверный вызов» или интервал времени (см. 5.2.15.1.1) |
| Группировка | Свойство, в разрезе которого создаются экземпляры счетчика: по одному экземпляру на каждое уникальное значение | **Пользователи** — раздельное накопление по сеансам разных пользователей «1С:Предприятия»; **Разделение данных** — раздельное накопление по сеансам, работающим с разными областями данных |
| Отбор | Условия, по которым отбираются сеансы, чьи свойства использует счетчик | Синтаксис — ниже |
| Тип отбора | Как применять заданный отбор целиком: на равенство или на неравенство | — |

Поведение при изменении свойств:

- Изменение **Группировки** очищает счетчик — удаляются все его экземпляры, после чего накопление начинается заново уже с новой группировкой.
- Изменение остальных свойств счетчик не очищает.

Параметры поля **Отбор**:

| Параметр | По чему отбирает | Значения / примечание |
|---|---|---|
| `infobase` | Имя информационной базы | — |
| `data-separation` | Значения разделителей, описывающих область данных | Задаются так же, как в параметре `/Z` командной строки запуска клиентского приложения (ссылка на другой раздел) |
| `user` | Имя пользователя | — |
| `appID` | Идентификатор приложения, использующего сеанс | Значение в точности совпадает со значением свойства `СоединениеИнформационнойБазы.ИмяПриложения` |
| `safe-mode-profile-name` | Профиль безопасности | Чтобы отобрать профиль безопасности по умолчанию, значение оставляют пустым: `safe-mode-profile-name=;` |
| `safe-mode` | Признак установки безопасного режима | `on` — безопасный режим включен; `off` — выключен |

Синтаксис отбора:

| Элемент | Смысл |
|---|---|
| `=` | Сравнение на равенство |
| `<>` | Сравнение на неравенство |
| `;` | Разделяет отдельные условия (разделитель виден из примера документации); условия объединяются по «И» |
| `\|` | Разделяет группы условий; группы объединяются по «ИЛИ» |

Пример из документации:

```
infobase=IB; user<>Admin; user<>Руководитель; safe-mode-profile-name=profile | infobase<>IB; safe-mode=on
```

Как это читается:

- Первая группа: информационная база равна `IB` **И** пользователь не `Admin` **И** пользователь не `Руководитель` **И** профиль безопасности равен `profile`.
- Вторая группа: информационная база не равна `IB` **И** включен безопасный режим.
- Группы объединены по **ИЛИ**.

#### 5.2.15.1.3. Удаление одного или всех экземпляров счетчика

- Удалить можно и счетчик целиком, и отдельный его экземпляр. Операция одинакова: выбрать объект → в контекстном меню **Удалить**.
- Счетчик целиком выбирается в дереве объектов кластера либо в списке счетчиков (пункт **Счетчики потребления ресурсов** в дереве объектов).
- Экземпляр выбирается так: сначала нужный счетчик, затем нужный экземпляр в списке экземпляров этого счетчика.

### 5.2.15.2. Ограничения потребления ресурсов

#### 5.2.15.2.1. Общая информация

- Зачем: разные клиентские приложения нагружают кластер по-разному, и отдельная операция может парализовать работу всех. Пример из документации — «отчет» по всем движениям всех товаров за всё время существования базы: он надолго останавливает систему и может привести к аварийному завершению, например из-за исчерпания оперативной памяти.
- Обнаруживать такие действия позволяют счетчики потребления ресурсов; автоматически ограничивать пользователей и области данных (в зависимости от группировки счетчика), превысивших заданный администратором порог, — механизм ограничения потребления ресурсов. Он работает только совместно со счетчиками.

Действия при превышении порога:

| Действие | Что происходит |
|---|---|
| Завершение сеанса | Серверный вызов прерывается, сеанс завершается |
| Прерывание серверного вызова | Серверный вызов прерывается, сеанс остается |
| Понижение приоритета потока | Понижается приоритет потока, исполняющего текущий серверный вызов |
| Нет | В технологический журнал пишется запись о «нарушении», выполнение серверного вызова никак не ограничивается |

Правила работы механизма:

- При выполнении **любого** из действий в технологический журнал всегда записывается событие `ATTN`.
- Порядок настройки:
  1. Создать один или несколько счетчиков с нужными характеристиками.
  2. Для счетчика создать правило (ограничение) с пороговыми значениями параметров счетчика.
  3. После этого система начинает применять заданные настройки.
- Ограничивающее действие выполняется только при превышении **всех** заданных в правиле порогов (условие по «И»).
- При этом в технологический журнал записывается только **первое** из установленных ограничений.
- Если счетчик настроен на анализ за интервал времени, то срабатывание действий «Завершение сеанса» и «Прерывание серверного вызова» приводит к тому, что новые серверные вызовы не выполняются до тех пор, пока показатели счетчика не опустятся ниже контрольных значений.

#### 5.2.15.2.2. Просмотр и изменение настроек ограничения

- Создание: в консоли кластера ветка **Ограничения потребления ресурсов** → контекстное меню **Создать → Ограничение потребления ресурсов**.
- Изменение: курсор на нужное ограничение в списке → **Свойства**.
- В обоих случаях открывается окно параметров ограничения (рис. 88). У существующего ограничения свойство «Имя» изменить нельзя.

| Свойство | Назначение | Значения / примечание |
|---|---|---|
| Имя | Идентификация ограничения | После создания не меняется |
| Описание | Описание ограничения | — |
| Счетчик потребления ресурсов | Имя счетчика, по данным которого работает ограничение | **Обязательное.** Вводится с клавиатуры или выбирается из выпадающего списка текущих счетчиков |
| Действие при превышении | Что сделать, если текущие значения счетчика превысили пороги, заданные в этом окне | Завершение сеанса / Прерывание серверного вызова / Понижение приоритета потока / Нет (см. 5.2.15.2.1) |
| Группы «Предельное значение…» | Пороги, при превышении которых выполняется «Действие при превышении» | Смысл значений — как у показателей счетчика (5.2.15.1.1). Полные названия групп в текстовой копии источника не приведены |
| Сообщение об ошибке | Текст, который увидит пользователь, если система прервала его серверный вызов или сеанс | — |

## Что важно администратору Linux

1. **Пустой список администраторов кластера = административные действия с кластером доступны без аутентификации.** Список пуст по умолчанию, и аутентификация начинает запрашиваться только после появления в нем хотя бы одного администратора (5.2.8, 5.2.8.4).
2. Администратор, у которого не включен ни один вид аутентификации, может выполнять только действия, не требующие аутентификации. Виды: пароль (включен по умолчанию), средства ОС, открытый ключ; документация рекомендует открытый ключ (5.2.8.1).
3. Флажок «Аутентификация паролем только с локального компьютера» разрешает парольный вход лишь с компьютеров, где работает кластер; снимать его документация не рекомендует (5.2.8.1).
4. Формат пользователя для аутентификации ОС в документации дан в виде `\\имя домена\имя пользователя`; утилита генерации ключей названа только для Windows (`ssh-keygen.exe`), но оговорено, что годится любая утилита создания ключей (5.2.8.1).
5. Менеджеры кластера и рабочие процессы вручную не создаются и не удаляются — их число и размещение определяет кластер (на менеджеры влияют требования назначения функциональности и свойства сервера «Менеджер под каждый сервис» и «Центральный сервер»). Рабочий процесс можно только выключить командой «Выключить» (5.2.9, 5.2.10).
6. У рабочего процесса полезны для диагностики: «PID процесса ОС», «IP порт» (выделяется динамически из диапазона портов сервера), «Занято памяти» и «Реакция сервера» — среднее время обслуживания одного соединения, равное сумме «Затрачено сервером» + «Затрачено СУБД» + «Затрачено менеджером блокировок» (5.2.10).
7. **Для PostgreSQL удаление соединения невозможно: команда «Удалить» над соединением не выполняет никаких действий.** Попытка разрыва при длительном запросе предусмотрена только для Microsoft SQL Server, IBM Db2 и Oracle Database (5.2.12.3).
8. Прерывание серверного вызова работает только для тонкого, веб- и мобильного клиента и срабатывает при переходе на следующую строку кода встроенного языка. Соединение нельзя разорвать, пока исполнение «висит» внутри одной строки (долгий вызов метода COM-объекта, http-вызов), кроме случая обращения к СУБД (5.2.11.3, 5.2.12.3).
9. Удаление сеанса сначала прерывает текущий серверный вызов, затем удаляет сеанс. Стандартные тексты для пользователя: `Выполнение текущей операции прервано администратором`, `Сеанс отсутствует или удален`, `Сеанс работы завершен администратором`. Нужны права администратора кластера; для разрыва соединения клиента, выполняющего код на сервере, — еще и администратора информационной базы (5.2.11.3, 5.2.12.3).
10. «IP Клиента» при работе через веб-сервер берется из заголовков веб-сервера; при наличии reverse proxy на нем нужно настроить `X-Forwarded-For`. Для фоновых заданий адрес недоступен; у сеансов веб-клиента, тонкого клиента через веб-сервер и Web-сервисов пустое поле «Компьютер» (5.2.11.1, 5.2.11.2).
11. Для разбора ожиданий на блокировках в списке сеансов есть «Заблокировано СУБД» и «Заблокировано упр.» (номер сеанса-блокировщика), «Захвачено СУБД» (сколько удерживается соединение с БД) и «Соединение с СУБД» — идентификатор процесса сервера баз данных; он виден, только пока соединение захвачено: идет вызов СУБД, открыта транзакция или удерживается `МенеджерВременныхТаблиц` хотя бы с одной временной таблицей (5.2.11.1).
12. Номер соединения 0 — признак служебного соединения, не связанного с информационной базой; нумерация соединений базы возвращается к 1 только после отключения всех клиентов, включая регламентные и фоновые задания (5.2.12.1).
13. В профиле безопасности параметр «к объектам COM» для серверов под Linux не имеет смысла, а перечень в «к приложениям операционной системы» зависит от ОС сервера (5.2.14.1).
14. Счетчики потребления ресурсов доступны только при лицензии КОРП. Отбор сеансов задается параметрами `infobase`, `data-separation`, `user`, `appID`, `safe-mode-profile-name`, `safe-mode` (`on`/`off`), операторами `=` и `<>`, условия через `;` — по «И», группы через `|` — по «ИЛИ». Смена группировки очищает счетчик (5.2.15.1).
15. Ограничение срабатывает только при превышении всех заданных порогов сразу; любое срабатывание пишет в технологический журнал событие `ATTN` (но только по первому из установленных ограничений). При счетчике «за интервал» действия «Завершение сеанса» и «Прерывание серверного вызова» блокируют выполнение новых серверных вызовов, пока показатели не опустятся ниже порога. Действие «Нет» только записывает факт нарушения в технологический журнал и выполнение вызова не ограничивает (5.2.15.2).
