## 4.1. Утилита тестирования (chdbfl)

Автономная проверка и исправление **файла базы данных** (файловый формат).

- Работает **только с файловой базой данных**. Файловая база используется в двух случаях:
  - информационная база в файловом варианте;
  - хранилище конфигурации.
- Утилита существует **только в 32-разрядном варианте**.
- Перед запуском **обязательно** сделать резервную копию файла базы данных (документация выделяет это как «Внимание!»).
- Запуск: приложение `chdbfl` из каталога установки «1С:Предприятия». Утилита оконная (в документации — рис. 97 «Утилита тестирования и исправления информационных баз»).

Элементы окна:

| Элемент | Назначение |
|---|---|
| поле **Имя файла БД** | указать или выбрать файл информационной базы |
| флажок **Исправлять обнаруженные ошибки** | включить исправление найденных ошибок; его же нужно ставить, если требуется оптимизировать размещение служебной информации, ускоряющей открытие ИБ |
| кнопка **Выполнить** | старт проверки |
| текстовое поле | сообщения о найденных ошибках |
| область под текстовым полем | сообщения об итогах работы утилиты |

Ограничение: к моменту нажатия **Выполнить** база не должна быть открыта ни конфигуратором, ни в режиме 1С:Предприятие.

Утилита пригодна и для проверки хранилища конфигурации.

Рекомендуемый порядок работы:

1. Сделать резервную копию файла базы данных (обязательно).
2. Запустить тестирование **без** флажка «Исправлять обнаруженные ошибки».
3. Если проблем нет — можно запустить повторно **с** флажком: при этом выполняется реиндексация информационной базы (или базы хранилища). Такую операцию рекомендуется делать регулярно.
4. Если проблемы есть — попытаться исправить базу. Если в ходе исправления утилита сообщила о потере каких-либо данных, продолжать работу с такой базой не рекомендуется. Из получившейся базы можно:
   - извлечь уцелевшие данные и конфигурацию и на их основе создать новую информационную базу;
   - получить последнюю версию конфигурации и на её основе создать другое хранилище.

## 4.2. Утилита контроля целостности (ci)

### 4.2.1. Общая информация

`ci` отслеживает неизменность объектов файловой системы и базы данных, используемых «1С:Предприятием». Принцип: сначала формируются эталонные хеш-суммы объектов контроля, затем регулярно выполняется проверка — пересчёт хешей и сравнение с эталоном.

- В общем описании сказано, что хеши вычисляются по алгоритму SHA-1. ⚠ в источнике неясно: в описании параметра `--method` (раздел 4.2.6) значением по умолчанию названо `sha256`.
- **macOS не поддерживается.**
- Объекты контроля:
  - файлы в файловой системе;
  - некоторые таблицы базы данных «1С:Предприятия».
- Перечень объектов задаётся **шаблонами источника информации** в формате универсального описателя (4.2.3). Шаблоны можно указать прямо в командной строке либо в файле — **списке шаблонов** (4.2.2), путь к которому передаётся параметром `in`.
- Пара «объект контроля + хеш-сумма» называется **эталоном**; эталоны хранятся в **базе эталонов** (4.2.4), которую утилита создаёт в режиме формирования.
- В режиме проверки хеши вычисляются заново и сверяются с базой эталонов; результат — файл отчёта (4.2.5).
- Собственную целостность утилита **не контролирует** ни при запуске, ни в каких-либо режимах. Ограничение доступа к самой утилите, базе эталонов и отчётам — задача средств операционной системы.

### 4.2.2. Список шаблонов источников информации

Файл, в котором перечислено несколько объектов (наборов объектов) контроля.

- Одна строка — один шаблон источника информации (формат — 4.2.3).
- Количество строк не ограничено.
- Комментарий начинается с символа `#`.
- Строки-комментарии, пустые строки и строки из одних пробелов при формировании списка объектов игнорируются.
- Кодировка файла — **только UTF-8**.

Примеры описателей из документации:

```text
# объект контроля - файл /tmp/vokas/spru.cvs
file:///tmp/vokas/spru.cvs
# объект контроля - все файлы в каталоге c:\Program Files\1cv8\8.3.4.408\bin
rdir://c:\Program Files\1cv8\8.3.4.408\bin
# объект контроля - все файлы .rc и .cfg в каталоге /home/user/.kde и подчиненных каталогах
rdir:///home/user/.kde?*.rc,*.cfg
# объект контроля - все файлы, начинающиеся с "V8" файлы в каталоге /tmp, без подкаталогов
ndir:///tmp?V8*.txt
# объект контроля - все поддерживаемые таблицы в базе данных, расположенной на MS SQL Server
mssql://user:password@server/instance/dbname
# объект контроля - таблицы users и config на сервер PostrgeSQL
postgre://user:password@server:123/dbname?users,config
# объект контроля - таблицы users в файловой базе данных
dbe://c:\DB\checked_db?users
```

### 4.2.3. Универсальный описатель источника информации

Общий вид:

```text
proto://[user:[password]@][server[:port]][/path/resource][?mask]
```

**`proto`** — тип объекта контроля:

| Значение | Что контролируется |
|---|---|
| `file` | отдельный файл файловой системы |
| `ndir` | файлы каталога, без обхода подкаталогов |
| `rdir` | файлы каталога и всех вложенных каталогов |
| `mssql` | база данных в Microsoft SQL Server |
| `ora` | база данных в Oracle Database |
| `postgre` | база данных в PostgreSQL |
| `db2` | база данных в IBM Db2 |
| `dbe` | файловый вариант базы данных «1С:Предприятия» |

**`user:password@`** — имя и пароль для доступа к объекту контроля.
- При контроле таблиц базы данных это пользователь **СУБД**, а не пользователь информационной базы «1С:Предприятия».
- Рекомендуется указывать того пользователя СУБД, от имени которого создавалась база «1С:Предприятия».
- Символ `@` обязателен, если заданы имя пользователя и пароль.

**`server:port`** — имя компьютера (и порт), где работает СУБД, обслуживающая базу «1С:Предприятия».

**`/path/resource`** — полный путь к файлу или каталогу в нотации используемой ОС.
- Windows: путь начинается с имени диска.
- Linux: путь начинается с корня файловой системы (`/`).
- Для клиент-серверной базы вместо пути указывается:
  - имя базы данных в терминах СУБД — если СУБД не поддерживает экземпляры сервера;
  - комбинация «имя экземпляра + имя базы» — если СУБД экземпляры поддерживает.
- Если в пути указан экземпляр СУБД, подключение идёт по **порту по умолчанию**; задать номер порта в имени сервера в этом случае нельзя (не поддерживается).

**`?mask`** — список параметров описателя через запятую; смысл зависит от протокола:
- для `ndir` и `rdir` — маски файлов;
- для таблиц базы «1С:Предприятия» — имена таблиц:

| Имя | Содержимое |
|---|---|
| `config` | конфигурация базы данных |
| `users` | таблица пользователей конфигурации |

Обе таблицы **виртуальные**: каждая объединяет данные нескольких физических таблиц базы (целиком или частично). Хеш считается по всем данным, входящим в такую таблицу; контролировать фрагмент таблицы нельзя.

Примечание о символах. При составлении описателя следует избегать символов:
- `@` — кроме разделителя между «имя/пароль» и именем компьютера СУБД;
- `/`, `\`, `:`;
- `?` — кроме использования в масках файлов (но не раньше них);
- `~`.

### 4.2.4. Файл базы эталонов

Файл с хеш-суммами объектов контроля. Кодировка — UTF-8. Имя и расположение задаются при запуске утилиты.

Формат:

```text
[Нормализованный вид универсального описателя источника информации]
<объект контроля> = <хеш>
```

- В квадратных скобках — описатель из шаблона, приведённый к нормализованному виду.
- Строк `<объект> = <хеш>` под одним описателем может быть несколько.
- Если описатель указывает на конкретный файл, часть `<объект>` отсутствует и строка начинается сразу со знака `=`.

Правила нормализации описателя:

| № | Правило |
|---|---|
| 1 | для всех протоколов в конец описания объекта контроля (перед `?`) добавляется прямой слеш `/` |
| 2 | для протоколов-каталогов при отсутствии маски добавляется маска `*` |
| 3 | для протоколов баз данных при отсутствии маски явно добавляются параметры `config,users` |
| 4 | для протоколов баз данных маска `*` заменяется на явное `config,users` |
| 5 | маски сортируются лексикографически |
| 6 | обратные слеши `\` заменяются прямыми `/` |
| 7 | несколько подряд идущих слешей (любых) заменяются одним прямым (например, `//\\//` → `/`) |

Пример фрагмента базы эталонов:

```text
[dbe://C:/1C DB/DB folder/?config]
config = FEC3FC5E46AE98299217D6885B3BE28C4F4D6FB9
[dbe://C:/1C DB/Another DB folder/?config,users]
config = FEC3FC5E46AE98299217D6885B3BE28C4F4D6FB9
users = A244BE3830C2B7075C0BB684896B97A0324984A0
[file://C:/Program Files (x86)/1cv82/8.2.9.356/docs/ru/V8UpdateFrom82Beta.htm]
= 392BC75149AE02565C7E31592EDCD60F00BFA03C
[ndir://C:/Program Files (x86)/1cv8/8.3.5.625/bin/?*]
1cv8.exe = 232F2BCCE6ABB95FD56E3CB3FADE528D851A5D69
1cv8_root.hbk = 025B4C8465D3CD851363B2102478B1CAF2EC444E
1cv8_root.res = 8F48869F82BB222EE25E18502605AC117BB5736A
1cv8_ru.hbk = 81CBB0D5573D8517913053EA88AAADE9785AB443
...
```

### 4.2.5. Файл отчета

Результат работы утилиты. Кодировка — UTF-8. Имя и расположение задаются при запуске, но к имени автоматически добавляются дата и время формирования отчёта. Пример: задано `C:\temp\report.rpt` → фактически создаётся `C:\temp\report-14.02.26-14.07.58.019446.rpt`.

Формат:

```text
[.params]
Key=value
[Нормализованный вид универсального описателя источника информации]
<Объект контроля> = <Обнаруженное изменение>
```

Секция **`.params`** присутствует всегда и описывает параметры запуска. Ключи:

| Ключ | Значение |
|---|---|
| `datetime` | дата и время запуска утилиты |
| `workdir` | рабочий каталог при запуске |
| `exepath` | путь к исполняемому файлу утилиты |
| `mode` | режим запуска: `create` — формирование базы эталонов; `check` — проверка эталонов |
| `etalon` | путь к базе эталонов |
| `report` | путь к файлу отчёта в том виде, как он указан в командной строке |
| `debug` | путь к файлу отладочной информации либо пустая строка, если отладочный вывод не задан |
| `in` | путь к файлу с параметрами; если в командной строке несколько параметров `in`, ключей `in` в секции тоже может быть несколько |
| `param` | все распознанные параметры командной строки через запятую |

Секции источников попадают в отчёт только для тех источников (из базы эталонов), где найдены расхождения между эталоном и фактическим состоянием; под секцией перечисляются изменившиеся объекты. По неизменившимся объектам ничего не выводится.

Коды изменений:

| Код | Смысл |
|---|---|
| `A` | в источнике появился новый объект контроля |
| `D` | удалён объект, существовавший на момент формирования базы эталонов |
| `M` | объект контроля модифицирован |

Пример фрагмента отчёта:

```text
[dbe://C:/1C DB/DB folder/?config,users]
users = M
[ndir://C:/Program Files (x86)/1cv81/bin/?*]
1CMailV8.dll = D
1CMailV8.dll.32 = A
```

Расшифровка примера: в файловой ИБ из каталога `C:/1C DB/DB folder` изменилось содержимое таблицы пользователей; в каталоге `C:/Program Files (x86)/1cv81/bin` удалён файл `1CMailV8.dll` и появился новый файл `1CMailV8.dll.32`.

### 4.2.6. Использование утилиты

Синтаксис:

```text
ci <mode> --in <ШаблонИсточника> --etalon <ФайлБазыЭталонов> --report <ФайлОтчета> --debug <ФайлОтладочнаяИнформация> [описание источника]
```

**`mode`** — режим работы:

| Режим | Назначение |
|---|---|
| `--version`, `-v` | показать номер версии утилиты |
| `--help`, `-h` | справка по режимам `make` и `check`; нужный режим указывается через пробел после команды справки |
| `make` | сформировать файл базы эталонов либо обновить в существующей базе данные по источникам, указанным при запуске (если данные по такому источнику в базе уже есть) |
| `check` | проверить целостность переданного списка источников по базе эталонов |

Остальные параметры указываются только для режимов `make` и `check`:

| Параметр | Обязательность | Назначение |
|---|---|---|
| `--in`, `-i` | см. примечание | путь к файлу списка шаблонов источников информации (4.2.2); параметр можно повторять несколько раз |
| `--etalon`, `-e` | обязателен для `make` и `check` | полный путь к файлу базы эталонов (4.2.4) |
| `--report`, `-r` | обязателен для `make` и `check` | полный путь к файлу отчёта (4.2.5) |
| `--debug`, `-d` | необязателен | полный путь к файлу отладочной информации; файл нужен техническому персоналу фирмы «1С» при расследовании некорректного поведения утилиты |
| `--method=<значение>`, `-m=<значение>` | только для `make` | алгоритм хеш-функции для расчёта контрольных сумм (значения — ниже) |
| `описание источника` | необязателен | источник информации, заданный прямо в командной строке без файла шаблона (можно несколько); формат — точно как у строки списка шаблонов |

Примечание: для `make` и `check` должно быть указано **хотя бы одно** описание источника — параметром `--in` (`-i`) или прямым указанием описателя. Утилита использует все источники, найденные при запуске обоими способами.

Значения `--method`:

| Значение | Алгоритм |
|---|---|
| `sha1` | SHA-1 |
| `sha256` | SHA-256 — **значение по умолчанию** |
| `gost2012` | ГОСТ Р 34.11-2012 (512 бит) |

### 4.2.7. Рекомендации по установке и использованию

У утилиты нет самоконтроля, поэтому неизменность её собственных файлов обеспечивает системный администратор — например, правами доступа файловой системы на каталог утилиты, файлы баз эталонов и файлы отчётов.

Возможный сценарий развёртывания:

1. Установить утилиту в каталог, **отличный** от каталога установки «1С:Предприятия».
2. Создать для работы с ней отдельного привилегированного пользователя с ограниченными правами — но достаточными для чтения всех объектов контроля.
3. Ограничить доступ к исполняемым и конфигурационным файлам утилиты этим пользователем (любой доступ других пользователей запретить).
4. Работать с утилитой только от имени этого пользователя.

Схема использования при таком развёртывании:

1. Войти в систему под привилегированным пользователем. Если утилиту запускает системный планировщик — обеспечить запуск от того же пользователя.
2. Запустить утилиту в нужном режиме: создание базы эталонов либо проверка целостности источников.
3. Проанализировать отчёт.

Итог: пользоваться утилитой и её результатами может только ограниченный круг доверенных лиц, знающих имя и пароль выделенного пользователя.

## 4.3. Утилита преобразования (cnvdbfl)

Файл файловой базы данных `1Cv8.1CD` существует в нескольких версиях внутреннего формата:

| Формат | Размер внутренней страницы | Предел размера внутреннего файла | Примечание |
|---|---|---|---|
| **8.2.14** | 4 096 байт | 4 Гбайта | — |
| **8.3.8** | 4 096, 8 192, 16 384, 32 768 или 65 536 байт | 4 Гбайта при странице 4 096; 6 Гбайт при странице 8 192, 16 384, 32 768 и 65 536 | более оптимальное хранение некоторых внутренних данных |

(Что такое «внутренний файл», документация в этом месте не раскрывает — даётся отсылка на книгу.)

Совместимость версий платформы:

| Версия «1С:Предприятия» | С какими форматами `1Cv8.1CD` работает |
|---|---|
| 8.3.8 и старше | с любым форматом, без дополнительных действий |
| 8.3.7 и младше | только с форматом 8.2.14 |

Преобразовать формат можно двумя способами: выгрузкой/загрузкой информационной базы через файл `.dt` либо утилитой `cnvdbfl`.

`cnvdbfl` — утилита командной строки, которая умеет:
1. преобразовывать `1Cv8.1CD` между форматами;
2. менять размер страницы файла для формата 8.3.8.

Синтаксис:

```text
cnvdbfl <команда> <путь к 1CV8.1CD>
```

Команды:

| Команда | Короткая форма | Назначение |
|---|---|---|
| `--help` | `-h` | краткая информация об утилите |
| `--version` | `-v` | версия утилиты |
| `--info` | `-i` | информация о формате файла `1Cv8.1CD`. Для файлов, с которыми не работали в «1С:Предприятии» версии 8.2.14 и старше, выдаётся диагностическое сообщение о невозможности показать информацию |
| `--convert` | `-c` | конвертация файла `1Cv8.1CD`. Без параметров — конвертация в формат 8.3.8 с размером страницы 8192 байта |

Параметры команды `--convert`:

| Параметр | Назначение | Значения |
|---|---|---|
| `--format=<формат>` или `-f <формат>` | целевой формат | `8.2.14` — конвертировать в формат 8.2.14; `8.3.8` — конвертировать в формат 8.3.8 |
| `--page=<размер страницы>` или `-p <размер страницы>` | размер страницы для формата 8.3.8; **по умолчанию 8192**; при `-f 8.2.14` игнорируется | `4096` или `4K`; `8192` или `8K`; `16384` или `16K`; `32768` или `32K`; `65536` или `64K` |

Примеры из документации:

| Задача | Команда |
|---|---|
| конвертация в формат 8.2.14 | `cnvdbfl -c -f 8.2.14 c:\temp\1cv8.1cd` |
| конвертация в формат 8.3.8 со страницей по умолчанию | `cnvdbfl -c -f 8.3.8 c:\temp\1cv8.1cd` |
| конвертация в формат 8.3.8 со страницей 16К | `cnvdbfl -c -f 8.3.8 -p 16k c:\temp\1cv8.1cd` |
| информация о файле `1Cv8.1CD` | `cnvdbfl -i c:\temp\1cv8.1cd` |

## 4.4. Утилита ring

### 4.4.1. Общая информация

`ring` — кроссплатформенная консольная утилита (без графического интерфейса). Назначение: управление локальной конфигурацией процессов «1С:Предприятия» и выполнение различных операций поддержки работы системы.

Архитектура модульная:
- **модуль** — набор функциональности, объединённой по смыслу или по выполняемым действиям; доступ к ней — через команды; число команд в модуле не ограничено;
- **команда** — действие с набором параметров (или без них);
- один вызов `ring` = одна команда одного модуля;
- утилита может одновременно использовать несколько модулей.

Перечень установленных и используемых модулей хранится в **реестре экземпляров модулей** — файле `ring-commands.cfg` (его формат и расположение описаны в другом месте документации).

Общая схема вызова:

```text
ring <module> <command> [--parameter "parameter value"]
```

| Часть | Смысл |
|---|---|
| `ring` | имя утилиты |
| `<module>` | имя модуля |
| `<command>` | имя команды |
| `--parameter` | параметр команды и его значение; состав параметров, обязательность и значения по умолчанию у каждой команды свои |

Правила передачи параметров:
- значение параметра не может содержать пробелы «как есть»; значение с пробелом нужно заключать в кавычки;
- только Windows: символы, вводимые в аргументах командной строки, не должны требовать более 8 бит; для символов, не укладывающихся в это требование, рекомендуется подбирать замену (пример из документации: вместо «ə» — «a» или «e»).

### 4.4.2. Системные требования

- Поддерживаются те же операционные системы, что и для самого «1С:Предприятия».
- Есть 32- и 64-разрядные версии утилиты.
- Дополнительно требуется:
  - **Java 8 и выше** (`https://www.java.com/ru/download/`);
  - на **Linux** — установленный **GNU Awk**, причём он должен использоваться по умолчанию.

### 4.4.3. Установка утилиты

- `ring` ставится в составе других продуктов, которым она нужна. Такие продукты могут сами быть модулями `ring` или содержать модули для неё.
- Отдельная установка «голой» `ring` **не поддерживается**: без модулей утилита практической ценности не имеет.

### 4.4.4. Рекомендации по использованию

#### 4.4.4.1. Установка языка вывода утилиты

- По умолчанию язык вывода определяется операционной системой (как его сменить — см. документацию ОС).
- Чтобы язык вывода отличался от настроек ОС, в переменную окружения **`RING_OPTS`** добавляют параметр `-Duser.country=ru -Duser.language=RU`.
- Если `RING_OPTS` уже содержит значение — дописать к нему пробел и эту строку.
- Поддерживаются два языка вывода: русский и английский.

Примеры установки переменной из командной строки (значение приведено в источнике именно так, без кавычек).

Windows:

```text
set RING_OPTS=-Duser.country=ru -Duser.language=RU
```

Linux (командный процессор bash):

```text
export RING_OPTS=-Duser.country=ru -Duser.language=RU
```

#### 4.4.4.2. Некорректный вывод утилиты

- Для терминала нужно выбрать шрифт Consolas или другой TrueType-шрифт с поддержкой Unicode.
- Проверить, что нужный язык выбран в ОС как язык для программ, не поддерживающих Unicode; изменение этой настройки вступает в силу после перезагрузки.
- Если менять настройки ОС нельзя — при шрифте Consolas перед запуском `ring` сменить кодовую страницу на подходящую для нужного языка, например:

```text
chcp 1251
```

(Настройка «язык для программ, не поддерживающих Unicode» и команда `chcp` — только Windows.)

#### 4.4.4.3. Задание кодировки при переадресации вывода утилиты в файл

Только Windows: при перенаправлении вывода `ring` в файл содержимое может оказаться нечитаемым. Причина — несоответствие языка для программ, не поддерживающих Unicode, и языка интерфейса системы. Способы получить читаемый файл:

- привести язык для программ, не поддерживающих Unicode, в соответствие с языком интерфейса (за подробностями документация даёт ссылку; сама настройка упоминается в 4.4.4.2);
- задать кодировку UTF-8 через переменную окружения `RING_OPTS` (документация отсылает за подробностями по ссылке; конкретное значение параметра в этой части не приведено).

## 4.5. Утилита лицензирования (ring license)

### 4.5.1. Общая информация

Задачи, которые решает утилита:
- первичное получение лицензии;
- повторное получение и обновление лицензии;
- проверка соответствия файла лицензии текущему компьютеру;
- вывод списка лицензий;
- получение информации о лицензии;
- удаление лицензии;
- обновление лицензии.

**Хранилище лицензий** — каталог с файлами активированных программных лицензий. Каталоги по умолчанию:

| ОС | Каталог хранилища лицензий по умолчанию |
|---|---|
| Windows | `%ProgramData%\1C\licenses` |
| Linux | `/var/1C/licenses` |

Полный перечень каталогов, где могут лежать программные лицензии, приведён в другом разделе документации.

**Имя лицензии** — унифицированное представление вида `пинкод-номер`. Пример: пинкод `123-456-789-012`, регистрационный номер продукта `8000314159` → лицензия показывается как `123456789012-8000314159`. Это же имя передаётся командам, которые принимают имя лицензии параметром.

Два способа активации программной лицензии:

| Способ | Команды | Как работает |
|---|---|---|
| 1. Онлайн | `activate` | активация сразу, через веб-сервис центра лицензирования, без промежуточных файлов |
| 2. Через файлы | `prepare-request` → `acquire` → `generate` | `prepare-request` готовит файл запроса; запрос передаётся в центр лицензирования по электронной почте, ответ приходит файлом; либо файл ответа формируется через веб-сервис без почты командой `acquire`; затем `generate` по запросу и ответу создаёт файл лицензии |

### 4.5.2. Системные требования

Утилита лицензирования — это модуль **`license`** для утилиты `ring`. С точки зрения выполняемых действий «модуль license» и «утилита лицензирования» — взаимозаменяемые понятия; технически «утилита лицензирования» = `ring` + модуль `license`.

- Нужна установленная утилита `ring`.
- Модуль доступен в 32- и 64-разрядных версиях.
- Требования модуля:
  - `ring` версии **0.8.2 и выше**;
  - **JCE для Java 8** (`https://www.oracle.com/technetwork/java/javase/downloads/jce8-download-2133166.html`) либо корректная настройка конфигурационного файла Java (зависит от версии Java);
  - только Windows: Windows Script Host на компьютере, где запускается модуль.

### 4.5.3. Установка модуля

#### 4.5.3.1. Установка модуля

Дистрибутив — на портале «1С:Обновление программ»: `https://releases.1c.ru/project/EnterpriseLicenseTools`.

Порядок установки:

1. Определить разрядность и ОС, в которой будет работать утилита.
2. Скачать соответствующую версию.
3. Создать временный каталог.
4. Распаковать в него скачанный архив.
5. Перейти в этот каталог.
6. Установить утилиту (нужны **права администратора**).

В распакованном комплекте два установщика:

| Файл | Что это |
|---|---|
| `1ce-installer` | программа установки с графическим интерфейсом |
| `1ce-installer-cli` | программа установки с интерфейсом командной строки |

Версии утилиты лицензирования, `ring` и программы установки читаются из имён файлов. Пример структуры распакованного архива:

```text
<lib>
```

Как это читать:

- программа установки — версия 1.9.1.3;
- утилита `ring` — версия 0.19.5.12;
- утилита лицензирования (license tools) — версия 0.15.0.2.

Работа с программой установки (графической и консольной) описана на 1С:ИТС: `https://its.1c.ru/db/inst10doc`.

После установки можно проверить, что модуль зарегистрирован в реестре экземпляров модулей (`ring-commands.cfg`, см. 4.4.1).

#### 4.5.4.1. acquire

Формирует файл ответа по ранее подготовленному файлу запроса, обращаясь к веб-сервису центра лицензирования.

```text
ring license acquire [--request <ФайлЗапроса>] [--response <ФайлОтвета>] [--conf-location] [--send-statistics <режим>]
```

| Параметр | Назначение |
|---|---|
| `--request` | полное имя файла с запросом к центру лицензирования; если не указан — содержимое запроса читается из стандартного потока ввода |
| `--response` | полное имя файла для ответа центра лицензирования; если не указан — ответ выводится в стандартный поток вывода |
| `--conf-location` | каталог с `conf.cfg` (см. общие параметры; `~` — домашний каталог пользователя сервера «1С:Предприятия») |
| `--send-statistics` | см. общие параметры |

Результат: ответ центра лицензирования. Код возврата: `0` — успех; иначе — не `0`, сообщение об ошибке выводится в стандартный поток вывода.

#### 4.5.4.2. activate

Активация лицензии через веб-сервис центра лицензирования.

```text
ring license activate --first-name <имя> --middle-name <отчество> --last-name <фамилия> [--email <email>] --company <компания> --country <страна> --zip-code <индекс> [--region <область> --district <район>] --town <город> --street <улица> --house <дом> --building <строение> --apartment <квартира> --serial <серийныйНомер> --pin <пинкод> [--previous-pin <предыдущийПинкод>] [--path <хранилище>] [--validate] [--conf-location <путь>] [--send-statistics <режим>]
```

Параметры:
- сведения о владельце и продукте, `--previous-pin`, `--validate` — по таблице выше;
- `--path` — хранилище лицензий, если отличается от умолчания;
- `--conf-location <путь>` — каталог с `conf.cfg` (`~` — домашний каталог пользователя сервера «1С:Предприятия»);
- `--send-statistics` — см. общие параметры.

Результат: при успешной регистрации сервер возвращает файл лицензии, который помещается в указанное хранилище. При повторном вводе идентичных данных (включая данные комплекта) на той же машине генерируется подобный файл лицензии.

Код возврата: `0` — успех; иначе — не `0`, сообщение об ошибке в стандартный поток вывода.

См. также: файл `conf.cfg`.

#### 4.5.4.7. prepare-request

Используется, когда активация через веб-сервис центра лицензирования невозможна: лицензию активируют через электронное письмо в центр лицензирования, последовательно применяя команды `prepare-request`, `acquire`, `generate`. Сама `prepare-request` готовит файл для передачи в центр лицензирования.

```text
ring license prepare-request --first-name <имя> --middle-name <отчество> --last-name <фамилия> [--email <email>] --company <компания> --country <страна> --zip-code <индекс> [--region <область> --district <район>] --town <город> --street <улица> --house <дом> --building <строение> --apartment <квартира> --serial <серийныйНомер> --pin <пинкод> [--previous-pin <предыдущийПинкод> --request <файл>] --validate [--send-statistics <режим>]
```

Параметры:
- сведения о владельце и продукте, `--previous-pin`, `--validate` — по общей таблице из 4.5.4 (описания идентичны `activate`);
- `--request <файл>` — полный путь к файлу, куда будет записана информация для передачи в центр лицензирования; если не указан — текст запроса выводится в стандартный поток вывода;
- `--send-statistics` — см. общие параметры.

В отличие от `activate`, параметров `--path` и `--conf-location` у этой команды в документации нет.

Результат: содержимое файла запроса в центр лицензирования (в файле или в стандартном потоке вывода). Код возврата: `0` — успех; иначе — не `0`, сообщение об ошибке в стандартный поток вывода.

#### 4.5.4.10. update

Обновляет (переполучает) **все** лицензии из хранилища лицензий. Обновление — это повторное получение лицензии в центре лицензирования с теми же параметрами: регистрационный номер, пинкод, ключевые параметры. Файлы активированных лицензий, существовавшие до обновления, сохраняются с расширением **`.oldlic`** как резервные копии.

```text
ring license update --conf-location <КонфигурационныйФайл> [--force <значение>] [--path <хранилище>] [--validate] [--send-statistics <режим>]
```

| Параметр | Назначение | Значения / умолчание |
|---|---|---|
| `--conf-location` | каталог конфигурационных файлов платформы; в нём ищется `conf.cfg`, из которого берётся параметр `ExternalResourcesMode` | если не указан или `conf.cfg` в каталоге нет — поиск в каталогах по умолчанию (таблица в 4.5.4); для Linux `~` здесь — домашний каталог пользователя, запускающего утилиту лицензирования |
| `--force` | поведение при ошибках обновления лицензии | `true` — ошибка игнорируется, проблемный файл пропускается, обработка продолжается; `false` — обработка прерывается, все лицензии восстанавливаются из резервных копий (**по умолчанию**) |
| `--path` | см. общие параметры | — |
| `--validate` | проверять ли аппаратные данные, полученные от системы | `true` — проверять; `false` — не проверять (**по умолчанию**) |
| `--send-statistics` | см. общие параметры | `true` по умолчанию |

Результат: обновлены все лицензии хранилища. Код возврата: `0` — успех; иначе — не `0`.

#### 4.5.4.11. validate

```text

```

| Параметр | Назначение |
|---|---|
| `--name` | имя лицензии; если параметр не задан — утилита ждёт из стандартного потока ввода **содержимое** файла активированной лицензии (не имя файла) |
| `--path` | см. общие параметры |
| `--send-statistics` | см. общие параметры |

Результат: либо сообщение, что оборудование соответствует зафиксированному при активации, либо перечень различий.

Коды возврата:

| Код | Смысл |
|---|---|
| `0` | успешное завершение |
| не `0` | ошибка; сообщение выводится в стандартный поток вывода |
| `1` | изменены параметры компьютера |
| `2` | ошибка проверки цифровой подписи лицензии |

#### 4.5.4.12. Информация для сервиса 1С:Пульт

- номер пакета данных;
- уникальный идентификатор компьютера — хеш в формате UUID, сгенерированный на основе MAC-адреса сервера;

## 4.6. Утилита административной консоли (1cv8a)

`1cv8a` ускоряет проверку и исправление определённых проблем информационной базы:
- тестирование и исправление таблиц узлов планов обмена;
- тестирование и исправление хеш-полей таблиц информационной базы.

Смысл утилиты: исправить некоторые проблемы ИБ без запуска конфигуратора и быстрее. Достигается это тем, что обрабатываются только проблемные объекты и выполняется ограниченный набор исправлений.

Синтаксис:

```text
1cv8a <режимы> <ключи>
```

Режимы:

| Режим | Короткая форма | Назначение |
|---|---|---|
| `help [режим]` | `h [режим]` | краткая информация об утилите или об указанном режиме работы |
| `ib-check-and-repair` | `ibcr` | тестирование и исправление данных |

Параметры режима `ib-check-and-repair`:

| Параметр | Короткая форма | Назначение |
|---|---|---|
| `--repair` | `-r` | исправлять найденные ошибки |
| `--exchange-plan-integrity` | `-epi` | тестирование и исправление таблиц узлов планов обмена |
| `--exchange-plan-integrity-outFile=<имя XML-файла>` | `-epiof <имя XML-файла>` | XML-файл для сохранения состояния записей «ЭтотУзел» планов обмена; **обязателен**, если команда выполняется с `--exchange-plan-integrity` |
| `--data-history-integrity` | `-dhis` | тестирование и исправление таблиц истории данных |
| `--dimhash-integrity` | `-dhi` | пересчёт итогов для устранения некорректного расчёта итогов регистров накопления и бухгалтерии (условия — ниже) |
| `--connection-string=<string>` | — | строка соединения с информационной базой |
| `--file=<path>` | `-f <path>` | путь к каталогу информационной базы в файловом варианте |
| `--server=<server:port/infobase>` | `-s <server:port/infobase>` | параметры подключения к информационной базе в клиент-серверном варианте |
| `--user=<name>` | `-u <name>` или `-n <name>` | имя пользователя, от имени которого выполняется подключение к ИБ |
| `--password=<password>` | `-p <password>` | пароль этого пользователя информационной базы |
| `--unlock-code=<code>` | — | код разрешения соединения с информационной базой (если задан) |
| `--security-level=<level>` | — | уровень защищённости соединения с сервером |
| `--verbose` | — | подробный вывод сообщений о ходе выполнения |

Подробности по `--dimhash-integrity`:
- касается регистров накопления и бухгалтерии, у которых среди измерений есть хотя бы одно измерение типа «Строка» и в индекс по измерениям входит **более 16 полей** базы данных;
- пересчёт итогов выполняется только при одновременном указании `--repair`;
- без `--repair` выполняется лишь проверка — есть ли в информационной базе некорректные итоги регистров накопления и бухгалтерии.

Примеров командной строки `1cv8a` и допустимых значений `--security-level` в этой части документации нет.

## Что важно администратору Linux

1. **В этой части нет серверных командных строк.** `ragent`, `rmngr`, `rphost`, `ras`, `rac`, `ibcmd`, `ibsrv`, `crserver`, `webinst` сюда не вошли (искать в конспектах частей 2 и 3); здесь — вспомогательные утилиты `chdbfl`, `ci`, `cnvdbfl`, `ring`, `ring license`, `1cv8a`.
2. **Хранилище программных лицензий на Linux по умолчанию — `/var/1C/licenses`.** Все команды `ring license` работают с ним, если не задан `--path`.
3. **`ring` требует Java 8+ и GNU Awk, установленный и используемый по умолчанию** (требование именно для Linux). Отдельно `ring` не ставится — только вместе с модулем (например, license tools), через `1ce-installer` или `1ce-installer-cli`, с правами администратора.
4. **Модулю `license` нужны `ring` ≥ 0.8.2 и JCE для Java 8** (или корректная настройка конфигурационного файла Java). Дистрибутив: `https://releases.1c.ru/project/EnterpriseLicenseTools`; версии читаются из имён файлов `*.e1c.car`.
5. **Имя лицензии для команд — `пинкод-регномер` без дефисов в пинкоде** (например, `123456789012-8000314159`). Список — `ring license list`, сведения — `ring license info --name ...`, проверка привязки к оборудованию — `ring license validate --name ...` (код возврата `1` — изменены параметры компьютера, `2` — ошибка цифровой подписи лицензии).
6. **`ring license info` не проверяет соответствие оборудования** — он только показывает содержимое лицензии. Раздел `TechnicalInfo` всегда на английском и пригоден для разбора скриптами (`LicenseType`, `LicenseAssociationType`, `LicenseGenerationDate` и др.).
7. **Активация без `--validate` может дать неработоспособную лицензию**: если какой-то ключевой параметр компьютера не удалось получить, поля лицензии останутся пустыми. При активации (`activate`, `prepare-request`) имеет смысл указывать `--validate`, чтобы получить ошибку сразу.
8. **`ring license update` переполучает все лицензии хранилища** и оставляет прежние файлы с расширением `.oldlic`. По умолчанию (`--force false`) при ошибке всё откатывается из резервных копий; при `--force true` проблемный файл просто пропускается.
9. **Адрес центра лицензирования выбирается по параметру `ExternalResourcesMode` из `conf.cfg`.** На Linux файл ищется в `~/.1cv8/1C/1cv8/conf`, если каталог не задан через `--conf-location`; обратите внимание, чей домашний каталог имеется в виду (пользователь сервера «1С:Предприятия» для `acquire`/`activate`, запускающий пользователь для `update`).
10. **По умолчанию утилита лицензирования отправляет статистику в «1С:Пульт»** (`pult.1c.com`, порт `443`), включая идентификаторы-хеши на основе MAC-адреса (полный перечень — 4.5.4.12). Отправка отключается параметром `--send-statistics false`, который есть у каждой команды модуля.
11. **Офлайн-активация**: `prepare-request` (файл запроса) → `acquire` (ответ через веб-сервис) или переписка с центром лицензирования по почте → `generate` (файл лицензии); поместить готовый файл в хранилище позволяет `put`. `prepare-request`, `acquire`, `generate`, `get`, `info`, `validate` умеют работать через стандартные потоки ввода/вывода, если файл или имя лицензии не указаны.
12. **`ci` поддерживает PostgreSQL** (протокол `postgre://user:password@server:port/dbname?users,config`) и каталоги (`ndir://`, `rdir://`); пользователь в описателе — пользователь СУБД, не пользователь ИБ. Пути Linux начинаются с `/`, то есть файл описывается как `file:///путь`. Для `make` и `check` обязательны `--etalon` и `--report`; имя отчёта дополняется датой и временем. Алгоритм по умолчанию для `make` — `sha256`, доступны `sha1` и `gost2012`.
13. **`ci` сама себя не защищает**: ставить её в каталог, отличный от каталога платформы, запускать от отдельного пользователя с правом только чтения объектов контроля, закрыть правами ФС утилиту, базы эталонов и отчёты; в планировщике запускать от того же пользователя.
14. **`chdbfl` и `cnvdbfl` — только для файловых баз** (`1Cv8.1CD`: файловая ИБ или хранилище конфигурации). `chdbfl` — оконная и только 32-разрядная; перед запуском обязательна резервная копия, база должна быть закрыта. К клиент-серверной базе на PostgreSQL эти утилиты не относятся; `chdbfl` применима также к хранилищу конфигурации. `cnvdbfl` нужна, когда файл базы должен открываться платформой 8.3.7 и младше (только формат 8.2.14) или требуется сменить размер страницы формата 8.3.8.
15. **`1cv8a ib-check-and-repair`** позволяет без конфигуратора проверить и починить таблицы узлов планов обмена (`-epi` + обязательный `-epiof <файл.xml>`), историю данных (`-dhis`) и итоги регистров с хеш-полями измерений (`-dhi`); исправление выполняется только с `--repair`, без него — одна проверка. К клиент-серверной базе подключение задаётся через `--server=<server:port/infobase>`.
