## 15.1–15.2. Универсальные механизмы обмена данными (обзорно)

- Два уровня механизмов: **универсальные** (для обмена с любыми системами) и **распределённые информационные базы** (РИБ) — готовый механизм поверх универсальных.
- Универсальные механизмы:
  - средства чтения и записи XML;
  - **XML-сериализация** — запись объектов данных «1С:Предприятия» в XML и чтение из XML;
  - **планы обмена** — определяют состав данных и узлы обмена. У плана обмена обязательно есть код и наименование;
  - **инфраструктура сообщений** — нумерация сообщений и подтверждение приёма;
  - **служба регистрации изменений** — запоминает, какие элементы данных изменены и для каких узлов.

## 15.3. Распределённые информационные базы

### 15.3.1. Принципы

- РИБ — иерархия информационных баз (узлов). **Конфигурация изменяется только в корневом узле** и распространяется вниз; во всех узлах она одинакова.
- Данные можно менять в любом узле; изменения расходятся по всей структуре.
- Полная идентичность данных не обязательна: состав обмена ограничивают «по вертикали» (составом плана обмена) и «по горизонтали» (условиями на отдельные элементы данных).
- Документ должен участвовать в последовательности документов только в одном узле.

### 15.3.2. Планы обмена в РИБ

- У плана обмена должно быть установлено свойство **«Распределенная информационная база»**. РИБ может строиться на нескольких таких планах.
- Содержимое сообщения регламентировано платформой (в отличие от универсального обмена). Изменения конфигурации регистрируются и передаются автоматически.
- Запись и чтение сообщения выполняются одним вызовом метода.
- Обработчики модуля плана обмена для управления отдельными элементами данных: `ПриОтправкеДанныхПодчиненному`, `ПриОтправкеДанныхГлавному`, `ПриПолученииДанныхОтПодчиненного`, `ПриПолученииДанныхОтГлавного`.

**Главный и подчинённый узлы.** У узла один главный и сколько угодно подчинённых; узел без главного — корневой. Каждый узел знает только своих «соседей».

**Коллизии.** Изменение, сделанное в главном узле, имеет приоритет. Если элемент пришёл от подчинённого, а его изменение зарегистрировано для этого подчинённого, — он не принимается, регистрация сохраняется. Если пришёл от главного — записывается, регистрация удаляется.

**Начальный образ.** Подчинённый узел создаётся из главного как новая информационная база:

- конфигурация переносится без изменений; расширения — если план обмена их поддерживает;
- узлы плана обмена в образе инициализируются так, что обмен можно начинать сразу;
- данные переносятся по правилам плана обмена (состав и обработчик `ПриОтправкеДанныхПодчиненному`).

Образ можно создать повторно (например, если база узла утрачена); при этом записи регистрации изменений для узла удаляются.

**Структура сообщения.** В теле (`Body`) один элемент `Changes`: `Signature` («подпись» плана обмена), `Config` (изменения конфигурации в элементах `Metadata` — только от главного к подчинённому; контрольные суммы `Digest1`, `Digest2` — в обе стороны), `ConfigurationExtensions`, `Nodes` (только от главного), `Data` (изменённые элементы данных).

**Изменение состава плана обмена.** Добавление объекта в состав работающей РИБ само по себе не регистрирует уже существующие данные — о передаче их в другие узлы нужно позаботиться отдельно.

**Параметры обработчиков:**

- При отправке второй параметр — `ОтправкаЭлементаДанных`: `Авто` (поместить в сообщение), `Удалить` (поместить объект `УдалениеОбъекта`), `Игнорировать` (ничего не помещать).
- При получении второй параметр — `ПолучениеЭлементаДанных`: `Авто` (по правилу коллизий), `Принять` (записать в любом случае), `Игнорировать`. Третий параметр (`ОтправкаНазад`) при значении `Истина` регистрирует изменение для узла-отправителя.

### 15.3.3. Работа с РИБ

**Создание начального образа** — `ПланыОбмена.СоздатьНачальныйОбраз(<узел>, <строка соединения>)`. Целевая база должна быть пустой или не существовать. Вся операция идёт в **одной транзакции** главного узла; при активной работе пользователей возможны конфликты, поэтому целесообразно заранее установить монопольный режим.

**Запись сообщения** — `ПланыОбмена.ЗаписатьИзменения(<ЗаписьСообщенияОбмена>, <число элементов в транзакции>)`. Значение 0 (по умолчанию) — всё в одной транзакции: лучшая согласованность, но выше риск конфликтов. Менять без острой необходимости не рекомендуется.

**Чтение сообщения** — `ПланыОбмена.ПрочитатьИзменения(<ЧтениеСообщенияОбмена>, <число элементов в транзакции>)`. Порядок действий:

1. проверка «подписи» плана обмена;
2. чтение изменений конфигурации и сверка контрольных сумм;
3. удаление записей регистрации для подтверждённых сообщений;
4. если конфигурации узлов различаются: в главном узле приём невозможен; в подчинённом **нужно обновить конфигурацию базы данных** (в конфигураторе), после чего то же сообщение читается повторно. В обоих случаях возникает исключение;
5. чтение и запись элементов данных с вызовом обработчиков.

Логика РИБ допускает потерю отдельных сообщений, но не повторный приём одного и того же; поэтому при `НачатьЧтение()` следует оставлять значение по умолчанию `ДопустимыйНомерСообщения.Больший`.

**Что содержит сообщение** (для автоматического обмена):

- `ПланыОбмена.ПрочитатьОписаниеИзменений()` возвращает `ОписаниеИзмененийКонфигурацийВСообщенииОбмена` со свойствами `КонфигурацияИзменена`, `РасширенияКонфигурацииИзменены`, `ИзмененныеМетаданныеРасширенийКонфигурацииИзменяютСтруктуруДанных`. После него продолжить чтение нельзя.
- `ПрочитатьИзмененияКонфигурацииИРасширенийКонфигурации()` — то же, но чтение можно продолжить, если метаданные не изменились.

**Главный узел.**

- `ПланыОбмена.ГлавныйУзел()` — получить; `ПланыОбмена.УстановитьГлавныйУзел(<узел или Неопределено>)` — установить или отменить. Нужно, чтобы в базе не было других активных пользователей, включая конфигуратор.
- Отменить назначение главного узла из командной строки: ключ пакетного режима конфигуратора **`/ResetMasterNode`**.
- **Восстановление конфигурации в узле РИБ** при наличии предопределённых данных:
  1. `УстановитьОбновлениеПредопределенныхДанныхИнформационнойБазы(ОбновлениеПредопределенныхДанных.НеОбновлятьАвтоматически)` либо ключ `/SetPredefinedDataUpdate -DoNotUpdateAutomatically`;
  2. запомнить ссылку `ГлавныйУзел()`;
  3. отключить от главного узла (`УстановитьГлавныйУзел(Неопределено)` или `/ResetMasterNode`);
  4. восстановить конфигурацию;
  5. вернуть главный узел `УстановитьГлавныйУзел(<запомненная ссылка>)`;
  6. вернуть режим `Авто` (метод или ключ `/SetPredefinedDataUpdate -Auto`).
- При окончательном отключении базы от РИБ для баз, работавших на версиях 8.3.3–8.3.5, сначала вызывают `УстановитьИнициализациюПредопределенныхДанных(Истина)` для объектов с предопределёнными элементами.

**Интерактивно** — команды меню «Еще» (или «Все действия») в списке узлов плана обмена: «Создать начальный образ…», «Записать изменения…», «Прочитать изменения…». Все операции выгрузки и загрузки выполняются на стороне сервера «1С:Предприятия».

### 15.3.4. Сценарии

- **По умолчанию** — каждое изменение стремится попасть во все узлы; коллизии решаются в пользу главного. Обработчики не нужны.
- **Распределение данных по подчинённым узлам** — в `ПриОтправкеДанныхПодчиненному` для «чужих» элементов задают `ОтправкаЭлементаДанных.Удалить` (или `Игнорировать`, если признак распределения не меняется после создания); в `ПриПолученииДанныхОтПодчиненного` при необходимости ставят `ОтправкаНазад = Истина`.
- **Приоритет подчинённого узла** — в `ПриПолученииДанныхОтПодчиненного` задают `ПолучениеЭлементаДанных.Принять`; в `ПриПолученииДанныхОтГлавного` — `Игнорировать`, если `ПланыОбмена.ИзменениеЗарегистрировано()` возвращает «Истина».
