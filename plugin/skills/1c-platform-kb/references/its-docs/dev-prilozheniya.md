## Приложение 1. Конвертация баз 7.7

- Конвертер — программа `V7Cnv.exe`; на компьютере должны стоять и «1С:Предприятие 8», и «1С:Предприятие 7.7» релиза не ниже 7.70.021 (и именно такой релиз должен был запускаться последним).
- Для конвертации в клиент-серверную базу вместо каталога указывают строку соединения с базой на сервере.
- Не конвертируются базовые конфигурации и конфигурации с паролем.
- Ограничения: переносятся объявления процедур, функций и переменных, а исполняемый код комментируется; **пароли пользователей не переносятся**; свойство «Движения» документов после конвертации заполняют вручную.

## Приложение 2. Форматы навигационных ссылок

Ссылка = адрес хоста информационной базы + внутренняя ссылка + параметры. Внешняя ссылка: `<адрес хоста ИБ>#<внутренняя ссылка>?<параметры>` (открытие формы, навигация: объект, отчёт, обработка, раздел, команда) или `<адрес хоста ИБ>/<внутренняя ссылка>?<параметры>` (ресурс: реквизит объекта, запись регистра, временное хранилище).

### Адрес хоста

| Вариант базы | Формат | Пример |
|---|---|---|
| Файловая, путь UNC | `e1c:/file/<UNC путь>` | `\\dbsrvr\bases\mybase` → `e1c:/file/dbsrvr/bases/mybase` |
| Файловая, путь с буквой диска | `e1c:/filev/<буква>/<путь>` | `s:\bases\mybase` → `e1c:/filev/s/bases/mybase` |
| Клиент-серверная | `e1c://server/<имя сервера>/<имя базы>` | `Srvr="srv1C";Ref="mybase"` → `e1c://server/srv1C/mybase` |
| Через веб-сервер | `http(s)://<адрес хоста>/<путь к базе>` | `http://localhost/mybase` |

- В разделённой базе к адресу добавляется `?Z=<значения разделителей>`. Для веб-клиента и тонкого клиента через веб-сервер указываются только те разделители, значения которых при публикации не вынесены в адрес базы.
- **Совет документации:** если с базой работают разные клиенты, сохранять лучше **внутренние** ссылки: внешняя ссылка, полученная в веб-клиенте, может не открыться в тонком клиенте, подключённом напрямую к серверу.

### Внутренние ссылки

Общий вид: `<принадлежность>/<тип>/<путь>[?<параметр>=<значение>[&…]]`; принадлежность `e1cib` — данные в информационной базе, `e1ccs` — на сервере системы взаимодействия.

| Что | Формат |
|---|---|
| Объект | `e1cib/data/<путь к метаданным>?ref=<идентификатор ссылки>` |
| Реквизит объекта | `e1cib/data/<путь>.<реквизит>?ref=<идентификатор>` |
| Реквизит табличной части | `e1cib/data/<путь>.<табличная часть>.<реквизит>?ref=<идентификатор>&index=<индекс строки>` |
| Запись регистра, запись таблицы внешнего источника данных | `e1cib/data/<путь>?<ключевое поле>=<значение>[&…]` |
| Реквизит записи регистра | `e1cib/data/<путь>.<реквизит>?<ключевое поле>=<значение>[&…]` |
| Отчёт | `e1cib/app/<путь>?vrn=<вариант>&stngs=<ключ хранилища>` (при обоих параметрах действует `stngs`) |
| Обработка | `e1cib/app/<путь>` |
| Раздел | `e1cib/navigationpoint/<имя раздела>` |
| Стандартная команда раздела | `e1cib/navigationpoint/<имя раздела>/<имя команды>` |
| Начальная страница | `e1cib/navigationpoint/startpage` (в режиме совместимости 8.3.2 и ниже — `…/desktop`) |
| Временное хранилище | `e1cib/tempstorage/<идентификатор>` |
| Команда глобального командного интерфейса | `e1cib/command/<имя команды>?cmdprm=<параметр>&extdata=<адрес>` |
| Динамический список | `e1cib/list/<имя списка>?stngs=<ключ хранилища>` |
| Обсуждение системы взаимодействия | `e1ccs/data/conv?id=<идентификатор>` |
| Сообщение системы взаимодействия | `e1ccs/data/msg?id=<идентификатор>` |

Правила параметров: разделитель `&`; элементы массива — через запятую; ссылочное значение предваряется именем типа через двоеточие (`ДокументСсылка.РасходнаяНакладная:<идентификатор>`); из одноимённых параметров берётся первый; неизвестные параметры игнорируются; значения ключевых полей кодируются по RFC 1738 (`%` и два шестнадцатеричных символа).

## Приложение 5. Поисковые выражения полнотекстового поиска

| Оператор | Смысл |
|---|---|
| пробел, `И`, `AND`, `&` | должны быть оба слова |
| `ИЛИ`, `OR`, `\|`, `,` | хотя бы одно из слов |
| `НЕ`, `NOT`, `~` (между словами) | первое слово есть, второго нет |
| `РЯДОМ/[±]n`, `NEAR/[±]n` | слова в одном реквизите на расстоянии до n слов; знак задаёт направление |
| `РЯДОМ`, `NEAR` | краткая форма: не дальше 8 слов в любую сторону |
| `"…"` | точная фраза |
| `( )` | группировка |
| `*` | групповой символ |
| `#Хэштег`, `#Хэшт*` | поиск хэштега |

- `И`, `ИЛИ`, `НЕ`, `РЯДОМ` (и английские варианты) пишутся **только в верхнем регистре**; операторы не бывают унарными (нельзя начать ими строку). Спецсимволы и служебные слова для поиска как текста заключают в кавычки.
- По умолчанию поиск с синонимами и нечёткий поиск не выполняются.
- Особенности объекта встроенного языка `ПолнотекстовыйПоиск`:
  - `*` — только один и только в конце слова;
  - `~` — нечёткий поиск: `~Система` (то же, что `Система~1`), `Система~2` — число отличий; только для поиска в данных;
  - `!слово` — поиск с учётом синонимов (русский, английский, украинский языки).

## Приложение 8. Особенности работы с различными СУБД

### Общие

- **В индекс входит не более 16 полей** (в файловом варианте — 256).
- Сравнение строк в языке запросов **не учитывает концевые пробелы**, во встроенном языке — учитывает.

### Файловая база данных

- Не в полной мере поддерживает уникальность индексов: уникальный индекс может содержать неуникальные ключи. **При загрузке `.dt`, выгруженного из такой файловой базы, в клиент-серверную базу возможны фатальные ошибки загрузки** — данные не загрузятся. Рекомендация: найти и исправить ошибочные объекты в файловой базе, затем выгрузить и загрузить заново.
- Файл `.1CD` состоит из внутренних файлов (до четырёх на таблицу: описание, записи, индексы, значения неограниченной длины). Предел размера внутреннего файла: формат 8.2.14 — 4 Гбайт; формат 8.3.8 со страницей 4096 байт — 4 Гбайт; формат 8.3.8 со страницей 8192 байт и больше — 6 Гбайт (в 8.5.1 — 16 Гбайт, см. `otlichiya-8.5.1-ot-8.3.27.md`).
- Длина ключа индекса — не более 1920 байт.

### PostgreSQL (8.6)

- **В автоматическом режиме блокировок используются табличные блокировки**: транзакция, захватившая одну запись, блокирует всю таблицу. Автоматический режим — только для совместимости, **для реальной эксплуатации не рекомендуется**; разработку вести в режиме управляемых блокировок (см. `dev-gl09-rabota-s-dannymi.md`).
- При сортировке по возрастанию `NULL` — последние, по убыванию — первые.
- При интенсивном удалении и добавлении записей (например, перепроведение документов) производительность деградирует; **рекомендуется регулярно выполнять `REINDEX` (или `VACUUM`)** для интенсивно изменяемых таблиц (см. `../postgresql/05-obsluzhivanie-vacuum-analyze-reindex.md`).
- Производительность сильно зависит от дисковой подсистемы, так как `fsync` по умолчанию включён. Документация допускает отключение `fsync` при RAID-контроллере с энергонезависимым кешем и ИБП. Замечание конспекта: документация PostgreSQL предупреждает, что отключение `fsync` грозит невосстановимой порчей данных при сбое, — в базе знаний рекомендуется `fsync` не отключать (`../postgresql/02-postgresql-conf-tyuning-dlya-1c.md`).
- **`ПОЛНОЕ ВНЕШНЕЕ СОЕДИНЕНИЕ` использовать не рекомендуется** (реализовано в СУБД недостаточно эффективно); нельзя сочетать его с обращением к табличным частям в списке полей выборки.
- В `ПОДОБНО` квадратные скобки — спецсимволы только в текстовом литерале, но не в выражении.

### Microsoft SQL Server (8.4)

- Запись таблицы — не более 8060 байт; запись индекса — не более 900 байт (ошибка возникает при вставке значения, а не при обновлении конфигурации).
- При региональных настройках «Казахстан» используется порядок сортировки `Cyrillic_Generic_CI_AS`.
- Ограничения для SQL Server 2000/2005 (256 таблиц в запросе, особенности `ИМЕЮЩИЕ` и группировок по датам) — исторические.

### Oracle Database (8.5), IBM Db2 (8.3) — кратко

- Oracle: в автоматическом режиме — табличные блокировки (как у PostgreSQL); `NULL` при сортировке по возрастанию — последние; важна актуальность статистики (`dbms_stats.gather_schema_stats`), в том числе после загрузки `.dt`; для регистров более чем с тремя строковыми измерениями может потребоваться табличное пространство `V81C_INDEX_BIG`.
- Db2: числа до 31 знака (а не 38), ресурсы регистров до 25 знаков, данные неограниченной длины до 1 Гбайт, до 1012 колонок в выборке; при `COLLATION_SEQUENCE`, отличном от `UCA500R1_LROOT_AN_CX_EX_FX_HX_NX_S2`, не работает фоновое обновление конфигурации базы данных.

## Приложение 10. Особенности отдельных механизмов

- **Форма:** сервер оповещается о закрытии формы (и снимает блокировку объекта) не мгновенно, а при одном из событий: закрытие формы с заблокированным объектом, получение формы с сервера, серверный вызов из формы, закрытие 20 форм, **ожидание более 20 секунд**, некоторые команды динамического списка. Отсюда — объект может оставаться заблокированным до 20 секунд после закрытия формы.
- **Файлы:** в Windows полный путь к файлу — не более 260 символов.
- **Табличный документ:** особенности экспорта в Excel, HTML, PDF, ODS, Word (обрезание многострочного текста, объединение ячеек, картинки, колонтитулы). Текст ячейки длиннее 32 767 символов не сохраняется в формат Excel (ошибка). При экспорте в PDF для символов, отсутствующих в шрифте, шрифт подбирается: в Windows — по таблице диапазонов Юникода, **в Linux и веб-клиенте — из шрифтов, доступных в системе** (на сервере без установленных шрифтов PDF может выглядеть иначе).
- **Почта:** отключение OpenSSL для `ИнтернетПочта` в Windows — через системный реестр (актуально для 8.3.3–8.3.5 и режима совместимости 8.3.5 и ниже).
- **HTML-документ:** элемент `<TABLE>` не может быть вложен в `<P>`.

## Приложения 3, 4, 9, 11, 12 (обзорно)

- **Приложение 3.** Как из свойств метаданных (представления объекта, списка, расширенные представления) складываются тексты стандартных команд и заголовки форм; если свойства не заданы — используется результат метода `Представление()`.
- **Приложение 4.** Какие настройки платформа сохраняет автоматически и в каком хранилище: варианты отчёта, настройки отчёта, данные форм, настройки динамического списка, системное хранилище (настройки форм, отчётов, клиентского приложения, панелей, история глобального поиска, настройки внешних компонент, параметры подключения стандартной обработки управления серверами — адрес и порт сервера администрирования кластера). Ключи объектов зависят от режима совместимости (до и после 8.3.2: `РабочийСтол/…` и `ОсновнойРаздел/…`). Полезно при переносе или очистке настроек пользователей.
- **Приложение 9.** Термины и приёмы работы с объектом `XBase` (файлы DBF): поля и записи, индексы и индексные файлы, пометка удаления без физического удаления. Основное назначение — экспорт и импорт во внешние DBF-файлы.
- **Приложение 11.** Правила автоматического формирования имён элементов формы (префиксы `КоманднаяПанель`, `КонтекстноеМеню`, `Форма`); рекомендация называть программно создаваемые элементы по тем же правилам.
- **Приложение 12.** Сущности стандартного интерфейса OData по видам объектов: состав свойств, имена составных типов (`Catalog_<Имя>_<ТЧ>_RowType`, `Document_…`, `AccumulationRegister_<Имя>_RowType` и т. д.), функции и методы (`Post` для документов, `Balance` и обороты для регистров, `Start` для бизнес-процессов, `ExecuteTask` для задач, `ScheduledData` для регистров расчёта). Для констант не поддерживается удаление; для виртуальных таблиц регистров не поддерживается разворот итогов по периодам. Общие сведения об OData — в `dev-gl17-integraciya.md`.
