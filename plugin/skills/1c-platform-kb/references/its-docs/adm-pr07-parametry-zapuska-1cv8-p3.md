### Формат значения Srvr

```
[<протокол>://]<адрес>[:<порт>]
```

- `<протокол>` — необязателен; поддерживается **только TCP**.
- `<адрес>` — имя сервера либо IP-адрес в формате IPv4 или IPv6.
- `<порт>` — необязателен; это порт главного менеджера кластера, **по умолчанию 1541**.

Примеры из документации:

| Значение | Что задано |
|---|---|
| `server` | Только имя сервера; протокол и порт — по умолчанию. |
| `tcp://server:1641` | Протокол, имя сервера и сетевой порт. |
| `127.0.0.1:1541` | IPv4-адрес и порт. |
| `[fe10::c47b:90b7:fa32:a2fa%12]` | IPv6-адрес (в квадратных скобках); протокол и порт — по умолчанию. |

### Несколько адресов кластера (бесперебойная работа клиентов)

- Значением `Srvr` может быть **список адресов кластера через запятую**. Пробелы в списке недопустимы.
- То же самое допускается в диалоге добавления информационной базы в клиентском приложении: в свойстве «Кластер серверов 1С:Предприятия» можно указать список адресов через запятую.

## 7.8. Командная строка веб-клиента

Раздел описывает два механизма, действующие при запуске веб-клиента:

1. **Команды (параметры) запуска**, управляющие поведением веб-клиента (таблица ниже).
2. **Навигационная ссылка особого вида в URL запуска** — веб-клиент сразу открывает форму указанной стандартной функции.

Как именно параметры записываются в URL, текстом в этой части не объясняется; способ виден только из единственного примера (параметры идут после `?`, разделяются `&`, навигационная ссылка — после `#`).

### Открытие формы стандартной функции

Формат навигационной ссылки:

```
#e1cib/system/<stdFuncName>
```

- Ссылка указывается в URL запуска веб-клиента и приводит к открытию формы названной стандартной функции.
- Возможность работает **только при запуске веб-клиента**.

Пример URL запуска из документации:

```
http://localhost/InfoBase/?mainWindowMode=Workplace&DisableHomePageForms#e1cib/system/AnalyticsSystemManagement
```

(В примере имя параметра написано как `mainWindowMode`, в таблице параметров — `MainWindowMode`.)

### Подробнее об OIDA (OpenID-аутентификация)

- Если параметр `/OIDA` при запуске клиента не задан или задан `/OIDA+`, клиент пытается аутентифицироваться через OpenID-провайдера. Адрес провайдера берётся из файла `default.vrd` публикации этой информационной базы.
- Когда провайдер требует интерактивной аутентификации (это первое обращение либо истёк срок жизни аутентификационных данных), клиент показывает диалог ввода имени и пароля.
- Проверка идёт по списку пользователей информационной базы OpenID-провайдера.
- Пользователь информационной базы, работающей через OpenID-аутентификацию, должен совпадать **по имени** с пользователем информационной базы OpenID-провайдера.

## 7.9. Командная строка мобильной версии

Мобильная версия «1С:Предприятия» понимает часть команд и параметров, которые используются в командной строке запуска клиентских приложений для персонального компьютера. Собственных описаний параметров в этом разделе нет — только перечень поддерживаемого, сгруппированный по тому, в каком разделе описаны соответствующие параметры «настольных» клиентов. Сами ссылки на разделы в текстовой копии утрачены (⚠ в источнике неясно, какие именно разделы имеются в виду), поэтому ниже группы просто пронумерованы в порядке документации.

| Группа (как в документации) | Поддерживаемые параметры |
|---|---|
| 1 | `/N`, `/P`, `/WSN`, `/WSP`, `/WSA`, `/OIDA`, `/Authoff`, `/UsePrivilegedMode`, `/Z`, `/O` |
| 2 | `/HttpsForceTLS1_0` |
| 3 | `/L`, `/VL` |
| 4 | `/ClearCache`, `/C`, `/URL` |
| 5 | `/DisableStartupMessages` |
| 6 | `/TestClient`, `/UILogRecorder` |

Всего 19 параметров. Назначение `/WSN`, `/WSP`, `/WSA`, `/HttpsForceTLS1_0`, `/ClearCache`, `/URL`, `/UILogRecorder` в этой части не описано — документация отсылает к разделам о командной строке клиентских приложений для ПК (ссылки в копии утрачены).

## Что важно администратору Linux

1. **Строка для базы на PostgreSQL** собирается из параметров 7.7.4: `Srvr` (сервер 1С), `Ref` (имя ИБ в кластере), `DBMS=PostgreSQL` (значение пишется именно так), `DBSrvr`, `DB`, `DBUID`, `DBPwd`. Синтаксис самой строки (разделители, кавычки) — в части 2.
2. **`CrSQLDB` по умолчанию `N`**: если базы данных на сервере СУБД ещё нет, без `CrSQLDB=Y` она создана не будет.
3. **Порт по умолчанию в `Srvr` — 1541** (порт главного менеджера кластера); протокол поддерживается только TCP. Нестандартный порт указывается явно, как в примере документации `tcp://server:1641`.
4. **Несколько адресов кластера** перечисляются в `Srvr` через запятую без пробелов — так документация предлагает обеспечивать бесперебойную работу клиентских приложений. То же допускается в поле «Кластер серверов 1С:Предприятия» диалога добавления базы.
5. **IPv6-адрес в `Srvr`** записывается в квадратных скобках, например `[fe10::c47b:90b7:fa32:a2fa%12]`.
6. **`SUsr`** (имя администратора кластера; пароль — в `SPwd`) необходимо задавать, когда в кластере заведены администраторы, а аутентификация ОС для них не настроена или не подходит. Не путать с `DBUID` / `DBPwd` (пользователь СУБД) и `Usr` / `Pwd` (пользователь информационной базы).
7. **`SchJobDn=Y`** создаёт базу с включённой блокировкой регламентных заданий; по умолчанию (`N`) блокировка выключена.
8. **`SQLYOffs`** (0 или 2000, по умолчанию 0) описан как смещение дат для Microsoft SQL Server; применительно к PostgreSQL в этой части о нём ничего не сказано.
9. **`disstt=Y`** запрещает локальное распознавание речи, то есть загрузку моделей распознавания в адресное пространство процессов кластера или автономного сервера. По умолчанию распознавание разрешено.
10. **`LicDstr` по умолчанию `N`**: клиент не берёт клиентскую лицензию у сервера 1С. При `Y` обращение к серверу происходит только после того, как не найдены ни программная лицензия, ни ключ HASP (локальный или сетевой).
11. **Файловая база**: `File` — это каталог, а не файл; формат по умолчанию `8.2.14`; размер страницы (`DBPageSize`, 4k–64k, по умолчанию 4k) настраивается только для формата `8.3.8`.
12. **Блокировка установки соединений и веб-клиент**: чтобы войти в заблокированную базу через веб-клиент, в URL добавляют `UC=<код доступа>`.
13. **Административные формы прямо по URL** (только веб-клиент): `#e1cib/system/<stdFuncName>` — например `EventLog` (журнал регистрации), `ActiveUsers` (активные пользователи), `ServersManagement` (управление серверами), `DataBaseCopiesManagement` (копии базы данных), `FullTextSearchManagement` (полнотекстовый поиск). Всего 26 функций.
14. **Аутентификация в веб-клиенте**: `N=` / `P=` — имя и пароль пользователя ИБ; `WA-` отключает аутентификацию ОС (без параметра действует `WA+`); `OIDA-` отключает OpenID (без параметра действует `OIDA+`, адрес провайдера берётся из `default.vrd` публикации); `OidcSelectedProvider` выбирает провайдера OpenID Connect; `AccessToken` передаёт JWT; `Authoff` выполняет OpenID logout.
15. **Запуск веб-клиента без оператора**: `DisableUnrecoverableErrorMessage` убирает окно невосстановимой ошибки и уводит вкладку на `about:blank` (отчёт уходит автоматически, если это настроено и он не больше 5 Мбайт); `DisableStartupMessages` подавляет стартовый вопрос о несоответствии конфигурации базы данных сохранённой; `TestClient` + `TestClientID=` — режим клиента тестирования. Привилегированный режим (`UsePrivilegedMode` в веб-клиенте, `prmod=1` в строке параметров ИБ) доступен только пользователю с административными правами и всегда отражается в журнале регистрации.
