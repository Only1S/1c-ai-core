## 2.1. Общая информация

- «1С:Предприятие» = набор программных модулей (платформа) + конфигурация (или несколько конфигураций). Модули платформы универсальны и работают с любой конфигурацией в пределах лицензионного соглашения.
- Вместе с платформой ставится драйвер защиты от несанкционированного использования.
- Программа установки позволяет:
  - держать на одном компьютере несколько версий платформы одновременно;
  - выбирать состав устанавливаемых компонентов;
  - выбирать вариант установки сервера «1С:Предприятия».
- Программа запуска из состава платформы работает с единым списком информационных баз для всех версий: 8.0, 8.1, 8.2 и 8.3.

## 2.2. Варианты установки

Для каждой поддерживаемой ОС своя программа установки: семейство Linux, macOS, семейство Windows.

| ОС | Как устанавливается | Особенности |
|---|---|---|
| Windows | Специальная программа установки | Два режима: «для компьютера» и «для пользователя»; режим зависит от прав пользователя и параметров установки (см. 2.5.2.2) |
| Linux | Два способа: программа установки **или** пакетный менеджер ОС | Поддерживается несколько процессорных архитектур |
| macOS | Специальная программа установки | Выбор компонентов невозможен |

Сравнение двух способов установки в Linux:

| Признак | Программа установки | Пакетный менеджер |
|---|---|---|
| Пакетный менеджер ОС | не используется | используется штатный менеджер ОС |
| Графический интерфейс | есть | нет |
| Как задаётся состав компонентов | в GUI либо параметрами командной строки (пакетная установка) | набором устанавливаемых пакетов |
| Архитектуры процессора | только x86 / x86-64 | все поддерживаемые архитектуры |
| Примечание источника | — | привычнее администраторам Linux-сетей |

Перед установкой:
- убедиться, что на компьютере нет вирусов, диск без ошибок и свободного места достаточно;
- могут понадобиться дистрибутивные носители установленной ОС и права локального или сетевого администратора.

## 2.3. Установка в ОС Linux

### 2.3.1. Правила именования файлов дистрибутива

**Способы установки несовместимы между собой.** Чем ставили — тем и удаляют:
- поставлено пакетным менеджером → удалять пакетным менеджером;
- поставлено программой установки → удалять инструментом удаления, который лежит в каталоге конкретной версии.

#### Имена файлов при использовании программы установки

Программа установки для Linux сделана на базе VMware InstallBuilder и существует только для x86 / x86-64. Доступны два установщика, оба в 32- и 64-разрядном вариантах:

| Установщик | Что умеет |
|---|---|
| «1С:Предприятие 8» | установка любого компонента системы |
| «1С:Предприятие 8 Тонкий клиент» | только тонкий клиент и компоненты доступа к серверу «1С:Предприятия» |

Установщики поставляются в zip-архивах; имя архива и имя установщика совпадают с точностью до расширения. Шаблон имени:

```
setup-name-A.B.C.D-arch.ext
```

| Часть имени | Значения | Смысл |
|---|---|---|
| `name` | `full` | установка всех компонентов системы |
| | `thin` | установка тонкого клиента (и компонентов доступа к кластеру серверов) |
| `A.B.C.D` | например `8.3.24.100` | полный номер версии платформы |
| `arch` | `i386` | архитектура x86 |
| | `x86_64` | архитектура x86-64 |
| `ext` | `zip` | архив с программой установки и сопутствующими файлами |
| | `run` | собственно программа установки |

Пример: `setup-full-8.3.24.100-x86_64.run` — 64-разрядный установщик версии 8.3.24.100, позволяющий поставить все компоненты.

Работа со всеми установщиками одинакова, поэтому документация описывает только «1С:Предприятие 8».

**Файл `installAsRoot`** (исполняемый, лежит в том же zip-архиве) — упрощает запуск для неподготовленного пользователя:
1. проверяет, есть ли у текущего пользователя права суперпользователя (root);
2. если прав нет — запрашивает пароль суперпользователя в собственном диалоге;
3. при успешном вводе пароля запускает программу установки с правами root в интерактивном (графическом) режиме.

Эквивалент для подготовленного пользователя:

```
sudo ./setup-*.run
```

(`*` — остальная часть имени установщика.) Если в каталоге несколько run-файлов, `installAsRoot` запустит тот, чьё имя окажется первым в результате поиска по маске `setup-*.run`.

#### Имена файлов при использовании пакетного менеджера

Дистрибутив поставляется набором пакетов; одни и те же пакеты служат и для клиентских приложений, и для кластера серверов. Шаблон имени файла пакета:

```
1c-enterprise-<версия1>-<компонента>_<версия2>.<arch>.<расширение>
```

**`<компонента>`:**

| Компонента | Содержимое |
|---|---|
| `client` | клиентские приложения: толстый клиент и тонкий клиент |
| `thin-client` | тонкий клиент; работа с файловым вариантом информационной базы **не поддерживается** |
| `common` | общие компоненты «1С:Предприятия» |
| `server` | компоненты сервера «1С:Предприятия» и утилита контроля целостности |
| `ws` | адаптер для публикации веб-клиента и интернет-сервисов на веб-сервере Apache HTTP Server (поддерживаемых версий) |
| `crs` | сервер хранилища конфигураций |
| суффикс `-nls` | дополнительные национальные ресурсы (все языки, кроме русского и английского) для соответствующего пакета |

Пример про `-nls`: серверная компонента лежит в двух файлах — `server` (сам сервер + русские и английские ресурсы) и `server-nls` (остальные языки).

**`<версия1>` и `<версия2>`** — обе содержат полный номер версии платформы, но записаны по-разному:

| Позиция | Формат | Пример для 8.3.22.100 |
|---|---|---|
| `<версия1>` | все разделители — точки | `8.3.22.100` |
| `<версия2>` | первые три элемента через точку, четвёртый — через дефис | `8.3.22-100` |

**`<arch>`:**

| Значение | Архитектура | Вариант пакета |
|---|---|---|
| `aarch64` | ARM64 | RPM |
| `amd64` | x86-64 | DEB |
| `arm64` | ARM64 | DEB |
| `e2k` | E2K | RPM |
| `e2k-8c` | E2K | DEB |
| `i386` | x86 | (вариант не уточнён) |
| `x86_64` | x86-64 | RPM |

⚠ в источнике неясно: значение для E2K (DEB) в тексте документации набрано как `e2k-8с` с кириллической буквой «с» на конце — по всей видимости, опечатка; в таблице выше приведено латиницей.

**`<расширение>`:** `rpm` — RPM-версия пакетов; `deb` — DEB-версия пакетов.

Дальше в документации пакеты называются коротко — по имени компоненты. Пример полного имени пакета `common` (DEB, версия 8.3.22.100):

```
1c-enterprise-8.3.22.100-common_8.3.22-100.arm64.deb
```

⚠ в источнике неясно: в этом примере документации префикс набран как `1с-enterprise` с кириллической «с» (опечатка); по шаблону имени префикс — `1c-enterprise` латиницей.

### 2.3.2. Установка с использованием программы установки

#### 2.3.2.1. Описание программы установки

##### 2.3.2.1.1. Общая информация

- Установка начинается с запуска файла `*.run`. До запуска у файла должно быть право на выполнение — обязательно для текущего пользователя; для группы и остальных — по желанию. Выставляется командой `chmod` или через диалог свойств файла в графической оболочке; для этого могут потребоваться права root.
- Два режима работы установщика: интерактивный (описан в 2.3.2.1) и пакетный (см. 2.3.2.2).
- Интерактивный режим — мастер со страницами, переход кнопкой **Далее >**.
- Перед стартом мастера запрашивается язык: на нём строится интерфейс самого установщика, и этот же язык выбирается для установки соответствующего интерфейса платформы. В списке — только языки, на которых реализован пользовательский интерфейс приложений «1С:Предприятия».
- В ходе установки может быть показан список пакетов ОС, нужных платформе, но не найденных на компьютере. Их нужно поставить самостоятельно пакетным менеджером ОС (нужны права root).
- Примеры в документации — для полного дистрибутива в 64-разрядном варианте.

##### 2.3.2.1.2. Приветствие

Стартовое окно мастера установки; настроек нет.

##### 2.3.2.1.3. Выбор компонентов

На странице выбираются устанавливаемые компоненты (флажок перед названием) и каталог установки.

| Компонент | Что входит |
|---|---|
| 1С:Предприятие | основные компоненты платформы, включая компоненты для работы с файловым вариантом ИБ |
| 1С:Предприятие — тонкий клиент | тонкий клиент только для клиент-серверного варианта |
| 1С:Предприятие — тонкий клиент, файловый вариант | тонкий клиент, включая компоненты для работы с файловым вариантом ИБ |
| Сервер 1С:Предприятия 8 | компоненты сервера, включая сервер администрирования и утилиту администрирования |
| Модули расширения веб-сервера | модули расширения веб-серверов для работы веб-клиента и Web-сервисов |
| Администрирование сервера 1С:Предприятия | сервер администрирования кластера серверов |
| Интерфейсы на разных языках | пользовательские интерфейсы на разных языках; английский ставится всегда, отказаться от него нельзя |
| Сервер хранилища конфигураций 1С:Предприятия | компоненты сервера хранилища конфигураций |
| Дополнительные функции администрирования | утилита административной консоли |
| Дистрибутивы тонких клиентов | установка дистрибутивов клиентских приложений (условия доступности — ниже) |
| Liberica JRE | Java Runtime Environment — минимальная реализация виртуальной машины для запуска Java-приложений, без компилятора и средств разработки. Нужна, например, оптимизированному механизму обновления конфигурации базы данных (v2) и утилите лицензирования |
| Контроль целостности | утилита контроля целостности данных |

Компонент «Дистрибутивы тонких клиентов» становится доступен, только если одновременно:
- для установки выбран компонент «Модули расширения веб-сервера»;
- в каталоге с установочными файлами платформы лежит файл вида `win-mac-clients-distr-A.B.C.D.*.run` или `all-clients-distr-A.B.C.D.*.run`.

##### 2.3.2.1.4. Начало установки

После **Далее >** установщик:
- создаёт нужные каталоги;
- копирует файлы выбранных компонентов;
- создаёт конфигурационные файлы;
- регистрирует программные компоненты системы;
- добавляет в список программ ярлыки запуска приложений «1С:Предприятия».

Ход установки показывается индикатором с пояснением текущего действия.

##### 2.3.2.1.5. Завершающие действия

По окончании установщик сообщает об этом; завершение — кнопкой **Завершить**. Перед установкой собственно платформы выполняются две попытки доустановки:

1. **Внешние компоненты-зависимости** — если нужные платформе компоненты отсутствуют на компьютере либо установлены в версиях, не отвечающих системным требованиям платформы.
2. **TrueType-шрифты из набора Microsoft Core Fonts for Web**, в таком порядке:
   - ищется уже установленный пакет со шрифтами;
   - если не найден — попытка поставить из официального репозитория ОС;
   - если в репозитории ОС их нет — попытка загрузки с зеркал SourceForge:

```
http://dfn.dl.sourceforge.net/sourceforge/corefonts/
http://downloads.sourceforge.net/corefonts/
http://heanet.dl.sourceforge.net/sourceforge/corefonts/
http://internode.dl.sourceforge.net/sourceforge/corefonts/
http://jaist.dl.sourceforge.net/sourceforge/corefonts/
http://kent.dl.sourceforge.net/sourceforge/corefonts/
http://nchc.dl.sourceforge.net/sourceforge/corefonts/
http://switch.dl.sourceforge.net/sourceforge/corefonts/
http://ufpr.dl.sourceforge.net/sourceforge/corefonts/
http://voxel.dl.sourceforge.net/sourceforge/corefonts/
```

При пакетной (unattended) установке выполняются те же действия. После успешного завершения платформа готова к работе.

⚠ в источнике неясно: порядок событий в этом разделе описан противоречиво — сначала сказано, что установка завершена, затем что после кнопки «Завершить» «начнётся процесс установки» и перед ним будут выполнены перечисленные попытки доустановки.

#### 2.3.2.2. Пакетная установка

Установщик умеет работать без оконного менеджера, полностью в консоли. Пакетная установка применяется при обновлении клиентского приложения.

| Команда установщика | Назначение |
|---|---|
| `--mode unattended` | включает пакетный (неинтерактивный) режим |
| `--enable-components <список>` | перечень устанавливаемых компонентов; идентификаторы через запятую |

**Идентификаторы компонентов для `--enable-components`:**

| Идентификатор | Что устанавливается |
|---|---|
| `additional_admin_functions` | утилита административной консоли |
| `client_full` | толстый клиент и возможность работы в конфигураторе |
| `client_thin` | тонкий клиент без возможности работы с файловым вариантом ИБ |
| `client_thin_fib` | тонкий клиент, работающий с любым вариантом ИБ |
| `config_storage_server` | сервер хранилища конфигураций |
| `desktop_icons` | ярлыки для различных компонентов системы «1С:Предприятие» |
| `integrity_monitoring` | утилита контроля целостности |
| `liberica_jre` | Java Runtime Environment (JRE) |
| `server` | кластер серверов «1С:Предприятия» |
| `server_admin` | сервер администрирования кластера серверов «1С:Предприятия» |
| `v8_install_deps` | внешние зависимости платформы |
| `ws` | модули расширения веб-сервера |

**Идентификаторы языков интерфейса** (указываются в том же списке `--enable-components`):

| Код | Язык | Код | Язык |
|---|---|---|---|
| `ar` | Арабский | `kk` | Казахский |
| `az` | Азербайджанский | `lt` | Литовский |
| `bg` | Болгарский | `lv` | Латышский |
| `de` | Немецкий | `pl` | Польский |
| `el` | Греческий | `ro` | Румынский |
| `es` | Испанский | `ru` | Русский |
| `fr` | Французский | `tk` | Туркменский |
| `hu` | Венгерский | `tr` | Турецкий |
| `hy` | Армянский | `uk` | Украинский |
| `it` | Итальянский | `vi` | Вьетнамский |
| `ka` | Грузинский | `zh` | Китайский |

Идентификатора для английского в перечне нет: английский интерфейс ставится всегда (см. 2.3.2.1.3).

**Пример из документации.** Задача: 64-разрядная ОС, версия 8.3.24.100, кластер серверов + средства администрирования + JRE + работа с веб-сервером, языки русский и английский. Нужен полный установщик:

```
setup-full-8.3.24.100-x86_64.run --mode unattended --enable-components server,ws,server_admin,liberica_jre,ru
```

В документации «1С» описаны только те команды VMware InstallBuilder, которые нужны для установки платформы; остальные — в пользовательской документации VMware InstallBuilder.

### 2.3.3. Установка с использованием пакетного менеджера

**Лицензионное ограничение:** работа «1С:Предприятия» на процессорах архитектуры ARM64 или E2K доступна только для лицензии КОРП.

- Пакетных менеджеров в Linux много, команды у них разные; за конкретными командами установки из файлов документация отсылает к документации используемого пакетного менеджера (конкретные команды пакетных менеджеров в этом разделе не приводятся).
- Пакеты платформы зависят и друг от друга, и от системных библиотек, которые должны уже стоять на компьютере.
- **`v8-install-deps.sh`** — пакетный файл (скрипт) из комплекта поставки клиентских приложений. Запускается от имени администратора (root) и ставит библиотеки (включая конкретные их версии), необходимые платформе. Порядок: сначала разрешить зависимости этим скриптом, затем ставить клиентское приложение.

**Зависимости между пакетами платформы:**

| Пакет | Зависит от | Примечание |
|---|---|---|
| `common` | — | зависимостей нет |
| `server` | `common` | |
| `ws` | `common` | |
| `crs` | `common`, `server`, `ws` | |
| `client` | `server` | (и, транзитивно, `common`) |
| `thin-client` | — | другие пакеты платформы не нужны; **конфликтует с `common`**: ставится либо `thin-client`, либо остальные пакеты |
| `*-nls` | «свой» базовый пакет | национальные ресурсы |

Пакет ставится только после всех пакетов, от которых он зависит. Пример: для толстого клиента и конфигуратора порядок такой — `common` → `server` → `client`.

Перечень системных зависимостей в ОС Linux вынесен в отдельный раздел документации (вне этой части).

## 2.5. Установка в ОС Windows

> Весь раздел 2.5 — **только Windows**; изложен сжато, но справочные значения сохранены.

### 2.5.1. Доступные программы установки

| Установщик | Что умеет | Разрядность |
|---|---|---|
| «1С:Предприятие 8» | любой компонент системы | 32 и 64 |
| «1С:Предприятие 8 Тонкий клиент» | тонкий клиент и компоненты доступа к серверу | 32 и 64 |
| «1С:Предприятие 8 (x86-64) Сервер» | только 64-разрядный сервер «1С:Предприятия» | только 64 |

Принципы работы одинаковы; документация описывает «1С:Предприятие 8».

### 2.5.2. Описание программы установки

#### 2.5.2.1. Общая информация

- Запуск мастера — `setup.exe` из каталога дистрибутива; страницы листаются кнопкой **Далее >>**.
- **`setup.exe /S`** — «бесшумная» установка: определяется режим установки, параметры берутся из файла `1cestart.cfg`, соответствующего этому режиму; если файла нет — используются настройки по умолчанию.
- **Поиск аппаратного ключа защиты** при запуске клиента управляется параметром `UseHwLicenses` в `1cestart.cfg` пользователя, выполняющего установку. Установщик запишет его, если задать `USEHWLICENSES` одним из способов:
  - в командной строке:
    ```
    setup.exe USEHWLICENSES=0
    ```
  - в файле `setup.ini` — в параметре `CmdLine` группы `Startup`.

#### 2.5.2.2. Определение режима установки

Режим определяется по двум вещам: (1) значение параметра `InstallForUsers` файла `1cestart.cfg` и параметра `ALLUSERS` командной строки установщика; (2) права пользователя, выполняющего установку.

Результирующее значение параметра (по приоритетам):
- нигде не задано (первая установка) → `0`;
- задано только в `1cestart.cfg` → берётся значение из файла;
- задан `ALLUSERS` в командной строке → берётся он, независимо от содержимого `1cestart.cfg`.

Пользователь считается администратором, если выполняется хотя бы одно: права администратора локального компьютера; членство в группе локальных администраторов; разрешение на установку программ (политика `AlwaysInstallElevated`).

| Значение параметра | Администратор | Обычный пользователь |
|---|---|---|
| `0` — установка зависит от прав | К | Д или П |
| `1` — установка «для компьютера» | К | Д или К |
| `2` — установка «для пользователя» | П | Д или П |
| `3` — установка «для пользователя» без вопросов | П | П |

Обозначения: **К** — «для компьютера» без выбора; **П** — «для пользователя» без выбора; **Д** — показывается диалог выбора режима.
- Для не-администратора при значениях 0–2: «Д» — при интерактивной установке, второй из указанных режимов — во всех остальных случаях.
- Если выбран режим, требующий пароля администратора, а пользователь его не знает — установка невозможна.
- Выбор, сделанный в диалоге, запоминается в `1cestart.cfg`.

Каталоги по умолчанию: «для компьютера» — `%PROGRAMFILES%` или `%PROGRAMFILES(x86)%`; «для пользователя» — `%LOCALAPPDATA%\Programs`.

Для успешной установки «для пользователя» в системе должен стоять пакет Microsoft Visual C++ Redistributable из состава устанавливаемой версии платформы (`vc_redist.x86.exe` или `vc_redist.x64.exe`); его установка в любом случае требует прав локального или сетевого администратора.

#### 2.5.2.3. Приветствие

Стартовое окно мастера; настроек нет.

#### 2.5.2.6. Установка сервера «1С:Предприятия»

- Страница появляется, если выбран компонент «Сервер 1С:Предприятия 8»: выбирается режим установки сервера и пользователь, под которым сервер будет работать как сервис ОС Windows.
- При установке «для пользователя» страница недоступна — сервер нельзя поставить как сервис Windows.
- Для режима сервиса обязательно указать пароль выбранного пользователя, иначе установщик не сможет запустить сервер.
- Если уже есть версия платформы с сервером-сервисом, установщик переустановит сервис.

#### 2.5.2.7. Начало установки

После **Установить**: создаются каталоги, копируются файлы, создаются конфигурационные файлы, регистрируются компоненты, на рабочем столе создаётся ярлык, запускается сервер (если выбран режим сервиса). В «Установка и удаление программ» для каждой версии появляется своя запись вида `1С:Предприятие 8 (A.B.C.D)`.

#### 2.5.2.8. Установка драйвера защиты

- Недоступно при установке «для пользователя». После установки мастер предлагает поставить драйвер защиты **HASP Device Driver**.
- Драйвер нужен, если к USB-порту компьютера будет подключаться аппаратный ключ (основная поставка, клиентская лицензия хотя бы на одно рабочее место, лицензия на сервер). Рекомендуется ставить драйвер **до** подключения ключа.
- Вместе с драйвером автоматически ставится веб-интерфейс управления им. Для безопасности рекомендуется его отключить — оставить флажок «Отключить неиспользуемые 1С:Предприятием возможности аппаратных ключей защиты (рекомендуется)». Подробности об обновлении драйвера и отключении веб-интерфейса: https://its.1c.ru/db/metod8dev#content:5936:hdoc

#### 2.5.2.9. Завершающие действия

- Флажок «Открыть файл Readme» — откроет `readme.htm` на языке интерфейса по умолчанию.
- Флажок «Установить дистрибутивы тонкого клиента для автоматического обновления клиентов через веб-сервер в каталог установки» — запустит установку дистрибутивов клиентских приложений; рекомендуется только на компьютере с расширением веб-сервера; нужны права администратора. Доступен, если выбран компонент «Модули расширения веб-сервера» **и** в каталоге установочных файлов есть файл вида `win-mac-clients-distr_A.B.C.D.exe` или `all-clients-distr_A.B.C.D.exe`.
- Состояние этого флажка запоминается в параметре `InstallComponents` файла `1cestart.cfg`, ключ `COPYTHINCLIENTDST`.
- Завершение — кнопкой **Готов**.

### 2.5.3. Особенности регистрации компонент

- Установщик регистрирует COM-объекты `V83.COMConnector` (COM-соединение) и `V83.Application` (клиентское приложение): при установке «для компьютера» — для компьютера, при установке «для пользователя» — для пользователя.
- **Правило совместимости версий COM-соединения:** версия, к которой подключаются через `V83.COMConnector`, и версия, из которой создаётся соединение, должны либо различаться по первым двум числам версии, либо совпадать полностью. Примеры: из 8.3 можно подключиться к 8.2, 8.1 и т. д.; из 8.3.6 к 8.3.5 — нельзя; 8.3.6.2100 ↔ 8.3.6.2100 — можно.
- Ошибка `regsvr32`: `The module ... was loaded but the call to DllRegisterServer failed with error code 0x80070005` — у пользователя нет прав на изменение реестра или файлов в `System32`. Регистрировать от имени администратора, запуская `regsvr32` через «Запуск от имени администратора».

#### 2.6.3.10. Установка с использованием административных средств ОС Windows

##### 2.6.3.10.1. Установка с помощью групповых политик

- Язык установки задаётся языковым файлом трансформации: имя = десятичный LCID Microsoft Windows с расширением `.mst`; для русского — `1049.mst`.
- Дополнительно указывается файл трансформации **`adminstallrestart.mst`**: при несовпадении версий клиента и сервера платформа предложит перезагрузить компьютер для установки новой версии. Новый дистрибутив администратор должен заранее добавить в групповые политики.
- Через групповые политики можно ставить несколько версий; для новой версии создаётся новая установка в политиках.

##### 2.6.3.10.2. Установка с помощью logon-скрипта

- Установка из скрипта, выполняемого при входе пользователя в домен (задаёт администратор домена). Если у пользователя нет прав на установку ПО — скрипт выполняется от имени пользователя, которому установка разрешена.
- Скриптом можно ставить и удалять несколько версий — вызовом процедуры `installOrUninstall` с нужными параметрами (сам пример скрипта — в другом разделе документации).
- Для новой версии достаточно поправить пути общих сетевых ресурсов и код продукта (берётся из `setup.ini`).
- Дополнительно указывается файл трансформации **`adminstallrelogon.mst`**: при несовпадении версий клиента и сервера платформа предложит завершить сеанс пользователя для установки новой версии. Скрипт и дистрибутив на сетевом ресурсе должны быть актуальны.

##### 2.6.3.10.3. Обновление версии

- При установке административными средствами в каталоге конфигурационных файлов создаётся файл **`adminstall.cfg`**.
- Если при запуске ИБ нужная версия платформы на компьютере не найдена и у пользователя нет прав её установить — ему предлагается действие из `adminstall.cfg`: перезагрузка компьютера или повторный вход в систему (logon).

## Что важно администратору Linux

1. **Два способа установки несовместимы.** Что поставлено пакетным менеджером — удалять им же; что поставлено `.run`-установщиком — удалять инструментом из каталога конкретной версии. Смешивать нельзя.
2. **`.run`-установщик есть только для x86 / x86-64.** На ARM64 и E2K — только пакеты, причём работа платформы на ARM64/E2K доступна лишь по лицензии КОРП.
3. **Имена пакетов:** `1c-enterprise-<версия1>-<компонента>_<версия2>.<arch>.<расширение>`; версия записана дважды в разном формате (`8.3.22.100` и `8.3.22-100`). Для DEB на x86-64 архитектура — `amd64`, для RPM — `x86_64`.
4. **Порядок установки пакетов задаётся зависимостями:** `common` → `server` → `client`; `ws` требует `common`; `crs` требует `common`, `server` и `ws`; `*-nls` требуют свой базовый пакет.
5. **`thin-client` конфликтует с `common`** — на одной машине либо `thin-client`, либо остальные пакеты платформы; значит, рядом с пакетом `server` (которому нужен `common`) `thin-client` не поставить.
6. **Пакет `server` требует только `common`;** для публикации на веб-сервере добавляется `ws` (адаптер под Apache HTTP Server поддерживаемых версий, зависит от `common`). Пакеты `-nls` — это ресурсы языков помимо русского и английского.
7. **Утилита контроля целостности входит в пакет `server`;** для административной консоли по документации ставятся `client` + `server`.
8. **Системные зависимости** при установке пакетами разрешает скрипт `v8-install-deps.sh` из комплекта поставки клиентских приложений (запуск от root, до установки клиентского приложения); у `.run`-установщика есть идентификатор компонента `v8_install_deps` — «внешние зависимости платформы».
9. **Тихая установка `.run`:** `--mode unattended --enable-components <id,id,...>`; пример документации для сервера с веб-публикацией — `server,ws,server_admin,liberica_jre,ru`. Перед запуском дать файлу право на выполнение (`chmod`); запуск с правами root — `sudo ./setup-*.run`.
10. **Сервер администрирования кластера** в `.run`-установщике — отдельный идентификатор (`server_admin`), административная консоль — `additional_admin_functions`, JRE — `liberica_jre` (нужна, например, механизму обновления конфигурации БД v2 и утилите лицензирования).
11. **Шрифты Microsoft Core Fonts** `.run`-установщик пытается поставить сам (и в пакетном режиме тоже): ищет установленный пакет, затем официальный репозиторий ОС, затем зеркала SourceForge по HTTP. Последний шаг требует исходящего доступа к этим адресам.
12. **Вся установка в Linux — с правами root.** Ярлыки клиентских приложений (`1cestart`, `1cv8c`, `1cv8`) появляются в меню приложений: категория Office, подкатегория Finance.
13. **Публикация веб-клиента** после установки `ws` делается из конфигуратора (диалог публикации на веб-сервере) или утилитой `webinst` (она — только для веб-клиента).
14. **Версии COM-соединения** (правило из раздела о Windows, 2.5.3): версии должны либо отличаться в первых двух числах, либо совпадать полностью — из 8.3.6 к 8.3.5 подключиться нельзя.
15. **В документации есть опечатки и нестыковки:** кириллическая «с» в `e2k-8с` и `1с-enterprise`, `client-nls` для `thin-client`, противоречие о поддержке файловых ИБ пакетом `thin-client`. При сомнениях сверяться с фактическими именами файлов дистрибутива.
