## 34.2. Интеграция с «1С:Аналитикой»

- Чтобы пользователи могли работать с системой аналитики: опубликовать базу на веб-сервере с флажком **«Публиковать систему аналитики»**; стандартной функцией указать в базе адрес сервера «1С:Аналитики»; дать пользователям право `КлиентСистемыАналитики`.
- Адреса: `http://host/base/ans` — клиент системы аналитики; `http://host/base/ans/data` — доступ аналитики к данным базы. Оба работают только после публикации с указанным флажком. Разделители параметром `Z` не указываются.
- Аутентификацию выполняет «1С:Предприятие».
- Из встроенного языка — свойство `СистемаАналитики`: `УстановитьАдресСервераСистемыАналитики()`, `ПолучитьАдресСервераСистемыАналитики()`, `Открыть()`.

## 34.3. Региональные настройки

- Задаются для информационной базы (интерактивно в конфигураторе или из кода) и для сеанса (только читаются).
- База: `ПолучитьРегиональныеНастройкиИнформационнойБазы()`, `УстановитьРегиональныеНастройкиИнформационнойБазы()` (нужно право «Администрирование»). Объект `РегиональныеНастройкиИнформационнойБазы`: `КодЛокализации` (допустимые — `ПолучитьДопустимыеКодыЛокализации()`), `ИспользоватьНастройкиТекущегоСеанса`, `РазделительДробнойЧастиЧисел`, `РазделительГруппЦифрЧисел`, `ФорматГруппировкиЦифрЧисел`, `ПредставлениеОтрицательныхЧисел` (−1 — авто, 0…4 — варианты записи минуса), `ПредставлениеБулевоЛожь`, `ПредставлениеБулевоИстина`, `ФорматПредставленияДаты`, `ФорматПредставленияВремени`, `ПервыйДеньНедели` (0 — по коду локализации).
- Сеанс: `ПолучитьРегиональныеНастройкиСеанса()` возвращает `РегиональныеНастройкиСеанса` (только чтение; формируются до старта сеанса). Учитывают ключи командной строки клиента `/L` (язык интерфейса, свойство `КодЯзыкаИнтерфейса`) и `/VL` (язык локализации, свойство `КодЛокализации`).

## 34.4. Активация программных лицензий из встроенного языка

Менеджер — свойство глобального контекста `ПолучениеЛицензий`. Позволяет повторить в коде диалог «Сервис — Получение лицензии» конфигуратора.

**Различия видов лицензий:**

| | Обычная (ПРОФ, КОРП, клиентская, серверная) | Для разработчиков |
|---|---|---|
| Параметры | регистрационный номер комплекта и пинкод | имя и пароль учётной записи на портале разработчиков (`developer.1c.ru` или `1c-dn.com`) |
| Владелец | вводится при активации (организация или физическое лицо) | берётся с портала, только физическое лицо |
| Привязка | компьютер или аппаратный ключ HASP | только компьютер |

**Объект `ЗапросНаПолучениеЛицензии`:**

- `РегистрационныйНомер`, `Пинкод` (**без разделителей**), `СтарыйПинкод` (при повторном получении по резервному пинкоду — пинкод прежней активации, тоже без разделителей), данные владельца, `Страна` (двухбуквенный код; допустимые — `ПолучитьДопустимыеСтраны()`);
- для лицензии разработчика — только `ИмяУчетнойЗаписи`, `ПарольУчетнойЗаписи`, при желании `ПорталРазработчиков`;
- `ДляВсехПользователей` — куда класть файл лицензии: в каталог текущего пользователя или в общий;
- `ИмяФайлаЛицензии`; `ВремяЗапроса`;
- `ПараметрыПривязки` — объект `ПараметрыПривязкиККомпьютеруПолученияЛицензий` либо `ПараметрыПривязкиККлючуПолученияЛицензий`;
- **`АдресАгента` и `Порт`** — адрес и порт агента сервера «1С:Предприятия», если лицензия активируется не для текущего компьютера, а для компьютера с кластером серверов.

**Порядок:**

1. Параметры привязки: `ПолучитьПараметрыПривязкиККомпьютеру()` (для компьютера с кластером версии клиента и кластера должны **точно совпадать**; состав параметров зависит от ОС) или `ПолучитьДоступныеКлючи()` (ключи HASP, доступные сейчас).
2. Проверка: `ПолучитьДоступностьПолученияЛицензии()` — можно ли записать файл лицензии в нужный каталог на текущем компьютере или на компьютере агента сервера.
3. Получение одним из способов:
   - `ПолучитьЛицензиюАвтоматически()`;
   - по телефону — `СоздатьЗапросНаПолучениеЛицензииПоТелефону()`, `СформироватьКонтрольнуюСуммуСтрокиКодаПолученияЛицензии()`, затем `ПолучитьЛицензиюПоТелефону()`;
   - на носителе — `СоздатьЗапросНаПолучениеЛицензииПоНосителе()`, затем `ПолучитьЛицензиюНаНосителе()`.
4. Запрос можно сохранить и загрузить: `СохранитьЗапросНаПолучениеЛицензии()`, `ЗагрузитьЗапросНаПолучениеЛицензии()` (сохранённые данные подхватит и диалог конфигуратора).

Сведения о Центре лицензирования: `АдресЦентраЛицензирования()`, `АдресЭлектроннойПочтыЦентраЛицензирования()`, `НомерТелефонаЦентраЛицензирования()`, `ПредставлениеЦентраЛицензирования()`, `ПолучитьДоступностьЦентраЛицензирования()`. Параметр страны: пустая строка (по коду локализации базы), `ru`/`ru_RU`, `kk`/`kk_KZ`, `uk`/`uk_UA`.

Для лицензии разработчика: `ПолучитьДоступностьИспользованияЛицензииРазработчика()`, `ПолучитьЛицензионноеСоглашениеРазработчика()`.

## 34.5. Уведомление клиента со стороны сервера

- Менеджер `УведомленияКлиента` — уведомления без системы взаимодействия.
- Сервер (например, фоновое задание): `ОтправитьУведомление(Ключ, Данные, Адресаты)`; адресаты — номера сеансов (`СеансИнформационнойБазы.НомерСеанса`; у фонового задания — `НомерРодительскогоСеанса`, 0 — если задание запущено не клиентом).
- Клиент: `ПодключитьОбработчик(Ключ, <ОписаниеОповещения>)`, `ОтключитьОбработчик(Ключ)`; ключ `Неопределено` — все уведомления.
- Уведомление хранится в специальном хранилище до получения адресатом или до исчезновения сведений о сеансе. Хранилище обслуживает: в клиент-серверном варианте — **специальный сервис кластера**; в файловом — клиентское приложение или расширение веб-сервера.

## 34.6. Пользователи и аутентификация из встроенного языка

Менеджеры: `ПользователиИнформационнойБазы`, `ДополнительныеНастройкиАутентификации`, `ПолитикиПаролейПользователей`.

### 34.6.2. Пользователи

- `СоздатьПользователя()`, `ТекущийПользователь()`, `НайтиПоИмени()` (без имени — «пользователь по умолчанию»), `НайтиПоУникальномуИдентификатору()`, `ПолучитьПользователей()`.
- Свойства `ПользовательИнформационнойБазы`: `Имя`, `ПолноеИмя`, `Аутентификация…` (доступные виды аутентификации), `ЗапрещеноИзменятьПароль`, `ПоказыватьВСпискеВыбора`, `Роли`, `КлючиСопоставленияПользователя` (для OpenID Connect и токена доступа; используется, когда в `default.vrd` у провайдера `authenticationUserPropertyName` равно `matchingKey`), **`КлючТребованияНазначения`** (группировка пользователей для требований назначения функциональности — привязка соединений к рабочим серверам), `ПарольНеСоответствуетТребованиям`, `РазделениеДанных`, `ИмяПолитикиПаролей`.
- `ТекущийПользователь()` возвращает состояние пользователя на момент старта сеанса, даже если его запись потом изменили.

### 34.6.3. Сохранение аутентификации

`ПолучитьНастройкиАвтоматическогоСохраненияАутентификации()` и `УстановитьНастройкиАвтоматическогоСохраненияАутентификации()`; объект `НастройкиАвтоматическогоСохраненияАутентификации`: `РазрешитьСохранение` (флажок «Запомнить» в диалоге входа), `СохранятьПоУмолчанию`, `ВремяЖизниСохраненнойАутентификации`.

### 34.6.4. Политика паролей

- Объект `ПолитикаПаролейПользователей` (свойства повторяют диалог параметров информационной базы, плюс `Имя`; методы `Записать()`, `Удалить()`). Менеджер: `ПолучитьПолитики()`, `НайтиПоИмени()`, `СоздатьПолитику()`, `ПроверитьСоответствиеПароляПолитике()`.
- Проверка возвращает массив значений `РезультатПроверкиСоответствияПароляПолитике`: `НеСоответствуетТребованиямМинимальнойДлины`, `НеСоответствуетТребованиямОграниченияПовторенияСредиПоследних`, `НеСоответствуетТребованиямПроверкиРаскрытия`, `НеСоответствуетТребованиямСложности`; пустой массив — пароль подходит.
- Отдельная политика для пользователя: создать и записать политику, затем указать её имя в `ПользовательИнформационнойБазы.ИмяПолитикиПаролей`.
- Политика всей базы — пары методов `Получить…`/`Установить…`: `ДействиеПриНесоответствииПаролейПользователейТребованиямПриАутентификации`, `ОграничениеПовторенияПаролейПользователей`, `МаксимальныйСрокДействияПаролейПользователей`, `МинимальнуюДлинуПаролейПользователей`, `МинимальныйСрокДействияПаролейПользователей`, `ПроверкуРаскрытияПаролейПользователей`, `ПроверкуСложностиПаролейПользователей`, `СрокПредупрежденияОбИстеченииСрокаДействияПаролейПользователей`.

**Пароль пользователя:**

- `Пароль` — только запись; `СохраняемоеЗначениеПароля` — хеш, читается и пишется (годится для переноса пользователей в другую базу; восстановить пароль по нему нельзя).
- `ГенераторСлучайныхПаролей.СлучайныйПароль()` — по умолчанию 7 символов (или минимальная длина из настроек базы, если она больше); параметры `ДлинаПароля`, `ЗапоминающийсяПароль`.
- `ВычислитьСохраняемоеЗначениеПароляПользователя()` (для одного пароля может давать разные хеши — это нормально), `ПроверитьСоответствиеПароляПользователяСохраняемомуЗначению()`.
- `ТипАлгоритмаХешированияПароля`: хеш пользователя пересчитывается при его следующей аутентификации после смены алгоритма базы. Если у пользователя алгоритм отличается от текущего алгоритма базы — он не входил после смены.
- `ДатаУстановкиПароля` (видна администратору), `ЗаписываемаяДатаУстановкиПароля`.

### 34.6.5. Восстановление пароля

- Способы (`СпособВосстановленияПароляПользователяИнформационнойБазы`): `Нет`; `ПереходПоНавигационнойСсылке` (вся логика на внешнем сайте; к ссылке добавляется `?Z="…"`); `ОтправкаКодаПодтвержденияЧерезСтандартныйСервис` (почтовый сервис фирмы «1С», письма приходят с адреса `recoverypassword@1c.com`; в базе должны быть заданы имя и пароль Портала ИТС — «Администрирование — Установить настройки клиента лицензирования» или `УстановитьНастройкиКлиентаЛицензирования()`); `ОтправкаКодаПодтвержденияПоЗаданнымПараметрам` (свой SMTP).
- Объект `НастройкиВосстановленияПароляПользователя`: `АдресСервераSMTP`, `ПортSMTP`, `ПользовательSMTP`, `ПарольSMTP`, `ИспользоватьSSL`, `ТолькоЗащищеннаяАутентификацияSMTP`, `АутентификацияПоТокену`, `ТокенДоступа`, `Отправитель`, `ИмяОтправителя`, `Заголовок`, `ТекстСообщенияHTML` (переменные `&UserName`, `&UserPresentation`, `&VerificationCode`, `&ApplicationPresentation`), `ДлинаКодаПодтверждения`, `СрокДействияКодаПодтверждения`, `МаксимальноеКоличествоНеуспешныхПроверокКодаПодтверждения`, `ДлительностьБлокировкиЗапросаОбновленияКодаПодтверждения`, `НавигационнаяСсылкаВосстановленияПароля`, `ОтображатьГиперссылкуПомощи`, `НавигационнаяСсылкаПомощи`.
- Методы: `ПолучитьНастройкиВосстановленияПароля()`, `УстановитьНастройкиВосстановленияПароля()`. У каждого пользователя должен быть корректный адрес электронной почты.
- При OpenID-аутентификации пароль меняется на стороне провайдера.

### 34.6.6. Аутентификация через электронную почту

- Объект `НастройкиАутентификацииЧерезЭлектроннуюПочту` — те же параметры SMTP и кода подтверждения, плюс `АлфавитКодаПодтверждения` (пусто — цифры; иначе от 10 до 256 разных символов) и `СпособАутентификацииЧерезЭлектроннуюПочту` (`Нет`, `ОтправкаКодаПодтвержденияЧерезСтандартныйСервис` — письма с адреса `authentication@1c.com`, `ОтправкаКодаПодтвержденияПоЗаданнымПараметрам`).
- Методы: `ПолучитьНастройкиАутентификацииЧерезЭлектроннуюПочту()`, `УстановитьНастройкиАутентификацииЧерезЭлектроннуюПочту()`. Пользователю нужно включить этот вид аутентификации и задать уникальный адрес почты.

### 34.6.7. Проверка раскрытия паролей

- Объект `НастройкиПроверкиРаскрытияПароля`: `ИспользоватьСтандартныйСписокПроверкиРаскрытияПароля` (список, встроенный в платформу), `ИспользоватьЗаданныйСписокПроверкиРаскрытияПароля` (свой список), `ИспользоватьСервисПроверкиРаскрытияПароля` и `АдресСервисаПроверкиРаскрытияПароля` (внешний REST-сервис; в примере документации — `https://api.pwnedpasswords.com/range/`), `ТаймаутЗапросаСервисаПроверкиРаскрытияПароля`, `ИгнорироватьОшибкиСервисаПроверкиРаскрытияПароля`.
- При обращении к сервису платформа передаёт заголовок `user-agent` вида `1C:Enterprise 8.3 (A.B.C.D)`.
- Свой список: менеджер `ДополнительныеНастройкиАутентификации.СписокПроверкиРаскрытияПаролей` — `УстановитьСписокИзПаролей()`, `ДобавитьВСписокИзПаролей()`, `УстановитьСписокИзСохраняемыхЗначенийПаролей()`, `ДобавитьВСписокИзСохраняемыхЗначенийПаролей()` (хеш SHA-1 в Base64), `ПолучитьСписокСохраняемыхЗначенийПаролей()`, `ПолучитьКоличествоСохраняемыхЗначенийПаролей()`. Не более **100 000** значений.
- Проверить один пароль — `ПроверитьРаскрытиеПароля()`.
