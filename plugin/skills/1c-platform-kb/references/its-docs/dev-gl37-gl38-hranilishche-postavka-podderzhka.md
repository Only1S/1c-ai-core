# Глава 37. Групповая разработка конфигурации

## 37.1. Принцип

- Хранилище конфигурации — общая база версий конфигурации. Объект конфигурации может менять только тот разработчик, который его **захватил**; одновременно объект захвачен только одним пользователем.
- «Конфигурация» в этой главе — и основная конфигурация, и любое расширение, подключённое к базе, где ведётся разработка.
- Чтобы добавить объект, нужно захватить его родителя (для новой константы или справочника — корневой объект конфигурации; для реквизита или формы — сам объект). Чтобы удалить объект — захватить его, его родителя и все подчинённые ему объекты.
- Доступ к хранилищу: каталог в локальной сети либо удалённо — через сервер хранилища (TCP) и веб-сервер (HTTP).

## 37.2. Администрирование хранилища

### Создание и формат

- При создании задаются имя и пароль администратора хранилища. Ссылка «Сгенерировать пароль» создаёт пароль по политике паролей; если политика не задана — 7 символов.
- **Хранилище конфигурации и хранилище расширения несовместимы**: к одному нельзя подключиться для работы с другим.
- Файл базы хранилища — `1cv8ddb.1CD`, создаётся в формате версии **8.3.8**. Размер страницы в тексте документации указан как «8 912 байта» (по смыслу, скорее всего, опечатка вместо 8 192 — такое значение страницы по умолчанию приведено в описании `cnvdbfl`; это вывод конспекта, а не текст документации).
- Формат и размер страницы меняет утилита `cnvdbfl`. К хранилищу, созданному платформой 8.3.10 и новее, конфигуратор 8.3.7 и старше не подключится без конвертации файла в формат 8.2.14.

### Подключение и соединение

- Подключение: «Конфигурация — Хранилище конфигурации — Подключиться к хранилищу». **Текущая конфигурация базы замещается конфигурацией из хранилища.**
- Для одного пользователя хранилища к хранилищу может быть подключена только одна информационная база. Если подключить вторую под тем же пользователем, работать сможет только подключившийся последним; первый получит «Информационная база не связана с хранилищем конфигурации» и должен подключиться под другим пользователем хранилища.
- Сообщения, которые встречаются при соединении:
  - «Ошибка аутентификации! Проверьте правильность введенного имени пользователя и пароля.» — неверные имя или пароль либо этот пользователь уже работает с хранилищем;
  - «Пользователь существующей связи отличается от текущего» — попытка соединиться под другим пользователем: нужно отключиться от хранилища и подключиться заново;
  - «Месторасположение информационной базы изменилось. Продолжить?» — база перенесена; при согласии хранилище запоминает новое место.
- Если переехало само хранилище, новый адрес указывают в диалоге соединения.

### Права пользователей хранилища

| Право | Что даёт |
|---|---|
| Административные функции | создание, удаление и отключение пользователей, отмена чужого захвата, смена режима совместимости хранилища, оптимизация |
| Изменение состава версий | откат и сокращение истории версий |
| Захват объектов | захват и изменение; без этого права — только просмотр |

Пользователь может менять собственные имя и пароль, но не права. Администратору в списке видно, у кого не задан пароль. Отключить можно пользователя, не работающего в этот момент с хранилищем; отключённый теряет возможность поместить изменения захваченных им объектов.

### Режим совместимости хранилища

| Режим | Реализован в версии | Какие версии могут работать |
|---|---|---|
| Версии 8.3.2 и младше | 8.3.3 | любая |
| Версии 8.3.3 – 8.3.5 | 8.3.6 | 8.3.3 и новее |
| Не использовать | — | 8.3.6 и новее |

- Переход к режиму «8.3.3 – 8.3.5» и выше преобразует хранилище в оптимизированный формат (быстрее, в том числе через сервер хранилища). Преобразование может идти долго; выполняет его пользователь с административными правами. Обратное преобразование возможно.
- У нового хранилища режим — «Не использовать».
- **Оптимизация данных хранилища** (для хранилищ не в режиме совместимости с 8.3.2) — выполнять, когда система сама это предложит; во время оптимизации работать с хранилищем не рекомендуется. Из командной строки — ключ запуска конфигуратора `/ConfigurationRepositoryOptimizeData`.
- **Политика паролей** пользователей хранилища настраивается в том же окне (менять может только администратор хранилища); параметры глобального файла — см. `cfgrepo.conf`.

### Кеш версий

- Два кеша: **локальный** (на компьютере конфигуратора) и **глобальный** (там, где лежит каталог хранилища). Поиск версии идёт сначала в локальном, потом в глобальном, и только затем — в самом хранилище.
- Локальный кеш создаётся, когда хранилище лежит на сетевом диске или работа идёт через сервер хранилища. Каталог по умолчанию:
  - Windows: `%APPDATA%\1C\1Cv8\<идентификатор ИБ>\cfgrepo\cache`;
  - Linux: `~/.1cv8/1C/1cv8/<идентификатор ИБ>/cfgrepo/cache`.
- Размер по умолчанию — 500 Мбайт; при превышении удаляются самые старые версии в объёме 50 % кеша. Глобальный кеш чистится по тому же алгоритму.
- Параметры обоих кешей задаются в окне администрирования хранилища или в файле `cfgrepo.conf`.

### 37.2.8. Резервное копирование хранилища

**Во время копирования к хранилищу не должно быть ни одного подключения.** Что копировать:

- режим совместимости «Версии 8.3.2 и младше» — только файл `1Cv8ddb.1CD`;
- любой другой режим — файл `1Cv8ddb.1CD` **и целиком каталог `data`**, лежащий рядом с ним.

## 37.3. Работа с хранилищем (кратко)

- **Захват**: вместе с выбранным объектом могут потребоваться связанные объекты — их нужно получить из хранилища, иначе захват не выполняется. Флажок «Выполнять рекурсивно» распространяет действие на подчинённые объекты. Флажок «Разрешить получать захваченные» перезаписывает локальные изменения в уже захваченных объектах — они теряются.
- **Помещение**: связанные объекты помещаются вместе с выбранным; флажок «Оставить захваченными» сохраняет захват.
- **Отмена захвата** возвращает объект к состоянию из хранилища.
- **История хранилища**: просмотр версий, сравнение, загрузка версии вместо текущей конфигурации, сохранение версии в файл, отчёт по истории, метки версий, отбор.
  - **Откат до версии** удаляет все версии, помещённые после выбранной, без возможности восстановления.
  - **Сокращение до версии** удаляет все версии, сделанные раньше выбранной.
  - При откате или сокращении сразу на несколько тысяч версий возможна ошибка нехватки памяти — рекомендуется действовать порциями по несколько сотен версий.
  - **Объединение версий** сводит несколько последовательных версий в одну.
- **Выборочное сравнение** отдельных свойств объекта (модуль, макет, форма, права роли и др.) доступно, если у хранилища отключён режим совместимости с 8.3.2.
- **Без подключения базы** к хранилищу (режим соединения) доступны просмотр, сравнение, история и всё администрирование; недоступно получение объектов.
- «Конфигурация — Хранилище конфигурации — Сохранить конфигурацию хранилища в файл» сохраняет конфигурацию хранилища в файл.

## 37.4. Удалённая работа с хранилищем (сервер хранилища)

### Общее

- Сервер хранилища работает под Windows и Linux. Клиенты подключаются по TCP (локальная сеть) или по HTTP (через веб-сервер).
- Механизм рассчитан на быстрый канал: операции с большим объёмом данных (например, получение полной версии) при удалённой работе заметно дольше.
- Пользователю, от имени которого работает сервер хранилища, нужны права чтения и записи на каталог хранилища (файл `1Cv8DDB.1CD` и каталог `data`).
- **Версии сервера хранилища и конфигуратора должны совпадать** — иначе работа невозможна.
- Корневой каталог хранилищ лучше размещать на том же компьютере, где работает сервер хранилища; размещение на сетевом ресурсе допустимо, но медленнее.

### Запуск сервера хранилища

Windows:

```
crserver.exe -instsrvc | -rmsrvc -usr <пользователь> -pwd <пароль>
    -start | -stop
    -port <порт> -d <каталог>
```

Имя сервиса — `1C:Enterprise 8 Configuration Repository Server`. Каталог по умолчанию — `%LOCALAPPDATA%\1C\1Cv8\`. Пользователю сервиса нужно право «Вход в систему как сервис», чтение каталога исполняемых файлов версии и полные права на корневой каталог хранилищ.

Linux:

```
./crserver -daemon -port <порт> -d <каталог>
```

| Ключ | Значение |
|---|---|
| `-d` | корневой каталог хранилищ; по умолчанию `/home/usr1cv8/.1cv8` или `~/.1cv8` |
| `-daemon` | запуск демоном |
| `-port` | рабочий порт; по умолчанию **1542** |

Имя ключа и его значение разделяются пробелом.

**Ошибка `<файл> too many open files`** на Linux: увеличить предел открытых файлов (`nofile`) для пользователя сервера хранилища в `/etc/security/limits.conf` (от `root`). Значение подбирается опытным путём; начальное значение в документации записано как «10 0000» (написание неоднозначное — 10 000 или 100 000; уточнить нельзя, это текст первоисточника). Практическое замечание конспекта: `limits.conf` действует на сеансы через PAM; если `crserver` запускается юнитом systemd, предел задаётся директивой `LimitNOFILE=` в юните — см. `../linux/05-systemd-sluzhby-zhurnaly-cron.md`.

### Адрес хранилища для клиента

```
tcp://<имя сервера хранилища>/<относительный путь к хранилищу>
<адрес файла описания>/<относительный путь к хранилищу>
```

Примеры: `tcp://RepServ/MyConfRep`, `http://www.MyCompany.ru/VirtualFolder/storage.1ccr/MyConfRep`.

- Относительный путь считается от корневого каталога (по умолчанию или из ключа `-d`).
- Если путь не указан — открывается хранилище по умолчанию, каталог **`maincr`**; он создаётся при первом запуске сервера хранилища.
- Новое хранилище создают из конфигуратора, указав новый каталог.

### Публикация через веб-сервер (для HTTP)

Три действия: зарегистрировать модуль расширения веб-сервера; зарегистрировать виртуальное приложение; положить в виртуальный каталог файл с расширением `1ccr`, в котором указан адрес сервера хранилища в схеме TCP.

- Модуль расширения имеет идентификатор `_1cws_module`, строка загрузки — `LoadModule _1cws_module <путь к модулю>`. Обработчик для виртуального каталога — `1c-application`.
- Имена модулей в этом разделе документации приведены только для Apache 2.0 и 2.2 (`wsapch2.so`, `wsap22.so`), а пример пути — от версии 8.2 (`/opt/1C/v8.2/i386/wsap22.so`): раздел не обновлялся. Для Apache 2.4 модуль — `wsap24.so` (см. `../1c/05-veb-publikaciya-apache-nginx.md`), а вместо `Order allow,deny` / `Allow from all` пишут `Require all granted`.
- Содержимое файла `.1ccr` — один XML-узел с атрибутом `connectString="tcp://<сервер хранилища>"`. В самой главе в двух примерах узел назван по-разному (`storage` и `repository`); по описанию файла в «Руководстве администратора» имя узла произвольное (`adm-pr03-sluzhebnye-fajly-p1.md`, раздел 3.2).
- Для IIS расширением служит `wsisapi.dll` из каталога `bin` версии; нужна поддержка ISAPI-расширений.
- **Несколько версий платформы одновременно:** для каждой — свой экземпляр сервера хранилища на своём порту и своё виртуальное приложение со своим `1ccr`; для IIS — отдельный пул приложений на каждую полную версию (четыре числа), для Apache — **отдельный экземпляр веб-сервера** на каждую версию.

### Особенности удалённой работы

- Состояние объектов не обновляется автоматически — нужна команда «Действия — Обновить статусы».
- Активные удалённые пользователи не выделяются жирным в списке пользователей хранилища.

## 37.5. Рекомендации

- При помещении изменений составлять их описание (текстовый отчёт о сравнении рабочей конфигурации с хранилищем по помещаемым объектам).
- Администратор хранилища периодически архивирует хранилище и отчёты об изменениях.
- Не выполнять групповые операции с хранилищем и не снимать конфигурацию с поддержки при открытом окне сравнения конфигураций.

# Глава 38. Поставка и поддержка конфигурации

## 38.1. Термины

- **Поставка** — полная (файл `*.cf`, сформированный специальным образом) или поставка обновлений (файл `*.cfu`).
- **Поддержка** — способность конфигурации обновляться средствами конфигуратора по файлам поставки; назначение — защита логической целостности конфигурации. «Конфигурация на поддержке» — именно это состояние.
- **Комплект поставки** — дистрибутив: программа установки (`setup.exe` для Windows, `setup` для Linux, каталог `setup.app` для macOS) и файлы поставки в архиве `1cv8.efd`.

## 38.2. Поставка (сторона поставщика)

### Правила поставки для объектов

| Правило поставщика | Смысл |
|---|---|
| Изменения разрешены (по умолчанию) | любые изменения в пользовательской конфигурации |
| Изменения не рекомендуются | изменять можно, но будет предупреждение |
| Изменения запрещены | объект нельзя изменить и нельзя снять с поддержки отдельно — только сняв с поддержки всю конфигурацию |
| Включение в конфигурацию не рекомендуется | при постановке на поддержку или обновлении объект по умолчанию не предлагается к включению |

- Модули можно поставлять без исходного текста (только скомпилированный код). Нельзя исключить исходный текст для модуля управляемого приложения, модулей форм и команд, модулей с директивами препроцессора и клиентских общих модулей управляемого режима.
- Флажок «Файл поставки может использоваться для обновления» снимают для промежуточных версий, предназначенных только для последовательного перехода (например, при смене типа реквизита через вспомогательный реквизит).

### Файлы поставки и обновления

- «Конфигурация — Поставка конфигурации — Создать файлы поставки и обновления конфигурации». Заранее заполняются свойства конфигурации «Поставщик» и «Версия».
- Рекомендуемая структура номера версии: `<версия>.<подверсия>.<релиз>.<сборка>` (десятичные числа) — по ней сортируются шаблоны и обновления.
- В файл обновления включают предыдущие версии, с которых возможен переход (команда «Добавить из предыдущих версий»).
- Текстовые файлы комплекта готовят в UTF-8.

### Комплект поставки

- Описание комплекта (файл) содержит четыре ветви: шаблоны конфигураций, варианты поставки, базовые каталоги, языки. Параметры шаблона попадают в файл-манифест.
- «Создать архив комплекта» — zip с `1cv8.efd`, вспомогательными файлами и программами установки для трёх ОС. У файлов для Linux и macOS выставлен признак исполняемого; **если распаковать архив в Windows и скопировать файлы на носитель для Linux/macOS, признак исполняемого теряется** (на Linux его возвращают `chmod +x setup`).
- «Создать комплект файлов поставки» — те же файлы без упаковки и без программы установки.
- Ключи пакетного режима конфигуратора: `/CreateDistributionFiles`, `/CreateDistributivePackage`; параметр `-DigiSign` задаёт файл с параметрами лицензирования для конфигураций, распространяемых по схеме лицензирования рабочего места (возможность предоставляется партнёрам по отдельному договору).

## 38.3. Поддержка (сторона пользователя)

### Состояния

| Состояние | Что можно |
|---|---|
| **Конфигурация находится на поддержке** (полная поддержка) | объекты изменять нельзя; обновление автоматическое, без окна сравнения и объединения |
| **На поддержке с возможностью изменения** | включается кнопкой «Включить возможность изменения»; после этого все объекты заблокированы от случайных правок, и возможность изменения включается явно для каждого объекта |
| **Снята с поддержки** | обновления от поставщика штатным способом не принимаются |

- Типовая конфигурация после установки ставится на поддержку автоматически.
- Поставить на поддержку конфигурацию, которая на ней не находится: «Конфигурация — Сравнить, объединить с конфигурацией из файла», выбрав файл поставки; конфигуратор предложит объединение с постановкой на поддержку.
- Если база подключена к хранилищу, для постановки на поддержку должны быть захвачены корневой объект и все объекты, целиком берущиеся из конфигурации поставщика.

### Правила пользователя для объекта

1. объект поставщика не редактируется;
2. объект поставщика редактируется с сохранением поддержки;
3. объект поставщика снят с поддержки.

- Доступность зависит от правила поставщика: при «Изменения запрещены» менять правило нельзя; при «Изменения не рекомендуются» — можно, с предупреждением.
- **После «снят с поддержки» вернуть «не редактируется» нельзя.**
- Вернуть полную поддержку всей конфигурации можно только так: снять конфигурацию с поддержки (корневой объект — «Снять с поддержки»), затем «Конфигурация — Загрузить конфигурацию из файла» и выбрать файл поставки. Практическое следствие: все собственные доработки при этом теряются — перед действием нужна выгрузка конфигурации и резервная копия базы (вывод конспекта).
- Снятие с поддержки не мешает обновлять конфигурацию сравнением и объединением.
- Действия, сделанные по ошибке, отменяются закрытием конфигурации без сохранения.

### Обновление конфигурации на поддержке

- «Конфигурация — Поддержка — Обновить конфигурацию». Источник: отдельный файл обновления либо поиск в каталоге шаблонов, на съёмных дисках (для CD-ROM — каталог `v8updates`) и по адресу каталога обновлений, указанному в конфигурации. Обновление из удалённого каталога копируется в локальный каталог шаблонов.
- Конфигуратор предупреждает: источник файла обновления должен быть надёжным — файл может содержать нежелательные изменения.
- При изменённой конфигурации обновление идёт через окно сравнения и объединения трёх конфигураций: основной, старой и новой конфигурации поставщика. Режимы «Взять из…», «Объединить с приоритетом…», а при настроенной внешней программе — «Объединить с помощью внешней программы» (трёхстороннее объединение).
- Сначала объединяются модули. Если хотя бы один конфликт в модулях не разрешён, объединение останавливается со списком необъединённых модулей; их объединяют вручную и продолжают кнопкой «Выполнить».
- Объединение значений типа «Тип» в режиме «с приоритетом»: тип, исчезнувший из новой конфигурации поставщика или из основной, в результат не попадает; появившийся — попадает; при различии квалификаторов берётся то значение, которое изменилось относительно старой конфигурации поставщика (если изменились оба — из приоритетной).

### 38.3.5. Каталог шаблонов на HTTP(S)- или FTP-ресурсе

- Перечень конфигураций на таком ресурсе описывает файл **`v8cscdsc.lst`** в корне каталога шаблонов.
- Создаётся в конфигураторе: «Конфигурация — Поддержка — Шаблоны конфигураций и обновлений» → «Создать файл списка шаблонов». Список каталогов шаблонов берётся из `1CEStart.cfg`.
- Порядок: создать локальный каталог → установить в него нужные шаблоны → добавить каталог в список каталогов шаблонов → создать файл списка → перенести каталог вместе с файлом на ресурс.
- При поиске обновлений в удалённых каталогах файл списка шаблонов ищется только в самих указанных каталогах; в локальных — и в подкаталогах.
