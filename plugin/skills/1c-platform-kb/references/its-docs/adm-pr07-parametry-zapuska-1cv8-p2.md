## 7.4.5. Проверки конфигурации и расширений

### /CheckModules — проверка программных модулей

```
/CheckModules [-ThinClient] [-WebClient] [-MobileClient] [-MobileClientStandalone] [-MobileAppClient] [-Server] [-MobileAppServer] [-ExternalConnection] [-ThickClientOrdinaryApplication] [-ExtendedModulesCheck] [-Extension <Имя расширения>] [-AllExtensions]
```

Обязательно нужен хотя бы один ключ, задающий режим проверки. Если ни одного ключа нет, проверка не выполняется вовсе.

| Ключ | Режим / действие |
|---|---|
| `-ThinClient` | проверка для тонкого клиента |
| `-WebClient` | проверка для веб-клиента |
| `-MobileClient` | проверка для мобильного клиента |
| `-MobileAppClient` | проверка для клиента мобильного приложения |
| `-MobileClientStandalone` | проверка для мобильного клиента в автономном режиме |
| `-Server` | проверка для сервера «1С:Предприятия» |
| `-MobileAppServer` | проверка для сервера мобильного приложения |
| `-ExternalConnection` | проверка для внешнего соединения |
| `-ThickClientOrdinaryApplication` | проверка для клиентского приложения (так в источнике; у `/CheckConfig` тот же ключ описан как обычное приложение, толстый клиент) |
| `-ExtendedModulesCheck` | расширенная проверка: обращения к методам и свойствам объектов «через точку» (для ограниченного набора типов) и корректность строковых литералов — параметров некоторых функций, например `ПолучитьФорму()` |
| `-Extension <Имя расширения>` | выполнить заданные проверки для указанного расширения |
| `-AllExtensions` | выполнить заданные проверки для всех расширений |

### /CheckConfig — централизованная проверка конфигурации

```
/CheckConfig [-ConfigLogIntegrity] [-IncorrectReferences] [-ThinClient] [-WebClient] [-MobileClient] [-MobileAppClient] [-Server] [-MobileAppServer] [-MobileClientStandalone] [-ExternalConnection] [-ExternalConnectionServer] [-ThickClientManagedApplication] [-ThickClientServerManagedApplication] [-ThickClientOrdinaryApplication] [-ThickClientServerOrdinaryApplication] [-DistributiveModules] [-UnreferenceProcedures] [-HandlersExistence] [-EmptyHandlers] [-ExtendedModulesCheck] [-CheckUseModality] [-CheckUseSynchronousCalls] [-UnsupportedFunctional] [-MobileClientDigiSign] [-Extension <Имя расширения>] [-AllExtensions]
```

Общие проверки:

| Ключ | Что делает |
|---|---|
| `-ConfigLogIntegrity` | проверка логической целостности конфигурации — стандартная проверка, которая обычно выполняется перед обновлением базы данных |
| `-IncorrectReferences` | поиск некорректных ссылок: ссылки на удалённые объекты (по всей конфигурации, включая права, формы, макеты, интерфейсы и т. д.) и логически неправильные ссылки |
| `-DistributiveModules` | поставка модулей без исходных текстов: если в настройках поставки для каких-то модулей задана поставка без исходников, проверяется, можно ли сгенерировать образы этих модулей |
| `-UnreferenceProcedures` | поиск неиспользуемых локальных (не экспортных) процедур и функций, на которые нет ссылок; в том числе неиспользуемых обработчиков событий |
| `-HandlersExistence` | проверка существования назначенных обработчиков событий интерфейсов, форм и элементов управления |
| `-EmptyHandlers` | поиск назначенных, но пустых обработчиков событий (ничего не делают; могут снижать производительность) |
| `-ExtendedModulesCheck` | расширенная проверка: обращения «через точку» к методам и свойствам объектов (для ограниченного набора типов), корректность строковых литералов — параметров некоторых функций, например `ПолучитьФорму()` |
| `-CheckUseModality` | поиск в модулях методов, связанных с модальностью. Работает только вместе с `-ExtendedModulesCheck` |
| `-CheckUseSynchronousCalls` | поиск в модулях синхронных методов. Работает только вместе с `-ExtendedModulesCheck` |
| `-UnsupportedFunctional` | поиск функциональности, невыполнимой в приложении для мобильного устройства (состав проверки — ниже) |
| `-MobileClientDigiSign` | проверка цифровой подписи конфигурации для мобильного клиента |
| `-Extension <Имя расширения>` | выполнить заданные проверки для указанного расширения |
| `-AllExtensions` | выполнить заданные проверки для всех расширений |

Синтаксический контроль модулей в режиме эмуляции среды:

| Ключ | Эмулируемая среда |
|---|---|
| `-ThinClient` | управляемое приложение, тонкий клиент, файловый режим |
| `-WebClient` | веб-клиент |
| `-MobileClient` | мобильный клиент |
| `-MobileClientStandalone` | мобильный клиент в автономном режиме |
| `-Server` | сервер «1С:Предприятия» |
| `-ExternalConnection` | внешнее соединение, файловый режим |
| `-ExternalConnectionServer` | внешнее соединение, клиент-серверный режим |
| `-MobileAppClient` | мобильная платформа, клиентский режим запуска |
| `-MobileAppServer` | мобильная платформа, серверный режим запуска |
| `-ThickClientManagedApplication` | управляемое приложение, толстый клиент, файловый режим |
| `-ThickClientServerManagedApplication` | управляемое приложение, толстый клиент, клиент-серверный режим |
| `-ThickClientOrdinaryApplication` | обычное приложение, толстый клиент, файловый режим |
| `-ThickClientServerOrdinaryApplication` | обычное приложение, толстый клиент, клиент-серверный режим |

Что выявляет `-UnsupportedFunctional`:

- метаданные, классы которых не реализованы на мобильной платформе;
- планы обмена с установленным свойством «Распределенная информационная база»;
- типы, не реализованные на мобильной платформе:
  - в свойстве «Тип» реквизитов метаданных, констант, параметров сеанса;
  - в свойстве «Тип параметра команды» объекта конфигурации «Команда»;
  - в свойстве «Тип» реквизитов и колонок реквизита формы;
- формы с типом формы «Обычная»;
- элементы управления в форме, не реализованные на мобильной платформе (не проверяется для форм, чьё свойство «Назначения использования» не предполагает работу на мобильном устройстве);
- сложный состав рабочего стола (более одной формы).

### /CheckCanApplyConfigurationExtensions — применимость расширений

```
/CheckCanApplyConfigurationExtensions [-Extension <ИмяРасширения>] [-AllZones] [-Z «Значения разделителей»]
```

Проверяет, можно ли применить расширение в конкретной информационной базе.

| Ключ | Назначение | Примечания |
|---|---|---|
| `-Extension <ИмяРасширения>` | проверить указанное расширение с учётом всех расширений, загружаемых раньше него | если имя не задано — проверяются все расширения в порядке загрузки |
| `-AllZones` | проверить расширение во всех областях данных текущей ИБ | результат по каждой области предваряется выводом `-Z` со значениями разделителей этой области |
| `-Z «Значения разделителей»` | значения разделителей, для которых выполняется проверка | если не задан — проверка идёт для области с неустановленными значениями разделителей; подробности — в документации (ссылка утеряна) |

Ограничения сочетаний: нельзя совмещать `-Extension` с `-AllZones` и `-Z` с `-AllZones`.

Команда `/Z` и ключ `-Z` одновременно: значения из команды `/Z` применяются для запуска конфигуратора и выбора пользователя, а значения из ключа `-Z` (ключ самой команды `/CheckCanApplyConfigurationExtensions`) задают область данных, для которой проверяется применимость.

### /IBCheckAndRepair — тестирование и исправление информационной базы

```
/IBCheckAndRepair [-ReIndex] [-LogIntegrity [MDtype[,MDtype]] | -LogAndRefsIntegrity [MDtype[,MDtype]]] [-RecalcTotals] [-IBCompression] [-Rebuild] [-RebuildStandaloneCfg] [-TestOnly | [[-BadRefCreate | -BadRefClear | -BadRefNone] [-BadDataCreate | -BadDataDelete]]] [-UseStartPoint] [-TimeLimit:hhh:mm] [-ConfigurationExtensionsLogIntegrity] [-RefreshTableLocation] [-BinaryDataStorageIntegrity [MDtype[,MDtype]]] [-JobsCount <количество>] [-Z: «значения разделителей»] [-CheckAndEnableCORPFunctionality]
```

Правило: ключи, объединённые в одну подгруппу альтернатив (через `|`), одновременно указывать нельзя.

| Ключ | Действие | Значения / умолчание / примечания |
|---|---|---|
| `-ReIndex` | реиндексация таблиц | — |
| `-LogIntegrity [MDtype[,MDtype]]` | проверка логической целостности | без значения — все таблицы ИБ; со значением — только перечисленные через запятую виды объектов (таблица ниже). Альтернатива `-LogAndRefsIntegrity` |
| `-LogAndRefsIntegrity [MDtype[,MDtype]]` | проверка логической и ссылочной целостности | без значения — все таблицы ИБ; со значением — перечисленные виды объектов. Альтернатива `-LogIntegrity` |
| `-RecalcTotals` | пересчёт итогов | — |
| `-IBCompression` | сжатие таблиц | в файловом варианте дополнительно выполняется специальная оптимизация (описание — ссылка утеряна) |
| `-Rebuild` | реструктуризация таблиц ИБ | — |
| `-RebuildStandaloneCfg` | пересоздание конфигурации для мобильного клиента с автономным режимом | — |
| `-RebuildConfigurationExtension` | реструктуризация всех таблиц расширений | если указан только этот ключ — монопольный доступ к ИБ не требуется. ⚠ в источнике ключ описан в перечне, но отсутствует в строке синтаксиса |
| `-Z: «значения разделителей»` | тестирование и исправление расширений конфигурации в указанных областях данных | формат значений такой же, как у команды `/Z` запуска конфигуратора (ссылка утеряна); для нескольких областей ключ `-Z:` повторяется несколько раз. ⚠ в источнике написано «формат указания значений расширений» — по смыслу речь о значениях разделителей |
| `-ConfigurationExtensionsLogIntegrity` | проверка и (если возможно) исправление логической целостности расширений конфигурации | вместе с `-TestOnly` — только проверка. Если указан только этот ключ — монопольный доступ не требуется |
| `-TestOnly` | только тестирование, без исправления | альтернатива группе `-BadRef…` / `-BadData…` |
| `-BadRefCreate` | при ссылках на несуществующие объекты — создавать объекты | только без `-TestOnly`; один из трёх `-BadRef…` |
| `-BadRefClear` | при ссылках на несуществующие объекты — очищать объекты (формулировка источника) | только без `-TestOnly` |
| `-BadRefNone` | при ссылках на несуществующие объекты — не изменять при частичной потере объектов (формулировка источника) | только без `-TestOnly` |
| `-BadDataCreate` | при частичной потере информации об объектах — создавать объекты | только без `-TestOnly`; один из двух `-BadData…` |
| `-BadDataDelete` | при частичной потере информации об объектах — удалять объекты | только без `-TestOnly` |
| `-UseStartPoint` | продолжить с сохранённой точки возврата — с места, где тестирование прервалось в прошлом сеансе | — |
| `-TimeLimit:hhh:mm` | предел длительности сеанса тестирования | `hhh` — часы, 0…999; `mm` — минуты, 0…59 |
| `-RefreshTableLocation` | обновление сведений о размещении таблиц в пользовательских табличных пространствах | — |
| `-BinaryDataStorageIntegrity [MDtype[,MDtype]]` | проверка целостности хранилища двоичных данных | без значения — все таблицы ИБ; со значением — перечисленные виды объектов |
| `-JobsCount <количество>` | число системных фоновых заданий для операции | по умолчанию `0` — столько заданий, сколько ядер процессора на компьютере, выполняющем тестирование и исправление; `1` — параллельное выполнение отключено |
| `-CheckAndEnableCORPFunctionality` | проверка и актуализация ИБ в зависимости от различных настроек | подробности — ссылка утеряна |

Замечания:

- `/IBCheckAndRepair` несовместима с командой `/Z`: совместное указание даёт ошибку времени выполнения (для областей данных используется собственный ключ `-Z:`).
- `-TimeLimit` не гарантирует остановку точно в указанное время: не все этапы можно прервать в произвольный момент, а некоторые нельзя прервать совсем. Прерывание случится после истечения лимита, в первый момент, когда это возможно.
- Наибольший выигрыш от параллельности (`-JobsCount`) достигается, когда кластер серверов «1С:Предприятия» и сервер СУБД стоят на одном компьютере либо связаны каналом с высокой пропускной способностью (1 Гбит и более).

Значения `MDtype` для ключей `-LogIntegrity`, `-LogAndRefsIntegrity`, `-BinaryDataStorageIntegrity` (несколько значений — через запятую):

| Объект | Значение параметра |
|---|---|
| Бизнес-процессы | `BusinessProcesses` |
| Документы | `Documents` |
| Другие объекты | `Other` |
| Журнал документов | `DocumentJournals` |
| Задачи | `Tasks` |
| Константы | `Constants` |
| Планы видов расчета | `ChartsOfCalculationTypes` |
| Планы видов характеристик | `ChartsOfCharacteristicTypes` |
| Планы обмена | `ExchangePlans` |
| Планы счетов | `ChartsOfAccounts` |
| Регистры бухгалтерии | `AccountingRegisters` |
| Регистры накопления | `AccumulationRegisters` |
| Регистры расчета | `CalculationRegisters` |
| Регистры сведений | `InformationRegisters` |
| Справочники | `Catalogs` |

## 7.4.6. Поддержка конфигурации

### /UpdateCfg — обновление конфигурации на поддержке

```
/UpdateCfg <имя cf или cfu файла> -Settings <имя файла настроек> [-IncludeObjectsByUnresolvedRefs | -ClearUnresolvedRefs] [-DumpListOfTwiceChangedProperties] [-force]
```

Обновляет конфигурацию, находящуюся на поддержке: текущая конфигурация объединяется с файлом по файлу настроек.

| Параметр | Назначение | Примечания |
|---|---|---|
| `<имя cf или cfu файла>` | файл объединяемой конфигурации (`.cf`) или файл обновления конфигурации (`.cfu`) | — |
| `-Settings <имя файла настроек>` | файл с настройками объединения конфигураций | формат файла настроек описан отдельно (ссылка утеряна) |
| `-IncludeObjectsByUnresolvedRefs` | если на объекты, не включённые в список объединяемых и отсутствующие в основной конфигурации, ссылаются включённые объекты — такие объекты тоже помечаются к объединению и попытка повторяется | попытки идут, пока не кончатся объекты со ссылками на невключённые либо пока не будет выбрана вся конфигурация. Аналог кнопки «Пометить все для объединения» в окне неразрешённых ссылок, но с повтором попыток. Альтернатива `-ClearUnresolvedRefs` |
| `-ClearUnresolvedRefs` | ссылки на объекты, не включённые в список объединяемых, очищаются | аналог кнопки «Продолжить» в окне неразрешённых ссылок. Альтернатива `-IncludeObjectsByUnresolvedRefs` |
| `-DumpListOfTwiceChangedProperties` | вывести список всех дважды изменённых свойств в файл служебных сообщений | — |
| `-force` | не прерывать объединение при предупреждениях (перечень ниже) | без ключа объединение в этих случаях прерывается |

С ключом `-force` объединение продолжается при наличии:

- предупреждений об удаляемых объектах, на которые ссылаются объекты, не участвующие в объединении (такие объекты исключаются из объединения);
- предупреждений о дважды изменённых свойствах, для которых не выбран режим объединения (объединяются с настройками по умолчанию);
- объектов, изменение которых запрещено правилами поддержки (исключаются из объединения);
- предупреждений о применении настроек.

Предупреждения о дважды изменённых свойствах пишутся в файл служебных сообщений независимо от `-force`.

### /ManageCfgSupport — снятие с поддержки

```
/ManageCfgSupport [-disableSupport [-force]]
```

| Ключ | Назначение | Примечания |
|---|---|---|
| `-disableSupport` | снять конфигурацию с поддержки | без этого ключа команда завершается ошибкой |
| `-force` | снять с поддержки, даже если в конфигурации запрещены изменения | без ключа — ошибка, если в интерактивном режиме управления поддержкой изменения для конфигурации запрещены |

## 7.4.7. Команды создания файла поставки и обновления

### /CreateTemplateListFile — файл списка шаблонов конфигураций

```
/CreateTemplateListFile <имя файла> [-TemplatesSourcePath]
```

| Параметр | Назначение | Примечания |
|---|---|---|
| `<имя файла>` | имя файла списка шаблонов конфигураций | не указано — файл создаётся в заданном каталоге с именем по умолчанию; указано только имя — создаётся с этим именем в заданном каталоге; указан полный путь — используется он. ⚠ в источнике не уточнено, какой каталог считается «заданным» и каково имя по умолчанию |
| `-TemplatesSourcePath` | путь поиска файлов шаблонов конфигураций | не задан — берётся путь, установленный в диалоге настройки при запуске. ⚠ в строке синтаксиса значение после ключа не показано |

### /CreateDistributivePackage — архив комплекта поставки


## 7.4.8. Внешние обработки (отчеты)

Как передаются типы при выгрузке/загрузке в XML в пакетном режиме:

- Если внешняя обработка (отчёт) ссылается на объекты конфигурации, то при выгрузке в файлы типы таких ссылок записываются как уникальные идентификаторы типов. Загрузить такие файлы с корректным определением типов можно только в ту же конфигурацию или в конфигурацию-потомка той, где выполнялась выгрузка. Иначе типы определятся неверно.
- Чтобы этого избежать, выгрузку и загрузку нужно выполнять с указанием параметров подключения к информационной базе в командной строке пакетного запуска конфигуратора. Тогда в файлы вместо идентификаторов попадают текстовые представления типов.
- При загрузке параметры ИБ тоже нужно указывать — только так в результирующей обработке появится ссылка на реальный тип реальной конфигурации. Загрузка без параметров ИБ приводит к потере информации о типе.
- Если ссылок на объекты конфигурации в обработке (отчёте) нет, выгружать и загружать можно без параметров подключения к ИБ.

### /DumpExternalDataProcessorOrReportToFiles

```
/DumpExternalDataProcessorOrReportToFiles <корневой файл выгрузки> <внешняя обработка (отчет)> [-Format Plain|Hierarchical]
```

Выгружает внешнюю обработку (отчёт) в XML. Применяется выгрузка формата 2.0 (подробности — ссылка утеряна).

| Параметр | Назначение | Значения |
|---|---|---|
| `<корневой файл выгрузки>` | полный путь к корневому каталогу выгрузки | обязателен |
| `<внешняя обработка (отчет)>` | полный путь к исходному файлу `.epf` (`.erf`) | — |
| `-Format` | формат выгрузки | `Plain` — линейный; `Hierarchical` — иерархический (по умолчанию) |

### /LoadExternalDataProcessorOrReportFromFiles

```
/LoadExternalDataProcessorOrReportFromFiles <корневой файл выгрузки> <внешняя обработка (отчет)>
```

Загружает внешнюю обработку (отчёт) из XML (формат выгрузки 2.0).

### 7.4.15.2. Создание хранилища

```
/ConfigurationRepositoryCreate [-AllowConfigurationChanges -ChangesAllowedRule <Правило поддержки> -ChangesNotRecommendedRule <Правило поддержки>] [-NoBind] [-MinPasswordLenght <Длина>] [-CheckPasswordComplexity] [-Extension <Имя расширения>]
```

| Ключ | Назначение | Значения |
|---|---|---|
| `-AllowConfigurationChanges` | если конфигурация на поддержке без возможности изменения — включить возможность изменения | — |
| `-ChangesAllowedRule <Правило поддержки>` | правило поддержки для объектов, изменение которых поставщик разрешает | `ObjectNotEditable`, `ObjectIsEditableSupportEnabled`, `ObjectNotSupported` |
| `-ChangesNotRecommendedRule <Правило поддержки>` | правило поддержки для объектов, изменение которых поставщик не рекомендует | `ObjectNotEditable`, `ObjectIsEditableSupportEnabled`, `ObjectNotSupported` |
| `-NoBind` | не подключаться к созданному хранилищу | — |
| `-MinPasswordLenght <Длина>` | минимальная длина пароля для создаваемого хранилища | в источнике имя ключа записано именно так (`Lenght`) — и в синтаксисе, и в описании |

| `-Extension <Имя расширения>` | создать хранилище указанного расширения | без ключа создаётся хранилище основной конфигурации |

Значения правил поддержки:

| Значение | Смысл |
|---|---|
| `ObjectNotEditable` | объект поставщика не редактируется |
| `ObjectIsEditableSupportEnabled` | объект поставщика редактируется с сохранением поддержки |
| `ObjectNotSupported` | объект поставщика снят с поддержки |

## 7.4.16. Команды работы в режиме агента

Режим агента конфигуратора: агент работает как SSH-сервер и SFTP-сервер. Подробное описание режима — в отдельном разделе документации «Работа конфигуратора в режиме агента» (ссылка утеряна).

| Команда | Назначение | Умолчание / примечания |
|---|---|---|
| `/AgentMode` | включить режим агента конфигуратора | при этой команде игнорируются `/DisableStartupMessages` и `/DisableStartupDialogs`, если они указаны |
| `/AgentPort <Порт>` | сетевой порт агента в режиме SSH-сервера | по умолчанию `1543` |
| `/AgentListenAddress <Адрес>` | IP-адрес, который слушает агент | по умолчанию `127.0.0.1` |
| `/AgentSSHHostKey <приватный ключ>` | путь к закрытому ключу хоста | если не задан — должна быть указана `/AgentSSHHostKeyAuto`; без обеих команд запуск в режиме агента невозможен |
| `/AgentSSHHostKeyAuto` | использовать закрытый ключ хоста из стандартного расположения (таблица ниже) | если файла нет — создаётся закрытый ключ RSA длиной 2048 бит |
| `/AgentBaseDir <рабочий каталог>` | рабочий каталог SFTP-сервера и команд загрузки/выгрузки конфигурации | если не задан — стандартный каталог (таблица ниже) |

Стандартные расположения:

| ОС | Закрытый ключ хоста (`/AgentSSHHostKeyAuto`) | Рабочий каталог по умолчанию (`/AgentBaseDir` не задан) |
|---|---|---|
| Linux | `~/.1cv8/1C/1cv8/host_id` | `~/.1cv8/1C/1cv8/<Уникальный идентификатор информационной базы>/sftp` |
| macOS | `~/.1cv8/1C/1cv8/host_id` | `~/.1cv8/1C/1cv8/<Уникальный идентификатор информационной базы>/sftp` |
| Windows | `%LOCALAPPDATA%\1C\1cv8\host_id` | `%LOCALAPPDATA%\1C\1cv8\<Уникальный идентификатор информационной базы>\sftp` |

## 7.4.17. Прочие параметры

| Команда | Назначение | Примечания |
|---|---|---|
| `/Visible` | сделать выполнение пакетной команды видимым пользователю | на время работы конфигуратора открывается окно заставки; в режиме агента на экран выводится информационное окно |
| `/RunEnterprise` | запустить «1С:Предприятие» после выполнения пакетной команды | после команды можно указать дополнительную командную строку: её параметры используются при запуске «1С:Предприятия» вместо параметров текущей сессии. Дополнительная строка обязательно берётся в кавычки, вложенные кавычки удваиваются |
| `/ConvertFiles <имя файла\|путь>` | пакетная конвертация файлов «1С:Предприятия» 8.x | аргумент — имя файла или каталога; подробности ниже |
| `/DumpResult <имя файла>` | записать результат работы конфигуратора в файл | результат — число; `0` означает успех |

Особенности `/ConvertFiles`:

- Указан каталог — конвертируются все доступные документы в нём и во вложенных каталогах.

- Механизм требует запущенного конфигуратора с открытой конфигурацией, в среде которой идёт конвертация. Имя ИБ и параметры авторизации задаются стандартными параметрами командной строки; если их нет — будут выданы запросы, как и в других механизмах командной строки режима «Конфигуратор».

## 7.5. Пакетный режим запуска клиентского приложения

Суть: специальный режим запуска, в котором платформа не формирует диалоговых окон.

| Характеристика | Значение |
|---|---|
| Чем включается | команда `/DisableStartupDialogs` в командной строке запуска клиентского приложения |
| Какие клиенты поддерживают | тонкий и толстый клиент |
| Кто не поддерживает | веб-клиент |
| Когда действует | от момента запуска до окончания обработчика события `ПередНачаломРаботыСистемы` модуля приложения |
| `ПриНачалеРаботыСистемы` | вызывается уже после завершения пакетного режима запуска |
| Завершение приложения | автоматически не происходит — после окончания пакетного режима клиент продолжает работать |
| Куда пишутся ошибки | могут записываться в файл служебных сообщений, заданный командой `/Out` |

Действуют все особенности команды `/DisableStartupDialogs` (описаны в другом месте документации; ссылка утеряна) и дополнительно следующие.

Асинхронные методы, вызванные во время пакетного режима запуска:

- при успешном запуске клиента и открытии основного окна приложения — выполняются после завершения обработчика `ПередНачаломРаботыСистемы`, но до окончания пакетного режима;
- если запуск отклонён (параметр `Отказ` обработчика `ПередНачаломРаботыСистемы` установлен в `Истина`) — не выполняются.

Открытие окон в пакетном режиме запрещено. При попытке:

- открытие формы блокируется;
- формируется ошибка.

Проверить, запрещено ли сейчас открытие окон, позволяет метод глобального контекста `ЗапрещеноОткрытиеФорм()`.

Прочее:

- Внешняя обработка, переданная командой `/Execute`, запускается после завершения пакетного режима запуска.
- Если в пакетном режиме запуска методы глобального контекста `ЗапуститьПриложения()` / `НачатьЗапускПриложения()` (имена — как в источнике) встречают ошибку времени исполнения, формируется исключение.

## 7.6. Регистрация «1С:Предприятия» в качестве OLE-Automation-сервера

Пометка конспекта: раздел относится к OLE/COM-регистрации и для сервера на Linux практического значения не имеет; сама документация в этом месте операционную систему явно не называет. Изложено кратко.

```
/RegServer [-AllUsers | -CurrentUser | -Auto]
/UnregServer
```

| Команда / ключ | Действие |
|---|---|
| `/RegServer` | регистрация объектов `V83.Application` и `V83C.Application`; допустим один из ключей ниже |
| `-AllUsers` | регистрация для всех пользователей компьютера; при нехватке прав — ошибка (при заданном `/Out <ИмяФайла>` сообщение уходит в файл, иначе на экран) |
| `-CurrentUser` | регистрация для текущего пользователя |
| `-Auto` | без диалогов: для всех пользователей, если права есть; для текущего пользователя, если прав нет |
| без ключей | есть привилегии на регистрацию для всего компьютера — регистрация для компьютера; привилегий недостаточно — задаётся вопрос о регистрации для текущего пользователя |
| `/UnregServer` | отмена регистрации объектов `V83.Application` и `V83C.Application` |

## 7.7. Строка соединения с информационной базой

### 7.7.1. Общая информация

Строка соединения — строка с параметрами информационной базы. Она состоит из фрагментов вида:

```
<Имя параметра>=<Значение>
```

Правила записи:

- фрагменты разделяются символом `;`;
- значение, содержащее пробельные символы, заключается в двойные кавычки (`"`);
- набор параметров зависит от варианта информационной базы — файловый или клиент-серверный;
- кроме того, есть общий набор параметров, применимый к любому варианту.

Где встречается строка соединения:

- показывается в форме списка информационных баз (под списком);
- задаётся в параметре командной строки режима `CREATEINFOBASE`;
- передаётся параметром методов `СоздатьНачальныйОбраз()`.

Перечни самих параметров строки соединения в эту часть не вошли — продолжение раздела 7.7 находится в части 3.

## Что важно администратору Linux

1. Тестирование и исправление ИБ из командной строки — `/IBCheckAndRepair`. Безопасный прогон «только посмотреть» — ключ `-TestOnly`; ключи `-BadRef…` и `-BadData…` допустимы только без него. Альтернативы внутри одной группы (`-LogIntegrity` / `-LogAndRefsIntegrity`, три `-BadRef…`, два `-BadData…`) вместе не указываются.
2. `/IBCheckAndRepair` нельзя сочетать с командой `/Z` — будет ошибка времени выполнения. Для областей данных у команды свой ключ `-Z:` (повторяется для нескольких областей).
3. Параллельность тестирования задаёт `-JobsCount`: `0` (умолчание) — по числу ядер процессора компьютера, выполняющего операцию; `1` — без параллельности. Максимальный эффект — когда кластер 1С и сервер СУБД на одной машине или соединены каналом от 1 Гбит.
4. Длинное тестирование можно дробить на сеансы: `-TimeLimit:hhh:mm` (часы 0…999, минуты 0…59) плюс `-UseStartPoint` для продолжения с точки возврата. Лимит времени не точный — прерывание происходит в первый возможный момент после его истечения.
5. Монопольный доступ к ИБ не нужен, если у `/IBCheckAndRepair` указан только `-RebuildConfigurationExtension` или только `-ConfigurationExtensionsLogIntegrity`.
6. Для баз с пользовательскими табличными пространствами есть ключ `-RefreshTableLocation` — он обновляет сведения о размещении таблиц. Проверку можно сузить до видов объектов через `MDtype` (`Documents`, `Catalogs`, `InformationRegisters` и т. д.).
7. Сокращение журнала регистрации автоматизируется командой `/ReduceEventLogSize <ГГГГ-ММ-ДД>`; `-saveAs` сохраняет копию выгружаемых записей, `-KeepSplitting` оставляет разбиение по периодам.
8. Результат пакетного запуска конфигуратора для скриптов: `/DumpResult <файл>` пишет число (`0` — успех). Команды хранилища `Lock` / `UnLock` / `Commit` / `SetLabel` возвращают код `0` или `1`, текст ошибки — в файле служебных сообщений.
9. Режим агента конфигуратора (`/AgentMode`) по умолчанию слушает только `127.0.0.1`, порт `1543`. Для доступа извне нужен `/AgentListenAddress`. Без `/AgentSSHHostKey` или `/AgentSSHHostKeyAuto` агент не запустится.
10. На Linux ключ хоста агента при `/AgentSSHHostKeyAuto` лежит в `~/.1cv8/1C/1cv8/host_id` (при отсутствии создаётся RSA 2048 бит), рабочий каталог SFTP по умолчанию — `~/.1cv8/1C/1cv8/<идентификатор ИБ>/sftp`; изменить его можно через `/AgentBaseDir`. Пути привязаны к домашнему каталогу пользователя, от имени которого запущен конфигуратор.
11. В режиме агента команды `/DisableStartupMessages` и `/DisableStartupDialogs` игнорируются.
12. `/RunEnterprise` запускает «1С:Предприятие» после пакетной команды; дополнительную командную строку нужно брать в кавычки, а кавычки внутри неё удваивать — это надо учитывать при экранировании в shell-скриптах.
13. Команды этой части, требующие осторожности (по описанию их действия): `/EraseData` (удаление данных ИБ или области `/Z`, нужно право «Администрирование»), `/ConfigurationRepositoryUnLock -force` (локальные изменения теряются), `/ManageCfgSupport -disableSupport` (снятие с поддержки), `/ResetMasterNode` (отмена главного узла РИБ).
14. Выгрузку и загрузку внешних обработок/отчётов в XML (`/DumpExternalDataProcessorOrReportToFiles`, `/LoadExternalDataProcessorOrReportFromFiles`) нужно выполнять с параметрами подключения к ИБ, если обработка ссылается на объекты конфигурации, — иначе информация о типах теряется.
15. Пакетный режим запуска клиента (`/DisableStartupDialogs`) работает только в тонком и толстом клиентах, действует до конца `ПередНачаломРаботыСистемы`, открытие форм в нём блокируется с ошибкой, а клиент после него сам не завершается. Ошибки можно собрать в файл через `/Out`.
