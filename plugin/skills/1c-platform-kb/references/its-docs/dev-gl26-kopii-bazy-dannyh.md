> Пересказ своими словами; имена методов, свойств и значений приведены точно.
> Практическая сторона для PostgreSQL — в `../postgresql/07-replikaciya-otkazoustojchivost-obnovlenie-versij.md`; настройка сервера для Дата акселератора — в `cs-gl03-ustanovka-komponentov-p1.md`.

## 26.1. Общая информация

> Лицензия: доступно только для лицензии КОРП.

- Механизм создаёт и обновляет копии таблиц выбранных объектов конфигурации в **других физических базах данных**. Копий может быть несколько; запросы и отчёты системы компоновки данных могут выполняться на копии.
- Это **не резервная копия**: копия не является информационной базой, работать с ней как с базой нельзя.
- В файловом варианте не поддерживается.
- Назначение: обязательная часть **Дата акселератора** и вынос данных для аналитических отчётов на отдельный сервер СУБД.
- СУБД копии: Microsoft SQL Server, Oracle Database, PostgreSQL. СУБД копии и основной базы могут отличаться производителем, версией и разрядностью.
- Синхронизация — встроенными средствами платформы либо сторонними. Средства самой СУБД допустимы только при двух условиях одновременно: копия используется лишь через механизм копий, и в неё помещены **все** таблицы основной базы (полная копия).
- Разделение данных поддерживается.

## 26.2. Устройство механизма

### Обновление копии

- Состав таблиц задаёт свойство `Состав` объекта `МенеджерКопииБазыДанных`.
- `КопииБазыДанных.Обновить()` — синхронное обновление (целиком или порцией); удобно вызывать из регламентного задания.
- `КопииБазыДанных.ОбновитьВФоновомРежиме()` — обновление системным фоновым заданием; состояние читают методом `ПолучитьИнформациюОКопии()`.
- Внутри обновления две операции:
  1. **начальный перенос** в новую таблицу копии — системными фоновыми заданиями; повторяется после любого изменения структуры (добавление или удаление реквизита, объекта); для разделённых объектов переносятся данные всех областей;
  2. **текущий перенос** — без фоновых заданий, переносятся все успешно завершённые изменения отмеченных объектов. При большом объёме изменений может длиться долго.

### Тип репликации (`МенеджерКопииБазыДанных.ТипРепликации`)

- **Стандартный** — всё описанное выше делает платформа.
- **Внешний** — платформа не создаёт таблицы, не синхронизирует данные и считает копию всегда актуальной; она только направляет запросы в копию. Структура таблиц и регулярность репликации целиком на администраторе; любое несоответствие структуры даёт ошибку запроса.

### Версии стандартной репликации (`ВерсияСтандартнойРепликацииКопийБазыДанных`)

- `Версия1` — изменения отслеживает кластер серверов «1С:Предприятия».
- `Версия2` — изменения отслеживает СУБД основной базы.
- Методы менеджера копий: `ПолучитьВерсиюСтандартнойРепликации()`, `УстановитьВерсиюСтандартнойРепликации()`. Смена версии сбрасывает состояние всех копий со стандартной репликацией — следующее обновление станет начальным заполнением.
- Если задана `Версия2`, а СУБД её не поддерживает, работает `Версия1`.

**`Версия2` на PostgreSQL** (версия 10 и новее, механизм логического декодирования):

1. СУБД установлена **из дистрибутива, поставляемого фирмой «1С»**; с другой сборкой `Версия2` использовать нельзя.
2. В `postgresql.conf` задать `wal_level=logical`.
3. Перезапустить СУБД.
4. В стандартной функции управления копиями базы данных включить `Версия2`.

Если база настраивалась в прежних версиях платформы, будет действовать `Версия1`, даже когда в настройках показана `Версия2`, — версию нужно переключить заново.

**`Версия2` на Microsoft SQL Server** (2008 и новее, механизм Change Data Capture): включается автоматически, если пользователь СУБД входит в роль `sysadmin`; иначе администратор выполняет `sys.sp_cdc_enable_db` и задаёт `max text repl size = -1`. Должна работать служба SQL Server Agent. В SQL Server 2019 CU 20, 2022 CU 2 и новее CDC несовместим с отложенной фиксацией (`DELAYED_DURABILITY`). При высокой транзакционной нагрузке обновление может завершиться ошибкой `sp_cdc_create_change_table` — его повторяют позже.

### Куда направляется запрос

Свойства объекта `Запрос` и параметров вывода компоновки данных:

- `ИспользованиеКопийБазыДанных`: `НеИспользоватьКопии`; `ИспользоватьТолькоКопии` (не получилось — исключение); `ИспользоватьПреимущественноКопии` (не получилось — основная база); `Авто` (как «преимущественно копии»).
- `ИспользуемыеКопииБазыДанных` — список допустимых копий.
- `ТребуемаяАктуальностьДанных` (`Актуальные`, `Любые`, `Авто`) и `ТребуемоеВремяАктуальностиДанных` (число секунд, дата и время либо стандартная дата начала). При `Авто` для объекта `Запрос` берётся `Актуальные`, для компоновки данных — `Любые`.

Алгоритм выбора копии:

1. отбираются копии, где есть **все** таблицы запроса (включая данные, получаемые «через точку», и таблицы из ограничений доступа), актуальность удовлетворяет требованию, а условие запроса соответствует отбору, заданному на копию;
2. из них берутся наименее загруженные запросами текущего рабочего процесса;
3. из оставшихся копия выбирается случайно.

Откуда получены данные: свойства `РезультатЗапроса` — `ДанныеАктуальны`, `ВремяАктуальности`, `КопияБазыДанных`; в языке выражений компоновки — функции `ДанныеАктуальны()`, `ВремяАктуальностиДанных()`, `КопияБазыДанных()`; параметры вывода `ВыводитьАктуальностьДанных`, `ВыводитьКопиюБазыДанных`.

Для подбора таблиц есть внешняя обработка «Подбор таблиц для дата акселератора» на ИТС (`its.1c.ru/db/metod8dev#content:5951:hdoc`).

## 26.3. Дата акселератор

> Лицензия: один процесс Дата акселератора в кластере доступен с лицензией ПРОФ, более одного — только с КОРП.

- Это СУБД, база которой целиком находится **в оперативной памяти рабочего сервера** кластера. Работает только вместе с механизмом копий и только на 64-разрядной ОС.
- Варианты хранения: только в памяти (после перезапуска нужна полная синхронизация с основной базой) либо в памяти и на диске (после перезапуска база загружается с диска, досинхронизируется только изменившееся).
- Число экземпляров задаётся требованиями назначения функциональности.
- Рассчитан на аналитические запросы: большой объём обрабатываемых данных, малое число строк в результате. В других сценариях может быть медленнее основной базы.
- Порядок: настроить рабочий сервер → создать копию с признаком «Встроенный Дата акселератор» (синхронизация всегда встроенная) → задать список таблиц → запустить начальное обновление.
- Совет документации: не помещать в такую копию всю базу — только таблицы, нужные для ускоряемых отчётов.
- Регулярное обновление данных копии организует разработчик прикладного решения.
- Ограничение: реквизиты с данными больше 4 Кбайт не поддерживаются — возвращаются пустые значения.

## 26.4. Особенности и ограничения

- Запрос не уйдёт на копию, если в сеансе открыта транзакция или в запросе задан менеджер временных таблиц.
- После ошибки, связанной с копией, она перестаёт использоваться во всех сеансах до обновления копии или перезапуска кластера. Запрос, которому не требовалась «только копия», автоматически повторяется на основной базе или другой копии.
- `ВерсияДанных` в копии может не совпадать с основной базой.
- Новые таблицы попадают в копию после записи `МенеджерКопииБазыДанных` и вызова `КопииБазыДанных.Обновить()`; удаление таблиц происходит сразу при записи.
- Права:
  - в информационной базе — «Администрирование» для управления копиями; для каждого синхронизируемого объекта — «Чтение», «Добавление», «Изменение», «Удаление» (рекомендуется отдельный пользователь для синхронизации);
  - у пользователя СУБД копии — создание, изменение и удаление таблиц и полный доступ к данным базы копии.
- Расширения конфигурации, расширяющие данные, не поддерживаются: такие таблицы игнорируются, запросы к ним на копии не выполняются.

## 26.5. Управление составом копии

1. `КопииБазыДанных.Добавить()` — создать копию; для Дата акселератора параметр `ВариантХраненияДанныхДатаАкселератора`: `ВОперативнойПамяти` или `ВОперативнойПамятиИНаДиске`. Найти существующую — `КопииБазыДанных.Найти()`.
2. Настроить состав: `МенеджерКопииБазыДанных.Состав`, элементы — `ЭлементСоставаКопииБазыДанных`.
3. `МенеджерКопииБазыДанных.Записать()`.
4. `КопииБазыДанных.Обновить(<копия>)`.

Состав полей:

- Всегда входят стандартные реквизиты, разделители и измерения регистров.
- Групповые свойства (у менеджера копии и у элемента состава): `ИспользованиеХранилищЗначений`, `ИспользованиеСтрокНеограниченнойДлины`, `ИспользованиеПрочихПолей`, `ИспользованиеТабличныхЧастей`.
- Отдельное поле: `ЭлементСоставаКопииБазыДанных.Поля`, свойство `ПолеЭлементаСоставаКопииБазыДанных.Использование`.
- Значения — перечисление `ИспользованиеПоляЭлементаСоставаКопииБазыДанных`: `Использовать`, `НеИспользовать`, `Авто`.
- Порядок определения: поле → элемент состава → менеджер копии → умолчания платформы. Умолчания: при стандартной репликации табличные части и реквизиты типа `ХранилищеЗначения` **не используются**, остальное используется; при внешней — используется всё.
- Фактическое состояние поля — `ПолеЭлементаСоставаКопииБазыДанных.ПолучитьТекущееИспользование()`.

## 26.6. Защита от использования одной базы несколькими копиями

- Одна база данных СУБД может быть связана только с одной копией. Если её подключить к другой копии или к информационной базе, данные могут быть разрушены.
- `УстановитьИспользованиеБазыДанныхКопииЭтойКопией()` закрепляет базу данных за копией.
- `ПолучитьИнформациюОбИспользованииБазыДанныхКопии()` возвращает `ИнформацияОбИспользованииБазыДанныхКопии`: свойство `ВариантИспользования` (`ИспользованиеНеизвестно`, `ИспользуетсяЭтойКопией`, `ИспользуетсяДругойКопией`, `ИспользуетсяИнформационнойБазой`) и `Описание` (строка подключения).
- `Обновить()` проверяет допустимость; при нарушении копия перестаёт обновляться.
- Следствие: при дублировании информационной базы нужно дублировать и базы данных всех её копий.

## 26.7. Информация о копии

`ПолучитьИнформациюОКопии()` возвращает `ИнформацияОКопииБазыДанных`:

- `СерверБазыДанных`; `ВыполняетсяОбработкаДанныхДатаАкселератором`;
- `СостояниеКопии`: `Включена`, `ВременноОтключена` (Дата акселератору не хватает памяти; по таймауту попытка повторяется), `Отключена`;
- `ПричинаОтключения`: `НедопустимыйВариантИспользованияБазыДанныхКопии`, `НесответствиеДанных`, `ОшибкаВыполненияЗапроса`, `ОшибкаСоединенияСБазойДанных`; `ОшибкаПричиныОтключения`;
- `КоличествоТаблицДляНачальногоОбновления`, `КоличествоТранзакцийДляТекущегоОбновления`;
- `СостояниеОбновления`: `ВыполняетсяНачальноеОбновление`, `ВыполняетсяТекущееОбновление`, `ЗавершеноОбновлениеПорцииУспешно`, `ЗавершеноСОшибкой`, `ЗавершеноУспешно`, `Неактивно`;
- `ОбновляемыеДанные`, `ОшибкаОбновления`, `ОжидаемоеВремяВыполнения` (секунды, по статистике прошлых обновлений).
