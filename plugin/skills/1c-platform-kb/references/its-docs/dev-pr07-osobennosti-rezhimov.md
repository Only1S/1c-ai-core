## 7.1. Режим низкой скорости соединения

- Формы начальной страницы автоматически не показываются (в интерфейсе «Такси» — показываются сразу); картинки панели разделов не загружаются.
- Данные формы (представления ссылок, значения «через точку») получаются сразу при создании формы, без дополнительных вызовов сервера.
- Сервер узнаёт о закрытии формы и **снимает блокировку объекта отложенно**: при получении следующей формы, серверном вызове из формы, закрытии 20 форм, **ожидании более 20 секунд**, некоторых командах динамического списка.
- Настройки сохраняются отложенно: при следующем открытии формы, при накоплении 20 настроек, через 20 минут бездействия или при закрытии приложения.
- Для списков быстрого выбора и ввода по строке ведётся кеш на время сеанса (до 20 списков на тип объекта, до 200 всего).
- Поиск в динамическом списке выполняется не по мере набора, а после потери фокуса строкой поиска.

## 7.2. Режим совместимости: что меняется по версиям

Формат раздела в документации: для каждой версии — перечень особенностей «используется режим совместимости с версией N / не используется». Режим совместимости задаётся свойством конфигурации (см. `dev-gl02-rabota-s-konfiguraciej.md`); его повышение — изменение конфигурации, которое делает разработчик, а не администратор. Ниже — то, что может быть заметно при эксплуатации сервера.

## 7.4–7.5. Веб-клиент (обзорно)

В веб-клиенте не поддерживаются, в частности:

- работа с объектами `ЧтениеТекста`, `ЗаписьТекста`, `ЧтениеZipФайла`, `ЗаписьZipФайла`, `XBase`, а также с XML и XDTO — такую обработку рекомендуется выполнять на сервере;
- получение системной информации о клиентском компьютере; метод `ЗаблокироватьРаботуПользователя()`; прерывание исполнения модуля пользователем;
- перетаскивание файлов в формы, режим сравнения файлов, список последних файлов;
- масштаб веб-браузера, отличный от 100 %, и нестандартный dpi;
- открытие немодальной формы из модальной (все формы из модальной открываются модально);
- отображение в поле HTML-документа страниц с тем же именем хоста, что у веб-клиента (страницы рекомендуется хранить в информационной базе);
- в Safari — расширение работы с криптографией.

На iPad дополнительно не поддерживается печать.

## 7.6. Объекты системы при включённом разделении данных (обзорно)

Подробно механизм — в `dev-gl24-razdelenie-dannyh.md`. Из приложения:

- Нумерация объектов, настройки, избранное, история, настройки OData ведутся в разрезе комбинации значений разделителей.
- **Регламентные задания** могут быть разделёнными, но при большом числе областей частые разделённые задания не рекомендуются — лучше одно неразделённое, обходящее области.
- **Фоновое задание** запускается со значениями разделителей запустившего сеанса.
- **Список сеансов** (`ПолучитьСеансыИнформационнойБазы()`) содержит только сеансы с теми же значениями разделителей; **список соединений** (`ПолучитьСоединенияИнформационнойБазы()`) непуст, только если в сеансе не используется ни один разделитель.
- **Монопольный режим** действует на область, заданную разделителями сеанса: в одной базе монопольный режим может быть установлен сразу для нескольких областей.
- **Индекс полнотекстового поиска общий для всех областей**; обновляется только в сеансе, где разделители не используются, — задания обновления и слияния индекса должны быть неразделёнными.
- Часовой пояс информационной базы разделяется независимыми разделителями.
- Отдельные подразделы описывают журнал регистрации (отображение, отбор, получение записей), права доступа, пользователей, планы обмена, регистры, расширения, историю данных, систему взаимодействия, сервисы интеграции, политики паролей.

## 7.7. Клиентское приложение под Linux

Не поддерживаются:

- технология **COM** целиком: объект `COMОбъект`, запуск клиента в режиме Automation-сервера, внешние компоненты COM;
- **консоль администрирования кластера серверов** — администрирование выполняется сервером администрирования **`ras`** и утилитой **`rac`**;
- объект `Почта` (взамен — запуск почтового приложения по умолчанию через `ЗапуститьПриложение()` с URL схемы `mailto:`);
- метафайлы Windows (WMF, EMF).

## 7.8. Клиентское приложение под macOS

- Нет 32-разрядной версии; **кластер серверов на macOS не работает**; публикация на веб-сервере не поддерживается.
- Не поддерживаются: файловая база на сетевом ресурсе; COM; внешние источники данных на стороне клиента и в конфигураторе; **аутентификация средствами операционной системы**; консоль администрирования кластера; объект `Почта`; метафайлы Windows; панель меню macOS.
- В сочетаниях клавиш вместо Control используется Cmd.

## 7.10. Механизм защиты от опасных действий

### Что это

Защита от стороннего кода, попадающего в систему через **внешние отчёты и обработки и расширения**. При потенциально опасном действии пользователю выдаётся предупреждение с запросом разрешения. Опасными считаются:

- загрузка внешней обработки, отчёта или расширения; загрузка или обновление конфигурации или расширения;
- из внешней обработки, отчёта или расширения: загрузка другой внешней обработки, **выполнение команды операционной системы**, **управление пользователями**, загрузка внешней компоненты.

Где проявляется: интерактивная загрузка внешней обработки; подключение расширения; обновление конфигурации файлом обновления; методы `Создать()` и `Подключить()` менеджеров внешних обработок и отчётов; `ЗапуститьПриложение()`, `НачатьЗапускПриложения()`, `КомандаСистемы()`; `Записать()` и `Удалить()` объекта `ПользовательИнформационнойБазы`; `ПодключитьВнешнююКомпоненту()`, `НачатьПодключениеВнешнейКомпоненты()`; `ПолучитьCOMОбъект()` и конструктор `COMОбъект`; открытие URL в поле HTML-документа; табличный документ с OLE-объектами (Windows).

### Как работает

- Разрешение запоминается **в информационной базе** в разрезе пользователя, объекта (внешней обработки, отчёта или расширения) и действия; запрет не запоминается.
- Объект идентифицируется **по хешу**: после любого изменения обработки или расширения разрешение запрашивается заново.
- **Там, где нет интерактивного взаимодействия (например, в фоновом задании), действие, не разрешённое ранее интерактивно, блокируется, а в журнал регистрации делается запись.** Отсюда типичная картина: обработка работает у пользователя, но не работает в регламентном задании.
- При входе в обработчики событий модулей объектов платформа принудительно отключает защиту; восстановить её можно парой `ПолучитьОтключениеЗащитыОтОпасныхДействий()` / `УстановитьОтключениеЗащитыОтОпасныхДействий(Ложь)`.

### Отключение (7.10.2)

Способы:

1. снять флажок «Защита от опасных действий» (свойство `ЗащитаОтОпасныхДействий`) у конкретного пользователя;
2. параметр `ЗащитаОтОпасныхДействий` методов `Создать()` и `Подключить()` менеджеров внешних обработок и отчётов;
3. параметр **`DisableUnsafeActionProtection`** файла `conf.cfg` — отключает защиту для всех пользователей баз, строки соединения которых подходят под указанные шаблоны;
4. свойство расширения `ЗащитаОтОпасныхДействий`.

Защита считается отключённой, если выполнено любое из условий, проверяемых в таком порядке: флажок у пользователя снят → строка соединения подходит под шаблон `DisableUnsafeActionProtection` → обработка подключена с явно отключённой защитой → защита отключена свойством расширения.

Замечание конспекта: отключение через `conf.cfg` снимает защиту сразу для всех пользователей подходящих баз, поэтому шаблон следует делать максимально узким; описание параметра — в конспекте `conf.cfg` (`adm-pr03-sluzhebnye-fajly-p1.md` … `p6.md`, искать по имени параметра).
