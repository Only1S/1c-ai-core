### 3.17.11. ExternalSessionManagementRequired

Определяет, обязателен ли сервис внешнего управления сеансами для **файловой** информационной базы.

| Значение | Поведение |
|---|---|
| `1` | Внешнее управление сеансами обязательно. Если вызов сервиса завершился ошибкой — новый сеанс не создаётся. |
| `0` | Не обязательно. При ошибке вызова сервиса сеанс всё равно начинается. **Значение по умолчанию.** |

- Параметр работает в паре с `ExternalSessionManagementConnectionString`: при значении `1` параметры вызова сервиса должны быть заданы в `ExternalSessionManagementConnectionString`. То есть сервис внешнего управления сеансами в файловой ИБ настраивается двумя параметрами сразу.
- Алгоритм определения итоговых значений обоих параметров описан в другом месте документации (ссылка на др. раздел).

### 3.17.12. FileNamesEncodingInZipFile

Кодировка, в которой платформа записывает имена файлов в создаваемые ею zip-архивы.

| Значение | Особенности |
|---|---|
| `UTF8` (по умолчанию) | Имена с национальными символами неверно показываются встроенным архиватором Windows XP/2003/2008/7 и объектом `ЧтениеZipФайла` платформы версии 8.3.6 и младше. В macOS отображаются правильно. |
| `OSEncodingWithUTF8` | Имена с национальными символами неверно показываются только встроенным архиватором macOS; в остальных случаях проблем нет. |

### 3.17.13. ForceTLS`<Version>`

Задаёт максимальную версию протокола TLS, которую использует **клиентское приложение** «1С:Предприятия».

| Параметр | Версия TLS |
|---|---|
| `ForceTLS1_0` | 1.0 |
| `ForceTLS1_1` | 1.1 |
| `ForceTLS1_2` | 1.2 |

- `true` — используется TLS не выше версии, заданной именем параметра; более ранняя версия тоже возможна, если её требует веб-сервер.
- `false` (а также любое значение, отличное от `true`) — версия зависит только от настроек веб-сервера, с которым работает платформа; допустима любая версия TLS вплоть до 1.3.
- По умолчанию: `false`.
- Одновременно указывать несколько параметров `ForceTLS*` запрещено — поведение в этом случае не определено.

### 3.17.14. FtsJavaOpts

Дополнительные параметры запуска виртуальной машины Java для полнотекстового поиска версии 2 (ссылка на др. раздел).

- Значение не должно содержать кавычек.
- Указывается в `conf.cfg` на компьютере, где расположен кластер серверов «1С:Предприятия».
- При Java версии 17 и выше для корректной работы полнотекстового поиска версии 2 требуются дополнительные настройки этого параметра (подробности — ссылка на др. раздел, в этой части не раскрыты).
- Типичное применение — ограничение/задание объёма памяти JVM.

Примеры из документации:

```
#Минимальный размер кучи (реже срабатывает сборка мусора, реже выгружаются внутренние кеши)
FtsJavaOpts=-Xms2G
```

```
#Максимальный размер кучи (новая граница потребления памяти)
FtsJavaOpts=-Xmx8G
```

```
#Режим вывода в консоль — для расследования сбоев запуска сервера полнотекстового поиска версии 2
FtsJavaOpts=-Dconsole=none #Ничего не выводить в консоль (по умолчанию)
FtsJavaOpts=-Dconsole=all #Выводить всё в консоль
FtsJavaOpts=-Dconsole=start|stop #Выводить только строку запуска и остановки сервера
```

Значения `-Dconsole`: `none` (по умолчанию), `all`, `start|stop`.

### 3.17.15. IgnoreInternetMailServerCertificateVerificationList

- При вызове `ИнтернетПочта.Подключиться()` платформа проверяет сертификат почтового сервера (подключение по умолчанию идёт по защищённому соединению).
- Хосты почтовых серверов, для которых проверка сертификата не нужна, перечисляются в этом параметре.
- Разделитель списка — `;`.
- Подстановочные символы: `*` — произвольное количество любых символов, `?` — один произвольный символ.

### 3.17.16. IgnoreServerCertificatesChainRevocationSoftFail

Поведение в случае, когда платформа не может однозначно проверить отзыв сертификата сервера.

| Значение | Смысл | Результат в ситуации «сертификат предоставлен, цепочка корректна, отзыв проверить невозможно» |
|---|---|---|
| `true` (по умолчанию) | ошибки проверки отзыва игнорируются | соединение устанавливается |
| `false` | ошибки проверки отзыва не игнорируются | соединение не устанавливается, формируется исключение |

### 3.17.17. JavaHome

- Путь к каталогу установки Java.
- Если параметр не задан — путь берётся из переменной окружения `JAVA_HOME`.
- Указывается в `conf.cfg` на компьютере, где расположен кластер серверов «1С:Предприятия».
- Только Windows: если нет ни `JavaHome` в `conf.cfg`, ни переменной `JAVA_HOME`, путь установки Java определяется по системному реестру (туда его заносит установщик JRE).

### 3.17.18. LicConfigDebugTimeouts

Включает укороченные периоды проверки при работе с ЦЛ (ссылка на др. раздел; аббревиатура в этой части не расшифрована). По умолчанию: `false`.

| Проверка | `true` (укороченные) | `false` (обычные) |
|---|---|---|
| Проверка лицензии сервером | каждые 60 секунд | каждый 1 час |
| Проверка лицензии клиентами | каждые 30 секунд | каждый 1 час |
| Повторная проверка лицензии клиентами (при недоступности ЦЛ или после ввода данных клиента лицензирования) | 15 секунд | 10 минут |

### 3.17.19. PublishDistributiveLocation`<OS>`

Девять параметров, задающих расположение дистрибутива клиентского приложения для конкретной ОС и разрядности. По смыслу и содержимому совпадают с одноимёнными по назначению атрибутами `pubdst*` корневого элемента `point` файла `default.vrd` (см. раздел 3.21.2 ниже). Соответствие — по порядку перечисления в документации:

| Параметр `conf.cfg` | Атрибут `point` в `default.vrd` |
|---|---|
| `PublishDistributiveLocationLinux32` | `pubdstlin32` |
| `PublishDistributiveLocationLinux64` | `pubdstlin64` |
| `PublishDistributiveLocationLinuxDeb32` | `pubdstlindeb32` |
| `PublishDistributiveLocationLinuxDeb64` | `pubdstlindeb64` |
| `PublishDistributiveLocationLinuxRpm32` | `pubdstlinrpm32` |
| `PublishDistributiveLocationLinuxRpm64` | `pubdstlinrpm64` |
| `PublishDistributiveLocationMacOS64` | `pubdstmac64` |
| `PublishDistributiveLocationWindows32` | `pubdstwin32` |
| `PublishDistributiveLocationWindows64` | `pubdstwin64` |

Кеширование:

- Значения этих параметров кешируются при подключении первого клиентского приложения.
- После изменения параметров в `conf.cfg` кеш обновляется через 10 секунд.
- «Система», которая кеширует значения, — это рабочий процесс (клиент-серверный вариант, при любом способе подключения клиентов) либо модуль расширения веб-сервера (файловый вариант с доступом через веб-сервер).

### 3.17.20. RestructJavaOpts

Дополнительные параметры запуска JVM для оптимизированного механизма реструктуризации.

- Значение не должно содержать кавычек.
- Указывается в `conf.cfg` на компьютере, где расположен кластер серверов «1С:Предприятия».
- Типичное применение — задание максимального объёма памяти JVM.

```
#Задание максимального размера доступной памяти для JAVA-процесса
RestructJavaOpts=-Xmx2048m
```

```
#Запуск JAVA процессов с возможностью подключения отладчика
RestructJavaOpts=-agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=5005
```

### 3.17.21. SpeechToTextModelLocation

Каталог хранения файлов моделей распознавания речи для всех вариантов ИБ на компьютере, где лежит данный `conf.cfg`. Позволяет в одном месте на сервере задать один каталог для всех баз и кластеров.

Если параметр не указан, расположение моделей таково:

| Вариант ИБ | ОС | Каталог |
|---|---|---|
| Файловый | Windows | `%LOCALAPPDATA%\1C\1cv8\STT` (пользователя, под которым работает система) и `%ALLUSERSPROFILE%\1C\1cv8\STT` (данные для всех пользователей компьютера) |
| Файловый | Linux | `~/.1cv8/1C/1cv8/STT` |
| Файловый | macOS | `~/.1cv8/1C/1cv8/STT` |
| Клиент-серверный | любая | подкаталог `STT` каталога реестра кластера на каждом рабочем сервере; размещение хранилища моделей для рабочего сервера настраивается отдельно (ссылка на др. раздел) |

- Модели автоматически **не удаляются**. Размер каталога нужно контролировать вручную и чистить при превышении допустимого объёма (допустимый объём администратор определяет сам).
- Связанная тема: «Распознавание речи» (ссылка на др. раздел).

### 3.17.22. SystemLanguage

Язык интерфейса системы.

- Значение — код языка интерфейса (перечень кодов — ссылка на др. раздел) или `System`.
- Код языка — используется именно этот язык.
- `System` — язык интерфейса определяется локализацией операционной системы.
- Указан несуществующий язык локализации — платформа пробует язык по региональным установкам ОС.
- Интерфейс на указанном языке не установлен — используется английский интерфейс.
- Параметр не указан — работает механизм определения языка по файлу `*.res`. Если файла с расширением `*.res` нет — при запуске выбирается интерфейс по региональным установкам ОС. Неизвестный или несуществующий код языка равносилен отсутствию такого файла.
- Только Windows (клиентское приложение): `conf.cfg` в каталоге `conf` конкретной версии действует на эту версию; `conf.cfg` в каталоге `conf` корневого каталога установки — на все установленные версии на компьютере.

```
SystemLanguage=System
```

```
SystemLanguage=RU
```

Первый пример — язык по региональным установкам ОС, второй — русский (`RU`) интерфейс.

### 3.17.23. UpdateDBCfg

Версия механизма реструктуризации информационной базы, применяемая, когда она не указана явно. Задаётся в `conf.cfg` на компьютере, где **запускается конфигуратор**. По умолчанию: `v1`.

| Значение | Механизм | Условия и ограничения |
|---|---|---|
| `v1` | обычная реструктуризация | Единственный вариант в «1С:Предприятии» версии 8.3.10 и младше. |
| `v2` | оптимизированная реструктуризация | Только клиент-серверный вариант ИБ и только СУБД Microsoft SQL Server или PostgreSQL. Для MS SQL Server сервер «1С:Предприятия» должен соединяться с СУБД по сетевому протоколу TCP/IP (в терминах СУБД); при подключении по протоколам «Разделяемая память» или «Именованные каналы» оптимизированный механизм не поддерживается. |

Дополнительные параметры JVM оптимизированного механизма задаются параметром `RestructJavaOpts` (3.17.20).

## 3.18. ConfigDumpInfo.xml

Файл версий: хранит версии объектов конфигурации на момент выгрузки конфигурации в файлы.

- Расположение: каталог, в который выполняется выгрузка конфигурации в файлы.
- Формат: XML, кодировка UTF-8.
- Связанная тема: «Выгрузка и загрузка конфигурации в файлы» (ссылка на др. раздел).

Структура:

```
ConfigDumpInfo            (корневой; атрибуты format, version)
└─ ConfigVersions         (единственный подчинённый; атрибутов нет)
   └─ Metadata            (по одному на каждый объект выгружаемой конфигурации; атрибуты name, id, configVersion)
      └─ Metadata         (один или несколько вложенных — подчинённые объекты, не существующие отдельно от родителя, например реквизиты)
```

Количество элементов `Metadata` равно количеству объектов конфигурации «с точки зрения» механизма выгрузки в файлы.

| Элемент | Атрибут | Содержимое |
|---|---|---|
| `ConfigDumpInfo` | `format` | Формат выгрузки, к которой относится файл: `Plain` — плоский; `Hierarchical` — иерархический (ссылка на др. раздел). |
| `ConfigDumpInfo` | `version` | Номер версии формата выгрузки конфигурации в файлы. |
| `ConfigVersions` | — | Атрибутов нет. |
| `Metadata` | `name` | Полное имя выгруженного объекта конфигурации. |
| `Metadata` | `id` | Внутренний идентификатор объекта конфигурации. |
| `Metadata` | `configVersion` | «Версия» объекта. По ней определяется, что объект изменён и его нужно выгрузить повторно. |

Значения `id` и `configVersion` — служебные «магические числа» для внутренних механизмов платформы; для внешнего использования и воспроизведения не предназначены.

## 3.19. debugcfg.xml

Настройка **дополнительного** диапазона портов для отладки конфигураций.

- Расположение: каталог конфигурационных файлов «1С:Предприятия». Файл необязателен.
- Используется, только если отладка идёт по протоколу TCP/IP.
- Если файла нет — для отладки берутся порты стандартного диапазона `1560:1591`.
- Предметы отладки на сервере работают через те же порты, что и серверные процессы `rmngr` и `rphost`; дополнительные диапазоны портов для серверных предметов отладки задавать не нужно.

```xml
<config xmlns="http://v8.1c.ru/v8/debugcfg">
<debugports range="1540:1550"/>
</config>
```

| Элемент | Атрибут | Тип | Назначение |
|---|---|---|---|
| `debugports` | `range` | Строка | Дополнительный диапазон портов, используемых при отладке (в примере — `1540:1550`). |

## 3.21. default.vrd

### 3.21.1. Общая информация

- Назначение: параметры публикации прикладного решения на веб-сервере.
- Расположение: каталог виртуального приложения.
- Формат ссылок в файле должен соответствовать RFC 1738 (https://datatracker.ietf.org/doc/html/rfc1738.html) и RFC 2396 (https://datatracker.ietf.org/doc/html/rfc2396.html).

### 3.21.2. Корневой элемент `<point>`

Корневой элемент файла — `<point>`; он описывает настройки виртуального ресурса. Может содержать **по одному** элементу каждого вида:

`<ws>`, `<httpServices>`, `<pool>`, `<debug>`, `<zones>`, `<openid>`, `<openidconnect>`, `<exitURL>`, `<standardOData>`, `<analytics>`, `<progressiveWebApplication>`, `<accessTokenAuthentication>`, `<authentication>`, `<mobileApps>`.

Часть из них имеет собственные вложенные элементы. Общая схема файла (иерархия по документации, отступы добавлены для читаемости):

```
<point ...>
  <ws ...>
    <point>...</point>
    <zones>
      <zone>...</zone>
      <zone>...</zone>
    </zones>
    <point>...</point>
  </ws>
  <httpServices>
    <service>...<service/>
  </httpServices>
```

#### Атрибуты корневого элемента `<point>`

| Атрибут | Назначение | Значения / умолчание |
|---|---|---|
| `base` | Путь к каталогу виртуального приложения относительно корневого каталога сайта. | Рекомендуется имя каталога только из символов US ASCII. Пример: `base="/demoMA"` |
| `ib` | Строка подключения к информационной базе. | Для файлового и клиент-серверного вариантов выглядит по-разному (см. ниже). |
| `enable` | Разрешает работу с опубликованной ИБ тонким и веб-клиентами. | `true` (по умолчанию) — разрешено; `false` — работа тонким и веб-клиентом невозможна. |
| `temp` | Каталог временных файлов для расширения веб-сервера или файловой ИБ. | Не задан — см. ниже. |
| `pubdstlin32`, `pubdstlin64`, `pubdstlindeb32`, `pubdstlindeb64`, `pubdstlinrpm32`, `pubdstlinrpm64`, `pubdstmac64`, `pubdstwin32`, `pubdstwin64` | Полный URL файла с дистрибутивом клиентского приложения для случая несовпадения версий клиента и сервера. | См. ниже. |
| `allowexecutescheduledjobs` | Выполнение регламентных заданий расширением веб-сервера для файловой ИБ. | `off`, `force`; по умолчанию не задано. |

**Атрибут `ib`.**

- Символы строки подключения, недопустимые по стандарту XML (https://www.w3.org/TR/xml11/), должны быть заменены соответствующим образом (в примерах кавычки записаны как `&quot;`).
- Файловая база:

```
ib="File=c:/bases/demo;"
```

- Клиент-серверная база:

```
ib="Srvr=&quot;tcp://myServer&quot;;Ref=&quot;mybase&quot;;"
```

- В строке подключения можно указать логин и пароль (`Usr`, `Pwd`) — тогда подключение к ИБ идёт от имени этого пользователя. Пример для пользователя «Продавец»:

```
ib="Srvr=&quot;tcp://myServer&quot;;Ref=&quot;mybase&quot;;Usr=Продавец;Pwd=123;"
```

- Если логин и пароль заданы в командной строке запуска клиентского приложения — используются параметры командной строки, а не из `ib`.

**Атрибут `enable`.** При `true` адрес подключения для примера выше — `http://host/demo`.

**Атрибут `temp`.**

- Каталог временных файлов для расширения веб-сервера (`wsisapi.dll`, `wsap22.dll`, `wsapch2.dll`) или файлового варианта ИБ.
- Если атрибут не задан:
  - для файловой ИБ — подкаталог `1Cv8Temp` каталога, где лежит файл информационной базы;
  - в остальных случаях — каталог временных файлов пользователя, от имени которого выполняется запрос.
- Если каталог указан и используется расширением веб-сервера, пользователь, от имени которого работает расширение веб-сервера, должен иметь полный доступ к каталогу и его содержимому.

**Атрибуты `pubdst*`** (дистрибутив клиентского приложения).

URL должен обеспечивать доступ к дистрибутиву извне компьютера, на котором он лежит.

| Название в диалоге публикации | Атрибут `default.vrd` | Что публикуется |
|---|---|---|
| Linux (DEB) x32 | `pubdstlindeb32` | 32-разрядный тонкий клиент для Linux, пакеты DEB |
| Linux (DEB) x64 | `pubdstlindeb64` | 64-разрядный тонкий клиент для Linux, пакеты DEB |
| Linux (RPM) x32 | `pubdstlinrpm32` | 32-разрядный тонкий клиент для Linux, пакеты RPM |
| Linux (RPM) x64 | `pubdstlinrpm64` | 64-разрядный тонкий клиент для Linux, пакеты RPM |
| Linux x32 | `pubdstlin32` | 32-разрядный тонкий клиент для Linux, программа установки |
| Linux x64 | `pubdstlin64` | 64-разрядный тонкий клиент для Linux, программа установки |
| macOS x64 | `pubdstmac64` | 64-разрядный тонкий клиент для macOS |
| Windows x32 | `pubdstwin32` | 32-разрядный тонкий клиент для Windows |
| Windows x64 | `pubdstwin64` | 64-разрядный тонкий клиент для Windows |

Правила получения и установки:

- При скачивании по HTTPS компьютер-получатель проверяет сертификат сервера-источника по сертификатам корневых удостоверяющих центров из хранилища корневых сертификатов своей ОС.
- Установка выполняется с параметрами из файла `1cestart.cfg` (как при обычной установке клиентского приложения).
- При смене версии сервера достаточно заменить файл с архивом клиентского приложения.

Требования к упаковке дистрибутива:

- Дистрибутив должен быть помещён в архив вида **zip**. Исключения (можно не архивировать) — только для Linux:
  - run-файл программы установки;
  - rpm- или deb-файл установочного пакета, если вместе с дистрибутивом не нужно распространять национальные ресурсы (кроме русского и английского языков).
- Состав архива по ОС:

| ОС | Вариант | Требуемый файл |
|---|---|---|
| Linux | программа установки | run-файл тонкого клиента `setup-thin-A.B.C.D-arch.run` (A.B.C.D — полный номер версии платформы, arch — архитектура процессора) |
| Linux | пакетный менеджер (DEB или RPM) | файл пакета тонкого клиента `1с-enteprise-A.B.С.D-thin-client_A.B.C-D.arch.ext` (A.B.C.D / A.B.C-D — полный номер версии, arch — архитектура, ext — расширение пакетного менеджера). Пакет размещается либо сам по себе, либо в zip-архиве с произвольным именем; в архив можно добавить nls-файл клиентского приложения. Имена файлов внутри архива должны в точности совпадать с требуемыми. |
| macOS | — | файл `.dmg` |
| Windows | — | только файлы дистрибутива клиентского приложения, без иерархии и каталогов |

- Все файлы `.pkg` дистрибутива для macOS должны иметь цифровую подпись.
- Цифровые подписи файлов дистрибутива должны проходить проверку на компьютере, где выполняется установка.
- Только Windows (IIS): может потребоваться задать MIME-тип для расширения `.zip` (ссылка на др. раздел).

⚠ в источнике неясно: шаблон имени пакета записан как `1с-enteprise-…` (без буквы «r» и с кириллической «с»), а в примере ниже run-файл назван `setup-fhin-…`, хотя шаблон — `setup-thin-…`. Вероятно, это опечатки документации; сверяйте с фактическими именами файлов дистрибутива.

Пример из документации:

```
pubdstwin32="http://www.myhost.ru/files/client-win-32.zip"
pubdstmac64="http://www.myhost.ru/files/client-mac-64.zip"
pubdstlin64="http://www.myhost.ru/files/setup-fhin-8.3.22.100-x86_64.run"
pubdstlindeb32="http://www.myhost.ru/files/1с-enteprise-8.3.22.100-thin-client_8.3.22-100.i386.deb"
```

Те же сведения можно задать параметрами `PublishDistributiveLocation<OS>` файла `conf.cfg` (3.17.19).

**Атрибут `allowexecutescheduledjobs`** — выполнение регламентных заданий расширением веб-сервера для **файловой** ИБ.

| Значение | Поведение |
|---|---|
| `off` | Расширение веб-сервера регламентные задания не выполняет. Их выполняет клиентское приложение (если такое есть), подключённое к ИБ напрямую, без веб-сервера. |
| `force` | Регламентные задания выполняет расширение веб-сервера. |
| не задано (по умолчанию) | Задания выполняет то приложение, которым выполнено первое подключение к ИБ. |

### 3.21.3. Элемент `<ws>`

#### 3.21.3.1. Общее описание и атрибуты элемента

- Настройки публикации Web-сервисов. Подчинён корневому `<point>`; допускается один элемент `<ws>` или ни одного.
- Содержит произвольное количество вложенных элементов `<point>`, каждый описывает один Web-сервис.
- Если для доступа к Web-сервису нужна JWT-аутентификация — создаётся элемент `<accessTokenAuthentication>` (ссылка на др. раздел), подчинённый элементу `<ws/point>`.

| Атрибут `<ws>` | Назначение | По умолчанию |
|---|---|---|
| `enable` | Разрешает работу Web-сервисов в данной ИБ: `true` или отсутствие атрибута — разрешено; `false` — запрещено. | `true` |
| `pointEnableCommon` | Правило для Web-сервисов, у которых разрешение не задано явно (нет атрибута `enable` у элемента `point`): `true` — такие сервисы разрешены, иначе — запрещены. | `true` |
| `publishExtensionsByDefault` | Web-сервисы из расширений: `true` — доступны все Web-сервисы подключённых расширений; `false` — недоступны. | `false` |

#### 3.21.3.2. Элемент `<point>`

- Описание одного публикуемого Web-сервиса. Подчинён `<ws>`. По тексту раздела — элементов `<point>` «не менее одного» (в 3.21.3.1 — «произвольное количество»).
- В этом списке можно вручную указать и параметры Web-сервисов из расширений.
- Если Web-сервис **не указан** явно в `default.vrd`, а использование Web-сервисов прикладного решения разрешено — обращаться к нему можно только по имени (свойство Web-сервиса «Имя»). По синониму (alias) он будет недоступен, даже если синоним задан в свойстве Web-сервиса «Имя файла публикации». Чтобы работали и имя, и синоним — сервис нужно явно прописать в `default.vrd` вместе с синонимом.

| Атрибут | Назначение | Значения / умолчание |
|---|---|---|
| `name` | Имя публикуемого Web-сервиса. Рекомендуется только US ASCII. | — |
| `alias` | Синоним публикуемого Web-сервиса (работает, если указан в `default.vrd`). Рекомендуется только US ASCII. | — |
| `enable` | Разрешение или запрет конкретного Web-сервиса. | по умолчанию `true` (публикация разрешена) |
| `reuseSessions` | Режим повторного использования сеансов: `dontuse` — не используются повторно; `use` — определяется клиентом и регулируется параметрами HTTP-запроса к Web-сервису; `autouse` — автоматическое повторное использование. | по умолчанию `autouse` |
| `sessionMaxAge` | Время бездействия сеанса в секундах, после которого он принудительно завершается. | по умолчанию `20` |

Изменённые значения `reuseSessions` и `sessionMaxAge` вступают в силу только после перезапуска сервера «1С:Предприятия».

Адресация: к сервису можно обратиться по ссылке и с именем, и с синонимом.

```
…
base="/demo"
…
<point name="OperationalData" alias="OperData"/>
```

```
http://host/demo/ws/OperationalData
http://host/demo/ws/OperData
```

### 3.21.4. Элемент `<httpServices>`

#### 3.21.4.1. Общее описание и атрибуты элемента

- Настройки публикации HTTP-сервисов. Подчинён корневому `<point>`; один элемент или ни одного.
- Содержит произвольное количество элементов `<service>`, каждый описывает один HTTP-сервис.
- Для JWT-аутентификации при доступе к HTTP-сервису создаётся элемент `<accessTokenAuthentication>` (ссылка на др. раздел), подчинённый элементу `<httpServices/service>`.

| Атрибут `<httpServices>` | Назначение | По умолчанию |
|---|---|---|
| `publishByDefault` | Не задан или `true` — все добавляемые в конфигурацию HTTP-сервисы автоматически доступны, если это явно не запрещено элементом `<service>`. | `true` |
| `publishExtensionsByDefault` | HTTP-сервисы из расширений: `true` — доступны все HTTP-сервисы подключённых расширений; `false` — недоступны. | `false` |

#### 3.21.4.2. Элемент `<service>`

- Описание одного публикуемого HTTP-сервиса. Подчинён `<httpServices>`. По тексту раздела — элементов `<service>` «не менее одного».
- Здесь же можно вручную указать параметры HTTP-сервисов из расширений.

| Атрибут | Назначение | Значения / умолчание |
|---|---|---|
| `name` | Имя HTTP-сервиса, как оно задано в конфигураторе. Для обращения к сервису **не используется**. | — |
| `rootUrl` | Значение свойства «Корневой URL» HTTP-сервиса. По нему определяется, какой HTTP-сервис обрабатывает поступивший запрос. | — |
| `enable` | Разрешение или запрет конкретного HTTP-сервиса. | по умолчанию `false` (использование запрещено) |
| `reuseSessions` | Режим повторного использования сеансов: `dontuse` — не используются повторно; `use` — определяется клиентом и регулируется параметрами HTTP-запроса к HTTP-сервису; `autouse` — автоматическое повторное использование. | по умолчанию `autouse` |
| `sessionMaxAge` | Время бездействия сеанса в секундах до принудительного завершения. | по умолчанию `20` |

Обратите внимание на асимметрию умолчаний: у `<ws>/<point>` атрибут `enable` по умолчанию `true`, у `<httpServices>/<service>` — `false`.

### 3.21.5. Элемент `<pool>`

Настройки пула соединений с информационной базой. Один элемент или ни одного.

| Атрибут | Назначение | Единицы | По умолчанию | Максимум |
|---|---|---|---|---|
| `size` | Размер пула — максимальное число соединений в пуле. | шт. | 10 000 | — |
| `maxAge` | Максимальное время жизни соединения в пуле; невостребованное за это время соединение удаляется из пула. | секунды | 20 мин | — |
| `attempts` | Максимальное число попыток установить соединение с сервером «1С:Предприятия». | шт. | 5 | — |
| `attemptTimeout` | Время ожидания установления соединения с сервером «1С:Предприятия». | секунды | 500 с | — |
| `waitTimeout` | Пауза между попытками установить соединение с сервером «1С:Предприятия». | секунды | 500 с | — |
| `serverPingPeriod` | Период проверки системы отслеживания разрыва соединений. | миллисекунды | 1 000 мс | 65 535 мс |
| `serverPingTimeout` | Время, в течение которого система отслеживания разрыва соединений ждёт хотя бы одно сообщение от отслеживаемого процесса. | миллисекунды | 5 000 мс | 2 147 483 647 мс |

- Подробности о системе отслеживания разрыва соединений — в основной части документации («в книге»), в этой части не раскрыты.
- ⚠ в источнике неясно: для `maxAge` единица измерения указана как секунды, а значение по умолчанию записано как «20 мин».

```xml
<pool size="50" maxAge="10" attempts="2" attemptTimeout="1" waitTimeout="1"/>
```

### 3.21.6. Элемент `<debug>`

Настройки отладки для данной публикации (общее описание элемента в источнике отсутствует, приведены только атрибуты).

| Атрибут | Назначение | Значения |
|---|---|---|
| `enable` | Нужно ли запускать в отладочном режиме. | `true` — отладка включена; `false` — выключена |
| `protocol` | Протокол отладки для публикации, если отладка разрешена. | `tcp` — TCP/IP (по умолчанию); `http` — HTTP |
| `url` | Адрес отладчика, к которому нужно подключаться автоматически. | см. ниже |

Правила для `url`:

- `localhost` означает поиск отладчика на локальном компьютере; число после хоста (в документации приводится «1560») — номер сетевого порта.
- Порт не указан — перебираются все порты диапазона 1560–1591.
- `tcp://` равнозначно `tcp://localhost`.
- Адрес отладчика не указан — отладка при выполнении кода на встроенном языке не производится.
- Для протокола HTTP адрес обязательно задаётся с портом взаимодействия: `http://pc-name:1561`.
- Если протокол из атрибута `protocol` не совпадает со схемой в `url` — соединение с отладчиком не устанавливается, работа продолжается без отладки.

```xml
<debug enable="true" protocol="http" url="http://pc-name:1561"/>
```

### 3.21.7. Элемент `<zones>`

#### 13.4.2.1. Описание элемента

(Номер подраздела «13.4.2.1» приведён как в источнике — по-видимому, сбой нумерации внутри 3.21.7.)

- `<zones>` подчинён корневому `<point>`; один элемент или ни одного.
- Содержит один или несколько элементов `<zone>`.
- Собственных атрибутов не имеет.

#### 3.21.7.1. Элемент `<zone>`

Каждый `<zone>` описывает один разделитель.

- Порядок элементов `<zone>` внутри `<zones>` соответствует порядку разделителей в конфигураторе. Изменился порядок разделителей — нужно править `default.vrd`.
- Элементов `<zone>` не должно быть больше, чем разделителей: иначе при подключении к так опубликованной ИБ возникает исключение.
- Если элементов меньше, чем разделителей, — для неуказанных разделителей берётся значение по умолчанию для типа разделителя, а использование разделителя выключается.

| Атрибут | Назначение | По умолчанию |
|---|---|---|
| `safe` | Безопасный режим разделения данных: запрет менять значения объектов, связанных с разделением данных, при доступе через веб-клиент или тонкий клиент, подключённый через веб-сервер. Нужен как гарантия, что при доступе через Интернет нельзя попасть в чужую область данных. | `false` (изменения разрешены) |
| `specify` | Должно ли значение разделителя присутствовать в адресе публикуемой ИБ. | `false` (разделитель не участвует в формировании адреса) |
| `value` | Явное значение разделителя, стоящего на данной позиции. | не задано |

При `safe="true"` в сеансе, работающем через эту публикацию, запрещено:

- выключать использование разделителя, если разделение не является условно выключенным;
- менять значение используемого разделителя, если разделение не является условно выключенным;
- изменять объекты, управляющие условным разделением, — указанные и для самого разделителя, и для объектов, входящих в состав разделителя.

Правила для `value` и `specify`:

- `value` не задан и `specify="false"` — трактуется как отсутствие значения разделителя (то же, что «-» в параметре `Zn` строки соединения).
- `specify="true"` и задан `value` — именно это значение (без учёта регистра) должно стоять в адресе ИБ в соответствующей позиции; иначе при обращении к ИБ возвращается ошибка с кодом 404.
- Символы, недопустимые в URL по RFC 1738, переводятся в UTF-8 и кодируются по разделу 2.2 «URL Character Encoding Issues» RFC 1738 (символ `%` и две шестнадцатеричные цифры).

Пример файла из документации (в конфигурации 5 разделителей):

```xml
<?xml version="1.0" encoding="UTF-8"?>
<point xmlns=http://v8.1c.ru/8.2/virtual-resource-system xmlns:xs=http://www.w3.org/2001/XMLSchema xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
base="/test"
ib="File=&quot;с:\base&quot;;">
<ws enable="false"/>
<zones>
<zone value="8214" safe="true"/>
<zone specify="true" />
<zone />
<zone specify="true" />
<zone value="last" specify="true" />
</zones>
</point>
```

Адрес информационной базы для этого примера:

```
http://example.com/test/01/20101231235959/last
```

| Позиция | Запись в файле | Как трактуется |
|---|---|---|
| — | `base="/test"` | `http://example.com/test` — адрес самой ИБ |
| 1 | `<zone value="8214" safe="true"/>` | В адресе не указывается (`specify` по умолчанию `false`); значение 8214; программно управлять разделителем нельзя (`safe="true"`) |
| 2 | `<zone specify="true" />` | Обязателен в адресе; значение из адреса — `01` |
| 3 | `<zone />` | Разделитель отключён |
| 4 | `<zone specify="true" />` | Обязателен в адресе; значение `20101231235959` = 31-12-2010 23:59:59 |
| 5 | `<zone value="last" specify="true" />` | Обязателен в адресе, и допустимо только значение `last` |

Разделителями 2–5 можно управлять программно (`safe` не задан, умолчание `false`). Такой способ задания разделителей применим для тонкого клиента через веб-сервер, веб-клиента и Web-сервисов.

**Приоритет при одновременном указании разделителей разными способами:**

- Элемент `<zones>` в `default.vrd` **задан** — наивысший приоритет у значений разделителей из адреса ИБ. При этом игнорируются:
  - значения из параметра запуска `Z`;
  - значения из строки соединения (параметр `Zn` в атрибуте `ib` элемента `<point>`).
- Элемент `<zones>` **не задан**:
  - сначала выполняется попытка взять значения из параметра `Z` строки адреса;
  - если параметр не указан — из строки соединения (параметр `Zn` в атрибуте `ib` элемента `<point>`).
- Общий порядок приоритета (по убыванию):
  1. адрес информационной базы (если в `default.vrd` есть `<zones>`);
  2. командная строка запуска (параметр `Z`);
  3. строка соединения информационной базы (параметр `Zn` в атрибуте `ib` элемента `<point>`).

### 3.21.8. Элемент `<openid>`

#### 3.21.8.1. Описание элемента

- Настройки OpenID-аутентификации. Подчинён корневому `<point>`; один элемент или ни одного.
- Подчинённые элементы: `<rely>` и `<provider>` — каждый либо в единственном числе, либо отсутствует.
- Собственных атрибутов нет.

#### 3.21.8.2. Элемент `<rely>`

Адрес информационной базы, выступающей OpenID-провайдером.

| Атрибут | Назначение |
|---|---|
| `url` | URL информационной базы «1С:Предприятия» в роли OpenID-провайдера. Эта база должна быть опубликована особым образом. |

- Взаимодействие с OpenID-провайдером возможно **только по HTTPS**.
- URL провайдера не должен оканчиваться символом `/`. Верно: `https://myserver.org/users-ib/e1cib/oid2op`; неверно: `https://myserver.org/users-ib/e1cib/oid2op/`.

```xml
<rely url="https://myserver.org/users-ib/e1cib/oid2op"/>
```

#### 3.21.8.3. Элемент `<provider>`

##### 3.21.8.3.1. Описание элемента

Признак того, что данная информационная база сама является OpenID-провайдером. Может содержать элемент `<lifetime>` (один или ни одного) и элементы `<returnto>`.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<point xmlns=http://v8.1c.ru/8.2/virtual-resource-system xmlns:xs=http://www.w3.org/2001/XMLSchema xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
base="/demo"
ib="Srvr=&quot;tcp://Server&quot;;Ref=&quot;demo&quot;;"
enable="false">
<openid>
<provider/>
</openid>
</point>
```

##### 3.21.8.3.2. Элемент `<lifetime>`

Время жизни признака аутентификационных данных, в секундах (задаётся содержимым элемента).

| Параметр | Значение |
|---|---|
| По умолчанию (элемент не указан) | 86 400 секунд (24 часа) |
| Максимум | 604 800 секунд (7 суток) |
| Указано больше максимума | применяется максимальное значение |

```xml
<openid>
<provider>
<lifetime>432000</lifetime>
</provider>
</openid>
```

##### 3.21.8.3.3. Элемент `<returnto>`

- Подчинён `<provider>`; может повторяться неограниченное число раз или отсутствовать.
- Содержимое — регулярное выражение: маска разрешённых имён сайтов, на которые допускается переадресация пользовательского веб-браузера (параметр запроса `openid.return_to`) после выполнения команды OpenID-провайдера.
- Не используется, если к OpenID-провайдеру обращается тонкий клиент.
- Если при публикации OpenID-провайдера не указан ни один `<returnto>`, любой запрос веб-браузера к провайдеру с параметром `openid.return_to` завершается ошибкой HTTP 400.

```xml
<returnto>mysite\.org</returnto>
<returnto>.*\.1c\.ru</returnto>
```

### 3.21.9. Элемент `<openidconnect>`

#### 3.21.9.1. Описание элемента

- Настройки аутентификации по протоколу OpenID Connect. Применимо для тонкого клиента, мобильного клиента и веб-клиента.
- Подчинён корневому `<point>`; один элемент или ни одного.
- Подчинённые элементы: `<providers>` и `<allowStandardAuthentication>` — каждый в единственном числе либо отсутствует.
- Собственных атрибутов нет.

```xml
<openidconnect>
<providers><![CDATA[[
<json-data>
]]]>
</providers>
<allowStandardAuthentication>true</allowStandardAuthentication>
</openidconnect>
```

Описание элемента `<allowStandardAuthentication>` в эту часть источника не попало (в примерах он задан значением `true`).

#### 3.21.9.2. Элемент `<providers>`

Описание внешних OpenID-провайдеров, поддерживающих протокол авторизации OpenID Connect v1.0 (https://openid.net/connect/). Содержимое — JSON-массив объектов (внутри `CDATA`), каждый объект описывает одного провайдера.

**Свойства объекта-провайдера**

| Свойство | Назначение | Значения / примечания |
|---|---|---|
| `name` | Идентификатор провайдера. | Должен быть уникален в массиве; при совпадении идентификаторов используется последний провайдер из массива. |
| `title` | Текстовое представление провайдера. | Показывается на кнопке провайдера на странице аутентификации, если не задана картинка (`image`). |
| `image` | Графическое представление провайдера на кнопке страницы аутентификации. | Задаётся как `data:image` в формате Base64. |
| `discovery` | URL провайдера, по которому можно получить все его настройки (discovery endpoint URL). | Рекомендуется выбирать провайдеров с поддержкой discovery endpoint. |
| `authenticationClaimName` | Поле JSON-структуры (JSON Web Token, JWT) с результатами аутентификации, используемое как идентификатор для сопоставления пользователя ИБ и пользователя провайдера. | Не указано — берётся поле с электронной почтой. |
| `authenticationUserPropertyName` | Какое свойство пользователя ИБ сравнивается с идентификатором, пришедшим от провайдера. | `name`, `OSUser`, `email`, `matchingKey` (см. ниже). |
| `endSessionEndpoint` | URL, на который выполняется переход при команде завершения сеанса аутентификации. | К URL автоматически добавляется параметр `id_token_hint` с токеном, полученным при аутентификации пользователя. |
| `providerconfig` | Настройки провайдера в виде JSON-структуры — для провайдеров, не поддерживающих запрос получения настроек. | Формат OpenID Provider Metadata (https://openid.net/specs/openid-connect-discovery-1_0.html#ProviderMetadata). |
| `clientconfig` | Клиентская конфигурация в виде JSON-структуры. | Формат OAuth 2.0 Authorization Request (https://openid.net/specs/openid-connect-core-1_0.html#AuthRequest) плюс свойство `authority` — URL провайдера аутентификации. Содержимое зависит от провайдера. |
| `dialect` | Протокол взаимодействия с провайдером. | `ru-esia` — протокол ЕСИА (Единая система идентификации и аутентификации, https://minsvyaz.ru/ru/activity/directions/13/). Не указано или иное значение — OpenID Connect v1.0. |
| `crypto` | Структура с описанием модуля криптографии для подписи запросов. | Нужна, когда `dialect` = `ru-esia` (запросы к ЕСИА подписываются). Состав — см. ниже. |

Значения `authenticationUserPropertyName`:

| Значение | С чем сравнивается идентификатор от провайдера |
|---|---|
| `name` | имя пользователя (свойство `Имя` объекта `ПользовательИнформационнойБазы`) |
| `OSUser` | имя пользователя ОС (свойство `ПользовательОС` объекта `ПользовательИнформационнойБазы`) |
| `email` | адрес электронной почты (свойство `АдресЭлектроннойПочты` объекта `ПользовательИнформационнойБазы`) |
| `matchingKey` | значение из свойства `КлючиСопоставленияПользователя`; ключом поиска служит значение `name` из описания провайдера |

О завершении сеанса (`endSessionEndpoint`): закрытие вкладки браузера с веб-клиентом и завершение клиентского приложения сеанс аутентификации **не завершают**. В веб-клиенте после завершения сеанса аутентификации выполняется переход на стандартную страницу завершения сеанса.

**Структура `clientconfig`**

Свойство `response_type` определяет вид аутентификации:

| `response_type` | Сценарий | `client_secret` |
|---|---|---|
| `code` | Authorization Code Flow | Содержит данные, выданные OpenID-провайдером при регистрации. При отправке конфигурации клиентскому приложению удаляется из `clientconfig`. |
| `id_token` или `id_token token` | Implicit Flow | Не используется. Сценарий не рекомендуется по соображениям безопасности, оставлен для совместимости. |
| остальные комбинации | не поддерживаются | — |

Свойство `redirect_uri` — URL перехода в обработчик аутентификации приложения, запросившего аутентификацию. Обычный вид: `https://<IBhost>/<IBname>/authform.html`.

- `<IBhost>` — имя хоста, на котором опубликована ИБ.
- `<IBname>` — имя опубликованной ИБ: содержимое поля «Имя» диалога публикации либо атрибут `point.base` файла публикации. Должно совпадать с именем ИБ посимвольно, включая регистр.
- `{zones}` — шаблон, указываемый только когда разделители передаются как часть адреса ИБ (в теле URL) и описаны в секции `<zones>` файла `default.vrd`.
  - Если разделители передаются параметром строки запуска `Z` — шаблон `{zones}` в URL переадресации не указывается; значения из строки запуска применяются автоматически.
  - Если шаблон есть в `redirect_uri`, а разделители через URL не передаются (или секции `<zones>` нет) — шаблон заменяется пустой строкой.

| URL доступа к базе | Какой `redirect_uri` указывать |
|---|---|
| `https://example.com/test-db/val1/val2` (2 разделителя в адресе) | `https://example.com/test-db/{zones}/authform.html` |
| `https://example.com/test-db?Z=val1,val2` | `https://example.com/test-db/authform.html` |

**Структура `crypto`** (поля аналогичны параметрам конструктора объекта `МенеджерКриптографии`)

| Свойство | Назначение |
|---|---|
| `module_name` | имя модуля криптографии |
| `module_path` | путь к модулю криптографии |
| `module_type` | тип модуля криптографии |
| `cert_thumbprint` | отпечаток сертификата для подписи запросов; по отпечатку выполняется поиск сертификата, который заранее должен лежать в хранилище личных сертификатов |

Сопоставление по пользователю ОС и кнопка с картинкой (провайдер `microsoft`; остальные свойства `clientconfig` — как у `google`: `client_id`, `redirect_uri`, `"response_type": "id_token token"`, `"scope": "openid email"`):

**Сетевые обращения сервера к провайдеру OpenID Connect**

Кластер серверов «1С:Предприятия» (а для файловой ИБ — расширение веб-сервера) сам обращается к провайдеру OpenID Connect, чтобы:

- получить криптографические ключи для проверки подписи токена аутентификации;
- обменять значение `code` на токен аутентификации (при Authorization Code Flow).

Поэтому компьютеру, на котором работает рабочий сервер кластера, нужно разрешить обращение по URL из свойств `discovery`, `jwks_uri`, `token_endpoint` и, при необходимости, `end_session_endpoint`.

Откуда взять адреса: из описания провайдера (структура параметров выше). Если секция `providerconfig` не заполнена — нужно обратиться по URL из `discovery` и из ответа сервера взять `jwks_uri`, `token_endpoint` и `end_session_endpoint`.

## Что важно администратору Linux

1. **Java для сервера 1С задаётся в `conf.cfg` на компьютере кластера.** `JavaHome` — путь к каталогу Java; если его нет, используется переменная окружения `JAVA_HOME`. Третий способ (системный реестр) описан только для Windows — для Linux источник называет лишь эти два.
2. **`FtsJavaOpts` и `RestructJavaOpts` пишутся без кавычек** и тоже относятся к `conf.cfg` на сервере кластера. Через них задают память JVM (`-Xms2G`, `-Xmx8G`, `-Xmx2048m`); для диагностики запуска сервера полнотекстового поиска версии 2 есть опция `-Dconsole` со значениями `none` (по умолчанию), `all`, `start|stop`.
3. **Java 17 и выше требует дополнительных настроек `FtsJavaOpts`** для корректной работы полнотекстового поиска версии 2 — конкретные опции описаны в другом разделе документации (в этой части их нет).
4. **Оптимизированная реструктуризация (`UpdateDBCfg=v2`) поддерживается для PostgreSQL** в клиент-серверном варианте; по умолчанию действует `v1`. Параметр читается из `conf.cfg` на компьютере, где запущен конфигуратор, а не на сервере.
5. **Каталог моделей распознавания речи растёт без автоочистки.** В клиент-серверном варианте это подкаталог `STT` каталога реестра кластера на каждом рабочем сервере, в файловом на Linux — `~/.1cv8/1C/1cv8/STT`; единый каталог задаётся `SpeechToTextModelLocation`. Размер нужно контролировать вручную.
6. **Порты отладки:** стандартный диапазон `1560:1591`; дополнительный диапазон задаётся в необязательном `debugcfg.xml` (каталог конфигурационных файлов) и только для отладки по TCP/IP. Серверные предметы отладки используют порты `rmngr` и `rphost` — отдельные диапазоны для них не нужны.
7. **`def.usr` больше не используется** начиная с 8.3.26 — искать и сопровождать его не нужно.
8. **`default.vrd`, атрибут `temp`:** если каталог временных файлов задан для расширения веб-сервера, пользователь, от имени которого работает расширение веб-сервера, должен иметь полный доступ к каталогу и его содержимому. Без атрибута используется временный каталог пользователя, выполняющего запрос (для файловой ИБ — `1Cv8Temp` рядом с файлом базы).
9. **Умолчания публикации сервисов различаются:** Web-сервис в `<ws>/<point>` по умолчанию разрешён (`enable=true`), HTTP-сервис в `<httpServices>/<service>` — запрещён (`enable=false`), хотя `publishByDefault` по умолчанию `true`. Сервисы из расширений по умолчанию не публикуются (`publishExtensionsByDefault=false`) в обоих случаях.
10. **Изменение `reuseSessions` и `sessionMaxAge` у Web-сервисов требует перезапуска сервера «1С:Предприятия».** Умолчания: `autouse` и 20 секунд.
11. **Пул соединений `<pool>`:** по умолчанию `size` 10 000, `attempts` 5, `attemptTimeout` и `waitTimeout` по 500 с, `serverPingPeriod` 1 000 мс (макс. 65 535), `serverPingTimeout` 5 000 мс (макс. 2 147 483 647).
12. **Регламентные задания файловой базы за веб-сервером:** `allowexecutescheduledjobs="force"` заставляет выполнять их расширение веб-сервера, `off` — запрещает; без атрибута задания выполняет приложение, подключившееся первым.
13. **Раздача тонкого клиента для Linux через `pubdst*` / `PublishDistributiveLocation<OS>`:** run-файл программы установки и deb/rpm-пакет (если не нужны национальные ресурсы кроме русского и английского) можно выкладывать без zip; если пакет всё же кладётся в zip, имена файлов внутри архива должны точно соответствовать шаблонам. Изменения в `conf.cfg` подхватываются через 10 секунд; при HTTPS клиент проверяет сертификат по корневому хранилищу своей ОС.
14. **Разделители в адресе (`<zones>`):** число элементов `<zone>` не может превышать число разделителей (иначе исключение при подключении), порядок должен совпадать с порядком в конфигураторе. Если `<zones>` задан, параметр `Z` и `Zn` из строки соединения игнорируются; несовпадение обязательного значения в адресе даёт 404.
15. **OpenID и OpenID Connect:** с OpenID-провайдером работа только по HTTPS, URL в `<rely>` — без завершающего `/`, без `<returnto>` браузерные запросы с `openid.return_to` получают HTTP 400. Для OpenID Connect рабочему серверу кластера (в файловом варианте — расширению веб-сервера) нужен исходящий доступ к URL `discovery`, `jwks_uri`, `token_endpoint` и при необходимости `end_session_endpoint` провайдера.
