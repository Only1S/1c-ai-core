## 8.1. Общая информация

Глава описывает настройку веб-серверов для работы веб-клиента и Web-сервисов, а также настройку поддержки OpenID-аутентификации.

| Что публикуется | Шаблон адреса | Пример из документации |

## 8.2. Общие требования

### Базовые условия

- На компьютере, где делается публикация, должен быть установлен и настроен **поддерживаемый** веб-сервер. Для установки веб-сервера нужны административные привилегии.
- Публикация возможна **только если «1С:Предприятие» установлено на том же компьютере, что и веб-сервер**.
- Конфигурация, с которой работают через веб-сервер, **не должна быть пустой**.
- Для установки IIS может понадобиться дистрибутив ОС (только Windows). При установке веб-сервера обязательно установить поддержку ISAPI-расширений (в источнике это требование идёт сразу за фразой про IIS).

### HTTP и HTTPS

- Для работы через Интернет с информационной базой, находящейся в промышленной эксплуатации, протокол HTTP использовать не рекомендуется — он не обеспечивает безопасности подключения к веб-серверу.
- Настоятельно рекомендуется HTTPS. Как включить HTTPS — смотреть в документации самого веб-сервера (в этой части главы не описано).

### Два способа публикации

1. Диалог публикации на веб-сервере в конфигураторе — если на компьютере с веб-сервером можно запустить конфигуратор нужной разрядности.
2. Утилита `webinst`.

### Привилегии для публикации

| ОС | Что требуется |
|---|---|
| Linux | Права суперпользователя: получить `root` командой `su` либо запускать приложение, выполняющее публикацию, через `sudo` |
| Windows | Конфигуратор запускать через пункт контекстного меню «Запуск от имени администратора»; при использовании `webinst` от имени администратора должна быть запущена сама утилита либо интерпретатор командной строки |

Система проверяет привилегии при попытке публикации. Если их не хватает:

| Способ публикации | Поведение |
|---|---|
| Конфигуратор | Задаётся вопрос, продолжать ли публикацию; в диалоге указана причина и рекомендации, как получить привилегии |
| `webinst` | Выдаётся диагностическое сообщение, **но публикация продолжается** |

### Особенности работы через веб-сервер

**Файловый вариант информационной базы:**
- С файлом базы данных работает само расширение веб-сервера.
- Запросы от нескольких клиентских приложений к одной публикации исполняются **последовательно**, в порядке поступления в расширение веб-сервера.
- Один рабочий процесс веб-сервера обслуживает один экземпляр расширения веб-сервера.
- Из-за особенностей получения результатов фоновых заданий в файловом варианте (ссылка без адреса) рекомендуется настраивать веб-сервер так, чтобы **каждую публикацию обслуживало не более одного рабочего процесса** веб-сервера.

**Apache:**
- Публикация не поддерживается, если разрядность Конфигуратора не совпадает с разрядностью экземпляра веб-сервера, для которого выполняется публикация.
- Если на одном компьютере нужны разные версии «1С:Предприятия», для каждой уникальной версии создаётся **отдельный экземпляр веб-сервера**; публикация в таком случае — только вручную.
- **Под Linux рекомендуется модуль мультипроцессной обработки `worker`**; остальные доступные модули использовать не рекомендуется.
- Прочие особенности настройки Apache — (ссылка без адреса).

**IIS (только Windows):**
- Для IIS 7.x и старше не поддерживается публикация, если свойство «Каталог» (параметр `dir` утилиты `webinst`) указывает на `%SYSTEMDRIVE%\inetpub\wwwroot`.
- Публикация всегда делается для веб-сайта по умолчанию (Default Web Site) и пула приложений по умолчанию (DefaultAppPool). Для разных версий платформы в одном экземпляре IIS — отдельный пул приложений на каждую версию, публикация только вручную.
- У пула приложений для «1С:Предприятия» должна быть отключена поддержка .NET: свойство «Версии среды .NET Framework» = «Без управляемого кода».

## 8.3. Виды публикации

### 8.3.1. Общая схема публикации

Что происходит при публикации:

1. Регистрируется модуль обработки запросов (модуль расширения веб-сервера), соответствующий используемому веб-серверу.
2. На веб-сервере регистрируется виртуальное приложение.
3. Создаётся каталог виртуального приложения, в него помещается и настраивается файл `default.vrd` (описание файла — ссылка без адреса).
4. Пользователям назначаются права на каталог с файлом базы данных (только для файлового варианта).

**Версия платформы для публикации.** Публиковать нужно той же версией «1С:Предприятия», которая используется для работы с информационной базой. Пример из документации: установлены 8.3.24.100 и 8.3.24.150, запущен сервер 8.3.24.150 — значит, конфигуратор или `webinst` должны быть ровно версии 8.3.24.150.

**Разрядность.** Разрядность регистрируемого расширения веб-сервера должна совпадать с разрядностью веб-сервера.

| | 32-разрядный веб-сервер | 64-разрядный веб-сервер |
|---|---|---|
| 32-разрядное «1С:Предприятие» | Полностью | Частично |
| 64-разрядное «1С:Предприятие» | Не поддерживается | Полностью |

- «Полностью» — публикация возможна и из конфигуратора, и утилитой `webinst`.
- «Частично» — 32-разрядное приложение можно опубликовать для 64-разрядного **IIS** (только Windows; подробности настройки IIS — ссылка без адреса). `webinst` при этом вызывается из каталога `bin` 32-разрядной версии «1С:Предприятия». **Под Linux такая публикация не поддерживается.**

**Публикация из конфигуратора:** пункт меню «Администрирование — Публикация на веб-сервере…» (рис. 81). Порядок действий:

1. Поле «Имя» — имя виртуального каталога; допустимы **только символы латинского алфавита**.
2. Поле «Веб-сервер» — тип веб-сервера, для которого выполняется публикация.
3. Поле «Каталог» — физический каталог, где будут лежать файлы, описывающие виртуальный каталог. Для Apache имя каталога — **только латинские символы**.
4. По необходимости — флажки «Публиковать доступ для клиентских приложений» и «Публиковать Web-сервисы».
5. Для IIS можно включить аутентификацию на веб-сервере средствами ОС (только Windows).
6. При необходимости выбрать публикуемые Web-сервисы. Колонку «Адрес» можно менять — в ней задаётся синоним Web-сервиса; обращаться к сервису можно и по имени, и по синониму.
7. При необходимости настроить остальные параметры публикации.
8. Кнопка «Опубликовать» запускает публикацию; кнопка «Отключить» удаляет публикацию с выбранного веб-сервера.

**Когда после публикации предлагается перезапустить веб-сервер:**
- изменилась версия «1С:Предприятия»;
- изменился путь к модулю расширения веб-сервера;
- выполнена новая публикация для веб-сервера Apache;
- выполнено отключение публикации.

**Анонимная аутентификация + файловая база.** При публикации проверяется, есть ли у пользователя, от имени которого идёт анонимный доступ, права на каталог информационной базы. Если прав нет — выдаётся предупреждение о невозможности работы с этой базой через веб-сервер. Рекомендация: либо дать права на каталог базы, либо установить флажок «Использовать аутентификацию операционной системы на веб-сервере».

### 8.3.2. Диалог публикации

Назначение диалога — создать публикацию либо подготовить файл-шаблон для публикации утилитой `webinst` (шаблон передаётся параметром командной строки `-descriptor`).

⚠ в источнике неясно: сказано, что редактируемые параметры размещены «на двух закладках», но далее описаны три — «Основные» (с вложенными закладками «Web-сервисы» и «HTTP-сервисы»), «OpenID» и «Прочие».

#### 8.3.2.1. Кнопки диалога

| Кнопка | Действие |
|---|---|
| Опубликовать | Выполняет публикацию: создаёт каталог на диске и настраивает выбранный веб-сервер для работы с «1С:Предприятием». Для IIS — всегда Default Web Site и DefaultAppPool (только Windows) |
| Отключить | Удаляет приложение из веб-сервера и, если нужно, каталог публикации |
| Сохранить | Сохраняет параметры диалога в файл (система спрашивает имя и расположение). Формат файла — как у `default.vrd`. Так создаются файлы-шаблоны для параметра `-descriptor` утилиты `webinst`. В атрибуты `ib` и `base` элемента `point` записываются параметры той информационной базы, из которой выполняется сохранение |
| Загрузить | Загружает для редактирования произвольный файл `default.vrd`. Атрибуты `ib` и `base` элемента `point` загружаемого файла **игнорируются** |
| Закрыть | Закрывает диалог |
| Справка | Открывает справку по диалогу публикации |

**Что делает кнопка «Опубликовать» под ОС Linux** (рис. 82):

| Объект | Действие |
|---|---|
| Каталог, где лежит `default.vrd` | Группой-владельцем назначается группа пользователя, от имени которого работает веб-сервер |
| Файл `default.vrd` | Устанавливается доступ на чтение для группы, включающей пользователя, от имени которого работает веб-сервер |
| Каталог с файлом информационной базы (только файловый вариант) | Группой-владельцем назначается группа пользователя веб-сервера; дополнительно настраивается наследование группы-владельца — чтобы обеспечить работу с базой (подробнее — ссылка без адреса) |

#### 8.3.2.2. Закладка «Основные»

##### 8.3.2.2.1. Общие параметры

| Публиковать дистрибутив тонкого клиента | Возможность получить и установить тонкий клиент, когда версии клиентского приложения и сервера не совпадают | — | каждая строка списка дистрибутивов — атрибут семейства `pubdst*` элемента `point` | Дистрибутив — zip-архив (описание структуры и способы настройки обновления клиента — ссылки без адреса) |

| Наименование прогрессивного веб-приложения | Имя, отображаемое в заголовке прогрессивного веб-приложения при установке и использовании | — | элемент `progressiveWebApplication` | |

**Apache 2.2 или 2.4.** Если система не смогла однозначно определить версию установленного Apache (2.2 или 2.4), в списке «Веб-сервер» будут обе. ##### 8.3.2.2.2. Закладка Web-сервисы

Управление публикацией Web-сервисов (рис. 84).

| Элемент диалога | Назначение | В `default.vrd` |
|---|---|---|
| Флажок «Публиковать Web-сервисы» | Публикуются Web-сервисы, созданные в конфигурации и перечисленные в таблице под флажком | атрибут `enable` элемента `ws` |
| Флажок «Публиковать Web-сервисы по умолчанию» | Разрешает использовать в этой базе Web-сервисы, опубликованные без явного указания разрешения использования | атрибут `pointEnableCommon` элемента `ws` |
| Таблица, 1-я колонка (флажок) | Публикация конкретного Web-сервиса; если флажок снят — сервис запрещён, вызвать его нельзя | атрибут `enable` элемента `point` |
| Таблица, колонка «Имя» | Имя Web-сервиса, как оно задано при создании | атрибут `name` элемента `point` |
| Таблица, колонка «Адрес» | Псевдоним имени публикуемого Web-сервиса; редактируется в окне публикации. Обращаться к сервису можно и по имени, и по псевдониму | атрибут `alias` элемента `point` |
| Флажок «Публиковать Web-сервисы расширений по умолчанию» | Разрешает использовать Web-сервисы, поставляемые в расширениях конфигурации | атрибут `publishExtensionsByDefault` элемента `ws` |

Замечания:
- ⚠ в источнике неясно: сказано, что снятый флажок «Публиковать Web-сервисы» равносилен отсутствию элемента `ws` в `default.vrd` либо наличию элемента `ws` с атрибутом `enable`, установленным в значение `true` (в источнике именно `true`; по смыслу ожидалось бы `false` — сверять с описанием `default.vrd`).
- Web-сервисы из **подключённых расширений** в таблице не показываются; опубликовать их можно только ручным редактированием `default.vrd`.
- Имя `point` в источнике используется и для корневого элемента `default.vrd`, и для описания отдельного Web-сервиса (строка таблицы).

##### 8.3.2.2.3. Закладка HTTP-сервисы

Управление доступом к прикладному решению через HTTP-сервисы (рис. 85).

| Элемент диалога | Назначение | В `default.vrd` |
|---|---|---|
| Флажок «Публиковать HTTP сервисы по умолчанию» | Публикуются HTTP-сервисы, созданные в конфигурации и перечисленные в таблице под флажком | атрибут `publishByDefault` элемента `httpServices` |
| Таблица, 1-я колонка (флажок) | Публикация конкретного HTTP-сервиса; если флажок снят — сервис запрещён, вызвать его нельзя | атрибут `enable` элемента `service` |
| Таблица, колонка «Имя» | Имя HTTP-сервиса, как оно задано при создании | атрибут `name` элемента `service` |
| Флажок «Публиковать HTTP-сервисы расширений по умолчанию» | Разрешает использовать HTTP-сервисы, поставляемые в расширениях конфигурации | атрибут `publishExtensionsByDefault` элемента `httpServices` |

Замечания:
- Снятый флажок «Публиковать HTTP сервисы по умолчанию» равносилен отсутствию элемента `httpServices` в `default.vrd` либо элементу `httpServices` с `publishByDefault`, равным `false`.
- HTTP-сервисы из **подключённых расширений** в таблице не показываются; опубликовать их можно только ручным редактированием `default.vrd`.

#### 8.3.2.3. Закладка «OpenID»

Настройка OpenID-аутентификации для публикации (рис. 86). Фактически на закладке настраивается элемент `openid` файла `default.vrd` (подробное описание — ссылка без адреса).

| Элемент диалога | Назначение |
|---|---|
| Флажок «Использовать OpenID-аутентификацию» | Включает для этой информационной базы возможность OpenID-аутентификации |
| Свойство «Адрес OpenID-провайдера» | Адрес информационной базы, выступающей OpenID-провайдером. Доступ к этой базе — **только по HTTPS** |
| Флажок «Использовать в качестве OpenID-провайдера» | Устанавливается, если публикуемая база сама будет OpenID-провайдером |

#### 8.3.2.4. Закладка «Прочие»

Вспомогательные параметры публикации (рис. 87).

| Элемент диалога | Назначение | В `default.vrd` |
|---|---|---|
| Каталог временных файлов | Каталог временных файлов для работы расширения веб-сервера или файлового варианта информационной базы | атрибут `temp` элемента `point` |
| Группа «Пул соединений» | Параметры пула соединений; они же управляют работой системы отслеживания разрыва соединений (её описание — «в книге», ссылка без адреса) | элемент `pool` |
| Группа «Отладка» | Параметры отладки | элемент `debug` |
| Разделение данных | Таблица разделителей | элемент `zones` (строки — элементы `zone`) |
| Фоновые задания в файловом варианте | Возможность использования фоновых заданий в файловом варианте информационной базы | атрибут `allowexecutescheduledjobs` корневого элемента `point` |

**Таблица разделителей (элемент `zones`):**
- В таблицу попадают все независимые разделители, существующие в конфигурации или в загруженном файле.

| Колонка | Смысл | В `default.vrd` |
|---|---|---|
| 1-я (без имени, флажок) | Нужно ли создавать элемент `zone` для выбранного разделителя | наличие элемента `zone` |
| Имя | Имя разделителя, как оно задано в свойствах общего реквизита | — |
| Следующая (флажок) | Задавать ли значение разделителя в элементе `zone` | — |
| Значение | Используется как значение атрибута `value`, если флажок в предыдущей колонке установлен | атрибут `value` элемента `zone` |
| Указание (флажок) | см. примечание ⚠ ниже | по тексту источника — атрибут `safe` элемента `zone` |
| Безопасное (флажок) | см. примечание ⚠ ниже | по тексту источника — атрибут `specify` элемента `zone` |

- **Сопоставление элементов `zone` с разделителями идёт не по имени, а по порядковому положению в списке.** Если отключается первый разделитель, имеет смысл отключить и все остальные — иначе параметры элемента `zones` будут применены системой к другим разделителям.
- ⚠ в источнике неясно: написано, что флажки в колонках «Указание» и «Безопасное» отвечают за атрибуты `safe` и `specify` «соответственно», то есть буквально «Указание» → `safe`, «Безопасное» → `specify`. По смыслу названий порядок, вероятно, перепутан; сверять с описанием элемента `zone` в `default.vrd`.

### 8.3.3. Утилита webinst

#### 8.3.3.1. Общее описание

- Назначение: настройка веб-серверов для поддержки работы веб-клиента.
- Работает в ОС Windows и Linux.
- Входит в состав дистрибутива системы «1С:Предприятие».
- Описание командной строки — в другом разделе документации (ссылка без адреса; в эту часть не входит).

#### 8.3.3.2. Примеры публикации

**Публикация для IIS 7.0 и старше (только Windows), клиент-серверная база:**

```
webinst -publish -iis -wsdir demo -dir "c:\inetpub\demo" -connstr "Srvr=server:1741;Ref=demo;"
```

| Параметр | Значение в примере |
|---|---|
| `-wsdir demo` | виртуальный каталог `demo` |
| `-dir "c:\inetpub\demo"` | физический каталог, в который отображается виртуальный: `C:\inetpub\demo` |
| `-connstr "Srvr=server:1741;Ref=demo;"` | строка соединения с информационной базой (клиент-серверный вариант) |

**Публикация для Apache 2.2, файловая база (пример с Windows-путями):**

```
webinst -publish -apache22 -wsdir DemoWS -dir "c:\apache.www\demows" -connstr "File=""c:\my db\demows"";" -confpath "C:\Program Files\Apache Software Foundation\Apache2.2\conf\httpd.conf"
```

| Параметр | Значение в примере |
|---|---|
| `-wsdir DemoWS` | виртуальный каталог `DemoWS` (в пояснении источника записан как `demoWS`) |
| `-dir "c:\apache.www\demows"` | физический каталог `C:\apache.www\demows` |
| `-connstr "File=""c:\my db\demows"";"` | строка соединения `File="c:\my db\demows";` (файловый вариант); кавычки внутри значения удваиваются |
| `-confpath "…\Apache2.2\conf\httpd.conf"` | путь к конфигурационному файлу веб-сервера Apache |

**Публикация с файлом-шаблоном:**

```
webinst -publish -iis -wsdir demoMA -dir "c:\inetpub\wwwroot\demoMA" -connstr "Srvr=server:1741;Ref=demo;" -descriptor template.vrd
```

| Параметр | Значение в примере |
|---|---|
| `-publish -iis` | публикация на веб-сервере IIS |
| `-wsdir demoMA` | виртуальный каталог `demoMA` |
| `-dir "c:\inetpub\wwwroot\demoMA"` | физический каталог `c:\inetpub\wwwroot\demoMA` |
| `-connstr "Srvr=server:1741;Ref=demo;"` | строка соединения с информационной базой |
| `-descriptor template.vrd` | остальные параметры публикации берутся из файла-шаблона `template.vrd` |

**Удаление публикации (пример для IIS):**

```
webinst -delete -iis -wsdir DemoWS
```

Указывается только виртуальный каталог (`-wsdir DemoWS`); остальные параметры определяются автоматически по этому имени.

## 8.5. Настройка поддержки Web-сервисов

### 8.5.1. Общая информация

Поддержка Web-сервисов сводится к двум вещам: настройке веб-сервера на работу с Web-сервисами и выдаче прав доступа к каталогам исполняемых файлов и базы данных (последнее — для файлового варианта).

В диалоге публикации: на закладке «Web-сервисы» установить флажок «Публиковать Web-сервисы» и в таблице под ним отметить публикуемые сервисы.

### 8.5.2. Для ОС Linux

#### 8.5.2.1. Общая информация

- Предполагается, что веб-сервер уже установлен.
- В диалоге: закладка «Web-сервисы» → флажок «Публиковать Web-сервисы» → выбрать сервисы в таблице.
- После публикации — те же права, что в 8.4.2.1: пользователю Apache — чтение и выполнение на каталог исполняемых файлов конкретной версии «1С:Предприятия»; для файловой базы — права на модификацию каталога информационной базы пользователю, от имени которого работает веб-сервер.

**Общий порядок публикации Web-сервисов утилитой `webinst` (одинаков для Apache 2.0 / 2.2 / 2.4):**

1. Сначала в конфигураторе создаётся файл-шаблон:
   - в поле «Веб-сервер» указать нужную версию Apache;
   - установить флаг «Публиковать Web-сервисы»;
   - выбрать параметры публикуемых Web-сервисов;
   - при необходимости настроить остальные параметры на вкладке «Прочие»;
   - кнопкой «Сохранить» записать файл-шаблон (в примерах — `apache-template.vrd`).

webinst -publish -apache24 -wsdir demo-ws -dir "c:\inetpub\demo-ws" -connstr "Srvr=server:1741;Ref=demo;" -descriptor apache-template.vrd

## 8.6. Настройка поддержки стандартного интерфейса OData

### 8.6.1. Общая информация

Поддержка стандартного интерфейса OData сводится к настройке веб-сервера и выдаче прав доступа к каталогам исполняемых файлов и базы данных (последнее — для файлового варианта).

В диалоге публикации: на закладке «Основные» установить флажок «Публиковать стандартный интерфейс OData» (в `default.vrd` — атрибут `enableStandardOData` элемента `point`, см. 8.3.2.2.1).

### 8.6.2. Для ОС Linux

#### 8.6.2.1. Общая информация

- Предполагается, что веб-сервер уже установлен.
- После публикации — те же права, что в 8.4.2.1: пользователю Apache — чтение и выполнение на каталог исполняемых файлов конкретной версии «1С:Предприятия»; для файловой базы — права на модификацию каталога информационной базы пользователю, от имени которого работает веб-сервер.

**Общий порядок публикации OData утилитой `webinst` (одинаков для Apache 2.0 / 2.2 / 2.4):**

1. Сначала создаётся файл-шаблон в диалоге публикации:
   - в поле «Веб-сервер» указать нужную версию Apache;
   - установить флаг «Публиковать стандартный интерфейс OData»;
   - при необходимости настроить остальные параметры на вкладке «Прочие»;
   - кнопкой «Сохранить» записать файл-шаблон (в примерах — `apache-template.vrd`).
2. Затем выполняется публикация с этим шаблоном (параметр `-descriptor`).

#### 8.6.2.2. Apache версии 2.0

- **8.6.2.2.1. Диалог публикации.** «Веб-сервер» = `Apache 2.0`; остальное — при необходимости на вкладке «Прочие».
- **8.6.2.2.2. Утилита webinst.** Шаблон создаётся с «Веб-сервер» = `Apache 2.0`, затем:

```
webinst -publish -apache2 -wsdir demo-ws -dir /var/www/demo-ws -connstr "Srvr=server:1741;Ref=demo;" -confpath /etc/apache2/httd.conf -descriptor apache-template.vrd
```

#### 8.6.2.3. Apache версии 2.2

- **8.6.2.3.1. Диалог публикации.** «Веб-сервер» = `Apache 2.2`; остальное — при необходимости на вкладке «Прочие».
- **8.6.2.3.2. Утилита webinst.** Шаблон создаётся с «Веб-сервер» = `Apache 2.2`, затем:

```
webinst -publish -apache22 -wsdir demo-ws -dir /var/www/demo-ws -connstr "Srvr=server:1741;Ref=demo;" -confpath /etc/apache2/httd.conf -descriptor apache-template.vrd
```

#### 8.6.2.4. Apache версии 2.4

- **8.6.2.4.1. Диалог публикации.** «Веб-сервер» = `Apache 2.4`; остальное — при необходимости на вкладке «Прочие».
- **8.6.2.4.2. Утилита webinst.** Шаблон создаётся с «Веб-сервер» = `Apache 2.4`, затем (без `-confpath`):

Команды в 8.6.2.2–8.6.2.4 в источнике совпадают с командами из 8.5.2.2–8.5.2.4, включая имя виртуального каталога `demo-ws`; различается только содержимое файла-шаблона.

### 8.6.3. Для ОС Windows

Только Windows — кратко.

#### 8.6.3.1. Общая информация

## Что важно администратору Linux

1. **Под Linux публикация возможна только для Apache.** Ключи `webinst`: `-apache2` (2.0), `-apache22` (2.2), `-apache24` (2.4). Версию нужно указывать верно: для 2.2 и 2.4 в конфигурационный файл вносятся разные изменения, ошибка делает публикацию неработоспособной.
2. **Публиковать нужно с правами root** (`su`) или через `sudo`. При нехватке привилегий `webinst` лишь выводит диагностическое сообщение и продолжает публикацию (конфигуратор в той же ситуации спрашивает, продолжать ли).
3. **Версия `webinst`/конфигуратора должна точно совпадать с версией работающего сервера «1С:Предприятия»**, а сама платформа должна быть установлена на том же компьютере, что и веб-сервер.
4. **Разрядность расширения веб-сервера должна совпадать с разрядностью веб-сервера.** Вариант «32-разрядная платформа + 64-разрядный веб-сервер» под Linux не поддерживается (он есть только для IIS).
5. **Рекомендуемый MPM под Linux — `worker`**; другие модули мультипроцессной обработки не рекомендуются.
6. **Права после публикации:** пользователю Apache — чтение и выполнение на каталог исполняемых файлов конкретной версии платформы; для файловой базы — модификация каталога информационной базы. Сама публикация под Linux назначает группу пользователя веб-сервера владельцем каталога с `default.vrd`, даёт группе чтение `default.vrd`, а для файловой базы — назначает ту же группу на каталог базы и настраивает наследование группы-владельца.
7. **Файловая база через веб-сервер:** запросы к публикации исполняются последовательно; рекомендуется не более одного рабочего процесса веб-сервера на публикацию (из-за особенностей получения результатов фоновых заданий).
8. **Несколько версий платформы на одном хосте** — отдельный экземпляр Apache на каждую версию, и публикация только вручную.
9. **Имя виртуального каталога и (для Apache) физический каталог — только латиница**; физический каталог должен существовать заранее.
10. **Web-сервисы, OData и HTTP-сервисы утилитой `webinst` публикуются через файл-шаблон**: он сохраняется из диалога публикации конфигуратора кнопкой «Сохранить» и передаётся ключом `-descriptor`. Сервисы из расширений конфигурации в таблицах диалога не видны — отдельные такие сервисы публикуются только ручной правкой `default.vrd`; кроме того, есть флажки «Публиковать … расширений по умолчанию» (атрибут `publishExtensionsByDefault` элементов `ws` и `httpServices`).
11. **Перезапуск веб-сервера** после публикации предлагается в четырёх случаях: сменилась версия платформы, изменился путь к модулю расширения веб-сервера, выполнена новая публикация для Apache, публикация отключена.
12. **Адреса:** веб-клиент — `<хост>/<каталог>`, Web-сервисы — `<хост>/<каталог>/ws/<имя или адрес>`, HTTP-сервисы — `<хост>/<каталог>/hs/<путь к ресурсу>`.
13. **HTTPS:** для промышленной базы, доступной из Интернета, HTTP не рекомендуется; информационная база — OpenID-провайдер доступна только по HTTPS. Включение HTTPS описано в документации веб-сервера, а не здесь.
14. **Пути `-confpath` в Linux-примерах (`/etc/apache2/httd.conf`, `/etc/apache2/apache.conf`) условные** — подставлять реальный конфигурационный файл своего Apache; в примерах для Apache 2.4 `-confpath` не указан вовсе.
15. **Разделители в `default.vrd` (элементы `zone`) сопоставляются по порядку, а не по имени** — отключив первый, отключайте и остальные.
