## 5.1. Общая информация

- Список ИБ ведётся в окне «Запуск 1С:Предприятия»: добавление баз и групп, перенос базы из группы в группу, правка свойств, удаление из списка.
- Два представления списка: плоский список (по умолчанию) и дерево. Переключение — в диалоге настройки запуска (раздел 5.7).

## 5.2. Добавление информационной базы

### 5.2.1. Добавление новой информационной базы

#### 5.2.1.1. Общая информация

Кнопка «Добавить…» открывает выбор режима добавления. В режиме «Создание новой информационной базы» доступны два способа: из шаблона (выбирается в списке шаблонов) либо пустая база.

Какая версия платформы фактически создаёт базу из шаблона:

| Кто создаёт | Какая версия используется |
|---|---|
| Толстый клиент | Тот экземпляр толстого клиента, который сейчас запущен |
| Интерактивная программа запуска | По убыванию приоритета: 1) версия с наибольшим номером из параметра `AppVersion` файла манифеста шаблона; 2) версия из параметра `DefaultVersion` файла `1cestart.cfg`; 3) самая свежая версия платформы, установленная на компьютере |

Следующий шаг мастера — название ИБ и тип её расположения.

Наименование ИБ (строка в списке):

- произвольная строка, не длиннее 255 символов;
- должно быть уникальным в пределах всего списка ИБ;
- разрешено завести несколько записей с одной и той же строкой соединения — чтобы ходить в одну базу разными клиентами, не меняя свойства самой ИБ.

#### 5.2.1.2. Создание в файловом варианте

- Выбирается файловый тип расположения (рис. 38), затем каталог базы. Несуществующий каталог будет создан автоматически при запуске «1С:Предприятия».
- Имя каталога ИБ обязано соответствовать RFC 2396, раздел 2.4.3 «Excluded US-ASCII Characters» (https://datatracker.ietf.org/doc/html/rfc2396.html). Запрещённые символы:

```
< > # % " { } [ ] | \ ^ `
```

Кроме них запрещены символы с кодами 0–31 и 127.

- Поле «Язык» (для пустой базы) задаёт язык, по правилам которого данные хранятся и сортируются. При создании из шаблона поле может не показываться.
- После «Далее >» открывается страница параметров запуска (раздел 5.2.3).
- Если создана пустая ИБ и в каталоге нет файлов конфигурации, то при запуске в режиме «1С:Предприятие» окно выбора режима создания базы появится повторно; выбор шаблона на этом шаге создаст базу по шаблону.
- Формат файла базы данных:

| Что | Значение |
|---|---|
| Возможные форматы | формат версии 8.2.14 и формат версии 8.3.8 |
| По умолчанию | формат версии 8.3.8 |
| Как сменить формат по умолчанию | через файл `conf.cfg` |
| Преобразование `1Cv8.1CD` между форматами | утилита `cnvdbfl` |

#### 5.2.1.3. Создание в клиент-серверном варианте

##### 5.2.1.3.1. Общая информация

Клиент-серверная ИБ определяется парой «адрес кластера серверов + имя ИБ».

| Параметр | Правила |
|---|---|
| Адрес кластера | Имя центрального сервера и сетевой порт менеджера кластера, например `Test_Server:1541`. Если менеджер кластера слушает порт по умолчанию (1541), достаточно одного имени сервера |
| Имя ИБ | Уникально в пределах кластера. Регистронезависимо — в том числе для сервисных операций (пример из документации: требования назначения функциональности) |
| Несколько центральных серверов | В поле «Кластер серверов 1С:Предприятия» можно перечислить их списком в формате `Server1,Server2:Port,Server3`. Пробелы в списке недопустимы. Такая запись удобна, в частности, для списков общих ИБ |
| Имя базы данных в СУБД | Должно соответствовать RFC 2396, раздел 2.4.3: нельзя `< > # % " { } [ ] \| \ ^` и обратный апостроф, а также символы с кодами 0–31 и 127. Конкретная СУБД может дополнительно ужесточать требования |

Набор полей формы создания зависит от выбранной СУБД — ниже по каждой СУБД отдельно.

Сводка требований к имени базы данных и пользователю по СУБД (детали — в подразделах):

| СУБД | Формат поля «Сервер баз данных» | Первый символ имени БД | Остальные символы | Макс. длина имени БД | Пользователь БД |
|---|---|---|---|---|---|
| Microsoft SQL Server | имя компьютера или `Server/instance`; префикс `lpc:` для SHARED MEMORY | латинская буква или `_` | латинские буквы, цифры, `_`, `$` | 63 | `sa` либо владелец БД (+ права, см. ниже) |
| PostgreSQL | имя экземпляра; нестандартный порт — `<имя_экземпляра> port=<номер_порта>;` | буква Юникода 3.2 или `_` | буквы Юникода 3.2, `_`, `$` | 63 | `SUPERUSER` только на момент создания ИБ |
| IBM Db2 | имя экземпляра; `computer/db2name` | латинская буква | латинские буквы, цифры | 8 | `CREATEDB` или `SUPERUSER` либо собственник БД; имя пользователя не длиннее 8 символов |
| Oracle Database | TNS-name, например `//имя_сервера_БД/имя_сервиса` | латинская буква | английские буквы, цифры, `_` | 30 | DBA либо владелец готовой схемы с набором прав |

Для MS SQL Server и PostgreSQL дополнительно: в имени БД нельзя пробелы, имя не может совпадать с зарезервированным словом языка запросов сервера баз данных.

##### 5.2.1.3.2. Microsoft SQL Server

Не PostgreSQL — приведено справочно, но полностью.

| Поле | Содержание |
|---|---|
| Тип СУБД | Microsoft SQL Server |
| Сервер баз данных | Имя компьютера (если экземпляр один) либо имя конкретного экземпляра (если их несколько), пример: `Server/instance` |
| Протокол SHARED MEMORY | Если сервер «1С:Предприятия» и MS SQL Server стоят на одном компьютере и для MS SQL установлен Native Client, перед именем сервера ставится префикс `lpc:` — получится `lpc:Server/instance` |
| Имя базы данных | Первый символ — латинская буква или `_`; далее латинские буквы, цифры, `_`, `$`. До 63 символов, без пробелов, не зарезервированное слово |
| Пользователь базы данных | Должен быть администратором сервера БД (`sa`) либо владельцем базы (если она уже есть) — чтобы свободно менять структуру БД. Для владельца дополнительно нужны: чтение базы `master`, полный доступ к `tempdb`. Кроме того, пользователь должен входить в фиксированную серверную роль `processadmin` или `sysadmin` |
| Пользователь и пароль не указаны | Кластер подключается к СУБД с аутентификацией ОС — под учётной записью, от имени которой работает конкретный рабочий процесс (`rphost`), обращающийся к СУБД |
| Пароль пользователя | Пароль учётной записи, под которой идёт доступ к БД |
| Смещение дат | `0` или `2000`. Число лет, прибавляемое к датам при записи в MS SQL и вычитаемое при чтении. Причина: тип `DATETIME` хранит даты только с 1 января 1753 года по 31 декабря 9999 года. Нужны даты раньше нижней границы — ставить `2000`, иначе допустим `0`. После создания ИБ значение изменить нельзя |

Важные оговорки:

- MS SQL Server 2014: платформа требует `TRACE FLAG 4199` для используемой базы. Если флаг не установлен на всю базу, платформа пытается выставлять его для каждого соединения от имени пользователя из поля «Пользователь базы данных»; при нехватке прав — ошибка. Выход: указать пользователя с правами администратора сервера БД (`sa`) либо отдельно установить `TRACE FLAG 4199` для базы.
- Если в прикладном решении есть регистры накопления или регистры бухгалтерии, смещение дат обязано быть `2000`. Если база создана со смещением `0`: выгрузить ИБ в файл, заново создать базу данных со смещением `2000`, загрузить ИБ из файла.

##### 5.2.1.3.3. PostgreSQL

| Поле | Содержание |
|---|---|
| Тип СУБД | PostgreSQL (в источнике опечатка — «PostrgeSQL») |
| Сервер баз данных | Имя экземпляра сервера. Сетевой порт, отличный от порта по умолчанию, задаётся через ключевое слово `port` в формате `<имя_экземпляра> port=<номер_порта>;` |
| Имя базы данных | Первый символ — буква стандарта Юникод 3.2 или `_`. Далее — буквы Юникода 3.2, а также `_` и `$`. До 63 символов. Пробелы запрещены. Не может быть зарезервированным словом языка запросов сервера БД |
| Пользователь базы данных | Учётная запись сервера БД, под которой идёт доступ к базе. Привилегия `SUPERUSER` нужна только в момент создания ИБ; после успешного создания её можно отозвать |

Пример строки сервера с нестандартным портом (из документации):

```
localhost port=6432;
```

Отзыв `SUPERUSER` после создания ИБ (пример для пользователя `dbuser`):

```sql
alter user dbuser with nosuperuser;
```

Замечания:

- ⚠ в источнике неясно: в перечне допустимых «последующих» символов имени базы PostgreSQL цифры не названы (для MS SQL Server они названы явно). Конспект передаёт формулировку источника как есть.
- Общие для всех СУБД ограничения RFC 2396 (раздел 5.2.1.3.1) действуют и здесь.
- Поля «Пароль пользователя», «Создать базу данных в случае ее отсутствия», «Язык (Страна)», блокировка регламентных заданий — см. 5.2.1.3.6.

##### 5.2.1.3.4. IBM Db2

Не PostgreSQL — приведено справочно.

| Поле | Содержание |
|---|---|
| Тип СУБД | IBM Db2 |
| Сервер баз данных | Имя экземпляра сервера. Если на компьютере есть экземпляры, отличные от установленного по умолчанию, через слеш добавляется имя экземпляра IBM Db2, заданное при установке: `computer/db2name` |
| Имя базы данных | Уникально в пределах того расположения, где база занесена в каталог: в Db2 для Linux это каталог, в Windows — логический диск. Начинается с латинской буквы, далее латинские буквы и цифры. Не длиннее 8 символов |
| Пользователь базы данных | Должен иметь привилегию `CREATEDB` или `SUPERUSER` либо быть собственником базы (если она уже существует). Имя пользователя — не длиннее 8 символов |

##### 5.2.1.3.5. Oracle Database

Не PostgreSQL — приведено справочно.

| Поле | Содержание |
|---|---|
| Тип СУБД | Oracle Database |
| Сервер баз данных | Указывается TNS-name. Типовая запись: `//имя_сервера_БД/имя_сервиса` (допустимы и другие формы TNS-name) |
| Имя базы данных | «База данных» в терминах 1С = схема данных в терминах Oracle. При создании ИБ в Oracle создаются пользователь и его схема. Имя схемы: только английские буквы, цифры и `_`; начинается с латинской буквы; не длиннее 30 символов |
| Пользователь базы данных | Если схему создаёт сама система — пользователь с правами DBA (например, `SYSTEM`); начиная с Oracle версии 12.2 этому пользователю нужно выдать привилегии `CREATE ANY TABLE` и `EXECUTE ANY PROCEDURE`. Если схема уже создана администратором Oracle — можно указать другого пользователя, в том числе владельца этой схемы (тогда «Имя базы данных» и «Пользователь базы данных» совпадают) |

Права при работе с уже существующей схемой (пользователь без DBA):

| Вариант | Что выдать |
|---|---|
| Отдельные права | `CREATE SESSION`, `CREATE PROCEDURE`, `CREATE TRIGGER`, `CREATE SEQUENCE`, `CREATE TABLE` |
| Вместо отдельных прав — роли | `CONNECT`, `RESOURCE` |
| Если сеансы будут завершать из консоли управления кластером серверов | дополнительно `ALTER SYSTEM` |
| Квоты на табличные пространства | `V81C_DATA`, `V81C_INDEX`, `V81C_LOB`, `V81C_INDEX_BIG` (последнее — если существует) |

Пример выдачи прав из документации (приведён как в источнике):

```sql
create user <username> identified "<password>";
grant create session to <username>;
grant create table to <username>;
grant create trigger to <username>;
grant create sequence to <username>;
grant create procedure to <username>;
grant alter system to <username>;
alter user <username> quota UNLIMITED on v81c_data;
alter user <username> quota UNLIMITED on v81c_index;
alter user <username> quota UNLIMITED on v81c_lob;
```

⚠ в источнике неясно: первая строка примера записана без ключевого слова `by` (`identified "<password>"`), тогда как в примере смены пароля ниже используется `IDENTIFIED BY`. Квота на `v81c_index_big` в примере не задаётся, хотя в тексте это табличное пространство упомянуто.

Срок действия пароля:

- В Oracle Database версии 11 с настройками по умолчанию пароль действует 180 дней. По истечении срока возможна ошибка вида «Сервер баз данных не обнаружен. Ошибка СУБД: ORA-28002: дата действия пароля истечет в течение 7 дней».
- Лечение средствами СУБД: запустить SQL*Plus, подключиться к базе, выполнить

```sql
ALTER USER <ИмяПользователя> IDENTIFIED BY <Пароль>
```

- Сервер «1С:Предприятия» хранит пароль в файле настроек и продолжит подключаться со старым паролем. Поэтому проще в `ALTER USER` указать прежний пароль — фактически пароль при этом не меняется.
- Как отключить срок действия пароля — документация отсылает к документации Oracle нужной версии.

##### 5.2.1.3.6. Общие параметры

Поля формы создания (рис. 41), не зависящие от конкретной СУБД:

| Поле / флажок | Назначение | Поведение |
|---|---|---|
| Пароль пользователя | Пароль учётной записи из поля «Пользователь базы данных» | — |
| Создать базу данных в случае ее отсутствия | Разрешает создание БД на сервере СУБД | Установлен: если базы с указанным именем на сервере БД нет, она создаётся. Снят: попыток создать базу не будет |
| Язык (Страна) | Набор национальных настроек для работы с ИБ; выбирается из списка | Позже можно изменить в конфигураторе. Не показывается при создании из шаблона, содержащего файл выгрузки ИБ (`*.dt`), — язык уже записан в выгрузке |
| Установить блокировку регламентных заданий | Запрет выполнения регламентных заданий в создаваемой ИБ | Установлен: регламентные задания запрещены. Снят: при подключении базы к серверу имеющиеся регламентные задания запускаются сразу |
| Запретить локальное распознавание речи | Отключает локальное распознавание речи в клиент-серверной ИБ | — |

##### 5.2.1.3.7. Создание базы данных

Порядок действий платформы при корректно заполненных параметрах:

1. Попытка соединиться с указанной базой данных на указанном сервере БД под указанным пользователем.
2. Если базы нет и флажок «Создать базу данных в случае ее отсутствия» установлен — попытка создать базу.
3. Если в базе данных уже есть информационная база «1С:Предприятия» — устанавливается связь с ней. Если нет — инициализируется новая ИБ; указанный при создании шаблон применяется на этапе инициализации.

Особенность Oracle Database: при создании ИБ создаётся пользователь, пароль которого совпадает с именем пользователя; при создании его учётная запись блокируется. Сервер «1С:Предприятия» при соединении с Oracle использует имя и пароль, заданные при создании ИБ.

Далее — страница параметров запуска (раздел 5.2.3).

##### 5.2.1.3.8. Одновременное использование одной базы данных несколькими информационными базами

- Платформа программно не запрещает указать одну и ту же базу данных в нескольких ИБ на сервере «1С:Предприятия».
- Но служебные данные кластера устроены по принципу «одна база данных — один набор служебных данных». Несколько наборов служебных данных поверх одной БД нарушают их логическую целостность.

Что перестаёт работать, если одну БД одновременно используют несколько ИБ:

- блокировка информационной базы (в частности, запуск двух конфигураторов может разрушить конфигурацию);
- блокировка объектов;
- менеджер управляемых блокировок;
- получение оперативной отметки времени;
- прочие механизмы, опирающиеся на разделяемые данные, которые хранит менеджер кластера.

Последствия:

- параллельное изменение данных может привести к их необратимому разрушению;
- даже чтение может оказаться недостоверным в обеих ИБ, если хотя бы одна из них изменяла данные или ставила любые блокировки.

Вывод документации: в штатной эксплуатации так делать не следует. Допустимо лишь в исключительных случаях — для отладки конфигураций и расследования ошибок конфигураций и платформы — с пониманием перечисленных ограничений.

### 5.2.2. Добавление существующей информационной базы

#### 5.2.2.1. Общая информация

- В режиме добавления существующей ИБ в список можно внести базу: на локальном компьютере, в локальной сети, на сервере «1С:Предприятия» или на веб-сервере (последнее — только для тонкого клиента и веб-клиента).
- После «Далее >» — диалог с наименованием, типом расположения и параметрами доступа. Наименование — произвольная строка до 255 символов.
- Автозаполнение из буфера обмена: если в буфере лежит путь к каталогу ИБ (для файлового варианта — без кавычек) или URL доступа через веб-сервер, при открытии диалога система пытается сама определить тип расположения. При успехе переключатель «Выберите тип расположения информационной базы» выставляется автоматически и заполняются реквизиты базы. То же происходит, если вставить содержимое буфера в поле с именем ИБ и нажать Tab.

#### 5.2.2.2. Файловый вариант

- Тип расположения: «На данном компьютере или на компьютере в локальной сети».
- Указывается каталог ИБ; несуществующий каталог будет создан автоматически при запуске «1С:Предприятия».
- Ограничение на имя каталога то же, что в 5.2.1.2: RFC 2396, раздел 2.4.3; запрещены `< > # % " { } [ ] | \ ^`, обратный апостроф, символы с кодами 0–31 и 127.
- Далее — страница параметров запуска (5.2.3).

#### 5.2.2.3. Клиент-серверный вариант

Тип расположения: «На сервере 1С:Предприятия». Заполняются:

| Поле | Содержание |
|---|---|
| Кластер серверов 1С:Предприятия | Адрес кластера = адрес центрального сервера кластера с номером сетевого порта процесса менеджера кластера (по умолчанию 1541) |
| Имя информационной базы | Имя ИБ в кластере |

Примечания документации:

1. Если адрес центрального сервера задан IP-адресом в точечной нотации, его наличие в DNS (`hosts`) не требуется.
2. Для кластера с несколькими центральными серверами список задаётся прямо в поле «Кластер серверов 1С:Предприятия» в формате `Server1,Server2:Port,Server3` — без пробелов. Удобно, в частности, для списков общих ИБ.
3. Имя базы данных СУБД должно соответствовать RFC 2396, раздел 2.4.3 (тот же набор запрещённых символов и кодов 0–31, 127); конкретная СУБД может уточнять требования.

Поведение:

- При добавлении не проверяется, существует ли ИБ с такими параметрами.
- Если при запуске конфигуратора база с указанными параметрами не найдена, выводится сообщение и вопрос о создании новой ИБ. При согласии конфигуратор открывает форму «Создание информационной базы/группы» (рис. 46), в которую вносятся параметры создания новой ИБ.
- Далее — страница параметров запуска (5.2.3).

#### 5.2.2.4. База, расположенная на веб-сервере

- Добавлять такую базу нужно из тонкого клиента «1С:Предприятия» (файл `1cv8c`).
- Тип расположения: «На веб-сервере»; заполняется строка «Адрес информационной базы».
- Гиперссылка «Дополнительно…» под адресом открывает дополнительные параметры подключения к веб-серверу: работа с прокси-сервером и способ аутентификации пользователя веб-сервера.

| Параметр | Значения / формат | Смысл |
|---|---|---|
| Выберите способ аутентификации пользователя веб-сервера | «Выбирать автоматически» | Сначала попытка аутентификации на веб-сервере средствами ОС; при неудаче — явный запрос логина и пароля |
| | «Запрашивать имя и пароль» | Логин и пароль для веб-сервера запрашиваются всегда |
| Адрес управления разработкой | `host:port` | Адрес сервера, через который могут выполняться административные команды: адрес конфигуратора в режиме агента либо адрес автономного сервера, обслуживающего опубликованную базу |

Смежные темы, на которые ссылается раздел: конфигуратор в режиме агента; автономный сервер. Далее — страница параметров запуска (5.2.3).

### 5.2.3. Параметры запуска информационной базы

Страница мастера (рис. 49), общая для всех вариантов расположения ИБ.

| Параметр | Значение | Что означает |
|---|---|---|
| Вариант аутентификации | «Выбирать автоматически» | Сначала попытка аутентификации средствами ОС; при неудаче — запрос логина и пароля для доступа к ИБ |
| | «Запрашивать имя и пароль» | Всегда показывается окно ввода логина и пароля |
| Скорость соединения | «Выбирать при запуске» | Скорость выбирается при каждом запуске флажком «Низкая скорость соединения» внизу окна «Запуск 1С:Предприятия» |
| | «Обычная» | Обычная скорость, работа без особенностей |
| | «Низкая» | Низкая скорость соединения; работа платформы идёт с особенностями, описанными в «Руководстве разработчика» |
| Дополнительные параметры запуска | строка | Параметры командной строки, которые передаются исполняемому файлу. Справка по ним — во встроенной справке, раздел «Запуск 1С:Предприятие 8 и параметры запуска» |
| Основной режим запуска | «Выбирать автоматически» | Вид клиента определяется свойством конфигурации «Основной режим запуска» и свойством пользователя «Режим запуска» |
| | «Тонкий клиент» | Запуск тонким клиентом |
| | «Веб-клиент» | Запуск веб-клиентом; доступно только при доступе к ИБ через веб-сервер |
| | «Толстый клиент» | Запуск толстым клиентом; недоступно при доступе к ИБ через веб-сервер |
| Версия 1С:Предприятия | номер версии | Конкретная версия платформы для работы с этой ИБ. Допустимы также значения `8.1` и `8.0` — тогда используется установленная на компьютере версия 8.1 или 8.0; уточнять конкретный номер в этом случае бессмысленно |
| Разрядность | — | Разрядность клиентского приложения для этой ИБ. Поле доступно, только когда свойства ИБ редактируются под 64-разрядной ОС Windows (только Windows) |

Уточнения:

- Если в свойствах ИБ скорость задана явно («Обычная» или «Низкая»), флажок «Низкая скорость соединения» в окне запуска недоступен для изменения и лишь отражает значение из свойств базы.

- Параметры командной строки `L` и `VL`, записанные в поле «Дополнительные параметры запуска», действуют только при запуске ИБ через интерактивную программу запуска.

### 5.2.4. Параметры настройки сертификатов

Когда появляется: добавляется ИБ на веб-сервере (5.2.2.4) и в поле «Адрес информационной базы» указан протокол HTTPS — например, `https://localhost/DemoMA` вместо `http://localhost/DemoMA`. Тогда по кнопке «Дополнительно…» кроме параметров доступа к веб-серверу доступна страница настройки сертификатов (рис. 50 в документации показан для ОС Windows).

Группа «Выберите клиентский сертификат» — откуда брать клиентский сертификат:

| Вариант | Смысл |
|---|---|
| Не предоставлять сертификат | Соединение возможно только с веб-серверами, не требующими клиентского сертификата |
| Файл сертификата | Выбирается файл с клиентским сертификатом и его закрытым ключом. Если файл защищён паролем, пароль запрашивается у пользователя при установлении соединения |
| Сертификат Windows / Сертификат Linux / Сертификат macOS | Сертификат берётся из системного хранилища сертификатов ОС (Windows, macOS) либо из специального каталога в ОС Linux |

Если подходящих клиентских сертификатов в системе несколько (для варианта «Сертификат Windows / Linux / macOS»):

| Режим выбора | Поведение |
|---|---|
| Выбирать, используя ранее выбранный | Пользователь выбирает сертификат в системном диалоге; далее выбранный сертификат применяется автоматически |
| Выбирать всегда | Системный диалог выбора показывается независимо от того, выбирался ли сертификат раньше. Сделанный выбор потом может использоваться автоматически режимом «Выбирать, используя ранее выбранный» |
| Подбирать автоматически | Берётся произвольный сертификат, подходящий для соединения; диалог выбора не показывается |

Группа «Выберите способ проверки сертификатов сервера» — как проверять сертификат, предъявленный веб-сервером:

| Вариант | Смысл |
|---|---|
| Не проверять сертификат сервера | Сертификат веб-сервера не проверяется; сертификаты удостоверяющих центров (УЦ) не используются |
| Файл сертификатов CA | Выбирается файл с сертификатами УЦ. Если файл защищён паролем, пароль запрашивается при установлении соединения |
| Хранилище сертификатов Windows / Хранилище сертификатов Linux / Хранилище сертификатов macOS | Сертификаты УЦ берутся из системного хранилища сертификатов ОС (Windows, macOS) либо из специального каталога в ОС Linux |

Смежные темы, на которые ссылается раздел: использование сертификатов; самоподписанные сертификаты. Путь «специального каталога в ОС Linux» в этой главе не назван.

## 5.3. Редактирование информационной базы

Чтобы исправить имя или каталог ИБ: выбрать базу в списке и нажать «Изменить». Открывается диалог, аналогичный диалогу добавления существующей ИБ (5.2.2).

## 5.4. Удаление информационной базы из списка

- Выбрать базу в списке и нажать «Удалить» — запись исчезает из списка.
- Удаляется только запись списка. Каталог файловой базы на диске и база на сервере «1С:Предприятия» остаются на месте; удалять их нужно самостоятельно.
- Вместе с записью удаляются служебные каталоги этой ИБ, лежащие в:

| ОС | Каталоги |
|---|---|
| Windows | `%APPDATA%\1C\1cv8` и `%LOCALAPPDATA%\1C\1cv8` |
| Linux | `~/.1cv8/1C/1cv8` |
| macOS | `~/.1cv8/1C/1cv8` |

## 5.5. Порядок информационных баз в списке

Ручное изменение порядка возможно, только если в настройках диалога запуска не включена сортировка по наименованию.

| Способ | Как |
|---|---|
| Мышь | Перетаскивание строки левой кнопкой; при перемещении показывается контур будущего места |
| «Переместить вверх» | Контекстное меню или Ctrl + Shift + Стрелка вверх |
| «Переместить вниз» | Контекстное меню или Ctrl + Shift + Стрелка вниз |
| «Сортировать по возрастанию» / «Сортировать по убыванию» | Команды, упорядочивающие список соответствующим образом |

- Команды перемещения закольцованы: с первой позиции строка уходит в конец списка, с последней — в начало.
- В режиме дерева: если контур указывает на группу, строка попадает в конец списка этой группы; чтобы поставить базу или группу в конкретную позицию внутри группы, группу нужно заранее раскрыть.

## 5.6. Ведение иерархического списка информационных баз

Раздел о списке, отображаемом деревом.

### 5.6.1. Добавление группы информационных баз

- Группы полезны, когда на рабочем месте несколько однотипных баз или баз так много, что нужную трудно найти.
- Создание групп доступно, только если в настройке диалога запуска включён режим «Отображать в виде дерева».
- В дереве всегда есть корневая группа «Информационные базы»; её нельзя ни изменить, ни удалить.
- Порядок: выбрать группу-родителя (строку группы или любую строку базы из этой группы) → «Добавить» → режим «Создание новой группы» → «Далее >» → ввести наименование → «Готово».
- В наименовании группы запрещён символ `/`.
- Новая группа помещается в выбранную группу — в конец её списка, если не включена сортировка по наименованию.

### 5.6.2. Редактирование группы информационных баз

Выбрать строку группы → «Изменить» → окно «Редактирование группы» с текущим названием → ввести новое наименование (символ `/` запрещён) → «Готово».

### 5.6.3. Удаление группы информационных баз

Выбрать группу → «Удалить». Внимание: вместе с группой из списка удаляются все входящие в неё информационные базы.

## 5.7. Настройка окна запуска

Кнопка «Настройка» в диалоге запуска открывает диалог настройки (рис. 54). Состав полей зависит от того, откуда он вызван:

| Откуда вызвана настройка | Чего нет в диалоге |
|---|---|
| Интерактивная программа запуска | Полный набор полей |

| Тонкий клиент (`1cv8c`) | Нет полей «Используемые версии» и «Каталоги шаблонов конфигураций и обновлений» |

Параметры диалога:

| Параметр | Назначение | Связанный параметр конфигурационного файла / примечание |
|---|---|---|
| Отображать в виде дерева | Список ИБ показывается деревом | — |
| Сортировать по наименованию | Сортировка по наименованиям внутри каждой группы | — |
| Показывать последние выбранные информационные базы | Включает список последних выбранных баз | — |
| Запоминать последние выбранные | Количество последних вызванных баз в этом списке | — |
| Каталоги шаблонов конфигураций и обновлений | Перечень каталогов с шаблонами конфигураций и обновлений (например, общефирменный и локальный) | Поле недоступно в тонком клиенте. Колонка «Разрядность» задаёт разрядность запускаемого клиентского приложения | Только в интерактивной программе запуска. Предположительно `DefaultVersion` — ⚠ в источнике неясно: прямо соответствие поля и параметра в главе не названо |

Список последних выбранных баз:

- показывается в верхней части общего списка, наименования выделены полужирным;
- порядок — по времени выбора: наверху база, выбранная последней; включённая сортировка на этот порядок не влияет;

Пример строки сопоставления в поле «Используемые версии»:

```

```

При таком сопоставлении база, в свойствах которой указана версия `8.3`, запускается версией 8.3.24.100, а не версией с максимально доступным номером.

Откуда берётся итоговый список баз при запуске:

1. Основной список ИБ.
2. Базы из списков общих ИБ (поле «Адреса Интернет-сервисов и списки общих информационных баз»).
3. Если в локальном конфигурационном файле задан параметр `CommonCfgLocation` — базы из параметров `CommonInfoBases` (если заданы) общего конфигурационного файла `1cescmn.cfg`.
4. Базы, полученные через Интернет-сервисы получения списка общих ИБ.

Что видно в диалоге и что куда записывается:

- Пути к каталогам шаблонов и к спискам общих ИБ показываются в окне настройки, только если заданы параметрами локального конфигурационного файла `1cestart.cfg`. Заданные в общем файле `1cescmn.cfg` — в диалоге не отображаются.
- При настройке диалога запуска параметры `CommonInfoBases`, `ConfigurationTemplatesLocation`, `DefaultVersion`, `UseHwLicenses` меняются только в локальном конфигурационном файле того пользователя, от имени которого выполняется настройка.

Диалог автоматического удаления версий (рис. 55):

| Элемент | Назначение |
|---|---|
| Автоматически удалять неиспользуемые версии (флажок) | Включает и выключает механизм |
| Удалять версии старше | Критерий устаревания версии |
| Никогда не удалять версии (таблица) | Номера версий, которые не должны попадать под автоматическое удаление |

Сводка параметров конфигурационных файлов, упомянутых в главе:

| Параметр | Файл | Роль по тексту главы |
|---|---|---|
| `AppVersion` | файл манифеста шаблона | Версия платформы для создания ИБ из шаблона (берётся максимальный номер) |
| `DefaultVersion` | `1cestart.cfg` | Версия платформы — второй приоритет при создании ИБ из шаблона программой запуска; меняется при настройке диалога запуска (только в локальном файле пользователя) |
| `CommonInfoBases` | `1cestart.cfg`, `1cescmn.cfg` | Расположение списков общих ИБ; при настройке диалога запуска меняется только в локальном файле пользователя |
| `ConfigurationTemplatesLocation` | локальный конфигурационный файл (`1cestart.cfg`) | Меняется при настройке диалога запуска (только в локальном файле пользователя); назначение в этой главе отдельно не расписано |
| `CommonCfgLocation` | локальный конфигурационный файл (`1cestart.cfg`) | Если задан — к списку ИБ добавляются базы из параметров `CommonInfoBases` общего конфигурационного файла `1cescmn.cfg` |
| `UseHwLicenses` | `1cestart.cfg` | Поиск аппаратного ключа защиты при запуске клиента |
| `AppAutoInstallLastVersion` | `1cestart.cfg` | Автоматическая установка новой версии |

Подробное описание файлов `1cestart.cfg`, `1cescmn.cfg`, `conf.cfg` находится в других разделах документации (в этой главе — только ссылки).

## 5.8. Списки общих информационных баз

- Список общих ИБ — файл с расширением `v8i`, содержащий ссылки на общие информационные базы.
- Где лежат списки, задаётся параметром `CommonInfoBases` в конфигурационных файлах `1cestart.cfg` и `1cescmn.cfg`.
- Формат файла `v8i` совпадает с форматом основного списка информационных баз.
- Как получить файл: составить вручную либо сохранить существующие ссылки командой контекстного меню списка ИБ «Сохранить ссылку в файл».
- Файл `v8i` можно запускать напрямую: стартует «1С:Предприятие», и в диалоге запуска видны только ссылки из этого файла.
- Совет документации: в списках общих баз указывать скорость соединения «Обычная» (если нет удалённых пользователей и база не на удалённом сервере) — тогда флажок «Низкая скорость соединения» не отображается.
- Когда список из локальной сети недоступен (например, ИБ используется через Интернет, подключение через веб-сервер), можно указать адрес Интернет-сервиса, отдающего список общих ИБ.

Поведение при получении списка:

| Ситуация | Что происходит |
|---|---|
| Первое получение | Базы размещаются в корне списка либо в группе, указанной в самом списке общих ИБ |
| Повторное получение | Сведения о базе обновляются, но её положение в списке пользователя не меняется. Если пользователь перенёс общую базу в свою группу, она там и останется |

## Что важно администратору Linux

1. Сервер PostgreSQL на нестандартном порту указывается в поле «Сервер баз данных» строкой `<имя_экземпляра> port=<номер_порта>;`, пример из документации — `localhost port=6432;`.
2. Пользователю PostgreSQL привилегия `SUPERUSER` нужна только в момент создания ИБ; после успешного создания её можно снять: `alter user dbuser with nosuperuser;`.
3. Имя базы данных PostgreSQL: до 63 символов, без пробелов, не зарезервированное слово; начинается с буквы или `_`; плюс общий запрет символов по RFC 2396 (`< > # % " { } [ ] | \ ^`, обратный апостроф, коды 0–31 и 127).
4. Адрес кластера — `имя_центрального_сервера:порт_менеджера_кластера`; порт по умолчанию 1541 можно не писать. Несколько центральных серверов — `Server1,Server2:Port,Server3`, строго без пробелов.
5. Имя ИБ в кластере регистронезависимо и уникально в пределах кластера.
6. Если центральный сервер указан IP-адресом в точечной нотации, его присутствие в DNS (`hosts`) не требуется.
7. Флажок «Установить блокировку регламентных заданий» запрещает регламентные задания в создаваемой ИБ; если он не установлен, имеющиеся регламентные задания запускаются сразу после подключения базы к серверу.
8. Флажок «Создать базу данных в случае ее отсутствия» управляет созданием БД в СУБД. Если в указанной БД уже есть информационная база 1С, мастер не создаёт новую, а подключается к существующей.
9. Одну базу данных нельзя штатно подключать к нескольким ИБ кластера: ломаются блокировки ИБ и объектов, менеджер управляемых блокировок, оперативная отметка времени; возможна необратимая порча данных. Программного запрета в платформе нет; допустимо только в исключительных случаях для отладки и расследования ошибок.
10. Добавление существующей клиент-серверной ИБ в список ничего не проверяет; если базы нет, конфигуратор при запуске предложит её создать.
11. Удаление ИБ из списка не трогает базу на сервере и каталог файловой базы, но стирает клиентские служебные каталоги этой ИБ; на Linux они лежат в `~/.1cv8/1C/1cv8`.
12. При HTTPS-подключении клиент на Linux берёт клиентские сертификаты и сертификаты УЦ из «специального каталога в ОС Linux» (варианты «Сертификат Linux», «Хранилище сертификатов Linux») либо из указанного файла; проверку сертификата сервера можно отключить вариантом «Не проверять сертификат сервера».
13. Файловая база создаётся по умолчанию в формате версии 8.3.8 (альтернатива — формат 8.2.14); умолчание меняется в `conf.cfg`, конвертация `1Cv8.1CD` — утилитой `cnvdbfl`.
14. Централизованная раздача списка баз пользователям — через файлы `*.v8i` (параметр `CommonInfoBases` в `1cestart.cfg` / `1cescmn.cfg`) либо через Интернет-сервис; повторное получение списка обновляет сведения о базе, но не перемещает её в дереве пользователя.
15. Параметры `CommonInfoBases`, `ConfigurationTemplatesLocation`, `DefaultVersion`, `UseHwLicenses` из диалога настройки запуска пишутся только в локальный `1cestart.cfg` текущего пользователя; значения из общего `1cescmn.cfg` в диалоге не видны.
