## 4.10.3. Режим server

### 4.10.3.1. Общая информация
Команды режима служат для настройки автономного сервера.

### 4.10.3.2. Команды группы config
Управление конфигурацией автономного сервера (результат записывается в конфигурационный файл автономного сервера, см. параметр `--out`).

#### 4.10.3.2.1. init
(`ibcmd server config init`) Инициализирует конфигурацию автономного сервера.

| Параметр | Назначение | Значения / умолчание |
|---|---|---|
| `--database-name=<name>` / `--db-name=<name>` | Имя базы данных | — |
| `--database-password=<password>` / `--db-pwd=<password>` | Пароль пользователя сервера СУБД | — |
| `--database-path=<path>` / `--db-path=<path>` | Каталог файловой базы данных «1С:Предприятия». Относительный путь отсчитывается от каталога данных сервера | По умолчанию: подкаталог `db-data` каталога данных сервера |
| `--database-server=<address>` / `--db-server=<address>` | Имя сервера СУБД | — |
| `--database-user=<name>` / `--db-user=<name>` | Имя пользователя сервера СУБД | — |
| `--dbms=<kind>` | Тип СУБД, где размещена информационная база | `MSSQLServer` (Microsoft SQL Server), `PostgreSQL`, `IBMDB2` (IBM Db2), `OracleDatabase` (Oracle Database). Параметр не указан — файловая база данных |
| `--distribute-licenses=<flag>` | Выдача клиентских лицензий автономным сервером | `allow` / `yes` / `true` — включена; `deny` / `no` / `false` — выключена. По умолчанию `allow` |
| `--http-address=<address>` / `--address=<address>` / `-a <address>` | Основной IP-адрес, обслуживаемый сервером | `localhost` — локальный интерфейс; `any` — все доступные интерфейсы; адрес IPv4 (`xxx.xxx.xxx.xxx`); адрес IPv6 (`xxxx:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx`). По умолчанию `localhost` |
| `--http-base=<location>` / `--base=<location>` / `-b <location>` | Базовый путь публикации информационной базы | По умолчанию `/` |
| `--http-port=<number>` / `--port=<number>` / `-p <number>` | Основной сетевой порт сервера | По умолчанию `8314` |
| `--id=<uuid>` | Идентификатор информационной базы | UUID вида `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` либо `auto` (сгенерировать уникальный). По умолчанию `auto` |
| `--name=<name>` / `-n <name>` | Имя информационной базы | По умолчанию — строковое представление идентификатора ИБ |
| `--out=<path>` / `-o <path>` | Путь к конфигурационному файлу автономного сервера, в который будет записана заданная конфигурация | — |
| `--request-database-password` / `--request-db-pwd` / `-W` | Запросить пароль пользователя СУБД через стандартный ввод (stdin) | флаг |
| `--schedule-jobs=<flag>` | Планирование регламентных заданий | `allow` / `yes` / `true` — включено; `deny` / `no` / `false` — выключено. По умолчанию `allow` |

#### 4.10.3.2.2. import
(`ibcmd server config import`) Импортирует конфигурацию автономного сервера из реестра существующего кластера серверов «1С:Предприятия».

| Параметр | Назначение | Значения / умолчание |
|---|---|---|
| `--address=<address>` / `-a <address>` | Основной IP-адрес, обслуживаемый сервером | `localhost`, `any`, адрес IPv4, адрес IPv6 (как в `init`). По умолчанию `localhost` |
| `--base=<location>` / `-b <location>` | Базовый путь публикации информационной базы | По умолчанию `/` |
| `--cluster-data=<path>` | Каталог данных центрального сервера кластера «1С:Предприятия» | По умолчанию `%LOCALAPPDATA%/1C/1cv8` (в источнике умолчание приведено только в таком, Windows-виде; значение для Linux не указано) |
| `--manager-port=<port>` | Сетевой порт менеджера кластера | По умолчанию `1541` |
| `--name=<name>` / `-n <name>` | Имя информационной базы | — |
| `--out=<path>` / `-o <path>` | Путь к конфигурационному файлу автономного сервера для записи результата | — |
| `--port=<number>` | Основной сетевой порт сервера | По умолчанию `8314` |
| `--publication=<path>` / `-p <path>` | Путь к файлу описания публикации ИБ на веб-сервере (файл `default.vrd`) | — |

Отличия от `init`, видимые по таблицам источника: в `import` короткий ключ `-p` означает `--publication` (в `init` это порт), у `--port` короткой формы нет, синонимы `--http-address` / `--http-base` / `--http-port` не перечислены.

См. также в документации: описание файла `default.vrd`.

### 4.10.4.7. Команды группы config

#### 4.10.4.7.1. Общая информация

Сводка команд группы:

| Команда | Что делает |
|---|---|
| `load` | загрузка конфигурации из cf-файла |
| `save` | выгрузка конфигурации в cf-файл |
| `check` | проверка конфигурации |

#### 4.10.4.7.5. apply
Обновление конфигурации базы данных.

Синтаксис параметров с перечислимыми значениями:

```
--dynamic=<auto|disable|prompt|force>
--session-terminate=<disable|prompt|force>
```

| Параметр | Назначение | Значения / умолчание |
|---|---|---|
| `--dynamic` | Использование динамического обновления | `auto` — автоматически; `disable` — запрещено; `prompt` — спросить пользователя; `force` — только динамическое обновление. По умолчанию `auto` |
| `--extension=<extension>` / `-e <extension>` | Имя расширения (см. правило имени) | — |
| `--force` / `-F` | Автоматически подтверждать выполнение операции при наличии предупреждений | флаг |
| `--session-terminate` | Завершение активных сеансов, когда требуется монопольная (эксклюзивная) блокировка ИБ. Применим при обновлении и основной конфигурации, и расширения | `disable` — запрещено; `prompt` — спросить пользователя; `force` — принудительно завершить сеансы. По умолчанию `disable` |
| `--session-terminate-message` | Текст, который увидят пользователи перед принудительным завершением сеанса; имеет смысл только вместе с `--force` | — |

Примечание источника к `--session-terminate`: если параметр установлен в `auto` или `prompt`, а `--session-terminate-message` не задан, то при необходимости завершить работу пользователей утилита запросит в консоли текст сообщения для них.
⚠ в источнике неясно: значение `auto` упомянуто в этом примечании, но в перечне допустимых значений `--session-terminate` его нет (есть только `disable`, `prompt`, `force`).

#### 4.10.4.7.8. Команды группы export

##### Общая информация
Выгрузка конфигурации информационной базы в xml-файлы. Поддерживается только иерархический формат выгрузки. (В документации есть отдельный раздел о выгрузке конфигурации в xml-файлы.)

##### Параметры export
Применимы ко всем командам группы `export`.

| Параметр | Назначение | Значения / умолчание |
|---|---|---|
| `<path>` | Каталог, в который выгружаются xml-файлы конфигурации | — |
| `--archive` / `-A` | Упаковать выгружаемые файлы в архив | флаг |
| `--base=<file>` / `-b <file>` | Путь к файлу сведений о конфигурации (`ConfigDumpInfo.xml`), относительно которого вычисляются изменения текущей конфигурации | — |
| `--extension=<extension>` / `-e <extension>` | Имя расширения (см. правило имени) | — |
| `--file=<file>` / `-f <file>` | Путь к файлу: конфигурации (`*.cf`), расширения конфигурации (`*.cfe`), внешней обработки (`*.epf`) или отчёта (`*.erf`) | — |
| `--force` | Выполнить полную выгрузку, если при попытке обновить выгрузку оказалось, что текущая версия формата выгрузки не совпадает с версией, записанной в `ConfigDumpInfo.xml` | флаг (короткая форма не указана) |
| `--ignore-unresolved-refs` | Не выгружать неразрешимые ссылки | флаг |
| `--sync` | Синхронизировать уже имеющиеся xml-файлы с конфигурацией информационной базы | флаг |
| `--threads=<n>` / `-T <n>` | Число потоков при экспорте | По умолчанию — число логических ядер процессора компьютера, где работает автономный сервер |

##### info
Формирует файл `ConfigDumpInfo.xml` со сведениями о состоянии конфигурации.

| Параметр | Назначение |
|---|---|
| `--extension=<extension>` / `-e <extension>` | Имя расширения (см. правило имени) |
| `--out=<file>` / `-o <file>` | Файл, в который записываются сведения о конфигурации |

##### status
Показывает различия между конфигурацией информационной базы и конфигурацией в каталоге выгрузки (сведения о последней берутся из `ConfigDumpInfo.xml`).

| Параметр | Назначение |

## 4.11. Сервер отладки (dbgs)

### 4.11.1. Командная строка запуска
Варианты запуска сервера отладки:
- как приложение — в любой поддерживаемой ОС;
- как «демон» — только в Linux;
- как служба ОС — только в Windows.

Общий вид командной строки для ручного запуска:

```
dbgs --version|--help --service|--daemon --addr=<host> --port=<port>|--range=<range> --ownerPID=<PID> --password=<pwd> --notify=<file> --debugServerUsers=<file>
```

| Команда | Назначение | Значения / умолчание / примечания |
|---|---|---|
| `--version` / `-v` | Показать версию сервера отладки | — |
| `--help` / `-h` / `-?` | Краткая справка по параметрам командной строки | — |
| `--service` | Сообщает серверу отладки, что он работает как служба ОС Windows | Только Windows. Несовместим с `--daemon` |
| `--daemon` | Запуск в режиме «демона» Linux — фонового приложения, не взаимодействующего с терминалом, из которого оно запущено | Только Linux. Сам по себе не обеспечивает автозапуск после перезагрузки системы. Несовместим с `--service` |
| `--addr=<host>` / `-a <host>` | IP-адрес, который будет адресом сервера отладки; нужен, когда на компьютере несколько сетевых карт с разными адресами | Не указан — берётся адрес произвольной сетевой карты |
| `--port=<port>` / `-p <port>` | Порт для соединений с сервером отладки | Умолчания нет — порт задаётся явно. Порт недоступен — сервер отладки не запустится, отладка невозможна. При запуске сервера отладки кластером серверов используется порт `1550` (устанавливается кластером по умолчанию, меняется ключами запуска кластера). При одновременном указании `port` и `range` параметр `port` игнорируется |
| `--range=<range>` / `-r <range>` | Диапазон портов, из которого выбирается один порт для соединений | Границы диапазона разделяются `:`, несколько диапазонов или отдельных портов — `,`. Пример: `2560:2590, 4567, 9000:12000` (порты 2560–2590, порт 4567, порты 9000–12000). Выбранный порт вместе с адресом сервера отладки записывается в файл из параметра `notify`. Все порты недоступны — сервер отладки не запустится. При одновременном указании `port` и `range` параметр `port` игнорируется |
| `--ownerPID=<PID>` / `-opid <PID>` | Идентификатор процесса ОС, время жизни которого определяет время жизни сервера отладки | Сервер отладки следит за этим процессом и завершается после его завершения; при этом завершаются и все процессы отладки, идущие через этот сервер. При отладке файловой ИБ конфигуратор сам подставляет сюда свой PID; при запуске из кластера серверов параметр не используется |
| `--password=<pwd>` / `-pwd <pwd>` | Пароль доступа к серверу отладки; его должны указывать все отладчики, работающие через этот сервер | Игнорируется, если одновременно указан `debugServerUsers` |
| `--notify=<file>` | Полное имя файла, в который сервер отладки записывает свой адрес | Конфигуратор или менеджер кластера считывает адрес и удаляет файл |
| `--debugServerUsers=<file>` / `-dbgsUsers <file>` | Файл со списком пользователей отладки | Имеет приоритет над `password`. Если не указан — сервер отладки никак не ограничивает возможности отладки |

Ограничение режима службы и «демона»: через такой сервер отладки можно отлаживать предметы отладки файловых информационных баз и **клиентские** предметы отладки клиент-серверных баз. Отладка **серверных** предметов отладки клиент-серверных информационных баз через сервер отладки, запущенный как служба или «демон», не поддерживается.

### 4.11.2. Регистрация службы сервера отладки (ОС Windows)
**Только Windows.** Документация приводит образец командного файла `register-dbgs.bat` (можно брать за основу): параметр `%1` — полный номер версии «1С:Предприятия», `%2` — сетевой порт сервера отладки. В файле перед применением нужно задать пользователя и пароль службы (`set DbgsUserName=`, `set DbgsUserPwd=`). Скрипт делает `sc stop`, `sc delete`, затем `sc create` службы с именем `Debug Server <порт>`, режим запуска автоматический (`start= auto`); проверка существования службы с таким номером не выполняется. Командная строка службы:

```
"C:\Program Files\1cv8\<версия>\bin\dbgs.exe" --service --port=<порт>
```

Пример запуска (нужны права администратора): `register-dbgs.bat 8.3.25.100 1550` — служба `Debug Server 1550`, отображаемое имя вида `1C:Enterprise 8.3 Debug server. Parameters: <версия>, port: 1550`.
⚠ в источнике неясно: в примере передаётся версия `8.3.25.100`, а в описании результата (используемая версия и отображаемое имя) фигурирует `8.3.24.100`.

### 4.11.3. Отмена регистрации службы сервера отладки (ОС Windows)
**Только Windows.** Образец `unregister-dbgs.bat`: параметр `%1` — сетевой порт сервера отладки; выполняет `sc stop` и `sc delete` для службы `Debug Server %1` (имя формируется так же, как при регистрации). Пример (права администратора): `unregister-dbgs 1550`.

## 4.12. Агент кластера (ragent)

### 4.12.1. Командная строка запуска
Варианты запуска агента сервера по источнику: как приложение или служба — в любой поддерживаемой ОС; как «демон» — только в Linux.

Общий вид командной строки (для всех поддерживаемых ОС):

```
./ragent /daemon /instsrvc /rmsrvc /start /stop /usr <значение> /pwd <значение> /port <значение> /regport <значение> /range <значение> /seclev <значение> /d <значение> /pingPeriod <значение> /pingTimeout <значение> /debug -<значение> /debugServerAddr <значение> /debugServerPort <значение> /debugServerPwd <значение> /debugServerUsers <значение>
```

**Важно:** команда и её значение разделяются пробелом.

Колонка «ОС»: `L` — только Linux, `W` — только Windows, пусто — любая поддерживаемая ОС.

| Команда | ОС | Назначение | Значения / умолчание / примечания |
|---|---|---|---|
| `/d <значение>` | | Каталог данных сервера: в нём лежат (или будут созданы) служебные файлы кластера серверов, включая список кластеров и список информационных баз кластера | По умолчанию: Linux — `~/.1cv8`; Windows — `%LOCALAPPDATA%\1C\1cv8`. Путь с пробелами берётся в кавычки: `/d "~/cluster data"` (Linux), `/d "c:\Server data\cluster 2"` (Windows). В Windows путь в кавычках не должен оканчиваться на `\`: верно `"c:\my path"`, неверно `"c:\my path\"` |
| `/daemon` | L | Запуск агента сервера в режиме «демона» Linux — фонового приложения, не взаимодействующего с терминалом, из которого оно запущено | Сам по себе не обеспечивает автозапуск агента после перезагрузки системы |
| `/debug -<значение>` | | Запуск кластера серверов в режиме отладки конфигураций; значение задаёт протокол работы отладчика на этом кластере | `-tcp` — протокол TCP/IP; `-http` — протокол HTTP. По умолчанию `-tcp`. Совет документации: в режиме отладки производительность сервера падает, поэтому включать его только на серверах, где действительно ведётся отладка |
| `/debugServerAddr <значение>` | | Адрес компьютера, на котором работает сервер отладки; рекомендуется при нескольких сетевых картах | Не указана — берётся произвольный сетевой адрес компьютера, на котором запускается сервер отладки |
| `/debugServerPort <значение>` | | Порт, который должен использовать сервер отладки | По умолчанию `1550` |
| `/debugServerPwd <значение>` | | Пароль, который клиентское приложение должно указать при соединении с сервером отладки этого кластера | По умолчанию пароль не установлен. Игнорируется, если одновременно указана `/debugServerUsers` |
| `/debugServerUsers <значение>` | | Файл со списком пользователей отладки для сервера отладки | По умолчанию список не указан — тогда сервер отладки не ограничивает возможности отладки. При одновременном указании с `/debugServerPwd` используется список пользователей |
| `/instsrvc` | W | Регистрация агента кластера как службы Windows: `ragent` регистрируется в списке служб и завершается | Несовместима с `/rmsrvc`, `/start`, `/stop` |
| `/pingPeriod <значение>` | | Период проверки системы отслеживания разрыва соединений, в миллисекундах | По умолчанию `1 000`. Может меняться средствами администрирования кластера (см. правило приоритета ниже) |
| `/pingTimeout <значение>` | | Таймаут проверки системы отслеживания разрыва соединений, в миллисекундах | По умолчанию `5 000`. Может меняться средствами администрирования кластера (см. правило приоритета ниже) |
| `/port <значение>` | | Сетевой порт агента сервера (`ragent`). Через него консоль кластера обращается к центральному серверу; он же указывается как сетевой порт рабочего сервера | По умолчанию `1540` |
| `/pwd <значение>` | W | Пароль пользователя Windows, от имени которого `ragent` запускается как служба | Только вместе с `/usr` и `/instsrvc` при регистрации службы |
| `/range <значение>` | | Диапазоны сетевых портов для динамического выбора. Служат начальным значением свойства «Диапазоны IP портов» рабочего сервера кластера, создаваемого по умолчанию при первом запуске `ragent` | По умолчанию `1560:1591`. Примеры: `4549:4567, 7072:7790` |
| `/regport <значение>` | | Сетевой порт главного менеджера кластера (`rmngr`), создаваемого по умолчанию при первом запуске `ragent` | По умолчанию `1541` |
| `/rmsrvc` | W | Отмена регистрации агента кластера как службы Windows: `ragent` снимает регистрацию и завершается | Несовместима с `/instsrvc`, `/start`, `/stop` |
| `/seclev <значение>` | | Уровень безопасности процесса агента кластера — уровень защиты соединений, устанавливаемых с процессом `ragent` | `0` (по умолчанию) — соединения незащищённые; `1` — защищены только на время аутентификации пользователей; `2` — защищены постоянно |
| `/start` | W | Запустить `ragent`, ранее зарегистрированный как служба Windows, и завершиться | Несовместима с `/instsrvc`, `/rmsrvc`, `/stop` |
| `/stop` | W | Остановить `ragent`, зарегистрированный и запущенный как служба Windows, и завершиться | Несовместима с `/instsrvc`, `/rmsrvc`, `/start` |
| `/usr <значение>` | W | Имя пользователя Windows, от имени которого `ragent` запускается как служба | Только вместе с `/instsrvc` при регистрации службы |

Про `/pingPeriod` и `/pingTimeout`:
- **Область действия:** значения применяются ко всем исходящим соединениям процессов кластера на данном сервере, запущенных через этот процесс агента сервера.
- **Приоритет:** если в настройках кластера хотя бы один из параметров «Период проверки» и «Таймаут проверки» отличен от 0 — действуют настройки кластера; иначе — параметры командной строки запуска кластера серверов.
- **Рекомендации**, если в кластере несколько рабочих серверов и значения по умолчанию решено менять: таймаут проверки ставить в 3–10 раз больше периода проверки; период проверки не делать меньше 1 000 мс; на всех серверах одного кластера задавать одинаковые период и таймаут.

Остановка агента сервера, запущенного как приложение, — сочетанием клавиш Ctrl+C.

См. также в документации: раздел о запуске кластера серверов; раздел об уровне безопасности соединения.

### 4.12.2. Регистрация службы запуска агента кластера (ОС Windows)
**Только Windows.** Образец командного файла `register-agent.bat` (можно брать за основу). Параметры: `%1` — полный номер версии «1С:Предприятия»; `%2` — первые две цифры номеров портов (для 1540, 1541, 1560:1591 это `15`); `%3` — каталог данных реестра кластера. В файле задаются пользователь и пароль службы (`set SrvUserName=`, `set SrvUserPwd=`); порты вычисляются как `CtrlPort=%240` (порт `ragent`), `BasePort=%241` (порт `rmngr`), `RangePort=%260:%291`. Скрипт создаёт каталог `%3`, если его нет, выполняет `sc stop`, `sc delete` и `sc create` со `start= auto` и зависимостями `depend= Dnscache/Tcpip/Tcpip6/lanmanworkstation/lanmanserver`. Имя службы — `Server Agent <CtrlPort> <версия>`. Командная строка службы:

```
"C:\Program Files\1cv8\<версия>\bin\ragent.exe" /srvc /agent /regport <BasePort> /port <CtrlPort> /range <RangePort> /d "<каталог>" /debug
```

Примеры (права администратора):

```
register-agent 8.3.27.100 25 "c:\cluster_data\cluster 1"
register-agent 8.3.27.100 35 "c:\cluster_data\cluster 2"
```

Результат: служба `Server Agent 2540 8.3.27.100`, порты 2540, 2541, 2560:2591, каталог `C:\cluster_data\cluster 1`; служба `Server Agent 3540 8.3.27.100`, порты 3540, 3541, 3560:3591, каталог `C:\cluster_data\cluster 2`. Описание службы имеет вид `1C:Enterprise 8.3 Server Agent. Parameters: 8.3.27.100, ragent port: 2540, rmngr port: 2541, range: 2560:2591`.

⚠ в источнике неясно:
- ключи `/srvc` и `/agent` из командной строки службы в таблице раздела 4.12.1 не описаны; `/debug` в образце указан без значения протокола;
- в тексте сказано, что в имя службы входит номер порта главного менеджера кластера, но и в скрипте (`%CtrlPort%`), и в примерах (`2540`, `3540`) в имени стоит порт агента (`…40`), а порт менеджера — `…41`.

### 4.12.3. Отмена регистрации службы запуска агента кластера (ОС Windows)
**Только Windows.** Образец `unregister-agent.bat`: `%1` — полный номер версии, `%2` — первые две цифры номеров портов; выполняет `sc stop` и `sc delete` для службы `Server Agent %240 %1` (имя строится так же, как при регистрации). Пример (права администратора): `unregister-agent 8.3.27.100 25`.

## 4.13. Сервер администрирования (ras)

### 4.13.1. Командная строка запуска
Варианты запуска сервера администрирования:
- как приложение — в любой поддерживаемой ОС;
- как «демон» — только в Linux;
- как служба ОС — только в Windows.

Общий вид командной строки (ключи в Windows и Linux одинаковы):

```
ras cluster --port=<port> --monitor-address=<address> --monitor-base=<location> --monitor-port=<port> <host[:port]>
```

| Команда | Назначение | Значения / умолчание |
|---|---|---|
| `cluster` | Запуск сервера администрирования в режиме администрирования кластера серверов | **Обязательный** параметр |
| `<host[:port]>` | Адрес агента кластера серверов, для администрирования которого запускается `ras` | Не указан — `localhost:1540` |
| `--monitor-address=<address>` | IP-адрес, который обслуживает шлюз монитора производительности по протоколу HTTP | `localhost` — локальный интерфейс; `any` — все доступные интерфейсы; адрес IPv4 (`xxx.xxx.xxx.xxx`); адрес IPv6 (`xxxx:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx`). По умолчанию `localhost` |
| `--monitor-base=<location>` | Базовый путь публикации показателей производительности; всегда должен начинаться с `/` | По умолчанию `/` |
| `--monitor-port=<port>` | Сетевой порт, который обслуживает шлюз монитора производительности по протоколу HTTP | По умолчанию `1555` |
| `--port=<port>` / `-p <port>` | Сетевой порт, обслуживаемый сервером администрирования | По умолчанию `1545` |

Аутентификация в кластере — средствами аутентификации «1С:Предприятия».

⚠ в источнике неясно: отдельного ключа для запуска `ras` в режиме «демона» Linux в таблице нет (режим только упомянут в тексте); ключ `--service`, который используется в Windows-образце из 4.13.2, в таблице также не описан.

### 4.13.2. Регистрация службы запуска сервера администрирования (ОС Windows)
**Только Windows.** Образец командного файла `register-ras.bat` (можно брать за основу). Параметры: `%1` — полный номер версии «1С:Предприятия»; `%2` — сетевой порт сервера администрирования; `%3` — имя экземпляра кластера серверов (хост), к которому подключается `ras`; `%4` — сетевой порт агента сервера. В файле задаются пользователь и пароль службы (`set RasUserName=`, `set RasUserPwd=`). Скрипт выполняет `sc stop`, `sc delete`, `sc create` со `start= auto`. Имя службы — `Remote Server <порт ras>` (для порта 1545 — `Remote Server 1545`). Командная строка службы:

```
"C:\Program Files\1cv8\<версия>\bin\ras.exe" cluster --service --port=<порт ras> <хост>:<порт агента>
```

Пример (права администратора): `register-ras 8.3.27.100 1545 localhost 1540` — служба `Remote Server 1545`, порт `ras` 1545, кластер `localhost`, порт агента 1540, описание `1C:Enterprise 8.3 Remote Server. Parameters: 8.3.27.100, port: 1545, cluster: localhost:1540`, запуск автоматический.

### 4.13.3. Отмена регистрации службы запуска сервера администрирования (ОС Windows)
**Только Windows.** Образец `unregister-ras.bat`: выполняет `sc stop` и `sc delete` для службы `Remote Server %1` (имя строится так же, как при регистрации). Пример из источника (права администратора): `unregister-ras 25`.
⚠ в источнике неясно: оба комментария в скрипте относятся к `%1` (и «полный номер версии», и «номер сетевого порта сервера администрирования»); в тексте единственный параметр описан как «первые две цифры номеров сетевых портов» с примером `25`, хотя по самому скрипту имя службы `Remote Server %1` совпадает с именем из 4.13.2 только при передаче номера порта сервера администрирования.

## 4.14. Утилита публикации на веб-сервере (webinst)
Утилита `webinst` настраивает веб-серверы для работы веб-клиента. Работает в Windows и Linux, входит в дистрибутив «1С:Предприятия».

```
webinst [-publish]|-delete <веб-сервер> -wsdir <виртуальный каталог> -dir <физический каталог> -connstr <строка соединения> -confpath <путь к файлу httpd.conf> -descriptor <путь к файлу default.vrd> [-osauth]
```

Для публикации утилиту нужно запускать от имени администратора (в Windows при запуске запрашивается повышение привилегий). Набор команд одинаков для всех поддерживаемых ОС.

| Команда | Назначение | Значения / примечания |
|---|---|---|
| `<веб-сервер>` | Для какого веб-сервера выполняется действие (публикация или удаление публикации). Допускается указать только одно значение | `-iis` — Microsoft Internet Information Services версий 5.1, 6.0, 7.x, 8.x, 10.0 (только Windows); `-apache2` — Apache 2.0; `-apache22` — Apache 2.2; `-apache24` — Apache 2.4. Для Apache 2.4 путь к конфигурационному файлу (`-confpath`) можно не указывать. Изменения, вносимые в конфигурационный файл для Apache 2.2 и 2.4, различаются, поэтому неверно указанная версия веб-сервера делает публикацию неработоспособной |
| `-confpath` | Полный путь к конфигурационному файлу (`httpd.conf`) веб-сервера Apache | Применяется только для веб-серверов Apache |
| `-connstr` | Строка соединения с информационной базой | — |
| `-delete` | Удалить публикацию из указанного каталога | Для удаления достаточно одного параметра `-wsdir`; остальные можно указать для контроля |
| `-descriptor` | Публикация по шаблону — существующему файлу, путь к которому (включая имя) задаётся в параметре. Имя файла-шаблона не обязано быть `default.vrd` | При публикации существующий `default.vrd` полностью замещается файлом-шаблоном. Если вместе с ним заданы `-wsdir` или `-connstr`, их значения заменяют атрибуты `base` и `ib` (соответственно) элемента `point`. Вместе с `-delete`: из шаблона берутся имя виртуального каталога (атрибут `base` элемента `point`) и строка соединения (атрибут `ib` элемента `point`); публикация удаляется, только если оба значения совпадают у удаляемой публикации и у шаблона |
| `-dir` | Физический каталог, в который отображается виртуальный каталог веб-сервера. Каталог должен существовать | Для IIS 7.x и старше (только Windows) не поддерживается публикация, если параметр указывает на каталог `%SYSTEMDRIVE%\Inetpub\wwwroot`. Имя каталога в кавычках не должно оканчиваться на `\`: верно `"c:\my path"`, неверно `"c:\my path\"` |
| `-osauth` | При публикации настроить использование аутентификации ОС на веб-сервере | Только для веб-серверов IIS |
| `-publish` | Опубликовать веб-клиент на веб-сервере | В строке синтаксиса показан как необязательный (`[-publish]`) |
| `-wsdir` | Имя виртуального каталога | — |

Правила записи параметров: имя параметра и его значение разделяются пробелом; значение с пробелами заключается в кавычки (`""`); кавычки внутри значения удваиваются.

См. также в документации: раздел «Использование утилиты webinst» (в источнике ссылка с пометкой «377»).

## Что важно администратору Linux

Сводка сетевых портов по умолчанию, названных в этой части:

| Компонент | Параметр | Порт по умолчанию |
|---|---|---|
| Агент кластера `ragent` | `/port` | 1540 |
| Главный менеджер кластера `rmngr` | `/regport` (у `ragent`), `--manager-port` (у `ibcmd server config import`) | 1541 |
| Диапазон портов рабочего сервера | `/range` | 1560:1591 |
| Сервер отладки при запуске кластером | `/debugServerPort` | 1550 |
| Сервер администрирования `ras` | `--port` / `-p` | 1545 |
| Шлюз монитора производительности `ras` (HTTP) | `--monitor-port` | 1555 |
| Автономный сервер (основной порт) | `--http-port` / `--port` / `-p` в `init`; `--port` в `import` | 8314 |

Практические выводы:

1. **Каталог данных кластера в Linux по умолчанию — `~/.1cv8`**; другой каталог задаётся ключом `ragent /d <путь>`, путь с пробелами — в кавычках. В нём лежат служебные файлы кластера, включая списки кластеров и информационных баз.
2. **`/daemon` у `ragent` и `--daemon` у `dbgs` — это только фоновый режим**, отвязанный от терминала; автозапуск после перезагрузки системы эти ключи сами по себе не дают.
3. **У `ragent` команда и значение пишутся через пробел** (`/port 1540`, `/debug -http`), а у `ras`, `dbgs`, `ibcmd` длинные параметры — через `=` (`--port=1545`).
4. **`/regport` и `/range` — стартовые значения**: они применяются к менеджеру кластера и рабочему серверу, создаваемым по умолчанию при первом запуске `ragent`.
5. **Отладка на сервере:** `/debug -tcp` (по умолчанию) или `/debug -http`; режим отладки снижает производительность, включать только там, где отлаживают. Доступ к серверу отладки ограничивается `/debugServerPwd` или `/debugServerUsers` (список пользователей имеет приоритет); без них ограничений нет.
6. **`dbgs` как «демон» не годится для отладки серверного кода клиент-серверных баз**: поддерживаются только файловые базы и клиентские предметы отладки клиент-серверных баз. У самостоятельного `dbgs` порта по умолчанию нет — нужен `--port` или `--range` (при обоих действует `--range`).
7. **Отслеживание разрыва соединений:** `/pingPeriod` 1 000 мс и `/pingTimeout` 5 000 мс по умолчанию; если в настройках кластера хотя бы одно из значений ненулевое, действуют настройки кластера. Рекомендации: таймаут в 3–10 раз больше периода, период не меньше 1 000 мс, одинаковые значения на всех серверах кластера.
8. **Уровень безопасности соединений с агентом** — `/seclev 0|1|2` (по умолчанию 0, незащищённые соединения).
9. **`ras` запускается как `ras cluster [--port=<порт>] [<хост>[:<порт>]]`**: слово `cluster` обязательно, адрес агента по умолчанию `localhost:1540`, собственный порт 1545; у HTTP-шлюза монитора производительности умолчания — адрес `localhost`, порт 1555, базовый путь `/` (меняются `--monitor-address`, `--monitor-port`, `--monitor-base`).
10. **`ibcmd infobase dump` / `restore` работают с dt-файлом и резервным копированием базы данных не являются** — так прямо сказано в документации. `restore --force` принудительно завершает сеансы.
11. **Перенос базы между СУБД (в том числе в PostgreSQL) — `ibcmd infobase replicate`** с параметрами `--target-dbms=PostgreSQL`, `--target-db-server`, `--target-db-name`, `--target-db-user`, `--target-create-database`; параллелизм — `-j` (выгрузка) и `-J` (загрузка), по умолчанию по числу логических ядер. Из файловой базы в клиент-серверную так переносить нельзя.
12. **Пароль СУБД можно не писать в командной строке**: `-W` / `--request-db-pwd` (и `--target-request-db-pwd` для целевой СУБД) запрашивают его через stdin.
13. **`ibcmd server config import`**: умолчание `--cluster-data` в документации дано только как Windows-путь (`%LOCALAPPDATA%/1C/1cv8`), значение для Linux не названо — каталог данных кластера стоит указывать явно. Короткий ключ `-p` здесь означает файл публикации (`default.vrd`), а в `init` — порт.
14. **Режимы `ibcmd session` и `ibcmd lock` требуют работающего автономного сервера** (offline-режим не поддерживается); `ibcmd eventlog export` и `model export`, наоборот, работают без подключения к базе — достаточно пути к каталогу журнала регистрации; `--follow` даёт непрерывную выгрузку новых событий (опрос раз в 1000 мс по умолчанию), форматы `xml` и `json`.
15. **`webinst` на Linux:** тип веб-сервера указывается точно по версии (`-apache2`, `-apache22`, `-apache24`) — ошибка в версии ломает публикацию; для Apache 2.4 `-confpath` можно не задавать; каталог `-dir` должен существовать заранее; для удаления публикации достаточно `-delete` и `-wsdir`; запуск — от имени администратора; `-iis` и `-osauth` относятся только к IIS.
