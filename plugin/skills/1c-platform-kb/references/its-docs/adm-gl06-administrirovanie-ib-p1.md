## 6.1. Общая информация

- Административные задачи, которые решаются средствами конфигуратора (примеры из документации): ведение списка пользователей, назначение им прав, резервное копирование, настройка технологического журнала для разбора ошибок.
- Список пользователей **не входит в конфигурацию**: он заводится отдельно в каждой организации, где эксплуатируется система, и служит для проверки пользователя при входе.
- Каждому пользователю можно задать пароль на вход.
- Резервное копирование нужно делать периодически; чем интенсивнее меняются данные, тем чаще.
- Глава 6 описывает только то администрирование, которое выполняется через конфигуратор.

## 6.2. Ведение списка пользователей

### 6.2.1. Общая информация

- Открытие списка: **Администрирование → Пользователи**.
- Окно: панель инструментов и таблица из двух колонок — **Имя** и **Полное имя** (расшифровка имени).
- Пиктограммы строк:
  - с замочком — у пользователя задан пароль;
  - с вопросом — у пользователя не определена роль или аутентификация.
- Меню **Действия**: ведение списка, настройка его показа (отбор, состав и порядок колонок, сортировка), вывод списка в табличный или текстовый документ.
- Программный доступ: свойство глобального контекста `ПользователиИнформационнойБазы` и объект типа `ПользовательИнформационнойБазы`.

### 6.2.2. Добавление нового пользователя

Команда **Действия → Добавить** открывает окно свойств пользователя. Заполнять все поля сразу не обязательно.

**Уникальность пользователя** обеспечивается сочетанием трёх полей: имя, полное имя и имя пользователя ОС (последнее — если включена аутентификация ОС).

#### Закладка «Основные»

| Поле / флажок | Назначение | Ограничения и примечания |
|---|---|---|
| Имя | Имя для входа в систему | Символ `:` использовать не рекомендуется. Уникальность — по первым 64 символам; длину больше 64 допускать не рекомендуется. Совет документации: давать осмысленные имена (фамилия, должность, функция) |
| Полное имя | Расшифровка имени | Уникальность — по первым 128 символам |
| Адрес электронной почты | Нужен для аутентификации через электронную почту и для восстановления пароля | Уникален для каждого пользователя ИБ (сравнение без учёта регистра), не длиннее 128 символов. Если не задан — восстановить пароль по почте нельзя, только через веб-сайт |
| Пользователю запрещено восстанавливать пароль | Запрет самостоятельного восстановления | Забытый пароль восстанавливает только администратор |
| Аутентификация 1С:Предприятия | Вход по имени и паролю | — |
| Пользователю запрещено изменять пароль | Пользователь не может сменить свой пароль | Применяется, когда включена аутентификация 1С:Предприятия |
| Показывать в списке выбора | Показ пользователя в списке выбора при подключении к ИБ | Если аутентификация 1С:Предприятия запрещена — флажок недоступен, пользователь в списке не виден |
| Аутентификация операционной системы | Вход по учётной записи ОС | После установки становится доступно поле **Пользователь** |
| Пользователь | Сопоставленный пользователь ОС | Формат `\\имя_домена\имя_пользователя`; не длиннее 128 символов; уникальность — по первым 128 символам |
| Аутентификация OpenID | Вход через OpenID-провайдера | Нужна соответствующая настройка публикации на веб-сервере |
| Аутентификация OpenID Connect | Вход через провайдера OpenID Connect | Нужна соответствующая настройка публикации на веб-сервере |
| Аутентификация токеном доступа | Вход по токену доступа | — |
| Аутентификация QR кодом | Вход по QR-коду | Нужна соответствующая настройка публикации на веб-сервере |
| Аутентификация через электронную почту | Вход по коду из письма | Дополнительно нужен заполненный адрес электронной почты. ⚠ в источнике флажок назван двояко: «через электронную почту» и «по электронной почте» |
| Защита от опасных действий | Включает для пользователя защиту от опасных действий | Подробности — в отдельном разделе документации |

Правила для флажков «Аутентификация…»:

- Флажки определяют только **разрешённость** способа; на порядок попыток аутентификации они не влияют.
- Все флажки сняты — пользователю доступ к прикладному решению закрыт.
- Пользователь, прошедший аутентификацию средствами ОС, OpenID, OpenID Connect или QR-кодом, всё равно не будет допущен, если соответствующий флажок у него снят.
- Попытку аутентификации средствами ОС или OpenID можно отключить параметрами командной строки клиента (см. 6.2.10.3 и 6.2.10.4).
- **Обязательное условие:** в ИБ должен существовать хотя бы один пользователь с административными правами, которому разрешена аутентификация средствами «1С:Предприятия».

Ограничения клиентов:

- клиентское приложение под macOS не поддерживает аутентификацию ОС;
- толстый клиент (в любой поддерживаемой ОС) не поддерживает аутентификацию OpenID ни в каком варианте.

Совет документации: если ИБ опубликована на веб-сервере, доступном из Интернета, или пользователей в базе много — снять «Показывать в списке выбора» у всех пользователей, в первую очередь у администраторов.

#### Закладка «Прочие»

| Свойство | Назначение |
|---|---|
| Доступные роли | Можно отметить несколько ролей, если в конфигурации их несколько |
| Язык | Язык пользователя |
| Режим запуска | `Авто` — используется значение свойства конфигурации «Режим запуска». Конкретное значение (например, «Управляемое приложение») задают тем, кто должен работать в особом режиме |
| Ключ требования назначения | Позволяет распределять подключения пользователей по рабочим серверам (описано в разделе о требованиях назначения) |

#### Закладка разделения данных

- Появляется, если в системе включено разделение пользователей.
- Показывает все доступные **разделители** (а не все общие реквизиты).
- Флажок слева от имени разделителя — признак того, что для пользователя задано значение; само значение вводится в поле справа.
- Когда у пользователя указаны и значение, и признак использования, свойства разделителя «Разделение пользователей» и «Разделение аутентификации» начинают влиять на то, виден ли пользователь и доступен ли он для выбора и аутентификации.

### 6.2.3. Копирование пользователя

- Команда **Действия → Скопировать** на выбранной строке списка.
- Имя копии может быть изменено системой ради уникальности.
- Все прочие свойства переносятся с образца, **кроме пароля**.

### 6.2.4. Установка пароля

- Пароль обязан соответствовать политике паролей, действующей для ИБ или для пользователя. Политику, назначенную конкретному пользователю, можно посмотреть только из встроенного языка.
- Максимальная длина пароля — **255 символов**. При вводе символы скрыты.

**Встроенный генератор** (гиперссылка «Сгенерировать пароль») учитывает параметры ИБ; состав пароля зависит от настроенной минимальной длины:

| Минимальная длина в параметрах ИБ | Что генерируется |
|---|---|
| меньше 7 | только строчные латинские буквы |
| 7 и больше | цифры, строчные и заглавные латинские буквы; пароль проходит проверку сложности независимо от того, включена ли она в ИБ |
| 0 (длина не контролируется) | пароль длиной 7 символов, сложный: цифры, строчные и заглавные латинские буквы |

**Поле «Подтверждение пароля»:**

- пароль введён вручную — поле доступно; при расхождении по кнопке ОК выводится «Пароль и подтверждение пароля не совпадают», пароль не устанавливается;
- пароль сгенерирован — поле недоступно, значение подставляется автоматически; генерировать заново можно сколько угодно раз.

**Просмотр и очистка:**

- пока изменённый пароль не подтверждён кнопкой ОК, кнопка в правой части полей переключает показ реальных символов и маски;
- после записи и повторного открытия формы пароль посмотреть нельзя — в поле выводится надпись «Пароль установлен»;
- `Shift + F4` в поле «Пароль» или «Подтверждение пароля» очищает пароль: оба поля сразу, если пароль сгенерирован системой, либо только текущее поле, если введён вручную;
- кнопка «Отмена» отменяет не только смену пароля, но и все остальные изменения, сделанные в диалоге.

**Если пользователь забыл пароль:**

1. администратор задаёт новый пароль (нужен административный доступ к списку пользователей);
2. пользователь проходит процедуру восстановления пароля — она должна быть настроена в ИБ и разрешена этому пользователю (см. 6.2.6.4).

### 6.2.5. Политика паролей

#### 6.2.5.1. Общая информация

- Политика паролей — набор требований к сложности, уникальности и сроку жизни паролей; для разных баз и разных уровней доступа пользователей эти требования могут отличаться.
- Задаётся как для **ИБ в целом**, так и для **конкретных пользователей**.
- Для ИБ в целом — диалог параметров информационной базы, группа **«Требования к паролям»**.
- Из встроенного языка используется объект `ПолитикаПаролейПользователей`; набор параметров у него тот же, что в диалоге.

#### 6.2.5.2. Параметры политики паролей

| Параметр в интерфейсе | Свойство `ПолитикаПаролейПользователей` | Что задаёт | Значения / примечания |
|---|---|---|---|
| Проверка сложностей паролей пользователей | `ПроверкаСложностиПаролей` | Включает требования к сложности (см. ниже) | флажок |
| Проверка раскрытия паролей пользователей | `ПроверкаРаскрытияПаролей` | Пароль дополнительно проверяется на допустимость в принципе: не скомпрометирован ли он, не входит ли в корпоративный список стоп-слов | флажок; источники проверки настраиваются в 6.2.6.5 или из встроенного языка |
| Минимальная длина паролей пользователей | `МинимальнаяДлинаПаролей` | Минимальная длина пароля | При включённой проверке сложности не может быть меньше 7. Из встроенного языка, тем не менее, можно установить пароль любой длины |
| Действие при несоответствии паролей пользователей требованиям при аутентификации | `ДействиеПриНесоответствииПаролейТребованиямПриАутентификации` | Что делает платформа, если при входе пароль не соответствует действующей политике (системной или пользовательской) | значение перечисления `ДействиеПриНесоответствииПароляТребованиямПриАутентификации` (см. ниже) |
| Максимальный срок действия паролей пользователей | `МаксимальныйСрокДействияПаролей` | Время от установки пароля, по истечении которого его обязательно нужно сменить | секунды; 0 — не действует |
| Минимальный срок действия паролей пользователей | `МинимальныйСрокДействияПаролей` | Время от установки пароля, раньше которого пользователь не может его сменить | секунды; 0 — не действует |
| Срок предупреждения об истечении срока действия паролей | `СрокПредупрежденияОбИстеченииСрокаДействияПаролей` | За сколько до окончания срока действия система начинает напоминать о смене пароля | секунды; 0 — не действует |
| Запретить повторение пароля среди последних | `ОграничениеПовторенияПаролейСредиПоследних` | Сколько последних паролей пользователя учитывается при проверке уникальности нового (при значении 5 новый пароль не должен совпасть ни с одним из 5 предыдущих) | число; 0 — не действует |

**Требования при включённой проверке сложности:**

- длина не меньше большего из двух чисел: 7 и значения «Минимальная длина паролей пользователей»;
- символы минимум из трёх групп из четырёх: заглавные буквы, строчные буквы, цифры, специальные символы;
- пароль не совпадает с именем пользователя;
- пароль не является последовательностью символов.

**Как ограничения применяются к существующим паролям:**

- уже заданные пароли не затрагиваются — ограничения срабатывают при смене пароля или при создании нового пользователя;
- но сама **проверка пароля при входе идёт по текущей настройке ИБ**: после включения проверки сложности пароль начинает сверяться **с учётом регистра**. Пример документации: пароль `PaRoL` до включения параметра принимался как `parol`, `PAROL`, `ParoL`; после включения — только `PaRoL`.

**Значения перечисления `ДействиеПриНесоответствииПароляТребованиямПриАутентификации`:**

| Значение | Поведение |
|---|---|
| `Нет` | Ничего не происходит |
| `ПредложитьСменуПароля` | Пользователю сообщается о несоответствии и открывается форма смены пароля; делается запись в журнал регистрации; работать можно и без смены пароля |
| `ПотребоватьСменуПароля` | То же, но отказаться от смены нельзя; делается запись в журнал регистрации. Если пользователю запрещено изменять пароль — возникает исключение, вход в ИБ невозможен |

### 6.2.6. Дополнительные настройки аутентификации

#### 6.2.6.1. Общая информация

- Диалог: **Главное меню → Администрирование → Дополнительные настройки аутентификации**.
- Что настраивается: параметры диалога аутентификации, восстановление забытого пароля, проверка раскрытия пароля и ряд других параметров.
- Закладки: «Аутентификация», «Аутентификация через электронную почту», «Восстановление пароля», «Проверка раскрытия пароля».

#### 6.2.6.2. Аутентификация

**Группа «Дополнительная информация»**

- Флажок `Отображать гиперссылку "Нужна помощь?"` открывает поле **Адрес ссылки** — URL, на который ведёт пиктограмма с вопросительным знаком в диалоге аутентификации.
- Перед переходом к URL добавляются параметры области данных, для которой открыт диалог; формат такой же, как у параметра `Z` командной строки клиента:

```
URL?Z="значения разделителей"
```

**Группа «Сохранение аутентификации»**

| Параметр | Назначение |
|---|---|
| Разрешить сохранение аутентификации | Добавляет в диалог аутентификации флажок «Запомнить»: пользователь может какое-то время не вводить имя и пароль |
| Время жизни сохраненной аутентификации | Срок хранения параметров аутентификации, в секундах |
| Сохранять аутентификацию по умолчанию | Вид аутентификации, которым пользователь успешно воспользовался, становится способом по умолчанию при следующем входе |

- Те же параметры можно задать в файле публикации `default.vrd`; **настройки из `default.vrd` приоритетнее** настроек диалога.
- На компьютере пользователя сохраняется не пароль, а токен: он ограничен по времени жизни и привязан к паролю — после смены пароля токен недействителен.
- При подозрении на компрометацию токена: (1) сменить пароль всем затронутым пользователям; (2) дополнительно можно запретить способ аутентификации, которым они пользовались, — но это отрежет и пользователей с нескомпрометированными паролями/токенами. Выбор зависит от масштаба компрометации, уровня доступа пользователей и прочих параметров информационной безопасности организации.
- Чтобы «забыть» сохранённую аутентификацию конкретного пользователя — сменить ему пароль (в конфигураторе или административными средствами прикладного решения). На всех устройствах, где он сохранял вход, придётся войти заново с новым паролем.
- Не рекомендуется одновременно включать сохранение аутентификации и завершение сеанса при бездействии, если последнее включено ради защиты от несанкционированного доступа: при сохранённой аутентификации принудительное завершение сеанса от такого доступа не защищает.

#### 6.2.6.3. Аутентификация через электронную почту

- Механизм включается флажком **«Использовать аутентификацию через электронную почту»** на одноимённой закладке.
- Ход входа: в диалоге выбора пользователя выбирается аутентификация через электронную почту → вводится адрес → если в ИБ есть пользователь с таким адресом, ему уходит письмо с кодом подтверждения → после ввода кода пользователь аутентифицирован.

**Параметры кода подтверждения:**

| Параметр | Назначение |
|---|---|
| Длина кода | Длина кода подтверждения аутентификации |
| Максимальное количество неуспешных попыток ввода | Сколько раз можно ошибиться; после превышения код недействителен, нужно запросить новый |
| Длительность блокировки запроса обновления кода подтверждения | Минимальный интервал между двумя подряд идущими запросами кода |
| Срок действия кода подтверждения | Время жизни высланного кода; после истечения нужен новый код |
| Алфавит кода подтверждения | Набор символов для кода. Либо пустая строка, либо от 10 до 256 различных символов. Пустая строка — десятичные цифры 0–9 |
| Использовать стандартный сервис отправки | Письмо отправляется через стандартный почтовый сервис фирмы «1С» |

**Стандартный сервис отправки:**

- отправитель, тема, формат и текст письма не настраиваются; письма приходят с адреса `1С:Подтверждение входа <authentication@1c.com>` с темой «Код подтверждения входа»;
- в ИБ должны быть заданы имя пользователя и пароль Портала ИТС. Способы:
  - конфигуратор: **Главное меню → Администрирование → Установить настройки клиента лицензирования**;
  - встроенный язык: метод глобального контекста `УстановитьНастройкиКлиентаЛицензирования()`;
  - средства прикладного решения, если оно это предусматривает.

**Группа «Параметры отправителя»** (доступна при снятом флажке стандартного сервиса). Гиперссылка «Заполнить из настроек восстановления пароля» копирует настройки почтового сервера из закладки восстановления пароля.

| Параметр | Назначение | Значения |
|---|---|---|
| Адрес сервера SMTP | Адрес SMTP-сервера | — |
| Пользователь SMTP, Пароль SMTP | Учётные данные для аутентификации на SMTP-сервере | — |
| Порт SMTP | Сетевой порт протокола SMTP | `465` — защищённые соединения (**по умолчанию**); `25` — незащищённые |
| Использовать SSL | Требование SSL при соединении с SMTP-сервером | флажок |
| Имя отправителя | Автор письма (поле From) | текст |
| Заголовок сообщения | Тема письма (поле Subject) | текст |
| Текст сообщения (гиперссылка) | Открывает редактор HTML-документа с текстом письма | допускаются псевдопеременные |

**Псевдопеременные текста письма** (в тексте перед именем ставится `&`, например `&UserPresentation`):

| Имя | Что подставляется |
|---|---|
| `ApplicationPeresentation` | Представление конфигурации текущей ИБ. ⚠ в источнике неясно: имя приведено именно в таком написании («Peresentation») в обоих разделах — возможно, опечатка документации |
| `UserName` | Имя пользователя |
| `UserPresentation` | Полное имя пользователя |
| `VerificationCode` | Код подтверждения аутентификации |

Программный доступ к настройкам: свойство глобального контекста `ДополнительныеНастройкиАутентификации`.

#### 6.2.6.4. Восстановление пароля

Настройки механизма распределены по двум местам:

- **Свойства пользователя ИБ:** «Адрес электронной почты» (на него уходит письмо с кодом для установки нового пароля) и флажок «Пользователю запрещено восстанавливать пароль» (делает невозможным восстановление по почте — только через администратора ИБ). Возможность восстановления через навигационную ссылку (веб-сайт) определяется логикой самой страницы.
- **Закладка «Восстановление пароля»** диалога дополнительных настроек аутентификации.

**Два взаимоисключающих способа** (включить оба одновременно нельзя):

| Флажок | Как работает |
|---|---|
| Переход по навигационной ссылке | В веб-браузере открывается страница из поля **Адрес ссылки**. К адресу добавляются параметры области данных в формате параметра `Z`: `URL?Z="значения разделителей"`. Вся логика восстановления реализуется на этой странице |
| Отправка кода на адрес электронной почты | Пользователь вводит адрес; если он принадлежит какому-либо пользователю ИБ, туда уходит письмо с кодом. В следующем диалоге вводятся код из письма и новый пароль |

Особенности способа с кодом:

- новый пароль проверяется по политике паролей пользователя, которому восстанавливается пароль; если политика для него не задана или политики с таким именем в ИБ нет — по политике ИБ;
- доступна гиперссылка «Сгенерировать пароль» (правила — как в 6.2.4; пароль удовлетворяет всем действующим требованиям);
- адрес, не принадлежащий ни одному пользователю, — диагностическое сообщение; пользователю запрещено восстанавливать пароль — ошибка после ввода адреса.

**OpenID:** при OpenID-аутентификации пароль меняется на стороне провайдера (аутентификация выполняется именно там); после смены происходит переход на форму аутентификации провайдера. Доступные варианты восстановления зависят от возможностей используемого OpenID-провайдера.

**Параметры закладки:**

| Параметр | Назначение |
|---|---|
| Длина кода | Длина кода подтверждения установки нового пароля |
| Максимальное количество неуспешных попыток ввода | Допустимое число ошибок; после превышения код недействителен, нужен новый код восстановления |
| Длительность блокировки запроса обновления кода подтверждения | Минимальный интервал между двумя подряд идущими запросами кода |
| Срок действия кода подтверждения | Время жизни высланного кода восстановления |
| Использовать стандартный сервис отправки | Отправка через почтовый сервис фирмы «1С»; отправитель, тема, формат и текст не настраиваются; адрес отправителя — `1C:Восстановление пароля <recoverypassword@1c.com>`. Требуются учётные данные Портала ИТС в ИБ (способы задания — те же, что в 6.2.6.3) |

- Параметра «Алфавит кода подтверждения» на этой закладке источник не описывает.
- **Группа «Параметры отправителя»** (при снятом флажке стандартного сервиса) — тот же состав, что в 6.2.6.3: Адрес сервера SMTP; Пользователь SMTP и Пароль SMTP; Порт SMTP (`465` — защищённые соединения, по умолчанию; `25` — незащищённые); Использовать SSL; Имя отправителя (From); Заголовок сообщения (Subject); Текст сообщения (редактор HTML).
- Псевдопеременные те же: `ApplicationPeresentation`, `UserName`, `UserPresentation`, `VerificationCode` (здесь — код подтверждения смены пароля); в тексте предваряются `&`.
- Программный доступ: свойство глобального контекста `ДополнительныеНастройкиАутентификации`.

#### 6.2.6.5. Проверка раскрытия пароля

Назначение: не дать пользователям задавать простые, широко известные или легко подбираемые пароли.

Настройка в двух местах:

- **источники данных** — закладка «Проверка раскрытия пароля» диалога дополнительных настроек аутентификации;
- **необходимость проверки и выполняемые действия** — параметры ИБ и политики паролей, назначенные пользователям (6.2.5.2).

**Три канала проверки** (включаются независимо, включённые работают одновременно):

| Канал | Флажок | Особенности |
|---|---|---|
| Стандартный список платформы | Использовать стандартный список проверки раскрытия пароля | Встроенный список, обновляется вместе с версией платформы. Сведения о пароле не покидают периметр ИБ |
| Пользовательский список нежелательных паролей | Использовать заданный список проверки раскрытия пароля | Свой для каждой ИБ. Заполняется из встроенного языка или командами группы «Список проверки раскрытия паролей»: **Загрузить из файла**, **Очистить**. Предельный размер — 100 000 |
| Внешний сервис | Использовать сервис проверки раскрытия паролей | Специализированный HTTP-сервис; параметры ниже |

**Параметры внешнего сервиса:**

| Параметр | Назначение |
|---|---|
| Адрес сервиса | URL сервиса |
| Таймаут запроса сервиса | Предельное время запроса; превышение считается ошибкой запроса |
| Игнорировать ошибки сервиса | Установлен — ошибка пишется только в журнал регистрации, работа продолжается так, будто внешнего сервиса нет. Снят — ошибка показывается пользователю, а проверяемый пароль **считается раскрытым** |

**Протокол обращения к сервису:**

```
GET <URL>/abcde
```

- `<URL>` — значение поля «Адрес сервиса»;
- `abcde` — первые 5 символов SHA-1-хеша проверяемого пароля (префикс хеша).

Сервис возвращает все известные ему хеши с таким префиксом; платформа сама ищет в ответе оставшуюся часть хеша. Найдена — пароль раскрыт. Полный хеш сервису не передаётся, восстановить пароль он не может.

- Такой сервис можно написать и на платформе «1С:Предприятие»: тогда база проверки ведётся централизованно и в неё можно включать слова, запрещённые именно в данной организации.
- Пример публичного сервиса — «Have I Been Pwned» (https://haveibeenpwned.com/), HTTP-интерфейс `https://api.pwnedpasswords.com/range/`; описание интерфейса: https://haveibeenpwned.com/API/v3#SearchingPwnedPasswordsByRange. Платформа ожидает от сервиса поведение, описанное по этой ссылке.

**Когда выполняется проверка раскрытия** (если механизм включён и корректно настроен):

- запись значения типа `ПользовательИнформационнойБазы`;
- создание или редактирование пользователя в конфигураторе;
- смена пароля при восстановлении пароля;
- смена пароля в процессе аутентификации;
- истёк срок действия пароля;
- выявлен факт компрометации.

Проверка раскрытия выполняется только после того, как пароль прошёл остальные проверки действующей политики. Отключённая проверка просто пропускается и остальные проверки не отменяет.

### 6.2.10. Виды аутентификации

#### 6.2.10.1. Общая информация

- **Аутентификация** — проверка того, что предъявленный идентификатор (имя) действительно принадлежит данному пользователю.
- **Авторизация** — предоставление прав на действия и подтверждение этих прав при попытке их выполнить. Документация подчёркивает, что это разные понятия.
- Платформа поддерживает несколько вариантов аутентификации. В этой части описаны четыре (сводка составлена по разделам 6.2.10.2–6.2.10.5):

| Вид | Раздел | Где работает | Чем управляется |
|---|---|---|---|
| Средствами «1С:Предприятия» (стандартная) | 6.2.10.2 | диалог аутентификации, командная строка, строка соединения | имя и пароль пользователя ИБ |
| Операционной системы | 6.2.10.3 | Windows (SSPI), Linux (GSS-API); не в клиенте macOS | поле «Пользователь» + параметры `/WA+`, `/WA-` |
| OpenID | 6.2.10.4 | только HTTP/HTTPS: веб-клиент, мобильный клиент, тонкий клиент через веб-сервер; не в толстом клиенте | `default.vrd` (элемент `<rely>`) + параметры `/OIDA+`, `/OIDA-` |
| OpenID Connect | 6.2.10.5 | тонкий, мобильный и веб-клиент | описание провайдеров в `default.vrd` |

#### 6.2.10.2. Средствами системы «1С:Предприятие» (стандартная аутентификация)

- Имя и пароль передаются одним из способов: в диалоге аутентификации; параметрами командной строки; в строке соединения с ИБ — для внешнего соединения или automation-сервера.
- Существование пользователя и правильность пароля проверяет сама платформа.

#### 6.2.10.3. Операционная система

- Аутентификация неявная: пользователю ИБ сопоставляется пользователь ОС.
- При старте платформа запрашивает у ОС текущего аутентифицированного пользователя: в Windows — через интерфейс **SSPI**, в Linux — через **GSS-API**. Затем ищет пользователя ИБ, которому сопоставлен этот пользователь ОС. Найден — аутентификация успешна, диалог аутентификации не показывается.

**Ограничения:**

- клиентское приложение для macOS аутентификацию ОС не поддерживает;
- аутентификация ОС не поддерживается, если клиент подключается к ИБ через веб-сервер **Apache, работающий под Windows**;
- только Windows: для стабильной работы аутентификации ОС при подключении тонким клиентом через веб-сервер или веб-клиентом адрес ИБ нужно внести в список надёжных сайтов в свойствах веб-браузера.

**Формат имени пользователя ОС:** `\\имя_домена\имя_пользователя`.

- Имя пользователя не должно содержать символов нелатинских алфавитов.
- Точный вид имени домена и пользователя может зависеть от настроек контроллера домена и учётных записей в нём.
- Как узнать правильное написание: в технологическом журнале найти событие `CONN`, у которого свойство `Txt` начинается с `Srvr: DstUserName2:`.

Пример события из документации:

```
30:30.551013-0,CONN,2,process=rmngr,OSThread=24204,t:clientID=3,Txt=Srvr: DstUserName2: d1.d2\user1(d1.d2\user1)
```

Для такого события в свойствах пользователя ИБ нужно указать `\\d1.d2\user1`.

**Параметры командной строки клиента:**

| Параметр | Действие |
|---|---|
| `/WA-` | Принудительно использовать аутентификацию средствами «1С:Предприятия» |
| `/WA+` | Принудительно применять аутентификацию средствами ОС (**действует по умолчанию**) |

#### 6.2.10.4. С помощью OpenID

- OpenID (https://openid.net/) — протокол единой учётной записи для не связанных между собой ресурсов. Платформа использует протокол на основе **OpenID версии 2.0, модель Direct Identity**.
- Не применяется при обращении к веб-сервисам, опубликованным из «1С:Предприятия».

**Схема работы:**

1. Пользователь пытается войти в систему.
2. По файлу публикации `default.vrd` система определяет, что для ИБ включена OpenID-аутентификация.
3. Провайдеру OpenID уходит запрос на аутентификацию. Провайдер должен быть доступен с того адреса, где опубликована ИБ.
4. Если нужно интерактивное действие (первая аутентификация для данного идентификатора либо истёк срок жизни его аутентификационных данных), провайдер сообщает об этом; система запрашивает имя и пароль и возвращает их провайдеру.
5. Провайдер аутентифицирует пользователя и возвращает системе признак успешной аутентификации.

- Аутентификационные данные хранятся в файлах cookie — в хранилище, отдельном для каждого веб-браузера; у тонкого клиента хранилище собственное.
- Работает только при доступе к ИБ по **HTTP и HTTPS**, то есть в веб-клиенте, мобильном клиенте и в тонком клиенте, подключённом через веб-сервер.
- Кросс-доменные запросы при OpenID-аутентификации возможны в тонком клиенте и в браузерах Mozilla Firefox, Google Chrome и Safari.

**OpenID-провайдер:**

- им может быть ИБ «1С:Предприятия», специальным образом опубликованная на веб-сервере, либо сторонняя система, реализующая протокол OpenID Authentication 2.0 и его расширение, принятое в платформе;
- адрес провайдера задаётся в `default.vrd` — элемент `<rely>` — при публикации ИБ, выступающей клиентом провайдера.

**Сопоставление пользователей:** ключевое поле — свойство **Имя** пользователя ИБ. Вход возможен, если в «Имя» записан идентификатор, который возвращает провайдер (что именно возвращается — смотреть в документации провайдера).

**Пароль:**

- задаётся у провайдера. Если провайдер — ИБ «1С:Предприятия», пароль задаётся в этой ИБ; у стороннего провайдера — его средствами;
- пароль, заданный в ИБ — клиенте провайдера, при OpenID-аутентификации игнорируется;
- после смены пароля в хранилище провайдера: текущие сеансы пользователя остаются аутентифицированными до завершения; при создании нового сеанса пароль будет запрошен, даже если аутентификационные данные ещё не устарели.

**Параметры командной строки клиента:**

| Параметр | Действие |
|---|---|
| `/OIDA+` | Принудительно выполнять аутентификацию через OpenID (**действует по умолчанию**) |
| `/OIDA-` | Принудительно отключить аутентификацию через OpenID (в текстовой копии источника знак после `/OIDA` набран типографским дефисом) |

**Что не работает при OpenID:** окно с требованием сменить пароль не показывается, когда срок действия пароля истёк, когда он скоро истечёт и когда пароль при аутентификации не соответствует требованиям (при включённой проверке надёжности пароля) — эти механизмы OpenID-аутентификацией не поддерживаются.

Связанные материалы: спецификация OpenID Authentication 2.0 — https://openid.net/specs/openid-authentication-2_0.html; настройка веб-сервера для OpenID и дополнительные требования к OpenID-провайдеру — в других разделах документации.

#### 6.2.10.5. С помощью OpenID Connect

- OpenID Connect (https://openid.net/connect/) — расширение протокола OAuth 2.0; платформа проверяет личность пользователя по результату аутентификации у стороннего провайдера.
- Применим в тонком клиенте, мобильном клиенте и веб-клиенте.
- «1С:Предприятие» **не может быть провайдером** OpenID Connect — только внешние провайдеры.
- Поддержка протокола даёт возможность использовать Единую систему идентификации и аутентификации (ЕСИА).

**Сопоставление пользователей:**

| Сторона | Ключ по умолчанию | Что можно настроить |
|---|---|---|
| Провайдер аутентификации | адрес электронной почты | при настройке доступа к провайдеру указывается, какое поле токена аутентификации считать ключевым |
| «1С:Предприятие» | свойство **Имя** пользователя ИБ | вместо него — свойство `ПользовательОС`, `АдресЭлектроннойПочты` или значение из коллекции `КлючиСопоставленияПользователя` |

Коллекция `КлючиСопоставленияПользователя` заполняется только из встроенного языка. Пример из документации (пробел после точки во второй строке — как в источнике):

```bsl
ПользовательИБ = ПользователиИнформационнойБазы.Найти(КодПользователя);
ПользовательИБ. КлючиСопоставленияПользователя.Вставить("googleIV", "user-name@google.com");
ПользовательИБ.Записать();
```

- Элемент коллекции сработает, если в списке провайдеров в `default.vrd` описан провайдер со свойством `name`, равным `googleIV`.
- Пользователь из примера будет выбран при запуске сеанса, если поле сопоставления в токене, возвращённом провайдером, равно `user-name@google.com`.
- Описание провайдера `googleIV` приведено в документации в примере к элементу `openidconnect.providers` файла `default.vrd`.

**Разделённые ИБ:** OpenID Connect (включая ЕСИА) поддерживается; значения разделителей участвуют в определении аутентифицированного пользователя. Чтобы они использовались, может потребоваться дополнительная настройка в `default.vrd` — параметр `redirect_uri` в описании провайдера.

**Мобильный клиент:** аутентификация выполняется через веб-браузер устройства.

| ОС | Требование |
|---|---|
| Android | веб-браузер Google Chrome |
| iOS | версия 9.0 и новее |

- Если устройство требованиям не соответствует, пользователю может понадобиться заново проходить аутентификацию у провайдера в мобильном клиенте.
- Чтобы принудительно пройти аутентификацию при следующем входе, в мобильном клиенте выполняют команду «Завершить работу».

Связанные материалы: схема работы с провайдером OpenID Connect и описание файла `default.vrd` — в других разделах документации.

## Что важно администратору Linux

1. **Аутентификация ОС на Linux идёт через GSS-API** (в Windows — SSPI). Имя в поле «Пользователь» задаётся как `\\домен\пользователь`, только латиницей, не длиннее 128 символов.
2. **Точное написание имени пользователя ОС берётся из технологического журнала**: событие `CONN`, свойство `Txt`, начинающееся с `Srvr: DstUserName2:` (в примере документации — `process=rmngr`). Значение `d1.d2\user1` из события записывается как `\\d1.d2\user1`.
3. Если нужно войти под именем и паролем 1С, минуя учётную запись ОС, клиент запускают с `/WA-`; `/WA+` действует по умолчанию. Для OpenID аналогично: `/OIDA+` (по умолчанию) и `/OIDA-`.
4. **В ИБ всегда должен оставаться хотя бы один администратор с аутентификацией «1С:Предприятия»**. Пользователь со всеми снятыми флажками «Аутентификация…» войти не может.
5. OpenID, OpenID Connect и вход по QR-коду требуют настройки публикации на веб-сервере (`default.vrd`); OpenID работает только по HTTP/HTTPS и недоступен в толстом клиенте. OpenID-провайдер должен быть доступен с адреса публикации ИБ.
6. Ограничение на аутентификацию ОС через веб-сервер в этой части сформулировано только для **Apache под Windows**; про Apache под Linux здесь ничего не сказано.
7. Для ИБ, опубликованных в Интернет, и для баз с большим числом пользователей — снять «Показывать в списке выбора» у всех, прежде всего у администраторов.
8. Параметры сохранения аутентификации из `default.vrd` **приоритетнее** настроек, сделанных в конфигураторе. Чтобы сбросить сохранённый вход пользователя, ему меняют пароль. Сохранение аутентификации не рекомендуется сочетать с завершением сеанса при бездействии.
9. Все сроки политики паролей (максимальный, минимальный, срок предупреждения) задаются **в секундах**; 0 отключает параметр. То же значение 0 отключает запрет повторения паролей.
10. Включение проверки сложности паролей не меняет существующие пароли, но делает их проверку **регистрозависимой** — пользователи, вводившие пароль не в том регистре, перестанут входить.
11. Действие `ПотребоватьСменуПароля` вместе с флажком «Пользователю запрещено изменять пароль» приводит к исключению и невозможности входа.
12. Для отправки кодов (вход по почте, восстановление пароля) нужен либо стандартный сервис «1С» с учётными данными Портала ИТС в ИБ, либо свой SMTP-сервер: порт `465` (защищённый, по умолчанию) или `25` (незащищённый), флажок «Использовать SSL». У каждого пользователя адрес почты должен быть уникальным.
13. Внешний сервис проверки раскрытия паролей вызывается запросом `GET <URL>/<первые 5 символов SHA-1>`. При снятом флажке «Игнорировать ошибки сервиса» любая ошибка или таймаут запроса означает, что пароль считается раскрытым; при установленном — ошибка только фиксируется в журнале регистрации.
14. Размер пользовательского списка нежелательных паролей ограничен значением 100 000, список ведётся отдельно в каждой ИБ; стандартный список платформы обновляется вместе с версией платформы.
15. «1С:Предприятие» не может выступать провайдером OpenID Connect; по умолчанию сопоставление идёт по адресу электронной почты у провайдера и свойству «Имя» пользователя ИБ. Для разделённых ИБ может понадобиться параметр `redirect_uri` в описании провайдера в `default.vrd`.
