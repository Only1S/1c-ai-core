## 1.1. Требования к аппаратуре

### 1.1.1. Общая информация

- Раздел задаёт МИНИМАЛЬНЫЕ характеристики компьютеров, на которых работает «1С:Предприятие».
- Компьютеры Apple: поддерживаются и процессоры x86-64, и процессоры Apple; на процессорах Apple — только в режиме трансляции, что может сказываться на производительности.
- Реально необходимая конфигурация оборудования зависит не только от вида клиентского приложения, но и от:
  - установленного ПО;
  - размера и количества информационных баз;
  - числа подключённых пользователей;
  - используемой конфигурации (прикладного решения);
  - доработок конфигурации;
  - расширений конфигурации;
  - задействованных механизмов платформы (пример из документации — Дата акселератор) и прочего.
- Рекомендации: не ограничиваться минимальными требованиями, а оценивать оборудование на практике; при внедрениях с большим числом пользователей проводить тестирование, сравнивать результат с желаемой производительностью и корректировать требования.
- Методика расчёта параметров серверного оборудования: https://its.1c.ru/db/metod8dev#content:5810
- Актуальные системные требования с текущими уточнениями: http://www.v8.1c.ru/requirements/

## 1.4. Прочие требования

### 1.4.1. Общие требования

Java на компьютерах кластера серверов:
- Для части механизмов платформы на компьютерах с кластером серверов нужна Java версии 1.8 или последующих.
- Разрядность Java должна совпадать с разрядностью кластера серверов «1С:Предприятия».
- Рекомендуемый дистрибутив — Liberica.

Механизмы, которым нужна Java:

| Механизм | Примечание |
|---|---|
| Утилита `ring` и связанные с ней утилиты | пример — утилита лицензирования `ring license` |
| Полнотекстовый поиск в данных, версия 2 | — |

В клиент-серверном варианте установленную Java могут требовать и другие (дополнительные) компоненты системы.

### 1.4.2. Для ОС Linux

Для отдельных возможностей системы могут понадобиться библиотеки:

| Библиотека | Имя загружаемой библиотеки | Версия | Для чего нужна |
|---|---|---|---|
| fontconfig | `libfontconfig` | 2.3.0 и выше | работа сервера «1С:Предприятия» в управляемом режиме; использование на сервере объектов `Диаграмма`, `ГрафическаяСхема`, `ТабличныйДокумент`; сохранение в PDF |
| unixOdbc | `libodbc` | 2.2.11 и выше | работа с внешними источниками данных |
| Kerberos | `libkrb5` | 1.4.2 и выше | аутентификация средствами ОС |
| GSS-API Kerberos | `libgssapi_krb5` | 1.4.2 и выше | аутентификация средствами ОС |
| Microsoft Core Fonts | — (в источнике имя библиотеки, версия и назначение не указаны) | — | — |

Как платформа ищет и загружает библиотеку:
- Имя файла формируется по шаблону `<имя загружаемой библиотеки>.so.X.Y`, где:
  - `<имя загружаемой библиотеки>` — значение из таблицы выше;
  - `so` — признак файла библиотеки;
  - `X.Y` — цифры суффикса той библиотеки, которая присутствует в системе.
- Используются только библиотеки, зарегистрированные в системном кеше динамического линковщика времени выполнения. Посмотреть содержимое кеша:

```
ldconfig -p
```

- Если в системе несколько версий одной библиотеки, загружается самая старшая.

### 1.4.3. Для ОС Windows

Только Windows, кратко:
- Пользователь, от имени которого запущено клиентское приложение, должен иметь право «Список содержимого папки» на каталог временных файлов.
- Для программного лицензирования должна быть запущена служба WMI (Windows Management Instrumentation, https://msdn.microsoft.com/en-us/library/aa394582.aspx).
- После установки некоторых шрифтов может понадобиться перезагрузка того компьютера, где шрифт используется: клиентского — если шрифт использует клиентское приложение, серверного — если сервер.
- Windows 10 через «Подключение к удаленному рабочему столу»: рекомендуется снять флажок «Визуальные эффекты при отображении меню и окон» (дополнительные параметры подключения, закладка «Взаимодействие»).
- Невизуальная доступность интерфейса — на Windows 7 и последующих. Требуется Microsoft UI Automation; рекомендуется программа экранного доступа NVDA (https://www.nvaccess.org/); для русского языка — синтезатор речи RHVoice (https://github.com/Olga-Yakovleva/RHVoice).
- Невизуальная доступность обеспечивается: в управляемых формах; в интерфейсе «Такси» при любом механизме размещения элементов форм; в тонком и толстом клиентских приложениях. Рекомендации по построению интерфейса под программы экранного доступа — в другой книге документации (ссылка без адреса).

## 1.5. Ограничения

Файловая информационная база:
- Совместно работать с файловой ИБ могут только клиентские приложения ОДНОЙ версии. Разрядность (32 или 64) и ОС (Windows или Linux) клиентского приложения при этом не ограничиваются.
- Максимум одновременных соединений с одной файловой ИБ — 1024.
- Совместная работа с файловой ИБ по сети поддерживается только для сетевых ресурсов с доступом по протоколу SMB (CIFS). Сам ресурс может находиться как на компьютере с Windows, так и на компьютере с Linux.
- Клиентское приложение под macOS не поддерживает работу с ИБ, расположенной на сетевом ресурсе.

Разрядность внешних компонент и COM-объектов:
- Разрядность внешних компонент и COM-объектов (COM — при работе под Windows) должна совпадать с разрядностью и типом используемого приложения «1С:Предприятия» (тонкий или толстый клиент, сервер, веб-браузер). Пример: COM-объект, существующий только в 32-разрядном варианте, нельзя использовать в 64-разрядной версии платформы.

Ограничения по архитектурам процессоров:

| Ограничение | ARM64 | E2K |
|---|---|---|
| Работа под управлением ОС Windows | не поддерживается | не поддерживается |
| Аппаратные ключи защиты | не поддерживаются | не поддерживаются |
| Автоматическое обновление клиентского приложения | не поддерживается | не поддерживается |
| Процессоры Apple | только в режиме трансляции | — (в источнике не упоминается) |

## 1.6. Варианты платформы и лицензий

### 1.6.1. Общая информация

У платформы несколько вариантов поставки и несколько видов лицензий; вид лицензии определяет, какие возможности платформы разрешено использовать. Далее — перечень вариантов поставки и лицензий.

### 1.6.2. Варианты поставки

| Вариант поставки | Нужна ли лицензия | Суть |
|---|---|---|
| Обычная версия платформы | да | возможности могут ограничиваться имеющимися лицензиями |
| Учебная версия (https://v8.1c.ru/edu/) | нет | набор ограничений — см. ниже |
| «1С:Предприятие — Работа с файлами» (https://v8.1c.ru/metod/fileworkshop.htm) | нет | только просмотр файлов, без работы с ИБ — см. ниже |

Ограничения учебной версии (полный перечень):
- нельзя вести реальный учёт на предприятии;
- нельзя собирать дистрибутивы мобильных приложений для последующей публикации и тиражирования;
- лимиты объёма данных:

| Что ограничено | Максимум |
|---|---|
| записей в таблицах счетов | 2 000 |
| записей в главных таблицах объектов | 2 000 |
| записей в табличных частях объектов | 1 000 |
| записей в наборах записей | 2 000 |
| записей из внешних источников данных | 200 |

- нет клиент-серверного варианта;
- нет распределённых информационных баз;
- нет локального распознавания речи;
- нет COM-соединения;
- для пользователей нельзя использовать пароли и аутентификацию операционной системы;
- печать и сохранение табличных документов — только в режиме Конфигуратора;
- в режиме 1С:Предприятия нельзя копировать содержимое более чем одной ячейки табличного документа;
- быстродействие ниже, чем у коммерческой версии;
- нет работы с хранилищем конфигурации;
- недоступна функциональность, связанная с поставкой конфигурации;
- одновременно с информационной базой работает не более одного сеанса;
- значения разделителей — только значения по умолчанию для данного типа разделителя.

«1С:Предприятие — Работа с файлами»:
- с информационными базами «1С:Предприятия» не работает;
- открывает и показывает файлы: табличный документ, текстовый документ, графическая схема, географическая схема, HTML-документ.

### 1.6.3. Виды лицензий

#### 1.6.3.1. Общая информация

Для работы «1С:Предприятия» (кроме учебной версии) нужны лицензии; разным элементам системы — разные. Ниже описаны возможные варианты.

#### 1.6.3.2. Клиентская лицензия

Назначение: нужна для работы клиентского приложения в любом варианте — и файловом, и клиент-серверном.

| Вид | Что даёт / чем ограничена |
|---|---|
| Клиентская лицензия КОРП | все возможности системы |
| Клиентская лицензия ПРОФ | возможности системы в пределах ограничений серверной лицензии ПРОФ (см. 1.6.3.3) |
| Клиентская лицензия «1С:Аналитика» | работа с системой «1С:Аналитика» — см. ниже |
| Базовая лицензия | набор жёстких ограничений — см. ниже |

Клиентская лицензия «1С:Аналитика»:
- позволяет работать с «1С:Аналитикой» нескольким пользователям одновременно (один сеанс — один пользователь); число одновременных сеансов не больше номинала лицензии;
- совместима с любой серверной лицензией «1С:Предприятия»;
- если в информационной базе одновременно обслуживается не более 5 сеансов клиентских приложений, то технически и лицензионно допускается 1 сеанс «1С:Аналитики» без клиентской лицензии «1С:Аналитики»;
- при серверной лицензии уровня ПРОФ клиентская лицензия «1С:Аналитики» разрешает использовать механизм копий базы данных совместно с Дата акселератором; Дата акселератор при этом может быть запущен только в одном экземпляре.

Ограничения базовой лицензии (полный перечень):
- одновременно с системой работает 1 пользователь;
- нельзя редактировать конфигурацию в конфигураторе;
- нет клиент-серверного варианта;
- нет работы в распределённой информационной базе;
- нет предоставления интернет-сервисов;
- нет режима веб-клиента;
- нет режима внешнего соединения;
- нет работы с расширениями.

#### 1.6.3.3. Серверная лицензия

Назначение: нужна для работы кластера серверов «1С:Предприятия», то есть для клиент-серверного варианта. Клиентские лицензии в клиент-серверном варианте нужны дополнительно к серверной.

| Вид | Разрядность сервера | Суть |
|---|---|---|
| КОРП | только 64-разрядный сервер | доступны все возможности сервера. Информация: https://1c.ru/news/info.jsp?id=18887 |
| ПРОФ | 32- и 64-разрядный сервер | все возможности сервера, кроме перечня ниже |
| МИНИ | 32- и 64-разрядный сервер | ограничения ПРОФ плюс собственные (см. ниже). Информация: https://www.1c.ru/news/info.jsp?id=17577 |

Серверная лицензия ПРОФ — что покрывает на одном физическом компьютере:
- лицензия 32-разрядного сервера: произвольное число 32-разрядных рабочих процессов;
- лицензия 64-разрядного сервера: произвольное число 32- и 64-разрядных рабочих процессов.

Что НЕДОСТУПНО при любой серверной лицензии ПРОФ (полный перечень; каждая позиция в документации снабжена ссылкой «см. здесь» без адреса):

#### 1.6.3.4. Расширения лицензий

Расширение лицензии уровня ПРОФ (информация: https://www.1c.ru/news/info.jsp?id=25491):
- Применимо, если «1С:Предприятие» приобретено ранее 11.02.2019. Позволяет снять два ограничения ПРОФ: «более 500 сеансов в одной ИБ» и «более 12 ядер процессора для процессов кластера».
- Порядок зависит от системы защиты:
  - программная лицензия — обновление происходит автоматически, действий не требуется;
  - ключ защиты HASP — нужно бесплатно получить на портале 1С:ИТС специальные программные лицензии расширения уровня ПРОФ. При активации такая лицензия обязательно привязывается к произвольному доступному аппаратному ключу защиты «1С:Предприятия» (клиентскому или серверному) и работает только вместе с той аппаратной лицензией, для которой получена. Инструкция по обновлению выдаётся вместе с пинкодом.

Расширение лицензии уровня КОРП (информация: https://www.1c.ru/news/info.jsp?id=25491):
- Начиная с 10.09.2019 все возможности аппаратной лицензии КОРП (ключ HASP) доступны только после её расширения специальной программной лицензией. Её получают дополнительно через Центр лицензирования фирмы «1С».
- При активации лицензия расширения обязательно привязывается к произвольному доступному аппаратному ключу защиты (клиентскому или серверному) и используется только совместно с той аппаратной лицензией КОРП, для которой получена. Инструкция по получению выдаётся вместе с пинкодом.
- Если лицензия КОРП программная — ничего делать не нужно.

#### 1.6.3.5. Лицензия сервера системы взаимодействия

- Назначение: развёртывание собственного экземпляра сервера системы взаимодействия.
- Информация: https://1c.ru/news/info.jsp?id=26598
- Собственный экземпляр можно развернуть при выполнении ЛЮБОГО из условий:
  - есть серверная лицензия КОРП;
  - есть программный продукт «1С:Сервер взаимодействия».

#### 1.6.3.6. Лицензия для разработчиков (community версия)

- Назначение: полноценная разработка на платформе без покупки лицензий. Платформу с активированной лицензией для разработчиков нельзя использовать в коммерческих системах.
- Информация: https://1c.ru/news/info.jsp?id=30506

Особенности:

| Свойство | Значение |
|---|---|
| Версия платформы | только 8.3.23 и последующие |
| Форма | только программная лицензия |
| Активация | одновременно на 1 клиентский и 1 серверный компьютер (это могут быть разные компьютеры) |
| Срок действия | 1 неделя; обновляется автоматически при наличии подключения к Интернету |
| Суммирование | лицензии для разработчиков не суммируются |
| Смешанная работа с ПРОФ/КОРП | если к ИБ подключены сеансы на лицензиях ПРОФ или КОРП, то к одной ИБ одновременно может быть подключено не более 3 (включительно) клиентских сеансов, получивших одну лицензию для разработчиков |
| Когда используется, файловая ИБ | если не найдена никакая другая лицензия (базовая, ПРОФ или КОРП) |
| Когда используется, клиент-серверная ИБ | если не найдена никакая другая лицензия (ПРОФ или КОРП); может выступать одновременно и клиентской, и серверной |
| Статистика | собирается и отправляется в Центр Контроля Обновлений: статистика использования механизмов платформы; пользовательские данные ИБ не передаются. Собирается с компьютера разработчика из приложения, использующего активированную лицензию |

Разрешает:
- совместную работу в одной информационной базе следующих сеансов (лицензии раздаёт сервер «1С:Предприятия»):
  - не более 3 сеансов с прямым подключением;
  - не более 1 сеанса через веб-сервер;
  - не более 1 сеанса клиента «1С:Аналитики»;
  - не более 1 сеанса мобильного клиента;
- функциональность лицензии типа КОРП, если с информационной базой работает не более 10 лицензируемых сеансов.

Не разрешает:
- коммерческое использование;
- доступ к механизмам, требующим лицензию для тестирования выделенной функциональности;
- привязку лицензии к аппаратному ключу защиты;
- более 2 разных лицензий для разработчиков в одной информационной базе;
- более 1 рабочего сервера в кластере: при добавлении рабочего сервера выдаётся ошибка; если в кластере уже есть более одного рабочего сервера, работать будет только один (произвольный);
- использование клиентских лицензий ПРОФ или КОРП для доступа к кластеру серверов, у которого серверной лицензией служит лицензия для разработчиков.

#### 1.6.3.7. Лицензия для тестирования выделенной функциональности

- Назначение: тестирование механизмов в статусе бета-тестирования (выделенной функциональности). Является ДОПОЛНЕНИЕМ к клиентской или серверной лицензии любого вида.
- Информация: http://1c.ru/news/info.jsp?id=25182
- Получение: запрос по электронной почте на betaplatform@1c.ru

Особенности:
- Активируется на компьютер:
  - кластера серверов «1С:Предприятия»;
  - расширения веб-сервера, работающего с файловой ИБ, в которой используется выделенная функциональность;
  - клиентского приложения, работающего с файловой ИБ, в которой используется выделенная функциональность.
- Может раздаваться сервисом лицензирования кластера серверов.
- Необходимое количество:
  - клиент-серверный вариант — не меньше числа серверных лицензий кластера, на котором идёт тестирование;
  - файловый вариант — хотя бы одна.
- Не заменяет обычную лицензию: без соответствующей серверной или клиентской лицензии кластером или клиентским приложением пользоваться нельзя.
- Какие возможности требуют такой лицензии — определяется при выпуске версии платформы.
- Окончательные лицензионные требования к тестируемым механизмам определяются в момент их вывода из статуса бета-версии.

### 1.6.4. Применимость лицензии КОРП

Правило «до 10 сеансов»:
- Все возможности системы, включая относящиеся к КОРП, КРОМЕ Дата акселератора, доступны, если к КАЖДОЙ информационной базе кластера одновременно подключено не более 10 клиентских сеансов. Серверная и все клиентские лицензии при этом могут быть уровня ПРОФ.
- При подключении 11-го сеанса хотя бы к одной из баз кластера этот сеанс получит ошибку, если в кластере используются возможности уровня КОРП, а лицензий КОРП недостаточно.
- Если возможности КОРП используются и число сеансов пользователей одной ИБ превышает 10, новый сеанс в этой ИБ начнётся только при достаточном количестве клиентских и серверных лицензий КОРП.

Когда количество лицензий КОРП считается достаточным: все серверные лицензии, используемые кластером, имеют уровень КОРП, И дополнительно выполняется одно из двух:
1. Клиентское приложение получило клиентскую лицензию КОРП.
2. Клиентское приложение получило лицензию ПРОФ, и в момент подключения нового клиентского соединения выполняется соотношение:

```
УП <= 1,1 * ЛК
```

где:
- `УП` — число уникальных пользователей (уникальность — по именам пользователей) клиентских сеансов кластера с любыми видами лицензий, включая начинающийся сеанс;
- `ЛК` — число клиентских лицензий КОРП, доступных для выдачи сервером «1С:Предприятия» (независимо от фактического состояния флага выдачи лицензий сервером).

Пример из документации: на компьютере с сервером установлены серверная лицензия КОРП и клиентская лицензия КОРП на 50 пользователей. Тогда:
- число клиентских подключений произвольно, если у каждого подключения лицензия уровня КОРП;
- клиент с лицензией ПРОФ подключится, только если после подключения сервер будет обслуживать сеансы не более чем 1,1 * 50 = 55 уникальных пользователей (считая стартующий сеанс).

Оговорка документации: техническая возможность входа небольшой доли пользователей с лицензиями ПРОФ в систему, использующую возможности КОРП, сделана как страховка от массового отказа в обслуживании из-за случайной ошибки или недосмотра. Правомерной работа пользователей с лицензиями ПРОФ в системе уровня КОРП при этом не считается.

## Что важно администратору Linux

1. Ubuntu 20.04 LTS, 22.04 LTS и 24.04 LTS входят в перечень поддерживаемых ОС (и для x86-64, и для ARM64). Но этот перечень в главе 1 дан в таблицах КЛИЕНТСКИХ компьютеров; отдельного списка ОС для кластера серверов и списка поддерживаемых версий PostgreSQL здесь нет — актуальные требования нужно смотреть на http://www.v8.1c.ru/requirements/, расчёт серверного железа — по методике https://its.1c.ru/db/metod8dev#content:5810.
2. На сервере кластера нужна Java 1.8 или новее той же разрядности, что и кластер (рекомендуется Liberica), если используются утилита `ring` / `ring license` или полнотекстовый поиск версии 2.
3. Библиотеки на Linux-сервере: `libfontconfig` (2.3.0+) — для управляемого режима сервера, серверного формирования `Диаграмма` / `ГрафическаяСхема` / `ТабличныйДокумент` и сохранения в PDF; `libodbc` (unixOdbc 2.2.11+) — внешние источники данных; `libkrb5` и `libgssapi_krb5` (1.4.2+) — аутентификация средствами ОС; плюс Microsoft Core Fonts.
4. Платформа берёт библиотеки только из кеша динамического линковщика и грузит самую старшую версию из имеющихся. Проверка наличия — `ldconfig -p`; библиотека, лежащая вне кеша, использована не будет.
5. Поддерживаемые веб-серверы — IIS (Windows) и Apache HTTP Server 2.0 / 2.2 / 2.4. Если через веб-сервер на Linux публикуется файловая база с внешними источниками данных, unixOdbc 2.2.11+ нужен на машине веб-сервера. Минимум для машины веб-сервера, обслуживающего файловую базу (независимо от внешних источников): Celeron 2 700 МГц, 4 Гбайт ОЗУ (рекомендуется 8), около 1 Гбайт на диске.
6. Серверная лицензия ПРОФ: кластер использует не более 12 ядер (ядра виртуальной машины считаются как ядра) и не более 500 сеансов в одной ИБ. Для систем, купленных до 11.02.2019, эти два ограничения снимаются расширением лицензии ПРОФ (для программной лицензии — автоматически, для HASP — через получение лицензии расширения на портале 1С:ИТС).
7. Под ПРОФ недоступны, в частности: фоновое обновление конфигурации БД, профили безопасности, дополнительное управление распределением сервисов кластера и соединений с ИБ по рабочим серверам, параметры «Безопасный расход памяти за один вызов» и «Количество ИБ на процесс», режим «Приоритет по памяти», копии базы данных, пользовательские табличные пространства, произвольные индексы, хранилище двоичных данных (включая S3), HTTP-сервис метрик OpenMetrics, управление потреблением ресурсов, аудит прав доступа, внешнее управление сеансами, смена каталога данных сервисов кластера. Полный перечень — таблица в 1.6.3.3.
8. Исключение «до 10 сеансов»: пока к каждой ИБ кластера подключено не более 10 клиентских сеансов, возможности КОРП (кроме Дата акселератора) работают и на лицензиях ПРОФ. 11-й сеанс при использовании возможностей КОРП без достаточных лицензий КОРП получит ошибку — это надо учитывать, включая КОРП-функции на небольшой базе.
9. Серверная лицензия КОРП существует только для 64-разрядного сервера. Аппаратная лицензия КОРП (HASP) с 10.09.2019 полноценно работает только после расширения программной лицензией из Центра лицензирования.
10. Серверная лицензия МИНИ: один рабочий сервер в кластере, не более 5 клиентских сеансов и 1 сеанс конфигуратора, без «1С:Аналитики», плюс все ограничения ПРОФ.
11. ARM64 и E2K: требуется лицензия КОРП, не работают аппаратные ключи защиты и автоматическое обновление клиентского приложения, Windows на этих архитектурах не поддерживается.
12. Файловая база: все клиенты должны быть одной версии платформы (разрядность и ОС могут различаться), максимум 1024 одновременных соединения, сетевой доступ только по SMB (CIFS); ресурс может лежать и на Linux. Клиент под macOS с базой на сетевом ресурсе не работает.
13. Разрядность внешних компонент должна совпадать с разрядностью и типом того приложения платформы, в котором они загружаются (сервер, тонкий/толстый клиент, браузер).
14. Лицензия для разработчиков (community): платформа 8.3.23+, только программная, срок 1 неделя с автопродлением через Интернет, не более 1 рабочего сервера в кластере, некоммерческое использование; клиентские лицензии ПРОФ/КОРП к такому кластеру подключать нельзя.
15. Веб-клиент на Linux: Chromium-gost 64+, Chrome 64+, Edge 19+, Firefox 68+, Яндекс.Браузер 22+; для внешних компонент и расширений работы с файлами и криптографией нужна GTK-3. PWA — только по HTTPS с действительным сертификатом (Chrome 73+, Edge 73+, Яндекс.Браузер 22+).
