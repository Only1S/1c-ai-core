# ИТС-конспект: отличия документации 1С:Предприятие 8.5.1 от 8.3.27
> Источник: автоматическое сравнение документации its.1c.ru/db/v851doc и its.1c.ru/db/v8327doc (книги «Руководство администратора» и «Клиент-серверный вариант. Руководство администратора»). Документация тестовой версии 8.5.4 была недоступна. Составлено 2026-10-10.

## Как читать этот конспект

- Сравнение построчное, внутри одной главы: в него попали абзацы 8.5.1, которых **дословно** нет в той же главе 8.3.27. Старую редакцию абзаца сравнение не показывает — она найдена вручную по полным текстам глав 8.3.27.
- **Удалённые** из 8.5.1 абзацы сравнение не показывает вообще. Там, где об удалении можно только догадываться, стоит пометка «⚠ в источнике неясно».
- Сравнивались 18 глав: adm-gl01, gl02, gl04, gl05, gl06, gl07, gl08, gl10, pr03, pr04, pr06, pr07 и cs-gl01, gl02, gl03, gl04, gl05, pr03. По остальным главам обеих книг файлов сравнения не было.
- Обозначение «было → стало» везде означает «в документации 8.3.27 → в документации 8.5.1».
- Если абзац отличался только типом тире (`–` → `-`), номером страницы, номером версии в примере или исправленной опечаткой — он вынесен в раздел «Отфильтрованный шум» в конце.

## Кратко: главное для администратора Linux

1. **Изменений в двух административных книгах мало.** Основная масса — переименование 8.3 → 8.5 (COM-объекты, имя службы Windows, режим интерфейса) и перестройка глав с системными требованиями. Новых требований к библиотекам Linux, Java, правам пользователя, порядку установки пакетов и к юнитам systemd сравнение не выявило.
2. **Списки поддерживаемых ОС вынесены в единые разделы**: для клиентов — «1.1.2.1. Поддерживаемые операционные системы» (Руководство администратора), для кластера — «1.1.2. Поддерживаемые операционные системы» (Клиент-серверный вариант). Ни одна строка с дистрибутивами Linux не помечена как новая или изменённая: в 8.5.1 нет дистрибутивов и версий Linux, которых не было бы в тех же главах 8.3.27. Что из старых списков исключено — сравнение не показывает (⚠ сверить вручную).
3. **PostgreSQL: список версий не менялся.** В разделе «PostgreSQL» (был 1.5.8, стал 1.3.9) нет ни одной новой или изменённой строки. В 8.3.27 значилось: 8.1.5, 8.2.4, 8.3.8, 8.4.3, 9.0.3, 9.1 ‑ 9.6, 10 ‑ 18.
4. **Новая СУБД — Jatoba** (раздел 1.3.4): версии 6.13.1 и 18.3.1; не поддерживается при кластере на процессорах x86 и E2K.
5. **Pangolin**: появилась строка «Версии 6.4.2, 6.5.1» (в 8.3.27 была только версия 5.3.2). В таблицу «СУБД \ архитектура процессора» добавлены строки Arenadata Prosperity, Jatoba, Nexign NORD.
6. **Установка PostgreSQL (cs 3.2.5.1)**: перечень «PostgreSQL 8.1.5-X.1C ‑ 9.1.2-1.1C; 9.2.1-2.1C; стандартная версия» заменён одной фразой — работа возможна с кластером, созданным стандартной версией PostgreSQL, при совпадении locale кластера и создаваемой базы.
7. **Запуск сервера под Linux: изменений не выявлено.** Абзацы про systemd (`srv1cv8-A.B.C.D@.service`, каталог `/opt/1cv8/arch/A.B.C.D/`) в сравнение не попали. В абзацах про init (архитектура E2K) поменялся только пример номера версии (`srv8-5-1-100`); исходный скрипт в тексте 8.5.1 по-прежнему называется `srv1cv83`.
8. **`ragent /regport`**: добавлено предупреждение — если на одном компьютере несколько кластеров, у каждого должен быть уникальный порт главного менеджера кластера, иначе менеджеры с одинаковым портом считаются одним кластером с непредсказуемым поведением.
9. **Расписание перезапуска рабочих процессов** (cron-формат, у кластера и у рабочего сервера): добавлено уточнение — расписание не влияет на резервные рабочие процессы.
10. **Переименования 8.3 → 8.5**: `V83.COMConnector` → `V85.COMConnector`, `V83.Application` → `V85.Application`, `V83C.Application` → `V85C.Application`; служба Windows `1C:Enterprise 8.3 Server Agent` → `1C:Enterprise 8.5 Server Agent`; User-Agent Web-сервиса `1C + Enterprise/8.3` → `1C+Enterprise/8.5` (важно для правил прокси).
11. **Файл .dt** из версий 8.1, 8.2 и 8.3 загружается в 8.5 (было: из 8.1 и 8.2 — в 8.3).
12. **Шаблоны и список баз**: `AppVersion` в манифесте `*.mft` для поставки из 8.5 равен `8.3` при режиме совместимости 8.3.27 и ниже, иначе `8.5`; поле «Версия 1С:Предприятия» у базы из такого шаблона автоматически не заполняется — база открывается максимальной версией на компьютере, а в клиент-серверном варианте версию клиента определяет версия кластера.
13. **Новые ключи запуска 1cv8**: `/i85` (интерфейс «Версия 8.5») и `/Theme` со значениями `-Dark`, `-Light`; в веб-клиенте — `i85` и `Theme=Dark` / `Theme=Light`.
14. **Пакетный режим конфигуратора**: у `/LoadConfigFromFiles` появился `-JobsCount` (по умолчанию 0 — автоматически по числу ядер); новые команды `/ModuleGetSourceCodeAccess` и `/ModuleSetSourceCodeAccess`; у `/SignCfg` — параметр `-SignType` (`ConfigurationPatch`, `Copyright`); явно сказано, что текстовый вывод пакетных команд сохраняется только при указании `/Out`.
15. **Многопоточная загрузка конфигурации из файлов**: в режиме агента у `config load-config-from-files` появился `--threads` (по умолчанию `auto`); в `ibcmd` у группы `import` появился параметр количества потоков (по умолчанию — число логических ядер).
16. **Технологический журнал**: изменился набор свойств с кодом возврата провайдеров MS SQL — появились `hResultMSOLEDBSQL19`, `hResultMSOLEDBSQL`, `hResultNC2012`; в 8.3.27 были `hResultOLEDB`, `hResultNC2005`, `hResultNC2008`, `hResult2012`.
17. **default.vrd**: у провайдера OpenID Connect новый атрибут `imageDark` (картинка кнопки для тёмной темы окна аутентификации).
18. **Лицензирование по существу не менялось**: раздел о видах лицензий только перенумерован (1.6 → 1.5), в главе 10 — две редакционные правки.
19. **cnvdbfl**: предел размера внутреннего файла для формата 8.3.8 при странице 8 192 байт и больше указан как 16 Гбайт (было 6 Гбайт).
20. **Клиентские платформы**: macOS 14 ‑ 15 на процессорах Apple работают без режима трансляции; мобильная платформа — Android до 16.x и новая ОС Аврора 5.1.3 ‑ 5.1.6.

**`/ModuleGetSourceCodeAccess <имя файла>`** — новая команда (в 8.3.27 отсутствует).

- Формирует список модулей конфигурации и всех подключённых расширений с режимами доступа к ним. В список попадают только модули, на которые может быть установлен пароль или которые могут поставляться без исходных текстов. Сам пароль не выгружается.
- Файл в кодировке UTF-8, один модуль на строку. Вид строки: `[Расширение ]ИмяМодуля:режим:`.
  - `Расширение` — имя расширения, после него обязателен пробел; если не указано — модуль относится к основной конфигурации.
  - `ИмяМодуля` — полное имя модуля на английском языке.
  - `режим`: `open` — исходный код без пароля; `encrypted` — на модуль установлен пароль; `hidden` — модуль поставляется в скомпилированном виде без исходных текстов.
- Информационная база при выполнении не изменяется.

**`/ModuleSetSourceCodeAccess <имя файла>`** — новая парная команда (в 8.3.27 отсутствует).

- Устанавливает режим доступа к модулям конфигурации и установленных расширений по списку из файла того же формата.
- Трактовка поля `режим` при установке: `open` — снять пароль, пароль для расшифровки указывается после режима (`…:open:123`); `encrypted` — зашифровать модуль паролем, указанным после режима (`…:encrypted:123`); `hidden` — удалить исходный текст, оставив модуль в скомпилированном виде (операция необратима).
- Рекомендуемый порядок: получить список через `/ModuleGetSourceCodeAccess`, оставить в файле нужные модули, применить `/ModuleSetSourceCodeAccess`. Чтобы сменить пароль, сначала нужно снять старый, затем установить новый.
- Команда изменяет основную конфигурацию; обновление конфигурации базы данных выполняется отдельно командой `/UpdateDBCfg`.

Результат `/ModuleSetSourceCodeAccess` (строки — режим в файле, столбцы — текущее состояние модуля):

| Режим | Открытый | С паролем | Без исходного текста |
|---|---|---|---|
| `open` | Нет изменений | Пароль снимается, модуль становится открытым | Невозможно |
| `encrypted` | На модуль устанавливается пароль | Нет изменений | Невозможно |
| `hidden` | Модуль компилируется, исходный код удаляется безвозвратно | Зашифрованный код удаляется безвозвратно, модуль остаётся скомпилированным | Нет изменений |

⚠ в источнике неясно: в 8.3.27 в разделе 7.4.1 была фраза о том, что в пакетном режиме модули, требующие пароля, игнорируются с диагностическим сообщением. Сохранена ли она в 8.5.1 — сравнение не показывает.
