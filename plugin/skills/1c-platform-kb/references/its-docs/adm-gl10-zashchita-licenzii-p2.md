## 10.3 (окончание раздела; заголовок — в части 1)

### 10.3.4 (окончание подраздела; заголовок — в части 1)

#### 10.3.4.8. Интернет-сервисы, фоновые задания

- Web-сервисы, HTTP-сервисы, запросы к OData и фоновые задания **клиентских лицензий не требуют**.
- Если информационная база, предоставляющая интернет-сервисы, работает в клиент-серверном варианте, то **серверная лицензия** для сервера «1С:Предприятия» всё равно необходима.

#### 10.3.4.9. Терминальный сервер

##### 10.3.4.9.1. Общая информация

Относится к Windows-системам (только Windows).

- Для системы программного лицензирования «рабочее место» определяется **идентификатором сессии**. Все запросы на получение лицензии с одного компьютера и с одним идентификатором сессии считаются запросами с одного рабочего места.
- Следствие: на компьютере с однопользовательской программной лицензией интерактивно можно запустить произвольное число клиентских приложений.
- Если на том же компьютере клиентское приложение (в любом виде) запускается **из службы Windows**, это приравнивается к терминальному серверу и требует дополнительной лицензии.
- Правило действует для любых программных лицензий, не только однопользовательских.

##### 10.3.4.9.2. Однопользовательская программная лицензия

- Даёт запуск произвольного числа экземпляров системы в режимах 1С:Предприятие и Конфигуратор **в пределах одной терминальной сессии**.
- Программные лицензии (и однопользовательские, и многопользовательские), размещённые на терминальном сервере, **суммируются**, если файлы лицензий доступны всем пользователям терминального сервера.

##### 10.3.4.9.3. Многопользовательская программная лицензия

- Может размещаться на терминальном сервере и использоваться как для файлового, так и для клиент-серверного варианта.
- Обеспечивает запуск произвольного числа экземпляров (1С:Предприятие или Конфигуратор) для такого количества одновременных терминальных сессий, на сколько пользователей активирована лицензия.
- Правило суммирования то же: лицензии складываются, если файлы доступны всем пользователям терминального сервера.

#### 10.3.4.10. Мобильный клиент

| Вариант информационной базы | Кто считает лицензии |
|---|---|
| Файловый | Модуль расширения веб-сервера |
| Клиент-серверный | Сервер «1С:Предприятия» |

- Файл программной лицензии может лежать на компьютере с модулем расширения веб-сервера либо на компьютере с сервером «1С:Предприятия».
- Расход — по правилу **«один сеанс — одна лицензия»**.
- Два экземпляра мобильного клиента на одном мобильном устройстве = 2 лицензии.
- Конфигуратор, запущенный на компьютере с веб-сервером, плюс мобильный клиент, работающий через этот веб-сервер = тоже 2 лицензии.

#### 10.3.4.11. Автономный сервер

Лицензию при работе с автономным сервером можно получить двумя способами:

| Источник лицензии | Как расходуется | Условия |
|---|---|---|
| Локальная программная лицензия (получает сам клиент; **только тонкий клиент**) | На одном компьютере — произвольное число экземпляров в режиме 1С:Предприятие | — |
| Автономный сервер «1С:Предприятия» выдаёт лицензию | **«На сеанс»** | Файл активированной программной лицензии должен быть доступен тому экземпляру автономного сервера, который обслуживает данную информационную базу (учитывать, от имени какого пользователя ОС запущен экземпляр). В конфигурационном файле автономного сервера должна быть включена выдача лицензий — параметр `infobase.distribute-licenses` |

### 10.3.5. Особенности активации и получения серверной лицензии

#### 10.3.5.1. Кластер серверов

- Программная серверная лицензия активируется для компьютера, на котором:
  - выполняется один или несколько рабочих процессов (`rphost`) кластера, **или**
  - работает менеджер кластера (`rmngr`), на который назначен **сервис лицензирования**.
- Наличие серверной лицензии проверяется в момент, когда клиентское приложение подключается к рабочему процессу (`rphost`).
- Особенность сервиса лицензирования кластера: если ему одновременно доступны программные лицензии на 32- и 64-разрядный сервер, то на запрос лицензии для 32-разрядного сервера может быть выдана лицензия 64-разрядного. Так происходит, когда 64-разрядная лицензия оказывается первой свободной **по порядку следования файлов в каталоге с активированными лицензиями**.
- Рекомендация: не раздавать одним сервисом лицензирования программные лицензии и на 32-, и на 64-разрядные серверы.
- См. также: «Сервисы кластера» (в источнике — ссылка на другой раздел).

#### 10.3.5.2. Автономный сервер

Программная лицензия активируется для компьютера, на котором выполняется автономный сервер. Когда автономный сервер проверяет наличие серверной лицензии:

| Тип информационной базы | Условие проверки серверной лицензии |
|---|---|
| **Не файловая** (клиент-серверная) | Любое из подключений к автономному серверу: (1) клиентское приложение «1С:Предприятия»; (2) утилита `ibcmd`, подключающаяся к запущенному экземпляру на локальном компьютере (протокол IPC, параметр запуска `--pid`); (3) утилита `ibcmd`, подключающаяся к запущенному экземпляру на удалённом компьютере (протокол SSH, параметр запуска `--remote`); (4) подключение к автономному серверу по протоколу SSH |
| **Файловая** | Только когда с базой одновременно работает **более 3** клиентских сеансов |

Дополнительно:

- При работе с файловой базой до 3 клиентских сеансов включительно автономный сервер серверную лицензию не требует и не проверяет.
- Сеансы фоновых заданий и интернет-сервисов в подсчёт одновременных сеансов технически не входят.
- Утилита `ibcmd` в **offline-режиме** (параметр запуска `--data`) при подключении к клиент-серверной информационной базе требует серверную лицензию. Следствие: `ibcmd` в offline-режиме можно запускать только на компьютере, где доступна серверная лицензия.

Сводка параметров `ibcmd`, упомянутых в разделе:

| Параметр | Режим | Протокол |
|---|---|---|
| `--pid` | Подключение к запущенному экземпляру автономного сервера на локальном компьютере | IPC |
| `--remote` | Подключение к запущенному экземпляру автономного сервера на удалённом компьютере | SSH |
| `--data` | Offline-режим | — (в источнике не указан) |

### 10.3.6. Особенности активации и получения лицензии для разработчиков

**Порталы разработчиков**, на которых активируется лицензия: `https://developer.1c.ru` или `https://1c-dn.com`.

Выбор портала при первичном получении:

| Язык локализации компьютера пользователя | Портал |
|---|---|
| армянский, азербайджанский, грузинский, латышский, казахский, русский, туркменский | автоматически `https://developer.1c.ru` |
| любой другой | в диалоге активации предлагается выбрать портал (на языке пользователя) |

- Если лицензия разработчика уже получена, автоматическая перепривязка к другому порталу не выполняется.
- Выбор портала **не зависит** от значения параметра `ExternalResourcesMode` файла `conf.cfg` — всегда действует правило из таблицы.
- Текст лицензионного соглашения при активации зависит от портала: `https://developer.1c.ru` — на русском языке, `https://1c-dn.com/` — на английском.

**Причины, по которым лицензию нельзя активировать:**

- для аккаунта разработчика на портале уже активированы лицензии на **3 различных компьютерах**;
- учётная запись на портале разработчиков не действует или не подтверждена;
- Центр Контроля Обновлений нашёл основания для запрета продления.

**Когда действие лицензии может прекратиться:**

- **Нет доступа к интернет-ресурсам фирмы «1С».** Лицензия разработчика имеет срок действия; по его истечении платформа должна получить новую лицензию. Без доступа к Центру лицензирования переполучить её нельзя, и существующая лицензия становится недоступной.
- **Учётная запись заблокирована фирмой «1С».** Продление невозможно, текущая лицензия также перестаёт работать.
- **Выдача лицензии на этот компьютер приостановлена на портале разработчиков.** Возможные причины:
  - превышено количество лицензий для разработчиков, которые могут быть активны одновременно;
  - разработчик сам приостановил действие активированной лицензии (или всех лицензий) на портале, чтобы использовать лицензию на другом компьютере.

### 10.3.7. Активация программной лицензии

#### 10.3.7.1. Общие правила

Программная лицензия — одна из составных частей системы защиты.

**Инструменты активации**

| Инструмент | Как вызвать | Ограничения |
|---|---|---|
| Помощник активирования лицензии в Конфигураторе | Сервис — Получение лицензии… | — |
| Помощник активирования лицензии в режиме 1С:Предприятие | Сервис и настройки — Функции для технического специалиста — Стандартные — Получение лицензии | Доступ к функциям для технического специалиста должен быть заранее включён |
| Утилита `ring` | (описание утилиты — в источнике ссылка на другой раздел) | **Не умеет** активировать лицензию системы «1С:Аналитика» и лицензию для разработчиков |

**Шаги помощника**

1. Выбор действия:
   - «Получить лицензию» — получение лицензии;
   - «Загрузить файл-ответ» — загрузка файла-ответа, если лицензия получается на электронном носителе;
   - «Активировать community-лицензию» — активация лицензии для разработчиков.
2. При получении лицензии — ввод **номера комплекта** и **пинкода**.
3. Гиперссылка «Дополнительно» открывает дополнительные параметры:

   | Параметр | Назначение |
   |---|---|
   | Флажок «Установка на сервер», поля «Сервер» и «Порт» | Привязка лицензии к параметрам компьютера сервера «1С:Предприятия». Выбирать, когда сервер, к компьютеру которого привязывается лицензия, — не тот компьютер, где запущен конфигуратор. В поля вводятся параметры доступа к серверу. Файл активированной лицензии в этом режиме всегда размещается на компьютере сервера, в каталоге профиля пользователя, от имени которого работает сервер (по умолчанию `usr1cv83`) |
   | Флажок «Автоматическое получение» | Установлен — выполняется попытка автоматической активации. Сброшен — на заключительном шаге предлагается вручную выбрать один из трёх способов: автоматический, на электронном носителе, по телефону |

4. Выбор операции с лицензией:
   - «Первый запуск» — первичное получение;
   - «Восстановление» — повторное получение или обновление лицензии.
5. Для «Первого запуска»: указать параметры владельца лицензии, затем выбрать объект привязки — **компьютер** (показываются его характеристики) или один из доступных **ключей защиты HASP** (список доступных ключей обновляется автоматически).
6. Для «Восстановления» — два случая:
   - параметры компьютера, к которому привязана лицензия, не менялись — оставить установленным флажок «Я уверен(-а), что ключевые параметры компьютера не изменялись»;
   - параметры компьютера изменились — снять этот флажок и в поле «Резервный пинкод» ввести следующий неиспользованный (резервный) пинкод комплекта.

   Затем проверить регистрационные данные владельца и указать объект привязки.
7. Лицензия активируется **для всех пользователей компьютера**. Если у пользователя, выполняющего активацию, нет права записи в каталог, доступный всем пользователям, система сообщит об этом и предложит активировать лицензию только для текущего пользователя.

**Способы получения, кроме автоматического**

| Способ | Что нужно сделать |
|---|---|
| На электронном носителе | Создать файл запроса лицензии; получить лицензию из Центра лицензирования (затем загрузить файл-ответ) |
| Вручную (по телефону) | Продиктовать оператору Центра лицензирования набор цифр из помощника — **48 цифр**; ввести под диктовку оператора данные программной лицензии — **120 цифр** |
| Лицензия для разработчиков | Нужен подтверждённый профиль на портале `https://developer.1c.ru`; вводятся имя пользователя и пароль доступа к порталу 1С для разработчиков, других данных не требуется |

Примечание из источника: при загрузке файла, полученного из Центра лицензирования, параметры в диалоге активации (сведения о программном продукте и владельце лицензии) должны **в точности** совпадать с теми, что были указаны при формировании файла запроса.

**Особенности активации**

- Первичная активация по Интернету или на электронном носителе → повторная активация и обновление возможны только по Интернету или на электронном носителе.
- Первичная активация вручную по телефону → повторная активация и обновление возможны только вручную по телефону.
- Дополнительную клиентскую программную лицензию на компьютере, где уже активирована программная лицензия, нужно активировать **точно тем же способом**, что и первую на этом компьютере.
- Перед повторным получением или обновлением лицензии файл текущей лицензии (для данного пинкода и серийного номера) нужно **переместить в каталог, который система не использует для поиска лицензий**. Иначе и новая, и существующая лицензии попадут в чёрный список и станут непригодны.
- Если активируются серверная и многопользовательская программные лицензии и на компьютере сервера «1С:Предприятия» можно запустить Конфигуратор — рекомендуется активировать обе лицензии с компьютера сервера.
- При проверке привязки файла лицензии к компьютеру **не учитываются** сетевые устройства и внешние накопители, подключаемые через USB и IEEE 1394.
- Исключение для получения на носителе: в момент формирования запроса в Центр лицензирования и в момент построения файла лицензии по ответу параметры компьютера должны совпадать **с учётом** устройств USB и IEEE 1394. Иначе при загрузке файла-ответа выдаётся ошибка, начинающаяся словами «Ответ Центра лицензирования не соответствует введенным данным лицензии или владельца» (далее — предложение проверить регистрационный номер комплекта, пинкод и данные о владельце).
  - Как завершить активацию: вернуть конфигурацию компьютера к состоянию на момент формирования запроса (например, вставить в USB-порт тот же внешний накопитель) и повторно загрузить тот же файл ответа; после этого накопитель можно извлечь.
  - Если восстановить параметры компьютера нельзя — потребуется повторное получение лицензии с использованием дополнительного пинкода.
- Перед повторной активацией на ранее использованный пинкод или на новый пинкод из того же комплекта нужно убедиться, что в локальной сети нет приложений «1С:Предприятия», использующих ранее полученный файл лицензии с пинкодом из этого комплекта.

**Структура файла активированной лицензии**

| Часть файла | Содержимое | Значение |
|---|---|---|
| Начало файла | Зашифрованные параметры активированной лицензии и параметры объекта привязки | Только эта часть существенна для работоспособности лицензии |
| После зашифрованного блока | Человекочитаемый вариант той же информации (параметры объекта привязки могут показываться сокращённо) | Может редактироваться, ни в каких процедурах контроля не используется |

Один и тот же файл лицензии не рекомендуется держать сразу в нескольких каталогах, доступных приложениям «1С:Предприятия»: это рассматривается как вариант нарушения лицензионного соглашения, и файл может стать непригодным. В таком случае в начале файла может появиться текст с причиной, по которой платформа сочла файл непригодным.

**Куда помещается файл при автоматическом получении**

| Сценарий | Windows | Linux |
|---|---|---|
| Компьютер с сервером «1С:Предприятия» | `%ALLUSERSPROFILE%\1C\licenses` пользователя, от имени которого работает сервер | `/var/1C/licenses` |
| Текущий компьютер, выбран «текущий пользователь» | `%LOCALAPPDATA%\1C\1cv8\conf` пользователя, выполняющего получение | `~/.1cv8/conf` (`~` — домашний каталог пользователя, от имени которого запущен конфигуратор) |
| Текущий компьютер, выбраны «все пользователи» | `%ALLUSERSPROFILE%\1C\licenses` (каталог данных для всех пользователей компьютера) | **Такой вариант не поддерживается** |

Для текущего компьютера помощник спрашивает, кому должна быть доступна получаемая лицензия.

**Каталоги лицензий и права на них**

Каталоги `%ALLUSERSPROFILE%\1C\licenses` и `/var/1C/licenses` создаются при установке системы (каждый — в своей ОС).

- Windows (только Windows): права чтения и записи на каталог получает пользователь, от имени которого работает сервер «1С:Предприятия» (выбирается в окне установки). Если флажок «Установить сервер 1С:Предприятия как сервис Windows» при установке не установлен, права никому не назначаются и остаются по умолчанию.
- **Linux:** при установке создаётся группа `grp1cv8`. В неё должны входить все учётные записи данного компьютера, от имени которых:
  - исполняются процессы кластеров серверов «1С:Предприятия» в режиме демона;
  - запускаются клиентские приложения на этом компьютере.

  Нужно убедиться, что у пользователей группы `grp1cv8` есть доступ **на запись** к файлам программных лицензий.

Права на каталог с программными лицензиями в Linux:

| Кто | Значение | Права |
|---|---|---|
| Владелец каталога | `root` | чтение и запись (`rwx`) |
| Группа владельца | `grp1cv8` | чтение и запись (`rwx`) |
| Остальные пользователи | — | только чтение (`r-x`) |

#### 10.3.7.2. Рекомендации по активации

- Активировать многопользовательскую программную лицензию на клиентский компьютер не имеет смысла (при любом варианте информационной базы).
- Примечание из источника: клиентское приложение в Linux позволяет активировать лицензию, доступную всем пользователям, только если активация выполняется с правами суперпользователя (`root`).

⚠ в источнике неясно: в 10.3.7.1 для Linux указано, что вариант «для всех пользователей» текущего компьютера не поддерживается, а примечание в 10.3.7.2 допускает его при активации от `root`. Как эти два утверждения соотносятся, источник не поясняет.

### 10.3.8. Расположение файлов с программными лицензиями

#### 10.3.8.1. Общая информация

- Программная лицензия — файл с расширением **`.lic`**; он может находиться в разных местах файловой системы.
- Совет из источника (повтор): не размещать один файл лицензии сразу в нескольких каталогах, доступных приложениям «1С:Предприятия», — файл может стать непригодным (расценивается как вариант нарушения лицензионного соглашения).

Алгоритм получения программной лицензии:

1. Составляется список файлов программных лицензий по всем каталогам, где они могут лежать. Порядок файлов — **тот, в котором их возвращает операционная система при поиске**. Перечень каталогов для каждой ОС — в подразделах ниже.
2. По каждому файлу списка выполняется попытка получить требуемую лицензию (клиентскую или серверную) — до первой успешно полученной доступной лицензии (в источнике — ссылка на другой раздел) либо до конца списка.

#### 10.3.8.2. Для ОС Windows

Только Windows. Каталоги в порядке поиска:

1. Каталог конфигурационных файлов конкретной версии платформы; по умолчанию `C:\Program Files\1cv8\A.B.C.D\bin\conf`.
2. `%LOCALAPPDATA%\1C\1cv8\conf` пользователя, от имени которого работает система.
3. Каталог из параметра `ConfLocation` файла `conf.cfg` (из каталога `bin\conf` конкретной версии).
4. `%ALLUSERSPROFILE%\1C\1cv8\conf`.
5. `%ALLUSERSPROFILE%\1C\licenses`.
6. `%ProgramData%\1C\licenses`.

Если лицензия нигде не найдена — используется каталог `%APPDATA%\1C\1cv8\`; если в нём есть файл `location.cfg`, поиск идёт в каталоге, заданном параметром `location`.

#### 10.3.8.3. Для ОС Linux

Каталоги в порядке поиска:

```
1. /opt/1cv8/arch/A.B.C.D/conf      — каталог conf конкретной версии
2. /opt/1cv8/conf                   — каталог conf корневого каталога установки
3. ~/.1cv8/conf                     — ~ = домашний каталог пользователя, от имени которого работает «1С:Предприятие»
4. <значение параметра ConfLocation файла conf.cfg из каталога conf конкретной версии>
5. /var/1C/licenses
```

Запасной вариант, если ни в одном из каталогов лицензия не найдена:

```
~/.1cv8/1C/1cv8/                    — каталог поиска
~/.1cv8/1C/1cv8/location.cfg        — если файл есть, поиск идёт в каталоге из параметра location
```

Формат файлов `conf.cfg` и `location.cfg` описан в других разделах документации (в источнике — ссылки). Обозначения `arch` и `A.B.C.D` приведены как в источнике, в этой части не расшифровываются.

#### 10.3.8.4. Для ОС macOS

Каталоги в порядке поиска:

1. Каталог `conf` установленной версии: `/opt/1cv8/A.B.C.D/conf`.
2. `~/.1cv8/conf` (`~` — домашний каталог пользователя, от имени которого работает «1С:Предприятие»).
3. Каталог из параметра `ConfLocation` файла `conf.cfg` (из каталога `conf` конкретной версии).
4. `/var/1C/licenses`.

Запасной вариант тот же, что в Linux: каталог `~/.1cv8/1C/1cv8/`, а при наличии в нём `location.cfg` — каталог из параметра `location`.

## 10.4. Определение возможности запуска

### 10.4.1. При запуске клиентского приложения

Проверка идёт по шагам; как только нужная лицензия найдена, поиск прекращается.

**Шаг 1. На компьютере с клиентским приложением**

1. Попытка получить лицензию оттуда же, откуда она была получена при последнем успешном подключении: из того же файла программной лицензии или из ключа защиты HASP того же типа (серия, сетевой или локальный).
2. Поиск программных лицензий на локальном компьютере (порядок поиска — в источнике ссылка на другой раздел; каталоги поиска описаны в 10.3.8).
3. Поиск локального ключа HASP (порядок — в источнике ссылка на другой раздел).
4. Поиск многопользовательского ключа HASP, доступного через программу HASP License Manager, в порядке серий: **`ORGL8` → `ORG8A` → `ORG8B`**.
   - Если в локальной сети доступно несколько HASP License Manager с ключами одной серии, ключ выбирается случайно либо в порядке, заданном в файле `nethasp.ini`, доступном приложению.
   - Предостережение источника: когда в системе много разных аппаратных и программных лицензий, нужно избегать неоднозначности выбора свободной лицензии при запуске клиентов, иначе возможен неоправданный перерасход лицензий.
5. Если конфигурация базовая — клиентское приложение ищет лицензию базовой версии на локальном компьютере.

**Шаг 2. На компьютере менеджера кластера, на который назначен сервис сеансовых данных**

1. Попытка получить лицензию из того же файла программной лицензии или многопользовательского ключа HASP того же типа (серия, сетевой или локальный), что и при последнем успешном подключении.
2. Поиск программных лицензий на компьютере менеджера кластера.
3. Поиск многопользовательских ключей HASP, установленных на компьютере менеджера кластера.
4. Поиск многопользовательского ключа HASP, доступного через HASP License Manager.

**Шаг 3. На компьютере менеджера кластера, на который назначен сервис лицензирования**

1. Попытка получить лицензию из того же файла программной лицензии, что и при последнем успешном подключении.
2. Поиск программных лицензий на компьютере этого менеджера кластера.

**Отключение поиска ключей HASP на клиенте**

Параметр `UseHwLicenses=0` в конфигурационном файле `1cestart.cfg` выключает поиск ключа защиты HASP. При этом в ходе определения возможности запуска:

- не ищутся свободные лицензии в ключах HASP, доступных на клиентском компьютере (ни в локальных, ни в сетевых);
- не выполняется попытка получить лицензию из запомненного ключа.

### 10.4.2. При запуске сервера

Наличие серверной лицензии проверяется при установке соединения клиентского приложения с сервером «1С:Предприятия». Поиск прекращается на первом шаге, где лицензия найдена.

**Шаг 1. На компьютере рабочего процесса, обслуживающего соединение с информационной базой**

1. Попытка получить лицензию из того же файла программной лицензии или ключа HASP, что и при последнем успешном подключении.
2. Поиск программной лицензии 32-разрядного сервера — только для 32-разрядного сервера «1С:Предприятия».
3. Поиск программной лицензии 64-разрядного сервера.
4. Поиск локального ключа 32-разрядного сервера — только для 32-разрядного сервера.
5. Поиск локального ключа 64-разрядного сервера.

**Шаг 2. На менеджере кластера, на который назначен сервис лицензирования**

1. Попытка получить лицензию из того же файла программной лицензии, что и при последнем успешном подключении.
2. Поиск программной лицензии 32-разрядного сервера — только для 32-разрядного сервера.
3. Поиск программной лицензии 64-разрядного сервера.

Сводно — что и где ищется:

| Место поиска | Клиентская лицензия | Серверная лицензия |
|---|---|---|
| Компьютер клиента | запомненный источник; файлы `.lic`; локальный HASP; сетевой HASP через HASP License Manager; лицензия базовой версии (для базовой конфигурации) | — |
| Компьютер рабочего процесса (`rphost`) | — | запомненный источник; файлы `.lic` (32/64); локальные ключи HASP сервера (32/64) |
| Менеджер кластера с сервисом сеансовых данных | запомненный источник; файлы `.lic`; многопользовательские HASP на этом компьютере; HASP через HASP License Manager | — |
| Менеджер кластера с сервисом лицензирования | запомненный файл `.lic`; файлы `.lic` (в перечне шагов источника — только файлы программных лицензий) | запомненный файл `.lic`; файлы `.lic` (32/64) (в перечне шагов источника — только файлы программных лицензий) |

### 10.4.3. Действия при неполучении лицензии

Если по описанному алгоритму ни одной лицензии не найдено:

| Приложение | Поведение |
|---|---|
| Конфигуратор, тонкий клиент, толстый клиент | Запускают помощника получения программной лицензии. При отказе от получения — выдают те же сообщения об ошибке, что и веб-клиент |
| Веб-клиент | Формирует сообщение об ошибке |

Тексты сообщений:

- «Не найдена лицензия. Не обнаружен ключ защиты программы или полученная электронная лицензия!»
- то же сообщение с началом «На сервере 1С:Предприятия не найдена лицензия.» (вместо «Не найдена лицензия.»)

Диагностика: кнопка **«Подробно»** в окне ошибки открывает окно **«Журнал поиска ключа»**. В нём показано, где выполнялся поиск лицензий, статус каждого поиска (успешно / не успешно) и причины неуспеха.

## 10.5. Защита от неправомерного использования прикладных решений

### 10.5.1. Общая информация

- Покупая лицензию на основную поставку прикладного решения, пользователь получает дистрибутивы платформы и указанной в лицензии конфигурации тех версий, которые актуальны на момент покупки.
- Права на последующие версии этой конфигурации и на конфигурации с другими названиями, как правило, автоматически не предоставляются — пользователь сам должен следить за оформлением прав на обновлённые конфигурации.
- Назначение механизма — вовремя сообщать пользователю, что он фактически использует версии или релизы конфигурации, на которые у него нет прав, и о связанных юридических рисках.

Типовые случаи использования с нарушением порядка, установленного правообладателем:

1. Нет лицензии на основную поставку конфигурации данного вида.
2. Лицензия на основную поставку приобреталась, но конфигурация потом обновлена с нарушением правил сопровождения (пример: используются версии/релизы, выпущенные после окончания периода обслуживания по договору ИТС). Условия сопровождения — на Портале 1С:ИТС: `https://portal.1c.ru/app/update`.

Правила работы проверки:

- Для прикладного решения, использующего **базовую лицензию**, проверка правомерности **не выполняется**.
- При **загрузке информационной базы из файла `*.dt`** проверка **не выполняется**.
- В проверке используются сведения о прикладном решении и данные учётной записи, созданной при регистрации прикладного решения и договора сопровождения на Портале 1С:ИТС. В документации эти данные называются **клиент лицензирования**.
- При неправомерном использовании прикладное решение периодически показывает диалог с причинами неправомерности.
- Результат проверки также виден в диалоге «О программе».

### 10.5.2. Устройство механизма

- **Момент проверки:** после завершения обновления конфигурации базы данных платформа отправляет запрос в Центр лицензирования (ЦЛ) со сведениями о прикладном решении. Запрос персонифицируется данными клиента лицензирования.
- **Сетевой доступ:** системе «1С:Предприятие» нужен доступ к сайту **`https://1cv8update.com` по порту `443`**.
- При успешном обращении ЦЛ возвращает состояние правомерности использования данного прикладного решения для указанного клиента лицензирования.
- Если ЦЛ правомерность не подтверждает, платформа начинает сообщать **всем пользователям информационной базы** о неправомерном использовании, показывая информацию, полученную из ЦЛ.

Статусы в диалоге «О программе»:

| Текст статуса | Что означает |
|---|---|
| «Проверка лицензионного использования не выполнялась» | Платформа ещё не связывалась с ЦЛ для проверки |
| «Проверка лицензионного использования выполнена успешно» | Платформа связалась с ЦЛ и получила подтверждение правомерности |
| «Нелицензионное использование конфигурации» | Прикладное решение используется неправомерно |
| «Недоступен центр лицензирования» | Платформа не может получить доступ к ЦЛ |

Данные клиента лицензирования:

- Должны быть заданы **в информационной базе** используемого прикладного решения.
- Задаются из конфигуратора: Главное меню — Администрирование — Установить настройки клиента лицензирования.
- Если к моменту обращения к ЦЛ данные для базы не заданы, аналогичный диалог отображается в режиме 1С:Предприятие.
- В распределённой информационной базе данные клиента лицензирования вводятся **в каждом узле**.

Возможности для разработчика прикладного решения:

| Метод встроенного языка | Назначение |
|---|---|
| `УстановитьНастройкиКлиентаЛицензирования()` | Собственный механизм установки данных клиента лицензирования (например, получение их при стартовой настройке прикладного решения) |
| `ПодключитьОбработчикЗапросаНастроекКлиентаЛицензирования()` | Реакция на запрос платформой данных клиента лицензирования: в обработчике открывается собственный, более удобный диалог ввода настроек |

## Что важно администратору Linux

1. **Каталог серверных лицензий в Linux — `/var/1C/licenses`.** Он создаётся при установке; владелец `root` (`rwx`), группа `grp1cv8` (`rwx`), остальные — `r-x`. В группу `grp1cv8` должны входить все учётные записи, от имени которых работают демоны кластера и запускаются клиентские приложения; у членов группы должен быть доступ на запись к файлам лицензий.
2. **Порядок поиска файлов `.lic` в Linux:** `/opt/1cv8/arch/A.B.C.D/conf` → `/opt/1cv8/conf` → `~/.1cv8/conf` → каталог из `ConfLocation` в `conf.cfg` → `/var/1C/licenses`; затем запасной `~/.1cv8/1C/1cv8/` (с учётом `location.cfg`, параметр `location`). Внутри списка файлы перебираются в том порядке, в каком их вернула ОС, до первой подходящей лицензии.
3. **Не держать один файл лицензии в нескольких каталогах поиска** — файл может стать непригодным; причина при этом может быть записана текстом в начало файла.
4. **Перед повторным получением или обновлением лицензии** старый файл (для того же пинкода и серийного номера) нужно убрать из каталогов поиска, иначе и новая, и старая лицензии попадут в чёрный список. Перед повторной активацией пинкода из того же комплекта в сети не должно быть приложений, использующих прежний файл лицензии этого комплекта.
5. **Серверная лицензия активируется для компьютера**, где работает `rphost` либо `rmngr` с назначенным сервисом лицензирования; проверяется в момент подключения клиента к `rphost`. Не раздавать одним сервисом лицензирования лицензии и 32-, и 64-разрядного сервера.
6. **Web-сервисы, HTTP-сервисы, OData и фоновые задания клиентских лицензий не расходуют**, но в клиент-серверном варианте серверная лицензия обязательна.
7. **`ibcmd` и серверная лицензия:** для клиент-серверной базы лицензия нужна при `--pid`, `--remote` и в offline-режиме `--data`; offline-режим запускается только там, где серверная лицензия доступна.
8. **Автономный сервер с файловой базой** не требует серверной лицензии при числе клиентских сеансов до 3 включительно (фоновые задания и интернет-сервисы в счёт не идут). Чтобы автономный сервер выдавал лицензии клиентам, должен быть включён параметр `infobase.distribute-licenses`, а файл лицензии должен быть доступен пользователю, под которым запущен экземпляр.
9. **Удалённая активация на сервер:** флажок «Установка на сервер» с полями «Сервер» и «Порт» — файл лицензии окажется на компьютере сервера (по умолчанию пользователь сервера — `usr1cv83`; в Linux каталог для сервера — `/var/1C/licenses`). Если на сервере можно запустить Конфигуратор, серверную и многопользовательскую лицензии рекомендуется активировать прямо с него.
10. **Способ активации фиксируется при первичном получении:** Интернет / электронный носитель — отдельно, телефон — отдельно; смешивать при повторной активации нельзя. По телефону диктуется 48 цифр и вводится 120 цифр.
11. **Привязка к оборудованию:** сетевые устройства и внешние накопители USB / IEEE 1394 при проверке привязки не учитываются, но при получении через файл запроса/ответа параметры компьютера с учётом устройств USB и IEEE 1394 в момент запроса и в момент загрузки ответа должны совпадать.
12. **Клиент на Linux:** лицензия «для текущего пользователя» кладётся в `~/.1cv8/conf`; вариант «для всех пользователей» по 10.3.7.1 не поддерживается, а по примечанию 10.3.7.2 возможен только при активации от `root` (⚠ в источнике неясно).
13. **Утилита `ring`** не активирует лицензии «1С:Аналитики» и лицензии для разработчиков.
14. **Сетевые доступы:** для проверки правомерности использования конфигурации (после обновления конфигурации базы данных) нужен доступ к сайту `https://1cv8update.com` по порту 443; лицензия разработчика требует периодического доступа к интернет-ресурсам фирмы «1С», иначе перестаёт действовать по истечении срока.
15. **Диагностика:** кнопка «Подробно» в окне ошибки «Не найдена лицензия…» открывает «Журнал поиска ключа» с местами и причинами неуспешного поиска. Поиск ключей HASP на клиенте отключается параметром `UseHwLicenses=0` в `1cestart.cfg`.
