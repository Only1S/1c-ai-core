## 29.1. Общая информация

- **Приложение** в терминах системы взаимодействия — одна информационная база или область данных, однозначно идентифицируемая сервером взаимодействия.
- Состав: клиентская часть — в самой платформе; серверная — сервис **«1С:Диалог»** либо свой экземпляр продукта **«1С:Сервер взаимодействия»**. Содержимое обсуждений хранится на сервере взаимодействия; сведения о видеозвонках не хранятся.
- Отдельно регистрироваться пользователям базы не нужно: авторизацию в системе взаимодействия выполняет «1С:Предприятие».
- **Обсуждения:** неконтекстные (не привязаны к объекту базы, сколько угодно) и контекстные (привязаны к объекту; участвуют только пользователи с доступом к объекту; у объекта одно обсуждение).
- **Вложения файлов** возможны, только если сервер взаимодействия подключён к внешнему хранилищу с протоколом **Amazon S3**.

### Сеть

- Клиентская часть обменивается с сервером взаимодействия по **WebSocket**. И клиентское приложение, и сервер «1С:Предприятия» выступают клиентами сервера взаимодействия — исходящий доступ нужен обоим.
- Прокси: настройки берутся из системных настроек ОС (сценарий автоматической настройки не поддерживается) или из **`inetcfg.xml`**. **NTLM-аутентификация на прокси не поддерживается.**
- Видеозвонки — соединение «точка-точка», устанавливается через сервер взаимодействия.
- Для сервиса «1С:Диалог» должны быть доступны:

| URL | Порт | Назначение |
|---|---|---|
| `wss://1cdialog.com` | 443 | точка подключения к сервису |
| `https://api.s3.az1.t1.cloud` | 443 | хранилище файлов сервиса |
| `http://clr.globalsign.com` | 80 | проверка отзыва сертификатов |

Для своего сервера взаимодействия адреса и порты определяются его настройками.

### Видеозвонки — где поддерживаются

- Тонкий клиент: Windows 7 и новее, macOS и Linux любых поддерживаемых версий; работает и через удалённый рабочий стол (RDP), если туда проброшены микрофон и камера.
- Веб-клиент: Google Chrome 64+, Microsoft Edge 64+, Mozilla Firefox 68+, Safari 13+; сервер взаимодействия версии 10 и новее; **только при доступе к базе по HTTPS**. Трансляция экрана — в Chrome и Firefox, тоже только по HTTPS.

### Копии информационной базы

**Работа с несколькими копиями одной базы не поддерживается.** Скопированная база подключится к сервису, но:

- обсуждения и оповещения будут видны во всех копиях;
- возникнут проблемы с контекстными обсуждениями объектов, созданных после копирования;
- возникнут проблемы с получателями сообщений для пользователей, созданных после копирования.

Практический вывод конспекта: копия рабочей базы (тестовая, учебная) не должна оставаться подключённой к тому же приложению системы взаимодействия. Каким способом отключать копию, чтобы не затронуть рабочую базу, документация прямо не говорит: описаны отмена регистрации (действие с участием сервера взаимодействия) и `УстановитьДанныеРегистрацииИнформационнойБазы(Неопределено)` (см. ниже 29.4.2) — прежде чем применять их в копии, проверить поведение на своём сервере взаимодействия. Если несколько баз должны работать вместе — их регистрируют по отдельности и объединяют («совместное использование»).

## 29.2. Устройство: регистрация приложения

При регистрации создаются и сохраняются:

- **уникальный идентификатор приложения** — хранится и в базе, и на сервере взаимодействия; получить или задать его самостоятельно нельзя;
- **криптографические ключи** обмена — у каждой стороны свой набор;
- имя приложения и **адрес электронной почты**, использованный при регистрации. Адрес олицетворяет **абонента** сервиса; абонент может зарегистрировать несколько приложений и имеет в них административные права («администратор абонента»).

Термины документации: «параметры регистрации приложения в сервисе» = адрес сервиса, имя приложения, электронная почта, код активации; «данные регистрации приложения» = эти параметры + идентификатор приложения + ключи.

- Отмена регистрации удаляет в приложении ключи — обмен становится невозможным. Повторная регистрация того же приложения создаёт новую пару ключей и возвращает доступ к истории, **если идентификатор приложения остался прежним**; иначе история недоступна.
- В базе должны быть заведены пользователи — без них регистрация невозможна.
- Для каждого пользователя базы создаётся парный пользователь системы взаимодействия (при первой аутентификации после регистрации или методами встроенного языка). Сопоставление — по уникальному идентификатору пользователя информационной базы; имя и полное имя актуализируются при каждом входе.

## 29.3. Интерактивная работа (обзорно)

- Параметры пользователя, неконтекстные и контекстные обсуждения, текстовые сообщения, видеозвонки и видеоконференции, оповещения.
- Поиск в списке обсуждений идёт по темам и именам пользователей; поиск обсуждения по тексту сообщений не поддерживается.
- **Внешние пользователи** — постоянные, идентифицируются электронной почтой, работают через внешний сайт. **Гостевые пользователи** — разовые участники обсуждения или звонка.

## 29.4. Программный интерфейс (свойство глобального контекста `СистемаВзаимодействия`)

### 29.4.2. Регистрация и отмена регистрации

- Методы: `НачатьРегистрациюИнформационнойБазы()` и `ВыполнитьРегистрациюИнформационнойБазыАсинх()` — на клиенте, асинхронные; `ВыполнитьРегистрациюИнформационнойБазы()` — на сервере, синхронный. Параметры — объект `ПараметрыРегистрацииИнформационнойБазыСистемыВзаимодействия`, результат — `РезультатРегистрацииИнформационнойБазыСистемыВзаимодействия` (свойства `РегистрацияВыполнена`, `ТекстСообщения`).
- Шаги:
  1. вызвать метод, заполнив `АдресЭлектроннойПочты` и `АдресСервера`;
  2. сервер взаимодействия присылает на почту **код активации**;
  3. вызвать метод повторно, заполнив ещё и `КодАктивации`.
- Адрес сервера — `wss://1cdialog.com:443` либо адрес своего сервера взаимодействия. `ИмяИнформационнойБазы` — представление приложения.
- По завершении приходит письмо с **ключом администрирования** — конфиденциальное значение, позволяющее выполнять некоторые операции, не будучи администратором абонента.
- **Отмена регистрации:** `НачатьОтменуРегистрацииИнформационнойБазы()`, `ОтменитьРегистрациюИнформационнойБазыАсинх()`, `ОтменитьРегистрациюИнформационнойБазы()`. Ключи удаляются; повторная регистрация **на тот же адрес почты** возвращает доступ ко всей переписке. Регистрация на другой адрес фактически создаёт новое приложение — доступ к прежним объектам теряется. Можно зарегистрироваться повторно без указания почты — код уйдёт на адрес первой регистрации (способ узнать забытый адрес).
- **Полное отключение с безвозвратной потерей переписки:** `УстановитьДанныеРегистрацииИнформационнойБазы(Неопределено)`.
- Пара `ПолучитьДанныеРегистрацииИнформационнойБазы()` / `УстановитьДанныеРегистрацииИнформационнойБазы()` переносит всю регистрацию вместе с ключами: база, в которую установлены данные, считается сервером взаимодействия тем же приложением. Основное назначение — **миграция области данных между базами**.
- Справочные методы: `АдресСервера()`, `АдресЭлектроннойПочтыАбонента()`, `ВерсияСервера()`, `ИнформационнаяБазаЗарегистрирована()`, `ИспользованиеДоступно()`, `ТекущийПользовательЯвляетсяАдминистраторомАбонента()`; смена адреса почты абонента — метод, записанный в документации как `УстановитьАдресЭлектроннойПочтыВбонента()` (вероятная опечатка в имени; точное написание смотреть в синтакс-помощнике).

### Боты и фоновые задания (обзорно, 29.4.6)

- Объект `БотСистемыВзаимодействия`; сообщения от системы взаимодействия обрабатывают несколько фоновых заданий.
- Каждое задание обрабатывает одно сообщение и завершается. В файловом варианте фоновые задания выполняются последовательно одним экземпляром клиентского приложения. В клиент-серверном запускаются все три задания работы с сообщениями; задание обработки полученных сообщений после работы «засыпает» на 20 секунд, чтобы сразу обработать следующее сообщение.

### Совместное использование (29.4.7)

Несколько зарегистрированных приложений можно объединить в единое пространство с общим списком пользователей; при объединении задают способ сопоставления пользователей.

## 29.5. Интеграция с внешними системами (обзорно)

- Поддерживаются мессенджеры (в документации — Telegram, ВКонтакте, WhatsApp, MAX), вызовы HTTP-сервисов (**webhook**) и **чат на сайте**.
- Описания действий в сторонних системах даны «по состоянию на момент написания документации» — сверять с актуальными интерфейсами этих систем.
- У каждой внешней системы свои ограничения на кнопки в сообщениях; для шаблонов сообщений WhatsApp не поддерживаются команды в сообщениях.

## 29.6. Выгрузка и перенос данных

- Назначение — **перенос данных между серверами взаимодействия** (в том числе из «1С:Диалог» в свой сервер и обратно). **Это не средство регулярного резервного копирования:** для резервных копий базы данных сервера взаимодействия и хранилища файлов документация рекомендует стандартные средства СУБД **PostgreSQL** и самого хранилища.
- Выгрузка создаётся в файл на файловой системе сервера взаимодействия или в хранилище S3. По умолчанию сервер взаимодействия хранит **не более 5 файлов выгрузки** (настраивается на самом сервере).
- Методы (у каждого есть вариант с суффиксом `Асинх`):

| Действие | Метод |
|---|---|
| создать выгрузку | `НачатьСозданиеВыгрузкиДанных()` — возвращает идентификатор |
| состояние выгрузки | `ПолучитьВыгрузкуДанных()` — объект `ВыгрузкаДанныхСистемыВзаимодействия` (свойства `Идентификатор`, `ДатаСоздания`, `Описание`, `Статус`, `СтатусВосстановления`, `ДоступнаВыгрузка`); готово при `Статус = СтатусВыгрузкиДанныхСистемыВзаимодействия.Готово` |
| получить файл | `ПолучитьАдресВыгрузкиДанных()` — временная ссылка (для хранилища) или путь на сервере взаимодействия |
| загрузить файл с клиента | `ЗагрузитьВыгрузкуДанных()` |
| зарегистрировать файл, положенный на сервер или в хранилище | `ВыполнитьРегистрациюВыгрузкиДанных()` |
| восстановить | `НачатьВосстановлениеИзВыгрузкиДанных()` |
| список, описание, удаление | `ПолучитьВыгрузкиДанных()`, `УстановитьОписаниеВыгрузкиДанных()`, `УдалитьВыгрузкуДанных()` |

- `УдалитьВыгрузкуДанных()` убирает выгрузку из списка, **но файл с диска или из хранилища физически не удаляется** — место нужно освобождать отдельно.
- Перенос: выгрузка на сервере-источнике → получение файла → перенос файла на сервер-приёмник → регистрация → восстановление.

## 29.7. Администрирование

Описано в справке стандартной функции «Управление системой взаимодействия»; развёртывание и администрирование сервера — `https://its.1c.ru/db/csdoc`.

## 29.8. Безопасность

- База данных системы взаимодействия содержит сведения не менее конфиденциальные, чем сама информационная база, — защищать её нужно так же.
- **Не включать совместное использование с незнакомой или ненадёжной базой.** Сценарий из документации: злоумышленник просит объединить приложения, создаёт в своей базе пользователя с именем доверенного пользователя вашей базы и получает всю его переписку (сопоставление по имени выполняется автоматически).
- **Код регистрации (активации) не передавать посторонним** — это аналог одноразового кода подтверждения банковской операции.
- При совместном использовании со сторонними базами сопоставлять пользователей **по ключу сопоставления**, а не по имени, либо иметь полный административный доступ к подключаемой базе.
- **Если копия информационной базы могла попасть к посторонним — перерегистрировать базу** в системе взаимодействия: `ОтменитьРегистрациюИнформационнойБазы()`, затем `ВыполнитьРегистрациюИнформационнойБазы()`.
- Прекратить совместное использование: `ОтменитьСовместноеИспользованиеПриложенийАбонента()`; список — `ПолучитьСовместноеИспользованиеПриложенийАбонента()`.

## Что из этого важно администратору

1. Резервная копия информационной базы (`.dt`, дамп PostgreSQL) содержит данные регистрации и ключи системы взаимодействия: развёрнутая из неё копия для сервера взаимодействия — «то же приложение». Тестовые копии от системы взаимодействия отключать (способ — см. оговорку в разделе о копиях базы); при утечке копии — перерегистрировать рабочую базу (раздел 29.8).
2. Серверу «1С:Предприятия» нужен исходящий доступ к серверу взаимодействия (WebSocket, для «1С:Диалог» — порт 443); через прокси с NTLM-аутентификацией работать не будет.
3. Собственный сервер взаимодействия бэкапится средствами PostgreSQL и хранилища S3, а не механизмом выгрузок из этой главы.
