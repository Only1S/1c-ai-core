## 1.1. 32-разрядный сервер

Минимальные требования к рабочим серверам, входящим в 32-разрядный кластер серверов «1С:Предприятия».

### Аппаратные требования (32-разрядный кластер)

| Параметр | Значение |
|---|---|
| Процессор | Intel Pentium/Xeon с тактовой частотой от 2 400 МГц. Желательны многопроцессорные/многоядерные машины: число процессоров/ядер повышает пропускную способность кластера, особенно при интенсивной одновременной работе нескольких пользователей |
| ОЗУ | от 4 Гбайт |
| Накопитель | Жёсткий диск или SSD. На установку уходит от 1 Гбайта. Объём базы данных в это требование не входит |
| Порты | USB-порт — только если используется ключ аппаратной защиты |

### Поддерживаемые ОС (32-разрядный кластер)

**ОС Linux, процессоры архитектуры x86:**

| Дистрибутив | Версии |
|---|---|
| Astra Linux Common Edition | 2.12 |
| Astra Linux Special Edition | 1.6 |
| CentOS | 7 |
| Debian | 10, 11, 12 |
| Mint | 20, 21 |
| Oracle Linux | 7, 8, 9 |
| Red Hat Enterprise Linux (RHEL) | 7, 8, 9 |
| Ubuntu | 18.04 LTS, 20.04 LTS, 22.04 LTS |
| Альт Линукс | 10 СП, Образование 10, Рабочая станция 10, Рабочая станция К 10 |

- Linux на ARM64 — не поддерживается.
- Linux на E2K — не поддерживается.

**ОС macOS:** не поддерживается ни на x86, ни на ARM64, ни на E2K.

**ОС Windows (только Windows, кратко):**
- x86: Windows 7 Service Pack 1, 8.0, 8.1. Windows Server — не поддерживаются. Должны стоять все актуальные обновления используемой версии ОС.
- ARM64, E2K — не поддерживаются.

Поддержка СУБД зависит от архитектуры процессора, на котором работает система. «+» — СУБД работает на компьютере с процессором указанной архитектуры; пусто — отметки в источнике нет.

### 1.2.2. Требования для работы Дата акселератора

**Лицензионное ограничение:** Дата акселератор доступен только при лицензии КОРП (подробности о видах лицензий — по ссылке «см. здесь»; ⚠ в источнике неясно: адрес ссылки не сохранился).

Компьютер, на котором работает сервис Дата акселератора, должен отвечать специальным требованиям.

| Параметр | Требование |
|---|---|
| Процессор — архитектура | Intel Haswell (в источнике написано «Haswel») или AMD Piledriver, либо любая более поздняя архитектура процессоров Intel или AMD |
| Процессор — число ядер | Не менее двух ядер |
| Что считается ядром | Физическое ядро процессора компьютера (включая ядра, появившиеся за счёт включённого hyper-threading) либо любое ядро виртуальной машины, в которой работает Дата акселератор |
| ОС | Только 64-разрядная (перечень ниже) |
| ОЗУ | Минимум — 64 Гбайта; рекомендуется — 512 Гбайт |

Поддерживаемые 64-разрядные ОС для Дата акселератора:
- **Семейство ОС Linux:** перечень совпадает с требованиями самой системы «1С:Предприятие» (только версии ОС для поддерживаемых архитектур) — см. 1.2.1.
- Семейство Microsoft Windows (только Windows): 7, 8, 8.1, 10, 11 — со всеми установленными обновлениями.
- Семейство Microsoft Windows Server (только Windows): 2012, 2012 R2, 2016, 2019, 2022.

**Особенность Linux — transparent hugepage.** При работе под ОС Linux параметр ядра `/sys/kernel/mm/transparent_hugepage` должен иметь значение `madvise` или `never`. Дата акселератор проверяет значение этого параметра при старте. (Путь приведён так, как он записан в источнике.)

| Параметр ядра Linux | Допустимые значения | Когда проверяется |
|---|---|---|
| `/sys/kernel/mm/transparent_hugepage` | `madvise`, `never` | При старте Дата акселератора |

**Особенность Hyper-V:** если операционная система с Дата акселератором работает под управлением гипервизора Hyper-V, в настройках виртуальной машины нужно выключить флажок «Выполнить перенос на физический компьютер с другой версией процессора». Источник не уточняет, для какой гостевой ОС это требование, — оно сформулировано для любой ОС под Hyper-V.

## 1.3. Общие требования для клиент-серверного варианта работы

### 1.3.1. Общие требования

#### Сеть между компонентами

Когда кластер серверов «1С:Предприятия» и сервер баз данных стоят на разных компьютерах, пропускная способность сетевого соединения между ними может существенно влиять на производительность системы. Рекомендуются сетевые карты с пропускной способностью **1 Гбит и выше** для следующих соединений:

| Соединение | Условие |
|---|---|
| Компьютеры кластера серверов ↔ компьютер с СУБД основной базы данных | всегда |
| Компьютеры кластера серверов ↔ компьютер с СУБД копии базы данных | если используется механизм копии базы данных |
| Компьютер кластера, на котором работает сервис Дата акселератора ↔ остальные компьютеры кластера серверов | если используется механизм Дата акселератора |

#### Ограничение для виртуальных машин с NAT

Не поддерживается запуск клиентского приложения в виртуальной машине при одновременном выполнении двух условий:
- сетевой адаптер виртуальной машины настроен на тип подключения NAT;
- кластер серверов «1С:Предприятия», с которым должно работать клиентское приложение, расположен на компьютере, который является хост-компьютером этой виртуальной машины.

#### Java на компьютерах кластера серверов

Для некоторых механизмов «1С:Предприятия» на компьютерах с кластером серверов должна быть установлена Java.

| Требование | Значение |
|---|---|
| Версия Java | 1.8 или более поздняя |
| Разрядность Java | Должна соответствовать разрядности кластера серверов «1С:Предприятия» |
| Рекомендуемый дистрибутив | Liberica |
| Дополнительная настройка | Для корректной работы механизмов Java может потребовать дополнительной настройки; описание — по ссылке «см. здесь» (⚠ в источнике неясно: адрес ссылки не сохранился) |

Механизмы, которым нужна Java:
- утилита `ring` и связанные с ней утилиты, например утилита лицензирования (`ring license`);
- оптимизированный механизм реструктуризации информационной базы — при использовании СУБД Microsoft SQL Server или PostgreSQL;
- полнотекстовый поиск в данных, версия 2.

#### Энергосбережение на клиентских компьютерах

Важное требование: для нормальной работы клиент-серверного варианта на **клиентских** компьютерах нужно отключить энергосберегающие режимы Sleep, Standby и Hibernate. (Условия, при которых энергосбережение вообще допускается, — в разделе 1.4.)

### 1.3.2. Права пользователя

Речь о пользователе ОС, от имени которого выполняются процессы кластера серверов. По умолчанию это пользователь `USR1CV8`.

| Область | Требуемое право | Примечание |
|---|---|---|
| Общее (любая ОС) | Полные права на каталог, указанный как каталог данных кластера | Если рабочие процессы кластера запускаются от имени отдельного пользователя (через файл `swpuser.ini`), такому пользователю рекомендуется запретить доступ к каталогу данных кластера |
| **ОС Linux** | Право «Чтение» на каталог временных файлов | — |
| ОС Windows (только Windows) | «Список содержимого папки» (List folder contents) на каталог временных файлов | — |
| ОС Windows (только Windows) | «Вход в качестве службы» (Log on as a service) | — |
| ОС Windows (только Windows) | «Вход в качестве пакетного задания» (Log on as a batch job) | — |
| ОС Windows (только Windows) | Членство в группе «Пользователи журналов производительности» (Performance Log Users) | — |

Рекомендации по безопасности:
- Для повышения безопасности кластера в файле `swpuser.ini` рекомендуется задать такие настройки, чтобы рабочие процессы (`rphost`) запускались от имени пользователя, у которого **нет** доступа к каталогу, указанному как каталог данных кластера.
- Если файл `swpuser.ini` используется, то права, которые надо выдать соответствующим пользователям, перечислены в описании этого конфигурационного файла (ссылка «см. здесь»; ⚠ в источнике неясно: адрес ссылки не сохранился).

#### Как «1С:Предприятие» ищет и загружает библиотеки

- Библиотека загружается по имени вида `<имя загружаемой библиотеки>.so.X.Y`, где:
  - `<имя загружаемой библиотеки>` — значение из таблицы выше (например, `libfreetype`);
  - `so` — признак файла с библиотекой;
  - `X.Y` — цифры суффикса той библиотеки, которая присутствует в системе.
- Используются **только** библиотеки, зарегистрированные в системном кеше динамического линковщика времени выполнения. Посмотреть содержимое кеша можно командой:

```
ldconfig -p
```

- Если в системе есть несколько версий одной библиотеки, загружается самая старшая.

## 1.4. Использование энергосберегающих режимов работы компьютера

Если на компьютере запущено «1С:Предприятие», энергосберегающие режимы возможны только при одновременном выполнении **всех** условий:

1. ключ защиты установлен локально;
2. используется файл-серверный вариант;
3. файл базы данных расположен на локальном диске.

Если хотя бы одно условие не выполнено, переход в энергосберегающий режим будет запрещён — независимо от причины, которая его вызвала.

Связь с 1.3.1: там же отдельно требуется отключить режимы Sleep, Standby и Hibernate на клиентских компьютерах клиент-серверного варианта. (Что при клиент-серверной работе условие 2 не выполняется — вывод из перечня условий; отдельной фразой в источнике это не записано.)

## Что важно администратору Linux

1. **Ubuntu для 64-разрядного сервера 1С 8.3.27:** 20.04 LTS, 22.04 LTS, 24.04 LTS — и на x86-64, и на ARM64. Ubuntu 18.04 LTS есть только в перечне 32-разрядного сервера (вместе с 20.04 и 22.04), в 64-разрядном перечне её нет.
2. **За текущими списками документация отсылает на сайт.** Актуальные дистрибутивы ОС, разрядность, точные номера версий СУБД и патчи для Oracle — на `http://www.v8.1c.ru/requirements/` (в разделах 1.5.1 и 1.5.6 тот же адрес записан без `www`: `http://v8.1c.ru/requirements/`).
3. **Минимум ресурсов 64-разрядного рабочего сервера:** ОЗУ от 4 Гбайт (рекомендуется от 8 Гбайт), от 1 Гбайта диска на саму установку без учёта базы данных; многоядерность прямо влияет на пропускную способность кластера. Требования к серверу СУБД сюда не входят — их задаёт документация СУБД.
4. **ARM64 и E2K — только с лицензией КОРП.** На x86-64 такого ограничения в главе нет.
5. **PostgreSQL — единственная СУБД, отмеченная для всех трёх архитектур 64-разрядного кластера** (x86-64, ARM64, E2K). Поддерживаемые версии: 8.1.5, 8.2.4, 8.3.8, 8.4.3, 9.0.3, 9.1–9.6, 10–18. Варианты: сборка с патчем «1С» (`https://releases.1c.ru/project/AddCompPostgre`, нужен доступ к техподдержке), PostgreSQL от Postgres Pro, Postgres Pro Standard, Postgres Pro Enterprise.
6. **Разрядность сервера 1С и СУБД независимы,** но на 64-разрядную ОС следует ставить 64-разрядную версию СУБД (если она существует), на 32-разрядную — 32-разрядную.
7. **Сеть 1 Гбит и выше** между кластером 1С и сервером СУБД, если они на разных машинах; то же — до СУБД копии базы данных и до узла с Дата акселератором, если эти механизмы используются.
8. **Java 1.8+ той же разрядности, что и кластер** (рекомендуется Liberica) нужна на серверах кластера для: утилиты `ring` (включая `ring license`), оптимизированной реструктуризации ИБ на PostgreSQL (и MS SQL Server), полнотекстового поиска версии 2. Java может потребовать дополнительной настройки.
9. **Библиотеки Linux для сервера:** `libfreetype` ≥ 2.1.9, `libgsf-1` ≥ 1.10.1, `libglib-2.0` ≥ 2.12.4, `libodbc` ≥ 2.2.11, `libkrb5` ≥ 1.4.2, `libgssapi_krb5` ≥ 1.4.2, плюс Microsoft Core Fonts. Назначение: `libfreetype` — управляемый режим, табличные документы/диаграммы/графические схемы на сервере и сохранение в PDF; `libgsf-1` и `libglib-2.0` — экспорт/импорт XLS; `libodbc` — внешние источники данных; `libkrb5` и `libgssapi_krb5` — аутентификация средствами ОС.
10. **1С видит только библиотеки из кеша динамического линковщика.** Проверка — `ldconfig -p`. Библиотека грузится по имени `<имя>.so.X.Y`; при нескольких версиях берётся самая старшая. Библиотека, лежащая вне кеша `ldconfig`, использована не будет.
11. **Права пользователя кластера (по умолчанию `USR1CV8`) в Linux:** полные права на каталог данных кластера и право чтения на каталог временных файлов.
12. **Усиление безопасности через `swpuser.ini`:** рабочие процессы `rphost` рекомендуется запускать от отдельного пользователя, у которого нет доступа к каталогу данных кластера; нужные этому пользователю права описаны в документации по самому файлу `swpuser.ini`.
13. **Дата акселератор на Linux:** только лицензия КОРП, процессор архитектуры Intel Haswell / AMD Piledriver или более поздней и не менее 2 ядер, ОЗУ минимум 64 Гбайта (рекомендуется 512 Гбайт), параметр ядра `/sys/kernel/mm/transparent_hugepage` — `madvise` или `never` (проверяется при старте). Под Hyper-V в настройках ВМ выключается флажок переноса на физический компьютер с другой версией процессора.
14. **Виртуальные машины и NAT:** клиентское приложение в ВМ с сетевым адаптером типа NAT не поддерживается, если кластер серверов 1С расположен на хост-компьютере этой же ВМ.
15. **Энергосбережение:** на клиентских компьютерах клиент-серверного варианта режимы Sleep, Standby и Hibernate нужно отключить; при запущенной 1С энергосберегающий режим допускается только при локальном ключе защиты, файл-серверном варианте и файле базы на локальном диске одновременно.
