## 3.1. Общая информация

Приложение 3 — справочник по назначению и расположению служебных файлов, которые платформа «1С:Предприятие» может использовать в работе.

## 3.2. *.1ccr

Конфигурационный файл веб-сервиса для работы с удалённым хранилищем конфигурации.

- Имя файла произвольное, расширение `1ccr` обязательно.
- Формат — XML с единственным узлом. Имя узла произвольное.
- Единственный атрибут узла — `connectString`: адрес сервера хранилища в схеме TCP.

Пример (`repository.1ccr`; имя узла `repository` выбрано произвольно, сервер хранилища — `tcp://RepServ`):

```xml
<?xml version="1.0" encoding="UTF-8"?>
<repository connectString="tcp://RepServ"/>
```

## 3.3. *.mft

Файл-манифест, описывающий шаблон конфигурации.

- Имя произвольное, расширение `mft`; лежит в каталоге установленного шаблона конфигурации.
- Внутренний формат близок к ini-файлу; кодировка UTF-8 (ради поддержки нескольких языков).
- В каталоге шаблона конфигурации может быть несколько cfu-файлов.

Параметры в начале файла (до секций):

| Параметр | Назначение |
|---|---|
| `Vendor` | поставщик решения; совпадает с указанным в конфигурации |
| `Name` | наименование решения; совпадает с указанным в конфигурации |
| `Version` | версия решения; совпадает с указанной в конфигурации |
| `AppVersion` | версия «1С:Предприятия», которой создавался комплект поставки |

Параметры частей решения. Части разделяются секциями; имена секций произвольные, в квадратных скобках:

| Параметр | Назначение |
|---|---|
| `Source` | относительный путь к файлу конфигурации (cf), файлу обновления (cfu) или выгрузке базы (dt) |
| `Catalog_<суффикс языка>` | наименование решения в каталоге решений. Параметров может быть несколько; суффикс задаёт язык интерфейса платформы (например, `ru`). `Catalog` без суффикса действует для всех языков интерфейса, для которых в этой секции нет своего `Catalog_<язык>` |
| `Destination` | рекомендуемый каталог создания ИБ при создании базы из шаблона. Частичный путь; одной из частей должен быть каталог поставщика (чтобы каталоги разных решений не совпали) |

Пример:

```ini
Vendor=Фирма "1С"
Name=Управление Торговлей
Version=8.10.0.2
[Main]
Source=Main\1cv8.cf
Catalog_ru=Управление торговлей/Управление торговлей
Destination=1C\Trade
[Demo]
Source=Demo\1cv8.dt
Catalog_ru=Управление торговлей/Управление торговлей (Демо)
Destination=1C\DemoTrd
```

## 3.4. *.v8i

Файл описаний зарегистрированных информационных баз; этим списком пользуются все клиенты. Имя по умолчанию — `ibases.v8i`.

Расположение:

- Linux: `~\.1C\1cestart` (в разделе 3.4 путь записан с обратными слэшами; в разделе 3.6.1 тот же каталог дан как `~/.1C/1cestart`).
- macOS: `~\.1C\1cestart`.
- Windows: `%APPDATA%\1C\1CEStart\` локального компьютера.

Формат: текстовый документ в кодировке UTF-8, состоит из секций; одна секция — одна информационная база. Наименование секции и каждый параметр — на отдельной строке.

Шаблон секции (как приведён в источнике):

```ini
[Наименование секции]
Connect=
ID=
OrderInList=
Folder=
OrderInTree=
External=
ClientConnectionSpeed=
App=
AppArch=
DefaultApp=
WA=
WSA=
Version=
DefaultVersion=
AdditionalParameters=
WebCommonInfoBaseURL=
HttpsCA=
HttpsCert=
HttpsCAFile=
HttpsCertFile=
HttpsCertSelect=
ShowInList=
MobilePublicKey=
WebCommonInfoBases=
```

⚠ в источнике неясно: параметры `External` и `WebCommonInfoBases` присутствуют в шаблоне секции, но отдельного описания для них в разделе 3.4 нет. И наоборот: описанные ниже `UseProxy`, `PSrv`, `PPort`, `PUser`, `PPasswd`, `StartupErrorHelpURL`, `StartupErrorHelpText`, `InternetService` и параметры мобильного клиента в шаблоне не перечислены.

### Параметры секции (общие)

| Параметр | Обязательность | Назначение | Значения / умолчание / примечание |
|---|---|---|---|
| `[Наименование секции]` | обязательный | совпадает с наименованием ИБ; пишется в квадратных скобках | редактируется в окне свойств ИБ. Пример: `[Демонстрационная версия 8.2]` |
| `ID` | — | внутренний идентификатор ИБ | формируется автоматически; уникален в пределах одного v8i; задавать вручную не рекомендуется. Пример: `ID=cf9f0d4b-b4a3-11d8-861e-0050baaa2f3f` |
| `Connect` | обязательный | строка соединения с ИБ | допускается несколько описаний с одинаковой строкой, но разными наименованиями (например, чтобы запускать одну базу тонким и толстым клиентом, не меняя свойств ИБ). Форматы — ниже |
| `Folder` | — | папка в дереве информационных баз | если не указан или пуст — база лежит в корне списка. Пример: `Folder=/Торговыебазы` |
| `OrderInList` | — | порядок в списке при представлении списком | число; действует, когда сортировка по наименованию не установлена. Пример: `OrderInList=5` |
| `OrderInTree` | — | порядок в ветви при представлении деревом | пример: `OrderInTree=16358` |
| `UseProxy` | — | вариант использования прокси для ws-соединения | `0` — прокси не используется; `1` — автоопределение настроек прокси; `2` — явное указание настроек. Если параметр не указан — автоопределение. Для файлового и клиент-серверного вариантов смысла не имеет |
| `PSrv` | обязателен только при `UseProxy=2` | адрес прокси-сервера | пример: `PSrv=192.168.0.1` |
| `PPort` | обязателен только при `UseProxy=2` | порт прокси-сервера | пример: `PPort=123` |
| `PUser` | — | имя пользователя прокси-сервера | пример: `PUser=userName` |
| `PPasswd` | — | зашифрованный пароль прокси-сервера | пример: `PPasswd=XNKxbVEqnXUCwwk1Urovbo7bZFpG/Zpf6cQ10qVtzpk=` |
| `ClientConnectionSpeed` | — | скорость клиентского соединения (только тонкий и веб-клиент) | `Normal` — обычная; `Low` — низкая. Если не указан — определяется флажком «Низкая скорость соединения» окна запуска (эквивалент значения «Выбирать при запуске» параметра «Скорость соединения» в свойствах ИБ) |
| `WA` | — | вариант аутентификации пользователя | `1` — сначала аутентификация средствами ОС, при неудаче запрашивается логин/пароль; `0` — всегда логин/пароль |
| `WSA` | — | вариант аутентификации на веб-сервере, когда веб-сервер — промежуточное звено (тонкий клиент через веб-сервер и веб-клиент) | `1` — сначала аутентификация ОС на веб-сервере, при неудаче запрос логина/пароля; `0` — всегда запрашивать логин/пароль |
| `App` | — | тип клиентского приложения | `Auto` — автовыбор; `ThinClient` — тонкий клиент; `ThickClient` — толстый клиент; `WebClient` — веб-клиент. Редактируется в окне свойств ИБ |
| `DefaultApp` | — | тип клиента, который программа запуска определила и записала сама при автоопределении (ключ `/AppAutoCheckMode`) | `ThinClient`, `ThickClient`. Если `App=Auto` и `DefaultApp` не задан — запускается тонкий клиент с ключом `/AppAutoCheckMode`. Если `DefaultApp` задан — запускается указанный в нём клиент с ключом `/AppAutoCheckMode` |
| `Version` | — | версия платформы, которой следует запускать ИБ | редактируется в окне свойств ИБ. Пример: `Version=8.3.24` |
| `DefaultVersion` | — | версия платформы, реально использованная при последнем запуске этой ИБ | записывается программой запуска автоматически при запуске с ключом `/AppAutoCheckVersion`. При следующих запусках используется именно она, а не значение `Version`. Пример: `DefaultVersion=8.3.24.100` |
| `AdditionalParameters` | — | дополнительные параметры запуска (поле «Дополнительные параметры запуска» окна свойств ИБ) | пример: `AdditionalParameters=/TechnicalSpecialistMode` |
| `WebCommonInfoBaseURL` | — | адрес интернет-сервиса, от которого получено описание этой ИБ (если база попала в список через интернет-сервис получения списка общих ИБ) | пример: `WebCommonInfoBaseURL=http://info-server/listservice`. Подробности — ниже |
| `HttpsCA` | — | тип источника сертификатов удостоверяющих центров для проверки серверного сертификата | `None` — сертификаты УЦ не используются, серверный сертификат не проверяется; `File` — сертификаты УЦ в файле; `Windows` — системное хранилище сертификатов Windows; `Linux` — каталог сертификатов ОС Linux; `macOS` — системное хранилище сертификатов macOS |
| `HttpsCert` | — | тип источника клиентского сертификата и его закрытого ключа | `None` — клиентский сертификат не используется; `File` — в файле; `Windows` — системное хранилище Windows; `Linux` — каталог сертификатов ОС Linux; `macOS` — системное хранилище macOS |
| `HttpsCAFile` | — | путь к файлу с сертификатами УЦ | если `HttpsCA=File`, а параметр отсутствует или пуст — считается `HttpsCA=None` |
| `HttpsCertFile` | — | путь к файлу с клиентским сертификатом и его закрытым ключом | если `HttpsCert=File`, а параметр отсутствует или пуст — считается `HttpsCert=None` |
| `HttpsCertSelect` | — | способ выбора клиентского сертификата ОС Windows, когда подходящих для соединения сертификатов больше одного | `Recent` — использовать запомненный; если запомненного нет — открыть диалог выбора и запомнить выбор; `Choose` — всегда выбирать (выбор запоминается и может быть использован позже при `Recent`); `Auto` — подобрать автоматически без диалога |
| `AppArch` | — | разрядность клиентского приложения для этой ИБ | значения совпадают с параметрами команды `/AppArch` командной строки запуска клиента |
| `StartupErrorHelpURL` | — | URL для гиперссылки «Нужна помощь?» в диалоге ошибки подключения к ИБ | рекомендуется адрес страницы с типовыми проблемами подключения и их решениями, контактами техподдержки и т. п. |
| `StartupErrorHelpText` | — | вспомогательный текст в диалоге ошибки подключения к ИБ (например, телефон поддержки) | простая строка либо форматированная строка. Для форматированной — значение должно быть сериализованным: `СериализаторXDTO.XMLСтрока(ТекстДляДиалога)`, где `ТекстДляДиалога` — значение типа `ФорматированнаяСтрока` |

Форматы значения `Connect`:

```ini
; файловый вариант
Connect=File=<Путь>;
; клиент-серверный вариант
Connect=Srvr=<ИмяСервера1СПредприятия>;Ref=<ИмяИнформационнойБазыНаСервере>;
; подключение через веб-сервер
Connect=ws="http://web-server/resource/";
```

(Строки-комментарии с `;` в блоке выше — пояснения конспекта, не часть синтаксиса из источника.)

Поведение, связанное с `WebCommonInfoBaseURL`:

- Если интерактивная программа запуска (`1cv8s`) при интерактивном запуске выясняет, что список общих ИБ, полученный от интернет-сервиса, обновлять не нужно (вызов веб-сервиса `WebCommonInfoBases.CheckInfoBases()` вернул `InfoBaseChanged` = Ложь), описания всех баз из этого источника остаются в списке до следующего запуска.
- Если из `1cestart.cfg` удалить параметры `InternetService` или `WebCommonInfoBases`, сведения о базах, полученных из удалённых источников, будут убраны из списка.

## 3.5. 1cescmn.cfg

**Только Windows.** Общий конфигурационный файл программ запуска (`1cestart` и `1cv8s`). Лежит в каталоге, откуда выполняется установка, если дистрибутивы расположены в сетевом каталоге. Текст в UTF-8 или UTF-16LE, строки вида `<Параметр>=<Значение>`. Состав параметров тот же, что у `1cestart.cfg` (раздел 3.6), кроме `CommonCfgLocation` — его общий файл содержать не может.

```ini
CommonInfoBases=ibcommon.v8i
DistributiveLocation=\\server\v8dst
```

В примере `ibcommon.v8i` — файл списка общих ИБ, который должен лежать в одном каталоге с интерактивной программой запуска (`1cestart`); `\\server\v8dst` — каталог дистрибутивов версий платформы.

## 3.6. 1cestart.cfg

### 3.6.1. Общая информация

Файл настроек, которыми пользуются программы запуска (`1cestart` и `1cv8s`), клиентские приложения (`1cv8` и `1cv8c`) и внешнее соединение.

Расположение:

- Linux: `~/.1C/1cestart`.
- macOS: `~/.1C/1cestart`.
- Windows, установка «для компьютера»:
  - `%APPDATA%\1C\1CEStart` — файл конкретного пользователя; меняется при настройке окна запуска;
  - `%ALLUSERSPROFILE%\1C\1CEStart` — файл для всех пользователей компьютера; меняется только во время установки платформы.
- Windows, установка «для пользователя»: `%APPDATA%\1C\1CEStart` — файл конкретного пользователя; меняется при настройке окна запуска.

Формат: текстовый документ в кодировке **UTF-16LE**, строки вида `<Параметр>=<Значение>`.

Терминология, используемая в правилах приоритета ниже (по смыслу разделов 3.5 и 3.6.1; отдельного определения терминов в источнике нет):

- «локальный конфигурационный файл» — `1cestart.cfg` конкретного пользователя;
- «локальный конфигурационный файл для всех пользователей» — `1cestart.cfg` из `%ALLUSERSPROFILE%` (Windows);
- «общий конфигурационный файл» — `1cescmn.cfg` (раздел 3.5).

Пример файла:

```ini
DefaultVersion=8.2-8.2.16
DefaultVersion=8.3-8.3.24
CommonCfgLocation=\\Server\v8\1cescmn.cfg
CommonInfoBases=\\Server\common\common_dblist.v8i
InstalledLocation=C:\Program Files\1cv8
DistributiveLocation=\\server\dst1C\v8
ConfigurationTemplatesLocation=\\server\tmplts
ConfigurationTemplatesLocation=C:\Documents and Settings\User\Application Data\1C\1cv8\tmplts
InstallComponents=DESIGNERALLCLIENTS=1 THINCLIENT=1 WEBSERVEREXT=1 SERVER=1 CONFREPOSSERVER=0 CONVERTER77=1 SERVERCLIENT=1 LANGUAGES=RU
UseHwLicenses=0
AppAutoInstallLastVersion=0
```

Сводка параметров (подробности — в подразделах):

| Параметр | Кратко | Умолчание | Из каких файлов берётся значение |
|---|---|---|---|
| `AppAutoInstallLastVersion` | автоустановка новой версии платформы | `1` | из одного файла: локальный → локальный для всех пользователей → общий |
| `AutoUninstall` | автоудаление устаревших версий | `1` | из одного файла: общий → локальный → локальный для всех пользователей |
| `AutoUninstallVersionsAfter` | через сколько дней после установки версия считается устаревшей | `90` | из одного файла: общий → локальный → локальный для всех пользователей |
| `CommonCfgLocation` | путь и имя общего конфигурационного файла | — | из всех файлов; допускается несколько строк |
| `CommonInfoBases` | путь и имя файла списка общих ИБ | — | из всех файлов |
| `ConfigurationTemplatesLocation` | каталог шаблонов конфигураций | — | из всех файлов; допускается несколько записей |
| `DefaultVersion` | версия (и разрядность), используемая по умолчанию | — | из всех файлов; допускается несколько строк |
| `DisableInstallerVerification` | отключение проверки подписи программы установки клиента | `0` | только Windows |
| `DistributiveLocation` | каталог поиска новой версии для автоустановки | — | из всех файлов |
| `DontUninstallVersion` | версия, защищённая от автоудаления | — | из всех файлов; допускается много строк |
| `InstallComponents` | перечень компонентов (установленных / к установке) | — | из одного файла: локальный для всех пользователей → локальный → общий |
| `InstalledLocation` | каталог, куда установлена платформа | корневой каталог установки для данной ОС | из всех файлов, в порядке: общий → локальный для всех пользователей → локальный |
| `InstallForUsers` | режим установки в зависимости от прав пользователя | `0` | только Windows |
| `InternetService` | URL интернет-сервиса списка общих ИБ и дистрибутива клиента | — | в источнике не указано |
| `UseHwLicenses` | поиск ключа защиты при запуске | `1` | из одного файла: локальный → локальный для всех пользователей → общий |
| `WebCommonInfoBases` | URL интернет-сервиса списка общих ИБ | — | в источнике не указано |
| `WebDistributiveLocation` | URL интернет-сервиса дистрибутива клиента | — | в источнике не указано |

### 3.6.2. AppAutoInstallLastVersion

Нужно ли автоматически устанавливать новую версию «1С:Предприятия»:

- `0` — автоустановка выключена;
- `1` — автоустановка включена (по умолчанию).

Берётся значение из одного файла по приоритету: локальный → локальный для всех пользователей → общий.

Исключение: если на компьютере нет версии, которую требует сервер (клиент-серверный вариант) или которая явно задана для ИБ, значение параметра (и из файлов, и из командной строки) игнорируется — попытка установить новую версию будет предпринята в любом случае.

### 3.6.3. AutoUninstall

Нужно ли автоматически удалять устаревшие версии:

- `0` — не удалять;
- `1` — удалять (по умолчанию).

Берётся значение из одного файла по убыванию приоритета: общий → локальный → локальный для всех пользователей.

### 3.6.4. AutoUninstallVersionsAfter

Число дней с момента установки версии, после которого она считается устаревшей. По умолчанию `90`.

Приоритет тот же, что у `AutoUninstall`: общий → локальный → локальный для всех пользователей (значение из одного файла).

### 3.6.5. CommonCfgLocation

Путь и имя общего конфигурационного файла. Строк с параметром может быть несколько; используются значения из всех конфигурационных файлов.

Примечание документации: в общем конфигурационном файле (`1cescmn.cfg`) использовать параметр не рекомендуется (в разделе 3.5 сказано жёстче — общий файл такой строки содержать не может).

### 3.6.6. CommonInfoBases

Путь и имя файла со списком общих информационных баз (формат — раздел 3.4). Используются значения из всех конфигурационных файлов.

### 3.6.7. ConfigurationTemplatesLocation

Путь к каталогу шаблонов конфигураций. Записей может быть несколько; используются значения из всех конфигурационных файлов.

### 3.6.8. DefaultVersion

Версия, используемая по умолчанию. Строк может быть несколько; используются значения из всех конфигурационных файлов.

В значении можно указать и разрядность запускаемого клиента: версия и разрядность разделяются символом `;`. Допустимые значения разрядности — те же, что у параметра `/AppArch` командной строки запуска клиентского приложения.

| Пример | Смысл |
|---|---|
| `DefaultVersion=8.3-8.3.24.100` | при запуске ИБ с указанной версией 8.3 будет использована 8.3.24.100 |
| `DefaultVersion=8.2.15-8.2.15.315` | при запуске ИБ с версией 8.2.15 будет использована 8.2.15.315 |
| `DefaultVersion=8.3;x86_64_prt` | любая ИБ запускается клиентом версии 8.3 с приоритетом 64-разрядного приложения |

### 3.6.9. DisableInstallerVerification

**Только Windows.** Отключает проверку цифровой подписи программы установки клиентского приложения, полученной по HTTP или из самораспаковывающегося архива прикладного решения (созданного утилитой `1CEClientSetupMake`): `1` — проверка отключена; `0` — проверка включена (по умолчанию).

### 3.6.10. DistributiveLocation

Каталог, в котором ищется новая версия для автоматической установки. Используются значения из всех конфигурационных файлов. Дополнительно дистрибутивы новых версий ищутся в каталоге, где лежит общий конфигурационный файл (`1cescmn.cfg`).

### 3.6.11. DontUninstallVersion

Версия, на которую не распространяется механизм автоматического удаления. Параметров в файле может быть много — удаление блокируется для всех перечисленных версий. Используются значения из всех конфигурационных файлов.

### 3.6.12. InstallComponents

- В локальном файле и локальном файле для всех пользователей (`1cestart.cfg`) — перечень уже **установленных** компонентов.
- В общем файле (`1cescmn.cfg`) — перечень компонентов, которые **нужно установить** (составляет администратор).

Берётся значение из одного файла по приоритету: локальный для всех пользователей → локальный → общий.

Значение — строка «компонент=признак», разделённых пробелом; признак `0` — не устанавливать, `1` — устанавливать.

| Компонент | Описание |
|---|---|
| `CONFREPOSSERVER` | сервер хранилища конфигураций «1С:Предприятия» |
| `CONVERTER77` | конвертер информационных баз из «1С:Предприятия 7.7» |
| `DESIGNERALLCLIENTS` | все клиенты и конфигуратор |
| `LANGUAGES` | список устанавливаемых языков интерфейса; несколько языков — через запятую |
| `SERVER` | сервер «1С:Предприятия». Если программа установки запущена из программы запуска, сервер ставится как приложение |
| `SERVERCLIENT` | компоненты администрирования кластера серверов «1С:Предприятия» |
| `THINCLIENT` | тонкий клиент для клиент-серверного варианта |
| `THINCLIENTFILE` | тонкий клиент с возможностью работы с файловыми ИБ |
| `WEBSERVEREXT` | компоненты расширения веб-сервера |

Язык с кодом `EN` устанавливается всегда — даже если не перечислен в `LANGUAGES` или сам `LANGUAGES` не задан.

```ini
LANGUAGES=RU,UK,BG
InstallComponents=DESIGNERALLCLIENTS=0 THINCLIENT=1 WEBSERVEREXT=0 SERVER=0 CONFREPOSSERVER=0 CONVERTER77=0 SERVERCLIENT=1 LANGUAGES=RU,EN
```

(Первая строка — пример значения компонента `LANGUAGES`, вторая — пример параметра целиком.)

### 3.6.13. InstalledLocation

Каталог, в который установлена платформа. По умолчанию — корневой каталог установки соответствующей ОС.

Используются значения из всех конфигурационных файлов в порядке: общий → локальный для всех пользователей → локальный.

Примечание документации: в общем конфигурационном файле (`1cescmn.cfg`) использовать параметр не рекомендуется.

### 13.4.1. InstallForUsers

(Номер подраздела «13.4.1» — так в источнике; подраздел расположен внутри 3.6, между 3.6.13 и 3.6.14.)

**Только Windows.** Режим установки платформы в зависимости от прав текущего пользователя:

| Значение | Режим |
|---|---|
| `0` | режим определяется правами текущего пользователя (по умолчанию) |
| `1` | установка «для компьютера» |
| `2` | установка «для текущего пользователя» с возможностью уточнить режим у пользователя |
| `3` | установка «для текущего пользователя» без уточнения режима у пользователя |

### 3.6.14. InternetService

URL интернет-сервиса, который отдаёт и список общих информационных баз, и дистрибутив клиентского приложения.

Порядок получения нужного файла (списка общих ИБ или дистрибутива клиента): сначала HTTP-запрос, при неудаче — обращение через Web-сервис.

```text
HTTP-запрос:  <Адрес из параметра InternetService>/<Имя сервиса>/<Имя метода>/?<Параметры метода>
WSDL-адрес:   <Адрес из параметра InternetService>/<Имя сервиса>/?wsdl
```

### 3.6.15. UseHwLicenses

Управляет поиском ключа защиты (и локального, и сетевого) при запуске «1С:Предприятия»:

- `1` — поиск ключа выполняется (по умолчанию);
- `0` — поиск ключа не выполняется.

Берётся значение из одного файла по приоритету: локальный → локальный для всех пользователей → общий.

Назначение: отключить поиск ключа там, где клиентские лицензии выдаёт расширение веб-сервера или сервер «1С:Предприятия», либо используется базовая версия.

Система может менять значение сама:

- Поиск включён, ключ не найден, запуск при этом успешен, а поиск занял больше 3 секунд — пользователю предлагается отключить поиск для ускорения следующих запусков. При согласии в `1cestart.cfg` этого пользователя пишется `UseHwLicenses=0`.
- Поиск отключён, а при запуске лицензия не получена ни от сервера «1С:Предприятия», ни от расширения веб-сервера — пользователю предлагается включить поиск. При согласии в `1cestart.cfg` этого пользователя пишется `UseHwLicenses=1`, клиентское приложение перезапускается.

Внешнее соединение: параметр читается из `1cestart.cfg` в профиле пользователя, от имени которого запускается внешнее соединение. Если профиля у пользователя нет (например, `LocalSystem` в Windows), поиск ключа выполняется всегда.

### 3.6.16. WebCommonInfoBases

URL интернет-сервиса, который отдаёт список общих информационных баз. Порядок тот же: сначала HTTP-запрос, при неудаче — Web-сервис.

```text
HTTP-запрос:  <Адрес из параметра WebCommonInfoBases>/<Имя сервиса>/<Имя метода>/?<Параметры метода>
WSDL-адрес:   <Адрес из параметра WebCommonInfoBases>/<Имя сервиса>/?wsdl
```

Если заданы и `InternetService`, и `WebCommonInfoBases` — сначала используется адрес из `WebCommonInfoBases`, при неудаче — адрес из `InternetService`.

### 13.4.2. WebDistributiveLocation

(Номер подраздела «13.4.2» — так в источнике; подраздел расположен внутри 3.6, после 3.6.16.)

URL интернет-сервиса, который отдаёт дистрибутив клиентского приложения. Сначала HTTP-запрос, при неудаче — Web-сервис.

```text
HTTP-запрос:  <Адрес из параметра WebDistributiveLocation>/<Имя сервиса>/<Имя метода>/?<Параметры метода>
WSDL-адрес:   <Адрес из параметра WebDistributiveLocation>/<Имя сервиса>/?wsdl
```

Если заданы и `InternetService`, и `WebDistributiveLocation` — сначала используется адрес из `WebDistributiveLocation`, при неудаче — адрес из `InternetService`.

## 3.7. 1CV8Clst.lst

Реестр кластера. Файл лежит в каталоге данных каждого рабочего сервера, отмеченного как центральный.

Содержит:

- список информационных баз, зарегистрированных в кластере;
- список рабочих серверов кластера;
- список рабочих процессов кластера;
- список менеджеров кластера;
- список сервисов кластера;
- список администраторов кластера.

Пример пути (в источнике приведён только Windows-вариант):

```text
C:\Program Files\1cv8\srvinfo\reg_1541\1CV8Clst.lst
```

## 3.8. 1cv8conn.pfl

Содержит список центральных серверов кластера в разрезе информационных баз и другую информацию, нужную клиентским и серверным приложениям платформы.

Требование к правам: пользователи, от имени которых запускаются приложения «1С:Предприятия», должны иметь права на создание, чтение и изменение данных в каталоге, где лежит файл, — иначе надёжная работа не гарантируется.

Расположение:

- Linux: `~/.1cv8/1C/1cv8`.
- macOS: `~/.1cv8/1C/1cv8`.
- Windows: `%ALLUSERSPROFILE%\1C\1cv8`.

Только Windows: если платформой на одном компьютере пользуются разные пользователи, рекомендуется дать всем им (или группе USERS) полный доступ к каталогу файла, а пользователя «СОЗДАТЕЛЬ-ВЛАДЕЛЕЦ» (CREATOR OWNER) убрать из списка безопасности каталога.

## 3.9. 1cv8wsrv.lst

Список кластеров, зарегистрированных на данном компьютере сервера «1С:Предприятия». Хранится на компьютере рабочего сервера, отмеченного как центральный, в каталоге служебных файлов кластера. Данные файла нужны для нормальной работы приложений, использующих этот сервер.

Пример пути (в источнике приведён только Windows-вариант):

```text
C:\Program Files\1cv8\srvinfo\1cv8wsrv.lst
```

## 3.10. adminstall.cfg

**Только Windows.** Признак того, что платформа устанавливалась средствами администрирования ОС Windows. Лежит в каталоге конфигурационных файлов платформы, текст в UTF-8, единственная строка:

```ini
AdmInstall=<Mode>
```

`<Mode>`: `Logon` — установка logon-скриптом при входе пользователя в домен; `Restart` — установка через групповые политики.

В документации приведён пример VBScript-сценария установки/удаления через `WindowsInstaller.Installer` (процедура `installOrUninstall` с параметрами `productCode` — значение `ProductCode` из `setup.ini`, `msiPackage`, `mstTransform`, `requiredAction`; установка с `TRANSFORMS=adminstallrelogon.mst;` плюс языковое преобразование вида `1049.mst`, удаление с `REMOVE=ALL`; создание ярлыка на `1cestart.exe`; в командную строку инсталлятора можно добавить перечень компонентов в том же виде, что у `InstallComponents`). Для Linux не применимо.

## 3.11. agentbasedir.json

Соответствие имени пользователя и его рабочего каталога при работе агента конфигурирования.

- Лежит в рабочем каталоге конфигуратора, запущенного в режиме агента.
- Рабочий каталог задаётся командой `/AgentBaseDir` командной строки запуска конфигуратора в режиме агента.

Структура:

```json
{
"usersInfo": [
{
"name": "имя_пользователя",
"dir": "имя_каталога"
},
…
]
}
```

`имя_пользователя` — пользователь, работающий с агентом; `имя_каталога` — имя служебного каталога этого пользователя. Если с агентом работают несколько пользователей, в массиве будет по записи на каждого.

См. также (ссылки документации): работа конфигуратора в режиме агента; параметры командной строки запуска в режиме агента.

## 3.12. appsrvrs.lst

**Только Windows.** Список серверов «1С:Предприятия», зарегистрированных в утилите администрирования информационных баз в варианте клиент-сервер. Лежит в `%LOCALAPPDATA%\1C\1cv8`; примеры: `C:/Documents and Settings/User/Local Settings/Application Data/1C/1cv8/appsrvrs.lst`, `C:/Users/User/AppData/Local/1C/1cv8/appsrvrs.lst`.

## 3.13. cacertnx.pem и cacert.pem

Файлы с сертификатами доверенных удостоверяющих центров. Платформа использует их для проверки валидности сертификатов, предъявляемых при установке защищённого соединения. Какой файл используется — зависит от версии платформы и режима совместимости:

| Версия платформы | Режим совместимости | Что используется |
|---|---|---|
| до 8.3.8 | «Версия 8.3.7» и предыдущие | только `cacert.pem` |
| с 8.3.8 и до 8.3.19 | «Версия 8.3.8» | только механизм получения сертификатов УЦ, предоставляемый операционной системой |
| начиная с 8.3.20 | «Версия 8.3.8» и последующие | сначала `cacertnx.pem`, затем механизм операционной системы |
| начиная с 8.3.20 | «Версия 8.3.7» и предшествующие | только `cacert.pem` |

Обновление `cacertnx.pem` при обновлении платформы: обновлённый файл можно положить в состав одного из дистрибутивов —

- тонкий клиент (32- и 64-разрядный);
- полный дистрибутив (клиент и сервер) (32- и 64-разрядный).

Новый файл кладётся на одном уровне («рядом») с MSI-файлом дистрибутива; при установке он заменит файл из комплекта поставки. Процедура описана в терминах MSI-дистрибутива; способ для Linux-пакетов в источнике не описан.

## 3.15. ClientUpdate.cfg

Настройка предварительной загрузки дистрибутива клиентского приложения при работе по протоколу HTTP.

- Лежит в каталоге конфигурационных файлов платформы; наличие необязательно.
- Регистр имени: в Windows не важен; в Linux и macOS важен — имя должно быть ровно `ClientUpdate.cfg`.
- Формат: пары «ключ=значение», кодировка UTF-8; наличие BOM роли не играет.

| Ключ | Обязательность | Назначение |
|---|---|---|
| `Version` | обязательный | номер версии, для которой в файле заданы параметры обновления (дата обновления и пути к дистрибутивам); вид `A.B.C.D` |
| `UpdateDate` | — | дата и время предполагаемого обновления версии на стороне кластера серверов; клиент по этому значению планирует скачивание дистрибутива. Канонический формат `YYYYMMDDHHMMSS` (год, месяц, день, часы, минуты, секунды) |

| `PublishDistributiveLocationWindows64` | — | расположение дистрибутива клиента для Windows, 64 разряда |

| `PublishDistributiveLocationLinux32` | — | расположение дистрибутива клиента для Linux, 32 разряда |
| `PublishDistributiveLocationLinux64` | — | расположение дистрибутива клиента для Linux, 64 разряда |

Ключи `PublishDistributiveLocation*` по поведению и содержанию аналогичны атрибутам `pubdst32`, `pubdst64`, `pubdstmac64`, `pubdstlin32` и `pubdstlin64` элемента `point` файла `default.vrd`.

См. также (ссылка документации): использование файла clientupdate.cfg.

## 3.16. comcntrcfg.xml

**Только Windows.** Указывает внешнему соединению, что запускаться нужно в отладочном режиме. Лежит в каталоге конфигурационных файлов платформы; необязателен — если файла нет, внешнее соединение открывается в обычном режиме.

```xml
<config xmlns="http://v8.1c.ru/v8/comcntrcfg">
<debugconfig debug="true" protocol="tcp" debuggerURL="tcp://localhost:1560"/>
</config>
```

Атрибуты элемента `debugconfig`:

| Атрибут | Назначение | Значения / умолчание |
|---|---|---|
| `debug` | запуск в отладочном режиме (тип Булево) | `true` — отладка включена; `false` — выключена |
| `protocol` | протокол отладки (если отладка разрешена) | `tcp` — TCP/IP (по умолчанию); `http` — HTTP |
| `debuggerURL` | адрес отладчика для автоматического подключения | `localhost` — искать на локальном компьютере, `1560` — сетевой порт. Порт не указан — перебираются порты диапазона 1560–1591. `tcp://` эквивалентно `tcp://localhost`. Адрес не указан — отладка при исполнении кода не производится. Для HTTP порт указывать обязательно, например `debuggerURL="http://pc-name:1561"` |

Если протокол из `protocol` не совпадает со схемой в адресе отладчика, соединение с отладчиком не устанавливается и работа продолжается без отладки. ⚠ в источнике неясно: в этой фразе атрибут назван `url`, хотя описан атрибут `debuggerURL`.

## 3.17. conf.cfg

### 3.17.1. Общая информация

Файл задаёт расположение каталога общих конфигурационных файлов, язык интерфейса системы по умолчанию и множество других параметров поведения платформы. Текстовый документ в кодировке UTF-8.

Расположение:

- **Linux:**
  - каталог `conf` каталога конкретной версии «1С:Предприятия» соответствующей разрядности (в разделе 3.17.10 этот каталог записан как `/opt/1cv8/arch/A.B.C.D/conf`);
  - каталог `~/.1cv8/1C/1cv8/conf`, где `~` — домашний каталог пользователя, от имени которого работает сервер «1С:Предприятия».
- **macOS:**
  - каталог `conf` установленной версии, например `/opt/1cv8/A.B.C.D/conf`;
  - каталог `~/.1cv8/1C/1cv8/conf` (`~` — домашний каталог пользователя, от имени которого работает сервер).
- **Windows** (кратко):
  - `bin\conf` каталога конкретной версии соответствующей разрядности;
  - `%LOCALAPPDATA%\1C\1cv8\conf` — используется платформой любой версии, разрядности и варианта установки;
  - установка «для компьютера»: `%PROGRAMFILES(x86)%\1cv8\conf` (32-разрядная система в 64-разрядной ОС), в остальных случаях `%PROGRAMFILES%\1cv8\conf`;
  - установка «для пользователя»: `%LOCALAPPDATA%\Programs\1cv8\conf` (32 в 32), `%LOCALAPPDATA%\Programs\1cv8_x86\conf` (32 в 64), `%LOCALAPPDATA%\Programs\1cv8_x64\conf` (64 в 64).

Для некоторых параметров `conf.cfg` может лежать ещё и в каталоге информационной базы — в описании таких параметров это оговаривается явно.

Параметры conf.cfg, описанные в этой части (продолжение перечня — в следующих частях):

| Параметр | Кратко | Умолчание |
|---|---|---|
| `ConfLocation` | резервный каталог поиска конфигурационных файлов | Linux: `/opt/1cv8/conf` |
| `CryptoAPILibraryLocation` | пути поиска библиотеки КриптоПро CSP (Linux, macOS) | — |
| `DBFormatVersion` | формат новой файловой базы данных | `8.2.14` |
| `DisableLocalSpeechToText` | запрет локального распознавания речи (файловая ИБ) | `0` |
| `DisableUnsafeActionProtection` | отключение защиты от опасных действий по шаблонам строк соединения | — |
| `EnableAccessRightAuditEventsWrite` | запись событий аудита прав доступа (файловая ИБ, КОРП) | `false` |
| `EnableCheckScriptCircularRefs` | поиск циклических ссылок во встроенном языке | `false` |
| `ExternalResourcesMode` | набор служебных интернет-ресурсов | `D` |
| `ExternalSessionManagementConnectionString` (+ `ExternalSessionManagementRequired`) | внешнее управление сеансами для файловой ИБ | — |

### 3.17.2. ConfLocation

Каталог, в котором платформа ищет конфигурационные файлы (`logcfg.xml`, `nethasp.ini` и т. д.), если они не найдены по стандартным путям поиска. Параметр имеет смысл, когда `conf.cfg` лежит в каталоге `conf` конкретной версии.

Значение по умолчанию:

- Linux: `/opt/1cv8/conf`.
- macOS: `/opt/1cv8/A.B.C.D` (так в источнике, без `/conf`).
- Windows, установка «для компьютера»: `%PROGRAMFILES(x86)%\1cv8\conf` (32-разрядная система в 64-разрядной ОС), в остальных случаях `%PROGRAMFILES%\1cv8\conf`.
- Windows, установка «для пользователя»: `%LOCALAPPDATA%\Programs\1cv8\conf` (32 в 32), `%LOCALAPPDATA%\Programs\1cv8_x86\conf` (32 в 64), `%LOCALAPPDATA%\Programs\1cv8_x64\conf` (64 в 64).

Пример (из источника, Windows-путь):

```ini
ConfLocation=C:\MySettings\v8\conf
```

### 3.17.3. CryptoAPILibraryLocation

Путь (или несколько путей), по которым платформа ищет библиотеку КриптоПро CSP при работе под Linux или macOS. Несколько путей (по аналогии с переменной окружения `PATH`) разделяются символом `;`.

### 3.17.4. DBFormatVersion

Формат, в котором создаётся новая база данных в файловом варианте ИБ.

- Допустимые значения: `8.2.14` и `8.3.8`.
- По умолчанию: `8.2.14`.

### 3.17.5. DisableLocalSpeechToText

Управляет локальным распознаванием речи в клиентском приложении для файлового варианта ИБ:

- `1` — локальное распознавание речи в файловой ИБ запрещено, в том числе при работе через публикацию на веб-сервере;
- `0` — локальное распознавание речи в файловой ИБ поддерживается (в любом варианте использования).

По умолчанию `0`.

Действующее значение читается только из `conf.cfg`, расположенного:

- в каталоге информационной базы;
- в каталоге, заданном параметром `ConfLocation` того `conf.cfg`, что лежит в каталоге информационной базы (если по этому пути есть конфигурационный файл и параметр в нём указан).

В остальных `conf.cfg` параметр не используется.

### 3.17.6. DisableUnsafeActionProtection

Отключает защиту от опасных действий для выбранных информационных баз.

- Значение — набор шаблонов (регулярных выражений), разделённых символом `;`.
- Если строка соединения с ИБ удовлетворяет хотя бы одному из выражений, для этой ИБ защита отключается.
- Синтаксис выражений — POSIX Basic Regular Expressions (https://pubs.opengroup.org/onlinepubs/9699919799/basedefs/V1_chap09.html#tag_09_03).

Параметр читает тот процесс, который фактически выполняет потенциально опасное действие:

| Действие | Процесс, который читает параметр |
|---|---|
| загрузка внешних обработок/отчётов или расширений конфигурации | толстый клиент (обычное приложение) или сервер (процесс `rphost`) |
| загрузка внешних компонент | клиентское приложение или сервер (процесс `rphost`) |
| запуск внешнего приложения | клиентское приложение или сервер (процесс `rphost`) |
| открытие табличного документа | только клиентское приложение |
| открытие URL элементом формы `ПолеHTMLДокумента` | только клиентское приложение |

```ini
DisableUnsafeActionProtection=test_.*;stage_.*;
```

### 3.17.7. EnableAccessRightAuditEventsWrite

Доступно только для лицензии КОРП.

Управляет записью событий аудита прав доступа — только для файлового варианта ИБ:

- `true` — события аудита прав доступа пишутся в журнал регистрации;
- `false` — не пишутся.

По умолчанию `false`.

Действующее значение читается только из `conf.cfg`, расположенного:

- в каталоге информационной базы;
- в каталоге, заданном параметром `ConfLocation` того `conf.cfg`, что лежит в каталоге информационной базы (если по этому пути есть конфигурационный файл и параметр в нём указан).

В остальных `conf.cfg` параметр не используется.

См. также (ссылки документации): события аудита прав доступа; управление регистрацией событий аудита прав доступа в кластере серверов.

### 3.17.8. EnableCheckScriptCircularRefs

Управляет поиском циклических ссылок при выполнении кода на встроенном языке:

- `true` — поиск выполняется;
- `false` — поиск не выполняется.

По умолчанию `false`.

### 3.17.9. ExternalResourcesMode

Определяет набор используемых служебных ресурсов сети Интернет и некоторые особенности поведения платформы.

| Свойство | `D` (по умолчанию) | `A` (альтернативный список ресурсов) |
|---|---|---|
| серверы системы программного лицензирования платформы и конфигураций | расположены в России | расположены в Европе |
| команды меню «Справка — Информация в Интернете» | обращение к российским ресурсам | обращение к европейским ресурсам |
| регистрация в системе взаимодействия | поддерживается | не поддерживается |
| специальный сервис фирмы «1С» для рассылки PUSH-уведомлений | поддерживается | не поддерживается |

### 3.17.10. ExternalSessionManagementConnectionString

Строка параметров вызова сервиса внешнего управления сеансами при работе с **файловым** вариантом ИБ.

Сервис внешнего управления сеансами в файловой ИБ управляется двумя параметрами conf.cfg:

- `ExternalSessionManagementConnectionString` — параметры вызова сервиса;
- `ExternalSessionManagementRequired` — включает (`1`) или выключает (`0`) использование сервиса. Если строка параметров вызова задана, этот параметр должен быть указан в конфигурационном файле явно.

Формат строки параметров Web-сервиса — пары `Параметр=Значение;`:

| Параметр | Обязательность | Назначение | Значения / умолчание |
|---|---|---|---|
| `wsdl` | обязательный | URL для получения описания Web-сервиса в формате WSDL | — |
| `ns` | обязательный | пространство имён Web-сервиса | — |
| `srvc` | обязательный | имя Web-сервиса внешнего управления сеансами | — |
| `port` | обязательный | имя порта, используемого Web-сервисом | — |
| `tout` | необязательный | максимальное время ожидания обращения к Web-сервису, в секундах | по умолчанию 5 секунд |
| `wsver` | необязательный | номер версии используемого Web-сервиса внешнего управления сеансами | допустимо `1`, `2`, `3`, `4`; по умолчанию `4` |

Пример строки:

```text
wsdl=http://server/sm/ws/manager?wsdl;ns=http://www.sessioncontrol.org;srvc=ExternalSessionControl;port=ExternalSessionControlSoap;tout=10;wsver=4;
```

Поиск значений. Если в `conf.cfg` из каталога информационной базы не указан один или оба параметра (`ExternalSessionManagementRequired`, `ExternalSessionManagementConnectionString`), платформа пытается взять их из других конфигурационных файлов. Для каждого параметра действует первое найденное значение; порядок просмотра, как он перечислен в источнике:

1. Каталог конфигурационных файлов конкретной версии:
   - Linux: `/opt/1cv8/arch/A.B.C.D/conf`;
   - macOS: `/opt/1cv8/A.B.C.D/conf`;
   - Windows: `%PROGRAMFILES%\1cv8\A.B.C.D\bin\conf`.
2. Каталог конфигурационных файлов корневого каталога установки:
   - Linux: `/opt/1cv8/conf`;
   - macOS: `/opt/1cv8/conf`;
   - Windows: `%LOCALAPPDATA%\1C\1cv8\conf`.
3. Каталог, заданный параметром `ConfLocation` конфигурационного файла конкретной версии (сам этот файл лежит в каталоге из п. 1: Linux `/opt/1cv8/arch/A.B.C.D/conf`, macOS `/opt/1cv8/A.B.C.D/conf`, Windows `%PROGRAMFILES%\1cv8\A.B.C.D\bin\conf`). Применимо, если по указанному пути есть конфигурационный файл и параметр в нём указан.
4. Каталог информационной базы.
5. Каталог, заданный параметром `ConfLocation` файла `conf.cfg` из каталога информационной базы. Применимо, если по указанному пути есть конфигурационный файл и параметр в нём указан.

⚠ в источнике неясно: перечень вводится как порядок поиска на случай, когда параметров нет в `conf.cfg` каталога ИБ, но сам каталог ИБ в этом перечне стоит четвёртым, а не первым; порядок перенесён в конспект так, как он дан в документации.

(Источник части 1 обрывается на разделе 3.17.10; остальные параметры `conf.cfg` — в следующих частях.)

## Что важно администратору Linux

1. **Где лежит conf.cfg.** В Linux файл ищется в каталоге `conf` конкретной версии платформы (в документации путь записан как `/opt/1cv8/arch/A.B.C.D/conf`) и в `~/.1cv8/1C/1cv8/conf` пользователя, от имени которого работает сервер «1С:Предприятия». Кодировка — UTF-8.
2. **ConfLocation — резервный каталог.** Если `logcfg.xml`, `nethasp.ini` и подобные файлы не найдены по стандартным путям, платформа смотрит в каталог из `ConfLocation`; для Linux умолчание — `/opt/1cv8/conf`. Параметр имеет смысл только в `conf.cfg` из каталога `conf` конкретной версии.
3. **Файлы клиента.** Список баз (`ibases.v8i`, UTF-8) и `1cestart.cfg` в Linux лежат в `~/.1C/1cestart`. Кодировка `1cestart.cfg` по документации — UTF-16LE (не UTF-8).
4. **1cv8conn.pfl** лежит в `~/.1cv8/1C/1cv8`; пользователю, под которым запускаются приложения 1С, нужны права на создание, чтение и изменение данных в этом каталоге — это условие надёжной работы.
5. **Реестр кластера** — файл `1CV8Clst.lst` в каталоге данных центрального сервера (в примере — подкаталог `reg_1541`); список кластеров компьютера — `1cv8wsrv.lst` в каталоге служебных файлов кластера. В реестре хранятся списки ИБ, рабочих серверов, рабочих процессов, менеджеров, сервисов и администраторов кластера. Linux-пути для этих двух файлов в данном разделе документации не приведены — только Windows-примеры.
6. **Регистр имени ClientUpdate.cfg** в Linux значим. Для раздачи клиентских дистрибутивов под Linux служат ключи `PublishDistributiveLocationLinux32` и `PublishDistributiveLocationLinux64`; ключ `Version` обязателен, `UpdateDate` задаётся как `YYYYMMDDHHMMSS`.
7. **Сертификаты УЦ.** Начиная с 8.3.20 в режиме совместимости «Версия 8.3.8» и новее платформа сначала использует `cacertnx.pem`, затем хранилище ОС; в режиме совместимости 8.3.7 и старее — только `cacert.pem`. С версии 8.3.8 (режим совместимости «Версия 8.3.8») и до 8.3.19 использовался только механизм ОС.
8. **HTTPS в v8i.** У параметров `HttpsCA` / `HttpsCert` есть значение `Linux` (каталог сертификатов ОС Linux) и `File` (с путём в `HttpsCAFile` / `HttpsCertFile`; при пустом пути считается `None`). `HttpsCA=None` означает, что серверный сертификат не проверяется.
9. **КриптоПро CSP.** Пути поиска библиотеки на Linux задаются в `conf.cfg` параметром `CryptoAPILibraryLocation`, несколько путей — через `;`.
10. **Защита от опасных действий.** `DisableUnsafeActionProtection` — список регулярных выражений POSIX BRE через `;`, сопоставляемых со строкой соединения ИБ. Параметр читает тот процесс, который выполняет действие: для действий, выполняемых на сервере, — процесс `rphost`; для открытия табличного документа и URL в `ПолеHTMLДокумента` — только клиентское приложение.
11. **Ключи защиты.** `UseHwLicenses=0` в `1cestart.cfg` отключает поиск аппаратного ключа, когда лицензии выдаёт сервер 1С или расширение веб-сервера. Внешнее соединение берёт параметр из профиля пользователя, под которым оно запущено; если профиля нет — ключ ищется всегда.
12. **Параметры только для файловых ИБ.** `DisableLocalSpeechToText` и `EnableAccessRightAuditEventsWrite` (последний — только КОРП) читаются исключительно из `conf.cfg` в каталоге ИБ (или в каталоге его `ConfLocation`); в остальных `conf.cfg` они не используются. Внешнее управление сеансами файловой ИБ требует пары `ExternalSessionManagementRequired` + `ExternalSessionManagementConnectionString`.
13. **Формат новых файловых баз** по умолчанию — `8.2.14`; для формата `8.3.8` нужно задать `DBFormatVersion=8.3.8` в `conf.cfg`.
14. **Хранилище конфигураций.** Файл `*.1ccr` для веб-сервиса хранилища — XML с одним узлом и атрибутом `connectString="tcp://<сервер хранилища>"`. Кеш версий настраивается в `cfgrepo.conf`: глобальный — в каталоге хранилища, локальный — в `~/.1cv8/1C/1cv8/<UUID ИБ>/cfgrepo`; там же задаются `cfgrepo.users.minPasswordLength` и `cfgrepo.users.checkPasswordComplexity` (глобальный файл).
15. **К Linux не относятся:** файлы `1cescmn.cfg`, `adminstall.cfg`, `appsrvrs.lst`, `comcntrcfg.xml` и параметры `DisableInstallerVerification`, `InstallForUsers` файла `1cestart.cfg` — документация помечает их как применимые только в Windows.
