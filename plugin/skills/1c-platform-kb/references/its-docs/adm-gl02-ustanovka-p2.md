## 2.7. Рекомендации по развертыванию системы

Раздел описывает схему сетевого каталога, при которой программа запуска (`1cestart`) сама ставит новые версии платформы на компьютеры пользователей, включая первую установку. Пример в документации построен для каталога на Windows-сервере.

### Рекомендуемая структура каталога

Сам рисунок (рис. 17) в текстовую копию не попал; дерево ниже восстановлено по текстовому описанию элементов.

```text
\\Server\1CDistr\
    1cestart            программа запуска
    ibcommon.v8i        список общих информационных баз (если есть)
    1cescmn.cfg         общий конфигурационный файл
    8.3.18.100\
        Win32\          дистрибутив Windows, 32 разряда
        Win64\          дистрибутив Windows, 64 разряда
        macOS\          дистрибутив macOS (файлы *.dmg)
        Lin32\          дистрибутив Linux, 32 разряда (файлы *.run)
        Lin64\          дистрибутив Linux, 64 разряда (файлы *.run)
    8.3.18.150\         та же структура, что у 8.3.18.100
```

| Элемент | Назначение | Примечания |
|---|---|---|
| `\\Server\1CDistr` | Каталог на сервере `Server` со всем, что нужно для развертывания | На Linux и macOS каталог должен быть **смонтирован**; UNC-пути в Linux и macOS не поддерживаются |
| `1cestart` | Программа запуска | Для первоначальной установки достаточно запустить её из сетевого каталога. Можно запускать и с локального диска, если в конфигурационных файлах верно заданы пути к дистрибутивам и в настройках программы запуска не запрещена автоматическая установка новой версии. Брать рекомендуется из самой свежей версии платформы, установленной в локальной сети |
| `ibcommon.v8i` | Список общих информационных баз | Файл необязателен, имя условное (в документации есть отдельное описание формата `*.v8i`) |
| `1cescmn.cfg` | Общий конфигурационный файл | См. рекомендуемые параметры ниже. **Не должен лежать на компьютере пользователя** |
| `8.3.18.100`, `8.3.18.150` | Каталог с дистрибутивами конкретной версии | Имя каталога — номер версии |
| `Win32` / `Win64` | Дистрибутивы для Windows по разрядности | Разрядность нужно соблюдать |
| `macOS` | Дистрибутив для macOS | Дистрибутивы — файлы `*.dmg` |
| `Lin32` / `Lin64` | Дистрибутивы для Linux, 32 и 64 разряда | Дистрибутивы — файлы `*.run` |

### Рекомендуемые параметры общего конфигурационного файла `1cescmn.cfg`

| Параметр | Что указать | Зачем |
|---|---|---|
| `CommonInfoBases=ИмяФайлаСоСпискомОбщихИнформационныхБаз.v8i` | Файл со списком общих баз | Нужен, если пользователь при запуске должен сразу видеть нужный список информационных баз |
| `InstallComponents` | Набор компонентов для установки на компьютеры пользователей | Используется только при установке на Windows; на Linux и macOS игнорируется |
| `DistributiveLocation` | Каталог, где лежат дистрибутивы «1С:Предприятия» | В примере задан тремя строками — UNC-путь для Windows и точки монтирования для macOS и Linux |

Пример из документации. ⚠ в источнике неясно: по тексту этот файл задаёт установку всех компонентов и языков «русский и английский», но в самой строке указано только `LANGUAGES=ru`.

```ini
CommonInfoBases=ibcommon.v8i
DistributiveLocation=\\Server\1CDistr
DistributiveLocation=/Volumes/Server/1CDistr
DistributiveLocation=/mnt/server/1CDistr
InstallComponents=DESIGNERALLCLIENTS=1 SERVER=1 WEBSERVEREXT=1 CONFREPOSSERVER=1 SERVERCLIENT=1 CONVERTER77=1 LANGUAGES=ru
```

Ключи компонентов, встречающиеся в примере: `DESIGNERALLCLIENTS`, `SERVER`, `WEBSERVEREXT`, `CONFREPOSSERVER`, `SERVERCLIENT`, `CONVERTER77`, `LANGUAGES`. Расшифровка ключей в этой части источника не приводится (она в описании параметра `InstallComponents`, на которое источник ссылается).

### Действия при выходе новой версии (пример — 8.3.18.200)

1. В `\\Server\1CDistr` создать для версии `8.3.18.200` такую же структуру подкаталогов, как у предыдущих версий.
2. Разложить файлы дистрибутивов по «своим» подкаталогам: по операционной системе, а для Windows — ещё и по разрядности.

Дальше установка произойдёт автоматически, когда пользователь запустит «1С:Предприятие».

### Особенности схемы по операционным системам

**Windows (только Windows, кратко):**
- Установка через программу запуска всегда идёт в каталог по умолчанию; чтобы поставить в другой каталог, программу установки (`setup.exe`) нужной версии запускают вручную.
- Из общего конфигурационного файла при установке берётся только `InstallComponents`; остальные параметры на установку не влияют и в локальный конфигурационный файл не переносятся.
- При установке в локальный конфигурационный файл записывается параметр `CommonCfgLocation` — путь к общему конфигурационному файлу в каталоге развертывания (в примере `\\server\1cdistr\1cescmn.cfg`). В дальнейшем параметры этого файла используются программами запуска и диалогом запуска клиентского приложения.

**Linux:**
- Серверный каталог с установочными файлами должен быть смонтирован на клиентском компьютере — любым доступным способом.
- На **всех** клиентских Linux-компьютерах точка монтирования должна называться одинаково. В примере `\\Server\1CDistr` смонтирован в `/mnt/server/1CDistr`.
- Пути записываются с прямыми слешами (`/`).
- Параметр `InstallComponents` общего конфигурационного файла **игнорируется**.

**macOS:**
- Требования те же, что для Linux: каталог смонтирован, точка монтирования одинакова на всех компьютерах Apple (в примере `/Volumes/Server/1CDistr`), прямые слеши.
- `InstallComponents` игнорируется.

**Доступ через веб-сервер:** если к информационной базе обращаются через веб-сервер, дистрибутив клиентского приложения можно доставлять и другими способами (источник ссылается на отдельный раздел без номера; в этой же части с темой связаны 2.8.1.3 и 2.8.2.2).

## 2.8. Установка и настройка дополнительного программного обеспечения

### 2.8.1. Для ОС Linux

#### (без номера) Особенности настройки для работы с файловым вариантом информационной базы

Подраздел идёт в документации сразу под заголовком 2.8.1, собственного номера у него нет.

**Сетевой доступ к каталогу файловой базы**

| Где | Чего нельзя делать | Комментарий |
|---|---|---|
| Клиент Linux, подключение сетевого ресурса командой `mount.cifs` | Использовать ключ `nobrl` | Справка (англ.): `https://www.samba.org/~ab/output/htmldocs/manpages-3/mount.cifs.8.html` |
| Сервер Samba, раздающий каталог с информационной базой (`smb.conf`) | Задавать `locking=no` для публикуемого ресурса | Справка (англ.): `https://www.samba.org/~ab/output/htmldocs/manpages-3/smb.conf.5.html` |

**Несколько пользователей одного компьютера работают с одной файловой базой**

Суть проблемы:
- В Linux владельцем нового файла становится пользователь, от имени которого работает создающий процесс, а группой-владельцем — основная группа этого пользователя.
- «1С:Предприятие» создаёт файлы с правом чтения и записи для владельца и для группы-владельца — явно выставляет режим **`0660`**.
- Поэтому при совместной работе с одной файловой базой второй и следующие пользователи того же компьютера не получают доступа к уже созданным файлам.

Решение:
1. Включить всех этих пользователей в одну группу.
2. Назначить эту группу группой-владельцем каталога информационной базы.
3. Поставить на каталог флаг set-group-ID:

```bash
chmod g+s ib_dir
```

где `ib_dir` — каталог, в котором расположена информационная база.

Результат: у новых файлов в каталоге группой-владельцем будет не основная группа создавшего пользователя, а группа-владелец каталога базы.

**Про `umask`:**
- Маска создания файлов из окружения может только ужесточить права, то есть сбросить уже выставленные флаги.
- Флаги доступа для «прочих» платформа при создании файла не выставляет вовсе, поэтому добавить их через `umask` невозможно.

**Доступ к файловой базе через веб-сервер на Linux**

1. Пользователя, от имени которого запускается **конфигуратор**, добавить в группу `www-data` или `apache`.
2. Сделать эту группу группой-владельцем каталога информационной базы.
3. Установить на каталог флаг set-group-ID.
4. Задать для Apache маску `0002` — иначе у файлов, которые веб-сервер создаёт в процессе работы, будет сброшено право записи для группы-владельца (`g-w`).

Способы задать маску:

| Способ | Куда вносить | Что вносить |
|---|---|---|
| Файл окружения Apache (один из трёх, зависит от дистрибутива; какой файл какому дистрибутиву соответствует, источник не уточняет) | `/etc/apache2/envvars`, `/etc/default/apache2` или `/etc/sysconfig/httpd` | строка `umask 0002` |
| systemd (если службами управляет systemd) | `/etc/systemd/system/apache2.service.d/override.conf` или `/etc/systemd/system/httpd.service.d/override.conf` | секция `[Service]` с `UMask=0002` |

Для systemd файл переопределения создаётся от имени суперпользователя (root) командой:

```bash
systemctl edit apache2
# или
systemctl edit httpd
```

Содержимое переопределения:

```ini
[Service]
UMask=0002
```

**Хранилище конфигурации:** совместная работа с хранилищем конфигурации настраивается точно так же, только вместо каталога информационной базы берётся каталог хранилища.

#### 2.8.1.1. Установка шрифтов

Для корректной работы «1С:Предприятия» в Linux должны быть установлены шрифты из набора **Microsoft Core Fonts**. Варианты установки:

| Вариант | Как |
|---|---|
| Пакет из состава дистрибутива ОС | Наличие пакета проверяется для каждого дистрибутива отдельно (имя пакета источник не называет) |
| RPM-системы | Инструкция: `https://corefonts.sourceforge.net/` (на английском) |
| Вручную | 1) скачать все файлы шрифтов с `https://sourceforge.net/projects/corefonts/files/the%20fonts/final/`; 2) распаковать; 3) положить файлы шрифтов в каталог `~/.fonts` того пользователя (или тех пользователей), от имени которого запускается «1С:Предприятие» (`~` — домашний каталог) |

#### 2.8.1.2. Аутентификация операционной системы при использовании веб-сервера Apache

Аутентификацию ОС можно настроить для **тонкого клиента** и **веб-клиента**, работающих через Apache. Исходное условие: Apache уже установлен и настроен для доступа веб-клиентом.

**Требование:** в сети должен быть развернут PDC под управлением Windows 2000 или новее.

Порядок настройки:

1. Установить модуль аутентификации `mod_auth_kerb`. Он есть в большинстве дистрибутивов:

   | ОС | Имя пакета |
   |---|---|
   | Fedora | `mod_auth_kerb` |
   | Debian | `libapache2-mod-auth-kerb` |
   | Модуля нет в поставке ОС | исходный код — на странице проекта `https://modauthkerb.sourceforge.net/` |

2. Подключить модуль:
   - установлен из дистрибутива ОС — достаточно перезапустить веб-сервер, модуль подключится сам;
   - собран и установлен самостоятельно (инструкция: `https://modauthkerb.sourceforge.net/install.html`, на английском) — добавить в `httpd.conf` строку ниже и перезапустить Apache:

   ```apache
   LoadModule auth_kerb_module /путь/к/файлу/mod_auth_kerb.so
   ```

3. Подготовить закрытый ключ Kerberos на имя `HTTP/Server.domain@DOMAIN`. Ключ генерируется по правилам из руководства по настройке аутентификации Kerberos (отдельный раздел документации). У учётной записи, с которой связано это имя, должен быть установлен флажок **«Учетная запись доверена для делегирования»** (Account is trusted for delegation).

4. Добавить директивы Kerberos в секцию, описывающую виртуальный каталог веб-сервера. В примере документации файл ключа называется `HTTP.keytab` и лежит в домашнем каталоге пользователя `usr1cv8`:

```apache
<Directory "/home/usr1cv8/www/MyApp">
AllowOverride None
Options None
Order allow,deny
Allow from all
SetHandler 1c-application
ManagedApplicationDescriptor /home/usr1cv8/www/MyApp/default.vrd
AuthName "1C:Enterprise web client"
AuthType Kerberos
Krb5Keytab /home/usr1cv8/HTTP.keytab
KrbVerifyKDC off
KrbDelegateBasic off
KrbServiceName HTTP/Server.domain@DOMAIN
KrbSaveCredentials on
KrbMethodK5Passwd off
KrbMethodNegotiate on
Require valid-user
</Directory>
```

Значения директив аутентификации в примере (пояснений к отдельным директивам источник не даёт):

| Директива | Значение в примере |
|---|---|
| `AuthName` | `"1C:Enterprise web client"` |
| `AuthType` | `Kerberos` |
| `Krb5Keytab` | `/home/usr1cv8/HTTP.keytab` |
| `KrbVerifyKDC` | `off` |
| `KrbDelegateBasic` | `off` |
| `KrbServiceName` | `HTTP/Server.domain@DOMAIN` |
| `KrbSaveCredentials` | `on` |
| `KrbMethodK5Passwd` | `off` |
| `KrbMethodNegotiate` | `on` |
| `Require` | `valid-user` |

Условия и ограничения:
- Путь к файлу ключа должен быть указан верно, а сам файл должен быть доступен на чтение пользователю, от имени которого работает Apache.
- Kerberos-аутентификация может не работать в домене, где одновременно есть контроллеры Windows 2000 и Windows 2003, веб-серверы на Linux и серверы «1С:Предприятия» на Windows, — из-за особенностей реализации Kerberos в Windows 2000.

#### 2.8.1.3. Установка дистрибутивов клиентских приложений

Назначение: чтобы клиентские приложения удалённых компьютеров обновлялись через расширение веб-сервера, дистрибутивы клиентских приложений нужно установить на тот компьютер, где работает расширение веб-сервера.

Шаги:

1. Скачать с `https://releases.1c.ru/` один из файлов (`A.B.C.D` в имени — место номера версии):

   | Файл | Суффикс архитектуры | Что содержит |
   |---|---|---|
   | `all-clients-distr-A.B.C.D-i386.run` | `i386` | клиентские дистрибутивы для всех ОС, поддерживающих обновление клиентских приложений по HTTP(S) |
   | `all-clients-distr-A.B.C.D-x86_64.run` | `x86_64` | то же |
   | `win-mac-clients-distr-A.B.C.D-i386.run` | `i386` | клиентские дистрибутивы для macOS и Windows |
   | `win-mac-clients-distr-A.B.C.D-x86_64.run` | `x86_64` | то же |

   Файл выбирают по версии, разрядности и пакетному менеджеру целевой системы.

2. Установить выбранный пакет. Нужны права суперпользователя (root). Возможен пакетный режим — в командной строке запуска run-файла указываются параметры:

   ```text
   --mode unattended
   ```

3. Результат: в каталоге «1С:Предприятия» появляется каталог **`distr`** с дистрибутивами клиентского приложения:
   - после `win-mac-clients*` — для macOS и Windows;
   - после `all-clients*` — для всех ОС, поддерживающих обновление клиентских приложений по HTTP(S).

Примечание: дистрибутивы клиентских приложений удаляются автоматически при удалении соответствующей версии «1С:Предприятия».

См. также (в документации, без номера раздела в источнике): автоматизированное обновление клиентского приложения с помощью каталога `distr`.

### 2.8.2. Для ОС Windows

Раздел целиком **только Windows** — конспект краткий.

#### 2.8.2.1. Невизуальная доступность для пользователей с ограничениями по зрению

- Только Windows. Для невизуального доступа к интерфейсу «1С:Предприятия» на клиентский компьютер ставится программа экранного доступа **NVDA**: `https://nvda.ru/` (на русском) или `https://www.nvaccess.org/` (на английском).
- Синтезаторы речи для озвучивания: `https://github.com/nvaccess/nvda/wiki/ExtraVoices`. Для русского языка рекомендован **RHVoice**: `https://github.com/Olga-Yakovleva/RHVoice/wiki`.

#### 2.8.2.2. Установка дистрибутивов клиентских приложений

Только Windows. Назначение то же, что в 2.8.1.3: дистрибутивы ставятся на компьютер с расширением веб-сервера, чтобы через него обновлять клиентские приложения удалённых компьютеров.

- Файлы с `https://releases.1c.ru/`: `all-clients-distr-A.B.C.D.exe` или `win-mac-clients-distr-A.B.C.D.exe`. Если файл положить в каталог с установочными файлами той же версии платформы, он установится одновременно с платформой.
- Нужны права администратора. Результат — каталог `distr` в каталоге «1С:Предприятия»: после `win-mac-clients*.exe` — дистрибутивы для macOS и Windows, после `all-clients*.exe` — для всех ОС, поддерживающих обновление клиентов по HTTP(S). При удалении соответствующей версии платформы дистрибутивы удаляются автоматически.
- Куда ставится: программа ищет каталог установки версии с тем же номером. Если вариантов этой версии несколько, берётся первый найденный в порядке: 1) каталог 64-разрядного сервера «1С:Предприятия»; 2) полный дистрибутив, 64-разрядный вариант; 3) полный дистрибутив, 32-разрядный вариант.
- Ключ запуска `/D=<ПутьККаталогу>` — установка в указанный каталог без поиска установленных версий.
- Есть и более простой способ — он описан в разделе про установку платформы на Windows (в источнике ссылка без номера раздела).

### 2.8.3. Настройка Java

Часть компонентов «1С:Предприятия» требует установленной Java, причём с разными настройками виртуальной машины.

#### Полнотекстовый поиск в данных, версия 2

| Версия Java | Что нужно сделать |
|---|---|
| Строго меньше 17 | Ничего |
| 17 и выше | В конфигурационный файл `conf.cfg` добавить параметр `FtsJavaOpts` со значением `--add-opens java.base/java.lang=ALL-UNNAMED` |

Значение параметра:

```text
--add-opens java.base/java.lang=ALL-UNNAMED
```

Точный синтаксис строки параметра в этой части источника не показан — он в описании параметра `FtsJavaOpts` файла `conf.cfg` (источник на него ссылается).

#### Утилита лицензирования (`ring license`)

| Версия Java | Что нужно сделать |
|---|---|
| Младше 1.8 update 151 | Установить JCE |
| 1.8 update 151 или старше | Один из двух вариантов: а) в файле `java.security` выставить `crypto.policy` в `unlimited`; б) установить JCE |
| 9 и выше | В файле `java.security` выставить `crypto.policy` в `unlimited` |

Настройка в `java.security` — добавить строку или снять комментарий с уже имеющейся:

```properties
crypto.policy=unlimited
```

Расположение файла `java.security` (источник приводит пути только в Windows-записи, через `%JAVA_HOME%`):

| Версия и вариант Java | Каталог с `java.security` |
|---|---|
| Java 1.8, JDK | `%JAVA_HOME%\jre\lib\security` |
| Java 1.8, JRE | `%JAVA_HOME%\lib\security` |
| Java 9 и выше | `%JAVA_HOME%\conf\security` |

## Что важно администратору Linux

1. **UNC-пути в Linux не работают.** Сетевой каталог с дистрибутивами монтируется, причём на всех Linux-клиентах — в точку с одним и тем же именем (в примере `/mnt/server/1CDistr`); в `DistributiveLocation` путь пишется с прямыми слешами.
2. **`InstallComponents` на Linux игнорируется** — набор компонентов через общий конфигурационный файл для Linux-клиентов не задаётся.
3. **`1cescmn.cfg` не кладут на компьютер пользователя** — общий конфигурационный файл живёт только в сетевом каталоге развертывания. Linux-дистрибутивы в этой схеме лежат в подкаталогах `Lin32` / `Lin64` каталога версии в виде файлов `*.run`.
4. **Новая версия платформы** раздаётся добавлением каталога с номером версии и той же структурой подкаталогов; дальше установка идёт автоматически при запуске пользователем.
5. **Файловая база по сети:** при `mount.cifs` не использовать `nobrl`, в `smb.conf` не ставить `locking=no` на ресурс с базой.
6. **Платформа создаёт файлы с режимом `0660`**; `umask` может только отнять права, добавить доступ «прочим» ею нельзя.
7. **Несколько пользователей одной файловой базы:** общая группа, она же группа-владелец каталога базы, плюс `chmod g+s ib_dir` — иначе второй пользователь не откроет файлы первого.
8. **Файловая база + Apache:** пользователь конфигуратора — в группу `www-data` или `apache`, эта группа владеет каталогом базы, на каталоге set-group-ID, у Apache маска `0002` (строка `umask 0002` в `/etc/apache2/envvars`, `/etc/default/apache2` или `/etc/sysconfig/httpd`, либо `UMask=0002` в секции `[Service]` через `systemctl edit apache2` / `systemctl edit httpd`).
9. **Хранилище конфигурации** на Linux настраивается по тем же правилам прав и групп, что и каталог файловой базы.
10. **Шрифты Microsoft Core Fonts обязательны** для корректной работы; при ручной установке файлы кладутся в `~/.fonts` пользователя, запускающего «1С:Предприятие».
11. **Аутентификация ОС через Apache** делается модулем `mod_auth_kerb` (пакет `libapache2-mod-auth-kerb` в Debian, `mod_auth_kerb` в Fedora); нужен keytab на имя `HTTP/Server.domain@DOMAIN`, читаемый пользователем Apache, флажок доверия для делегирования у учётной записи и PDC на Windows 2000 или новее в сети.
12. **Обновление клиентов через веб-сервер:** на машину с расширением веб-сервера ставится `all-clients-distr-…run` или `win-mac-clients-distr-…run` (от root, пакетный режим — `--mode unattended`); появляется каталог `distr`, который удаляется вместе с версией платформы.
13. **Java 17 и выше + полнотекстовый поиск версии 2:** в `conf.cfg` обязателен параметр `FtsJavaOpts` со значением `--add-opens java.base/java.lang=ALL-UNNAMED`; для Java младше 17 настройка не нужна.
14. **`ring license`:** для Java 9+ в `java.security` нужно `crypto.policy=unlimited`; для Java 1.8 от update 151 — это же либо установка JCE; для более ранних — только JCE.
