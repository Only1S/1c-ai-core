### 4.8. Особенности различных вариантов запуска (прочитано полностью)

**Инструкции препроцессора** (`#Если … Тогда … #КонецЕсли`) вырезают текст модуля до компиляции; **директивы компиляции** (`&НаКлиенте`, `&НаСервере`, `&НаСервереБезКонтекста`, `&НаКлиентеНаСервереБезКонтекста`, `&НаКлиентеНаСервере`) определяют, где компилируется метод или переменная.

Символы препроцессора: `Сервер` / `НаСервере`, `Клиент` / `НаКлиенте`, `ТонкийКлиент`, `ВебКлиент`, `МобильныйКлиент`, `ТолстыйКлиентУправляемоеПриложение`, `ТолстыйКлиентОбычноеПриложение`, `ВнешнееСоединение`, `МобильноеПриложениеКлиент`, `МобильноеПриложениеСервер`, `МобильныйАвтономныйСервер` (английские имена: `Server`, `AtServer`, `Client`, `AtClient`, `ThinClient`, `WebClient`, `MobileClient`, `ThickClientManagedApplication`, `ThickClientOrdinaryApplication`, `ExternalConnection`, …).

Какие символы определены в серверной части:

| Способ работы | Файловый вариант | Клиент-серверный вариант |
|---|---|---|
| Тонкий, веб-, мобильный клиент — серверная часть | `Сервер`, `НаСервере` | `Сервер`, `НаСервере` |
| **Интернет-сервисы, фоновые и регламентные задания** | `Сервер`, `НаСервере` | `Сервер`, `НаСервере` |
| Внешнее соединение | `Сервер`, `НаСервере`, `ВнешнееСоединение` | **только `ВнешнееСоединение`** |
| Толстый клиент | и клиентские, и серверные символы одновременно (в обеих частях) | клиентская часть — клиентские, серверная — `Сервер`, `НаСервере` |

Следствия:

- код под `#Если Сервер Тогда` во внешнем соединении к **клиент-серверной** базе не выполняется (там определён только символ `ВнешнееСоединение`) — частая причина различий в поведении обмена и интеграций между файловой и серверной базой;
- перед передачей модуля на тонкий или веб-клиент сервер заменяет пробелами текст, который на клиенте не исполняется (серверный код на клиент не попадает).

**Аннотации** `&Перед` (`Before`), `&После` (`After`), `&Вместо` (`Around`), `&ИзменениеИКонтроль` (`ChangeAndValidate`) используются только механизмом расширений (`dev-gl30-rasshireniya.md`); пользовательские аннотации не поддерживаются. Инструкции `#Вставка` / `#КонецВставки`, `#Удаление` / `#КонецУдаления` — только в расширениях вместе с `&ИзменениеИКонтроль`.

**Доступность объектов** (4.8.3): для каждого объекта синтакс-помощник указывает, где он доступен (тонкий клиент, веб-клиент, сервер, толстый клиент, внешнее соединение, мобильные варианты), сериализуется ли и передаётся ли между клиентом и сервером. Пометка «Безопасный режим на время исполнения данного обработчика будет отключен» означает принудительное отключение безопасного режима платформой. Ключ запуска клиента **`/EnableCheckServerCalls`** включает диагностику запрещённых серверных вызовов в обработчиках событий (то же — флажок конфигуратора «Проверять серверные вызовы в обработчиках событий»).

## Глава 7. Формы (`/content/52/hdoc`)

Самая большая глава (около 460 тыс. знаков): реквизиты и параметры формы, специальные типы реквизитов (динамический список, табличный документ, диаграммы и др.), команды, модуль формы, элементы формы, командный интерфейс формы, программная работа с формой.

Что из неё связано с производительностью и жалобами пользователей:

- **Динамический список:**
  - соединения, нужные только для дополнительных данных, рекомендуется делать необязательными (расширение языка запросов компоновки данных);
  - в запросе списка не поддерживаются `ПЕРВЫЕ` и `УПОРЯДОЧИТЬ ПО`; не поддерживается сортировка по полям составного типа более чем из 100 типов (в режиме без совместимости 8.3.23 — более 10, см. `dev-pr07-osobennosti-rezhimov.md`);
  - **поиск по объектам, не индексируемым полнотекстовым поиском, работает, но крайне медленно** — такой поиск использовать не рекомендуется;
  - строка поиска может быть очень медленной при сложном запросе списка.
- Условное оформление не рекомендуется использовать для скрытия строк таблицы целиком — страдает производительность.
- Перетаскивание файлов «как файл» в веб-клиенте не поддерживается.

## Глава 8. Работа с запросами (`/content/53/hdoc`)

Структура: объект `Запрос`; источники данных — реальные и виртуальные таблицы; виртуальные и обычные поля; язык запросов (секции, соединения, временные таблицы, группировки, итоги, выражения, функции, условия); выполнение запросов, менеджер временных таблиц, пакетные запросы, `СхемаЗапроса`.

Факты для сопровождения и разбора медленных запросов:

- `РАЗРЕШЕННЫЕ` — выбрать только записи, на которые у пользователя есть права; без него запрос завершается ошибкой при встрече недоступной записи.
- **`ДЛЯ ИЗМЕНЕНИЯ`**: в файловом варианте блокируются указанные таблицы, в клиент-серверном — только выбранные записи; блокировка держится до конца транзакции (см. `dev-gl09-rabota-s-dannymi.md`).
- **Подзапросы в условиях соединения использовать не следует**: это может сильно замедлить запрос, а на некоторых СУБД сделать его неработоспособным.
- Получение выборок очень большого размера (**более 64 Мб**) требует свободного места на диске для **временных файлов сервера и клиента**.
- **Индексы временных таблиц** — только для производительности, не для контроля уникальности; при нескольких индексах первый будет кластерным на Microsoft SQL Server и обычным на остальных СУБД.
- Строка длиннее 1024 символов считается строкой неограниченной длины; для неё не поддерживается операция «+».
- Арифметика: платформа обеспечивает точность не ниже 8 знаков после запятой, но не округляет принудительно — результат на разных СУБД может различаться.
- Сравнение строк — без учёта регистра и концевых пробелов; `ПОДОБНО` — без учёта регистра на любой СУБД; при слишком длинном шаблоне запрос может не выполниться (предел зависит от СУБД).
- Функции дат могут давать разный результат на разных СУБД (переход на летнее/зимнее время, границы диапазона дат). Максимальная дата литерала `ДАТАВРЕМЯ` — 31.12.3999 23:59:59.
- Особенности конкретных СУБД, включая PostgreSQL, собраны в приложении 8 (`dev-prilozheniya.md`).

## Глава 36. Механизм сравнения и объединения конфигураций (`/content/81/hdoc`)

- Сравнение и выборочное объединение двух конфигураций или расширений; **сравнение и объединение основной конфигурации с расширением не поддерживается**.
- Соответствие объектов устанавливается по именам (можно задать вручную); предопределённые данные сопоставляются только по внутреннему идентификатору.
- Режимы объединения объекта: взять из файла или объединить с приоритетом; для модулей — попроцедурная настройка.
- При открытом окне сравнения и объединения не рекомендуется выполнять длительные операции с конфигурацией (операции с хранилищем, снятие с поддержки).
- **Загрузка конфигурации из файла** (36.15, «Конфигурация — Загрузить конфигурацию из файла», по умолчанию файл `1Cv8.cf`) — **полная замена конфигурации**: при непустой конфигурации конфигуратор предупреждает «Конфигурация не пустая. При загрузке измененной конфигурации она будет потеряна. Продолжить?», затем анализирует различия структур и предлагает обновить конфигурацию базы данных. Практическое замечание конспекта: перед загрузкой сохранить текущую конфигурацию в файл и сделать резервную копию базы. О связи с режимом поддержки — `dev-gl37-gl38-hranilishche-postavka-podderzhka.md`.

## Глава 39. Сервисные возможности (`/content/84/hdoc`)

Управление окнами конфигуратора, **параметры конфигуратора** («Сервис — Параметры»), шаблоны текста, синтакс-помощник, сравнение файлов, справка.

- **Параметры отладки (39.2.4):** «Использовать локальный сервер отладки» (ставится автоматически для файловой базы; при нескольких сетевых картах указывают IP-адрес нужной) либо «Использовать сервер отладки кластера» (автоматически для клиент-серверной базы; кластер должен быть запущен с ключом `/debug`). Имя базы для сервера отладки: `DefAlias` для файловой базы, имя базы в кластере — для серверной. Подробно — `dev-gl31-otladka-oshibki-testirovanie.md`.
- **Внешние программы сравнения и объединения (39.2.6):** в списке поддерживаемых есть работающие и под Linux — KDiff3 (`kdiff3`) и P4Merge (`p4merge`).
- **Синтакс-помощник** показывает, с какой версии доступен объект и доступен ли он в текущем режиме совместимости конфигурации; устаревшие объекты скрываются (флажок «Отображать нерекомендуемые объекты»). Пример из документации: `ФоновоеЗадание.ОжидатьЗавершения()` объявлен устаревшим в 8.3.13.
- Стандартные шаблоны текста лежат в каталоге `bin` версии платформы и не редактируются; пользовательские шаблоны рекомендуется хранить вне каталога установки.
