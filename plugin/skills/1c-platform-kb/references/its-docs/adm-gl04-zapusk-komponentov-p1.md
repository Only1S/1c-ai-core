## 4.1. Общая информация

Раздел перечисляет ярлыки, которые появляются в меню после установки платформы. `A.B.C.D` везде означает полный номер установленной версии.

### 4.1.1. Для ОС Linux

В меню программ оконного менеджера создаются три ссылки:

| Пункт меню | Что запускает |
|---|---|
| `1С:Предприятие A.B.C.D` | интерактивная программа запуска (`1cv8s`) версии A.B.C.D |
| `1С:Предприятие A.B.C.D - Тонкий клиент` | тонкий клиент версии A.B.C.D |
| `1С:Предприятие A.B.C.D - Толстый клиент` | толстый клиент версии A.B.C.D |

Других пунктов для Linux источник не перечисляет (в частности, отдельных пунктов для конфигуратора и для программы запуска `1cestart` в списке нет).

### 4.1.2. Для ОС macOS

В меню «Программы» создаётся папка `1С Предприятие 8`:

| Пункт | Назначение |
|---|---|
| `1С:Предприятие` (верхний уровень) | программа запуска (`1cestart`) |
| `A.B.C.D` (папка) | каталог приложений версии с полным номером A.B.C.D |
| `1С:Предприятие` (внутри папки версии) | интерактивная программа запуска (`1cv8s`) |
| `1С:Предприятие - Тонкий клиент` | тонкий клиент |
| `1С:Предприятие - Толстый клиент` | толстый клиент |
| `Удалить 1С:Предприятие` | удаление той версии, в папке которой находится этот пункт |

Правило: если имя программы указано без версии, используется программа/файл из версии, установленной последней по времени.

### 4.1.3. Для ОС Windows

Только Windows (структура приведена для Windows 10), кратко. В меню «Пуск — Программы»:

| Пункт | Назначение |
|---|---|
| `1С Предприятие` | программа запуска (`1cestart`) |
| `1С Предприятие (A.B.C.D)` | интерактивная программа запуска (`1cv8s`) |
| `Тонкий клиент (A.B.C.D)` / `Толстый клиент (A.B.C.D)` | соответствующий клиент |
| `Конфигуратор (A.B.C.D)` | запуск в режиме Конфигуратор |
| `Установка драйвера защиты` / `Удаление драйвера защиты` | установка / удаление драйвера защиты |
| `ReadMe - Дополнительная информация` | сведения, не вошедшие в документацию |
| `Конвертор ИБ 1С Предприятия 7.7 (A.B.C.D)` | конвертация баз формата 7.7 (есть в таблице назначений, но отсутствует в приведённом дереве меню — ⚠ в источнике неясно) |
| `Администрирование серверов 1С Предприятия` | утилита администрирования кластера (если установлены компоненты доступа к кластеру серверов) |
| `Запуск сервера (A.B.C.D)` | запуск сервера как сервиса (если при установке отмечен флажок «Установить сервер 1С:Предприятия 8 как сервис Windows») либо как приложения (если флажок не отмечен; тогда остановка — закрытие обычного приложения) |
| `Регистрация утилиты администрирования серверов (A.B.C.D)` | регистрация `radmin.dll` конкретной версии; после неё утилитой администрирования можно подключаться к серверам этой версии |

Примечания источника:
- имя без версии — берётся версия, установленная последней по времени;
- пункт с `(A.B.C.D)` повторяется по числу установленных версий (пример: 8.3.12.100 и 8.3.12.150 дают две строки «Тонкий клиент (…)»);
- для 64-разрядной установки в названии папки и пунктов присутствует строка `x86-64`;
- сервер, установленный в режиме «для пользователя», не может работать как сервис Windows.

## 4.2. Режимы работы системы

| Режим | Что это |
|---|---|
| Конфигуратор | режим конфигурирования: правка структур данных, обновление конфигурации, ведение списка пользователей и их прав, выгрузка и загрузка данных |
| 1С:Предприятие | исполняемая часть: ввод и обработка данных на основе структур, описанных в конфигураторе |

Варианты исполняемой части:

| Вариант | Исполняемый файл | Какие конфигурации исполняет |
|---|---|---|
| Тонкий клиент | `1cv8c` | только написанные в режиме управляемого приложения |
| Веб-клиент | исполняемого файла нет — его роль играет веб-браузер | только написанные в режиме управляемого приложения |
| Толстый клиент | `1cv8` | и конфигурации для предыдущих версий платформы, и конфигурации управляемого приложения |

## 4.3. Запуск клиентского приложения или конфигуратора

### 4.3.1. Общая информация

Способы запуска:

| Способ | Файл | Примечание |
|---|---|---|
| Программа запуска | `1cestart` | рекомендованный способ |
| Интерактивная программа запуска | `1cv8s` | |
| Исполняемый файл клиента конкретной версии | `1cv8` (толстый), `1cv8c` (тонкий) | |
| Веб-браузер | — | только веб-клиент |

Конфигурационные файлы, участвующие в запуске:

| Файл | Роль |
|---|---|
| `1cestart.cfg` | локальный конфигурационный файл |
| `1cestart.cfg` | локальный конфигурационный файл для всех пользователей (то же имя, другое расположение) |
| `1cescmn.cfg` | общий конфигурационный файл — **кроме ОС Linux** (в Linux не используется) |

### 4.3.2. Программа запуска

#### 4.3.2.1. Общая информация

- `1cestart` умеет запускать все виды клиентов (толстый, тонкий, веб-клиент) и конфигуратор.
- Запускается либо без параметров, либо со ссылкой на конкретную ИБ.
- Только Windows: программа запуска может лежать на сетевом ресурсе (дополнительные компоненты ей не нужны) и выполнять как первичную установку платформы, так и установку новых версий; если в каталоге запуска найден общий конфигурационный файл, ссылка на него записывается в параметр `CommonCfgLocation` локального конфигурационного файла; при установке через программу запуска возможен запрос на перезагрузку ОС.

#### 4.3.2.2. Запуск без параметров

Алгоритм `1cestart` без параметров:

1. При запуске с сетевого диска — попытка найти общий конфигурационный файл в каталоге запуска; при успехе из него читаются параметры.
2. Поиск локального `1cestart.cfg` — и в каталогах режима установки «для компьютера», и в каталогах режима «для пользователя»; при успехе читаются параметры.
3. Поиск установленных версий платформы по параметрам `InstalledLocation` конфигурационных файлов. **Если `InstalledLocation` нигде не задан — запуск прекращается с сообщением об ошибке.**
4. Определяется максимальный номер установленной версии.
5. Определяется максимальный номер версии, доступной для установки, в каталогах из параметров `DistributiveLocation`.
6. Если доступна к установке версия с большим номером — она устанавливается автоматически с набором компонентов из параметра `InstallComponents`. Если `InstallComponents` не задан, ставятся: тонкий клиент, толстый клиент и компоненты доступа к серверам «1С:Предприятия». Режим установки выбирается исходя из прав текущего пользователя (источник отсылает к стр. 76).
7. Из каталога версии с максимальным номером (уже имевшейся или только что установленной) запускается интерактивная программа запуска с параметром `/AppAutoCheckVersion`.

#### 4.3.2.3. Запуск с указанием информационной базы

При запуске с именем базы (параметр `/IBName`):

1. Читаются параметры из локальных (`1cestart.cfg`) и общего (`1cescmn.cfg`) конфигурационных файлов.
2. Формируется общий список ИБ: локальный список (`ibases.v8i`) плюс списки из параметров `CommonInfoBases` конфигурационных файлов.
3. Если указанного имени в списке нет — запуск прекращается с сообщением об ошибке.
4. Если база найдена — из её свойств берутся параметры запуска и стартует соответствующий клиент. Из свойств ИБ определяются:
   - вид клиента;
   - требуемый номер версии;
   - разрядность клиентского приложения;
   - прочие параметры, сохранённые в свойствах базы.
5. Запуск выполняется с параметром `/AppAutoCheckVersion`.

### 4.3.3. Интерактивная программа запуска

#### 4.3.3.1. Общая информация

- `1cv8s` запускает все виды клиентов, конфигуратор и 1C:Enterprise Development Tools (1C:EDT).
- Кнопки окна:
  - «1С:Предприятие» — клиентское приложение для текущей базы списка;
  - «Конфигуратор» — вход конфигуратором, если это допускает способ доступа к базе. **Для базы, опубликованной через веб-сервер, вход конфигуратором невозможен — кнопка недоступна**;
  - «1C:EDT» — запуск 1C:EDT для текущей базы; доступность кнопки задаётся в настройках окна запуска; если EDT не установлен, будет предложена установка. Запуск EDT возможен только интерактивно из формы `1cv8s`.
- `1cv8s` использует часть компонентов платформы, поэтому последующий старт клиента той же версии, что и сама `1cv8s`, идёт быстрее, чем отдельный запуск исполняемого файла клиента.
- Может запускаться интерактивно или программой запуска `1cestart`.
- При первом запуске:
  - формируется единый список ИБ в файле `ibases.v8i`, куда попадают базы всех версий «1С:Предприятия»; перенос списков версий 8.0 и 8.1 сопровождается вопросом; дальнейшая актуализация списка не предусмотрена;
  - определяются каталоги шаблонов конфигураций предыдущих версий, найденные пути записываются в параметр `ConfigurationTemplatesLocation` файла `1cestart.cfg`. Какой именно `1cestart.cfg` используется — зависит от того, откуда запущена `1cv8s`.
- Запускается без параметров или со ссылкой на конкретную ИБ.

#### 4.3.3.2. Запуск без параметров

Без параметров открывается окно выбора ИБ. После выбора базы поведение зависит от параметра `/AppAutoCheckVersion`:

| Условие запуска `1cv8s` | Поведение |
|---|---|
| Запущена программой запуска либо интерактивно: с `/AppAutoCheckVersion+` или вообще без этого параметра | 1) определяется версия, нужная для базы, и ищутся исполняемые файлы этой версии; 2) если нужная версия не установлена и не может быть установлена — ошибка, запуск прекращается; 3) определяются клиент и прочие параметры, из каталога версии запускается нужный клиент с нужными параметрами (включая `/AppAutoCheckVersion`); 4) если в каталоге версии нет нужного клиента — ошибка, запуск прекращается |
| Запущена из каталога конкретной версии с `/AppAutoCheckVersion-` | используются исполняемые файлы только той версии, из каталога которой запущена `1cv8s`; если у базы задан автоматический выбор типа клиента — стартует тонкий клиент с параметром `/AppAutoCheckMode` |

#### 4.3.3.3. Запуск с параметрами

Запуск `1cv8s` с параметром `/IBName` (указание конкретной базы) ничем не отличается от такого же запуска программы запуска — см. 4.3.2.3.

### 4.3.4. Варианты подключения к информационной базе

Способ размещения базы и подключения к ней выбирается в диалоге добавления ИБ.

| Где расположена ИБ | Какие клиенты | Вариант работы |
|---|---|---|
| На локальном компьютере или на компьютере локальной сети | тонкий и толстый | файловый |
| На сервере «1С:Предприятия» | тонкий и толстый | клиент-серверный |
| На веб-сервере | тонкий клиент и веб-клиент | файловый или клиент-серверный |

Особенности:

- **Тонкий клиент в файловом варианте.** На компьютере, где запущен тонкий клиент, создаётся специализированная среда, в которой загружаются серверные компоненты, прикладная конфигурация и выполняется всё остальное, нужное для работы с базой. Тонкий клиент общается с этой средой теми же протоколами, что и с сервером «1С:Предприятия» или веб-сервером, то есть для него она выступает сервером. Отдельного процесса ОС при этом нет — среда живёт внутри процесса тонкого клиента.
- **Подключение через веб-сервер.** Требуется установленный и настроенный веб-сервер. Строка соединения — URL, например:

```
http://MyServer/DemoBase
```

### 4.3.5. Выбор информационной базы

- Окно «Запуск 1С:Предприятия» содержит список «Информационные базы». Каждая строка связана либо с каталогом файлов базы (файловый вариант), либо с парой «сервер + база на сервере» (клиент-серверный вариант).
- Управление списком: кнопки «Изменить», «Добавить», «Удалить» (горячие клавиши `F2`, `Ins`, `Del`).
- Запуск: кнопка «1С:Предприятие» — режим 1С:Предприятие, «Конфигуратор» — режим Конфигуратор, «Выход» — отказ от запуска.
- Размер и положение окна запоминаются до следующего сеанса.
- Гиперссылка «Перейти по ссылке» — запуск клиента по внешней навигационной ссылке на объект прикладного решения (открывается диалог, в него вводится ссылка, затем кнопка «Перейти»).
- Базу можно открыть и без регистрации в списке: с помощью файла `.v8i` или указав параметры базы в командной строке клиента.

**Важно про незарегистрированную базу:** если база не внесена в список ИБ на компьютере, с которого идёт доступ, для неё **не выполняется кеширование данных конфигурации**, из-за чего многие операции заметно замедляются. Рекомендация источника при такой проблеме — добавить базу в список информационных баз.

### 4.3.6. Выбор и использование клиентского приложения

#### 4.3.6.1. Общая информация

Раздел описывает выбор запускаемого клиента (включая разрядность) и поведение системы при несовпадении версий в клиент-серверном и файловом вариантах.

#### 4.3.6.2. Необходимый клиент конкретной версии

Конкретный клиент (тонкий или толстый) запускается:

- пунктом меню ОС — вид клиента определяется словами «тонкий клиент» / «толстый клиент» в названии пункта;
- непосредственно исполняемым файлом: `1cv8c` — тонкий клиент конкретной версии, `1cv8` — толстый клиент конкретной версии.

Поведение при прямом запуске клиента:

- Для **файловой** базы сначала делается попытка установить новую версию клиента (по параметру `DistributiveLocation` конфигурационных файлов) и только потом — открыть базу самой новой версией, установленной на компьютере.
- Управление автоустановкой новой версии:

| Средство | Действие |
|---|---|
| `/AppAutoCheckVersion-` (параметр командной строки клиента) | отключает установку новой версии |
| флажок «Устанавливать автоматически новую версию» в диалоге настройки окна запуска | управляет установкой новой версии |
| `/AppAutoInstallLastVersion` (параметр командной строки клиента) | управляет установкой новой версии |

- Если клиент запущен **без** `/AppAutoCheckMode`, выбранная база открывается именно этим клиентом этой версии — подбор вида клиентского приложения не выполняется.

#### 4.3.6.3. Определение разрядности запускаемого приложения и использование приложений разной разрядности

Где выбор разрядности вообще действует:

| ОС клиента | Поведение |
|---|---|
| 64-разрядная Windows | выбор разрядности клиента применяется (только здесь) |
| Linux | используется приложение той же разрядности, что и ОС; выбор не применяется |
| macOS | доступны только 64-разрядные приложения |

На одном компьютере могут стоять несколько версий клиента разной разрядности; разрядность можно задать как для конкретной базы, так и для всех баз.

Средства управления разрядностью — в порядке **убывания** приоритета:

1. ключ командной строки `/AppArch`;
2. свойство информационной базы;
3. свойство интерактивной программы запуска.

Допустимые значения настройки (источник говорит о «четырёх значениях», но перечисляет пять пунктов — пятый равнозначен отсутствию явного выбора):

| Значение | Поведение |
|---|---|
| 32 (x86) | всегда 32-разрядный клиент; 64-разрядные версии игнорируются, даже если они новее |
| 64 (x86-64) | всегда 64-разрядный клиент; 32-разрядные версии игнорируются, даже если они новее |
| Приоритет 32 (x86) | предпочтение 32-разрядному клиенту, но если среди 64-разрядных есть более свежая версия — берётся самая свежая (64-разрядная) |
| Приоритет 64 (x86-64) | предпочтение 64-разрядному клиенту, но если среди 32-разрядных есть более свежая версия — берётся самая свежая (32-разрядная) |
| Автоматически | разрядность явно не задана; применяется вариант «Приоритет 32 (x86)» |

Совместимость разрядностей:

- Работоспособность системы не зависит от разрядности, ОС и процессора клиентских приложений и кластера серверов. С одной базой одновременно могут работать клиенты разной разрядности, на разных процессорах и под разными ОС; разрядность кластера может не совпадать с разрядностью, ОС и процессором клиентов.
- Разрядность и ОС приложения существенны в двух случаях:
  - COM-соединение (только Windows);
  - внешние компоненты — в составе компоненты должен быть файл, соответствующий тому приложению, где она будет использоваться; манифест компоненты описывает, для каких вариантов запуска она собрана (описание манифеста: https://its.1c.ru/db/metod8dev#content:3221:hdoc). Действует для всех окружений, где поддерживаются внешние компоненты.

Связанные настройки (в источнике только перечислены ссылками): настройки окна запуска, ключи командной строки, `1cestart.cfg`, `1cescmn.cfg`, `*.v8i`.

#### 4.3.6.4. Несовпадение версии клиента и сервера

**В клиент-серверном варианте версии клиента и сервера должны совпадать в точности; при различии работа невозможна.**

При несовпадении клиент (тонкий или толстый) пытается найти и установить нужную версию. Порядок поиска дистрибутива:

| № | Где ищется | Чем задаётся |
|---|---|---|
| 1 | каталог установки «1С:Предприятия» | свойство `InstalledLocation` файлов `1cestart.cfg` и `1cescmn.cfg` |
| 2 | каталоги дистрибутивов новых версий | свойство `DistributiveLocation` файлов `1cestart.cfg` и `1cescmn.cfg`, а также свойство `CommonCfgLocation` файла `1cestart.cfg` |
| 3 | URL из серверного исключения о несовпадении версий клиента и сервера | параметр `PublishDistributiveLocation*` файла `conf.cfg` и атрибут `pubdst*` элемента `ws` файла `default.vrd` |
| 4 | интернет-сервисы получения дистрибутива клиентского приложения | — |

Оговорки:

- Поиск и получение дистрибутива через интернет-сервисы тонкий клиент выполняет **только при подключении к базе по HTTP**.
- Получение дистрибутива по URL из исключения о несовпадении версий тонкий клиент выполняет при **любом** клиент-серверном подключении.
- Если в списке баз (файл `*.v8i`) для базы указана версия, которую невозможно установить, база запускается максимальной версией, доступной на компьютере; путь к дистрибутиву нужного клиента в этом случае может быть получен от сервера «1С:Предприятия».

#### 4.3.6.5. Несовпадение версий при работе файлового варианта информационной базы

- С файловой базой одновременно могут работать только клиентские приложения **строго одной версии**.
- Требуемая версия определяется версией клиента, выполнившего **первое** подключение к файлу `1Cv8.1CD`. Первым считается подключение, в момент которого с базой не было соединений других клиентских приложений.

### 4.3.7. Веб-клиент

#### 4.3.7.1. Общая информация

- Запуск веб-клиента: открыть веб-браузер и ввести URL доступа к базе. Браузер должен быть специально настроен, веб-сервер — тоже (описания настроек в других разделах документации).
- Одна и та же база (один и тот же URL) может быть открыта в нескольких закладках одного браузера.

#### 4.3.7.2. Выбор языка интерфейса и региональных установок

**Язык интерфейса** — источники в порядке повышения приоритета:

1. предпочтительные языки в настройках веб-браузера;
2. параметр `L` в URL.

Алгоритм выбора языка при запросе к ресурсу базы (например `http://localhost/demo`):

1. Если в URL есть параметр `L` — анализируется его значение. Если язык по нему подобрать не удалось — анализируется заголовок `Accept-Language`.
2. Если параметра `L` нет — анализируется стандартный HTTP-заголовок `Accept-Language` (предпочтительные языки браузера).
3. Язык выбирается из набора локализаций, установленных на веб-сервере. При отсутствии точного совпадения имя языка усекается и поиск повторяется (например `en_US` → `en`).
4. Если язык так и не найден — используется английский (`en`).
5. Выбранный язык дописывается к базовому URL приложения, и браузер автоматически переадресуется на новый URL.

```
http://localhost/demo?l=en      -> запрос с явным указанием английского языка интерфейса
http://localhost/demo/en        -> URL после автоматической переадресации
```

**Региональные установки сеанса** (влияют на отображение значений типа Число и Дата) — источники в порядке повышения приоритета:

1. предпочтительные языки в настройках веб-браузера;
2. параметр `VL` в URL.

Алгоритм:

- Есть параметр `VL` — применяются региональные установки локализации с указанным кодом. **Если указан код несуществующей локализации — веб-клиент завершает работу с ошибкой** (в отличие от параметра `L`, где происходит откат к `Accept-Language`).
- Параметра `VL` нет — анализируется заголовок `Accept-Language`.

```
http://localhost/demo?vl=en     -> региональные установки сеанса для английского языка
```

Примечание источника: браузер Safari не поддерживает настройку предпочтительных языков — вместо неё берётся язык интерфейса операционной системы.

#### 4.3.7.3. Аутентификация с помощью POST-запроса

Назначение: запуск веб-клиента в обход стандартного окна аутентификации — когда вход нужно выполнять через собственную форму (например, встроенную в сайт) или когда логины и пароли хранятся во внешней базе данных.

Механизм: POST-запрос к специальному ресурсу информационной базы `e1cib/start`.

Последовательность:

1. Выполняется POST-запрос для аутентификации клиента.
2. При успешной аутентификации от имени пользователя, переданного в запросе, создаётся сеанс.
3. Запускается веб-клиент; в его командную строку передаются параметры POST-запроса: `LowClientConnectionSpeed`, `LaunchParameter`, `LocaleCode`, `Zone`.
4. Запущенный веб-клиент подключается к сеансу, аутентифицированному на шаге 2.

Совет источника: для такой аутентификации рекомендуется протокол HTTPS.

Параметры POST-запроса:

| Параметр | Обязательность | Назначение | Значения / умолчание |
|---|---|---|---|
| `Usr` | обязательный | имя пользователя | — |
| `Pwd` | необязательный | пароль пользователя | по умолчанию — пустая строка |
| `LowClientConnectionSpeed` | необязательный | скорость соединения | `on` — низкая скорость; `off` — нормальная скорость (по умолчанию) |
| `LaunchParameter` | необязательный | параметры, передаваемые в прикладное решение (аналог параметра `C` командной строки веб-клиента) | по умолчанию — пустая строка |
| `SystemLanguage` | необязательный | язык интерфейса | если не задан — язык и региональные установки определяются по правилам 4.3.7.2 |
| `LocaleCode` | необязательный | в тексте источника описан теми же словами, что и `SystemLanguage` («язык интерфейса»); в примере формы поле подписано «Код локализации сеанса» — ⚠ в источнике неясно | если не задан — определение по правилам 4.3.7.2 |
| `Zone` | необязательный | значения разделителей (подробности задания разделителей в веб-клиенте — в другой книге документации) | — |
| `AuthFailHandling` | необязательный | поведение при ошибке аутентификации | `error` — вернуть код ошибки **402** и текст сообщения об ошибке (по умолчанию); `start` — запустить веб-клиент с запросом аутентификации средствами «1С:Предприятия»; `redirect` — перейти на URL из `AuthFailRedirectURL` |
| `AuthFailRedirectURL` | необязательный | URL перехода при ошибке аутентификации, когда `AuthFailHandling` = `redirect` | URL должен быть абсолютным |

Приоритет: параметры из тела запроса имеют преимущество перед параметрами командной строки запуска веб-клиента.

Пример собственной формы аутентификации для базы по адресу `http://localhost/demoapp` (из источника, разметка приведена к читаемому виду):

```html
<HTML xmlns="http://www.w3.org/1999/xhtml"><HEAD>
<META http-equiv="Content-Type" content="text/html; charset=utf-8" />
<BODY>
<FORM action="http://localhost/demoapp/e1cib/start" method="post">
  Пользователь: <INPUT id="usr" name="usr" /><BR />
  Пароль: <INPUT id="pwd" type="password" value="" name="pwd" /><BR />
  Низкая скорость: <INPUT id="lowclientconnectionspeed" type="checkbox" name="lowclientconnectionspeed" /><BR />
  Параметр запуска: <INPUT id="launchparameter" name="launchparameter" /><BR />
  Язык интерфейса: <SELECT id="systemlanguage" name="systemlanguage">
    <OPTION value="ru" selected="">Русский</OPTION>
    <OPTION value="en">Английский</OPTION>
  </SELECT><BR />
  Код локализации сеанса: <SELECT id="localecode" name="localecode">
    <OPTION value="ru" selected="">Русский</OPTION>
    <OPTION value="en">Английский</OPTION>
  </SELECT><BR />
  Область данных: <INPUT id="zone" name="zone" />
  <INPUT id="authfailhandling" type="hidden" value="error" name="authfailhandling" />
  <P><INPUT type="submit" value="ОК" /></P>
</FORM>
</BODY>
</HTML>
```

В примере имена полей формы записаны строчными буквами (`usr`, `pwd`, `lowclientconnectionspeed`, `launchparameter`, `systemlanguage`, `localecode`, `zone`, `authfailhandling`), тогда как в перечне параметров они даны в виде `Usr`, `Pwd` и т. д.

### 4.3.8. Пользователи информационной базы

#### 4.3.8.1. Аутентификация пользователей

**Когда появляется диалог.** Если у базы есть список пользователей (создаётся и редактируется в конфигураторе), при входе показывается диалог аутентификации.

**Заголовок диалога** (строка под логотипом «1С»):

| Откуда открыт вход | Что выводится |
|---|---|
| из программы запуска, в списке баз которой есть эта база | название информационной базы |
| веб-клиент либо запуск с параметрами доступа в командной строке клиента | текст «1С:Предприятие» |

**Имя пользователя:**

- выбор из списка поля «Пользователь» — возможен, если есть пользователи, которых разрешено показывать в списке выбора;
- ручной ввод — когда список слишком велик или у пользователя не установлено свойство «Показывать в списке выбора».

После успешной аутентификации введённое имя попадает в список последних пользователей; список хранит **до 4 имён**.

**Пароль:**

- вводится в поле «Пароль», вход — кнопка «Войти»; отказ от подключения — кнопка «X» в правом верхнем углу;
- кнопка в правой части поля пароля циклически переключает показ: символы `*` ↔ открытый текст; при повторном открытии диалога поле снова в маскированном режиме.

**Флажок «Запомнить».** Отображается, если в настройках ИБ (или в параметрах публикации на веб-сервере) разрешено сохранение аутентификации. Если его установить, при следующем входе в эту базу на этом же компьютере аутентификация не запрашивается — вход сразу выполняется от имени пользователя, который был указан в диалоге.

**Гиперссылка «Забыли пароль?».** Отображается, если в базе включено самостоятельное восстановление пароля; запускает механизм восстановления пароля.

**Несколько видов аутентификации.** Если для базы настроено несколько видов, диалог показывает их все:

- блок в нижней части диалога, озаглавленный «Войти через…»;
- вход по QR-коду показывается отдельно — гиперссылкой «Войти через QR-код» под кнопкой «Войти» (если возможность включена);
- виды, которые может отображать диалог: стандартная; через электронную почту; с помощью QR-кода; OpenID; OpenID Connect;
- может быть настроено и показано несколько провайдеров OpenID Connect;
- активный вид (его параметры показаны в верхней части диалога) выделен подчёркиванием под своей картинкой.

Условия отображения вида аутентификации в диалоге (нужны оба):

1. вид аутентификации настроен для данной ИБ;
2. для данной ИБ включена возможность выбора этого вида.

Всё это настраивается в файле публикации `default.vrd`:

| Элемент `default.vrd` | Назначение |
|---|---|
| `<openid>` | настройка аутентификации OpenID |
| `<openidconnect>` | настройка аутентификации OpenID Connect |
| `<mobileApps>` | размещение мобильных приложений, которые могут использоваться для входа по QR-коду |
| `<authentication>` | какие виды аутентификации показывать в диалоге и в каком порядке |

Правила взаимодействия настроек:

- Скрытие вида в `<authentication>` имеет **более высокий приоритет**, чем настройки в остальных разделах `default.vrd`. Пример источника: OpenID настроен и провайдер доступен клиенту, но в `<authentication>` он выключен — выбрать OpenID в диалоге нельзя.
- Включение отображения вида в `<authentication>` **не настраивает** этот вид автоматически.
- Для провайдера OpenID Connect: если в описании провайдера задано поле `image`, в диалоге провайдер показывается этой картинкой; подсказкой служит содержимое поля `title` описания провайдера.

**Ошибки доступа при аутентификации.** Касается запуска любого клиента: тонкий, веб-клиент, мобильный клиент, толстый клиент, конфигуратор. Ошибки доступа: нет свободной лицензии; запрет от сервиса внешнего управления сеансами; ошибка монопольного доступа к базе/области. Действия системы:

| Ситуация | Что происходит |
|---|---|
| В текущей базе/области нет других сеансов этого пользователя | показывается ошибка, клиентское приложение не запускается |
| Есть другие сеансы этого пользователя, их клиентские приложения были запущены на том же клиентском компьютере и уже завершились | такие сеансы завершаются автоматически, аутентификация повторяется |
| Иначе: сеансы пользователя есть, но их клиентские приложения ещё работают либо запущены на другом компьютере | показывается диалог со списком сеансов пользователя и предложением завершить все или некоторые; при согласии выбранные сеансы завершаются и аутентификация повторяется |

#### 4.3.8.2. Порядок аутентификации при доступе к данным информационной базы

##### 4.3.8.2.1. Общая информация

Перед доступом к данным клиентское приложение обязано указать пользователя ИБ и пройти проверку его подлинности. «Клиентским приложением» здесь считается и клиент «1С:Предприятия», и любой сторонний программный продукт, обращающийся к данным через внешние интерфейсы прикладного решения.

Способы доступа к данным:

- прямой доступ к файловой базе или серверу «1С:Предприятия» — по протоколу TCP/IP;
- доступ через веб-сервер — по протоколу HTTP(s).

Способы аутентификации:

| № | Способ | Примечание |
|---|---|---|
| 1 | Имя пользователя и пароль (аутентификация средствами «1С:Предприятия», стандартная) | возможна двухфакторная аутентификация, если она настроена на стороне «1С:Предприятия» |
| 2 | Аутентификация операционной системы | |
| 3 | Протоколы OpenID и OpenID Connect | провайдеры OpenID могут применять свои виды двухфакторной аутентификации — зависит от настроек провайдера |
| 4 | Специальный токен доступа | |
| 5 | QR-код | |
| 6 | Электронная почта | |

Набор доступных видов зависит от способа доступа к данным.

**Прямое подключение** (к файловой базе или кластеру серверов, без промежуточных серверов) — доступны только:

- аутентификация операционной системы;
- аутентификация средствами «1С:Предприятия»;
- аутентификация через электронную почту (только интерактивная).

**Подключение по HTTP(s)** — добавляются два участника:

| Участник | Роль | Допущение источника |
|---|---|---|
| Прокси-сервер | посредник между клиентским приложением и целевым сервером; необязательный элемент | расположен в сети клиентского приложения |
| Веб-сервер | организует доступ по HTTP(s) к базе или кластеру серверов | расположен в той же сети, что кластер серверов или база |

Данные между прокси-сервером и веб-сервером могут идти как через локальную сеть (Интранет), так и через Интернет.

**HTTPS (защищённое соединение).** К аутентификации напрямую не относится, но повышает уверенность, что клиент и сервер — те, за кого себя выдают. Организуется между клиентским приложением и веб-сервером, на котором опубликована база, и только если на веб-сервере включена поддержка HTTPS для этой базы. Как клиент указывает использование защищённого соединения:

| Клиент | Как настраивается |
|---|---|
| Веб-клиент | всё делает сам веб-браузер; на клиентском компьютере должны быть установлены корневые сертификаты, которыми можно проверить сертификат веб-сервера |
| Тонкий клиент | настройки сертификатов выполняются в интерактивной программе запуска: как проверять сертификат веб-сервера и какой сертификат предъявляет клиент |
| Встроенный язык | объект `ЗащищенноеСоединениеOpenSSL`, параметры аналогичны настройкам интерактивной программы запуска |

В самом полном случае в аутентификации участвуют четыре элемента: клиентское приложение (на клиентском устройстве), прокси-сервер, веб-сервер, кластер серверов «1С:Предприятия» (или расширение веб-сервера — для файловой базы). Варианты комбинируются (например, клиент → веб-сервер → файловая база). Во всех случаях процесс инициирует клиентское приложение, и оно же снабжает остальных участников данными для каждого шага.

Три точки аутентификации (нумерация как на рис. 32 источника):

**1. Аутентификация на прокси-сервере**

- Виды: средствами «1С:Предприятия»; операционной системы.
- Где задаются параметры:
  - настройки доступа к ИБ в интерактивной программе запуска;
  - параметр командной строки клиента `/Proxy` (в тексте источника буква «х» набрана кириллицей — опечатка источника);
  - объект `ИнтернетПрокси` — при программном доступе;
  - конфигурационный файл `inetcfg.xml`.

**2. Аутентификация на веб-сервере**

- Виды: средствами «1С:Предприятия»; операционной системы.
- Где задаются параметры:
  - параметры командной строки клиента `/WSA`, `/WSN` и `/WSP`;
  - объект `ИнтернетПрокси` — при программном доступе (так в источнике; в разделе 4.3.8.2.3 для программной аутентификации на веб-сервере названы объекты `HTTPСоединение` и `WSОпределения` — ⚠ в источнике неясно).
- Может использоваться защищённое соединение (HTTPS).

**3. Аутентификация в информационной базе**

Виды: токен доступа; аутентификация ОС; различные варианты протокола OpenID; QR-код; имя пользователя и пароль; электронная почта (только интерактивный вход).

Где задаются параметры:

| Вид аутентификации | Средство | Примечание |
|---|---|---|
| Токен доступа | параметр командной строки клиента `/AccessToken` | |
| Токен доступа | параметр строки соединения с ИБ `AccessToken` | |
| Токен доступа | заголовок HTTP-запроса к ИБ `Authorization: Bearer` | |
| Аутентификация ОС | параметр командной строки клиента `/WA` | допускает только включение/выключение этого способа |
| Аутентификация ОС | параметр `ИспользоватьАутентификациюОС` конструкторов объектов `HTTPСоединение` или `WSОпределения` | |
| OpenID | параметр командной строки клиента `/OIDA` | допускает только включение/выключение; сами параметры аутентификации берутся из настроек публикации базы, к которой выполняется доступ |
| OpenID | заголовок HTTP-запроса к ИБ `Authorization: Bearer` | |
| Имя пользователя и пароль | параметры командной строки клиента `/N` и `/P` | |
| Имя пользователя и пароль | параметры строки соединения с ИБ | |
| Имя пользователя и пароль | заголовок HTTP-запроса к ИБ `Authorization: Basic` | |
| Электронная почта | параметр командной строки клиента `/EmailAuth` | |

Для QR-кода средство задания параметров в этом перечне источника не приведено.

##### 4.3.8.2.2. Интерактивная аутентификация

###### Аутентификация на веб-сервере

Тонкий клиент:

| Что указано в командной строке | Поведение |
|---|---|
| `/WSA-` | интерактивный запрос имени пользователя и пароля для веб-сервера |
| корректные `/WSN` и `/WSP` | аутентификация на веб-сервере от имени указанного пользователя |
| `/WSN` не задан | выполняется аутентификация ОС; при неудаче — запрос имени пользователя и пароля |
| `/WSN` задан, `/WSP` не задан или задан некорректно | интерактивный запрос имени пользователя и пароля для веб-сервера |

Веб-клиент: процессом управляет веб-браузер.

###### Аутентификация в информационной базе

Одинаково для прямого соединения с сервером/базой (тонкий и толстый клиенты) и для соединения через веб-сервер (тонкий клиент или веб-клиент). Шаги выполняются строго по порядку:

1. Аутентификация токеном сохранённой аутентификации — если возможно.
2. Аутентификация с помощью JWT — если возможно. **Если она не выполнена, дальнейшие способы аутентификации не выполняются.**
3. Аутентификация операционной системы — если возможно. При неудаче или при указанной команде `/WA-` попытки продолжаются другими видами.
4. Аутентификация по имени и паролю — если в командной строке указан один или оба параметра аутентификации:

| Состояние параметров | Поведение |
|---|---|
| корректные `/N` и `/P` | вход от имени указанного пользователя |
| `/N` не задан | запрос имени и пароля пользователя |
| `/P` не задан | попытка аутентификации с пустым паролем; при неудаче — окно аутентификации |
| `/P` задан некорректно | попытка аутентификации; при неудаче — окно аутентификации |
| попытка неудачна и `/N` указан | в открывшемся окне значение `/N` подставлено в поле имени пользователя |

5. Пользователь выбирает способ аутентификации в диалоге и пытается войти этим способом. Диалог настраивается файлом публикации `default.vrd` (элемент `<authentication>`): отключённый там вид выбрать нельзя, даже если остальные его настройки есть и корректны. При параметре командной строки `/OIDA-` аутентификация OpenID недоступна для выбора.

##### 4.3.8.2.3. Аутентификация при программном доступе к информационной базе

###### Аутентификация на веб-сервере

Настраивается объектами `HTTPСоединение` или `WSОпределения` (в зависимости от вида сервиса) — параметрами конструктора `ИмяПользователя`, `Пароль` и `ИспользоватьАутентификациюОС`:

| `ИспользоватьАутентификациюОС` | Настройка веб-сервера | Поведение |
|---|---|---|
| `Истина` | аутентификация ОС на веб-сервере включена | выполняется аутентификация ОС. Если заданы `ИмяПользователя` и `Пароль` — они используются для аутентификации по протоколам NTLM и Kerberos; имя должно иметь вид `DOMAIN\user` или `user@domain`. Если не заданы — берутся параметры пользователя, от имени которого исполняется текущий сеанс |
| `Истина` | аутентификация ОС на веб-сервере не включена | аутентификация на веб-сервере не выполняется; `ИмяПользователя` и `Пароль` используются для доступа к информационной базе |
| `Ложь` | — | если заданы `ИмяПользователя` и `Пароль` — аутентификация по имени пользователя и паролю |

Предостережение источника (формулировка запутана — ⚠ в источнике неясно): не рекомендуется указывать имя пользователя и пароль доступа к ИБ, «которые указаны в URL доступа к информационной базе», — по контексту речь о передаче учётных данных базы через URL; в ряде случаев это приводит к труднодиагностируемым ошибкам.

###### Аутентификация в информационной базе

После аутентификации на веб-сервере расширение веб-сервера пытается аутентифицироваться в базе в таком порядке:

| № | Условие | Действие | При неудаче |
|---|---|---|---|
| 1 | есть заголовок `Authorization: Bearer` | попытка аутентификации токеном доступа | доступ к ИБ невозможен |
| 2 | есть заголовок `Authorization: Basic` | попытка аутентификации по имени пользователя и паролю | в источнике не указано |
| 3 | стандартные заголовки не используются | расширение веб-сервера пытается взять имя и пароль из строки соединения с ИБ в файле `default.vrd`; если они определены — передаются служебными заголовками запроса | — |
| 4 | имя и пароль определить не удалось | попытка аутентификации операционной системы | доступ к ИБ невозможен |

## Что важно администратору Linux

Все пункты — выводы из текста этой части; номера разделов указаны для ссылки.

1. **`1cescmn.cfg` в Linux не используется** (4.3.1): общий конфигурационный файл применяется во всех ОС, кроме Linux. На Linux-клиентах работают только локальные `1cestart.cfg` (пользовательский и «для всех пользователей»). Сценарии установки и обновления платформы программой запуска с сетевого ресурса описаны только для Windows (4.3.2.1).
2. **Без `InstalledLocation` программа запуска не стартует** (4.3.2.2): если параметр не задан ни в одном конфигурационном файле, `1cestart` завершает запуск с ошибкой.
3. **Версии клиента и сервера должны совпадать в точности** (4.3.6.4). После обновления сервера клиенты ищут дистрибутив по цепочке: `InstalledLocation` → `DistributiveLocation` / `CommonCfgLocation` → URL от сервера (`PublishDistributiveLocation*` в `conf.cfg`, атрибут `pubdst*` элемента `ws` в `default.vrd`) → интернет-сервисы (только тонкий клиент и только при подключении по HTTP).
4. **Файловая база — строго одна версия клиентов** (4.3.6.5): версию задаёт клиент, первым подключившийся к `1Cv8.1CD` при отсутствии других соединений.
5. **Разрядность на Linux не выбирается** (4.3.6.3): клиент имеет разрядность ОС; `/AppArch` и соответствующие свойства информационной базы и интерактивной программы запуска действуют только на 64-разрядной Windows. Разрядность/ОС/процессор сервера и клиентов могут не совпадать; ограничения касаются только COM-соединения (только Windows) и внешних компонент (нужна сборка под конкретное окружение).
6. **База вне списка ИБ работает медленно** (4.3.5): при запуске через `.v8i` или параметры командной строки без регистрации в списке баз не кешируются данные конфигурации. При жалобах на медленную работу стоит проверить, зарегистрирована ли база на клиентском компьютере.
7. **Через веб-публикацию конфигуратор не подключается** (4.3.3.1); к опубликованной на веб-сервере базе ходят тонкий клиент и веб-клиент (4.3.4).
8. **Язык веб-клиента управляется из URL**: `?l=<код>` — язык интерфейса (при неудаче откат к `Accept-Language`, затем к `en`), `?vl=<код>` — региональные установки сеанса; несуществующий код в `vl` приводит к ошибке веб-клиента (4.3.7.2). Набор доступных языков определяется локализациями, установленными на веб-сервере.
9. **Вход в веб-клиент собственной формой** — POST на `<URL базы>/e1cib/start` с параметрами `Usr`, `Pwd`, `LowClientConnectionSpeed`, `LaunchParameter`, `SystemLanguage`, `LocaleCode`, `Zone`, `AuthFailHandling`, `AuthFailRedirectURL`; при ошибке по умолчанию возвращается код 402; рекомендуется HTTPS (4.3.7.3).
10. **Состав диалога входа определяет `default.vrd`** (4.3.8.1): элементы `<openid>`, `<openidconnect>`, `<mobileApps>`, `<authentication>`. Выключение вида в `<authentication>` сильнее любых других настроек, а включение отображения само по себе ничего не настраивает.
11. **При прямом подключении к кластеру (TCP/IP)** доступны только аутентификация ОС, аутентификация средствами «1С:Предприятия» и вход через электронную почту (только интерактивно). Токен доступа, OpenID и QR-код в перечне видов для прямого подключения отсутствуют (4.3.8.2.1).
12. **Порядок интерактивной аутентификации в базе** (4.3.8.2.2): сохранённый токен → JWT (при неудаче дальнейшие способы не пробуются) → аутентификация ОС (отключается `/WA-`) → `/N` и `/P` → диалог выбора способа (OpenID отключается `/OIDA-`). Пустой `/P` означает попытку входа с пустым паролем.
13. **Аутентификация тонкого клиента на веб-сервере** управляется `/WSA`, `/WSN`, `/WSP`: без `/WSN` сначала пробуется аутентификация ОС, `/WSA-` сразу запрашивает имя и пароль (4.3.8.2.2). Параметры прокси — `/Proxy`, файл `inetcfg.xml`, объект `ИнтернетПрокси` (4.3.8.2.1).
14. **Программный доступ через веб-сервер** (объекты `HTTPСоединение` / `WSОпределения`; 4.3.8.2.3): расширение веб-сервера проверяет `Authorization: Bearer` → `Authorization: Basic` → имя и пароль из строки соединения в `default.vrd` → аутентификацию ОС. Неудача с Bearer или с аутентификацией ОС означает отказ в доступе. Источник предостерегает от использования имени и пароля ИБ, указанных в URL доступа к базе (труднодиагностируемые ошибки).
15. **Ошибки «нет свободной лицензии» / запрет внешнего управления сеансами / монопольный доступ при входе** (4.3.8.1): оставшиеся сеансы того же пользователя с того же компьютера, чьи клиенты уже завершились, платформа завершает сама и повторяет вход; для сеансов с ещё работающими клиентами или с другого компьютера показывается список с предложением их завершить.
