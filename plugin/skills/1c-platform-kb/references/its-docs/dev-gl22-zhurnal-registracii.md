# ИТС-конспект: Руководство разработчика — Глава 22. Журнал регистрации

> Источник: документация «1С:Предприятие 8.3.27», «Руководство разработчика», глава 22 (`https://its.1c.ru/db/v8327doc/content/67/hdoc`, нужен вход по подписке). Прочитана полностью 11.10.2026.
> Глава описывает программную работу с журналом. Интерактивная работа и настройка — в «Руководстве администратора» (`adm-gl06-administrirovanie-ib-p1.md` и следующие части).
> Пересказ своими словами; имена методов, событий и свойств приведены точно.

## 22.1. Общая информация

- Журнал регистрации фиксирует действия пользователей: изменение данных, доступ и отказ в доступе, регламентные операции, вход и выход.
- Журнал **не хранится в базе данных** и **не переносится** при выгрузке и загрузке информационной базы.

## 22.2. Управление детализацией

- Методы `ПолучитьИспользованиеЖурналаРегистрации()` и `УстановитьИспользованиеЖурналаРегистрации()`; в качестве параметра — массив уровней.
- Уровни — перечисление `УровеньЖурналаРегистрации`: `Ошибка`, `Предупреждение`, `Информация`, `Примечание`.

## 22.3. Запись событий

- Метод `ЗаписьЖурналаРегистрации()`. Системные события им записать нельзя.
- Имена пользовательских событий — фиксированные строки без переменных данных; точка в имени образует группу (`Подготовка.Шаг 1`). Рекомендуется не более **1000 уникальных имён** — иначе работа с журналом замедляется.
- Подробности события следует помещать в параметр `Комментарий`.

## 22.4. Управление регистрацией событий

- Включить или выключить регистрацию события: `ПолучитьИспользованиеСобытияЖурналаРегистрации()`, `УстановитьИспользованиеСобытияЖурналаРегистрации()` и объект `ИспользованиеСобытияЖурналаРегистрации` (свойство `Использование`). Пример события: «Ошибка выполнения» — `_$PerformError$_`.
- События транзакций `_$Transaction$_.Begin`, `_$Transaction$_.Commit`, `_$Transaction$_.Rollback` этим методом отключить нельзя.
- Два события имеют расширенную настройку: «Доступ» (`_$Access$_.Access`) и «Отказ в доступе» (`_$Access$_.AccessDenied`). Менять их настройку следует в **монопольном режиме**; изменение гарантированно действует только после перезапуска всех активных сеансов базы.

### 22.4.2. Событие «Доступ»

- Настройка — объект `ОписаниеИспользованияСобытияДоступЖурналаРегистрации`: `Объект` (имя объекта метаданных), `ПоляДоступа` (чтение каких полей регистрировать), `ПоляРегистрации` (значения каких полей записывать в журнал).
- Событие возникает только при **успешном** чтении полей доступа — при любом обращении из сеанса пользователя, включая серверный код.
- Если поля доступа не заданы — событие не регистрируется; заданы без полей регистрации — регистрируется без детализации.
- В поле регистрации можно указать массив альтернатив: в журнал попадёт то поле, которое участвовало в запросе (при нескольких — с меньшим индексом).

### 22.4.3. Событие «Отказ в доступе»

- Настройка — объект `ОписаниеИспользованияСобытияОтказВДоступеЖурналаРегистрации` (`Объект`, `ПоляРегистрации`).
- Возникает при отказе в праве на объект целиком (в поле `Данные` — структура со свойством `Право`) и при нарушении ограничений доступа к данным (в `Данные` — свойства `Действие` и `Данные`).
- Значения полей регистрации записываются только для операции чтения; для изменения, удаления и добавления событие пишется без данных.

## 22.5. События аудита прав доступа

> Лицензия: доступно только для лицензии КОРП.

- События: `_$InfoBase$_.RoleUpdate` (изменение роли), `_$User$_.PermissionChange` (изменение прав пользователей вследствие изменения ролей), `_$InfoBase$_.AdministrationParametersChange` (изменение параметров базы в кластере), `_$InfoBase$_.SecurityProfileChange` (изменение профиля безопасности, назначенного базе).
- Включение:
  - клиент-серверный вариант — флажок «Разрешать запись событий аудита прав доступа» в свойствах кластера либо свойство `АдминистрированиеКластер.РазрешитьЗаписьСобытийАудитаПравДоступа`;
  - файловый вариант — параметр `EnableAccessRightAuditEventsWrite` файла `conf.cfg` в каталоге информационной базы.
- Подготовка данных этих событий занимает заметное время — без необходимости не включать.
- `RoleUpdate` записывается для каждой изменённой роли при обновлении конфигурации базы данных; в данных — структура с ключами `Права` (`ДоступВключен`, `ДоступВыключен`), `Ограничения` (`Добавлены`, `Изменены`, `Удалены`), `ШаблоныОграничений`. Прежнее содержимое изменённых ограничений не сохраняется.
- `PermissionChange` содержит `Пользователи`, `РазделениеДанных`, `ПрофильБезопасности` и те же `Права`, `Ограничения`, `ШаблоныОграничений`.
- `SecurityProfileChange` и `AdministrationParametersChange` записываются отложенно, системными фоновыми заданиями `InfoBaseSecurityProfileChange` и `InfoBaseAdministrationParametersChange`. В данных — имя администратора кластера и новые значения свойств (ключи совпадают со свойствами объектов `АдминистрированиеПрофильБезопасности` и `АдминистрированиеИнформационнаяБаза`).

## 22.6. Получение записей журнала

- Метод `ВыгрузитьЖурналРегистрации()`. С параметром `ИмяВходногоФайла` можно читать журнал **другой** информационной базы, если его файлы доступны локально.
- Чтение журнала может быть долгим, поэтому:
  1. в клиент-серверном варианте одновременно обслуживается **не более 4 запросов** к журналу на одну информационную базу и не более 1 на область данных; в файловом варианте ограничений нет;
  2. по умолчанию журнал разбит по **неделям**; период разбиения рекомендуется подбирать так, чтобы один файл `.lgp` не превышал **100 Мбайт**;
  3. отбор работает быстро только по индексируемым полям: `Дата`, `Важность`, `Пользователь`, `Компьютер`, `ИмяПриложения`, `Событие`, `Данные` (только ссылочного типа), `Метаданные`, `РазделениеДанныхСеанса`.
- Колонка `ПредставлениеДанных` показывается только тем, у кого есть право «Администрирование» или подтверждённое право на просмотр объекта; иначе она пуста.
- Параметр `Фильтр`: одна структура — условия объединяются по «И»; массив структур — по «ИЛИ». Значением элемента может быть одиночное значение, массив (достаточно совпадения с одним элементом) или структура (должны совпасть все элементы). По полю `Данные` можно отбирать строкой, числом, датой, ссылкой, а для событий «Доступ», «Отказ в доступе», «Аутентификация», «Ошибка аутентификации», добавления, изменения и удаления пользователя — структурой.

## 22.7. Дополнительные методы

- `ПолучитьЗначенияОтбораЖурналаРегистрации()` — какие значения реально есть в журнале для отборов `Пользователь`, `Компьютер`, `ИмяПриложения`, `Событие`, `Метаданные`, `РабочийСервер`, `ОсновнойIPПорт`, `ВспомогательныйIPПорт`.
- `ПредставлениеСобытияЖурналаРегистрации()` — представление события на языке интерфейса.
- `СкопироватьЖурналРегистрации()` — копирование фрагмента журнала с фильтром.
- `ПолучитьПериодРазделенияХраненияДанныхЖурналаРегистрации()` и `УстановитьПериодРазделенияХраненияДанныхЖурналаРегистрации()` (перечисление `ПериодРазделенияХраненияДанныхЖурналаРегистрации`) — период разбиения; только для журнала последовательного формата (`.lgf`).
- `ПолучитьПериодЖурналаРегистрации()` — за какой интервал журнал хранит данные.
- `СократитьЖурналРегистрации()` — сокращение журнала; работает для обоих форматов.
