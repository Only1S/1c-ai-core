## 3.1. Установка сервера «1С:Предприятия»

## 3.1.1. Общая информация

- «1С:Предприятие» — это набор универсальных программных модулей (платформа) плюс одна или несколько конфигураций. Модули платформы работают с любой конфигурацией в пределах лицензионного соглашения.
- Вместе с платформой ставится драйвер защиты от несанкционированного использования.
- Программа установки умеет:
  - ставить на один компьютер несколько версий платформы одновременно;
  - выбирать состав устанавливаемых компонентов;
  - выбирать вариант установки сервера.

## 3.1.2. Варианты установки

- Кластер серверов ставится программой установки, своей для каждого семейства ОС: Linux и Windows.
- **Под macOS кластер серверов не работает.**
- Windows: специальная программа установки, режимы «для компьютера» и «для пользователя» (зависит от прав пользователя и параметров установки) — подробности в 3.1.4.
- Linux: поддерживается несколько процессорных архитектур и два способа установки.

| Способ | Пакетный менеджер ОС | Графический интерфейс | Как задаётся состав компонентов | Архитектуры |
|---|---|---|---|---|
| Программа установки | не используется | есть; возможен запуск из командной строки (пакетная установка) | в GUI — флажками; в пакетном режиме — параметрами командной строки | только x86 / x86-64 |
| Пакетный менеджер | используется штатный менеджер ОС | нет | набором устанавливаемых пакетов | все поддерживаемые архитектуры |

Вариант с пакетным менеджером документация называет более привычным для администраторов Linux.

Перед установкой рекомендуется убедиться, что:
- на компьютере нет вирусов;
- диск не содержит ошибок;
- свободного места достаточно.

Примечание источника: могут понадобиться дистрибутивные носители установленной ОС и права локального или сетевого администратора.

## 3.1.3. Установка в ОС Linux

## 3.1.3.1. Правила именования файлов дистрибутива

**Способы установки несовместимы между собой.** Что поставлено пакетным менеджером — удаляется им же. Что поставлено программой установки — удаляется её собственным инструментом удаления, который лежит в каталоге конкретной версии.

### Имена файлов при использовании программы установки

- Применима только на Linux с процессором x86 / x86-64.
- Сделана на основе VMware InstallBuilder.
- Доступная программа установки: «1С:Предприятие 8» — ставит любой компонент системы; есть 32- и 64-разрядный варианты.
- Поставляется в zip-архиве. Имя архива и имя программы совпадают с точностью до расширения.

Шаблон имени:

```
setup-full-A.B.C.D-arch.ext
```

| Часть имени | Значение |
|---|---|
| `A.B.C.D` | полный номер версии платформы, для которой предназначена программа установки |
| `arch` | `i386` — архитектура x86; `x86_64` — архитектура x86-64 |
| `ext` | `zip` — архив с программой установки и сопутствующими файлами; `run` — сама программа установки |

Пример: `setup-full-8.3.24.100-x86_64.run` — программа установки 64-разрядной версии 8.3.24.100, позволяющая поставить все компоненты.

- **Кластер серверов можно установить только программой установки в полном варианте** (`setup-full-…`). О прочих программах установки для Linux документация отсылает в другое место (⚠ в источнике неясно — ссылка «см. здесь» без адреса).

**Файл `installAsRoot`** (лежит в том же zip-архиве) — помощник для неподготовленного пользователя. Что он делает:
1. Проверяет, есть ли у текущего пользователя права суперпользователя (root).
2. Если прав нет — запрашивает пароль суперпользователя в собственном диалоге.
3. При верном пароле запускает программу установки от имени root в интерактивном (графическом) режиме.

Эквивалент для подготовленного пользователя:

```
sudo ./setup-*.run
```

Здесь `*` — остальная часть имени программы установки. Если в каталоге несколько run-файлов, `installAsRoot` запустит тот, чьё имя окажется первым при поиске по маске `setup-*.run`.

### Имена файлов при использовании пакетного менеджера

Дистрибутив поставляется набором пакетов; одни и те же пакеты служат и для клиентских приложений, и для кластера серверов.

Шаблон имени:

```
1c-enterprise-<версия1>-<компонента>_<версия2>.<arch>.<расширение>
```

**`<компонента>`:**

| Компонента | Содержимое |
|---|---|
| `client` | клиентские приложения: толстый клиент и тонкий клиент |
| `thin-client` | только тонкий клиент; работа с файловым вариантом информационной базы не поддерживается |
| `common` | общие компоненты «1С:Предприятия» |
| `server` | компоненты сервера «1С:Предприятия» и утилита контроля целостности (в источнике ссылка «см. стр. 674») |
| `ws` | адаптер для публикации веб-клиента и Интернет-сервисов на веб-сервере Apache HTTP Server (поддерживаемых версий) |
| `crs` | сервер хранилища конфигураций |

Суффикс **`-nls`** в имени компоненты означает пакет дополнительных национальных ресурсов (все языки, кроме русского и английского) для соответствующего основного пакета. Пример: сервер состоит из двух файлов — `server` (сам сервер + русские и английские ресурсы) и `server-nls` (остальные языки).

**`<версия1>` и `<версия2>`** — обе содержат полный номер версии, но с разными разделителями:

| Поле | Формат | Пример для 8.3.22.100 |
|---|---|---|
| `<версия1>` | все четыре элемента через точку | `8.3.22.100` |
| `<версия2>` | первые три элемента через точку, четвёртый — через дефис | `8.3.22-100` |

**`<arch>`:**

| Значение | Архитектура процессора | Формат пакета |
|---|---|---|
| `aarch64` | ARM64 | RPM |
| `amd64` | x86-64 | DEB |
| `arm64` | ARM64 | DEB |
| `e2k` | E2K | RPM |
| `e2k-8c` | E2K | DEB |
| `i386` | x86 | (формат в источнике не уточнён) |
| `x86_64` | x86-64 | RPM |

⚠ в источнике неясно: в значении `e2k-8c` последняя буква набрана кириллической «с».

**`<расширение>`:** `rpm` — RPM-пакеты; `deb` — DEB-пакеты.

Дальше в документации пакеты называются просто по имени компоненты («пакет common», «пакет server»). Пример полного имени пакета `common` (DEB, версия 8.3.22.100, ARM64):

```
1c-enterprise-8.3.22.100-common_8.3.22-100.arm64.deb
```

(⚠ в источнике в этом примере буква «с» в начале имени, `1c-`, набрана кириллицей — опечатка; в шаблоне имени в источнике стоит латиница.)

## 3.1.3.2. Установка с использованием программы установки

## 3.1.3.2.1. Описание программы установки

### Общая информация

- Установка начинается с запуска файла `*.run`.
- Перед запуском нужно убедиться, что у файла есть право на выполнение для текущего пользователя (для группы и остальных — по желанию). Выдать право можно командой `chmod` или через свойства файла в графической оболочке; для этого могут потребоваться права root.
- Режимы запуска: интерактивный (описан здесь) и пакетный (см. 3.1.3.2.2).
- Программа установки — пошаговый помощник; переход между страницами кнопкой «Далее >». Документация обещает отмечать страницы, которые пропускаются в режиме установки «для пользователя».
- Первым делом спрашивается язык (рис. 17 «Выбор языка установки»): на нём строится интерфейс программы установки, и этот же язык выбирается для установки соответствующего интерфейса платформы. В списке — только языки, на которых реализован пользовательский интерфейс приложений «1С:Предприятия».
- В ходе установки программа может показать список пакетов ОС, необходимых для корректной работы платформы и не найденных на компьютере. Их нужно поставить самостоятельно штатным пакетным менеджером ОС (нужны права root).
- Примеры в документации даны для полного 64-разрядного дистрибутива.

### Приветствие

Стартовое окно помощника (рис. 18).

### Выбор компонентов

На странице (рис. 19) выбираются устанавливаемые компоненты (флажок перед названием) и каталог установки. Типовые наборы компонентов — в 3.1.5.

| Компонент | Назначение |
|---|---|
| 1С:Предприятие | основные компоненты платформы, включая работу с файловым вариантом информационной базы |
| 1С:Предприятие — тонкий клиент | тонкий клиент только для клиент-серверного варианта |
| 1С:Предприятие — тонкий клиент, файловый вариант | тонкий клиент, включая компоненты для файлового варианта информационной базы |
| Сервер 1С:Предприятия 8 | компоненты сервера, включая сервер администрирования и утилиту администрирования |
| Модули расширения веб-сервера | модули расширения веб-серверов для работы веб-клиента и Web-сервисов |
| Администрирование сервера 1С:Предприятия | сервер администрирования кластера серверов |
| Интерфейсы на разных языках | пользовательские интерфейсы на различных языках; английский ставится всегда, отменить его нельзя |
| Сервер хранилища конфигураций 1С:Предприятия | компоненты сервера хранилища конфигураций |
| Дополнительные функции администрирования | утилита административной консоли |
| Дистрибутивы тонких клиентов | установка дистрибутивов клиентских приложений (условия доступности — ниже) |
| Liberica JRE | Java Runtime Environment — минимальная виртуальная машина для исполнения Java-приложений, без компилятора и средств разработки; нужна, например, оптимизированному механизму обновления конфигурации базы данных (v2) и утилите лицензирования |
| Контроль целостности | утилита контроля целостности данных |

Компонент «Дистрибутивы тонких клиентов» становится доступным, только если одновременно:
- для установки выбран компонент «Модули расширения веб-сервера»;
- в каталоге с установочными файлами платформы лежит файл вида `win-mac-clients-distr-A.B.C.D.*.run` или `all-clients-distr-A.B.C.D.*.run`.

### Начало установки

После «Далее >» (рис. 20) выполняется:
- создание каталогов;
- копирование файлов выбранных компонентов;
- создание конфигурационных файлов;
- регистрация программных компонентов системы;
- создание ярлыков запуска приложений «1С:Предприятия» в списке программ.

Ход установки отображается индикатором с пояснениями.

### Завершающие действия

Программа сообщает о завершении (рис. 21); работа заканчивается кнопкой «Завершить». Дополнительно программа установки выполняет две попытки:

1. Поставить компоненты, необходимые для работы платформы, если их нет на компьютере или установлены версии, не отвечающие системным требованиям платформы.
2. Поставить TrueType-шрифты из набора Microsoft Core Fonts for Web. Порядок:
   - ищется уже установленный пакет со шрифтами;
   - если не найден — попытка установки из официального репозитория ОС;
   - если и там нет — попытка скачать с одного из зеркал:

```
http://dfn.dl.sourceforge.net/sourceforge/corefonts/
http://downloads.sourceforge.net/corefonts/
http://heanet.dl.sourceforge.net/sourceforge/corefonts/
http://internode.dl.sourceforge.net/sourceforge/corefonts/
http://jaist.dl.sourceforge.net/sourceforge/corefonts/
http://kent.dl.sourceforge.net/sourceforge/corefonts/
http://nchc.dl.sourceforge.net/sourceforge/corefonts/
http://switch.dl.sourceforge.net/sourceforge/corefonts/
http://ufpr.dl.sourceforge.net/sourceforge/corefonts/
http://voxel.dl.sourceforge.net/sourceforge/corefonts/
```

- При пакетной установке выполняются те же действия.
- После успешного завершения платформа готова к работе.

⚠ в источнике неясно: последовательность описана противоречиво — сначала сказано, что установка завершена, затем что после нажатия «Завершить» система «начнёт процесс установки» и перед этим выполнит перечисленные попытки. По смыслу это действия, сопровождающие установку.

## 3.1.3.2.2. Пакетная установка

- Программа установки может работать без оконного менеджера, целиком в консоли.
- Документация отдельно отмечает: пакетная установка применяется при обновлении клиентского приложения.

Ключи командной строки:

| Ключ | Назначение |
|---|---|
| `--mode unattended` | включает пакетный (неинтерактивный) режим |
| `--enable-components <список>` | перечень устанавливаемых компонентов; идентификаторы через запятую |

Идентификаторы компонентов для `--enable-components`:

| Идентификатор | Что устанавливается |
|---|---|
| `additional_admin_functions` | утилита административной консоли |
| `client_full` | толстый клиент и возможность работы в конфигураторе |
| `client_thin` | тонкий клиент без возможности работы с файловым вариантом информационной базы |
| `client_thin_fib` | тонкий клиент, работающий с любым вариантом информационной базы |
| `config_storage_server` | сервер хранилища конфигураций |
| `desktop_icons` | ярлыки для различных компонентов системы «1С:Предприятие» |
| `integrity_monitoring` | утилита контроля целостности |
| `liberica_jre` | Java Runtime Environment (JRE) |
| `server` | кластер серверов «1С:Предприятия» |
| `server_admin` | сервер администрирования кластера серверов |
| `ws` | модули расширения веб-сервера |

Идентификаторы языков интерфейса (указываются в том же списке `--enable-components`):

| Код | Язык | Код | Язык | Код | Язык |
|---|---|---|---|---|---|
| `ar` | арабский | `hy` | армянский | `ro` | румынский |
| `az` | азербайджанский | `it` | итальянский | `ru` | русский |
| `bg` | болгарский | `ka` | грузинский | `tk` | туркменский |
| `de` | немецкий | `kk` | казахский | `tr` | турецкий |
| `el` | греческий | `lt` | литовский | `uk` | украинский |
| `es` | испанский | `lv` | латышский | `vi` | вьетнамский |
| `fr` | французский | `pl` | польский | `zh` | китайский |
| `hu` | венгерский | | | | |

Английский интерфейс ставится безусловно, указывать его не нужно (идентификатора для него в таблице нет).

Пример из документации. Задача: кластер серверов + средства администрирования + JRE + работа с веб-сервером; версия 8.3.24.100; языки — русский и английский; 64-разрядная ОС. Нужна программа установки полной версии:

```
setup-full-8.3.24.100-x86_64.run --mode unattended --enable-components server,ws,server_admin,liberica_jre,ru
```

Остальные ключи программы установки в документации 1С не описаны — за ними отсылают к пользовательской документации VMware InstallBuilder.

## 3.1.3.3. Установка с использованием пакетного менеджера

- **Лицензионное ограничение:** использование «1С:Предприятия» на процессорах ARM64 или E2K доступно только с лицензией КОРП.
- Конкретные команды установки пакетов из файлов документация не приводит: пакетных менеджеров много, команды у них разные — нужно смотреть документацию на менеджер своей ОС.

Зависимости между пакетами:

| Пакет | Зависит от | Примечание |
|---|---|---|
| `common` | — | зависимостей нет |
| `server` | `common` | |
| `ws` | `common` | |
| `crs` | `common`, `server`, `ws` | |
| `client` | `server` | |
| `thin-client` | — | другие пакеты «1С:Предприятия» не нужны; **конфликтует с `common`**: ставится либо `thin-client`, либо все остальные пакеты |
| пакеты `*-nls` | свой основной пакет | национальные ресурсы |

Порядок установки — сначала всё, от чего пакет зависит. Пример из документации: для толстого клиента (и конфигуратора) сначала ставятся `common`, `server` и только потом `client`.

## 3.1.4.3. Общая информация

## 3.1.4.3.1. Определение режима установки

Режим определяется по двум источникам:
1. параметр `InstallForUsers` файла `1cestart.cfg` и параметр `ALLUSERS` командной строки программы установки;
2. права пользователя, выполняющего установку.

Итоговое значение параметра:
- нигде не задано (первая установка) → `0`;
- задано только в `1cestart.cfg` → берётся из файла;
- задан `ALLUSERS` в командной строке → берётся из командной строки независимо от файла.

Пользователь считается администратором, если выполняется хотя бы одно: права администратора локального компьютера; членство в группе локальных администраторов; разрешение на установку программ (политика `AlwaysInstallElevated`).

| Значение параметра | Администратор | Обычный пользователь |
|---|---|---|
| `0` — зависит от прав | К | Д или П |
| `1` — «для компьютера» | К | Д или К |
| `2` — «для пользователя» | П | Д или П |
| `3` — «для пользователя» без вопросов | П | П |

К — установка «для компьютера» без выбора; П — «для пользователя» без выбора; Д — показывается диалог выбора режима (рис. 22). Для не-администратора при значениях 0–2: «Д» — при интерактивной установке, второй вариант — во всех остальных случаях. Если выбран режим, требующий пароля администратора, а пользователь его не знает — установка невозможна. Выбор, сделанный в диалоге, запоминается в `1cestart.cfg`.

Каталоги по умолчанию: «для компьютера» — `%PROGRAMFILES%` или `%PROGRAMFILES(x86)%`; «для пользователя» — `%LOCALAPPDATA%\Programs`. Режим «для пользователя» не поддерживается для продукта «1С:Предприятие 8 (x86-64)» (в нём только 64-разрядный кластер серверов). Для установки «для пользователя» в системе уже должен стоять Microsoft Visual C++ Redistributable из состава устанавливаемой версии (`vc_redist.x86.exe` или `vc_redist.x64.exe`); его установка всегда требует прав локального или сетевого администратора.

## 3.1.4.4. Особенности регистрации компонент

## 3.1.5.1.3. Добавление сервера в кластер серверов

## 3.1.5.3. Настройки Дата акселератора

Раздел общий для обеих ОС.

### Лицензионные ограничения

| Уровень лицензии | Число экземпляров (процессов) Дата акселератора в одном кластере |
|---|---|
| ПРОФ | один |
| КОРП | лицензионно не ограничено (более одного — только КОРП) |

### Два варианта развёртывания

1. **Кластер из одного рабочего сервера.** Сервис Дата акселератора по умолчанию запускается на этом сервере. Оперативная память сервера должна быть не меньше суммы: потребление кластера серверов «1С:Предприятия» + требования Дата акселератора. Пример источника: если в обычном режиме кластер занимает 5 Гбайт, то с Дата акселератором минимальное требование к серверу становится 69 Гбайт, рекомендованное — 520 Гбайт.
2. **Кластер из нескольких рабочих серверов.** Можно запустить несколько экземпляров Дата акселератора. Каждый сервер, где он будет работать, должен отвечать системным требованиям Дата акселератора. Размещение по серверам задаётся требованиями назначения функциональности (см. ниже).

Физически установленная память набирается стандартными модулями и должна быть не меньше расчётного значения для выбранного варианта.

### Настройки ОС на каждом рабочем сервере с Дата акселератором

| ОС | Что настроить |
|---|---|
| Linux | изменить стратегию управления памятью: системный параметр `vm.overcommit_memory` установить в `1` |
| Windows | принудительно задать размер файла подкачки: минимум — не меньше объёма установленной оперативной памяти; рекомендуется 512 Гбайт и выше |

Команда для Linux из документации (нужен пароль суперпользователя):

```
sudo sysctl -w vm.overcommit_memory=1
```

Источник приводит только эту команду; о сохранении значения между перезагрузками в этом разделе ничего не сказано.

### Размещение через требования назначения функциональности

Применяется, когда рабочих серверов несколько. Требования условно делятся на два вида:

- **Разрешающие** — разрешают исполнение экземпляра Дата акселератора на рабочем сервере.
- **Запрещающие** — запрещают его размещение на рабочем сервере. Все требования для сервиса Дата акселератора, стоящие в списке после запрещающего, игнорируются. Если запрещающее требование стоит первым среди требований для этого сервиса, считается, что на данном рабочем сервере сервис Дата акселератора не выполняется.

Алгоритмы размещения:

**А. Разрешающих требований не более одного** (от уровня лицензии не зависит):
1. Определяются все рабочие серверы, у которых есть хотя бы одно разрешающее требование для Дата акселератора. Параметры требований при этом игнорируются.
2. Если разрешающих требований нет вовсе — экземпляр может быть запущен на любом рабочем сервере, где нет запрещающих требований.
3. Из полученного списка выбирается произвольный рабочий сервер.
4. На нём запускается экземпляр Дата акселератора.

**Б. Разрешающих требований более одного** (нужна лицензия КОРП):
1. Если в кластере нет ни одного разрешающего требования — размещается один экземпляр по алгоритму А.
2. Если есть хотя бы одно разрешающее требование — формируется список рабочих серверов, для которых настроены разрешающие требования (параметры требований игнорируются).
3. Экземпляр Дата акселератора запускается на каждом сервере из списка.
4. Список серверов, где работает сервис, может измениться после применения новых требований назначения функциональности.

### Примеры требований назначения функциональности

| Назначение | Объект требования | Тип требования | Имя ИБ | Значение дополнительного параметра |
|---|---|---|---|---|
| Разрешающее — задаётся для каждого рабочего сервера, где планируется Дата акселератор | Сервис Дата акселератора | Назначать | не указывается | можно не указывать (в этом примере не учитывается) |
| Дополнительное к разрешающему — если на сервере должен исполняться только Дата акселератор, а прочие сервисы кластера не должны | Любой объект требования | Не назначать | не указывается | не указывается |
| Запрещающее | Сервис Дата акселератора | Не назначать | не указывается | не указывается |

Смежные темы, на которые ссылается раздел: механизм копий базы данных; системные требования Дата акселератора; применение требований назначения функциональности (⚠ ссылки «см. здесь» без адресов).

## 3.1.6. Установка и настройка дополнительного программного обеспечения

## 3.1.6.1. Для ОС Windows

## 3.1.6.1.1. Создание имени службы сервера для Kerberos-аутентификации

Раздел про кластер на Windows; общие понятия (SPN, делегирование) пригодятся и при настройке Kerberos для Linux-сервера, поэтому команды сохранены.

Общие положения:
- Аутентификация Windows включает два протокола: NTLM и Kerberos. Для прозрачной аутентификации (Single Sign-On, SSO) используется Kerberos: он поддерживает делегирование — безопасную передачу данных авторизации другим службам для действий от имени клиента.
- Если веб-сервер с опубликованной информационной базой и кластер серверов стоят на разных компьютерах **или** кластер состоит из нескольких серверов — аутентификация Windows возможна только по Kerberos.
- SPN (Service Principal Name, имя участника службы, «имя службы сервера») — уникальный идентификатор экземпляра службы; связывает экземпляр службы с учётной записью, под которой служба работает.
- Создание SPN **рекомендуется** для корректной работы Kerberos-аутентификации и **обязательно** для ограниченного делегирования Kerberos. SPN привязывается к доменной учётной записи, от имени которой запущена служба сервера «1С:Предприятия».
- SPN нужно задать для каждого рабочего сервера кластера.
- Самый распространённый формат: `<класс сервиса>/<имя хоста>` (host-based services).
- Общеупотребимые классы (`http`, `host`, `termsrv` и т. п.) использовать для кластера «1С:Предприятия» не рекомендуется. Рекомендуются имена, ассоциирующиеся с 1С, например `srv1c` или `svc1c`.
- Примеры для компьютера `myserver.mydomain`: `srv1c/myserver.mydomain` или `svc1c/myserver.mydomain`.

Порядок действий:

1. Зарегистрировать SPN на контроллере домена командой `setspn`:

```
setspn -S srv1c/myserver.mydomain mydomain\svc-1c
```

   - `srv1c/myserver.mydomain` — имя службы сервера;
   - `mydomain\svc-1c` — доменная учётная запись, от имени которой работает служба кластера серверов.

   Просмотр SPN, зарегистрированных для учётной записи (выполняется на контроллере домена):

```
setspn -L mydomain\svc-1c
```

2. Указать значение свойства **«Имя службы (SPN) сервера 1С:Предприятия»** у рабочего сервера (в примере компьютер `myserver`, SPN — `srv1c/myserver.mydomain`). Если служба кластера работает под локальной системной учётной записью (Local System), можно использовать уже зарегистрированное имя вида `HOST/имя_сервера`, но это не рекомендуется.
3. На контроллере домена в свойствах компьютера, где работает веб-сервер, или в свойствах учётной записи, от имени которой работает веб-сервер, разрешить полное или ограниченное делегирование для SPN `srv1c/myserver.mydomain`.

Ссылки раздела: описание SPN у Microsoft — `https://docs.microsoft.com/windows/win32/ad/service-principal-names`; свойства рабочего сервера (⚠ «см. здесь» без адреса).

## 3.1.6.2. Для ОС Linux

## 3.1.6.2.1. Настройка Kerberos-аутентификации

Описывается настройка Kerberos-аутентификации сервера «1С:Предприятия» на примере базовой системы из трёх компьютеров: контроллер домена, центральный сервер кластера, рабочая станция. **В эту часть главы попали только описание стенда и настройка контроллера домена; продолжение — в части 2.**

### Описание базовой системы

| Роль | Параметры в примере |
|---|---|
| Контроллер домена Active Directory | hostname `main`; IP `192.168.29.150`; имя домена `krb.local` |
| Центральный сервер кластера «1С:Предприятия» | ОС Fedora 7; hostname `srv1c`; IP `192.168.29.151`; установлена реализация Kerberos от MIT (пакет `krb5-workstation`) |
| Рабочая станция | параметры не приводятся |

### Настройка контроллера домена

Исходное условие: контроллер домена Active Directory уже настроен и работает.

**Шаг 1. DNS.** Все Linux-компьютеры регистрируются в DNS-сервере вручную. Windows-компьютеры регистрируются автоматически при включении в домен. В примере: вручную регистрируется центральный сервер кластера (на нём Linux-версия сервера), а рабочая станция включается в домен и регистрируется сама.

**Шаг 2. Учётная запись в домене.** Создаётся пользователь домена, с которым будут ассоциироваться запросы авторизации к серверу «1С:Предприятия». В примере — пользователь `usr1cv8` с паролем `pass1cv8`.
- В свойствах учётной записи флажок **Use DES encryption types with this account** нужно снять.
- Исключение: если используемая реализация Kerberos не поддерживает алгоритм шифрования RC4-HMAC — флажок обязательно установить.

**Шаг 3. Файл с секретным ключом (keytab).** Для пользователя домена `usr1cv8` генерируется файл ключа утилитой **`ktpass`** из пакета Windows Support Tools (подкаталог `SUPPORT` установочного диска Microsoft Windows).

Обычный вариант:

```
C:\>ktpass -princ usr1cv8/srv1c.krb.local@KRB.LOCAL -mapuser usr1cv8 -pass pass1cv8 -out usr1cv8.keytab
```

Если алгоритм RC4-HMAC не поддерживается:

```
C:\>ktpass -crypto DES-CBC-CRC -princ usr1cv8/srv1c.krb.local@KRB.LOCAL -mapuser usr1cv8 -pass pass1cv8 -out usr1cv8.keytab
```

Параметры `ktpass`, использованные в примере (источник прямо поясняет только `-pass`, `-out` и требование к регистру в `-princ`; остальное — по смыслу примера и примечаний):

| Параметр | Значение в примере | Смысл |
|---|---|---|
| `-princ` | `usr1cv8/srv1c.krb.local@KRB.LOCAL` | имя службы сервера; до `@` — `usr1cv8/srv1c.krb.local`, где первая часть совпадает с именем пользователя, от имени которого работает сервер «1С:Предприятия», вторая — полное имя компьютера с сервером |
| `-mapuser` | `usr1cv8` | пользователь домена, с которым ассоциируется имя службы |
| `-pass` | `pass1cv8` | пароль учётной записи пользователя домена |
| `-out` | `usr1cv8.keytab` | имя создаваемого файла с ключом |
| `-crypto` | `DES-CBC-CRC` | добавляется, только если алгоритм RC4-HMAC не поддерживается |

Результат:
- в текущем каталоге (в примере — корень диска `C:`) создаётся файл `usr1cv8.keytab`;
- с пользователем `usr1cv8` ассоциируется имя службы сервера `usr1cv8/srv1c.krb.local`;
- это имя службы используется при настройке ограниченного делегирования в домене Windows.

Замечания источника:
- **Имя пользователя ОС в SPN.** Если сервер «1С:Предприятия» версии 8.3 работает от имени пользователя `usr1cv82`, имя службы сервера должно быть `usr1cv82/srv1c.krb.local`. Имя доменного пользователя при этом может остаться прежним (`usr1cv8` в примере).
- **Регистр.** При генерации ключа полное имя компьютера с сервером «1С:Предприятия» в имени службы (параметр `-princ`) указывается в нижнем регистре; иначе работа аутентификации не гарантируется. (⚠ в источнике в этом месте параметр набран как `-prinс` с кириллической «с» — опечатка.)
- **Имя файла ключа.** Если кластер серверов версии 8.3 работает от имени другого пользователя, например `usr1cv82`, файл ключа следует называть `usr1cv82.keytab`.

На этом текст части 1 обрывается; дальнейшие шаги (настройка центрального сервера кластера на Linux и рабочей станции) — в части 2 главы.

## Что важно администратору Linux

1. **Два способа установки несовместимы.** Поставили пакетным менеджером — удалять тем же менеджером; поставили `.run`-программой — удалять её инструментом из каталога версии. Смешивать нельзя.
2. **Имена пакетов.** Шаблон `1c-enterprise-<A.B.C.D>-<компонента>_<A.B.C-D>.<arch>.<deb|rpm>`. Для DEB-систем на x86-64 (случай Ubuntu) суффикс архитектуры — `amd64`; `x86_64` — это RPM. Русские и английские ресурсы лежат в основном пакете, остальные языки — в пакетах `*-nls`.
3. **Минимум для рабочего сервера:** `common` → `server`; `ws` добавляется, только если на этом же компьютере будет веб-сервер с публикацией базы. Зависимости: `server` и `ws` требуют `common`; `crs` требует `common`, `server`, `ws`; `client` требует `server`.
4. **`thin-client` конфликтует с `common`** — на одном компьютере ставится либо `thin-client`, либо остальные пакеты; вместе с серверными пакетами (они зависят от `common`) он не уживётся.
5. **Программа установки `.run`** существует только для x86 / x86-64; кластер серверов ставится только её полным вариантом (`setup-full-A.B.C.D-<arch>.run`). Автоматическая установка: `--mode unattended --enable-components server,ws,server_admin,liberica_jre,ru`. Русский язык нужно указывать явно (`ru`), английский ставится всегда.
6. **ARM64 и E2K** — только через пакетный менеджер и только с лицензией КОРП.
7. **Установка выполняется от root.** При установке создаётся пользователь ОС `usr1cv8`, под которым работают серверные процессы. **Автозапуск сервера сам не настраивается** — это отдельный ручной шаг.
8. **Шрифты.** Программа установки пытается поставить Microsoft Core Fonts for Web: сначала из репозитория ОС, затем с зеркал sourceforge по HTTP. Это стоит учитывать на сервере без доступа в интернет. Также она может выдать список недостающих пакетов ОС — их ставят вручную пакетным менеджером.
9. **Консоль кластера (графическая) работает только в Windows.** На Linux кластером управляют через сервер администрирования и утилиту администрирования (компонент «Администрирование сервера 1С:Предприятия» / идентификатор `server_admin`).
10. **Добавление рабочего сервера в кластер:** поставить сервер на новом узле, добавить его в существующий кластер, при необходимости задать требования назначения функциональности, затем желательно удалить на новом узле регистрацию «своего» главного сервера кластера.
11. **Публикация веб-клиента** — утилитой `webinst`; для неё нужен пакет `ws` (адаптер для Apache HTTP Server).
12. **Дата акселератор на Linux:** обязателен `vm.overcommit_memory=1` (`sudo sysctl -w vm.overcommit_memory=1`); память сервера = память кластера + требования Дата акселератора (в примере источника 5 Гбайт кластера дают минимум 69 Гбайт, рекомендовано 520 Гбайт). При лицензии ПРОФ — один экземпляр на кластер, несколько — только КОРП. Размещение по серверам — требованиями назначения функциональности с объектом «Сервис Дата акселератора».
13. **Kerberos для Linux-сервера:** Linux-узлы регистрируются в DNS домена вручную; на контроллере домена создаётся учётная запись и keytab утилитой `ktpass`. Имя службы в `-princ` строится по образцу примера: `<пользователь, от имени которого работает сервер 1С>/<полное имя компьютера в нижнем регистре>@<имя домена заглавными>` (в примере `usr1cv8/srv1c.krb.local@KRB.LOCAL`), имя файла ключа — `<тот же пользователь>.keytab`. Флажок «Use DES encryption types with this account» снимается, если реализация Kerberos поддерживает RC4-HMAC; иначе флажок ставится и к `ktpass` добавляется `-crypto DES-CBC-CRC`.
14. **Без Kerberos не обойтись**, если веб-сервер с публикацией и кластер серверов находятся на разных компьютерах или кластер состоит из нескольких серверов: по разделу 3.1.6.1.1 аутентификация Windows в таких схемах возможна только по протоколу Kerberos (не NTLM).
