## 4.7. Работа конфигуратора в режиме агента

### 4.7.1. Общая информация

**Суть.** Режим агента — особый вариант пакетного запуска конфигуратора, при котором конфигуратор сам выступает SSH- и SFTP-сервером и исполняет команды, приходящие по этим протоколам.

**Ограничения и свойства:**

- Один агент в каждый момент работает только с одной информационной базой (ИБ). Для параллельной работы с несколькими ИБ запускают несколько конфигураторов в режиме агента.
- К одному агенту может быть подключён **один** SSH-клиент и **несколько** SFTP-клиентов.
- Все команды интерактивные и синхронные; узнать промежуточное состояние выполняемой команды нельзя (исключение — оповещение о прогрессе, см. 4.7.9).
- Тексты сообщений по итогам команд те же, что у одноимённых операций пакетного режима конфигуратора.

**Порядок работы:**

1. Запустить конфигуратор в режиме агента.
2. Подключиться к агенту с удалённого компьютера.
3. Файлы передавать SFTP-клиентом.
4. Команды отдавать и результат получать SSH-клиентом.

**Командная строка запуска:**

```
1cv8 DESIGNER <информационная база> /AgentMode [параметры режима агента] [/Visible]
```

| Элемент | Что нужно знать |
|---|---|
| `<информационная база>` | Любой штатный способ: `/IBName`, `/F` или `/S` |
| Имя пользователя и пароль ИБ | В командной строке бессмысленны — игнорируются. Логин и пароль вводятся в ответ на запросы в консоли удалённого доступа (SSH) |
| Пользователь ИБ | Не рекомендуется пользователь, в имени которого есть национальные символы |
| `/AgentMode` | При его наличии конфигуратор игнорирует все параметры, кроме: параметров режима агента, параметров указания ИБ и `/Visible` |
| `/Visible` | Показывает окно, из которого можно остановить агента. Без него завершить режим агента можно только командой из удалённой консоли |
| `[параметры режима агента]` | В этой части главы не перечисляются |

**Вид сеанса после подключения** (пример из документации; строка логина приведена как в источнике):

```
login as: adminadmin
admin@localhost's password:
1C:Enterprise 8.3 1C Designer Shell © 1C LLC 1996-2018
designer>
```

**Формат результата команд:**

- текстовый — по умолчанию;
- JSON-сообщения — сервер всегда отдаёт **массив** сообщений о результате.

Формат переключается командой `options set --output-format=...` (см. 4.7.5.4). Обработка любой команды заканчивается сообщением одного из типов: `success`, `error`, `cancel` или `question`. `help` завершается сообщением `success`, неизвестная команда — `error`.

⚠ в источнике неясно: в 4.7.1 тип назван `cancel`, а в перечне типов раздела 4.7.8 — `canceled`.

### 4.7.2. Список команд

| Команда / группа | Назначение |
|---|---|
| `help` | Справка |
| `common` | Общие команды |
| `options` | Работа с настройками сеанса |
| `config` | Редактирование конфигурации |
| `infobase-tools` | Сервисные операции с информационной базой |

Замечания документации: в разделе вывод команд показан в текстовом виде, JSON-вариант демонстрируется только на `help`; при этом в режиме JSON в этом формате отвечают абсолютно все команды, включая справочные. Примеры раздела — иллюстрации, а не законченные сценарии.

### 4.7.3. Команда help

- `help` без параметров — общая справка по режиму агента.
- Справка по группе команд или по конкретной команде: уточнение пишется после слова `help`, например `help options`.
- `help --version` (короткая форма `-v`) — версия платформы, под которой запущен агент.
- Сокращённое имя режима: `h`.

Общая справка (вывод сокращён и сжат по строкам; описания режимов — в таблице 4.7.2):

```
designer> help
Использование:
  help [options] [arguments]
Общие параметры:
  --version | -v      получение версии утилиты
Режим:
  help (h)
Аргументы:
  MODE                режим, для которого нужна информация о ключах
Поддерживаемые режимы:
  help  common  options  config  infobase-tools
```

Справка по группе `options` (вывод сокращён и сжат по строкам):

```
designer> help options
Использование:
  options [command] [options]
Команды:
  list
  get   --output-format  --show-prompt
  set   --output-format=<text|json>  --show-prompt=<yes|no>
```

Версия платформы в текстовом формате:

```
designer> help --version
8.3.10.2000
```

То же после переключения на JSON (первая команда меняет формат, вторая запрашивает версию):

```
designer> options set --output-format=json
[
{
"type": "success",
"message": ""
}
]
designer> help --version
[
{
"type": "success",
"body": "8.3.10.1772"
}
]
```

### 4.7.4. Команды группы common

Общие операции. Параметров у команд группы нет.

| Команда | Действие |
|---|---|
| `connect-ib` | Подключиться к ИБ, параметры которой заданы при запуске агента |
| `disconnect-ib` | Отключиться от ИБ, к которой ранее подключились через `connect-ib` |
| `shutdown` | Завершить работу конфигуратора в режиме агента |

### 4.7.5. Команды группы options

#### 4.7.5.1. Назначение группы команд

Управление настройками текущей сессии.

#### 4.7.5.2. get

Чтение значений настроек.

| Параметр | Что возвращает |
|---|---|
| `--output-format=<значение>` | Формат вывода результата: `text` — текст; `json` — JSON-сообщения |
| `--show-prompt=<значение>` | Наличие приглашения `designer>`: `yes` — есть; `no` — нет |
| `--notify-progress` | Включено ли отображение прогресса выполнения команды |
| `--notify-progress-interval` | Интервал обновления сведений о прогрессе |

Примечание: в описании команды первые два параметра записаны с `=<значение>`, а в выводе `help options` у `get` они показаны без значения (`--output-format`, `--show-prompt`).

#### 4.7.5.3. list

Показывает перечень настроек и их текущие значения.

#### 4.7.5.4. set

Установка значений настроек.

| Параметр | Значения | Умолч. / примечание |
|---|---|---|
| `--output-format=<значение>` | `text` — текстовый вывод; `json` — JSON-сообщения | текст (см. 4.7.1) |
| `--show-prompt=<значение>` | `yes` — приглашение `designer>` выводится; `no` — не выводится | — |
| `--notify-progress=<значение>` | `yes` — прогресс показывается; `no` — не показывается | `no`. Перечень команд с прогрессом — в 4.7.9 |
| `--notify-progress-interval=<значение>` | Интервал обновления прогресса; задаётся с точностью 0.1 секунды | 1 секунда. Нарушение точности даёт ошибку `CommandLineFormaError` (написание как в источнике) |

| Параметр | Назначение |
|---|---|

#### 4.7.6.3. dump-config-to-files

Выгружает конфигурацию в XML-файлы.

| Параметр | Назначение | Значения / умолч. / примечание |
|---|---|---|
| `--dir=<путь>` | Каталог, куда выгружается конфигурация | **Обязательный** |
| `--extension=<имя расширения>` | Выгрузить указанное расширение | — |
| `--all-extensions` | Выгрузить все расширения конфигурации | — |
| `--format=<значение>` | Формат выгрузки | `hierarchical` — иерархический (умолч.); `plain` — линейный |
| `--update` | Обновить существующую выгрузку: выгружаются только объекты, версии которых отличаются от записанных в `ConfigDumpInfo.xml` | — |
| `--force` | Сделать полную выгрузку, если при обновлении (`--update`) оказалось, что текущая версия формата выгрузки не совпадает с версией из `ConfigDumpInfo.xml` | — |
| `--get-changes=<путь>` | Сформировать файл с изменениями между текущей и указанной выгрузками | — |
| `--config-dump-info-for-changes=<путь>` | Путь к `ConfigDumpInfo.xml`, по которому строится файл изменений между двумя выгрузками | — |
| `--list-file=<файл>` | Выгрузить только объекты метаданных и/или внешние свойства, перечисленные в файле, независимо от того, менялись ли они | — |
| `--server` | Выполнять выгрузку на стороне сервера «1С:Предприятия» — многопоточно и быстрее. Число потоков задаёт `--threads` | Игнорируется при работе с автономным сервером и при работе агента конфигуратора с файловой ИБ |
| `--threads=<количество>` | Число одновременно работающих фоновых заданий серверной выгрузки | Только вместе с `--server`. Умолч. `auto` — платформа определяет число сама по количеству ядер процессора на компьютере с кластером серверов |
| `--archive=<имя файла>` | Выгрузка в zip-архив | Подходит для полной и частичной выгрузки и для выгрузки всех расширений (`--all-extensions`) |
| `--ignore-unresolved-refs` | Не выгружать ссылки на недостижимые объекты (удалённые в одной из прежних версий конфигурации) | — |

#### 4.7.6.7. load-config-from-files

Загружает конфигурацию из XML-файлов.

| Параметр | Назначение | Значения / умолч. / примечание |
|---|---|---|
| `--dir=<путь>` | Каталог, из которого загружается конфигурация | **Обязательный** (по описанию параметра); при этом должен быть указан либо `--dir`, либо `--archive`, одновременно — нельзя |

| `--partial` | Частичная загрузка: загружаются только те элементы описания объекта, которые представлены указанным файлом | Таким файлом может быть: файл описания объекта метаданных (без внешних свойств); файл внешнего свойства (форма и т. п.); файл модуля формы (без файла описания формы) |

#### 4.7.6.13. sign-cfg

Подписывает расширение конфигурации цифровой подписью. После подписи расширение можно применять в базовых версиях конфигураций, подписанных тем же ключом.

| Параметр | Назначение | Значения / когда используется |
|---|---|---|
| `--configuration-type=<тип конфигурации>` | Где находится подписываемое расширение | `extension-configuration` — расширение конфигурации; `extension-db-configuration` — расширение в базе данных; `extension-configuration-repository` — расширение в хранилище расширения конфигурации; `file` — файл расширения |
| `--name=<имя расширения>` | Имя расширения | Для типов `extension-configuration`, `extension-db-configuration`, `extension-configuration-repository` |
| `--version=<версия>` | Версия расширения в хранилище | Для типа `extension-configuration-repository` |
| `--digisign=<имя файла с параметрами лицензирования>` | Параметры лицензирования рабочего места пользователя | — |
| `--file=<путь к cfe-файлу>` | Файл подписываемого расширения | Для типа `file` |
| `--signed-file=<путь к cfe-файлу>` | Путь к результирующему (подписанному) файлу | — |

#### 4.7.6.14. update-db-cfg

Обновляет конфигурацию базы данных.

| Параметр | Назначение | Значения / умолч. / примечание |
|---|---|---|
| `--prompt-confirmation` | Запрашивать у пользователя подтверждение принятия изменений при реструктуризации ИБ | — |
| `--dynamic-enable` | Сначала попытаться обновить динамически; при неудаче запускается фоновое обновление | — |
| `--dynamic-disable` | Запретить динамическое обновление | — |
| `--warnings-as-errors` | Все предупреждения при обновлении считать ошибками | — |
| `--background-start` | Запустить фоновое обновление и завершить текущий сеанс | — |
| `--background-cancel` | Отменить запущенное фоновое обновление | — |
| `--background-finish` | Завершить запущенное фоновое обновление: накладывается монопольная блокировка базы и выполняется финальная фаза | Можно сочетать с `session-terminate` и `session-terminate-message` |
| `--background-resume` | Продолжить ранее приостановленное фоновое обновление | — |
| `--server` | Выполнять обновление на стороне сервера «1С:Предприятия» | — |
| `--extension=<имя расширения>` | Имя расширения | — |
| `--session-terminate=<назначение>` | Завершение активных сеансов, если нужна эксклюзивная блокировка ИБ | `disable` — запрещено (умолч.); `prompt` — спросить пользователя; `force` — принудительно завершить. Работает для основной конфигурации и расширений, для интерактивного и фонового обновления |
| `--session-terminate-message=<сообщение>` | Текст о причине завершения сеанса, показываемый отключаемому клиенту | Для интерактивного и фонового обновления |

**Алгоритм выполнения `update-db-cfg`:**

1. Монопольная блокировка невозможна, а динамическое обновление допустимо (нет `--dynamic-disable`) — пользователю предлагается выбор: отменить операцию, обновить динамически или повторить попытку установить монопольный режим.
2. Выбран повтор и задан `--session-terminate=prompt` — выбор: отмена, ещё один повтор или завершение сеансов, мешающих обновлению.
3. Выбрано завершение сеансов — запрашивается подтверждение (или отказ от операции); после подтверждения сеансы завершаются и обновление выполняется.
4. Монопольная блокировка возможна, реструктуризация не нужна — обычное обновление конфигурации БД.
5. Монопольная блокировка возможна и реструктуризация нужна:
   - определяется список изменённых объектов;
   - список выводится в консоль;
   - при `--prompt-confirmation` пользователю задаётся вопрос о принятии изменений;
   - отрицательный ответ — обновление отменяется с уведомлением;
   - положительный ответ, либо вопрос не требовался, либо `--prompt-confirmation` не задан — обновление идёт штатно.

## 4.8. Агент клиентского приложения (1cecla)

### 4.8.1. Общая информация

Приложение «1С:Предприятие — оповещение и запуск» (далее — агент клиентского приложения):

- получает сообщения от сервера системы взаимодействия и централизованно показывает оповещения, в том числе когда приложение-адресат не запущено;
- накапливает оповещения, позволяет быстро перейти к приложению, для которого пришло сообщение, и управлять показом оповещений;
- если приложение не запущено — запускает его;
- только Windows: заменяет значки информационных баз в системном лотке одним значком агента.

Варианты поставки:

| Вариант | Разрядность |
|---|---|
| Исполняемый файл для Windows | 32 бит |
| Исполняемый файл для Linux | 32 и 64 бит |
| Расширение браузера Google Chrome, Mozilla Firefox | 32 и 64 бит (по разрядности браузера) |
| Расширение Microsoft Internet Explorer | 32 бит |

### 4.8.2. Установка агента

**Где лежит дистрибутив.** При установке «1С:Предприятия» (кроме отдельного дистрибутива тонкого клиента) пакет агента кладётся в каталог `ExtDst` конкретной версии платформы — и в Windows, и в Linux.

**Имя пакета:** `1c-enterprise-client-application-agent-a.b.c.d.arch`

| Часть имени | Значение |
|---|---|
| `a.b.c.d` | Полный номер версии агента в пакете |
| `arch` | Архитектура: Windows — `x86` (32 бит); Linux — `i386` (32 бит) или `x86_64` (64 бит) |
| Расширение | Windows — `.exe`; Linux — `.sh` |

**Способы запуска установки:** вручную запуском пакета, средствами встроенного языка либо из диалога настроек системы взаимодействия в клиентском приложении.

**Каталоги установки:**

| ОС | Каталог |
|---|---|
| Linux | `~/bin/1cecla/ecs_ver_<api-version>` (независимо от разрядности ОС) |
| Windows, 32-разрядная система в 64-разрядной ОС | `%PROGRAMFILES(x86)%\1C\1CE\1cecla\ecs_ver_<api-version>` |
| Windows, остальные случаи | `%PROGRAMFILES%\1C\1CE\1cecla\ecs_ver_<api-version>` |

`<api-version>` — цифра, равная версии протокола взаимодействия с сервером системы взаимодействия. Имя исполняемого файла — `1cecla`.

**Правила версий:**

- На компьютере одновременно может быть установлена только одна версия агента.
- Если при установке платформы найден агент более старой версии, чем поставляемый с ней, то: агент обновляется до актуальной версии; при необходимости обновляется расширение браузера; агент перезапускается, если был запущен до установки платформы.
- При старте клиентского приложения сверяется версия установленного и запущенного агента; если доступна более новая — показывается диалог с гиперссылкой, запускающей обновление.

**Автозапуск:**

- Windows: после установки агент стартует автоматически вместе с системой.
- Linux: автозапуск при старте системы пользователь настраивает **сам**; к моменту запуска агенту нужен работающий графический интерфейс.

### 4.8.3. Программный интерфейс агента

Доступ — через менеджер агента клиентского приложения, свойство глобального контекста `АгентКлиентскогоПриложения`. Возможности:

- установить агент;
- проверить наличие новых версий агента;
- получить/задать представление клиентского приложения в контекстном меню агента;
- подключить/отключить текущее клиентское приложение от агента;
- подключить/отключить обработчик изменения состояния агента.

Детали:

- К запущенному клиентскому приложению агент подключается автоматически при его старте.
- Чтобы агент показывал оповещения и при незапущенном приложении, вызывают `АгентКлиентскогоПриложения.НачатьПодключение()`.
- Представление приложения в списке агента: `АгентКлиентскогоПриложения.ПолучитьНаименованиеПриложения()` / `АгентКлиентскогоПриложения.УстановитьНаименованиеПриложения()`.
- Фактическое состояние подключения узнают через обработчик изменения состояния.

⚠ в источнике неясно: метод, которым подключается этот обработчик, назван `АгентКлиентскогоПриложения.ОтключитьОбработчикИзмененияСостояния()` — по смыслу должен быть метод подключения обработчика; вероятна опечатка в документации.

## 4.9. Автономный сервер (ibsrv)

**Управление.** Автономный сервер настраивается конфигурационным файлом и параметрами командной строки. **Командная строка приоритетнее файла:** если параметр задан в обоих местах, действует значение из командной строки.

**Синтаксис:**

```
ibsrv [--parameter[=value]] [--parameter[=value]]
```

- `parameter` — параметр автономного сервера (см. таблицы ниже);
- `value` — значение, если параметр его требует;
- параметров может быть несколько, разделитель — пробел.

**Справка** (выдаёт тот же перечень, что и таблицы ниже; в документации таблица упорядочена по имени параметра):

```
ibsrv --help
```

Ниже параметры сгруппированы по смыслу (в источнике — единый алфавитный список; состав перенесён полностью, 56 параметров).

Общие для нескольких параметров наборы значений:

- **Флаг** (`<flag>`): `allow`, `yes`, `true` — «да»; `deny`, `no`, `false` — «нет».
- **Адрес** (`<address>`): `localhost` — локальный сетевой интерфейс; `any` — все доступные сетевые интерфейсы; `xxx.xxx.xxx.xxx` — адрес интерфейса IPv4; `xxxx:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx` — адрес интерфейса IPv6.

## 4.10. Утилита администрирования автономного сервера (ibcmd)

### 4.10.1. Общая информация

`ibcmd` — инструмент управления автономным сервером и выполнения административных операций.

**Приоритет настроек:** как и у `ibsrv`, параметр командной строки перекрывает одноимённый параметр конфигурационного файла.

**Синтаксис:**

```
ibcmd mode command [command] [--parameter[=value]] [--parameter[=value]]
```

| Элемент | Смысл |
|---|---|
| `mode` | Режим работы утилиты |
| `command` | Команда режима. Бывают «многословные» команды из нескольких идентификаторов, например `ibcmd infobase config load` |
| `parameter` | Параметр команды (перечни — в таблицах по каждой команде режима) |
| `value` | Значение параметра, если оно требуется |

Параметров может быть несколько, разделитель — пробел.

**Версия и справка:**

```
ibcmd --version
ibcmd --help
```

Особенности оформления в документации: сама утилита печатает справку одним блоком на режим, а в документации параметры разнесены по командам и упорядочены по алфавиту. Обязательные параметры в таблицах документации выделены подчёркиванием (образец: `--param` — обычный параметр, `--req-param` — обязательный).

⚠ в текстовой копии источника подчёркивание не сохраняется, поэтому обязательность параметра по одному оформлению определить нельзя.

### 4.10.2. Общие параметры

`ibcmd` умеет управлять и работающим экземпляром автономного сервера, и сервером в offline-режиме (не запущенным). Параметры подключения делятся на две группы.

#### Группа 1. Подключение к работающему автономному серверу

Применимы ко всем командам `ibcmd`, кроме отдельных команд, для которых это оговаривается в их описании.

| Параметр (синонимы) | Назначение | Примечание |
|---|---|---|
| `--pid=<pid>`, `-p <pid>` | Идентификатор процесса автономного сервера, к которому нужно подключиться | Только если сервер запущен на том же компьютере, что и утилита |
| `--remote=<url>`, `-r <url>` | Сетевой адрес шлюза администрирования автономного сервера | Сервер может находиться на другом компьютере |

Параметры СУБД и базы данных здесь не нужны: работающий сервер уже знает, с какой СУБД и базой он работает, и утилита использует эти сведения.

#### Группа 2. Работа с автономным сервером в offline-режиме

Группа заметно больше: многие команды работают непосредственно с информационной базой, поэтому нужно задать всё необходимое для подключения к базе данных в СУБД.

Параметры подключения и файлы настроек:

| Параметр (синонимы) | Назначение | Значения / умолч. / примечание |
|---|---|---|
| `--config=<path>`, `-c <path>` | Путь к конфигурационному файлу | — |
| `--system=<path>` | Путь к системному конфигурационному файлу | — |
| `--dbms=<kind>` | Тип СУБД, где размещена ИБ | `MSSQLServer` — Microsoft SQL Server; `PostgreSQL` — PostgreSQL; `IBMDB2` — IBM Db2; `OracleDatabase` — Oracle Database. Не указан — файловая база данных |
| `--database-server=<address>`, `--db-server=<address>` | Имя сервера СУБД | — |
| `--database-name=<name>`, `--db-name=<name>` | Имя базы данных | — |
| `--database-user=<name>`, `--db-user=<name>` | Имя пользователя сервера СУБД | — |
| `--database-password=<password>`, `--db-pwd=<password>` | Пароль пользователя сервера СУБД | — |
| `--request-database-password`, `--request-db-pwd`, `-W` | Запросить пароль пользователя СУБД через stdin | — |
| `--database-path=<path>`, `--db-path=<path>` | Каталог файловой базы данных «1С:Предприятие» | Относительный путь — от каталога данных сервера. Умолч.: каталог `db-data` в каталоге данных |
| `--user=<name>`, `-u <name>` | Имя пользователя **информационной базы**, от имени которого выполняется операция | — |
| `--password=<password>`, `-P <password>` | Пароль пользователя информационной базы, от имени которого выполняется операция | — |

| `--temp=<path>`, `-t <path>` | Каталог временных файлов ИБ | `temp` в каталоге данных | отн. |

| `--log-data=<path>` | Каталог данных журнала регистрации | `log-data` в каталоге данных | отн. |
| `--ftext-data=<path>` | Каталог данных полнотекстового поиска | `ftext-data` в каталоге данных | отн. |
| `--ftext2-data=<path>` | Каталог данных полнотекстового поиска версии 2 | `ftext2-data` в каталоге данных | отн. |
| `--openid-data=<path>` | Каталог данных OpenID-аутентификации | `openid-data` в каталоге данных | отн. |

**Соотношение с параметрами `ibsrv`.** Перечень по составу и смыслу повторяет параметры `ibsrv`, но он короче: утилите нужны только параметры доступа к информационной базе, а прочие настройки сервера (например, параметры доступа по HTTP) не требуются. Сверх параметров `ibsrv` здесь есть `--user`/`-u` и `--password`/`-P` (пользователь ИБ).

**Короткие ключи, смысл которых у `ibsrv` и `ibcmd` не совпадает** (сопоставление таблиц 4.9 и 4.10.2):

| Ключ | В `ibsrv` | В `ibcmd` |
|---|---|---|
| `-p` | `--http-port` (порт HTTP) | `--pid` (идентификатор процесса сервера) |
| `-P` | в таблице параметров нет | `--password` (пароль пользователя ИБ) |

**Ограничение offline-режима:** режимы `session` и `lock` утилиты недоступны — у неработающего автономного сервера нет ни сеансов, ни блокировок.

## Что важно администратору Linux

1. **Приоритет настроек.** И у `ibsrv`, и у `ibcmd` значение из командной строки перекрывает значение того же параметра из конфигурационного файла.
2. **Умолчания `ibsrv` в Linux.** Каталог данных — `~/.1cv8/standalone-server`; в нём по умолчанию лежат `db-data`, `temp`, `session-data`, `log-data`, `ftext-data`, `ftext2-data`, `openid-data`, `stt-data`, `users-data`, `binary-storage-data`, `clnt-notif-data` и файл блокировки `lock.pid`.
3. **Порты автономного сервера по умолчанию:** HTTP 8314, прямое соединение 1541 и диапазон 1560:1591, SSH 1543, отладка по HTTP 1550, монитор производительности 1555.
4. **Все адреса по умолчанию — `localhost`** (`--http-address`, `--ssh-address`, `--debug-address`, `--monitor-address`). `localhost` означает только локальный сетевой интерфейс; для обслуживания других интерфейсов задаётся `any` (все доступные интерфейсы) либо конкретный IPv4/IPv6-адрес интерфейса.
5. **PostgreSQL для автономного сервера** задаётся связкой `--dbms=PostgreSQL`, `--db-server`, `--db-name`, `--db-user` и паролем (`--db-pwd` либо `-W` — запрос пароля через stdin). Без `--dbms` сервер работает с файловой базой в каталоге `db-data`. Подключение без имени и пароля (аутентификация ОС) описано только для Microsoft SQL Server.
6. **Режим демона.** `--daemon` применим только в Linux; `--service` — только в Windows.
7. **`--ssh-host-key`:** умолчание в документации записано как `%USERPROFILE%/.ssh/id_rsa`, отдельного значения для Linux нет — см. пометку ⚠ в 4.9 (е).
8. **Обратная логика флага** `--disable-local-speech-to-text`: `allow/yes/true` запрещает распознавание речи, `deny/no/false` (умолчание) — разрешает. У остальных флагов (`--schedule-jobs`, `--distribute-licenses`, `--access-right-audit-events-recording`) `allow` означает «включено»; аудит прав доступа по умолчанию выключен (`deny`), регламентные задания и выдача клиентских лицензий — включены (`allow`).
9. **`ibcmd`: два способа работы.** С запущенным сервером — `--pid=<pid>` (тот же компьютер) или `--remote=<url>` (шлюз администрирования, возможен другой компьютер), параметры СУБД не нужны. С остановленным (offline) — полный набор параметров базы (`--dbms`, `--db-server`, `--db-name`, `--db-user`, `--db-pwd`/`-W`, при необходимости `--data` и каталоги) плюс пользователь ИБ `--user`/`--password`. В offline недоступны режимы `session` и `lock`.
10. **Не путать короткие ключи:** `-p` у `ibsrv` — порт HTTP, у `ibcmd` — PID процесса сервера; `-P` у `ibcmd` — пароль пользователя ИБ.
11. **Конфигуратор в режиме агента** запускается как `1cv8 DESIGNER <ИБ> /AgentMode [...]` и работает как SSH/SFTP-сервер: один агент — одна ИБ, один SSH-клиент и несколько SFTP-клиентов. Учётные данные ИБ в командной строке игнорируются и вводятся в SSH-консоли; пользователей с национальными символами в имени использовать не рекомендуется. Без `/Visible` остановить агента можно только из удалённой консоли (команда `shutdown` группы `common`).
12. **Настройки сеанса агента** задаются командой `options set`: вывод можно переключить на JSON (`--output-format=json`), приглашение `designer>` убрать (`--show-prompt=no`), прогресс долгих операций включить (`--notify-progress=yes`, интервал `--notify-progress-interval` с точностью 0.1 с, умолчание 1 с). В формате JSON результат всегда приходит массивом сообщений с обязательным полем `type`.
13. **`restore-ib` в режиме агента рвёт SSH-соединение** и завершает сеанс с ИБ; агент при этом не перезапускается и ждёт нового подключения — после загрузки dt-файла к агенту нужно подключаться заново.
14. **Обновление конфигурации БД через агента (`update-db-cfg`):** завершение мешающих сеансов по умолчанию запрещено (`--session-terminate=disable`); для принудительного завершения — `force`, для запроса — `prompt`; текст для отключаемых пользователей — `--session-terminate-message`. Серверная выгрузка `dump-config-to-files --server` игнорируется для автономного сервера и для агента, работающего с файловой ИБ.
15. **Агент клиентского приложения `1cecla` в Linux:** пакет `.sh` лежит в каталоге `ExtDst` установленной версии платформы, ставится в `~/bin/1cecla/ecs_ver_<api-version>`, автозапуск нужно настраивать самостоятельно, для работы нужен графический интерфейс. На компьютере допускается только одна версия агента.
