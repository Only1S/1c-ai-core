## 3.31 (окончание). Элемент `<Subsystem>` и примеры файла с перечнем объектов конфигурации

Начало раздела 3.31 находится в предыдущей части (часть 5); точное название раздела в этой части источника не приведено. Здесь — только последний подпункт 3.31.4.1 и примеры 3.31.5. Из примеров видно: корневой элемент `<Objects>`, пространство имён `http://v8.1c.ru/8.3/config/objects`, атрибут `version="1.0"`, дочерние элементы `<Configuration>` и `<Object>` с атрибутами `includeChildObjects` и `fullName`.

### 3.31.4.1. Элемент `<Subsystem>`

Вложенный элемент для `<Object>`, который указывает на подсистему. Задаёт, нужно ли включать в операцию объекты, входящие в состав этой подсистемы. Применим только к `<Object>`, описывающему подсистему. Количество: 0 или 1.

| Атрибут | Обязательность | Тип | Назначение / значения |
|---|---|---|---|
| `includeObjectsFromSubordinateSubsystems` | обязательный | Булево | Если указан, в список обрабатываемых объектов попадают все объекты (с подчинёнными), входящие в состав подсистемы родительского элемента. |
| `configuration` | необязательный | Строка | Из какой конфигурации брать состав подсистемы при настройке сравнения конфигураций: `Main` — из основной (по умолчанию); `Second` — из второй. |

### 3.31.5. Примеры

Все объекты конфигурации:

```xml
<Objects xmlns="http://v8.1c.ru/8.3/config/objects" version="1.0">
<Configuration includeChildObjects = "true"/>
</Objects>
```

Справочник «Товары» вместе с подчинёнными объектами:

```xml
<Objects xmlns="http://v8.1c.ru/8.3/config/objects" version="1.0">
<Object fullName = "Справочник.Товары" includeChildObjects= "true" />
</Objects>
```

Подсистема «Администрирование» без подчинённых подсистем плюс объекты (с подчинёнными), входящие только в саму эту подсистему:

```xml
<Objects xmlns="http://v8.1c.ru/8.3/config/objects" version="1.0">
<Object fullName = "Подсистема.Администрирование" includeChildObjects= "false">
<Subsystem includeObjectsFromSubordinateSubsystems = "true"/>
</Object>
</Objects>
```

Корневой объект конфигурации без подчинённых плюс подсистема «ТоварныйУчет» с подчинёнными подсистемами и объектами, входящими в неё и в подчинённые подсистемы:

```xml
<Objects xmlns="http://v8.1c.ru/8.3/config/objects" version="1.0">
<Configuration includeChildObjects = "false"/>
<Object fullName = "Подсистема.ТоварныйУчет" includeChildObjects= "true">
<Subsystem includeObjectsFromSubordinateSubsystems = "true"/>
</Object>
</Objects>
```

Что видно из двух последних примеров: при `includeChildObjects="false"` у `<Object>` подсистемы подчинённые подсистемы не берутся, при `"true"` — берутся; вложенный `<Subsystem includeObjectsFromSubordinateSubsystems="true"/>` в обоих случаях добавляет объекты, входящие в состав выбранных подсистем (в первом случае — только самой подсистемы, во втором — её и подчинённых).

## 3.32. Файл настроек объединения

### 3.32.1. Общая информация

Файл появляется при сохранении настроек объединения конфигураций. В него попадают:

- версия файла настроек и минимальная версия платформы, поддерживающая эту версию настроек;
- описания конфигураций: имя, версия, поставщик;
- параметры объединения: отношение основной и второй конфигурации, языки сравнения, признак разрешения удаления объектов основной конфигурации, режим копирования объектов;
- признаки участия объекта/свойства в объединении;
- установленные порядки подчинённых объектов;
- настройки объединения свойств, в том числе модулей, форм, макетов табличных документов.

Записываются только те настройки, которые отличаются от значений по умолчанию.

Формат — XML. Пространство имён: `http://v8.1c.ru/8.3/config/merge/settings`.

Каркас файла:

```xml
<Settings…>
<MainConfiguration>
<Name/>
<Version/>
<Vendor/>
</MainConfiguration>
<SecondConfiguration>
<Name/>
<Version/>
<Vendor/>
</SecondConfiguration >
<OldVendorConfiguration>
<Name/>
<Version/>
<Vendor/>
</OldVendorConfiguration>
<SupportRules>
// Настройка правил поддержки
</SupportRules>
<Parameters>
// Параметры объединения
</Parameters>
<Conformities>
// Настройки ручных соответствий объектов
</Conformities>
<Objects>
// Настройки объединения объектов
</Objects>
</Settings>
```

Порядок дочерних элементов `<Settings>` значим: при ручном формировании файла его нужно соблюдать именно таким, как в каркасе (MainConfiguration → SecondConfiguration → OldVendorConfiguration → SupportRules → Parameters → Conformities → Objects).

### 3.32.2. Элемент `<Settings>`

#### 3.32.2.1. Общее описание

Корневой элемент файла.

| Атрибут | Обязательность | Тип | Назначение |
|---|---|---|---|
| `version` | обязательный | Строка | Версия файла настроек. |
| `platformVersion` | необязательный | Строка | Минимальная версия платформы «1С:Предприятие», с которой файл можно использовать. Записывается платформой при сохранении настроек. |

#### 3.32.2.2. Элемент `<MainConfiguration>`

Параметры основной конфигурации. Необязательный элемент.

| Вложенный элемент | Обязательность | Тип | Назначение |
|---|---|---|---|
| `<Name>` | обязательный | Строка | Имя основной конфигурации. |
| `<Version>` | необязательный | Строка | Версия основной конфигурации. |
| `<Vendor>` | необязательный | Строка | Имя поставщика. |

#### 3.32.2.3. Элемент `<SecondConfiguration>`

Описание второй конфигурации, участвующей в объединении. Необязательный. Состав тот же, что у `<MainConfiguration>` (`<Name>`, `<Version>`, `<Vendor>`).

#### 3.32.2.4. Элемент `<OldVendorConfiguration>`

Описание конфигурации поставщика, участвующей в объединении. Необязательный. Состав тот же, что у `<MainConfiguration>`.

#### 3.32.2.5. Элемент `<SupportRules>`

##### 3.32.2.5.1. Общее описание

Настройки правил поддержки. Необязательный элемент. Состав:

```xml
<SupportRules>
<NewObjects>
<ChangesAllowedRule/>
<ChangesNotRecommendedRule/>
</NewObjects>
<DuplicateObjectsAndModifiedObjectsWithGetFromSecondConfigurationRule>
<ChangesAllowedRule/>
<ChangesNotRecommendedRule/>
</DuplicateObjectsAndModifiedObjectsWithGetFromSecondConfigurationRule>
<ModifiedObjectsWithoutGetFromSecondConfigurationRule>
<ChangesAllowedRule/>
<ChangesNotRecommendedRule/>
</ModifiedObjectsWithoutGetFromSecondConfigurationRule>
</SupportRules>
```

В каждой из трёх групп есть два необязательных вложенных элемента:

- `<ChangesAllowedRule>` — правило поддержки для объектов поставщика с правилом поставки «Изменения разрешены»;
- `<ChangesNotRecommendedRule>` — правило поддержки для объектов поставщика с правилом поставки «Изменения не рекомендуются».

Значения этих элементов (словарь):

| Значение | Правило поддержки |
|---|---|
| `KeepCurrentRule` | Сохранить текущее правило поддержки. Только при обновлении конфигурации, находящейся на поддержке. В перечне значений группы `<NewObjects>` это значение отсутствует. |
| `ObjectNotEditable` | «Объект поставщика не редактируется». |
| `ObjectIsEditableSupportEnabled` | «Объект поставщика редактируется с сохранением поддержки». |
| `ObjectNotSupported` | «Объект поставщика снят с поддержки». |

##### 3.32.2.5.2. Элемент `<NewObjects>`

Правила поддержки для новых объектов поставщика.

| Вложенный элемент | Допустимые значения | По умолчанию |
|---|---|---|
| `<ChangesAllowedRule>` | `ObjectNotEditable`, `ObjectIsEditableSupportEnabled`, `ObjectNotSupported` | `ObjectNotEditable` |
| `<ChangesNotRecommendedRule>` | `ObjectNotEditable`, `ObjectIsEditableSupportEnabled`, `ObjectNotSupported` | `ObjectNotEditable` |

##### 3.32.2.5.3. Элемент `<DuplicateObjectsAndModifiedObjectsWithGetFromSecondConfigurationRule>`

Правила поддержки для идентичных объектов и для объектов с режимом объединения «Взять из второй конфигурации».

| Вложенный элемент | Допустимые значения | По умолчанию |
|---|---|---|
| `<ChangesAllowedRule>` | `KeepCurrentRule`, `ObjectNotEditable`, `ObjectIsEditableSupportEnabled`, `ObjectNotSupported` | при постановке на поддержку — `ObjectNotEditable`; при обновлении на поддержке — `KeepCurrentRule` |
| `<ChangesNotRecommendedRule>` | те же четыре значения | при постановке на поддержку — `ObjectNotEditable`; при обновлении на поддержке — `KeepCurrentRule` |

##### 3.32.2.5.4. Элемент `<ModifiedObjectsWithoutGetFromSecondConfigurationRule>`

Правила поддержки для изменённых объектов, у которых режим объединения отличается от «Взять из второй конфигурации».

| Вложенный элемент | Допустимые значения | По умолчанию |
|---|---|---|
| `<ChangesAllowedRule>` | `KeepCurrentRule`, `ObjectNotEditable`, `ObjectIsEditableSupportEnabled`, `ObjectNotSupported` | при постановке на поддержку — `ObjectIsEditableSupportEnabled`; при обновлении на поддержке — `KeepCurrentRule` |
| `<ChangesNotRecommendedRule>` | те же четыре значения | при постановке на поддержку — `ObjectIsEditableSupportEnabled`; при обновлении на поддержке — `KeepCurrentRule` |

#### 3.32.2.6. Элемент `<Parameters>`

##### 3.32.2.6.1. Общее описание

Параметры объединения. Необязательный элемент. Состав:

```xml
<Parameters>
<ConfigurationsRelation/>
<ComparisonLanguages>
<Language/>
</ComparisonLanguages>
<AllowMainConfigurationObjectDeletion/>
<CopyObjectsMode/>
</Parameters>
```

| Вложенный элемент | Обязательность | Тип / значения | По умолчанию | Назначение |
|---|---|---|---|---|
| `<ConfigurationsRelation>` | необязательный | `ConfigurationsNotRelated` — конфигурации не связаны; `SecondConfigurationIsDescendantOfMainConfiguration` — вторая является потомком основной; `MainConfigurationIsDescendantOfSecondConfiguration` — основная является потомком второй | `ConfigurationsNotRelated` | Связь между основной и второй конфигурациями. |
| `<AllowMainConfigurationObjectDeletion>` | необязательный | Булево | Ложь | Разрешено ли удалять объекты основной конфигурации. |
| `<CopyObjectsMode>` | необязательный | Булево | Ложь | Режим копирования объектов загружаемой конфигурации; в этом режиме внутренние идентификаторы объектов не сохраняются. |
| `<ComparisonLanguages>` | — | вложенные `<Language>` | — | См. 3.32.2.6.2. |

##### 3.32.2.6.2. Элемент `<ComparisonLanguages>`

Наличие элемента означает выборочное сравнение по языкам. Коды языков, участвующих в сравнении, перечисляются вложенными элементами `Language`.

#### 3.32.2.7. Элемент `<Conformities>`

Перечень объектов, соответствие которых установлено вручную. Необязательный элемент.

```xml
<Conformities>
<Conformity/>
</Conformities>
```

Элемент `<Conformity>` описывает одну пару сопоставленных объектов:

| Атрибут | Обязательность | Тип | Назначение |
|---|---|---|---|
| `fullName` | обязательный | Строка | Полное имя объекта основной конфигурации. |
| `fullNameInSecondConfiguration` | обязательный | Строка | Полное имя объекта второй конфигурации. |

#### 3.32.2.8. Элемент `<Objects>`

##### 3.32.2.8.1. Общее описание

Настройки объединения объектов конфигурации. Необязательный элемент. Состав:

```xml
<Objects>
<Configuration>
<MergeRule/>
<MergeRuleForPropertiesChangedTwice/>
<MergeRuleForPropertiesChangedOnce/>
<ObjectOrder/>
<Properties/>
</Configuration>
<Object>
<MergeRule/>
<MergeRuleForPropertiesChangedTwice/>
<MergeRuleForPropertiesChangedOnce/>
<ObjectOrder/>
<Subsystem>
<MergeRule/>
<MergeRuleForPropertiesChangedTwice/>
<MergeRuleForPropertiesChangedOnce/>
<ObjectOrder/>
</Subsystem>
<Properties/>
</Object>
</Objects>
```

##### 3.32.2.8.2. Элемент `<Configuration>`

Настройки объединения корневого элемента конфигурации. Должен содержать хотя бы один из элементов: `<MergeRule>`, `<MergeRuleForPropertiesChangedTwice>`, `<MergeRuleForPropertiesChangedOnce>`, `<ObjectOrder>`, `<Properties>`.

| Вложенный элемент | Обязательность | Назначение | Формат |
|---|---|---|---|
| `<MergeRule>` | необязательный | Режим объединения корневого элемента. | 3.32.3.3 |
| `<MergeRuleForPropertiesChangedTwice>` | необязательный | Режим объединения дважды изменённых свойств корневого элемента. | 3.32.3.4 |
| `<MergeRuleForPropertiesChangedOnce>` | необязательный | Режим объединения свойства корневого элемента, изменённого только в одной конфигурации. | 3.32.3.5 |
| `<ObjectOrder>` | необязательный | Порядок подчинённых объектов. | 3.32.3.6 |
| `<Properties>` | необязательный | Настройки объединения свойств корневого объекта конфигурации. | 3.32.3.1 |

##### 3.32.2.8.3. Элемент `<Object>`

Настройки объединения конкретного объекта конфигурации.

| Атрибут | Обязательность | Тип | Назначение |
|---|---|---|---|
| `fullName` | необязательный | Строка | Полное имя объекта в первой конфигурации. |
| `fullNameInSecondConfiguration` | в источнике не указана | Строка | Полное имя объекта во второй конфигурации. |

Правила:

- при настройке объединения должен быть задан хотя бы один из двух атрибутов — `fullName` или `fullNameInSecondConfiguration`;
- элемент должен содержать хотя бы один из элементов `<MergeRule>`, `<ObjectOrder>`, `<Properties>`, `<Subsystem>`;
- если режим объединения не `DoNotMerge`, то объект, существующий только в основной конфигурации, будет удалён, а объект, существующий только во второй конфигурации, — добавлен.

| Вложенный элемент | Обязательность | Назначение | Формат |
|---|---|---|---|
| `<MergeRule>` | необязательный | Режим объединения объекта. | 3.32.3.3 |
| `<MergeRuleForPropertiesChangedTwice>` | необязательный | Режим объединения дважды изменённых свойств объекта. | 3.32.3.4 |
| `<MergeRuleForPropertiesChangedOnce>` | необязательный | Режим объединения свойств объекта, изменённых только в одной конфигурации. | 3.32.3.5 |
| `<ObjectOrder>` | необязательный | Порядок подчинённых объектов у объекта. | 3.32.3.6 |
| `<Subsystem>` | — | См. ниже. | — |
| `<Properties>` | (есть в каркасе, отдельно для `<Object>` не расписан) | Настройки объединения свойств. | 3.32.3.1 |

###### Элемент `<Subsystem>`

Настройки объединения объектов, входящих в состав подсистемы. Используется только у `<Object>`, описывающего подсистему.

| Атрибут | Обязательность | Тип | Назначение / значения |
|---|---|---|---|
| `includeObjectsFromSubordinateSubsystems` | обязательный | Булево | Если указан, в обработку попадают все объекты (с подчинёнными), входящие в состав подсистемы родительского элемента. |
| `configuration` | обязательный | Строка | Из какой конфигурации брать состав подсистемы: `Main` — из основной (используется по умолчанию); `Second` — из второй. |

⚠ в источнике неясно: атрибут `configuration` здесь помечен обязательным, но при этом для `Main` указано «используется по умолчанию» (в файле списка объектов, 3.31.4.1, тот же атрибут необязательный).

| Вложенный элемент | Обязательность | Назначение | Формат |
|---|---|---|---|
| `<MergeRule>` | необязательный | Режим объединения объекта. | 3.32.3.3 |
| `<MergeRuleForPropertiesChangedTwice>` | необязательный | Режим объединения дважды изменённых свойств объекта. | 3.32.3.4 |
| `<MergeRuleForPropertiesChangedOnce>` | необязательный | Режим объединения свойств объекта, изменённых только в одной конфигурации. | 3.32.3.5 |
| `<ObjectOrder>` | необязательный | Порядок подчинённых объектов у объекта. | 3.32.3.6 |

### 3.32.3. Вспомогательные элементы

#### 3.32.3.1. Элемент `<Properties>`

##### 3.32.3.1.1. Общее описание

Настройки объединения свойств объекта конфигурации. Каркас (как в документации):

```xml
<Properties>
<Property name="…">
<MergeRule/>
<MergeRuleForPropertiesChangedTwice/>
<MergeRuleForPropertiesChangedOnce/>
<Module>
<Methods/>
<Patch/>
</Module>
<FormModule>
<MergeRule/>
<MergeRuleForPropertiesChangedTwice/>
<MergeRuleForPropertiesChangedOnce/>
<Module/>
</FormModule>
<SpreadsheetDocument>
<MergeRule/>
<MergeRuleForPropertiesChangedTwice/>
<MergeRuleForPropertiesChangedOnce/>
</SpreadsheetDocument>
<Types>
<Type>
<MergeRule/>
</Type>
…
</Types>
<Content>
<Item>
<MergeRule/>
</Item>
…
</Content>
<Property/>
</Properties>
```

⚠ в источнике неясно: в каркасе закрывающий тег свойства записан как `<Property/>` (по смыслу — `</Property>`).

##### 3.32.3.1.2. Элемент `<Property>`

Настройки объединения одного свойства объекта конфигурации.

| Атрибут | Тип | Назначение |
|---|---|---|
| `name` | Строка | Имя свойства объекта конфигурации. От значения зависит, какой из специализированных элементов может находиться внутри `<Property>` (один из): `<Module>`, `<FormModule>`, `<SpreadsheetDocument>`, `<Types>`, `<Content>`. |

| Вложенный элемент | Обязательность | Назначение | Формат |
|---|---|---|---|
| `<MergeRule>` | не указана | Режим объединения свойства. | 3.32.3.3 |
| `<MergeRuleForPropertiesChangedTwice>` | не указана | Режим объединения дважды изменённых свойств объекта. | 3.32.3.4 |
| `<MergeRuleForPropertiesChangedOnce>` | необязательный | Режим объединения свойств объекта, изменённых только в одной конфигурации. | 3.32.3.5 |

##### 3.32.3.1.3. Элемент `<Module>`

Дополнительные настройки объединения модуля.

| Вложенный элемент | Назначение |
|---|---|
| `<Methods>` | Настройки объединения модуля по процедурам (см. 3.32.3.2). |
| `<Patch>` | Данные для автоматизированного внесения изменений в текст модуля на встроенном языке в универсальном формате (unidiff). |

##### 3.32.3.1.4. Элемент `<FormModule>`

#### 3.32.3.2. Элемент `<Methods>`

##### 3.32.3.2.1. Общее описание

Настройки объединения модулей конфигурации по частям. Внутри могут быть:

- `<Method>` — объединение процедуры/функции; один или несколько;
- `<VariableDeclarationArea>` — объединение раздела объявления переменных; не более одного (может отсутствовать);
- `<MainArea>` — объединение раздела основной программы; не более одного (может отсутствовать).

Каркас (как в документации):

```xml
<Methods>
<Method>
<MergeRule/>
<Patch/>
<Method/>
<VariableDeclarationArea>
<Methods/>
<Patch/>
</VariableDeclarationArea>
<MainArea>
<Methods/>
<Patch/>
</MainArea>
</Methods>
```

⚠ в источнике неясно: в каркасе внутри `<VariableDeclarationArea>` и `<MainArea>` показаны `<Methods/>` и `<Patch/>`, а в описаниях этих элементов (3.32.3.2.3, 3.32.3.2.4) перечислены `<MergeRule>` и `<Patch>`; закрывающий тег метода записан как `<Method/>`.

##### 3.32.3.2.2. Элемент `<Method>`

Настройки объединения одной процедуры/функции модуля на встроенном языке.

| Атрибут | Тип | Назначение |
|---|---|---|
| `name` | Строка | Имя метода в основной и во второй конфигурации (если не задан `nameInSecondConfiguration`). |
| `nameInSecondConfiguration` | Строка | Имя метода во второй конфигурации, когда соответствие установлено вручную. Может отсутствовать. |

Поведение:

- метод есть в обоих файлах — выполняется объединение по заданному режиму либо применяется содержимое `<Patch>`;
- метод есть только в первом файле — он удаляется, если режим объединения не `DoNotMerge`;
- метод есть только во втором файле — он добавляется, если режим объединения не `DoNotMerge`.

| Вложенный элемент | Назначение |
|---|---|
| `<MergeRule>` | Режим объединения метода (формат — 3.32.3.3). |
| `<Patch>` | Данные для автоматизированного изменения текста модуля в формате unidiff. |

##### 3.32.3.2.3. Элемент `<VariableDeclarationArea>`

Настройки объединения раздела объявления переменных.

| Вложенный элемент | Назначение |
|---|---|
| `<MergeRule>` | Режим объединения раздела объявления переменных (формат — 3.32.3.3). |
| `<Patch>` | Данные для автоматизированного изменения текста модуля в формате unidiff. |

##### 3.32.3.2.4. Элемент `<MainArea>`

Настройки объединения раздела основной программы.

| Вложенный элемент | Назначение |
|---|---|
| `<MergeRule>` | Режим объединения раздела основной программы (формат — 3.32.3.3). |
| `<Patch>` | Данные для автоматизированного изменения текста модуля в формате unidiff. |

#### 3.32.3.3. Элемент `<MergeRule>`

Режим объединения элемента. Допустимые значения:

| Значение | Смысл |
|---|---|
| `DoNotMerge` | Не объединять. |
| `GetFromSecondConfiguration` | Взять из второй конфигурации. |
| `MergePrioritizingMainConfiguration` | Объединить с приоритетом основной конфигурации. |
| `MergePrioritizingSecondConfiguration` | Объединить с приоритетом второй конфигурации. |
| `MergeWithExternalTool` | Объединить внешней программой (поддерживается модулями). |

Исключение: у `<SpreadsheetDocument>` элемент `<MergeRule>` принимает значения `Merge` / `Unite` (см. 3.32.3.1.5).

#### 3.32.3.4. Элемент `<MergeRuleForPropertiesChangedTwice>`

Режим объединения дважды изменённых свойств объекта. Значения те же пять, что у `<MergeRule>`: `DoNotMerge`, `GetFromSecondConfiguration`, `MergePrioritizingMainConfiguration`, `MergePrioritizingSecondConfiguration`, `MergeWithExternalTool` (последнее поддерживается модулями).

#### 3.32.3.5. Элемент `<MergeRuleForPropertiesChangedOnce>`

Режим объединения свойств объектов, изменённых только в одной из конфигураций. Значения:

| Значение | Смысл |
|---|---|
| `DoNotMerge` | Не объединять. |
| `GetFromSecondConfiguration` | Взять из второй конфигурации. |

#### 3.32.3.6. Элемент `<ObjectOrder>`

Порядок подчинённых объектов. Значения:

| Значение | Смысл |
|---|---|
| `GetFromMainConfiguration` | Взять порядок из основной конфигурации. |
| `GetFromSecondConfiguration` | Взять порядок из второй конфигурации. |

## 3.33. Файл различий в выгрузках конфигураций

Файл создаётся командой пакетного запуска конфигуратора `/DumpConfigToFiles` с параметром `-getChanges` (в источнике параметр набран с типографским тире: «–getChanges») и содержит перечень различий между двумя сравниваемыми конфигурациями.

Формат:

- кодировка UTF-8;
- один объект — одна строка;
- изменений нет — файл пустой;
- если изменения требуют полной выгрузки, вместо списка объектов в файле единственная строка `FullDump`;
- каждая строка начинается с префикса, обозначающего вид изменения.

| Префикс | Что содержит строка |
|---|---|
| `New:` | Полное имя добавленного объекта. |
| `Modified:` | Полное имя изменённого объекта. Переименование объекта фиксируется отдельной строкой. |

Других префиксов в этом разделе источника не приведено.

## 3.34. Конфигурационный файл автономного сервера

### 3.34.1. Общая информация

Файл настроек автономного сервера — YAML версии 1.2 (https://www.yaml.org/spec/1.2/spec.html), кодировка UTF-8. В нём задаются параметры самого сервера и параметры информационной базы, которую он обслуживает.

Имя файла и его расположение в этой части источника не приводятся.

Единицы измерения для параметров-интервалов времени (если значением параметра служит диапазон времени, единица обязательна):

| Обозначения | Единица |
|---|---|
| `nano`, `ns` | наносекунды |
| `micro`, `us` | микросекунды |
| `milli`, `ms` | миллисекунды |
| `seconds`, `sec`, `s` | секунды |
| `minutes`, `min`, `m` | минуты |
| `hours`, `h` | часы |
| `days`, `d` | дни |

Секции файла:

| Секция | Содержимое | Раздел |
|---|---|---|
| `server` | параметры сервера | 3.34.2 |
| `database` | параметры базы данных | 3.34.3 |
| `infobase` | параметры информационной базы | 3.34.4 |
| `http` | параметры веб-доступа к информационной базе | 3.34.5 |
| `gates` | способы доступа к информационной базе (шлюзы) | 3.34.6 |
| `features` | функциональные характеристики автономного сервера | 3.34.7 |
| `debug` | параметры отладки | 3.34.8 |

Секция `debug` в общем перечне секций (3.34.1) не упомянута, но описана отдельным разделом 3.34.8.

Схема вложенности параметров (навигационная; составлена по заголовкам и таблицам раздела — готового YAML-примера в источнике нет, поэтому это не образец синтаксиса):

```text
server
    access-right-audit-events-recording, host, address, port
database
    dbms, server, name, user, password, path
infobase
    id, name, distribute-licenses, schedule-jobs, disable-local-speech-to-text
http
    base
    application        -> exit-url, publish
    auth
        openid
            provider   -> lifetime, return-to
            rely       -> url
        openid-connect -> allow-standard, providers
    zones              -> записи: safe, specify, value
    odata              -> publish, reuse-sessions
    web-services       -> publish-by-default, publish-extensions-by-default, service
        service        -> alias, name, publish, reuse-sessions
    http-services      -> publish-by-default, publish-extensions-by-default, service
        service        -> name, root, publish, reuse-sessions
    pubdst             -> lin32, lin64, lindeb32, lindeb64, linrpm32, linrpm64, mac64, win32, win64
    reuse-sessions (внутри odata и внутри service) -> max-age, mode, pool-size, pool-timeout
gates
    direct             -> regport, range, seclevel
    ssh
        <имя шлюза>    -> address, host-key, port
    http
        <имя шлюза>    -> address, port, endpoint (структура секции http)
    monitor
        <имя шлюза>    -> address, base, port
features
    direct-gate, extended-designer-features, http-gate, ssh-gate
debug
    address, password, port, type
    server             -> url
```

Сводка сетевых значений по умолчанию:

| Параметр | Умолчание |
|---|---|
| `server` → `address` | `localhost` |
| `server` → `port` | `8314` |
| `gates` → `direct` → `regport` | `1541` |
| `gates` → `direct` → `range` | `1560:1591` |
| `gates` → `direct` → `seclevel` | `0` |
| `gates` → `ssh` → `port` | `8282` |
| `gates` → `monitor` → `address` | `localhost` |
| `gates` → `monitor` → `port` | `1555` |
| `gates` → `monitor` → `base` | `/` |
| `debug` → `address` | `localhost` |
| `debug` → `port` | `1550` |
| `http` → `base` | `/` |

### 3.34.2. Секция server

| Параметр | Назначение | Значения | По умолчанию |
|---|---|---|---|
| `access-right-audit-events-recording` | Запись событий аудита прав доступа. | `allow`, `yes`, `true` — запись включена; `deny`, `no`, `false` — запись отключена | `deny` |
| `host` | Имя компьютера, на котором запущен автономный сервер. | — | не указано |

### 3.34.3. Секция database

Параметры базы данных. Обязательность зависит от варианта размещения:

- информационная база в СУБД — обязательны `dbms`, `server`, `name`;
- информационная база в файле `1Cv8.1CD` — обязателен `path`.

Одновременно использовать `dbms` и `path` нельзя.

| Обяз. | Параметр | Назначение | Значения |
|---|---|---|---|
| + | `dbms` | Тип СУБД. | `MSSQLServer` — Microsoft SQL Server; `PostgreSQL` — PostgreSQL; `IBMDB2` — IBM Db2; `OracleDatabase` — Oracle Database |
| + | `name` | Имя базы данных. | — |
|  | `password` | Пароль пользователя СУБД. | — |
| + | `path` | Путь к файлу базы данных `1Cv8.1CD`. | — |
| + | `server` | Имя сервера СУБД. | — |
|  | `user` | Имя пользователя, от имени которого автономный сервер подключается к СУБД. | — |

Знак «+» в первой колонке — признак обязательности (с учётом варианта размещения, см. выше). Прочие параметры перечисленных СУБД соответствуют требованиям клиент-серверного варианта платформы «1С:Предприятие».

### 3.34.4. Секция infobase

Параметры информационной базы, размещённой в базе данных из секции `database`.

| `id` | Идентификатор информационной базы в формате UUID. | UUID либо символическое значение `unique` — тогда при каждом запуске сервера генерируется новый уникальный идентификатор (пригодно для тестирования) | `unique` |

### 3.34.5. Секция http

#### 3.34.5.1. Общая информация

#### 3.34.5.2. Основная секция

| Параметр | Назначение | По умолчанию |

| `base` | Базовый путь доступа к информационной базе через веб-сервер. К одной базе можно сделать несколько публикаций, различающихся базовым путём и другими параметрами публикации. | `/` |
| `http-services` | Подсекция: публикация HTTP-сервисов (3.34.5.8). | — |
| `odata` | Подсекция: публикация OData (3.34.5.6). | — |
| `pubdst` | Подсекция: публикация дистрибутивов клиентских приложений (3.34.5.9). | — |

| `zones` | Подсекция: параметры разделителей (3.34.5.4). | — |

#### 3.34.5.3. Параметры аутентификации (auth)

| Параметр | Назначение |
|---|---|

| Параметр | Назначение |
|---|---|

##### 3.34.5.3.3. Параметры информационной базы, выступающей в роли OpenID-провайдера (provider)

| Параметр | Назначение | По умолчанию |

##### 3.34.5.3.4. Параметры аутентификации OpenIDConnect (openid-connect)

Массив объектов, по одному на провайдера; массив представлен в виде JSON-сериализации. | состав объектов в этой части не раскрыт (в источнике — ссылка на другой раздел) |

#### 3.34.5.4. Параметры разделителей (zones)

Описание разделителей для базового каталога доступа. Если в прикладном решении несколько разделителей, секция может содержать несколько записей; каждая запись описывает один разделитель, записи идут в порядке следования разделителей в метаданных.

| Параметр | Назначение | Значения | По умолчанию |

### 3.34.6. Секция gates

#### 3.34.6.1. Общая информация

#### 3.34.6.2. Секция direct

##### 3.34.6.2.1. Общая информация

Параметры доступа к информационной базе по TCP/IP (прямое подключение). По смыслу они соответствуют параметрам запуска кластера серверов в части сетевых портов и уровня безопасности. Если шлюз настроен, автономный сервер принимает прямые подключения Конфигуратора и тонкого клиента.

⚠ в источнике неясно: в общей информации сказано, что секция содержит именованную последовательность описаний параметров шлюза, а в описании секции — что она описывает единственный шлюз прямого подключения.

##### 3.34.6.3.1. Общая информация

## 3.35. Конфигурационный файл настройки пользователей сервера отладки

### 3.35.1. Общая информация

Файл определяет, какие пользователи в каких информационных базах могут пользоваться отладкой, и какие возможности отладки у них есть.

Формат: XML, кодировка UTF-8; наличие BOM не принципиально. Имя файла и его расположение в этой части источника не приводятся.

Структура (иерархия элементов):

| Элемент | Родитель | Кол-во | Назначение |
|---|---|---|---|
| `config` | — | 1 | Корневой элемент файла. |
| `infobase` | `config` | 1 или несколько | Одна или несколько информационных баз, для которых задаются пользователи отладчика. |
| `user` | `infobase` | 1 или несколько | Пользователь информационной базы с настройками возможностей отладки. Имена пользователей уникальны в пределах одной информационной базы. |
| `allowConfigurationExtensionsDebugging` | `user` | 0 или 1 | Список расширений, которые пользователь может отлаживать. Если элемент не задан — доступны все расширения, подключённые к информационной базе. |
| `configurationExtension` | `allowConfigurationExtensionsDebugging` | 1 или несколько | Расширение, которое пользователь может отлаживать в информационной базе. |
| `zones` | `user` | 0 или 1 | Область, в которую подключается пользователь; определяется значениями разделителей. Если элемент не задан — пользователь видит предметы отладки из всех областей разделённой информационной базы. |
| `zone` | `zones` | 1 или несколько | Значение одного разделителя. |

Пример из документации:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<config>
<infobase name="test_at_20">
<user name="Петя Иванов"
storedPasswordValue="QL0AFWMIX8NRZTKeof9cXsvbvu8="
comment="Произвольное описание пользователя"
allowPrivilegedModeDebugging="false"
allowConfigurationDebugging="true"
allowExpressionEvaluation="false">
<allowConfigurationExtensionsDebugging>
<configurationExtension name="Расширение1"/>
</allowConfigurationExtensionsDebugging>
<zones>
<zone name="Разделитель1" value="1"/>
<zone name="Разделитель2" value="a"/>
</zones>
</user>
</infobase>
</config>
```

### 3.35.2. Элемент infobase

Описывает информационную базу, для которой задаются разрешения пользователей. База определяется атрибутом `name`: это либо имя информационной базы, либо регулярное выражение, охватывающее несколько баз.

Регулярные выражения — в синтаксисе POSIX Basic Regular Expressions (https://pubs.opengroup.org/onlinepubs/9699919799/basedefs/V1_chap09.html#tag_09_03).

Пример:

```xml
<infobase name = "test_base">
<infobase name = "Infobase*">
```

### 3.35.3. Элемент user

Описывает пользователя и его возможности при отладке прикладного решения.

| Атрибут | Тип | Назначение / значения (как в источнике) |
|---|---|---|
| `name` | Строка | Имя пользователя сервера отладки — идентификатор пользователя, пытающегося подключиться к серверу отладки. Должно быть уникально в пределах информационной базы. |
| `storedPasswordValue` | Строка | Строка в формате Base64, полученная из хеша SHA1 пароля пользователя; пароль задаётся строкой в кодировке UTF-8. |
| `comment` | Строка | Произвольное описание пользователя отладки. |
| `allowPrivilegedModeDebugging` | Булево | По тексту источника — возможность отладки кода основной конфигурации: `true` — пользователь может отлаживать код основной конфигурации; `false` — не может. |
| `allowConfigurationDebugging` | Булево | По тексту источника — возможность отладки модулей в привилегированном режиме: `true` — отладка возможна после включения привилегированного режима; `false` — после включения привилегированного режима отладка невозможна и возобновляется после выхода из него. |
| `allowExpressionEvaluation` | Булево | Вычисление значений выражений при отладке: `true` — пользователь может вычислять и просматривать выражения, при этом все вычисляемые им выражения фиксируются в журнале регистрации; `false` — не может вычислять и просматривать выражения. |

⚠ в источнике неясно: описания атрибутов `allowPrivilegedModeDebugging` и `allowConfigurationDebugging` выглядят переставленными местами относительно их имён (первому приписана отладка кода основной конфигурации, второму — отладка в привилегированном режиме). В конспекте сохранено так, как в источнике; перед использованием проверить на практике.

Как получить значение для `storedPasswordValue`:

- диалогом конфигуратора: Главное меню — Администрирование — «Получить хранимое значение пароля для пользователя сервера отладки…»;
- кодом на встроенном языке:

```bsl
Хеширование = Новый ХешированиеДанных(ХешФункция.SHA1);
Хеширование.Добавить("UserSecretPassword");
Хеш = Хеширование.ХешСумма;
Хеш64 = Base64Строка(Хеш);
```

### 3.35.4. Элемент configurationExtension

Расширение, которое пользователь может отлаживать в данной информационной базе. Имя расширения задаётся атрибутом `name`; допускается регулярное выражение в синтаксисе POSIX Basic Regular Expressions (ссылка та же, что в 3.35.2).

### 3.35.5. Элемент zone

Значения разделителей (если они есть в информационной базе), с которыми пользователь будет подключаться к информационной базе.

| Атрибут | Тип | Назначение |
|---|---|---|
| `name` | Строка | Имя разделителя в том виде, как он задан в конфигурации. |
| `value` | Строка | Значение, устанавливаемое для разделителя. Правила записи значения те же, что для значений разделителей в файле `default.vrd`. |

## Что важно администратору Linux

1. Автономный сервер настраивается одним YAML-файлом (YAML 1.2, UTF-8) с секциями `server`, `database`, `infobase`, `http`, `gates`, `features` и `debug`. Параметры-интервалы времени пишутся с единицей измерения (`ms`, `s`, `min`, `h`, `d` и т. д.).
2. Порты автономного сервера по умолчанию: `8314` (`server.port`), `1541` и диапазон `1560:1591` (шлюз `direct`: `regport` и `range`), `8282` (шлюз `ssh`), `1555` (шлюз `monitor`), `1550` (`debug.port`).
3. Адреса по умолчанию — `localhost` (`server.address`, `gates.monitor.address`, `debug.address`). Чтобы сервис был доступен с других машин, задаётся `any` либо конкретный адрес IPv4/IPv6.
4. Для базы в PostgreSQL в секции `database` обязательны `dbms` (значение `PostgreSQL`), `server` и `name`; `user` и `password` необязательны. `dbms` и `path` (файл `1Cv8.1CD`) одновременно указывать нельзя.
5. `infobase.id` по умолчанию равен `unique` — при каждом запуске сервера генерируется новый идентификатор (режим для тестирования). Имя базы, если не задано, строится из фактического идентификатора.
6. Выдачей клиентских лицензий и выполнением регламентных заданий автономным сервером управляют `infobase.distribute-licenses` и `infobase.schedule-jobs`; значения по умолчанию для них (и для `disable-local-speech-to-text`) в этой части документации не приведены.
7. Шлюз `monitor` отдаёт метрики производительности по HTTP без аутентификации; не работает, если HTTP-доступ к автономному серверу отключён. По умолчанию слушает `localhost:1555`, базовый путь `/`.
8. Шлюз `ssh` превращает автономный сервер в SSH/SFTP-сервер; при значении `auto` параметра `host-key` на Linux в качестве закрытого ключа хоста берётся файл `~/.ssh/id_rsa`. Порт шлюза по умолчанию — `8282`.
9. Для шлюза `gates.http.<имя>` все параметры публикации (аналог `default.vrd`: `base`, `application`, `auth`, `odata`, `web-services`, `http-services`, `pubdst`, `zones`) размещаются внутри `endpoint`.
10. Секция `features` — общий выключатель: `direct-gate` и `http-gate` при отключении закрывают любой доступ по соответствующему протоколу вместе с отладкой; `extended-designer-features` по умолчанию `disable` (недоступны `--mobile-app-write-file` и `--mobile-client-write-file`).
11. Умолчания публикации сервисов: OData — выключена (`publish` = `false`); Web- и HTTP-сервисы конфигурации — включены (`publish-by-default` = `true`), сервисы из расширений — выключены (`publish-extensions-by-default` = `false`). Повторное использование сеансов по умолчанию `autouse`, пул 10 сеансов, ожидание 5 с, простой 20 с.
12. Дистрибутивы клиентов для Linux публикуются параметрами `pubdst`: `lin32`/`lin64`, `lindeb32`/`lindeb64` (deb), `linrpm32`/`linrpm64` (rpm).
13. Файл пользователей сервера отладки — XML в UTF-8: пароль хранится как Base64 от SHA1-хеша пароля (`storedPasswordValue`), имена баз и расширений можно задавать регулярными выражениями POSIX BRE; вычисление выражений пользователем при отладке фиксируется в журнале регистрации.
14. Файл различий, формируемый `/DumpConfigToFiles` с параметром `-getChanges`: UTF-8, по строке на объект с префиксами `New:` / `Modified:`; пустой файл — изменений нет; единственная строка `FullDump` — нужна полная выгрузка.
15. Файлы настроек объединения (пространство имён `http://v8.1c.ru/8.3/config/merge/settings`) и списка объектов (`http://v8.1c.ru/8.3/config/objects`, `version="1.0"`) — XML-файлы; в файле объединения порядок дочерних элементов `<Settings>` обязателен (важно при самостоятельном формировании файла), а при сохранении в него попадают только настройки, отличные от умолчаний.
