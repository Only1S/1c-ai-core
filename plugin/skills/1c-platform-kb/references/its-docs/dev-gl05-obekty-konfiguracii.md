## 5.1. Свойства конфигурации

### 5.1.1. Категория «Основные»

- **Основной режим запуска** — «Управляемое приложение» (по умолчанию для новой конфигурации) или «Обычное приложение». Не меняется в режиме совместимости «Версия 8.1».
- **Вариант встроенного языка** — русский или английский; влияет на то, как платформа сама формирует имена. Оба варианта конструкций можно использовать всегда.
- **Основные роли** — роли, действующие, когда **список пользователей пуст**: авторизация не выполняется, а пользователь считается обладающим административными правами. Если основных ролей нет и список пользователей пуст — работа идёт **без ограничения прав**. Эти же роли применяются к регламентным заданиям без указанного пользователя (глава 19).
- Ссылки на модуль управляемого приложения, модуль сеанса, модуль внешнего соединения.
- Хранилища настроек: общих настроек, пользовательских настроек отчётов, вариантов отчётов, данных форм, настроек динамических списков, внешних данных навигационных ссылок.
- «Дополнительные словари полнотекстового поиска» (глава 20).

### 5.1.2. Категория «Представление»

- Настройки командного интерфейса, начальной страницы, расположения панелей.
- **Режим основного окна клиентского приложения**: `Обычный`, `Рабочее место`, `Полноэкранное рабочее место`, `Киоск` (только интерфейс «Такси»; скрываются панели, меню, часть сочетаний клавиш), `Встроенное рабочее место` (только веб-клиент, встроенный в сторонний сайт; показывается неубираемая надпись «РАБОТАЕТ НА 1С»).
  - Задаётся тремя способами по возрастанию приоритета: свойство конфигурации → ключ командной строки `MainWindowMode` → метод `УстановитьРежимОсновногоОкна()`.
- Основной стиль, основной язык, краткая и подробная информация, логотип (до 64×64), заставка (600×255), авторские права, адреса информации о поставщике и конфигурации — выводятся в окне «О программе».
- Основные формы (констант, отчётов, настроек, истории данных, выбора пользователей системы взаимодействия) и основной макет оформления отчётов.

### 5.1.3–5.1.5. «Разработка», мобильные устройства, справка

- Поставщик, версия, «Адрес каталога обновлений».
- «Назначения использования» (приложение для платформы и/или для мобильной платформы), используемая функциональность мобильного приложения, подпись мобильного клиента (хеш публичного ключа указывается в параметре `MobilePublicKey` файла списка баз `.v8i`), состав автономной конфигурации, роли ограничения автономного мобильного приложения.

### 5.1.6. Категория «Совместимость»

- **Режим управления блокировкой данных** — см. `dev-gl09-rabota-s-dannymi.md`.
- **Режим хранилища двоичных данных** — доступен при режиме совместимости от «Версия 8.3.10» до «Версия 8.3.21»; начиная с «Версия 8.3.22» хранилище двоичных данных доступно всегда.
- **Режим автонумерации объектов** — `ОсвобождатьАвтоматически` (неиспользованные номера выдаются повторно) или `НеОсвобождатьАвтоматически`. Номер, выделенный **в транзакции**, переиспользуется в любом режиме.
- **Режим использования модальности** — `Использовать`, `Не использовать`, `Использовать с предупреждением`. С версии 8.3.5 тонкий и толстый клиенты учитывают запрет только при запуске с ключом `/EnableCheckModal` (при запуске из конфигуратора ключ ставится принудительно).
- **Режим использования синхронных вызовов расширений платформы и внешних компонент** — те же три значения; контроль включается ключом `/EnableCheckExtensionsAndAddInsSyncCalls`. Толстый клиент свойство игнорирует. Google Chrome с версии 45 и Mozilla Firefox с версии 43 синхронные вызовы не поддерживают.
- **Режим совместимости интерфейса** — `Версия 8.2`, `Версия 8.2. Разрешить Такси`, `Такси. Разрешить Версия 8.2`, `Такси`. Веб-клиент работает только в «Такси».
- **Режим использования табличных пространств** — редактируется при режиме совместимости «Версия 8.3.22» и ниже; выше — табличные пространства доступны всегда. Если режим включён, с базой можно работать только платформой **8.3.23 и новее**; чтобы вернуться на 8.3.22, нужно сначала перенести все объекты в пространство по умолчанию и отключить режим.
- **Режим совместимости** — управляет поведением механизмов, изменённых в новых версиях. Значения: «Версия 8.3.26» … «Версия 8.3.1», «Версия 8.2.16», «Версия 8.2.13», «Версия 8.1», «Не использовать». Особенности каждого режима — приложение 7 (`dev-pr07-osobennosti-rezhimov.md`).
  - Конфигурация с **неизвестным** (более новым) режимом совместимости не запускается и не загружается — выдаётся ошибка с требуемой версией.
  - Файл `.dt`, выгруженный в 8.3.1 и новее, нельзя загрузить платформой младше 8.3.1 (кроме случая, когда режим совместимости был «Версия 8.2.16»).
  - У мобильной платформы режим совместимости не задаётся свойством, а определяется версией платформы, создавшей или обновившей базу.

## 5.2–5.4. Модули приложения, внешнего соединения, сеанса

Сохраняются только в составе конфигурации; описание событий — в главе 4.

## 5.5. Ветвь «Общие»

### 5.5.1. Подсистемы

Формируют глобальный командный интерфейс. Имя `Desktop` давать подсистеме не рекомендуется.

### 5.5.2. Общие модули

- Содержат только процедуры и функции. Свойства определяют, где модуль доступен: «Клиент (управляемое приложение)», «Клиент (обычное приложение)», «Сервер», «Внешнее соединение», «Вызов сервера», «Привилегированный», «Глобальный».
- Привилегированный модуль исполняется только на сервере, при выключенной проверке прав.
- Свойство «Вызов сервера» рекомендуется снимать у серверных модулей, методы которых нежелательно вызывать с клиента.

**5.5.2.2. Повторное использование возвращаемых значений** («Не использовать», «На время вызова», «На время сеанса»):

- Результат функции запоминается по значениям параметров; повторный вызов с теми же параметрами функцию не выполняет. Процедуры выполняются всегда.
- Кеш очищается: через 20 минут после вычисления или через 6 минут после последнего использования; при нехватке памяти в рабочем процессе; **при перезапуске рабочего процесса**; при переключении клиента на другой рабочий процесс.
- Параметры — только примитивные типы, ссылки и структуры из них.
- Кеш не учитывает привилегированный режим: объект, полученный в привилегированном вызове, будет возвращён и непривилегированному коду.
- Внутри своего модуля функцию нужно вызывать по полному имени (`ОбщийМодуль.МояФункция()`), иначе кеш не используется.
- Сброс всего кеша — `ОбновитьПовторноИспользуемыеЗначения()`.

### 5.5.3. Параметры сеанса

- Используются в запросах и ограничениях доступа к данным. Права — «Получение» и «Установка».
- Инициализируются в обработчике `УстановкаПараметровСеанса()` модуля сеанса; чтение неинициализированного параметра вызывает этот обработчик, а если значение так и не задано — исключение.
- В клиент-серверном варианте хранятся на сервере. Объём одного параметра при передаче — не более 4 Гбайт.

### 5.5.4. Роли и права доступа

**5.5.4.1. Общее.** Права бывают основные (проверяются всегда) и интерактивные (при работе в формах). Права задаются на конфигурацию, объекты, реквизиты, табличные части. У новой роли на корневой объект установлены `ТонкийКлиент`, `ВебКлиент`, `СохранениеДанныхПользователя`, `Вывод`. Перечень прав — приложение 6 (`dev-prilozheniya.md`).

**5.5.4.2. Привилегированный режим.**

- Не проверяются права и ограничения на уровне записей. Включается `УстановитьПривилегированныйРежим()`, проверяется `ПривилегированныйРежим()`. На клиенте в клиент-серверном варианте вызов ничего не делает.
- Включения и выключения парные; незакрытые включения снимаются при выходе из процедуры.
- **Привилегированный сеанс** — режим включён с самого начала и не отключается. Запустить может только пользователь с правом «Администрирование»: ключ командной строки `UsePrivilegedMode` либо параметр строки соединения `prmod`.

**5.5.4.3. Безопасный режим.** Предназначен для «ненадёжного» кода (внешние обработки, текст для `Выполнить()` и `Вычислить()`). Включается `УстановитьБезопасныйРежим()`. В безопасном режиме:

- привилегированный режим отменяется, попытки его включить игнорируются;
- запрещены, с генерацией исключения:
  - **COM**: `COMОбъект()`, `ПолучитьCOMОбъект()`;
  - **внешние компоненты**: `ЗагрузитьВнешнююКомпоненту()`, `ПодключитьВнешнююКомпоненту()`;
  - **файловая система**: `КопироватьФайл()`, `ПереместитьФайл()`, `УдалитьФайлы()`, `СоздатьКаталог()`, `ЗначениеВФайл()`, `Новый Файл`, `Новый xBase`, открытие файлов объектами чтения и записи XML, HTML, ZIP, текста и двоичных данных, `Новый ДвоичныеДанные()`, `Новый ФайловыйПоток()`, `Новый ИзвлечениеТекста()`, методы `Прочитать()`, `Записать()`, `Напечатать()` табличного, текстового документов и схем;
  - **интернет**: `Новый ИнтернетСоединение`, `Новый ИнтернетПочта`, `Новый ИнтернетПрокси`, `Новый HTTPСоединение`, `Новый FTPСоединение`.
- Внешние отчёты и обработки, открытые через «Файл — Открыть», выполняются в безопасном режиме, если у пользователя нет административных прав.
- В обработчиках событий модулей объекта и менеджера платформа **автоматически отключает** безопасный режим (если код не в расширении). Узнать это — `ПолучитьОтключениеБезопасногоРежима()`; управлять — `УстановитьОтключениеБезопасногоРежима()` (в расширениях не работает).

**5.5.4.4. Режимы удаления.** Непосредственное удаление (без контроля ссылок) и пометка на удаление с контролем ссылочной целостности. Самый надёжный способ включить контроль — снять право непосредственного удаления.

**5.5.4.5. Сочетание ролей.** Доступ открыт, если разрешение есть **хотя бы в одной** роли пользователя.

**5.5.4.8. Ограничение доступа к данным (обзорно).**

- Ограничения задаются в ролях на права «Чтение», «Добавление», «Изменение», «Удаление» на специальном языке — подмножестве языка запросов (только секции `ИЗ` и `ГДЕ`). Для чтения можно задать разные условия на разные поля.
- Условия добавляются к SQL-запросам на стороне сервера «1С:Предприятия». Ограничения замедляют обращение к данным; чрезмерно сложные — особенно.
- Способ действия: «все» (операция завершается ошибкой, если затронуты недоступные записи) или «разрешенные» — включается в запросе ключевым словом `РАЗРЕШЕННЫЕ`. Объектная модель работает только способом «все».
- В условиях можно использовать параметры сеанса, функциональные опции (не зависящие от параметров), шаблоны ограничений (`#ИмяШаблона("…")`), инструкции препроцессора.
- Обращение к полю объекта из встроенного языка читает объект целиком.

### 5.5.5–5.5.23. Прочие общие объекты (обзорно)

- **Общие реквизиты** — реквизит, добавляемый многим объектам; основа разделения данных (глава 24).
- **Планы обмена**, **критерии отбора**, **подписки на события**.
- **Регламентные задания** (подробно — глава 19). В клиент-серверном варианте их запускает менеджер кластера, даже если к базе никто не подключён; автоматический запуск можно запретить для базы в утилите администрирования.
- **Функциональные опции** — не влияют на состав базы данных: все таблицы и поля существуют независимо от их состояния. При файловой базе через веб-сервер изменение опции отражается в интерфейсе только после **перезапуска веб-сервера**.
- **Определяемые типы** (с 8.3.3), **хранилища настроек**, общие формы, команды, группы команд, макеты, картинки (BMP, GIF, JPEG, PNG, TIFF, ICO, SVG, WMF, EMF), XDTO-пакеты, Web-сервисы, HTTP-сервисы, WS-ссылки, стили, языки.

## 5.6. Общие свойства объектов конфигурации (обзорно)

- Основные свойства: имя, синоним, комментарий; представления объекта.
- **Произвольное представление данных** — обработчик `ОбработкаПолученияПредставления` вызывается при любом получении представления; лишние данные в нём сильно замедляют работу.
- Стандартные реквизиты; предопределённые данные (в распределённой базе связывание с предопределёнными элементами требует, чтобы конфигурация пришла в узел раньше данных).
- **Нумерация**: серии кодов, периодичность, префиксы.
- **Ввод по строке**: действуют ограничения доступа; режим получения данных может быть фоновым (через фоновое задание).
- Табличные части, формы, команды, заполнение реквизитов новых объектов, проверка заполнения.
- **Индексирование реквизитов**: свойство «Индексировать» («Индексировать», «Индексировать с доп. упорядочиванием») создаёт индекс по реквизиту; см. также дополнительные индексы в главе 9.
- Способ выбора, история выбора, параметры выбора и их связи.

## 5.7–5.14. Прикладные объекты (обзорно)

- **Константы** — при изменении прежнее значение теряется; если нужна история, вместо константы используют регистр сведений без измерений.
- **Справочники** — иерархия (групп и элементов либо элементов), подчинение владельцу; максимальная длина кода — 50, наименования — 150. При обращении элемент читается целиком вместе с табличными частями. Справочнику с владельцем нельзя создать предопределённые элементы.
- **Документы** — номер, дата, проведение (оперативное и неоперативное), момент времени, нумераторы, последовательности, ввод на основании. Свойства «Привилегированный режим при проведении» и «…при отмене проведения». Если часовой пояс базы не задан, берётся часовой пояс компьютера сервера «1С:Предприятия».
- **Журналы документов**, **перечисления**.
- **Отчёты и обработки**, в том числе **внешние**. Внешнюю обработку можно подключить в безопасном режиме либо под профилем безопасности: параметр `БезопасныйРежим` методов `Подключить()` и `Создать()` принимает `Истина` или имя профиля; если профиля с таким именем на сервере нет — действует безопасный режим.
- **Планы видов характеристик** — дополнительные свойства объектов и субконто.
- **Регистры сведений** — измерения, ресурсы, реквизиты, периодичность, подчинение регистратору; свойство «Индексировать» у измерений и ресурсов.
- **Регистры накопления** — остатки и обороты, движения, итоги. Для оборотных регистров есть **агрегаты**: перестроение и расчёт оптимальных агрегатов ресурсоёмки, их выполняют в периоды минимальной нагрузки; рекомендуется режим разделения итогов.
