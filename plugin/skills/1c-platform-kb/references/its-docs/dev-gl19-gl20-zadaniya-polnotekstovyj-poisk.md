# Глава 19. Механизм заданий

## 19.1. Общая информация

- Состав механизма: **фоновые задания**, **метаданные регламентных заданий**, **регламентные задания**, **планировщик заданий**.
- Фоновое задание — асинхронный вызов процедуры или функции на сервере. Регламентное задание хранится в информационной базе, создаётся на основе метаданных и выполняется по расписанию; фактически его выполняет фоновое задание, которое запускает планировщик.
- **Ключ задания** обеспечивает, чтобы одновременно выполнялось не более одного задания с таким ключом. Уникальность считается отдельно для «самостоятельных» фоновых заданий (по ключу и имени метода) и для «регламентных» (по ключу и породившему регламентному заданию).

## 19.2. Фоновые задания

### 19.2.1. Свойства

- Метод задания — экспортная процедура или функция **неглобального общего модуля**, доступного на сервере. Возвращаемое значение функции игнорируется.
- Параметры должны поддерживать сериализацию; в сериализованном виде — не более **1 Гбайт**, иначе исключение.
- Создать задание может любой пользователь; оно выполняется от его имени. Получать задания и ждать их завершения может администратор либо создатель.
- Для каждого задания создаётся отдельный системный сеанс. Сохраняемого состояния у заданий нет.
- Задание может порождать дочерние задания — так в клиент-серверном варианте вычисления распределяются по рабочим процессам кластера.
- Задание может класть данные во временное хранилище вызвавшего сеанса; передать данные из вызывающего сеанса в сеанс задания нельзя.
- Порядок запуска: запись в журнал регистрации, установка параметров соединения с внешними источниками данных, обработчик `УстановкаПараметровСеанса` модуля сеанса, затем сам метод.
- Сведения о завершившихся заданиях хранятся **сутки**. История ведётся по каждой информационной базе: не более 1000 фоновых заданий, не более 1000 запусков регламентных (платформа старается сохранить хотя бы 3 последних запуска каждого регламентного задания, при нехватке места — 2, затем 1), не более 1000 системных фоновых заданий (отчёты, поиск и подобное).

### 19.2.2. Работа из встроенного языка

- Менеджер `ФоновыеЗадания`: `Выполнить()` (имя метода, массив параметров, ключ, наименование; возвращает объект `ФоновоеЗадание`), `ПолучитьФоновыеЗадания()`, `НайтиПоУникальномуИдентификатору()`, `ОжидатьЗавершенияВыполнения()` (для массива заданий).
- Объект `ФоновоеЗадание`: свойства `УникальныйИдентификатор`, `Состояние`; методы `ОжидатьЗавершенияВыполнения(<таймаут>)`, `Отменить()`, `ПолучитьСообщенияПользователю()`.
- Свойство `Состояние` фиксируется в момент получения объекта и само не обновляется: перед проверкой объект нужно получить заново. Значения — перечисление `СостояниеФоновогоЗадания` (например, `Активно`).
- После `Отменить()` «уборку» (временные файлы и подобное) нужно делать самому.

### 19.2.3. Фоновые задания и расширения

В сеансе задания подключаются те же расширения, что в родительском сеансе. Запустить со всеми расширениями базы — `РасширенияКонфигурации.ВыполнитьФоновоеЗаданиеСРасширениямиБазыДанных()`, совсем без расширений — `РасширенияКонфигурации.ВыполнитьФоновоеЗаданиеБезРасширений()`.

## 19.3. Регламентные задания

- Создавать регламентные задания и управлять ими могут только пользователи с административными правами.
- **Предопределённое** регламентное задание создаётся и удаляется автоматически при обновлении конфигурации (по признаку в метаданных); параметров не имеет. Начальные свойства, в том числе расписание, берутся из метаданных; последующее изменение метаданных на уже созданное задание в базе не влияет.
- Расписание (`РасписаниеРегламентногоЗадания`): `ПериодПовтораДней`, `ПериодПовтораВТечениеДня` (секунды), `ВремяНачала`, `ВремяКонца`, `ДниНедели`, `ПериодНедель`, `ДеньВМесяце` (отрицательное число — от конца месяца), `ДеньНеделиВМесяце`. Примеры: каждый час один день — `ПериодПовтораДней = 0`, `ПериодПовтораВТечениеДня = 3600`; последнее число месяца в 9:00 — `ПериодПовтораДней = 1`, `ДеньВМесяце = -1`, `ВремяНачала = 09.00`. Метод `ТребуетсяВыполнение()` проверяет, нужно ли запускать задание на заданную дату.
- Задание всегда выполняется от имени пользователя. Если пользователь не указан — с правами ролей из свойства конфигурации `ОсновныеРоли`; если и там пусто — **без ограничения прав**.
- Уже выполняющееся регламентное задание повторно не запускается, каким бы ни было расписание.
- Перезапуск при аварии: свойства «Количество повторов при аварийном завершении» и «Интервал повтора при аварийном завершении». Перезапуск происходит и при аварийном завершении рабочего процесса. Метод начинается заново, а не с места сбоя. После исчерпания повторов попытки прекращаются до следующего срока по расписанию.
- При записи задания, время которого по расписанию уже наступило, оно выполняется сразу (если момент записи попадает в интервал запуска).
- В недельном расписании с повтором реже одного раза в неделю граница недели определяется «первым днём недели» из региональных настроек базы.

## 19.4. Где выполняются задания

### 19.4.1. Файловый вариант

- Задания выполняет клиентское приложение или расширение веб-сервера, строго **последовательно**.
- Сведения о «самостоятельных» фоновых заданиях видны только в том приложении, которое их запустило, и не сохраняются после его закрытия; контроль уникальности ключа — в пределах одного клиента.
- Регламентные задания выполняет **одно** клиентское приложение — первое запущенное, которому это не запрещено. Управление: ключ командной строки `/AllowExecuteScheduledJobs` для тонкого и толстого клиентов, атрибут `allowexecutescheduledjobs` элемента `point` в `default.vrd` для публикации на веб-сервере.
- Расширение веб-сервера выполняет регламентные задания, только пока обслуживает хотя бы один клиентский сеанс. Если в назначенное время ни одно приложение не работает, задание не выполнится.
- Регламентные задания обрабатываются раз в 60 секунд. Планировщик фоновых заданий запускается через 60 секунд после старта клиента, планировщик регламентных — ещё через 60 секунд, то есть регламентные задания начинают работать не позже чем через 120 секунд после запуска.
- Фоновые задания, не завершившиеся за 30 секунд после закрытия клиента, завершаются принудительно; в журнал регистрации пишется событие `_$Job$_.Terminate`.
- В сеансе automation-сервера и COM-соединения регламентные задания файловой базы не работают.

### 19.4.2. Клиент-серверный вариант

- Планировщик находится в **менеджере кластера**. Он выбирает наименее загруженный рабочий процесс и передаёт ему задание.
- Регламентные задания блокируются, если: на базу установлена блокировка регламентных заданий (через консоль кластера); установлена блокировка начала сеансов; вызван `УстановитьМонопольныйРежим(Истина)`; идёт, например, обновление конфигурации базы данных.

### 19.4.3. Мобильное приложение

Регламентные задания не поддерживаются; фоновые выполняются последовательно.

## 19.5. Метаданные регламентного задания

Объект создаётся в ветви «Общие — Регламентные задания». Свойства: «Имя метода», «Ключ», «Расписание», «Использование», «Предопределенное», «Количество повторов при аварийном завершении», «Интервал повтора при аварийном завершении». В расписании можно задать время начала и окончания запуска, время принудительного завершения, период повтора, паузу между повторами. Создание в базе — `РегламентныеЗадания.СоздатьРегламентноеЗадание("<имя метаданных>")`, затем `Записать()`.

# Глава 20. Механизм полнотекстового поиска в данных

## 20.1. Общие сведения

- Состав: **индекс** полнотекстового поиска и средства поиска. Поисковые операторы — `И`, `ИЛИ`, `НЕ`, `РЯДОМ` и другие; поддерживаются хештеги (`#Заказ`, `#Заказ*`).
- Индексируются объекты, у которых включено свойство «Полнотекстовый поиск»: планы обмена, справочники, документы, планы видов характеристик, счетов и расчёта, регистры всех видов, бизнес-процессы, задачи. Реквизиты — строки, даты, числа, ссылки, хранилище значения.
- Изменения объектов фиксируются в файлах регистрации изменений в момент записи. При откате транзакции запись в них остаётся.
- Индексирование выполняется в привилегированном режиме на сервере и монопольного доступа не требует.
- Расположение файлов индекса описано в методической статье ИТС (`its.1c.ru/db/metod8dev#content:1591:hdoc`).
- Поиск идёт с учётом прав пользователя, включая ограничения на уровне записей; всегда с начала слова; находит слова с перепутанной раскладкой и похожими буквами разных алфавитов. В поисковой строке не более 1000 слов.

**Две версии механизма:**

| | Версия 1 | Версия 2 |
|---|---|---|
| С какой версии платформы | с 8.3 | с 8.3.22 |
| Устройство индекса | основной и дополнительный; нужно слияние | один индекс |
| Обновление индекса | регламентным заданием, которое пишет разработчик | автоматически платформой |
| Буквы «е» и «ё» | не различаются | различаются |
| Файловая база | поддерживается | не поддерживается (кроме файловой базы под автономным сервером) |
| Дополнительные словари | поддерживаются | не поддерживаются |

Поиск выполняется на сервере: в клиент-серверном варианте — в кластере серверов.

## 20.2. Программный интерфейс

Менеджер — свойство глобального контекста `ПолнотекстовыйПоиск` (тип `МенеджерПолнотекстовогоПоиска`).

Состояние и настройка:

- `ПолучитьРежимПолнотекстовогоПоиска()` и `УстановитьРежимПолнотекстовогоПоиска()` — значения `РежимПолнотекстовогоПоиска.Разрешить` и `Запретить`. Повторное разрешение после запрета **очищает** индекс.
- `ПолучитьВерсиюПолнотекстовогоПоиска()` и `УстановитьВерсиюПолнотекстовогоПоиска()`. Смена версии требует **монопольного доступа**. Индекс прежней версии остаётся как есть, поэтому можно быстро вернуться; ненужный индекс очищают вручную до смены. При переходе на версию 2 сначала проверяется возможность её запуска; при обратном переходе задания индексации прерываются.
- `ДатаАктуальности()`, `ИндексАктуален()`, `ОбновлениеИндексаЗавершено()`.
- `ПолучитьМаксимальныйРазмерИндексируемыхДанных()` и `УстановитьМаксимальныйРазмерИндексируемыхДанных()` — предел для одного реквизита, по умолчанию 1 Мбайт.
- `ПолучитьКоличествоЗаданийИндексирования()` и `УстановитьКоличествоЗаданийИндексирования()` — число одновременных фоновых заданий индексации; его можно менять по нагрузке.
- `ПолучитьРежимРазделенияСоставныхСлов()` и `УстановитьРежимРазделенияСоставныхСлов()` — только для версии 1.

Индексирование:

- `ОбновитьИндекс(РазрешитьСлияние, Порционное)`. Версия 1: при `Порционное = Истина` индексируется порция из 10 000 объектов и метод завершается. Версия 2: метод запускает обновление и сразу возвращает управление, состояние проверяют методом `ИндексАктуален()`.
- `ОчиститьИндекс()` — удаляет файлы индекса; рекомендуется после массовой замены данных (например, после загрузки базы). В версии 2 выполняется асинхронно.

Поиск: `СоздатьСписок(СтрокаПоиска, РазмерПорции)` возвращает `СписокПолнотекстовогоПоиска` с методами `ПерваяЧасть()`, `СледующаяЧасть()`, `ПредыдущаяЧасть()`, `Количество()`, `ПолноеКоличество()`, `СлишкомМногоРезультатов()`, `ПолучитьОтображение()` и свойствами `ПолучатьОписание`, `ОграничиватьСтрокуПоиска` (не более 1000 символов и 32 слов). Элемент списка — `Значение`, `Метаданные`, `Представление`, `Описание`.

## 20.3. Дополнительные словари (только версия 1)

- Словари морфологии и синонимов — макеты или константы, указанные в свойстве конфигурации «Дополнительные словари». Формат XML: корень `Dictionary`, секции `Words` (`lemma`, `forms`), `Synonyms` (наборы `item`), `Roots` (значащие части слов).
- Нечёткий поиск включается оператором `*`, поиск по синонимам — оператором `!`.
- После изменения словаря нужен перезапуск: в клиент-серверном варианте — **сервера «1С:Предприятия»**, при файловой базе через веб-сервер — веб-сервера. Индекс после этого перестраивают вручную.

## 20.4. Поддержание актуальности индекса

- **Версия 1:** нужно регламентное задание с вызовом `ПолнотекстовыйПоиск.ОбновитьИндекс(Ложь, Истина)`, обычно раз в 60 секунд. Слияние индексов — отдельно, в часы минимальной нагрузки.
- **Версия 2:** администратор один раз запускает первоначальное заполнение стандартной функцией «Управление полнотекстовым поиском» (или вызовом `ОбновитьИндекс()`); дальше платформа обновляет индекс сама.
- Для версии 2 важен запас места: если на диске с каталогом данных полнотекстового поиска остаётся **меньше 10 % свободного пространства**, индексация прерывается, индекс становится неактуальным и поиск недоступен, пока место не освободят.

## 20.5. Мобильная платформа

Не поддерживаются версия 2, морфология, дополнительные словари и извлечение текста. Индекс обновляется автоматически порциями по 10 000 объектов.
