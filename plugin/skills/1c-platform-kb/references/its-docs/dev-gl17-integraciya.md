## 17.1. Способы интеграции

| Способ | Что даёт | Средства платформы |
|---|---|---|
| Обмен файлами | интеграция данных; слабая связанность, невысокая оперативность | XML/XDTO, JSON, двоичные данные, DBF (`XBase`), `ТабличныйДокумент` (MXL, XLS, XLSX, ODS), текст |
| Общая база данных | интеграция данных; сильная связанность, высокая скорость | внешние источники данных (17.6) |
| Вызов программного интерфейса | функциональная интеграция | Web-сервисы (SOAP), HTTP-сервисы (REST), OData; клиент — `HTTPСоединение`, `WSПрокси`; COM — только Windows |
| Обмен сообщениями через сервисную шину | асинхронная интеграция, слабая связанность | сервисы интеграции, протокол AMQP (17.8) |

## 17.2. Web-сервисы (SOAP)

- Web-сервис описывается в конфигурации и публикуется на веб-сервере; с клиентами работает расширение веб-сервера (IIS или Apache), в котором находится пул соединений с информационной базой.
- Поддерживается: SOAP 1.1 и 1.2, WSDL 1.1, WS-I Basic Profile 1.1, HTTP 1.1, TLS 1.x (включая алгоритмы ГОСТ), MTOM; аутентификация Basic и NTLM/Negotiate.
- Не поддерживается: WS-Policy, WS-Addressing, WS-Security.
- **Адрес**: `http://host/base/ws/<ИмяWebСервиса>` или `http://host/base/ws/<имя файла публикации>` (например, `…/ws/shipment.1cws`; описание — `…?wsdl`). Указание разделителей параметром `Z` не поддерживается.
- Порядок вызова: из пула берётся (или создаётся) соединение → создаётся сеанс, выполняется `УстановкаПараметровСеанса` модуля сеанса (в привилегированном режиме) → вызывается метод сервиса (в обычном режиме). Ресурсоёмкие действия в `УстановкаПараметровСеанса` не рекомендуются: они выполняются при каждом вызове.
- Свойства операции: тип возвращаемого значения (XDTO), «В транзакции», «Имя метода». Свойства сервиса: «URI пространства имен», «Пакеты XDTO», «Имя файла публикации».
- **Чужие веб-сервисы**: статическая WS-ссылка в конфигурации (описание загружается один раз — быстрее) либо динамическая (`Новый WSОпределения(<адрес WSDL>)`, `Новый WSПрокси(…)` — описание запрашивается при каждом создании). Фактический адрес сервиса можно задать последним параметром при создании прокси. При ошибках в WSDL выдаётся исключение с перечнем нарушений (ссылки вида «Правило R2717» относятся к WS-I Basic Profile 1.1).

## 17.3. HTTP-сервисы

### Клиент HTTP

- Объекты `HTTPСоединение`, `HTTPЗапрос`, `HTTPОтвет`; есть асинхронные варианты для клиентских приложений.
- Защищённое соединение: `ЗащищенноеСоединениеOpenSSL` или `ЗащищенноеСоединениеКриптоПро`. Сертификаты удостоверяющих центров: `СертификатыУдостоверяющихЦентровОС`, `…Linux`, `…MacOS`, `…Windows`, `СертификатыУдостоверяющихЦентровФайл` либо `Неопределено` (сертификат сервера не проверяется). Клиентские сертификаты: `СертификатКлиентаLinux`, `СертификатКлиентаMacOS`, `СертификатКлиентаWindows`.

### 17.3.1.4. JWT

- JWT (RFC 7519) — три части: заголовок, полезная нагрузка, подпись; в «1С:Предприятии» применяется для аутентификации пользователей базы, для HTTP- и Web-сервисов и при настройке публикации на веб-сервере.
- Объект `ТокенДоступа`: свойства `Заголовки` (обязательны `typ` — `JWT` или `JWS` — и `alg`), `ПолезнаяНагрузка`, `ВремяЖизни` (`exp`), `ВремяСоздания` (`iat`, `nbf`), `Идентификатор` (`jti`), `КлючСопоставленияПользователя` (`sub`), `Получатели` (`aud`), `Эмитент` (`iss`). Алгоритмы — перечисление `АлгоритмПодписиТокенаДоступа`. Отключать подпись (`alg = none`) не рекомендуется.
- Передача: заголовок `Authorization: Bearer <токен>` (вручную или методом `HTTPЗапрос.ДобавитьТокенДоступа()`), параметр запроса `?AccessToken=<токен>`, команда `AccessToken` командной строки клиентского приложения.
- Настройка на стороне публикации — элемент `<accessTokenAuthentication>` файла `default.vrd`.

### 17.3.2. Собственные HTTP-сервисы

- **Адрес**: `http://host/base/hs/<корневойURL>/<относительныйURL>`. `hs` — признак HTTP-сервиса. Корневой URL задаётся свойством объекта «HTTP-сервис», относительный сопоставляется с шаблоном URL. Разделители параметром `Z` не указываются.
- Для каждого HTTP-метода шаблона пишется обработчик в модуле сервиса. Запрос методом, для которого обработчика нет, получает ошибку 405.
- Публикация — диалогом «Администрирование — Публикация на веб-сервере».

## 17.4. Стандартный интерфейс OData

- Назначение: доступ к данным извне **без изменения конфигурации** (важно для конфигураций на поддержке).
- **Адрес**: `http://host/base/odata/standard.odata/<ресурс>?<параметры>`. Имя ресурса — `<Префикс>_<ИмяОбъекта>_<Суффикс>`, например `Catalog_Контрагент(guid'…')`.
- Формат ответа: `$format=atom` (по умолчанию, atom-xml) или `$format=json` (либо заголовок `Accept: application/json`).
- Методы: `GET` — чтение; `POST` — создание; `PATCH` — обновление части свойств; `PUT` — обновление всех свойств; `DELETE` — удаление. **Удаление непосредственное**, без пометки на удаление. Табличную часть при изменении передают целиком.
- Параметры запроса: `$filter`, `$select`, `$top`, `$skip`, `$count`, `$inlinecount`, `$orderby`, `$expand`, `$metadata`; `allowedOnly` — вернуть только записи, разрешённые ограничениями доступа.
- Значения: `guid'8d04ce3c-…'`, `datetime'1945-05-09T06:00:00'`.
- Не поддерживаются: сравнение с реквизитом типа `ХранилищеЗначения`; функции `indexof`, `replace`, `tolower`, `toupper`, `trim` и ряд других; расширение (`$expand`) реквизитов табличных частей.
- Разделители задаются только частями URL или в `default.vrd`; параметр `Z` не поддерживается.
- **Публикация**: диалог публикации на веб-сервере. Кроме того, состав доступных объектов нужно разрешить методом `УстановитьСоставСтандартногоИнтерфейсаOData()` — это можно сделать внешней обработкой, не меняя конфигурацию. В режиме совместимости 8.3.4 и ниже метод не используется: доступны все поддерживаемые объекты.
- Упрощённое описание (список сущностей) — `GET http://host/base/odata/standard.odata`; полное — `…/$metadata` (в формате JSON полное описание не выдаётся).
- Перечень сущностей и их свойств — приложение 12.

## 17.5. WebSocket (обзорно)

- Клиент WebSocket (RFC 6455) используется двумя способами: «динамически» — объект `WebSocketКлиентСоединение` (на клиенте и в кластере серверов), и через объект конфигурации «WebSocket-клиент» (ветвь «Общие»; работает только на стороне кластера серверов).
- Свойства соединения: `ИспользоватьПроксиОС`, `Прокси` (`ИнтернетПрокси`), `Пользователь`, `Пароль`, `Таймаут`.

## 17.6. Внешние источники данных

### 17.6.2. Реляционные источники

- Доступ через **ODBC**, на чтение и запись. Таблицы источника можно использовать в запросах, компоновке данных, динамических списках, управляемых формах; на них действуют права и ограничения доступа.
- **Нельзя** использовать этот механизм для доступа к базам данных самого «1С:Предприятия» и как замену штатному хранению данных.
- Полнее всего поддерживаются (свойство «Тип СУБД»): Microsoft SQL Server, IBM Db2, **PostgreSQL**, Oracle Database, MySQL. Неверно указанный тип СУБД приводит к ошибкам. Для прочих СУБД функции языка запросов переводятся в управляющие последовательности ODBC.
- Параметры соединения, заданные в конфигураторе, в режиме «1С:Предприятие» **не используются** — подключение настраивается отдельно.
- Строка соединения: пары `Ключ=Значение` через `;` (например, `DRIVER={SQL Server};SERVER=…;UID=…;PWD=…;DATABASE=…`) либо `DSN=<имя>`. Имя пользователя и пароль из диалога «Параметры соединения» дописываются справа и поэтому имеют приоритет.
- Описание источника данных (DSN) создаётся утилитой администрирования ODBC; **в Linux она называется `ODBCConfig`** и ставится отдельным пакетом. В 64-разрядной Windows разрядность утилиты должна совпадать с разрядностью «1С:Предприятия», выполняющего запросы.
- Особенности PostgreSQL как внешнего источника: не поддерживается запись полей типа `УникальныйИдентификатор`.
- Удаление записей только непосредственное. Порядок сортировки в динамическом списке определяется настройками внешней базы и может отличаться от принятого в информационной базе.
- В одном запросе — только один источник данных; смешивать внешний источник с данными информационной базы нельзя.

### 17.6.3–17.6.4. OLAP и функции

- Аналитические источники (кубы, таблицы измерений) подключаются по XMLA; есть таблица ограничений языка запросов по OLAP-системам.
- «Функции» внешнего источника — обёртки над функциями и хранимыми процедурами СУБД или произвольное выражение на языке СУБД.

### 17.6.7.1. Где выполняются запросы к внешним источникам

- файловый вариант — на компьютере клиентского приложения;
- файловый вариант через веб-сервер — на компьютере с расширением веб-сервера;
- **клиент-серверный вариант — на компьютере, где работает сервис кластера «работа с внешними источниками данных через ODBC»** (для OLAP — «…через XMLA»). Практический вывод (в документации прямо не сформулирован): драйвер ODBC и описание источника данных должны быть настроены именно на этом рабочем сервере и доступны пользователю, от имени которого работает сервер.

## 17.7. Повторное использование сеансов интернет-сервисов

- Каждый вызов Web-сервиса, HTTP-сервиса или OData по умолчанию создаёт сеанс (с загрузкой конфигурации и обработчиками) — на больших конфигурациях это заметная задержка.
- Три варианта: «Не использовать»; «Использовать» — сеансом управляет клиент заголовком `IBSession` (`start`, `finish`; cookie `ibsession`; ошибки 406 и 400); «Использовать автоматически» — платформа ведёт **пул сеансов** в разрезе типа и имени сервиса, пользователя, пароля, набора разделителей и безопасного режима; свободный сеанс уничтожается по истечении времени жизни.
- Настраивается в свойствах сервисов («Повторное использование сеансов», «Время жизни сеанса») и в `default.vrd`; значения из `default.vrd` **приоритетнее**.
- Для OData по умолчанию: автоматическое повторное использование, время жизни 20 секунд.
- Подробности протокола `IBSession` — `dev-rukovodstvo-razrabotchika-vyborka.md`.

## 17.8. Сервисы интеграции (обзорно)

- Объект конфигурации «Сервис интеграции» (ветвь «Общие») — адаптер к сервисной шине предприятия по протоколу AMQP; у него есть свойство «Адрес внешнего сервиса интеграции» и каналы.
- Отправка: `СоздатьСообщение()` у менеджера сервиса, затем `ОтправитьСообщение()` у менеджера канала.
- Настройки — из встроенного языка или стандартной обработкой «Управление сервисами интеграции».
- Получение и отправку ведут фоновые задания. В клиент-серверном варианте задание обработки полученных сообщений после работы «засыпает» на 20 секунд, а не завершается; в файловом варианте задания выполняются последовательно одним клиентским приложением.

## 17.9. Буфер обмена (обзорно)

Свойство глобального контекста `СредстваБуфераОбмена`. В Linux с X11 помещение данных в буфер асинхронно: чтение сразу после записи может вернуть прежнее содержимое.
