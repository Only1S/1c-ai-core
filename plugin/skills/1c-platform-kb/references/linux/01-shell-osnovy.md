# Bash и основы работы в терминале Ubuntu Server: навигация, файлы, перенаправления, окружение

> Область: командная оболочка Bash и базовые утилиты на сервере «1С:Предприятие 8» (клиент-серверный вариант) + PostgreSQL под Ubuntu Server в ВМ на Windows-хосте | Версии: Ubuntu 22.04 LTS (bash 5.1, GNU coreutils 8.32), 24.04 LTS (bash 5.2.21, GNU coreutils 9.4), 26.04 LTS (bash 5.3, rust-coreutils + sudo-rs); платформа 1С 8.3.x / 8.5.x; PostgreSQL 14–18 | Актуальность: 2026-10-10 (в тот же день прошёл независимый фактчек по первоисточникам; что осталось непроверенным — помечено «⚠» и перечислено в конце раздела «Источники»)

Обозначения: в блоках кода текст после `#` — комментарий; `NN` — мажорная версия PostgreSQL (16, 17, 18); `<версия>` — полный номер платформы 1С вида `8.3.27.1688` (в примерах это условный номер — подставляйте свой); имена `admin`, `srv1c`, `base1`, адрес `192.168.56.10` — условные; «⚠ не подтверждено» — утверждение не удалось проверить по первоисточнику, перепроверьте на своей системе.

## Кратко

1. Оболочка по умолчанию на Ubuntu Server — **Bash**: 5.1 (22.04), 5.2.21 (24.04), 5.3 (26.04). `/bin/sh` — это `dash`, а не bash: скрипты с башизмами (`[[ ]]`, массивы, `&>`) должны начинаться с `#!/bin/bash` (или `#!/usr/bin/env bash`).
2. **Ubuntu 26.04 сильно отличается от 22.04/24.04** в базовых утилитах: `ls`, `cat`, `date`, `stat`, `sort` и почти все coreutils — это Rust-реализация **uutils** (пакет `rust-coreutils`), а `cp`, `mv`, `rm` остались от GNU; `sudo` — это **sudo-rs** (классический доступен как `sudo.ws`); `/tmp` — это **tmpfs** в оперативной памяти. Проверка: `ls --version | head -1`, `sudo --version`, `findmnt /tmp`.
3. Где что лежит: платформа 1С — `/opt/1cv8/x86_64/<версия>/`; данные кластера 1С — `/home/usr1cv8/.1cv8/1C/1cv8/`; PostgreSQL из пакетов Ubuntu/PGDG — конфигурация `/etc/postgresql/NN/main/`, данные `/var/lib/postgresql/NN/main/`, журнал `/var/log/postgresql/`; сборка «PostgreSQL для 1С» от Postgres Professional (пакеты `postgrespro-1c-NN`, служба `postgrespro-1c-NN`; ниже для краткости — «Postgres Pro для 1С», хотя формально это не СУБД Postgres Pro, а свободная сборка PostgreSQL с патчами для 1С) — `/opt/pgpro/1c-NN/` и `/var/lib/pgpro/1c-NN/data/`.
4. **Всегда берите переменные в двойные кавычки**: `"$var"`, `"$@"`, `"$(cmd)"`. Без кавычек значение режется по пробелам и раскрывается как шаблон — источник 90 % «странных» ошибок и случайных удалений.
5. Порядок перенаправлений важен: `cmd > file 2>&1` (оба потока в файл) ≠ `cmd 2>&1 > file` (stderr остаётся на экране). Короткая форма bash: `cmd &> file`, дозапись — `cmd &>> file`.
6. Перенаправление выполняет **ваша** оболочка, а не sudo: `sudo echo x > /etc/f` не сработает. Правильно: `echo x | sudo tee /etc/f >/dev/null` или `sudo sh -c 'echo x > /etc/f'`.
7. Команды от имени служебных пользователей: `sudo -u postgres psql`, `sudo -iu postgres` (логин-оболочка), `sudo -u usr1cv8 <команда>`. Root-пароля в Ubuntu по умолчанию нет — вместо `su -` используйте `sudo -i`.
8. Долгие операции по SSH (pg_dump/pg_restore, выгрузка/загрузка базы, реиндексация, обновление конфигурации) запускайте только в **tmux** (или screen): `tmux new -s work` → работа → `Ctrl+b d` → позже `tmux attach -t work`. Обрыв SSH убивает всё, что запущено в обычной сессии.
9. Копирование с сохранением владельца, прав, времени и ссылок: `cp -a`. Копировать *содержимое* каталога, включая скрытые файлы: `cp -a src/. dst/`.
10. `rm -rf` необратим, корзины нет. Перед удалением по шаблону сначала выполните ту же команду с `ls` или `echo`; в скриптах — `rm -rf -- "${DIR:?}/"*`.
11. `find … -delete` ставится **последним** в выражении (иначе удалит всё дерево); имена с пробелами передавайте как `find … -print0 | xargs -0 …` либо `-exec … {} +`.
12. Службы systemd (сервер 1С, PostgreSQL) **не читают** `~/.bashrc`, `~/.profile`, `/etc/profile.d/*` и `/etc/environment`. Их окружение задаётся в юните (`Environment=`, `EnvironmentFile=`): `sudo systemctl edit <юнит>`.
13. Код возврата последней команды — `$?` (0 = успех). В конвейере по умолчанию учитывается только последняя команда; для скриптов включайте `set -o pipefail` (или смотрите `"${PIPESTATUS[@]}"`).
14. Узнать, что именно запустится: `type -a имя` и `command -v имя` (встроенные средства bash, надёжнее `which`).
15. Справка: `man команда`, `man 5 файл`, `команда --help`, `help встроенная_команда`, `apropos слово`, `tldr команда`.
16. Клавиши: `Ctrl+C` — прервать, `Ctrl+Z` — приостановить (затем `bg`/`fg`), `Ctrl+D` — конец ввода/выход, `Ctrl+R` — поиск по истории, `Ctrl+L` — очистить экран, `Tab` — автодополнение. «Зависший» терминал после `Ctrl+S` размораживается `Ctrl+Q`.
17. Переключить символическую ссылку на каталог: `ln -sfn новая_цель ссылка` (без `-n` ссылка создастся *внутри* старого каталога). Гарантированно атомарный вариант (одним `rename`): `ln -s новая_цель ссылка.new && mv -T ссылка.new ссылка`.
18. Двухпанельный файловый менеджер: `sudo apt install mc`; `F3` просмотр, `F4` правка, `F5` копия, `F6` перенос, `F8` удаление, `F10` выход, `Ctrl+O` — показать/скрыть панели.
19. `/tmp` и `/var/tmp` — не хранилище: в 22.04/24.04 `/tmp` очищается при каждой загрузке (в 24.04 — ещё и от файлов старше 30 дней), в 24.10+/26.04 `/tmp` живёт в ОЗУ и чистится от файлов старше 10 дней, `/var/tmp` — старше 30 дней. Дампы, дистрибутивы и выгрузки держите в специально созданных каталогах (`/srv/…`, `/var/backups/…`, отдельный том).
20. `cp -n` непереносим между LTS: 22.04 — молча пропускает; 24.04 — пропускает с предупреждением в stderr; 26.04 — молча пропускает, но ключ объявлен нежелательным. `cp --update=none` есть только с 24.04. Для скриптов «на все версии» — явная проверка `[[ -e "$dst" ]] || cp -a "$src" "$dst"`.

### Что нужно знать про Ubuntu 26.04 (и 25.10)

**rust-coreutils (официально, release notes 26.04).** Базовые утилиты поставляет пакет `rust-coreutils`; они «not fully compatible yet», поэтому GNU-версии тоже установлены и вызываются с префиксом `gnu` (например, `gnuls`, `gnudate`, `gnusort`). `cp`, `mv`, `rm` из-за нерешённых ошибок остаются GNU-шными.

```bash
ls --version | head -1        # ls (uutils coreutils) 0.x  — Rust;  «ls (GNU coreutils) 9.x» — GNU
cp --version | head -1        # на 26.04: cp (GNU coreutils) 9.x
readlink -f /usr/bin/ls       # куда на самом деле указывает команда
ls /usr/bin/gnu* | head       # список GNU-двойников

# Официальный способ вернуть GNU coreutils целиком (и обратно):
sudo apt install coreutils-from-gnu coreutils-from-uutils- --allow-remove-essential
sudo apt install coreutils-from-uutils coreutils-from-gnu- --allow-remove-essential
```

Версии: на релизе 26.04 — `rust-coreutils` 0.8.0 (`0.8.0-0ubuntu3`), в `resolute-updates` — 0.10.0 (`0.10.0-1ubuntu2~26.04.1`); GNU-двойники и `cp`/`mv`/`rm` — из пакета `gnu-coreutils` 9.7. Пакет `coreutils` в 26.04 — метапакет, зависящий от `coreutils-from-uutils` *или* `coreutils-from-gnu`. В release notes («Changes since 25.10») для релизной версии перечислены известные уязвимости rust-coreutils (CVE-2026-35341 … CVE-2026-35377) — ставьте обновления (`sudo apt update && sudo apt full-upgrade`) и проверяйте `apt policy rust-coreutils`. По заявлению Canonical (Discourse), `cp`/`mv`/`rm` оставлены GNU из-за нерешённых TOCTOU-проблем, а полный переход на Rust намечен на 26.10.

Известные расхождения uutils и GNU (практика сообщества, проверяйте на своей версии): `uname -p` выдаёт `unknown` (подтверждено по исходному коду uutils: ключи `-p` и `-i` всегда печатают «unknown»; используйте `uname -m`); в выводе `stat` некоторые подписи пишутся иначе (не парсите вывод `stat`, берите `stat -c '%s'`); сортировка `sort` в UTF-8-локали может отличаться (для стабильности — `LC_ALL=C sort`); тексты сообщений об ошибках другие (не сравнивайте их в скриптах); `dd status=progress` обновляется по блокам, а не раз в секунду. В release notes также отмечено: `mkdir -p` не всегда корректно наследует POSIX ACL от родительского каталога.

**sudo-rs (официально: release notes, Ubuntu Server docs).** Отличия, заметные в повседневной работе:

- приглашение выглядит как `[sudo: authenticate] Password:` вместо `[sudo] password for user:` — скрипты на `expect`, ждущие старую строку, ломаются (обход: `sudo --prompt ""` или `sudo -S`);
- при вводе пароля печатаются звёздочки (`pwfeedback` включён по умолчанию; отключение — строка `Defaults !pwfeedback` через `sudo visudo`);
- **`sudo -E` не поддерживается**: выводится предупреждение `preserving the entire environment is not supported, '-E' is ignored`, и команда выполняется без сохранения окружения. Работает только явный список: `sudo --preserve-env=VAR1,VAR2 команда`. Проверено по исходному коду тега `v0.2.13` — именно эта версия (`0.2.13-0ubuntu1.x`) стоит в 26.04; README проекта прямо называет `sudo -E` неподдерживаемым;
- нет журналирования ввода-вывода (`sudoreplay`), отправки почты, `sudoers.ldap`, `cvtsudoers`; `-H` молча принимается (HOME и так выставляется на целевого пользователя); `env_reset` включён всегда; `use_pty` включён по умолчанию; журнал — только через syslog/journal (`logfile` не поддерживается);
- то, что **работает** как в классическом sudo (man-страница sudo-rs; `-b` дополнительно проверен по коду `v0.2.13`): `-i`, `-s`, `-u`, `-g`, `-l`/`-U`, `-n`, `-S`, `-k`/`-K`/`-v`, `-b` (фон), `-D`/`--chdir`, `-p`/`--prompt`, `-A`/`--askpass`, `-e`/`sudoedit`. Документация Ubuntu Server советует сверяться с установленной версией: `sudo-rs --help` (список ключей) и `man sudoers-rs` (поддерживаемые директивы `/etc/sudoers`);
- переключение реализации (Ubuntu Discourse, для 25.10+; Canonical называет его «not recommended»): интерактивно `sudo update-alternatives --config sudo`; явно на классический — `sudo update-alternatives --set sudo /usr/bin/sudo.ws`, обратно на sudo-rs — `sudo update-alternatives --set sudo /usr/lib/cargo/bin/sudo`. Классический бинарник всегда доступен напрямую как `sudo.ws` (а также `/usr/sbin/visudo.ws`, `/usr/bin/sudoreplay.ws`).

**`/tmp` — tmpfs.** С 24.10 Ubuntu использует штатный `tmp.mount` из systemd (release notes 24.10 и 26.04): `/tmp` живёт в оперативной памяти (и свопе). В исходном юните systemd опции `mode=1777,strictatime,nosuid,nodev,size=50%,nr_inodes=1m`, то есть лимит — половина ОЗУ (это потолок: память занимается только по мере появления файлов). Вместе с этим Ubuntu с версии systemd 256 (24.10) отказалась от собственных правок `tmpfiles.d/tmp.conf` и приняла правила upstream — подтверждено журналом изменений пакета systemd:

| Выпуск | `/tmp` | `/var/tmp` |
|---|---|---|
| 22.04, 24.04 | Каталог на диске. Содержимое **удаляется при каждой загрузке**; в 24.04, кроме того, файлы старше **30 дней** удаляет ежедневный `systemd-tmpfiles-clean.timer`, в 22.04 срока хранения нет — см. поправку в соседней ячейке (правка Ubuntu `tmpfiles.d-tmp.conf-make-cleanup-age-30d-on-Ubuntu.patch` поверх правила Debian `D /tmp 1777 root root -`) | Автоматически не очищается (строка `q /var/tmp … 30d` закомментирована правкой Debian) — подтверждено 11.10.2026 текстом правки Debian (метка `debian/255.4-1` на salsa.debian.org): исходные строки `q /tmp 1777 root root 10d` и `q /var/tmp 1777 root root 30d` заменены на `D /tmp 1777 root root -` и `#q /var/tmp 1777 root root 30d`. Поправка по журналам изменений пакета systemd: срок 30 дней для `/tmp` добавлен в Ubuntu только с версии 255.4-1ubuntu2 (LP: #2019026), то есть в 24.04; в журнале пакета 22.04 (249.11-0ubuntu3.22) такой правки нет — там `/tmp` очищается только при загрузке. Ранее отмечалось: формулировка для `/var/tmp` дана по памяти о содержимом правки, сверяйте `cat /usr/lib/tmpfiles.d/tmp.conf` |
| 24.10 … 26.04 | tmpfs в ОЗУ. Теряется при перезагрузке; файлы, которыми не пользовались **10 дней**, удаляются | На диске; файлы старше **30 дней** удаляются (перезагрузку переживают) |

При обновлении 24.04 → 26.04 `/tmp` тоже становится tmpfs (новый `tmp.mount` перемонтирует `/tmp`, см. LP #2144032), и начинают действовать новые сроки очистки: файл-заглушку `/etc/tmpfiles.d/tmp.conf`, которым Debian 13 при обновлении сохраняет прежние правила очистки, Ubuntu намеренно **не создаёт** (журнал изменений `256-1ubuntu1`: «to be aligned with what a new install would look like»). Если `/tmp` — отдельный раздел в `/etc/fstab`, он остаётся как был. Файлы, лежавшие в старом `/tmp` на диске, после перезагрузки окажутся «под» tmpfs и невидимы (достать: `sudo mount --bind / /mnt && ls /mnt/tmp`).

Для сервера 1С и СУБД это существенно в двух отношениях: (1) всё, что пишется в `/tmp`, расходует ОЗУ, которая нужна `rphost` и PostgreSQL; (2) дистрибутивы, дампы и выгрузки, оставленные в `/tmp` (а на 24.10+ и в `/var/tmp`), будут удалены автоматически. Куда именно рабочие процессы сервера 1С пишут временные файлы и учитывают ли они `TMPDIR` — **Уточнено 10.10.2026** (статья ИТС «Изменение каталога временных файлов сервера 1С:Предприятия», 2010, `https://its.1c.ru/db/metod8dev/content/1736/hdoc`): каталог временных файлов сервера по умолчанию — `/tmp`; он меняется переменной окружения `TMPDIR` у пользователя, от имени которого работает сервер, и новое значение действует после перезапуска сервера. Статья старая (в ней `.bash_profile` и `tmpwatch`); для службы systemd переменную задают в юните. Ранее было не подтверждено по документации 1С (нужна закрытая страница ИТС); проверяйте фактом, а не предположением (команды ниже).

```bash
findmnt /tmp                         # FSTYPE tmpfs → /tmp в памяти
df -h /tmp /var/tmp
cat /usr/lib/tmpfiles.d/tmp.conf     # фактические правила авто-очистки на вашей версии
systemd-tmpfiles --cat-config | grep -E '^[a-zA-Z!+-]+ +/(var/)?tmp( |$)'   # итоговые правила с учётом переопределений в /etc/tmpfiles.d
systemctl status tmp.mount
systemctl list-timers systemd-tmpfiles-clean.timer

# Что реально пишет в /tmp сервер 1С (проверка вместо предположений):
sudo find /tmp /var/tmp -xdev -user usr1cv8 -printf '%s\t%p\n' 2>/dev/null | sort -nr | head
sudo ls -l /proc/"$(pgrep -o rphost)"/fd 2>/dev/null | grep -E '/tmp/|\(deleted\)'      # открытые (в т. ч. удалённые) временные файлы rphost
systemctl show 'srv1cv8-*@default' -p PrivateTmp -p Environment                             # задан ли юниту приватный /tmp или TMPDIR

# Изменить лимит tmpfs (пример из release notes Debian 13; тот же юнит tmp.mount):
sudo systemctl edit tmp.mount
#   [Mount]
#   Options=mode=1777,strictatime,nosuid,nodev,size=2G,nr_inodes=1m
# затем перезагрузка

# Вернуть /tmp на диск: способ из журнала изменений пакета systemd (256~rc3-3, вошёл в пакет Ubuntu) и release notes Debian 13:
sudo systemctl mask tmp.mount && sudo reboot

# Отключить авто-очистку /tmp и /var/tmp целиком (пустой файл «перекрывает» штатный /usr/lib/tmpfiles.d/tmp.conf):
sudo touch /etc/tmpfiles.d/tmp.conf
# Точечно защитить отдельные файлы/каталоги от очистки — свой файл в /etc/tmpfiles.d, например local-tmp-files.conf:
#   x /var/tmp/keep-this-dir
```

Крупные и долгоживущие временные файлы (дампы, архивы, дистрибутивы) кладите на отдельный том или в специально созданный каталог (`/srv/…`, `/var/backups/…`), а не в `/tmp`; `/var/tmp` годится только для того, что нужно не дольше нескольких дней.

## Подключение и первые шаги

С Windows-хоста к ВМ удобнее всего подключаться по SSH (встроенный клиент OpenSSH в PowerShell / Windows Terminal либо PuTTY), а не работать в окне консоли гипервизора: в SSH-сессии работают буфер обмена, прокрутка и нормальная кодировка.

```powershell
# На Windows-хосте (PowerShell)
ssh admin@192.168.56.10
scp .\file.dt admin@192.168.56.10:/var/tmp/      # копирование файла на сервер
```

Строка приглашения Ubuntu: `admin@srv1c:~$` — пользователь, имя хоста, текущий каталог (`~` — домашний), `$` — обычный пользователь, `#` — root. Сразу после входа полезно выполнить:

```bash
whoami; id                 # кто я и в каких группах (есть ли sudo)
hostnamectl                # имя хоста, версия ОС, ядро, тип виртуализации
lsb_release -a             # выпуск Ubuntu
echo "$SHELL $BASH_VERSION"
df -h / /var /home /tmp    # свободное место
```

## Файловая система: стандарт FHS и что где лежит

Linux использует единое дерево каталогов от корня `/` (нет букв дисков): диски и разделы монтируются в каталоги. Раскладку описывает Filesystem Hierarchy Standard 3.0. В Ubuntu выполнено «слияние /usr»: `/bin`, `/sbin`, `/lib` — символические ссылки на `/usr/bin`, `/usr/sbin`, `/usr/lib`. Имена чувствительны к регистру (`/opt/1cv8` ≠ `/opt/1CV8`), разделитель — `/`, скрытые файлы начинаются с точки.

| Каталог | Назначение (FHS 3.0) | Что там на сервере 1С + PostgreSQL |
|---|---|---|
| `/etc` | Конфигурация этого хоста (текстовые файлы) | `/etc/postgresql/NN/main/` — `postgresql.conf`, `pg_hba.conf`, `pg_ident.conf`, `conf.d/` (пакеты Ubuntu/PGDG); `/etc/default/postgrespro-1c-NN` — путь к каталогу данных Postgres Pro; `/etc/systemd/system/` — подключённые юниты и их drop-in-переопределения; `/etc/hosts`, `/etc/hostname` (сервер 1С критичен к разрешению имён); `/etc/apache2/` — веб-сервер для публикаций; `/etc/sudoers`, `/etc/sudoers.d/`; `/etc/environment`, `/etc/profile.d/`; `/etc/fstab`; `/etc/netplan/`; `/etc/ssh/`; `/etc/sysctl.d/`; `/etc/security/limits.d/`; `/etc/cron.d/`, `/etc/logrotate.d/` |
| `/opt` | Дополнительные пакеты ПО, не входящие в дистрибутив | `/opt/1cv8/x86_64/<версия>/` — платформа 1С (`ragent`, `rmngr`, `rphost`, `ras`, `rac`, `ibcmd`, `ibsrv`, `webinst`, `wsap24.so`, файл юнита `srv1cv8-<версия>@.service`); `/opt/1cv8/x86_64/<версия>/conf/` — каталог настроек конкретной версии (`logcfg.xml`, `nethasp.ini` — подтверждено практикой сообщества; `conf.cfg` — (расположение подтверждено приложением 1 документации 8.3.27, сверено 10.10.2026) ранее не подтверждено; см. ниже); `/opt/1cv8/conf/` — общие для всех версий настройки (подтверждено приложением 1 документации 8.3.27 (сверено 10.10.2026): каталог входит в порядок поиска конфигурационных файлов и является значением `ConfLocation` по умолчанию; ранее не подтверждено, см. ниже); `/opt/pgpro/1c-NN/` — «PostgreSQL для 1С» от Postgres Professional (`bin/pg-setup`, `bin/pg-wrapper`, `bin/psql`, `bin/pg_dump`…). Старые сборки 1С (до перехода на установщик `.run`) жили в `/opt/1C/v8.3/x86_64/` со службой `srv1cv83` |
| `/var` | Изменяемые данные: БД, журналы, кэши, очереди | `/var/lib/postgresql/NN/main/` — каталог данных PostgreSQL (пакеты Ubuntu/PGDG); `/var/lib/postgresql` — домашний каталог пользователя `postgres` в этих пакетах; `/var/lib/pgpro/1c-NN/data/` — каталог данных Postgres Pro (журнал сервера — в `data/log/`); `/var/log/postgresql/postgresql-NN-main.log`; `/var/log/syslog`, `/var/log/auth.log`, `/var/log/journal/`; `/var/log/apache2/`; `/var/www/` — обычное место каталогов веб-публикаций; `/var/1C/licenses/` — программные лицензии 1С (`*.lic`) для всех пользователей компьютера (подтверждено практикой сообщества — проект onec-docker копирует файлы лицензий именно сюда и отмечает, что платформа не работает с лицензиями на файловой системе «только для чтения»; по документации ИТС не сверено — уточнено 10.10.2026 по разд. 10.3.8.3 документации 8.3.27: порядок поиска в Linux — `/opt/1cv8/<arch>/A.B.C.D/conf`, `/opt/1cv8/conf`, `~/.1cv8/conf`, каталог из `ConfLocation`, `/var/1C/licenses`, затем `~/.1cv8/1C/1cv8/` с учётом `location.cfg`; ранее: перечень *всех* каталогов поиска лицензий не подтверждён); `/var/tmp` — временные файлы, переживающие перезагрузку (на 24.10+/26.04 авто-удаление через 30 дней); `/var/backups`, `/var/cache/apt`, `/var/lib/dpkg` |
| `/home` | Домашние каталоги пользователей | `/home/usr1cv8/` — домашний каталог пользователя службы 1С; `/home/usr1cv8/.1cv8/1C/1cv8/` — данные кластера (значение `SRV1CV8_DATA` по умолчанию): `1cv8wsrv.lst` (список кластеров), `reg_1541/1CV8Clst.lst` (реестр кластера), `reg_1541/<id-базы>/1Cv8Log/` (журнал регистрации). Домашние каталоги в Ubuntu ≥ 21.04 создаются с правами `750` — посторонние пользователи (в т. ч. `postgres`) в них не попадут |
| `/usr` | Программы и библиотеки дистрибутива (только чтение при работе) | `/usr/bin`, `/usr/sbin`, `/usr/lib`; `/usr/lib/postgresql/NN/bin/` — настоящие бинарники PostgreSQL из пакетов Ubuntu/PGDG (`postgres`, `initdb`, `pg_ctl`, `pg_dump`), в `/usr/bin` — обёртки `psql`, `pg_dump`, `pg_lsclusters`, `pg_ctlcluster`; `/usr/lib/systemd/system/` — юниты из пакетов; `/usr/local/bin`, `/usr/local/sbin` — место для собственных скриптов администратора; `/usr/share/doc`, `/usr/share/man` |
| `/tmp` | Временные файлы; программа не вправе рассчитывать на их сохранность между запусками | Временные файлы утилит, `mktemp`, установщиков (и, вероятно, процессов 1С — подтверждено статьёй ИТС 1736 (каталог временных файлов сервера 1С по умолчанию — `/tmp`), сверено 10.10.2026; ранее не подтверждено документацией, см. проверку в разделе про 26.04). В 26.04 — tmpfs в ОЗУ с авто-удалением через 10 дней; в 22.04/24.04 — на диске, очищается при загрузке. Права `1777` (sticky bit: удалять файл может только его владелец, владелец каталога или root) |
| `/run` | Данные времени выполнения с момента загрузки (tmpfs, очищается при перезагрузке) | `/run/postgresql/.s.PGSQL.5432` — Unix-сокет PostgreSQL из пакетов Ubuntu/PGDG (`/var/run` — ссылка на `/run`); PID-файлы; `/run/systemd/`; `/run/user/<UID>/`. У сборок Postgres Professional (`postgrespro-std-NN`, `postgrespro-1c-NN`) сокет по умолчанию в `/tmp` (`/tmp/.s.PGSQL.5432`), как в «ванильном» PostgreSQL: документация Postgres Pro 17 — «значение по умолчанию обычно `/tmp`, но оно может быть изменено во время сборки»; для конкретного пакета `1c-NN` значение сборки по документации не подтверждено (⚠) — проверьте `SHOW unix_socket_directories;` и при подключении указывайте `psql -h /tmp` либо `-h localhost` |
| `/srv` | Данные сервисов, которые этот хост предоставляет наружу | По умолчанию пуст. Удобное место для файловых баз, каталогов обмена, общих шар Samba: `/srv/1c/…` (соглашение, не требование) |
| `/proc` | Виртуальная ФС ядра: процессы и параметры | `/proc/cpuinfo`, `/proc/meminfo`, `/proc/loadavg`, `/proc/mounts`; `/proc/<PID>/cmdline`, `environ`, `limits`, `status`, `fd/`; `/proc/sys/vm/swappiness`, `/proc/sys/vm/overcommit_memory`, `/proc/sys/vm/nr_hugepages` (то же, что `sysctl vm.…`) |
| `/sys` | Виртуальная ФС ядра: устройства и подсистемы | `/sys/kernel/mm/transparent_hugepage/enabled`, `/sys/block/sda/queue/scheduler`, `/sys/class/net/` |
| `/dev` | Файлы устройств | `/dev/null`, `/dev/zero`, `/dev/urandom`; диски `/dev/sda`, `/dev/sda1`, `/dev/nvme0n1p1`, LVM `/dev/mapper/ubuntu--vg-ubuntu--lv`; `/dev/shm` — разделяемая память POSIX (её использует PostgreSQL); `/dev/pts/N` — псевдотерминалы SSH-сессий |
| `/boot` | Ядро, initrd, загрузчик | `/boot/vmlinuz-*`, `/boot/grub/`, `/boot/efi/` (UEFI). Переполнение `/boot` старыми ядрами ломает обновления |
| `/root` | Домашний каталог root | Не путать с корнем `/` |
| `/mnt`, `/media` | Точки временного монтирования / съёмные носители | Сюда монтируют диск с резервными копиями, общую папку гипервизора, ISO |
| `/snap` | Смонтированные snap-пакеты (особенность Ubuntu, не FHS) | Обычно `snapd`, `core*`; в выводе `df`/`lsblk` дают строки `loop*` |
| `/lost+found` | Найденные `fsck` фрагменты (ext4) | В норме пуст |

Проверить фактические пути на конкретном сервере (ничего не предполагая):

```bash
ls /opt/1cv8/x86_64/                               # установленные версии платформы 1С
systemctl list-units 'srv1cv8*' 'ras*' --all       # юниты сервера 1С
sudo find /opt/1cv8 -maxdepth 4 \( -name 'conf.cfg' -o -name 'logcfg.xml' -o -name 'nethasp.ini' \) -ls
getent passwd usr1cv8 postgres                     # домашние каталоги и оболочки служебных пользователей
pg_lsclusters                                      # кластеры PostgreSQL (пакеты Ubuntu/PGDG): версия, порт, каталог данных, журнал
sudo -u postgres psql -At -c 'SHOW data_directory' -c 'SHOW config_file' -c 'SHOW hba_file'   # где данные и конфигурация
ls /opt/pgpro/ 2>/dev/null                         # установлена ли сборка Postgres Professional (std-NN, 1c-NN…)
cat /etc/default/postgrespro-1c-* 2>/dev/null      # каталог данных сборки 1c-NN (его читают pg-setup и служба)
systemctl list-units 'postgres*' --all             # postgresql@NN-main.service (Ubuntu/PGDG) или postgrespro-1c-NN.service
sudo cat /proc/"$(pgrep -o ragent)"/environ | tr '\0' '\n'   # реальное окружение работающего агента сервера 1С
systemctl cat 'srv1cv8-*@default'                  # полный текст юнита сервера 1С со всеми Environment= и ExecStart=
sudo ls -la /var/1C/licenses/ /home/usr1cv8/.1cv8/1C/1cv8/conf/ 2>/dev/null   # файлы программных лицензий и пользовательский каталог настроек
```

Про каталоги настроек платформы 1С (`logcfg.xml`, `nethasp.ini`, `conf.cfg` и другие служебные файлы). Что подтверждено и чем:

- **Старая схема (до 8.3.20)** — официальная открытая статья ИТС для 8.3.13: каталог `/opt/1C/v8.3/x86_64/conf` (создаётся вручную, туда кладут `logcfg.xml`).
- **Новая схема, каталог версии** — `/opt/1cv8/x86_64/<версия>/conf/` и **пользовательский каталог** `~usr1cv8/.1cv8/1C/1cv8/conf/` (т. е. `/home/usr1cv8/.1cv8/1C/1cv8/conf/`): практика сообщества — проект onec-docker кладёт `logcfg.xml` в оба этих каталога, а `nethasp.ini` — в `<каталог версии>/conf/`. Каталог `conf` может отсутствовать сразу после установки — его создают вручную (владелец/права — чтобы читал `usr1cv8`).
- **Общий каталог `/opt/1cv8/conf`** (общие для всех установленных версий настройки, на который ссылается `conf/conf.cfg` в каталоге версии параметром вида `ConfLocation=`) — **Уточнено 10.10.2026** (полный текст приложений 1 и 3 документации 8.3.27): для Linux порядок поиска — каталог `conf` версии, затем `/opt/1cv8/conf`, затем `~/.1cv8/1C/1cv8/conf`, затем каталог из `ConfLocation`; значение `ConfLocation` по умолчанию в Linux — `/opt/1cv8/conf`. Ранее было не подтверждено: так устроена схема в Windows (`C:\Program Files\1cv8\conf`), для Linux перенесено по аналогии и по памяти; страницы документации ИТС закрыты подпиской.
- **Платформа 8.5.x**: что она ставится в `/opt/1cv8/x86_64/8.5.x.x/` и использует ту же схему имён юнитов `srv1cv8-<версия>@.service` — уточнено 10.10.2026 сравнением документации 8.5.1 и 8.3.27: в главе о запуске компонентов схема имён юнитов не изменилась; ранее было не подтверждено (перенесено по аналогии с 8.3.20+; документация `v85*doc` на ИТС закрыта).

Поэтому на конкретном сервере не предполагайте, а смотрите: команда `find` выше покажет, какие из каталогов реально существуют; содержимое `conf.cfg` — `sudo cat /opt/1cv8/x86_64/*/conf/conf.cfg 2>/dev/null`.

Кроме сборки Postgres Professional существует сборка PostgreSQL от самой фирмы «1С» (deb-пакеты с суффиксом `.1C`, раздаются через releases.1c.ru по подписке) — она использует раскладку пакетов Debian/Ubuntu (`/etc/postgresql/NN/main`, `/var/lib/postgresql/NN/main`, `/usr/lib/postgresql/NN/bin`, `pg_lsclusters`) — ⚠ не подтверждено в этой сессии (по памяти; сайт релизов требует входа), проверяйте `pg_lsclusters` и `dpkg -l 'postgresql*'`.

Практические соглашения (практика сообщества, не требование вендоров): собственные скрипты — в `/usr/local/bin` (общие) или `~/bin`, `~/.local/bin` (личные; `~/.profile` Ubuntu добавляет их в `PATH`, если каталоги существуют); резервные копии — на отдельном томе (`/mnt/backup`, `/srv/backup`), а не в `/tmp` и не в домашнем каталоге; всё, с чем работает сервер 1С, должно принадлежать `usr1cv8:grp1cv8`, а всё, с чем работает СУБД, — `postgres:postgres`.

## Навигация и просмотр: pwd, cd, ls, tree, stat, file

### pwd, cd

```bash
pwd                 # текущий каталог (логический путь, с учётом символических ссылок)
pwd -P              # физический путь (ссылки раскрыты)
cd /var/log         # перейти по абсолютному пути
cd postgresql       # по относительному (от текущего каталога)
cd ..               # на уровень вверх;  cd ../..  — на два
cd                  # в домашний каталог (то же: cd ~)
cd -                # в предыдущий каталог ($OLDPWD) — «туда-обратно»
cd ~postgres        # в домашний каталог пользователя postgres (/var/lib/postgresql)
cd -P /opt/1cv8/current   # перейти, раскрыв символическую ссылку до реального каталога
pushd /etc/postgresql; popd; dirs -v   # стек каталогов: запомнить, вернуться, показать
```

`cd` — встроенная команда оболочки, поэтому `sudo cd /каталог` не работает («command not found»): используйте `sudo -i`, `sudo -s` или `sudo ls /каталог`.

### ls

`ls [ключи] [файл|каталог…]` — список файлов. Ключи комбинируются: `ls -lAh`.

| Ключ | Действие |
|---|---|
| `-l` | Длинный формат: тип и права, число жёстких ссылок, владелец, группа, размер, время изменения, имя |
| `-a` / `-A` | Показать скрытые (с точкой) / скрытые без `.` и `..` |
| `-h` / `--si` | Размеры в K/M/G по 1024 / по 1000 (вместе с `-l` или `-s`) |
| `-t` / `-S` / `-X` / `-v` | Сортировка: по времени изменения (новые сверху) / по размеру (крупные сверху) / по расширению / «естественная» по номерам версий |
| `-r` | Обратный порядок сортировки (`-ltr` — самые свежие внизу, удобно в терминале) |
| `-R` | Рекурсивно по подкаталогам |
| `-d` | Показать сам каталог, а не его содержимое (`ls -ld /var/lib/postgresql`) |
| `-1` | По одному имени в строке |
| `-i` | Номер inode (для проверки жёстких ссылок) |
| `-n` | Как `-l`, но числовые UID/GID (полезно, когда владельца нет в `/etc/passwd`) |
| `-F` / `-p` | Добавить признак типа (`/` каталог, `*` исполняемый, `@` ссылка, `=` сокет, `\|` FIFO) / только `/` каталогам |
| `-c` / `-u` | Показывать и сортировать по ctime (смена атрибутов) / atime (доступ) вместо mtime |
| `-s`, `--block-size=M` | Занятое место в блоках / единица размера |
| `-L` | Для ссылок показывать сведения о цели |
| `-Z` | Контекст безопасности SELinux (в Ubuntu с AppArmor обычно показывает `?`) |
| `--time-style=long-iso` | Дата вида `2026-10-10 14:05`; также `full-iso`, `iso`, `locale`, `+ФОРМАТ` (как у `date`) |
| `--full-time` | То же, что `-l --time-style=full-iso` (с секундами и часовым поясом) |
| `--group-directories-first` | Каталоги перед файлами |
| `--color=auto\|always\|never` | Раскраска (в Ubuntu `ls` — алиас на `ls --color=auto`) |
| `-N`, `-Q`, `-b` | Имена без кавычек / в двойных кавычках / с C-экранированием непечатных символов |
| `-o` / `-g` | Длинный формат без столбца группы / без столбца владельца |
| `-I ШАБЛОН`, `--hide=ШАБЛОН` | Не показывать имена, подходящие под шаблон оболочки (`ls -I '*.bak'`); `--hide` отменяется ключами `-a`/`-A` |
| `-B` | Не показывать резервные копии (`имя~`) |
| `-U` / `-f` | Не сортировать (порядок каталога) / то же плюс `-a` — заметно быстрее на каталогах с сотнями тысяч файлов |
| `--sort=СЛОВО`, `--time=СЛОВО` | Сортировка словом: `size`, `time`, `version`, `extension`, `none` / какое время показывать и по какому сортировать: `atime`, `ctime`, `birth` (время создания) |
| `-m`, `-x`, `-C`, `-w N` | Через запятую / по строкам / по столбцам / ширина вывода |
| `--zero` | Разделять имена нулевым байтом (GNU ≥ 9.0, т. е. 24.04+; в uutils 26.04 тоже есть) |

Первый символ в `-l`: `-` файл, `d` каталог, `l` символическая ссылка, `b`/`c` блочное/символьное устройство, `s` сокет, `p` именованный канал. Код возврата `ls`: 0 — успех, 1 — мелкие проблемы (нет доступа к подкаталогу), 2 — серьёзные (нет доступа к аргументу командной строки).

```bash
ls -lAh --group-directories-first /etc/postgresql/16/main
ls -ltr /var/log/postgresql | tail -5          # пять самых свежих журналов
ls -lhS /var/backups/pg | head                 # самые большие файлы
ls -ld /home/usr1cv8/.1cv8 /var/lib/postgresql/16/main   # права и владелец самих каталогов
ls -l --time-style=long-iso /opt/1cv8/x86_64/  # установленные версии платформы с датами
ls -d /opt/1cv8/x86_64/*/                      # только каталоги
sudo ls -la /var/lib/postgresql/16/main        # каталог данных доступен только postgres (0700/0750)
```

Стандартные алиасы из `~/.bashrc` Ubuntu: `ll` = `ls -alF`, `la` = `ls -A`, `l` = `ls -CF`. У служебных пользователей (`postgres`, `usr1cv8`) и в скриптах этих алиасов нет. При выводе в терминал `ls` берёт имена с пробелами и спецсимволами в кавычки (`'Мои документы'`) — кавычек в самом имени нет; отключается ключом `-N`. Не разбирайте вывод `ls` в скриптах — используйте шаблоны оболочки или `find`.

### tree

Не установлен по умолчанию: `sudo apt install tree` (компонент universe во всех трёх LTS).

```bash
tree -L 2 /opt/1cv8                 # дерево на 2 уровня
tree -d -L 3 /home/usr1cv8/.1cv8    # только каталоги
tree -a -h -D -pug /etc/postgresql  # скрытые, размеры, даты, права/владелец/группа
sudo tree -L 1 -I 'pg_wal|base' /var/lib/postgresql/16/main   # исключить по шаблону (каталог данных читается только от postgres/root)
tree --du -h -L 1 /var/log          # с суммарными размерами каталогов
tree -f -P '*.conf' --prune /etc/postgresql         # полные пути, только *.conf, без пустых веток
```

### stat и file

```bash
stat /etc/hosts                           # всё о файле: размер, inode, права, владелец, времена atime/mtime/ctime/birth
stat -c '%U:%G %a %s %y %n' /etc/hosts    # свой формат: владелец:группа, права (восьмерично), байты, mtime, имя
stat -c '%a %U %G' /var/lib/postgresql/16/main   # ожидаемо: 700 (или 750) postgres postgres
stat -L -c '%n -> %s байт' /opt/1cv8/current     # -L: следовать по ссылке
stat -f /var/lib/postgresql               # сведения о файловой системе (тип, блоки, inode)
```

Основные спецификаторы `-c`: `%n` имя, `%N` имя с целью ссылки, `%s` размер в байтах, `%a`/`%A` права числом/буквами, `%U`/`%G` (`%u`/`%g`) владелец/группа именем (числом), `%y`/`%Y` mtime текстом/в секундах эпохи, `%x` atime, `%z` ctime, `%w` время создания, `%i` inode, `%h` число жёстких ссылок, `%F` тип. Три времени: **mtime** — изменение содержимого, **ctime** — изменение метаданных (права, владелец, переименование), **atime** — последнее чтение (на практике обновляется редко из-за опции монтирования `relatime`).

```bash
file /opt/1cv8/x86_64/*/ragent    # ELF 64-bit LSB … x86-64 — тип по содержимому, а не по расширению
file -i backup.dump               # MIME-тип и кодировка
file -b script.sh                 # кратко, без имени; «with CRLF line terminators» → файл сохранён в Windows
sudo file -s /dev/sda1            # что находится на блочном устройстве (тип ФС)
file -L /opt/1cv8/current         # следовать по ссылке;  file -z архив.gz — заглянуть внутрь сжатого
```

## Создание, копирование, перемещение, удаление

### touch, mkdir

```bash
touch file.txt                       # создать пустой файл или обновить mtime/atime существующего
touch -c file.txt                    # не создавать, если файла нет
touch -d '2026-10-01 03:00' f        # задать время (строка как у date -d);  -t 202610010300 — формат [[CC]YY]MMDDhhmm
touch -r образец f                   # взять время у другого файла
mkdir dir                            # создать каталог
mkdir -p /srv/1c/exchange/in         # создать всю цепочку; не ругаться, если уже есть
mkdir -p /var/backups/{pg,1c}/{daily,weekly}   # вместе с brace expansion — 4 каталога разом
sudo mkdir -m 750 /srv/1c && sudo chown usr1cv8:grp1cv8 /srv/1c   # сразу с правами, затем владелец
sudo install -d -o postgres -g postgres -m 750 /var/backups/pg    # каталог + владелец + права одной командой
```

Права новых файлов и каталогов определяет `umask` (в Ubuntu обычно `0002` у пользователя с личной группой или `0022`): файл получает `666 & ~umask`, каталог — `777 & ~umask`.

### cp

`cp [ключи] источник… назначение`. Если назначение — существующий каталог, источник копируется *внутрь* него.

| Ключ | Действие |
|---|---|
| `-r`, `-R` | Рекурсивно (каталоги). Время и владелец **не** сохраняются (владельцем копии становится тот, кто копирует; права — с учётом `umask`) |
| `-a`, `--archive` | Архивный режим: то же, что `-dR --preserve=all` — рекурсивно, ссылки как ссылки, сохраняются права, владелец, время, xattr/ACL. Основной режим для переноса данных |
| `-p` | `--preserve=mode,ownership,timestamps` |
| `--preserve=СПИСОК` | Выборочно: `mode`, `ownership`, `timestamps`, `links`, `context`, `xattr`, `all` |
| `-d` | Копировать сами символические ссылки, сохранять жёсткие |
| `-L` / `-P` | Следовать по ссылкам (копировать содержимое) / никогда не следовать |
| `-i` / `-n` / `-u` | Спросить перед перезаписью / не перезаписывать / копировать только более новые |
| `--update=none` | Не перезаписывать существующие и не считать это ошибкой (GNU coreutils ≥ 9.3, т. е. **24.04 и 26.04; в 22.04 с coreutils 8.32 этой формы нет** — там только `-n`). См. ниже |
| `--no-preserve=СПИСОК` | Наоборот, *не* сохранять перечисленные атрибуты (`cp -a --no-preserve=ownership …`) |
| `--reflink[=auto\|always\|never]` | Копирование «клоном» (CoW) на Btrfs/XFS; с coreutils 9.0 режим `auto` включён по умолчанию, на ext4 просто идёт обычное копирование |
| `-v` | Печатать, что копируется |
| `-t КАТАЛОГ` | Назначение первым аргументом (удобно с `xargs`/`find -exec … +`) |
| `-T` | Считать назначение обычным файлом/каталогом, а не «каталогом, внутрь которого» |
| `-x` | Не выходить за пределы одной файловой системы |
| `-b`, `--backup=numbered` | Сохранять перезаписываемые файлы как `имя~` / `имя.~1~` |
| `--parents` | Воссоздать путь источника под каталогом назначения |
| `--sparse=always` | Создавать разреженные файлы (образы дисков) |
| `-l` / `-s` | Вместо копий — жёсткие / символические ссылки |

```bash
sudo cp -a /etc/postgresql/16/main/postgresql.conf{,.bak-$(date +%F)}   # резервная копия конфига перед правкой
sudo cp -a /home/usr1cv8/.1cv8 /mnt/backup/usr1cv8-1cv8-$(date +%F)    # копия данных кластера 1С с владельцем и правами (делать при ОСТАНОВЛЕННОМ сервере 1С, иначе копия несогласованна)
cp -a src/. dst/            # содержимое src (включая скрытые файлы) в существующий dst
cp -r src dst               # если dst существует → получится dst/src; если нет → dst станет копией src
cp -av --parents etc/hosts /mnt/backup/    # → /mnt/backup/etc/hosts
cp --update=none *.dt /srv/1c/dt/          # не трогать уже существующие (24.04/26.04; на 22.04 пишите cp -n)
```

Важно: сохранить *владельца* может только root (`sudo cp -a`); обычный пользователь получит копии на своё имя.

`cp -n` (не перезаписывать) ведёт себя по-разному в разных версиях — проверено по NEWS coreutils, журналу изменений пакета Ubuntu и man-странице noble:

| Где | Поведение `cp -n` при существующем файле назначения |
|---|---|
| Ubuntu 22.04 (GNU 8.32) | Тихо пропускает, код возврата 0. `--update=none` **не поддерживается** |
| upstream GNU 9.2–9.4 | Пропускает, но код возврата **ненулевой** (с 9.3 ещё и сообщение об ошибке) |
| Ubuntu 24.04 (GNU 9.4 **с правкой Debian**, `9.4-3` и новее) | Поведение возвращено к старому: пропускает, код возврата 0 (man: «do not overwrite an existing file and do not fail… equivalent to --update=none»), но печатает предупреждение `cp: warning: behavior of -n is non-portable and may change in future; use --update=none instead` — оно попадёт в stderr скриптов и письма cron |
| upstream GNU 9.5+ (в т. ч. GNU `cp` 9.7 в Ubuntu 26.04) | Снова тихо пропускает с кодом 0; ключ `-n` объявлен нежелательным («best avoided due to platform differences») |

Вывод для скриптов: на 24.04/26.04 пишите `--update=none` (тихо пропустить, код 0); если пропуск должен считаться ошибкой — `--update=none-fail` (заявлен в 9.5, но фактически работает только с 9.6 — в 9.5 ключ ошибочно отвергался; в Ubuntu 26.04 с GNU 9.7 доступен, в 24.04 его нет); на 22.04 остаётся только `cp -n`. Если скрипт должен работать на всех трёх LTS — проверяйте существование сами: `[[ -e "$dst" ]] || cp -a "$src" "$dst"`. Про `mv -n`: в upstream его поведение менялось так же, как у `cp -n`, но правка Debian в журнале изменений описана только для `cp -n` — значит, в 24.04 `mv -n` при пропуске, по-видимому, возвращает ненулевой код (⚠ не подтверждено на живой системе; проверьте `mv -n a b; echo $?`). Для больших объёмов и копирования по сети удобнее `rsync -a` (отдельная статья).

### mv

```bash
mv old.txt new.txt                 # переименовать
mv file1 file2 /каталог/           # переместить несколько объектов в каталог
mv -i src dst                      # спросить перед перезаписью;  -n — не перезаписывать;  -v — показывать
mv -t /mnt/backup/ *.dump          # назначение первым аргументом
mv -T newdir dir                   # заменить каталог целиком, а не положить внутрь
sudo mv /var/lib/pgpro/1c-17/data{,.old}   # типовой приём: отложить старый каталог перед пересозданием (только при ОСТАНОВЛЕННОЙ СУБД)
mv -u src/* dst/                   # -u: переносить только то, чего нет в dst или что новее;  -b / --backup=numbered — сохранять перезаписываемое
```

В пределах одной файловой системы `mv` — мгновенное атомарное переименование (данные не копируются), владелец и права сохраняются. Между разными ФС `mv` = копирование + удаление: долго, требует места, и при обрыве остаются обе неполные копии — большие каталоги между дисками переносите `rsync -a` с последующей проверкой.

### rm, rmdir

```bash
rm file                      # удалить файл
rm -i *.log                  # спрашивать о каждом;  -I — один вопрос, если файлов > 3 или задан -r
rm -r dir                    # каталог с содержимым
rm -rf dir                   # то же без вопросов и без ошибок на несуществующее
rm -v -- -странное-имя       # «--» завершает ключи: всё дальше — имена файлов
rm -rf --one-file-system /mnt/x/   # не заходить в подмонтированные внутрь файловые системы
rmdir dir                    # удалить ПУСТОЙ каталог (безопаснее rm -r)
rmdir -p a/b/c               # удалить цепочку пустых каталогов
```

Правила безопасности: корзины нет; `rm -rf /` блокируется защитой `--preserve-root`, но `rm -rf /*` и `rm -rf "$DIR"/*` при пустой `DIR` — нет. В скриптах пишите `rm -rf -- "${DIR:?переменная DIR пуста}/"*` и проверяйте шаблон через `ls`/`echo` перед удалением. Удалённый файл, который держит открытым работающий процесс (типично — журнал), место не освобождает до закрытия: ищите такие `sudo lsof +L1`, обнуляйте журнал `: > file` или `truncate -s 0 file` вместо удаления.

### ln: жёсткие и символические ссылки; readlink, realpath

| | Символическая (`ln -s`) | Жёсткая (`ln`) |
|---|---|---|
| Что это | Отдельный файл-указатель с путём к цели | Ещё одно имя того же inode |
| Каталоги | Да | Нет |
| Между файловыми системами | Да | Нет |
| Если удалить оригинал | Ссылка «висит» (broken) | Данные живы, пока есть хоть одно имя |
| Вид в `ls -l` | `lrwxrwxrwx … имя -> цель` | Обычный файл, счётчик ссылок > 1 |

```bash
sudo ln -s /opt/1cv8/x86_64/8.3.27.1688 /opt/1cv8/current    # символическая ссылка: ln -s ЦЕЛЬ ИМЯ_ССЫЛКИ
sudo ln -sfn /opt/1cv8/x86_64/8.3.27.1700 /opt/1cv8/current   # переключить ссылку на каталог: -f заменить, -n не заходить внутрь
sudo ln -s /opt/1cv8/x86_64/8.3.27.1700 /opt/1cv8/current.new && sudo mv -T /opt/1cv8/current.new /opt/1cv8/current   # то же гарантированно атомарно (один rename)
sudo ln -s /opt/1cv8/current/rac /usr/local/bin/rac     # сделать утилиту доступной в PATH (и через sudo)
ln -sr ../shared/conf conf        # -r: относительная ссылка (переживает перенос дерева целиком)
ln file hardlink                  # жёсткая ссылка
ls -li file hardlink              # одинаковый inode и счётчик ссылок 2
find -L /opt/1cv8 -maxdepth 2 -type l      # «висячие» ссылки (с -L тип l остаётся только у битых)

readlink /opt/1cv8/current        # куда указывает ссылка (один шаг, как записано)
readlink -f /usr/bin/psql         # полный канонический путь (все ссылки раскрыты)
realpath ./conf/../data           # абсолютный нормализованный путь;  -e — требовать существование;  -m — не требовать
realpath --relative-to=/opt /opt/1cv8/conf   # → 1cv8/conf
realpath -s ../file               # нормализовать, не раскрывая ссылки
```

Ссылка `/opt/1cv8/current` — распространённая практика сообщества (стабильный путь к «текущей» версии платформы для `PATH` и скриптов; так делает, например, проект onec-docker), а не часть установщика 1С. Права на самой символической ссылке (`lrwxrwxrwx`) ничего не значат — действуют права цели. Об атомарности `ln -sf`: GNU coreutils с 8.27 при `-f` не удаляет старое имя перед созданием нового (NEWS 8.27: «commands like 'ln -f A B' and 'cp -fl A B' no longer remove B before creating the new link»); в актуальном коде uutils `ln` сделано так же (временное имя + `renameat`), но для версий 0.8.0/0.10.0 из 26.04 это не проверено (⚠) — если пропадание ссылки даже на миг недопустимо (её читает работающая служба), используйте вариант с `mv -T`: `mv` в пределах одной ФС — это один системный вызов `rename`. Битые ссылки ищет также `find /путь -xtype l`.

### basename, dirname, mktemp

```bash
basename /var/backups/pg/base1.dump          # base1.dump
basename /var/backups/pg/base1.dump .dump    # base1 (отрезать суффикс);  то же: basename -s .dump …
dirname  /var/backups/pg/base1.dump          # /var/backups/pg
f=/var/backups/pg/base1.dump
echo "${f##*/}  ${f%/*}  ${f%.dump}"         # то же средствами bash, без запуска процессов
script_dir=$(dirname "$(realpath "$0")")     # каталог, где лежит выполняемый скрипт

tmp=$(mktemp)                        # безопасно создать уникальный файл /tmp/tmp.XXXXXXXXXX с правами 600
tmpd=$(mktemp -d)                    # временный каталог (права 700)
mktemp -p /var/tmp dump.XXXXXX       # в заданном каталоге по шаблону (минимум три X в конце)
mktemp --suffix=.sql                 # с расширением
trap 'rm -rf -- "$tmpd"' EXIT        # в скрипте: убрать за собой при любом завершении
```

Не придумывайте имена временных файлов сами (`/tmp/my.tmp`, `/tmp/x.$$`) — это гонки и атаки через символические ссылки; `mktemp` создаёт файл атомарно. В 26.04 `/tmp` находится в памяти — для больших временных файлов задавайте `-p /var/tmp`.

## Поиск файлов и команд

### find

`find [где…] [условия] [действие]` — обход дерева каталогов в реальном времени. Условия по умолчанию соединяются через «И»; `-o` — «ИЛИ», `!` (или `-not`) — отрицание, группировка — `\( … \)`. Действие по умолчанию — `-print`. В 26.04 `find` и `xargs` остались GNU-шными.

| Условие / действие | Смысл |
|---|---|
| `-name 'шаблон'` / `-iname` | Имя файла (без пути) по шаблону оболочки / без учёта регистра. Шаблон обязательно в кавычках |
| `-path 'шаблон'` / `-regex 'рв'` | Совпадение по всему пути / регулярное выражение по всему пути (диалект Emacs; сменить — `-regextype posix-extended`) |
| `-type f\|d\|l\|b\|c\|p\|s` | Тип: файл, каталог, ссылка, блочное, символьное устройство, FIFO, сокет (можно списком `-type f,l`) |
| `-mtime N` / `-mmin N` | Изменён N суток / минут назад. `+N` — больше, `-N` — меньше. Дробная часть суток отбрасывается: `-mtime +7` = «не менее 8 полных суток назад», `-mtime -1` = «за последние 24 часа» |
| `-newer файл`, `-newermt 'дата'` | Новее, чем файл / чем указанная дата (`-newermt '2026-10-01 00:00'`) |
| `-daystart` | Считать сутки от полуночи, а не от текущего момента |
| `-size N[ckMG]` | Размер: `c` байты, `k`, `M`, `G`; без суффикса — блоки по 512 байт. **Округление вверх**: `-size -1M` находит только пустые файлы; «меньше 1 МиБ» пишется `-size -1048576c` |
| `-empty` | Пустые файлы и каталоги |
| `-user имя`, `-group имя`, `-uid N`, `-nouser`, `-nogroup` | По владельцу/группе; `-nouser` — владелец отсутствует в системе |
| `-perm 640` / `-perm -g+w` / `-perm /o+w` | Права: точно / все перечисленные биты / любой из перечисленных |
| `-maxdepth N`, `-mindepth N` | Ограничить глубину (`-maxdepth 1` — стартовый каталог и его непосредственное содержимое, без спуска в подкаталоги; `-mindepth 1` — исключить саму стартовую точку). Пишутся первыми |
| `-xdev` (`-mount`) | Не заходить на другие файловые системы |
| `-prune` | Не спускаться в каталог: `find / -path /proc -prune -o -name 'x' -print` |
| `-L` / `-P` / `-H` | Следовать по ссылкам / не следовать (по умолчанию) / только для аргументов командной строки |
| `-print0` | Разделять имена нулевым байтом (для `xargs -0`) — единственный безопасный способ для имён с пробелами и переводами строк |
| `-printf 'формат'` | Свой вывод: `%p` путь, `%f` имя, `%s` байты, `%u`/`%g` владелец/группа, `%m` права, `%TY-%Tm-%Td %TT` дата и время изменения; `\n` нужно писать явно |
| `-ls` | Вывод как `ls -dils` |
| `-exec cmd {} \;` | Запустить `cmd` для **каждого** найденного файла отдельно |
| `-exec cmd {} +` | Запустить `cmd` с пачкой файлов (как `xargs`) — намного быстрее |
| `-execdir cmd {} \;` | То же, но из каталога найденного файла (безопаснее) |
| `-ok cmd {} \;` | Как `-exec`, но с подтверждением каждого запуска |
| `-delete` | Удалить найденное. Включает `-depth`. **Ставить последним**: `find . -delete -name '*.tmp'` удалит всё |
| `-quit` | Остановиться после первого совпадения |

```bash
# По имени
sudo find /opt/1cv8 -maxdepth 3 -type f -name 'rac'                   # где лежит утилита rac
sudo find / -xdev -iname '*logcfg.xml*' 2>/dev/null                    # по всей корневой ФС, без «Permission denied»
sudo find /etc -type f -name '*.conf' -newermt '2026-10-01'            # конфиги, изменённые с 1 октября

# По времени и размеру
find /var/backups/pg -type f -name '*.dump' -mtime +7 -print           # старше ~8 суток — СНАЧАЛА посмотреть
find /var/backups/pg -type f -name '*.dump' -mtime +7 -delete          # …потом удалить
sudo find /var/log -type f -mmin -10                                   # что писалось за последние 10 минут
sudo find / -xdev -type f -size +1G -exec ls -lh {} + 2>/dev/null      # файлы больше 1 ГиБ
sudo find /var/lib/postgresql -type f -printf '%s\t%p\n' | sort -nr | head -20   # 20 самых больших файлов

# По владельцу и правам
sudo find /home/usr1cv8/.1cv8 ! -user usr1cv8 -ls                      # файлы кластера 1С с «чужим» владельцем (частая причина сбоев)
sudo find /home/usr1cv8/.1cv8 ! -user usr1cv8 -exec chown usr1cv8:grp1cv8 {} +   # исправить
sudo find /srv/1c -type d -exec chmod 750 {} + -o -type f -exec chmod 640 {} +   # каталогам 750, файлам 640
sudo find / -xdev -nouser -o -nogroup 2>/dev/null                      # «бесхозные» файлы

# Действия над найденным
find . -type f -name '*.sh' -exec grep -l 'pg_dump' {} +               # в каких скриптах встречается pg_dump
find . -type f -name '*.log' -print0 | xargs -0 -r gzip -9             # сжать; -r — не запускать при пустом вводе
find . -type f -name '*.gz' -print0 | xargs -0 -r -n 50 -P 4 rm -f --  # пачками по 50, в 4 потока
find /tmp -maxdepth 1 -user "$USER" -empty -delete                     # убрать свои пустые файлы и каталоги
find . -type f \( -name '*.dt' -o -name '*.cf' \) -size +100M          # группировка условий
```

`xargs` (спутник `find`): `-0` — ввод, разделённый нулями; `-r` — не выполнять команду при пустом вводе (у GNU xargs); `-n N` — по N аргументов за запуск; `-P N` — N параллельных процессов; `-I {}` — подставить аргумент в указанное место (`… | xargs -I {} mv {} /dst/`).

### locate, updatedb

`locate` ищет по заранее построенной базе имён — мгновенно, но не видит файлы, созданные после последнего обновления базы. В Ubuntu 22.04+ это пакет `plocate` (не установлен по умолчанию; в 24.04 и 26.04 — из компонента universe).

## Шаблоны, кавычки, подстановки

Прежде чем выполнить команду, bash преобразует строку в таком порядке (Bash Reference Manual): 1) раскрытие фигурных скобок; 2) слева направо — тильда, параметры и переменные, арифметика, подстановка команд (и подстановка процессов); 3) разбиение на слова по `$IFS`; 4) раскрытие шаблонов имён файлов; 5) удаление кавычек. Команда получает уже готовый список аргументов — `ls *.txt` сам `ls` звёздочку не видит.

### Шаблоны имён файлов (globbing)

| Шаблон | Совпадает с |
|---|---|
| `*` | Любая строка, в том числе пустая (кроме имён, начинающихся с точки, и символа `/`) |
| `?` | Ровно один любой символ |
| `[abc]`, `[a-z]`, `[0-9]` | Один символ из набора / диапазона |
| `[!abc]`, `[^abc]` | Один символ не из набора |
| `[[:digit:]]`, `[[:alpha:]]`, `[[:space:]]`, `[[:upper:]]` | Классы символов POSIX |
| `**` | Рекурсивно по подкаталогам — только после `shopt -s globstar` |
| `?(p)`, `*(p)`, `+(p)`, `@(p1\|p2)`, `!(p)` | Расширенные шаблоны extglob: 0–1, 0+, 1+, ровно один из, всё кроме. В интерактивном bash Ubuntu обычно уже включены (пакет bash-completion), в скриптах — `shopt -s extglob` |

```bash
ls /var/log/postgresql/postgresql-1[5-8]-main.log*     # журналы версий 15–18 с ротацией
ls -d /opt/1cv8/x86_64/8.3.2[0-9].*                    # версии платформы 8.3.20–8.3.29
ls -d .[!.]*                                           # скрытые файлы и каталоги (без . и ..)
shopt -s globstar; ls -l /etc/**/*.conf                # все .conf рекурсивно
rm -- !(*.conf)                                        # всё, кроме *.conf (extglob)
echo /opt/1cv8/x86_64/*/ragent                         # echo + шаблон = безопасно посмотреть, во что он раскроется
```

Важные свойства: шаблон раскрывает оболочка, причём с правами **текущего** пользователя, до запуска `sudo`; если ничего не подошло, шаблон передаётся команде **как есть** (отсюда `ls: cannot access '*.dump': No such file or directory`); изменить это — `shopt -s nullglob` (пустой список) или `failglob` (ошибка); `shopt -s dotglob` включает в `*` скрытые файлы. Шаблоны — не регулярные выражения: `*` здесь «что угодно», а в регулярном выражении — «повтор предыдущего».

### Кавычки и экранирование

| Запись | Что происходит внутри |
|---|---|
| `'…'` | Ничего не раскрывается, всё буквально. Вставить апостроф внутрь нельзя (приём: `'it'\''s'`) |
| `"…"` | Раскрываются `$переменные`, `$(команды)`, `` `команды` ``, `$((арифметика))`; `\` экранирует только `$`, `` ` ``, `"`, `\` и перевод строки. Шаблоны и разбиение на слова **не** действуют |
| `\x` | Экранирует один следующий символ; `\` в конце строки — продолжение команды на следующей строке |
| `$'…'` | ANSI-C-строка: `$'\n'`, `$'\t'`, `$'\e[1m'`, `$'\x41'` |

```bash
name='Отчёт за октябрь.txt'
touch "$name"        # один файл с пробелами в имени
touch $name          # ОШИБКА: три файла — «Отчёт», «за», «октябрь.txt»
rm "$name"
echo "Сегодня $(date +%F), пользователь $USER, дом: $HOME"
echo 'Буквально: $HOME и $(date)'
sudo -u postgres psql -c "SELECT datname FROM pg_database WHERE datname = 'base1';"   # SQL с апострофами — в двойных кавычках
sudo -u postgres psql -c 'SELECT "ИмяКолонки" FROM t;'                                # SQL с двойными кавычками — в одинарных
grep -r 'listen_addresses' /etc/postgresql/      # шаблоны/регулярные выражения для grep, find, sed — всегда в кавычках
```

В двойных кавычках в интерактивной оболочке срабатывает `!` (подстановка истории): `echo "Готово!"` даст ошибку `event not found` — пишите `'Готово!'` или отключите `set +H`. `"$@"` — все аргументы скрипта, каждый отдельным словом (правильно); `$*` и `$@` без кавычек — режутся по пробелам.

### Переменные и подстановка параметров

```bash
var=значение          # присваивание: БЕЗ пробелов вокруг «=»
var="два слова"
echo "$var" "${var}_suffix"     # фигурные скобки отделяют имя от следующего текста
readonly PGVER=17               # константа
unset var                       # удалить
```

| Запись | Результат |
|---|---|
| `${var:-умолч}` | Значение `var`, а если пусто или не задано — `умолч` (сама `var` не меняется) |
| `${var:=умолч}` | То же, но ещё и присвоить `var` |
| `${var:?сообщение}` | Если пусто или не задано — ошибка с сообщением и выход из скрипта (защита `rm -rf "${DIR:?}/"`) |
| `${var:+альт}` | `альт`, если `var` непуста; иначе пусто |
| `${#var}` | Длина строки |
| `${var#шабл}` / `${var##шабл}` | Отрезать с начала самое короткое / самое длинное совпадение |
| `${var%шабл}` / `${var%%шабл}` | Отрезать с конца самое короткое / самое длинное совпадение |
| `${var/что/чем}` / `${var//что/чем}` | Заменить первое / все вхождения |
| `${var:смещ:длина}` | Подстрока |
| `${var^^}` / `${var,,}` | В верхний / нижний регистр |
| `${!имя}` | Косвенная ссылка: значение переменной, чьё имя хранится в `имя` |
| `${var@Q}` | Значение в виде, безопасном для повторного ввода в оболочку |

Специальные параметры: `$?` — код возврата последней команды; `$$` — PID оболочки; `$!` — PID последнего фонового задания; `$0` — имя скрипта; `$1…$9`, `${10}` — аргументы; `$#` — их число; `$@`, `$*` — все аргументы; `$_` — последний аргумент предыдущей команды; `$-` — флаги оболочки (есть `i` → интерактивная).

```bash
f=/var/backups/pg/base1_2026-10-10.dump
echo "${f##*/}"        # base1_2026-10-10.dump   (имя файла)
echo "${f%/*}"         # /var/backups/pg         (каталог)
echo "${f%.dump}.log"  # замена расширения
db=${1:-base1}         # первый аргумент скрипта или значение по умолчанию
: "${PGPORT:=5432}"    # задать значение по умолчанию, если переменная пуста
```

### Подстановка команд, арифметика, подстановка процессов

```bash
today=$(date +%F)                         # $(…) — вывод команды как строка (хвостовые переводы строк отрезаются)
files=$(ls | wc -l)                       # старая форма `…` работает, но вкладывается только с экранированием и хуже читается
cfg=$(< /etc/hostname)                    # содержимое файла без запуска cat
echo "Ядро: $(uname -r), версий 1С: $(ls -d /opt/1cv8/x86_64/*/ 2>/dev/null | wc -l)"
echo $(( (1024 * 8) / 3 ))                # целочисленная арифметика: + - * / % ** << >> & |
n=$(( n + 1 )); (( n++ )); (( n > 5 )) && echo 'больше пяти'
diff <(ls /etc/postgresql/16/main) <(ls /etc/postgresql/17/main)     # <(cmd) — вывод команды как «файл»
sudo -u postgres pg_dump -Fc base1 | tee >(sha256sum > /var/tmp/base1.sha256) > /var/tmp/base1.dump   # >(cmd) — «файл» для записи
```

В bash 5.3 (Ubuntu 26.04; проверено по NEWS bash 5.3 и man-странице `bash` пакета `5.3-2ubuntu1`) добавлены формы `${ команда; }` (команда выполняется в текущей среде оболочки, без порождения подпроцесса; вывод захватывается, хвостовые переводы строк отрезаются; после `{` обязателен пробел, табуляция или перевод строки, а `}` должна стоять там, где допустимо зарезервированное слово, — отсюда `;` перед ней) и `${| команда; }` (подставляется значение переменной `REPLY` после выполнения команды, хвостовые переводы строк **не** отрезаются), а также переменная `GLOBSORT` (порядок сортировки результатов раскрытия шаблонов; по man-странице допустимые спецификаторы — `name`, `numeric`, `size`, `mtime`, `atime`, `ctime`, `blocks`; с префиксом `-` — по убыванию; есть и спецификатор отключения сортировки — его точное написание смотрите в `man bash`, раздел GLOBSORT). В скриптах, которые должны работать и на 22.04/24.04, их не используйте.

```bash
# только bash 5.3+ (Ubuntu 26.04):
now=${ date +%F; }                        # как $(date +%F), но без порождения подпроцесса
host=${| REPLY=${HOSTNAME%%.*}; }         # результат берётся из переменной REPLY
GLOBSORT=-mtime; printf '%s\n' /var/backups/pg/*.dump   # шаблон раскроется по убыванию mtime (свежие первыми); ls здесь не годится — он пересортирует сам
```

### Раскрытие фигурных скобок (brace expansion)

Чисто текстовая генерация строк; выполняется самым первым, существование файлов не проверяется, в кавычках не работает.

```bash
echo {a,b,c}.txt                 # a.txt b.txt c.txt
echo {1..5} {01..10} {a..e}      # диапазоны; ведущий ноль сохраняет ширину
echo {0..20..5}                  # с шагом: 0 5 10 15 20
cp postgresql.conf{,.bak}        # = cp postgresql.conf postgresql.conf.bak
mv file.{txt,md}                 # = mv file.txt file.md
mkdir -p /srv/1c/{bases,exchange/{in,out},logs}
for n in {1..3}; do echo "rphost_$n"; done
n=5; echo {1..$n}                # НЕ работает ({1..5} раскрывается раньше переменных) → используйте $(seq 1 "$n")
```

## Перенаправления, конвейеры, tee, /dev/null

У каждого процесса три стандартных потока: **0 — stdin** (ввод), **1 — stdout** (вывод), **2 — stderr** (сообщения об ошибках). Перенаправления обрабатываются слева направо.

| Оператор | Действие |
|---|---|
| `cmd > file` | stdout в файл (файл создаётся или **обнуляется**) |
| `cmd >> file` | stdout в конец файла (дозапись) |
| `cmd 2> file`, `cmd 2>> file` | stderr в файл / дозапись |
| `cmd > file 2>&1` | stdout и stderr в один файл («направить 2 туда же, куда сейчас смотрит 1») |
| `cmd &> file`, `cmd &>> file` | То же короче (только bash) / с дозаписью |
| `cmd > out.log 2> err.log` | Потоки в разные файлы |
| `cmd 2>/dev/null` | Выбросить ошибки; `cmd >/dev/null 2>&1` или `cmd &>/dev/null` — выбросить всё |
| `cmd >&2` | Писать в stderr (для сообщений об ошибках в скриптах: `echo 'Ошибка' >&2`) |
| `cmd < file` | stdin из файла |
| `cmd <<EOF … EOF` | here-document: stdin из следующих строк до строки-ограничителя; переменные и `$(…)` раскрываются |
| `cmd <<'EOF' … EOF` | here-document **без** раскрытия (ограничитель в кавычках) — так передают SQL и скрипты буквально |
| `cmd <<-EOF … EOF` | То же, но ведущие табуляции (не пробелы) удаляются — для отступов в скриптах |
| `cmd <<< "строка"` | here-string: строка (с добавленным переводом строки) на stdin |
| `cmd1 \| cmd2` | Конвейер: stdout первой команды → stdin второй |
| `cmd1 \|& cmd2` | То же вместе со stderr (сокращение для `2>&1 \|`) |
| `cmd >\| file` | Перезаписать файл даже при включённом `set -o noclobber` |
| `cmd <> file` | Открыть файл на чтение и запись |
| `exec > file`, `exec 3< file`, `exec 3<&-` | Перенаправить потоки всей оболочки/скрипта, открыть/закрыть дескриптор |

```bash
sudo -u postgres psql -Atc 'SELECT datname FROM pg_database' > /var/tmp/dbs.txt   # результат в файл
ls /nonexistent /etc/hostname > out.txt 2> err.txt                                # вывод и ошибки раздельно
./backup.sh >> /var/log/backup.log 2>&1                                           # типовая строка для cron: всё в журнал
./backup.sh 2>&1 > /var/log/backup.log        # ОШИБКА порядка: stderr останется на экране
sort < unsorted.txt > sorted.txt              # stdin из файла, stdout в файл
: > /var/tmp/big.log                          # обнулить файл, не удаляя (то же: truncate -s 0 file)
set -o noclobber                              # запретить случайную перезапись через «>» (снять: set +o noclobber)

# here-document: выполнить несколько SQL-команд от имени postgres
sudo -u postgres psql -v ON_ERROR_STOP=1 <<'SQL'
SELECT version();
SELECT datname, pg_size_pretty(pg_database_size(datname)) FROM pg_database ORDER BY 2 DESC;
SQL

# here-document: создать конфигурационный файл от root (tee, потому что «>» выполняет не sudo)
# (значение параметра здесь — только иллюстрация синтаксиса, а не рекомендация по настройке)
sudo tee /etc/sysctl.d/90-1c-pg.conf >/dev/null <<'EOF'
vm.swappiness = 10
EOF

grep -c processor <<< "$(cat /proc/cpuinfo)"  # here-string
bc <<< '2^32/1024/1024'                       # если установлен bc
```

### Конвейеры и коды возврата

```bash
ps aux | grep -E '[r]agent|[r]mngr|[r]phost'             # процессы сервера 1С ([r] — чтобы grep не нашёл сам себя)
sudo journalctl -u 'srv1cv8*' --since today | grep -i error | tail -20
du -sh /var/lib/postgresql/*/main 2>/dev/null | sort -h   # размеры каталогов данных
sudo -u postgres pg_dump base1 | gzip > /var/backups/pg/base1.sql.gz   # текстовый дамп со сжатием «на лету» (файл создаёт ваша оболочка, а не postgres)

echo $?                         # код возврата последней команды: 0 — успех, 1–255 — ошибка
cmd1 && cmd2                    # cmd2 только если cmd1 успешна
cmd1 || cmd2                    # cmd2 только если cmd1 завершилась ошибкой
cmd1 ; cmd2                     # последовательно, независимо от результата
mkdir -p /mnt/backup && cd /mnt/backup || exit 1
( cd /var/tmp && tar czf etc.tgz /etc )      # ( … ) — подоболочка: смена каталога не затронет текущую сессию
{ date; uptime; free -h; } > /var/tmp/state.txt   # { …; } — группа команд с общим перенаправлением

set -o pipefail                 # код возврата конвейера = код последней НЕуспешной команды (в скриптах включать всегда)
false | true; echo "${PIPESTATUS[@]}"   # 1 0 — коды всех звеньев последнего конвейера
```

Без `pipefail` строка `pg_dump base1 | gzip > f.gz` вернёт 0, даже если `pg_dump` упал, — и в резервной копии окажется пустой архив. Типовое начало скрипта: `set -euo pipefail` (`-e` — выход при ошибке, `-u` — ошибка при обращении к незаданной переменной).

### tee и /dev/null

`tee [-a] файл…` копирует stdin одновременно в файл(ы) и на stdout; `-a` — дозапись.

```bash
sudo apt-get -y full-upgrade 2>&1 | tee /var/tmp/upgrade-$(date +%F).log    # видеть на экране и сохранить
echo '192.168.56.10 srv1c.example.local srv1c' | sudo tee -a /etc/hosts      # дописать строку в системный файл (для сервера 1С имя хоста сопоставляйте с РЕАЛЬНЫМ адресом, а не с 127.0.1.1 — см. «Типичные ошибки»)
echo 'never' | sudo tee /sys/kernel/mm/transparent_hugepage/enabled          # записать в /sys от root (действует до перезагрузки)
cmd | tee >(logger -t mytag) >/dev/null                                      # отправить копию в syslog/journal
exec > >(tee -a /var/log/myscript.log) 2>&1     # первой строкой скрипта: весь его вывод — на экран и в журнал
```

`/dev/null` — «чёрная дыра»: всё записанное исчезает, чтение сразу даёт конец файла. `cmd >/dev/null` — нужен только код возврата; `cmd </dev/null` — гарантировать, что команда не будет ждать ввода (для фоновых заданий). Родственные устройства: `/dev/zero` (бесконечные нули), `/dev/urandom` (случайные байты), `/dev/stdin`, `/dev/stdout`, `/dev/stderr`, `/dev/tty` (управляющий терминал).

## Управление заданиями и сигналы с клавиатуры

| Клавиша / команда | Действие |
|---|---|
| `Ctrl+C` | Послать SIGINT — прервать текущую команду |
| `Ctrl+Z` | Послать SIGTSTP — приостановить и вернуть приглашение (задание остаётся в памяти в состоянии Stopped) |
| `Ctrl+D` | Конец ввода (EOF): завершает `cat`, `psql`, а в пустой строке приглашения — саму оболочку. Это не сигнал |
| `Ctrl+\` | SIGQUIT — аварийно завершить (с дампом памяти), когда `Ctrl+C` не помогает |
| `Ctrl+S` / `Ctrl+Q` | Остановить / возобновить вывод на терминал (терминал «завис» → нажмите `Ctrl+Q`) |
| `cmd &` | Запустить в фоне; печатается `[номер_задания] PID` |
| `jobs -l` | Список заданий текущей оболочки с PID; `+` — текущее, `-` — предыдущее |
| `fg [%N]` | Вернуть задание на передний план |
| `bg [%N]` | Продолжить приостановленное задание в фоне |
| `kill %N`, `kill -9 %N` | Завершить задание (SIGTERM / SIGKILL); `kill -STOP`/`-CONT` — пауза/продолжение |
| `wait [%N\|PID]` | Дождаться завершения фоновых заданий (в скриптах) |
| `disown [-h] [%N]`, `disown -a` | Убрать задание из таблицы оболочки; `-h` — оставить, но не посылать ему SIGHUP |
| `nohup cmd &` | Запустить с игнорированием SIGHUP |

Задание адресуется как `%1` (номер), `%+` или `%%` (текущее), `%-` (предыдущее), `%имя` (по началу команды), `%?текст` (по подстроке). `$!` — PID последнего фонового процесса.

```bash
sleep 600 &                       # [1] 12345
jobs -l
fg %1                             # на передний план;  Ctrl+Z — приостановить;  bg — пусть работает в фоне
long_command; echo "код: $?"      # забыли «&» у долгой команды: Ctrl+Z → bg → disown -h

# Долгая операция, которая должна пережить выход из SSH (если нет tmux):
nohup sudo -u postgres pg_dump -Fc -f /var/backups/pg/base1.dump base1 > /var/tmp/dump.log 2>&1 &
echo $! > /var/tmp/dump.pid
tail -f /var/tmp/dump.log         # наблюдать;  Ctrl+C прервёт только tail
```

Что происходит при разрыве SSH: терминал закрывается, оболочка получает SIGHUP и рассылает его всем своим заданиям — они завершаются. Не затрагиваются: процессы под `nohup`, задания после `disown -h`, всё, что запущено внутри tmux/screen, и службы systemd. При обычном `exit` фоновые задания bash не убивает (если не включено `shopt -s huponexit`). Особенности `nohup`: если stdout — терминал, вывод дописывается в `./nohup.out` (или `~/nohup.out`), stderr направляется туда же; лучше перенаправлять явно. `sudo` с запросом пароля в фоне работать не будет — сначала выполните `sudo -v`.

Штатный для systemd способ запустить разовую долгую задачу вне сессии — временный (transient) юнит: `sudo systemd-run --unit=dump-base1 --uid=postgres --gid=postgres /usr/bin/pg_dump -Fc -f /var/backups/pg/base1.dump base1`, затем `systemctl status dump-base1` и `journalctl -u dump-base1`. Команда возвращает управление сразу (юнит работает в фоне под надзором systemd); чтобы дождаться завершения и получить код возврата, добавьте `--wait`, а чтобы неудачно завершившийся юнит не «залипал» в состоянии failed и не мешал повторному запуску с тем же именем — `--collect` (иначе перед повтором: `sudo systemctl reset-failed dump-base1`). Программа указывается полным путём или должна находиться в стандартном `PATH` systemd; ваши алиасы, функции и переменные оболочки туда не попадают (переменные передаются ключом `--setenv=ИМЯ=значение`).

## История команд, readline, алиасы

### History

История текущей сессии хранится в памяти и записывается в `~/.bash_history` при выходе из оболочки. Настройки по умолчанию в `~/.bashrc` Ubuntu: `HISTCONTROL=ignoreboth`, `shopt -s histappend`, `HISTSIZE=1000`, `HISTFILESIZE=2000`.

| Запись | Действие |
|---|---|
| `history`, `history 20` | Вся история / последние 20 команд с номерами |
| `history \| grep pg_dump` | Поиск по истории |
| `Ctrl+R` | Обратный инкрементальный поиск: набирайте подстроку, `Ctrl+R` ещё раз — более раннее совпадение, `Enter` — выполнить, `→`/`Ctrl+E` — взять в строку для правки, `Ctrl+G` — отмена |
| `!!` | Предыдущая команда целиком. `sudo !!` — повторить её с sudo |
| `!$` / `!^` / `!*` | Последний / первый / все аргументы предыдущей команды |
| `Alt+.` (или `Esc` затем `.`) | Вставить последний аргумент предыдущей команды (повторное нажатие — более ранние) |
| `!N` / `!-N` | Команда с номером N / N-я с конца |
| `!строка` / `!?строка?` | Последняя команда, начинающаяся со строки / содержащая строку |
| `^было^стало^` | Повторить предыдущую команду с заменой первого вхождения |
| `!!:s/было/стало/`, `!!:gs/было/стало/` | То же через модификатор; `gs` — все вхождения |
| `!N:p` | Только показать (и положить в историю), не выполняя |
| `fc` | Открыть предыдущую команду в редакторе (`$FCEDIT`/`$EDITOR`) и выполнить после сохранения |
| `history -d N` | Удалить запись N (например, со случайно введённым паролем) |
| `history -c` / `history -w` / `history -a` | Очистить историю в памяти / записать её в файл / дописать в файл новые команды сессии |

| Переменная | Смысл |
|---|---|
| `HISTCONTROL` | Список через двоеточие: `ignorespace` — не сохранять команды, начинающиеся с пробела; `ignoredups` — не сохранять повтор предыдущей; `ignoreboth` — оба; `erasedups` — удалять все прежние дубликаты |
| `HISTSIZE` | Сколько команд держать в памяти (умолчание bash — 500; отрицательное — без ограничения) |
| `HISTFILESIZE` | Сколько строк хранить в файле |
| `HISTFILE` | Файл истории (по умолчанию `~/.bash_history`) |
| `HISTTIMEFORMAT` | Формат времени (как у `strftime`): если задана, `history` показывает время, а в файл пишутся метки времени |
| `HISTIGNORE` | Шаблоны команд, которые не сохранять: `'ls:ll:pwd:history*'` |

Рекомендуемые добавления в `~/.bashrc` администратора:

```bash
HISTSIZE=100000
HISTFILESIZE=200000
HISTCONTROL=ignoreboth:erasedups
HISTTIMEFORMAT='%F %T '
shopt -s histappend                       # дописывать, а не перезаписывать файл истории
shopt -s histverify                       # результат !!, !$ и т. п. сначала показать в строке, а не сразу выполнять
PROMPT_COMMAND="history -a${PROMPT_COMMAND:+; $PROMPT_COMMAND}"   # сбрасывать историю в файл после каждой команды (не теряется при обрыве SSH)
```

Безопасность: пароли в командной строке (`rac … --cluster-pwd=…`, `psql 'postgresql://user:pass@host/db'`, `PGPASSWORD=… psql`) попадают в историю и видны в `ps`. Используйте `~/.pgpass` (права `0600`) для PostgreSQL, файлы с параметрами, запрос пароля с клавиатуры (`read -rs`); если ввели — начните команду с пробела (при `ignorespace`) или удалите запись `history -d`. История root и история каждого пользователя раздельны; `sudo команда` попадает в историю вызывающего, а команды внутри `sudo -i` — в `/root/.bash_history`.

### Горячие клавиши readline (режим emacs, по умолчанию)

Настройки readline — `~/.inputrc` (общие — `/etc/inputrc`); список привязок — `bind -P`; режим vi — `set -o vi`. Начиная с bash 5.1 включена «скобочная вставка» (bracketed paste): вставленный из буфера многострочный текст не выполняется, пока вы не нажмёте `Enter`, — это защищает от случайного запуска. В клиентах, где `Alt` не передаётся (часть настроек PuTTY), вместо `Alt+X` нажимайте `Esc`, затем `X`.

### alias

```bash
alias                          # список алиасов
alias ll='ls -alF'             # определить (действует до конца сессии)
alias pgl='sudo tail -n 50 -f /var/log/postgresql/postgresql-17-main.log'
alias j1c="sudo journalctl -u 'srv1cv8*' -n 100 -f"
unalias pgl                    # удалить
\ls                            # выполнить команду в обход алиаса (или: command ls)
```

Постоянные алиасы кладут в `~/.bash_aliases` — стандартный `~/.bashrc` Ubuntu подключает этот файл, если он существует. Алиасы работают только в интерактивной оболочке: в скриптах, в `cron`, через `ssh хост команда` и после `sudo` они не раскрываются (приём `alias sudo='sudo '` — пробел в конце заставляет bash раскрывать алиас и в следующем слове). Для чего-то сложнее одной строки пишите функцию:

```bash
pgsize() { sudo -u postgres psql -Atc "SELECT pg_size_pretty(pg_database_size('${1:?укажите имя базы}'));"; }
```

## Переменные окружения и стартовые файлы

**Переменная оболочки** видна только в текущей оболочке; **переменная окружения** (экспортированная) наследуется всеми запускаемыми из неё процессами. Дочерний процесс не может изменить окружение родителя — поэтому настройки из скрипта применяют через `source`, а не запуском.

```bash
env                          # всё окружение (только экспортированные переменные);  printenv — то же
printenv PATH HOME LANG      # значения отдельных переменных
echo "$PATH"
set | less                   # ВСЕ переменные оболочки и функции (не только окружение)
declare -p PATH              # как переменная объявлена (declare -x — экспортирована)
VAR=значение                 # переменная оболочки (дочерним процессам не видна)
export VAR                   # сделать её переменной окружения;  сразу: export VAR=значение
export -n VAR                # снять признак экспорта;  export -p — список экспортированных
unset VAR                    # удалить переменную
VAR=значение команда         # задать переменную только для одной команды
LC_ALL=C sort file           # типичный пример: разовая смена локали
env -i PATH=/usr/bin:/bin bash --noprofile --norc   # запустить с чистым окружением (отладка «у меня работает, в cron нет»)
env -u http_proxy apt-get update                    # запустить без одной переменной
source ~/.bashrc             # выполнить файл в ТЕКУЩЕЙ оболочке (то же: . ~/.bashrc)
exec bash -l                 # заменить текущую оболочку новой логин-оболочкой (перечитать все стартовые файлы)
```

Часто используемые переменные: `PATH`, `HOME`, `USER`, `LOGNAME`, `SHELL`, `PWD`, `OLDPWD`, `LANG`, `LC_ALL`, `TZ`, `TERM`, `EDITOR`/`VISUAL`, `PAGER`, `TMPDIR`, `PS1` (вид приглашения), `HIST*`; для клиентов PostgreSQL (libpq) — `PGHOST`, `PGPORT`, `PGUSER`, `PGDATABASE`, `PGPASSFILE` (вместо `PGPASSWORD` используйте `~/.pgpass`: строки `хост:порт:база:пользователь:пароль`, права `0600`).

### PATH

`PATH` — список каталогов через двоеточие, в которых оболочка ищет команды; берётся первое совпадение слева. Значение по умолчанию в Ubuntu задаётся в `/etc/environment`: `/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin`.

```bash
export PATH="$PATH:/opt/1cv8/current"              # добавить каталог в конец (на текущую сессию)
export PATH="/opt/pgpro/1c-17/bin:$PATH"           # в начало — будет иметь приоритет над системными
./script.sh                                        # текущий каталог в PATH не входит: локальный файл запускают с «./»
sudo /opt/pgpro/1c-17/bin/pg-wrapper links update  # Postgres Pro: создать ссылки на psql, pg_dump… в стандартных каталогах
```

Постоянно для всех пользователей — файл в `/etc/profile.d/`:

```bash
sudo tee /etc/profile.d/1c.sh >/dev/null <<'EOF'
# утилиты 1С (rac, ibcmd) — через стабильную ссылку /opt/1cv8/current
if [ -d /opt/1cv8/current ]; then
    PATH="$PATH:/opt/1cv8/current"
fi
EOF
```

`sudo` **не использует** ваш `PATH`: он подставляет `secure_path` из `/etc/sudoers` (в Ubuntu: `/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/snap/bin`). Поэтому `sudo rac …` даст `command not found`, даже если `rac` находится у вас в `PATH`: указывайте полный путь либо сделайте ссылку в `/usr/local/bin`. Никогда не добавляйте в `PATH` текущий каталог (`.`) и каталоги, доступные на запись другим пользователям.

### Какие файлы читаются при запуске

| Ситуация | Тип оболочки | Что читается |
|---|---|---|
| Вход по SSH или с консоли, `sudo -i`, `su - user`, новое окно tmux | логин-оболочка, интерактивная | `/etc/profile` (в Ubuntu он подключает `/etc/bash.bashrc` и все `/etc/profile.d/*.sh`), затем **первый найденный** из `~/.bash_profile`, `~/.bash_login`, `~/.profile`. Стандартный `~/.profile` Ubuntu подключает `~/.bashrc` и добавляет в `PATH` каталоги `~/bin` и `~/.local/bin`, если они существуют |
| `bash`, `sudo -s`, `su user` (без дефиса), окно screen | интерактивная, не логин | `/etc/bash.bashrc`, затем `~/.bashrc` |
| Скрипт `./script.sh`, `bash -c '…'`, `sudo -u user команда`, задания cron | неинтерактивная | Ничего (только файл из переменной `BASH_ENV`, если она задана) |
| `ssh хост 'команда'` | неинтерактивная, ввод из сети | bash читает `/etc/bash.bashrc` и `~/.bashrc`, но стандартный `~/.bashrc` Ubuntu первой же проверкой выходит, если оболочка неинтерактивная; `~/.profile` и `/etc/profile.d/*` не читаются |
| Служба systemd (сервер 1С, PostgreSQL, Apache) | это не оболочка | Ничего из перечисленного. Только `Environment=` / `EnvironmentFile=` из юнита |
| Выход из логин-оболочки | — | `~/.bash_logout` |

Куда что писать:

| Файл | Для чего |
|---|---|
| `~/.bashrc` | Алиасы, функции, приглашение, настройки истории — всё для интерактивной работы |
| `~/.profile` | Переменные окружения пользователя (`PATH`, `EDITOR`, `PG*`). Если создать `~/.bash_profile`, то `~/.profile` перестанет читаться |
| `~/.bash_aliases` | Алиасы (подключается из `~/.bashrc`) |
| `/etc/profile.d/имя.sh` | Переменные и `PATH` для всех пользователей (shell-синтаксис, только логин-оболочки) |
| `/etc/environment` | Простые пары `ИМЯ=значение` для всех сеансов. **Не скрипт**: читает PAM-модуль `pam_env` при входе, подстановки `$VAR` не работают, слово `export` игнорируется |
| `/etc/bash.bashrc` | Общие настройки интерактивного bash для всех пользователей |
| `/etc/default/locale` | Системная локаль (`LANG=…`); менять командой `sudo update-locale LANG=ru_RU.UTF-8` |
| `~/.pam_environment` | Устарел: по умолчанию не читается (`user_readenv` отключён, объявлен устаревшим с PAM 1.5.0); сервер OpenSSH в 26.04 его не читает — не используйте |

Изменения в стартовых файлах действуют на **новые** сеансы; в текущем — `source файл` или перелогиниться. Окружение службы меняют так:

```bash
systemctl show 'srv1cv8-8.3.27.1688@default' -p Environment -p EnvironmentFiles -p User -p Group   # что задано в юните
sudo systemctl edit 'srv1cv8-8.3.27.1688@default'     # создать drop-in override.conf, например:
#   [Service]
#   Environment=SRV1CV8_DATA=/srv/1c/cluster
sudo systemctl daemon-reload && sudo systemctl restart 'srv1cv8-8.3.27.1688@default'
```

Юнит сервера 1С использует переменные `SRV1CV8_DATA`, `SRV1CV8_PORT`, `SRV1CV8_REGPORT`, `SRV1CV8_RANGE`, `SRV1CV8_DEBUG`, `SRV1CV8_KEYTAB` (подробно — в статье о сервере 1С); в разных версиях платформы набор переменных в файле юнита отличается, поэтому точный список и значения по умолчанию смотрите в самом юните: `systemctl cat 'srv1cv8-<версия>@default'` (полный перечень по документации 8.3.27 (сверено 10.10.2026): `SRV1CV8_DATA`, `SRV1CV8_DEBUG`, `SRV1CV8_KEYTAB`, `SRV1CV8_PINGPERIOD`, `SRV1CV8_PINGTIMEOUT`, `SRV1CV8_PORT`, `SRV1CV8_RANGE`, `SRV1CV8_REGPORT`, `SRV1CV8_SECLEV`; ранее: полный перечень для 8.3.27/8.5 по документации не сверен — открыто подтверждены `SRV1CV8_DATA` и `SRV1CV8_DEBUG` в статье ИТС для 8.3.13 и `SRV1CV8_KEYTAB` в руководстве 8.3.22). В cron окружение минимальное (`PATH=/usr/bin:/bin`, оболочка `/bin/sh`, стартовые файлы bash не читаются, локаль может отличаться от интерактивной) — в заданиях указывайте полные пути и нужные переменные явно.

Локаль важна для 1С и PostgreSQL (кластер БД обычно создают в `ru_RU.UTF-8`):

```bash
locale                       # текущие значения LANG и LC_*
locale -a | grep -i ru       # сгенерированные локали
sudo locale-gen ru_RU.UTF-8 && sudo update-locale LANG=ru_RU.UTF-8   # сгенерировать и сделать системной
```

## Справка: man, --help, apropos, info, tldr

```bash
man ls                   # руководство по команде
man 5 crontab            # страница из конкретного раздела
man -a passwd            # все страницы с этим именем по очереди (passwd(1), passwd(5)…)
man -f passwd            # в каких разделах есть страница (то же: whatis passwd)
man -k 'copy files'      # поиск по названиям и кратким описаниям (то же: apropos)
man -K 'hugepages'       # полнотекстовый поиск по всем страницам (медленно)
man -w bash              # путь к файлу страницы
help cd                  # справка по ВСТРОЕННЫМ командам bash (cd, read, test, set, shopt, export…) — у них нет своих man-страниц
help test | less
ls --help | less         # краткая справка самой программы
info coreutils           # документация GNU в формате info (подробнее man; клавиши: n/p/u — узлы, q — выход)
```

Разделы man: **1** — пользовательские команды, **2** — системные вызовы, **3** — библиотечные функции, **4** — устройства, **5** — форматы файлов и конфигурации, **6** — игры, **7** — обзоры и соглашения (`man 7 signal`, `man 7 glob`, `man hier` — описание дерева каталогов), **8** — команды администрирования. Навигация (просмотрщик `less`): `Пробел`/`b` — страница вперёд/назад, `/текст` — поиск вперёд, `?текст` — назад, `n`/`N` — следующее/предыдущее совпадение, `g`/`G` — начало/конец, `h` — справка, `q` — выход.

`tldr` — короткие примеры «как обычно используют» (сообщество tldr-pages): 22.04 — `sudo apt install tldr`; 24.04 — `sudo apt install tealdeer` (или `tldr`, это переходный пакет на `tldr-hs`); 26.04 — `sudo apt install tealdeer` (или `tldr-py`; пакета `tldr` в 25.10/26.04 уже нет). `tealdeer` и `tldr` — из компонента universe. Первый запуск (tealdeer и Haskell-клиент): `tldr --update`, затем `tldr tar`, `tldr find`. У `tldr-py` (0.7.0 во всех трёх LTS) интерфейс другой — подкоманды `tldr init`, `tldr update`, `tldr find tar` (⚠ не подтверждено в этой сессии, по памяти; смотрите `tldr --help`), поэтому предпочтителен `tealdeer`. Клиенту нужен доступ в интернет для загрузки базы страниц (GitHub) — на изолированном сервере пользуйтесь `man` и `--help`.

Дополнительно: онлайн-страницы для конкретного выпуска — `https://manpages.ubuntu.com/manpages/noble/` (подставьте `jammy`, `noble`, `resolute`); документация пакета — `/usr/share/doc/<пакет>/`; если индекс `apropos` пуст — `sudo mandb`. В 26.04 страницы `man ls`, `man date` и т. п. описывают uutils, а не GNU. В psql справка — `\?` (метакоманды) и `\h КОМАНДА` (синтаксис SQL); у клиентских утилит PostgreSQL есть `man psql`, `man pg_dump`, `pg_dump --help`.

## tmux и screen: сессии, переживающие обрыв SSH

Терминальный мультиплексор держит оболочки на сервере независимо от SSH-подключения: соединение оборвалось — команды продолжают работать, после повторного входа к ним можно подключиться. По документации Ubuntu Server, `tmux` и GNU `screen` предустановлены на Ubuntu Server; рекомендуется `tmux`, а `screen` — для унаследованных сценариев. `byobu` (оболочка над tmux) с 25.10 по умолчанию не ставится.

### tmux

Иерархия: сервер → сессии → окна → панели. Все клавиши вводятся после префикса `Ctrl+b` (нажать, отпустить, затем клавиша).

```bash
tmux new -s work                 # новая сессия с именем
tmux new -A -s work              # подключиться к сессии work или создать её (удобно как единая команда входа)
tmux ls                          # список сессий (= tmux list-sessions)
tmux attach -t work              # подключиться (= tmux a -t work);  -d — отключив других клиентов
sudo -u postgres tmux new -d -s dump 'pg_dump -Fc -f /var/backups/pg/base1.dump base1; echo "код: $?"; read'   # команда в отсоединённой сессии от имени postgres
sudo -u postgres tmux attach -t dump     # посмотреть ход/итог (read в конце не даёт сессии закрыться сразу после команды)
tmux kill-session -t work        # завершить сессию;  tmux kill-server — все сразу
tmux capture-pane -pS - > ~/tmux-screen.txt     # (внутри tmux) сохранить всю прокрутку панели в файл
tmux pipe-pane -o 'cat >> ~/tmux-#S.log'        # (внутри tmux) включить/выключить запись вывода панели в файл
```

| Клавиши после `Ctrl+b` | Действие |
|---|---|
| `d` | Отсоединиться (сессия продолжает работать) |
| `c` / `,` / `&` | Новое окно / переименовать окно / закрыть окно |
| `n` / `p` / `0`–`9` / `l` / `w` | Следующее / предыдущее окно / окно по номеру / последнее активное / выбор из списка |
| `%` / `"` | Разделить панель слева-направо / сверху-вниз |
| стрелки / `o` / `;` | Перейти в панель по направлению / в следующую / в предыдущую активную |
| `Ctrl+стрелки`, `Alt+стрелки` | Изменить размер панели на 1 / на 5 ячеек |
| `z` | Развернуть панель на всё окно и обратно |
| `x` / `!` | Закрыть панель / вынести панель в отдельное окно |
| `Пробел` | Переключить раскладку панелей |
| `[` или `PageUp` | Режим копирования и прокрутки (стрелки, `PageUp`/`PageDown`; выход — `q`) |
| `]` | Вставить скопированное |
| `s` / `$` / `(` `)` | Выбрать сессию / переименовать сессию / предыдущая-следующая сессия |
| `:` | Командная строка tmux (например, `:setw synchronize-panes on`) |
| `?` | Список всех клавиш |
| `t` | Часы |
| `Ctrl+b` | Передать сам `Ctrl+b` программе внутри |

Настройки — `~/.tmux.conf` (общие — `/etc/tmux.conf`), применить без перезапуска: `tmux source-file ~/.tmux.conf`.

```bash
# ~/.tmux.conf
set -g mouse on               # мышь: выбор панели, прокрутка колесом (в PuTTY/Windows Terminal для выделения текста удерживайте Shift)
set -g history-limit 50000    # строк прокрутки на панель (по умолчанию 2000)
setw -g mode-keys vi          # клавиши vi в режиме копирования: / поиск, Space — начать выделение, Enter — скопировать
set -g base-index 1           # нумерация окон с 1
```

Типовой сценарий долгой операции: `ssh` → `tmux new -A -s work` → запустить команду → `Ctrl+b d` → можно закрывать SSH → позже `tmux attach -t work`. Закрытие последней оболочки сессии (`exit` или `Ctrl+D`) сессию уничтожает. Автоподключение при входе по SSH (практика сообщества), в конец `~/.bashrc`:

```bash
if [[ -n $SSH_TTY && -z $TMUX ]] && command -v tmux >/dev/null; then
    tmux new -A -s main
fi
```

### screen

```bash
screen -S work            # новая сессия с именем
screen -ls                # список сессий
screen -r work            # подключиться к отсоединённой;  screen -d -r work — отцепить от другого терминала и подключиться
screen -D -R work         # «дай мне эту сессию любой ценой»: отцепить, подключиться, а если её нет — создать
screen -x work            # подключиться к уже подключённой сессии (общий экран для двоих)
screen -d -m -S dump команда     # запустить команду в отсоединённой сессии
screen -L -S work         # вести журнал вывода в файл screenlog.N
screen -S work -X quit    # завершить сессию снаружи;  screen -wipe — убрать «мёртвые» записи
```

Префикс — `Ctrl+a`: `d` — отсоединиться, `c` — новое окно, `n`/`p` — следующее/предыдущее, `0`–`9` — по номеру, `"` — список окон, `A` — переименовать окно, `k` — закрыть окно, `[` — режим прокрутки и копирования (выход `Esc`), `]` — вставить, `S` / `|` — разделить горизонтально / вертикально, `Tab` — перейти в соседнюю область, `X` — закрыть область, `H` — журнал окна в файл, `?` — справка, `a` — передать сам `Ctrl+a` программе (в bash это «в начало строки»). Настройки — `~/.screenrc`; прокрутка по умолчанию всего 100 строк — добавьте `defscrollback 10000`.

## sudo и su: работа от имени root, postgres и usr1cv8

В Ubuntu учётная запись root заблокирована (пароля нет); административные команды выполняют через `sudo` участники группы `sudo` (`sudo usermod -aG sudo имя`, вступает в силу после нового входа). Пароль запрашивается свой, результат проверки кэшируется на 15 минут.

| Команда | Что делает |
|---|---|
| `sudo команда` | Выполнить от root. Текущий каталог сохраняется, окружение сбрасывается (`env_reset`), `PATH` заменяется на `secure_path` |
| `sudo -i` | Логин-оболочка root: читаются `/root/.profile` и `/root/.bashrc`, каталог — `/root`. Замена `su -` |
| `sudo -s` | Оболочка из `$SHELL` от root без «логина»: каталог остаётся прежним |
| `sudo -u пользователь команда` | Выполнить от имени другого пользователя |
| `sudo -iu postgres` | Логин-оболочка пользователя (его каталог, его `~/.profile`) |
| `sudo -u пользователь -s` | Оболочка из **вашей** `$SHELL` от имени пользователя — работает, даже если у него оболочка `nologin` |
| `sudo -g группа команда` | Выполнить с другой основной группой |
| `sudo -E команда` | Сохранить всё текущее окружение (нужно разрешение в sudoers). **В sudo-rs (26.04) не поддерживается** |
| `sudo --preserve-env=A,B команда` | Сохранить только перечисленные переменные (работает и в sudo-rs) |
| `sudo -u user env VAR=знач команда` | Надёжный способ передать переменную — работает везде |
| `sudo -H` | Установить `HOME` целевого пользователя (в современных Ubuntu это и так по умолчанию) |
| `sudo -l`, `sudo -l -U user` | Что разрешено мне / другому пользователю |
| `sudo -v` / `sudo -k` / `sudo -K` | Продлить кэш пароля / сбросить для текущего сеанса / сбросить полностью |
| `sudo -n команда` | Не спрашивать пароль: если он нужен — завершиться с ошибкой (для скриптов) |
| `sudo -b команда` | Запустить в фоне |
| `sudoedit файл` (`sudo -e файл`) | Безопасно править системный файл: редактор (`$SUDO_EDITOR`, `$VISUAL`, `$EDITOR`) работает от вашего имени с временной копией |
| `sudo visudo`, `sudo visudo -f /etc/sudoers.d/имя` | Единственный правильный способ править правила sudo (проверка синтаксиса перед сохранением) |
| `sudo !!` | Повторить предыдущую команду с sudo |

```bash
sudo -i                                   # стать root надолго (выход: exit или Ctrl+D)
sudo sh -c 'cat /var/log/postgresql/*.log | wc -l'      # шаблон и конвейер должны выполняться от root → sh -c
sudo sh -c 'date >> /var/log/maintenance.log'           # перенаправление от root: вся строка выполняется в sh под root
date | sudo tee -a /var/log/maintenance.log >/dev/null  # то же через tee
sudo --preserve-env=http_proxy,https_proxy apt-get update
```

`su` (переключение пользователя с вводом **его** пароля; root — без пароля):

```bash
su -                         # логин-оболочка root — в Ubuntu не сработает, пока root не задан пароль; используйте sudo -i
su - postgres                # (от root) логин-оболочка postgres;  «-» = полноценный вход: его окружение и каталог
su postgres                  # без дефиса: окружение и каталог остаются вызывающего — источник путаницы
su - postgres -c 'psql -c "SELECT 1"'        # одна команда
su -s /bin/bash - usr1cv8    # (от root) явно указать оболочку, если у учётной записи nologin
runuser -u postgres -- psql -Atc 'SELECT 1'  # (только root) без PAM-аутентификации — удобно в скриптах и юнитах
```

### От имени postgres

Суперпользователь СУБД `postgres` соответствует системному пользователю `postgres` (peer-аутентификация по Unix-сокету — настройка `pg_hba.conf` по умолчанию в пакетах Ubuntu). Пароля у системного пользователя нет, вход — только через sudo.

```bash
sudo -u postgres psql                                    # консоль СУБД
sudo -u postgres psql -d base1 -Atc 'SELECT count(*) FROM pg_stat_activity'
sudo -iu postgres                                        # оболочка postgres: каталог /var/lib/postgresql
sudo -u postgres pg_dump -Fc -f /var/backups/pg/base1.dump base1    # каталог назначения должен быть доступен postgres на запись
sudo -u postgres psql -Atc 'SHOW config_file'
```

Если текущий каталог недоступен пользователю `postgres` (например, ваш домашний с правами `750`), утилиты печатают предупреждение `could not change directory to "/home/admin": Permission denied` — оно безвредно; чтобы не видеть его, сначала `cd /tmp` или используйте `sudo -iu postgres`. Для Postgres Pro, если `psql` нет в `PATH`: `sudo -u postgres /opt/pgpro/1c-NN/bin/psql`.

### От имени usr1cv8

Сервер 1С работает от пользователя `usr1cv8` (группа `grp1cv8`), которого создаёт установщик платформы. Всё, что читает и пишет сервер (каталог кластера, файловые базы, каталоги обмена, технологический журнал), должно быть доступно этому пользователю.

```bash
getent passwd usr1cv8; id usr1cv8                        # домашний каталог, оболочка, группы
sudo -u usr1cv8 ls -la /home/usr1cv8/.1cv8/1C/1cv8/      # посмотреть «его глазами»
sudo -u usr1cv8 test -w /srv/1c/exchange && echo 'запись есть' || echo 'нет доступа'   # проверить права, не гадая
sudo -u usr1cv8 -s                                       # оболочка от имени usr1cv8
V1C=8.3.27.1688                                          # пример; подставьте свою версию (ls /opt/1cv8/x86_64/)
/opt/1cv8/x86_64/$V1C/rac cluster list                   # rac — сетевой клиент сервера администрирования ras (порт 1545), запускается от любого пользователя; сам ras должен быть запущен
sudo chown -R usr1cv8:grp1cv8 /srv/1c                    # вернуть владельца после работы от root
```

Правило: утилиты платформы, которые сами работают с файлами (`ibcmd`, `ibsrv`, конфигуратор в пакетном режиме, ручной запуск `ragent`), запускайте от `usr1cv8` (`sudo -u usr1cv8 …`), а не от root — иначе созданные ими файлы получат владельца root, и служба, работающая от `usr1cv8`, не сможет их открыть (лечится `chown -R usr1cv8:grp1cv8`). Если `sudo -iu usr1cv8` отвечает `This account is currently not available`, у учётной записи оболочка `nologin` — используйте `sudo -u usr1cv8 -s`.

Какая оболочка входа у `usr1cv8` — зависит от того, как учётную запись создал установщик платформы; документацией это не подтверждено (⚠). Смотрите седьмое поле `getent passwd usr1cv8` и учитывайте три варианта: `/bin/bash` — `sudo -iu usr1cv8` даёт обычный bash; `/bin/sh` (значение по умолчанию `useradd` в Ubuntu, если оболочка не задана явно) — `sudo -iu usr1cv8` запустит `dash` без истории, автодополнения и без чтения `~/.bashrc`, поэтому удобнее `sudo -u usr1cv8 -s` (возьмёт ваш bash) или `sudo -u usr1cv8 bash -l`; `/usr/sbin/nologin` — вход запрещён, работает только `sudo -u usr1cv8 -s` / `sudo -u usr1cv8 команда`. Файлы `~/.bashrc` и `~/.profile` у `usr1cv8` появляются, только если домашний каталог создавался с копированием `/etc/skel` (`useradd -m`); их может и не быть — и в любом случае на *службу* они не влияют. В `sudo -u usr1cv8 -s` переменная `HOME` указывает на `/home/usr1cv8`, а текущий каталог остаётся вашим — если он недоступен пользователю `usr1cv8` (домашний каталог с правами `750`), сразу выполните `cd`.

### Сведения о системе: uname, lsb_release, hostnamectl, uptime, whoami

### date, cal

```bash
date                               # текущие дата и время
date +%F                           # 2026-10-10
date '+%F %T'                      # 2026-10-10 14:05:33
date +%Y%m%d_%H%M%S                # 20261010_140533 — для имён файлов и каталогов
date -Is                           # ISO 8601 с часовым поясом
date -u                            # в UTC
date +%s                           # секунды с начала эпохи;  date -d @1760000000 — обратное преобразование
date -d yesterday +%F              # вчера;  также: '7 days ago', 'next monday', '2026-10-01 +1 month'
date -r /var/log/syslog '+%F %T'   # время изменения файла
TZ=Europe/Moscow date              # время в другом часовом поясе
timedatectl                        # часовой пояс, состояние синхронизации времени
sudo timedatectl set-timezone Asia/Tashkent      # сменить пояс (список: timedatectl list-timezones)
```

Спецификаторы: `%Y` год, `%m` месяц, `%d` день, `%H` `%M` `%S` время, `%F` = `%Y-%m-%d`, `%T` = `%H:%M:%S`, `%a`/`%A` день недели, `%b`/`%B` месяц словом, `%j` день года, `%u` день недели 1–7, `%V` номер ISO-недели, `%z`/`%Z` пояс, `%s` эпоха, `%N` наносекунды. В 26.04 `date` — из uutils: если разбор нестандартной строки в `-d` ведёт себя не так, как в 24.04, вызовите `gnudate`.

`cal` в Ubuntu находится в пакете `ncal` и по умолчанию не установлен: `sudo apt install ncal`; затем `cal` (текущий месяц), `cal -3` (три месяца), `cal 10 2026`, `cal -y` (весь год), `ncal -w` (с номерами недель).

### clear, watch, time, sleep, seq

```bash
clear                    # очистить экран (то же: Ctrl+L)
reset                    # восстановить терминал после вывода двоичного «мусора» (то же: stty sane)

watch -n 5 'df -h / /var/lib/postgresql /tmp'            # повторять команду каждые 5 с (по умолчанию 2 с); выход — Ctrl+C
watch -d -n 2 'ps -o pid,rss,etime,cmd -C rphost'        # -d — подсвечивать изменения
watch -t -n 1 date                                       # -t — без заголовка
watch -g 'ls /var/backups/pg | wc -l'                    # -g — выйти, когда вывод изменится;  -e — выйти при ошибке команды
# команда в кавычках целиком: иначе конвейер применится к самому watch

time sudo -u postgres pg_dump -Fc -f /var/tmp/t.dump base1   # сколько заняло: real (по часам), user и sys (процессорное время)
time { cmd1; cmd2; }                                     # время группы команд
/usr/bin/time -v команда                                 # подробно, включая пиковую память (пакет time)

timeout 30 pg_isready -h 192.168.56.10                   # ограничить время работы команды: через 30 с послать SIGTERM; код возврата 124 — «время вышло»
timeout -k 10 2h ./backup.sh                             # через 2 ч SIGTERM, ещё через 10 с — SIGKILL, если не завершилась

sleep 5; sleep 0.5; sleep 2m; sleep 1h 30m               # пауза: секунды, дробные, суффиксы s m h d
until pg_isready -q; do sleep 1; done; echo 'PostgreSQL принимает подключения'   # ждать готовности сервиса
while true; do date; free -m | sed -n 2p; sleep 60; done >> /var/tmp/mem.log     # простейший самописный мониторинг

seq 5                    # 1 2 3 4 5 (по одному в строке)
seq 0 5 20               # с шагом: 0 5 10 15 20
seq -w 1 10              # с ведущими нулями: 01 … 10
seq -s, 1 5              # с разделителем: 1,2,3,4,5
for i in $(seq 1 "$n"); do echo "$i"; done     # цикл с переменной границей (вместо {1..$n})
```


### test, [ ] и [[ ]]

`test выражение` и `[ выражение ]` — одна и та же команда (POSIX), возвращающая 0 («истина») или 1. `[[ выражение ]]` — конструкция самого bash: внутри неё не происходит разбиения на слова и раскрытия шаблонов, работают `&&`, `||`, сравнение с шаблоном и регулярные выражения. В скриптах с `#!/bin/bash` используйте `[[ ]]`; в `sh`/`dash` его нет.

| Проверка | Истинно, если |
|---|---|
| `-e путь` / `-f` / `-d` / `-L` | Существует / обычный файл / каталог / символическая ссылка |
| `-s файл` | Существует и не пуст |
| `-r` / `-w` / `-x` | Текущему пользователю доступно чтение / запись / выполнение (для каталога `-x` — вход) |
| `-b` / `-c` / `-p` / `-S` | Блочное / символьное устройство / FIFO / сокет |
| `f1 -nt f2` / `f1 -ot f2` / `f1 -ef f2` | f1 новее / старее f2 / это один и тот же файл (inode) |
| `-z строка` / `-n строка` | Строка пустая / непустая |
| `s1 = s2` (`==`) / `s1 != s2` | Строки равны / не равны. В `[[ ]]` правая часть без кавычек — шаблон: `[[ $v == 8.3.* ]]` |
| `s1 < s2` / `s1 > s2` | Лексикографическое сравнение (в `[ ]` знаки нужно экранировать: `\<`) |
| `s =~ рв` | Только `[[ ]]`: совпадение с расширенным регулярным выражением; группы — в массиве `BASH_REMATCH` |
| `n1 -eq n2`, `-ne`, `-lt`, `-le`, `-gt`, `-ge` | Сравнение целых чисел (или арифметика: `(( n1 < n2 ))`) |
| `! выр` | Отрицание |
| `[[ a && b ]]`, `[[ a \|\| b ]]` | И / ИЛИ внутри `[[ ]]`. Для `[ ]` пишите `[ a ] && [ b ]` (устаревшие `-a`, `-o` не используйте) |
| `-v имя` | Переменная с таким именем задана |

```bash
[[ -d /opt/1cv8/x86_64 ]] && echo 'платформа 1С установлена'
[[ -f $cfg && -r $cfg ]] || { echo "нет доступа к $cfg" >&2; exit 1; }
[[ $EUID -eq 0 ]] || { echo 'запустите через sudo' >&2; exit 1; }
[[ -z ${1:-} ]] && { echo "Использование: $0 имя_базы" >&2; exit 2; }
[[ $ver =~ ^8\.([0-9]+)\.([0-9]+)\.([0-9]+)$ ]] && echo "версия 8.${BASH_REMATCH[1]}, сборка ${BASH_REMATCH[3]}"
[ "$a" = "$b" ]                       # POSIX-форма: кавычки и пробелы вокруг скобок обязательны
(( $(df --output=pcent / | tail -1 | tr -dc '0-9') > 90 )) && echo 'корневой раздел заполнен более чем на 90 %'
if pg_isready -q; then echo 'PostgreSQL отвечает'; else echo 'PostgreSQL недоступен' >&2; fi   # if проверяет код возврата любой команды
if ! getent passwd usr1cv8 >/dev/null; then echo 'пользователя usr1cv8 нет'; fi
```

### Опции оболочки и отладка скриптов: set, shopt, bash -n / -x

```bash
set -o                       # текущие значения всех опций set (errexit, nounset, pipefail, noclobber, vi…)
shopt                        # опции shopt (extglob, globstar, nullglob, dotglob, histappend, huponexit…);  shopt -p — в виде команд
set -e                       # errexit: прервать скрипт при первой команде с ненулевым кодом возврата
set -u                       # nounset: обращение к незаданной переменной — ошибка (ловит опечатки вроде rm -rf "$DRI/")
set -o pipefail              # код возврата конвейера — от последнего упавшего звена
set -x                       # xtrace: печатать каждую команду после всех подстановок (с префиксом «+»);  set +x — выключить
bash -n script.sh            # только проверить синтаксис, ничего не выполняя
bash -x script.sh            # выполнить с трассировкой, не правя сам скрипт
PS4='+ ${BASH_SOURCE##*/}:${LINENO}: ' bash -x script.sh      # трассировка с именем файла и номером строки
trap 'echo "ошибка в строке $LINENO: $BASH_COMMAND (код $?)" >&2' ERR   # в скрипте: сообщить, где именно упало
shellcheck script.sh         # статический анализатор shell-скриптов: sudo apt install shellcheck (компонент universe)
```

Ограничения `set -e`, о которые спотыкаются чаще всего: он **не** срабатывает для команд в условии `if`/`while`/`until`, для всех звеньев списка `&&`/`||`, кроме последнего, для команд после `!` и для звеньев конвейера, кроме последнего (без `pipefail`); `local var=$(cmd)` и `export var=$(cmd)` скрывают код возврата `cmd` (объявляйте и присваивайте раздельно: `local var; var=$(cmd)`). Поэтому критичные шаги (дамп, копирование, удаление старых копий) проверяйте явно: `pg_dump … || { echo 'дамп не удался' >&2; exit 1; }`. В трассировке `set -x` видны значения всех переменных — не включайте её там, где в командах есть пароли.

## Файловый менеджер mc (Midnight Commander)

Двухпанельный менеджер в стиле Norton/FAR с собственными просмотрщиком (`mcview`) и редактором (`mcedit`). Пакет `mc` из компонента universe: 4.8.27 (22.04), 4.8.30 (24.04), 4.8.33 (26.04).

```bash
sudo apt install mc
mc                       # запуск;  mc /etc /var/log — с заданными каталогами в панелях
sudo mc                  # от root (осторожно: созданные файлы будут принадлежать root)
mcedit /path/file        # сразу редактор (то же: mc -e file);  mcview file — просмотрщик (mc -v file)
mc -b                    # монохромный режим;  mc -a — рамки ASCII-символами (если в PuTTY вместо линий «мусор»)
mc -d                    # без мыши (выделение текста мышью останется за терминалом)
```

| Клавиша | Действие |
|---|---|
| `F1` / `F2` / `F9` / `F10` | Справка / пользовательское меню / верхнее меню / выход |
| `F3` / `F4` | Просмотр / правка файла (`Shift+F4` — создать новый файл) |
| `F5` / `F6` / `F7` / `F8` | Копировать / переместить-переименовать / создать каталог / удалить |
| `Shift+F5`, `Shift+F6` | Копировать / переименовать в том же каталоге |
| `Tab` | Перейти в другую панель |
| `Insert` (или `Ctrl+T`) | Отметить файл; `+` — отметить по шаблону, `\` — снять по шаблону, `*` — инвертировать |
| `Ctrl+O` | Скрыть/показать панели (увидеть вывод команд; под панелями работает обычная оболочка) |
| `Ctrl+U` / `Ctrl+R` | Поменять панели местами / перечитать каталог |
| `Ctrl+S` или `Alt+S` | Быстрый поиск по имени в панели |
| `Alt+?` | Поиск файлов (по имени и содержимому) |
| `Alt+C` / `Ctrl+\` | Быстрый переход в каталог / список избранных каталогов |
| `Alt+I` / `Alt+O` | Открыть в другой панели тот же каталог / каталог под курсором |
| `Alt+.` | Показать/скрыть скрытые файлы |
| `Alt+Enter` (`Ctrl+Enter`) / `Ctrl+Shift+Enter` | Вставить в командную строку имя файла / полный путь |
| `Ctrl+X` `P` / `Ctrl+X` `T` | Вставить в командную строку путь текущей панели / отмеченные файлы |
| `Alt+H` / `Alt+P`, `Alt+N` | История команд / предыдущая, следующая команда |

В просмотрщике (`F3`): `F4` — hex-режим, `F7` — поиск, `F2` — перенос строк, `F8` — «сырой»/разобранный вид, `F10`/`Esc`/`q` — выход. В редакторе (`F4`, он же `mcedit`): `F2` — сохранить, `F10` — выйти, `F3` — начать/закончить выделение блока, `F5`/`F6`/`F8` — копировать/переместить/удалить блок, `F7` — поиск, `F4` — замена, `Ctrl+U` — отмена, `Ctrl+Y` — удалить строку, `Alt+L` — перейти к строке.

Полезное: `Enter` на архиве (`.tar.gz`, `.zip`, `.deb`) открывает его как каталог; в командной строке mc можно набрать `cd sh://user@host/path` (панель на удалённом сервере через SSH) или `cd sftp://user@host/path`; настройки хранятся в `~/.config/mc/ini` (меню `F9` → «Настройки» → «Сохранить настройки»); чтобы `F4` открывал встроенный редактор, а не `nano`/`vi`, в «Настройки» → «Конфигурация» включите «Встроенный редактор». Править системные файлы удобно так: `sudo mcedit /etc/postgresql/17/main/postgresql.conf`. Возврат в оболочку в каталоге активной панели обеспечивает обёртка `/usr/lib/mc/mc-wrapper.sh`. В Ubuntu она **не подключается автоматически**: в пакете `mc` (проверен список файлов для 24.04) нет файла `/etc/profile.d/mc.sh` (он есть в дистрибутивах семейства RHEL), а лежат только `/usr/lib/mc/mc.sh` и `/usr/lib/mc/mc-wrapper.sh` (копии — в `/usr/share/mc/bin/`). Чтобы включить, добавьте в `~/.bashrc` строку `. /usr/lib/mc/mc.sh` (так советует `man mc`; файл определяет алиас `mc='. /usr/lib/mc/mc-wrapper.sh'`) либо для всех пользователей: `sudo ln -s /usr/lib/mc/mc.sh /etc/profile.d/mc.sh`. После этого `F10` оставляет вас в каталоге активной панели, а `Shift+F10` — выйти, оставшись в исходном каталоге. Под `sudo mc` алиас не действует.

Замечания к таблице клавиш (сверено с `man mc` 4.8.30 и штатной раскладкой `mc.default.keymap`): `+`, `\` и `*` на основной клавиатуре срабатывают, только когда командная строка mc пуста (иначе символ уходит в неё), на цифровом блоке — всегда; `Shift+F4`/`F5`/`F6` в раскладке записаны как `F14`/`F15`/`F16` — в части SSH-клиентов (PuTTY с нестандартной раскладкой функциональных клавиш) они не передаются, тогда пользуйтесь меню `F9`; `Ctrl+Enter` и `Ctrl+Shift+Enter`, по `man mc`, работают не во всех терминалах и не по SSH — надёжнее `Alt+Enter` и `Ctrl+X` `P`.

## Типичные ошибки и подводные камни

| Симптом | Причина | Решение |
|---|---|---|
| `sudo echo x > /etc/file` → `Permission denied` | Перенаправление `>` выполняет ваша оболочка до запуска sudo | `echo x \| sudo tee /etc/file >/dev/null` или `sudo sh -c 'echo x > /etc/file'` |
| `sudo cd /каталог` → `command not found` | `cd` — встроенная команда оболочки, отдельной программы нет | `sudo -i` или `sudo -s`, затем `cd`; либо `sudo ls /каталог` |
| `sudo ls /var/lib/postgresql/17/main/*.conf` → `No such file or directory`, хотя файлы есть | Шаблон раскрывает ваша оболочка, а у вас нет прав читать каталог — шаблон уходит в `ls` буквально | `sudo sh -c 'ls /var/lib/postgresql/17/main/*.conf'` |
| `sudo rac …` / `sudo psql` → `command not found`, без sudo работает | sudo заменяет `PATH` на `secure_path` | Полный путь к программе или ссылка в `/usr/local/bin` |
| Скрипт работает в терминале, но не в cron / не из юнита systemd | Нет вашего `PATH`, алиасов, переменных; cron запускает `/bin/sh` | Полные пути, явные переменные, `#!/bin/bash`; отладка: `env -i PATH=/usr/bin:/bin bash script.sh` |
| Правки `PATH`/переменных в `~/.bashrc` пользователя usr1cv8 не влияют на сервер 1С | Служба systemd не читает стартовые файлы оболочки | `sudo systemctl edit <юнит>` → `[Service]` `Environment=…` → `daemon-reload`, `restart` |
| `/bin/bash^M: bad interpreter`, `$'\r': command not found` | Файл сохранён в Windows с окончаниями строк CRLF | `sed -i 's/\r$//' script.sh` (или `dos2unix`); проверка: `file script.sh`; в редакторе на Windows выбрать окончания строк LF |
| `Syntax error: "(" unexpected`, `[[: not found` | Скрипт с bash-синтаксисом запущен через `sh` (в Ubuntu это dash) | `bash script.sh` или `#!/bin/bash` + `chmod +x` + `./script.sh` |
| `./script.sh: Permission denied` | Нет бита выполнения (или ФС смонтирована с `noexec`) | `chmod +x script.sh` либо `bash script.sh` |
| Команда с переменной «не находит файл» или обрабатывает не те файлы | Переменная без кавычек: значение с пробелами распалось на слова, `*` раскрылась | Всегда `"$var"`; проверка — `printf '<%s>\n' $var` |
| `rm` не может удалить файл с именем на `-` (`rm: invalid option`) | Имя воспринято как ключ | `rm -- -имя` или `rm ./-имя` |
| `Argument list too long` при `rm *`, `cp *` | Шаблон раскрылся в слишком длинный список (предел `getconf ARG_MAX`) | `find . -maxdepth 1 -name '*.log' -delete` или `find … -print0 \| xargs -0 rm -f --` |
| `find . -delete -name '*.tmp'` удалил всё | `-delete` стоит раньше условия | Условия — первыми, `-delete` — последним; сначала прогон с `-print` |
| `find -mtime +7` оставляет файлы «семидневной давности» | Возраст считается в целых сутках с отбрасыванием дроби: `+7` = 8 суток и более | `-mtime +6` либо точнее `-mmin +$((7*24*60))` |
| `ln -sf новый_каталог ссылка` создал ссылку *внутри* старого каталога | Существующая ссылка на каталог разыменовывается | `ln -sfn новый_каталог ссылка` |
| После `cp -r` сервер 1С или PostgreSQL не может открыть файлы | `cp -r` не сохраняет владельца и права; копирование от root делает владельцем root | `sudo cp -a` (или `rsync -a`); исправить: `sudo chown -R usr1cv8:grp1cv8 …` / `postgres:postgres …` |
| Сервер 1С перестал запускаться или не видит базу после «ручных» действий администратора | Утилиты 1С запускались от root — в каталоге кластера появились файлы root | `sudo find /home/usr1cv8/.1cv8 ! -user usr1cv8 -ls` → `sudo chown -R usr1cv8:grp1cv8 /home/usr1cv8/.1cv8` |
| `could not change directory to "/home/admin": Permission denied` при `sudo -u postgres …` | Текущий каталог недоступен пользователю postgres | Безвредно; `cd /tmp` перед командой или `sudo -iu postgres` |
| `This account is currently not available` при `sudo -iu usr1cv8` / `su - usr1cv8` | У учётной записи оболочка `nologin` | `sudo -u usr1cv8 -s` или `sudo su -s /bin/bash - usr1cv8` |
| Терминал «завис», не реагирует на ввод | Нажат `Ctrl+S` (остановка вывода) | `Ctrl+Q`; отключить навсегда: `stty -ixon` в `~/.bashrc` |
| После `cat` двоичного файла на экране «мусор», сбита кодировка | Управляющие последовательности перенастроили терминал | `reset` (вслепую, затем `Enter`) |
| Долгая операция прервалась при обрыве SSH или закрытии окна | Оболочка получила SIGHUP и разослала его заданиям | Запускать в `tmux`; на крайний случай `nohup … &`, `disown -h`, `systemd-run` |
| `-bash: !…: event not found` | `!` внутри двойных кавычек — подстановка истории | Одинарные кавычки, `\!` или `set +H` |
| `cmd 2>&1 > file` — ошибки всё равно на экране | Перенаправления применяются слева направо | `cmd > file 2>&1` или `cmd &> file` |
| Резервная копия `pg_dump … \| gzip > f.gz` пустая, а скрипт сообщил об успехе | Код возврата конвейера — от последней команды (`gzip`) | `set -o pipefail` в скрипте; проверять `${PIPESTATUS[0]}` |
| `df` показывает заполненный диск, `du` — намного меньше | Файл удалён, но открыт процессом (журнал) — место не освобождается | `sudo lsof +L1`; перезапустить или переоткрыть процесс; журналы обнулять `truncate -s 0`, а не удалять |
| В 26.04 `No space left on device` в `/tmp` при свободном диске; растёт использование памяти | `/tmp` — tmpfs с лимитом 50 % ОЗУ | Большие временные файлы — в `/var/tmp` (`mktemp -p /var/tmp`, `TMPDIR=/var/tmp`); `df -h /tmp`; изменить лимит — `sudo systemctl edit tmp.mount`; вернуть на диск — `sudo systemctl mask tmp.mount` + перезагрузка |
| Дистрибутив, дамп или выгрузка, оставленные в `/tmp` или `/var/tmp`, «сами исчезли» | `systemd-tmpfiles-clean.timer`: в 24.10+/26.04 из `/tmp` удаляется всё, чем не пользовались 10 дней, из `/var/tmp` — 30 дней; в 22.04/24.04 `/tmp` очищается при каждой загрузке, а в 24.04 ещё и от файлов старше 30 дней; в 26.04 `/tmp` к тому же теряется при перезагрузке | Не хранить нужное во временных каталогах; `cat /usr/lib/tmpfiles.d/tmp.conf`; исключения — строки `x /путь` в `/etc/tmpfiles.d/*.conf` |
| После обновления 24.04 → 26.04 «пропали» файлы из `/tmp` | Поверх старого каталога смонтирован tmpfs; прежние файлы остались на диске под точкой монтирования | `sudo mount --bind / /mnt && ls /mnt/tmp` (потом `sudo umount /mnt`) |
| `cp: warning: behavior of -n is non-portable and may change in future; use --update=none instead` (24.04) | Правка Debian/Ubuntu в coreutils 9.4: `cp -n` работает по-старому, но предупреждает | Заменить `-n` на `--update=none` (на 22.04 этой формы нет — там оставить `-n`) |
| Ошибка вида `cp: option '--update' doesn't allow an argument` (22.04) или `cp: invalid argument 'none-fail' for '--update'` (24.04); точный текст зависит от версии и локали | `--update=none` появился в coreutils 9.3 (в 22.04 — 8.32), `none-fail` работает с 9.6 (в 24.04 — 9.4) | На 22.04 — `cp -n`; переносимо — `[[ -e "$dst" ]] \|\| cp -a "$src" "$dst"` |
| Клиенты не подключаются к серверу 1С (ошибки сетевого доступа), хотя служба запущена и порты открыты | Одна из типичных причин (практика сообщества, ⚠ с документацией 1С не сверено): в `/etc/hosts` имя хоста сопоставлено с `127.0.1.1` (так записывает установщик Ubuntu), и имя сервера разрешается в петлевой адрес | Сопоставить имя хоста с реальным IP (`192.168.56.10 srv1c.example.local srv1c`); проверка — `getent hosts "$(hostname)"`, `hostname -f`, `hostname -I`; при cloud-init учесть `manage_etc_hosts` (подробнее — в статьях о сети и о сервере 1С) |
| Скрипт, работавший на 22.04/24.04, на 26.04 ведёт себя иначе | uutils вместо GNU coreutils: другой текст вывода/ошибок, отличия в `stat`, `sort`, `uname -p` | Не разбирать «человеческий» вывод (использовать `stat -c`, `date +…`, `LC_ALL=C`); вызвать `gnu`-вариант (`gnustat`, `gnusort`); в крайнем случае `coreutils-from-gnu` |
| В 26.04 `sudo -E …` не передаёт переменные; `expect`-скрипт «не видит» запрос пароля sudo | sudo-rs: `-E` игнорируется, приглашение имеет другой текст | `sudo --preserve-env=VAR1,VAR2 …` или `sudo env VAR=… cmd`; `sudo --prompt ""`/`-S`; при необходимости `sudo.ws` |
| `[: too many arguments`, `[: =: unary operator expected` | В `[ ]` переменная без кавычек: пустая или с пробелами | `[ "$var" = x ]` либо `[[ $var == x ]]` |
| `var = value` → `var: command not found` | Пробелы вокруг `=` | `var=value` |
| `echo {1..$n}` печатает `{1..5}` | Фигурные скобки раскрываются раньше переменных | `seq 1 "$n"` или `for ((i=1; i<=n; i++))` |
| Изменил `~/.profile` — ничего не поменялось | Нужен новый вход; либо существует `~/.bash_profile`, и `~/.profile` не читается | `exec bash -l` или перелогиниться; проверить `ls -la ~/.bash_profile ~/.bash_login` |
| Команды из параллельных сессий не попадают в историю | Файл истории перезаписывается при выходе последней сессией | `shopt -s histappend` и `PROMPT_COMMAND='history -a'` |
| Пароль остался в `~/.bash_history` | Передан аргументом команды | `history -d N` и `history -w`; впредь `~/.pgpass`, `read -rs`, пробел перед командой |
| `locate` не находит только что созданный файл | База обновляется раз в сутки | `sudo updatedb` или `find` |
| В mc не работает `F10` (открывается меню терминала) или другие F-клавиши | Клавишу перехватывает терминал/SSH-клиент | `Esc`, затем цифра (`Esc` `0` = `F10`); отключить перехват в настройках терминала |
| В screen `Ctrl+A` не переводит курсор в начало строки | `Ctrl+A` — префикс команд screen | `Ctrl+A`, затем `a`; или перейти на tmux (префикс `Ctrl+B`) |
| `nohup: ignoring input and appending output to 'nohup.out'` | Это информационное сообщение, а не ошибка | Перенаправлять явно: `nohup cmd > file.log 2>&1 &` |
| Алиас `ll` не работает у postgres/usr1cv8, в скрипте, после sudo | Алиасы определены в `~/.bashrc` конкретного пользователя и действуют только интерактивно | Писать полную команду (`ls -la`); в скриптах — функции |
