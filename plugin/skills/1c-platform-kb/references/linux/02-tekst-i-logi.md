# Обработка текста и анализ логов в Ubuntu: grep, sed, awk и смежные утилиты; редакторы nano и vim

> Область: работа с текстом и журналами на сервере «1С:Предприятие 8» + PostgreSQL под Ubuntu Server (просмотр файлов, поиск, потоковая правка, агрегация, JSON/XML, кодировки и BOM, редакторы, практикум по journald, /var/log, журналам PostgreSQL и технологическому журналу 1С) | Версии: Ubuntu 22.04 LTS (jammy) / 24.04 LTS (noble) / 26.04 LTS (resolute); GNU grep 3.7 / 3.11 / 3.12; GNU sed 4.8 / 4.9 / 4.9; mawk 1.3.4-20200120 / -20240123 / -20260129; gawk 5.1.0 / 5.2.1 / 5.3.2; coreutils GNU 8.32 / GNU 9.4 / uutils (Rust) 0.8.0; less 590 / 590 / 668; nano 6.2 / 7.2 / 8.7.1; vim 8.2 / 9.1.0016 / 9.1.2141; jq 1.6 / 1.7.1 / 1.8.1; ripgrep 13.0 / 14.1 / 15.1; PCRE2 (библиотека для `grep -P`) 10.39 / 10.42 / 10.46; платформа 1С 8.3.x–8.5.x (на ИТС опубликована документация до 8.5.4; раздела v855doc на 2026-10-10 нет); PostgreSQL 14–18 (на 2026-10-10 актуальны корректирующие выпуски 18.6 / 17.11 / 16.15 / 15.19 / 14.24 от 2026-08-13; PostgreSQL 19 — Beta 4 от 2026-09-24, не выпущен; поддержка ветки 14 заканчивается 2026-11-12) | Актуальность: 2026-10-10 (фактчекинг по первоисточникам выполнен 2026-10-10; что проверить не удалось — помечено «⚠»)

Условные обозначения: «⚠ не подтверждено» — утверждение записано по памяти/косвенным данным и не проверено по первоисточнику; «(ИТС)» — официальная методика фирмы «1С»; «(адаптация)» — доработка автора статьи на основе официальной методики.

## Кратко

1. **Базовый конвейер анализа любого лога:** `grep … | sed … | awk … | sort | uniq -c | sort -rn | head`. Почти любая задача «найти, выделить, сгруппировать, отсортировать, показать топ» решается этой цепочкой.
2. **`awk` в Ubuntu — это либо `mawk`, либо GNU awk (`gawk`); всегда проверяйте: `readlink -f "$(command -v awk)"`.** Базовая реализация — `mawk`: в контейнерах, минимизированных установках и облачных minimal-образах есть только она. Но на стандартной установке Ubuntu Server 22.04/24.04 метапакет `ubuntu-server` тянет `byobu`, а `byobu` зависит от `gawk` — и тогда `awk` указывает на gawk (у него приоритет альтернативы выше); в манифесте установочного образа Server 26.04.1 `gawk` тоже присутствует. mawk быстрый, но работает с байтами (кириллица в UTF-8 = 2 байта на букву), не имеет `gensub()`, `IGNORECASE`, `FPAT`, `-i inplace`; в Ubuntu 22.04 (mawk 20200120) не понимает интервалы `{n,m}` в регулярных выражениях. Нужен gawk, а его нет — `sudo apt install gawk` (после установки `awk` начинает указывать на gawk).
3. **Ubuntu 26.04: `cat`, `head`, `tail`, `sort`, `uniq`, `cut`, `tr`, `wc`, `tee`, `od` и др. — это Rust-реализация uutils 0.8.0** (пакет `rust-coreutils`), а не GNU coreutils; `cp`, `mv`, `rm` остались GNU. GNU-варианты доступны с префиксом `gnu` (`gnusort`, `gnutail`, `gnucut` …). `grep`, `sed`, `awk`, `less`, `diff`, `find`/`xargs` — отдельные пакеты, они по-прежнему GNU/mawk. `sudo` в 26.04 — это `sudo-rs`.
4. **Технологический журнал (ТЖ) 1С** — текстовые файлы `<каталог>/<процесс>_<PID>/ГГММДДЧЧ.log` в UTF-8 **с BOM**; строка события: `мм:сс.микросекунды-длительность,СОБЫТИЕ,уровень,свойство=значение,…`; длительность в 8.3+ — в **микросекундах** (1 с = 1 000 000). Событие может занимать несколько строк (Context, Sql) — перед grep/awk его надо «склеить» в одну строку.
5. **BOM (`EF BB BF`)** в начале файла ломает якорь `^` на первой строке, shebang скриптов и сравнение строк. Проверка: `head -c3 файл | xxd -p` → `efbbbf`. Удаление: `sed -i '1s/^\xEF\xBB\xBF//' файл`.
6. **Кириллица:** поиск без учёта регистра (`grep -i`), классы `[[:alpha:]]`, `\w`, `.` как «один символ» работают с кириллицей только в UTF-8-локали (`ru_RU.UTF-8`, `C.UTF-8`). Исключение — `grep -P`: там `\w` и `\b` в Ubuntu 22.04 и 24.04 остаются ASCII-только даже в UTF-8-локали (Юникод — лишь в 26.04); переносимо пишите `\p{L}`/`\p{Cyrillic}` (раздел 3.4). `LC_ALL=C` ускоряет grep/sort в разы, но превращает всё в байты.
7. **Числа и локаль:** в `ru_RU.UTF-8` десятичный разделитель — запятая: `sort -n` неверно сортирует `12.5`, а `printf '%.2f' 1.5` в bash даёт ошибку. Для разборов логов: `export LC_NUMERIC=C LC_COLLATE=C`.
8. **grep:** `-E` (расширенные выражения), `-P` (Perl-совместимые: `\d`, `\K`, просмотры), `-F` (строка буквально), `-o` (только совпадение), `-r` (рекурсивно), `-n`, `-c`, `-l`/`-L`, `-v`, `-w`, `-A/-B/-C` (контекст), `--include='*.log'`. Извлечь значение свойства: `grep -oP 'SessionID=\K\d+'`.
9. **Слежение за логом:** `tail -F файл` (переживает ротацию), `less +F файл` (Ctrl+C — остановить и листать, `F` — снова следить), `journalctl -fu юнит`. В конвейере с `tail -f` у grep нужен `--line-buffered`.
10. **sed:** `sed -i.bak 's/старое/новое/g' файл` — правка на месте с резервной копией; `sed -n '10,20p'` — строки 10–20; `sed '/шаблон/d'` — удалить строки; `-E` — расширенные регулярные выражения.
11. **Ротированные логи:** `zgrep`, `zcat`, `zless` читают и обычные, и `.gz`-файлы: `zgrep -h FATAL /var/log/postgresql/postgresql-17-main.log*`. `zgrep` не умеет `-r`.
12. **journald:** `journalctl -u ЮНИТ -p err -b --since "1 hour ago" --no-pager`; `-g 'шаблон'` — встроенный grep (PCRE2; шаблон целиком в нижнем регистре = без учёта регистра); `-o json | jq` — структурный разбор; `-k` — ядро (OOM-killer).
13. **Журнал PostgreSQL в Ubuntu (пакеты PGDG/Ubuntu):** `/var/log/postgresql/postgresql-<версия>-<кластер>.log`, префикс строки по умолчанию `'%m [%p] %q%u@%d '`. Длительные запросы пишутся при `log_min_duration_statement` ≥ 0 строкой `duration: 1234.567 ms  statement: …`. При `lc_messages = ru_RU.UTF-8` метки уровня и текст переводятся (`ОШИБКА`, `ВАЖНО`, `продолжительность`) — шаблоны grep надо менять.
14. **xargs:** всегда `find … -print0 | xargs -0 -r …` (пробелы в именах; `-r` — не запускать команду при пустом вводе); `-P N` — параллельно; `-I{}` — подстановка; `-n N` — по N аргументов.
15. **sort:** `-n` числа, `-r` обратный порядок, `-k2,2` ключ (именно `2,2`, а не `2`), `-t';'` разделитель, `-u` уникальные, `-h` «человеческие» размеры (`du -sh * | sort -h`), `-V` версии (`8.3.9 < 8.3.27`). `uniq` требует отсортированного ввода.
16. **JSON/XML:** `jq` — для JSON (journald, jsonlog PostgreSQL 15+, ТЖ 1С в формате json с 8.3.25); `xmllint --noout файл` — проверка, что XML корректен (logcfg.xml, default.vrd); у XML-файлов 1С есть пространство имён по умолчанию — в XPath нужен `local-name()` либо `xmlstarlet -N`.
17. **Кодировки:** `file -i файл` (определить), `iconv -f CP1251 -t UTF-8 вход > выход` (перекодировать, не в тот же файл), `dos2unix`/`unix2dos` (CRLF↔LF; `dos2unix` по умолчанию ещё и удаляет BOM).
18. **Редакторы:** системный редактор по умолчанию — nano (`Ctrl+O` записать, `Ctrl+X` выйти, `Ctrl+W` поиск, `Ctrl+\` замена, `Alt+U` отмена). В vim: `i` — ввод, `Esc` — команды, `:wq` — сохранить и выйти, `:q!` — выйти без сохранения. Сменить редактор: `sudo update-alternatives --config editor` или переменная `EDITOR`. Системные файлы править через `sudoedit файл`.
19. **Официальная методика 1С по разбору ТЖ** (ИТС, «Анализ технологического журнала с помощью регулярных выражений», bash): склейка событий perl-однострочником → удаление BOM → `grep -P` → нормализация `perl -pe`/`sed` → группировка `awk` → `sort -rnb | head`. Готовые конвейеры — в разделе практикума.

### 1.3. Ubuntu 26.04: uutils вместо GNU coreutils

Официально (Canonical, заметки к выпуску 26.04): базовые утилиты поставляет пакет `rust-coreutils`; из-за нерешённых ошибок `cp`, `mv` и `rm` по-прежнему берутся из GNU; GNU-варианты всех утилит вызываются с префиксом `gnu` (например, `gnuls`).

```bash
gnusort --version | head -1              # GNU-версия рядом с системной (пакет gnu-coreutils)
ls /usr/bin/gnu* | head                  # полный список GNU-двойников

# Полностью переключить систему на GNU coreutils (официальная команда из заметок к выпуску):
sudo apt install coreutils-from-gnu coreutils-from-uutils- --allow-remove-essential
# Вернуть uutils:
sudo apt install coreutils-from-uutils coreutils-from-gnu- --allow-remove-essential
```

Практические следствия для работы с текстом:

- Скрипты и однострочники из этой статьи используют только общие для GNU и uutils возможности. Если команда из coreutils в 26.04 ведёт себя неожиданно — проверьте её GNU-двойником (`gnusort`, `gnucut`, `gnutr`…).
- Известное отличие: порядок сортировки `sort` в многобайтовых локалях может отличаться от GNU; при `LC_ALL=C` (или `LC_COLLATE=C`) результат одинаков (практика сообщества). По исходному коду uutils 0.8.0 (`src/uu/sort/src/sort.rs`): в UTF-8-локали `sort` использует сравнение по правилам локали (модуль `uucore::i18n::collator`; это не тот же код, что `strcoll` в GNU sort, — отсюда возможные расхождения в порядке; какие именно — ⚠ не проверено), а `sort -n` берёт десятичный разделитель и разделитель групп из локали, как GNU.
- `cut -c` в uutils 0.8.0 работает **с байтами** — точно так же, как `-b` (в исходном коде версии 0.8.0 оба режима обрабатывает одна функция `cut_bytes`), т. е. ведёт себя как GNU coreutils 8.32/9.4: `echo 'привет' | cut -c1-3` выдаст «п» и половину буквы «р». В более новых версиях uutils (ветка `main` после 0.8.0) `-c` в многобайтовой локали уже считает символы — после обновления пакета поведение может измениться, поэтому для обрезки по символам пользуйтесь `grep -oP '^.{0,N}'` или gawk `substr`.
- `tr` в uutils 0.8.0 тоже побайтовый (таблица трансляции на 256 значений), как и GNU `tr`: регистр кириллицы им сменить нельзя.
- `sudo-rs` поддерживает `sudoedit` (появилось в sudo-rs 0.2.8 от 2025-08-04; в 26.04 — sudo-rs 0.2.13); классический sudo доступен как `sudo.ws`.
- В журнале обсуждения Canonical упоминаются жалобы пользователей на отдельные утилиты uutils 0.8.0 (`install`, `cp`, `mv`); к текстовым утилитам из этой статьи они не относятся, но при обработке важных данных в 26.04 результат стоит перепроверять GNU-двойником.

## 2. Просмотр файлов

### 2.1. cat, tac, nl

```bash
cat файл                      # вывести целиком
cat -n файл                   # с номерами всех строк
cat -A файл                   # показать невидимое: ^I = табуляция, $ = конец строки, ^M$ = CRLF, M-… = не-ASCII байты
cat -s файл                   # сжать подряд идущие пустые строки в одну
cat a.log b.log > all.log     # склеить файлы
tac файл                      # строки в обратном порядке (последние — первыми)
nl -ba файл                   # пронумеровать все строки (без -ba пустые не нумеруются)
nl -ba -w3 -s': ' файл        # ширина номера 3, разделитель «: »
```

`cat -A` — самый быстрый способ увидеть, что файл пришёл из Windows (`^M$` в конце строк) или что отступы сделаны табуляциями.

### 2.2. head и tail

```bash
head файл                     # первые 10 строк
head -n 50 файл               # первые 50 строк
head -n -5 файл               # всё, кроме последних 5 строк
head -c 3 файл | xxd          # первые 3 байта (проверка BOM)

tail файл                     # последние 10 строк
tail -n 200 файл              # последние 200
tail -n +2 файл               # начиная со 2-й строки (пропустить заголовок)
tail -c 1M файл               # последний мебибайт
tail -f файл                  # следить за дописыванием (по дескриптору файла)
tail -F файл                  # = --follow=name --retry: следить по ИМЕНИ, переживает ротацию/пересоздание
tail -f --pid=12345 файл      # завершиться, когда умрёт процесс 12345
tail -f -s 5 файл             # опрашивать раз в ~5 с (по умолчанию 1.0)
tail -q -f a.log b.log        # несколько файлов без заголовков «==> имя <==»
```

Ключевые флаги `tail`: `-n [+]N` — число строк (`+N` — начиная с N-й); `-c [+]N` — байты; `-f` — следить; `-F` — следить по имени с повторными попытками открыть; `--retry` — повторять открытие недоступного файла; `--pid=PID` — вместе с `-f` завершиться после смерти процесса; `-s N` — интервал опроса; `-q`/`-v` — без заголовков/всегда с заголовками; `-z` — разделитель строк NUL.

Примеры:

```bash
# Журнал PostgreSQL в реальном времени, только ошибки:
tail -F /var/log/postgresql/postgresql-17-main.log | grep --line-buffered -E 'ERROR|FATAL|PANIC'

# Смотреть лог, пока работает фоновая команда (tail завершится вместе с ней):
pg_dump -Fc -f /backup/erp.dump erp & tail -f --pid=$! /var/log/postgresql/postgresql-17-main.log

# Все файлы ТЖ рабочих процессов сразу (ИТС):
tail -f rphost*/*.log | grep --line-buffered ',EXCP,'
```

Важно: `tail -f` продолжает читать старый файл после ротации (logrotate переименовал файл и создал новый) — для логов, которые ротируются, используйте `-F`. Шаблон `rphost*/*.log` раскрывается оболочкой один раз: файлы следующего часа (`ГГММДДЧЧ.log`) в уже запущенный `tail` не попадут.

### 2.3. less — основной просмотрщик

```bash
less файл
less -N файл                  # с номерами строк
less -S файл                  # не переносить длинные строки (стрелки ←/→ — горизонтальная прокрутка)
less -i файл                  # поиск без учёта регистра, если в шаблоне нет заглавных (-I — всегда)
less -R файл                  # пропускать цветовые ESC-последовательности (для вывода grep --color=always)
less +G файл                  # открыть сразу в конце
less +F файл                  # открыть в режиме слежения (как tail -f)
less +/FATAL файл             # открыть на первом совпадении (то же: less -p FATAL файл)
less --follow-name +F файл    # в режиме F переоткрывать файл по имени (переживает ротацию)
команда | less -S             # просмотр вывода команды
zless файл.log.2.gz           # просмотр сжатого файла
```

Клавиши внутри `less`:

| Клавиша | Действие |
|---|---|
| `Пробел` / `f`, `b` | страница вперёд / назад |
| `d`, `u` | полстраницы вперёд / назад |
| `j`/`↓`, `k`/`↑` | строка вниз / вверх |
| `g`, `G` | в начало / в конец файла; `123g` — к строке 123 |
| `50p` или `50%` | перейти на 50 % файла |
| `/шаблон`, `?шаблон` | поиск вперёд / назад (регулярное выражение) |
| `n`, `N` | следующее / предыдущее совпадение |
| `&шаблон` | показывать только строки с шаблоном (фильтр); пустой `&` — снять фильтр |
| `Esc u` | включить/выключить подсветку найденного |
| `F` | режим слежения (как `tail -f`); `Ctrl+C` — выйти из слежения и листать |
| `Esc F` | следить, но остановиться, когда появится строка, совпавшая с последним поиском |
| `-N`, `-S`, `-i` | переключить опцию прямо во время просмотра |
| `m` + буква, `'` + буква | поставить метку / вернуться к метке |
| `v` | открыть текущий файл в редакторе (`$VISUAL`/`$EDITOR`) |
| `s файл` | сохранить ввод в файл (когда читаем из конвейера) |
| `:n`, `:p` | следующий / предыдущий файл из списка |
| `h`, `q` | справка / выход |

Переменные окружения: `LESS` — опции по умолчанию (например, `export LESS='-R -i -M'`), `LESSCHARSET=utf-8` — если кириллица показывается как `<D0><9F>`, `LESSOPEN` — препроцессор. Файл в CP1251 `less` в UTF-8-терминале покажет «кракозябрами» — сначала перекодируйте: `iconv -f CP1251 файл | less`.

### 2.4. more

Простейший постраничный просмотрщик (util-linux), полезен там, где нет `less`: `Пробел` — страница, `Enter` — строка, `/шаблон` — поиск, `q` — выход. `more +100 файл` — начать со строки 100; `more -s` — сжимать пустые строки. Назад листает только для файлов (не для конвейера).

### 2.5. wc

```bash
wc -l файл                    # число строк (точнее — символов перевода строки)
wc -w файл                    # слов
wc -c файл                    # байт
wc -m файл                    # символов (в UTF-8-локали кириллическая буква = 1 символ, 2 байта)
wc -L файл                    # длина самой длинной строки
wc -l rphost_*/*.log | sort -n | tail    # самые большие (по строкам) файлы ТЖ
```

Файл без завершающего перевода строки `wc -l` посчитает на одну строку меньше.

### 2.6. od, xxd, hexdump — побайтовый просмотр

```bash
head -c 16 файл | xxd                 # 00000000: efbb bf3c 3f78 6d6c …  (видно BOM ef bb bf)
xxd -l 64 файл                        # первые 64 байта
xxd -s 1024 -l 64 файл                # 64 байта со смещения 1024
xxd -p файл                           # «голый» hex без адресов
xxd -r дамп.hex > файл.bin            # обратно из hex-дампа в двоичный файл
od -c файл | head                     # символы и \r \n \t, остальное восьмерично
od -An -tx1 -N3 файл                  # три первых байта: « ef bb bf»
od -A x -t x1z -v файл | head         # hex + ASCII, адреса в hex
hexdump -C файл | head                # классический вид «адрес | hex | ASCII»
```

Пакеты: `od` — coreutils; `xxd` — пакет `xxd`; `hexdump` — пакет `bsdextrautils`.

### 2.7. strings

Вытаскивает печатные последовательности из двоичных файлов (пакет `binutils`, на минимальной установке может отсутствовать):

```bash
strings файл | less                   # последовательности ASCII длиной от 4 символов
strings -n 8 файл                     # не короче 8 символов
strings -el файл                      # 16-битные little-endian строки (UTF-16LE — частый случай для файлов из Windows)
strings -t x файл                     # со смещением (hex) каждой строки
strings /proc/12345/environ           # переменные окружения процесса (разделены NUL)
```

### 2.8. file — тип и кодировка

```bash
file файл                     # «Unicode text, UTF-8 (with BOM) text, with CRLF line terminators»
file -i файл                  # MIME-тип и кодировка: «text/plain; charset=utf-8»
file -bi файл                 # то же без имени файла
file -i *.txt                 # для пачки файлов
```

Ограничение: однобайтовые кириллические кодировки `file` не различает — для CP1251/KOI8-R/CP866 он обычно пишет `charset=iso-8859-1` или `unknown-8bit`. Точнее определяют `uchardet файл` (пакет `uchardet`) и `enca -L ru файл` (пакет `enca`). Формулировка «(with BOM)» в старых версиях `file` выглядит как «UTF-8 Unicode (with BOM) text».

### 2.9. iconv — перекодировка

```bash
iconv -l | grep -iE '1251|866|koi8'                    # имена кодировок
iconv -f CP1251 -t UTF-8 вход.txt > выход.txt          # Windows-1251 → UTF-8
iconv -f CP1251 -t UTF-8 вход.txt -o выход.txt         # то же, с -o
iconv -f UTF-8 -t CP1251 вход.txt > выход.txt          # обратно (для обмена со старыми Windows-программами)
iconv -f UTF-8 -t CP1251//TRANSLIT вход.txt            # непредставимые символы заменять похожими
iconv -c -f UTF-8 -t CP1251 вход.txt                   # непредставимые символы молча выбрасывать
iconv -f CP866 -t UTF-8 dos.txt                        # DOS-кодировка
iconv -f UTF-16 -t UTF-8 файл.txt                      # UTF-16 с BOM (экспорт из Windows)
iconv -f UTF-8 -t UTF-8 файл > /dev/null && echo OK    # проверка: корректен ли файл как UTF-8
```

Правила:

- Не направляйте вывод в тот же файл, что читаете (`iconv … f > f` обнулит файл). Через временный файл: `iconv -f CP1251 -t UTF-8 f > f.tmp && mv f.tmp f`, либо `… | sponge f` (пакет `moreutils`).
- `iconv` в UTF-8 **не добавляет BOM**. Если принимающей стороне (например, загрузке в 1С) нужен BOM: `{ printf '\xEF\xBB\xBF'; iconv -f CP1251 -t UTF-8 вход.txt; } > выход.txt`.
- Повторная перекодировка уже перекодированного файла портит текст («Ð¿Ñ€Ð¸Ð²ÐµÑ‚» — признак двойного кодирования). Сначала `file -i`, потом `iconv`.

Массовая перекодировка:

```bash
find . -name '*.txt' -print0 | while IFS= read -r -d '' f; do
  iconv -f CP1251 -t UTF-8 "$f" > "$f.tmp" && mv "$f.tmp" "$f"
done
```

### 2.10. dos2unix / unix2dos — переводы строк

```bash
sudo apt install dos2unix
dos2unix файл                 # CRLF → LF на месте. ВНИМАНИЕ: BOM при этом удаляется (по умолчанию BOM в результат не пишется)
dos2unix -b файл              # CRLF → LF, BOM сохранить (--keep-bom)
dos2unix -r файл              # явно удалить BOM (--remove-bom)
dos2unix -n вход выход        # в новый файл, исходный не трогать
dos2unix -k файл              # сохранить дату изменения
unix2dos файл                 # LF → CRLF (BOM сохраняется, если был)
unix2dos -m файл              # LF → CRLF и добавить BOM (--add-bom)
dos2unix -i файл              # только информация: число DOS/Unix/Mac-переводов строк, BOM, text/binary
dos2unix -ic *.sh             # вывести имена только тех файлов, которые были бы преобразованы
```

Двоичные файлы пропускаются автоматически (`-f` — принудительно). Без пакета `dos2unix`:

```bash
sed -i 's/\r$//' файл         # CRLF → LF
tr -d '\r' < вход > выход     # удалить все \r
sed -i 's/$/\r/' файл         # LF → CRLF
grep -c $'\r' файл            # сколько строк содержит \r
```

## 3. grep — поиск строк по шаблону

### 3.1. Синтаксис и режимы

```
grep [ОПЦИИ] 'ШАБЛОН' [ФАЙЛ…]
grep [ОПЦИИ] -e 'ШАБЛОН1' -e 'ШАБЛОН2' [ФАЙЛ…]
grep [ОПЦИИ] -f файл_с_шаблонами [ФАЙЛ…]
```

Шаблон всегда берите в одинарные кавычки. Код возврата: `0` — найдено, `1` — не найдено, `2` — ошибка (удобно в скриптах: `if grep -q …; then`).

| Режим | Опция | Когда применять |
|---|---|---|
| Базовые регулярные выражения (BRE) | по умолчанию (`-G`) | простые шаблоны; символы `+ ? { } ( )` и вертикальная черта — обычные литералы, спецсмысл им даёт обратный слэш перед ними (см. таблицу в 3.4) |
| Расширенные (ERE) | `-E` | альтернативы, группы, квантификаторы без обратных слэшей — основной рабочий режим |
| Perl-совместимые (PCRE2) | `-P` | `\d`, ленивые квантификаторы, `\K`, просмотры вперёд/назад, `\p{Cyrillic}` |
| Фиксированная строка | `-F` | искать текст буквально (точки, скобки, `*` — не спецсимволы); самый быстрый режим |

`egrep`, `fgrep`, `rgrep` — устаревшие синонимы `grep -E`, `grep -F`, `grep -r`; в Debian/Ubuntu они сохранены для совместимости, но в новых скриптах пишите `grep -E` / `grep -F`.

### 3.2. Все основные опции

| Опция | Действие |
|---|---|
| `-i` | без учёта регистра (для кириллицы — только в UTF-8-локали) |
| `-v` | инвертировать: строки, НЕ содержащие шаблон |
| `-w` | совпадение целым словом |
| `-x` | совпадение целой строкой |
| `-n` | номер строки перед каждой найденной строкой |
| `-c` | вывести число совпавших **строк** (не совпадений) по каждому файлу |
| `-l` | только имена файлов, где есть совпадение |
| `-L` | только имена файлов, где совпадений нет |
| `-o` | выводить только совпавшую часть, каждое совпадение с новой строки |
| `-q` | ничего не выводить, только код возврата |
| `-s` | не сообщать о несуществующих/нечитаемых файлах |
| `-H` / `-h` | всегда / никогда не печатать имя файла перед строкой |
| `-r` | рекурсивно по каталогу; символические ссылки обходятся, только если указаны в командной строке |
| `-R` | рекурсивно, следуя всем символическим ссылкам |
| `--include='GLOB'` | при рекурсии искать только в файлах, чьё имя подходит под шаблон |
| `--exclude='GLOB'` | пропускать файлы с таким именем |
| `--exclude-dir='GLOB'` | пропускать каталоги с таким именем |
| `-A N` / `-B N` / `-C N` | показать N строк после / до / вокруг совпадения (группы разделяются строкой `--`) |
| `-m N` | остановиться после N совпавших строк в файле |
| `-e ШАБЛОН` | задать шаблон явно (несколько `-e` = ИЛИ; нужен и для шаблонов, начинающихся с `-`) |
| `-f ФАЙЛ` | брать шаблоны из файла, по одному на строку |
| `-E` / `-P` / `-F` | режим шаблона (см. выше) |
| `-a` | считать двоичный файл текстом (`--binary-files=text`) |
| `-I` | пропускать двоичные файлы |
| `-z` | строки ввода и вывода разделены NUL, а не `\n` (весь обычный текстовый файл становится одной «строкой»); в сочетании с `-P` считается экспериментальным |
| `-Z` | после имени файла выводить NUL (для `xargs -0`) |
| `-b` | смещение в байтах перед каждой строкой |
| `-T` | выравнивать вывод табуляцией |
| `--color=auto\|always\|never` | подсветка совпадений; `always` нужен, если дальше идёт `less -R` |
| `--line-buffered` | сбрасывать вывод построчно (обязательно в конвейере после `tail -f`) |
| `--no-group-separator` | не печатать `--` между группами контекста |

(В строке про `--color` запись `\|` — это экранированная для Markdown-таблицы вертикальная черта, т. е. значения: `auto`, `always`, `never`.)

В стандартном `~/.bashrc` Ubuntu определён псевдоним `alias grep='grep --color=auto'`.

### 3.3. Примеры

```bash
# Базовое
grep -n 'FATAL' /var/log/postgresql/postgresql-17-main.log        # с номерами строк
grep -c ',EXCP,' rphost_1234/26101009.log                         # сколько строк с исключениями
grep -i 'ошибка' файл.log                                          # без учёта регистра (нужна UTF-8-локаль)
grep -v '^#' /etc/postgresql/17/main/postgresql.conf | grep -v '^\s*$'   # конфиг без комментариев и пустых строк
grep -w 'rphost' список.txt                                        # «rphost», но не «rphost_1234»

# Несколько шаблонов
grep -E 'ERROR|FATAL|PANIC' файл.log
grep -e 'TTIMEOUT' -e 'TDEADLOCK' файл.log
grep -F -f sessions.txt файл.log                                   # строки, содержащие любой из идентификаторов из файла

# Рекурсия и отбор файлов
grep -rn 'Lock request timeout' /var/log/1c/techlog/               # по всему каталогу
grep -rl ',EXCP,' /var/log/1c/techlog/                             # только имена файлов
grep -rL 'ssl = on' /etc/postgresql/                               # файлы БЕЗ строки
grep -rn --include='*.conf' 'listen_addresses' /etc/postgresql/    # только в *.conf
grep -rn --include='*.log' --exclude-dir='ragent_*' 'EXCP' .       # исключить каталоги
grep -rc ',EXCP,' rphost_*/ | grep -v ':0$'                        # счётчики по файлам, без нулевых

# Контекст
grep -n -A3 -B1 'deadlock detected' файл.log                       # 1 строка до, 3 после
grep -C5 'OOM' /var/log/syslog

# Только совпадение (-o) и извлечение значений (-P с \K)
grep -oE '[0-9]{1,3}(\.[0-9]{1,3}){3}' auth.log | sort | uniq -c | sort -rn | head    # топ IP-адресов
grep -oP 'SessionID=\K\d+' файл.log | sort -n | uniq -c            # значения свойства SessionID
grep -oP ',Usr=\K[^,]+' файл.log | sort | uniq -c | sort -rn       # топ пользователей 1С
grep -oPh ',EXCP,\K(ClientID=\d+)' rphost_*/*.log                  # (ИТС) ClientID из событий EXCP
grep -oP 'duration: \K[0-9.]+(?= ms)' pg.log | sort -rn | head     # длительности запросов PostgreSQL
grep -o 'ERROR' файл.log | wc -l                                   # число СОВПАДЕНИЙ, а не строк

# В скриптах
if grep -q '^shared_preload_libraries' "$CONF"; then echo "задано"; fi
grep -m1 -n 'PANIC' файл.log                                       # первое вхождение и выход

# Цвет через less
grep --color=always -n 'ERROR' файл.log | less -R

# Двоичные/«почти текстовые» файлы
grep -a 'текст' файл.bin                                           # не отвечать «binary file matches»

# Многострочный поиск: -z превращает файл в одну строку, (?s) — точка совпадает с \n
grep -Pzo '(?s)<log .*?</log>' logcfg.xml | tr '\0' '\n'

# Имена с пробелами → xargs
grep -rlZ 'старый_хост' /etc/ | xargs -0 -r sed -i.bak 's/старый_хост/новый_хост/g'
```

Замечания:

- `-c` считает строки, а не вхождения; для вхождений — `grep -o … | wc -l`.
- `--include`/`--exclude` сопоставляются с **именем файла** (без пути) и работают при рекурсии; шаблон берите в кавычки, иначе его раскроет оболочка.
- При противоречащих `--include` и `--exclude` побеждает последний подходящий.
- Сообщение `grep: файл: binary file matches` означает, что в файле есть NUL-байты или последовательности, недопустимые в текущей кодировке (типичный случай — файл в CP1251 при локали UTF-8). Решения: `grep -a`, либо `iconv -f CP1251 -t UTF-8 файл | grep …`.
- `grep -r` без указания каталога ищет в текущем каталоге.

### 3.4. Регулярные выражения: BRE, ERE, PCRE

```
Элемент                   BRE (grep, sed)          ERE (grep -E, sed -E, awk)   PCRE (grep -P, perl)
любой символ              .                        .                            .
начало / конец строки     ^   $                    ^   $                        ^   $
0 и более                 *                        *                            *      (ленивый *?)
1 и более                 \+                       +                            +      (ленивый +?)
0 или 1                   \?                       ?                            ?
ровно n / от n до m       \{n\}  \{n,m\}           {n}  {n,m}                   {n}  {n,m}
группа                    \( … \)                  ( … )                        ( … )   (?: … ) без захвата
альтернатива (ИЛИ)        \|                       |                            |
обратная ссылка           \1 … \9                  \1 … \9 (GNU)                \1 … \9
набор / отрицание         [abc]  [^abc]  [a-z]     то же                        то же
POSIX-классы              [[:digit:]] [[:alpha:]] [[:alnum:]] [[:space:]] [[:upper:]] [[:lower:]] [[:punct:]]
цифра                     [0-9]                    [0-9]                        \d
«словесный» символ        \w  (= [_[:alnum:]])     \w (GNU)                     \w
пробельный символ         \s (GNU)                 \s (GNU)                     \s
граница слова             \<  \>  \b               \<  \>  \b (GNU)             \b
«забыть» левую часть      —                        —                            \K
просмотр вперёд / назад   —                        —                            (?=…) (?!…)  (?<=…) (?<!…)
без учёта регистра        опция -i                 опция -i                     (?i) внутри шаблона или -i
свойства Юникода          —                        —                            \p{Cyrillic}  \p{L}  \p{Lu}
символ по коду            —                        —                            \x{FEFF}  \xHH
```

Пояснения:

- `\+`, `\?`, `\|` в BRE и `\w`, `\s`, `\b`, `\<`, `\>` — расширения GNU; в других системах их может не быть.
- В BRE/ERE **нет** `\d`: `grep -E '\d+'` цифры не найдёт (новые версии grep предупреждают о «лишнем `\`»). Пишите `[0-9]+` или используйте `-P`.
- В awk (особенно mawk) нет `\w`, `\s`, `\b`, `\d` — только POSIX-классы и явные наборы; в mawk из Ubuntu 22.04 нет и `{n,m}`.
- Квантификаторы «жадные»: `a.*b` захватывает до последнего `b` в строке. Ленивые (`.*?`) есть только в PCRE; в ERE заменяйте отрицанием набора: `"[^"]*"`.
- В UTF-8-локали `.` совпадает с одним символом (кириллическая буква — один символ), `\w` и `[[:alpha:]]` включают кириллицу; диапазон `[а-я]` не включает `ё`, пишите `[а-яё]` / `[А-ЯЁ]`.
- В `grep -P` `\d` — только ASCII-цифры (для любых цифр Юникода — `\p{Nd}`). **`\w`, `\b` (и опция `-w` в сочетании с `-P`) понимают кириллицу только в Ubuntu 26.04** (grep 3.12, собранный с PCRE2 10.46). В Ubuntu 22.04 (grep 3.7 на старой библиотеке PCRE) и в Ubuntu 24.04 (grep 3.11 + PCRE2 10.42) они ASCII-только: `echo 'привет мир' | grep -oP '\w+'` там ничего не выведет. Причина (NEWS и исходный код grep, `src/pcresearch.c`): Юникод-режим (`PCRE2_UCP`) включили в grep 3.9, но из-за него `\d` стал совпадать с не-ASCII-цифрами; в 3.10 `\d` вернули к ASCII, а в 3.11 Юникод-режим оставили только при сборке с PCRE2 ≥ 10.43 (флаг `PCRE2_EXTRA_ASCII_BSD`), иначе — поведение «как в grep 3.8», то есть ASCII. Переносимая запись, работающая во всех трёх выпусках: для букв — `\p{L}` или `\p{Cyrillic}` (например, `[\p{L}\p{Nd}_]+` вместо `\w+`), для границы слова — просмотры `(?<![\p{L}\p{Nd}_])слово(?![\p{L}\p{Nd}_])`. В режимах BRE/ERE (без `-P`) `\w`, `\b`, `\<`, `\>`, `-w` и `[[:alpha:]]` учитывают кириллицу при UTF-8-локали во всех трёх выпусках. (Проверено по первоисточникам; на живой системе убедиться можно командой `echo 'привет' | grep -cP '^\w+$'` — `1` означает Юникод-режим, `0` — ASCII.)
- В `grep -P` при UTF-8-локали `\xEF\xBB\xBF` трактуется как три символа U+00EF U+00BB U+00BF, а не как байты BOM. BOM искать так: `grep -P '^\x{FEFF}'` (UTF-8-локаль) или `LC_ALL=C grep -P '^\xEF\xBB\xBF'`.

Полезные готовые выражения (ERE):

```
IPv4-адрес:            [0-9]{1,3}(\.[0-9]{1,3}){3}
GUID/UUID:             [0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}
Дата ГГГГ-ММ-ДД:       [0-9]{4}-[0-9]{2}-[0-9]{2}
Время ЧЧ:ММ:СС:        [0-9]{2}:[0-9]{2}:[0-9]{2}
Начало события ТЖ 1С:  ^[0-9]{2}:[0-9]{2}\.[0-9]+-[0-9]+,
Пустая строка:         ^[[:space:]]*$
Строка-комментарий:    ^[[:space:]]*#
```

### 3.5. zgrep и сжатые логи

`logrotate` в Ubuntu сжимает старые журналы gzip-ом (`файл.log.1`, `файл.log.2.gz`, …). Утилиты из пакета `gzip` читают и сжатые, и обычные файлы:

```bash
zgrep -h 'FATAL' /var/log/postgresql/postgresql-17-main.log*      # по текущему и всем ротированным
zgrep -c 'Out of memory' /var/log/kern.log*                       # счётчик по каждому файлу
zcat /var/log/syslog.2.gz | head                                  # распаковать в поток
zcat -f /var/log/syslog* | grep -c 'error'                        # -f: обычные файлы тоже пропускать как есть
zless /var/log/syslog.3.gz                                        # просмотр
zdiff a.gz b.gz                                                   # сравнение
```

`zgrep` — оболочка над `grep`: большинство опций (`-i -n -c -h -E -P -o -A/-B/-C`) передаются дальше, но рекурсия (`-r`), `--include`/`--exclude` и `-z` **не поддерживаются**. Рекурсивно: `find /var/log -name '*.gz' -exec zgrep -H 'шаблон' {} +`. Для других форматов сжатия — `xzgrep` (xz), `bzgrep` (bzip2), `zstdgrep` (zstd).

### 3.6. ripgrep (rg) — кратко

`sudo apt install ripgrep` (репозиторий universe), команда `rg`. Быстрее grep на больших деревьях каталогов, рекурсивен по умолчанию.

```bash
rg 'EXCP' /var/log/1c/techlog/            # рекурсивно, с номерами строк и именами файлов
rg -i 'ошибка' ; rg -S 'Error'            # -i без учёта регистра; -S «умный» регистр
rg -F 'a.b(c)' ; rg -w 'rphost'           # -F буквально; -w целое слово
rg -l 'FATAL' ; rg -c 'FATAL' ; rg -v 'DEBUG' файл
rg -o 'SessionID=\d+' ; rg -A3 -B1 'deadlock'
rg -g '*.log' 'TLOCK' ; rg -g '!ragent_*' 'EXCP'     # отбор файлов glob-шаблоном
rg -z 'FATAL' /var/log/postgresql/        # искать и внутри .gz/.xz/.bz2/.zst
rg -P 'Usr=\K[^,]+' -o                    # PCRE2 (просмотры, \K, обратные ссылки)
rg -U '(?s)Context=.*?Sql='               # многострочный поиск
rg -E windows-1251 'ошибка' файл.txt      # файл в CP1251
rg -uuu 'пароль' /etc                     # отключить все фильтры (.gitignore, скрытые, двоичные)
rg --no-heading -N 'x' | cut -d: -f1      # вывод в стиле grep для конвейера
```

Отличия от grep, о которых надо помнить: по умолчанию пропускает скрытые файлы, двоичные файлы и всё, что перечислено в `.gitignore` (снять — `-u`, `-uu`, `-uuu`); синтаксис регулярных выражений — Rust regex (близок к PCRE, но без просмотров и обратных ссылок — они появляются с `-P`); файлы в UTF-16 распознаются по BOM автоматически.

## 4. sed — потоковый редактор

### 4.1. Как работает

`sed` читает ввод построчно: очередная строка помещается в «пространство шаблона» (pattern space), к ней по очереди применяются команды скрипта, после чего строка печатается (если не задан `-n`), и цикл повторяется. Есть второй буфер — «область удержания» (hold space) для многострочных приёмов.

```
sed [ОПЦИИ] 'СКРИПТ' [ФАЙЛ…]
команда скрипта:  [АДРЕС[,АДРЕС]][!]КОМАНДА[АРГУМЕНТЫ]
```

| Опция | Действие |
|---|---|
| `-n` | не печатать строки автоматически (печатает только команда `p`) |
| `-e 'скрипт'` | добавить команды (можно несколько `-e`) |
| `-f файл` | взять скрипт из файла |
| `-E` (то же `-r`) | расширенные регулярные выражения (ERE) |
| `-i[СУФФИКС]` | править файл «на месте»; с суффиксом — сохранить копию (`-i.bak`) |
| `-s` | считать каждый файл отдельным потоком (номера строк и `$` — для каждого файла); `-i` подразумевает `-s` |
| `-z` | строки разделены NUL (обычный текстовый файл целиком становится одной «строкой» — удобно для замены `\n`) |
| `--follow-symlinks` | при `-i` править файл, на который указывает ссылка, а не заменять ссылку файлом |
| `--debug` | показать разбор скрипта и ход выполнения |
| `--posix` | отключить расширения GNU |
| `-u` | минимальная буферизация |
| `--sandbox` | запретить команды `e`, `r`, `w` |

### 4.2. Адреса

| Адрес | Какие строки выбирает |
|---|---|
| `5` | строка 5 |
| `$` | последняя строка |
| `5,10` | строки с 5 по 10 |
| `5,$` | с 5-й до конца |
| `/regex/` | строки, совпавшие с выражением (`\cregexc` — с другим ограничителем, напр. `\,/opt/1cv8,`) |
| `/начало/,/конец/` | диапазон от строки с «начало» до ближайшей строки с «конец» включительно |
| `/regex/,+3` | совпавшая строка и 3 следующих |
| `5,~4` | с 5-й до ближайшей строки с номером, кратным 4 |
| `1~2` | каждая 2-я, начиная с 1-й (нечётные); `0~3` — каждая третья |
| `0,/regex/` | от начала до первого совпадения (даже если оно в 1-й строке) |
| `адрес!` | все строки, КРОМЕ выбранных |
| `/regex/I` | совпадение без учёта регистра (GNU) |

### 4.3. Команды

| Команда | Действие |
|---|---|
| `s/regex/замена/флаги` | подстановка |
| `p` | напечатать пространство шаблона |
| `d` | удалить строку и перейти к следующей |
| `a текст` | добавить строку ПОСЛЕ |
| `i текст` | вставить строку ПЕРЕД |
| `c текст` | заменить строку целиком |
| `y/abc/xyz/` | транслитерация символ в символ |
| `q [код]` | вывести текущую строку и выйти; `Q` — выйти без вывода |
| `=` | напечатать номер строки |
| `l` | напечатать строку в «однозначном» виде (видны `\t`, `\r`, `$` в конце) |
| `r файл` | вставить содержимое файла после строки |
| `w файл` | записать строку в файл |
| `n` / `N` | прочитать следующую строку вместо текущей / дописать её к текущей через `\n` |
| `D` / `P` | удалить / напечатать пространство шаблона до первого `\n` |
| `h` `H` / `g` `G` / `x` | копировать/дописать в область удержания / из неё / обменять |
| `:метка`, `b метка`, `t метка`, `T метка` | метка; безусловный переход; переход, если была успешная замена; если не было |
| `{ … }` | блок команд для одного адреса |
| `e команда` | выполнить команду оболочки (опасно) |

Флаги `s`: `g` — все вхождения в строке; число `N` — только N-е вхождение; `p` — напечатать, если замена была; `I` (или `i`) — без учёта регистра; `w файл` — записать изменённые строки в файл; `e` — выполнить результат как команду; `M` — многострочный режим `^`/`$`.

В замене: `&` — всё совпадение; `\1`…`\9` — группы; `\n` — перевод строки; `\t` — табуляция; `\U…\E` / `\L…\E` — в верхний / нижний регистр; `\u`, `\l` — регистр одной следующей буквы (расширения GNU). Разделителем может быть любой символ: `s|/старый/путь|/новый/путь|g`, `s#a#b#`.

### 4.4. Подстановка: примеры

```bash
sed 's/foo/bar/' файл                     # первое вхождение в каждой строке
sed 's/foo/bar/g' файл                    # все вхождения
sed 's/foo/bar/2' файл                    # только второе вхождение в строке
sed 's/foo/bar/Ig' файл                   # без учёта регистра
sed -n 's/foo/bar/p' файл                 # печатать только изменённые строки
sed 's|/opt/1C/v8.3/x86_64|/opt/1cv8/x86_64|g' файл        # другой разделитель — не надо экранировать «/»
sed -E 's/([0-9]+)\.([0-9]+)/\2.\1/' файл                  # группы и обратные ссылки
sed -E 's/^[[:space:]]+|[[:space:]]+$//g' файл             # обрезать пробелы по краям
sed 's/[^,]*,//' файл                     # удалить первое поле CSV
sed 's/.*/\U&/' файл                      # всю строку в верхний регистр (кириллица — в UTF-8-локали)
sed -E 's/\b(.)/\u\1/g' файл              # каждое слово с заглавной
sed 's/\r$//' файл                        # убрать CR в конце строк
sed 's/\x1b\[[0-9;]*m//g' файл            # убрать цветовые ESC-последовательности
sed '0,/foo/s//bar/' файл                 # заменить только ПЕРВОЕ вхождение во всём файле (пустой regex = предыдущий)
sed '/^\[Service\]/,/^\[/ s/^Restart=.*/Restart=always/' юнит   # замена только внутри секции

# (ИТС) обезличивание GUID, портов и IP-адресов перед группировкой:
cat file | sed -r 's/.{8}-.{4}-.{4}-.{4}-.{12}/{GUID}/g' | sed -r 's/\:[0-9]{4,5}/{PORT}/g' | sed -r 's/[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+/{ADDR}/g'
# (ИТС) удалить всё до подстроки / всё после подстроки:
sed 's/^.*Context=//' файл
sed 's/,Context=.*$//' файл
```

Переменные оболочки — в двойных кавычках; если в значении возможен `/`, берите другой разделитель; символы `&` и `\` в замене надо экранировать:

```bash
IP=10.0.0.5
sed -i.bak "s/^#\?listen_addresses.*/listen_addresses = '$IP'/" postgresql.conf
DIR=/var/log/1c/techlog
sed "s|location=\"[^\"]*\"|location=\"$DIR\"|" logcfg.xml
```

### 4.5. Печать, удаление, вставка строк

```bash
# Печать (всегда с -n)
sed -n '5p' файл                          # строка 5
sed -n '5,10p' файл                       # строки 5–10
sed -n '$p' файл                          # последняя
sed -n '1~2p' файл                        # нечётные
sed -n '/BEGIN/,/END/p' файл              # от шаблона до шаблона включительно
sed -n '/BEGIN/,/END/{//!p}' файл         # то же без граничных строк
sed -n '/ERROR/,+3p' файл                 # строка с ERROR и три после
sed -n '/шаблон/=' файл                   # номера строк с шаблоном
sed -n '$=' файл                          # число строк в файле
sed 10q файл                              # первые 10 строк (как head)
sed -n '1000000,1000100p;1000100q' big.log    # кусок из середины большого файла, не читая его до конца

# Удаление
sed '5d' файл ; sed '1d' файл ; sed '$d' файл        # 5-я, первая, последняя
sed '2,4d' файл                           # диапазон
sed '/^$/d' файл                          # пустые строки
sed -E '/^[[:space:]]*(#|$)/d' файл       # комментарии и пустые строки
sed '/шаблон/d' файл                      # строки с шаблоном (как grep -v)
sed '/шаблон/!d' файл                     # оставить только строки с шаблоном (как grep)
sed '/BEGIN/,/END/d' файл                 # блок целиком

# Вставка и замена строк (однострочная форма GNU)
sed '3i новая строка' файл                # вставить ПЕРЕД 3-й
sed '3a новая строка' файл                # добавить ПОСЛЕ 3-й
sed '$a последняя строка' файл            # дописать в конец
sed '1i # управляется вручную' файл       # заголовок в начало
sed '/^\[Service\]/a LimitNOFILE=65536' юнит.service       # после строки-шаблона
sed '/^max_connections/c max_connections = 500' postgresql.conf   # заменить строку целиком
sed '/шаблон/r вставка.txt' файл          # вставить содержимое файла после строки
```

### 4.6. Несколько команд

```bash
sed -e 's/a/b/' -e 's/c/d/' файл          # несколько -e
sed 's/a/b/; s/c/d/' файл                 # через точку с запятой
sed '/шаблон/{s/a/b/; s/c/d/}' файл       # блок только для подходящих строк
sed -n '/ERROR/{=;p}' файл                # номер и сама строка
sed -f правки.sed файл                    # скрипт из файла (по команде на строку, # — комментарий)
```

### 4.7. Правка на месте: `-i`

```bash
sed -i 's/старое/новое/g' файл                    # без резервной копии — необратимо
sed -i.bak 's/старое/новое/g' файл                # копия исходного в файл.bak
sed -i.bak -E 's/^#?[[:space:]]*(max_connections)[[:space:]]*=.*/\1 = 500/' postgresql.conf
sed -i '/^PermitRootLogin/s/^/#/' /etc/ssh/sshd_config            # закомментировать строку
sed -i -E 's/^#[[:space:]]*(PasswordAuthentication)/\1/' /etc/ssh/sshd_config   # раскомментировать
sed -i '1s/^\xEF\xBB\xBF//' *.txt                 # снять BOM с пачки файлов (адрес 1 — для каждого файла)
sed -i -e '$a\' файл                              # добавить завершающий перевод строки, если его нет
sed -n -i.bak '/шаблон/p' файл                    # оставить в файле только совпавшие строки
```

Что важно знать про `-i`:

- `sed -i` не правит файл, а создаёт новый и переименовывает его поверх старого: меняется inode, рвутся жёсткие ссылки, символическая ссылка заменяется обычным файлом (чтобы править цель ссылки — `--follow-symlinks`). Процессы, державшие файл открытым, продолжают видеть старое содержимое.
- `-n -i` без команды `p` **обнулит файл**.
- Перед боевой правкой прогоните команду без `-i` и посмотрите разницу: `sed 's/…/…/' файл | diff -u файл -`.
- На BSD/macOS синтаксис другой (`sed -i '' …`) — на Ubuntu это не нужно.
- Суффикс пишется слитно с `-i`: `-i.bak`. Запись `-i .bak` воспринимается как скрипт `.bak`.

### 4.8. Многострочные приёмы

```bash
sed 'N;s/\n/ /' файл                      # склеить строки попарно
sed ':a;N;$!ba;s/\n/ /g' файл             # склеить ВСЕ строки в одну (читает файл в память)
sed -z 's/\n/,/g' файл                    # то же через -z: заменить все переводы строк запятыми
sed ':a;/\\$/{N;s/\\\n//;ba;}' файл       # склеить строки, оканчивающиеся на «\» (продолжение)
sed '$!N;/^\(.*\)\n\1$/!P;D' файл         # убрать подряд идущие дубликаты (как uniq)
sed = файл | sed 'N;s/\n/\t/'             # пронумеровать строки
sed -n '1!G;h;$p' файл                    # вывести строки в обратном порядке, как tac (пример с областью удержания)
```

Для сложной многострочной логики (например, склейки событий ТЖ 1С) удобнее `perl` или `awk` — см. практикум.

## 5. awk — обработка по полям и агрегация

### 5.1. Какая реализация awk у вас

| Возможность | mawk (базовый `awk`; единственный в минимальных установках и контейнерах) | gawk (становится `awk`, если установлен: на стандартном Ubuntu Server 22.04/24.04 — сразу, иначе `sudo apt install gawk`) |
|---|---|---|
| Многобайтовые символы (кириллица UTF-8) | нет: `length`, `substr`, `index`, ширина в `printf` считают **байты**; `toupper`/`tolower` — только ASCII | да, в UTF-8-локали считаются символы |
| Интервалы `{n,m}` в regex | с версии 20200724 (в Ubuntu 22.04 — **нет**; в 24.04/26.04 — есть) | да |
| `\w`, `\s`, `\y`, `\<`, `\>` в regex | нет | да |
| `gensub()`, `patsplit()`, `asort()`, `asorti()`, `strtonum()`, `match(s, re, массив)` | нет | да |
| `strftime()`, `systime()`, `mktime()` | да (с 20121129) | да |
| `IGNORECASE`, `FPAT`, `FIELDWIDTHS`, `BEGINFILE`/`ENDFILE`, `PROCINFO`, `RT` | нет | да |
| Правка файла на месте | нет | `gawk -i inplace '…' файл` |
| Разбор CSV с кавычками | нет | `gawk --csv` (с gawk 5.3, т. е. в 26.04) или `FPAT` |
| Построчный сброс вывода | `-W interactive` или `fflush()` | `fflush()` |
| Десятичный разделитель в выводе | берётся из `LC_NUMERIC` (в `ru_RU` — запятая) | всегда точка (если не задан `--use-lc-numeric`) |
| Скорость на простых задачах | выше | ниже |

Какая реализация стоит за командой `awk`, решает система альтернатив: у gawk приоритет выше, чем у mawk (10 против 5 — значения по памяти о сценариях установки пакетов Debian, ⚠ фактические покажет `update-alternatives --display awk`), поэтому при установленном gawk в автоматическом режиме `awk` → `/usr/bin/gawk`. На стандартной установке Ubuntu Server 22.04/24.04 gawk уже есть: метапакет `ubuntu-server` в jammy и noble зависит от `byobu`, а `byobu` — от `gawk` (проверено по packages.ubuntu.com). В 26.04 `byobu` из зависимостей `ubuntu-server` исключён, но `gawk` числится в манифесте установочного образа Server 26.04.1 — попадает ли он в установленную систему, ⚠ не проверено. В минимизированной установке, в контейнерах (`ubuntu:24.04`) и в образах minimal — только mawk. Поэтому один и тот же однострочник может вести себя по-разному на двух соседних серверах. Проверка и явный выбор:

```bash
readlink -f "$(command -v awk)"            # /usr/bin/mawk или /usr/bin/gawk
update-alternatives --display awk          # кто зарегистрирован и с каким приоритетом
mawk 'BEGIN { print length("привет") }'    # 12 — байты; явный вызов конкретной реализации
gawk 'BEGIN { print length("привет") }'    # 6 — символы (в UTF-8-локали)
sudo update-alternatives --config awk      # закрепить выбор вручную (обычно не требуется)
```

В скриптах, которым нужны возможности gawk, вызывайте `gawk` явно, а не `awk`. Ключ `-W interactive` понимает только mawk (gawk выдаст предупреждение о нераспознанной опции) — переносимый способ построчного вывода: `fflush()` или `stdbuf -oL awk …`.

Однострочники в этой статье написаны так, чтобы работать и в mawk, и в gawk (если не оговорено иное): без `{n,m}`, без `\w`/`\s`, без gawk-функций.

### 5.2. Структура программы

```
awk [-F РАЗДЕЛИТЕЛЬ] [-v ПЕРЕМЕННАЯ=ЗНАЧЕНИЕ] 'ПРОГРАММА' [ФАЙЛ…]
awk -f программа.awk [ФАЙЛ…]

ПРОГРАММА:   шаблон { действие }
             шаблон { действие }
             …
```

- Ввод делится на **записи** (по умолчанию — строки), запись — на **поля** (по умолчанию — по пробелам и табуляциям).
- Для каждой записи проверяются все пары «шаблон — действие» по порядку. Нет шаблона — действие выполняется для каждой записи. Нет действия — запись печатается (`{ print }`).
- `BEGIN { … }` выполняется до чтения ввода, `END { … }` — после.
- Переменные не объявляются; неинициализированная равна `""` и `0` одновременно. Строки склеиваются простым написанием рядом: `print $1 "-" $2`.

### 5.3. Поля, разделители, встроенные переменные

| Переменная | Смысл |
|---|---|
| `$0` | вся запись |
| `$1`, `$2`, … `$NF` | поля; `$NF` — последнее, `$(NF-1)` — предпоследнее |
| `NF` | число полей в текущей записи |
| `NR` | номер записи с начала всего ввода |
| `FNR` | номер записи в текущем файле |
| `FS` | разделитель полей ввода (то же, что `-F`); по умолчанию — любые пробелы/табуляции |
| `OFS` | разделитель полей вывода (по умолчанию пробел) — им `print a, b` разделяет аргументы |
| `RS` | разделитель записей ввода (по умолчанию `\n`); `RS=""` — «абзацный» режим (записи разделены пустыми строками) |
| `ORS` | разделитель записей вывода (по умолчанию `\n`) |
| `FILENAME` | имя текущего файла |
| `ENVIRON["ИМЯ"]` | переменные окружения |
| `RSTART`, `RLENGTH` | позиция и длина совпадения после `match()` |
| `SUBSEP` | разделитель индексов «многомерных» массивов `a[i,j]` |

```bash
awk '{ print $1, $3 }' файл                    # 1-е и 3-е поле (через OFS)
awk '{ print $NF }' файл                       # последнее поле
awk -F: '{ print $1, $7 }' /etc/passwd         # разделитель «:»
awk -F'\t' '{ print $2 }' файл.tsv             # табуляция
awk -F';' -v OFS='\t' '{ print $1, $3 }' f.csv # ввод через «;», вывод через табуляцию
awk -F'[,;]' '{ print $2 }' файл               # разделитель — регулярное выражение (запятая ИЛИ точка с запятой)
awk -F', *' '{ print $2 }' файл                # запятая и любые пробелы после неё
awk -F'Memory=' '{ print $2 }' файл            # разделитель — строка: $2 = всё после «Memory=»
awk -F'[-,]' '{ print $2 }' rphost_1/26101009.log    # длительность события ТЖ (между «-» и первой «,»)
awk 'BEGIN { FS=":"; OFS=" -> " } { print $1, $6 }' /etc/passwd
awk -F: -v OFS=: '{ $2 = "x"; print }' файл    # изменение поля пересобирает $0 через OFS
awk '{ $1 = $1; print }' OFS=, файл            # «пересобрать» запись с новым разделителем
```

`-F` с одним символом (кроме пробела) — это литерал, в том числе `-F'|'`, `-F'.'`, `-F';'`; строка длиннее одного символа — регулярное выражение, спецсимволы в ней экранируйте набором: `-F'[|][|]'` (две черты), `-F'[.]txt'`.

### 5.4. Шаблоны (условия отбора)

```bash
awk '/ERROR/' файл                             # строки, содержащие ERROR (как grep)
awk '!/DEBUG/' файл                            # не содержащие
awk '$3 ~ /^rphost/' файл                      # 3-е поле начинается с rphost
awk '$3 !~ /^(ragent|rmngr)$/' файл            # поле не равно ни одному из
awk '$2 > 1000' файл                           # числовое сравнение
awk '$1 == "usr1cv8"' файл                     # строковое сравнение
awk '$2+0 >= 5000000 && /,DBPOSTGRS,/' файл    # И; «+0» принудительно делает число
awk '/FATAL/ || /PANIC/' файл                  # ИЛИ
awk 'NR == 1' файл ; awk 'NR > 1' файл         # первая строка / всё, кроме заголовка
awk 'NR >= 10 && NR <= 20' файл                # строки 10–20
awk 'NR % 2 == 0' файл                         # чётные строки
awk 'NF' файл                                  # непустые строки (NF > 0)
awk 'NF != 5 { print FILENAME ": " NR ": полей " NF }' *.csv     # строки с неверным числом полей
awk 'length($0) > 500' файл                    # длинные строки (в mawk — длина в байтах)
awk '/BEGIN/,/END/' файл                       # диапазон от шаблона до шаблона
awk -v u="Иванов" '$0 ~ ("Usr=" u ",")' файл   # значение из переменной оболочки
```

### 5.5. Действия: print, printf, перенаправление

```bash
awk '{ print NR ": " $0 }' файл                        # нумерация строк
awk '{ printf "%-20s %10.2f\n", $1, $2 }' файл         # форматированный вывод (перевод строки — вручную)
awk '{ printf "%s%s", sep, $1; sep="," } END { print "" }' файл    # склеить первое поле всех строк через запятую
awk '{ print > ($1 ".txt") }' файл                     # разложить строки по файлам по значению 1-го поля
awk '{ print $1 | "sort -u" }' файл                    # вывод в команду
awk 'BEGIN { while (("ls -1" | getline f) > 0) print "файл:", f }'   # чтение вывода команды
```

Форматы `printf`: `%d` — целое; `%s` — строка; `%f`, `%.3f` — дробное; `%e` — экспоненциальная запись; `%x` — hex; `%c` — символ; `%%` — знак процента; `%10s` / `%-10s` — ширина с выравниванием вправо / влево; `%05d` — с ведущими нулями.

Встроенные функции (общие для mawk и gawk): `length(s)`, `substr(s, начало[, длина])`, `index(s, t)`, `split(s, массив[, разделитель])`, `sub(re, замена[, цель])`, `gsub(re, замена[, цель])`, `match(s, re)`, `sprintf(формат, …)`, `tolower(s)`, `toupper(s)`, `int(x)`, `sqrt`, `log`, `exp`, `rand()`, `srand()`, `system("команда")`, `close(файл)`, `fflush()`, `getline`. Операторы управления: `if/else`, `while`, `for (i=1; i<=NF; i++)`, `for (k in массив)`, `next` (перейти к следующей записи), `exit`.

### 5.6. Ассоциативные массивы, суммирование и группировка

Индекс массива — любая строка; элемент создаётся при первом обращении. Порядок обхода `for (k in a)` не определён — результат сортируйте командой `sort`.

```bash
# Сумма, количество, среднее, минимум, максимум по столбцу
awk '{ s += $2 } END { print s }' файл
awk '{ s += $2; if (NR == 1 || $2 < min) min = $2; if (NR == 1 || $2 > max) max = $2 }
     END { if (NR) printf "n=%d sum=%.3f avg=%.3f min=%s max=%s\n", NR, s, s/NR, min, max }' файл

# (ИТС) сумма значений после «Memory=» и сумма второго поля с разделителем «;»
awk -F'Memory=' '{sum+=$2;} END {print "Sum=" sum}'
awk -F';' '{sum+=$2;} END {print "Sum=" sum}'

# ТОП ПО КОЛИЧЕСТВУ: сколько раз встречается каждое значение 1-го поля
awk '{ c[$1]++ } END { for (k in c) print c[k], k }' файл | sort -rn | head -10

# ТОП ПО СУММЕ: сумма 3-го поля в разрезе 1-го
awk -F';' '{ s[$1] += $3 } END { for (k in s) printf "%.2f\t%s\n", s[k], k }' файл.csv | sort -rn | head -10

# Сумма, среднее и количество по ключу — классическая «сводная таблица»
awk -F';' '{ s[$1] += $3; c[$1]++ }
     END { for (k in s) printf "%12.2f %10.2f %6d %s\n", s[k], s[k]/c[k], c[k], k }' файл.csv | sort -rn | head

# (ИТС) группировка «ключ — сумма»
awk '{count[$1]+=$2;} END {for (i in count) {print i " " count[i]}}'

# Доля каждого значения в процентах
awk '{ c[$1]++; n++ } END { for (k in c) printf "%6d %5.1f%% %s\n", c[k], 100*c[k]/n, k }' файл | sort -rn

# Группировка по двум ключам
awk -F';' '{ s[$1 SUBSEP $2] += $3 }
     END { for (k in s) { split(k, p, SUBSEP); printf "%s\t%s\t%.2f\n", p[1], p[2], s[k] } }' файл.csv

# Удалить дубликаты строк, сохранив порядок (в отличие от sort -u)
awk '!seen[$0]++' файл
# Дубликаты по ключу (1-е поле): оставить первую встреченную строку
awk -F';' '!seen[$1]++' файл.csv

# Соединение двух файлов по ключу (первый файл — справочник)
awk -F'\t' 'NR == FNR { name[$1] = $2; next } { print $0 "\t" (($1 in name) ? name[$1] : "?") }' справочник.tsv данные.tsv

# Память процессов, сгруппированная по имени (rphost, postgres, …)
ps -eo rss=,comm= | awk '{ m[$2] += $1; n[$2]++ } END { for (p in m) printf "%10.1f МиБ %4d %s\n", m[p]/1024, n[p], p }' | sort -rn | head

# Размер файлов по расширениям
find . -type f -printf '%s %f\n' | awk '{ n = split($2, a, "."); e = (n > 1) ? a[n] : "(нет)"; s[e] += $1 }
     END { for (e in s) printf "%14d %s\n", s[e], e }' | sort -rn | head

# Гистограмма по часам для лога с меткой времени «ГГГГ-ММ-ДД ЧЧ:ММ:СС» в 1–2 полях
awk '{ print $1, substr($2, 1, 2) ":00" }' файл.log | sort | uniq -c

# (ИТС) анализ access.log nginx: доля, сумма, среднее и число запросов дольше 40 по полю 8
grep -P '24/Mar/2017:12' /var/log/nginx/access.log | awk -F'|' '{if($6>40) {sum[$8]+=$6; count[$8]+=1; countall+=1;}} END {for (i in sum) {print count[i]*100/countall "% " sum[i] " " sum[i]/count[i] " " count[i] " " i}}' | sort -nb | head -n 50
```

### 5.7. Подводные камни awk

- **Числа и строки.** Поле, похожее на число, сравнивается как число; иначе — как строка (`"10" < "9"`). Принудительно: `$2+0` — число, `$2 ""` — строка.
- **Одинарные кавычки** внутри программы в одинарных кавычках поставить нельзя: используйте `\047` (`print "\047" $1 "\047"`) или `-v q="'"`.
- **Переменные оболочки** передавайте через `-v имя="$ЗНАЧЕНИЕ"`, а не вставкой в текст программы.
- **Буферизация.** В конвейере `tail -f … | awk …` вывод появляется пачками; добавьте `fflush()` после `print` (работает и в mawk, и в gawk) либо запускайте `mawk -W interactive` (только mawk; по man-странице этот режим ещё и читает stdin построчно независимо от `RS`).
- **Точность и большие целые.** Все числа — double; целые точны до 2^53. Суммы микросекунд быстро превышают 2^31 (один час = 3,6·10⁹ мкс), поэтому в собственных конвейерах для таких сумм пишите `printf "%.0f"` — этот формат одинаково работает во всех реализациях и версиях. Формат `%d` и простой `print сумма` в gawk и современных mawk печатают большие целые верно, но старый mawk 1.3.3 (Ubuntu 18.04 и раньше) обрезал `%d` до 2147483647 и печатал большие числа в виде `3.6e+09`; для mawk 1.3.4-20200120 из Ubuntu 22.04 — ⚠ не проверено (по журналу изменений mawk расширенные 64-битные типы для таких преобразований появились в версии 20200731, т. е. позже). Признак проблемы — в итогах встречается ровно `2147483647` или запись с `e+`. Конвейеры ИТС (раздел 10.4) используют именно `%d` и `print` — на Ubuntu 22.04 с mawk сверяйте их результат с `gawk`. Для отображения удобнее делить: `s/1e6` (секунды).
- **Локаль.** При `LANG=ru_RU.UTF-8` mawk печатает дробные числа с запятой (журнал изменений mawk, версии 20121129 и 20121209: поддержка `LC_NUMERIC` меняет отображаемую десятичную точку и переводит точку в местный разделитель для `strtod()`; на практике ⚠ не проверено — проверка: `LC_ALL=ru_RU.UTF-8 mawk 'BEGIN { printf "%.1f\n", 1.5 }'`), gawk всегда печатает точку (если не задан `--use-lc-numeric`), а `sort -n` в этой локали ожидает запятую и число `12.5` разберёт как 12. Чтобы везде была точка — `export LC_NUMERIC=C`.
- **Кириллица в mawk** — байты: `length("привет")` вернёт 12, `substr` может разрезать букву пополам, `printf "%-20s"` выравнивает неверно. Для аккуратной работы с кириллицей — gawk.

## 6. Смежные утилиты

### 6.1. sort

| Флаг | Действие |
|---|---|
| `-n` | числовая сортировка (целые и дроби; десятичный разделитель — из локали) |
| `-g` | «общая» числовая (понимает `1e3`, медленнее) |
| `-h` | «человеческие» размеры: `2K`, `10M`, `1.5G` |
| `-V` | версии: `8.3.9 < 8.3.10 < 8.3.27` |
| `-M` | названия месяцев (`Jan` < `Feb`) |
| `-r` | обратный порядок |
| `-k П1[,П2][флаги]` | ключ сортировки: с поля П1 по поле П2; флаги `n r h V f b` можно дописывать к ключу |
| `-t 'С'` | разделитель полей (по умолчанию — переход от непробела к пробелу) |
| `-u` | вывести только уникальные (по ключу) строки |
| `-f` | без учёта регистра |
| `-b` | игнорировать ведущие пробелы |
| `-s` | устойчивая сортировка (не трогать порядок равных) |
| `-c` | только проверить, отсортирован ли ввод |
| `-o файл` | вывод в файл (можно тот же, что входной) |
| `-S 2G`, `-T /каталог`, `--parallel=N` | память под буфер, каталог временных файлов, число потоков — для очень больших файлов |
| `-z` | строки разделены NUL |
| `-R` | случайный порядок (одинаковые строки рядом) |

```bash
sort файл                                    # по алфавиту согласно локали
sort -u файл                                 # с удалением дубликатов
sort -rn числа.txt                           # числа по убыванию
sort -t';' -k3,3nr -k1,1 файл.csv            # по 3-му полю (число, убывание), затем по 1-му
sort -t$'\t' -k2,2 файл.tsv                  # разделитель — табуляция
sort -k2,2 -s файл                           # только по 2-му полю, равные — в исходном порядке
sort -u -t: -k1,1 файл                       # уникальные по первому полю
du -sh /var/lib/postgresql/*/ | sort -h      # каталоги по размеру
ls /opt/1cv8/x86_64/ | sort -V | tail -1     # самая новая установленная версия платформы 1С
sort -S 2G --parallel=4 -T /var/tmp -o big.sorted big.log    # большой файл
LC_ALL=C sort файл                           # быстрая побайтовая сортировка
```

Ловушки: `-k2` означает «со 2-го поля **до конца строки**» — почти всегда нужно `-k2,2`. Числа сортируйте с `-n`, иначе `10` окажется раньше `9`. В локали `ru_RU.UTF-8` десятичный разделитель — запятая (см. раздел о локалях).

### 6.2. uniq

Убирает или считает **подряд идущие** одинаковые строки — поэтому перед ним почти всегда стоит `sort`.

```bash
sort файл | uniq                # убрать повторы (то же, что sort -u)
sort файл | uniq -c             # с числом повторений
sort файл | uniq -c | sort -rn | head -20     # «топ-20 самых частых» — главный приём анализа логов
sort файл | uniq -d             # только строки, встречающиеся более одного раза
sort файл | uniq -u             # только строки, встречающиеся ровно один раз
sort файл | uniq -ci            # без учёта регистра
uniq -f 4 -c /var/log/syslog    # не учитывать при сравнении первые 4 поля («Oct 10 12:34:56 host»); если метка времени в формате ISO одним полем — -f 2
uniq -s 16 файл                 # пропустить первые 16 символов
uniq -w 10 файл                 # сравнивать только первые 10 символов
```

### 6.3. cut

```bash
cut -d: -f1 /etc/passwd                 # первое поле, разделитель «:»
cut -d: -f1,7 /etc/passwd               # поля 1 и 7
cut -d';' -f2-4 файл.csv                # поля со 2-го по 4-е
cut -d, -f3- файл.csv                   # с 3-го до конца
cut -f2 файл.tsv                        # разделитель по умолчанию — табуляция
cut -c1-80 файл                         # первые 80 позиций строки
cut -d' ' -f1 --complement файл         # всё, КРОМЕ первого поля
cut -d: -f1,7 --output-delimiter=' -> ' /etc/passwd
cut -s -d';' -f2 файл                   # строки без разделителя не выводить
```

Ограничения: разделитель — ровно один символ; несколько пробелов подряд дают пустые поля (сначала `tr -s ' '` или используйте `awk`); кавычки CSV не учитываются. И в GNU coreutils 8.32/9.4 (Ubuntu 22.04/24.04), и в uutils 0.8.0 (Ubuntu 26.04; проверено по исходному коду этой версии) `-c` считает **байты**, поэтому `cut -c1-10` может разрезать кириллическую букву пополам; безопасная обрезка по символам — `grep -oP '^.{0,10}'` (в UTF-8-локали) или gawk `substr($0, 1, 10)`. В последующих версиях uutils `-c` в многобайтовой локали считает символы — не закладывайтесь ни на то, ни на другое поведение.

### 6.4. paste и join

```bash
paste a.txt b.txt               # строки двух файлов рядом, через табуляцию
paste -d';' a.txt b.txt         # через «;»
paste -sd, файл                 # все строки файла в одну, через запятую
paste - - - < файл              # по три строки в одну
seq 1 5 | paste -sd+ | bc       # 1+2+3+4+5 = 15

join a.txt b.txt                                # соединить по первому полю (оба файла отсортированы по ключу)
join -t';' -1 2 -2 1 <(sort -t';' -k2,2 a.csv) <(sort -t';' -k1,1 b.csv)   # ключ: поле 2 в a, поле 1 в b
join -a 1 a.txt b.txt                           # левое соединение
join -a 1 -e '-' -o auto a.txt b.txt            # с заполнителем для отсутствующих значений
join -v 1 a.txt b.txt                           # строки из a, которым нет пары в b
```

`join` и `comm` требуют, чтобы входные данные были отсортированы в той же локали, в какой работает сама утилита; надёжнее всего `LC_ALL=C sort …` и `LC_ALL=C join …`.

### 6.5. tr

Преобразует или удаляет отдельные символы; читает только стандартный ввод.

```bash
tr 'a-z' 'A-Z' < файл                   # латиница в верхний регистр
tr -d '\r' < вход > выход               # удалить CR
tr -s ' ' < файл                        # сжать повторяющиеся пробелы в один
tr ',' '\n' < файл                      # запятые → переводы строк
tr '\n' ' ' < файл                      # всё в одну строку
tr -d '\000' < файл                     # удалить NUL-байты
tr '\0' '\n' < /proc/12345/environ      # окружение процесса построчно
tr -cd '[:print:]\n' < файл             # оставить только печатные ASCII-символы (кириллица будет удалена!)
tr -dc 'A-Za-z0-9' < /dev/urandom | head -c 20; echo      # случайная строка из 20 символов
```

GNU `tr` (22.04/24.04) и `tr` из uutils 0.8.0 (26.04) работают с байтами: регистр кириллицы ими сменить нельзя. Для кириллицы: `sed 's/.*/\L&/'` (нижний), `sed 's/.*/\U&/'` (верхний), gawk `tolower()`/`toupper()` либо `perl -CSD -pe '$_ = lc'`.

### 6.7. comm, diff, cmp, patch

```bash
comm a.txt b.txt                        # три столбца: только в a | только в b | в обоих (файлы отсортированы)
comm -12 <(sort a.txt) <(sort b.txt)    # общие строки
comm -23 <(sort a.txt) <(sort b.txt)    # есть в a, нет в b
comm -13 <(sort a.txt) <(sort b.txt)    # есть в b, нет в a

diff a b                                # классический формат
diff -u a b                             # unified: «-» — строка из a, «+» — строка из b, 3 строки контекста
diff -u --color=auto a b
diff -y -W 160 --suppress-common-lines a b      # два столбца рядом, только различия
diff -q a b                             # только факт различия
diff -r каталог1 каталог2               # рекурсивно
diff -rq каталог1 каталог2              # какие файлы различаются или отсутствуют
diff -ruN каталог1 каталог2 > изменения.patch   # патч по дереву (-N — отсутствующий файл считать пустым)
diff -w a b                             # игнорировать все пробелы; -b — изменения количества пробелов; -B — пустые строки; -i — регистр
diff --strip-trailing-cr win.txt lin.txt        # не считать различием CR в конце строк
diff -r -x '*.log' каталог1 каталог2    # исключить файлы по шаблону
diff <(sort a) <(sort b)                # сравнить без учёта порядка строк
diff -u postgresql.conf.bak postgresql.conf     # что изменили в конфиге
diff <(grep -vE '^\s*(#|$)' a.conf) <(grep -vE '^\s*(#|$)' b.conf)     # сравнить только значащие строки
diff <(ssh srv2 cat /etc/postgresql/17/main/postgresql.conf) /etc/postgresql/17/main/postgresql.conf

cmp a b                                 # побайтово: «a b differ: byte 123, line 4»
cmp -s a b && echo "одинаковые"         # тихо, только код возврата
cmp -l a b | wc -l                      # число различающихся байт
cmp -s -n 3 файл <(printf '\xEF\xBB\xBF') && echo "есть BOM"

diff -u старый.conf новый.conf > fix.patch
patch старый.conf < fix.patch           # применить патч к файлу
patch -p1 < изменения.patch             # к дереву; -pN отбрасывает N ведущих компонентов пути
patch -p1 --dry-run < изменения.patch   # проверить, не применяя
patch -R -p1 < изменения.patch          # откатить
patch -b старый.conf < fix.patch        # сохранить исходный файл как старый.conf.orig
```

Код возврата `diff` и `cmp`: `0` — одинаковы, `1` — различаются, `2` — ошибка. `diff`, `cmp` — пакет `diffutils`; `patch` — пакет `patch` (может потребоваться установка).

### 6.8. tee

```bash
команда | tee файл                              # и на экран, и в файл
команда | tee -a файл                           # дописывать, а не перезаписывать
команда 2>&1 | tee -a run.log                   # вместе с потоком ошибок
echo '10.0.0.5 srv1c' | sudo tee -a /etc/hosts  # запись в файл root (вариант «sudo echo … >> файл» не работает: перенаправление делает оболочка без прав)
```

Код возврата конвейера — код последней команды (то есть `tee`); чтобы не потерять ошибку первой: `set -o pipefail` или `${PIPESTATUS[0]}`.

### 6.9. xargs

Собирает аргументы из стандартного ввода и запускает с ними команду.

| Флаг | Действие |
|---|---|
| `-0` | элементы разделены NUL (парный к `find -print0`, `grep -Z`, `sort -z`) — единственный надёжный способ для имён с пробелами |
| `-d 'С'` | свой разделитель, например `-d '\n'` — по строкам |
| `-n N` | не более N аргументов на один запуск команды |
| `-L N` | не более N строк ввода на запуск |
| `-I СТРОКА` | подставлять каждую строку ввода вместо СТРОКА (обычно `{}`); подразумевает `-L 1` |
| `-P N` | до N процессов параллельно; `0` — сколько получится |
| `-r` | не запускать команду, если ввод пуст (в GNU xargs без `-r` команда запускается один раз даже при пустом вводе) |
| `-t` | печатать каждую команду перед запуском |
| `-p` | спрашивать подтверждение |
| `-a файл` | читать элементы из файла |

```bash
find /var/log/1c -name '*.log' -mtime +30 -print0 | xargs -0 -r gzip           # сжать старые логи
find . -name '*.log' -print0 | xargs -0 -r grep -l ',EXCP,'                     # grep по найденным файлам
find . -name '*.log' -print0 | xargs -0 -r -n 20 -P 4 grep -c ',TLOCK,'         # 4 процесса, по 20 файлов
ls /backup/*.gz | xargs -r -n 1 -P "$(nproc)" gzip -t                           # проверить архивы параллельно
xargs -a hosts.txt -I{} ssh {} 'hostname; uptime'                               # команда для каждого хоста
printf '%s\n' buh zup erp | xargs -I{} echo "база: {}"
xargs -a список.txt -d '\n' -r rm -v --                                         # удалить файлы по списку (по строке на имя)
# (ИТС) искать исключения внутри zip-архивов с логами:
find * -name '*.zip' -print0 | xargs -0 -i -n 1 unzip -p {} '*.log' 2>/dev/null | grep ',EXCP,'
```

Замечания: `-i` (как в примере ИТС) — устаревший синоним `-I{}`; при `-P` вывод параллельных процессов может перемешиваться; коды возврата: `123` — какая-то из команд завершилась с кодом 1–125, `124` — команда вернула 255, `126`/`127` — команду нельзя запустить / не найдена.

### 6.10. shuf, rev, fold, expand, split

```bash

shuf -i 1-100 -n 1              # случайное число от 1 до 100

```

### 6.11. perl — когда sed и awk не хватает

`perl` есть в любой установке Ubuntu (`perl-base` — обязательный пакет, полный `perl` входит в стандартную установку Server), а методика ИТС по разбору технологического журнала построена именно на нём. Для однострочников достаточно нескольких ключей:

| Ключ | Действие |
|---|---|
| `-e 'код'` | программа в командной строке |
| `-n` | цикл по строкам ввода без автоматической печати (как `sed -n`, как awk) |
| `-p` | цикл по строкам с печатью каждой строки после обработки (как `sed`) |
| `-l` | срезать перевод строки при чтении и добавлять его при `print` |
| `-a` | разбить строку на поля в массив `@F` (счёт с нуля: `$F[0]` — первое поле, `$F[-1]` — последнее) |
| `-F'разд'` | разделитель полей для `-a` (регулярное выражение) |
| `-i[.bak]` | правка файла на месте, с суффиксом — с резервной копией (как и `sed -i`, создаёт новый файл) |
| `-0777` | читать файл целиком как одну «строку» (многострочные замены); `-00` — по абзацам |
| `-CSD` | считать ввод и вывод текстом в UTF-8 (символы, а не байты) |
| `-Mutf8` | текст самой программы (шаблоны с кириллицей) — в UTF-8 |

```bash
perl -pe 's/старое/новое/g' файл                       # как sed 's/…/…/g', но с синтаксисом Perl: \d, \w, ленивые .*?, просмотры
perl -i.bak -pe 's/старое/новое/g' файл                # правка на месте с копией файл.bak
perl -ne 'print if /ERROR|FATAL/' файл                 # как grep -E
perl -ne 'print unless /^\s*(#|$)/' файл               # как grep -v: без комментариев и пустых строк
perl -ne 'print "$1\n" if /SessionID=(\d+)/' файл      # извлечь группу (как grep -oP 'SessionID=\K\d+')
perl -ne 'print "$1\n" while /Usr=([^,]+)/g' файл      # все вхождения в строке
perl -lane 'print "$F[0] $F[-1]"' файл                 # как awk '{ print $1, $NF }'
perl -F';' -lane '$s{$F[0]} += $F[2]; END { printf "%.2f\t%s\n", $s{$_}, $_ for sort { $s{$b} <=> $s{$a} } keys %s }' файл.csv   # сумма 3-го поля по 1-му, сразу по убыванию
perl -0777 -pe 's/\r\n/\n/g' файл                      # весь файл одной строкой: CRLF → LF
perl -0777 -ne 'print "$1\n" while /<log\b[^>]*\blocation="([^"]*)"/g' logcfg.xml    # многострочный поиск по всему файлу
perl -CSD -pe '$_ = uc' файл                           # верхний регистр, в том числе кириллицы
perl -Mutf8 -CSD -ne 'print if /ошибк\w*/i' файл       # \w и /i для кириллицы: нужны и -CSD (данные), и -Mutf8 (текст шаблона)
```

Главное отличие от grep/sed/gawk: **perl по умолчанию работает с байтами и не смотрит на локаль**. Без `-CSD` точка — это один байт, `\w` и `/i` действуют только на латиницу, `length` считает байты; зато шаблон `\xef\xbb\xbf` — это ровно три байта BOM при любой локали (в `grep -P` в UTF-8-локали это не так, см. 3.4), а поиск кириллической подстроки в том же регистре (`/Ошибка блокировки/`) работает без всяких ключей — сравниваются байты. Поэтому конвейеры ИТС дают одинаковый результат и при `ru_RU.UTF-8`, и при `LC_ALL=C`. С ключом `-CSD` BOM превращается в один символ `\x{FEFF}`. В хэше порядок ключей не определён — результат сортируйте (`sort { $s{$b} <=> $s{$a} }` внутри perl или `| sort -rn` снаружи). Числа в perl — double с точным целым диапазоном до 2^53, `printf "%d"` корректно печатает 64-битные целые.

### 6.12. Буферизация в конвейерах

Когда вывод программы идёт не на терминал, а в канал, большинство программ копит его блоками (обычно по 4–64 КиБ). Для разовой обработки файла это незаметно, но в «живом» конвейере (`tail -F … | фильтр | фильтр`) строки появляются с задержкой или не появляются вовсе, пока не накопится блок. Буферизацию надо отключать у **каждой промежуточной** команды (последняя пишет на терминал и так построчно):

| Команда | Как включить построчный вывод |
|---|---|
| `grep` | `--line-buffered` |
| `sed` | `-u` |
| `awk` | `fflush()` после `print` (mawk и gawk); у mawk ещё ключ `-W interactive` |
| `perl` | в начале программы присвоить 1 специальной переменной «доллар-вертикальная черта»: `BEGIN { $\| = 1 }` (в командной строке набирается без обратного слэша — он здесь только из-за синтаксиса Markdown-таблицы) |
| `jq` | `--unbuffered` |
| `cut`, `tr`, `uniq` и другие без собственного ключа | `stdbuf -oL команда` |
| `tee`, `cat`, `tail -f` | не буферизуют — ничего делать не нужно |

```bash
tail -F "$PGLOG" | grep --line-buffered -E ' (ERROR|FATAL|PANIC): ' | sed -u -E 's/^([^ ]+ [^ ]+) [^ ]+ /\1 /' | cut -c1-300
tail -F rphost_*/*.log | grep --line-buffered ',EXCP,' | awk '{ print substr($0, 1, 300); fflush() }'
journalctl -fu 'srv1cv8*' -o json | jq --unbuffered -r '.MESSAGE'
```

`stdbuf` (coreutils) действует через подмену настроек буферов стандартной библиотеки C, поэтому работает только с программами, которые пишут через неё и не настраивают буферы сами. В Ubuntu 26.04 утилиты `cut`, `tr`, `uniq` и др. — это uutils на Rust; действует ли на них `stdbuf` — ⚠ не проверено (проверка: `( echo a; sleep 3; echo b ) | stdbuf -oL cut -c1 | cat` — буква `a` должна появиться сразу, а не через три секунды; если нет — используйте GNU-двойник: `stdbuf -oL gnucut …`).

## 7. JSON, XML, YAML

### 7.1. jq — JSON

```bash
sudo apt install jq
```

Опции: `-r` — строки без кавычек (для дальнейшей обработки текстовыми утилитами); `-c` — компактно, один объект на строку; `-s` — прочитать все входные объекты в один массив; `-n` — не читать ввод; `-R` — читать ввод как обычные строки, а не JSON; `-e` — код возврата по результату (0 — истина, 1 — `false`/`null`); `--arg имя значение` — передать строку как `$имя`; `--argjson имя json` — передать JSON-значение; `-S` — сортировать ключи; `--tab`, `--indent N` — отступы; `-C` / `-M` — цвет включить / выключить; `-f файл` — фильтр из файла.

```bash
jq . файл.json                                  # красиво отформатировать и проверить корректность
jq -c . файл.json                               # сжать в одну строку на объект
jq '.name' файл.json                            # поле
jq -r '.server.host' файл.json                  # вложенное поле без кавычек
jq '.items[0]' ; jq '.items[-1]' ; jq '.items[2:5]'     # элементы массива
jq '.items | length'                            # длина массива
jq -r '.items[] | .id'                          # поле каждого элемента
jq -r '.items[] | [.id, .name, .size] | @tsv'   # в TSV (@csv — в CSV)
jq -r '.items[] | "\(.id): \(.name)"'           # строка по шаблону
jq '.items[] | select(.size > 1000)'            # фильтр
jq '.items[] | select(.name | test("^rphost"))' # фильтр по регулярному выражению
jq '[.items[] | .size] | add'                   # сумма
jq '.items | sort_by(-.size) | .[:10]'          # топ-10 по убыванию
jq '.items | group_by(.type) | map({type: .[0].type, n: length, total: (map(.size) | add)})'    # группировка
jq 'keys' ; jq 'has("port")' ; jq '.port // 1541'       # ключи; наличие ключа; значение по умолчанию
jq 'del(.password)' ; jq '.port = 1541' ; jq '.tags += ["new"]'    # правка (результат — в stdout)
jq -r 'to_entries[] | "\(.key)=\(.value)"'      # объект → строки ключ=значение
jq --arg u "Иванов" '.[] | select(.user == $u)' файл.json           # параметр из оболочки
jq -s '.' строки.jsonl                          # JSON Lines → один массив
jq -s 'map(.duration) | add / length' строки.jsonl                  # среднее по потоку объектов
```

`jq` не правит файл на месте: `jq '.port = 1541' f.json > f.tmp && mv f.tmp f`.

Применение к логам:

```bash
# journald в JSON: сообщения уровня err и выше с временем (UTC)
#   (.PRIORITY // "6" — у части записей поля PRIORITY нет; tostring — на случай, если MESSAGE пришёл массивом байтов)
journalctl -u postgresql@17-main -o json --since today \
  | jq -r 'select((.PRIORITY // "6" | tonumber) <= 3) | [(.__REALTIME_TIMESTAMP | tonumber / 1000000 | floor | strftime("%F %T")), (.MESSAGE | tostring)] | @tsv'

# Журнал PostgreSQL в формате jsonlog (PostgreSQL 15+, log_destination = 'jsonlog', logging_collector = on):
jq -r 'select(.error_severity == "ERROR" or .error_severity == "FATAL" or .error_severity == "PANIC")
       | [.timestamp, .user, .dbname, .message] | @tsv' /var/lib/postgresql/17/main/log/*.json
jq -r 'select(.message | startswith("duration:")) | .message' /var/lib/postgresql/17/main/log/*.json | sort -t' ' -k2,2nr | head
```

Ключи jsonlog PostgreSQL: `timestamp`, `user`, `dbname`, `pid`, `remote_host`, `remote_port`, `session_id`, `line_num`, `ps`, `session_start`, `vxid`, `txid`, `error_severity`, `state_code`, `message`, `detail`, `hint`, `internal_query`, `internal_position`, `context`, `statement`, `cursor_position`, `func_name`, `file_name`, `file_line_num`, `application_name`, `backend_type`, `leader_pid`, `query_id` (по документации PostgreSQL 18: строковые поля со значением NULL в вывод не включаются; в будущих версиях могут появляться новые ключи — разборщик должен игнорировать незнакомые). Сообщения в `message` при русской `lc_messages` тоже переведены, а `error_severity` содержит переведённую метку (`ОШИБКА`, `ВАЖНО` …) — ⚠ последнее не проверено, сверяйте со своим файлом.

### 7.2. xmllint — проверка и запросы к XML

`sudo apt install libxml2-utils`. Применяется к XML-файлам 1С: `logcfg.xml` (настройка технологического журнала), `default.vrd` (описание веб-публикации), XML-выгрузки конфигураций.

```bash
xmllint --noout logcfg.xml && echo "XML корректен"      # проверка правильности (well-formed); при ошибке — строка и позиция
xmllint --format logcfg.xml                             # красиво отформатировать (в stdout)
XMLLINT_INDENT='    ' xmllint --format файл.xml         # отступ 4 пробела (по умолчанию 2)
xmllint --format файл.xml --output красиво.xml          # в файл
xmllint --xpath 'string(/*/@ib)' /var/www/buh/default.vrd           # значение атрибута корневого элемента
xmllint --xpath '//*[local-name()="log"]/@location' logcfg.xml      # атрибуты location всех <log>
xmllint --xpath 'string(//*[local-name()="log"]/@history)' logcfg.xml       # значение первого history
xmllint --xpath 'count(//*[local-name()="event"])' logcfg.xml       # число элементов <event>
xmllint --shell файл.xml                                # интерактивно: cat, ls, cd, xpath, quit
xmllint --noout --schema схема.xsd файл.xml             # проверка по XSD
```

Главная ловушка — **пространство имён по умолчанию**. Корневой элемент `logcfg.xml` — `<config xmlns="http://v8.1c.ru/v8/tech-log">`, у `default.vrd` — своё пространство имён, поэтому XPath `//log/@location` вернёт пустое множество (`XPath set is empty`, ненулевой код возврата). В `xmllint --xpath` обходите это через `local-name()`: `//*[local-name()="log"]`. Атрибуты без префикса в пространство имён не входят — к ним обращаются как обычно (`@location`).

Практическое значение: платформа 1С перечитывает `logcfg.xml` примерно раз в минуту; файл с синтаксической ошибкой XML просто не будет работать, поэтому после ручной правки всегда `xmllint --noout`.

### 7.3. xmlstarlet — запросы и правка XML

`sudo apt install xmlstarlet` (universe). Подкоманды: `sel` (выборка), `ed` (правка), `val` (проверка), `fo` (форматирование), `el` (структура элементов), `tr` (XSLT), `c14n`, `esc`/`unesc`. Справка по опциям подкоманды: `xmlstarlet sel --help`.

```bash
xmlstarlet el -u logcfg.xml                             # уникальные пути элементов — быстро понять структуру
xmlstarlet el -a logcfg.xml                             # пути вместе с атрибутами
xmlstarlet val -e logcfg.xml                            # проверить корректность, показать ошибки
xmlstarlet fo -s 2 logcfg.xml                           # отформатировать с отступом 2

# Выборка: -N объявляет префикс пространства имён, -t шаблон, -m «для каждого узла», -v значение, -o литерал, -n перевод строки
xmlstarlet sel -N t=http://v8.1c.ru/v8/tech-log -t \
  -m '//t:log' -v '@location' -o ' history=' -v '@history' -n logcfg.xml

# Все условия отбора событий: «оператор свойство значение»
xmlstarlet sel -N t=http://v8.1c.ru/v8/tech-log -t \
  -m '//t:event/*' -v 'name()' -o ' ' -v '@property' -o ' ' -v '@value' -n logcfg.xml

# Правка: -L — на месте, -u — обновить значение узла
cp -a logcfg.xml logcfg.xml.bak
xmlstarlet ed -L -N t=http://v8.1c.ru/v8/tech-log -u '//t:log/@history' -v 48 logcfg.xml
xmlstarlet ed -N t=http://v8.1c.ru/v8/tech-log -d '//t:dump' logcfg.xml                 # удалить элемент (вывод в stdout)
xmlstarlet ed -N t=http://v8.1c.ru/v8/tech-log -i '//t:log' -t attr -n placement -v plain logcfg.xml    # добавить атрибут
```

Замечания: вместо `-N` можно использовать префикс `_` (или `DEFAULT`), автоматически связанный с пространством имён по умолчанию корневого элемента: `xmlstarlet sel -t -v '//_:log/@location' -n logcfg.xml`. Это задокументировано в руководстве пользователя xmlstarlet для версий 1.5.0 и новее; во всех выпусках Ubuntu 22.04–26.04 пакет имеет версию 1.6.1, то есть приём работает. `-N` остаётся более явным и переносимым вариантом. `ed -L` (`--inplace`) переписывает файл целиком (может измениться форматирование и пропасть BOM) — делайте копию и проверяйте результат `diff -u`; ключи `ed -P` / `-S` сохраняют исходное форматирование / незначащие пробелы. Опции подкоманд сверены с руководством пользователя xmlstarlet (`sel`: `-N -t -m -v -o -n -c -T`; `ed`: `-d -i -a -s -r -u -t -n -v -P -S`; `val`: `-w -d -s -e -q`; `fo`: `-n -t -s -o -e`; `el`: `-a -v -u`); ключ `ed -L` в этом (старом) руководстве не описан — он есть в выводе `xmlstarlet ed --help` версии 1.6.1 (⚠ по памяти; проверьте `xmlstarlet ed --help | grep -i inplace`).

### 7.4. yq — YAML (кратко)

В apt-репозитории Ubuntu пакет `yq` — это Python-обёртка над `jq` (автор kislyuk): YAML преобразуется в JSON и обрабатывается фильтром jq. Вместе с ним ставятся `xq` (XML → JSON) и `tomlq`. Наличие по выпускам (packages.ubuntu.com, компонент universe): **22.04 — пакета `yq` нет** (`apt install yq` ответит «Unable to locate package»; варианты — `sudo snap install yq` (это уже Go-версия с другим синтаксисом) или `pipx install yq`/`pip install yq` для Python-версии); 24.04 — `yq` 3.1.0; 26.04 — `yq` 3.4.3.

```bash
sudo apt install yq                                             # Ubuntu 24.04 и 26.04 (universe); в 22.04 такого пакета нет
sudo yq . /etc/netplan/50-cloud-init.yaml                       # YAML → JSON (имя файла netplan у вас может быть другим)
sudo yq -r '.network.ethernets | keys[]' /etc/netplan/*.yaml    # имена интерфейсов
sudo yq -y '.network.ethernets' /etc/netplan/50-cloud-init.yaml # результат снова в YAML
xq . logcfg.xml                                                 # XML → JSON; атрибуты получают префикс «@»
xq -r '.config.log."@location"' logcfg.xml                      # значение атрибута (если <log> один)
```

Есть другая, несовместимая по синтаксису программа с тем же именем — `yq` на Go (автор mikefarah). В apt-архивах Ubuntu 22.04, 24.04 и 26.04 её **нет** (пакет `yq-go` появляется только в следующем выпуске, 26.10, — на packages.ubuntu.com для resolute он «not available in this suite»); в любых версиях она ставится командой `sudo snap install yq` либо готовым бинарным файлом со страницы релизов проекта. Её синтаксис: `yq '.network.ethernets' файл.yaml`, правка на месте `yq -i '.a.b = "x"' файл.yaml`, вывод в JSON `yq -o=json . файл.yaml`. Snap-версия работает в строгой изоляции и не читает файлы вне домашнего каталога (в том числе в `/etc`) — подавайте их через стандартный ввод: `sudo cat /etc/netplan/50-cloud-init.yaml | yq '.network'` (по README проекта; ⚠ по памяти). Прежде чем копировать пример из интернета, проверьте `yq --version`.

## 8. Редакторы: nano, vim, sudoedit

### 8.1. nano

Редактор по умолчанию в Ubuntu (альтернатива `editor` с наивысшим приоритетом). Подсказка по клавишам — в двух нижних строках экрана: `^X` означает `Ctrl+X`, `M-U` — `Alt+U` (или `Esc`, затем `U`).

Запуск:

```bash
nano файл
nano +120 файл              # открыть на строке 120
nano +120,5 файл            # строка 120, столбец 5
nano -l файл                # с номерами строк
nano -v файл                # только просмотр
nano -B файл                # при сохранении оставить прежнюю версию как файл~
nano -u файл                # сохранять в формате Unix (LF), даже если файл был в DOS-формате
nano -N файл                # не преобразовывать автоматически файлы DOS/Mac
nano -T 4 -E файл           # ширина табуляции 4, Tab вставляет пробелы
```

Основные клавиши (действуют в nano 6.2, 7.2 и 8.x с привязками по умолчанию):

| Клавиши | Действие |
|---|---|
| `Ctrl+G` | справка |
| `Ctrl+O`, `Enter` | записать файл (можно изменить имя); `Ctrl+S` — сохранить без вопросов |
| `Ctrl+X` | выход (при несохранённых изменениях спросит: `Y` — сохранить, `N` — нет, `Ctrl+C` — отмена) |
| `Ctrl+R` | вставить в текст другой файл |
| `Ctrl+W` | поиск; `Alt+W` — следующее совпадение; `Ctrl+Q` — поиск назад, `Alt+Q` — предыдущее |
| `Ctrl+\` (или `Alt+R`) | поиск и замена: ввести что искать, на что заменить; далее `Y` — заменить, `N` — пропустить, `A` — заменить все |
| `Alt+C`, `Alt+R`, `Alt+B` в строке поиска | учитывать регистр / регулярное выражение / искать назад |
| `Ctrl+K` | вырезать строку (или выделенное) |
| `Alt+6` | копировать строку (или выделенное) |
| `Ctrl+U` | вставить |
| `Alt+A` | начать/снять выделение (далее стрелками); работает и `Shift+стрелки` |
| `Alt+T` | вырезать от курсора до конца файла |
| `Alt+Del` | удалить строку целиком |
| `Alt+U` / `Alt+E` | отменить / повторить |
| `Ctrl+_` (обычно набирается как `Ctrl+/`) или `Alt+G` | перейти к строке (`120` или `120,5`) |
| `Ctrl+A` / `Ctrl+E` | начало / конец строки |
| `Ctrl+Y` / `Ctrl+V` | страница вверх / вниз |
| `Alt+\` / `Alt+/` | начало / конец файла |
| `Ctrl+←` / `Ctrl+→` | на слово влево / вправо |
| `Alt+]` | парная скобка |
| `Ctrl+C` | показать позицию курсора |
| `Alt+D` | число строк, слов, символов |
| `Alt+N` | включить/выключить номера строк |
| `Alt+S` | мягкий перенос длинных строк |
| `Alt+P` | показать пробелы и табуляции |
| `Alt+3` | закомментировать/раскомментировать строку |
| `Tab` / `Shift+Tab` при выделении | сдвинуть блок вправо / влево |
| `Ctrl+T` | выполнить команду и вставить её вывод |
| `Alt+←` / `Alt+→` | предыдущий / следующий открытый файл (`nano a b c`) |

Отличия версий:

- **nano 8.0+ (Ubuntu 26.04):** `Ctrl+F` — начать поиск вперёд, `Ctrl+B` — поиск назад, `Alt+F`/`Alt+B` — повторить поиск в соответствующем направлении. В nano 6.2/7.2 (Ubuntu 22.04/24.04) `Ctrl+F`/`Ctrl+B` — это перемещение курсора на символ вперёд/назад. `Ctrl+W` и `Ctrl+\` работают одинаково во всех версиях.
- nano 8.0+: колесо мыши прокручивает экран, а не двигает курсор; ключ `--modernbindings` (`-/`) включает привязки в стиле «обычных» редакторов (`^Q` выход, `^X` вырезать, `^C` копировать, `^V` вставить и т. д.).
- nano 8.1+: запись `nano файл:120` (открыть на строке) работает только с ключом `--colonparsing`; надёжнее `nano +120 файл`.

Файл DOS-формата (CRLF): при открытии nano сообщает о преобразовании и при записи сохраняет исходный формат. Сменить формат при сохранении: `Ctrl+O`, затем `Alt+D` (DOS-формат вкл/выкл), `Enter`.

Настройки: системные — `/etc/nanorc`, личные — `~/.nanorc` (или `~/.config/nano/nanorc`). Минимальный полезный набор:

```
set linenumbers
set tabsize 4
set tabstospaces
set autoindent
set softwrap
set constantshow
set positionlog
set backup
include "/usr/share/nano/*.nanorc"
```

`set backup` оставляет копию `файл~` при каждом сохранении; `set positionlog` запоминает позицию курсора между запусками; `include …` включает подсветку синтаксиса (в `/etc/nanorc` Ubuntu эта строка уже есть). `set mouse` включает мышь, но мешает выделению текста терминалом (тогда выделять с зажатым `Shift`).

### 8.2. vim

Пакеты: `vim` (полный, исполняемый файл `vim.basic`), `vim-tiny` (урезанный `vi` на минимальных установках: без подсветки и многих команд), `vim-nox`. Учебник: `vimtutor` (русский: `vimtutor ru`).

Запуск:

```bash
vim файл
vim +120 файл               # открыть на строке 120
vim +/шаблон файл           # открыть на первом совпадении
vim -R файл                 # только чтение (то же: view файл)
vim -d a.conf b.conf        # сравнение двух файлов (vimdiff)
vim -p a b c                # каждый файл в своей вкладке
vim -u NONE файл            # без файлов настроек
```

**Режимы.** Обычный (Normal) — команды; в него всегда возвращает `Esc`. Вставка (Insert) — набор текста. Визуальный (Visual) — выделение. Командная строка — после `:`. Замена — `R`.

Вход в режим вставки: `i` / `a` — перед / после курсора; `I` / `A` — в начале / в конце строки; `o` / `O` — новая строка ниже / выше; `R` — режим замены (печать поверх текста).

| Перемещение (обычный режим) | |
|---|---|
| `h` `j` `k` `l` | влево, вниз, вверх, вправо (стрелки тоже работают) |
| `w` / `b` / `e` | начало следующего слова / предыдущего / конец слова |
| `0` / `^` / `$` | начало строки / первый непробельный символ / конец строки |
| `gg` / `G`; `120G` или `:120` | начало / конец файла; к строке 120 |
| `Ctrl+F` / `Ctrl+B` | страница вперёд / назад; `Ctrl+D` / `Ctrl+U` — полстраницы |
| `%`; `{` / `}` | парная скобка; предыдущий / следующий абзац |
| `f` + символ, `;` | к следующему такому символу в строке, повторить |
| `*` / `#` | искать слово под курсором вперёд / назад |
| `ma`, `'a` | поставить метку `a`, вернуться к ней |
| `Ctrl+O` / `Ctrl+I`; `zz` | назад / вперёд по истории переходов; текущую строку — в центр экрана |

| Правка (обычный режим) | |
|---|---|
| `x`; `r` + символ; `~` | удалить символ; заменить один символ; сменить регистр символа |
| `dd` / `3dd` | удалить (вырезать) строку / три строки |
| `dw`, `d$` (или `D`), `d0`, `dG`, `dgg` | удалить слово / до конца строки / до начала строки / до конца файла / до начала файла |
| `yy` / `5yy`, `yw` | копировать строку / пять строк / слово |
| `p` / `P` | вставить после / перед курсором |
| `u` / `Ctrl+R`; `.` | отмена / повтор; повторить последнюю правку |
| `cw`, `cc`, `C` | заменить слово / строку / до конца строки (с переходом во вставку) |
| `ciw`, `ci"`, `di(` | заменить слово под курсором / текст в кавычках; удалить текст в скобках |
| `J`; `>>` / `<<` | присоединить следующую строку; сдвинуть строку вправо / влево |

**Поиск и замена.**

```
/шаблон        поиск вперёд;  ?шаблон — назад;  n / N — следующее / предыдущее совпадение
/шаблон\c      без учёта регистра для одного поиска (или :set ignorecase)
:noh           убрать подсветку найденного
:s/старое/новое/           первое вхождение в текущей строке
:s/старое/новое/g          все вхождения в текущей строке
:%s/старое/новое/g         во всём файле
:%s/старое/новое/gc        во всём файле с подтверждением каждой замены (y/n/a/q)
:10,20s/старое/новое/g     в строках 10–20
:'<,'>s/старое/новое/g     в выделенном (диапазон подставляется сам при нажатии «:» в визуальном режиме)
:%s/\<слово\>/новое/g      только целое слово
:%s#/старый/путь#/новый/путь#g      другой разделитель
:%s/\s\+$//                убрать пробелы в концах строк
:%s/\r$//                  убрать CR (^M) в концах строк
:%s/шаблон//gn             посчитать вхождения, ничего не меняя
:g/шаблон/d                удалить все строки с шаблоном
:v/шаблон/d                удалить все строки БЕЗ шаблона
:g/^\s*$/d                 удалить пустые строки
```

В регулярных выражениях vim по умолчанию `+`, `|`, `(`, `)`, `{` требуют обратного слэша (`\+`, `\|`, `\(…\)`), как в BRE; префикс `\v` в начале шаблона включает «очень магический» режим, близкий к ERE: `:%s/\v(foo|bar)+/x/g`.

**Визуальный режим.** `v` — посимвольное выделение, `V` — построчное, `Ctrl+V` — прямоугольный блок. После выделения: `d` — вырезать, `y` — копировать, `c` — заменить, `>`/`<` — сдвиг, `~`/`u`/`U` — регистр, `:` — команда для диапазона (`:'<,'>sort`, `:'<,'>w кусок.txt`, `:'<,'>!sort -u` — пропустить через внешнюю команду). Вставка текста сразу в несколько строк (например, закомментировать блок): `Ctrl+V`, выделить столбец стрелками, `I`, набрать `#`, `Esc`. `gv` — выделить снова то же.

**Сохранение и выход.**

| Команда | Действие |
|---|---|
| `:w` | сохранить |
| `:w имя` | сохранить под другим именем |
| `:wq` или `:x` или `ZZ` | сохранить и выйти |
| `:q` | выйти (если нет изменений) |
| `:q!` или `ZQ` | выйти без сохранения |
| `:wa`, `:qa`, `:qa!` | сохранить все / закрыть все / закрыть все без сохранения |
| `:e!` | отбросить изменения и перечитать файл |
| `:e файл` | открыть другой файл |
| `:r файл`, `:r !команда` | вставить файл / вывод команды |
| `:w !sudo tee % > /dev/null` | сохранить файл, открытый без прав root (затем `:q!`) |
| `:!команда` | выполнить команду оболочки |

**Окна, буферы, вкладки.** `:ls` — список буферов, `:bn`/`:bp` — следующий/предыдущий, `:bd` — закрыть; `:sp файл` / `:vsp файл` — разделить окно горизонтально/вертикально, `Ctrl+W` затем `w`/`h`/`j`/`k`/`l` — переход между окнами, `Ctrl+W q` — закрыть окно; `:tabnew файл`, `gt`/`gT` — вкладки.

**Макросы.** `qa` — начать запись в регистр `a`; выполнить нужные действия; `q` — остановить запись. `@a` — воспроизвести, `@@` — повторить последний, `20@a` — 20 раз, `:%normal @a` — применить к каждой строке файла, `:5,30normal @a` — к строкам 5–30. Пример: превратить список имён в SQL — `qa` `I'` `Esc` `A',` `Esc` `j` `q`, затем `100@a`.

**Полезные настройки на лету.**

```
:set number            номера строк (:set nonumber — убрать; :set relativenumber — относительные)
:set list              показать табуляции (^I) и концы строк ($);  :set nolist
:set nowrap            не переносить длинные строки
:set hlsearch incsearch ignorecase smartcase
:set paste             перед вставкой текста из буфера терминала (не «лесенкой»);  :set nopaste
:set ff?               формат строк файла (unix/dos);  :set ff=unix — сохранить с LF, :set ff=dos — с CRLF
:set fenc?             кодировка файла;  :set fenc=utf-8 — сохранить в UTF-8
:set bomb?             есть ли BOM;  :set nobomb — сохранить без BOM;  :set bomb — с BOM
:e ++enc=cp1251        перечитать файл как CP1251;  :e ++ff=dos — как DOS-файл
:w ++enc=utf-8         записать в UTF-8
:syntax on             подсветка;  :set syntax=xml — принудительно задать тип
:set et ts=4 sw=4      Tab → 4 пробела;  :retab — преобразовать существующие табуляции
```

Перекодировать файл из CP1251 в UTF-8 без BOM с Unix-переводами строк: `:e ++enc=cp1251`, затем `:set fenc=utf-8 nobomb ff=unix`, `:w`.

**Минимальный `~/.vimrc`:**

```vim
" ~/.vimrc — минимум для администратора
set nocompatible
syntax on
set number
set hlsearch incsearch ignorecase smartcase
set tabstop=4 shiftwidth=4 expandtab autoindent
set backspace=indent,eol,start
set encoding=utf-8
set fileencodings=ucs-bom,utf-8,cp1251,koi8-r,cp866
set fileformats=unix,dos
set laststatus=2 ruler showcmd wildmenu
set mouse=
" команды обычного режима при включённой русской раскладке
set langmap=ФИСВУАПРШОЛДЬТЩЗЙКЫЕГМЦЧНЯ;ABCDEFGHIJKLMNOPQRSTUVWXYZ,фисвуапршолдьтщзйкыегмцчня;abcdefghijklmnopqrstuvwxyz
```

`fileencodings` задаёт порядок автоопределения кодировки при открытии: файл с BOM, затем UTF-8, затем CP1251. Системные настройки — `/etc/vim/vimrc` и `/etc/vim/vimrc.local`. Если `~/.vimrc` отсутствует, vim 8+ подгружает разумные умолчания из `defaults.vim`; с появлением собственного `~/.vimrc` они отключаются.

**Типовые ситуации.**

- «Не могу выйти»: `Esc`, затем `:q!` и `Enter`.
- `E325: ATTENTION Found a swap file` — файл уже открыт в другом vim или прошлый сеанс оборвался: `R` — восстановить, `Q` — выйти, `D` — удалить swap-файл (если уверены, что он не нужен). Восстановление вручную: `vim -r файл`.
- `E45: 'readonly' option is set` — нет прав на запись: `:w !sudo tee % > /dev/null`, или выйти и открыть через `sudoedit`.
- Экран «завис» после `Ctrl+S` — это остановка вывода терминала (XOFF); нажмите `Ctrl+Q`.
- В конце каждой строки видно `^M` — файл со смешанными переводами строк: `:%s/\r$//`.

### 8.3. sudoedit, EDITOR и выбор редактора по умолчанию

**`sudoedit файл`** (то же, что `sudo -e файл`) — безопасный способ править системные файлы: создаётся временная копия, принадлежащая вызывающему пользователю; редактор запускается **от имени пользователя, а не root** (со своими настройками `~/.vimrc`/`~/.nanorc`); после выхода изменённая копия записывается на место оригинала.

```bash
sudoedit /etc/postgresql/17/main/postgresql.conf
sudoedit /etc/hosts /etc/fstab                     # несколько файлов
SUDO_EDITOR=vim sudoedit /etc/ssh/sshd_config      # редактор на один раз
```

Редактор выбирается по переменным `SUDO_EDITOR`, `VISUAL`, `EDITOR` (в этом порядке); если ни одна не задана — первый редактор из параметра `editor` в sudoers (в Ubuntu это системная альтернатива `editor`). Ограничения: нельзя править символические ссылки и файлы в каталогах, куда вызывающий пользователь сам может писать; файлы устройств править нельзя. В Ubuntu 26.04 команда `sudo` — это sudo-rs (0.2.13); `sudoedit` в нём поддерживается (с версии 0.2.8), порядок переменных тот же — `SUDO_EDITOR`, `VISUAL`, `EDITOR` (man-страница sudo-rs для resolute), ограничения на символические ссылки, каталоги, доступные вызывающему на запись, и файлы устройств — те же. Отличие: аргументы внутри `SUDO_EDITOR` (например, `SUDO_EDITOR="vim -n"`) sudo-rs понимает только начиная с 0.2.13 (журнал изменений sudo-rs).

**Переменные окружения** (добавить в `~/.bashrc`):

```bash
export EDITOR=vim
export VISUAL=vim
```

**Системный редактор по умолчанию** — альтернатива `editor` (`/usr/bin/editor`):

```bash
update-alternatives --display editor                       # что выбрано и какие есть варианты
sudo update-alternatives --config editor                   # интерактивный выбор из списка
sudo update-alternatives --set editor /usr/bin/vim.basic   # без вопросов
sudo update-alternatives --auto editor                     # вернуть автоматический выбор (по приоритету)
select-editor                                              # личный выбор пользователя (файл ~/.selected_editor)
```

Типичный список `--config editor`: `/bin/nano` (приоритет 40, выбран автоматически), `/usr/bin/vim.basic` (30), `/usr/bin/vim.tiny` (15), `/bin/ed` (−100).

Кто какой редактор запускает:

| Команда | Откуда берёт редактор |
|---|---|
| `sudoedit`, `sudo -e` | `SUDO_EDITOR` → `VISUAL` → `EDITOR` → параметр `editor` sudoers |
| `crontab -e` | `VISUAL` → `EDITOR` → `sensible-editor` (`~/.selected_editor`, затем альтернатива `editor`); при первом запуске предлагает выбрать |
| `systemctl edit юнит` | `SYSTEMD_EDITOR` → `EDITOR` → `VISUAL` → `editor`, `nano`, `vim`, `vi` |
| `visudo` | `SUDO_EDITOR` → `VISUAL` → `EDITOR`, если включён параметр sudoers `env_editor` (в сборке sudo для Debian/Ubuntu и в sudo-rs он включён по умолчанию), затем список из параметра `editor` sudoers. Для sudo-rs 0.2.13 (Ubuntu 26.04) проверено по исходному коду: порядок переменных тот же, умолчание `editor` — `/usr/bin/editor:/usr/bin/nano:/usr/bin/vi`; man-страница `visudo` из sudo-rs об этом молчит. Переменную под `sudo` надо передать явно: `sudo EDITOR=vim visudo` (если политика sudo не пропустит переменную — смените системную альтернативу `editor`) |
| `psql`: `\e`, `\ef` | `PSQL_EDITOR` → `EDITOR` → `VISUAL` |
| `less`: клавиша `v` | `VISUAL` → `EDITOR` |
| `git commit` | `GIT_EDITOR` → `core.editor` → `VISUAL` → `EDITOR` |

`sudo` по умолчанию очищает окружение, поэтому `EDITOR` из вашей оболочки до команды под `sudo` не доходит: пишите `sudo EDITOR=vim crontab -e -u usr1cv8`.

## 9. Локали, кодировки и BOM

### 9.1. Локаль и её влияние на текстовые утилиты

```bash
locale                          # текущие значения LANG, LC_CTYPE, LC_COLLATE, LC_NUMERIC, …, LC_ALL
locale -a                       # какие локали сгенерированы в системе
localectl status                # системная локаль
sudo locale-gen ru_RU.UTF-8     # сгенерировать локаль
sudo update-locale LANG=ru_RU.UTF-8     # задать системную (записывается в /etc/default/locale; действует после нового входа)
```

Приоритет: `LC_ALL` перекрывает все `LC_*`, те перекрывают `LANG`. Локаль `C.UTF-8` в Ubuntu есть всегда (UTF-8 без национальных правил); `C` (она же `POSIX`) — чистые байты/ASCII.

| Категория | На что влияет в текстовых утилитах |
|---|---|
| `LC_CTYPE` | что считается символом и буквой: `.` в регулярных выражениях, `-i`, `[[:alpha:]]`, `\w`, `\U`/`\L` в sed, `wc -m`, `toupper()` в gawk, отображение в `less` |
| `LC_COLLATE` | порядок сортировки: `sort`, `uniq`, `join`, `comm`, `ls`, диапазоны `[a-z]` |
| `LC_NUMERIC` | десятичный разделитель: `sort -n`, `printf` в bash и mawk |
| `LC_MESSAGES` | язык сообщений программ |

Практические рецепты:

```bash
LC_ALL=C grep -c 'DBPOSTGRS' big.log          # максимально быстрый побайтовый поиск латиницы/цифр
LC_ALL=C sort big.txt | LC_ALL=C uniq -c      # быстрая сортировка; порядок — по кодам байтов
export LC_NUMERIC=C LC_COLLATE=C              # на сеанс разбора логов: точка в дробях, побайтовая сортировка, а LC_CTYPE остаётся UTF-8
LC_ALL=C.UTF-8 grep -i 'ошибка' файл          # UTF-8 без зависимости от того, сгенерирована ли ru_RU
```

Если `locale` показывает заданную `LC_ALL`, отдельные `LC_NUMERIC`/`LC_COLLATE` не подействуют — сначала `unset LC_ALL`.

Что ломается при `LC_ALL=C` (всё — байты):

- `grep -i 'ошибка'` не находит `ОШИБКА` (регистр кириллицы не сворачивается); подстрока в том же регистре находится нормально — сравниваются байты.
- `.` совпадает с одним байтом, а кириллическая буква — два байта: `grep -o 'Сеанс.'` вернёт «половину» следующей буквы.
- `\w`, `[[:alpha:]]`, `\b` кириллицу буквами не считают; `sed 's/./X/g'` заменит каждую русскую букву на `XX`; `sed 's/.*/\U&/'` не изменит кириллицу.
- `less` показывает кириллицу как `<D0><9F>…`.

Что нужно помнить в `ru_RU.UTF-8`:

- `sort -n` и `printf` ждут **запятую** в дробях: `echo 12.5 | sort -n` воспринимает число как 12; `printf '%.2f\n' 1.5` в bash завершится ошибкой «недопустимое число». Лекарство — `LC_NUMERIC=C`.
- `sort` без `-n` сортирует по правилам языка (регистр и знаки препинания почти не учитываются) и работает заметно медленнее, чем при `LC_ALL=C`.
- Диапазон `[а-я]` не включает `ё`; `[А-я]` — не «все русские буквы». Пишите `[А-Яа-яЁё]` или в `grep -P` — `\p{Cyrillic}`.
- `sort | uniq`, `join`, `comm` должны работать в одной и той же локали, иначе «файл не отсортирован».

Поиск в файле с кодировкой, отличной от локали:

```bash
iconv -f CP1251 -t UTF-8 файл.txt | grep -i 'ошибка'                              # перекодировать на лету
LC_ALL=C grep -a "$(printf 'ошибка' | iconv -f UTF-8 -t CP1251)" файл.txt         # или перекодировать сам шаблон
rg -E windows-1251 -i 'ошибка' файл.txt                                           # ripgrep умеет сам
```

Для сервера 1С системная локаль должна быть UTF-8 (обычно `ru_RU.UTF-8`); подробности — в статьях об установке сервера 1С и PostgreSQL.

### 9.2. BOM (маркер порядка байтов) в файлах 1С

BOM для UTF-8 — три байта `EF BB BF` (символ U+FEFF) в самом начале файла. Windows-программы и платформа 1С обычно пишут UTF-8 **с BOM**; большинство Unix-утилит BOM не ожидают и считают его частью первой строки.

Где встречается в окружении 1С:

- файлы технологического журнала (каждый `ГГММДДЧЧ.log` начинается с BOM — это учтено в методике ИТС: шаг `perl -pe 's/\xef\xbb\xbf//g'`);
- текстовые выгрузки конфигурации (модули `*.bsl`, XML), файлы, записанные из 1С объектом `ЗаписьТекста` в UTF-8;
- служебные текстовые файлы платформы — списки баз `*.v8i`, файлы кластера `*.lst`, текстовый журнал регистрации `*.lgf`/`*.lgp` (⚠ не подтверждено по документации — проверяйте `head -c3 файл | xxd -p`);
- любые файлы, отредактированные в Windows «Блокнотом» с сохранением как «UTF-8 со спецификацией».

Что ломает BOM:

- `grep '^шаблон'`, `awk '/^…/'`, `sed '/^…/'` не срабатывают на первой строке; в ТЖ это «потерянное» первое событие каждого файла;
- скрипт с BOM перед `#!/bin/bash` не запускается как положено (ядро не видит shebang);
- первая директива/ключ в конфигурационном файле не распознаётся; первый столбец CSV получает «невидимый» префикс;
- при склейке `cat a b` BOM второго файла оказывается в середине потока.

```bash
# Обнаружить
head -c3 файл | xxd -p                                  # efbbbf — BOM есть
file файл                                               # «… UTF-8 (with BOM) text»
grep -rlP '^\x{FEFF}' --include='*.sh' --include='*.conf' /etc /opt 2>/dev/null    # найти файлы с BOM (UTF-8-локаль)
LC_ALL=C grep -rl $'^\xEF\xBB\xBF' каталог/             # то же побайтово

# Удалить
sed -i '1s/^\xEF\xBB\xBF//' файл                        # на месте (GNU sed)
sed '1s/^\xEF\xBB\xBF//' файл > без_bom                 # в новый файл
dos2unix -r файл                                        # удалить BOM (и заодно CRLF → LF)
awk 'NR == 1 { sub(/^\357\273\277/, "") } { print }' файл     # в конвейере (восьмеричные коды понятны и mawk, и gawk)
perl -pe 's/^\xef\xbb\xbf//' файл                       # perl работает с байтами; удобно для потока из многих файлов
# в vim:  :set nobomb  затем  :w

# Добавить
sed -i '1s/^/\xEF\xBB\xBF/' файл
{ printf '\xEF\xBB\xBF'; cat файл; } > с_bom
# в vim:  :set bomb  затем  :w
```

### 9.3. Переводы строк и «гибридные» файлы

Файл из Windows — CRLF (`\r\n`), в Linux — LF (`\n`). Признаки CRLF: `file` пишет `with CRLF line terminators`, `cat -A` показывает `^M$`, скрипт падает с `/bin/bash^M: bad interpreter`, значение из конфигурационного файла «не совпадает», потому что в конце висит невидимый `\r`. Преобразование — раздел 2.10. При сравнении `diff --strip-trailing-cr`. В шаблонах для файлов неизвестного происхождения конец строки пишите как `\r?$`.

Порядок «привести чужой файл в порядок»: `file -i файл` (кодировка) → `head -c3 файл | xxd -p` (BOM?) → `grep -c $'\r' файл` (CRLF?) → `iconv -f CP1251 -t UTF-8 файл > файл.utf8` (если не UTF-8) → `dos2unix файл.utf8` (CRLF → LF, снять BOM) → `iconv -f UTF-8 -t UTF-8 файл.utf8 > /dev/null && echo OK` (проверка).

### 10.1. systemd-journald: journalctl

| Опция | Действие |
|---|---|
| `-u ЮНИТ` | сообщения юнита (можно шаблон: `-u 'srv1cv8*'`; можно несколько `-u`) |
| `-p УРОВЕНЬ` | по важности: `emerg`(0) `alert`(1) `crit`(2) `err`(3) `warning`(4) `notice`(5) `info`(6) `debug`(7); один уровень = он и все важнее; диапазон `-p warning..err` |
| `-b` | текущая загрузка; `-b -1` — предыдущая; `--list-boots` — список загрузок |
| `-k` | только сообщения ядра (как `dmesg`) |
| `-S`/`--since`, `-U`/`--until` | период: `"2026-10-10 09:00"`, `today`, `yesterday`, `"1 hour ago"`, `-30min` |
| `-f` | следить за новыми сообщениями |
| `-e` | открыть в конце журнала |
| `-n N` | последние N записей |
| `-r` | новые сверху |
| `-x` | добавить пояснения из каталога сообщений |
| `-g ШАБЛОН` | grep по тексту сообщения (PCRE2); шаблон в нижнем регистре — поиск без учёта регистра; `--case-sensitive` — принудительно |
| `-t ИМЯ` | по идентификатору syslog (`sudo`, `sshd`, `kernel`, `CRON`) |
| `-o ФОРМАТ` | `short` (по умолчанию), `short-iso`, `short-precise`, `cat` (только текст), `json`, `json-pretty`, `verbose`, `with-unit` |
| `--no-pager` | без `less` (для конвейеров) |
| `_PID=`, `_UID=`, `_COMM=`, `_SYSTEMD_UNIT=` | отбор по полям записи |
| `--disk-usage`, `--vacuum-size=1G`, `--vacuum-time=30d` | размер журнала и его очистка |

```bash
journalctl -p err -b --no-pager                                 # все ошибки с момента загрузки
journalctl -p warning..err --since today                        # предупреждения и ошибки за сегодня
journalctl -u postgresql@17-main --since "1 hour ago"           # юнит кластера PostgreSQL (Ubuntu/PGDG)
journalctl -u 'srv1cv8*' -e                                     # сервер 1С: точное имя юнита — systemctl list-units 'srv1cv8*'
journalctl -u apache2 -u 'srv1cv8*' -f                          # следить за несколькими службами
journalctl --since "2026-10-10 09:00" --until "2026-10-10 09:30" -o short-iso
journalctl -k -g 'out of memory|oom-kill|killed process'        # работа OOM-killer (кто убил rphost или postgres)
journalctl -k -g 'i/o error|ext4-fs error|xfs.*error'           # проблемы дисков и файловых систем
journalctl -g 'segfault|core dumped' --since yesterday          # аварийные завершения процессов
journalctl _COMM=rphost --since today                           # сообщения процессов с именем rphost
journalctl _UID="$(id -u usr1cv8)" -p err --since today         # ошибки всего, что запущено от usr1cv8
journalctl -t sudo --since today                                # кто и что запускал через sudo
journalctl -b -1 -e                                             # конец журнала предыдущей загрузки (что было перед перезагрузкой)
journalctl --disk-usage                                         # сколько места занимает журнал

# Топ источников ошибок за сутки:
journalctl -p err --since "24 hours ago" -o json --no-pager \
  | jq -r '.SYSLOG_IDENTIFIER // ._COMM // "?"' | sort | uniq -c | sort -rn | head

# Неудачные попытки входа по SSH — топ адресов:
journalctl -u ssh --since yesterday --no-pager -g 'failed password|invalid user' \
  | grep -oE '[0-9]{1,3}(\.[0-9]{1,3}){3}' | sort | uniq -c | sort -rn | head

# Обычный grep по journald (если нужен контекст -A/-B):
journalctl -u 'srv1cv8*' --since today --no-pager | grep -i -B2 -A5 'error'
```

Журнал службы показывает то, что процесс написал в stdout/stderr, и события systemd (запуск, остановка, код завершения). Сервер 1С пишет туда мало — подробная диагностика 1С находится в технологическом журнале; PostgreSQL в Ubuntu пишет основной журнал в файл (раздел 10.3), а в journald — только запуск/остановку.

### 10.2. Файлы в /var/log

| Файл | Содержимое |
|---|---|
| `/var/log/syslog` | общий системный журнал (пишет rsyslog; он входит в стандартную установку Ubuntu Server 22.04–26.04 — пакет есть в манифестах установочных образов 24.04.4 и 26.04.1; в минимальных и контейнерных образах rsyslog может отсутствовать — тогда файла нет, пользуйтесь `journalctl`) |
| `/var/log/auth.log` | аутентификация: ssh, sudo, su |
| `/var/log/kern.log` | сообщения ядра (OOM-killer, диски, сеть) |
| `/var/log/dpkg.log`, `/var/log/apt/history.log`, `/var/log/apt/term.log` | установка и обновление пакетов |
| `/var/log/unattended-upgrades/` | автоматические обновления |
| `/var/log/postgresql/` | журналы кластеров PostgreSQL |
| `/var/log/apache2/access.log`, `error.log` | веб-сервер (веб-клиент и веб-сервисы 1С) |
| `/var/log/journal/` | двоичные файлы journald (читать только через `journalctl`) |

Ротация — `logrotate` (настройки в `/etc/logrotate.d/`): `файл.log` → `файл.log.1` → `файл.log.2.gz` …; читать сжатые — `zgrep`/`zcat`/`zless`.

**Формат метки времени в файлах rsyslog зависит от выпуска.** В Ubuntu 22.04 — традиционный, без года и часового пояса: `Oct 10 12:34:56 host программа[PID]: текст` (метка занимает три поля). В Ubuntu 24.04 и новее — «высокоточный» ISO 8601 одним полем: `2026-10-10T12:34:56.123456+05:00 host программа[PID]: текст` (в Debian это умолчание rsyslog с выпуска 12 «bookworm» — заметки к выпуску Debian, п. 5.1.8; для Ubuntu 24.04/26.04 — практика, ⚠ сверьте: `sudo head -1 /var/log/syslog`). От формата зависят номера полей в `awk`, ключ `uniq -f` и шаблоны времени: под традиционный формат — `awk '{ print $1, $2, substr($3, 1, 2) ":00" }'`, под ISO — `awk '{ print substr($1, 1, 13) ":00" }'` (счёт событий по часам; в конец добавить `| uniq -c` — строки журнала и так идут по времени, сортировка не нужна; если всё же сортировать, то ISO-метки правильно упорядочивает обычный `sort`, а традиционные — только `sort -k1,1M -k2,2n -k3,3`).

```bash
sudo tail -F /var/log/syslog                                            # живой поток
sudo grep -iE 'error|fail|denied|refused' /var/log/syslog | tail -50
sudo zgrep -h 'Out of memory' /var/log/kern.log* | tail                 # OOM за всё время хранения
sudo zgrep -h 'Killed process' /var/log/kern.log* | grep -oP 'Killed process \d+ \(\K[^)]+' | sort | uniq -c | sort -rn   # кого убивал OOM-killer
sudo grep -E 'sudo(\[[0-9]+\])?:.*COMMAND=' /var/log/auth.log | tail -20   # последние команды через sudo (шаблон допускает и «sudo:», и «sudo[PID]:»)
sudo zgrep -h 'Failed password' /var/log/auth.log* | grep -oE 'from [0-9.]+' | sort | uniq -c | sort -rn | head
grep -E ' (install|upgrade|remove) ' /var/log/dpkg.log | tail -30       # что ставилось/обновлялось
zgrep -h -E ' (install|upgrade) .*(postgres|1c-enterprise)' /var/log/dpkg.log* | sort       # история установки PostgreSQL и 1С
awk '$9 >= 500' /var/log/apache2/access.log | tail                      # ответы 5xx (формат combined: 9-е поле — код)
awk '{ c[$9]++ } END { for (k in c) print c[k], k }' /var/log/apache2/access.log | sort -rn        # распределение кодов ответа
sudo grep -c '' /var/log/syslog                                         # число строк (grep -c '' считает и последнюю строку без \n)
sudo du -sh /var/log/* 2>/dev/null | sort -h | tail                     # что занимает место в /var/log
```

### 10.3. Журнал PostgreSQL

**Где лежит.** В Ubuntu с пакетами `postgresql-NN` (из Ubuntu или PGDG, управление через `postgresql-common`): `/var/log/postgresql/postgresql-<версия>-<кластер>.log`, например `/var/log/postgresql/postgresql-17-main.log`; путь показывает `pg_lsclusters` (столбец «Log file»). Ротация — logrotate. При `logging_collector = on` журналы пишутся в `log_directory` (по умолчанию `log` внутри каталога данных, имя `postgresql-%Y-%m-%d_%H%M%S.log`). Для сборок Postgres Pro (каталог данных `/var/lib/pgpro/<редакция>-<версия>/data`, например `/var/lib/pgpro/std-17/data`; служба `postgrespro-std-17`; программы в `/opt/pgpro/std-17/bin` — документация Postgres Pro Standard 17, «Установка из двоичных пакетов в Linux») расположение журнала в этой главе документации не описано — ⚠ не подтверждено. По практике сообщества эти сборки не используют `postgresql-common` и `/var/log/postgresql/`: журнал либо пишет сборщик (`logging_collector = on`) в подкаталог `log` каталога данных (файлы вида `postgresql-<день недели>.log`), либо, при выключенном сборщике, вывод сервера попадает в journald (`journalctl -u postgrespro-std-17`) — что именно у вас, показывают запросы ниже. Универсальный способ узнать:

```bash
sudo -u postgres psql -Atc "SELECT name || ' = ' || setting FROM pg_settings WHERE name IN ('logging_collector','log_destination','log_directory','log_filename','data_directory','log_line_prefix','log_min_duration_statement','lc_messages')"
sudo -u postgres psql -Atc "SELECT pg_current_logfile()"      # текущий файл сборщика журналов (пусто, если logging_collector = off)
```

**Формат строки.** В Ubuntu `postgresql-common` задаёт `log_line_prefix = '%m [%p] %q%u@%d '` (`%m` — время с миллисекундами, `%p` — PID, `%u@%d` — пользователь@база; встроенное умолчание PostgreSQL — `'%m [%p] '`):

```
2026-10-10 09:15:42.123 +05 [12345] usr1cv8@erp LOG:  duration: 5234.871 ms  statement: SELECT …
2026-10-10 09:15:43.001 +05 [12346] usr1cv8@erp ERROR:  deadlock detected
2026-10-10 09:15:43.001 +05 [12346] usr1cv8@erp DETAIL:  Process 12346 waits for ShareLock on transaction 9876; blocked by process 12350.
2026-10-10 09:15:43.001 +05 [12346] usr1cv8@erp STATEMENT:  UPDATE …
```

Продолжения многострочного сообщения (длинный SQL) начинаются с табуляции (поведение сервера при выводе в stderr/файл; в главе документации о журналировании не описано — убедиться можно командой `grep -c $'^\t' "$PGLOG"`). Уровни по возрастанию важности: `DEBUG5…DEBUG1`, `INFO`, `NOTICE`, `WARNING`, `ERROR`, `LOG`, `FATAL`, `PANIC`.

**Что должно быть включено, чтобы было что анализировать** (параметры `postgresql.conf`; значения — на усмотрение администратора, это не рекомендации по настройке):

| Параметр | Что даёт в журнале |
|---|---|
| `log_min_duration_statement = 1000` | запросы дольше 1000 мс: `duration: … ms  statement: …` (`-1` — выключено, это умолчание; `0` — все запросы) |
| `log_lock_waits = on` | ожидания блокировок дольше `deadlock_timeout`: `process N still waiting for …` |
| `log_temp_files = 0` | временные файлы (запись делается при удалении файла; размер в байтах): `temporary file: path "…", size N` |
| `log_checkpoints = on` (умолчание с 15-й версии) | контрольные точки |
| `log_autovacuum_min_duration` (умолчание 10 мин) | длительные автоочистки: `automatic vacuum of table "…"` |
| `lc_messages = 'en_US.UTF-8'` или `'C'` | сообщения по-английски — нужны для готовых шаблонов grep и pgBadger |

Дополнения по PostgreSQL 18 (документация, глава «Error Reporting and Logging»): `log_temp_files` записывает сообщение в момент **удаления** временного файла (значение без единиц — килобайты; `0` — все файлы, `-1` — выключено, это умолчание); появился параметр `log_lock_failures` (умолчание `off`; пока действует только для `SELECT … NOWAIT`); `log_connections` стал списком (`receipt`, `authentication`, `authorization`, `setup_durations`, `all`; прежние `on`/`off` принимаются). Умолчания: `log_lock_waits = off`, `log_min_duration_statement = -1`, `log_checkpoints = on`, `log_autovacuum_min_duration = 10min`, `log_line_prefix = '%m [%p] '`, `log_directory = 'log'`, `log_filename = 'postgresql-%Y-%m-%d_%H%M%S.log'`.

Если `lc_messages = 'ru_RU.UTF-8'` (так бывает, когда кластер создан с русской локалью), метки и тексты переведены. Переводы сверены с каталогом сообщений сервера `src/backend/po/ru.po` (ветка REL_18_STABLE):

| В английском журнале | В русском журнале (`lc_messages = ru_RU.UTF-8`) |
|---|---|
| `LOG:` | `СООБЩЕНИЕ:` |
| `ERROR:` / `FATAL:` / `PANIC:` | `ОШИБКА:` / `ВАЖНО:` / `ПАНИКА:` |
| `WARNING:` / `NOTICE:` / `INFO:` / `DEBUG:` | `ПРЕДУПРЕЖДЕНИЕ:` / `ЗАМЕЧАНИЕ:` / `ИНФОРМАЦИЯ:` / `ОТЛАДКА:` |
| `DETAIL:` / `HINT:` / `CONTEXT:` | `ПОДРОБНОСТИ:` / `ПОДСКАЗКА:` / `КОНТЕКСТ:` |
| `STATEMENT:` / `QUERY:` / `LOCATION:` | `ОПЕРАТОР:` / `ЗАПРОС:` / `ПОЛОЖЕНИЕ:` |
| `duration: 5234.871 ms  statement: SELECT …` (два пробела) | `продолжительность: 5234.871 мс, оператор: SELECT …` (**запятая** и один пробел) |
| `duration: 5234.871 ms` (отдельной строкой при `log_duration`) | `продолжительность: 5234.871 мс` |
| `duration: … ms  parse <имя>: …` / `… bind <имя>: …` | `продолжительность: … мс, разбор <имя>: …` / `продолжительность: … мс, сообщение Bind <имя>: …` |
| `deadlock detected` | `обнаружена взаимоблокировка` |
| `process N still waiting for ShareLock on … after … ms` | `процесс N продолжает ожидать в режиме ShareLock блокировку "…" в течение … мс` |
| `process N acquired … on … after … ms` | `процесс N получил в режиме … блокировку "…" через … мс` |
| `temporary file: path "…", size N` | `временный файл: путь "…", размер N` |
| `sorry, too many clients already` | `извините, уже слишком много клиентов` |
| `canceling statement due to lock timeout` | `выполнение оператора отменено из-за тайм-аута блокировки` |
| `automatic vacuum of table "база.схема.таблица": …` | `автоматическая очистка таблицы "база.схема.таблица": …` |
| `could not extend file "…": …` | `не удалось увеличить файл "…": …` |

Тогда в шаблонах ниже заменяйте слова соответственно: `grep -E ' (ОШИБКА|ВАЖНО|ПАНИКА): '`; длительность на обоих языках сразу — `grep -oP '(duration|продолжительность): \K[0-9.]+'`; в п. 6 сравнивайте с `"продолжительность:"`, в п. 8 — шаблон `продолжительность: ([\d.]+) мс, оператор: (.*)`. Строки формата расширенного протокола (`execute`) и остальные тексты (аутентификация, контрольные точки, аварийные завершения) в этой сверке не проверялись — ⚠ берите точные формулировки из своего журнала. Надёжнее всего один раз задать `lc_messages = 'en_US.UTF-8'` (или `'C'`) и выполнить `SELECT pg_reload_conf();` — тогда работают все шаблоны статьи и pgBadger.

```bash
PGLOG=/var/log/postgresql/postgresql-17-main.log

# 1. Сколько сообщений каждого уровня
grep -oE ' (LOG|WARNING|ERROR|FATAL|PANIC): ' "$PGLOG" | sort | uniq -c

# 2. Ошибки с контекстом (DETAIL / HINT / STATEMENT идут следом)
grep -n -A3 -E ' (ERROR|FATAL|PANIC): ' "$PGLOG" | less

# 3. Топ текстов ошибок (числа обезличены), по всем ротированным файлам
zgrep -hoP ' (ERROR|FATAL|PANIC):\s+\K.*' "$PGLOG"* | sed -E 's/[0-9]+/N/g' | sort | uniq -c | sort -rn | head -20

# 4. Ошибки по часам
grep -E ' (ERROR|FATAL|PANIC): ' "$PGLOG" | awk '{ print $1, substr($2, 1, 2) ":00" }' | sort | uniq -c

# 5. Ошибки по парам пользователь@база
grep -E ' (ERROR|FATAL): ' "$PGLOG" | grep -oP '\] \K\S+@\S+' | sort | uniq -c | sort -rn

# 6. Двадцать самых долгих запросов (нужен log_min_duration_statement)
awk '/duration: [0-9.]+ ms/ { for (i = 1; i <= NF; i++) if ($i == "duration:") { print $(i+1) "\t" $0; break } }' "$PGLOG" \
  | sort -rn | head -20 | cut -c1-400

# 7. Склейка многострочных сообщений (строки-продолжения начинаются с табуляции) — функция для дальнейших конвейеров
pg_glue() { awk '/^\t/ { printf " %s", substr($0, 2); next } { if (n++) printf "\n"; printf "%s", $0 } END { if (n) printf "\n" }' "$@"; }

# 8. Топ запросов по суммарному времени: литералы и числа заменяются на «?», запрос обрезается до 150 символов
#    Столбцы результата: суммарное время, мс | количество | текст
pg_glue "$PGLOG" | perl -ne '
    if (/duration: ([\d.]+) ms\s+(?:statement|execute [^:]*): (.*)/) {
        ($d, $q) = ($1, $2);
        $q =~ s/\x27[^\x27]*\x27/?/g;  $q =~ s/\b\d+\b/?/g;  $q =~ s/\s+/ /g;
        $q = substr($q, 0, 150);  $s{$q} += $d;  $c{$q}++;
    }
    END { printf "%.1f\t%d\t%s\n", $s{$_}, $c{$_}, $_ for keys %s }' | sort -rn | head -20

# 9. Соединения: отказы в аутентификации и исчерпание лимита подключений
grep -cE 'password authentication failed|no pg_hba.conf entry' "$PGLOG"
grep -c 'too many clients already' "$PGLOG"

# 10. Взаимоблокировки и ожидания блокировок (нужен log_lock_waits = on)
grep -c 'deadlock detected' "$PGLOG"
grep -E 'still waiting for|deadlock detected|canceling statement due to lock timeout' -A2 "$PGLOG" | less

# 11. Временные файлы: количество и суммарный объём (нужен log_temp_files)
grep -oP 'temporary file: path "[^"]+", size \K\d+' "$PGLOG" | awk '{ s += $1; n++ } END { printf "%d файлов, %.2f ГиБ\n", n, s / 1073741824 }'

# 12. Слишком частые контрольные точки и «тяжёлые» автоочистки
grep -c 'checkpoints are occurring too frequently' "$PGLOG"
grep -oP 'automatic vacuum of table "\K[^"]+' "$PGLOG" | sort | uniq -c | sort -rn | head

# 13. Аварии: нехватка места, падения процессов, восстановление
grep -nE 'No space left on device|could not (write|extend|fsync)|terminated by signal|server process .* was terminated|database system was (interrupted|not properly shut down)|PANIC' "$PGLOG"

# 14. Всё, что делал один серверный процесс (PID из квадратных скобок)
grep -F '[12345]' "$PGLOG" | less -S

# 15. Окно времени
awk '$1 == "2026-10-10" && $2 >= "09:00" && $2 < "09:30"' "$PGLOG" | less -S
```

Для полноценных отчётов по журналу есть pgBadger (практика сообщества): `sudo apt install pgbadger`, затем `pgbadger --prefix '%m [%p] %q%u@%d ' /var/log/postgresql/postgresql-17-main.log* -o /tmp/pg.html` (требует англоязычных сообщений).

### 10.4. Технологический журнал 1С

#### Что это и где лежит

Технологический журнал (ТЖ) включается файлом `logcfg.xml` в каталоге `conf` платформы; сервер перечитывает его примерно раз в 60 секунд, перезапуск не нужен; нет файла — журнал не ведётся. В Linux (ИТС, инструкция для платформы 8.3.25 и выше на Ubuntu 22.04): `/opt/1cv8/x86_64/<версия>/conf/logcfg.xml`, владелец — `usr1cv8:grp1cv8`. В практике сообщества встречаются также: общий для всех версий каталог `/opt/1cv8/conf/logcfg.xml`; каталог `~/.1cv8/1C/1cv8/conf/` пользователя, от имени которого работает процесс; для платформ до 8.3.18 (каталог установки `/opt/1C/v8.3/x86_64/`) — `/opt/1C/v8.3/x86_64/conf/logcfg.xml`. Все три варианта — **Уточнено 10.10.2026** (приложение 1 и глава 6 документации 8.3.27): конфигурационные файлы ищутся в каталоге `conf` версии, затем в `/opt/1cv8/conf`, затем в `~/.1cv8/1C/1cv8/conf`, затем в каталоге из `ConfLocation`; наличие и состав `logcfg.xml` платформа проверяет каждые 60 секунд. Ранее было не подтверждено первоисточником: раздел документации платформы «Описание и расположение служебных файлов» закрыт подпиской (нужные страницы перечислены в конце раздела «Источники»). Встречающийся в одной статье на Хабре путь `/opt/1cv8/x86_64/current/conf/` ничем не подтверждён — не используйте его без проверки (`ls -d /opt/1cv8/x86_64/*/conf`).

- `location` — каталог журнала (выделенный каталог, доступный на запись пользователю `usr1cv8`); `history` — сколько часов хранить.
- Структура: `<location>/<процесс>_<PID>/ГГММДДЧЧ.log` — отдельный подкаталог на каждый процесс (`rphost_12345`, `rmngr_2345`, `ragent_1234`), новый файл каждый час (`26101009.log` — 10 октября 2026 г., 09 часов).
- С 8.3.25 в элементе `<log>` доступны атрибуты `placement="plain"` и `format="json"` (ИТС, пример: `<log location="/1c/logs" history="4" placement="plain" format="json">`). По описанию изменений 8.3.25 в блоге 1C-DN: «плоское» размещение складывает все файлы журнала в один корневой каталог без подкаталогов процессов, а метка времени события становится полной (`2023-01-11T10:09:42.647004-7224999,CONN,2,process=1cv8,OSThread=8992,ClientID=2,Txt=Outgoing connection closed`); добавлены ротация по времени (интервал кратен часу) и по размеру файла, сжатие устаревших файлов, запись событий в JSON и свойство важности события `level` (`TRACE`, `DEBUG`, `INFO`, `WARNING`, `ERROR`), которое записывается после имени события и доступно в фильтре `<event>`. Имена атрибутов ротации и сжатия, а также точное место `level` в строке — **Уточнено 11.10.2026** (приложение 3 документации 8.3.27, разд. 3.24.2 и 3.24.3.4): атрибут `compress` принимает `none` (по умолчанию) или `zip` — сжатие выполняется при ротации, к имени файла добавляется `.zip`; атрибут `format` — `text` (по умолчанию) или `json`; в текстовой строке уровень важности идёт сразу после уровня вложенности в виде `level=INFO` — пример из документации: `45:31.831006-1,SCALL,2,level=INFO,process=1cv8,OSThread=13476,…`. Ранее было не подтверждено (в блоге их нет, документация закрыта).

Пример `logcfg.xml` (составлен по примерам ИТС: исключения плюс все события длиннее 5 секунд):

```xml
<?xml version="1.0" encoding="UTF-8"?>
<config xmlns="http://v8.1c.ru/v8/tech-log">
  <log location="/var/log/1c/techlog" history="24">
    <event>
      <eq property="Name" value="EXCP"/>
    </event>
    <event>
      <ne property="Name" value=""/>
      <ge property="Durationus" value="5000000"/>
    </event>
    <property name="all"/>
```

#### Формат записи

```
10:58.515038-3,TLOCK,4,process=rphost,p:processName=test_lock3,t:clientID=41,t:connectID=16,…

10:58        минуты:секунды внутри часа
.515038      микросекунды
-3           длительность события, мкс
TLOCK        имя события
4            уровень вложенности события в стеке потока
process=…    свойства «имя=значение» через запятую
```

- Время — минуты и секунды **внутри часа** (час и дата — из имени файла), дробная часть — микросекунды; после дефиса — длительность события в микросекундах (платформа 8.3 и новее; `5000000` = 5 с).
- Значения с запятыми и переводами строк заключаются в одинарные или двойные кавычки (подтверждено приложением 3 документации 8.3.27, разд. 3.24.3.4: значение с запятой или переводом строки заключается в кавычки или апострофы — берётся тот символ, которого в тексте меньше, а сами кавычки или апострофы внутри значения удваиваются; сверено 11.10.2026; ранее: правила кавычек — по памяти, без первоисточника); такие события (с `Context=`, `Sql=`, `planSQLText=`, `Descr=`) занимают **несколько строк** файла. Признак начала нового события — строка, начинающаяся с `ЦЦ:ЦЦ.ЦЦЦЦЦЦ-`.
- При `placement="plain"` (8.3.25+) строка события начинается с полной метки `ГГГГ-ММ-ДДTЧЧ:ММ:СС.мкс-длительность,…` — шаблоны вида `^\d\d:\d\d\.\d+-` на такие файлы **не срабатывают**; признак начала события там — `^\d{4}-\d\d-\d\dT\d\d:\d\d:\d\d\.\d+-\d+,`. Функция `tj_glue` ниже понимает оба варианта.
- Третье поле (число после имени события) — уровень вложенности события в стеке потока (подтверждено приложением 3 документации 8.3.27, разд. 3.24.3.4 — «уровень события в стеке текущего потока», в JSON-формате это ключ `depth`; сверено 11.10.2026; ранее: по памяти: описание формата в документации закрыто; пример строки `…,TLOCK,4,process=…` есть в открытой статье ИТС). Не путайте его со свойством `level=INFO/ERROR/…` (8.3.25+).
- Каждый файл начинается с BOM (`EF BB BF`) — это учтено в методике ИТС. Файл, в который ещё не попало ни одного события, может состоять из одного BOM (3 байта) — такие файлы надо пропускать при склейке (⚠ по практике; `find . -name '*.log' -size -4c` покажет их).
- Переводы строк в файлах ТЖ на Linux — ⚠ не подтверждено. Методика ИТС (шаблон `.\n`, «съедающий» символ перед переводом строки) написана на журналах Windows (в ней используются Git Bash и каталог `C:\LOGS\FULL`), где строки заканчиваются на CRLF; вывод о CRLF на Linux из неё не следует. Проверьте на своих файлах: `file rphost_*/*.log | head -3` (ищите «with CRLF line terminators») или `grep -c $'\r' файл`. Все собственные однострочники статьи работают при любом варианте.
- Длительность события-«обёртки» включает длительность вложенных: `CALL` (серверный вызов) содержит в себе `SDBL`, `DBPOSTGRS`, `TLOCK`. Суммы по разным типам событий между собой не складывают.

События, с которыми работают чаще всего: `EXCP` (исключение), `CALL`/`SCALL` (серверный вызов), `DBPOSTGRS` (запрос к PostgreSQL; для MS SQL — `DBMSSQL`), `SDBL` (запрос к модели БД, в т. ч. границы транзакций), `TLOCK` (управляемая блокировка), `TTIMEOUT` (таймаут блокировки), `TDEADLOCK` (взаимоблокировка), `CONN`, `SESN`, `PROC`, `CLSTR`, `ADMIN`. Свойства: `process`, `p:processName` (информационная база), `t:clientID`, `t:computerName`, `t:connectID`, `SessionID`, `Usr`, `Context` (стек встроенного языка), `Sql`, `Rows`, `RowsAffected`, `Descr`, `Memory`, `MemoryPeak`, `InBytes`, `OutBytes`, `CpuTime`, `WaitConnections`, `Regions`, `Locks`, `Func`. Из этого списка открытой статьёй ИТС (примеры `logcfg.xml` и разбор блокировок) подтверждаются `process`, `p:processName`, `t:clientID`, `t:applicationName`, `t:computerName`, `t:connectID`, `SessionID`, `Usr`, `AppID`, `Context`, `Descr`, `Func`, `Regions`, `Locks`, `WaitConnections`, `DeadlockConnectionIntersections` и свойство фильтра `Durationus`; методикой разбора на bash — `Memory`, `Sql`, `Interface`, `OutBytes`, `ClientID`. Остальные имена (`Rows`, `RowsAffected`, `MemoryPeak`, `InBytes`, `CpuTime`) и состав свойств конкретных событий — полный официальный перечень событий и свойств теперь есть в конспектах приложения 3 документации 8.3.27 (`../its-docs/adm-pr03-sluzhebnye-fajly-p3.md` и следующие части; этот список с ними построчно не сверялся); ранее отмечалось: по памяти: полный перечень находится в закрытой главе документации; реальный набор смотрите в своём журнале (команда в шаге 3 после списка разборов).

#### Шаг 2. Склейка многострочных событий

Официальный однострочник (ИТС): накапливает строки события в `$event`; встретив начало следующего события (`^\d\d:\d\d\.\d+`), заменяет внутренние переводы строк на маркер `<line>` и печатает событие одной строкой; затем удаляется BOM.

```bash
cat rphost_*/*.log | \
perl -n -e 'if (/^\d\d:\d\d\.\d+/) {$event =~ s/\n/<line>/g; print $event."\n"; $event = "";} $event .= $_; END{print $event."\n"};' | \
perl -pe 's/\xef\xbb\xbf//g' | \
grep "DBMSSQL.*SessionID=2049" | \
sed 's/<line>/\n/g' | \
less
```

(Текст сверен со страницей ИТС 2026-10-10: в этом примере подстановка записана как `s/\n/<line>/g`, без точки, а блок `END` печатает `$event."\n"`.)

Нюансы официального варианта:

1. В статье ИТС встречаются три записи подстановки: `s/\n/<line>/g` (пример выше), `s/.\n/<line>/g` (во всех конвейерах «топ-5», приведённых ниже) и `s/\n/ /g`. Вариант с точкой вместе с переводом строки съедает один символ перед ним — он рассчитан на `\r` из CRLF (методика писалась на журналах Windows); на файлах с LF будет пропадать последний символ каждой строки события. Вариант без точки на файлах с CRLF оставляет `\r` перед каждым `<line>` и в конце события (мешает шаблонам с `$`).
2. BOM удаляется после склейки, поэтому первое событие каждого файла (его строка начинается с BOM, а не с цифр) приклеивается к последнему событию предыдущего файла.
3. Начало события распознаётся шаблоном `^\d\d:\d\d\.\d+` — для файлов с `placement="plain"` (полная метка времени) он не подходит.
4. Первая итерация печатает пустую строку (пустой `$event`) — на результаты `grep` это не влияет.

Вариант на awk из той же статьи (в оригинале обратные слэши в строке шаблона одинарные — `\:`, `\.`, `\-`; gawk при этом выдаёт предупреждение «escape sequence … treated as plain …», а точка начинает означать «любой символ»; ниже — исправленная запись с двойными слэшами): `awk -vORS= '{if(match($0, "^[0-9][0-9]\\:[0-9][0-9]\\.[0-9]+\\-")) print "\n"$0; else print $0;}'`; BOM в этом варианте ИТС заменяет пробелом уже после отбора: `… | grep 'DBMSSQL.*SessionID=2049' | sed -e "s/\xef\xbb\xbf/ /g" | head`.

Доработанная функция (адаптация): снимает BOM до проверки, пропускает файлы из одного BOM, понимает и CRLF, и LF, и классическую, и полную (`placement="plain"`) метку времени, принимает файлы аргументами или поток:

```bash
tj_glue() {
  perl -ne 's/\r?\n\z//;                                        # убрать LF или CRLF в конце строки
            if (s/^\xef\xbb\xbf//) { next if $_ eq "" }          # BOM в начале файла; файл из одного BOM пропустить
            if (/^(?:\d{4}-\d\d-\d\dT\d\d:)?\d\d:\d\d\.\d+-\d+,/) { print "\n" if $n++; print }   # начало события
            elsif ($n) { print "<line>", $_ }                    # строка-продолжение текущего события
            END { print "\n" if $n }' "$@"
}
# Проверка: число событий после склейки должно совпасть с подсчётом из шага 0
tj_glue rphost_*/*.log | wc -l
```

Как это работает: perl без ключей `-C` обрабатывает байты, поэтому `\xef\xbb\xbf` — это именно три байта BOM при любой локали; `$n` считает уже начатые события — перевод строки печатается перед каждым событием, кроме первого, а строки, встретившиеся до первого события (обрывок в начале потока), отбрасываются. Внутри функции нельзя использовать одинарные кавычки (вся программа perl заключена в них). Ограничение: если строка-продолжение внутри `Context`/`Sql` сама начинается с текста вида `12:34.567890-12,`, она будет принята за начало события — на практике не встречается.

Функция проверена только логически, на реальных журналах не запускалась (⚠) — первым делом выполните проверку совпадения счётчиков с шагом 0.

После склейки каждая строка — одно событие: `мм:сс.мкс-длительность,СОБЫТИЕ,уровень,…`, внутренние переводы строк заменены на `<line>` (вернуть для чтения глазами: `sed 's/<line>/\n/g'`).

#### Шаг 3. Типовые разборы (адаптация; используют `tj_glue`)

Разборы рассчитаны на классический формат строки (`мм:сс.мкс-длительность,СОБЫТИЕ,…`): длительность — второе поле при разделителе `[-,]`. Для журналов с `placement="plain"` (полная метка `ГГГГ-ММ-ДДTЧЧ:ММ:СС.мкс-…`, в дате есть дефисы) сначала отрежьте дату и час, приведя строку к классическому виду, и подставляйте этот шаг сразу после `tj_glue`:

```bash
tj_glue *.log | sed -E 's/^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}://' | …      # 2023-01-11T10:09:42.647004-7224999,CONN,… → 09:42.647004-7224999,CONN,…
```

Все разборы проверены только логически (⚠ на реальных журналах не запускались): перед тем как доверять «топу», сверьте одну-две строки результата с исходным файлом.

```bash

tj_glue rphost_*/*.log | awk -F'[-,]' '{ print $2 "\t" $0 }' | sort -rn | head -20 | cut -c1-400

# 2. Сводка по типам событий: событие | количество | суммарно, с | в среднем, с
tj_glue rphost_*/*.log \
  | awk -F'[-,]' '{ n[$3]++; s[$3] += $2 }
      END { for (e in n) printf "%-14s %9d %12.1f %10.3f\n", e, n[e], s[e]/1e6, s[e]/n[e]/1e6 }' \

# 3. События заданного типа дольше порога (здесь: запросы к PostgreSQL дольше 5 с), с возвратом переводов строк

# 4. ТОП КОНТЕКСТОВ: какие строки кода дают наибольшее суммарное время запросов к PostgreSQL

  | sort -rn | head -10
#    Для серверных вызовов замените DBPOSTGRS на CALL, для транзакций — на SDBL.
#    Формат %.0f вместо %d — чтобы суммы больше 2^31 мкс (≈ 36 минут) печатались верно в любой реализации awk.

# 5. ТОП ЗАПРОСОВ по суммарному времени: тексты обезличены (GUID, временные таблицы ttNNN, числа)
#    Столбцы: сумма, мкс | среднее, мкс | количество | запрос
tj_glue rphost_*/*.log \
  | perl -lne 'next unless /^\d+:\d+\.\d+-(\d+),DBPOSTGRS,.*?,Sql=(.*)$/; ($d, $q) = ($1, $2);
      $q =~ s/,(Prm|planSQLText|Rows|RowsAffected|Result|Context)=.*$//; $q =~ s/<line>/ /g; $q =~ s/\s+/ /g;
      $q =~ s/\w+-\w+-\w+-\w+-\w+/{GUID}/g; $q =~ s/\btt\d+\b/{TT}/g; $q =~ s/\b\d+\b/{N}/g;
      $s{$q} += $d; $c{$q}++;
      END { printf "%d %d %d %s\n", $s{$_}, $s{$_}/$c{$_}, $c{$_}, $_ for keys %s }' \
  | sort -rn | head -5 | cut -c1-600

# 6. Топ текстов исключений (по всем процессам кластера)
tj_glue */*.log | grep ',EXCP,' | grep -oP ',Descr=\K.{1,200}' \
  | sed -E 's/[0-9a-f]{8}(-[0-9a-f]{4}){3}-[0-9a-f]{12}/{GUID}/g; s/<line>/ /g; s/[0-9]+/N/g' \
  | sort | uniq -c | sort -rn | head -20

# 7. Таймауты и взаимоблокировки: в каких файлах (часах) их больше всего
grep -rcE ',(TTIMEOUT|TDEADLOCK),' rphost_*/ | awk -F: '$NF > 0' | sort -t: -k2,2nr | head

# 8. Распределение исключений по минутам: количество | ГГММДДЧЧ:ММ
awk '/,EXCP,/ { sub(/^\357\273\277/, ""); n = split(FILENAME, p, "/"); print substr(p[n], 1, 8) ":" substr($0, 1, 2) }' rphost_*/*.log \
  | sort | uniq -c

# 9. Кто и в какой базе: топ пользователей и информационных баз по числу событий
grep -rh ',EXCP,' rphost_*/ | grep -oP ',Usr=\K[^,]+' | sort | uniq -c | sort -rn | head
grep -rhE ',(TTIMEOUT|TDEADLOCK),' rphost_*/ | grep -oP 'p:processName=\K[^,]+' | sort | uniq -c | sort -rn

# 10. Всё, что происходило в одном сеансе за конкретный час
tj_glue rphost_*/26101009.log | grep -P ',SessionID=2049(,|$)' | sed 's/<line>/\n/g' | less -S

# 11. Суммарная память по серверным вызовам (awk-часть — ИТС)
cat rphost_*/*.log | grep ',CALL,' | awk -F'Memory=' '{sum+=$2;} END {print "Sum=" sum}'
```

Имена свойств после `Sql=` в событии `DBPOSTGRS` (`Rows`, `RowsAffected`, `Result`, `Prm`, `planSQLText`) зависят от версии платформы и настроек — **Уточнено 11.10.2026** (приложение 3 документации 8.3.27, таблица свойств событий): `Rows` — количество полученных записей базы данных, `RowsAffected` — количество изменённых записей, `planSQLText` — план запроса из свойства `Sql` (для событий `DBV8DBENG`, `DBMSSQL`, `DBPOSTGRS`, `DB2`, `DBORACLE`, `EDS`). Свойства `Result` и `Prm` по таблице не проверялись. Ранее было не подтверждено: глава документации о составе свойств событий закрыта подпиской, в открытой статье ИТС эти свойства не упоминаются. ```

(Первая команда вырезает значения в кавычках, чтобы запятые и знаки «=» внутри текста запроса не принимались за свойства.)

Свойство `Dur=` и строки вида `…,Rows=15000,RowsAffected=0,Dur=12543210`, встречающиеся в одной статье на Хабре, документацией и методикой ИТС не подтверждаются: длительность события стоит в начале строки, после дефиса (в фильтрах `logcfg.xml` — свойства `Duration` и `Durationus`).

Если `grep -P` на склеенных событиях с очень длинным текстом запроса завершается ошибкой `exceeded PCRE's backtracking limit` (или `JIT stack limit`), замените этот шаг на `grep -E`/`grep -F` (например, `grep -F ',DBPOSTGRS,'`, затем `grep -F ',Context='`) или на `perl -ne 'print if /…/'`.

#### Готовые конвейеры из методики ИТС (написаны для MS SQL — событие `DBMSSQL`; для PostgreSQL заменяйте на `DBPOSTGRS`)

Результат каждого: `суммарная длительность | средняя | количество | ключ группировки`.

```bash
# Топ-5 контекстов по суммарной длительности транзакций (SDBL, Commit/RollbackTransaction)
cat rphost*/*.log | \
perl -n -e 'if (/^\d\d:\d\d\.\d+/) {$event =~ s/.\n/<line>/g; print $event."\n"; $event = "";} $event .= $_; END{print $event};' | \
perl -pe 's/\xef\xbb\xbf//g' | \
grep -P "SDBL.*Func=(Commit|Rollback)Transaction.*Context" | \
perl -pe 's/^\d+:\d+.\d+-//g' | \
perl -pe 's/,SDBL,.*Context.*<line>[ \t]+/,Context=/g' | \
perl -pe 's/,SDBL,.*Context=/,Context=/g' | \
sed 's/<line>//g' | \
awk -F',Context=' '{sum[$2]+=$1; count[$2]+=1;} END {for(i in sum) {print sum[i] " " sum[i]/count[i] " " count[i] " " i}}' | \
sort -rnb | \
head -n 5

# Топ-5 запросов к СУБД (без контекста), тексты обезличены: GUID, числа в скобках, временные таблицы (однострочная запись)
cat rphost*/*.log | perl -n -e 'if (/^\d\d:\d\d\.\d+/) {$event =~ s/.\n/<line>/g; print $event."\n"; $event = "";} $event .= $_; END{print $event};' | perl -pe 's/\xef\xbb\xbf//g' | grep -P "DBMSSQL.*Sql" | grep -v 'Context' | perl -pe 's/<line>//' | perl -pe 's/^\d+:\d+.\d+-//g' | perl -pe 's/,DBMSSQL,.*Sql=/,Sql=/g' | perl -pe 's/\w+-\w+-\w+-\w+-\w+/{GUID}/g' | perl -pe 's/\(\d+\)/({NUM})/g' | perl -pe 's/tt\d+/{TempTable}/g' | awk -F',Sql=' '{sum[$2]+=$1; count[$2]+=1;} END {for(i in sum) {print sum[i] " " sum[i]/count[i] " " count[i] " " i}}' | sort -rnb | head -n 5

# Топ-5 серверных вызовов (CALL) по контексту
cat rphost*/*.log | perl -n -e 'if (/^\d\d:\d\d\.\d+/) {$event =~ s/.\n/<line>/g; print $event."\n"; $event = "";} $event .= $_; END{print $event};' | perl -pe 's/\xef\xbb\xbf//g' | grep -P ",CALL,.*,Context=" | perl -pe 's/<line>//' | perl -pe 's/^\d+:\d+.\d+-//g' | perl -pe 's/,CALL,.*Context/,Context/g' | perl -pe 's/,Interface=.*OutBytes=\d+//g' | awk -F',Context=' '{sum[$2]+=$1; count[$2]+=1;} END {for(i in sum) {printf "%d %d %d %s\n",sum[i],sum[i]/count[i], count[i],i}}' | sort -rnb | head -n 5

# Топ-5 ожиданий управляемых блокировок (TLOCK с WaitConnections) по областям блокировок
cat rphost*/*.log | perl -n -e 'if (/^\d\d:\d\d\.\d+/) {$event =~ s/.\n/<line>/g; print $event."\n"; $event = "";} $event .= $_; END{print $event};' | perl -pe 's/\xef\xbb\xbf//g' | grep -P ",TLOCK,.*WaitConnections=\d+,Context" | perl -pe 's/^\d+:\d+.\d+-//g' | grep -P 'WaitConnections=\d+' | perl -pe 's/,Locks=.*$//g' | perl -pe 's/,TLOCK,.*Regions=/,Regions=/g' | sed 's/<line>//g' | awk -F',Regions=' '{sum[$2]+=$1; count[$2]+=1;} END {for(i in sum) {printf "%d %d %d %s\n", sum[i], sum[i]/count[i],count[i],i}}' | sort -rnb | head -n 5

# Поиск по нескольким серверам и в zip-архивах журналов
for i in `seq 1 100`; do ssh server$i 'grep ,EXCP, /var/log/srv1cv8/logs/FULL/rphost*/*.log'; done
find * -name '*.zip' -print0 | xargs -0 -i -n 1 unzip -p {} '*.log' 2>/dev/null | grep ',EXCP,'
```

Тексты конвейеров ИТС получены автоматическим извлечением со страницы статьи (кириллица на странице была искажена кодировкой, команды в латинице читаются); 2026-10-10 они повторно сверены рецензентом с печатной версией статьи — приведённые выше конвейеры (SDBL/транзакции, Sql без контекста, CALL, TLOCK, поиск по серверам и zip-архивам) совпадают с ней, включая `s/.\n/<line>/g`, `END{print $event}`, `sort -rnb` и `xargs -0 -i -n 1` (сверка тоже шла через автоматическое извлечение текста страницы, поэтому гарантии посимвольной точности нет). При расхождениях всё равно ориентируйтесь на оригинал статьи. В той же статье есть ещё несколько вариантов, не вошедших в подборку:

```bash
# Топ-5 контекстов по суммарной длительности запросов к СУБД (то же, что для SDBL, но событие DBMSSQL; для PostgreSQL — DBPOSTGRS)
cat rphost*/*.log | \
perl -n -e 'if (/^\d\d:\d\d\.\d+/) {$event =~ s/.\n/<line>/g; print $event."\n"; $event = "";} $event .= $_; END{print $event};' | \
perl -pe 's/\xef\xbb\xbf//g' | \
grep -P "DBMSSQL.*Context" | \
perl -pe 's/^\d+:\d+.\d+-//g' | \
perl -pe 's/,DBMSSQL,.*Context.*<line>[ \t]+/,Context=/g' | \
perl -pe 's/,DBMSSQL,.*Context=/,Context=/g' | \
sed 's/<line>//g' | \
awk -F',Context=' '{sum[$2]+=$1; count[$2]+=1;} END {for(i in sum) {print sum[i] " " sum[i]/count[i] " " count[i] " " i}}' | \
sort -rnb | \
head -n 5

# Последние 1000 строк журналов на каждом из серверов, только исключения
for i in `seq 1 100`; do ssh server$i 'tail -n 1000 /var/log/srv1cv8/logs/FULL/rphost*/*.log' | grep ",EXCP,"; done

# Только нужные каталоги внутри zip-архивов
find //server/disk/2017-05-04/logs -name '*.zip' -print0 | xargs -0 -i -n 1 unzip -p {} '*/FULL/rphost*/*.log' '*/FULL/rmngr*/*.log' 2>/dev/null | grep ",EXCP," | head
```

Замечания к применению конвейеров ИТС на Linux-сервере: (1) методика написана для журналов Windows, разбираемых в Git Bash (каталог `C:\LOGS\FULL`), отсюда расчёт на CRLF; (2) в `perl -pe 's/^\d+:\d+.\d+-//g'` точка не экранирована (означает «любой символ») — на результат не влияет; (3) в конвейерах с `print sum[i]` и `%d` суммы микросекунд велики — см. предостережение о больших целых в 5.7; (4) `sort -rnb` сортирует по первому столбцу (сумме) по убыванию; (5) для PostgreSQL замените `DBMSSQL` на `DBPOSTGRS`, а шаблон временных таблиц `tt\d+` оставьте (имена временных таблиц 1С в PostgreSQL тоже имеют вид `ttN` — ⚠ по практике, сверьте со своим журналом).

#### ТЖ в формате JSON (платформа 8.3.25+)

При `<log … placement="plain" format="json">` (ИТС) события записываются как JSON-объекты, perl-склейка не нужна, разбор ведётся `jq`. Раскладка (один объект на строку или нет), состав и имена ключей — **Уточнено 11.10.2026** (приложение 3 документации 8.3.27, разд. 3.24.3.4): файл — список JSON-объектов; служебные поля называются `ts` (дата и время с точностью до микросекунды), `duration` (длительность в микросекундах), `name` (имя события), `depth` (уровень в стеке потока) и `level`; остальные свойства идут под своими именами, значения записаны строками; пример из документации — `{"ts":"2023-08-02T08:48:05.982000","duration":"46998","name":"SCALL","depth":"0","level":"INFO","process":"1cv8c","OSThread":"15968",…}`. Один объект на строку или нет — документация не уточняет. Ранее было не подтверждено: открытая инструкция ИТС и блог 1C-DN сообщают только сам факт записи в JSON, описание формата — в закрытой документации платформы. Посмотреть на своём сервере: `head -c 1000 файл.log` и `head -n 1 файл.log | jq 'keys'`. Общая схема разбора та же: `jq -r 'select(…) | [поле1, поле2] | @tsv' файлы | sort | uniq -c | sort -rn | head`.

Порядок знакомства с JSON-журналом, не зависящий от догадок об именах ключей (jq читает и поток объектов, и «один объект на строку»; BOM в начале файла, если он есть, на всякий случай снимаем — не все версии jq его пропускают; есть ли BOM в JSON-файлах ТЖ — ⚠ не подтверждено, первая команда это покажет):

```bash
f=$(ls -1 /1c/logs/*.log | head -1)                       # каталог — из атрибута location
head -c 3 "$f" | xxd -p                                   # efbbbf — в файле есть BOM
sed '1s/^\xEF\xBB\xBF//' "$f" | jq -c . | head -3         # первые три события, по одному в строке
sed '1s/^\xEF\xBB\xBF//' "$f" | jq -r 'keys_unsorted | join(",")' | sort | uniq -c | sort -rn | head   # какие наборы ключей встречаются
```

После этого подставляйте реальные имена ключей в `select(...)` и `[...] | @tsv`.

#### Производительность разбора

- Сужайте вход: один час (`rphost_*/26101009.log`), одно событие (`LC_ALL=C grep -F ',DBPOSTGRS,'` перед тяжёлыми стадиями — только если событие заведомо однострочное или уже склеено).
- Пробуйте конвейер на малом объёме (`head -n 100000`) и меряйте `time` — совет из методики ИТС.
- Тысячи файлов в шаблоне `rphost_*/*.log` могут дать `Argument list too long` — тогда `find . -path './rphost_*' -name '*.log' -print0 | xargs -0 cat | …`.
- Сортировка больших промежуточных результатов: `sort -S 2G --parallel=4 -T /var/tmp`.

| Сумма длительностей событий ТЖ больше длины интервала наблюдения | вложенные события учтены дважды (`CALL` включает `DBPOSTGRS`, `SDBL`, `TLOCK`), плюс параллельные сеансы | считать по одному типу событий за раз |
| `grep ERROR` по журналу PostgreSQL ничего не находит, хотя ошибки были | `lc_messages = ru_RU.UTF-8`: метка — `ОШИБКА` | искать русские метки либо задать `lc_messages = 'en_US.UTF-8'` и перечитать конфигурацию |
| В журнале PostgreSQL нет длительных запросов | `log_min_duration_statement = -1` (умолчание) | задать порог в мс и `SELECT pg_reload_conf();` |
| nano в Ubuntu 26.04: `Ctrl+F` открывает поиск вместо сдвига курсора | изменение привязок в nano 8.0 | стрелки для перемещения; `Ctrl+W` — поиск во всех версиях |
| vim: текст из буфера обмена вставился «лесенкой» | автоотступ применяется к каждой вставленной строке | перед вставкой `:set paste`, после — `:set nopaste` |
| vim: команды не работают при русской раскладке | клавиши дают кириллицу | `set langmap=…` из раздела 8.2 |
| Терминал «завис» в nano/vim | нажат `Ctrl+S` (остановка вывода, XOFF) | `Ctrl+Q` |
| `less` показывает кириллицу как `<D0><9F>` | локаль не UTF-8 (`LC_ALL=C`) | `LESSCHARSET=utf-8 less файл` |
| В Ubuntu 26.04 команда из coreutils ведёт себя не как в инструкции | это uutils, а не GNU | проверить `команда --version`; GNU-двойник `gnuкоманда` |
| Пример с `yq` из интернета даёт синтаксическую ошибку | есть две разные программы `yq` (Python-обёртка jq и Go-версия) | `yq --version`; подобрать синтаксис под свою |
| `sudo apt install yq` в Ubuntu 22.04 — `Unable to locate package yq`; `apt install yq-go` не находит пакет в 22.04/24.04/26.04 | Python-версия `yq` есть в apt только с 24.04; `yq-go` появляется лишь в 26.10 | `sudo snap install yq` (Go-версия) или `pipx install yq` (Python-версия); для разовой задачи — `python3 -c 'import yaml,sys,json; json.dump(yaml.safe_load(sys.stdin), sys.stdout)' < файл.yaml \| jq .` (нужен пакет `python3-yaml`) |
| Шаблоны начала события ТЖ (`^\d\d:\d\d\.\d+-`) и склейка ничего не находят | журнал настроен с `placement="plain"` (8.3.25+): строка начинается с полной метки `ГГГГ-ММ-ДДTЧЧ:ММ:СС.мкс-` и файлы лежат без подкаталогов процессов | шаблон `^\d{4}-\d\d-\d\dT\d\d:\d\d:\d\d\.\d+-\d+,`; функция `tj_glue` из 10.4 понимает оба формата |
| После склейки ТЖ часть событий начинается с `<line>` или первое событие файла «пропало» | BOM в начале каждого файла и файлы из одного BOM (3 байта) | снимать BOM до проверки начала события и пропускать пустые файлы — так делает `tj_glue` |
| В русифицированном журнале PostgreSQL шаблон `duration: … ms  statement:` ничего не находит | при `lc_messages = ru_RU.UTF-8` строка выглядит как `продолжительность: … мс, оператор: …` | искать `(duration\|продолжительность): `; лучше `lc_messages = 'en_US.UTF-8'` |
| `jq`: `parse error: Invalid numeric literal` | на входе не JSON (обычный текст лога, обрезанная строка) | проверить вход `head -c 300`; для текста — `jq -R` |

(В ячейках таблицы `\|` означает обычный символ конвейера `|`.)

## Быстрая шпаргалка

В таблице символ конвейера записан как `\|` из-за синтаксиса Markdown-таблиц — в командной строке набирайте просто `|`.

| Задача | Команда |
|---|---|
| Последние 100 строк и слежение (с ротацией) | `tail -n 100 -F файл` |
| Следить и фильтровать | `tail -F файл \| grep --line-buffered -E 'ERROR\|FATAL'` |
| Просмотр без переноса строк, с номерами | `less -SN файл` |
| Слежение в less | `less +F файл` (`Ctrl+C` — листать, `F` — снова следить) |
| Строки 100–120 файла | `sed -n '100,120p' файл` |
| Найти рекурсивно в *.log, с номерами строк | `grep -rn --include='*.log' 'шаблон' каталог/` |
| Только имена файлов с совпадением / без | `grep -rl 'шаблон' каталог/` / `grep -rL 'шаблон' каталог/` |
| Контекст: 2 строки до, 5 после | `grep -B2 -A5 'шаблон' файл` |
| Несколько шаблонов (ИЛИ); строки без шаблона | `grep -E 'a\|b\|c' файл`; `grep -v 'шаблон' файл` |
| Конфиг без комментариев и пустых строк | `grep -vE '^[[:space:]]*(#\|$)' файл` |
| Извлечь значение свойства | `grep -oP 'SessionID=\K\d+' файл` |
| Топ-10 самых частых значений | `… \| sort \| uniq -c \| sort -rn \| head` |
| Поиск в ротированных .gz | `zgrep -h 'шаблон' файл.log*` |
| Замена во всём файле с резервной копией | `sed -i.bak 's/старое/новое/g' файл` |
| Замена в пачке файлов, где есть шаблон | `grep -rlZ 'старое' каталог/ \| xargs -0 -r sed -i.bak 's/старое/новое/g'` |
| Удалить строки с шаблоном | `sed -i.bak '/шаблон/d' файл` |
| Вставить строку после строки-шаблона | `sed -i.bak '/шаблон/a новая строка' файл` |
| Изменить параметр `ключ = значение` | `sed -i.bak -E 's/^#?[[:space:]]*(ключ)[[:space:]]*=.*/\1 = значение/' файл` |
| Что изменилось после правки | `diff -u файл.bak файл` |
| Вывести поля (разделитель `;`) | `awk -F';' '{ print $1, $3 }' файл` или `cut -d';' -f1,3 файл` |
| Сумма столбца | `awk '{ s += $2 } END { print s }' файл` |
| Количество по ключу (топ) | `awk '{ c[$1]++ } END { for (k in c) print c[k], k }' файл \| sort -rn \| head` |
| Сумма по ключу (топ) | `awk '{ s[$1] += $2 } END { for (k in s) print s[k], k }' файл \| sort -rn \| head` |
| Убрать дубликаты, сохранив порядок | `awk '!seen[$0]++' файл` |
| Сортировка по 3-му числовому полю CSV | `sort -t';' -k3,3nr файл` |
| Каталоги по размеру; сортировка версий | `du -sh каталог/* \| sort -h`; `sort -V` |
| Выровнять столбцы | `column -t -s';' файл` |
| Общие строки двух файлов | `comm -12 <(sort a) <(sort b)` |
| Сравнить каталоги | `diff -rq каталог1 каталог2` |
| Записать в файл root из конвейера | `… \| sudo tee файл > /dev/null` |
| Действие над найденными файлами | `find … -print0 \| xargs -0 -r команда` |
| Кодировка файла | `file -i файл` |
| CP1251 → UTF-8 | `iconv -f CP1251 -t UTF-8 вход > выход` |
| CRLF → LF | `dos2unix файл` или `sed -i 's/\r$//' файл` |
| Есть ли BOM | `head -c3 файл \| xxd -p` (ответ `efbbbf`) |
| Снять BOM | `sed -i '1s/^\xEF\xBB\xBF//' файл` |
| Показать невидимые символы; первые байты в hex | `cat -A файл \| head`; `xxd -l 64 файл` |

| Править системный файл | `sudoedit /etc/файл` |
| Сменить редактор по умолчанию | `sudo update-alternatives --config editor` |
| nano: сохранить / выйти / поиск / замена | `Ctrl+O` / `Ctrl+X` / `Ctrl+W` / `Ctrl+\` |
| vim: сохранить и выйти / выйти без сохранения | `:wq` / `:q!` |

Закрытые страницы ИТС, которые нужны, чтобы снять оставшиеся пометки «⚠» по 1С (открываются по подписке; ориентир — документация платформы https://its.1c.ru/db/v8327doc или https://its.1c.ru/db/v854doc, «Руководство администратора»):

- Приложение «Описание и расположение служебных файлов» → `logcfg.xml`: где ищется файл в Linux (каталог версии, общий `/opt/1cv8/conf`, `~/.1cv8/1C/1cv8/conf`), роль `conf.cfg`/`ConfLocation`, период перечитывания, полный список атрибутов `<log>` (`placement`, `format`, ротация, сжатие), элементы `<event>`, `<property>`, `<dump>`, `<plansql>`.
- Глава «Технологический журнал»: формат записи (поля, кавычки, смысл третьего поля), состав свойств событий `DBPOSTGRS`, `SDBL`, `CALL`, `TLOCK`, `EXCP` (в том числе `Rows`, `RowsAffected`, `Result`, `Prm`, `planSQLText`), формат JSON-журнала (имена ключей, один объект на строку или нет), кодировка, BOM и переводы строк файлов в Linux.
- Статьи методической поддержки https://its.1c.ru/db/metod8dev/content/5927/hdoc и https://its.1c.ru/db/metod8dev/content/5809/hdoc в обычном (не печатном) виде — для посимвольной сверки конвейеров и примеров `logcfg.xml`: автоматическое извлечение отдаёт кириллицу искажённой.
