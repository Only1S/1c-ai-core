## Кратко — главные факты и команды

1. Аутентификация ОС: клиент узнаёт у ОС, кто вошёл (Windows — SSPI, Linux — GSS-API), и ищет пользователя ИБ, которому сопоставлен этот пользователь ОС; нашёл — окно входа не показывается [ИТС-адм разд. 6.2.10.3].
2. Имя пишут как `\имя_домена\имя_пользователя`, латиницей, до 128 символов; точное написание — из события `CONN` техжурнала, строка `Srvr: DstUserName2:` [ИТС-адм разд. 6.2.2, 6.2.10.3; ИТС-мет 5944, 2018].
3. Сервер 1С на Windows понимает Kerberos и NTLM (NTLM — и без контроллера домена), на Linux — только Kerberos и/или имя с паролем [ИТС-КС разд. 2.3]. NTLM у Microsoft устарел, NTLMv1 удалён в Windows 11 24H2 и Server 2025 [MS Learn].
4. Веб-сервер и кластер на разных компьютерах или несколько рабочих серверов — аутентификация Windows только по Kerberos [ИТС-КС разд. 3.1.6.1.1].
5. SPN службы 1С на Windows — свой класс (`srv1c`), не `http`/`host`/`termsrv`: `setspn -S srv1c/srv1c01.corp.example CORP\svc-1c`, проверка `setspn -L`; затем SPN — в свойство рабочего сервера «Имя службы (SPN) сервера 1С:Предприятия», без него ограниченное делегирование не работает [ИТС-КС разд. 3.1.6.1.1, 5.2.6.1; MS Learn].
6. Вход через IIS на другом компьютере требует делегирования Kerberos от веб-сервера к SPN службы 1С (полного или ограниченного) [ИТС-КС разд. 3.1.6.1.1; ИТС-мет 5944, 2018].
7. Учётная запись службы кластера: полные права на каталог данных кластера, «Вход в качестве службы», «Вход в качестве пакетного задания», «Пользователи журналов производительности», «Список содержимого папки» на каталог временных файлов [ИТС-КС разд. 1.3.2]; для Kerberos через IIS — доменная, из Domain Users [ИТС-мет 5944, 2018].
8. Смешанная среда пользователя (клиенты Windows, сервер на Ubuntu): на Linux — keytab `usr1cv8/<FQDN>@<ОБЛАСТЬ>` (`../1c/08…`, разд. 5); на Windows — домен, DNS, время; проверка `klist get usr1cv8/srv-1c-app.corp.example` [MS Learn; практика].
9. Компоненты: тонкий клиент для клиент-сервера — `THINCLIENT`, с файловыми базами — `THINCLIENTFILE`, толстый клиент и конфигуратор — `DESIGNERALLCLIENTS`, консоль кластера — `SERVERCLIENT` [ИТС-адм разд. 2.5.2.4, прил. 3.6.12].
10. «Для компьютера» (`%PROGRAMFILES%\1cv8`) или «для пользователя» (`%LOCALAPPDATA%\Programs\1cv8_x64`) — по `ALLUSERS` у `setup.exe`, `InstallForUsers` в `1cestart.cfg` и правам; «для пользователя» требует заранее поставленного Visual C++ Redistributable [ИТС-адм разд. 2.5.2.2].
11. `setup.exe /S` — без диалогов, параметры из `1cestart.cfg` режима; `USEHWLICENSES=0` — не искать ключ HASP [ИТС-адм разд. 2.5.2.1].
12. Групповые политики: MSI + `1049.mst` + `adminstallrestart.mst`; logon-сценарий — `adminstallrelogon.mst`; новая версия — новый пакет; после такой установки `adminstall.cfg` содержит `AdmInstall=Restart` или `AdmInstall=Logon` [ИТС-адм разд. 2.6.3.10, прил. 3.10].
13. Клиент и сервер совпадают до сборки; при расхождении клиент ищет дистрибутив: `InstalledLocation` → `DistributiveLocation` → URL от сервера (`PublishDistributiveLocation*` в `conf.cfg`, `pubdst*` в `default.vrd`) → интернет-сервисы [ИТС-адм разд. 4.3.6.4].
14. Для смешанной среды: `PublishDistributiveLocationWindows64=<URL zip>` в `conf.cfg` Linux-сервера — URL получает тонкий клиент при любом клиент-серверном подключении [ИТС-адм разд. 4.3.6.4, прил. 3.17.19].
15. Список баз — `%APPDATA%\1C\1CEStart\ibases.v8i` (UTF-8); `1cestart.cfg` — там же и в `%ALLUSERSPROFILE%\1C\1CEStart\` (UTF-16LE); общий `1cescmn.cfg` — только в каталоге дистрибутивов [ИТС-адм прил. 3.4–3.6, разд. 2.7].
16. Общие списки — `.v8i` по `CommonInfoBases=` (учитываются из всех файлов); запись для них — «Сохранить ссылку в файл» [ИТС-адм разд. 5.8, прил. 3.6.6].
17. По умолчанию запускается «Приоритет 32 (x86)»; 64-разрядный клиент — `DefaultVersion=8.3;x86_64_prt` или `AppArch` в описании базы [ИТС-адм разд. 4.3.6.3, прил. 3.6.8].
18. Ключи ярлыков: `/S "сервер/база"`, `/IBName`, `/IBConnectionString`, `/WA-`, `/AppAutoCheckVersion-`, `/AppAutoInstallLastVersion-`, `/ClearCache`, `/OLow` [ИТС-адм прил. 7.3].
19. Автоудаление версий включено по умолчанию (`AutoUninstall=1`, 90 дней — `AutoUninstallVersionsAfter`, исключения — `DontUninstallVersion`) [ИТС-адм прил. 3.6, разд. 12.2.4].
20. RDS: рабочее место программной лицензии — терминальная сессия; локальный HASP в сессиях Windows 7/2012+ не работает, многопользовательский ключ — через HASP License Manager; 32-разрядный клиент может держать сессию из-за `SplWOW64.exe` [ИТС-адм разд. 10.2.5.9, 10.3.4.9; ИТС-мет 4064, 2010].
21. COM-соединение `V83.COMConnector` (8.5 — `V85.COMConnector`): регистрирует установщик; версии совпадают полностью или различаются первыми двумя числами; разрядность COM-объекта = разрядность процесса; `0x80070005` у `regsvr32` — нет прав администратора [ИТС-адм разд. 1.5, 2.5.3].
22. Linux-кластер COM не выполняет; COM-соединение к нему делают с Windows-компьютера с той же сборкой платформы [ИТС-КС разд. 2.3; ИТС-адм разд. 4.3.6.4].

### 1.3. Где платформа ищет конфигурационные файлы (`logcfg.xml`, `nethasp.ini` и др.)

Порядок в Windows [ИТС-адм прил. 1.3.4]:

1. `<каталог версии>\bin\conf`;
2. `%LOCALAPPDATA%\1C\1cv8\conf` пользователя, от имени которого работает процесс;
3. каталог из параметра `ConfLocation` файла `bin\conf\conf.cfg` (по умолчанию — `conf` корневого каталога установки);
4. `%ALLUSERSPROFILE%\1C\1cv8\conf`.

Следствие: на одном компьютере можно дать клиенту и службе сервера разные `logcfg.xml` — клиенту через `%LOCALAPPDATA%` его пользователя, службе — через общий `conf` [ИТС-адм прил. 1.3.1]. На терминальном сервере так включают техжурнал одному пользователю, не трогая остальных [практика].

### 1.4. Чем это отличается от клиента на Linux

В Linux те же файлы лежат в `~/.1C/1cestart/` (`ibases.v8i`, `1cestart.cfg`) и `~/.1cv8/1C/1cv8/` (кеш) [ИТС-адм прил. 3.4, 3.6.1]. Общий `1cescmn.cfg` по разд. 4.3.1 и прил. 3.5 применяется только в Windows, хотя разд. 2.7 описывает для Linux путь в нём и игнорирование `InstallComponents` — в документации это расходится. Подробно — `../1c/09-klient-linux-i-otlichiya-ot-windows.md`, раздел 2.6.

## 2. Аутентификация операционной системы

### 2.1. Как платформа узнаёт пользователя

- При старте клиент запрашивает у ОС текущего пользователя: Windows — интерфейс SSPI, Linux — GSS-API. Затем ищется пользователь ИБ, которому сопоставлен этот пользователь ОС; нашёлся — вход без окна аутентификации [ИТС-адм разд. 6.2.10.3].
- Клиент для macOS аутентификацию ОС не поддерживает. Через веб-сервер Apache под Windows аутентификация ОС не поддерживается. Для тонкого клиента через веб-сервер и для веб-клиента в Windows адрес базы нужно внести в надёжные сайты браузера [ИТС-адм разд. 6.2.10.3, 9.1].
- Толстый клиент не поддерживает OpenID в любом варианте [ИТС-адм разд. 6.2.2].
- Автономный сервер (`ibsrv`) аутентификацию ОС не поддерживает [ИТС-адм разд. 7.2].

### 2.2. Порядок попыток при интерактивном входе

Для тонкого и толстого клиента (напрямую к серверу или через веб-сервер) и веб-клиента [ИТС-адм разд. 4.3.8.2.2]:

1. Токен сохранённой аутентификации (флажок «Запомнить»), если есть.
2. JWT, если передан. Не прошёл — дальше не пробуют.
3. Аутентификация ОС. Не удалась или указан `/WA-` — пробуют следующие способы.
4. Имя и пароль из командной строки (`/N`, `/P`); `/N` без верного `/P` — окно входа с подставленным именем.
5. Окно входа со способами, разрешёнными в `default.vrd` (элемент `<authentication>`).

На веб-сервере для тонкого клиента: `/WSA-` — всегда спрашивать имя и пароль; заданы `/WSN` и `/WSP` — вход от этого пользователя; `/WSN` не задан — сначала аутентификация ОС, при неудаче запрос [ИТС-адм разд. 4.3.8.2.2].

В свойствах базы в окне запуска «Вариант аутентификации»: «Выбирать автоматически» (сначала ОС, потом логин и пароль) или «Запрашивать имя и пароль»; в файле списка это параметр `WA=1` / `WA=0`, для веб-сервера — `WSA=1` / `WSA=0` [ИТС-адм разд. 5.2.3, прил. 3.4].

### 2.3. Kerberos или NTLM

| Ситуация | Что работает | Источник |
|---|---|---|
| Клиент Windows → сервер 1С на Windows, один компьютер кластера, без веб-сервера | Kerberos, NTLM (в том числе без контроллера домена) | [ИТС-КС разд. 2.3, 3.1.6.1.1] |
| Клиент → IIS на одном компьютере → кластер на другом | только Kerberos с делегированием | [ИТС-КС разд. 3.1.6.1.1; ИТС-мет 5944, 2018] |
| Кластер из нескольких рабочих серверов (Windows) | только Kerberos; SPN — на каждый рабочий сервер | [ИТС-КС разд. 3.1.6.1.1] |
| Клиент Windows → сервер 1С на Linux | только Kerberos (keytab на сервере) | [ИТС-КС разд. 2.3, 3.1.6.2.1] |
| Клиент вне домена (рабочая группа) → сервер на Linux | аутентификация ОС невозможна, только имя и пароль | [ИТС-КС разд. 2.3; практика] |

NTLM всех версий Microsoft больше не развивает и советует заменять вызовы NTLM на Negotiate (сначала Kerberos, NTLM только в крайнем случае); NTLMv1 удалён начиная с Windows 11 24H2 и Windows Server 2025 [MS Learn, «Deprecated features»]. Вывод: если сейчас вход работает «через NTLM», считайте это временным и доводите Kerberos (SPN, DNS, время) [практика].

### 2.4. Сопоставление пользователя домена и пользователя ИБ

Конфигуратор: «Администрирование → Пользователи → Добавить/Изменить», закладка «Основные»: флажок «Аутентификация операционной системы», поле «Пользователь» [ИТС-адм разд. 6.2.2]. В типовых конфигурациях на БСП то же делается в карточке пользователя в режиме «1С:Предприятие» [практика].

Правила [ИТС-адм разд. 6.2.2, 6.2.10.3]:

- формат `\\имя_домена\имя_пользователя`, только латинские буквы, до 128 символов; уникальность пользователя ИБ проверяется по совокупности имени, полного имени и пользователя ОС;
- если у пользователя сняты все флажки «Аутентификация…», вход ему закрыт; если ОС его опознала, а флажок «Аутентификация операционной системы» снят — вход тоже закрыт;
- в базе обязан остаться хотя бы один пользователь с административными правами и аутентификацией «1С:Предприятия» (паролем);
- если вход по паролю запрещён, флажок «Показывать в списке выбора» недоступен; для баз, опубликованных в интернет, и для администраторов его рекомендуют снимать [ИТС-адм разд. 6.2.2; ИТС-КС прил. 3.11].

Точное написание имени: включить в техжурнале событие `CONN`, войти пользователем и найти строку `Txt=Srvr: DstUserName2: …`; `d1.d2\user1(d1.d2\user1)` означает `\\d1.d2\user1` в свойствах пользователя ИБ [ИТС-адм разд. 6.2.10.3]. В методической статье (сервер на Windows) там стояло короткое имя домена — `DOMAIN701\testuser2` [ИТС-мет 5944, 2018]: вид доменной части (`CORP` или `corp.example`) не угадывайте. Техжурнал для проверки на сервере 1С под Windows — `C:\Program Files\1cv8\conf\logcfg.xml` [ИТС-мет 5944, 2018; ИТС-адм прил. 1.3.4]:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<config xmlns="http://v8.1c.ru/v8/tech-log">
 <log location="C:\CONN\" history="24">
  <event>
   <eq property="Name" value="CONN"/>
  </event>
  <event>
   <eq property="Name" value="EXCP"/>
  </event>
  <property name="all"/>
 </log>
</config>
```

`C:\CONN\` должен быть доступен службе 1С на запись; после диагностики `logcfg.xml` удалите [практика]. Поиск: `Get-ChildItem C:\CONN -Recurse -Filter *.log | Select-String 'DstUserName2' | Select-Object -Last 5`. На Linux-сервере — `logcfg.xml` в `/opt/1cv8/conf` (`../1c/08…`, разд. 5.6).

Массовое сопоставление из встроенного языка:

```bsl
// ⚠ имена свойства АутентификацияОС и метода НайтиПоИмени сверить с синтакс-помощником версии;
// свойство ПользовательОС названо в документации [ИТС-адм разд. 6.2.10.5]
ПользовательИБ = ПользователиИнформационнойБазы.НайтиПоИмени("Иванов");
ПользовательИБ.АутентификацияОС = Истина;
ПользовательИБ.ПользовательОС = "\\CORP\ivanov";
ПользовательИБ.Записать();
```

Объекты — `ПользователиИнформационнойБазы`, `ПользовательИнформационнойБазы` [ИТС-адм разд. 6.2.1]; заводить пользователей без административных прав можно через привилегированный серверный модуль [ИТС-мет 3112, 2010; ⚠ пример для 8.2].

### 2.5. Администраторы кластера с аутентификацией ОС

В консоли кластера (оснастка MMC на Windows) у администратора центрального сервера и администратора кластера есть флажки «Аутентификация операционной системы» с полем «Пользователь» (`\\domainname\username`), «Аутентификация открытым ключом» и пароль с флажком «Аутентификация паролем только с локального компьютера» [ИТС-КС разд. 5.2.4.1, 5.2.8.1]. Рекомендация 1С: хотя бы один администратор с паролем, пароль — только с локального компьютера, остальным — открытый ключ или аутентификация ОС [ИТС-КС прил. 3.2, 3.3]. О `rac`/`ras` и аутентификации ОС — `../1c/08…`, раздел 8 (там сказано, что через `ras`/`rac` аутентифицировать администратора средствами ОС нельзя).

### 2.6. Аутентификация ОС через веб-сервер

Подробности IIS — в `03-veb-publikaciya-iis.md`. Здесь — то, что относится к рабочему месту:

- тонкий клиент через веб-сервер: `/WSA+` (по умолчанию) — сначала аутентификация ОС; `/WSN`, `/WSP` — явные учётные данные веб-сервера [ИТС-адм прил. 7.3.2];
- Internet Explorer/Edge в режиме IE: адрес базы — в доверенную зону [ИТС-адм разд. 9.1]; для Edge и Chrome — зона «Местная интрасеть» или политика `AuthServerAllowlist` [практика];
- Firefox: `network.negotiate-auth.trusted-uris` (Kerberos), при необходимости `network.negotiate-auth.delegation-uris`; для NTLM — `network.automatic-ntlm-auth.trusted-uris`; без записи в списке пользователь получит 401 [ИТС-адм разд. 9.2.2];
- через Apache на Windows аутентификация ОС не поддерживается [ИТС-адм разд. 6.2.10.3]; Apache на Linux — `mod_auth_kerb`, ключ `HTTP/Server.domain@DOMAIN`, учётная запись «доверена для делегирования» [ИТС-адм разд. 2.8.1.2; `../1c/08…`, разд. 5.7];
- из встроенного языка (`HTTPСоединение`, `WSОпределения`) параметр `ИспользоватьАутентификациюОС = Истина`: заданы `ИмяПользователя` и `Пароль` — они используются для NTLM/Kerberos (имя в виде `DOMAIN\user` или `user@domain`); не заданы — берутся учётные данные пользователя текущего сеанса [ИТС-адм разд. 4.3.8.2.3].

Альтернатива SSO без Kerberos — OpenID Connect с внешним провайдером (AD FS, Keycloak и т. п.) для тонкого клиента через веб-сервер, веб- и мобильного клиента [ИТС-адм разд. 6.2.10.5]; разбор ошибок — `../its-metod/kerberos-openid-autentifikaciya.md`. С 8.3.26 «Разрешить сохранение аутентификации» и «Сохранять аутентификацию по умолчанию» выключены по умолчанию [ИТС-мет 6029, 2026].

## 3. Сервер 1С на Windows в домене: учётная запись службы, SPN, делегирование

Установка самого сервера и регистрация службы — `01-ustanovka-servera-i-sluzhba-windows.md`. Здесь — только то, что нужно для аутентификации ОС.

### 3.1. Учётная запись службы

- При установке сервера службой выбирается пользователь и пароль; «для пользователя» сервер службой не ставится [ИТС-адм разд. 2.5.2.6]. По умолчанию это локальный `USR1CV8` [ИТС-КС разд. 1.3.2].
- Права учётной записи в Windows: полные права на каталог данных кластера; «Список содержимого папки» на каталог временных файлов; «Вход в качестве службы»; «Вход в качестве пакетного задания»; членство в «Пользователи журналов производительности» [ИТС-КС разд. 1.3.2]. Если рабочие процессы запускаются от другого пользователя (`swpuser.ini`), тому каталог данных кластера лучше закрыть [ИТС-КС разд. 1.3.2, прил. 3.4].
- Для Kerberos через IIS на другом компьютере процессы сервера 1С должны работать от доменной учётной записи из группы Domain Users [ИТС-мет 5944, 2018]. SPN привязывается именно к доменной учётной записи службы [ИТС-КС разд. 3.1.6.1.1]. Если служба работает от Local System, можно опереться на уже существующий SPN `HOST/имя_сервера`, но 1С это не рекомендует [ИТС-КС разд. 3.1.6.1.1].
- Групповые управляемые учётные записи служб (gMSA) в документации 1С не упоминаются ⚠ — применять только после проверки на стенде.
- При смене пользователя службы следите за путём к каталогу данных (`/d`): не найдя реестра кластера, агент создаст новый пустой кластер [ИТС-КС разд. 2.2.13].

Смена учётной записи на доменную (PowerShell от имени администратора; **перед этим — копия `srvinfo`**):

```powershell
# имя службы: "1C:Enterprise 8.3 Server Agent (x86-64)" или "Server Agent <порт> <версия>" [ИТС-КС разд. 4.2.3.2; ИТС-адм прил. 4.12.2]
Get-Service | Where-Object DisplayName -like '*1C*' | Format-Table Name, DisplayName, Status
$svc = '<имя службы из вывода>'
Stop-Service -Name $svc
Copy-Item 'C:\Program Files\1cv8\srvinfo' "D:\backup\srvinfo-$(Get-Date -Format yyyyMMdd)" -Recurse
icacls "C:\Program Files\1cv8\srvinfo" /grant "CORP\svc-1c:(OI)(CI)F"          # [практика]
Add-LocalGroupMember -SID 'S-1-5-32-559' -Member 'CORP\svc-1c'                  # «Пользователи журналов производительности» [практика]
sc.exe config "$svc" obj= "CORP\svc-1c" password= "<пароль>"                    # [MS Learn, sc.exe config]
Start-Service -Name $svc
Get-CimInstance Win32_Service -Filter "Name='$svc'" | Select-Object Name, StartName, State
```

⚠ `sc.exe config` не выдаёт право «Вход в качестве службы» (оснастка «Службы» выдаёт) — проверьте его и «Вход в качестве пакетного задания» в `secpol.msc` или доменной GPO [практика]. Доступ к MS SQL после смены учётной записи — `02-ms-sql-server-dlya-1c.md`.

### 3.2. SPN для сервера 1С на Windows

Что такое SPN: уникальный идентификатор экземпляра службы; по нему клиент запрашивает у KDC билет к службе, не зная имени её учётной записи [ИТС-КС разд. 3.1.6.1.1]. Для 1С SPN рекомендуется для корректной работы Kerberos и **обязателен для ограниченного делегирования** [ИТС-КС разд. 3.1.6.1.1, 5.2.6.1].

Правила [ИТС-КС разд. 3.1.6.1.1; MS Learn, `setspn`]:

- формат `<класс службы>/<имя хоста>`; общеупотребительные классы (`http`, `host`, `termsrv` и т. п.) для 1С не использовать, взять своё имя — `srv1c` или `svc1c`;
- SPN задаётся **для каждого рабочего сервера** кластера;
- регистрировать `setspn -S` (проверяет дубликаты), а не `-A`; `setspn` запускается в командной строке с повышенными правами на машине с ролью AD DS (или с установленными RSAT — [практика]); изменять SPN чужих объектов может администратор домена или тот, кому делегировано право «Validated write to service principal name»;
- в Windows SPN нечувствительны к регистру, в Unix-системах — чувствительны.

Команды (от имени администратора домена):

```cmd
:: зарегистрировать SPN службы 1С на рабочем сервере srv1c01 [ИТС-КС разд. 3.1.6.1.1]
setspn -S srv1c/srv1c01.corp.example CORP\svc-1c

:: ⚠ [практика] второй SPN по короткому имени — если клиенты обращаются к серверу без домена
setspn -S srv1c/srv1c01 CORP\svc-1c

:: список SPN учётной записи; поиск владельца SPN; поиск дубликатов в домене [MS Learn]
setspn -L CORP\svc-1c
setspn -Q srv1c/srv1c01.corp.example
setspn -X
```

Затем SPN вносится в свойство рабочего сервера «Имя службы (SPN) сервера 1С:Предприятия»: консоль кластера → «Рабочие серверы» → свойства сервера [ИТС-КС разд. 5.2.6.1]. В `rac` то же свойство — ключ `--service-principal-name` у `rac server update` (`../1c/03-administrirovanie-klastera-ras-rac.md`, таблица свойств сервера) ⚠ ключ не описан в документации 8.3.27 — сверить с `rac help server`.

Шифрование. Microsoft меняет тип шифрования Kerberos по умолчанию с RC4 на AES-SHA1 (обновление Windows Server апреля 2026 года) [MS Learn, FSLogix — предупреждение о Kerberos hardening]. Для учётной записи службы включите AES (`../1c/08…`, раздел 5.9):

```powershell
# модуль ActiveDirectory (RSAT) [практика; параметр командлета — по справке Microsoft]
Set-ADUser svc-1c -KerberosEncryptionType AES128,AES256
Get-ADUser svc-1c -Properties servicePrincipalName,msDS-SupportedEncryptionTypes |
  Select-Object Name, servicePrincipalName, msDS-SupportedEncryptionTypes
```

После смены типов шифрования у клиентов могут остаться старые билеты — `klist purge` или повторный вход в систему [MS Learn, `klist`].

### 3.3. Делегирование: когда и какое

Делегирование нужно, когда промежуточная служба (IIS с модулем 1С) представляется кластеру от имени пользователя; Kerberos это умеет, NTLM — нет [ИТС-КС разд. 3.1.6.1.1]. Тонкому клиенту, подключённому к кластеру напрямую по TCP, делегирование не нужно [практика].

| Вариант | Где | 1С | Microsoft |
|---|---|---|---|
| Полное | компьютер веб-сервера → «Делегирование» → «Доверять компьютеру делегирование любых служб (только Kerberos)» | советует статья 2018 года [ИТС-мет 5944]; документация допускает [ИТС-КС разд. 3.1.6.1.1] | ограниченное безопаснее [MS Learn, KCD] |
| Ограниченное (KCD) | компьютер веб-сервера или учётная запись веб-сервера → только указанным службам → `srv1c/…` | требует свойства «Имя службы (SPN)» у рабочего сервера [ИТС-КС разд. 3.1.6.1.1, 5.2.6.1] | настраивает администратор домена, в пределах одного домена [MS Learn] |
| На основе ресурсов (RBCD) | `PrincipalsAllowedToDelegateToAccount` у учётной записи службы 1С | ⚠ не описано | разрешает владелец ресурса, в том числе для другого домена [MS Learn] |

Команды (модуль ActiveDirectory, администратор домена; **сначала сохраните текущее состояние**):

```powershell
Get-ADComputer web01 -Properties TrustedForDelegation,msDS-AllowedToDelegateTo |
  Select-Object Name, TrustedForDelegation, msDS-AllowedToDelegateTo
# полное — как в [ИТС-мет 5944] [практика: эквивалент флажка в dsa.msc]
Set-ADComputer web01 -TrustedForDelegation $true
# ограниченное, «только Kerberos» [практика ⚠ проверить на стенде]
Set-ADComputer web01 -Add @{'msDS-AllowedToDelegateTo'=@('srv1c/srv1c01.corp.example','srv1c/srv1c01')}
# RBCD [MS Learn; ⚠ с 1С не описан]
Set-ADUser svc-1c -PrincipalsAllowedToDelegateToAccount (Get-ADComputer web01)
```

Если пул приложений IIS работает от доменной учётной записи, делегирование настраивают у неё [ИТС-КС разд. 3.1.6.1.1]; IIS — в `03-veb-publikaciya-iis.md`. Остальные шаги методики: в публикации IIS отключить анонимную и включить Windows-аутентификацию с Negotiate первым, `iisreset`, в браузере клиента разрешить встроенную проверку подлинности Windows, **перезагрузить клиентский компьютер** (серверы — не нужно); в тонком клиенте схема работает с 8.3.10.2620 [ИТС-мет 5944, 2018].

Признак проблемы в техжурнале рабочего процесса: `SrcUserName1` — учётная запись компьютера сервера 1С (`winserver1c$@…`, то есть служба не под доменным пользователем), `DstUserName2: NT AUTHORITY\ANONYMOUS LOGON`, затем `EXCP` «Идентификация пользователя не выполнена» [ИТС-мет 5944, 2018].

### 3.4. Проверки на сервере и клиенте Windows

```powershell
# На клиенте (обычный пользователь домена)
whoami /upn                                           # [практика]
klist                                                 # билеты текущего сеанса [MS Learn]
klist get srv1c/srv1c01.corp.example                  # запросить билет к службе 1С по SPN [MS Learn]
klist purge                                           # сбросить билеты (потом нужен повторный вход) [MS Learn]

# На контроллере домена или с RSAT
setspn -Q srv1c/srv1c01.corp.example                  # кому принадлежит SPN
setspn -X                                             # дубликаты SPN
```

`klist get` без ошибки и строка `Server: srv1c/srv1c01.corp.example @ CORP.EXAMPLE` в `klist` после запуска 1С означают, что клиент получил билет Kerberos к службе 1С [MS Learn; практика]. Ошибка «принципал не найден» при `klist get` — SPN нет или он у другой учётной записи [практика].

## 4. Смешанная среда: клиенты Windows и сервер 1С на Ubuntu

Это вариант пользователя: рабочие места Windows в домене, кластер 1С на `srv-1c-app` (Ubuntu), СУБД — «PostgreSQL для 1С» на `srv-1c-db`. На СУБД аутентификация ОС пользователей 1С не влияет: кластер ходит в PostgreSQL от своей учётной записи СУБД [ИТС-КС прил. 3.7].

### 4.1. Как устроено

- Сервер на Linux поддерживает только Kerberos и/или имя с паролем [ИТС-КС разд. 2.3]. NTLM-«подстраховки», к которой привыкли на Windows-сервере, нет: если Kerberos не сработал, пользователь увидит окно входа [ИТС-адм разд. 4.3.8.2.2; практика].
- В AD создаётся учётная запись (в документации — `usr1cv8`), для неё утилитой `ktpass` делается keytab с принципалом `usr1cv8/<FQDN сервера>@<ОБЛАСТЬ>`; DNS-записи Linux-сервера заводятся вручную [ИТС-КС разд. 3.1.6.2.1]. Все шаги на Linux — `../1c/08-konfiguracionnye-fajly-kerberos-bezopasnost.md`, разделы 5.1–5.9; конспект методики — `../its-metod/kerberos-openid-autentifikaciya.md`, раздел 1.
- На стороне Windows-клиента дополнительной настройки 1С нет: компьютер в домене, пользователь вошёл доменной учётной записью, клиент через SSPI сам получает билет [ИТС-адм разд. 6.2.10.3; практика].
- `ktpass` записывает SPN в учётную запись: проверять его можно теми же `setspn -L`/`-Q` [MS Learn; `../1c/08…`, разд. 5.3].

### 4.2. Чек-лист для `srv-1c-app`

| № | Что проверить | Где | Команда или действие | Источник |
|---|---|---|---|---|
| 1 | A- и PTR-записи сервера в DNS домена | клиент Windows | `Resolve-DnsName srv-1c-app.corp.example`; `Resolve-DnsName <IP сервера> -Type PTR` | [ИТС-КС разд. 3.1.6.2.1; практика] |
| 2 | Порты кластера доступны | клиент | `Test-NetConnection srv-1c-app.corp.example -Port 1541` (и 1540, один из 1560–1591) | [ИТС-КС прил. 3.8; практика] |
| 3 | Время клиента и сервера не расходится более чем на 5 минут | клиент / сервер | `w32tm /query /status`; на Ubuntu `timedatectl timesync-status` | [практика; `../1c/08…`, разд. 5.2] |
| 4 | SPN есть и он один | контроллер домена | `setspn -Q usr1cv8/srv-1c-app.corp.example`; `setspn -X` | [MS Learn] |
| 5 | Клиент получает билет к службе 1С | клиент | `klist get usr1cv8/srv-1c-app.corp.example` | [MS Learn; практика] |
| 6 | keytab читается службой, KVNO совпадает | сервер | `sudo -u usr1cv8 klist -e -k -t <keytab>`; `kvno …` | [ИТС-КС разд. 3.1.6.2.1; `../1c/08…`, разд. 5.4] |
| 7 | В списке баз сервер указан полным именем, совпадающим с SPN | клиент | `Connect=Srvr="srv-1c-app.corp.example";Ref="…";` | [практика ⚠] |
| 8 | Пользователь ИБ сопоставлен | конфигуратор / БСП | `\\<домен>\<имя>` по `DstUserName2` | [ИТС-адм разд. 6.2.10.3] |
| 9 | Не стоит `WA=0` или `/WA-` | `ibases.v8i`, ярлык | `WA=1` | [ИТС-адм прил. 3.4, 7.3.2] |

⚠ Обращение к серверу по IP-адресу или по имени, которое не совпадает с SPN, — частая причина отказа Kerberos: клиент строит имя службы из адреса сервера [практика; в документации 1С механизм построения имени не описан].

### 4.3. Чего в смешанной среде нет

- MS SQL Server для информационной базы на Linux-кластере не поддерживается, COM-объекты в серверном коде не выполняются, `ИнтернетСоединение` недоступен [ИТС-КС разд. 2.3].
- Публикация через Apache под Windows с аутентификацией ОС не работает [ИТС-адм разд. 6.2.10.3]; при веб-публикации на Linux — `mod_auth_kerb` и делегирование учётной записи `HTTP/…` [ИТС-адм разд. 2.8.1.2].
- Консоль кластера (MMC) на Windows-компьютере администратора подключается к Linux-кластеру, если на компьютере зарегистрирована утилита администрирования **той же версии**: пункт меню «Регистрация утилиты администрирования серверов (A.B.C.D)» или `RegMSC.cmd` из каталога версии [ИТС-адм разд. 4.1.3, прил. 1.2.17].
- Базы сервисов (GlitchTip, Redmine, NetBox) в кластер «PostgreSQL для 1С» не кладутся — это отдельный PostgreSQL (правило пользователя, `../00-INDEX.md`).

## 5. Установка клиентов на рабочие места

### 5.1. Программы установки и компоненты

Программы установки для Windows [ИТС-адм разд. 2.5.1]:

- «1С:Предприятие 8» — любые компоненты, 32- и 64-разрядный вариант;
- «1С:Предприятие 8 Тонкий клиент» — только тонкий клиент и всё нужное для доступа к серверу, 32- и 64-разрядный вариант;
- «1С:Предприятие 8 (x86-64) Сервер» — только 64-разрядный сервер.

Запуск — `setup.exe` из каталога дистрибутива [ИТС-адм разд. 2.5.2.1]. Тонкий клиент также поставляется самораспаковывающимся архивом `1CEClientSetup.exe`; у оригинала в свойствах файла должна быть цифровая подпись «1С» или доверенного поставщика [ИТС-польз гл. 2.1].

Компоненты и их ключи в `InstallComponents` (они же свойства MSI — см. 5.4) [ИТС-адм разд. 2.5.2.4, прил. 3.6.12]:

| Компонент в мастере | Ключ | Что даёт |
|---|---|---|
| 1С:Предприятие | `DESIGNERALLCLIENTS` | толстый и тонкий клиент, конфигуратор, компоненты администрирования |
| 1С:Предприятие ‑ тонкий клиент | `THINCLIENT` | тонкий клиент только для клиент-серверного варианта и веб-сервера |
| 1С:Предприятие ‑ тонкий клиент, файловый вариант | `THINCLIENTFILE` | тонкий клиент с файловыми базами |
| Сервер 1С:Предприятия 8 | `SERVER` | сервер; из программы запуска ставится как приложение, не служба |
| Модули расширения веб-сервера | `WEBSERVEREXT` | публикация на IIS/Apache |
| Администрирование сервера 1С:Предприятия 8 | `SERVERCLIENT` | консоль кластера и прочие средства администрирования |
| Сервер хранилища конфигураций | `CONFREPOSSERVER` | `crserver` |
| Конвертор ИБ 1С:Предприятия 7.7 | `CONVERTER77` | конвертер баз 7.7 |
| Интерфейсы на разных языках | `LANGUAGES=RU,EN,…` | английский ставится всегда |
| Liberica JRE, Контроль целостности, Дополнительные функции администрирования | ⚠ ключ в `InstallComponents` не описан | JRE для реструктуризации v2 и `ring`; утилита `ci`; утилита `1cv8a` |

Типовые наборы [ИТС-адм разд. 2.6.3.2–2.6.3.12]: пользователь только клиент-серверных баз (вариант пользователя) — `THINCLIENT=1` (конфигуратора нет); с файловыми базами — `THINCLIENTFILE=1`; разработчик и администратор баз — `DESIGNERALLCLIENTS=1`; администратор кластера — плюс `SERVERCLIENT=1` и «Дополнительные функции администрирования».

Драйвер HASP нужен только для локального ключа, ставить до подключения ключа; для сетевого ключа не нужен [ИТС-адм разд. 2.6.3.2–2.6.3.5]. При его установке оставьте флажок «Отключить неиспользуемые 1С:Предприятием возможности аппаратных ключей защиты (рекомендуется)» — отключает веб-интерфейс драйвера [ИТС-адм разд. 2.5.2.8; ИТС-мет 5936, 2017]. Если клиентские лицензии выдаёт сервер 1С, поиск ключа на клиентах выключают (`USEHWLICENSES=0`, раздел 5.3) [ИТС-адм прил. 3.6.15].

Требования к рабочему месту Windows для 8.3.27 [ИТС-адм разд. 1.1.2, 1.4.3, 1.5]:

- ОС: Windows 7 SP1, 8.0, 8.1, 10, 11; Windows Server 2012, 2012 R2, 2016, 2019, 2022; только x86/x86-64 (ARM64 не поддерживается), со всеми актуальными обновлениями. В 8.5.1 список Windows не менялся (`../its-docs/otlichiya-8.5.1-ot-8.3.27.md`, разд. 1.3). Windows Server 2025 в списке нет ⚠.
- Тонкий клиент: от 4 ГБ ОЗУ, от 350 МБ на диске, экран от 1280×768.
- Пользователю клиента — право «Список содержимого папки» на каталог временных файлов; для программных лицензий должна работать служба WMI.
- Энергосберегающие режимы Sleep, Standby, Hibernate на клиентах клиент-серверного варианта отключить [ИТС-КС разд. 1.3.1].

Сроки поддержки Microsoft на 19.10.2026 [MS Learn, Lifecycle]: Windows 10 Home/Pro — поддержка закончилась 14.10.2025 (22H2 — последняя версия); Windows Server 2012 R2 — расширенная поддержка закончилась 10.10.2023, третий год ESU — до 13.10.2026; Windows Server 2016 — расширенная до 12.01.2027; 2019 — до 09.01.2029; 2022 — основная поддержка закончилась 13.10.2026, расширенная до 14.10.2031; 2025 — основная до 13.11.2029, расширенная до 14.11.2034 (даты Microsoft указаны по тихоокеанскому времени). Итог: 1С 8.3.27 формально поддерживает Windows 7/8/2012, но Microsoft их уже не обновляет — для новых рабочих мест берите Windows 11 и Windows Server 2022 [практика].

### 5.2. «Для компьютера» или «для пользователя»

Режим определяется значением параметра (`ALLUSERS` в командной строке `setup.exe` важнее `InstallForUsers` в `1cestart.cfg`; если нигде не задан — 0) и правами пользователя. Администратором считается член локальных администраторов или пользователь при включённой политике `AlwaysInstallElevated` [ИТС-адм разд. 2.5.2.2, прил. 3.6.13 InstallForUsers]:

| Значение | Администратор | Обычный пользователь |
|---|---|---|
| 0 — по правам (по умолчанию) | для компьютера | диалог (интерактивно) или «для пользователя» |
| 1 — «для компьютера» | для компьютера | диалог или «для компьютера» (нужен пароль администратора) |
| 2 — «для пользователя» с вопросом | для пользователя | диалог или «для пользователя» |
| 3 — «для пользователя» без вопросов | для пользователя | для пользователя |

Следствия [ИТС-адм разд. 2.5.2.2, 2.5.2.6, 2.5.3, 4.1.3]:

- «для пользователя» версия ставится в `%LOCALAPPDATA%\Programs\1cv8_x64\A.B.C.D`; для этого на компьютере уже должен стоять Visual C++ Redistributable из дистрибутива (`vc_redist.x64.exe` / `vc_redist.x86.exe`) — его установка всё равно требует прав администратора;
- «для пользователя» сервер нельзя поставить службой; COM-соединение и `V83.Application` регистрируются только для этого пользователя;
- выбранный режим запоминается в `1cestart.cfg`.

`AlwaysInstallElevated` Microsoft прямо не рекомендует: это равносильно выдаче полных административных прав, причём после включения машинной политики пользователь может включить и пользовательскую [MS Learn, `AlwaysInstallElevated`]. Для 1С не включайте её — ставьте централизованно (5.4–5.6) [практика].

### 5.3. setup.exe: интерактивно и без диалогов

- `setup.exe /S` — «бесшумная» установка: определяется режим, параметры берутся из `1cestart.cfg` этого режима; если файла нет — умолчания [ИТС-адм разд. 2.5.2.1].
- `setup.exe USEHWLICENSES=0` — записать `UseHwLicenses=0` в `1cestart.cfg` пользователя, выполняющего установку; то же можно задать в `setup.ini`, параметр `CmdLine` группы `Startup` [ИТС-адм разд. 2.5.2.1].
- Язык интерфейса по умолчанию записывается в `C:\Program Files\1cv8\conf\conf.cfg`; другой язык для запуска — ключ `/L<код>` [ИТС-адм разд. 2.5.2.5].
- Флажок «Установить дистрибутивы тонкого клиента…» доступен при выбранных модулях расширения веб-сервера и файле `win-mac-clients-distr_A.B.C.D.exe` или `all-clients-distr_A.B.C.D.exe` рядом с установкой; состояние — ключ `COPYTHINCLIENTDST` в `InstallComponents` [ИТС-адм разд. 2.5.2.9].

Пример: тонкий клиент без диалогов «для компьютера» (cmd от имени администратора; ⚠ сочетание `/S` с `ALLUSERS=1` и `USEHWLICENSES=0` выведено из разд. 2.5.2.1–2.5.2.2 — проверьте на стенде):

```cmd
:: состав компонентов для режима «для компьютера» берётся из 1cestart.cfg для всех пользователей (UTF-16LE)
powershell -NoProfile -Command "New-Item -ItemType Directory -Force $env:ProgramData\1C\1CEStart | Out-Null; Set-Content -Path $env:ProgramData\1C\1CEStart\1cestart.cfg -Encoding Unicode -Value 'InstallComponents=DESIGNERALLCLIENTS=0 THINCLIENT=1 THINCLIENTFILE=0 SERVER=0 WEBSERVEREXT=0 CONFREPOSSERVER=0 CONVERTER77=0 SERVERCLIENT=0 LANGUAGES=RU'"
\\fs01\1CDistr\8.3.27.xxxx\Win64thin\setup.exe /S ALLUSERS=1 USEHWLICENSES=0
```

⚠ Если на компьютере уже есть `%ProgramData%\1C\1CEStart\1cestart.cfg`, первая команда его перезапишет — сначала сохраните копию (раздел 7.4 показывает, как менять отдельные строки).

Проверка (PowerShell):

```powershell
Get-ChildItem "$env:ProgramFiles\1cv8" -Directory | Select-Object Name
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*',
                 'HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*' |
  Where-Object DisplayName -like '*Предприятие 8*' |
  Select-Object DisplayName, DisplayVersion, PSChildName      # PSChildName — код продукта MSI {GUID} [практика]
```

### 5.4. msiexec, файлы трансформации и свойства

Дистрибутив — пакет Windows Installer. В примере сценария ИТС установка идёт через `WindowsInstaller.Installer.InstallProduct(<msi>, <командная строка>)` с `TRANSFORMS=adminstallrelogon.mst;1049.mst`, состав задаётся свойствами `DESIGNERALLCLIENTS=1 THINCLIENT=1 … LANGUAGES=RU`, удаление — `REMOVE=ALL`; код продукта (`ProductCode`) берётся из `setup.ini` [ИТС-адм разд. 2.6.3.10.2, прил. 3.10].

Файлы трансформации [ИТС-адм разд. 2.6.3.10]: `1049.mst` — язык установки (имя — десятичный LCID Windows); `adminstallrestart.mst` — для групповых политик: при несовпадении версий клиента и сервера 1С предложит **перезагрузку**; `adminstallrelogon.mst` — для logon-сценария: предложит **завершить сеанс**. Свойство `TRANSFORMS` — список через `;`, применяется по порядку, имена и полные пути в одном списке не смешивать; трансформации нужны и при последующем обслуживании пакета [MS Learn, `TRANSFORMS property`]. Ключи `msiexec`: `/i`, `/x`, `/qn`, `/qb`, `/norestart`, `/L*V <файл>` [MS Learn, `msiexec`].

Шаблон тихой установки тонкого клиента (cmd от имени администратора; **⚠ имя MSI взять из своего дистрибутива**, в примере ИТС для 8.2 — `1CEnterprise 8.2.msi`):

```cmd
pushd \fs01\1CDistr\8.3.27.xxxx\Win64thin
dir *.msi *.mst
msiexec /i "<имя>.msi" /qn /norestart TRANSFORMS="adminstallrestart.mst;1049.mst" THINCLIENT=1 THINCLIENTFILE=0 DESIGNERALLCLIENTS=0 SERVER=0 WEBSERVEREXT=0 CONFREPOSSERVER=0 CONVERTER77=0 SERVERCLIENT=0 LANGUAGES=RU /L*V "%WINDIR%\Temp\1c-8.3.27-install.log"
echo %ERRORLEVEL%
popd
```

⚠ Ключи компонентов как свойства MSI в ИТС показаны только закомментированной строкой сценария 8.2 — проверьте выбор компонентов по журналу `/L*V`. Код возврата 0 — успех, 3010 — нужна перезагрузка [практика]. `pushd` нужен потому, что `cmd` не делает UNC-путь текущим каталогом через `cd` [практика].

Удаление (⚠ **не удаляйте версию, на которой работает служба сервера или публикация IIS**): `msiexec /x {<ProductCode>} /qn /norestart /L*V "%WINDIR%\Temp\1c-uninstall.log"`.

После установки административными средствами в `C:\Program Files\1cv8\conf` появляется `adminstall.cfg` (UTF-8) со строкой `AdmInstall=Restart` (групповые политики) или `AdmInstall=Logon` (logon-сценарий); когда нужной версии нет, а прав на установку нет, 1С предложит это действие — перезагрузку или повторный вход [ИТС-адм разд. 2.6.3.10.3, прил. 3.10].

### 5.5. Групповые политики (Software Installation)

1С [ИТС-адм разд. 2.6.3.10.1]: указать языковой файл трансформации (`1049.mst`) и `adminstallrestart.mst`; дистрибутив новой версии добавить в политику заранее; для каждой новой версии — **новая** установка в политике (версий может быть несколько).

Microsoft [MS Learn, «Use Group Policy to remotely install software»]: назначение компьютеру ставит программу при старте компьютера для всех пользователей, назначение пользователю — при входе, публикация — только пользователям через «Программы и компоненты»; путь к пакету — полный UNC, не через «Обзор»; есть «Redeploy» и «Remove» (удалить сразу или запретить новые установки).

Порядок:

1. Ресурс `\\fs01\1CDistr` с правом чтения для компьютеров домена, дистрибутив в `\\fs01\1CDistr\8.3.27.xxxx\Win64thin\` [MS Learn; практика — кому давать доступ].
2. Если будут установки «для пользователя» — заранее раздать Visual C++ Redistributable из дистрибутива [ИТС-адм разд. 2.5.2.2].
3. `gpmc.msc` → GPO на OU рабочих станций → «Конфигурация компьютера → Политики → Конфигурация программ → Установка программ → Создать → Пакет» → UNC-путь к MSI → «Особый» → вкладка «Модификации» → `1049.mst`, `adminstallrestart.mst` [ИТС — какие файлы; практика — где в интерфейсе; ⚠ трансформации задаются только при создании пакета].
4. Назначать компьютерам: 1С ставится «для компьютера», при нехватке версии предлагает перезагрузку (`AdmInstall=Restart`) [практика; согласуется с ИТС-адм разд. 2.6.3.10].
5. Проверка: `gpupdate /force`, перезагрузка, `gpresult /r`, журнал «Приложение» (источники `Application Management Group Policy`, `MsiInstaller`) [практика].
6. Старую версию из политики не убирать, пока сервер не переведён (раздел 6.6) [практика].

### 5.6. Logon-сценарий

1С [ИТС-адм разд. 2.6.3.10.2, прил. 3.10]: установку можно выполнять сценарием при входе в домен; если у пользователя нет прав на установку, сценарий запускают от имени пользователя, который может устанавливать; в сценарий передаются путь к дистрибутиву, `ProductCode` из `setup.ini` и трансформация `adminstallrelogon.mst`; процедура `installOrUninstall` в примере ставит новую и удаляет старую версию и создаёт ярлык на `1cestart.exe` в сетевом каталоге.

Пример ИТС написан на VBScript (`WScript.CreateObject("WindowsInstaller.Installer")`) и для платформы 8.2. VBScript Microsoft объявила устаревшим: сначала он станет компонентом по запросу, затем будет удалён [MS Learn, «Deprecated features», октябрь 2023]. Тот же смысл на PowerShell — как **сценарий запуска компьютера** GPO (выполняется от SYSTEM, права пользователя не нужны) [практика ⚠ проверить на стенде; при сценарии запуска логичнее `adminstallrestart.mst`, при сценарии входа — `adminstallrelogon.mst`]:

```powershell
# \\corp.example\NETLOGON\1c-install.ps1 — сценарий запуска компьютера (GPO → Конфигурация компьютера → Сценарии → Автозагрузка);
# сохранить в UTF-8 с BOM, иначе Windows PowerShell 5.1 исказит кириллицу в фильтре [практика]
$ver  = '8.3.27.xxxx'
$src  = "\\fs01\1CDistr\$ver\Win64thin"
$msi  = Get-ChildItem $src -Filter *.msi | Select-Object -First 1      # ⚠ один MSI в каталоге
$log  = "$env:WINDIR\Temp\1c-$ver-install.log"
$inst = Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*' -ErrorAction SilentlyContinue |
        Where-Object { $_.DisplayName -like '*Предприятие 8*' -and $_.DisplayVersion -eq $ver }   # ⚠ формат DisplayVersion проверить
if (-not $inst) {
  $a = "/i `"$($msi.FullName)`" /qn /norestart TRANSFORMS=`"adminstallrestart.mst;1049.mst`" THINCLIENT=1 THINCLIENTFILE=0 DESIGNERALLCLIENTS=0 SERVER=0 WEBSERVEREXT=0 CONFREPOSSERVER=0 CONVERTER77=0 SERVERCLIENT=0 LANGUAGES=RU /L*V `"$log`""
  Push-Location $src                                                   # трансформации ищутся рядом с пакетом
  $p = Start-Process msiexec.exe -ArgumentList $a -Wait -PassThru
  Pop-Location
  "$(Get-Date -Format s) exit=$($p.ExitCode)" | Out-File "$env:WINDIR\Temp\1c-install-status.txt" -Append
}
```

### 5.7. Сетевой каталог дистрибутивов и программа запуска

Рекомендованная 1С схема для автоматической установки новых версий [ИТС-адм разд. 2.7]:

```text
\\fs01\1CDistr\
  1cestart.exe          ← программа запуска из самой новой версии в сети
  ibcommon.v8i          ← общий список баз (имя условное)
  1cescmn.cfg           ← общий конфигурационный файл
  8.3.27.xxxx\
    Win32\  Win64\  macOS\  Lin32\  Lin64\
  8.3.27.yyyy\ …
```

Пример `1cescmn.cfg` (UTF-8 или UTF-16LE) [ИТС-адм разд. 2.7, прил. 3.5]:

```ini
CommonInfoBases=ibcommon.v8i
DistributiveLocation=\\fs01\1CDistr
InstallComponents=DESIGNERALLCLIENTS=0 THINCLIENT=1 WEBSERVEREXT=0 SERVER=0 CONFREPOSSERVER=0 SERVERCLIENT=0 CONVERTER77=0 LANGUAGES=RU
```

Как это работает [ИТС-адм разд. 2.7, 4.3.2.1, 4.3.2.2]:

- первичная установка — запуск `\\fs01\1CDistr\1cestart.exe` с сетевого ресурса; найденный рядом `1cescmn.cfg` записывается в локальный `1cestart.cfg` как `CommonCfgLocation=\\fs01\1cdistr\1cescmn.cfg`;
- при каждом запуске программа запуска находит максимальную установленную версию и максимальную версию в `DistributiveLocation`; если в каталоге новее — ставит её с компонентами из `InstallComponents` (если параметра нет — тонкий, толстый клиент и компоненты доступа к серверу);
- через программу запуска установка всегда идёт в каталог по умолчанию; из общего файла при установке используется только `InstallComponents`;
- `1cescmn.cfg` **не должен** лежать на компьютере пользователя; в нём нельзя задавать `CommonCfgLocation`;
- при установке может прийти предложение перезагрузить компьютер.

Новая версия — новый подкаталог с тем же устройством; остальное программа запуска сделает при запуске 1С пользователем [ИТС-адм разд. 2.7]. Обычному пользователю без прав администратора такая установка пройдёт «для пользователя» (раздел 5.2).

### 5.8. 1CEClientSetupMake: свой установщик тонкого клиента с настройками

Утилита `1CEClientSetupMake.exe` (платформа 8.3.14 и новее) собирает самораспаковывающийся `1CEClientSetup.exe` с дистрибутивом и файлом `1CEStart.cfg`, настройки из которого при установке **добавляются** к пользовательскому `1CEStart.cfg`; после установки запускается неинтерактивная программа запуска [ИТС-мет 4914, 2024]:

```cmd
1CEClientSetupMake.exe /d D:\pack\thin-8.3.27 /o D:\out
1CEClientSetupMake.exe /f D:\pack\thin-8.3.27.zip /o D:\out
```

- `/f` (`--input-file`) — готовый zip; `/d` (`--input-directory`) — каталог, который будет упакован; `/o` (`--output-directory`) — куда положить `1CEClientSetup.exe` (по умолчанию текущий каталог); `/h` — справка; разделитель ключей — `/` или `-` [ИТС-мет 4914, 2024].
- Готовый файл должен быть подписан двойной подписью (SHA1+SHA256) поставщика [ИТС-мет 4914, 2024]. Проверку подписи программы установки, полученной по HTTP или из такого архива, отключает `DisableInstallerVerification=1` в `1cestart.cfg` — только для Windows; по умолчанию проверка включена (0) [ИТС-адм прил. 3.6.9]. Отключать проверку не рекомендуется [практика].
- Где лежит сама утилита в комплекте поставки ⚠ — в статье не сказано.

### 5.9. Что регистрирует установщик

- `V83.COMConnector`, `V83.Application` и консоль кластера — «для компьютера» или «для пользователя» по режиму установки [ИТС-адм разд. 2.5.3; ИТС-КС разд. 3.1.4.4]; в 8.5 — `V85.*` (`../its-docs/otlichiya-8.5.1-ot-8.3.27.md`).
- Меню «Пуск»: «1С Предприятие» (`1cestart`), «1С Предприятие (A.B.C.D)» (`1cv8s`), тонкий и толстый клиент, конфигуратор, «Регистрация утилиты администрирования серверов (A.B.C.D)» (`radmin.dll` нужной версии), драйвер защиты; у 64-разрядной версии в названиях «x86-64» [ИТС-адм разд. 4.1.3].

## 6. Обновление клиентов

### 6.1. Что делает клиент, когда версия сервера сменилась

Клиент и сервер должны совпадать в точности; при несовпадении тонкий или толстый клиент ищет нужную версию [ИТС-адм разд. 4.3.6.4]:

1. в каталоге установки (`InstalledLocation` в `1cestart.cfg` и `1cescmn.cfg`);
2. в каталогах дистрибутивов (`DistributiveLocation` в `1cestart.cfg`/`1cescmn.cfg`, а также рядом с файлом из `CommonCfgLocation`);
3. по URL из серверного исключения о несовпадении версий (`PublishDistributiveLocation*` в `conf.cfg` сервера, атрибуты `pubdst*` в `default.vrd`) — **тонким клиентом при любом клиент-серверном подключении**;
4. через интернет-сервисы получения дистрибутива — только тонким клиентом и только при подключении по HTTP.

`AppAutoInstallLastVersion=0` выключает автоматическую установку более новых версий, но если на компьютере нет версии, которую требует сервер (или явно указанной для базы), параметр игнорируется и установка всё равно будет предпринята [ИТС-адм прил. 3.6.2]. Для файловой базы все одновременно работающие клиенты должны быть одной версии — той, что подключилась первой [ИТС-адм разд. 4.3.6.5].

Разрядность скачиваемого дистрибутива: по настройке разрядности базы или окна запуска; если не задана — по разрядности запущенного клиента [ИТС-адм разд. 11.2.1].

### 6.2. Способы, и какой подходит смешанной среде

| Способ | Суть | Кому | Источник |
|---|---|---|---|
| A. Сетевой каталог + `1cestart` | `DistributiveLocation=\fs01\1CDistr`, подкаталог на версию | локальная сеть; без прав администратора — «для пользователя» | [ИТС-адм разд. 2.7, 4.3.2.2] |
| B. `conf.cfg` сервера 1С | `PublishDistributiveLocationWindows64=<URL zip>` | **смешанная среда пользователя** (TCP к `srv-1c-app`) | [ИТС-адм разд. 4.3.6.4, 11.2.4, прил. 3.17.19] |
| C. Веб-публикация | «Публиковать дистрибутив тонкого клиента» / `pubdstwin32`, `pubdstwin64` в `default.vrd`; каталог `bin\distr` | клиенты через веб-сервер | [ИТС-адм разд. 11.2.2, 11.2.3] |
| D. Предзагрузка `clientupdate.cfg` | версия и дата обновления заранее, скачивание в фоне | много клиентов по HTTP | [ИТС-адм разд. 11.2.6, прил. 3.15] |
| E. GPO / msiexec | версия «для компьютера» ставится заранее | без прав администратора, RDS | [ИТС-адм разд. 2.6.3.10] |
| F. Интернет-сервисы | `InternetService`, `WebDistributiveLocation` | только лицензия КОРП | [ИТС-адм прил. 6.2.1, 3.6.14] |

ARM64 и E2K — только ручное обновление [ИТС-адм разд. 11.2.1].

### 6.3. Способ B: `conf.cfg` на сервере 1С (Linux)

1. Подготовить zip с тонким клиентом для Windows: файлы дистрибутива лежат в корне архива, без каталогов; цифровые подписи файлов должны проходить проверку на компьютере, где идёт установка [ИТС-адм прил. 3.21.2, атрибуты `pubdst*`].

```powershell
# [практика] на Windows-компьютере администратора: архив из содержимого каталога дистрибутива тонкого клиента
Compress-Archive -Path 'D:\distr\thin64-8.3.27.xxxx\*' -DestinationPath 'D:\pub\windows64tc-8.3.27.xxxx.zip' -Force
```

2. Разместить архив на HTTP(S)-ресурсе, доступном с любого клиента (внутренний веб-сервер); при HTTPS клиент проверяет сертификат по корневым сертификатам ОС [ИТС-адм прил. 3.21.2]. Для IIS может понадобиться MIME-тип для `.zip` [ИТС-адм прил. 3.21.2] — `03-veb-publikaciya-iis.md`.
3. На сервере 1С (Ubuntu, `root`) добавить строку в `conf.cfg` каталога `conf` версии (`/opt/1cv8/x86_64/<версия>/conf/conf.cfg`, см. `../1c/08…`, разд. 1–2) [ИТС-адм прил. 3.17.1, 3.17.19]:

```bash
V=8.3.27.xxxx
sudo cp /opt/1cv8/x86_64/$V/conf/conf.cfg /opt/1cv8/x86_64/$V/conf/conf.cfg.bak-$(date +%F)
echo 'PublishDistributiveLocationWindows64=https://distr.corp.example/1c/windows64tc-8.3.27.xxxx.zip' | sudo tee -a /opt/1cv8/x86_64/$V/conf/conf.cfg
grep -n PublishDistributiveLocation /opt/1cv8/x86_64/$V/conf/conf.cfg
```

4. Перезапуск не нужен: рабочий процесс кеширует значения при первом подключении клиента и обновляет кеш через 10 секунд после изменения файла [ИТС-адм прил. 3.17.19].
5. Параметры для других ОС: `PublishDistributiveLocationWindows32`, `…Linux32/64`, `…LinuxDeb32/64`, `…LinuxRpm32/64`, `…MacOS64` [ИТС-адм прил. 3.17.19].

При установке по такому URL используются параметры установки из `1cestart.cfg` клиента — как при обычной установке [ИТС-адм прил. 3.21.2]. Без прав администратора это будет установка «для пользователя» (раздел 5.2) [ИТС-адм разд. 2.5.2.2].

### 6.4. Способы C и D: через веб-сервер

- Каталог `bin\distr` версии: имена `windows32tc.zip`, `windows64tc.zip`, `linux32tc.zip`, `linux64tc.zip`, `macOS64tc.zip`; файлы, положенные администратором, при удалении версии не удаляются [ИТС-адм разд. 11.2.3]. Готовые дистрибутивы для этого каталога — пакеты `all-clients-distr-A.B.C.D.exe` / `win-mac-clients-distr-A.B.C.D.exe` с releases.1c.ru, нужны права администратора; ключ `/D=<каталог>` ставит в указанный каталог без поиска версий [ИТС-адм разд. 2.8.2.2].
- `clientupdate.cfg` (UTF-8, в Linux регистр имени важен: `ClientUpdate.cfg`) кладут в каталог конфигурационных файлов текущей версии кластера или в общий: `Version` (версия после обновления, обязательно), `UpdateDate` (формат `YYYYMMDDHHMMSS`), `PublishDistributiveLocationWindows64` и др. [ИТС-адм прил. 3.15, разд. 11.2.6]. Клиент проверяет обновления раз в 20 минут; без даты скачивает в течение 40 минут; с датой — ночью (21:00–7:00) в первые сутки, потом в рабочее время (9:00–18:00), занимая не более 25 % канала; скачанное лежит в `%LOCALAPPDATA%\1C\1cv8\distr\A.B.C.D` [ИТС-адм разд. 11.2.6]. Документация описывает механизм для подключений по HTTP; ⚠ работает ли он при прямом TCP-подключении — не сказано.

### 6.5. Автоматическое удаление старых версий

`AutoUninstall` (1 — удалять, по умолчанию; 0 — нет), `AutoUninstallVersionsAfter` (дней после установки, по умолчанию 90) — значение берётся по приоритету «общий → локальный → для всех»; `DontUninstallVersion` (строк может быть несколько) — из всех файлов [ИТС-адм прил. 3.6.3, 3.6.4, 3.6.11].

Версия удаляется, если устарела, не в исключениях, не используется и у пользователя хватает прав. «Используется» — указана в `Version`/`DefaultVersion` баз из `ibases.v8i`, в службе сервера со стандартным именем, в `default.vrd` публикаций IIS (`c:\inetpub\wwwroot`) или в `httpd.conf` Apache. В пределах третьей цифры остаётся хотя бы одна версия (с наибольшей четвёртой, полный дистрибутив предпочтительнее тонкого). Проверка — через 2 минуты после начала работы, затем каждые 20 минут, за раз одна версия; в Windows пользователь видит диалог «Запустить фоновое удаление / Предложить позже / Не предлагать удалять»; версии «для компьютера» требуют прав администратора [ИТС-адм разд. 12.2.4; ИТС-польз гл. 2.8].

⚠ Служба, созданная `register-agent.bat` с нестандартным именем (`Server Agent <порт> <версия>`), по тексту документации может не считаться «использованием» — на таких серверах задайте `DontUninstallVersion` или `AutoUninstall=0` [вывод из ИТС-адм разд. 12.2.4 и прил. 4.12.2].

### 6.6. Порядок обновления платформы в смешанной среде (рабочая последовательность)

[практика; опирается на ИТС-адм разд. 4.3.6.4, 2.6.3.10, прил. 3.6.2]

1. За 1–3 дня: выложить дистрибутив новой версии в `\\fs01\1CDistr\<новая>\` и zip для `PublishDistributiveLocationWindows64`; назначить пакет новой версии групповой политикой (или поставить на терминальные серверы вручную) — старую не удалять.
2. Проверить на 2–3 рабочих местах, что новая версия установилась рядом со старой (`Get-ChildItem "$env:ProgramFiles\1cv8" -Directory`).
3. В окно обслуживания: бэкап баз и каталога кластера, обновление сервера на `srv-1c-app` (`../1c/02…`, `../guides/02-runbooki-i-shpargalki.md`), строка `PublishDistributiveLocationWindows64` в `conf.cfg` **новой** версии.
4. Клиенты при входе найдут уже установленную версию и подключатся без установки; у кого её нет — получат её по URL из шага 3 или по `DistributiveLocation`.
5. Через неделю — убрать старую версию из GPO: «Remove» с немедленным удалением (автоудаление версий «для компьютера» у пользователя без прав администратора не сработает) [MS Learn; ИТС-адм разд. 12.2.4].

## 7. Списки информационных баз

### 7.1. Формат `ibases.v8i`

Файл UTF-8 из секций; имя секции в квадратных скобках — наименование базы [ИТС-адм прил. 3.4]. Основные параметры:

| Параметр | Смысл | Пример |
|---|---|---|
| `Connect` (обязательный) | строка соединения: `File=<путь>;`, `Srvr=<сервер>;Ref=<база>;`, `ws="http://…/";` | `Connect=Srvr="srv-1c-app.corp.example";Ref="buh";` |
| `ID` | GUID записи, уникален в файле, по нему именуется каталог кеша; вручную формировать не рекомендуется | `ID=cf9f0d4b-…` |
| `Folder`, `OrderInList`, `OrderInTree` | папка в дереве, порядок | `Folder=/Торговые базы` |
| `ClientConnectionSpeed` | `Normal` / `Low` (тонкий и веб-клиент); нет параметра — флажок в окне запуска | `ClientConnectionSpeed=Normal` |
| `WA` | 1 — сначала аутентификация ОС, 0 — всегда логин и пароль | `WA=1` |
| `WSA` | то же для веб-сервера | `WSA=1` |
| `App` | `Auto`, `ThinClient`, `ThickClient`, `WebClient` | `App=ThinClient` |
| `AppArch` | разрядность, значения как у `/AppArch` | `AppArch=x86_64` |
| `Version` / `DefaultVersion` | требуемая версия / реально использованная при последнем запуске (`DefaultVersion` пишет программа запуска при `/AppAutoCheckVersion` и дальше использует его) | `Version=8.3.27` |
| `AdditionalParameters` | доп. параметры запуска | `AdditionalParameters=/TechnicalSpecialistMode` |
| `StartupErrorHelpURL`, `StartupErrorHelpText` | ссылка «Нужна помощь?» и текст в окне ошибки подключения | телефон поддержки |

Ещё есть прокси для ws-соединения (`UseProxy`, `PSrv`, `PPort`, `PUser`, `PPasswd`), сертификаты HTTPS (`HttpsCA`, `HttpsCert`, `HttpsCAFile`, `HttpsCertFile`, `HttpsCertSelect`; значение `Windows` — системное хранилище), `WebCommonInfoBaseURL` и параметры мобильного клиента; `External` есть в шаблоне секции, но не описан ⚠ [ИТС-адм прил. 3.4].

В строке `Srvr` можно перечислить несколько адресов кластера через запятую без пробелов; порт главного менеджера по умолчанию 1541 (`Srvr="tcp://srv:1641"`) [ИТС-адм прил. 7.7.4].

Базу без записи в списке (запуск по `.v8i` или по командной строке) клиент не кеширует — многие операции идут медленнее; проблемную базу добавьте в список [ИТС-адм разд. 4.3.5].

### 7.2. Общие списки баз

- Список общих баз — файл `.v8i` того же формата, путь задаётся `CommonInfoBases` в `1cestart.cfg` или `1cescmn.cfg`; используются значения из **всех** конфигурационных файлов; относительное имя в `1cescmn.cfg` ищется рядом с программой запуска [ИТС-адм разд. 5.8, прил. 3.5, 3.6.6].
- Записи получают командой «Сохранить ссылку в файл» в окне запуска — с корректным `ID` [ИТС-адм разд. 5.8].
- Запуск самого `.v8i` (или `/RunShortcut <файл>`) показывает только базы этого файла [ИТС-адм разд. 5.8, прил. 7.3.10].
- При повторном получении описание базы обновляется, место в дереве пользователя сохраняется; в общих списках ставьте `ClientConnectionSpeed=Normal` [ИТС-адм разд. 5.8].
- Пути из `1cescmn.cfg` в окне «Настройка» не видны, из `1cestart.cfg` — видны [ИТС-адм разд. 5.7].
- Список через интернет-сервис (`WebCommonInfoBases`, `InternetService`) — только с лицензией КОРП: `CheckInfoBases()` анонимно, `GetInfoBases()` с аутентификацией, две публикации без веб-клиента [ИТС-адм прил. 6.1].

Пример общего списка для пользователя (`\\fs01\1c$\lists\ibcommon.v8i`, UTF-8):

```ini
[Бухгалтерия WE (рабочая)]
Connect=Srvr="srv-1c-app.corp.example";Ref="buh";
ID=<GUID из «Сохранить ссылку в файл»>
Folder=/Рабочие базы
OrderInList=1
OrderInTree=1
ClientConnectionSpeed=Normal
App=ThinClient
AppArch=x86_64
WA=1
```

`Version` для клиент-серверной базы можно не задавать: версию определяет ответ сервера [ИТС-адм прил. 7.3.3, разд. 4.3.6.4; практика].

### 7.3. Параметры `1cestart.cfg`

Три файла и их роли — раздел 1.2. Параметры [ИТС-адм прил. 3.6]:

| Параметр | Смысл | Откуда берётся значение |
|---|---|---|
| `AppAutoInstallLastVersion` | 1 (по умолчанию) — ставить новые версии автоматически, 0 — нет (кроме требуемой сервером) | первый найденный: локальный → для всех → общий |
| `AutoUninstall`, `AutoUninstallVersionsAfter`, `DontUninstallVersion` | автоудаление (6.5) | общий → локальный → для всех |
| `CommonCfgLocation` | путь к общему `1cescmn.cfg`; в самом общем не задавать | из всех файлов |
| `CommonInfoBases` | путь к общему списку баз | из всех файлов |
| `ConfigurationTemplatesLocation` | каталоги шаблонов | из всех файлов |
| `DefaultVersion` | соответствие «маска версии → версия[;разрядность]» | из всех файлов |
| `DisableInstallerVerification` | 1 — не проверять подпись программы установки (только Windows) | — |
| `DistributiveLocation` | где искать дистрибутивы новых версий | из всех + каталог общего файла |
| `InstallComponents` | в локальных — что установлено; в общем — что ставить | для всех → локальный → общий |
| `InstalledLocation` | каталог установки | общий → для всех → локальный |
| `InstallForUsers` | режим установки 0–3 (только Windows) | раздел 5.2 |
| `InternetService`, `WebCommonInfoBases`, `WebDistributiveLocation` | интернет-сервисы списка баз и дистрибутива | сначала `WebCommonInfoBases`/`WebDistributiveLocation`, потом `InternetService` |
| `UseHwLicenses` | 1 (по умолчанию) — искать ключ HASP, 0 — нет | локальный → для всех → общий |

`UseHwLicenses` платформа меняет сама: если ключ не найден, а поиск длился больше 3 секунд, пользователю предлагают отключить поиск; если отключён, а лицензия не получена — включить. Для внешнего соединения читается `1cestart.cfg` профиля пользователя, от которого оно запущено; у пользователя без профиля (например, LocalSystem) ключ ищется всегда [ИТС-адм прил. 3.6.15].

Примеры `DefaultVersion` [ИТС-адм прил. 3.6.8]: `DefaultVersion=8.3-8.3.24.100` (базы с версией 8.3 запускать версией 8.3.24.100); `DefaultVersion=8.3;x86_64_prt` (любая база 8.3 — с приоритетом 64-разрядного клиента). В 8.5.1 пример заменён на `DefaultVersion=8.3.27-8.3.27.1326` (`../its-docs/otlichiya-8.5.1-ot-8.3.27.md`).

### 7.4. Как раздать список и настройки на рабочие места

Посмотреть файлы текущего пользователя (PowerShell):

```powershell
$dir = Join-Path $env:APPDATA '1C\1CEStart'
Get-Content (Join-Path $dir 'ibases.v8i') -Encoding UTF8
Get-Content (Join-Path $dir '1cestart.cfg') -Encoding Unicode        # UTF-16LE [ИТС-адм прил. 3.6.1]
Get-Content (Join-Path $env:ProgramData '1C\1CEStart\1cestart.cfg') -Encoding Unicode -ErrorAction SilentlyContinue
```

Способы раздачи:

1. **Через сетевой каталог** (5.7): `CommonInfoBases=ibcommon.v8i` в `1cescmn.cfg` — список придёт всем, кто ставил 1С из `\\fs01\1CDistr` [ИТС-адм разд. 2.7].
2. **Строка `CommonInfoBases` в общем для компьютера `1cestart.cfg`** — сценарием запуска компьютера (от SYSTEM) или вручную от администратора. ⚠ Значения `CommonInfoBases` берутся из всех файлов [ИТС-адм прил. 3.6.6], но этот файл платформа меняет при установке — после переустановки проверьте, что строка на месте.

```powershell
# от имени администратора; меняет только нужные ключи, остальные строки сохраняет
$cfg = Join-Path $env:ProgramData '1C\1CEStart\1cestart.cfg'
New-Item -ItemType Directory -Force (Split-Path $cfg) | Out-Null
if (Test-Path $cfg) { Copy-Item $cfg "$cfg.bak-$(Get-Date -Format yyyyMMddHHmm)" }
$lines = @(); if (Test-Path $cfg) { $lines = @(Get-Content $cfg -Encoding Unicode) }
$want = [ordered]@{
  'CommonInfoBases' = '\\fs01\1c$\lists\ibcommon.v8i'
  'UseHwLicenses'   = '0'                      # лицензии на сервере, ключей на клиентах нет
  'DefaultVersion'  = '8.3;x86_64_prt'         # приоритет 64-разрядного клиента
}
foreach ($k in $want.Keys) { $lines = @($lines | Where-Object { $_ -notmatch "^$([regex]::Escape($k))=" }); $lines += "$k=$($want[$k])" }
Set-Content -Path $cfg -Value $lines -Encoding Unicode
Get-Content $cfg -Encoding Unicode
```

3. **Групповые политики → «Настройка» (Preferences) → «Файлы»**: копировать подготовленный `.v8i` в общий ресурс или в `%AppData%\1C\1CEStart\` [практика]. Не перезаписывайте целиком пользовательские `ibases.v8i` и `1cestart.cfg`: в них лежат личные базы и настройки окна запуска (`UseHwLicenses` пользователь мог поменять сам) [практика].
4. **Ярлык с готовым списком**: `1cestart.exe /RunShortcut \\fs01\1c$\lists\ibcommon.v8i` [ИТС-адм прил. 7.3.10].

Кодировки: `ibases.v8i` — UTF-8, `1cestart.cfg` — UTF-16LE, `1cescmn.cfg` — UTF-8 или UTF-16LE [ИТС-адм прил. 3.4–3.6]. `Set-Content -Encoding Unicode` в Windows PowerShell 5.1 пишет UTF-16LE с меткой BOM, `-Encoding UTF8` — UTF-8 с BOM [практика; ⚠ что 1С принимает BOM в `ibases.v8i`, документация не уточняет].

Окно «Настройка» программы запуска (списки общих баз, «Используемые версии» с разрядностью, «Использовать аппаратную лицензию», «Устанавливать автоматически новую версию», «Удалять неиспользуемые версии») пишет изменения только в `1cestart.cfg` пользователя [ИТС-адм разд. 5.7].

## 9. Терминальный сервер (RDS)

### 9.1. Что поддерживается и как считаются лицензии

- ОС терминального сервера для клиента 8.3.27 — Windows Server 2012–2022; 2025 в списке нет ⚠ [ИТС-адм разд. 1.1.2]. Microsoft: узлы одной коллекции — одной версии ОС; сервер лицензирования RDS принимает CAL той же или более ранней версии Windows Server — при переходе узлов на 2025 обновляют и его; RDS CAL — отдельно от лицензий 1С [MS Learn, «Supported configurations for RDS»].
- Программная лицензия 1С: рабочее место — терминальная сессия; клиент, запущенный из службы Windows, — «аналог терминального сервера», нужна отдельная лицензия. Однопользовательская лицензия — любое число экземпляров в одной сессии, многопользовательская — на столько сессий, на сколько активирована; лицензии складываются, если файлы доступны всем пользователям сервера [ИТС-адм разд. 10.3.4.9]. В клиент-сервере с лицензией на сервере 1С — «один сеанс — одна лицензия» [ИТС-адм разд. 10.3.4.3.2].
- HASP: локальный ключ в терминальных сессиях Windows 7+/Server 2012+ не работает; многопользовательский ключ на терминальном сервере — только через установленный там HASP License Manager, сессия = рабочее место [ИТС-адм разд. 10.2.5.9]. Подробно — `05-licenzii-diagnostika-otlichiya-ot-linux.md`, `../1c/04-licenzirovanie.md`.

### 9.2. Установка и версии на терминальном сервере

[практика, опирается на ИТС-адм разд. 2.5.2.2, прил. 3.6]

1. Ставить платформу **«для компьютера»**, от администратора, 64-разрядную; набор — `THINCLIENT` (или `THINCLIENTFILE`), при необходимости `DESIGNERALLCLIENTS` для администраторов.
2. Перед установкой приложений на узел сеансов RD Microsoft рекомендует перевести сервер в режим установки: `change user /install`, после — `change user /execute`; проверить — `change user /query` [MS Learn, `change user`].
3. В общем для компьютера `1cestart.cfg` (`%ProgramData%\1C\1CEStart\`) задать `UseHwLicenses=0` (если ключей нет), `DefaultVersion=8.3;x86_64_prt`; в `1cescmn.cfg` или пользовательских файлах — `AutoUninstall=0` (удалять версии будет администратор) [ИТС-адм прил. 3.6.3, 3.6.8, 3.6.15].
4. Чтобы пользователи не ставили себе копии «для пользователя» в `%LOCALAPPDATA%\Programs`, ⚠ задать `InstallForUsers=1`: обычному пользователю тогда предлагается только установка «для компьютера», для которой нужен пароль администратора [вывод из таблицы ИТС-адм разд. 2.5.2.2 — проверить на стенде].
5. Новую версию ставить на терминальный сервер **до** обновления кластера: если требуемой сервером версии на компьютере нет, клиент попытается установить её, даже если `AppAutoInstallLastVersion=0` [ИТС-адм прил. 3.6.2].

### 9.3. Профили пользователей, кеш, внешние компоненты

- В перемещаемой части профиля (`%APPDATA%`) лежат `ibases.v8i`, пользовательский `1cestart.cfg`, внешние компоненты `ExtCompT`, шаблоны; в локальной (`%LOCALAPPDATA%\1C\1cv8\<ID базы>`) — кеш, который чистит `/ClearCache` (раздел 1.2) [ИТС-адм прил. 3.4, 3.6.1, 7.3.10; ИТС-разр гл. 32.2].
- Настройки форм и отчётов хранятся в информационной базе (хранилище системных настроек), поэтому при входе на другой узел фермы они сохраняются [ИТС-разр прил. 4]. Список баз и внешние компоненты — нет, если профиль не перемещается [практика].
- Для фермы из нескольких узлов Microsoft предлагает FSLogix: профиль подключается из контейнера на сетевом хранилище, приложения видят его как локальный, перемещаемые профили не нужны [MS Learn, FSLogix]. ⚠ Microsoft предупреждает: после апрельского (2026) обновления Windows Server с Kerberos AES-SHA1 по умолчанию файловые ресурсы с контейнерами FSLogix, не переведённые на AES, могут стать недоступны [MS Learn, FSLogix].
- Право «Список содержимого папки» на каталог временных файлов [ИТС-адм разд. 1.4.3]; техжурнал одному пользователю — `logcfg.xml` в его `%LOCALAPPDATA%\1C\1cv8\conf` (раздел 1.3).

### 9.4. Печать: сессия не закрывается из-за `SplWOW64.exe`

Статья 2010 года (Windows Server 2003/2008/2008 R2 x64): при печати из 1С запускается `SplWOW64.exe` (мост между 32- и 64-разрядными приложениями); пока он не завершился, терминальная сессия после закрытия 1С не закрывается. Решение — уменьшить тайм-аут `SplWOW64TimeOut` до 1 (DWORD) в `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Print` и добавить `SPLWOW64.EXE` = 0 (DWORD) в список процессов, завершаемых с сессией [ИТС-мет 4064, 2010].

```cmd
:: от имени администратора; сначала резервные копии ветвей
reg export "HKLM\SYSTEM\CurrentControlSet\Control\Print" "%USERPROFILE%\Desktop\print-backup.reg"
reg export "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\SysProcs" "%USERPROFILE%\Desktop\sysprocs-backup.reg"
reg add "HKLM\SYSTEM\CurrentControlSet\Control\Print" /v SplWOW64TimeOut /t REG_DWORD /d 1 /f
reg add "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\SysProcs" /v SPLWOW64.EXE /t REG_DWORD /d 0 /f
reg query "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\SysProcs" /v SPLWOW64.EXE
```

⚠ В тексте статьи ветка записана как `…\Control\TerminalServer\SysProcs` (без пробела); в Windows раздел называется `Terminal Server` — перед изменением убедитесь `reg query`, что ветка существует. Применимость к Windows Server 2016–2025 не проверена. Проблема касается только 32-разрядного клиента на 64-разрядной ОС — проще ставить 64-разрядный клиент (`DefaultVersion=8.3;x86_64_prt`) [практика].

### 9.5. Удобство и производительность

- Для Windows 10, доступной через «Подключение к удалённому рабочему столу», 1С рекомендует в параметрах подключения (вкладка «Взаимодействие») снять «Визуальные эффекты при отображении меню и окон» [ИТС-адм разд. 1.4.3].
- В интерфейсе «Такси» на удалённом рабочем столе (RDP) список функций раздела показывается без анимации; для видеозвонков системы взаимодействия в RDP-сеанс нужно пробросить микрофон и камеру компьютера, с которого идёт подключение (`../its-docs/usr-rukovodstvo-polzovatelya-i-taksi.md`) [ИТС, «Интерфейс Такси», гл. 1 и гл. 7].
- Если при входе возникает ошибка доступа (нет лицензии, запрет внешнего управления сеансами, монопольный режим), а у этого пользователя есть другие сеансы: завершившиеся клиенты с того же компьютера закрываются автоматически, иначе пользователю предлагают выбрать, какие сеансы завершить [ИТС-адм разд. 4.3.8.1]. На терминальном сервере «тот же компьютер» — сам сервер [практика ⚠].
- Узлы сеансов и кластер — в одной быстрой сети (режим низкой скорости не нужен); 1С можно публиковать как RemoteApp (`1cestart.exe`/`1cv8c.exe` с ключами из раздела 8) [практика].

## 10. COM-соединение и COM-объекты на Windows

### 10.1. Что есть что

| Объект | Назначение | Источник |
|---|---|---|
| `V83.COMConnector` (8.5 — `V85.COMConnector`) | внешнее соединение с базой (`Connect("Srvr=…;Ref=…")`), подключение к агенту (`ConnectAgent`) и рабочему процессу (`ConnectWorkingProcess`) для администрирования | [ИТС-КС разд. 2.2.4.2.1, 2.2.4.2.2, 5.3.1] |
| `V83.Application`, `V83C.Application` (8.5 — `V85.*`) | клиентское приложение как OLE Automation-сервер (толстый и тонкий клиент) | [ИТС-адм прил. 7.6] |
| `Новый COMОбъект("…")` во встроенном языке | любые COM-объекты Windows (Excel, Word, ADODB…) на клиенте или сервере Windows | [ИТС-разр гл. 4; ИТС-адм разд. 1.5] |

COM-соединение — это сеанс: «экземпляр внешнего соединения»; модуль внешнего соединения выполняется только в таком сеансе, интерфейса у него нет; снаружи доступны экспортные методы модуля внешнего соединения, общих модулей и глобальный контекст [ИТС-КС разд. 2.2.4.1; ИТС-разр гл. 4.2.3.2]. Право открывать внешнее соединение — `ВнешнееСоединение` (`ExternalConnection`), право на automation-сервер — `Automation` [ИТС-разр прил. 6]. Для механизма «запуск регламентных заданий при отсутствии активных сеансов» COM-соединение длительностью более 20 секунд считается сеансом пользователя, короче — нет [ИТС-КС разд. 2.2.7.3].

### 10.2. Регистрация

- Установщик регистрирует `V83.COMConnector` и `V83.Application` «для компьютера» или «для пользователя» по режиму установки (раздел 5.9) [ИТС-адм разд. 2.5.3].
- `regsvr32` с ошибкой `The module … was loaded but the call to DllRegisterServer failed with error code 0x80070005` — нет прав на реестр или `System32`: запускать от имени администратора [ИТС-адм разд. 2.5.3].
- Ключи `regsvr32`: `/u` — отменить регистрацию, `/s` — без сообщений [MS Learn, `regsvr32`].
- OLE-сервер: `/RegServer -AllUsers` (для всех; без прав — ошибка), `-CurrentUser`, `-Auto` (для всех, если хватает прав, иначе для себя, без диалогов); `/UnregServer` — отмена; вывод ошибок — в файл `/Out` [ИТС-адм прил. 7.6]. В прил. 7.2.2 регистрация OLE-сервера отнесена к командам режима `DESIGNER`.

```cmd
:: cmd от имени администратора. Файл библиотеки COM-соединения — comcntr.dll в каталоге bin версии
:: [практика ⚠: имя файла в документации 8.3.27 не названо]
:: 64-разрядная платформа — 64-разрядный regsvr32
%SystemRoot%\System32\regsvr32.exe "C:\Program Files\1cv8\8.3.27.xxxx\bin\comcntr.dll"
:: 32-разрядная платформа на 64-разрядной Windows — 32-разрядный regsvr32 [практика]
%SystemRoot%\SysWOW64\regsvr32.exe "C:\Program Files (x86)\1cv8\8.3.27.xxxx\bin\comcntr.dll"
:: отменить регистрацию
%SystemRoot%\System32\regsvr32.exe /u "C:\Program Files\1cv8\8.3.27.xxxx\bin\comcntr.dll"

:: OLE Automation-сервер V83.Application / V83C.Application для всех пользователей [ИТС-адм прил. 7.6]
"C:\Program Files\1cv8\8.3.27.xxxx\bin\1cv8.exe" DESIGNER /RegServer -AllUsers /Out "%TEMP%\regserver.log"
```

Какая версия зарегистрирована (PowerShell) [практика]:

```powershell
$clsid = (Get-ItemProperty 'Registry::HKEY_CLASSES_ROOT\V83.COMConnector\CLSID').'(default)'
Get-ItemProperty "Registry::HKEY_CLASSES_ROOT\CLSID\$clsid\InprocServer32"             # 64-разрядная регистрация
Get-ItemProperty "Registry::HKEY_CLASSES_ROOT\WOW6432Node\CLSID\$clsid\InprocServer32" -ErrorAction SilentlyContinue  # 32-разрядная
```

### 10.3. Версии и разрядность

- Версия, **к** которой подключаются, и версия, **из** которой создаётся COM-соединение, должны либо различаться по первым двум числам, либо совпадать полностью: из 8.3 можно подключиться к 8.2, но из 8.3.6 к 8.3.5 — нельзя; 8.3.6.2100 к 8.3.6.2100 — можно [ИТС-адм разд. 2.5.3; ИТС-КС разд. 3.1.4.4]. В 8.5.1 правило то же, пример — с 8.5 (`../its-docs/otlichiya-8.5.1-ot-8.3.27.md`).
- К клиент-серверной базе COM-соединение — это клиент, и для него действует общее правило совпадения версий клиента и кластера [ИТС-адм разд. 4.3.6.4]. Значит, после обновления сервера 1С нужно перерегистрировать `comcntr.dll` новой версии на всех компьютерах-интеграторах [практика].
- Разрядность COM-объекта должна совпадать с разрядностью процесса: 32-разрядный COM-объект не работает в 64-разрядной платформе [ИТС-адм разд. 1.5]. Для внешней программы: 64-разрядный PowerShell/IIS-пул видит только 64-разрядную регистрацию `V83.COMConnector` [практика].
- Автономный сервер (`ibsrv`) COM-соединение не поддерживает [ИТС-адм разд. 7.2].

### 10.4. Лицензии для COM-соединения

Программная лицензия ищется так: однопользовательские → многопользовательские → клиентские на сервере 1С (или на веб-сервере для файловой базы через веб); COM-соединение, созданное кодом на сервере 1С как внутрипроцессный COM-сервер при серверной программной лицензии, использует её [ИТС-адм разд. 10.3.4.7]. Для ключей HASP порядок свой; 64-разрядному соединению подходит только 64-разрядная серверная лицензия [ИТС-адм разд. 10.2.5.7]. Внешнее соединение читает `1cestart.cfg` профиля своего пользователя; без профиля (LocalSystem) ключ HASP ищется всегда [ИТС-адм прил. 3.6.15].

### 10.5. Отладка внешнего соединения

Файл `comcntrcfg.xml` в каталоге конфигурационных файлов (только Windows; нет файла — обычный режим) [ИТС-адм прил. 3.16]:

```xml
<config xmlns="http://v8.1c.ru/v8/comcntrcfg">
    <debugconfig debug="true" protocol="tcp" debuggerURL="tcp://localhost:1560"/>
</config>
```

`protocol` — `tcp` (по умолчанию) или `http`; для HTTP порт в `debuggerURL` обязателен (`http://pc-name:1561`); без порта при TCP проверяются 1560–1591; если протокол и схема URL не совпадают, отладка не подключится [ИТС-адм прил. 3.16; ИТС-разр гл. 31].

### 10.6. COM-объекты в коде: что учитывать

- Linux-сервер COM не выполняет (модуль компилируется, при выполнении — ошибка) [ИТС-КС разд. 2.3]; замены — `../1c/09-klient-linux-i-otlichiya-ot-windows.md`, разд. 4.2.
- Серверную (неинтерактивную, из службы, DCOM) автоматизацию Office Microsoft не рекомендует и не поддерживает — возможны зависания; замена — Open XML SDK [Microsoft Support, «Considerations for server-side Automation of Office»]. Office с методом `Quit` закрывать явно (у компонента — через `Application`/`Parent`) [ИТС-мет 2256, 2008].
- Длинные цепочки «через точку» к COM-объектам дают нестабильные ошибки — разбивайте на шаги [ИТС-мет 4988, 2012]; доступа по индексу `[]` через Automation нет — `Для Каждого`, `Получить()`/`Установить()` [ИТС-мет 2263, 2008].
- Пользователям ОС не давать доступ к произвольным COM-объектам на компьютерах кластера; COM из кода конфигурации ограничивают безопасный режим и профили безопасности [ИТС-КС прил. 3.5, 3.6; `../1c/08…`, разд. 9].
- Вынос `V83.COMConnector` в COM+ (`dcomcnfg`) для вызова из процесса другой разрядности или под другой учётной записью — практика сообщества ⚠, в документации 1С не описан.

### 10.7. Проверка COM-соединения к Linux-кластеру с Windows-компьютера

[практика ⚠ — на стенде не проверялось; имена методов `Connect` — ИТС-КС разд. 2.2.4.2.1]

```powershell
# 64-разрядный Windows PowerShell; на компьютере зарегистрирован V83.COMConnector ТОЙ ЖЕ сборки, что и кластер
$conn = New-Object -ComObject 'V83.COMConnector'
$ib   = $conn.Connect('Srvr="srv-1c-app.corp.example";Ref="buh";')   # без Usr/Pwd ⚠ ожидается аутентификация ОС
$ib.Metadata.Name                                                        # ⚠ имя конфигурации через глобальный контекст
[void][Runtime.InteropServices.Marshal]::ReleaseComObject($ib)
[void][Runtime.InteropServices.Marshal]::ReleaseComObject($conn)
```

Пароль в строке соединения (`Usr=…;Pwd=…`) не храните в сценариях открытым текстом; для служебных соединений заведите отдельного пользователя ИБ с минимальными ролями и правом `ВнешнееСоединение` [практика; ИТС-КС прил. 3.11].

## 11. Режим низкой скорости соединения (кратко)

- Назначение — работа по медленным каналам: меньше обращений к серверу, без несущественных данных [ИТС-польз гл. 14].
- Включение: в свойствах базы «Скорость соединения» = «Низкая» или «Выбирать при запуске» (тогда флажок «Низкая скорость соединения» в окне запуска); `ClientConnectionSpeed=Low` в `.v8i`; ключ `/OLow` [ИТС-адм разд. 5.2.3, прил. 3.4, 7.3.1]. Флажок в окне запуска тонкого клиента доступен, только если в списке есть база с «Выбирать при запуске» [ИТС-адм разд. 5.2.3].
- Что видно пользователю: нет картинок разделов; рабочий стол открывается по ссылке «Показать рабочий стол»; освобождение заблокированных формой данных — через 20 секунд или со следующим запросом; списки выбора берут ранее полученные данные (обновить — F5), выпадающий список при вводе — стрелкой вниз [ИТС-польз гл. 14].
- Соседние средства: сжатие трафика `/TComp` (по умолчанию `zstd`), имитация медленного канала для разработчика `/EmulateServerCallDelay -Call… -Send… -Recevie…` (написание `-Recevie` — как в документации), отображение числа вызовов сервера `DisplayPerformance` [ИТС-адм прил. 7.3.1, 7.3.7].

## Типичные ошибки (симптом → причина → решение)

| Симптом | Причина | Решение |
|---|---|---|
| Окно логина вместо входа по аутентификации ОС | пользователь ИБ сопоставлен не с тем написанием (`\\CORP\…` против `\\corp.example\…`) | техжурнал `CONN`, строка `DstUserName2`; записать `\\` + имя из неё [ИТС-адм разд. 6.2.10.3; ИТС-мет 5944] |
| В `CONN` `DstUserName2: NT AUTHORITY\ANONYMOUS LOGON` при входе через IIS | нет делегирования с веб-сервера на службу 1С, служба не под доменной учётной записью, в IIS не Negotiate | доменная учётная запись службы, SPN, делегирование, Windows-аутентификация с Negotiate первым, `iisreset`, перезагрузка клиента [ИТС-мет 5944; ИТС-КС разд. 3.1.6.1.1] |
| Ограниченное делегирование настроено, вход всё равно не проходит | у рабочего сервера не заполнено «Имя службы (SPN) сервера 1С:Предприятия» | заполнить SPN для каждого рабочего сервера [ИТС-КС разд. 5.2.6.1] |
| Вход по ОС работал на Windows-сервере 1С и перестал после переноса на Linux | работал NTLM; Linux-сервер поддерживает только Kerberos | keytab, SPN `usr1cv8/<FQDN>`, DNS, время (`../1c/08…`, разд. 5) [ИТС-КС разд. 2.3] |
| `klist get` — ошибка «principal unknown» | SPN нет или он на другой учётной записи | `setspn -Q`, `setspn -L`; пересоздать SPN/keytab [MS Learn; практика] |
| После апрельских (2026) обновлений Windows Server перестал работать Kerberos к службе | учётная запись службы/keytab только с RC4 | включить AES у учётной записи, пересоздать keytab с AES [MS Learn; `../1c/08…`, разд. 5.9] |
| «Версия клиента не соответствует версии сервера» и клиент не обновляется | нет дистрибутива в `DistributiveLocation`, нет `PublishDistributiveLocation*`, у пользователя нет прав | раздел 6: заранее поставить версию GPO или задать `PublishDistributiveLocationWindows64` [ИТС-адм разд. 4.3.6.4] |
| Установка «для пользователя» падает | нет Visual C++ Redistributable из дистрибутива | поставить `vc_redist.x64.exe` администратором/GPO [ИТС-адм разд. 2.5.2.2] |
| У пользователей в `%LOCALAPPDATA%\Programs\1cv8_x64` копии платформы | автоустановка без прав администратора идёт «для пользователя» | ставить версии централизованно; `InstallForUsers=1` ⚠; `AppAutoInstallLastVersion=0` [ИТС-адм разд. 2.5.2.2, прил. 3.6.2] |
| После установки через GPO 1С при запуске просит перезагрузку | `AdmInstall=Restart`: нужной версии нет, политика поставит её при перезагрузке | так и задумано; добавить пакет новой версии в GPO до обновления сервера [ИТС-адм разд. 2.6.3.10] |
| Пользователь не видит общий список баз | путь в `CommonInfoBases` недоступен, файл в неверной кодировке, строка в `1cescmn.cfg`, а 1С ставилась не из сетевого каталога | проверить доступ к `\\fs01\…`, UTF-8 у `.v8i`, `CommonCfgLocation` в `1cestart.cfg` [ИТС-адм прил. 3.4–3.6] |
| Запуск долгий, «поиск ключа защиты» | `UseHwLicenses=1`, ключей нет | `UseHwLicenses=0` или `USEHWLICENSES=0` при установке [ИТС-адм прил. 3.6.15, разд. 2.5.2.1] |
| Ошибка лицензии на терминальном сервере при локальном ключе HASP | локальный ключ в терминальных сессиях Windows 7/2012+ не работает | многопользовательский ключ + HASP License Manager, программные лицензии [ИТС-адм разд. 10.2.5.9] |
| Терминальная сессия не закрывается после выхода из 1С | висит `SplWOW64.exe` после печати 32-разрядным клиентом | реестр по статье 4064 или 64-разрядный клиент [ИТС-мет 4064, 2010] |
| `New-Object -ComObject V83.COMConnector` — «класс не зарегистрирован» | регистрация другой разрядности или версии | `regsvr32` нужной разрядности, проверить `InprocServer32` [ИТС-адм разд. 1.5; практика] |
| `excel.exe` копятся в памяти сервера | нет `Quit()`, серверная автоматизация Office | закрывать явно; не автоматизировать Office на сервере [ИТС-мет 2256; Microsoft Support] |

## Что не удалось подтвердить

1. Имена MSI-файлов в дистрибутивах 8.3.27 (пример ИТС — для 8.2: `1CEnterprise 8.2.msi`) и передача ключей компонентов (`THINCLIENT=1` …) как свойств MSI — проверять `dir *.msi *.mst` и журналом `/L*V`.
2. `setup.exe /S` вместе с `ALLUSERS=1` и `USEHWLICENSES=0`; чтение `InstallComponents` из общего `1cestart.cfg` при `/S`.
3. Учёт и сохранность `CommonInfoBases`, записанного в `%ProgramData%\1C\1CEStart\1cestart.cfg`; эффект `InstallForUsers=1` на терминальном сервере (выведено из таблицы разд. 2.5.2.2).
4. Имя библиотеки `comcntr.dll` (в документации не названо), проверка регистрации через реестр, вынос `V83.COMConnector` в COM+, пример PowerShell из раздела 10.7.
5. Ключ `rac server update --service-principal-name` (параметров `rac` в документации нет — `rac help server`).
6. Команды AD для делегирования (`msDS-AllowedToDelegateTo`, `-TrustedForDelegation`) как эквиваленты флажков из документации; RBCD и gMSA с 1С.
7. Как клиент строит имя службы Kerberos (класс `usr1cv8` для Linux-сервера, FQDN или IP в `Srvr`).
8. Работа `ClientUpdate.cfg` при прямом TCP-подключении (документация говорит о HTTP).
9. Считается ли «используемой» для автоудаления версия службы, созданной `register-agent.bat` с нестандартным именем.
10. Статья 4064 (2010) на Windows Server 2016–2025 и написание ветки `Terminal Server\SysProcs`.
11. Поддержка Windows Server 2025 клиентом 8.3.27/8.5 (в перечне ОС её нет).
12. Файлы `*.pfl` из статьи 3746 (2010) в 8.3.27; параметр `External` в `ibases.v8i`.
13. Свойство `АутентификацияОС` и метод `НайтиПоИмени` (пример в 2.4); приём BOM в `ibases.v8i`.
14. Где в комплекте поставки лежит `1CEClientSetupMake.exe`.
