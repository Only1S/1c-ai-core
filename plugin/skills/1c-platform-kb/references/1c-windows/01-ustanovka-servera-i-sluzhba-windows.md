## Кратко — главные факты и команды

1. **ОС для 64-разрядного кластера 8.3.27**: Windows 7 SP1, 8.0, 8.1, 10, 11; Windows Server 2012, 2012 R2, 2016, 2019, 2022 — с актуальными обновлениями [ИТС-КС разд. 1.2.1]. **Windows Server 2025** нет ни в документации 8.3.27/8.5.1, ни на v8.1c.ru (19.10.2026) ⚠ — для боевого сервера берите 2022 или 2019.
2. **Сроки Microsoft** [MS Learn]: 2012/2012 R2 — всё, включая ESU, закончилось 13.10.2026; 2016 — до 12.01.2027; 2019 — до 09.01.2029; 2022 — основная закончилась 13.10.2026, расширенная до 14.10.2031; 2025 — до 13.11.2029 / 14.11.2034.
3. **Три программы установки**: полная «1С:Предприятие 8» (32/64), «Тонкий клиент», «1С:Предприятие 8 (x86-64) Сервер» (только 64-разрядный сервер, без режима «для пользователя») [ИТС-адм разд. 2.5.1, ИТС-КС разд. 3.1.4.1]. Тихий режим — `setup.exe /S` с параметрами из `1cestart.cfg` [ИТС-адм разд. 2.5.2.1].
4. **Сервер службой — только при установке «для компьютера»** [ИТС-адм разд. 2.5.2.6, ИТС-КС разд. 4.1]; служба — рекомендованный способ [ИТС-КС разд. 3.1.5.2.2].
5. **Учётная запись службы** по умолчанию `USR1CV8`; созданному установщиком пользователю права выдаются автоматически [ИТС-КС разд. 3.1.5.2.2]. Нужны: полные права на каталог данных кластера, «Список содержимого папки» на каталог временных файлов, «Вход в качестве службы», «Вход в качестве пакетного задания», группа «Пользователи журналов производительности» [ИТС-КС разд. 1.3.2]. С пустым паролем установщик сервер не запустит.
6. **Имена стандартной службы**: `1C:Enterprise 8.3 Server Agent (x86-64)` (64-разрядная), `1C:Enterprise 8.3 Server Agent` (32-разрядная) [ИТС-КС разд. 4.2.3.2]; в 8.5 — `1C:Enterprise 8.5 Server Agent (x86-64)` [конспект отличий 8.5.1].
7. **Каталоги**: исполняемые файлы — `C:\Program Files\1cv8\<версия>\bin` (`ragent.exe`, `rmngr.exe`, `rphost.exe`, `crserver.exe`, `dbgs.exe`, `webinst.exe`; `ras`/`rac` входят в компонент «Сервер» [ИТС-адм разд. 2.5.2.4]); общие настройки — `C:\Program Files\1cv8\conf`; данные кластера при установке службой — `C:\Program Files\1cv8\srvinfo`; при запуске приложением без `/d` — `%LOCALAPPDATA%\1C\1cv8` [ИТС-адм прил. 1 разд. 1.1.4, ИТС-КС разд. 2.2.13].
8. **Порты по умолчанию**: 1540 — агент `ragent`, 1541 — главный менеджер `rmngr`, 1560–1591 — рабочие процессы `rphost`, 1545 — `ras`, 1550 — сервер отладки `dbgs`, 1542 — сервер хранилища `crserver`; 1555 — HTTP-шлюз монитора `ras`, по умолчанию только на `localhost` [ИТС-КС прил. 3 разд. 3.8, ИТС-адм прил. 4 разд. 4.13.1, ИТС-разр гл. 37.4.5.1].
9. **Штатная регистрация службы**: `ragent.exe /instsrvc /usr <пользователь> /pwd <пароль> …`; снятие — `ragent.exe /rmsrvc`; запуск и остановка зарегистрированной службы — `/start`, `/stop`; всё от имени администратора [ИТС-адм прил. 4 разд. 4.12.1].
10. **Несколько служб агента** штатными средствами не регистрируются — только `sc.exe create` (образец `register-agent.bat` в документации). Условия: разные порты агента и менеджера, непересекающиеся диапазоны, разные каталоги данных [ИТС-КС разд. 4.3.1, 4.3.3.2]; в 8.5.1 добавлено требование уникального `/regport` для каждого кластера на компьютере [конспект отличий 8.5.1].
11. **Синтаксис `ragent`**: ключ и значение разделяются пробелом; путь с пробелами — в кавычках, и в кавычках он **не должен заканчиваться** символом `\` («`"c:\my path"`», а не «`"c:\my path\"`») [ИТС-адм прил. 4 разд. 4.12.1].
12. **Если агент не найдёт реестр кластера в каталоге `/d`, он создаст новый пустой кластер** [ИТС-КС разд. 2.2.13]. При перерегистрации службы, смене пользователя или переходе «приложение ↔ служба» всегда указывайте прежний каталог данных.
13. **Ключ `/debug`** включает отладку на кластере и снижает производительность — держите его только на серверах, где отлаживают [ИТС-адм прил. 4 разд. 4.12.1]. Образец `register-agent.bat` из документации ставит `/debug` всегда — для боевого сервера уберите.
14. **`ras` как служба**: `sc.exe create "<имя>" binPath= "\"C:\Program Files\1cv8\<версия>\bin\ras.exe\" cluster --service --port=1545 localhost:1540" start= auto obj= … password= …` (образец `register-ras.bat`) [ИТС-адм прил. 4 разд. 4.13.2]. Версия `ras` должна совпадать с версией кластера [ИТС-КС разд. 5.3.3.1].
15. **Сервер хранилища**: `crserver.exe -instsrvc -usr <пользователь> -pwd <пароль> -port 1542 -d <каталог>`; служба называется `1C:Enterprise 8 Configuration Repository Server`; пользователю службы нужно право «Вход в систему как сервис»; версии сервера хранилища и конфигуратора должны совпадать [ИТС-разр гл. 37.4.5.1, 37.4.6].
16. **`dbgs` как служба** (`--service`) отлаживает файловые базы и клиентские предметы отладки, но **не серверный код клиент-серверных баз** [ИТС-адм прил. 4 разд. 4.11.1]. Для серверной отладки агент запускают с `/debug -http` — тогда `dbgs` на порту 1550 запускает сам кластер [ИТС-КС разд. 4.2.1].
17. **Брандмауэр**: документация советует открывать только порты кластера, а при работе пользователей только через веб-сервер — закрыть их совсем [ИТС-КС прил. 3 разд. 3.8]. Команда: `New-NetFirewallRule -DisplayName "1C agent, manager, rphost" -Direction Inbound -Protocol TCP -LocalPort 1540,1541,1560-1591 -RemoteAddress <подсеть клиентов> -Action Allow` [MS Learn].
18. **Обновление** [ИТС-КС гл. 6]: запретить сеансы → бэкап средствами СУБД → отключить пользователей → остановить службу → перевести её на новый `ragent.exe` → запустить → обновить публикации → разрешить сеансы. Стандартную службу установщик переустанавливает сам [ИТС-адм разд. 2.5.2.6], свои — `sc.exe config … binPath= …`.
19. **Версии клиента и сервера совпадают в точности** [ИТС-адм разд. 4.3.6.4]. **Смешанная среда:** Windows-клиенты Linux-сервера берут сборку из `conf.cfg` сервера (`PublishDistributiveLocationWindows64`), из `distr` веб-расширения или сетевого каталога (`1cescmn.cfg`) [ИТС-адм разд. 2.7, 11.2, прил. 3 разд. 3.17.19].
20. **Удаление**: остановить сервер → «Программы и компоненты» → «1С:Предприятие 8 (A.B.C.D)» [ИТС-КС разд. 7.2]; базы не удаляются [ИТС-адм разд. 12.1]; службы из `sc.exe` удаляйте сами.
21. **Автоудаление версий** считает сборку используемой, только если она в службе **со стандартным именем** [ИТС-адм разд. 12.2.4] — на сервере `AutoUninstall=0` или `DontUninstallVersion` [ИТС-адм прил. 3 разд. 3.6.3, 3.6.11].
22. **Методички 2008–2016 годов** (SynAttackProtect, MaxUserPort, MDAC, RC4) — для Windows Server 2003/2008; в статье 5908 команда `netsh … start=10000 num=64510` ошибочна (конец > 65535 [MS Learn]), правильно `num=55536`.

### 1.3. Аппаратные и программные требования к серверу

- **Минимум для рабочего сервера 64-разрядного кластера**: процессор x86-64 (желательно многоядерный), ОЗУ от 4 Гбайт (рекомендуется от 8 Гбайт), установка занимает от 1 Гбайта без учёта баз; USB-порт — только для аппаратного ключа [ИТС-КС разд. 1.2.1]. Реальный расчёт — по методике https://its.1c.ru/db/metod8dev#content:5810 [ИТС-адм разд. 1.1.1]; конспект — `../its-metod/raschet-oborudovaniya-i-nagruzochnoe-testirovanie.md`.
- **Сеть**: между серверами кластера и СУБД — от 1 Гбит/с [ИТС-КС разд. 1.3.1]. Клиент в ВМ с сетевым адаптером в режиме NAT не работает с кластером, расположенным на хост-машине этой ВМ [ИТС-КС разд. 1.3.1].
- **Java** (Liberica, 1.8+, разрядность = разрядность кластера) нужна для `ring`/`ring license`, оптимизированной реструктуризации (MS SQL Server, PostgreSQL) и ППД версии 2 [ИТС-КС разд. 1.3.1]; в полной программе установки есть компонент «Liberica JRE» [ИТС-адм разд. 2.5.2.4]; при Java 17+ для ППД v2 — `FtsJavaOpts=--add-opens java.base/java.lang=ALL-UNNAMED` в `conf.cfg` [ИТС-адм разд. 2.8.3].
- **Служба WMI** должна работать — без неё нет программного лицензирования [ИТС-адм разд. 1.4.3] (лицензии — `05-…`). **MS SQL Server** требует на сервере 1С Microsoft OLE DB Driver for SQL Server или SQL Server Native Client [ИТС-КС разд. 1.5.4] — `02-…`. После установки некоторых шрифтов нужна перезагрузка сервера [ИТС-адм разд. 1.4.3].
- **Дата акселератор** под Windows: файл подкачки фиксированного размера не меньше ОЗУ (рекомендуется от 512 Гбайт), ОЗУ от 64 Гбайт, лицензия КОРП (один экземпляр — ПРОФ); под Hyper-V выключить «Выполнить перенос на физический компьютер с другой версией процессора» [ИТС-КС разд. 1.2.2, 3.1.5.3].
- **Энергосбережение** на компьютерах кластера система запрещает (кроме локального ключа и файловой базы на локальном диске) [ИТС-КС разд. 1.4]; схема питания — «Высокая производительность» [ИТС-мет 5899, 2016; ИТС-мет 5908, 2022].
- **Visual C++** (`vc_redist.x86.exe`, `vc_redist.x64.exe`) входит в дистрибутив; без него не завершится установка «для пользователя», ставится только администратором [ИТС-адм разд. 2.5.2.2]. Историческое требование 8.3.11 — KB2999226 на Windows 7/2008 R2/8.x [ИТС-мет 5935, 2017]; на Windows 10/11 и Server 2016+ UCRT встроен [практика].

### 1.4. Смешанная среда: что из этой статьи нужно пользователю

- Сервер 1С пользователя — Linux; на Windows-машинах нужны только **клиент** и, для администратора, **«Администрирование сервера 1С:Предприятия 8»** (оснастка MMC и `rac.exe`) **той же сборки**, что на сервере [ИТС-адм разд. 4.3.6.4, ИТС-КС разд. 5.3.3.1]. Компонент «Сервер 1С:Предприятия 8» на рабочие места не ставьте.
- MMC-оснастка подключается к агенту Linux-сервера напрямую по 1540, `rac.exe` — к `ras` на Linux по 1545; со стороны Windows никаких входящих правил брандмауэра не нужно, достаточно исходящих (в Windows они по умолчанию разрешены [практика]). Входящие порты открываются на Linux-сервере — см. `../1c/02-ustanovka-servera-ubuntu.md`, раздел 10.
- Кластер возвращает клиенту **имена** рабочих серверов, поэтому Windows-клиенты должны разрешать `srv-1c-app` через DNS или `hosts` — см. там же.
- Обновлять клиентов после обновления Linux-сервера — раздел 10.5 этой статьи.

Что лежит в каталоге дистрибутива и используется дальше:

### 2.2. Режим установки «для компьютера» или «для пользователя»

Режим определяется параметром `InstallForUsers` файла `1cestart.cfg`, параметром `ALLUSERS` командной строки установщика (у него наивысший приоритет) и правами пользователя [ИТС-адм разд. 2.5.2.2]:

| Значение | Администратор | Обычный пользователь |
|---|---|---|
| 0 — зависит от прав (умолчание при первой установке) | «для компьютера» | диалог или «для пользователя» |
| 1 — «для компьютера» | «для компьютера» | диалог или «для компьютера» |
| 2 — «для пользователя» | «для пользователя» | диалог или «для пользователя» |
| 3 — «для пользователя» без вопросов | «для пользователя» | «для пользователя» |

- Администратор — член локальных администраторов или пользователь при политике `AlwaysInstallElevated`; выбранный режим запоминается в `1cestart.cfg` [ИТС-адм разд. 2.5.2.2].
- Каталоги по умолчанию: «для компьютера» — `%PROGRAMFILES%\1cv8\A.B.C.D` (32-разрядная система в 64-разрядной ОС — `%PROGRAMFILES(x86)%\1cv8\A.B.C.D`); «для пользователя» — `%LOCALAPPDATA%\Programs\1cv8_x64\A.B.C.D` (64 в 64), `…\1cv8_x86\…` (32 в 64), `…\1cv8\…` (32 в 32) [ИТС-адм разд. 2.5.2.4].
- **Для сервера** — только «для компьютера»: в режиме «для пользователя» страница выбора варианта установки сервера не показывается, сервер службой работать не может, а установщик «(x86-64) Сервер» этот режим вообще не поддерживает [ИТС-адм разд. 2.5.2.6, ИТС-КС разд. 3.1.4.3.1, 4.1].
- Значения `ALLUSERS` для командной строки документация не перечисляет отдельно — из текста следует, что они совпадают со шкалой 0–3 выше ⚠. Надёжнее запускать `setup.exe` из сеанса администратора (тогда при значении 0 будет «для компьютера»).

| Модули расширения веб-сервера | `WEBSERVEREXT` | модули для IIS/Apache | только если на этой машине веб-сервер |
| Администрирование сервера 1С:Предприятия 8 | `SERVERCLIENT` | оснастка MMC (консоль кластера) | да (и на машине администратора) |

| Контроль целостности | ключ не документирован ⚠ | утилита `ci`; факт установки не запоминается, при каждой версии выбирается вручную | по требованию ИБ |

### 2.4. Интерактивная установка сервера: шаги помощника

1. Запустить `setup.exe` от имени локального администратора; режим — «для компьютера» [ИТС-адм разд. 2.5.2.1–2.5.2.2].
2. Выбрать компоненты (раздел 2.3) и каталог; общие каталоги `common` и `conf` всё равно создаются в корне `%PROGRAMFILES%\1cv8` [ИТС-адм прил. 1 разд. 1.1.4].
3. Выбрать язык интерфейса по умолчанию — будет записан в `C:\Program Files\1cv8\conf\conf.cfg` [ИТС-адм разд. 2.5.2.5].
4. Страница «Установка сервера 1С:Предприятия»: флажок установки **как сервиса Windows**, пользователь (по умолчанию предлагается создать служебного пользователя) и **обязательно пароль** — с пустым паролем установщик не запустит сервер [ИТС-адм разд. 2.5.2.6, ИТС-КС разд. 3.1.5.2.2]. Если на компьютере уже есть версия с сервером-службой, установщик **переустановит** службу (на новую версию) [ИТС-адм разд. 2.5.2.6].
5. Установка: копирование, регистрация компонентов, ярлыки, **запуск сервера** (если выбрана служба) — после завершения кластер работоспособен [ИТС-адм разд. 2.5.2.7, ИТС-КС разд. 3.1.5.2.2]. В «Программах и компонентах» у каждой версии своя строка «1С:Предприятие 8 (A.B.C.D)» [ИТС-адм разд. 2.5.2.7].
6. Драйвер защиты HASP — только если на этот компьютер вставляется аппаратный ключ; ставить до подключения ключа; оставить флажок «Отключить неиспользуемые 1С:Предприятием возможности аппаратных ключей защиты (рекомендуется)» — он отключает веб-интерфейс драйвера [ИТС-адм разд. 2.5.2.8; ИТС-мет 5936, 2017]. Подробнее — `05-licenzii-diagnostika-otlichiya-ot-linux.md`.
7. Последнее окно: флажок установки дистрибутивов тонкого клиента в каталог установки (для автообновления клиентов через веб-сервер) — ставить только там, где работает расширение веб-сервера; нужен файл `*-clients-distr*.exe` рядом с дистрибутивом [ИТС-адм разд. 2.5.2.9].

Проверка после установки (PowerShell, администратор) [практика]:

```powershell
Get-Service -Name "1C:Enterprise 8.3 Server Agent*" | Format-List Name, DisplayName, Status, StartType
Get-CimInstance Win32_Service -Filter "Name LIKE '1C:Enterprise%'" | Select-Object Name, StartName, PathName
Get-NetTCPConnection -State Listen -LocalPort 1540,1541 -ErrorAction SilentlyContinue |
    Select-Object LocalAddress, LocalPort, OwningProcess
```

Ожидаемо: служба `Running`, `StartName` = `.\USR1CV8` (или выбранный пользователь), `PathName` указывает на `ragent.exe` нужной сборки и каталог `srvinfo`; порты 1540 и 1541 слушаются.

Стартовая строка стандартной службы, которую формирует установщик, в документации целиком не приведена. По наблюдениям сообщества она имеет вид `"C:\Program Files\1cv8\8.3.27.1688\bin\ragent.exe" -srvc -agent -regport 1541 -port 1540 -range 1560:1591 -d "C:\Program Files\1cv8\srvinfo" -debug` ⚠ — сверяйте по `PathName` на своём сервере. Документация подтверждает только, что каталог `<корень установки>\srvinfo` указывается явно в ключе `/d` службы [ИТС-КС разд. 2.2.13], а в примерах служб использует ключи `/srvc /agent` [ИТС-КС разд. 4.2.3.2, ИТС-адм прил. 4 разд. 4.12.2]. Если `-debug` в вашей строке есть — уберите его на боевом сервере (раздел 4.6).

### 2.5. Тихая (пакетная) установка

**Вариант 1 — `setup.exe /S` (документирован).** Помощник определит режим установки и возьмёт параметры из `1cestart.cfg` соответствующего режима; если файла нет — настройки по умолчанию [ИТС-адм разд. 2.5.2.1]. Для установки «для компьютера» общий для всех пользователей файл — `%ALLUSERSPROFILE%\1C\1CEStart\1cestart.cfg`, текст в кодировке **UTF-16LE** [ИТС-адм прил. 3 разд. 3.6.1]:

```powershell
# PowerShell 5.1 от имени администратора; кодировка Unicode = UTF-16LE
$dir = "$env:ALLUSERSPROFILE\1C\1CEStart"
New-Item -ItemType Directory -Force $dir | Out-Null
@(
  'InstallComponents=DESIGNERALLCLIENTS=0 THINCLIENT=0 THINCLIENTFILE=0 SERVER=1 WEBSERVEREXT=0 CONFREPOSSERVER=0 CONVERTER77=0 SERVERCLIENT=1 LANGUAGES=RU',
  'UseHwLicenses=0',
  'AutoUninstall=0'
) | Set-Content -Path "$dir\1cestart.cfg" -Encoding Unicode
Start-Process -FilePath "D:\distr\8.3.27.1688\setup.exe" -ArgumentList "/S" -Wait
```

Ключи `InstallComponents`, `UseHwLicenses`, `AutoUninstall` — из [ИТС-адм прил. 3 разд. 3.6]. Существующий файл перед заменой сохраните (в нём могут быть `DefaultVersion` и др.). Поставит ли `/S` сервер **службой**, документация не говорит ⚠ — после установки проверьте `Get-Service` и при необходимости зарегистрируйте службу сами (раздел 4.4). Параметр `USEHWLICENSES=0` можно также передать в командной строке `setup.exe USEHWLICENSES=0` или в `setup.ini` [ИТС-адм разд. 2.5.2.1].

**Вариант 2 — `msiexec` с открытыми свойствами пакета** [MS Learn — ключи `msiexec`; свойства 1С — ⚠]. Образец скрипта из документации передаёт установщику Windows Installer строку `TRANSFORMS=adminstallrelogon.mst;1049.mst` и ключи компонентов в виде свойств: `DESIGNERALLCLIENTS=1 THINCLIENT=1 WEBSERVEREXT=0 SERVER=0 CONFREPOSSERVER=0 CONVERTER77=0 SERVERCLIENT=1 LANGUAGES=RU`, удаление — `REMOVE=ALL` [ИТС-адм прил. 3 разд. 3.10]. Отсюда пакетная установка сервера (cmd, администратор):

```bat
rem Имя .msi подставьте из каталога дистрибутива; лог — подробный
msiexec /i "D:\distr\8.3.27.1688\<имя пакета>.msi" /qn /norestart /L*v "C:\Temp\1c-8.3.27.1688-install.log" ^
  TRANSFORMS=1049.mst DESIGNERALLCLIENTS=0 THINCLIENT=0 THINCLIENTFILE=0 SERVER=1 SERVERCLIENT=1 ^
  WEBSERVEREXT=0 CONFREPOSSERVER=0 CONVERTER77=0 LANGUAGES=RU
```

- Ключи `/i`, `/qn`, `/norestart`, `/L*v`, `/x` — [MS Learn]. `THINCLIENTFILE` в образце скрипта нет (есть в списке `InstallComponents`) — как свойство MSI не проверено ⚠.
- `adminstallrestart.mst`/`adminstallrelogon.mst` — для **клиентов** из GPO или logon-скрипта: при несовпадении версий платформа предложит перезагрузку или повторный вход; установка оставит в `C:\Program Files\1cv8\conf` файл `adminstall.cfg` со строкой `AdmInstall=Restart` или `AdmInstall=Logon` [ИТС-адм разд. 2.6.3.10, прил. 3 разд. 3.10]. На сервере кластера не используйте [практика].
- Регистрирует ли MSI-установка сервер службой и какими свойствами задаётся пользователь службы — не описано ⚠. Надёжно: поставить пакет, затем `ragent.exe /instsrvc /usr … /pwd …` (раздел 4.4) и проверить `PathName`; результат установки — в логе и по наличию `bin\ragent.exe` нужной сборки [практика].

**Групповые политики и logon-скрипты** — для клиентов (несколько версий параллельно, новая версия — новое назначение; для скрипта нужен `ProductCode` из `setup.ini`) [ИТС-адм разд. 2.6.3.10]; подробно — `04-domen-kerberos-klienty-terminalnyj-server.md`.

| `…\<A.B.C.D>\bin\jre`, `…\bin\dmf` | Java; файлы оптимизированного механизма обновления конфигурации БД | [ИТС-адм прил. 1 разд. 1.1.4] |
| `%ALLUSERSPROFILE%\1C\1cv8` | общие данные; при `swpuser.ini` пользователям `rphost`/`rmngr` нужен к нему полный доступ | [ИТС-адм прил. 3 разд. 3.29] |
| `%ALLUSERSPROFILE%\1C\licenses` | программные лицензии (для сервера — этого каталога пользователя службы) | [ИТС-адм гл. 10.3.8] |
| `%ALLUSERSPROFILE%\1C\1CEStart\1cestart.cfg` | настройки программы запуска для всех пользователей (меняется только установщиком) | [ИТС-адм прил. 3 разд. 3.6.1] |

Порядок поиска конфигурационных файлов (`logcfg.xml`, `nethasp.ini` и т. д.) в Windows [ИТС-адм прил. 1 разд. 1.3.4]: (1) `…\<версия>\bin\conf`; (2) `%LOCALAPPDATA%\1C\1cv8\conf` пользователя, **от имени которого работает процесс** (для сервера — пользователя службы); (3) каталог из параметра `ConfLocation` файла `bin\conf\conf.cfg` (после установки это `C:\Program Files\1cv8\conf`); (4) `%ALLUSERSPROFILE%\1C\1cv8\conf`. Практический вывод: общий `logcfg.xml` для сервера кладите в `C:\Program Files\1cv8\conf` — он подействует на все версии; файл в профиле `USR1CV8` перекроет общий [ИТС-адм прил. 1 разд. 1.3.1, 1.3.4]. Подробно о `conf.cfg` и `logcfg.xml` — `05-licenzii-diagnostika-otlichiya-ot-linux.md` и `../1c/07-tehzhurnal-diagnostika-zhurnal-registracii.md`.

Внутри каталога данных сервера (`srvinfo` или `/d`) для каждого кластера создаётся `reg_<порт главного менеджера>` (`reg_1541`) с реестром кластера `1CV8Clst.lst`, журналами регистрации `<uuid-базы>\1Cv8Log`, индексами ППД `1Cv8FTxt`/`1Cv8FTxt2`, сеансовыми данными `snccntx\<uuid-менеджера>` и др. [ИТС-КС разд. 2.2.3.2, ИТС-адм прил. 3 разд. 3.7]. С лицензией КОРП каталоги части сервисов можно перенести [ИТС-КС разд. 2.2.3.2].

### 2.7. Регистрация COM-компонентов и оснастки

- Установка «для компьютера» регистрирует для компьютера COM-соединение (`V83.COMConnector`) и клиентское приложение (`V83.Application`); «для пользователя» — для пользователя [ИТС-адм разд. 2.5.3]. В 8.5 — `V85.COMConnector`, `V85.Application`, `V85C.Application` [конспект отличий 8.5.1].
- COM-соединение работает только между версиями, отличающимися первыми двумя числами, либо **полностью одинаковыми**: из 8.3.27.1688 нельзя подключиться к 8.3.27.1700 [ИТС-адм разд. 2.5.3].
- Ошибка `regsvr32` вида `…DllRegisterServer failed with error code 0x80070005` — нет прав на реестр или `System32`: запускать от администратора [ИТС-адм разд. 2.5.3].
- Имя библиотеки COM-соединения (`comcntr.dll`) в документации 8.3.27 не названо ⚠; повторная регистрация нужной версии делается командой `regsvr32 "C:\Program Files\1cv8\8.3.27.1688\bin\comcntr.dll"` в `cmd` от администратора [практика].
- Оснастка MMC конкретной версии регистрируется ярлыком «Регистрация утилиты администрирования серверов (A.B.C.D)» — это `RegMSC.cmd`, регистрирующий `radmin.dll` версии [ИТС-адм разд. 4.1.3, прил. 1 разд. 1.2.17]. Без регистрации нужной версии консоль к серверу этой версии не подключится — подробно в `../1c/02-ustanovka-servera-ubuntu.md`, раздел 10.

## 3. Учётная запись службы и права

### 3.1. Какой пользователь

| Вариант | Как получить | Плюсы | Минусы | Источник |
|---|---|---|---|---|
| Локальный `USR1CV8` | создаёт установщик и выдаёт права | просто, документировано | пароль меняется вручную; доступ к сетевым ресурсам домена — отдельно | [ИТС-КС разд. 3.1.5.2.2] |
| Доменная учётная запись (`DOMAIN\svc-1c`) | в установщике или `/usr` | Kerberos SSO (SPN `srv1c/…`), сетевые ресурсы, несколько серверов кластера | права входа — через GPO, иначе доменная политика их сотрёт | [ИТС-КС разд. 3.1.6.1.1; MS Learn] |
| gMSA (`DOMAIN\gmsa-1c$`) | `New-ADServiceAccount`, пароль меняет домен | нет ручной смены пароля | 1С этот вариант не описывает; установщик и `ragent /instsrvc` требуют пароль ⚠ | [MS Learn] |
| Виртуальная `NT SERVICE\<имя службы>` | `sc.exe config … obj= "NT SERVICE\<имя>"` без пароля | нет пароля | 1С не описывает; профиль, `swpuser.ini`, лицензии, каталоги не проверены ⚠ — для 1С не рекомендуется | [MS Learn] |
| `LocalSystem` | значение `obj=` по умолчанию у `sc.exe create` | — | все процессы кластера с правами системы; документация прямо называет запуск от администратора «крайне небезопасным» | [MS Learn; ИТС-адм прил. 3 разд. 3.29] |

Для Kerberos-аутентификации (веб-сервер и кластер на разных машинах или кластер из нескольких серверов) служба должна работать от **доменной** учётной записи, к которой привязывается SPN вида `srv1c/myserver.mydomain` [ИТС-КС разд. 3.1.6.1.1] — настройка в `04-domen-kerberos-klienty-terminalnyj-server.md`. Виртуальные учётные записи ходят в сеть от имени учётной записи компьютера `<домен>\<компьютер>$` [MS Learn].

### 3.2. Какие права нужны

Пользователь, от которого работают процессы кластера (по умолчанию `USR1CV8`) [ИТС-КС разд. 1.3.2]:

| Право | Константа Windows | Источник |
|---|---|---|
| Полные права на каталог данных кластера (`srvinfo` или `/d`) | — (NTFS) | [ИТС-КС разд. 1.3.2] |
| «Список содержимого папки» (List folder contents) на каталог временных файлов | — (NTFS) | [ИТС-КС разд. 1.3.2; ИТС-адм разд. 1.4.3] |
| «Вход в качестве службы» (Log on as a service) | `SeServiceLogonRight` | [ИТС-КС разд. 1.3.2; MS Learn] |
| «Вход в качестве пакетного задания» (Log on as a batch job) | `SeBatchLogonRight` | [ИТС-КС разд. 1.3.2; MS Learn] |
| Член группы «Пользователи журналов производительности» (Performance Log Users) | группа `S-1-5-32-559` [практика] | [ИТС-КС разд. 1.3.2] |

Если рабочие процессы и менеджеры запускаются от отдельных пользователей через `swpuser.ini` (раздел 3.5) [ИТС-адм прил. 3 разд. 3.29]:

- агент должен работать от пользователя из группы администраторов **и** с правами «Настройка квот памяти для процесса» (`SeIncreaseQuotaPrivilege`) и «Замена маркера уровня процесса» (`SeAssignPrimaryTokenPrivilege`); членство в администраторах этих прав не гарантирует [ИТС-адм прил. 3 разд. 3.29; MS Learn — константы];
- пользователям `rphost`/`rmngr` — права из таблицы выше и полный доступ к `%ALLUSERSPROFILE%\1C\1cv8`; у всех должен существовать **профиль** ОС (создать при заведении или однократным интерактивным входом, затем интерактивный вход можно запретить) [ИТС-адм прил. 3 разд. 3.29; ИТС-мет 5899, 2016].

Методичка по ЦКК добавляет: пользователь, от которого работает `rphost`, должен входить в группу «Пользователи системного монитора» (Performance Monitor Users) для сбора данных о загрузке оборудования [ИТС-мет 5899, 2016] — это **другая** группа, чем в требованиях документации; при использовании ЦКК добавляйте в обе [практика].

**Групповая политика затирает локальные назначения прав**: при следующем обновлении GPO доменные настройки «Назначения прав пользователей» перезаписывают локальные, а «Отказать во входе в качестве службы» сильнее «Входа в качестве службы» [MS Learn]. Если в домене эти политики заданы, добавляйте учётную запись службы 1С **в доменный GPO**, иначе через час-другой служба перестанет стартовать (см. «Типичные ошибки»).

### 3.3. Команды: создать пользователя и выдать права

Если пользователя не создавал установщик (PowerShell, локальный администратор) [практика]:

```powershell
# 1. Локальный пользователь без смены пароля
$pw = Read-Host -AsSecureString "Пароль для USR1CV8"
New-LocalUser -Name "USR1CV8" -Password $pw -PasswordNeverExpires -UserMayNotChangePassword `
    -Description "1C:Enterprise server service account"
# 2. Группа «Пользователи журналов производительности» по SID (имя группы локализовано)
Add-LocalGroupMember -SID "S-1-5-32-559" -Member "USR1CV8"
# 3. Каталог данных кластера и полные права (наследование на файлы и подкаталоги)
New-Item -ItemType Directory -Force "D:\1C\srvinfo" | Out-Null
icacls "D:\1C\srvinfo" /grant "USR1CV8:(OI)(CI)F"
```

Синтаксис `icacls … /grant <sid>:<perm>` и флаги `(OI)(CI)`, `F` — [MS Learn]. Права «Вход в качестве службы» и «Вход в качестве пакетного задания» выдаются в `secpol.msc` → «Локальные политики» → «Назначение прав пользователя» (путь `Computer Configuration\Windows Settings\Security Settings\Local Policies\User Rights Assignment`) или доменным GPO [MS Learn]. Оснастка «Службы» при назначении учётной записи службе выдаёт «Вход в качестве службы» автоматически, а `sc.exe`/`New-Service` — нет [практика] ⚠.

Проверка назначенных прав (права в выгрузке записаны SID-ами) [MS Learn — синтаксис `secedit`]:

```powershell
secedit /export /cfg C:\Temp\rights.inf /areas USER_RIGHTS
Select-String -Path C:\Temp\rights.inf -Pattern "SeServiceLogonRight|SeBatchLogonRight|SeIncreaseQuotaPrivilege|SeAssignPrimaryTokenPrivilege"
(New-Object System.Security.Principal.NTAccount("USR1CV8")).Translate([System.Security.Principal.SecurityIdentifier]).Value  # SID пользователя для сравнения
Remove-Item C:\Temp\rights.inf
```

### 3.4. Каталог временных файлов

- Сервер пишет временные файлы в **системный каталог временных файлов**; так как он общий, кластер при создании каждого файла даёт полные права на него только `USR1CV8` и запрещает доступ остальным [ИТС-КС разд. 2.2.9.4.3].
- Какой именно каталог считается «системным» для службы, документация не уточняет ⚠. На практике процесс службы, работающей от пользователя с загруженным профилем, использует `%TEMP%` профиля (`C:\Users\USR1CV8\AppData\Local\Temp`), а службы `LocalSystem` — `C:\Windows\Temp` [практика]. Проверьте после запуска, где растут файлы, и дайте пользователю службы право «Список содержимого папки» на этот каталог [ИТС-КС разд. 1.3.2].
- Сценарий из методички 5899 при перезапуске удаляет `C:\Windows\Temp\*.*`, сеансовые данные `<srvinfo>\reg_1541\snccntx*` и `C:\ProgramData\1C\1cv8\*.pfl` [ИТС-мет 5899, 2016]. Удалять сеансовые данные и временные файлы можно **только при полностью остановленном кластере** (иначе пропадут данные активных сеансов) и после проверки путей под своей установкой [практика]; `C:\Windows\Temp` — общий каталог других служб, чистить его целиком не советуем.

### 3.5. `swpuser.ini` на Windows

Файл лежит в каталоге данных кластера рядом со списком кластеров агента (т. е. в каталоге `/d`), формат [ИТС-адм прил. 3 разд. 3.29]:

```ini
user=<пользователь для rphost>
password=<пароль>
rmngr_user=<пользователь для rmngr>
rmngr_pass=<пароль>
registry=<каталог реестров кластеров>
1541:
user=<пользователь rphost только для кластера с менеджером на 1541>
password=<пароль>
```

- Доменное имя записывается как `\\имя-домена\имя-пользователя` [ИТС-адм прил. 3 разд. 3.29].
- Без `registry` реестр кластера — `reg_<порт>` в каталоге `/d`; с `registry` — `<registry>\reg_<порт>`, и пользователю `rmngr` нужны полные права на этот каталог [ИТС-адм прил. 3 разд. 3.29].
- Смена пользователя агента **должна** сопровождаться `swpuser.ini`, иначе все процессы кластера работают от администратора [ИТС-адм прил. 3 разд. 3.29]. Документация рекомендует запускать `rphost` от пользователя без доступа к каталогу данных кластера [ИТС-КС разд. 1.3.2].
- Установщик ничего для `swpuser.ini` не готовит: пользователей, права и профили создают вручную [ИТС-мет 5899, 2016]. Пароли в файле лежат открытым текстом — ограничьте права на файл администраторами и пользователем агента [практика].

| Имя службы, 32-разрядная платформа 8.3 | `1C:Enterprise 8.3 Server Agent` | [ИТС-КС разд. 4.2.3.2] |

При первом запуске агент без найденного реестра создаёт **кластер по умолчанию**: менеджер на 1541, диапазон 1560:1591, один рабочий процесс, порт `dbgs` 1550 при HTTP-отладке [ИТС-КС разд. 4.2.1].

Управление службой (PowerShell, администратор) [практика]:

```powershell
$svc = "1C:Enterprise 8.3 Server Agent (x86-64)"
Stop-Service -Name $svc            # остановка: агент сам гасит rmngr/rphost
Start-Service -Name $svc
Get-Process ragent, rmngr, rphost -ErrorAction SilentlyContinue | Select-Object Name, Id, StartTime, Path
```

В PowerShell пишите **`sc.exe`**, а не `sc`: `sc` — псевдоним `Set-Content` [практика]; Microsoft в справке тоже пишет `sc.exe` [MS Learn].

### 4.2. Ключи командной строки `ragent` (Windows)

Общий вид: `ragent /daemon /instsrvc /rmsrvc /start /stop /usr <…> /pwd <…> /port <…> /regport <…> /range <…> /seclev <…> /d <…> /pingPeriod <…> /pingTimeout <…> /debug -<…> /debugServerAddr <…> /debugServerPort <…> /debugServerPwd <…> /debugServerUsers <…>`; команда и значение разделяются пробелом [ИТС-адм прил. 4 разд. 4.12.1].

| Ключ | ОС | Смысл | По умолчанию |
|---|---|---|---|
| `/d <каталог>` | все | каталог данных сервера (список кластеров, реестры) | Windows: `%LOCALAPPDATA%\1C\1cv8` пользователя, от которого запущен агент; путь в кавычках без завершающего `\` |
| `/port <порт>` | все | порт агента; он же сетевой порт рабочего сервера, по нему подключается консоль | 1540 |
| `/regport <порт>` | все | порт главного менеджера кластера, создаваемого по умолчанию при первом запуске | 1541 |
| `/range <диапазоны>` | все | начальное значение «Диапазоны IP портов» рабочего сервера по умолчанию; можно несколько: `4549:4567, 7072:7790` | 1560:1591 |
| `/debug -tcp` \| `/debug -http` | все | кластер в режиме отладки; протокол | выкл.; при `/debug` без значения — `-tcp` |
| `/debugServerAddr`, `/debugServerPort`, `/debugServerPwd`, `/debugServerUsers` | все | адрес, порт (1550), пароль сервера отладки, файл пользователей отладки (приоритетнее пароля) | — / 1550 / нет / нет |
| `/seclev 0\|1\|2` | все | уровень защищённости соединений с агентом | 0 |
| `/pingPeriod`, `/pingTimeout` | все | контроль разрыва соединений, мс; настройки кластера (если ненулевые) приоритетнее | 1000 / 5000 |
| `/instsrvc` | W | зарегистрировать агент службой и завершиться; несовместим с `/rmsrvc`, `/start`, `/stop` | — |
| `/usr <имя>` | W | пользователь службы; только вместе с `/instsrvc` | — |
| `/pwd <пароль>` | W | пароль; только вместе с `/usr` и `/instsrvc` | — |
| `/rmsrvc` | W | снять регистрацию службы и завершиться | — |
| `/start`, `/stop` | W | запустить / остановить зарегистрированную службу и завершиться | — |
| `/daemon` | L | только Linux | — |

Источник таблицы — [ИТС-адм прил. 4 разд. 4.12.1]. Ключи `/srvc` и `/agent` в таблице документации **не описаны**, но стоят во всех примерах строки службы [ИТС-КС разд. 4.2.3.2, ИТС-адм прил. 4 разд. 4.12.2] — это служебные ключи, с которыми служба запускает `ragent`; руками их не набирают, кроме как в `binPath=` при регистрации через `sc.exe`. В примерах документации ключи пишутся через `/`; форма через `-` (`-port`) применяется в строках служб и на Linux [ИТС-адм прил. 4 разд. 4.12.1; ИТС-КС гл. 4] — что Windows-версия принимает обе формы, документация явно не говорит ⚠.

Рекомендации документации к `/pingPeriod`/`/pingTimeout`: таймаут в 3–10 раз больше периода, период не меньше 1000 мс, на всех серверах кластера одинаково [ИТС-адм прил. 4 разд. 4.12.1]. В 8.5.1 у `/regport` добавлено: при нескольких кластерах на компьютере порт главного менеджера у каждого должен быть уникальным, иначе менеджеры с одинаковым портом считаются одним кластером [конспект отличий 8.5.1, разд. 2.3].

### 4.3. Запуск агента как приложения

Для отладки и экспериментов (cmd от пользователя, у которого есть права на каталог) [ИТС-КС разд. 4.2.3.1]:

```bat
"C:\Program Files\1cv8\8.3.27.1688\bin\ragent.exe" /d "D:\1C\test-srvinfo" /port 1640 /regport 1641 /range 1660:1691 /debug -http
```

- Без `/d` каталогом данных будет `%LOCALAPPDATA%\1C\1cv8` запустившего пользователя [ИТС-КС разд. 2.2.13]. **Не запускайте приложением на тех же портах и с тем же `/d`, что у работающей службы.**
- Остановка — `Ctrl+C` [ИТС-адм прил. 4 разд. 4.12.1].
- Пример документации `ragent.exe /d "D:\Рабочий каталог\1C srvinfo\" /debug -HTTP` [ИТС-КС разд. 4.2.3.1] сам нарушает правило про завершающий `\` в кавычках из [ИТС-адм прил. 4 разд. 4.12.1] — не копируйте его буквально.

### 4.4. Ручная регистрация службы

**Способ А — штатный `/instsrvc`** (cmd, администратор; регистрирует **одну** службу со стандартным именем — несколько экземпляров так не завести [ИТС-КС разд. 4.3.3.2]):

```bat
"C:\Program Files\1cv8\8.3.27.1688\bin\ragent.exe" /instsrvc /usr .\USR1CV8 /pwd "<пароль>" /port 1540 /regport 1541 /range 1560:1591 /d "D:\1C\srvinfo"
"C:\Program Files\1cv8\8.3.27.1688\bin\ragent.exe" /start
```

- `/usr` и `/pwd` с `/instsrvc` — [ИТС-адм прил. 4 разд. 4.12.1]. Что `/port`, `/regport`, `/range`, `/d` при `/instsrvc` переносятся в строку службы, документация явно не говорит ⚠ — сразу проверьте `PathName` (раздел 2.4). Запись локальной учётной записи как `.\USR1CV8` — соглашение Windows [практика].
- Документация (cs 4.2.3.2) называет «командной строкой регистрации сервиса» строку `ragent /srvc /agent /d "…"` — это строка **запуска** службы, а не регистрации; регистрирует `/instsrvc` (расхождение, см. «Что не удалось подтвердить»).
- Права и пароль: пароль виден в истории команд — после регистрации закройте окно и не сохраняйте команду в скриптах; вводите через `Read-Host -AsSecureString` в PowerShell-обёртке [практика].

**Способ Б — `sc.exe create`** (образец `register-agent.bat` из документации; позволяет своё имя службы и несколько экземпляров) [ИТС-адм прил. 4 разд. 4.12.2; MS Learn — синтаксис `sc.exe create`]. Командная строка (cmd), администратор:

```bat
sc.exe create "1C:Enterprise 8.3 Server Agent 1540 8.3.27.1688" ^
  binPath= "\"C:\Program Files\1cv8\8.3.27.1688\bin\ragent.exe\" /srvc /agent /regport 1541 /port 1540 /range 1560:1591 /d \"D:\1C\srvinfo\"" ^
  start= auto obj= ".\USR1CV8" password= "<пароль>" ^
  DisplayName= "1C:Enterprise 8.3 Server Agent. Parameters: 8.3.27.1688, ragent port: 1540, rmngr port: 1541, range: 1560:1591" ^
  depend= Dnscache/Tcpip/Tcpip6/lanmanworkstation/lanmanserver
sc.exe start "1C:Enterprise 8.3 Server Agent 1540 8.3.27.1688"
```

- После каждого `ключ=` обязателен пробел; ключ пишется со знаком `=`; `obj=` по умолчанию — `LocalSystem`, при другом пользователе обязателен `password=`; зависимости — через `/` [MS Learn].
- Набор зависимостей `Dnscache/Tcpip/Tcpip6/lanmanworkstation/lanmanserver` взят из образца документации [ИТС-адм прил. 4 разд. 4.12.2].
- Образец документации добавляет в строку `/debug` — для боевого сервера уберите [ИТС-адм прил. 4 разд. 4.12.1]. Имя службы образец строит как `Server Agent <порт агента> <версия>` [ИТС-адм прил. 4 разд. 4.12.2], а глава о нескольких экземплярах — как `1C:Enterprise 8.3 Server Agent <порт> <версия>` [ИТС-КС разд. 4.3.3.3.1]; имя произвольное, главное — единообразие в своих скриптах.
- Право «Вход в качестве службы» `sc.exe` не выдаёт — проверьте (раздел 3.3).

**Способ В — PowerShell `New-Service`** (параметры `-Name`, `-BinaryPathName` — путь с пробелами в кавычках, аргументы после пути, `-DisplayName`, `-StartupType Automatic`, `-Credential`, `-DependsOn` [MS Learn]):

```powershell
$ver = "8.3.27.1688"
$bin = "`"C:\Program Files\1cv8\$ver\bin\ragent.exe`" /srvc /agent /regport 1541 /port 1540 /range 1560:1591 /d `"D:\1C\srvinfo`""
New-Service -Name "1C:Enterprise 8.3 Server Agent 1540 $ver" -BinaryPathName $bin -StartupType Automatic `
  -Credential (Get-Credential ".\USR1CV8") -DependsOn Dnscache,Tcpip,lanmanworkstation,lanmanserver
```

Проверка (любой способ) [практика]:

```powershell
Get-CimInstance Win32_Service -Filter "Name LIKE '1C:Enterprise 8.3 Server Agent%'" | Format-List Name, State, StartMode, StartName, PathName
Test-NetConnection -ComputerName localhost -Port 1540
```

### 4.5. Изменение параметров существующей службы

> **Перед изменением** остановите службу и скопируйте каталог данных (`srvinfo` или `/d`) — в нём реестр кластера со списком баз, администраторами, требованиями назначения функциональности. Если агент после правки не найдёт реестр в указанном каталоге, он молча создаст новый пустой кластер [ИТС-КС разд. 2.2.13].

```powershell
$svc = "1C:Enterprise 8.3 Server Agent (x86-64)"
Stop-Service -Name $svc
# Резервная копия описания службы и каталога данных
reg export "HKLM\SYSTEM\CurrentControlSet\Services\$svc" "C:\Backup\1c-agent-service.reg" /y
robocopy "C:\Program Files\1cv8\srvinfo" "C:\Backup\srvinfo-$(Get-Date -Format yyyyMMdd)" /E /COPY:DAT /R:1 /W:1
```

Команды `reg export` и `robocopy` — [практика]. Затем новая строка запуска — в `cmd` (в PowerShell кавычки внутри аргументов для внешних программ передаются ненадёжно [практика]):

```bat
sc.exe config "1C:Enterprise 8.3 Server Agent (x86-64)" binPath= "\"C:\Program Files\1cv8\8.3.27.1688\bin\ragent.exe\" /srvc /agent /regport 1541 /port 1540 /range 1560:1591 /d \"C:\Program Files\1cv8\srvinfo\""
sc.exe config "1C:Enterprise 8.3 Server Agent (x86-64)" obj= ".\USR1CV8" password= "<новый пароль>"
```

`sc.exe config` с ключами `binPath=`, `obj=`, `password=` — [MS Learn]. Альтернатива — значение `ImagePath` в `HKLM\SYSTEM\CurrentControlSet\Services\<имя службы>` (`Set-ItemProperty`) [практика]. После правки — `Start-Service` и проверка `PathName`, портов и списка баз в консоли.

Сменить **порты работающего экземпляра** нельзя: новый экземпляр с нужными портами → зарегистрировать в нём базы → перевести клиентов → остановить и удалить старый вместе с данными кластера [ИТС-КС разд. 4.3.3.5]. Правка `/port`/`/regport` в строке службы при существующем реестре этого не делает: `/regport` и `/range` задают параметры только кластера, **создаваемого по умолчанию** при первом запуске [ИТС-адм прил. 4 разд. 4.12.1].

### 4.6. Отладочный режим на сервере

- `/debug` снижает производительность — «использовать отладочный режим только для тех серверов, на которых выполняется отладка» [ИТС-адм прил. 4 разд. 4.12.1]. Если строка стандартной службы содержит `-debug`/`/debug` (раздел 2.4 ⚠), на боевом сервере удалите ключ через `sc.exe config … binPath=` и перезапустите службу в окно обслуживания.
- Пароль или список пользователей сервера отладки: `/debugServerPwd`, `/debugServerUsers` (файл описан в [ИТС-адм прил. 3 разд. 3.35]); документация советует надёжные пароли для сервера отладки [ИТС-КС прил. 3 разд. 3.11].
- `/debug -http`: кластер сам запускает `dbgs` на порту 1550 (`/debugServerPort` меняет) [ИТС-КС разд. 4.2.1, ИТС-адм прил. 4 разд. 4.12.1]. Отладка внешнего соединения (COM) включается файлом `comcntrcfg.xml` в каталоге конфигурационных файлов (только Windows): `<debugconfig debug="true" protocol="tcp" debuggerURL="tcp://localhost:1560"/>`; без порта перебирается диапазон 1560–1591, для HTTP порт обязателен (`http://pc-name:1561`) [ИТС-адм прил. 3 разд. 3.16].

### 4.7. Отмена регистрации службы

```bat
rem Стандартная служба — штатно
"C:\Program Files\1cv8\8.3.27.1688\bin\ragent.exe" /rmsrvc
rem Служба, созданная sc.exe (образец unregister-agent.bat)
sc.exe stop "1C:Enterprise 8.3 Server Agent 2540 8.3.27.1688"
sc.exe delete "1C:Enterprise 8.3 Server Agent 2540 8.3.27.1688"
```

`/rmsrvc` — [ИТС-адм прил. 4 разд. 4.12.1]; `sc stop` + `sc delete` — образец `unregister-agent.bat` [ИТС-адм прил. 4 разд. 4.12.3]. Если служба запущена или кто-то держит её дескриптор (открыта оснастка «Службы»), `sc delete` лишь помечает её на удаление [MS Learn] — закройте оснастку. Каталог данных при этом не удаляется — данные кластера сохраняются.

## 5. Сервер администрирования `ras` как служба Windows

Нужен для `rac`, стандартной обработки «Управление серверами», «1С:Центра администрирования» и других программ, работающих через `ras`; MMC-консоль работает с агентом напрямую и `ras` не требует (см. `../1c/03-administrirovanie-klastera-ras-rac.md`).

Командная строка (одинакова в Windows и Linux) [ИТС-адм прил. 4 разд. 4.13.1]:

`ras cluster --port=<port> --monitor-address=<address> --monitor-base=<location> --monitor-port=<port> <host[:port]>`

| Параметр | Смысл | По умолчанию |
|---|---|---|
| `cluster` | режим администрирования кластера (обязателен) | — |
| `<host[:port]>` | агент кластера | `localhost:1540` |
| `--port=<port>` (`-p`) | порт `ras` | 1545 |
| `--monitor-address=<address>` | интерфейс HTTP-шлюза монитора производительности: `localhost`, `any`, IPv4, IPv6 | `localhost` |
| `--monitor-port=<port>` | порт шлюза монитора | 1555 |
| `--monitor-base=<location>` | базовый путь публикации показателей, начинается с `/` | `/` |

Регистрация службой — образец `register-ras.bat` [ИТС-адм прил. 4 разд. 4.13.2] (cmd, администратор):

```bat
sc.exe create "1C:Enterprise 8.3 Remote Server 1545" ^
  binPath= "\"C:\Program Files\1cv8\8.3.27.1688\bin\ras.exe\" cluster --service --port=1545 localhost:1540" ^
  start= auto obj= ".\USR1CV8" password= "<пароль>" ^
  DisplayName= "1C:Enterprise 8.3 Remote Server. Parameters: 8.3.27.1688, port: 1545, cluster: localhost:1540"
sc.exe start "1C:Enterprise 8.3 Remote Server 1545"
```

- Образец называет службу `Remote Server <порт>`; методичка 5899 в своих сценариях — `1C:Enterprise 8.3 Remote Server` [ИТС-адм прил. 4 разд. 4.13.2; ИТС-мет 5899, 2016]. Установщик 1С службу `ras` **не создаёт** — документация описывает только регистрацию командным файлом [ИТС-КС разд. 5.3.3.2.2].
- Ключ `--service` есть в образце, но не в таблице параметров [ИТС-адм прил. 4 разд. 4.13.1–4.13.2]; полный список — `ras help` [ИТС-КС разд. 5.3.3.1].
- Отдельный пользователь для `ras` не обязателен: `ras` обращается к агенту по сети как клиент [практика]; можно использовать `USR1CV8`.
- Версия `ras` = версия кластера; `rac` 8.3.9+ работает с `ras` 8.3.9+, при более старой `rac` доступна только её функциональность [ИТС-КС разд. 5.3.3.1]. Останавливать `ras` при перезапуске кластера не нужно, **кроме смены версии** кластера [ИТС-КС разд. 5.3.3.1].
- Один `ras` работает с одним агентом; к кластеру можно подключить несколько `ras` [ИТС-КС разд. 5.3.3.1]. `rac` не поддерживает аутентификацию ОС для администраторов [ИТС-КС разд. 5.3.3.1].
- Шлюз монитора (`--monitor-*`, порт 1555) — HTTP-сервис метрик производительности [ИТС-адм прил. 6 разд. 6.4]; при `--monitor-address=any` откройте 1555 в брандмауэре только для системы мониторинга [практика].

Отмена регистрации (образец `unregister-ras.bat`): `sc.exe stop "<имя>"`, `sc.exe delete "<имя>"` [ИТС-адм прил. 4 разд. 4.13.3].

**Смешанная среда.** На Windows-машине администратора `rac.exe` из каталога `bin` той же сборки подключается к `ras` на Linux-сервере пользователя [ИТС-КС разд. 5.3.3.1]:

```powershell
& "C:\Program Files\1cv8\8.3.27.1688\bin\rac.exe" srv-1c-app:1545 cluster list
```

Синтаксис и параметры `rac` — `../1c/03-administrirovanie-klastera-ras-rac.md`; сверяйте с `rac help <режим>` своей версии.

## 6. Сервер хранилища конфигурации `crserver`

Ставится компонентом «Сервер хранилища конфигураций» [ИТС-адм разд. 2.6.3.6]; работает приложением или службой Windows [ИТС-разр гл. 37.4.5]. Командная строка Windows [ИТС-разр гл. 37.4.5.1]:

`crserver.exe -instsrvc | -rmsrvc -usr <пользователь> -pwd <пароль> -start | -stop -port <порт> -d <каталог>`

| Ключ | Смысл | По умолчанию |
|---|---|---|
| `-d` | корневой каталог хранилищ | `%LOCALAPPDATA%\1C\1Cv8\` |
| `-port` | рабочий порт | 1542 |
| `-instsrvc` / `-rmsrvc` | зарегистрировать / снять службу | — |
| `-usr`, `-pwd` | пользователь и пароль службы | — |
| `-start` / `-stop` | запустить / остановить службу | — |

- Имя службы: `1C:Enterprise 8 Configuration Repository Server` [ИТС-разр гл. 37.4.5.1].
- Пользователю службы нужны: право «Вход в систему как сервис», чтение каталога исполняемых файлов версии, **полные права** на корневой каталог хранилищ, а также чтение и запись файла `1Cv8DDB.1CD` и каталога `data` каждого хранилища [ИТС-разр гл. 37.4.3, 37.4.5.1]. Ключ и значение разделяются пробелом.
- Корневой каталог лучше держать на самом сервере хранилища: сетевые ресурсы поддерживаются, но медленнее [ИТС-разр гл. 37.4.7]. При первом запуске создаётся хранилище по умолчанию `maincr`.
- **Версии сервера хранилища и конфигуратора должны совпадать**, иначе работа невозможна [ИТС-разр гл. 37.4.6]. Для разных версий — отдельный экземпляр `crserver` на своём порту и, для HTTP, отдельный пул приложений IIS на каждую сборку [ИТС-разр гл. 37.4.4.4].
- Адрес для конфигуратора: `tcp://<сервер>/<относительный путь>` или `http://<веб-сервер>/<каталог>/<файл>.1ccr/<путь>`; без пути — хранилище `maincr` [ИТС-разр гл. 37.4.6]. Публикация через IIS (`wsisapi.dll`, файл `*.1ccr` с `connectString="tcp://…"`) — `03-veb-publikaciya-iis.md`.

```bat
"C:\Program Files\1cv8\8.3.27.1688\bin\crserver.exe" -instsrvc -usr .\USR1CV8 -pwd "<пароль>" -port 1542 -d "D:\1C\repo"
"C:\Program Files\1cv8\8.3.27.1688\bin\crserver.exe" -start
```

Второй экземпляр другой версии штатно службой не регистрируется (`-instsrvc` создаёт службу со стандартным именем) ⚠ — регистрируйте `sc.exe create` с `binPath=` вида `"\"…\crserver.exe\" -port 1642 -d \"D:\1C\repo-8.3.26\""` и проверяйте на стенде: какие ключи `crserver` нужны в строке службы, документация не описывает ⚠.

Расхождение: каталог хранилищ по умолчанию в таблице ключей — `%LOCALAPPDATA%\1C\1Cv8\`, а в разделах о подключении и создании хранилища — `%APPDATA%\1C\1Cv8\` и `%APPDATA%\1C\1Cv8\maincr` [ИТС-разр гл. 37.4.5.1, 37.4.6, 37.4.7]. Всегда задавайте `-d` явно.

## 7. Сервер отладки `dbgs`

Запускается приложением (любая ОС), «демоном» (Linux) или службой (только Windows) [ИТС-адм прил. 4 разд. 4.11.1]:

`dbgs --version|--help --service|--daemon --addr=<host> --port=<port>|--range=<range> --ownerPID=<PID> --password=<pwd> --notify=<file> --debugServerUsers=<file>`

- `--service` — признак работы службой Windows (несовместим с `--daemon`); `--port` обязателен (умолчания нет); при одновременных `--port` и `--range` действует `--range`; `--debugServerUsers` приоритетнее `--password` [ИТС-адм прил. 4 разд. 4.11.1].
- **Ограничение:** через `dbgs`, работающий службой или «демоном», отлаживаются файловые базы и **клиентские** предметы отладки клиент-серверных баз; **серверные** предметы клиент-серверных баз — нет [ИТС-адм прил. 4 разд. 4.11.1]. Для отладки серверного кода по HTTP используйте `dbgs`, который запускает сам кластер с `/debug -http` (порт 1550).

Регистрация службой — образец `register-dbgs.bat` [ИТС-адм прил. 4 разд. 4.11.2] (cmd, администратор):

```bat
sc.exe create "Debug Server 1550" ^
  binPath= "\"C:\Program Files\1cv8\8.3.27.1688\bin\dbgs.exe\" --service --port=1550" ^
  start= auto obj= ".\<пользователь отладки>" password= "<пароль>" ^
  DisplayName= "1C:Enterprise 8.3 Debug Server. Parameters: 8.3.27.1688, port: 1550"
sc.exe start "Debug Server 1550"
```

Если на этом же компьютере агент запущен с `/debug -http`, порт 1550 уже занят кластером — службе дайте другой порт [практика]. Проверка: адрес сервера отладки в браузере возвращает текст вида «1C:Enterprise 8.3 Debug Server … it works!» (см. `../its-docs/dev-gl31-otladka-oshibki-testirovanie.md`). Снятие — `sc.exe stop`/`sc.exe delete` (образец `unregister-dbgs.bat`) [ИТС-адм прил. 4 разд. 4.11.3].

Неточности образца: в `binPath` стоит `--port=%2%` (лишний `%` — в `bat`-файле одиночный `%` отбрасывается, на результат не влияет [практика]), а в описании примера версия `8.3.24.100` при запуске с `8.3.25.100` — опечатка [ИТС-адм прил. 4 разд. 4.11.2].

## 8. Несколько экземпляров и версий на одном компьютере

Обычно на сервере один агент; несколько агентов нужны редко — например, чтобы держать разные версии платформы [ИТС-КС разд. 4.3.1]. Условия параллельной работы агентов [ИТС-КС разд. 4.3.1]:

1. разные порты агентов;
2. разные каталоги служебных файлов (`/d`);
3. разные порты кластеров (главных менеджеров);
4. непересекающиеся диапазоны портов рабочих процессов, если сервер входит в разные кластеры (это нужно и при одном агенте с несколькими кластерами).

Особенности Windows [ИТС-КС разд. 4.3.3.1–4.3.3.2]:

- Второй экземпляр рекомендуется ставить **как приложение**, а службой регистрировать позже с нужными параметрами; установщик порты не меняет — сразу после установки второй экземпляр не заработает.
- Установщик всегда правит **одну** стандартную службу; несколько служб — только `sc.exe` (образец `register-agent.bat`).
- Для 32-разрядного сервера на 64-разрядной ОС в путях `C:\Program Files` → `C:\Program Files (x86)`.

План портов (по схеме `register-agent.bat`: параметр — первые две цифры) [ИТС-адм прил. 4 разд. 4.12.2]:

| Экземпляр | Версия | Агент | Менеджер | Рабочие процессы | Каталог `/d` | `ras` |
|---|---|---|---|---|---|---|
| Основной | 8.3.27.1688 | 1540 | 1541 | 1560:1591 | `D:\1C\cluster1` | 1545 → `localhost:1540` |
| Тестовый | 8.3.26.xxxx | 2540 | 2541 | 2560:2591 | `D:\1C\cluster2` | 2545 → `localhost:2540` |

Регистрация второго экземпляра службой (cmd, администратор) — по образцу из раздела 4.4 с другими портами и каталогом:

```bat
sc.exe create "1C:Enterprise 8.3 Server Agent 2540 8.3.26.xxxx" ^
  binPath= "\"C:\Program Files\1cv8\8.3.26.xxxx\bin\ragent.exe\" /srvc /agent /regport 2541 /port 2540 /range 2560:2591 /d \"D:\1C\cluster2\"" ^
  start= auto obj= ".\USR1CV8" password= "<пароль>" depend= Dnscache/Tcpip/Tcpip6/lanmanworkstation/lanmanserver
sc.exe create "1C:Enterprise 8.3 Remote Server 2545" ^
  binPath= "\"C:\Program Files\1cv8\8.3.26.xxxx\bin\ras.exe\" cluster --service --port=2545 localhost:2540" ^
  start= auto obj= ".\USR1CV8" password= "<пароль>"
```

Приложением (например, для краткого теста) [ИТС-КС разд. 4.3.3.3.2]:

```bat
start "Server 1" "C:\Program Files\1cv8\8.3.27.1688\bin\ragent.exe" /port 1540 /regport 1541 /range 1560:1590 /d d:\ClusterData\Srv1
start "Server 2" "C:\Program Files\1cv8\8.3.27.1688\bin\ragent.exe" /port 2540 /regport 2541 /range 2560:2590 /d d:\ClusterData\Srv2
```

Подключение клиентов ко второму кластеру — с указанием порта менеджера: `Srvr="<сервер>:2541";Ref="<база>";` (строка соединения — [ИТС-адм прил. 7 разд. 7.7.4]; в окне добавления базы — `<сервер>:2541`) [практика].

Ошибки в примерах документации (не копировать буквально):

- В разделе «одна версия как сервис» вторая служба названа `… Server Agent 1540 8.3.27.200`, хотя у неё порты 2540/2541 [ИТС-КС разд. 4.3.3.4.1] — по правилу образца должно быть `… 2540 …`.
- В разделе «одна версия как приложение» каталоги данных указаны как `/home/usr1cv8/.1cv8/1C/srv1` (Linux-пути), а в командах — `d:\ClusterData\Srv1` [ИТС-КС разд. 4.3.3.4.2].
- Примеры запуска приложением используют диапазоны `1560:1590`/`2560:2590`, а службы — `…:1591`/`…:2591` [ИТС-КС разд. 4.3.3.3]; на работу это не влияет.

**8.3 и 8.5 на одном сервере.** В 8.5 платформа ставится рядом с 8.3 [конспект V8Update в `../1c/01-arhitektura-versii-trebovaniya.md`], а стандартная служба 8.5 имеет другое имя (`1C:Enterprise 8.5 Server Agent (x86-64)`) [конспект отличий 8.5.1]. Значит, установщик 8.5 не должен трогать службу 8.3 ⚠ (явно не описано). Порты и каталоги — по тем же правилам: два кластера с одинаковым `/regport` 8.5.1 прямо запрещает [конспект отличий 8.5.1].

**Методичка 3413** («Запуск нескольких экземпляров сервера на одном компьютере», 2016) сегодня содержит только отсылку к документации платформы [ИТС-мет 3413, 2016] — актуальный текст в [ИТС-КС разд. 4.3].

## 9. Брандмауэр Windows

### 9.1. Какие порты открывать

Документация: открывать только порты, которые использует кластер (по протоколам TCP и UDP), при нескольких кластерах — порты всех; если пользователи ходят только через веб-сервер — оставить 80/443, а порты кластера закрыть; при переназначенных портах — управлять теми, что указаны в командных строках [ИТС-КС прил. 3 разд. 3.8].

| Порт | Процесс | Кому нужен доступ | Источник |
|---|---|---|---|
| 1540/TCP | `ragent` | клиенты, консоль MMC, другие серверы кластера | [ИТС-КС прил. 3 разд. 3.8] |
| 1541/TCP | `rmngr` (главный менеджер) | клиенты, другие серверы кластера | [ИТС-КС прил. 3 разд. 3.8] |
| 1560–1591/TCP | `rphost` (из диапазона берут порты и дополнительные менеджеры [практика]) | клиенты (доступ ко **всему** диапазону), серверы кластера | [ИТС-КС прил. 3 разд. 3.8] |
| 1545/TCP | `ras` | только администраторы и системы мониторинга | [ИТС-КС прил. 3 разд. 3.8] |
| 1550/TCP | `dbgs` (HTTP-отладка) | только разработчики, только на тестовых серверах | [ИТС-КС прил. 3 разд. 3.8] |
| 1542/TCP | `crserver` | конфигураторы разработчиков; при HTTP — веб-сервер | [ИТС-разр гл. 37.4.5.1] |
| 1555/TCP | шлюз монитора `ras` | система мониторинга, если `--monitor-address` не `localhost` | [ИТС-адм прил. 4 разд. 4.13.1] |
| 80, 443/TCP | IIS | пользователи веб-клиента и тонкого клиента по HTTP | [ИТС-КС прил. 3 разд. 3.8]; `03-…` |
| HASP License Manager | сетевой ключ | клиенты, если ключ сетевой | `05-licenzii-diagnostika-otlichiya-ot-linux.md` |

Документация упоминает UDP, но все перечисленные службы 1С работают по TCP; правила UDP для них не требуются [практика] ⚠. Исходящие соединения сервера к СУБД (MS SQL Server — `02-ms-sql-server-dlya-1c.md`; PostgreSQL — 5432) по умолчанию разрешены [практика].

### 9.2. Команды

PowerShell, администратор; правила в одной группе, чтобы их было легко найти и удалить. Синтаксис `New-NetFirewallRule` (`-DisplayName`, `-Direction`, `-Protocol`, `-LocalPort` со списком и диапазонами, `-RemoteAddress` с подсетью или диапазоном, `-Profile`, `-Action`, `-Group`) — [MS Learn]:

```powershell
$clients = "192.168.10.0/24"        # подсеть пользователей (подставьте свою)
$admins  = "192.168.20.10","192.168.20.11"
$g = "1C:Enterprise server"

New-NetFirewallRule -DisplayName "1C ragent/rmngr/rphost (TCP 1540,1541,1560-1591)" -Group $g `
  -Direction Inbound -Protocol TCP -LocalPort 1540,1541,1560-1591 -RemoteAddress $clients -Profile Domain,Private -Action Allow
New-NetFirewallRule -DisplayName "1C ras (TCP 1545)" -Group $g `
  -Direction Inbound -Protocol TCP -LocalPort 1545 -RemoteAddress $admins -Profile Domain,Private -Action Allow
# Только на сервере хранилища:
New-NetFirewallRule -DisplayName "1C crserver (TCP 1542)" -Group $g `
  -Direction Inbound -Protocol TCP -LocalPort 1542 -RemoteAddress $clients -Profile Domain,Private -Action Allow
# Только на тестовом сервере с HTTP-отладкой:
New-NetFirewallRule -DisplayName "1C dbgs (TCP 1550)" -Group $g `
  -Direction Inbound -Protocol TCP -LocalPort 1550 -RemoteAddress $admins -Profile Domain,Private -Action Allow
```

- Вместо открытия портов можно разрешать по программе (`-Program "C:\Program Files\1cv8\8.3.27.1688\bin\rphost.exe"`) [MS Learn], но после каждого обновления путь меняется — правила по портам удобнее [практика].
- При нескольких кластерах добавьте их порты (2540, 2541, 2560-2591, 2545 и т. д.) [ИТС-КС прил. 3 разд. 3.8].
- Профиль `Public` для сервера в домене не нужен; если сервер не в домене и сеть определилась как «Общественная», правила с `-Profile Domain,Private` не сработают — проверьте `Get-NetConnectionProfile` [практика].
- Альтернатива для `cmd`: `netsh advfirewall firewall add rule name="1C cluster" protocol=TCP dir=in localport=1540,1541,1560-1591 action=allow` [MS Learn — синтаксис `add rule`; перечисление портов через запятую — практика].

Проверка [практика]:

```powershell
Get-NetFirewallRule -Group "1C:Enterprise server" | Format-Table DisplayName, Enabled, Profile, Action
Get-NetFirewallRule -Group "1C:Enterprise server" | Get-NetFirewallPortFilter | Format-Table Protocol, LocalPort
# с клиентского компьютера:
Test-NetConnection -ComputerName <сервер> -Port 1540
Test-NetConnection -ComputerName <сервер> -Port 1560
```

Порт из диапазона слушается, только если на нём запущен рабочий процесс: ответ на 1560 есть, а на 1575 нет — это нормально; номер порта `rphost` видно в консоли кластера или командой `Get-NetTCPConnection -State Listen -OwningProcess (Get-Process rphost).Id` [практика].

### 9.3. Смешанная среда

На Windows-клиентах и машине администратора правила для 1С не нужны — они только инициируют соединения [практика]. Входящие порты открываются на Linux-сервере `srv-1c-app` (`ufw`/`nftables`) — `../1c/02-ustanovka-servera-ubuntu.md` и `../linux/08-set-ssh-firewall.md`. Клиент на Windows проверяет доступность тем же `Test-NetConnection srv-1c-app -Port 1541`.

## 10. Обновление платформы на сервере Windows

### 10.1. Порядок (по главе 6 «Клиент-серверного варианта»)

**Подготовка** (сколько угодно долго) [ИТС-КС гл. 6]:

1. Получить дистрибутивы сервера и клиента **одной** версии.
2. Права администратора на всех компьютерах кластера и права DBA для резервных копий.
3. Разместить дистрибутив клиента на сетевом ресурсе или веб-сервере (раздел 10.5).
4. Выполнить приёмочное тестирование новой версии с вашей конфигурацией.
5. Подготовить сценарии перерегистрации служб (Windows) — раздел 10.2.
6. Установить новую версию на все серверы кластера (как приложение или «для компьютера» без замены службы — см. 10.2).

**Само обновление** (минимальное время простоя) [ИТС-КС гл. 6]:

1. Запретить начало новых сеансов во всех базах кластера (`rac infobase update … --sessions-deny=on` — `../1c/03-administrirovanie-klastera-ras-rac.md`).
2. Убедиться, что есть свежие резервные копии баз **средствами СУБД** (MS SQL — `02-ms-sql-server-dlya-1c.md`).
3. Отключить пользователей; остановить кластер; выполнить подготовленные сценарии на **всех** серверах; запустить кластер.
4. Обновить публикации на веб-серверах (конфигуратор или `webinst`) и перезапустить веб-серверы — `03-veb-publikaciya-iis.md`.
5. Разрешить новые сеансы.

### 10.2. Как перевести службу на новую версию

| Способ | Когда | Как | Риски |
|---|---|---|---|
| А. Установщик сам | одна стандартная служба | при установке новой версии отметить сервер «как сервис», тот же пользователь и пароль — установщик переустановит службу на новую версию [ИТС-адм разд. 2.5.2.6] | параметры строки (свои порты, `/d`, удалённый `-debug`) могут вернуться к значениям установщика ⚠ — сохраните `PathName` до обновления и сверьте после |
| Б. `sc.exe config` | нестандартные службы, несколько экземпляров, полный контроль | новую версию ставить без службы; в окно обслуживания `Stop-Service` → `sc.exe config … binPath=` (новый путь `…\<новая версия>\bin\ragent.exe`, прочие ключи без изменений) → `Start-Service` | ошибка в кавычках — служба не стартует (см. «Типичные ошибки») |
| В. Новая служба | смена имени/схемы | `sc.exe create` новой, `sc.exe delete` старой (раздел 4.4, 4.7) | не забыть тот же `/d` — иначе новый пустой кластер [ИТС-КС разд. 2.2.13] |

Сценарий для способа Б (cmd, администратор; одна служба):

```bat
set SVC=1C:Enterprise 8.3 Server Agent (x86-64)
set NEW=8.3.27.1700
sc.exe qc "%SVC%" > C:\Backup\1c-agent-before-%NEW%.txt
sc.exe stop "%SVC%"
rem дождаться остановки; проверить, что процессов не осталось:
tasklist /FI "IMAGENAME eq rphost.exe"
sc.exe config "%SVC%" binPath= "\"C:\Program Files\1cv8\%NEW%\bin\ragent.exe\" /srvc /agent /regport 1541 /port 1540 /range 1560:1591 /d \"C:\Program Files\1cv8\srvinfo\""
sc.exe start "%SVC%"
sc.exe qc "%SVC%"
```

`sc.exe qc` (вывод конфигурации службы) — [практика]; `tasklist` с фильтром — по образцу [ИТС-мет 5899, 2016]. Если процессы не завершаются, документация методички останавливает их `taskkill /F /IM rphost.exe` (`rmngr.exe`, `ragent.exe`) [ИТС-мет 5899, 2016] — **это аварийное завершение**: делайте его только после запрета сеансов и отключения пользователей, иначе прервутся транзакции.

Проверка версии кластера после старта: в консоли MMC новой версии или `rac` новой версии (в выводе `rac server list`/`rac process list` видна версия процессов — ⚠ сверяйте с `rac help`), и вход тонким клиентом [практика].

### 10.4. Откат

Старую версию не удаляйте до конца стабилизации: откат = остановить службу → вернуть прежний `binPath=` (сохранённый вывод `sc.exe qc` или `.reg`) → запустить [практика]. Если после обновления выполнялась реструктуризация базы новой версией, откат платформы может потребовать восстановления базы из бэкапа ⚠ — проверяйте на копии.

### 10.5. Клиенты: доставка той же сборки (в том числе с Linux-сервера)

Версии клиента и сервера должны совпадать в точности; при несовпадении клиент ищет дистрибутив в порядке: `InstalledLocation` → `DistributiveLocation`/`CommonCfgLocation` → URL из исключения сервера (`PublishDistributiveLocation*` файла `conf.cfg` или `pubdst*` в `default.vrd`) → интернет-сервисы [ИТС-адм разд. 4.3.6.4]. Способы:

- **Сетевой каталог** `\\Server\1CDistr` с `1cescmn.cfg` (`DistributiveLocation=…`, `InstallComponents=…`) и подкаталогами `<версия>\Win64`: клиенты ставят новую версию сами, всегда в каталог по умолчанию; из общего файла при установке берётся только `InstallComponents`; `1cescmn.cfg` не кладут на компьютер пользователя [ИТС-адм разд. 2.7].
- **`conf.cfg` сервера** (`PublishDistributiveLocationWindows64=<URL zip-архива>`) — при любом клиент-серверном подключении тонкого клиента; кеш обновляется через 10 с после правки [ИТС-адм разд. 4.3.6.4, прил. 3 разд. 3.17.19]. **Смешанная среда:** настраивается на самом Linux-сервере кластера (`conf.cfg` в каталоге `conf` версии — `../1c/08-konfiguracionnye-fajly-kerberos-bezopasnost.md`), архив `windows64tc.zip` раздаётся по HTTP.
- **Каталог `distr`** расширения веб-сервера (`windows64tc.zip`, `windows32tc.zip`, `linux64tc.zip`, `macOS64tc.zip`); для IIS нужен MIME-тип `.zip` [ИТС-адм разд. 11.2.3].
- **Интернет-сервисы** (`InternetService`, `WebDistributiveLocation` в `1cestart.cfg`) [ИТС-адм разд. 11.2.5].
- **`1CEClientSetupMake.exe`** — самораспаковывающийся `1CEClientSetup.exe` с дистрибутивом и `1CEStart.cfg`; должен быть подписан двойной подписью (SHA1+SHA256) поставщика [ИТС-мет 4914, 2024].

Разрядность скачиваемого клиента в Windows выбирается по настройке разрядности базы/окна запуска, иначе — по разрядности запущенного клиента [ИТС-адм разд. 11.2.1]. Предварительная загрузка дистрибутива до обновления кластера — файл `ClientUpdate.cfg` (`Version`, `UpdateDate`, `PublishDistributiveLocation…`) [ИТС-адм прил. 3 разд. 3.15].

### 10.6. Автоудаление версий на сервере

- Устаревшей считается версия, после установки которой прошло больше `AutoUninstallVersionsAfter` дней (по умолчанию 90); удаляются только неиспользуемые версии, и в пределах каждой «третьей цифры» остаётся хотя бы одна сборка [ИТС-адм разд. 12.2.4, прил. 3 разд. 3.6.4].
- «Используемая» на Windows: указана в `Version`/`DefaultVersion` списков баз; **прописана в службе со стандартным именем**; используется в публикациях (`default.vrd` в `c:\inetpub\wwwroot`, `httpd.conf` Apache) [ИТС-адм разд. 12.2.4]. Сборка, на которую ссылается только нестандартная служба (`sc.exe create`), или публикация вне `c:\inetpub\wwwroot`, формально «не используется» ⚠ (вывод из текста документации).
- Удаление на Windows запускается из программы запуска пользователя (диалог «Запустить фоновое удаление»), через 2 минуты после начала работы и затем каждые 20 минут, по одной версии [ИТС-адм разд. 12.2.4].
- На сервере кластера задайте в `%ALLUSERSPROFILE%\1C\1CEStart\1cestart.cfg` или в `1cescmn.cfg`: `AutoUninstall=0`, либо `DontUninstallVersion=8.3.27.1688` (строк может быть несколько) [ИТС-адм прил. 3 разд. 3.6.3, 3.6.11]. У `AutoUninstall` приоритет у общего файла `1cescmn.cfg` [ИТС-адм прил. 3 разд. 3.6.3].

### 10.7. Переход 8.3 → 8.5 и исторические требования

- В 8.5 переименованы служба (`1C:Enterprise 8.5 Server Agent…`), COM-объекты (`V85.COMConnector`, `V85.Application`, `V85C.Application`) и User-Agent веб-сервиса (`1C+Enterprise/8.5`) [конспект отличий 8.5.1] — правьте сценарии мониторинга, обновления и обмены через COM.
- В техжурнале 8.5.1 свойства кода возврата провайдеров MS SQL названы `hResultMSOLEDBSQL19`, `hResultMSOLEDBSQL`, `hResultNC2012` и др. [конспект отличий 8.5.1] — для фильтров `logcfg.xml`.
- 8.3.11 требовал на старых ОС последний Service Pack и KB2999226 (или Visual C++ 2015); без них не работали COM-соединение и консоль кластера; при GPO-развёртывании методичка советовала заранее ставить `vc_redist.x86.exe`/`vc_redist.x64.exe` [ИТС-мет 5935, 2017]. Для Windows Server 2016+ и Windows 10/11 неактуально (UCRT встроен) [практика].

## 11. Удаление

### 11.1. Порядок

> Удаление платформы **не удаляет** информационные базы и, по смыслу документации, каталоги данных — но удаление «лишней» версии, на которую указывает служба, остановит сервер. Перед удалением: проверьте `PathName` всех служб 1С, сделайте копию каталога данных кластера (`srvinfo`/`/d`) и бэкап баз средствами СУБД.

1. Определить, какие версии используются [практика]:

```powershell
Get-CimInstance Win32_Service -Filter "PathName LIKE '%1cv8%'" | Select-Object Name, State, PathName
Get-ChildItem "C:\Program Files\1cv8" -Directory | Where-Object Name -match '^\d+\.\d+\.\d+\.\d+$'
```

2. Остановить сервер «1С:Предприятия» (и всё, что работает от удаляемой версии: `ras`, `crserver`, `dbgs`, IIS-пулы с её `wsisapi.dll`) [ИТС-КС разд. 7.2, ИТС-адм разд. 12.2.3].
3. «Панель управления» → «Программы и компоненты» → строка «1С:Предприятие 8 (A.B.C.D)» → «Удалить» [ИТС-КС разд. 7.2, ИТС-адм разд. 12.2.3]. Пакетно — `msiexec /x "<путь к .msi этой сборки>" /qn /L*v C:\Temp\1c-uninstall.log` [MS Learn]; по коду продукта (`ProductCode` из `setup.ini`) — `msiexec /x {<ProductCode>} /qn` [практика]; документация использует для удаления свойство `REMOVE=ALL` в образце скрипта [ИТС-адм прил. 3 разд. 3.10].
4. Удалить службы, созданные вручную (`sc.exe delete`, раздел 4.7) — установщик знает только стандартную; правила брандмауэра — `Remove-NetFirewallRule -Group "1C:Enterprise server"` [практика].
5. Дистрибутивы клиентов из `bin\distr` удаляются вместе с версией [ИТС-адм разд. 2.8.2.2]; библиотека значков `1ceunt.dll` разрегистрируется при удалении **последней** версии [ИТС-адм прил. 1 разд. 1.2.18].
6. Каталоги баз удаляйте вручную и только после проверки, что они не нужны; их строки — из списков баз [ИТС-адм разд. 12.1]. Каталог `srvinfo` с реестром кластера удаляйте, только если кластер больше не нужен (после копии) [практика].
7. Драйвер HASP — ярлык «Удаление драйвера защиты» в меню «Пуск» [ИТС-КС разд. 4.1].

### 11.2. Перенос сервера на другую машину (кратко)

Реестр кластера переносится копированием каталога данных при остановленном агенте на ту же версию платформы и с тем же `/d`/портами ⚠ (документация процедуру не описывает); надёжнее — новый кластер и регистрация баз заново (`rac infobase create … --create-database=no`, см. `../1c/03-administrirovanie-klastera-ras-rac.md`) [практика]. Встроенное хранилище двоичных данных переносится вместе с базой, иначе данные «теряются» [ИТС-КС разд. 5.4.1]. Перенос сервера с Windows на Linux — чек-лист `../1c/09-klient-linux-i-otlichiya-ot-windows.md`, раздел 12.

## Типичные ошибки (симптом → причина → решение)

| Симптом | Причина | Решение |
|---|---|---|
| Служба агента не стартует: «Служба не была запущена из-за сбоя при входе» (ошибка 1069) | у пользователя нет права «Вход в качестве службы»; сменился или истёк пароль; доменный GPO перезаписал локальные права [MS Learn] | выдать право в GPO/`secpol.msc`; обновить пароль `sc.exe config "<служба>" obj= ".\USR1CV8" password= "…"`; у `USR1CV8` включить «Срок действия пароля не ограничен» |
| После перерегистрации службы или смены пользователя в консоли пустой кластер, баз нет | агент не нашёл реестр в новом `/d` и создал новый кластер [ИТС-КС разд. 2.2.13] | остановить службу, вернуть прежний `/d` в `binPath=`; ошибочно созданный каталог удалить после копии |
| В установщике нет страницы выбора «как сервис» | установка «для пользователя» (`InstallForUsers`=2/3, нет прав администратора) или используется установщик «(x86-64) Сервер» не от администратора [ИТС-адм разд. 2.5.2.2, 2.5.2.6] | запустить `setup.exe` из сеанса администратора; проверить `InstallForUsers` в `1cestart.cfg` |
| Установщик не может запустить сервер в конце установки | не задан пароль пользователя службы [ИТС-КС разд. 3.1.5.2.2] | задать пароль; при необходимости `ragent /instsrvc /usr … /pwd …` |
| Второй экземпляр сервера после установки не работает | установщик не меняет порты, конфликт с первым [ИТС-КС разд. 4.3.3.1] | регистрировать вручную с другими портами и `/d` (раздел 8) |
| Два кластера на одном компьютере ведут себя непредсказуемо | одинаковый порт главного менеджера (`/regport`) [конспект отличий 8.5.1] | уникальный `/regport` каждому кластеру |
| Клиент соединяется с 1540/1541, но висит или пишет о недоступности сервера | открыты 1540/1541, но закрыт диапазон 1560–1591 [ИТС-КС прил. 3 разд. 3.8] | открыть весь диапазон рабочих процессов |
| В PowerShell `sc create …` «ничего не делает» / появился файл `create` | `sc` — псевдоним `Set-Content` [практика] | писать `sc.exe` |
| Служба, созданная `sc.exe`, падает сразу при старте или не находит файл | ошибка в кавычках `binPath=`: путь с пробелами без `\"…\"`, путь `/d` в кавычках заканчивается на `\` [ИТС-адм прил. 4 разд. 4.12.1; MS Learn] | проверить `PathName` (`Get-CimInstance Win32_Service`); пересоздать в `cmd` |
| `regsvr32`: `DllRegisterServer failed with error code 0x80070005` | нет прав на реестр/`System32` [ИТС-адм разд. 2.5.3] | «Запуск от имени администратора» |
| Внешнее соединение: «Версия компоненты не соответствует…» после обновления | COM-соединение требует точно той же версии [ИТС-адм разд. 2.5.3] | перерегистрировать COM-компоненту нужной версии (⚠ `comcntr.dll`) или подключаться с машины с нужной сборкой |
| Консоль MMC не подключается к серверу новой версии | зарегистрирована оснастка старой версии [ИТС-адм разд. 4.1.3] | поставить ту же сборку и выполнить «Регистрация утилиты администрирования серверов (A.B.C.D)» |
| `rac` после обновления выдаёт ошибки или не видит новых свойств | служба `ras` осталась на старой версии [ИТС-КС разд. 5.3.3.1] | перевести `ras` на новую версию и перезапустить |
| Конфигуратор не подключается к хранилищу `tcp://…` | версии `crserver` и конфигуратора различаются; закрыт 1542 [ИТС-разр гл. 37.4.6] | выровнять версии; открыть порт |
| Отладка серверного кода через сервер отладки не останавливается на точках | `dbgs` работает службой — серверные предметы не отлаживаются [ИТС-адм прил. 4 разд. 4.11.1] | на тестовом сервере агент с `/debug -http` (dbgs от кластера, порт 1550) |
| С сервера пропала старая сборка платформы | автоудаление: сборка считалась неиспользуемой [ИТС-адм разд. 12.2.4] | `AutoUninstall=0` или `DontUninstallVersion` |
| Рабочие процессы не стартуют после ввода `swpuser.ini` | у агента нет `SeIncreaseQuotaPrivilege`/`SeAssignPrimaryTokenPrivilege`; у пользователей `rphost` нет профиля или прав на `%ALLUSERSPROFILE%\1C\1cv8` [ИТС-адм прил. 3 разд. 3.29] | выдать права, один раз войти под пользователями, проверить ACL |
| `netsh … dynamicport tcp start=10000 num=64510` — «Параметр задан неверно» | конец диапазона > 65535 [MS Learn] | `num=55536` |
| Windows-клиент не работает с Linux-сервером: «версия клиента не соответствует версии сервера» | клиент не нашёл нужную сборку [ИТС-адм разд. 4.3.6.4] | `PublishDistributiveLocationWindows64` в `conf.cfg` Linux-сервера или сетевой каталог `1cescmn.cfg` (раздел 10.5) |

## Быстрая шпаргалка — задача → команда

| Задача | Команда (администратор) |
|---|---|
| Тихая установка сервера через `setup.exe` | заполнить `%ALLUSERSPROFILE%\1C\1CEStart\1cestart.cfg` (UTF-16LE, `InstallComponents=… SERVER=1 SERVERCLIENT=1 …`), затем `setup.exe /S` |
| Тихая установка MSI с логом | `msiexec /i "<пакет>.msi" /qn /norestart /L*v C:\Temp\1c.log TRANSFORMS=1049.mst SERVER=1 SERVERCLIENT=1 DESIGNERALLCLIENTS=0 THINCLIENT=0 WEBSERVEREXT=0 CONFREPOSSERVER=0 CONVERTER77=0 LANGUAGES=RU` (свойства ⚠) |
| Создать пользователя службы | `New-LocalUser -Name USR1CV8 -Password (Read-Host -AsSecureString) -PasswordNeverExpires`; `Add-LocalGroupMember -SID S-1-5-32-559 -Member USR1CV8` |
| Права на каталог данных | `icacls "D:\1C\srvinfo" /grant "USR1CV8:(OI)(CI)F"` |
| Проверить права входа | `secedit /export /cfg C:\Temp\r.inf /areas USER_RIGHTS` + `Select-String SeServiceLogonRight` |
| Зарегистрировать стандартную службу | `ragent.exe /instsrvc /usr .\USR1CV8 /pwd "<пароль>" /port 1540 /regport 1541 /range 1560:1591 /d "D:\1C\srvinfo"` |
| Запуск/остановка стандартной службы | `ragent.exe /start` / `ragent.exe /stop` или `Start-Service`/`Stop-Service "1C:Enterprise 8.3 Server Agent (x86-64)"` |
| Снять стандартную службу | `ragent.exe /rmsrvc` |
| Своя служба агента | `sc.exe create "<имя>" binPath= "\"…\ragent.exe\" /srvc /agent /regport 2541 /port 2540 /range 2560:2591 /d \"D:\1C\cluster2\"" start= auto obj= ".\USR1CV8" password= "…"` |
| Посмотреть строку службы | `Get-CimInstance Win32_Service -Filter "Name LIKE '1C:Enterprise%'" \| Select Name, StartName, PathName` |
| Перевести службу на новую сборку | `sc.exe config "<служба>" binPath= "\"C:\Program Files\1cv8\<новая>\bin\ragent.exe\" /srvc /agent …"` |
| Сменить пароль службы | `sc.exe config "<служба>" obj= ".\USR1CV8" password= "<новый>"` |
| Удалить службу | `sc.exe stop "<служба>"`; `sc.exe delete "<служба>"` |
| `ras` службой | `sc.exe create "1C:Enterprise 8.3 Remote Server 1545" binPath= "\"…\ras.exe\" cluster --service --port=1545 localhost:1540" start= auto obj= … password= …` |
| `rac` с Windows к Linux-серверу | `& "C:\Program Files\1cv8\<версия>\bin\rac.exe" srv-1c-app:1545 cluster list` |
| Сервер хранилища службой | `crserver.exe -instsrvc -usr .\USR1CV8 -pwd "…" -port 1542 -d "D:\1C\repo"`; `crserver.exe -start` |
| Сервер отладки службой | `sc.exe create "Debug Server 1550" binPath= "\"…\dbgs.exe\" --service --port=1550" start= auto obj= … password= …` |
| Открыть порты кластера | `New-NetFirewallRule -DisplayName "1C cluster" -Group "1C:Enterprise server" -Direction Inbound -Protocol TCP -LocalPort 1540,1541,1560-1591 -RemoteAddress <подсеть> -Action Allow` |
| Проверить порт с клиента | `Test-NetConnection -ComputerName <сервер> -Port 1541` |
| Что слушает сервер | `Get-NetTCPConnection -State Listen -LocalPort 1540,1541,1545` |
| Зарегистрировать консоль MMC нужной версии | ярлык «Регистрация утилиты администрирования серверов (A.B.C.D)» (`RegMSC.cmd` в `bin`) |
| Перерегистрировать COM-соединение | `regsvr32 "C:\Program Files\1cv8\<версия>\bin\comcntr.dll"` (⚠ имя файла) |
| Выключить автоудаление версий | `AutoUninstall=0` или `DontUninstallVersion=<сборка>` в `1cestart.cfg`/`1cescmn.cfg` |
| Удалить версию платформы | «Программы и компоненты» → «1С:Предприятие 8 (A.B.C.D)»; пакетно `msiexec /x "<пакет>.msi" /qn` |
| Исключения Defender | `Add-MpPreference -ExclusionPath "C:\Program Files\1cv8\srvinfo"` |
| Диапазон динамических портов | `netsh int ipv4 show dynamicport tcp`; `netsh int ipv4 set dynamicport tcp start=10000 num=55536` |

## Что не удалось подтвердить

1. **Windows Server 2025** — нет в документации 8.3.27/8.5.1 и на v8.1c.ru (19.10.2026).
2. **Стартовая строка стандартной службы** от установщика (`-srvc -agent … -d "…\srvinfo" -debug`) — по наблюдениям сообщества; есть ли там `-debug` — не подтверждено.
3. **Ключи `/srvc`, `/agent`** не описаны; принимает ли Windows-версия ключи через `/` и `-` — не сказано.
4. **`ragent /instsrvc`**: попадают ли `/port`, `/regport`, `/range`, `/d` в строку службы, какое имя у службы. Пример cs 4.2.3.2 (`ragent /srvc /agent /d …` как «регистрация») по таблице ключей неточен.
5. **Тихая установка**: ставит ли `setup.exe /S` сервер службой; ключи `InstallComponents` как свойства MSI в 8.3 (образец для 8.2), свойства для пользователя службы; ключи «Liberica JRE», «Дополнительные функции администрирования», «Контроль целостности»; имя `.msi`; значения `ALLUSERS`.
6. **`comcntr.dll`** — имя в документации 8.3.27 не названо.
7. **Каталог временных файлов** службы под `USR1CV8` не уточнён.
8. **Виртуальные учётные записи и gMSA** для агента 1С не описаны и не проверены.
9. **Право «Вход в качестве службы»**: выдаётся оснасткой «Службы», но не `sc.exe`/`New-Service` — практика.
10. **Второй экземпляр `crserver` службой** через `sc.exe` — ключи строки службы не описаны.
11. **Переустановка стандартной службы установщиком** — сохраняет ли свои порты, `/d`, ключи.
12. **8.5 рядом с 8.3 на Windows** — не трогает ли установщик 8.5 службу 8.3; каталог установки 8.5.
13. **Автоудаление** сборок, используемых только нестандартными службами или публикациями вне `c:\inetpub\wwwroot`, — вывод из текста.
14. **Методички**: `MaxFreeTcbs`, `MaxUserPort`, AFD Dynamic Backlog на 2016+; `SynAttackProtect` на современных ОС; IPv4/IPv6; RC4 в 2016+; статус `wmic` — по Microsoft не сверялись.
15. **UDP** для служб 1С («TCP и UDP» в документации) — по практике не нужен.
16. **Перенос реестра кластера** копированием каталога данных — не описан.
