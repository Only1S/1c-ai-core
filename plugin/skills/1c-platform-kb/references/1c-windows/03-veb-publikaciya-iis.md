## Кратко — главные факты и команды

1. IIS для 1С — роль «Веб-сервер (IIS)» плюс **обязательно** «Расширения ISAPI» [ИТС-адм разд. 8.2]: `Install-WindowsFeature -Name Web-Server,Web-ISAPI-Ext,Web-ISAPI-Filter,Web-Windows-Auth,Web-Http-Tracing -IncludeManagementTools`; на Windows 10/11 — `Enable-WindowsOptionalFeature -Online -All -FeatureName IIS-WebServerRole,IIS-WebServer,IIS-ISAPIExtensions,…` [MS Learn; ИТС-мет 5977, 2020].
2. Модуль 1С для IIS — `wsisapi.dll` в `bin` версии [ИТС-разр гл. 37.4.4.2], компонент установщика «Модули расширения веб-сервера» (`WEBSERVEREXT=1`) [ИТС-адм разд. 2.5.2.4, прил. 3.6.12]; ставить «для компьютера» [практика].
3. **Версия модуля = версия кластера** (все четыре цифры) [ИТС-адм разд. 8.3.1]; модули, различающиеся 3-й/4-й цифрой, в одном пуле не уживаются — пул на версию [ИТС-адм разд. 8.10.2.2]. Разрядность модуля = разрядность IIS; 32-разрядный модуль в 64-разрядном IIS — только с `enable32BitAppOnWin64=true` [ИТС-адм разд. 8.3.1, 8.10.2.1].
4. Публикация — конфигуратор «Администрирование → Публикация на веб-сервере…» или `webinst`, **от имени администратора**; конфигурация не пустая, 1С стоит на хосте IIS [ИТС-адм разд. 8.2, прил. 4.14].
5. `webinst [-publish]|-delete <веб-сервер> -wsdir … -dir … -connstr … -confpath … -descriptor … [-osauth]`; для IIS — `-iis`, `-osauth` только для IIS [ИТС-адм прил. 4.14]. Пример: `webinst -publish -iis -wsdir demo -dir "C:\inetpub\wwwroot\demo" -connstr "Srvr=srv-1c-app;Ref=demo;"`.
6. Публикация всегда идёт в **Default Web Site / DefaultAppPool** [ИТС-адм разд. 8.2]; свой пул — переносом приложения после публикации (`appcmd set app … /applicationPool:…`).
7. Каталог публикации должен существовать, не может быть самим `%SYSTEMDRIVE%\inetpub\wwwroot`, в кавычках — без завершающего `\` [ИТС-адм прил. 4.14]. Лучше подкаталог `C:\inetpub\wwwroot\<имя>`: только там автоудаление версий видит, что версия нужна IIS [ИТС-адм разд. 12.2.4].
8. Пул: «Без управляемого кода» [ИТС-адм разд. 8.2]; файловая база — ровно 1 рабочий процесс [ИТС-адм разд. 8.10.2.2]; клиент-серверная база на 8.3.26+ — ~1 рабочий процесс IIS на ~100 сеансов [ИТС-мет 6034, 2025].
9. Права: `IIS_IUSRS` — чтение `bin` версии; файловая база — изменение каталога базы [ИТС-адм разд. 8.4.3.2.1]; каталог `temp` из `default.vrd` — полный доступ [ИТС-адм прил. 3.21.2].
10. Лимиты IIS по умолчанию: тело 30 000 000 байт (~28,6 МБ), URL 4096, строка запроса 2048 → 404.13/404.14/404.15; http.sys режет **сегмент** пути длиннее 260 символов (`UrlSegmentMaxLength`) [MS Learn; ИТС-адм разд. 8.10.2.4].
11. HTTPS: сертификат в `Cert:\LocalMachine\My`, привязка `New-IISSiteBinding … -Protocol https` [MS Learn; ИТС-мет 5977]; 1С — TLS 1.0–1.3, поля сертификата только US-ASCII/Punycode [ИТС-адм разд. 8.9.2]. Рецепт ИТС с параметром `DisableByDefault` [разд. 8.10.2.5] устарел: у Microsoft — `DisabledByDefault`; TLS 1.2 включён по умолчанию начиная с Windows 8 / Server 2012 [MS Learn, «Protocols in TLS/SSL (Schannel SSP)», сверено 20.10.2026 при проверке `iis/02`]; TLS 1.0/1.1 в Windows Server 2025 по той же таблице (ред. 20.03.2025) ещё **включены** — отключение 2024 года касалось только сборок Insider ⚠ (на своём сервере проверьте фактическое состояние, см. `../iis/02-…`, раздел 3.2).
12. Аутентификация Windows: флажок «Использовать аутентификацию операционной системы» / `-osauth`; в IIS — анонимная **выкл.**, Windows **вкл.**, первым поставщиком Negotiate, `iisreset`; имя пользователя ОС в 1С — `\\` + значение `DstUserName2` из события `CONN` техжурнала [ИТС-мет 5944, 2018].
13. IIS и сервер 1С на разных машинах — делегирование Kerberos от учётной записи компьютера IIS, сервер 1С под доменной учётной записью; тонкий клиент — с 8.3.10.2620 [ИТС-мет 5944]. AD — статья 04.
14. **Смешанная среда пользователя** (IIS на Windows + кластер на Ubuntu): Linux-сервер 1С принимает аутентификацию ОС только по Kerberos [`../1c/08`, `../1c/09`] — через IIS только с делегированием к SPN `usr1cv8` ⚠. Без такой нужды штатнее Apache 2.4 на Linux (`../1c/05`).
15. Сервисы и OData через `webinst` — только по шаблону `-descriptor` [ИТС-адм разд. 8.5.3.2.3, 8.6.3.2.3, 8.7.3.2.3]; сервисы расширений по умолчанию **не** публикуются, без `<standardOData>` OData выключен [ИТС-адм прил. 3.21.3, 3.21.4, 3.21.11].
16. С 8.3.26 при OpenID сохранение входа по умолчанию выключено — включить в настройках аутентификации базы [ИТС-мет 6029, 2026] и `<authentication allowSaveForReauthentication="true">` [ИТС-адм прил. 3.21.15].
17. Автообновление тонкого клиента через IIS требует MIME-типа `.zip` (`application/x-zip-compressed` или `application/zip`) [ИТС-адм разд. 8.10.2.6].
18. Безликая «500» → «Подробные сообщения об ошибках» [ИТС-адм разд. 8.10.2.3]; журналы — `%SystemDrive%\inetpub\logs\LogFiles\W3SVC<id>`, FREB — `…\FailedReqLogFiles\W3SVC<id>\fr*.xml` [MS Learn]. 503 — пул остановлен (5 падений за 5 мин) или очередь >1000; 404.2 — модуль не разрешён в «Ограничениях ISAPI и CGI» [MS Learn].
19. «Не удалось выполнить проверку отзыва сертификата» → журнал CAPI2, доступ к CRL; `IgnoreServerCertificatesChainRevocationSoftFail` (в 8.3.27 по умолчанию `true`) [ИТС-мет 5949, 2018; ИТС-адм прил. 3.17.16].
20. Apache под Windows: `-apache24`, служба `Apache2.4`; аутентификация ОС — только на IIS [ИТС-адм разд. 8.10.1.2.3, прил. 4.14]. В 8.5.x глава 8 не изменилась; служба Windows — `1C:Enterprise 8.5 Server Agent`, User-Agent веб-сервисов — `1C+Enterprise/8.5`; в 8.5.4 остался только Apache 2.4 [`../its-docs/otlichiya-8.5.1-ot-8.3.27.md`, `../1c/05`].

## 1. Архитектура и место IIS

### 1.1. Как идёт запрос

```
Браузер / тонкий клиент / мобильный клиент / внешняя система (SOAP, REST, OData)
        │  HTTP(S) :80/:443
        ▼
http.sys (ядро Windows: TLS, ограничения длины URL и заголовков, очередь пула)
        ▼
w3wp.exe — рабочий процесс пула приложений IIS
        │  фильтрация запросов, аутентификация IIS (анонимная / Basic / Windows)
        │  обработчик «*» → ISAPI-модуль wsisapi.dll из bin нужной версии 1С
        ▼
расширение веб-сервера 1С: читает default.vrd, держит пул соединений с кластером
        │  TCP: агент 1540, менеджер 1541, рабочие процессы 1560–1591 (умолчания)
        ▼
кластер серверов 1С (rphost) ──► СУБД (MS SQL / PostgreSQL)
```

- Публикация: регистрируется модуль обработки запросов веб-сервера, на веб-сервере регистрируется виртуальное приложение, создаётся каталог приложения с файлом `default.vrd`; для файловой базы дополнительно выдаются права на каталог базы [ИТС-адм разд. 8.3.1].
- Для клиент-серверной базы расширение веб-сервера — это клиент кластера: при новом сеансе берёт любое свободное соединение из своего пула, при продолжении сеанса ищет соединение с тем же рабочим процессом, через который шёл прошлый вызов [ИТС-КС разд. 2.2.7.2.2]. Состояние сеанса живёт в кластере, а не в `w3wp`, — поэтому несколько рабочих процессов IIS для клиент-серверной базы допустимы (раздел 12).
- В консоли кластера такие соединения видны с назначением `WebServerExtension` (веб-клиент, тонкий клиент через веб-сервер, мобильный клиент, интернет-сервис) [ИТС-КС разд. 2.2.7.4].
- Для **файловой** базы с файлом базы работает само расширение веб-сервера, запросы разных клиентов выполняются последовательно, каждый рабочий процесс веб-сервера держит свой экземпляр расширения [ИТС-адм разд. 8.2].
- Порты кластера по умолчанию: агент 1540, менеджер 1541, диапазон 1560:1591 для рабочих процессов и дополнительных менеджеров [ИТС-КС разд. 2.2.2]. Хост IIS должен достучаться до всех трёх.

### 1.4. Смешанная среда: IIS на Windows, кластер 1С на Ubuntu

Кластер пользователя — `srv-1c-app` (Ubuntu), СУБД — `srv-1c-db`, рабочие места — Windows. Модуль 1С на Windows — обычный клиент кластера, поэтому IIS в такой схеме возможен, но:

1. **Где публиковать.** Штатно — Apache 2.4 на Linux (`../1c/05`): одна ОС и одна сборка с кластером. IIS оправдан, если нужен вход по доменной учётной записи без пароля или корпоративный стандарт требует IIS [практика].
2. **Одна сборка.** `wsisapi.dll` — ровно той же версии, что кластер [ИТС-адм разд. 8.3.1]: при обновлении `srv-1c-app` в тот же день — Windows-дистрибутив той же сборки, новый пул, перепривязка публикации (раздел 4.7).
3. **Сеть.** С хоста IIS к `srv-1c-app` открыть TCP 1540, 1541, 1560–1591 (в `ufw`); проверка — `Test-NetConnection srv-1c-app -Port 1541` [ИТС-КС разд. 2.2.2; практика]. Имя сервера должно разрешаться с Windows-хоста; нестандартный порт менеджера — `Srvr=srv-1c-app:1741` [ИТС-адм разд. 8.3.3.2].
4. **Аутентификация ОС.** Linux-сервер 1С — только Kerberos [`../1c/08`, `../1c/09`]: NTLM через IIS не пройдёт, Kerberos — только с делегированием от хоста IIS к SPN `usr1cv8` (раздел 10.4, ⚠).
5. **Лицензии.** Для клиент-серверной базы лицензию веб-клиенту выдаёт кластер, ключ на хосте IIS нужен только для опубликованной на нём **файловой** базы [ИТС-мет 3596, 2009; ⚠ программные лицензии — статья 05].
6. **СУБД не участвует**: IIS ходит только в кластер; базы сервисов (GlitchTip, Redmine, NetBox) к публикации не относятся и в кластер «PostgreSQL для 1С» не кладутся.

## 2. Установка IIS: роли и компоненты

### 2.1. Что нужно и зачем

Звёздочкой отмечено то, что Microsoft ставит по умолчанию вместе с ролью «Веб-сервер (IIS)» [MS Learn, «Installing IIS 8.5 on Windows Server 2012 R2», таблица модулей; имена не менялись в IIS 10.0 — ⚠ сверьте `Get-WindowsFeature Web-*` на своём сервере].

| Компонент (рус. / англ.) | PowerShell (`Install-WindowsFeature`) | DISM (`Enable-WindowsOptionalFeature`) | Для 1С |
|---|---|---|---|
| Веб-сервер (IIS)* / Web Server Role | `Web-Server` | `IIS-WebServerRole` | обязательно |
| Веб-сервер* / Web Server | `Web-WebServer` | `IIS-WebServer` | обязательно |
| Ведение журнала HTTP* | `Web-Http-Logging` | `IIS-HttpLogging` | обязательно для диагностики [ИТС-мет 5899, 2016: «сбор access и error логов IIS»] |
| Трассировка / Tracing | `Web-Http-Tracing` | `IIS-HttpTracing` | рекомендуется: трассировка неудачных запросов (FREB) |
| Фильтрация запросов* / Request Filtering | `Web-Filtering` | `IIS-RequestFiltering` | ставится всегда; лимиты — раздел 8 |
| Расширения ISAPI / ISAPI Extensions | `Web-ISAPI-Ext` | `IIS-ISAPIExtensions` | **обязательно** [ИТС-адм разд. 8.2] |
| Фильтры ISAPI / ISAPI Filters | `Web-ISAPI-Filter` | `IIS-ISAPIFilter` | ставится по ИТС-мет 5977; модуль 1С — расширение, а не фильтр, ⚠ строгой необходимости в фильтрах не найдено |
| Проверка подлинности Windows | `Web-Windows-Auth` | `IIS-WindowsAuthentication` | если нужен вход по учётной записи Windows |
| Консоль управления IIS* | `Web-Mgmt-Console` | `IIS-ManagementConsole` | обязательно для ручной настройки |

По желанию [MS Learn — имена; назначение для 1С — практика]: `Web-Basic-Auth` (Basic на уровне IIS — обычно не нужна, 1С сама запрашивает Basic при анонимном доступе, раздел 10.1), `Web-IP-Security` (закрыть `/hs/`, `/odata/` от внешних адресов), `Web-Dyn-Compression` (раздел 12.3), `Web-Http-Redirect` (раздел 9.4), `Web-Scripting-Tools` (модуль `WebAdministration` ⚠). **Не нужны**: `Web-Asp-Net45`, `Web-Net-Ext45` — пул 1С без управляемого кода [ИТС-адм разд. 8.2]; `Web-DAV-Publishing` не ставить ⚠ (по практике WebDAV перехватывает PUT/DELETE, нужные HTTP-сервисам).

### 2.2. Команды установки и проверки

Windows Server 2016/2019/2022/2025, PowerShell от имени администратора [MS Learn: командлет требует повышения прав, средства управления ставятся только с `-IncludeManagementTools`]:

```powershell
Install-WindowsFeature -Name Web-Server, Web-ISAPI-Ext, Web-ISAPI-Filter, Web-Windows-Auth, Web-Http-Tracing -IncludeManagementTools
# Проверка: что установлено
Get-WindowsFeature -Name Web-* | Where-Object Installed | Format-Table Name, DisplayName
# Службы IIS
Get-Service W3SVC, WAS | Format-Table Name, Status, StartType
```

Windows 10/11 (стенд, рабочая станция), PowerShell от имени администратора [MS Learn: DISM-имена из той же таблицы; ИТС-мет 5977 — те же компоненты через «Включение или отключение компонентов Windows», `appwiz.cpl`]:

```powershell
Enable-WindowsOptionalFeature -Online -All -FeatureName IIS-WebServerRole, IIS-WebServer, IIS-ISAPIExtensions, IIS-ISAPIFilter, IIS-WindowsAuthentication, IIS-HttpTracing, IIS-ManagementConsole
Get-WindowsOptionalFeature -Online | Where-Object { $_.FeatureName -like 'IIS-*' -and $_.State -eq 'Enabled' } | Select-Object FeatureName
```

Проверка: на хосте `http://localhost/` — стартовая страница IIS; с клиента `Test-NetConnection web1c.corp.local -Port 80` [практика]. Для установки компонентов может понадобиться дистрибутив ОС [ИТС-адм разд. 8.2]. Порядок установки IIS и 1С неважен, но **«Расширения ISAPI» должны стоять до публикации**, иначе обработчик модуля 1С не заработает (404.3/500.21 — раздел 14) [практика].

## 3. Модуль расширения веб-сервера 1С

### 3.1. Компонент и файлы

- Компонент «**Модули расширения веб-сервера**» нужен для веб-клиента и Web-сервисов [ИТС-адм разд. 2.5.2.4, 2.6.3.8], для хранилища по HTTP — вместе с «Сервером хранилища конфигураций» [ИТС-адм разд. 2.6.3.7]. В `InstallComponents` (`1cestart.cfg`, `1cescmn.cfg`) он называется `WEBSERVEREXT` [ИТС-адм прил. 3.6.12]; тем же именем свойство передаётся MSI-установщику (пример logon-скрипта в прил. 3.10).
- Модуль для IIS — `wsisapi.dll` в `bin` версии [ИТС-разр гл. 37.4.4.2.2], `webinst.exe` — там же [ИТС-адм прил. 1.2.11]. Для Apache под Windows: `wsapch2.dll` (2.0), `wsap22.dll` (2.2) [ИТС-разр гл. 37.4.4.3]; для 2.4 — `wsap24.dll` ⚠ (имя для Windows в текстах 8.3.27 не приведено).
- Публикация из конфигуратора — только если на хосте IIS запускается конфигуратор нужной разрядности; иначе `webinst` с шаблоном, сохранённым на другом компьютере [ИТС-адм разд. 8.2, 8.3.2] (⚠ хватает ли одного компонента «Модули расширения веб-сервера» без конфигуратора — не проверялось).

Тихая установка — тема статьи 01; для веб-хоста коротко [ИТС-адм разд. 2.5.2.1, 2.7, прил. 3.6.12]:

```powershell
# Вариант 1 — setup.exe /S берёт состав компонентов из 1cestart.cfg режима установки
# (в 1cestart.cfg «для всех пользователей»: InstallComponents=DESIGNERALLCLIENTS=0 THINCLIENT=0 WEBSERVEREXT=1 SERVER=0 CONFREPOSSERVER=0 CONVERTER77=0 SERVERCLIENT=0 LANGUAGES=RU)
& "\\fs\1CDistr\8.3.27.xxxx\Win64\setup.exe" /S
# Вариант 2 — msiexec напрямую; ⚠ имя .msi для 8.3 в документации не приведено (в примере ИТС — «1CEnterprise 8.2.msi»), возьмите его из своего каталога дистрибутива
msiexec /i "\\fs\1CDistr\8.3.27.xxxx\Win64\<пакет>.msi" /qn /L*v C:\Temp\1c-ws.log TRANSFORMS=1049.mst DESIGNERALLCLIENTS=0 THINCLIENT=0 WEBSERVEREXT=1 SERVER=0 CONFREPOSSERVER=0 CONVERTER77=0 SERVERCLIENT=0 LANGUAGES=RU
# Проверка
Test-Path "C:\Program Files\1cv8\<версия>\bin\wsisapi.dll"
Test-Path "C:\Program Files\1cv8\<версия>\bin\webinst.exe"
```

`1049.mst` — трансформация для русского языка [ИТС-адм разд. 2.6.3.10.1]. Установка «для пользователя» для веб-хоста непригодна: каталог `%LOCALAPPDATA%\Programs\1cv8_x64\…` [ИТС-адм прил. 1.1.4] в профиле пользователя пулу IIS не виден [практика].

### 3.2. Разрядность

| | 32-разрядный веб-сервер | 64-разрядный веб-сервер |
|---|---|---|
| 32-разрядное «1С:Предприятие» | полностью | частично (только IIS) |
| 64-разрядное «1С:Предприятие» | не поддерживается | полностью |

«Частично» — 32-разрядный модуль в 64-разрядном IIS: `webinst` вызывать из `bin` 32-разрядной версии (`%PROGRAMFILES(x86)%\1cv8\<версия>\bin`), в пуле включить «Разрешены 32-разрядные приложения» = `True` (`enable32BitAppOnWin64`, по умолчанию `false`) [ИТС-адм разд. 8.3.1, 8.10.2.1; MS Learn]. Под Linux такой вариант не поддерживается [ИТС-адм разд. 8.3.1]. 32-разрядный модуль нужен разве что для 32-разрядных внешних компонент/COM в контексте веб-сервера файловой базы; для клиент-серверной базы код выполняется на сервере 1С [практика].

### 3.3. Несколько версий платформы на одном IIS

В одном пуле не могут работать модули, различающиеся третьей-четвёртой цифрой версии: пул на версию, приложения привязываются вручную [ИТС-адм разд. 8.10.2.2]; публикация же всегда идёт в Default Web Site и DefaultAppPool [ИТС-адм разд. 8.2]. Рабочая схема [практика]: **ни одной публикации в DefaultAppPool** — для каждой сборки пул `1C-<версия>`, после публикации приложение переносится в него (раздел 7.3); тогда новая публикация не задевает старые.

### 3.4. Дистрибутивы тонкого клиента для автообновления

- На хост IIS ставится `all-clients-distr-A.B.C.D.exe` или `win-mac-clients-distr-A.B.C.D.exe` (releases.1c.ru, права администратора) — появится `distr` в каталоге версии; лежащий рядом с установочными файлами пакет ставится вместе с платформой, `/D=<путь>` задаёт каталог явно [ИТС-адм разд. 2.8.2.2, 2.5.2.9, ключ `COPYTHINCLIENTDST`].
- Модуль сам отдаёт дистрибутив из `bin\distr` своей версии (`windows64tc.zip`, `windows32tc.zip`, `linux64tc.zip`, `linux32tc.zip`, `macOS64tc.zip`) [ИТС-адм разд. 11.2.3]; другой путь — URL в атрибутах `pubdst*` `default.vrd` [ИТС-адм разд. 11.2.2]. Для IIS нужен MIME-тип `.zip` (раздел 11.6).

### 3.5. Автоудаление старых версий и IIS

Программа запуска умеет удалять устаревшие версии. Версия считается используемой публикацией IIS, только если её упоминают файлы `default.vrd` **в `c:\inetpub\wwwroot` (с подкаталогами)** [ИТС-адм разд. 12.2.4]. Публикация в `D:\Web\demo` автоудалением не учитывается — версию, нужную IIS, могут удалить. Что делать [практика]: публиковать в подкаталоги `C:\inetpub\wwwroot\<имя>`, и/или на веб-хосте внести рабочую версию в `DontUninstallVersion` либо отключить автоудаление (`AutoUninstall`) в `1cestart.cfg` [ИТС-адм прил. 3.6.3, 3.6.11]. ⚠ Как именно программа запуска связывает `default.vrd` с версией (в самом `default.vrd` версии нет), в документации не раскрыто.

## 4. Публикация: конфигуратор и webinst

### 4.1. Предварительные условия

- Права администратора: конфигуратор запускать через «Запуск от имени администратора», `webinst` — сам или из консоли, запущенной от администратора [ИТС-адм разд. 8.2]; в Windows `webinst` выдаёт запрос на повышение прав [ИТС-адм прил. 4.14]. При нехватке прав конфигуратор спрашивает, продолжать ли, а `webinst` пишет диагностическое сообщение и **продолжает** — публикация может получиться неполной [ИТС-адм разд. 8.2].
- Конфигурация не пустая; «1С:Предприятие» установлено на компьютере с веб-сервером [ИТС-адм разд. 8.2].
- Версия конфигуратора/`webinst` = версия сервера 1С (пример ИТС: установлены 8.3.24.100 и 8.3.24.150, сервер 8.3.24.150 — публиковать только из 8.3.24.150) [ИТС-адм разд. 8.3.1].
- Каталог публикации существует [ИТС-адм разд. 8.3.2.2.1, прил. 4.14] (⚠ в разд. 8.3.2.1 сказано, что кнопка «Опубликовать» создаёт каталог на диске, — создавайте заранее, это работает в обоих случаях); это не сам `%SYSTEMDRIVE%\inetpub\wwwroot` [ИТС-адм разд. 8.2]; имя виртуального каталога — латиница [ИТС-адм разд. 8.3.1].
- Установлены «Расширения ISAPI» (раздел 2); для `-osauth` — «Проверка подлинности Windows» [ИТС-адм разд. 8.2; практика].

```powershell
New-Item -ItemType Directory -Force "C:\inetpub\wwwroot\demo" | Out-Null
```

### 4.2. Диалог публикации (конфигуратор)

«Администрирование → Публикация на веб-сервере…». Поля и их соответствие `webinst` и `default.vrd` [ИТС-адм разд. 8.3.2]:

- «Имя» → `-wsdir`, атрибут `base`; «Веб-сервер» → `-iis`/`-apache2`/`-apache22`/`-apache24` (в Linux только Apache); «Каталог» → `-dir`; «Использовать аутентификацию операционной системы» → `-osauth` (только IIS).
- «Публиковать доступ для клиентских приложений» → атрибут `enable` у `point` (тонкий, мобильный, веб-клиент; в разд. 8.4.3.1 тот же флажок назван «Публиковать тонкий клиент и веб-клиент»).
- Всё остальное `webinst` получает только из шаблона: OData (`<standardOData>`), аналитика (`<analytics>`), дистрибутив тонкого клиента (`pubdst*`), адрес выхода (`<exitURL>`), имя PWA (`<progressiveWebApplication>`, PWA требует HTTPS с действительным сертификатом [ИТС-адм разд. 1.1.4]), закладки «Web-сервисы» (`<ws>`), «HTTP-сервисы» (`<httpServices>`), «OpenID» (`<openid>`), «Прочие» (`temp`, `<pool>`, `<debug>`, `<zones>`, `allowexecutescheduledjobs`). Сервисы расширений в диалоге не видны — только правкой файла.

Кнопки: «Отключить» удаляет приложение из веб-сервера и, при необходимости, каталог; «Сохранить» пишет параметры в файл формата `default.vrd` — это и есть шаблон для `-descriptor` (`ib` и `base` — из текущей базы); «Загрузить» игнорирует `ib` и `base` [ИТС-адм разд. 8.3.2.1]. Перезапуск веб-сервера предлагается при смене версии 1С или пути к модулю, отключении публикации и новой публикации на Apache [ИТС-адм разд. 8.3.1].

При анонимной аутентификации и файловой базе публикация проверяет права анонимного пользователя на каталог базы и предупреждает, если их нет: дать права или включить аутентификацию ОС [ИТС-адм разд. 8.3.1].

### 4.3. Утилита webinst — ключи

```
webinst [-publish]|-delete <веб-сервер> -wsdir <виртуальный каталог> -dir <физический каталог> -connstr <строка соединения> -confpath <путь к файлу httpd.conf> -descriptor <путь к файлу default.vrd> [-osauth]
```

| Ключ | Смысл [ИТС-адм прил. 4.14] |
|---|---|
| `-publish` | опубликовать (действие по умолчанию) |
| `-delete` | удалить публикацию; достаточно `-wsdir`, остальное — для контроля |
| `-iis` | IIS версий 5.1, 6.0, 7.x, 8.x, 10.0 — только Windows |
| `-apache2`, `-apache22`, `-apache24` | Apache 2.0 / 2.2 / 2.4; для 2.4 `-confpath` можно не указывать; неверная версия Apache = неработающая публикация |
| `-wsdir` | имя виртуального каталога |
| `-dir` | физический каталог; должен существовать; для IIS 7.x+ нельзя `%SYSTEMDRIVE%\Inetpub\wwwroot`; в кавычках — без завершающего `\` (`"c:\my path"`, не `"c:\my path\"`) |
| `-connstr` | строка соединения с базой |
| `-confpath` | полный путь к `httpd.conf` — только Apache |
| `-descriptor` | публикация по шаблону; существующий `default.vrd` **полностью замещается** шаблоном; `-wsdir`/`-connstr` перекрывают `base`/`ib` шаблона; с `-delete` публикация удаляется, только если `base` и `ib` совпали |
| `-osauth` | настроить аутентификацию ОС на веб-сервере — только IIS |

Синтаксис значений: имя ключа и значение разделяются пробелом; значение с пробелами — в двойных кавычках; кавычки внутри значения удваиваются [ИТС-адм прил. 4.14]. Указывается только один ключ веб-сервера [ИТС-адм прил. 4.14].

### 4.4. Примеры для IIS

Перейдите в каталог версии (или пишите полный путь) — `webinst` той же сборки, что сервер:

```bat
cd /d "C:\Program Files\1cv8\<версия>\bin"

:: 1. Веб-клиент и тонкий клиент, клиент-серверная база в кластере на Ubuntu [ИТС-адм разд. 8.4.3.2.3]
webinst -publish -iis -wsdir demo -dir "C:\inetpub\wwwroot\demo" -connstr "Srvr=srv-1c-app;Ref=demo;"

:: 2. То же с аутентификацией ОС на IIS [ИТС-адм разд. 8.4.3.2.3]
webinst -publish -iis -wsdir demo -dir "C:\inetpub\wwwroot\demo" -connstr "Srvr=srv-1c-app;Ref=demo;" -osauth

:: 3. Файловая база: внутренние кавычки удваиваются [ИТС-адм разд. 8.3.3.2]
webinst -publish -iis -wsdir demofile -dir "C:\inetpub\wwwroot\demofile" -connstr "File=""D:\1CBases\demo"";"

:: 4. Сервисы / OData — по шаблону из кнопки «Сохранить» диалога [ИТС-адм разд. 8.5.3.2.3, 8.6.3.2.3, 8.7.3.2.3]
webinst -publish -iis -wsdir demo-api -dir "C:\inetpub\wwwroot\demo-api" -connstr "Srvr=srv-1c-app;Ref=demo;" -descriptor "C:\1C\templates\iis-template.vrd"

:: 5. Удаление [ИТС-адм разд. 8.3.3.2]
webinst -delete -iis -wsdir demo

:: Проверка [MS Learn — синтаксис appcmd]: ожидается APP "Default Web Site/demo" (applicationPool:DefaultAppPool)
%windir%\system32\inetsrv\appcmd list apps /site.name:"Default Web Site"
type "C:\inetpub\wwwroot\demo\default.vrd"
curl -I http://localhost/demo/
```

### 4.5. Что появляется в IIS после публикации

Документация говорит только об общей схеме (модуль, виртуальное приложение, каталог с `default.vrd`) [ИТС-адм разд. 8.3.1]. По практике [⚠ сверьте на своём сервере]: приложение `Default Web Site/<имя>` в `DefaultAppPool`; в каталоге публикации `default.vrd` и `web.config` с обработчиком пути `*` на `IsapiModule` с исполняемым файлом `…\<версия>\bin\wsisapi.dll` (имя обычно «1C Web-service Extension»); при `-osauth` — включённая «Проверка подлинности Windows»; разрешение `wsisapi.dll` в «Ограничениях ISAPI и CGI» (иначе 404.2). Как посмотреть:

```bat
cd /d %windir%\system32\inetsrv
appcmd list config "Default Web Site/demo" /section:handlers
appcmd list config /section:system.webServer/security/isapiCgiRestriction
appcmd list config "Default Web Site/demo" /section:system.webServer/security/authentication/windowsAuthentication
type "C:\inetpub\wwwroot\demo\web.config"
```

Форма `appcmd list config <URL> /section:<имя>` — по [MS Learn]. Коллекция `isapiCgiRestriction` настраивается только на уровне сервера (`applicationHost.config`); по умолчанию `notListedIsapisAllowed=false` — незарегистрированные ISAPI-модули запрещены [MS Learn].

### 4.6. Ручная публикация: свой сайт, свой пул

Нужна, когда публикация должна жить не в Default Web Site (отдельный сайт на 443 с другим именем хоста) или когда `webinst` недоступен. Последовательность [ИТС-адм разд. 8.3.1 — общая схема; ИТС-разр гл. 37.4.4.2.2 — то же для хранилища: «сопоставление сценария», путь запроса `*`, исполняемый файл `wsisapi.dll`, затем перезапуск веб-сервера; команды — практика, ⚠ проверить на стенде]:

```bat
cd /d %windir%\system32\inetsrv

:: 1. Пул под версию (раздел 7)
appcmd add apppool /name:"1C-<версия>" /managedRuntimeVersion:"" /enable32BitAppOnWin64:false

:: 2. Приложение в нужном сайте
appcmd add app /site.name:"Default Web Site" /path:/demo /physicalPath:"C:\inetpub\wwwroot\demo" /applicationPool:"1C-<версия>"

:: 3. Разрешить модуль в «Ограничениях ISAPI и CGI» (уровень сервера) ⚠ синтаксис добавления элемента — по образцу MS Learn
appcmd set config -section:system.webServer/security/isapiCgiRestriction /+"[path='C:\Program Files\1cv8\<версия>\bin\wsisapi.dll',allowed='True',description='1C <версия>']" /commit:apphost

:: 4. Обработчик «*» → wsisapi.dll для приложения ⚠ набор атрибутов — по практике
appcmd set config "Default Web Site/demo" -section:system.webServer/handlers /+"[name='1C Web-service Extension',path='*',verb='*',modules='IsapiModule',scriptProcessor='C:\Program Files\1cv8\<версия>\bin\wsisapi.dll',resourceType='Unspecified',requireAccess='None']"
```

5. Положить в каталог `default.vrd` (шаблон из диалога, с `base="/demo"` и нужным `ib`) — раздел 5.
6. Права NTFS — раздел 6; перезапуск: `iisreset` или `appcmd recycle apppool /apppool.name:"1C-<версия>"` (форма `appcmd recycle AppPool <имя>` есть в образце MS Learn «An End-to-End Extensibility Example for IIS 7.0 Developers» — уточнено 20.10.2026 при проверке `iis/`).

В диспетчере IIS (`inetmgr`) шаги 3–4 — это «Сопоставления обработчиков → Добавить сопоставление сценария…» (путь запроса `*`, исполняемый файл `wsisapi.dll`, имя произвольное); диспетчер сам предлагает разрешить расширение ISAPI [ИТС-разр гл. 37.4.4.2.2; практика].

### 4.7. Обновление платформы и перепубликация

При переходе кластера на новую сборку [ИТС-адм разд. 8.3.1, 8.10.2.2; практика]:

1. На хост IIS поставить ту же сборку с компонентом «Модули расширения веб-сервера» (старую не удалять до проверки).
2. Создать пул `1C-<новая версия>` (раздел 7), выдать права на её `bin` (раздел 6).
3. Перепубликовать: `"C:\Program Files\1cv8\<новая версия>\bin\webinst.exe" -publish -iis -wsdir demo -dir "C:\inetpub\wwwroot\demo" -connstr "…" -descriptor "<сохранённый шаблон>"` (шаблон сохраняет все настройки сервисов и `<pool>`), затем `appcmd set app "Default Web Site/demo" /applicationPool:"1C-<новая версия>"`.
4. Проверить обработчик: `appcmd list config "Default Web Site/demo" /section:handlers` — путь должен указывать на `bin` новой версии.
5. Когда все публикации перенесены, удалить старый пул и старую версию.

Если пул общий, а версии модулей разные, — ошибки при старте `w3wp` и 503 после нескольких падений (раздел 14).

## 5. default.vrd — что важно на IIS

Полный разбор элементов — `../1c/05-veb-publikaciya-apache-nginx.md`, раздел 5, и конспект `../its-docs/adm-pr03-sluzhebnye-fajly-p2.md`. Здесь — то, что чаще всего правят на IIS.

### 5.1. Корневой элемент `<point>`

Файл лежит в каталоге виртуального приложения [ИТС-адм прил. 3.21.1]. Атрибуты [ИТС-адм прил. 3.21.2]:

| Атрибут | Смысл | Умолчание |
|---|---|---|
| `base` | путь приложения относительно корня сайта (`/demo`), рекомендуется US-ASCII | — |
| `ib` | строка соединения; недопустимые в XML символы экранируются (`&quot;`); можно вписать `Usr=…;Pwd=…;` — тогда вход под этим пользователем, если клиент не передал свои | — |
| `enable` | работа тонкого и веб-клиента через публикацию | `true` |
| `temp` | каталог временных файлов расширения (`wsisapi.dll`, `wsap22.dll`, `wsapch2.dll`) или файловой базы; пользователю расширения нужен **полный доступ** | для файловой базы — `1Cv8Temp` рядом с базой; иначе — временный каталог пользователя, от имени которого выполняется запрос |
| `pubdstwin64`, `pubdstwin32`, `pubdstlin64`, `pubdstlindeb64`, `pubdstlinrpm64`, `pubdstmac64` и др. | URL архива тонкого клиента для автообновления | — |
| `allowexecutescheduledjobs` | регламентные задания файловой базы: `off` — не выполнять в расширении, `force` — выполнять | не задано: выполняет приложение, подключившееся первым |

Полный пример файла для отдельной публикации сервисов — раздел 11.1.

### 5.2. Сервисы: умолчания, о которых чаще всего спотыкаются

| Элемент / атрибут | Умолчание | Следствие | Источник |
|---|---|---|---|
| `<ws enable>` | `true` | веб-сервисы конфигурации разрешены, если нет явного запрета | [ИТС-адм прил. 3.21.3.1] |
| `<ws pointEnableCommon>` | `true` | сервисы без явного `enable` у `<point>` разрешены | там же |
| `<ws publishExtensionsByDefault>` | `false` | **веб-сервисы расширений не работают**, пока не включить или не перечислить их в `<point>` | там же |
| Синоним (`alias`) веб-сервиса | — | по синониму сервис доступен, только если он явно перечислен в `default.vrd` | [ИТС-адм прил. 3.21.3.2] |
| `<httpServices publishByDefault>` | `true` | все HTTP-сервисы конфигурации доступны | [ИТС-адм прил. 3.21.4.1] |
| `<httpServices publishExtensionsByDefault>` | `false` | **HTTP-сервисы расширений не работают** по умолчанию | там же |
| `<service enable>` | `false` | перечисленный без `enable="true"` сервис запрещён | [ИТС-адм прил. 3.21.4.2] |

| `<standardOData>` отсутствует | — | **OData недоступен** | [ИТС-адм прил. 3.21.11] |
| `<standardOData reuseSessions>` | `dontuse` | для OData сеансы по умолчанию не переиспользуются | там же |
| `<analytics poolSize>`, `poolTimeout` | 500, 5 с | пул сеансов «1С:Аналитики» | [ИТС-адм прил. 3.21.12] |

Изменённые `reuseSessions` и `sessionMaxAge` начинают действовать только после перезапуска сервера «1С:Предприятия» [ИТС-адм прил. 3.21.3.2]. Сервисы из расширений в диалоге не видны — только ручная правка `default.vrd` [ИТС-адм разд. 8.3.2.2.2, 8.3.2.2.3].

### 5.3. Пул соединений `<pool>`

Атрибуты и умолчания [ИТС-адм прил. 3.21.5]: `size` — 10 000 соединений; `maxAge` — время жизни невостребованного соединения, секунды (умолчание «20 мин»); `attempts` — 5 попыток; `attemptTimeout` — 500 с; `waitTimeout` — 500 с; `serverPingPeriod` — 1000 мс (максимум 65 535); `serverPingTimeout` — 5000 мс. Последние два управляют системой отслеживания разрыва соединений [ИТС-адм разд. 8.3.2.4]. Пул — на каждый экземпляр расширения, то есть на каждый рабочий процесс `w3wp` [ИТС-адм разд. 8.2; практика].

### 5.4. Аутентификация в окне входа: `<authentication>` (8.3.26+)

```xml
<authentication allowSaveForReauthentication="true" savedAuthenticationParametersLifeTime="432000">
    <logonView saveForReauthenticationByDefault="true">
        <method type="standard" visible="true"/>
        <method type="openid" visible="true"/>
    </logonView>
</authentication>
```

`allowSaveForReauthentication` (по умолчанию `false`) разрешает запоминать вход через эту публикацию (стандартная и OpenID-аутентификация); `savedAuthenticationParametersLifeTime` — время жизни токена повторного входа, 1…999 999 999 с, по умолчанию 432 000 (5 суток); `saveForReauthenticationByDefault` — начальное состояние флажка «Запомнить» (по умолчанию `false`); у `<method>` атрибуты `type` (`standard`, `email`, `openID`, `openIDConnect`, `qr`) и `visible` [ИТС-адм прил. 3.21.15]. ⚠ В таблице ИТС значения `type` написаны `openID`/`openIDConnect`, а в примере того же раздела — `openid`/`openidconnect`; регистр проверьте на своей версии. Сбросить запомненный вход на клиенте — ключ `/ResetSavedAuth` [ИТС-адм прил. 3.21.15].

### 5.5. Правка `default.vrd` на работающем IIS

- Файл — XML в UTF-8; после правки проверьте, что он открывается браузером/`[xml](Get-Content … -Raw)` без ошибок [практика].
- Расширение читает файл при старте экземпляра; надёжный способ применить — перезапуск пула приложения [практика ⚠: момент перечитывания в документации не описан].
- `webinst -descriptor` полностью **заменяет** `default.vrd` шаблоном [ИТС-адм прил. 4.14] — ручные правки, не перенесённые в шаблон, пропадут. Храните шаблоны в репозитории или рядом с регламентом.

## 6. Права NTFS и учётные записи

### 6.1. Кто обращается к файлам

- `w3wp` работает под идентификатором пула: с IIS 7.5 по умолчанию `ApplicationPoolIdentity` — виртуальная учётная запись `IIS AppPool\<имя пула>` [MS Learn], входящая в `IIS_IUSRS` [практика].
- Запрос выполняется от лица пользователя запроса [ИТС-адм разд. 8.4.3.2.1]: при анонимном доступе — анонимная учётная запись IIS (`IUSR` ⚠), при проверке Windows — сам доменный пользователь (олицетворение [ИТС-адм разд. 8.9.1]). Поэтому для файловой базы с аутентификацией ОС права на файлы версии и каталог базы нужны **всем** таким пользователям, а не только `IIS_IUSRS` [ИТС-адм разд. 8.9.1].

### 6.2. Какие права нужны

| Объект | Кому | Право | Источник |
|---|---|---|---|
| `C:\Program Files\1cv8\<версия>\bin` | `IIS_IUSRS` (IIS 7+), раньше `IUSR_<имя_компьютера>` | чтение (и выполнение) | [ИТС-адм разд. 8.4.3.2.1, 8.5.3.2.1, 8.6.3.2.1, 8.7.3.2.1] |
| Каталог файловой базы | `IIS_IUSRS`; при аутентификации ОС — пользователи базы | изменение | там же; [ИТС-адм разд. 8.9.1] |
| Каталог из атрибута `temp` | пользователь расширения | полный доступ | [ИТС-адм прил. 3.21.2] |
| Временный каталог пользователя клиентского приложения | тот, от чьего имени работает приложение | «Список содержимого папки» | [ИТС-адм разд. 1.4.3] |
| Каталог технологического журнала | пользователь расширения веб-сервера | запись | [ИТС-адм разд. 6.14.2] |
| Каталог публикации (`default.vrd`, `web.config`) | `IIS_IUSRS` | чтение | [практика ⚠; ИТС этого явно не требует — по умолчанию права на `C:\inetpub\wwwroot` наследуются] |

Если 1С установлена «для компьютера» в `C:\Program Files`, группа «Пользователи» уже имеет там чтение и выполнение, и `bin` обычно доступен без правок [практика]. Явная выдача нужна при нестандартном каталоге установки.

### 6.3. Команды

```bat
:: Чтение и выполнение каталога bin версии
icacls "C:\Program Files\1cv8\<версия>\bin" /grant "IIS_IUSRS:(OI)(CI)RX"
:: Файловая база: изменение
icacls "D:\1CBases\demo" /grant "IIS_IUSRS:(OI)(CI)M"
:: Отдельный каталог временных файлов (атрибут temp)
icacls "D:\1CWebTemp" /grant "IIS_IUSRS:(OI)(CI)F"
:: Каталог техжурнала на веб-хосте
icacls "D:\1CLogs\web" /grant "IIS_IUSRS:(OI)(CI)M"
:: Проверка
icacls "C:\Program Files\1cv8\<версия>\bin"
```

[практика: стандартный синтаксис `icacls`, наследование `(OI)(CI)`]. Для конкретного пула вместо группы можно указать `"IIS AppPool\1C-<версия>"` [практика].

### 6.4. Когда пулу нужна доменная учётная запись

Обычно — нет: с `ApplicationPoolIdentity` Kerberos работает через SPN учётной записи компьютера [MS Learn, «Troubleshoot Kerberos failures»]. Доменная учётная запись нужна, если код в контексте веб-сервера (файловая база) ходит в сеть от своего имени, или для фермы IIS под общим именем (раздел 10.5) [MS Learn]; ей нужны те же права, что `IIS_IUSRS` [практика].

## 7. Пул приложений

### 7.1. Параметры и почему так

| Параметр (диспетчер IIS → Пулы приложений → Дополнительные параметры) | Атрибут | Умолчание IIS [MS Learn] | Для 1С |
|---|---|---|---|
| Версия среды .NET CLR | `managedRuntimeVersion` | `""` в схеме; у новых пулов, созданных диспетчером, обычно `v4.0` ⚠ | **«Без управляемого кода»** (`""`) [ИТС-адм разд. 8.2] |
| Разрешены 32-разрядные приложения | `enable32BitAppOnWin64` | `false` | `false` для 64-разрядной 1С; `true` — только для 32-разрядного модуля [ИТС-адм разд. 8.10.2.1] |
| Удостоверение | `processModel.identityType` | `ApplicationPoolIdentity` (IIS 7.5+) | оставить, если нет причин (раздел 6.4) |
| Максимальное число рабочих процессов | `processModel.maxProcesses` | `1` (2 и больше — «веб-сад», 0 — по числу узлов NUMA) | файловая база — **1** [ИТС-адм разд. 8.10.2.2]; клиент-серверная, 8.3.26+ — ~1 на 100 сеансов [ИТС-мет 6034] |
| Тайм-аут простоя | `processModel.idleTimeout` | `00:20:00` | `00:00:00` (не гасить процесс ночью и в обед, первый запрос не ждёт старта модуля) [практика] |
| Режим запуска | `startMode` (IIS 7.5+) | `OnDemand` (справочник iis-docs `applicationPools/add` — уточнено 20.10.2026 при проверке `iis/`) | `AlwaysRunning` — процесс поднимается сразу [MS Learn: значение есть; польза для 1С — практика] |
| Регулярный интервал перезапуска | `recycling.periodicRestart.time` | `29:00:00` (каждые 29 ч, в произвольное время суток) | `00:00:00` и перезапуск **по расписанию** ночью (`periodicRestart/schedule`) — иначе переработка может прийтись на рабочий день [практика] |
| Длина очереди | `queueLength` | `1000` | при превышении http.sys отдаёт 503 [MS Learn] |
| Защита от частых сбоев | `failure.rapidFailProtection`, `…Interval`, `…MaxCrashes` | `true`, 5 мин, 5 сбоев | после 5 падений за 5 минут пул останавливается → 503.0 [MS Learn] |
| Предел времени завершения | `processModel.shutdownTimeLimit` | 90 с | при переработке запросы старого процесса дольше 90 с обрываются [MS Learn] |

Лимиты памяти для переработки (`recycling.periodicRestart.memory`/`privateMemory`) по умолчанию выключены (`0`), проверка связи (`pingResponseTime`) — 90 с [MS Learn]; `loadUserProfile` (в схеме `false` — подтверждено справочником iis-docs `add/processModel` 20.10.2026 при проверке `iis/01`; значение в готовом `applicationHost.config` ⚠) влияет на временный каталог процесса, см. атрибут `temp` (раздел 5.1) [практика].

### 7.2. Команды

Создание пула для версии и настройка [синтаксис `appcmd add apppool /name:…` и `set apppool "<имя>" /<атрибут>:<значение>`, точечная нотация `processModel.<атрибут>` — MS Learn; значения — по таблице выше]:

```bat
cd /d %windir%\system32\inetsrv
appcmd add apppool /name:"1C-<версия>"
appcmd set apppool "1C-<версия>" /managedRuntimeVersion:""
appcmd set apppool "1C-<версия>" /enable32BitAppOnWin64:false
appcmd set apppool "1C-<версия>" /processModel.idleTimeout:00:00:00
appcmd set apppool "1C-<версия>" /startMode:AlwaysRunning
appcmd set apppool "1C-<версия>" /recycling.periodicRestart.time:00:00:00
:: Ночной перезапуск в 03:00 ⚠ синтаксис добавления в коллекцию schedule — по образцу MS Learn для коллекций
appcmd set config -section:system.applicationHost/applicationPools /+"[name='1C-<версия>'].recycling.periodicRestart.schedule.[value='03:00:00']" /commit:apphost
:: Клиент-серверная база, ~400 одновременных сеансов через IIS, 8.3.26+ (ИТС-мет 6034)
appcmd set apppool "1C-<версия>" /processModel.maxProcesses:4
:: Проверка
appcmd list apppool "1C-<версия>" /text:*
```

В PowerShell то же делается модулем `WebAdministration` (`New-WebAppPool`, `Set-ItemProperty "IIS:\AppPools\1C-<версия>" -Name processModel.maxProcesses -Value 4`) [практика ⚠ — не сверялось с документацией].

### 7.3. Перенос публикации в свой пул

```bat
%windir%\system32\inetsrv\appcmd set app "Default Web Site/demo" /applicationPool:"1C-<версия>"
%windir%\system32\inetsrv\appcmd list apps /site.name:"Default Web Site"
```

[синтаксис — MS Learn: `APPCMD set app "MySite/" /applicationPool:MyAppPool`]. Ожидается `APP "Default Web Site/demo" (applicationPool:1C-<версия>)`. Повторный запуск `webinst` для той же публикации может вернуть приложение в DefaultAppPool ⚠ — после каждой перепубликации проверяйте `list apps`.

### 7.4. Веб-сад: когда можно и когда нельзя

- **Файловая база** — нельзя: публикацию должен обслуживать один рабочий процесс, при фоновых заданиях — строго 1 [ИТС-адм разд. 8.2, 8.10.2.2].
- **Клиент-серверная база, 8.3.26+** — «1 thread pool ("рабочий процесс" IIS) на каждые ~100 сеансов» (1000 сеансов — 10), чтобы избежать кратковременных зависаний [ИТС-мет 6034, 2025]. ⚠ Термины в статье смешаны; буквальное прочтение для IIS — «Максимальное число рабочих процессов» пула (`maxProcesses`), альтернатива — несколько пулов по группам пользователей. Подбирайте на нагрузочном тесте: каждый `w3wp` держит свой экземпляр модуля и пул соединений [практика]. Сеанс 1С не теряется — его состояние в кластере [ИТС-КС разд. 2.2.7.2.2].

## 8. Ограничения размера и длины запросов

### 8.1. Фильтрация запросов IIS (`requestFiltering/requestLimits`)

| Атрибут | Умолчание | Код при превышении | Где бьёт по 1С |
|---|---|---|---|
| `maxAllowedContentLength` | `30000000` байт (~28,6 МБ) | 404.13 (в справочнике кодов) / 413.1 (в описании `requestLimits`) | загрузка файлов в веб-клиенте, `ПоместитьФайл`, POST в HTTP-сервисы, большие SOAP-пакеты, обмен с мобильными приложениями |
| `maxUrl` | `4096` байт | 404.14 | длинные URL OData и HTTP-сервисов |
| `maxQueryString` | `2048` байт | 404.15 | `$filter`/`$select` OData, GET-параметры HTTP-сервисов |
| `headerLimits` | — | 404.10 | редко |

Источник умолчаний и кодов — [MS Learn, «Request Limits <requestLimits>»; «HTTP status code overview»]. Обратите внимание: клиент видит просто 404, подстатус виден только в журнале IIS (`sc-substatus`, раздел 14.2) [MS Learn].

Увеличить для публикации (до 1 ГБ тела и длинных строк запроса) [форма команды — по образцу MS Learn `appcmd.exe set config "<сайт>" -section:system.webServer/security/requestFiltering …`; значения — практика]:

```bat
cd /d %windir%\system32\inetsrv
appcmd set config "Default Web Site/demo" -section:system.webServer/security/requestFiltering /requestLimits.maxAllowedContentLength:1073741824
appcmd set config "Default Web Site/demo" -section:system.webServer/security/requestFiltering /requestLimits.maxQueryString:32768
appcmd set config "Default Web Site/demo" -section:system.webServer/security/requestFiltering /requestLimits.maxUrl:65536
appcmd list config "Default Web Site/demo" -section:system.webServer/security/requestFiltering
```

Если `maxQueryString` больше `MaxFieldLength` http.sys (16 384), упрётесь уже в http.sys (ответ 400) — см. 8.2 [практика ⚠].

Прочие фильтры, о которые спотыкаются HTTP-сервисы и OData [MS Learn — коды; связь с 1С — практика ⚠]: 404.8 «скрытый сегмент» (корневой URL HTTP-сервиса не называйте `bin`), 404.11 «двойное экранирование» (`%25`, `+` в пути; `allowDoubleEscaping="true"` у приложения), 404.7 «запрещённое расширение» в последнем сегменте URL.

### 8.2. Ограничения http.sys (реестр)

`HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\HTTP\Parameters` [MS Learn, «Http.sys registry settings for Windows»]:

| Параметр | Умолчание | Смысл |
|---|---|---|
| `UrlSegmentMaxLength` | 260 | максимум символов в **одном сегменте** пути (между `/`); 0 — без ограничения (до `ULONG`); диапазон 0–32 766 |
| `UrlSegmentMaxCount` | 255 | число сегментов пути |
| `MaxFieldLength` | 16 384 | предел одного заголовка (и примерно 32 тыс. символов URL) |
| `MaxRequestBytes` | 16 384 | предел строки запроса + всех заголовков |

ИТС пишет, что «IIS ограничивает URL 260 символами», и советует создать `UrlSegmentMaxLength` (DWORD) больше максимальной длины запросов или 0 и перезагрузить компьютер [ИТС-адм разд. 8.10.2.4]. По Microsoft 260 — предел **сегмента**, а не всего URL (для OData важно: ключ `Catalog_Товары(guid'…')` — один длинный сегмент); изменение этих параметров Microsoft считает рискованным — ставьте разумный предел, а не 0 [MS Learn].

```powershell
# От имени администратора; затем перезагрузка (по ИТС) — или как минимум перезапуск службы HTTP с остановкой IIS ⚠
New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\HTTP\Parameters" -Name UrlSegmentMaxLength -PropertyType DWord -Value 4096 -Force
# Только при ошибках 400 из-за больших билетов Kerberos (много групп у пользователя) — раздел 10.6
New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\HTTP\Parameters" -Name MaxFieldLength -PropertyType DWord -Value 65534 -Force
New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\HTTP\Parameters" -Name MaxRequestBytes -PropertyType DWord -Value 1048576 -Force
Get-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Services\HTTP\Parameters" | Select-Object UrlSegmentMaxLength, MaxFieldLength, MaxRequestBytes
```

Перед правкой реестра — экспорт ветки: `reg export "HKLM\SYSTEM\CurrentControlSet\Services\HTTP\Parameters" C:\Backup\http-params.reg` [практика].

### 8.3. Длительные запросы

У ISAPI-обработчика IIS нет аналога `executionTimeout` ASP.NET; длинный вызов HTTP-сервиса или формирование отчёта в веб-клиенте ограничиваются скорее клиентом, прокси и балансировщиками, чем IIS [практика ⚠]. Обрывы длинных операций чаще связаны с переработкой пула (`shutdownTimeLimit` 90 с, раздел 7.1) или с тайм-аутом обратного прокси. Долгие операции в прикладном коде лучше выносить в фоновые задания [практика].

## 9. HTTPS

### 9.1. Требования 1С

- Через Интернет — только HTTPS [ИТС-адм разд. 8.2; ИТС-мет 5977, 2020]; без HTTPS не работают PWA [ИТС-адм разд. 1.1.4] и OpenID-провайдер 1С [ИТС-адм разд. 8.3.2.3].
- TLS 1.0–1.3, есть ГОСТ-алгоритмы; при TLS 1.3 клиентские сертификаты — только ГОСТ, серверные — любые; SSL 3.0 не поддерживается [ИТС-адм разд. 8.9.2].
- Поля сертификата — только US-ASCII или Punycode; сертификат действителен: подпись, срок, имя сайта [ИТС-адм разд. 8.9.2].

### 9.2. Сертификат

- Рабочий вариант — сертификат корпоративного ЦС (AD CS) или публичного ЦС; тестовый — самоподписанный («Диспетчер служб IIS → сервер → Сертификаты сервера → Создать самозаверенный сертификат…»), для реальных систем 1С его не рекомендует [ИТС-мет 5977]; в PowerShell — `New-SelfSignedCertificate -DnsName "web1c.corp.local" -CertStoreLocation Cert:\LocalMachine\My` [практика].
- Импорт PFX в хранилище компьютера [практика]:

```powershell
$pfxPass = Read-Host -AsSecureString "Пароль PFX"
Import-PfxCertificate -FilePath "C:\Certs\web1c.pfx" -CertStoreLocation Cert:\LocalMachine\My -Password $pfxPass
Get-ChildItem Cert:\LocalMachine\My | Select-Object Thumbprint, Subject, NotAfter, @{n='SAN';e={$_.DnsNameList -join ','}}
```

### 9.3. Привязка к сайту

Через диспетчер: Default Web Site → «Привязки…» → «Добавить…» → тип `https`, порт 443, «SSL-сертификат» — импортированный [ИТС-мет 5977]. Через PowerShell (модуль `IISAdministration`, синтаксис по [MS Learn, `New-IISSiteBinding`]; командлеты `*-IISSiteBinding` появились в IIS 10.0 версии 1709 — на Windows Server 2016 их нет, там `New-WebBinding` или `appcmd` + `netsh http add sslcert`, см. `../iis/02-…` — уточнено 20.10.2026 при проверке `iis/`):

```powershell
Import-Module IISAdministration
$thumb = "<отпечаток сертификата>"
New-IISSiteBinding -Name "Default Web Site" -BindingInformation "*:443:" -CertificateThumbPrint $thumb -CertStoreLocation "Cert:\LocalMachine\My" -Protocol https
# Несколько имён на одном IP — SNI: -BindingInformation "*:443:web1c.corp.local" -SslFlag "Sni"
Get-IISSiteBinding -Name "Default Web Site"
```

Проверка: `Test-NetConnection web1c.corp.local -Port 443`, `curl.exe -v https://web1c.corp.local/demo/`, в браузере — замок без предупреждений [практика]. Правила брандмауэра для 80/443 роль IIS обычно создаёт сама ⚠ — проверьте.

### 9.4. HTTP → HTTPS

Простейший путь — оставить на сайте только привязку 443 [практика]. Перенаправление: компонент «Перенаправление HTTP» (`Web-Http-Redirect`) [MS Learn] или модуль URL Rewrite — его нет среди компонентов Windows, ставится отдельно с сайта iis.net [ИТС-мет 5973, 2020, через конспект `../its-metod/veb-https-apache-nginx-i-nastrojka-rabochih-serverov.md`, раздел 3.6]. Тонкий клиент и интеграции лучше сразу настраивать на `https://` — перенаправление POST-запросов SOAP/REST клиенты выполняют не всегда [практика].

### 9.5. Протоколы TLS на сервере

- ИТС при ошибках загрузки больших объёмов по HTTPS советует включить TLS 1.1/1.2 параметром `DisableByDefault` = 0 в `HKLM\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL\Protocols\TLS 1.x\Server` и перезагрузиться [ИТС-адм разд. 8.10.2.5]. Рецепт времён Windows 7/2008 R2, и у Microsoft параметр называется **`DisabledByDefault`** (вместе с `Enabled`) [MS Learn, «Manage SSL/TLS protocols…»; страница «TLS registry settings» (ред. 18.04.2025) описывает только `Enabled`, а `DisabledByDefault` встречается в руководстве по AD FS — уточнено 20.10.2026 при проверке `iis/02`] — параметр с именем из ИТС, по-видимому, не действует ⚠.
- На современных Windows Server TLS 1.2 включён по умолчанию ⚠; в выпусках Windows 11 и Windows Server с 2024 года TLS 1.0/1.1 **выключены по умолчанию** (уже выпущенных ОС это не касается) [MS Learn, «TLS 1.0 and TLS 1.1 deprecation in Windows»]. Возвращать их ради 1С не нужно — 1С умеет TLS 1.2/1.3 [ИТС-адм разд. 8.9.2].
- Клиент 1С может ограничить максимальную версию TLS: `ForceTLS1_0`/`ForceTLS1_1`/`ForceTLS1_2` = `true` в `conf.cfg` (по умолчанию `false`, несколько сразу — нельзя) [ИТС-адм прил. 3.17.13] — обходной путь для несовместимостей.

Перед правкой SCHANNEL — `reg export "HKLM\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL" C:\Backup\schannel.reg`: ошибка там ломает RDP и сайт [практика].

### 9.6. Проверка сертификата клиентами 1С на Windows

- С 8.3.12 платформа проверяет сертификат сервера средствами Windows [ИТС-мет 5949, 2018] — корневой сертификат вашего ЦС должен быть в «Доверенных корневых центрах сертификации» клиента (в домене — групповой политикой, статья 04) [практика]; так же проверяются дистрибутивы автообновления, скачиваемые по HTTPS [ИТС-адм прил. 3.21.2].
- «Удалённый узел не прошёл проверку. Не удалось выполнить проверку отзыва сертификата» — учётная запись процесса (служба сервера 1С, клиент, пул IIS) не может скачать CRL: прокси, брандмауэр, доступ только у доменных пользователей [ИТС-мет 5949]. Диагностика — журнал «Microsoft → Windows → CAPI2 → Operational» (по умолчанию выключен; поле `UserID` показывает, чья операция) [ИТС-мет 5949]; включить командой `wevtutil sl Microsoft-Windows-CAPI2/Operational /e:true` [практика].
- Параметр `conf.cfg` `IgnoreServerCertificatesChainRevocationSoftFail`: `true` — соединяться, если цепочка верна, а отзыв проверить невозможно; `false` — исключение [ИТС-адм прил. 3.17.16]. **По документации 8.3.27 умолчание — `true`**; методичка 2018 года описывает поведение по умолчанию как исключение и советует включать `true` вручную [ИТС-мет 5949] — то есть умолчание с тех пор поменялось ⚠ (версия изменения не установлена). Отозванный сертификат всё равно отвергается [ИТС-мет 5949].
- Linux-клиенты и Linux-сервер 1С (смешанная среда) доверяют ЦС из `/etc/ssl/certs` — свой корневой сертификат нужно добавить и туда (`../1c/09`, п. 17 «Кратко»).

## 10. Аутентификация

### 10.1. Три уровня

По документации различаются аутентификация на прокси, на веб-сервере и в «1С:Предприятии» [ИТС-адм разд. 8.9.1]:

| Режим IIS | Что происходит | Когда выбирать |
|---|---|---|
| Анонимная | IIS пропускает всех под анонимной учётной записью; 1С сама запрашивает у клиента Basic-аутентификацию с именем/паролем пользователя 1С (UTF-8) | пользователи 1С с паролями, OpenID, внешние интеграции; **только поверх HTTPS** |
| Basic на IIS | имя и пароль проверяет IIS (учётная запись Windows), они же передаются в 1С — должны совпадать для IIS и для 1С | почти не нужно |
| Проверка подлинности Windows | IIS определяет пользователя Windows и передаёт его в 1С вместе с данными запроса; если в запросе есть имя/пароль 1С — используются они, иначе — пользователь ОС | вход по доменной учётной записи без пароля |

[ИТС-адм разд. 8.9.1]. Аутентификация ОС для веб- и тонкого клиента через веб-сервер основана на олицетворении пользователя в потоке веб-сервера и зависит от браузера, IIS, прав и политик домена; эти настройки — вне документации 1С [ИТС-адм разд. 8.9.1].

Тонкий клиент [ИТС-адм разд. 4.3.8.2.2, прил. 7.3.1–7.3.2]: `/WSA+` (по умолчанию) — аутентификация ОС на веб-сервере, `/WSA-` — запрос имени и пароля; `/WSN <имя>`, `/WSP <пароль>` — явная учётная запись; в строке соединения — `wsn`, `wsp`, прокси `wspauto`, `wspsrv`, `wspport`, `wspuser`, `wsppwd`. В списке баз — `Connect=ws="https://web1c.corp.local/demo";` [ИТС-адм прил. 3.4].

### 10.2. Включение проверки подлинности Windows на IIS

1. Компонент `Web-Windows-Auth` установлен (раздел 2).
2. Публикация с флажком «Использовать аутентификацию операционной системы» или `webinst … -osauth` [ИТС-адм разд. 8.4.3.2.2, 8.4.3.2.3].
3. В IIS для приложения: «Проверка подлинности» → **анонимная — отключить**, «Проверка подлинности Windows» — **включить**; в её «Поставщиках» на первом месте **Negotiate**; пул можно не менять; затем `iisreset` [ИТС-мет 5944, 2018]. По умолчанию IIS перечисляет поставщиков в порядке `Negotiate`, `NTLM`, а режим ядра (`useKernelMode`) включён [MS Learn].

Командами [синтаксис, включая `/commit:apphost`, — образец MS Learn для `windowsAuthentication`; `/commit:apphost` пишет настройку в `applicationHost.config`, потому что секции аутентификации обычно заблокированы для `web.config` — практика]:

```bat
cd /d %windir%\system32\inetsrv
appcmd set config "Default Web Site/demo" -section:system.webServer/security/authentication/anonymousAuthentication /enabled:"False" /commit:apphost
appcmd set config "Default Web Site/demo" -section:system.webServer/security/authentication/windowsAuthentication /enabled:"True" /commit:apphost
appcmd list config "Default Web Site/demo" -section:system.webServer/security/authentication/windowsAuthentication
iisreset
```

4. В 1С у пользователя информационной базы включить аутентификацию операционной системы и указать пользователя ОС. Если вход не проходит, хотя пользователь указан, — сравнить с тем, что видит сервер: включить на сервере 1С технологический журнал событий `CONN` и `EXCP` со всеми свойствами, воспроизвести вход, найти `EXCP` «Идентификация пользователя не выполнена» и предшествующий `CONN` со свойством `DstUserName2`; в свойство «Пользователь» записать `\\` + имя из `DstUserName2` без скобок (например, `\\CORP\ivanov`) [ИТС-мет 5944]:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<config xmlns="http://v8.1c.ru/v8/tech-log">
  <log location="C:\1CLogs\conn" history="24">
    <event><eq property="Name" value="CONN"/></event>
    <event><eq property="Name" value="EXCP"/></event>
    <property name="all"/>
  </log>
</config>
```

(Файл `logcfg.xml` кладётся в каталог конфигурационных файлов сервера 1С — на Windows `C:\Program Files\1cv8\conf` [ИТС-адм прил. 1.3.4], на Linux-сервере пользователя — `/opt/1cv8/conf/`, а `location` — Linux-путь, доступный `usr1cv8` на запись, например `/var/log/1c/conn` [`../1c/07`, `../1c/08`]; после диагностики журнал выключить.)

### 10.3. IIS и рабочие серверы 1С на разных машинах (двойной переход)

Признак: в `CONN` `DstUserName1` — реальный пользователь, а `DstUserName2` — `NT AUTHORITY\ANONYMOUS LOGON`, затем `EXCP` «Идентификация пользователя не выполнена» [ИТС-мет 5944] — «двойной переход» Kerberos без делегирования. Проверить по ИТС-мет 5944:

1. Процессы сервера 1С запущены от доменной учётной записи из группы Domain Users.
2. IIS настроен, как в 10.2 (Negotiate первым).
3. В AD у **учётной записи компьютера с IIS** на вкладке «Делегирование» — «Доверять компьютеру делегирование любых служб (только Kerberos)» (оснастка `dsa.msc`). ⚠ Это неограниченное делегирование; более безопасный вариант — ограниченное делегирование только к SPN службы сервера 1С — 1С не описывает, настройка со стороны AD — в статье 04 [практика].
4. На клиенте в свойствах обозревателя разрешена встроенная проверка подлинности Windows; после изменений перезагрузить **клиентский** компьютер (рабочие серверы — не нужно).

Аутентификация Windows при разнесённых IIS и рабочих серверах в **тонком клиенте** работает начиная с 8.3.10.2620 [ИТС-мет 5944].

Браузеры в 2026 году [ИТС-адм разд. 9.2.2; MS Learn]:

| Браузер | Разрешить встроенную аутентификацию | Разрешить делегирование билета |
|---|---|---|
| Firefox (`about:config`) | `network.negotiate-auth.trusted-uris` (Kerberos), `network.automatic-ntlm-auth.trusted-uris` (NTLM) | `network.negotiate-auth.delegation-uris` — нужно для клиент-серверной базы с отдельным веб-сервером |
| Microsoft Edge (политики) | `AuthServerAllowlist` | `AuthNegotiateDelegateAllowlist` |
| Google Chrome | одноимённые политики Chromium ⚠ (не сверялось по документации Google) | то же |

Без политики Edge отвечает на запрос встроенной аутентификации только для сайтов, распознанных как интрасеть [MS Learn]. Если имени веб-сервера нет в `network.negotiate-auth.trusted-uris`, Firefox показывает 401 [ИТС-адм разд. 9.2.2].

### 10.4. Смешанная среда: IIS на Windows, сервер 1С на Ubuntu

- Linux-сервер 1С принимает аутентификацию ОС только по Kerberos, по keytab службы `usr1cv8` (SPN вида `usr1cv8/<FQDN сервера>@REALM`) [`../1c/08`, пп. 6–9 «Кратко»; `../its-metod/kerberos-openid-autentifikaciya.md`].
- Для входа через IIS нужны: Kerberos (не NTLM) между браузером и IIS, делегирование от учётной записи компьютера IIS к этому SPN и keytab на Linux-сервере. Если браузер откатится на NTLM (нет SPN `HTTP/…`, обращение по IP, нет доверия к сайту), делегировать будет нечего — вход не пройдёт [практика ⚠: сценарий «IIS → Linux-кластер» в документации 1С не описан, проверить на стенде].
- Альтернативы без двойного перехода: Apache на Linux с Kerberos (`../1c/05`, раздел 11.3), OpenID/OpenID Connect от корпоративного провайдера, пароли 1С поверх HTTPS.

### 10.5. SPN и пул приложений

- Если SPN явно не объявлен, Kerberos в IIS работает только при идентичностях `NetworkService`, `ApplicationPoolIdentity` или системных — билет строится по SPN учётной записи компьютера [MS Learn, «Troubleshoot Kerberos failures in Internet Explorer»].
- Если пул работает под доменной учётной записью и SPN `HTTP/<имя>` объявлен на ней (типично для фермы IIS за одним именем), режим ядра не расшифрует билет — нужно `useAppPoolCredentials="true"` (или выключить режим ядра, что хуже) [MS Learn]. Дублирующиеся SPN на разных учётных записях дают ошибки `KRB_AP_ERR_MODIFIED`; поиск дублей — `setspn -X` [MS Learn].
- Регистрация SPN, делегирование и проверка `klist` — статья 04.

### 10.6. Большие билеты Kerberos → HTTP 400

У пользователей с большим числом групп заголовок `Authorization: Negotiate …` превышает 16 384 байта, http.sys отвечает 400 «Request header too long» ещё до IIS. Лечится увеличением `MaxFieldLength` и `MaxRequestBytes` (раздел 8.2) [MS Learn, «HTTP 400 error responses to HTTP requests» — по результатам поиска; «Http.sys registry settings»].

### 10.7. OpenID, OpenID Connect, токены, сохранение входа

- OpenID 2.0: провайдер — `<openid><provider><lifetime>…</lifetime></provider></openid>`, клиент — `<openid><rely url="https://<хост>/<провайдер>/e1cib/oid2op"/></openid>`, провайдер только по HTTPS [ИТС-адм разд. 8.8.1, 8.8.2]; требования к внешним провайдерам (cookie `vrs_oid2op_auth`, формат `?lid=<логин>`) — [ИТС-адм разд. 8.8.4]. OpenID Connect (`<openidconnect>`, в 8.5.1 — атрибут `imageDark`) и JWT (`<accessTokenAuthentication>`) — `../1c/05`, разделы 5.7–5.9, 11.5 [ИТС-адм прил. 3.21.9, 3.21.14].
- С 8.3.26 при OpenID-аутентификации флажки «Разрешить сохранение аутентификации» и «Сохранять аутентификацию по умолчанию» по умолчанию **выключены** и читаются из настроек сервера OpenID; раньше вход запоминался автоматически. Включить — в конфигураторе в дополнительных настройках аутентификации, программно (`ДополнительныеНастройкиАутентификации.ПолучитьНастройкиАвтоматическогоСохраненияАутентификации()` → `РазрешитьСохранение`, `СохранятьПоУмолчанию` → `УстановитьНастройкиАвтоматическогоСохраненияАутентификации()`) или готовой обработкой `SetSavePassByDefaultInAdditionalAuthSettings.epf` с диска ИТС: `1cv8 enterprise /Lru /F<база> /DisableStartupMessages /Execute SetSavePassByDefaultInAdditionalAuthSettings.epf` [ИТС-мет 6029, 2026]. Для клиент-серверной базы вместо `/F` — `/S <сервер>/<база>` (прямой слеш работает в любой ОС) [ИТС-адм прил. 7.3.1]. Подробнее — `../its-metod/kerberos-openid-autentifikaciya.md`, раздел 3.

## 11. Веб-сервисы, HTTP-сервисы, OData, мобильный и веб-клиент

### 11.1. Публикация сервисов

- В диалоге: закладка «Web-сервисы» → «Публиковать Web-сервисы» и выбор (колонка «Адрес» — синоним); «HTTP-сервисы» → «Публиковать HTTP-сервисы по умолчанию»; OData — флажок на закладке «Основные» [ИТС-адм разд. 8.3.2.2.2, 8.3.2.2.3, 8.5.1, 8.6.1, 8.7.1].
- Через `webinst` — только с шаблоном: в диалоге выбрать IIS, отметить сервисы, «Сохранить» (`iis-template.vrd`), затем `webinst -publish -iis … -descriptor iis-template.vrd` [ИТС-адм разд. 8.5.3.2.3, 8.6.3.2.3, 8.7.3.2.3]; без шаблона `webinst` публикует только веб-клиент [ИТС-адм разд. 2.6.3.8]. Права — как для клиента [ИТС-адм разд. 8.5.3.2.1].
- Для интеграций удобна **отдельная публикация** той же базы только под сервисы: `enable="false"` у `point`, явный список сервисов, свой пул, при необходимости ограничение по IP (`Web-IP-Security`) [ИТС-адм прил. 3.21.2, 3.21.4; схема — практика].

Пример шаблона для отдельной публикации API (имена сервисов условные):

```xml
<?xml version="1.0" encoding="UTF-8"?>
<point xmlns="http://v8.1c.ru/8.2/virtual-resource-system"
       xmlns:xs="http://www.w3.org/2001/XMLSchema"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       base="/demo-api"
       ib="Srvr=&quot;srv-1c-app&quot;;Ref=&quot;demo&quot;;"
       enable="false">
    <ws enable="true" pointEnableCommon="false" publishExtensionsByDefault="false">
        <point name="ExchangeService" alias="exchange" enable="true"/>
    </ws>
    <httpServices publishByDefault="false" publishExtensionsByDefault="true">
        <service name="API" rootUrl="api" enable="true" reuseSessions="autouse" sessionMaxAge="20"/>
    </httpServices>
    <standardOData enable="true" reuseSessions="autouse" sessionMaxAge="20"/>
</point>
```

Атрибуты и значения — [ИТС-адм прил. 3.21.3, 3.21.4, 3.21.11]; `rootUrl` должен совпадать со свойством «Корневой URL» HTTP-сервиса [ИТС-адм прил. 3.21.4.2]. Повторное использование сеансов (`reuseSessions`) для OData по умолчанию выключено [ИТС-адм прил. 3.21.11] — для интенсивного опроса OData его включают, иначе каждый запрос начинает новый сеанс [практика].

### 11.2. OData: ещё два условия

- Объекты нужно разрешить в самой базе методом `УстановитьСоставСтандартногоИнтерфейсаOData()` (в режиме совместимости 8.3.4 и ниже — не требуется); это можно сделать внешней обработкой без изменения конфигурации [ИТС-разр гл. 17.4.12].
- Длина URL: OData-запросы упираются в `maxQueryString` IIS (2048) и `UrlSegmentMaxLength` http.sys (260 символов на сегмент) — раздел 8 [ИТС-адм разд. 8.10.2.4; MS Learn].
- Проверка: `curl.exe -u "<пользователь 1С>:<пароль>" "https://web1c.corp.local/demo/odata/standard.odata/$metadata"` — ответ XML с описанием [ИТС-разр гл. 17.4; форма команды — практика]. В PowerShell `$metadata` берите в одинарные кавычки, иначе PowerShell подставит переменную.

### 11.3. Мобильный клиент и мобильные приложения

Мобильный клиент работает через ту же публикацию, что тонкий и веб-клиент (флажок «Публиковать доступ для клиентских приложений») [ИТС-адм разд. 8.3.2.2.1]. Обмен мобильных приложений на мобильной платформе, как правило, идёт через веб-сервисы, требования задаёт прикладное решение [ИТС-адм разд. 13.3]. Для входа по QR-коду в `default.vrd` перечисляются мобильные приложения (`<mobileApps><application type="googleplay|appstore|huaweiappgallery|rustore" …/>`) [ИТС-адм прил. 3.21.16]. Через Интернет — только HTTPS с сертификатом, которому доверяет устройство [практика].

### 11.4. Веб-клиент: встраивание, выход, обратный прокси

- Встраивание веб-клиента в чужой сайт — заголовок `X-Frame-Options` у приложения: `sameorigin`, `allow-from <сайт>` или `deny`; если не нужно — убедиться, что `deny` не задан [ИТС-адм разд. 8.10.2.7]. В IIS — «Заголовки ответа HTTP» приложения (`allow-from` устарел: браузеры игнорируют заголовок с этим значением целиком, вместо него — `Content-Security-Policy: frame-ancestors <сайт>` [MDN; так же в `../apache/02-…` и `../iis/02-…`]).
- За обратным прокси (ARR, nginx, балансировщик) передавать `X-Forwarded-Port`, `X-Forwarded-Host`, `X-Forwarded-Proto`, `X-Forwarded-For` [ИТС-адм разд. 8.10.3]. Сервер отладки через IIS (`/debugger/` → порт 1550 через URL Rewrite и ARR) — `../its-metod/veb-https-apache-nginx-i-nastrojka-rabochih-serverov.md`, раздел 3.6 [ИТС-мет 5973, 2020]; на продуктиве без ограничения доступа не публиковать.

### 11.5. Отладка через публикацию

Элемент `<debug enable="true" protocol="http" url="http://<ПК разработчика>:1561"/>` включает отладку сеансов публикации; при `protocol="tcp"` без порта проверяются порты 1560–1591; протокол должен совпадать со схемой URL, иначе работа идёт без отладки [ИТС-адм прил. 3.21.6]. На продуктивной публикации отладку держать выключенной [практика].

### 11.6. Автообновление тонкого клиента через IIS

Для `.zip` должен быть MIME-тип `application/x-zip-compressed` (умолчание IIS) или `application/zip` (рекомендация IANA); проверять в «Типах MIME» на уровне сервера, сайта и приложения, при отсутствии записи для `.zip` — создать [ИТС-адм разд. 8.10.2.6]. Проверка: `%windir%\system32\inetsrv\appcmd list config "Default Web Site/demo" -section:staticContent | findstr /i zip` [практика ⚠: имя секции `staticContent` не сверялось]. Архив — без каталогов внутри, подписи файлов должны проходить проверку на клиенте [ИТС-адм прил. 3.21.2].

## 12. Настройка под нагрузку и стабильность

### 12.1. Рабочие процессы и пулы

- Клиент-серверная база, 8.3.26+: ~1 рабочий процесс на ~100 сеансов (1000 сеансов — 10) [ИТС-мет 6034, 2025]; файловая — строго 1 [ИТС-адм разд. 8.10.2.2]; реализация — раздел 7.4.
- Отдельные пулы для «тяжёлых» интеграций (OData-выгрузки в BI, обмены) и для пользователей; ночная переработка по расписанию, `idleTimeout` = 0, `AlwaysRunning` — раздел 7 [практика].
- `<pool>` (раздел 5.3) обычно не трогают; `serverPingPeriod`/`serverPingTimeout` управляют обнаружением разрыва соединения с кластером [ИТС-адм прил. 3.21.5] — через нестабильный канал (VPN до кластера) их увеличивают [практика ⚠].

### 12.2. Очереди и отказы

- Очередь пула (`queueLength`, 1000) переполнена → 503 от http.sys [MS Learn]: `w3wp` не успевает — смотреть и медленные вызовы в кластере 1С [практика]. 503.2 — превышен `appConcurrentRequestLimit` (умолчание 5000 по справочнику `serverRuntime` — уточнено 20.10.2026 при проверке `iis/`), 500.13 — сервер слишком занят [MS Learn].
- Текущие запросы и длительность: `appcmd list requests` (по пулу — `/apppool.name:"1C-<версия>"`), рабочие процессы — `appcmd list wps` [MS Learn].

### 12.3. Сжатие и антивирус

Динамическое сжатие (`Web-Dyn-Compression`) экономит канал ценой CPU хоста [практика ⚠]; трафик тонкого клиента 1С сжимает сама платформа (параметр `/TComp`, по умолчанию Zstandard [ИТС-адм прил. 7]), поэтому для публикации 1С сжатие в IIS обычно не включают — см. `../iis/03-…`. Каталоги публикации, `bin` версий, временный каталог модуля и журналы IIS обычно исключают из проверки антивирусом в реальном времени [практика; `06-windows-server-dlya-administratora-1c.md`].

### 12.4. Несколько серверов IIS

Состояние сеансов хранится в кластере 1С, поэтому несколько IIS за балансировщиком обслуживают одну базу; при аутентификации Windows с общим именем фермы SPN `HTTP/<общее имя>` ставится на доменную учётную запись пулов, а в IIS включается `useAppPoolCredentials` (раздел 10.5) [MS Learn; схема для 1С — практика ⚠: нужна ли «липкость» сессий на балансировщике для веб-клиента, в документации не сказано — по умолчанию включайте привязку к узлу]. Версии модулей на всех узлах — одинаковые [ИТС-адм разд. 8.3.1].

## 13. Apache под Windows (кратко)

Когда нужен: IIS использовать нельзя или требуется единая с Linux конфигурация публикаций. На Linux всё про Apache — `../1c/05-veb-publikaciya-apache-nginx.md`; ниже только отличия Windows.

- Установка по методичке 2020 года: ZIP-сборка Apache 2.4 для Windows, распаковка в `C:\Apache24`, в консоли администратора `httpd.exe -k install` — служба Apache [ИТС-мет 5978, 2020]. ИТС отсылает за дистрибутивом на сайт проекта [ИТС-адм разд. 8.1], а методичка берёт первую сборку из списка реализаций для Windows [ИТС-мет 5978]; сам проект Apache, по практике, двоичных сборок для Windows не выпускает и ссылается на сторонние ⚠ — скачивать только из доверенного источника и сверять контрольные суммы.
- HTTPS: сертификат и ключ выпускаются OpenSSL, в `C:\Apache24\conf\extra\httpd-ahssl.conf` в секции `VirtualHost _default_:443` прописываются `SSLCertificateFile "${SRVROOT}/certs/<сервер>.crt"` и `SSLCertificateKeyFile "${SRVROOT}/certs/<сервер>.key"` [ИТС-мет 5978]. ⚠ Имя `httpd-ahssl.conf` специфично для сборки, использованной в методичке.
- Публикация: диалог (Apache обнаруживается автоматически) или `webinst -publish -apache24 -wsdir demo -connstr "Srvr=srv-1c-app;Ref=demo;" -dir "C:\Apache24\htdocs\demo"`; для 2.4 `-confpath` можно не указывать, для 2.0/2.2 — путь к `httpd.conf` обязателен [ИТС-адм разд. 8.4.3.5.3, прил. 4.14]. Разрядность конфигуратора и Apache должны совпадать; для разных версий 1С — отдельные экземпляры Apache, публикация вручную [ИТС-адм разд. 8.2].
- Как 1С ищет Apache 2.4 в Windows: параметр реестра `HKLM\SYSTEM\CurrentControlSet\Services\Apache2.4\ImagePath` (служба с именем **`Apache2.4`**), затем `HKLM\Software\Apache Software Foundation\Apache\2.4` (`ServerRoot`), затем `C:\Program Files\Apache Software Foundation\Apache2.4\conf` [ИТС-адм разд. 8.10.1.2.3]. ⚠ `httpd.exe -k install` без `-n` создаёт службу с именем `Apache2.4` — тогда обнаружение срабатывает; при другом имени службы указывайте `-confpath` явно.
- Права: пользователю, от которого работает служба Apache, — чтение `bin` версии; для файловой базы — изменение каталога базы [ИТС-адм разд. 8.4.3.5.1].
- Файловая база на Apache 2.2 в Windows: рекомендуется `<IfModule mpm_winnt_module> ThreadStackSize 8388608 </IfModule>`, при исчерпании стека — увеличить [ИТС-адм разд. 8.10.1.1].
- Аутентификация ОС через Apache в Windows не настраивается: `-osauth` применяется только к IIS [ИТС-адм прил. 4.14; `../1c/05`, раздел 11.1].
- `X-Frame-Options` в Apache — `Header set X-Frame-Options "sameorigin"` с модулем `mod_headers` [ИТС-адм разд. 8.10.1.3].
- В 8.5.4 поддержка Apache 2.0 и 2.2 прекращена, остаётся 2.4 (`../1c/05`, п. 1 «Кратко», по V8Update 8.5.4).

Отличия от Linux-публикации (`../1c/05`): `.dll` вместо `.so`, `httpd.conf` в каталоге установки Apache, служба Windows вместо `systemd`, без групп-владельцев каталогов (в Linux публикация выставляет группу веб-сервера на каталог с `default.vrd` [ИТС-адм разд. 8.3.2.1]), `mpm_winnt` вместо `worker`/`event` [практика].

## 14. Диагностика

### 14.1. Порядок проверки

1. Открывается ли `http(s)://<хост>/` (стартовая страница IIS)? Нет — сеть, брандмауэр, привязки, служба `W3SVC`.
2. Есть ли приложение и в каком пуле (`appcmd list apps`), запущен ли пул (`appcmd list apppools`), есть ли `w3wp` (`appcmd list wps`).
3. Что в журнале IIS для этого запроса: код, **подстатус**, `sc-win32-status`, `time-taken`.
4. Если 500 — включить подробные ошибки (14.4) или FREB (14.3).
5. Если IIS отдал запрос модулю, а 1С ругается — техжурнал на хосте IIS и на сервере 1С (14.5), журнал регистрации базы.
6. Если сеанс не стартует — доступность кластера с хоста IIS (`Test-NetConnection srv-1c-app -Port 1541`, затем порты рабочих процессов), совпадение версий модуля и кластера.

### 14.2. Журналы IIS и Windows

- Журнал сайта — по умолчанию в `%SystemDrive%\inetpub\logs\LogFiles` (подкаталог `W3SVC<id сайта>`, у Default Web Site id = 1) [MS Learn, `logFile directory`]. Полезные поля W3C: `sc-status`, `sc-substatus`, `sc-win32-status`, `time-taken`, `cs-username` [практика]. Быстрый поиск ошибок:

```powershell
Get-ChildItem "C:\inetpub\logs\LogFiles\W3SVC1" | Sort-Object LastWriteTime -Descending | Select-Object -First 1 |
  Get-Content -Tail 2000 | Select-String " 50[0-9] | 40[0-4] " | Select-Object -Last 30
```

- Ошибки уровня http.sys (до IIS: 400, 503 при остановленном пуле, обрывы соединений) пишутся в `HTTPERR` — `%SystemRoot%\System32\LogFiles\HTTPERR` (параметр `ErrorLoggingDir` в документации HTTP Server API — уточнено 20.10.2026 при проверке `iis/`).
- Журнал Windows «Система» (источник WAS) — остановка пула защитой от частых сбоев; «Приложение» — падения `w3wp.exe` с указанием сбойного модуля (если `wsisapi.dll` — версия/разрядность модуля или ошибка 1С) [практика].

### 14.3. Трассировка неудачных запросов (FREB)

Нужен компонент «Трассировка» (`Web-Http-Tracing`) [MS Learn]. Порядок: в диспетчере IIS у сайта «Действия → Трассировка неудачных запросов…» → «Включить» (в `applicationHost.config` появится `traceFailedRequestsLogging enabled="true"`); затем «Правила трассировки неудачных запросов → Добавить…»: содержимое «Всё (*)», условие — коды состояния (например, `500,503,404.2`) или время выполнения, поставщик «WWW Server», подробность «Подробно». Файлы — по одному на неудачный запрос — пишутся в `%SystemDrive%\inetpub\logs\FailedReqLogFiles\W3SVC<id>\fr000001.xml` вместе с таблицей стилей `freb.xsl`; правило можно задать и по превышению времени выполнения (`timeTaken`) [MS Learn, «Troubleshoot failed requests using tracing in IIS»]. Перед экспериментами — резервная копия конфигурации IIS: `appcmd add backup <имя>`, откат — `appcmd restore backup "<имя>"` [MS Learn].

### 14.4. Подробные сообщения об ошибках

Если ошибки 1С видны как «500 — внутренняя ошибка сервера. Проблема с запрашиваемым ресурсом…», в диспетчере IIS: сайт → приложение → «Страницы ошибок» → «Изменить параметры…» → «Подробные сообщения об ошибках» → ОК [ИТС-адм разд. 8.10.2.3]. На публикации, доступной из Интернета, после диагностики вернуть «Подробные для локальных запросов, настраиваемые для удалённых» [практика] — подробные ошибки раскрывают внутренние пути.

### 14.5. Технологический журнал на хосте IIS

- `logcfg.xml` ищется в каталогах конфигурационных файлов: `bin\conf` версии, `%LOCALAPPDATA%\1C\1cv8\conf` пользователя процесса, каталог из `ConfLocation`, `%ALLUSERSPROFILE%\1C\1cv8\conf`; при установке общие конфигурационные файлы пишутся в `C:\Program Files\1cv8\conf` [ИТС-адм прил. 1.3.4]. Каталог журнала должен быть доступен на запись пользователю расширения веб-сервера [ИТС-адм разд. 6.14.2].
- События HTTP-запросов к расширению — `VRSREQUEST`, `VRSRESPONSE` (у `VRSRESPONSE` есть свойство с кодом состояния HTTP) [ИТС-адм прил. 3.24]. Подробно о техжурнале — `../1c/07-tehzhurnal-diagnostika-zhurnal-registracii.md`.
- Проблемы аутентификации Windows — события `CONN`/`EXCP` на **сервере 1С** (раздел 10.2) [ИТС-мет 5944].

### 14.6. Коды ответа: что значат для публикации 1С

Подстатусы и общие значения — [MS Learn, «HTTP status code overview»]; связь с 1С — по разделам статьи.

| Код | Значение IIS | Типичная причина в публикации 1С | Что делать |
|---|---|---|---|
| 400 (от http.sys) | неверный запрос / заголовок слишком длинный | большой билет Kerberos; сегмент URL длиннее `UrlSegmentMaxLength` | раздел 8.2, 10.6 |
| 401.1 / 401.2 | вход не выполнен / ошибка конфигурации аутентификации | Windows-аутентификация без нужного поставщика, браузер не доверяет сайту, отключены все методы | раздел 10.2–10.3 |
| 403.14 | просмотр каталога запрещён | у приложения нет обработчика `wsisapi.dll`, IIS ищет документ по умолчанию | раздел 4.5–4.6 |
| 404.2 | ограничение ISAPI или CGI | `wsisapi.dll` (новой версии) не разрешён в «Ограничениях ISAPI и CGI» | разрешить путь модуля (4.6, шаг 3) |
| 404.3 | ограничение MIME-типа | обработчик не сопоставлен — запрос ушёл статическому обработчику; либо не установлены «Расширения ISAPI»; для `.zip` дистрибутива — нет MIME-типа | разделы 2, 4.6, 11.6 |
| 404.4 | обработчик не настроен | нет сопоставления `*` → `wsisapi.dll` | раздел 4.6 |
| 404.7 / 404.8 / 404.11 | расширение запрещено / скрытый сегмент / двойное экранирование | URL HTTP-сервиса или OData задевает фильтры запросов | раздел 8.1 |
| 404.13 (413.1) | слишком большое содержимое | загрузка файла > 28,6 МБ | `maxAllowedContentLength` |
| 404.14 / 404.15 | длинный URL / строка запроса | OData, GET-параметры HTTP-сервиса | `maxUrl`, `maxQueryString` |
| 500.0 | ошибка модуля или ISAPI | ошибка внутри 1С (нет связи с кластером, неверный `ib`, нет прав на `bin`, версия модуля ≠ версии кластера) | подробные ошибки (14.4), техжурнал (14.5) |

| 503 (без подстатуса, HTTPERR) | очередь пула переполнена | `w3wp` не успевает (медленный кластер, мало рабочих процессов) | раздел 12 |

## Типичные ошибки (симптом → причина → решение)

| Симптом | Причина | Решение |
|---|---|---|
| Публикация из конфигуратора «прошла», но в IIS ничего нет | конфигуратор запущен без «от имени администратора», пользователь согласился продолжить | повторить от администратора [ИТС-адм разд. 8.2] |
| `webinst` отработал, публикация неполная | `webinst` при нехватке прав только предупреждает и продолжает | запускать из консоли администратора; проверить `appcmd list apps` [ИТС-адм разд. 8.2] |
| После обновления кластера на новую сборку веб-клиент не входит, ошибки версии | модуль на IIS старой сборки | поставить ту же сборку на хост IIS, перепубликовать, отдельный пул (раздел 4.7) [ИТС-адм разд. 8.3.1] |
| После перепубликации новой версией перестали работать **старые** публикации | две версии модуля (разные 3-я/4-я цифры) в DefaultAppPool | пул на версию, перенести приложения [ИТС-адм разд. 8.10.2.2] |
| 503, в журнале «Система» — пул остановлен | 5 падений `w3wp` за 5 минут; разрядность модуля не та | `enable32BitAppOnWin64` по разрядности модуля, запуск пула [ИТС-адм разд. 8.10.2.1; MS Learn] |
| `webinst` отказывается публиковать | `-dir` указывает на сам `wwwroot` или путь в кавычках с завершающим `\` | подкаталог `"C:\inetpub\wwwroot\demo"` без `\` в конце [ИТС-адм прил. 4.14] |
| Веб-клиент файловой базы «теряет» результаты фоновых заданий, зависает | в пуле больше одного рабочего процесса | `maxProcesses=1` для пулов файловых баз [ИТС-адм разд. 8.10.2.2] |
| Кратковременные зависания у пользователей веб-клиента на 8.3.26+ при сотнях сеансов | один `w3wp` на всё | ~1 рабочий процесс на 100 сеансов [ИТС-мет 6034] |
| Раз в сутки обрываются длинные операции; первый вход утром долгий | переработка пула каждые 29 ч (`shutdownTimeLimit` 90 с); `idleTimeout` 20 мин | ночной перезапуск по расписанию, `idleTimeout=0`, `AlwaysRunning` (раздел 7) [MS Learn; практика] |
| Файл > ~28 МБ не загружается; длинные запросы OData дают 404/400 | `maxAllowedContentLength`, `maxQueryString`, `maxUrl`, `UrlSegmentMaxLength` | разделы 8.1–8.2 [MS Learn; ИТС-адм разд. 8.10.2.4] |
| Аутентификация ОС: окно ввода логина и пароля вместо входа | имя пользователя ОС в 1С не совпадает с тем, что видит сервер | `DstUserName2` из техжурнала, формат `\\ДОМЕН\имя` [ИТС-мет 5944] |
| То же, в техжурнале `DstUserName2: NT AUTHORITY\ANONYMOUS LOGON` | IIS и сервер 1С на разных машинах, нет делегирования Kerberos | раздел 10.3 [ИТС-мет 5944] |
| То же, сервер 1С на Linux | NTLM вместо Kerberos или нет делегирования к SPN `usr1cv8` | раздел 10.4 ⚠ |
| HTTP 400 только у части доменных пользователей | большой билет Kerberos (много групп) | `MaxFieldLength`, `MaxRequestBytes` [MS Learn] |
| Веб- или HTTP-сервис из расширения недоступен | `publishExtensionsByDefault=false` по умолчанию у `<ws>` и `<httpServices>` | включить или перечислить сервис в `default.vrd` [ИТС-адм прил. 3.21.3.1, 3.21.4.1] |
| Веб-сервис доступен по имени, но не по синониму | сервис не перечислен в `default.vrd` | добавить `<point name=… alias=…/>` [ИТС-адм прил. 3.21.3.2] |
| OData отвечает ошибкой, хотя публикация есть | нет `<standardOData>` или состав не задан `УстановитьСоставСтандартногоИнтерфейсаOData()` | [ИТС-адм прил. 3.21.11; ИТС-разр гл. 17.4.12] |
| Изменили `sessionMaxAge`/`reuseSessions`, ничего не поменялось | действуют после перезапуска сервера 1С | перезапуск службы сервера 1С в окно обслуживания [ИТС-адм прил. 3.21.3.2] |
| После `webinst -descriptor` пропали ручные правки `default.vrd` | шаблон полностью замещает файл | держать правки в шаблоне [ИТС-адм прил. 4.14] |
| Тонкий клиент не обновляется через веб-сервер | нет MIME-типа `.zip` или нет `bin\distr` | раздел 11.6, 3.4 [ИТС-адм разд. 8.10.2.6, 11.2.3] |
| После 8.3.26 OpenID перестал запоминать вход | новые флажки сохранения аутентификации выключены по умолчанию | включить в настройках аутентификации базы и `<authentication>` [ИТС-мет 6029; ИТС-адм прил. 3.21.15] |
| «Не удалось выполнить проверку отзыва сертификата» | учётная запись процесса не достаёт до CRL | журнал CAPI2, доступ к CRL, при необходимости `IgnoreServerCertificatesChainRevocationSoftFail` [ИТС-мет 5949; ИТС-адм прил. 3.17.16] |
| Сертификат установлен, клиент 1С ругается на него | Unicode в полях сертификата, неверное имя, нет корневого ЦС в хранилище Windows клиента | перевыпустить с ASCII/Punycode и правильным SAN, раздать корневой сертификат [ИТС-адм разд. 8.9.2; ИТС-мет 5949] |
| Версия 1С на веб-хосте «сама» удалилась | автоудаление не видит публикации вне `c:\inetpub\wwwroot` | публиковать в подкаталоги `wwwroot`, `DontUninstallVersion` [ИТС-адм разд. 12.2.4, прил. 3.6.11] |
| Apache под Windows: публикация не видит Apache | служба названа не `Apache2.4` | указать `-confpath` [ИТС-адм разд. 8.10.1.2.3] |

## Быстрая шпаргалка — задача → команда

Все команды — в консоли от имени администратора; `appcmd` — из `%windir%\system32\inetsrv`.

| Задача | Команда |
|---|---|
| Установить IIS для 1С (Server) | `Install-WindowsFeature -Name Web-Server,Web-ISAPI-Ext,Web-ISAPI-Filter,Web-Windows-Auth,Web-Http-Tracing -IncludeManagementTools` |
| То же (Windows 10/11) | `Enable-WindowsOptionalFeature -Online -All -FeatureName IIS-WebServerRole,IIS-WebServer,IIS-ISAPIExtensions,IIS-ISAPIFilter,IIS-WindowsAuthentication,IIS-HttpTracing,IIS-ManagementConsole` |
| Что из IIS установлено | `Get-WindowsFeature Web-* \| Where-Object Installed` |
| Есть ли модуль 1С нужной версии | `Test-Path "C:\Program Files\1cv8\<версия>\bin\wsisapi.dll"` |
| Опубликовать веб-клиент | `webinst -publish -iis -wsdir demo -dir "C:\inetpub\wwwroot\demo" -connstr "Srvr=srv-1c-app;Ref=demo;"` |
| То же с аутентификацией ОС | добавить `-osauth` |
| Опубликовать сервисы/OData по шаблону | `webinst -publish -iis -wsdir demo-api -dir "C:\inetpub\wwwroot\demo-api" -connstr "…" -descriptor iis-template.vrd` |
| Удалить публикацию | `webinst -delete -iis -wsdir demo` |
| Список приложений и их пулов | `appcmd list apps /site.name:"Default Web Site"` |
| Создать пул для версии | `appcmd add apppool /name:"1C-<версия>"` и `appcmd set apppool "1C-<версия>" /managedRuntimeVersion:""` |
| Рабочих процессов в пуле (8.3.26+, ~100 сеансов на процесс) | `appcmd set apppool "1C-<версия>" /processModel.maxProcesses:4` |
| Перенести публикацию в пул | `appcmd set app "Default Web Site/demo" /applicationPool:"1C-<версия>"` |
| Параметры пула целиком | `appcmd list apppool "1C-<версия>" /text:*` |
| Обработчики публикации | `appcmd list config "Default Web Site/demo" /section:handlers` |
| Разрешённые ISAPI-модули | `appcmd list config /section:system.webServer/security/isapiCgiRestriction` |
| Увеличить лимит тела запроса до 1 ГБ | `appcmd set config "Default Web Site/demo" -section:system.webServer/security/requestFiltering /requestLimits.maxAllowedContentLength:1073741824` |
| Длинная строка запроса OData | `appcmd set config "Default Web Site/demo" -section:system.webServer/security/requestFiltering /requestLimits.maxQueryString:32768` |
| Сегмент URL длиннее 260 | `New-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Services\HTTP\Parameters" -Name UrlSegmentMaxLength -PropertyType DWord -Value 4096 -Force` + перезагрузка |
| Включить Windows-аутентификацию, выключить анонимную | `appcmd set config "Default Web Site/demo" -section:system.webServer/security/authentication/windowsAuthentication /enabled:"True" /commit:apphost` и то же для `anonymousAuthentication` с `"False"` |
| Привязать сертификат к 443 | `New-IISSiteBinding -Name "Default Web Site" -BindingInformation "*:443:" -CertificateThumbPrint <отпечаток> -CertStoreLocation "Cert:\LocalMachine\My" -Protocol https` |
| Включить журнал CAPI2 | `wevtutil sl Microsoft-Windows-CAPI2/Operational /e:true` |
| Проверить порт кластера с хоста IIS | `Test-NetConnection srv-1c-app -Port 1541` |
| Текущие запросы и рабочие процессы | `appcmd list requests` / `appcmd list wps` |
| Резервная копия и откат конфигурации IIS | `appcmd add backup before-1c` / `appcmd restore backup "before-1c"` |
| Перезапуск IIS | `iisreset` |
| Публикация на Apache 2.4 (Windows) | `webinst -publish -apache24 -wsdir demo -connstr "…" -dir "C:\Apache24\htdocs\demo"` |

## Что не удалось подтвердить

1. Точное содержимое того, что `webinst`/конфигуратор записывают в IIS: `web.config` с обработчиком «1C Web-service Extension», набор его атрибутов, автоматическое добавление `wsisapi.dll` в «Ограничения ISAPI и CGI», состояние анонимной аутентификации при `-osauth` — документация описывает только общую схему (разд. 8.3.1). 2. Команды ручной публикации `appcmd set config … /section:handlers /+"[…]"` и `… isapiCgiRestriction /+"[…]"` — синтаксис построен по образцу Microsoft для коллекций, на IIS не выполнялся.

4. Имя msi-пакета дистрибутива 8.3 для `msiexec` — в ИТС пример только для 8.2 («1CEnterprise 8.2.msi»); в статье оставлено `<пакет>.msi`.

7. Работа аутентификации Windows «браузер → IIS (Windows) → кластер 1С на Linux» через делегирование Kerberos к SPN `usr1cv8` — 1С описывает делегирование только для рабочих серверов Windows (ИТС-мет 5944).
