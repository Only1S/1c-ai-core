## Кратко — главные факты и команды

1. Драйвер ключа HASP: `C:\Program Files\1cv8\common\haspdinst.exe` — `-i` установка, `-r` удаление (в методичке 5936 — `-remove`), `-info` версия; ставить **до** подключения ключа [ИТС-адм разд. 10.2.7.1; ИТС-мет 5936, 2017].
2. С драйвером ставится служба **Sentinel LDK License Manager** (`hasplms`, веб-интерфейс `http://localhost:1947`); 1С она не нужна — `sc.exe config hasplms start= disabled`, `sc.exe stop hasplms` [ИТС-мет 5936, 2017; ИТС-адм разд. 2.5.2.8].
3. Сетевые ключи раздаёт **HASP License Manager** (`lmsetup.exe` → служба «HASP Loader», `nhsrvw32.exe`): только **UDP 475**, только **IPv4**; на терминальный сервер не ставить [ИТС-адм разд. 10.2.1, 10.2.8.1, 10.2.9].
4. Клиент 1С ищет менеджер по `nethasp.ini` (`NH_SERVER_ADDR`) — удобно `C:\Program Files\1cv8\conf\nethasp.ini`; менеджер читает `nhsrv.ini` рядом со своим исполняемым файлом, для ключей на 300/500 поднять `NHS_USERLIST` (умолчание 250) [ИТС-адм прил. 3.25–3.26; ИТС-мет 3059, 2009].
5. Серверный ключ (`EN8SA`, `ENSR8`) только локальный — там, где `rphost`; USB over IP не поддерживается; локальный ключ в терминальной сессии не работает на Windows 7 / Server 2012 и новее [ИТС-адм разд. 10.2.3, 10.2.5.9.1, 10.2.6.1].
6. Файлы `*.lic` ищутся: `bin\conf` версии → `%LOCALAPPDATA%\1C\1cv8\conf` → `ConfLocation` → `%ALLUSERSPROFILE%\1C\1cv8\conf` → `%ALLUSERSPROFILE%\1C\licenses` → `%ProgramData%\1C\licenses`; серверная лицензия кладётся в `C:\ProgramData\1C\licenses` [ИТС-адм разд. 10.3.7.1, 10.3.8.2].
7. На Windows в привязку входят ещё **серийный номер и дата установки ОС** (кроме Windows 10) и версия ОС: переустановка Windows, переименование, обновление BIOS, замена сетевой карты, уменьшение памяти — повторная активация [ИТС-адм разд. 10.3.1.4].
8. «Рабочее место» на Windows = сеанс ОС: клиент 1С, запущенный из службы, занимает отдельную лицензию [ИТС-адм разд. 10.3.4.9.1].
9. `ring license` на Windows: хранилище `%ProgramData%\1C\licenses`, нужны Java 8+ и Windows Script Host; `ring license validate --name <пинкод-номер>` → код 1 — оборудование изменилось, 2 — подпись [ИТС-адм прил. 4.5].
10. Каталоги: программы `C:\Program Files\1cv8\<версия>\bin`, общие настройки `C:\Program Files\1cv8\conf` (на него указывает `ConfLocation`), данные кластера службы `C:\Program Files\1cv8\srvinfo` (путь в ключе `/d` службы) [ИТС-адм прил. 1.1.4, 1.3.4; ИТС-КС разд. 2.2.13].
11. Учётной записи службы (`USR1CV8`) нужны: полные права на каталог данных, «Вход в качестве службы», «Вход в качестве пакетного задания», группа Performance Log Users, «Список содержимого папки» на каталог временных файлов [ИТС-КС разд. 1.3.2].
12. `logcfg.xml` — в `C:\Program Files\1cv8\conf\`, перечитывается раз в 60 с; процессу нужны полные права на каталоги журнала, дампов и временных файлов и чтение каталога-владельца [ИТС-адм разд. 6.14.1, прил. 3.24.2.5.4].
13. Без `logcfg.xml` на Windows пишутся техжурнал по умолчанию (`%LOCALAPPDATA%\1C\1cv8\logs`, `SYSTEM`/`ERROR`, 24 ч) и **минимальные дампы** в `%LOCALAPPDATA%\1C\1cv8\dumps` — у службы это профиль `USR1CV8` [ИТС-адм прил. 3.24.1, 3.24.2.11].
14. Дампы платформы — элемент `<dump>` (только Windows): `<dump create="true" location="D:\1C\dumps" type="3" prntscrn="false" externaldump="1"/>`; `externaldump="1"` — дамп пишет `dumper.exe` [ИТС-адм прил. 3.24.2.5.4; ИТС-мет 5899, 2016].
15. Дампы ОС — WER `LocalDumps` (`HKLM\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps\<имя.exe>`: `DumpFolder`, `DumpType`, `DumpCount`) [MS Learn]; 1С советует их для `ragent` и `rmngr`, не для `rphost` [ИТС-мет 5908, 2022]. Зависший процесс — `procdump.exe -ma <PID>` [ИТС-мет 5899, 2016].
16. Журнал событий: падение службы — Service Control Manager 7034/7031 (System), падение процесса — «Application Error» (Application); причины — в техжурнале и дампе [MS Learn; практика].
17. Ошибки проверки отзыва сертификата — журнал `Microsoft-Windows-CAPI2/Operational` (`wevtutil sl … /e:true`) и событие техжурнала `WINCERT`; в 8.3.27 `IgnoreServerCertificatesChainRevocationSoftFail` по умолчанию `true` [ИТС-мет 5949, 2018; ИТС-адм прил. 3.17.16].
18. Счётчики — постоянно, раз в 15 с: `logman create counter 1C_server -f bincirc -max 2048 -si 15 -cf <список> -o <файл>`, `logman start 1C_server`, автозапуск — планировщиком [ИТС-мет 5838, 2021; MS Learn].
19. Память процесса для мониторинга кластера: Windows — `PagefileUsage`, Linux — `VmRSS + VmSwap`; пороги 80% и 95% ОЗУ по умолчанию [ИТС-КС разд. 2.2.12].
20. Смешанная среда (сервер 1С на Ubuntu): серверная лицензия — на Linux-сервере; сетевой ключ в Windows-компьютере с HASP License Manager обслуживает и клиентов, и сервер (UDP 475, `nethasp.ini` на сервере); клиентам с лицензиями от сервера — `UseHwLicenses=0`; в 8.5.4+ вместо HASP License Manager — `rmlic` (TCP/UDP 475, 1544) [ИТС-адм разд. 10.4.1, прил. 3.6.15; ИТС-мет 6041, 2026].

## 2. Аппаратные ключи HASP на Windows

Общие правила (маркировка, порядок поиска, учёт «на компьютер» и «на сеанс», ключи в ВМ) уже разобраны в `../1c/04-licenzirovanie.md`, разд. 2, 5 и 6. Ниже — только то, что специфично для Windows.

### 2.1. Что важно знать до установки

| Правило | Источник |
|---|---|
| Защита — сетевая система HASP4 Net; в один компьютер имеет смысл ставить не более одного ключа каждой серии (`ORGL8`, `ORG8A`, `ORG8B`): одинаковые ключи неразличимы, работать будет один | [ИТС-адм разд. 10.2.1, 10.2.3] |
| Маркировка: `ORGL8` — локальный клиентский; `NET5…NET100 ORGL8` — многопользовательские на 5–100; `NET250+ ORG8A` — 300; `NET250+ ORG8B` — 500; `ENSR8` — 32-разрядный сервер; `EN8SA` — 64-разрядный сервер; 1000 пользователей = два ключа `ORG8B` | [ИТС-адм разд. 10.2.2] |
| Ключ сервера локальный и по сети недоступен; он должен стоять там, где работают `rphost` | [ИТС-адм разд. 10.2.6.1] |
| USB over IP (проброс ключа с хоста в ВМ по сети) не поддерживается; для ВМ — программные лицензии или сервис лицензирования на физическом компьютере | [ИТС-адм разд. 10.2.3] |
| Драйвер на компьютерах без ключа не нужен: многопользовательский ключ обслуживает HASP License Manager по сети | [ИТС-адм разд. 10.2.1] |
| Локальный ключ в терминальной сессии не работает на клиентских Windows 7 и новее и на Windows Server 2012 и новее; на старых ОС — только в сеансе с идентификатором 0 | [ИТС-адм разд. 10.2.5.9.1] |
| Многопользовательский ключ в терминальном сервере доступен только через HASP License Manager на этом же сервере; одно рабочее место = одна терминальная сессия | [ИТС-адм разд. 10.2.5.9.2] |
| HASP License Manager на терминальный сервер ставить не рекомендуется (возможна нестабильная работа) | [ИТС-адм разд. 10.2.8.1] |

Две последние строки документации противоречат друг другу: многопользовательский ключ в терминальном сервере требует менеджера на этом сервере, а сам менеджер там ставить не рекомендуется. Практический выход — ключ и менеджер на отдельном компьютере, терминальный сервер получает лицензии по сети [практика]. Для 8.5.4+ на терминальном сервере 1С, наоборот, рекомендует ставить свой «Менеджер Лицензий» как службу [ИТС-мет 6041, 2026].

### 2.2. Драйвер ключа (HASP Device Driver): установка, проверка, удаление

Программа установки драйвера `haspdinst.exe` входит в дистрибутив и при установке кластера кладётся в `C:\Program Files\1cv8\common\`; в меню «Пуск → 1С Предприятие 8» есть пункты «Установка драйвера защиты» и «Удаление драйвера защиты» [ИТС-адм разд. 10.2.7.1; ИТС-КС разд. 4.1]. Свежие версии — https://releases.1c.ru/project/AddCompDriverHASP (или сайт производителя, Thales/Gemalto) [ИТС-адм разд. 10.2.1; ИТС-мет 5936, 2017].

```powershell
# От имени администратора. Сначала драйвер, потом ключ в USB.
$hasp = 'C:\Program Files\1cv8\common\haspdinst.exe'
& $hasp -info      # версия установленного драйвера и версия драйвера внутри haspdinst [ИТС-мет 5936]
& $hasp -i         # установка [ИТС-адм разд. 10.2.7.1]
# & $hasp -r       # удаление по документации; в методичке 5936 — «-remove»

# Версия драйвера из реестра [ИТС-мет 5936]
reg.exe query "HKLM\SOFTWARE\Aladdin Knowledge Systems\HASP\Driver\Installer" /v Version
```

Проверка: `haspdinst -info` показывает версию; в «Диспетчере устройств» ключ виден как USB-устройство Sentinel/HASP [практика ⚠ — точное имя устройства не проверялось]. В методичке 2017 года минимально допустимая версия драйвера — 7.60; сейчас брать актуальную с releases.1c.ru [ИТС-мет 5936, 2017].

Ключ реестра указан в методичке для 32-разрядного представления; на 64-разрядной Windows он может оказаться в `HKLM\SOFTWARE\WOW6432Node\Aladdin Knowledge Systems\...` ⚠ — если первая команда ничего не нашла, проверить второй путь.

Установщик платформы предлагает поставить драйвер последним шагом (только при установке «для компьютера»); при «бесшумной» установке это делают отдельно командой выше [ИТС-адм разд. 2.5.2.8; ИТС-КС разд. 3.1.4.3.7].

### 2.3. Безопасность драйвера: служба Sentinel и веб-интерфейс на порту 1947

Методичка 5936 (21.11.2017, актуальна по смыслу) [ИТС-мет 5936, 2017]:

- драйвер состоит из собственно драйвера USB-ключа и веб-интерфейса управления; веб-интерфейс открывается в браузере на том же компьютере по адресу `http://localhost:1947/`;
- веб-интерфейс обслуживает служба **«Sentinel LDK License Manager»** (имя службы `hasplms`); её не путать с HASP License Manager, который раздаёт сетевые ключи 1С;
- защита 1С веб-интерфейс не использует, поэтому службу отключают; если аппаратная защита не используется вовсе — драйвер удаляют.

```powershell
Get-Service hasplms -ErrorAction SilentlyContinue | Format-List Name, DisplayName, Status, StartType
sc.exe config hasplms start= disabled     # пробел после «start=» обязателен
sc.exe stop hasplms
# Проверка: служба остановлена и отключена, порт 1947 никто не слушает
Get-Service hasplms | Select-Object Status, StartType
Get-NetTCPConnection -LocalPort 1947 -State Listen -ErrorAction SilentlyContinue   # пусто = выключено [практика]
```

На Linux тот же компонент — демон `hasplmd` из пакета Sentinel LDK RTE (см. `../1c/04-licenzirovanie.md`, разд. 6.5).

### 2.4. HASP License Manager на Windows

Нужен, только если **многопользовательский** ключ раздаёт лицензии по сети (клиентам или серверу 1С младше 8.5.4). Не нужен, если ключ вставлен в сервер 1С и клиентам лицензии выдаёт сам сервер [ИТС-адм разд. 10.2.5.3.3; ИТС-мет 3596, 2009].

Установка [ИТС-адм разд. 10.2.1, 10.2.8.1]: установщик `lmsetup.exe` с диска платформы или https://releases.1c.ru/project/AddCompNetHASP; режим «Service» — служба с автозапуском, исполняемые файлы кладутся в системный каталог Windows; в оснастке «Службы» она называется **«HASP Loader»** [ИТС-адм разд. 10.2.8.1.2]; драйвер, если уже стоит, повторно не ставить.

Ключи `nhsrvw32.exe` (режим приложения, с `-` или `/`) [ИТС-адм разд. 10.2.8.1.1]: `-tcpip` — только TCP/IP (в документации пример с опечаткой `nsrvw32`); `-portnum=<n>` — порт, по умолчанию **475**; `-localnet` — только локальная сеть (чужим — ошибка 140); `-nbname=<имя>` — имя NetBIOS до 8 символов; `-userlist` — лимит пользователей, по умолчанию 250; `-ipx`, `-ipxnosap`, `-netbios` — устаревшие протоколы, не включать [практика].

Брандмауэр компьютера с менеджером — входящий **UDP 475** (обращение всегда по UDP, только IPv4) [ИТС-адм разд. 10.2.1, 10.2.9]:

```powershell
New-NetFirewallRule -DisplayName '1C HASP License Manager UDP 475' -Direction Inbound `
  -Protocol UDP -LocalPort 475 -Action Allow -Profile Domain,Private      # [практика]
Get-Process -Id (Get-NetUDPEndpoint -LocalPort 475).OwningProcess        # кто слушает порт
```

Занятость ключей показывает утилита Aladdin Monitor (последняя версия 1.4.2, 2008, со сторонних сайтов [ИТС-мет 6041, 2026, по конспекту]); лицензии с `Timeout = 0` сервер 1С считает занятыми, поэтому один ключ не раздают одновременно менеджером и сервером 1С [ИТС-адм разд. 10.2.5.11].

### 2.5. `nhsrv.ini` — настройки менеджера лицензий

Порядок поиска файла на Windows [ИТС-адм прил. 3.26]: каталог исполняемого файла менеджера → текущий каталог Windows → системный каталог (`%SYSTEMROOT%\system32` для 32-разрядной, `%SYSTEMROOT%\SysWOW64` для 64-разрядной Windows) → `%SYSTEMROOT%` → каталоги из `PATH` (только в режиме приложения). Рекомендация: держать **единственную** копию рядом с исполняемым файлом менеджера; для службы это системный каталог, путь виден в свойствах службы «HASP Loader» (поле «Исполняемый файл») [ИТС-адм прил. 3.26; ИТС-мет 3059, 2009]. Для режима приложения на 64-разрядной Windows каталог по умолчанию — `C:\Program Files (x86)\Aladdin\HASP LM` [ИТС-мет 3059, 2009].

```ini
[NHS_SERVER]
; не более 250 подключений по умолчанию — для ключей на 300/500/1000 обязательно увеличить
NHS_USERLIST=600
; обслуживать только свою подсеть
NHS_IP_LIMIT=192.168.10.*
```

Параметры секции `[NHS_SERVER]`: `NHS_IP_LIMIT` (какие станции обслуживать: `10.1.1.1`, `10.1.1.*`, `10.1.1.1/24`), `NHS_ADAPTER` (через какие сетевые карты работать, только Win32), `NHS_USERLIST` (умолчание 250) [ИТС-адм прил. 3.26]. После правки — перезапустить службу и по журналу «Activity Log / Server Activity Log» в окне менеджера убедиться, что файл найден [ИТС-адм прил. 3.26; ИТС-мет 3059, 2009].

```powershell
# Где лежит исполняемый файл службы (там же должен быть nhsrv.ini)
Get-CimInstance Win32_Service | Where-Object { $_.DisplayName -like '*HASP*' -or $_.Name -like '*HASP*' } |
  Select-Object Name, DisplayName, State, StartName, PathName | Format-List
Restart-Service -DisplayName 'HASP Loader'      # ⚠ если отображаемое имя другое — взять Name из вывода выше
```

### 2.6. `nethasp.ini` на Windows: где лежит и как настроить

Файл читает **то приложение 1С, которое ищет сетевой ключ**: клиент на рабочем месте, сервер 1С (менеджер кластера с сервисом сеансовых данных), модуль расширения веб-сервера [ИТС-адм разд. 10.4.1; ИТС-мет 3596, 2009].

Порядок поиска на Windows [ИТС-адм прил. 3.25.1, прил. 1.3.4]:

1. каталоги конфигурационных файлов платформы: `bin\conf` версии → `%LOCALAPPDATA%\1C\1cv8\conf` → каталог `ConfLocation` (обычно `C:\Program Files\1cv8\conf`) → `%ALLUSERSPROFILE%\1C\1cv8\conf`;
2. если там нет: каталог исполняемых файлов запущенной версии → текущий каталог → `%SYSTEMROOT%\System32` (32-разрядная Windows) или `%SYSTEMROOT%\SysWOW64` (64-разрядная) → `%SYSTEMROOT%\System` → `%SYSTEMROOT%` → каталоги из `PATH`.

Установщик кладёт закомментированный образец в каталог `conf` установки; он ничего не переопределяет [ИТС-адм прил. 3.25.1]. Для сервера и для клиентов практично править именно `C:\Program Files\1cv8\conf\nethasp.ini` — файл не зависит от номера версии [практика].

Типовой файл: явный адрес менеджера, без широковещания, только TCP/IP [ИТС-адм разд. 10.2.9, прил. 3.25]:

```ini
[NH_COMMON]
NH_IPX=Disabled
NH_NETBIOS=Disabled
NH_TCPIP=Enabled

[NH_TCPIP]
NH_SERVER_ADDR=192.168.10.20
NH_PORT_NUMBER=475
NH_USE_BROADCAST=Disabled
; NH_TCPIP_METHOD=TCP игнорируется — обращение всегда по UDP
```

Умолчания: `NH_SESSION=2` с, `NH_SEND_RCV=1` с, `NH_PORT_NUMBER=475`, `NH_USE_BROADCAST=Enabled`; `NH_SERVER_NAME` — до 6 имён по 7 символов; `NH_NBNAME` — до 8 символов; регистр имён параметров не важен, комментарий — с `;` [ИТС-адм прил. 3.25.2–3.25.5]. Полная таблица параметров — `../1c/04-licenzirovanie.md`, разд. 6.6.

Приём из методички 3596 (2009, принцип действует): чтобы веб-пользователи не занимали лицензии офиса, ключ для веб-доступа вставить в сервер 1С **без** менеджера лицензий, а на сервере запретить поиск ключей по сети [ИТС-мет 3596, 2009]:

```ini
; C:\Program Files\1cv8\<версия>\bin\conf\nethasp.ini на сервере 1С
[NH_COMMON]
NH_IPX=Disabled
NH_NETBIOS=Disabled
NH_TCPIP=Disabled
```

Ограничение той же статьи: сервер работает максимум с одним локальным и одним сетевым ключом каждой серии, то есть через один менеджер кластера — не более 1800 клиентских лицензий; больше — назначить сервис сеансовых данных нескольким менеджерам кластера на разных компьютерах, каждому — свой `nethasp.ini` со своим `NH_SERVER_ADDR` [ИТС-мет 3596, 2009].

### 2.8. Переход на 8.5.4: менеджер лицензий `rmlic` вместо HASP License Manager

С 8.5.4 клиенты и серверы платформы не получают лицензии через HASP License Manager. На Windows [ИТС-мет 6041, 2026; конспект `../its-metod/licenzii-hasp-java-api-prochee-administrirovanie.md`, разд. 1]: на компьютере с **сетевым** ключом установить «1С:Предприятие 8 — Менеджер Лицензий» (`rmlic.exe`) службой и открыть TCP/UDP **475 и 1544**; HASP License Manager держать только на переходный период, затем остановить «HASP Loader» и отключить её автозапуск; на терминальном сервере с лицензиями `rmlic` тоже рекомендуется; на сервере 1С первым запускать агента кластера; часы машин — расхождение не больше 20 минут; настройки `nethasp.ini` действуют. Проверка — процесс `rmlic` и порты (`netstat -q -b` в `cmd` от администратора), при отказе запуска — `logcfg.xml` с `PROC` и `EXCP` в `conf` его каталога. Команды регистрации службы `rmlic` в доступных источниках нет ⚠ (документация 8.5.4 закрыта); остальное — `../1c/04-licenzirovanie.md`, разд. 4.9.

```powershell
Get-Process rmlic -ErrorAction SilentlyContinue | Select-Object Id, Path, StartTime
Get-NetTCPConnection -State Listen | Where-Object LocalPort -in 475,1544
Get-NetUDPEndpoint | Where-Object LocalPort -in 475,1544      # [практика]
```

## 3. Программные лицензии на Windows

### 3.1. Где лежат файлы `*.lic` и куда их кладёт активация

Порядок поиска на Windows [ИТС-адм разд. 10.3.8.2]:

| № | Каталог | Типичный путь |
|---|---|---|
| 1 | каталог конфигурационных файлов версии | `C:\Program Files\1cv8\8.3.27.1688\bin\conf` |
| 2 | `%LOCALAPPDATA%\1C\1cv8\conf` пользователя, от которого работает приложение | для службы: `C:\Users\USR1CV8\AppData\Local\1C\1cv8\conf` [практика] |
| 3 | каталог `ConfLocation` из `bin\conf\conf.cfg` | обычно `C:\Program Files\1cv8\conf` |
| 4 | `%ALLUSERSPROFILE%\1C\1cv8\conf` | `C:\ProgramData\1C\1cv8\conf` |
| 5 | `%ALLUSERSPROFILE%\1C\licenses` | `C:\ProgramData\1C\licenses` |
| 6 | `%ProgramData%\1C\licenses` | на современных Windows совпадает с п. 5 [практика] |
| запасной | `%APPDATA%\1C\1cv8\` или каталог из параметра `location` файла `location.cfg` в нём | — |

Куда кладёт файл автоматическая активация [ИТС-адм разд. 10.3.7.1]:

| Сценарий | Windows | Linux (для сравнения) |
|---|---|---|
| Лицензия для сервера 1С (в том числе «Установка на сервер» с другого компьютера) | `%ALLUSERSPROFILE%\1C\licenses` | `/var/1C/licenses` |
| Текущий компьютер, «только текущему пользователю» | `%LOCALAPPDATA%\1C\1cv8\conf` | `~/.1cv8/conf` |
| Текущий компьютер, «всем пользователям» | `%ALLUSERSPROFILE%\1C\licenses` | не поддерживается (только при запуске от `root`) |
| `ring license` по умолчанию | `%ProgramData%\1C\licenses` [ИТС-адм прил. 4.5.1] | `/var/1C/licenses` |

В примерах строк лицензии в документации встречается и третий вариант — файл в `C:/Users/USR1CV8/AppData/Local/1C/1cv8/conf/` профиля учётной записи службы [ИТС-КС прил. 1]: такое бывает у лицензий, активированных «для текущего пользователя» под этой учётной записью. Колонка «Лицензия» в консоли кластера (и `rac session list --licenses`) показывает полный путь к использованному файлу — по нему и находят, какой файл реально работает [ИТС-КС прил. 1; ИТС-КС разд. 5.2.11].

Правила, общие с Linux [ИТС-адм разд. 10.3.1.5, 10.3.7.1, 10.3.8.1]: один и тот же файл нельзя держать в двух каталогах поиска; в сети не должно быть двух файлов на один пинкод и номер комплекта — иначе файл попадает в чёрный список; при повторном получении текущий файл сначала переносят в каталог, где 1С лицензии не ищет. Подробно — `../1c/04-licenzirovanie.md`, разд. 3.5–3.8.

```powershell
# Все файлы лицензий во всех каталогах поиска (запускать от администратора)
$dirs = @(
  'C:\Program Files\1cv8\*\bin\conf', 'C:\Program Files\1cv8\conf',
  'C:\ProgramData\1C\1cv8\conf', 'C:\ProgramData\1C\licenses',
  'C:\Users\*\AppData\Local\1C\1cv8\conf', 'C:\Users\*\AppData\Roaming\1C\1cv8'
)
Get-ChildItem -Path $dirs -Filter *.lic -ErrorAction SilentlyContinue |
  Select-Object FullName, Length, LastWriteTime | Sort-Object LastWriteTime
# Дубликаты по содержимому (один файл в двух местах — риск чёрного списка)
Get-ChildItem -Path $dirs -Filter *.lic -ErrorAction SilentlyContinue | Get-FileHash |
  Group-Object Hash | Where-Object Count -gt 1 | ForEach-Object { $_.Group.Path }
```

### 3.2. Права на каталог лицензий

- При установке сервера службой установщик даёт учётной записи службы права чтения и записи на `%ALLUSERSPROFILE%\1C\licenses`. Если флажок установки службы не ставили, права остаются по умолчанию [ИТС-адм разд. 10.3.7.1].
- Если пользователь, от которого работает приложение, не может прочитать файл или каталог, лицензия просто не будет найдена [ИТС-адм разд. 10.3.1.1].
- Активация «для всех пользователей» требует записи в общий каталог; если прав нет, помощник предложит активировать только для текущего пользователя [ИТС-адм разд. 10.3.7.1].
- Сервису лицензирования кластера нужны права создания, чтения и изменения файла `1cv8conn.pfl` (`%ALLUSERSPROFILE%\1C\1cv8`) для процессов `rphost` и `rmngr` [ИТС-КС разд. 2.2.3.1; ИТС-адм прил. 3.8].

```powershell
icacls 'C:\ProgramData\1C\licenses'
icacls 'C:\ProgramData\1C\1cv8'
# Если служба сменила учётную запись — выдать права новой (пример для локальной USR1CV8):
icacls 'C:\ProgramData\1C\licenses' /grant 'USR1CV8:(OI)(CI)M'          # [практика]
```

Для `1cv8conn.pfl` документация советует на многопользовательских Windows дать полный доступ к каталогу всем пользователям 1С или группе USERS и убрать из списка доступа «СОЗДАТЕЛЬ-ВЛАДЕЛЕЦ» [ИТС-адм прил. 3.8].

### 3.3. Привязка к оборудованию на Windows: что сбрасывает лицензию

Ключевые параметры при привязке к компьютеру [ИТС-адм разд. 10.3.1.4]: наименование ОС; версия ОС (для Windows — только первые две цифры); **серийный номер ОС и дата установки ОС — только для Windows, кроме Windows 10**; сетевое имя; модель материнской платы; объём ОЗУ; тип и версия BIOS; процессоры; сетевые адаптеры с MAC-адресами (кроме Bluetooth, адаптеров IEEE 1394/USB, программных WAN/RAS и адаптеров без MAC и без `VEN_`/`DEV_`); жёсткие диски (кроме внешних по USB/IEEE 1394). Анализируется **удаление** устройств, а не добавление; ОЗУ можно увеличивать, но не уменьшать ниже объёма на момент активации; параметры опрашиваются не чаще раза в сутки [ИТС-адм разд. 10.3.1.4, 10.3.1.7]. В Linux наименование и версия ОС не проверяются [ИТС-адм разд. 10.3.1.4].

| Действие на Windows | Повторная активация | Обоснование |
|---|---|---|
| Переименование компьютера | да | сетевое имя |
| Переустановка Windows | да | серийный номер и дата установки ОС; ⚠ «кроме Windows 10» не уточняет Windows 11 и Server 2016–2025 (ядро тоже 10.0) — считать, что сбросит |
| Обновление «на месте» 2012 R2 → 2016+ | да | версия ОС 6.3 → 10.0 и наименование [вывод] |
| Обновление «на месте» 2016 → 2019 → 2022 | вероятно | наименование ОС ⚠ [вывод] |
| Обновление BIOS/UEFI | вероятно | «тип и версия BIOS» ⚠ — `ring license validate` до и после |
| Замена сетевой карты, смена MAC (динамический MAC Hyper-V) | да | удаление адаптера [ИТС-адм разд. 10.3.1.7] |
| Уменьшение ОЗУ ниже активированного | да | [ИТС-адм разд. 10.3.1.7]; динамическая память Hyper-V ⚠ |
| Уменьшение числа vCPU, замена или удаление диска | да | удаление устройств [вывод] |
| Миграция ВМ на хост с другими параметрами | да | [ИТС-адм разд. 10.3.1.6] |
| Добавление памяти, дисков, сетевых карт | нет | учитывается только удаление [ИТС-адм разд. 10.3.1.7] |

Как этого избежать в ВМ [ИТС-адм разд. 10.3.1.6]: сервис лицензирования кластера на физическом компьютере или на ВМ с фиксированными параметрами; привязка лицензии к ключу HASP, доступному ВМ до и после миграции. Для Hyper-V дополнительно: статический MAC, фиксированная (не динамическая) память, окончательное имя и число vCPU до активации [практика]; настройка ВМ — `06-windows-server-dlya-administratora-1c.md`, разд. 15.

Проверка до изменения оборудования:

```cmd
:: cmd от администратора; имя лицензии — «пинкод-номер» из «ring license list»
ring license list
ring license validate --name 123456789012-8000314159
echo %ERRORLEVEL%
:: 0 — совпадает; 1 — изменились параметры компьютера; 2 — ошибка подписи [ИТС-адм прил. 4.5.4.11]
```

В техжурнале несовпадение видно по событию `LIC` со свойством `res=binding` и текстом `Computer binding parameter changed`, а также по спискам `Removed after license acquisition` / `Available in current computer configuration` [ИТС-адм прил. 3.24.2.4]. Пример `logcfg.xml` с `LIC` и `HASP` — разд. 5.3.

### 3.4. Рабочее место = сеанс Windows: службы, планировщик, терминальный сервер

Особенность именно Windows [ИТС-адм разд. 10.3.4.9.1]: для программного лицензирования рабочее место определяется **идентификатором сеанса ОС**. Все запросы лицензии с одного компьютера и одного сеанса считаются одним рабочим местом. Если клиентское приложение запущено **из службы Windows**, это приравнивается к терминальному серверу и требует дополнительной лицензии — даже если на компьютере есть однопользовательская лицензия.

Практические следствия [практика]:

- пакетные запуски `1cv8.exe` / `1cv8c.exe` из «Планировщика заданий» с параметром «Выполнять вне зависимости от регистрации пользователя» или из своих служб (обмены, выгрузки) занимают отдельную лицензию;
- внешнее соединение (`V83.COMConnector`) из кода на сервере 1С, работающем как внутрипроцессный COM-сервер, использует **серверную** программную лицензию, иначе ищет клиентскую в порядке: однопользовательские → многопользовательские → лицензии сервера 1С [ИТС-адм разд. 10.3.4.7];
- у внешнего соединения от `LocalSystem` нет профиля, поэтому `UseHwLicenses` из `1cestart.cfg` не читается и поиск ключа выполняется всегда [ИТС-адм прил. 3.6.15].

Терминальный сервер [ИТС-адм разд. 10.3.4.9.2–10.3.4.9.3]: однопользовательская лицензия обслуживает одну терминальную сессию; многопользовательская на терминальном сервере работает и для файлового, и для клиент-серверного варианта — столько сессий, на сколько активирована; лицензии на терминальном сервере складываются, если файлы доступны всем его пользователям (то есть лежат в `%ALLUSERSPROFILE%\1C\licenses`). Остальное про терминальный сервер — `04-domen-kerberos-klienty-terminalnyj-server.md`.

### 3.5. Активация и проверка на Windows: конфигуратор и `ring license`

Способы [ИТС-адм разд. 10.3.7.1]:

1. Конфигуратор: «Сервис → Получение лицензии…». Для привязки к **серверу** с другого компьютера — «Дополнительно» → «Установка на сервер», поля «Сервер» и «Порт»; файл появится у учётной записи службы на компьютере сервера (в документации — «по умолчанию usr1cv83» ⚠, у установщика 8.3 — `USR1CV8` [ИТС-КС разд. 1.3.2]).
2. Клиент: «Сервис и настройки → Функции для технического специалиста → Стандартные → Получение лицензии».
3. Утилита `ring license` (лицензии 1С:Аналитики и для разработчиков не умеет).

Серверную и многопользовательскую лицензии, если можно, активировать конфигуратором на самом сервере 1С [ИТС-адм разд. 10.3.7.1].

`ring license` на Windows [ИТС-адм прил. 4.4, 4.5]: дистрибутив https://releases.1c.ru/project/EnterpriseLicenseTools, установщик `1ce-installer` или `1ce-installer-cli` (права администратора); нужны Java 8+, JCE или настройка Java и **Windows Script Host**; аргументы — только 8-битные символы; при «кракозябрах» — шрифт Consolas и `chcp 1251`, язык вывода — `RING_OPTS`.

```cmd
:: cmd от имени администратора
set RING_OPTS=-Duser.country=ru -Duser.language=RU
chcp 1251
ring license list
ring license info --name 123456789012-8000314159
ring license validate --name 123456789012-8000314159
:: хранилище не по умолчанию
ring license list --path "D:\lic-backup"
```

В PowerShell код возврата — `$LASTEXITCODE`. Куда установщик кладёт `ring` и попадает ли он в `PATH`, документация не говорит ⚠ — проверить `Get-Command ring`. Активация без интернета (`prepare-request` → `acquire` → `generate`) и синтаксис `activate` — `../1c/04-licenzirovanie.md`, разд. 4.6–4.7; у `get` и `remove` в документации `-name` с одним дефисом ⚠ — использовать `--name`.

### 3.6. Клиентские лицензии через сервер и смешанная среда

Порядок поиска клиентской лицензии одинаков для Windows и Linux [ИТС-адм разд. 10.4.1]: на компьютере клиента (последний успешный источник → программные лицензии → локальный ключ → сетевой ключ через менеджер в порядке `ORGL8`, `ORG8A`, `ORG8B`) → на менеджере кластера с сервисом сеансовых данных → на менеджере кластера с сервисом лицензирования. Если поиск ключа отключён параметром `UseHwLicenses=0` в `1cestart.cfg`, клиент не ищет ни локальные, ни сетевые ключи и не обращается к запомненному ключу [ИТС-адм разд. 10.4.1].

На Windows-клиентах [ИТС-адм прил. 3.6.15, разд. 2.5.2.1]:

- `UseHwLicenses=0` в `%APPDATA%\1C\1CEStart\1cestart.cfg` пользователя или в `%ALLUSERSPROFILE%\1C\1CEStart\1cestart.cfg` (для всех; файл в кодировке UTF-16LE) [ИТС-адм прил. 3.6.1];
- при массовой установке — `setup.exe USEHWLICENSES=0` или тот же параметр в `CmdLine` группы `Startup` файла `setup.ini`;
- платформа сама предлагает отключить поиск, если ключ не найден, запуск удался и поиск занял больше 3 секунд, и наоборот — включить, если лицензию не дал сервер;
- приоритет: локальный файл пользователя → локальный файл для всех → общий файл.

Важно для пользователя этой базы (сервер 1С на Ubuntu, клиенты Windows) — разд. 10.

### 3.7. Резервная копия и перенос лицензий

- Резервную копию файлов `*.lic` держать **вне** каталогов поиска (иначе — дубликат и риск чёрного списка) [ИТС-адм разд. 10.3.8.1; практика].
- Файл привязан к параметрам компьютера: на другом сервере он не заработает; при переносе сервера нужна активация резервным пинкодом («Восстановление» с выключенным флажком «Я уверен(-а), что ключевые параметры компьютера не изменялись») [ИТС-адм разд. 10.3.7.1].
- Перед повторной активацией тем же или новым пинкодом комплекта в сети не должно остаться приложений, использующих старый файл [ИТС-адм разд. 10.3.7.1].
- `ring license update` переполучает все лицензии хранилища и оставляет старые файлы с расширением `.oldlic` [ИТС-адм прил. 4.5.4.10].

```powershell
$dst = 'D:\Backup\1C-lic\' + (Get-Date -Format yyyyMMdd)
New-Item -ItemType Directory -Force $dst | Out-Null
Copy-Item 'C:\ProgramData\1C\licenses\*.lic' $dst
Get-ChildItem $dst      # D:\Backup — НЕ каталог поиска лицензий
```

### 4.2. Поиск конфигурационных файлов и `conf.cfg`

Порядок поиска `logcfg.xml`, `nethasp.ini` и других конфигурационных файлов на Windows [ИТС-адм прил. 1.3.4]:

1. `bin\conf` конкретной версии (`C:\Program Files\1cv8\8.3.27.1688\bin\conf`);
2. `%LOCALAPPDATA%\1C\1cv8\conf` пользователя, от которого работает процесс;
3. каталог из параметра `ConfLocation` файла `bin\conf\conf.cfg`;
4. `%ALLUSERSPROFILE%\1C\1cv8\conf`.

Установщик записывает конфигурационные файлы в `conf` корневого каталога и прописывает этот путь в `bin\conf\conf.cfg` версии [ИТС-адм прил. 1.3.4]. Поэтому «один файл на все версии» на Windows — это `C:\Program Files\1cv8\conf\`. Значение `ConfLocation` по умолчанию — тот же `%PROGRAMFILES%\1cv8\conf` (или `%PROGRAMFILES(x86)%…`, или `%LOCALAPPDATA%\Programs\…\conf` для установки «для пользователя») [ИТС-адм прил. 3.17.2].

`conf.cfg` на Windows бывает в `bin\conf` версии, в `%LOCALAPPDATA%\1C\1cv8\conf` (действует для любой версии и разрядности) и в `conf` корневого каталога; кодировка UTF-8 [ИТС-адм прил. 3.17.1].

Практические следствия [практика]:

- настройки только для клиентов одного пользователя (например, клиентский техжурнал) можно положить в `%LOCALAPPDATA%\1C\1cv8\conf` **без прав администратора** — удобно для диагностики на рабочем месте;
- профиль службы `USR1CV8` тоже участвует в поиске (п. 2): забытый там `logcfg.xml` или `conf.cfg` перекрывает общие настройки — проверять при «необъяснимом» поведении сервера.

```powershell
# Все экземпляры ключевых конфигурационных файлов на компьютере
$names = 'logcfg.xml','conf.cfg','nethasp.ini','swpuser.ini','location.cfg'
Get-ChildItem -Path 'C:\Program Files\1cv8','C:\Program Files (x86)\1cv8','C:\ProgramData\1C',
                    'C:\Users\*\AppData\Local\1C','C:\Users\*\AppData\Roaming\1C' `
  -Recurse -Include $names -ErrorAction SilentlyContinue |
  Select-Object FullName, LastWriteTime
Get-Content 'C:\Program Files\1cv8\8.3.27.1688\bin\conf\conf.cfg'   # ожидается ConfLocation=C:\Program Files\1cv8\conf
```

### 4.3. Каталог данных кластера (`srvinfo`)

Где он [ИТС-КС разд. 2.2.13]:

- сервер установлен **службой**: `<корневой каталог установки>\srvinfo` (обычно `C:\Program Files\1cv8\srvinfo`), путь явно записан в параметрах службы ключом `/d`;
- сервер запущен **приложением** без `/d`: `%LOCALAPPDATA%\1C\1cv8` пользователя;
- при смене способа запуска или учётной записи службы `/d` нужно указать явно: не найдя реестр, агент создаст **новый пустой кластер** [ИТС-КС разд. 2.2.13].

Содержимое (`<sdf>` — каталог данных, `<port>` — порт главного менеджера, обычно 1541) [ИТС-адм прил. 3.7, 3.9, 3.27, 3.29; ИТС-КС разд. 2.2.3.2]:

| Путь | Что |
|---|---|
| `<sdf>\1cv8wsrv.lst` | список кластеров на этом сервере |
| `<sdf>\swpuser.ini` | переопределение учётных записей `rphost`/`rmngr` (рядом со списком кластеров) |
| `<sdf>\reg_<port>\1CV8Clst.lst` | реестр кластера: базы, серверы, процессы, менеджеры, сервисы, администраторы |
| `<sdf>\reg_<port>\rescntsrv.lst` | значения счётчиков потребления ресурсов (обновляются каждые 20 с) |
| `<sdf>\reg_<port>\<uuid-ИБ>\1Cv8Log` | журнал регистрации базы |
| `<sdf>\reg_<port>\<uuid-ИБ>\1Cv8FTxt`, `1Cv8FTxt2` | индексы полнотекстового поиска |
| `<sdf>\reg_<port>\snccntx<…>` | сеансовые данные |
| `<sdf>\reg_<port>\BinDataStrg\<uuid-ИБ>` | хранилище двоичных данных |

```powershell
# Где на самом деле данные кластера: смотрим /d в строке запуска службы
Get-CimInstance Win32_Service -Filter "Name LIKE '1C:Enterprise%'" |
  Select-Object Name, State, StartName, PathName | Format-List
sc.exe qc "1C:Enterprise 8.3 Server Agent (x86-64)"     # BINARY_PATH_NAME и SERVICE_START_NAME
```

Права: учётная запись агента — полные права на каталог данных, остальным доступ запрещён; временные файлы кластера защищаются правами на каждый файл [ИТС-КС разд. 2.2.9.4.2–2.2.9.4.3]. Эксплуатационные правила 1С [ИТС-мет 5908, 2022]: не включать каталог кластера в файловое резервное копирование (там сеансовые данные), не включать сжатие NTFS на этом диске, держать сеансовые данные на быстрых дисках; не размещать технологический журнал на диске с `snccntx` — исчерпание места ударит по стабильности [ИТС-мет 6005, 2022, по конспекту `../its-metod/sbor-dannyh-dlya-rassledovaniya-problem.md`, п. 16]. Кэш клиентов (каталоги-UUID в `%APPDATA%\1C\1cv8` и `%LOCALAPPDATA%\1C\1cv8` на рабочих местах) и каталог данных кластера — разные вещи; «чистку кэша» к каталогу кластера не применять (`../1c/03-administrirovanie-klastera-ras-rac.md`).

### 4.5. Учётная запись службы и права

Требования к учётной записи процессов кластера на Windows (по умолчанию `USR1CV8`) [ИТС-КС разд. 1.3.2]: полные права на каталог данных кластера (`icacls "C:\Program Files\1cv8\srvinfo"`); «Список содержимого папки» на каталог временных файлов (какой именно каталог временных файлов у службы — ⚠); права «Вход в качестве службы» (`SeServiceLogonRight`) и «Вход в качестве пакетного задания» (`SeBatchLogonRight`) — `secpol.msc` → Локальные политики → Назначение прав пользователя, проверка `secedit /export /cfg C:\Temp\sec.inf` [практика]; членство в группе «Пользователи журналов производительности» (Performance Log Users).

```powershell
# Performance Log Users по SID S-1-5-32-559 — не зависит от языка ОС
Add-LocalGroupMember -SID 'S-1-5-32-559' -Member 'USR1CV8'            # или 'ДОМЕН\svc-1c'
Get-LocalGroupMember -SID 'S-1-5-32-559'
```

SID `S-1-5-32-559` — общеизвестный [практика ⚠, страница MS Learn о встроенных группах не читалась]; зачем 1С нужна эта группа, документация не объясняет ⚠.

`swpuser.ini` на Windows [ИТС-адм прил. 3.29; ИТС-мет 5899, 2016]: агент — член группы администраторов с правами «Настройка квот памяти для процесса» (Adjust memory quotas for a process) и «Замена маркера уровня процесса» (Replace a process level token) — членство в группе их не гарантирует; учётным записям `rphost` и `rmngr` — полный доступ к `%ALLUSERSPROFILE%\1C\1cv8` и созданные профили; доменное имя записывается как `\\имя-домена\имя-пользователя` (два обратных слеша в начале); сменить учётную запись агента без `swpuser.ini` — значит запустить все процессы кластера от администратора (недопустимо). Общий принцип: `rphost` — без доступа к каталогу данных кластера; пользователям ОС — без доступа к файлам кластера, компьютеру СУБД и произвольным COM-объектам [ИТС-КС прил. 3.4–3.5].

## 5. Технологический журнал на Windows

Справочник событий и свойств, разбор `logcfg.xml`, готовые настройки и анализ — в `../1c/07-tehzhurnal-diagnostika-zhurnal-registracii.md`; формат файла одинаков на Windows и Linux. Здесь — только особенности Windows.

### 5.1. Где лежит `logcfg.xml` и как он подхватывается

- Файл ищется в каталогах конфигурационных файлов (разд. 4.2); для сервера — `C:\Program Files\1cv8\conf\logcfg.xml` [ИТС-адм разд. 6.14.1; прил. 1.3.4].
- Платформа проверяет наличие и содержимое `logcfg.xml` каждые **60 секунд** — изменения применяются без перезапуска [ИТС-адм разд. 6.14.1].
- Права на Windows [ИТС-адм разд. 6.14.1; прил. 3.24.2.5.4]: пользователю процесса — **полные** права на каталог техжурнала, каталог дампов и каталог временных файлов; **чтение** каталогов конфигурационных файлов и каталога-владельца каталога дампов (и каталога-владельца каталога журнала).
- Значения `location` у всех `<log>`, у `<dump>` и `<defaultlog>` должны быть разными; элементов `<log>` — не больше 20 [ИТС-адм прил. 3.24.2.2].
- Без файла: техжурнал выключен, техжурнал по умолчанию включён (`%LOCALAPPDATA%\1C\1cv8\logs`, `SYSTEM` уровня `ERROR`, 24 часа; файлы появляются только при событиях), дампы — минимальные в `%LOCALAPPDATA%\1C\1cv8\dumps` [ИТС-адм прил. 3.24.1, 3.24.2.11].

Для службы под `USR1CV8` эти каталоги по умолчанию — `C:\Users\USR1CV8\AppData\Local\1C\1cv8\logs` и `…\dumps` [вывод из ИТС-адм прил. 3.24.1 и разд. 4.4].

### 5.2. Включение журнала пошагово (PowerShell)

```powershell
# 1. Каталоги на отдельном диске, права учётной записи службы
$acct = 'USR1CV8'                      # или 'ДОМЕН\svc-1c' — см. StartName службы (разд. 4.3)
$dirs = 'D:\1C\TJ\all', 'D:\1C\TJ\call', 'D:\1C\TJ\lic', 'D:\1C\dumps'
New-Item -ItemType Directory -Force $dirs | Out-Null
icacls 'D:\1C\TJ'    /grant "${acct}:(OI)(CI)F"
icacls 'D:\1C\dumps' /grant "${acct}:(OI)(CI)F"
icacls 'D:\1C'       /grant "${acct}:(RX)"             # чтение каталога-владельца [ИТС-адм прил. 3.24.2.5.4]

# 2. Готовим файл в стороне и проверяем, что XML корректен
$tmp = 'C:\Temp\logcfg.xml'                             # текст — из разд. 5.3
[xml](Get-Content -Raw -Encoding UTF8 $tmp) | Out-Null  # исключение = ошибка в XML

# 3. Кладём на место (одним действием)
Copy-Item $tmp 'C:\Program Files\1cv8\conf\logcfg.xml' -Force

# 4. Через 1–2 минуты должны появиться каталоги процессов вида rphost_<PID>
Start-Sleep -Seconds 90
Get-ChildItem 'D:\1C\TJ\all' | Select-Object Name, LastWriteTime
```

Платформа не сообщает об ошибке в `logcfg.xml`; при ошибке может перестать писаться весь техжурнал — поэтому проверка XML и контроль появления файлов обязательны [ИТС-мет 5809 — по `../1c/07-tehzhurnal-diagnostika-zhurnal-registracii.md`, разд. 2.2]. Выключение — переименовать файл, через минуту запись прекратится.

Если путь к `logcfg.xml` нужно хранить не в `Program Files`, можно изменить `ConfLocation` в `bin\conf\conf.cfg` каждой версии — но при обновлении платформы новая версия получит `conf.cfg` от установщика ⚠ [вывод]; надёжнее общий каталог `C:\Program Files\1cv8\conf`.

### 5.3. Базовый `logcfg.xml` для рабочего сервера Windows

Основа — чек-лист 1С для продукционных серверов: постоянный журнал ошибок и событий кластера, отдельный журнал серверных вызовов, дампы [ИТС-мет 5899, 2016]; добавлен журнал лицензирования [события `LIC`, `HASP` — ИТС-адм прил. 3.24.2.3; набор событий для расследования проблем с лицензиями — ИТС-мет 6005, 2022, по конспекту `../its-metod/sbor-dannyh-dlya-rassledovaniya-problem.md`, п. 21].

```xml
<?xml version="1.0" encoding="UTF-8"?>
<config xmlns="http://v8.1c.ru/v8/tech-log">
  <!-- Дампы: только Windows; type 3 = сегмент данных + вся память процесса; внешний dumper.exe -->
  <dump create="true" location="D:\1C\dumps" type="3" prntscrn="false" externaldump="1"/>

  <!-- Постоянный журнал: ошибки, процессы, администрирование, соединения, сеансы, кластер, сервисы, мониторинг -->
  <log location="D:\1C\TJ\all" history="168" compress="zip">
    <event><eq property="Name" value="EXCP"/></event>
    <event><eq property="Name" value="PROC"/></event>
    <event><eq property="Name" value="ADMIN"/></event>
    <event><eq property="Name" value="CONN"/></event>
    <event><eq property="Name" value="SESN"/></event>
    <event><eq property="Name" value="CLSTR"/></event>
    <event><eq property="Name" value="SRVC"/></event>
    <event><eq property="Name" value="ATTN"/></event>
    <property name="all"/>
  </log>

  <!-- Серверные вызовы (для топ-вызовов, разд. 5.5); объём большой — история 12 ч -->
  <log location="D:\1C\TJ\call" history="12">
    <event><eq property="Name" value="CALL"/></event>
    <event><eq property="Name" value="SCALL"/></event>
    <property name="all"/>
  </log>

  <!-- Лицензирование: получение/освобождение лицензий, привязка, обращения к ключу -->
  <log location="D:\1C\TJ\lic" history="72">
    <event><eq property="Name" value="LIC"/></event>
    <event><eq property="Name" value="HASP"/></event>
    <property name="all"/>
  </log>
</config>
```

Комментарии:

- В чек-листе 5899 история — 28 часов, контекст у `CALL`/`SCALL` отключён фильтром `<property name="Context">`; здесь контекст оставлен — он нужен для группировки в разд. 5.5 [ИТС-мет 5899, 2016; ИТС-мет 5906, 2016].
- `compress="zip"` сжимает файлы при ротации; `history` — в часах; `0` отключает удаление старых файлов (тогда очищать самим) [ИТС-адм прил. 3.24.2.2].
- `ATTN` — записи мониторинга кластера, в том числе превышение критического объёма памяти [ИТС-КС разд. 2.2.12].
- В примере `externaldump="1"`: при 32-разрядной платформе в 64-разрядной ОС для видеомодуля он игнорируется [ИТС-адм прил. 3.24.2.5.4].
- 1С рекомендует архивировать техжурнал и копировать архивы на сетевой ресурс [ИТС-мет 5899, 2016].

### 5.5. Анализ на Windows: топ-25 вызовов `CALL` (статья 5906)

Методика 1С [ИТС-мет 5906, 2016]: собрать события `CALL` с контекстом, сложить длительности по последней строке контекста встроенного языка и взять 25 самых «дорогих». В оригинале обработка — `cat | perl call.pl | awk` под cygwin; длительность в 8.3 — в микросекундах (делитель 1 000 000; для 8.2 — 10 000). Группируются только вызовы, у которых в журнале есть контекст.

Варианты на Windows:

1. Скопировать журнал на машину с bash (Git Bash, WSL) и выполнить готовые команды из `../1c/07-tehzhurnal-diagnostika-zhurnal-registracii.md`, разд. 8.3 и 8.5 — они учитывают окончания строк `\r\n` [практика].
2. Аналог на PowerShell (тот же алгоритм, что у `call.pl`: событие начинается строкой `мм:сс.микросекунды-длительность,`, берётся последняя непустая строка `Context`) [практика; не проверялся на реальном журнале ⚠]:

```powershell
# Топ-25 контекстов CALL по суммарной длительности. Запускать на КОПИИ журнала.
$root = 'D:\1C\TJ\call'
$stat = @{}
Get-ChildItem -Path $root -Recurse -Filter *.log | ForEach-Object {
    $text = [IO.File]::ReadAllText($_.FullName)          # BOM учитывается, иначе UTF-8
    foreach ($ev in [regex]::Split($text, '(?m)^(?=\d\d:\d\d\.\d+-\d+,)')) {
        if ($ev -notmatch '^\d\d:\d\d\.\d+-(\d+),CALL,') { continue }
        $dur = [double]$Matches[1]
        if ($ev -notmatch ',Context=(''[^'']*''|"[^"]*"|[^,\r\n]*)') { continue }
        $ctx = $Matches[1] -replace '^[''"]|[''"]$', ''
        $ctx = ($ctx -split '\r?\n' | Where-Object { $_.Trim() } | Select-Object -Last 1)
        if (-not $ctx) { continue }
        $ctx = $ctx.Trim()
        if (-not $stat.ContainsKey($ctx)) { $stat[$ctx] = @(0.0, 0) }
        $stat[$ctx][0] += $dur
        $stat[$ctx][1] += 1
    }
}
$stat.GetEnumerator() | ForEach-Object {
    [pscustomobject]@{
        SumSec  = [math]::Round($_.Value[0] / 1e6, 3)
        AvgSec  = [math]::Round($_.Value[0] / $_.Value[1] / 1e6, 3)
        Count   = $_.Value[1]
        Context = $_.Key
    }
} | Sort-Object SumSec -Descending | Select-Object -First 25 | Format-Table -AutoSize -Wrap
```

Файлы в сотни мегабайт `ReadAllText` читает целиком в память — для больших журналов анализировать по одному часу или на отдельной машине [практика]. Самые тяжёлые запросы на стороне СУБД (MS SQL) — `02-ms-sql-server-dlya-1c.md`; для PostgreSQL — `../1c/07-tehzhurnal-diagnostika-zhurnal-registracii.md`, разд. 7.3.

## 6. Дампы аварийного завершения на Windows

На Linux элемент `<dump>` игнорируется, дампы настраиваются средствами ОС (`../1c/07-tehzhurnal-diagnostika-zhurnal-registracii.md`, разд. 9). На Windows — наоборот: дампы платформы настраиваются только `logcfg.xml`, а WER — дополнительный независимый механизм [ИТС-адм прил. 3.24.2.5.1, разд. 6.14.1; MS Learn].

### 6.1. Элемент `<dump>`: атрибуты и типы

| Атрибут | Значения | Источник |
|---|---|---|
| `create` | `1`/`true` — писать, `0`/`false` — не писать | [ИТС-адм прил. 3.24.2.5.4] |
| `location` | каталог дампов (не совпадает с каталогами `<log>`/`<defaultlog>`) | там же |
| `type` | сумма флагов (десятично или `x0002`): `0` минимальный, `1` сегмент данных, `2` вся память процесса, `4` хэндлы, `8` только для восстановления стеков, `16`, `32` выгруженные модули, `64` память по ссылкам, `128` сведения о файлах модулей, `256` локальные данные потоков, `512` всё виртуальное адресное пространство. **Рекомендуется `3`** | там же |
| `externaldump` | `1` — дамп формирует `dumper.exe` из поставки (исключает зависание при записи дампа; рекомендуется для серверов без ежесуточного присмотра); `0` — сам падающий процесс (умолчание) | там же; [ИТС-адм прил. 1.2.15] |
| `prntscrn` | `1` — снимок экрана `.png` рядом с дампом при падении клиента | там же |

Без элемента `<dump>` дампы пишутся (минимальные) в `%LOCALAPPDATA%\1C\1cv8\dumps` пользователя процесса; чтобы запретить запись — `create="0"` [ИТС-адм прил. 3.24.2.5.4, разд. 6.14.2]. Если `logcfg.xml` нужен только ради дампов, он не должен содержать ни одного `<log>` [ИТС-адм разд. 6.14.6.1]:

```xml
<config xmlns="http://v8.1c.ru/v8/tech-log">
  <dump location="D:\1C\dumps" create="1" type="3"/>
</config>
```

Объём: дамп с флагом `2` содержит всю память процесса — для `rphost` это гигабайты; на диске дампов держать запас не меньше суммарной памяти рабочих процессов [практика].

### 6.2. Рекомендуемая настройка для сервера

1. `<dump create="true" location="D:\1C\dumps" type="3" prntscrn="false" externaldump="1"/>` в общем `logcfg.xml` [ИТС-мет 5899, 2016].
2. Права учётной записи службы на `D:\1C\dumps` — полные, на `D:\1C` — чтение (разд. 5.2).
3. Свойство кластера «Записывать дамп процесса при превышении критического объёма памяти» — при расследовании утечек памяти включить: тогда процесс, который кластер завершает по превышению «Критического объёма памяти процессов», оставит дамп по настройкам `logcfg.xml` [ИТС-КС разд. 5.2.5.1 (свойства кластера), 2.2.12]; в `rac` — `cluster update … --kill-by-memory-with-dump=yes` (по `../1c/03-administrirovanie-klastera-ras-rac.md`, разд. о свойствах кластера; сверить с `rac help cluster`).
4. Контроль места: старые дампы платформа не удаляет ⚠ — чистить по расписанию [практика]:

```powershell
# Дампы старше 14 дней — удалить (сначала посмотреть список без -WhatIf!)
Get-ChildItem 'D:\1C\dumps' -Recurse -File | Where-Object LastWriteTime -lt (Get-Date).AddDays(-14) |
  Remove-Item -WhatIf
```

### 6.3. Windows Error Reporting: `LocalDumps`

Механизм ОС: после падения пользовательского процесса WER сохраняет дамп локально; настраивается в `HKLM\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps`, по умолчанию выключен, нужны права администратора [MS Learn, «Collecting User-Mode Dumps»]:

| Значение | Тип | Умолчание | Смысл |
|---|---|---|---|
| `DumpFolder` | `REG_EXPAND_SZ` | `%LOCALAPPDATA%\CrashDumps` | каталог; для служб — профиль учётной записи службы (у системных — `%WINDIR%\System32\Config\SystemProfile`) |
| `DumpCount` | `REG_DWORD` | 10 | сколько файлов хранить; старейший заменяется |
| `DumpType` | `REG_DWORD` | 1 | `0` — custom (`CustomDumpFlags`), `1` — мини, `2` — полный |
| `CustomDumpFlags` | `REG_DWORD` | `0x121` | флаги `MINIDUMP_TYPE` при `DumpType=0` |

Настройки можно задать для отдельной программы — подключ `LocalDumps\<имя.exe>` переопределяет глобальные. WER `LocalDumps` работает, даже если отправка отчётов отключена. Дамп не собирается, если включена автоматическая отладка падений [MS Learn].

Рекомендация 1С: собирать WER для `rmngr` и `ragent`, `rphost` не указывать [ИТС-мет 5908, 2022]. В чек-листе 2016 года — WER на `ragent`, `rmngr`, `rphost` [ИТС-мет 5899, 2016]; актуальнее статья 2022 года. Для `rphost` дампы даёт `<dump>` платформы.

```powershell
# От имени администратора. Полные дампы ragent и rmngr в D:\1C\wer, хранить по 5.
New-Item -ItemType Directory -Force 'D:\1C\wer' | Out-Null
icacls 'D:\1C\wer' /grant 'USR1CV8:(OI)(CI)F'
foreach ($exe in 'ragent.exe', 'rmngr.exe') {
    $k = "HKLM:\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps\$exe"
    New-Item -Path $k -Force | Out-Null
    New-ItemProperty -Path $k -Name DumpFolder -PropertyType ExpandString -Value 'D:\1C\wer' -Force | Out-Null
    New-ItemProperty -Path $k -Name DumpType   -PropertyType DWord        -Value 2           -Force | Out-Null
    New-ItemProperty -Path $k -Name DumpCount  -PropertyType DWord        -Value 5           -Force | Out-Null
}
reg.exe query "HKLM\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps" /s   # проверка
```

Ограничение: приложения с собственной обработкой аварий WER `LocalDumps` не поддерживает [MS Learn]; платформа сама пишет дампы через `<dump>`, поэтому WER — страховка на случай, когда её механизм не успел; срабатывание проверять по факту появления файлов ⚠ [практика].

Методичка 2924 (2008) настраивает WER групповой политикой «Corporate upload file path» для Windows XP/2003 [ИТС-мет 2924, 2008] — **устарела**: с Vista SP1/Server 2008 локальные дампы задаются `LocalDumps` [MS Learn].

### 6.4. Дамп зависшего процесса: ProcDump и диспетчер задач

Если процесс не упал, а завис или «съел» память — снять дамп работающего процесса:

```cmd
:: cmd от администратора, из каталога с procdump.exe (Sysinternals)
procdump.exe -accepteula -ma <PID> D:\1C\dumps\rphost_<PID>.dmp
```

Ключ `-ma` — полный дамп; пакетный файл 1С снимает так все `rmngr`, `rphost`, `ragent` (и при необходимости `w3wp`, `httpd`, `1cv8c`, `1cv8`) — серия дампов в момент зависания нужна поддержке при деградации у всех пользователей [ИТС-мет 5899, 2016; ИТС-мет 6005, 2022 — шаблон П в `../its-metod/sbor-dannyh-dlya-rassledovaniya-problem.md`]. Ключ `-accepteula` и путь к файлу — [практика].

```powershell
# PID процессов 1С и их учётные записи (для выбора, чей дамп снимать)
Get-CimInstance Win32_Process -Filter "Name='rphost.exe' OR Name='rmngr.exe' OR Name='ragent.exe'" |
  ForEach-Object {
    $o = Invoke-CimMethod -InputObject $_ -MethodName GetOwner
    [pscustomobject]@{ PID = $_.ProcessId; Name = $_.Name; User = "$($o.Domain)\$($o.User)";
                       PrivateMB = [math]::Round($_.PrivatePageCount / 1MB); Cmd = $_.CommandLine }
  } | Format-Table -AutoSize
```

Альтернатива без утилит — «Диспетчер задач → Подробности → правый щелчок → Создать файл дампа»; в Windows 11 появился и «живой» дамп памяти (Create live memory dump file) [MS Learn, упоминание в «Collecting User-Mode Dumps»]. Дамп процесса службы, работающей под другой учётной записью, требует запуска диспетчера от администратора [практика].

### 6.5. Что передавать в поддержку

Для анализа своими силами — WinDbg (`!analyze -v`) [практика].

## 7. Журнал событий Windows

Общие приёмы работы с журналами Windows Server (размеры, экспорт, пересылка) — `06-windows-server-dlya-administratora-1c.md`, разд. 11. Здесь — что относится к 1С.

### 7.1. Что туда попадает от 1С

| Журнал | Событие | Смысл | Источник |
|---|---|---|---|
| System | Service Control Manager **7034** | служба (агент 1С, «HASP Loader», `hasplms`) неожиданно завершилась | [MS Learn] |
| System | SCM 7031; 7000 / 7009 / 7038 | завершилась с действием восстановления; не запустилась / таймаут / ошибка входа (сменили пароль `USR1CV8`) | [практика ⚠] |
| Application | **Application Error** (обычно 1000) | авария `ragent.exe`, `rmngr.exe`, `rphost.exe`, `1cv8c.exe`: модуль и код исключения | [MS Learn — источник; код — практика ⚠] |
| Application | Windows Error Reporting (обычно 1001) | отчёт WER о том же падении, путь к дампу | [практика ⚠] |
| журнал Windows (какой — в статье не сказано) | ошибка регистрации имени `AladinHaspV01.2:30` | два HASP License Manager с одинаковым именем NetBIOS | [ИТС-мет 2382, 2008] |
| `Microsoft-Windows-CAPI2/Operational` | CAPI2 (по умолчанию выключен) | ошибки цепочки и проверки отзыва сертификатов | [ИТС-мет 5949, 2018] |

Платформа пишет диагностику в технологический журнал (в том числе журнал по умолчанию, разд. 5.1), а не в журнал событий; собственного источника 1С в журнале Application документация не называет ⚠. Журнал событий отвечает на вопрос «упала ли служба и с каким кодом», «почему» — техжурнал и дамп.

### 7.2. Запросы: PowerShell и `wevtutil`

```powershell
$since = (Get-Date).AddDays(-7)
# Падения служб за неделю (7031/7034), только про 1С и HASP
Get-WinEvent -FilterHashtable @{ LogName='System'; ProviderName='Service Control Manager'; Id=7031,7034; StartTime=$since } -ErrorAction SilentlyContinue |
  Where-Object Message -match '1C|HASP|Sentinel' | Format-List TimeCreated, Id, Message

# Аварийные завершения процессов 1С (пример MS Learn: ProviderName='Application Error' + Data='<имя.exe>')
'rphost.exe','rmngr.exe','ragent.exe','1cv8c.exe' | ForEach-Object {
  Get-WinEvent -FilterHashtable @{ LogName='Application'; ProviderName='Application Error'; Data=$_; StartTime=$since } -ErrorAction SilentlyContinue
} | Sort-Object TimeCreated | Format-List TimeCreated, Id, Message

# Ошибки и критические события Application за сутки
Get-WinEvent -FilterHashtable @{ LogName='Application'; Level=1,2; StartTime=(Get-Date).AddDays(-1) } |
  Format-Table TimeCreated, Id, ProviderName -AutoSize
```

Ключи `FilterHashtable` (`LogName`, `ProviderName`, `ID`, `Level`, `StartTime`, `EndTime`, `Data` …) — [MS Learn, Get-WinEvent]. Текст `Message` локализован: на русской Windows ищите по именам процессов и служб, а не по английским фразам [практика].

```cmd
:: cmd: последние 20 событий SCM 7031/7034, новые сверху (синтаксис wevtutil — MS Learn)
wevtutil qe System /q:"*[System[Provider[@Name='Service Control Manager'] and (EventID=7031 or EventID=7034)]]" /c:20 /rd:true /f:text
:: Экспорт журнала для поддержки
wevtutil epl Application D:\1C\support\application.evtx
wevtutil epl System D:\1C\support\system.evtx
```

Настройка восстановления службы после падения (перезапуск) — `01-ustanovka-servera-i-sluzhba-windows.md`; посмотреть текущие действия: `sc.exe qfailure "1C:Enterprise 8.3 Server Agent (x86-64)"` [практика].

### 7.3. Ошибки проверки сертификатов: журнал CAPI2 (статья 5949)

С 8.3.12 платформа проверяет сертификат сервера при TLS-соединении средствами Windows. Сообщение «Удалённый узел не прошёл проверку. Не удалось выполнить проверку отзыва сертификата» чаще всего значит, что учётная запись процесса не может скачать список отзыва (CRL): нет доступа в интернет, прокси, сетевой экран или доступ только у доменных пользователей, а служба 1С работает от локальной учётной записи [ИТС-мет 5949, 2018].

Диагностика [ИТС-мет 5949, 2018; синтаксис — MS Learn, wevtutil]:

```powershell
# 1. Включить журнал CAPI2 (по умолчанию выключен), воспроизвести ошибку
wevtutil sl Microsoft-Windows-CAPI2/Operational /e:true
wevtutil gl Microsoft-Windows-CAPI2/Operational          # enabled: true
# 2. Посмотреть ошибки: URL CRL, таймаут, UserID (под кем шла проверка)
Get-WinEvent -LogName 'Microsoft-Windows-CAPI2/Operational' -MaxEvents 200 |
  Where-Object LevelDisplayName -in 'Error','Ошибка' | Format-List TimeCreated, Id, Message
# 3. Выключить после разбора (журнал «шумный»)
wevtutil sl Microsoft-Windows-CAPI2/Operational /e:false
```

Имя канала совпадает с путём в «Просмотре событий» (Журналы приложений и служб → Microsoft → Windows → CAPI2 → Operational) [ИТС-мет 5949]; если команда не находит журнал, имя проверить так: `wevtutil el | findstr /i capi2` [практика].

Что делать:

1. Дать учётной записи процесса доступ к адресу CRL (прокси, правила сетевого экрана) или запустить службу от доменной учётной записи, у которой доступ есть [ИТС-мет 5949, 2018].
2. Параметр `IgnoreServerCertificatesChainRevocationSoftFail` в `conf.cfg`: в статье 2018 года по умолчанию ошибки проверки отзыва давали исключение и параметр предлагалось ставить в `true`; в документации 8.3.27 умолчание уже `true` — соединение устанавливается, если отзыв проверить нельзя, а отозванный сертификат всё равно отвергается [ИТС-мет 5949, 2018; ИТС-адм прил. 3.17.16]. Если ошибка есть на 8.3.27 — проверьте, не задан ли в `conf.cfg` явный `false`.
3. В техжурнале включить событие `WINCERT` — оно покажет, какой вызов Windows API не прошёл и код ошибки (разд. 5.4).

## 8. Счётчики производительности и анализ загрузки

### 8.1. Права на сбор счётчиков

- Учётная запись процессов кластера должна входить в группу «Пользователи журналов производительности» (Performance Log Users) [ИТС-КС разд. 1.3.2] — команда в разд. 4.5.
- Для сбора счётчиков агентом ЦКК (КИП) учётная запись агента — в группе «Пользователи системного монитора» (Performance Monitor Users) [ИТС-мет 5838, 2021; ИТС-мет 5899, 2016].
- Создавать сборщики `logman` — от администратора или члена Performance Log Users [практика].

### 8.2. Набор счётчиков (статья 5838)

Обязательный набор для всех серверов кластера, сервера СУБД и нагруженных рабочих станций, частота — раз в 15 секунд на рабочей системе, раз в секунду в нагрузочных тестах [ИТС-мет 5838, 2021]. Имена ниже — английские, как в статье; в списке статьи два счётчика продублированы, а пути процессов записаны с лишними кавычками (`"\Process("1cv8*")\…"`) — здесь исправлено [ИТС-мет 5838, 2021].

```powershell
New-Item -ItemType Directory -Force 'D:\PerfLogs' | Out-Null
@'
\Processor(_Total)\% Processor Time
\Processor(_Total)\% User Time
\Processor(_Total)\% Idle Time
\Processor(_Total)\Interrupts/sec
\System\Processor Queue Length
\System\Context Switches/sec
\System\Processes
\System\Threads
\System\File Read Bytes/sec
\System\File Write Bytes/sec
\Memory\Available MBytes
\Memory\Pages/sec
\PhysicalDisk(_Total)\Avg. Disk Queue Length
\PhysicalDisk(_Total)\Avg. Disk sec/Read
\PhysicalDisk(_Total)\Avg. Disk sec/Write
\LogicalDisk(_Total)\% Free Space
\Network Interface(*)\Bytes Total/sec
\Process(ragent*)\% Processor Time
\Process(ragent*)\Private Bytes
\Process(ragent*)\Virtual Bytes
\Process(rmngr*)\% Processor Time
\Process(rmngr*)\Private Bytes
\Process(rmngr*)\Virtual Bytes
\Process(rphost*)\% Processor Time
\Process(rphost*)\Private Bytes
\Process(rphost*)\Virtual Bytes
\Process(rphost*)\ID Process
'@ | Set-Content -Encoding ASCII 'D:\PerfLogs\1c-counters.txt'
```

Пояснения:

- `\Memory\Pages/sec` и `\Network Interface(*)\Bytes Total/sec` — из таблицы пороговых значений статей 2923 и 5838; `\Process(rphost*)\ID Process` добавлен, чтобы сопоставлять экземпляры `rphost#1`, `rphost#2` с PID (разд. 8.5) [практика].
- Частичная маска в имени экземпляра (`rphost*`) взята из статьи 5838 ⚠; если сборщик не находит такие счётчики, использовать `\Process(*)\…` и фильтровать при анализе [практика].
- Имена счётчиков «могут незначительно отличаться в зависимости от версии ОС» [ИТС-мет 5838, 2021]; на русской Windows консоль показывает их по-русски, а `logman`/`typeperf` обычно принимают английские ⚠ — проверить: `typeperf -q Memory` и `typeperf -qx Process` [MS Learn, typeperf].
- Счётчики MS SQL Server (блокировки, ожидания, буферный кэш) — `02-ms-sql-server-dlya-1c.md`.

### 8.3. Сбор `logman`, просмотр `typeperf`, выгрузка `relog`

```powershell
# Сборщик: кольцевой двоичный файл до 2 ГБ, раз в 15 с [параметры — MS Learn, logman create counter]
logman create counter 1C_server -f bincirc -max 2048 -si 15 -cf 'D:\PerfLogs\1c-counters.txt' -o 'D:\PerfLogs\1C_server'
logman start 1C_server
logman query 1C_server            # состояние Running, путь к файлу .blg
# logman stop 1C_server  /  logman delete 1C_server

# Сборщик не стартует сам после перезагрузки — задача планировщика при загрузке [ИТС-мет 5838/5899; синтаксис — практика]
schtasks /create /tn "1C_perf_start" /sc onstart /ru SYSTEM /tr "logman start 1C_server"

# Быстрый просмотр без сборщика: 12 замеров раз в 5 с
typeperf "\Processor(_Total)\% Processor Time" "\Memory\Available MBytes" "\System\Processor Queue Length" -si 5 -sc 12

# Выгрузка .blg в CSV для анализа (каждое 4-е значение — раз в минуту)
relog 'D:\PerfLogs\1C_server_000001.blg' -f csv -o 'D:\PerfLogs\1C_server.csv' -t 4
```

Двоичный `.blg` открывается в Performance Monitor двойным щелчком: для выбранного счётчика видны среднее, минимум, максимум; интересны среднее и пики [ИТС-мет 5838, 2021]. Формат CSV удобен для программной обработки, но ограничен 2 ГБ на файл [MS Learn, logman create counter]. Имя файла с номером версии (`_000001`) зависит от параметров `-v`/`-cnf` ⚠ — смотреть в `logman query`.

Альтернатива для сбора и анализа — ЦКК из «Корпоративного инструментального пакета» (сбор через агент КИП или Performance Data Helper) [ИТС-мет 5838, 2021].

### 8.4. Пороговые значения (статьи 2923 и 5838)

| Счётчик | Критерий (5838, 2021 — действующий) | Было в 2923 (2008) | Узкое место |
|---|---|---|---|
| `Memory\Pages/sec` | среднее около 0, максимум не более 20 | > 20 — добавлять память | память |
| `Processor(_Total)\% Processor Time` | не более 70% длительное время | > 85% в среднем | процессор |
| `System\Processor Queue Length` | не более 2 × число ядер длительное время | > 2 длительное время | процессор |
| `PhysicalDisk\Avg. Disk Queue Length` | не более 2 × число параллельно работающих дисков | рост очереди | дисковая подсистема |
| `Network Interface\Bytes Total/sec` | не более 65% пропускной способности адаптера | то же | сеть |
| `SQL Server: Locks\…` | — | `Lock Wait Time (ms)`, `Average Wait Time (ms)`, `Number of Deadlocks/sec` ≠ 0 — проблема | блокировки СУБД (`02-ms-sql-server-dlya-1c.md`) |

Статья 2923 написана под 8.0/8.1 и SQL Server 2000/2005 (рекомендации вроде «диски SCSI» устарели), но перечень счётчиков и логика остаются; пороги брать из 5838 [ИТС-мет 2923, 2008; ИТС-мет 5838, 2021]. Для остальных счётчиков значения зависят от оборудования и нагрузки — сравнивать со своей «нормой» [ИТС-мет 5838, 2021].

### 8.5. Процессы `rphost` в счётчиках: экземпляры и PID

Несколько одноимённых процессов Windows показывает как экземпляры `rphost`, `rphost#1`, `rphost#2`…; номер не постоянен и меняется при перезапуске процессов [практика]. Чтобы понять, какой экземпляр — какой процесс кластера, собирать `\Process(rphost*)\ID Process` и сверять PID со списком процессов в консоли кластера (или `rac process list`) [практика]. Существует настройка реестра `ProcessNameFormat` для подсистемы `PerfProc`, добавляющая PID к имени экземпляра ⚠ — на MS Learn в эту сессию найдено описание только аналогичного параметра для счётчиков .NET; применять после проверки на стенде.

```powershell
# Текущая картина по процессам 1С: CPU и частная память (без сборщика)
Get-Counter '\Process(rphost*)\% Processor Time','\Process(rphost*)\Private Bytes','\Process(rphost*)\ID Process' -SampleInterval 5 -MaxSamples 1 |
  Select-Object -ExpandProperty CounterSamples | Sort-Object InstanceName, Path |
  Format-Table InstanceName, Path, CookedValue -AutoSize
```

`% Processor Time` процесса считается от одного ядра: на 16-ядерном сервере процесс, занявший все ядра, покажет до 1600% [практика].

### 8.6. Память процесса: как её считает кластер

Мониторинг кластера каждые 5 секунд проверяет процессы; «память, занимаемая процессом» на Windows — значение `PagefileUsage` структуры `PROCESS_MEMORY_COUNTERS`, на Linux — сумма `VmRSS` и `VmSwap` [ИТС-КС разд. 2.2.12]. `PagefileUsage` соответствует частной выделенной памяти процесса — ближайший счётчик `\Process(...)\Private Bytes` [практика ⚠ — соответствие по MS Learn не сверялось]. С этим значением сравниваются параметры рабочего сервера: «Временно допустимый объём памяти процессов» (`0` = 80% ОЗУ; при превышении — новые соединения не назначаются, затем «мягкий» перезапуск самых больших процессов) и «Критический объём памяти процессов» (`0` = 95%; аварийное завершение самых больших процессов, с дампом — если включено свойство кластера, разд. 6.2); `-1` отключает проверку; событие `ATTN` пишется в техжурнал [ИТС-КС разд. 2.2.12].

Сетевой стек под большое число соединений (`MaxUserPort`, `TcpTimedWaitDelay`, динамический диапазон портов — [ИТС-мет 5908, 2022]) — `06-windows-server-dlya-administratora-1c.md`, разд. 6.2.

## 10. Смешанная среда: клиенты Windows и сервер 1С на Linux

Как это выглядит у пользователя базы: сервер 1С на `srv-1c-app` (Ubuntu), СУБД на `srv-1c-db`, рабочие места — Windows, ВМ — на Windows-хосте.

**Лицензии**

1. Серверная лицензия должна быть доступна компьютеру, где работают `rphost`: программная — в `/var/1C/licenses` на `srv-1c-app` (или на рабочем сервере, куда назначен сервис лицензирования), аппаратная `EN8SA` — локально в этой ВМ [ИТС-адм разд. 10.2.6.1, 10.3.5.1]. Серверный ключ в Windows-компьютере пользователя Linux-серверу не поможет — по сети он недоступен. Проброс USB в ВМ — `../1c/04-licenzirovanie.md`, разд. 6.9; USB over IP не поддерживается [ИТС-адм разд. 10.2.3].
2. Клиентские лицензии проще всего держать **на сервере** (многопользовательская программная лицензия в `/var/1C/licenses`; у базы разрешена выдача лицензий сервером) — расход «на сеанс» [ИТС-адм разд. 10.3.4.3.2; `../1c/04-licenzirovanie.md`, разд. 5.3].
3. Сетевой ключ HASP можно вставить в любой Windows-компьютер (в том числе Windows-хост ВМ) с HASP License Manager: его лицензии получат и Windows-клиенты напрямую («на компьютер»), и Linux-сервер для клиентов, которые сами лицензию не нашли («на сеанс»). На сервере — `/opt/1cv8/conf/nethasp.ini` с `NH_SERVER_ADDR=<адрес Windows-компьютера>`; на Windows-компьютере — входящий UDP 475 [ИТС-адм разд. 10.4.1, 10.2.9; практика]. Не раздавать один ключ одновременно менеджером клиентам и сервером 1С — лицензии с `Timeout = 0` сервер сочтёт занятыми [ИТС-адм разд. 10.2.5.11].
4. На Windows-клиентах, получающих лицензии только от сервера, — `UseHwLicenses=0` (быстрее запуск, нет случайного захвата ключа) [ИТС-адм прил. 3.6.15]; при массовой установке — `setup.exe USEHWLICENSES=0` [ИТС-адм разд. 2.5.2.1].
5. При переходе на 8.5.4: на компьютере с сетевым ключом — `rmlic` службой, TCP/UDP 475 и 1544, часы всех машин синхронны (расхождение не больше 20 минут); на Linux-сервере — первым запускать агента кластера [ИТС-мет 6041, 2026].

**Диагностика**

6. Серверный техжурнал и дампы — на Linux (`../1c/07-tehzhurnal-diagnostika-zhurnal-registracii.md`); на Windows-клиентах — свой `logcfg.xml`: для одного пользователя без прав администратора — `%LOCALAPPDATA%\1C\1cv8\conf\logcfg.xml`, для всех — `C:\Program Files\1cv8\conf\logcfg.xml` [ИТС-адм прил. 1.3.4]. Дампы падений клиента по умолчанию уже пишутся в `%LOCALAPPDATA%\1C\1cv8\dumps` (минимальные) [ИТС-адм разд. 6.14.2].
7. Пример клиентского `logcfg.xml` для расследования «тормозит у одного пользователя» (полный клиентский журнал — шаблон К, `../its-metod/sbor-dannyh-dlya-rassledovaniya-problem.md`, п. 6):

```xml
<?xml version="1.0" encoding="UTF-8"?>
<config xmlns="http://v8.1c.ru/v8/tech-log">
  <dump create="true" location="C:\1C-diag\dumps" type="3" prntscrn="true"/>
  <log location="C:\1C-diag\tj" history="4">
    <event><ne property="Name" value=""/></event>
    <property name="all"/>
  </log>
</config>
```

   Условие `<ne property="Name" value=""/>` («имя события не пустое») отбирает все события; элементы сравнения `eq`, `ne`, `gt`, `ge`, `lt`, `le`, `like` описаны в [ИТС-адм прил. 3.24.2.3]; «полный» журнал для Linux — `../1c/07-…`, разд. 7.5. Журнал быстро растёт — включать на минуты, затем удалять файл.

8. Ошибки сертификатов на Windows-клиентах (HTTP-сервисы, ЭДО, обновления) — CAPI2 и `WINCERT` (разд. 7.3); на Linux-сервере эти механизмы не работают: там сертификаты проверяются по `/etc/ssl/certs` и `cacertnx.pem` (`../1c/09-klient-linux-i-otlichiya-ot-windows.md`, разд. 7).
9. Консоль MMC на Windows-машине администратора работает с Linux-кластером напрямую (порт агента 1540), но версия зарегистрированной консоли (`RegMSC.cmd`) должна совпадать с версией сервера [ИТС-КС разд. 4.1 — пункт меню «Регистрация утилиты администрирования серверов (A.B.C.D)»; `../1c/02-ustanovka-servera-ubuntu.md`, п. 13 «Кратко»].
10. Память процессов сервера на Linux сравнивается с порогами по `VmRSS + VmSwap`, а не по `PagefileUsage` — цифры «из Windows-опыта» переносить с поправкой [ИТС-КС разд. 2.2.12].
