# /1c-platform-kb — база знаний по платформе 1С и окружению

Снимок базы знаний администратора 1С (149 статей, сверены с первоисточниками: документацией ИТС 8.3.27, PostgreSQL 18, Microsoft, Ubuntu Server). Статьи лежат в `references/`; читаются по нужде, целиком не загружаются.

**Что внутри и когда открывать.** 1С на Linux и Windows, кластер `ras`/`rac`, `ibcmd` и пакетный режим `1cv8`, технологический журнал, служебные файлы, лицензии, веб-публикация (Apache, nginx, IIS), PostgreSQL и MS SQL для 1С, Linux Ubuntu, Kafka и RabbitMQ в обмене с 1С, конспекты документации ИТС 8.3.27 (руководства администратора и разработчика) и методички ИТС. Открывать, когда нужен факт о платформе, утилите, ключе запуска, событии техжурнала, настройке СУБД, веб-сервера или ОС, о механизме платформы (транзакции, блокировки, расширения, фоновые задания, сервисы интеграции) — и его нет в справке `bsl-platform`/`bsl-context` и в стандартах `v8std`.

## Как искать

1. Открыть `references/INDEX.md`: в начале — «Состояние проверки» (что сверено, что нет), дальше «Маршрутизатор «задача → файл»» и оглавление каждого раздела со списком глав статей. Пути в нём — от каталога `references/`.
2. Найти место поиском (Grep) по ключевому слову — имя команды, ключа, параметра, события, текст ошибки — в нужном каталоге `references/<раздел>/`.
3. Читать найденную статью частями (`offset`/`limit`): тематические статьи весят 150–300 КБ.

## Чему верить

- **Факты о платформе** (ключи `ibcmd`, `rac`, `webinst`, `1cv8`, служебные файлы, пути, порты, умолчания) — конспектам `its-docs/`: в них номера разделов документации. Параметры `rac` в документации нет — они из `rac help` и помечены.
- **`dev-*`:** в начале каждого — строка «Как читалось»; часть глав прочитана обзорно.
- **`its-metod/`** — официальные рекомендации, но многие 2007–2016 годов: у каждой статьи строка «Оценка применимости».
- **Пометка «⚠ не подтверждено»** — утверждение не удалось проверить по первоисточнику: не выдавать его за факт, сказать пользователю, как проверить на его сервере. Список открытых вопросов — `guides/06`.
- **Живой прогон — только у части руководств:** сквозной пример `1c/02` разд. 16 (сервер 8.3.27.2214 на Ubuntu 24.04.5, 20.10.2026) и `guides/07` («PostgreSQL для 1С» 18.4, 21.10.2026) прогнаны на тестовых ВМ; остальные `guides/` — нет. Статьи `kafka/`, `rabbitmq/`, `postgresql/10` независимой сверки не проходили.
- **Расхождения живого прогона `1c/02` разд. 16 (20.10.2026), пока снимок не обновлён:** в той установке Ubuntu Server нет `ufw` и `fuser` — ставить отдельно (`apt install ufw psmisc`); `apt-get` — с `-o DPkg::Lock::Timeout=120` (параллельный apt держал блокировку dpkg); кроме `ragent`/`rmngr`/`rphost` кластер сразу поднимает `dbda` (Дата акселератор) на портах 1561–1562 — внутри диапазона 1560–1591, но в сводке портов статьи его нет.
- **Версия** — 8.3.27; для 8.5.x — `its-docs/otlichiya-8.5.1-ot-8.3.27.md`. Изменчивое (версии, сроки поддержки) — перепроверить по первоисточнику.
- **Справка платформы и стандарты** по-прежнему — `bsl-platform`/`bsl-context` и `v8std`: эта база их дополняет (как устроено и как администрируется), а не заменяет.

## Где перепроверять изменчивое без сервера

Версии, юниты и состав пакетов меняются — их сверяют по первоисточнику (probe-tool-capabilities), а не по статье:
- пакеты Ubuntu и Debian — `packages.ubuntu.com/<выпуск>/<арх>/<пакет>/filelist`, `changelogs.ubuntu.com`, исходники — `git.launchpad.net/…/plain/debian/…?h=ubuntu/<выпуск>-updates` и API `salsa.debian.org`;
- «PostgreSQL для 1С» — `https://repo.postgrespro.ru` (документация — раздел doc/pg1c по версии, состав ветки — файл meta.json в каталоге ветки 1c, индекс Packages); пакет `.deb` разбирается без установки: `tar.exe` по `control.tar.zst` и `data.tar.zst`, сумма — по `Packages`;
- сроки поддержки Windows и SQL Server — `learn.microsoft.com/lifecycle`;
- ИТС: методички `its.1c.ru/db/metod8dev` открыты без входа, но текст во фрейме в windows-1251 — `WebFetch` портит кириллицу, читать скиллом `page-fetch`; документация 8.3.27 — `its.1c.ru/db/v8327doc`, нужен вход владельца (пароли агент не вводит); документация 8.5.4 и инструкция по программным лицензиям под подпиской закрыты (403).

## Особенно важно для разработки

- `its-docs/dev-gl09` — транзакции, объектные и управляемые блокировки; `dev-gl02` — выгрузка в XML и режим совместимости; `dev-gl30` — расширения; `dev-gl31` — отладка; `dev-gl37-gl38` — хранилище, поставка, поддержка; `dev-gl17` — интеграция; `dev-pr07` — особенности режимов; `dev-prilozheniya` — особенности СУБД, навигационные ссылки, JSON.
- `its-docs/adm-pr04` (`ibcmd`, `ragent`, `webinst`) и `adm-pr07` (параметры `1cv8`, пакетный режим) — по полным текстам. В 8.3.27 `ibcmd config …` и `ibcmd infobase config …` равноценны (разд. 4.10.5); `config export --file` без подключения к базе — только с 8.5.4.
- `postgresql/10`, разд. 2 — чек-лист «что в запросе 1С дорого на PostgreSQL» с номерами стандартов v8std (сам стандарт — через `v8std`).
- Техжурнал — `its-docs/adm-pr03` p3–p5 и `1c/07` (готовые `logcfg.xml` — разд. 7): `<plansql/>` — только на тестовом сервере.
- «PostgreSQL для 1С»: сначала узнать, чья сборка на хосте (1С, Postgres Pro, PGDG) — на хост с `postgrespro-1c` не ставить `postgresql` из Ubuntu или PGDG (конфликт `postgresql-common`); быстрая установка применяет только `default.tune` — при разборе проблем первым делом проверить `max_locks_per_transaction = 256`, `standard_conforming_strings = off` и plantuner (живой прогон 18.4, `guides/07`).
- PostgreSQL 19 всегда держит `standard_conforming_strings = on`, а 1С требует `off`; в бесплатной сборке «PostgreSQL для 1С» 16.14 нет `pg_hint_plan`, `pg_wait_sampling`, `pgpro_pwr`, `ptrack`; `auto_dump` сборки и `auto_dump` из методичек ИТС — разные (`guides/07`, разд. 8.7).
- Команды для сервера давать точные, с пользователем (`root`, `postgres`, `usr1cv8`) и способом проверить результат; рабочий сервер и рабочую базу не трогать ([secrets-and-production-database](../../docs/safety/secrets-and-production-database.md)).

## Ограничение

Конспекты ИТС — пересказ платного материала по подписке владельца своими словами. С 13.11.2026 скилл входит и в открытый репозиторий ядра — решение владельца (ADR-0014 мастера, `THIRD-PARTY.md`). Дословно тексты ИТС в ответы и файлы не переносить — пересказ со ссылкой на раздел.

## Обновление снимка

Источник — база знаний администратора владельца; разделы Redmine, NetBox и стенда наблюдаемости в снимок не входят. Обновляет мастер ядра: `python tools/indexes/sync-platform-kb.py --src <каталог kb>` показывает новые, изменённые и пропавшие статьи, с `--apply` — записывает снимок; в проекты обновление приходит с выпуском ядра.
