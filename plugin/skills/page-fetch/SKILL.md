# /page-fetch — Чистое чтение веб-страницы

Извлекает читаемую часть страницы в markdown через `defuddle` и **кладёт в файл**, откуда её можно читать точечно (`Read` с `offset`/`limit`), не заливая контекст целиком.

## Использование

```
/page-fetch <URL> [-o OutputPath]
```

По умолчанию результат — `<scratchpad>/page-<хост>.md`.

## Команда

```bash
defuddle parse "<URL>" --md -o "<OutputPath>"
```

Затем читать файл `Read`-ом — сначала объём (`wc -c`), потом нужные фрагменты.

## Когда применять именно этот скилл, а не WebFetch

| Ситуация | Инструмент |
|---|---|
| Нужен **дословный** текст: стандарт, спецификация, документация к API, длинный README | **`/page-fetch`** — WebFetch отдаёт пересказ малой моделью, детали и точные формулировки теряются |
| Страницу надо читать **по частям** или возвращаться к ней | **`/page-fetch`** — файл переживает ход, повторное чтение бесплатно |
| Нужен короткий ответ на вопрос по странице | `WebFetch` — дешевле, ответ сразу |
| URL заканчивается на `.md` / это raw-файл | `WebFetch` напрямую — извлекать нечего |
| Структура GitHub-репозитория, список файлов, релизы, метаданные | `gh api` — факты, а не отрендеренная страница |
| Страница за авторизацией, приватный ресурс | ни то ни другое — `gh`/MCP с доступом |

## Требование среды и деградация

`defuddle` — внешний CLI (npm-пакет, ставится глобально), **в git ядра не входит** и в свежей копии может отсутствовать. Проверка и установка — версией, проверенной в мастере ядра (0.19.6), и **только с согласия владельца**: это установка программы из npm:

```bash
defuddle --version || npm install -g defuddle@0.19.6
```

Нет Node/npm или установка невозможна — **не блокируемся**: берём `WebFetch` и отмечаем в ответе, что чтение шло пересказом, а не дословно.

## Проверка результата

1. `exit code` = 0 и файл непустой (`wc -c`) — иначе страница отдала пусто/защиту от ботов → `WebFetch`.
2. Первые строки — осмысленный заголовок, а не мусор разметки.
3. Кириллица не побита (UTF-8 подтверждён зондом на русскоязычной странице).
