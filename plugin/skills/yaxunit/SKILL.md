# YAXUnit: написать тест и прогнать

Тесты живут **отдельным расширением** (`<Префикс>_Тесты`), не в основной конфигурации; один общий модуль — на объект тестирования. Прогон — команда `/ones-core:tests yaxunit` (харнесс `tools/yaxunit/run-tests.py`, рецепт `docs/tools/task-recipes.md` §12). Справочник API — `references/api.md`: экспортные методы движка 25.12, собранные из модулей поставки, а не по памяти.

## Структура модуля

```bsl
#Область СлужебныйПрограммныйИнтерфейс

Процедура ИсполняемыеСценарии() Экспорт

	ЮТТесты
		.ДобавитьТестовыйНабор("Расчёт скидки")
		.ДобавитьТест("СкидкаНеБольшеСуммы")
		.ДобавитьТест("ПустаяСуммаБезСкидки");

КонецПроцедуры

#КонецОбласти

#Область Тесты

Процедура СкидкаНеБольшеСуммы() Экспорт

	Скидка = ПР_Скидки.РассчитатьСкидку(100, 150);

	ЮТест.ОжидаетЧто(Скидка, "скидка не больше суммы").Равно(100);

КонецПроцедуры

#КонецОбласти
```

- `ИсполняемыеСценарии()` — **без параметров** (с параметром движок пишет предупреждение об устаревшей сигнатуре); вызовы `ЮТТесты` идут цепочкой.
- Контекст: `ДобавитьТест` — во всех контекстах модуля, `ДобавитьСерверныйТест` / `ДобавитьКлиентскийТест` — явно; `ВТранзакции()` — откат данных теста транзакцией; `УдалениеТестовыхДанных()` — удалить созданное.
- Имя теста называет **поведение** («СкидкаНеБольшеСуммы»), а не метод. Язык имён — по языковому профилю проекта.

## Утверждения

- Значение: `ЮТест.ОжидаетЧто(Значение, "что проверяем")` → `.Равно`, `.Больше`, `.Заполнено`, `.ИмеетТип`, `.Содержит`, `.ИмеетДлину`, `.ЭтоИстина`, `.Свойство("Имя").Равно(…)`, `.ВСписке`, `.МеждуВключаяГраницы`.
- Исключение: `ЮТест.ОжидаетЧто(Модуль).Метод("Имя").Параметр(1).ВыбрасываетИсключение("текст")`.
- Данные базы: `ЮТест.ОжидаетЧтоТаблицаБазы("РегистрНакопления.Остатки").СодержитЗаписи(ЮТест.Предикат()...)`, `СодержитТолькоОднуЗапись`, `СодержитЗаписиСКодом`.
- Явный провал — `ЮТест.Упал("причина")`, пропуск — `ЮТест.Пропустить("причина")`.

## Тестовые данные и моки

- `ЮТест.Данные()` (модуль `ЮТТестовыеДанные`): `СоздатьЭлемент`, `СоздатьДокумент`, `КонструкторОбъекта(Менеджер)`, `КонструкторДвижений(Документ, ИмяРегистра)`, `СлучайнаяСтрока`, `УникальнаяСтрока`, `Фикция(ТипЗначения)`, моки `HTTPСоединение()`, `HTTPОтвет()`.
- Чтение данных — `ЮТЗапросы`: `ЗначениеРеквизита`, `Записи`, `ДвиженияДокумента`.
- Подмена вызовов — `Мокито`: `Мокито.Обучение(Модуль).Когда("Метод").Вернуть(Результат).Прогон()`, после теста — `Мокито.Проверить(Модуль).КоличествоВызовов("Метод").Равно(1)`.
- Данные — только в тестовой базе (secrets-and-production-database); настоящих данных о людях в тестах нет (personal-data-masked-from-1c).

## Три антипаттерна (тест, который врёт)

1. **Связанность с реализацией** — тест знает порядок вызовов и внутренние функции: краснеет от рефакторинга при живом поведении. Проверять наблюдаемое: возврат, движения регистров, записанные данные.
2. **Тавтология** — эталон вычислен тем же кодом. Эталон независим: литерал, ручной расчёт, цифра из ТЗ.
3. **Горизонтальная нарезка** — тест на каждый метод вместо теста на поведение через шов. Шов (экспортный метод общего модуля, менеджер, проведение) согласуется с владельцем до тестов.

## Порядок работы

1. Шов и поведение — по проработке доработки (design-before-code), регрессионный тест на баг — **до** исправления (bug-diagnosis-loop).
2. Тест-модуль — в расширении тестов: создать модуль скиллом `meta-compile` (общий модуль) в исходниках расширения, тело — по шаблону выше; для EDT-проекта — через `edt-mcp`. Флаги — явно `"server": true` (клиентские тесты — ещё `"clientManagedApplication": true`), **без** «Вызов сервера» и «Глобальный»: такой модуль движок пропускает, и прогон даёт 0 тестов (сокращение `context: "server"` ставит Вызов сервера).
3. Загрузить расширение в тестовую базу (`db-load-xml -Extension`, `db-update -Extension`; свойства — `db-cfe-admin`: безопасный режим и защита от опасных действий выключаются у расширения тестов, §12 п.4).
4. Прогон — `/ones-core:tests yaxunit <ИмяРасширенияТестов>`; новый тест сначала **красный**, после правки — зелёный. Красный тест чинится правкой кода: не ослаблять утверждение, не брать эталон из выдачи кода, не пропускать и не удалять тест. Тест неверен — сказать владельцу и править только после его «да» (bug-diagnosis-loop Ф5).
5. Итог — в отчёт по чекерам (full-checker-set-before-done): красный тест — правка не готова.

Источник API — поставка YAxUnit 25.12 (bia-technologies/yaxunit, Apache-2.0); справочник обновляется при смене версии движка в `plugin/tools/setup/tools-manifest.json`.
